## 🤔 고민했던 점 및 설계 의사결정

- **Lesson 파일 관리 방식 고민 (정적 생성 vs 동적 조립):** 
  매번 100개가 넘는 HTML을 통째로 렌더링하면 유지보수가 불가능할 것이라 판단했습니다. 본문(Contents)만 분리하고, 뼈대(Viewer)는 JS 로직으로 런타임에 조립하는 방식으로 결정했습니다. 이는 React/Vue 같은 무거운 SPA 프레임워크 없이 순수 바닐라 JS만으로도 충분히 모듈화를 달성할 수 있음을 증명하기 위한 설계 선택이었습니다.

- **용어 사전 팝업 충돌 문제:** 
  기존에 널리 쓰이던 `data-term` 속성이 `common.js`의 무거운 모달 창과 강력하게 연결되어 있어, 단순히 가벼운 툴팁만 띄우려는 새로운 기획과는 부적합했습니다. 기존 코드를 수정하면 다른 페이지들이 망가질 위험(Side-effect)이 컸기 때문에, 아예 독립적인 `data-glossary`라는 새로운 네임스페이스(Namespace)를 부여하여 충돌을 원천 차단했습니다.

- **클릭 고정(Pin) UX 설계:** 
  "텍스트를 복사하고 싶다"는 사용자의 명확한 니즈를 충족시키기 위해 고민했습니다. 툴팁이 마우스가 벗어나는 순간 사라지면 모바일 환경이나 텍스트 복사 시 극도로 불편합니다. 이를 해결하기 위해 클릭 시 `.pinned` CSS 클래스를 토글하고, `pointer-events: auto`를 부여하여 상호작용이 가능하게 만들었으며, 외부 빈 공간을 클릭하면 닫히는(Outside Click) 범용적인 UX 패턴을 적용했습니다. 또한 X (닫기) 버튼을 추가해 마우스 사용자에게 직관적인 탈출구를 제공했습니다.

- **네비게이션 탭의 역할 분리:**
  처음에는 요구사항을 "목차를 Chapter로 대체하라"로 오해하여, 원래 있던 Lesson 목차를 덮어써버리는 실수를 했습니다. 하지만 사용자의 진정한 의도가 '현재 위치(Lesson)' 파악과 '전체 숲(Chapter 진척도)' 파악 모두를 원한다는 것을 깨닫고, 2개의 탭으로 분리하여 각자의 목적에 맞는 UI를 독립적으로 배치하는 방향으로 선회했습니다.
