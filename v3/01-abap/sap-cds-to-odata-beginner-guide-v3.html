CDS View에서 OData 노출까지

S/4HANA에서 CDS View를 설계하고, Interface View와 Projection View를 분리한 뒤, Service Definition과 Service Binding으로 OData 서비스를 노출하는 전체 흐름을 정리한다.

P0 CDS OData 예상 50~60분
01 · 큰 그림

CDS는 데이터 모델이고 OData는 외부로 노출되는 서비스 계약이다

CDS View는 DB 테이블을 직접 화면에 연결하기 위한 도구가 아니다. 데이터 의미, 키, 연관관계, 금액/수량 단위, 권한, 노출 범위를 명확히 정의하는 모델링 계층이다. OData는 이 모델을 UI5, Fiori Elements, 외부 소비자가 사용할 수 있도록 HTTP 기반 서비스로 노출하는 계약이다.

1
원천 테이블 확인

SCARR, SPFLI, SFLIGHT 같은 표준 테이블의 키, 단위, 관계를 확인한다.

2
Interface View 작성

ZI_* View에서 원천 데이터를 안정적인 재사용 모델로 정의한다.

3
Projection View 작성

ZC_* View에서 UI나 서비스 소비자에게 보여줄 필드와 의미를 정리한다.

4
Service Definition / Binding

노출 대상을 선택하고 OData V2 또는 V4 서비스로 바인딩한다.

5
Metadata와 EntitySet 테스트

Service Binding Preview, Gateway Client, Browser Network에서 실제 응답을 확인한다.

02 · View Layer

Interface View와 Projection View를 분리하면 변경 영향이 줄어든다

구분 이름 예시 역할 초급자 관점
Interface View ZI_JHY_Flight 원천 테이블을 재사용 가능한 의미 모델로 감싼다. DB 구조를 바로 노출하지 않고 안정적인 내부 모델을 만든다.
Projection View ZC_JHY_Flight 소비자에게 필요한 필드와 노출 형태를 정리한다. UI, OData, Fiori Elements가 사용할 외부 계약에 가깝다.
Service Definition ZUI_JHY_FLIGHT 어떤 Projection View를 서비스로 노출할지 선언한다. 서비스에 포함할 Entity 목록을 정한다.
Service Binding ZUI_JHY_FLIGHT_O2 OData 프로토콜과 런타임 노출 방식을 결정한다. Preview와 Metadata 확인의 출발점이다.
03 · Interface View

ZI_* View는 원천 데이터를 안정적으로 감싸는 계층이다

아래 예시는 SFLIGHT를 기준으로 항공편 데이터를 읽는 Interface View다. 실습에서는 먼저 키 필드와 금액/통화 필드를 명확히 지정한다. 

@AbapCatalog.viewEnhancementCategory: [#NONE]
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: 'Interface View 항공편'
@Metadata.ignorePropagatedAnnotations: true
define view entity ZI_JHY_Flight
  as select from sflight
{
  key carrid     as Carrid,
  key connid     as Connid,
  key fldate     as Fldate,

      @Semantics.amount.currencyCode: 'Currency'
      price      as Price,
      currency   as Currency,
      planetype  as Planetype,
      seatsmax   as Seatsmax,
      seatsocc   as Seatsocc,

      @Semantics.amount.currencyCode: 'Currency'
      paymentsum as Paymentsum
}
실습 기준 금액 필드는 통화 필드와 함께 의미를 지정한다. 수량, 단위, 금액, 통화는 나중에 UI와 OData Metadata에서 중요한 의미 정보가 된다.
04 · Projection View

ZC_* View는 서비스 소비자에게 보여줄 형태를 정리한다

Projection View는 Interface View를 그대로 외부에 내보내는 것이 아니라, 소비자 관점에서 필요한 필드와 노출 이름, UI 관련 Annotation, 검색/필터 기준을 정리하는 계층이다. 

@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: 'Projection View 항공편'
@Metadata.ignorePropagatedAnnotations: true
define view entity ZC_JHY_Flight
  as projection on ZI_JHY_Flight
{
  key Carrid,
  key Connid,
  key Fldate,
      Price,
      Currency,
      Planetype,
      Seatsmax,
      Seatsocc,
      Paymentsum
}
주의 교육용 예제에서는 `authorizationCheck: #NOT_REQUIRED`를 사용할 수 있다. 실무에서는 권한 모델과 DCL 적용 여부를 반드시 별도로 판단한다.
05 · Service Definition

Service Definition은 노출할 Entity를 선언한다

Service Definition에서는 어떤 CDS Entity를 외부 서비스에 포함할지 결정한다. 여러 Projection View를 하나의 서비스에 묶을 수도 있지만, 초급 단계에서는 하나의 Entity부터 시작한다. 

@EndUserText.label: 'Flight Service Definition'
define service ZUI_JHY_FLIGHT {
  expose ZC_JHY_Flight as Flight;
}
명명 기준 교육용 예제에서는 Service Definition을 `ZUI_*` 또는 프로젝트 기준 Prefix로 통일하면 찾기 쉽다. 중요한 것은 CDS View와 Service 객체의 역할을 이름에서 구분하는 것이다.
06 · Service Binding

Service Binding은 실제 OData 런타임 노출 지점이다

ADT에서 Service Binding을 생성하면 Service Definition을 어떤 프로토콜로 노출할지 선택한다. S/4HANA 실습에서는 시스템 상황에 따라 OData V2 또는 OData V4 바인딩을 사용한다.

확인 항목 의미 문제가 있을 때
Activate Service Binding이 활성화되어야 Preview와 Metadata가 가능하다. 관련 CDS View, Service Definition 활성화 오류를 먼저 확인한다.
Preview EntitySet 목록과 기본 조회 결과를 확인한다. 권한, 필드 타입, 키 정의, 데이터 존재 여부를 확인한다.
$metadata OData 소비자가 읽는 서비스 구조 계약이다. Entity 이름, 필드 이름, 타입, 단위/통화 Annotation을 확인한다.
07 · 테스트 흐름

UI를 만들기 전에 서비스가 단독으로 정상 응답해야 한다

  1. CDS View Entity가 활성화되는지 확인한다.
  2. Projection View에서 필요한 필드가 보이는지 확인한다.
  3. Service Definition에 Entity가 expose 되었는지 확인한다.
  4. Service Binding을 활성화하고 Preview를 실행한다.
  5. $metadata에서 EntityType, EntitySet, 필드 타입을 확인한다.
  6. EntitySet URL을 호출해 실제 데이터가 반환되는지 확인한다.
  7. 오류가 발생하면 Browser Network와 Gateway Client에서 HTTP 상태와 응답 메시지를 확인한다.
08 · 자주 발생하는 문제

CDS 자체 오류와 OData 노출 오류를 구분한다

증상 가능한 원인 확인 위치
CDS View가 활성화되지 않음 키 누락, 타입 오류, Annotation 위치 오류 ADT Problems, DDL Source 활성화 로그
Preview에 Entity가 보이지 않음 Service Definition에 expose 누락 Service Definition Source
$metadata는 보이나 데이터가 없음 원천 테이블 데이터 없음, WHERE 조건, 권한 CDS Data Preview, SQL Console, 권한 확인
UI5 바인딩에서 필드가 비어 있음 OData 필드명과 UI Binding Path 불일치 Browser Network 응답 payload, XML View Binding
09 · 학습 완료 체크

다음 단계로 넘어가기 전에 확인한다

  1. ZI_* Interface View와 ZC_* Projection View의 역할 차이를 설명한다.
  2. 금액 필드와 통화 필드를 Metadata 관점에서 함께 봐야 하는 이유를 설명한다.
  3. Service Definition과 Service Binding의 역할 차이를 설명한다.
  4. $metadata와 EntitySet 응답을 각각 확인한다.
  5. UI 오류를 보기 전에 OData 서비스 단독 테스트를 먼저 수행한다.
  6. CDS 활성화 오류와 OData 런타임 오류를 구분한다.
