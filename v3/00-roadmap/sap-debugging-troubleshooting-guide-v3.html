SAP 디버깅 / 트러블슈팅 통합 가이드

ABAP, OData, SAPUI5 화면에서 문제가 발생했을 때 원인을 좁혀가는 순서를 정리한다.

P0핵심 문서초급자 기준Stage 6
01 · 기본 원칙

디버깅은 추측이 아니라 범위 축소 과정이다

오류가 발생하면 화면, OData 서비스, ABAP 로직, 데이터, 권한, 설정 중 어느 위치에서 문제가 시작되었는지 먼저 구분한다.

현상 확인

오류 메시지, 발생 화면, 입력값, 재현 절차를 고정한다.

계층 분리

UI, OData, ABAP, DB, 설정 중 오류 계층을 나눈다.

증거 기반 수정

Network 응답, Debugger 값, 로그를 근거로 수정 대상을 결정한다.

02 · 오류 계층

오류 위치를 계층별로 나누어 판단한다

계층대표 증상확인 도구첫 판단 기준
UI5 화면버튼 미동작, 값 비어 있음Browser DevTools, VS Code/BAS이벤트 함수명, Binding Path, Model 데이터
OData 서비스404, 500, Metadata 오류Gateway Client, NetworkURL, HTTP 상태, payload
ABAP 로직계산 오류, DumpADT Debugger, ST22입력값, Internal Table, 예외 지점
데이터 / 권한특정 사용자만 오류SAP GUI, SU53, ST05권한 객체, 필터, 데이터 존재 여부
03 · 표준 점검 순서

화면 오류는 바깥에서 안쪽으로 추적한다

1
재현 조건 고정

사용자, 화면, 입력값, 발생 시각을 기록한다.

2
Browser Console 확인

JavaScript 오류와 UI5 모듈 로딩 오류를 확인한다.

3
Browser Network 확인

OData 요청 URL, HTTP 상태 코드, 응답 payload를 확인한다.

4
Gateway Client 단독 테스트

UI를 제외하고 서비스 자체가 정상 응답하는지 확인한다.

5
ABAP Debugger 진입

서비스 로직, CDS 조건, RAP Behavior의 실제 값을 확인한다.

04 · 학습 완료 체크

다음 문서로 넘어가기 전에 확인한다

  1. UI5, OData, ABAP, 데이터/권한, 설정 계층을 구분한다.
  2. 화면 오류 발생 시 Console과 Network를 먼저 확인한다.
  3. OData 오류 발생 시 Gateway Client로 서비스를 단독 테스트한다.
  4. ABAP Debugger에서 입력값, Internal Table, 메시지 생성 지점을 확인한다.
