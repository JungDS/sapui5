Classic ABAP Report / Internal Table / ALV 입문

SAP 개발의 첫 기본기는 조건을 입력받고, 데이터를 조회하고, Internal Table에 담은 뒤, ALV로 출력하는 흐름을 이해하는 것이다.

P0 ABAP 기본기 실습 중심 예상 45~60분
01 · 큰 그림

Classic ABAP Report는 조회형 프로그램의 기본 흐름이다

Classic ABAP Report는 사용자가 Selection Screen에서 조건을 입력하고, ABAP 프로그램이 DB에서 데이터를 조회한 뒤, Internal Table에 담아 가공하고, 최종 결과를 ALV로 보여주는 구조다. 이 흐름은 이후 CDS, OData, RAP, UI5를 배울 때도 데이터 처리 사고방식의 기준이 된다.

1
조건 입력

PARAMETERS와 SELECT-OPTIONS로 사용자가 조회 조건을 입력한다.

2
DB 조회

Open SQL로 테이블이나 CDS View에서 필요한 데이터를 읽는다.

3
Internal Table 처리

조회 결과를 Internal Table에 담고 LOOP, READ, MODIFY, APPEND로 처리한다.

4
ALV 출력

사용자가 확인할 수 있도록 결과 데이터를 표 형태로 출력한다.

02 · Report 구조

Report Program은 이벤트 블록을 기준으로 읽는다

초급자는 처음부터 모든 ABAP 이벤트를 외우기보다, 조회형 Report에서 자주 쓰는 구조를 먼저 익힌다. Selection Screen 정의, START-OF-SELECTION, 데이터 조회, 출력 호출 순서가 핵심이다. 

REPORT z_demo_flight_report.

TABLES: sflight.

PARAMETERS p_carrid TYPE sflight-carrid.
SELECT-OPTIONS s_fldate FOR sflight-fldate.

START-OF-SELECTION.
  "1. 조건 기준으로 데이터 조회
  "2. Internal Table 가공
  "3. ALV 출력
핵심 Report Program은 “입력 조건 → 조회 → 가공 → 출력” 순서로 읽는다. 코드가 길어져도 이 네 단계를 기준으로 나누면 구조가 단순해진다.
03 · Selection Screen

PARAMETERS와 SELECT-OPTIONS는 입력 조건을 만드는 도구다

구문 용도 예시
PARAMETERS 단일 값을 입력받는다. 항공사 코드 1개, 회사 코드 1개
SELECT-OPTIONS 범위, 복수 값, 제외 조건을 입력받는다. 기간, 전표번호 범위, 자재번호 목록 
PARAMETERS p_carrid TYPE sflight-carrid OBLIGATORY.
SELECT-OPTIONS s_fldate FOR sflight-fldate.

Selection Screen은 단순한 화면이 아니라 SQL 조건의 출발점이다. 잘못 설계된 입력 조건은 불필요한 대량 조회와 성능 문제로 이어질 수 있다.

04 · Internal Table

Internal Table은 ABAP 프로그램 내부의 작업용 데이터 집합이다

DB 테이블은 시스템에 저장된 원본 데이터이고, Internal Table은 ABAP 프로그램 안에서 처리하는 임시 데이터다. 조회 결과를 그대로 출력하는 경우도 있지만, 실무에서는 대부분 Internal Table에서 계산, 텍스트 보강, 상태 판단, 합계 처리 같은 가공을 수행한다.

Internal Table

여러 행을 담는 메모리상의 표 구조다.

Work Area

Internal Table의 한 행을 담아 처리하는 구조다.

Structure

필드 묶음의 타입 또는 단일 행 구조를 의미한다.

TYPES: BEGIN OF ty_flight,
         carrid TYPE sflight-carrid,
         connid TYPE sflight-connid,
         fldate TYPE sflight-fldate,
         price  TYPE sflight-price,
       END OF ty_flight.

DATA gt_flight TYPE STANDARD TABLE OF ty_flight.
DATA gs_flight TYPE ty_flight.
05 · Open SQL

Open SQL은 필요한 데이터만 읽도록 작성한다

초급자는 SELECT 구문을 쓸 때 “무엇을 얼마나 읽는가”를 먼저 생각해야 한다. 전체 컬럼과 전체 행을 읽는 습관은 성능 문제로 이어진다. 

SELECT carrid,
       connid,
       fldate,
       price
  FROM sflight
 WHERE carrid = @p_carrid
   AND fldate IN @s_fldate
  INTO TABLE @gt_flight.
주의 실무 프로그램에서 조건 없는 SELECT는 피한다. 테스트 목적이라도 조회 건수와 조건을 먼저 제한한다.
06 · 데이터 처리

LOOP, READ, MODIFY, APPEND는 Internal Table 처리의 기본 동작이다

구문 역할 초급자 관점
LOOP AT Internal Table을 한 행씩 반복 처리한다. 전체 데이터 가공의 기본이다.
READ TABLE 조건에 맞는 한 행을 찾는다. 키 기준 검색과 실패 처리를 함께 본다.
MODIFY Internal Table의 기존 행을 변경한다. 어떤 행을 바꾸는지 명확해야 한다.
APPEND Internal Table에 새 행을 추가한다. 출력용 결과 테이블을 만들 때 자주 쓴다. 
LOOP AT gt_flight INTO gs_flight.
  IF gs_flight-price > 1000.
    "고가 항공편 표시 로직
  ENDIF.
ENDLOOP.
07 · ALV 출력

ALV는 조회 결과를 실무자가 읽을 수 있는 표로 보여준다

ALV는 단순 출력 도구가 아니라 정렬, 필터, 합계, 레이아웃 저장 같은 실무 기능을 제공한다. 초급 단계에서는 Internal Table을 ALV에 넘겨 화면에 표시하는 흐름을 먼저 익힌다. 

DATA go_alv TYPE REF TO cl_salv_table.

cl_salv_table=>factory(
  IMPORTING
    r_salv_table = go_alv
  CHANGING
    t_table      = gt_flight ).

go_alv->display( ).
실습 방향 먼저 SELECT 결과를 그대로 ALV로 출력하고, 이후 컬럼명, 정렬, 합계, 이벤트를 단계적으로 추가한다.
08 · 초급자 실수

문법보다 데이터 흐름을 놓치는 실수가 더 많다

실수 문제 예방 방법
조건 없는 SELECT 대량 데이터 조회와 성능 저하 Selection Screen 조건과 최대 조회 범위를 먼저 설계한다.
Internal Table 구조 혼동 필드 접근 오류 또는 잘못된 가공 TYPES, DATA 선언을 먼저 읽고 테이블 구조를 확인한다.
READ 실패 처리 누락 빈 값 또는 이전 값 사용 READ TABLE 후 `sy-subrc` 또는 결과 존재 여부를 확인한다.
ALV 출력만 확인 조회/가공 단계의 오류를 놓침 Debugger에서 SELECT 결과와 가공 후 결과를 각각 확인한다.
09 · 학습 완료 체크

다음 단계로 넘어가기 전에 확인한다

  1. Report Program의 기본 흐름을 입력 조건, 조회, 가공, 출력으로 설명한다.
  2. PARAMETERS와 SELECT-OPTIONS의 차이를 설명한다.
  3. Internal Table, Work Area, Structure의 차이를 설명한다.
  4. Open SQL에서 필요한 컬럼과 조건만 조회해야 하는 이유를 설명한다.
  5. LOOP, READ, MODIFY, APPEND의 역할을 구분한다.
  6. Internal Table을 ALV로 출력하는 기본 코드를 읽는다.
  7. Debugger로 SELECT 결과와 ALV 출력 전 데이터를 확인한다.
