SAP 디버깅 / 트러블슈팅 통합 가이드

ABAP, OData, SAPUI5 화면에서 문제가 발생했을 때 원인을 좁혀가는 순서를 정리한다. 초급자는 “어디에서 깨졌는가”를 먼저 판단해야 한다.

P0 디버깅 문제 해결 흐름 예상 35~45분
01 · 기본 원칙

디버깅은 추측이 아니라 범위 축소 과정이다

SAP 개발에서 오류가 발생하면 화면, OData 서비스, ABAP 로직, 데이터, 권한, 설정 중 어느 위치에서 문제가 시작되었는지 먼저 구분한다. 처음부터 코드를 무작정 고치면 원인이 흐려지고 같은 오류가 반복된다.

현상 확인

사용자가 보는 오류 메시지, 발생 화면, 입력값, 재현 절차를 먼저 고정한다.

계층 분리

UI, OData, ABAP, DB, 설정 중 어느 계층에서 오류가 발생했는지 나눈다.

증거 기반 수정

Network 응답, Debugger 값, 로그, 메시지 클래스를 근거로 수정 대상을 결정한다.

02 · 오류 계층

오류 위치를 계층별로 나누어 판단한다

계층 대표 증상 확인 도구 첫 판단 기준
UI5 화면 버튼이 동작하지 않음, 값이 비어 있음, Console 오류 Browser DevTools, VS Code/BAS 이벤트 함수명, Binding Path, Model 데이터 존재 여부
OData 서비스 404, 500, Metadata 오류, EntitySet 응답 없음 Gateway Client, Browser Network 서비스 URL, HTTP 상태, 응답 payload, 오류 메시지
ABAP 로직 계산 결과 오류, Validation 실패, Dump 발생 ADT Debugger, SAP GUI Debugger, ST22 입력 파라미터, Internal Table, 조건문, 예외 발생 지점
데이터 / 권한 특정 사용자만 오류, 조회 결과 차이, 빈 결과 SAP GUI, SU53, ST05, SQL Trace 권한 객체, 필터 조건, 테이블 데이터 존재 여부
설정 / 배포 로컬은 정상이나 서버 배포 후 오류 FLP 설정, 서비스 등록, 캐시, 로그 배포 경로, Component ID, Target Mapping, 캐시 상태
03 · 표준 점검 순서

화면 오류는 바깥에서 안쪽으로 추적한다

1
재현 조건 고정

사용자, 화면, 입력값, 클릭 순서, 발생 시각을 기록한다.

2
Browser Console 확인

JavaScript 오류, UI5 모듈 로딩 오류, Binding 경고를 확인한다.

3
Browser Network 확인

OData 요청 URL, HTTP 상태 코드, 응답 payload, CSRF Token 흐름을 확인한다.

4
Gateway Client 단독 테스트

UI를 제외하고 서비스 자체가 정상 응답하는지 확인한다.

5
ABAP Debugger 진입

서비스 로직, CDS 조건, RAP Behavior, Validation/Determination의 실제 값을 확인한다.

6
로그와 설정 확인

ST22, SU53, Gateway Error Log, 서비스 등록, FLP 설정을 확인한다.

04 · 증상별 판단표

자주 발생하는 증상은 첫 확인 위치가 정해져 있다

증상 우선 확인 다음 확인
화면에 데이터가 표시되지 않음 Network 응답에 데이터가 있는지 확인 Binding Path, Model 이름, Formatter 확인
저장 버튼 클릭 후 403 오류 CSRF Token 요청/전달 여부 확인 권한, 서비스 설정, HTTP Method 확인
OData 500 오류 Gateway Error Log와 응답 메시지 확인 ABAP Debugger, ST22 Dump 확인
특정 사용자만 오류 발생 SU53, 권한 객체, 사용자별 조직값 확인 필터 조건, User Exit/BAdI, CDS 권한 확인
로컬 미리보기는 정상이나 FLP에서 오류 Component ID, manifest, Target Mapping 확인 UI5 cache, app index, 배포 경로 확인
05 · ABAP Debugger 관점

ABAP Debugger에서는 값의 흐름을 확인한다

ABAP Debugger는 코드가 실행되는지 확인하는 도구가 아니라, 입력값이 어떤 조건을 지나 어떤 결과로 바뀌는지 추적하는 도구다. 초급자는 Breakpoint를 많이 찍기보다 “값이 처음 달라지는 지점”을 찾는 데 집중한다.

확인할 값

Importing parameter, Internal Table, Work Area, SELECT 결과, 메시지 변수, Exception 객체를 확인한다.

확인할 흐름

조건문 진입 여부, Loop 처리 건수, MODIFY/APPEND 결과, RETURN 이전 메시지 생성 지점을 확인한다.

06 · 주의점

초급자는 오류 메시지보다 먼저 원인 계층을 판단해야 한다

주의 같은 500 오류라도 원인은 ABAP Dump, 권한 문제, 데이터 형식 오류, 메시지 처리 오류일 수 있다. HTTP 상태 코드만 보고 결론을 내리지 않는다.
주의 화면이 비어 있을 때 곧바로 서버 로직을 수정하지 않는다. Network 응답에 데이터가 있는지 먼저 확인한다. 응답에 데이터가 있으면 UI5 Binding 또는 Formatter 문제일 가능성이 높다.
07 · 학습 완료 체크

다음 문서로 넘어가기 전에 확인한다

  1. UI5, OData, ABAP, 데이터/권한, 설정 계층을 구분한다.
  2. 화면 오류가 발생했을 때 Browser Console과 Network를 먼저 확인한다.
  3. OData 오류가 발생했을 때 Gateway Client로 서비스를 단독 테스트한다.
  4. ABAP Debugger에서 입력값, Internal Table, 메시지 생성 지점을 확인한다.
  5. 특정 사용자만 오류가 발생할 때 SU53과 권한 조건을 확인한다.
  6. 오류 수정 전 재현 조건과 증거를 기록한다.
