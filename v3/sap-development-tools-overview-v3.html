SAP Developer Learning Library

SAP 개발 환경과 도구 입문

SAP GUI, ADT, VS Code/BAS, Gateway Client, Browser DevTools가 SAP 개발 흐름에서 각각 어떤 역할을 맡는지 초급자 기준으로 정리한다.

P0 도구 초급자 기준 예상 25~35분
01 · 도구 지도

도구를 먼저 구분하면 실습 흐름이 단순해진다

SAP 개발 도구는 하나의 IDE로 끝나지 않는다. 서버 개발, 서비스 테스트, 프론트엔드 구현, 브라우저 디버깅, 운영 확인이 서로 다른 도구에서 이루어진다. 초급자는 도구 이름보다 “어느 층의 문제를 확인하는 도구인가”를 먼저 구분해야 한다.

도구 주 용도 처음 배울 때의 관점
SAP GUI T-Code 실행, 표준 화면 확인, 테이블/로그 확인 표준 SAP 동작과 시스템 상태를 확인하는 기본 진입점
ADT / Eclipse ABAP, CDS, RAP 개발 서버 로직과 데이터 모델을 작성하는 개발 도구
VS Code / BAS SAPUI5, Fiori 앱 개발 XML View, Controller, Model, npm, UI5 Tooling을 다루는 화면 개발 도구
Gateway Client OData V2 요청/응답 테스트 UI 없이 서비스가 정상 응답하는지 확인하는 API 테스트 도구
Browser DevTools UI5 화면, Network, Console 디버깅 브라우저에서 실제 요청과 화면 오류를 확인하는 도구
02 · 계층별 이해

문제가 발생한 위치에 따라 사용하는 도구가 달라진다

서버 로직 문제

ABAP Class, Function Module, CDS, RAP Behavior에서 발생한 문제는 ADT와 ABAP Debugger로 확인한다. 데이터가 잘못 계산되거나 권한/조건에 따라 결과가 달라지는 경우가 여기에 속한다.

서비스 응답 문제

OData Metadata, EntitySet, HTTP 상태 코드, payload 문제는 Gateway Client와 Browser Network에서 확인한다. UI가 없어도 서비스만 독립적으로 테스트할 수 있어야 한다.

화면 바인딩 문제

UI5 View, Controller, Model, Binding Path 문제는 VS Code/BAS와 Browser DevTools에서 확인한다. 화면에 값이 비어 있으면 먼저 Network 응답과 Binding 경로를 함께 본다.

운영 상태 문제

서비스 등록, 시스템 설정, 표준 로그, T-Code 기반 확인은 SAP GUI에서 수행한다. 개발 도구에서 문제가 보이지 않을 때 시스템 설정과 런타임 로그를 확인한다.

03 · 실습 흐름

개발 흐름에 맞춰 도구를 순서대로 사용한다

1
요구사항과 표준 데이터 확인

SAP GUI에서 관련 T-Code, 표준 테이블, 기본 데이터를 확인한다.

2
ABAP / CDS / RAP 구현

ADT에서 Class, CDS View, Behavior Definition, Service Definition을 작성한다.

3
OData 응답 확인

Gateway Client 또는 Service Binding Preview로 Metadata와 EntitySet 응답을 확인한다.

4
UI5 화면 구현

VS Code 또는 BAS에서 XML View, Controller, manifest, ODataModel 설정을 작성한다.

5
통합 디버깅

Browser DevTools의 Network/Console과 ADT의 ABAP Debugger를 함께 사용한다.

04 · 상황별 도구 선택

증상만 보고도 첫 확인 위치를 정할 수 있어야 한다

증상 먼저 확인할 도구 판단 기준
화면에 데이터가 비어 있음 Browser DevTools → Gateway Client Network 응답이 비었는지, UI Binding 경로가 틀렸는지 구분한다.
OData 호출이 404 또는 500 오류 Gateway Client → SAP GUI 로그 서비스 등록, 메타데이터, 서버 예외를 확인한다.
계산 결과가 예상과 다름 ADT Debugger ABAP 로직, CDS 조건, RAP Determination/Validation을 확인한다.
UI 이벤트가 실행되지 않음 Browser Console → VS Code/BAS Controller 함수명, 이벤트 바인딩, JavaScript 오류를 확인한다.
표준 화면과 개발 화면 결과가 다름 SAP GUI → ADT 표준 데이터 기준과 개발 로직의 필터 조건을 비교한다.
05 · 초급자가 자주 헷갈리는 지점

도구를 잘못 선택하면 문제 원인 파악이 늦어진다

주의 화면 오류를 곧바로 ABAP 문제로 판단하지 않는다. 먼저 브라우저 Network에서 서버 응답이 정상인지 확인한다. 서버 응답이 정상인데 화면만 이상하면 UI5 Binding, Formatter, Controller 이벤트를 확인한다.

SAP GUI와 ADT의 역할 혼동

SAP GUI는 표준 기능과 시스템 상태 확인에 강하고, ADT는 개발 객체 작성과 디버깅에 강하다.

Gateway Client와 Browser Network 혼동

Gateway Client는 서비스 자체 테스트에 적합하고, Browser Network는 UI에서 실제로 보낸 요청 확인에 적합하다.

06 · 학습 완료 체크

다음 문서로 넘어가기 전에 확인한다

  1. SAP GUI, ADT, VS Code/BAS, Gateway Client, Browser DevTools의 역할을 구분한다.
  2. 데이터가 화면에 나오지 않을 때 Browser Network와 Gateway Client를 순서대로 확인한다.
  3. 서버 로직 문제와 화면 바인딩 문제를 증상 기준으로 구분한다.
  4. ABAP Debugger와 Browser DevTools를 함께 써야 하는 상황을 설명한다.
  5. 본인의 실습 환경에서 `index.html` 또는 UI5 앱을 열고 Network 탭을 확인한다.
