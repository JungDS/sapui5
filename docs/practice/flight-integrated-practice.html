Flight 통합 실습 최신본

이 실습은 하나의 Flight 시나리오를 ClassRun, Gateway CRUD, UI5 ODataModel, Messaging, RAP BO로 확장해 본다. 개별 문서를 읽은 뒤 실제 개발 흐름을 연결하는 종합 연습으로 사용한다.

Stage 7 통합 실습 End-to-End 배포자: 정훈영
01 · 목표

하나의 업무 데이터를 여러 개발 계층으로 연결합니다

초급 학습에서는 ABAP, OData, UI5, RAP가 서로 다른 주제로 보일 수 있다. 하지만 실무에서는 하나의 업무 데이터를 조회하고, 검증하고, 저장하고, 사용자에게 메시지로 알려주는 흐름이 반복된다. Flight 통합 실습은 이 흐름을 작은 범위에서 끝까지 경험하게 만드는 연습이다.

최종 목표는 완벽한 앱 하나를 만드는 것이 아니라, 개발자가 요구사항을 받았을 때 데이터 모델, 서비스, 화면, 메시지, 확장 모델을 어떤 순서로 생각해야 하는지 익히는 것이다.

02 · 시나리오

항공편 좌석과 예약 상태를 조회하고 관리하는 흐름으로 잡습니다

실습 시나리오는 단순하게 시작한다. 항공사와 노선을 선택하고, 날짜별 운항의 좌석 현황을 확인한 뒤, 예약 또는 알림 데이터를 관리하는 화면을 만든다. 이후 같은 모델을 RAP 관점으로 다시 구성해 본다.

조회 중심

SCARR, SPFLI, SFLIGHT를 읽어 항공사/노선/운항 현황을 보여준다.

저장 중심

예약 또는 알림성 데이터를 생성, 수정, 삭제하면서 Gateway CRUD와 UI5 저장 흐름을 익힌다.

03 · 단계

ClassRun에서 시작해 UI5와 RAP까지 확장합니다

  1. Flight 테이블 관계를 확인하고 조회 기준 필드를 정한다.
  2. ABAP ClassRun으로 항공사, 노선, 운항 KPI를 출력한다.
  3. Gateway OData V2 서비스로 목록 조회와 CRUD 메서드를 구성한다.
  4. UI5 List/Detail 화면을 만들고 ODataModel로 데이터를 바인딩한다.
  5. Input Validation과 MessageManager로 사용자 오류를 보여준다.
  6. 동일 업무를 RAP BO 관점으로 재해석하고 Service Binding까지 연결한다.
04 · 산출물

완료 기준은 실행 가능한 작은 결과물입니다

  • Flight 데이터를 읽어 KPI를 출력하는 ABAP ClassRun
  • 목록 조회와 생성, 수정, 삭제를 테스트할 수 있는 Gateway 서비스
  • 목록, 상세, 저장 버튼을 가진 UI5 화면
  • 필수값 누락과 백엔드 오류를 구분해서 보여주는 메시지 처리
  • RAP로 확장할 때 필요한 Entity, Behavior, Service 구성 초안
학습 기준 모든 기능을 한 번에 완성하려고 하지 않는다. 각 단계마다 "입력, 처리, 출력"이 무엇인지 확인하고 다음 단계로 넘어간다.
05 · 리뷰

실습 후에는 기술보다 연결 흐름을 복기합니다

  • ABAP에서 읽은 데이터 구조가 OData Entity 구조와 어떻게 연결되는지 설명한다.
  • UI5 화면의 List, Detail, Save 동작이 어떤 OData 요청으로 이어지는지 확인한다.
  • 입력 오류와 서버 오류가 사용자에게 다른 메시지로 보이는지 점검한다.
  • Gateway 방식과 RAP 방식에서 개발자가 직접 구현하는 부분이 어떻게 다른지 비교한다.
  • 다음 실습에서 재사용할 수 있는 코드와 다시 설계해야 할 코드를 구분한다.
주의 통합 실습은 범위가 넓다. 막히는 지점이 생기면 전체를 멈추기보다 해당 계층의 최소 동작을 먼저 확인한다. 예를 들어 UI5 저장이 실패하면 네트워크 요청, OData 응답, MessageManager 표시를 분리해서 본다.
