SAP 개발 요구사항 분석법

실무 현업의 요구사항 정의서로부터 데이터를 어떻게 설계하고, Standard 테이블과 Custom 테이블을 어떤 규칙 하에 구성할 것인가에 대한 개발 설계 분석 방법론을 설명한다.

01 · 요구사항 분석 흐름

정의서 수신부터 프로그램 설계서 작성까지의 4단계

현업의 요건은 대개 비정형적이고 기술적으로 정의되어 있지 않습니다. 개발자는 다음 프로세스를 거쳐 비즈니스 언어를 기술 언어로 변환해야 합니다.

단계활동 내용산출물 및 검증 조건
1. 현업 요구사항 식별현업 인터뷰, 프로세스 매핑, 기존 T-Code 동작 수집요구사항 식별 정의서
2. 데이터 매핑 및 DB 설계필요한 정보가 어떤 Standard 테이블에 있는지 매핑, 부족한 필드 C-Table 설계ERD 및 테이블 명세서
3. 프로그램 기능 명세C-Table CRUD, ABAP Logic 설계, OData API Spec 정의개발 사양서 (프로그램 상세설계서)
4. 화면 Mockup 및 매핑UI 화면 컨트롤과 데이터 바인딩 속성 정의UI 레이아웃 및 바인딩 명세
02 · 핵심 분석 요령

데이터 매핑 시 실패하지 않는 원칙

Standard vs Custom의 조화

모든 데이터를 독자적인 테이블(Z-Table)에 넣으려 하지 마십시오. 가능한 Standard 데이터를 읽어오거나 표준 테이블의 뷰(CDS View)를 사용해 가공하고, 순수 비즈니스 정보만 Custom 테이블로 관리하는 것이 유지보수에 뛰어납니다.

도메인 지식 연계

예를 들어 "매출 실적" 요구사항이라면 FI의 ACDOCA 테이블이나 SD의 VBRK/VBRP 테이블 중 어느 관점이 타당한지 현업 업무 프로세스 측면에서 타당성을 먼저 검토하십시오.

03 · 분석 완료 체크리스트

다음 단계로 넘어가기 위한 설계 검증

  1. 요구사항 요건 중 '어떤 정보'가 Master 정보고, '어떤 정보'가 Transaction 정보인지 분류한다.
  2. Custom 테이블(Z-Table) 설계 시 Key 컬럼과 인덱스 구성이 효율적인지 중복 저장은 없는지 확인한다.
  3. UI5 화면에 필요한 API의 Response 구조와 Parameter를 ABAP OData Entity 구조와 1:1 매핑하여 사양서를 작성한다.
