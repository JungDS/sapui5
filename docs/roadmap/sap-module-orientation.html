01 · 오리엔테이션

개발자에게 모듈 프로세스 지식이 왜 중요한가?

SAP 시스템은 기술적 프레임워크와 비즈니스 기능(모듈)이 강력하게 결합되어 있습니다. 업무 프로세스를 모르고 설계하는 개발자는 단순 화면 복사 수준에 머무르게 되며, 비즈니스를 이해할 때 비로소 Standard 기능을 효율적으로 확장하는 진정한 SAP 컨설턴트/개발자가 될 수 있습니다.

ERP 업무 프로세스는 유기적이다

예를 들어, (영업)에서 가 발생하면, (생산)에서 생산 계획과 자재 수급을 조율하고, (자재)에서 원자재를 구매하여 입고한 뒤, (재무)에서 최종 분개 전표가 끊기고 원가가 로 분석됩니다. 이 흐름을 이해해야 각 테이블의 관계가 이해됩니다.

개발 생산성 향상

모듈의 표준 데이터 흐름(- 관계, Document Flow)과 상태 값들의 구조를 알면, 데이터 가공에 필요한 DB 조회 쿼리(Open SQL / ) 작성이 훨씬 직관적이고 쉬워집니다.

02 · 주요 핵심 모듈 개요

가장 먼저 학습해야 할 4대 핵심 모듈

모듈명대표 업무핵심 Standard 테이블 예시
(자재관리)자재 마스터 관리, 구매요청, 구매오더, 입고, 송장 검증MARA (자재마스터), EKKO/EKPO (구매오더), MSEG (자재문서)
(영업관리)고객 정보, 판매계약, , 출하/출고, 대금 청구VBAK/VBAP (), LIKP/LIPS (납품문서), VBRK/VBRP (청구문서)
(재무회계)G/L 계정 관리, 일반 분개 전표, 채권/채무, 결산BKPF/BSEG (회계전표), ACDOCA (Universal Journal 통합테이블)
(관리회계)원가 센터, 내부 오더, 손익 센터, 제조원가 계산CSKS (원가센터), COSP/COSS (원가거래값 테이블)

03 · 모듈 학습 접근 방법

학습을 효율적으로 진행하기 위한 방법론

  1. 마스터 데이터(Master Data)와 트랜잭션 데이터(Transaction Data)를 확실히 구분하고 표준 화면을 직접 봅니다.
  2. 모든 모듈의 공통 규칙인 '전표 흐름(Document Flow, 예: VBFA 테이블)' 개념을 완전히 파악합니다.
  3. 데이터 구조를 이해하기 위해 Standard Table Map 입문을 먼저 숙독합니다.
