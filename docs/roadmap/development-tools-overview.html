SAP 개발 환경과 도구 입문

SAP GUI, ADT, VS Code/BAS, Gateway Client, Browser DevTools가 SAP 개발 흐름에서 각각 어떤 역할을 맡는지 초급자 기준으로 정리한다.

Stage 7 Docs 로드맵 개발 도구
01 · 도구 지도

도구를 먼저 구분하면 실습 흐름이 단순해진다

💡 핵심 마인드셋 SAP 개발 도구는 하나의 IDE로 끝나지 않습니다. 프론트엔드와 백엔드가 분리되어 있으므로, '내가 지금 서버 로직을 고치는 중인가, 화면 바인딩을 고치는 중인가'에 따라 도구를 명확히 전환해야 합니다.
도구주 용도처음 배울 때의 관점
SAP GUIT-Code 실행, 표준 화면 확인, 테이블/로그 확인표준 SAP 동작과 시스템 상태 확인
ADT / Eclipse, , 개발서버 로직과 데이터 모델 작성
VS Code / BAS, Fiori 앱 개발XML View, Controller, Model, npm, UI5 Tooling
Gateway Client V2 요청/응답 테스트서비스가 정상 응답하는지 독립 확인
Browser DevToolsUI5 화면, Network, Console 디버깅브라우저 실제 요청과 화면 오류 확인
02 · 계층별 이해

문제가 발생한 위치에 따라 사용하는 도구가 달라진다

서버 로직 문제

Class, , Behavior는 ADT와 Debugger로 확인한다.

서비스 응답 문제

Metadata, EntitySet, HTTP 상태는 Gateway Client와 Network에서 확인한다.

화면 바인딩 문제

View, Controller, Model, Binding Path는 VS Code/BAS와 Browser DevTools에서 확인한다.

운영 상태 문제

서비스 등록, 시스템 설정, 표준 로그는 SAP GUI에서 확인한다.

03 · 상황별 도구 선택

증상만 보고도 첫 확인 위치를 정할 수 있어야 한다

🔍 문제 해결의 첫걸음 오류가 발생했을 때 가장 먼저 해야 할 일은 오류의 진원지가 프론트엔드인지 백엔드인지 격리하는 것입니다.
증상먼저 확인할 도구판단 기준
화면 데이터가 비어 있음Browser DevTools → Gateway ClientNetwork 응답과 Binding 경로를 분리한다.
OData 404/500 오류Gateway Client → SAP GUI 로그서비스 등록, 서버 예외, 메시지를 확인한다.
계산 결과 오류ADT DebuggerABAP 로직과 CDS 조건을 확인한다.
UI 이벤트 미실행Console → VS Code/BASController 함수명과 이벤트 바인딩을 확인한다.
04 · 학습 완료 체크

다음 문서로 넘어가기 전에 확인한다

  1. SAP GUI, ADT, VS Code/BAS, Gateway Client, Browser DevTools의 역할을 구분한다.
  2. 화면 데이터 오류 시 Network와 Gateway Client를 순서대로 확인한다.
  3. 서버 로직 문제와 화면 바인딩 문제를 증상 기준으로 구분한다.
