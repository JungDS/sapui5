Classic ABAP 기본기

Report 프로그램, Selection Screen, Internal Table, Open SQL, ALV 출력까지 개발자가 가장 먼저 익혀야 할 기본 실행 흐름을 실무 관점으로 정리한다.

Stage 7 ABAP 개발 Classic ABAP
01 · 역할

Classic ABAP은 SAP 서버 개발의 기본 체력입니다

은 오래된 방식이라는 의미가 아니라, SAP 시스템 안에서 데이터를 조회하고 처리하고 결과를 사용자에게 보여주는 가장 기본적인 서버 개발 흐름이다. , , 를 배우더라도 Internal Table, Open SQL, 메시지 처리, 디버깅 기본기는 계속 필요하다.

💡 학습 관점 초급자는 문법을 많이 외우기보다 입력값이 들어오고, DB를 조회하고, 내부 테이블에 담고, 화면에 출력되는 전체 흐름을 먼저 잡아야 한다.
02 · 기본 흐름

Report 프로그램은 입력, 조회, 가공, 출력 순서로 읽습니다

Selection Screen

사용자가 회사코드, 기간, 자재번호 같은 조건을 입력하는 영역이다. 실무에서는 필수값, 기본값, 검색도움, 권한 체크를 함께 고려한다.

Open SQL

SAP 테이블이나 CDS View에서 데이터를 읽는 구문이다. 최신 ABAP에서는 호스트 변수, 인라인 선언, CDS 기반 조회를 함께 사용한다.

Internal Table

DB에서 읽은 데이터를 ABAP 메모리 안에서 정렬, 필터, 합산, 변환하는 핵심 자료구조다.

ALV

조회 결과를 사용자가 필터링, 정렬, 다운로드할 수 있게 보여주는 SAP 표준 리스트 출력 방식이다.

03 · 실무 패턴

초급 Report는 아래 골격으로 안정적으로 작성합니다

REPORT zsample_classic_report.

PARAMETERS p_carrid TYPE s_carr_id.

START-OF-SELECTION.
  SELECT carrid, connid, fldate, price, currency
    FROM sflight
    WHERE carrid = @p_carrid
    INTO TABLE @DATA(lt_flight).

  IF lt_flight IS INITIAL.
    MESSAGE '조회 결과가 없습니다.' TYPE 'S'.
    RETURN.
  ENDIF.

  cl_salv_table=>factory(
    IMPORTING r_salv_table = DATA(lo_alv)
    CHANGING  t_table      = lt_flight ).

  lo_alv->display( ).

이 예제는 단순하지만 실무의 핵심 구조를 담고 있다. 입력값을 받고, DB에서 조회하고, 결과가 없을 때 메시지를 처리하고, ALV로 출력한다. 이후 권한 체크, 예외 처리, 필드 카탈로그, 합계, 핫스팟, 더블클릭 이벤트를 단계적으로 추가하면 된다.

04 · 주의점

초급자가 자주 놓치는 부분은 데이터 양과 키 구조입니다

  • 조건 없이 대용량 테이블을 조회하지 않는다.
  • Header/Item 구조에서는 Key 필드를 정확히 확인한다.
  • 금액과 수량은 통화, 단위 필드와 함께 다룬다.
  • READ TABLE, LOOP, SORT, DELETE ADJACENT DUPLICATES의 기준 필드를 명확히 한다.
05 · 완료 체크

다음 단계로 가기 전 확인합니다

  1. Report 프로그램의 실행 이벤트와 START-OF-SELECTION의 역할을 설명할 수 있다.
  2. Selection Screen 입력값이 Open SQL 조건으로 연결되는 흐름을 설명할 수 있다.
  3. Internal Table을 정렬, 반복, 검색, 합산하는 기본 패턴을 사용할 수 있다.
  4. 조회 결과를 SALV 또는 ALV로 출력할 수 있다.
