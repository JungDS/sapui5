RAP End-to-End 입문

RAP는 CDS 기반 데이터 모델, Behavior Definition, Behavior Implementation, Service Definition, Service Binding을 연결해 S/4HANA 스타일의 비즈니스 객체를 만드는 개발 방식이다. 이 문서는 초급자가 RAP 전체 흐름을 한 번에 이해할 수 있도록 End-to-End 관점으로 정리한다.

Stage 7 ABAP 개발 RAP
01 · 개념

RAP는 화면보다 먼저 비즈니스 객체를 정의합니다

RAP(Restful ABAP Programming Model)는 단순히 OData 서비스를 빠르게 만드는 도구가 아니다. 업무 데이터를 비즈니스 객체 단위로 모델링하고, 해당 객체가 어떤 동작을 할 수 있는지 정의한 뒤, 이를 Fiori Elements나 외부 소비자가 사용할 수 있도록 서비스로 노출하는 개발 모델이다.

초급자는 RAP를 처음 배울 때 CDS View, Behavior, Service Binding을 따로 외우려는 경향이 있다. 하지만 실무에서는 이 세 가지를 하나의 흐름으로 읽어야 한다. 데이터 모델이 있고, 그 데이터가 생성·수정·삭제될 수 있는 규칙이 있으며, 마지막으로 그 규칙을 포함한 서비스를 노출한다.

학습 기준 RAP 실습에서는 항상 Interface View ZI_*와 Projection View ZC_*를 함께 구성하는 것을 기본으로 한다. 그래야 재사용 계층과 소비 계층의 역할을 초급 단계부터 구분할 수 있다.
02 · 구성요소

RAP 객체는 데이터 모델, 동작 정의, 서비스 노출로 나뉩니다

Interface View · ZI_*

테이블이나 표준 View를 기반으로 핵심 필드, Key, Association, Semantics를 정의하는 재사용 계층이다.

Projection View · ZC_*

앱이나 API 소비 목적에 맞춰 필드와 Association을 노출하는 소비 계층이다. UI Annotation도 주로 이 계층에 둔다.

Behavior Definition

Entity가 생성, 수정, 삭제, Action, Validation, Determination을 지원하는지 선언한다.

Service Binding

Service Definition을 실제 OData V4 서비스로 publish하여 Fiori Elements나 외부 소비자가 호출할 수 있게 한다.

03 · 모델링 흐름

먼저 Root Entity와 Item Entity의 관계를 안정적으로 잡습니다

RAP 학습용 예제에서는 Header/Item 구조를 사용하는 것이 좋다. 예를 들어 항공 예약, 주문, 요청서처럼 상위 문서와 하위 항목이 있는 구조는 Composition, Association, Lock, Draft 개념을 설명하기 쉽다. 

@EndUserText.label: 'Interface View Booking Root'
define root view entity ZI_JHY_Booking
  as select from zbooking
  composition [0..*] of ZI_JHY_BookingItem as _Item
{
  key booking_uuid as BookingUuid,
      booking_id   as BookingId,
      customer_id  as CustomerId,
      status       as Status,
      total_amount as TotalAmount,
      currency     as Currency,
      _Item
}

@EndUserText.label: 'Projection View Booking Root'
define root view entity ZC_JHY_Booking
  as projection on ZI_JHY_Booking
{
  key BookingUuid,
      BookingId,
      CustomerId,
      Status,
      TotalAmount,
      Currency,
      _Item
}

실제 교육에서는 테이블 설계, UUID Key, 상태 필드, 금액/통화 필드를 함께 설명해야 한다. 특히 금액 필드는 통화 필드와 함께 Semantics를 지정해야 UI와 서비스 소비자가 올바르게 해석할 수 있다.

04 · Behavior

Behavior Definition은 객체가 허용하는 업무 동작을 선언합니다

managed implementation in class zbp_i_jhy_booking unique;
strict ( 2 );

behavior for ZI_JHY_Booking alias Booking
persistent table zbooking
lock master
authorization master ( instance )
{
  create;
  update;
  delete;

  field ( readonly ) BookingUuid, BookingId;

  validation validateCustomer on save { field CustomerId; }
  determination calculateTotal on modify { field TotalAmount; }
  action confirm result [1] $self;

  association _Item { create; }
}

초급자는 여기서 create, update, delete만 보는 것이 아니라, 저장 시점에 수행되는 Validation과 값 보정 역할을 하는 Determination, 사용자가 명시적으로 실행하는 Action의 차이를 구분해야 한다.

05 · Validation / Determination / Action

세 가지 확장 포인트의 실행 시점이 다릅니다

Validation

저장 전에 데이터가 업무 규칙을 만족하는지 확인한다. 오류가 있으면 메시지를 반환하고 저장을 막는다.

Determination

필드 변경이나 저장 시점에 파생값을 계산한다. 총액 계산, 상태 기본값, 날짜 보정에 사용한다.

Action

사용자가 명시적으로 실행하는 업무 동작이다. 승인, 확정, 취소처럼 상태 변화가 있는 기능에 적합하다.

06 · Service

Service Definition과 Binding으로 외부 소비 지점을 만듭니다

@EndUserText.label: 'Booking Service Definition'
define service ZUI_JHY_BOOKING {
  expose ZC_JHY_Booking     as Booking;
  expose ZC_JHY_BookingItem as BookingItem;
}

Service Definition은 어떤 Projection View를 외부에 노출할지 선언한다. Service Binding은 이를 OData V4 서비스로 publish하고, Fiori Elements 미리보기 또는 실제 앱에서 사용할 수 있게 한다.

07 · 주의점

RAP 초급 실습에서 가장 많이 흔들리는 부분은 Key와 계층 분리입니다

  • Root Entity의 Key는 안정적이어야 하며, 실무에서는 UUID 기반 설계를 자주 사용한다.
  • Interface View에 소비 전용 UI Annotation을 과도하게 넣지 않는다.
  • Projection View 없이 Interface View를 바로 노출하면 이후 변경 영향도가 커질 수 있다.
  • Action은 단순 버튼 이벤트가 아니라 업무 상태를 변경하는 명시적 동작으로 설계한다.
  • Validation 메시지는 UI 사용자가 이해할 수 있는 문장으로 작성한다.
08 · 완료 체크

다음 단계로 가기 전 확인합니다

  1. RAP에서 Interface View와 Projection View의 역할 차이를 설명할 수 있다.
  2. Behavior Definition이 Entity의 허용 동작을 선언한다는 점을 설명할 수 있다.
  3. Validation, Determination, Action의 실행 시점과 목적을 구분할 수 있다.
  4. Service Definition과 Service Binding의 역할을 구분할 수 있다.
  5. Fiori Elements Preview에서 EntitySet과 Object Page가 어떻게 연결되는지 설명할 수 있다.
