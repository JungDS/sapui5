학습 목표

객체가 만들어질 때 자동으로 실행되어 초기 상태를 준비하는 생성자(Constructor)를 배웁니다. 객체를 "쓸 수 있는 상태"로 태어나게 하는 초기화의 의미를 익힙니다.

1. 지난 시간 연결: 태어날 때 준비를 끝내자 👶

객체를 NEW로 만든 직후, 속성이 비어 있으면 곤란합니다. 항공편 객체라면 적어도 "어느 항공편인지"는 처음부터 정해져 있어야겠죠.

객체가 만들어지는 바로 그 순간 자동으로 실행되어 초기값을 채우는 특별한 메서드가 생성자(Constructor)입니다.

비유: 출고 전 기본 세팅

새 휴대폰이 공장에서 나올 때 기본 설정이 되어 있듯, 생성자는 객체가 "쓸 준비가 된 상태"로 태어나게 합니다. 매번 따로 초기화할 필요가 없죠.

3. 필수값을 강제하는 효과 🔒

생성자에 IMPORTING iv_carrid를 필수로 두면, 객체를 만들 때 반드시 항공사 코드를 줘야 합니다. 안 주면 컴파일 오류죠. 즉 "불완전한 객체"가 태어나는 걸 막습니다.

  • ✅ 정상: 필요한 초기값을 생성자로 받아 완전한 객체 생성.
  • ❌ 오류: 생성자가 요구하는 값을 안 주면 객체를 만들 수 없음(좋은 강제).

4. Static Constructor 한 줄 소개 🧱

객체마다 실행되는 일반 생성자 외에, 클래스가 처음 한 번 쓰일 때 실행되는 Static Constructor(CLASS_CONSTRUCTOR)도 있습니다. 클래스 전체가 공유하는 초기 준비에 쓰입니다. 지금은 "그런 것도 있다" 정도만 기억하면 됩니다(Static 개념은 다음 Lesson).

5. 실무에서 조심할 점 🚨

⚠️

생성자에 무거운 작업을 넣지 마세요

생성자는 "객체를 쓸 수 있게 준비"하는 곳입니다. 여기에 대량 DB 조회나 복잡한 로직을 넣으면, 객체를 만들 때마다 무거워집니다. 또 생성자에서 오류가 나면 객체 자체가 안 만들어져 추적이 까다롭습니다. 생성자는 가볍게 초기값 세팅 위주로 두고, 무거운 작업은 별도 메서드로 분리하세요.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • 생성자(constructor)는 객체가 만들어질 때 자동 실행됩니다.
  • 초기값을 채워 객체를 "쓸 준비가 된 상태"로 태어나게 합니다.
  • 필수 IMPORTING 값으로 불완전한 객체 생성을 막을 수 있습니다.
  • 생성자는 가볍게, 무거운 작업은 별도 메서드로.

객체 하나의 생애를 봤으니, 객체 없이도 쓰는 기능을 봅니다. 다음 Lesson Static Method와 Instance Method에서 둘의 차이를 배웁니다.
