학습 목표

Data Element가 방금 전 배운 Domain 위에 어떻게 의미(Semantic)와 필드 라벨(Field Label)을 예쁘게 입히는지 배웁니다. 왜 테이블에서 Domain을 바로 쓰지 않고 굳이 Data Element를 거치는지, 그 깊은 뜻을 이해해 봅니다.

1. 지난 시간 요약 & Data Element란 무엇인가? 🏷️

이전 Lesson에서 우리는 데이터의 "재질"을 결정하는 Domain을 만들었습니다. 그런데 문제가 하나 있습니다. Domain은 "이건 3자리 문자(CHAR 3)야!"라는 것만 알 뿐, 그게 무엇을 뜻하는지는 전혀 모른다는 것입니다. 똑같은 CHAR 3 재질이라도 어떨 때는 '항공사 코드'일 수도 있고, 어떨 때는 '통화 코드'일 수도 있잖아요?

바로 여기서 등장하는 것이 Data Element(데이터 엘리먼트)입니다. Data Element는 재질(Domain) 위에 '의미(Semantic)'와 '화면에 보여줄 이름표(Label)'를 붙여주는 역할을 하는 핵심 부품입니다.

🔗

3단 조립 구조를 꼭 기억하세요!

SAP의 필드는 아래에서 위로 조립되는 상향식(Bottom-Up) 구조를 가집니다.

  1. Domain: 재질 결정 (예: CHAR 3)
  2. Data Element: 의미 부여 (예: 이 CHAR 3는 "항공사 코드"임 + 이름표 달기)
  3. Table Field: 최종 사용 (실제 테이블에서 이 Data Element를 가져다 씀)

2. 필드 라벨(Field Label) — 화면에 뜨는 예쁜 글자 📋

Data Element의 가장 중요한 임무 중 하나는 바로 필드 라벨(Field Label)을 설정하는 것입니다. 화면에 덩그러니 입력 칸만 있으면 사용자가 뭘 입력해야 할지 모르겠죠? 그래서 길이별로 4종류의 라벨을 미리 등록해 둡니다.

  • Short (짧은): 최대 10자. 공간이 아주 좁은 표의 머리글로 쓰입니다. (예: "항공사")
  • Medium (중간): 최대 20자. 일반적인 화면의 필드 이름표로 자주 쓰입니다. (예: "항공사 코드")
  • Long (긴): 최대 40자. 공간이 아주 넉넉할 때 자세히 보여줍니다. (예: "해당 비행기의 항공사 코드")
  • Heading (제목): 리포트나 ALV(목록 화면)의 컬럼(열) 제목으로 전용으로 쓰입니다.
놀라운 자동화 마법: 이 Data Element에 한 번만 라벨을 정성껏 입력해 두세요. 그러면 이 부품을 가져다 쓰는 수많은 화면, 수많은 리포트 프로그램이 자동으로 똑같은 한글 제목을 달고 화면에 튀어나옵니다! 화면을 만들 때마다 일일이 글자를 칠 필요가 없어지는 엄청난 생산성의 비밀입니다.

보너스로 하나 더! 사용자가 어떤 입력 칸에 마우스를 두고 키보드 F1(도움말) 키를 누르면 나오는 상세한 텍스트 설명도 바로 이 Data Element에서 관리(Documentation)합니다.

3. 굳이 이렇게 나눠서 쓰는 이유가 뭘까? 🤔

초보자분들이 가장 많이 하는 질문입니다. "아니, 그냥 테이블에다가 바로 '이건 3자리 문자고 이름은 항공사 코드야'라고 쓰면 편하지 않나요? 왜 Domain 만들고, 그걸로 또 Data Element 만들고 귀찮게 2번 일하나요?"

정답은 철저한 분업과 완벽한 재사용 때문입니다.

  • ✅ 일관성의 끝판왕: 'BUKRS(회사코드)'라는 Data Element를 100개의 테이블이 공유한다고 해봅시다. 나중에 회사 정책이 바뀌어서 화면에 표시되는 이름을 "회사코드"에서 "법인코드"로 바꿔야 한다면? 저 Data Element 라벨 딱 한 군데만 "법인코드"로 고치면, 100개 테이블을 쓰는 수백 개의 화면 이름이 한 방에 1초 만에 전부 다 바뀝니다.
  • ✅ 위험 분산: 재질(길이·타입)은 Domain이 관리하고, 의미(라벨·뜻)는 Data Element가 나눠서 관리하죠? 라벨(이름표)만 바꾸고 싶을 때 시스템에 부담을 주는 Domain을 건드릴 필요 없이 Data Element만 쏙 고치면 훨씬 안전합니다.

4. 실무에서 조심해야 할 점 🚨

Data Element를 설계할 때 주의해야 할 핵심 포인트를 알려드릴게요.

⚠️

"길이가 같다고 아무 Data Element나 막 쓰면 안 됩니다!"

'출발 공항'과 '도착 공항'은 둘 다 3자리 문자(CHAR 3)입니다. 재질(Domain)은 똑같은 걸 재사용해도 됩니다. 하지만 Data Element를 똑같은 걸 쓰면 어떻게 될까요? 화면에 둘 다 이름표가 똑같이 "공항"이라고 떠서 사용자가 헷갈리게 됩니다!

따라서 의미와 화면 표시 라벨이 달라야 한다면, 재질(Domain)이 같더라도 Data Element는 각각 '출발 공항용', '도착 공항용'으로 따로 만들어야 합니다.

물론 반대로, SAP가 만들어둔 표준 Data Element(BUKRS, MATNR 등)의 의미와 라벨이 내가 만들려는 것과 정확히 똑같다면 절대로 새로 만들지 말고 표준을 재사용하는 것이 베스트 프랙티스입니다!

5. 한눈에 정리 🏁

📝

오늘의 요약

  • Data Element는 의미 없는 재질(Domain)에 '의미'와 '이름표(Field Label)'를 달아주는 역할을 합니다.
  • Data Element에 설정한 길이별 필드 라벨(Short, Medium, Long, Heading)은 모든 화면과 프로그램에서 자동으로 통일되어 출력됩니다. (번거로운 수작업 안녕!)
  • 테이블을 만들 때는 Domain을 직접 쓰지 않고 항상 Data Element를 거쳐서 사용합니다. 이는 철저한 분업과 유지보수의 편의를 위한 SAP만의 천재적인 설계입니다.
  • 재질이 같아도 화면에 띄울 이름이나 의미가 다르면 Data Element는 별도로 분리해야 합니다.

자, 여기까지 우리는 재질(Domain) + 의미(Data Element)를 완벽하게 결합하여 어디 내놔도 손색없는 훌륭한 "낱개 필드 부품" 하나를 완성했습니다.

하지만 실무에서 데이터는 혼자 다니지 않죠? 사원번호, 이름, 부서가 뭉쳐 다녀야 하나의 '사원 데이터'가 됩니다. 다음 Lesson 'Structure 기본 생성'에서는 지금까지 만든 낱개 부품들을 하나로 예쁘게 묶어주는 구조체(Structure)에 대해 배워보겠습니다. 가볼까요?
