학습 목표

지난 Lesson에서 Domain이 값의 재질을 정한다는 것을 봤습니다. 이번에는 그 재질 위에 업무 의미, Field Label, F1 Help를 얹는 Data Element를 배웁니다. 목표는 “같은 CHAR 3이라도 왜 다른 Data Element가 필요할 수 있는가?”를 설명하는 것입니다.

1. 재질만 있으면 사용자가 못 알아본다

Domain이 CHAR 3이라고 말해도, 사람은 그 값이 항공사 코드인지 공항 코드인지 회사 코드인지 알 수 없습니다. SAP 화면을 쓰는 사용자는 “몇 자리 문자”보다 “이 칸에 무엇을 입력해야 하는가”를 알아야 합니다.

Data Element는 바로 이 의미를 담당합니다. 같은 기술 규격이라도 업무 의미가 다르면 다른 이름표와 다른 도움말이 필요합니다. 그래서 SAP의 two-level domain concept는 Domain과 Data Element를 나눠 둡니다.

Domain은 값의 재질입니다. Data Element는 그 재질에 붙는 업무 이름표입니다.

2. Domain → Data Element → Table Field

Chapter 1의 조립 흐름을 다시 한 번 고정해 봅시다. 테이블 필드는 보통 Domain을 직접 참조하지 않고, Data Element를 통해 기술 속성과 의미 속성을 함께 받습니다.

SAP Learning은 테이블 필드 편집 시 Data Element 사용을 권장하고, Domain은 데이터 타입으로 직접 사용할 수 없다고 설명합니다.

Domain을 ABAP 변수 타입으로 직접 쓸 수 있을까?

아닙니다. SAP 공식 자료 기준으로 Domain은 Data Element의 기반일 뿐, 그 자체가 ABAP 변수나 테이블 필드의 타입이 되지는 않습니다. 변수나 필드에는 Data Element, Structure, Table Type 같은 Dictionary 타입을 사용합니다.

3. Data Element가 맡는 세 가지 일

초급 단계에서는 Data Element 화면을 아래 세 묶음으로 이해하면 됩니다. 기술 타입을 어디서 받을지, 화면 텍스트를 어떻게 줄지, 사용자 도움을 어디까지 줄지를 정합니다.

Data Element 설계 판단표

Type Source

선택기존 Domain, 새 Domain, 직접 타입 입력
주의재사용할 규격이면 Domain을 먼저 검토한다.

Data Element는 단순한 이름표가 아니라 UI 텍스트와 도움말을 중앙에서 재사용하게 만드는 의미 컨테이너입니다.

4. Field Label 4종은 화면 공간을 위한 이름표다

SAP Learning은 Data Element에서 세 가지 label과 heading을 관리한다고 설명합니다. 초급자 입장에서는 “화면 공간에 따라 쓸 이름표를 여러 길이로 준비한다”라고 기억하면 됩니다.

항공사 코드 라벨 4종 예시

라벨 예시 주로 쓰이는 상황
Short 항공사 공간이 매우 좁은 입력 필드
Medium 항공사 코드 일반 화면 필드 라벨
Long 항공편 항공사 코드 설명을 조금 더 보여줄 수 있는 화면
Heading 항공사 리스트, 테이블, ALV의 컬럼 제목
✨

좋은 라벨의 기준

짧게 쓰되 약어만 남기지 마세요. 여러 화면에서 자동으로 재사용될 텍스트이므로, 개발자만 알아보는 줄임말보다 현업 사용자가 바로 읽을 수 있는 표현이 좋습니다.

5. F1 Help와 F4 Help는 책임이 다르다

Data Element는 화면 텍스트뿐 아니라 도움 기능의 연결점이 되기도 합니다. 다만 F1, F4, Parameter ID는 모두 사용자 편의와 관련이 있어도 같은 기능이 아닙니다.

사용자 도움 기능 구분

F1 Help
  • 필드 의미를 설명하는 문서입니다.
  • Data Element documentation에서 관리할 수 있습니다.
  • 사용자가 “이 칸이 뭐지?”라고 물을 때 답합니다.
F4 Help
  • 입력할 값을 찾도록 돕는 값 도움입니다.
  • Search Help를 Data Element에 연결할 수 있습니다.
  • 사용자가 “어떤 값을 고를까?”라고 물을 때 답합니다.

F1은 의미 설명, F4는 값 찾기입니다. 둘 다 Data Element와 연결될 수 있지만 목적은 다릅니다.

Parameter ID는 검증 기능일까?

아닙니다. Parameter ID는 SAP Memory의 값을 기본값으로 채우는 편의 기능에 가깝습니다. 사용자가 잘못된 값을 입력했는지 검사하는 기능은 Check Table, Foreign Key, 화면 로직, 애플리케이션 검증 같은 별도 영역입니다.

6. 같은 Domain, 다른 Data Element가 필요한 순간

가장 중요한 실무 판단은 “기술 규격이 같아도 의미가 다른가?”입니다. 같다면 재사용할 수 있고, 다르다면 Data Element를 분리하는 것이 자연스럽습니다.

재사용 판단 예시

상황 Domain Data Element 판단
출발 공항과 도착 공항 CHAR 3 공항 코드 재질은 같음 분리 라벨과 F1 설명이 다릅니다.
여러 테이블의 회사 코드 표준 회사 코드 규격과 의미가 같음 재사용 표준 Data Element를 먼저 찾습니다.
개발자 전용 임시 타입 DDIC 의미 속성이 필요 없음 주의 새 DDIC 객체보다 클래스/인터페이스 type이 나을 수 있습니다.
⚠️

표준 Data Element를 직접 고치지 마세요

화면 텍스트가 마음에 들지 않는다고 SAP 표준 Data Element의 라벨을 직접 수정하면 같은 객체를 쓰는 다른 화면까지 영향을 받을 수 있습니다. 표준 재사용과 표준 수정은 완전히 다른 문제입니다.

7. 생성 흐름: 의미를 먼저 쓰고 활성화한다

Data Element를 만들 때는 “기술 타입만 맞으면 끝”이 아닙니다. 실제 화면에서 어떤 이름과 도움말로 보일지까지 채우고 활성화해야 다른 객체가 믿고 쓸 수 있습니다.

Data Element 생성 흐름

1. 이름과 설명ZDE_CARRID처럼 네이밍 규칙을 따른다.
2. 기술 타입Domain 또는 직접 타입 입력을 선택한다.
3. Field LabelsShort, Medium, Long, Heading을 입력한다.
4. DocumentationF1 Help에 보일 설명을 작성한다.
5. Activate활성화 후 테이블 필드와 프로그램에서 사용한다.
Data Element를 ABAP 코드에서 타입으로 쓸 수 있을까?

가능합니다. SAP Help는 Data Element를 ABAP 프로그램의 TYPE에 참조할 수 있다고 설명합니다. 다만 최신 ABAP에서는 단순 내부 코드용 타입만 필요하다면 클래스나 인터페이스의 public type도 검토합니다.

8. 미니 실습: 이름표 설계하기

지난 Lesson의 예약 등급 Domain을 이미 만들었다고 가정하고, 이를 참조하는 Data Element를 설계해 보세요.

🧪

실습 과제

  1. Data Element 이름을 정합니다. 예: ZDE_BOOK_CLASS
  2. 참조할 Domain을 적습니다. 예: ZBOOK_CLASS
  3. Short, Medium, Long, Heading 라벨을 각각 작성합니다.
  4. F1 Help에 들어갈 한 문장 설명을 작성합니다.
  5. 같은 Domain을 쓰지만 의미가 달라 다른 Data Element가 필요한 예시를 하나 적습니다.

완료 조건: 라벨 4종, F1 설명, 재사용/분리 판단 근거를 모두 설명할 수 있으면 성공입니다.

10. 확인 퀴즈

  1. Domain과 Data Element를 “재질”과 “의미”로 나눠 설명해보세요.
  2. 테이블 필드 타입에 Domain을 직접 쓰는 것이 왜 맞지 않을까요?
  3. Field Label 4종은 어떤 문제를 해결하기 위해 존재할까요?
  4. F1 Help와 F4 Help의 차이는 무엇인가요?
  5. 출발 공항과 도착 공항이 둘 다 CHAR 3이면 반드시 같은 Data Element를 써야 할까요?
정답/해설 보기
  1. Domain은 기술 재질, Data Element는 업무 의미입니다. Domain은 타입과 길이, Data Element는 라벨과 설명을 담당합니다.
  2. Domain은 데이터 타입으로 직접 쓰는 객체가 아니기 때문입니다. 테이블 필드는 의미까지 포함한 Data Element를 쓰는 것이 일반적입니다.
  3. 화면 공간에 맞는 이름표를 제공하기 위해서입니다. 좁은 화면, 일반 필드, 긴 설명, 컬럼 제목에 맞는 텍스트를 중앙에서 관리합니다.
  4. F1은 의미 설명, F4는 값 찾기입니다. F1은 문서, F4는 Search Help나 값 도움과 연결됩니다.
  5. 아니요. 재질은 같아도 의미와 라벨이 다르면 Data Element를 분리하는 것이 안전합니다.
