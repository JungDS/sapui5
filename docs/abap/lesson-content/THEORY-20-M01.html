학습 목표

현대 SAP 데이터 모델의 핵심, CDS View Entity의 기본 구조를 배웁니다. 코드(소스)로 View를 정의하는 DDL Source가 무엇인지, Classic View와 무엇이 다른지 익힙니다.

1. 지난 시간 연결: 화면 클릭에서 "코드"로 📝

Chapter 12에서 Classic View(Database/Projection 등)를 SE11 화면에서 만들었습니다. Chapter 17 끝에서 "그 한계를 넘는 게 CDS"라고 예고했죠. 드디어 그 CDS로 들어갑니다.

가장 큰 차이: CDS는 화면 클릭이 아니라 텍스트 소스 코드(DDL)로 정의합니다. ADT(이클립스)에서 작성하며, 버전 관리·이관이 쉽고 표현력이 훨씬 강합니다.

2. 가장 단순한 CDS View Entity ✍️

@AccessControl.authorizationCheck: #NOT_REQUIRED
define view entity ZI_Flight
  as select from sflight
{
  key carrid,
  key connid,
  key fldate,
      price,
      currency
}
  • define view entity: CDS View를 선언하는 키워드(최신 문법). 이름은 보통 ZI_로 시작.
  • as select from: 원천 테이블/뷰. SQL의 SELECT와 비슷합니다.
  • key: 키 필드 지정(여러 개 가능).
  • { ... }: 노출할 필드 목록.
💡

"View Entity"라는 이름

옛 CDS는 define view였는데, 최신(ABAP Cloud)은 define view entity를 씁니다. 더 깔끔하고 자동 SQL View 생성이 없는 개선판이에요. 신규는 무조건 view entity로 만드세요.

3. CDS는 그냥 "테이블처럼" 읽힌다 🔍

한 번 활성화하면 ABAP에서 일반 테이블처럼 SELECT할 수 있습니다.

ABAP
1
2
3 
SELECT * FROM zi_flight
  WHERE carrid = @lv_carrid
  INTO TABLE @DATA(lt).

JOIN·계산·집계를 CDS 안에 미리 정의해 두면, 쓰는 쪽은 이렇게 간단하게 읽기만 하면 됩니다(Chapter 17의 코드 푸시다운 흐름과 연결됩니다).

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: DDL 작성 → 활성화 → 테이블처럼 SELECT.
  • ❌ 오류 1: @AccessControl.authorizationCheck 헤더 누락 → 활성화 경고/오류(권한 검사 방식 명시 필요, 이번 Chapter의 Lesson 6에서 다룸).
  • ❌ 오류 2: 옛 define view로 신규 작성 → ABAP Cloud에서 비권장. view entity 사용.

5. 실무에서 조심할 점 🚨

⚠️

CDS는 "릴리즈된 표준"을 원천으로 우선 고려

ABAP Cloud에서는 아무 테이블이나 직접 읽을 수 없고, SAP가 공개(릴리즈)한 객체만 원천으로 쓸 수 있습니다(Chapter 21에서 다룸). 또 CDS 이름·필드 규칙(ZI_/ZC_, 카멜케이스)을 팀 표준에 맞춰야 나중에 RAP·Fiori로 확장할 때 깔끔합니다. 처음부터 명명 규칙을 지키세요.

6. 미니 실습: 첫 CDS View Entity 점검표 만들기 🧪

이번 실습은 define view entity의 최소 구조를 외우는 것이 아니라, 어떤 줄이 어떤 역할을 하는지 직접 표시하는 데 목적이 있습니다.

✍️

실습 과제

  1. 예제 CDS에서 View 이름, 원천 테이블, key 필드, 일반 필드를 각각 다른 색으로 표시합니다.
  2. @AccessControl.authorizationCheck가 왜 헤더에 있는지 한 문장으로 적습니다.
  3. Classic CDS의 @AbapCatalog.sqlViewName이 최신 CDS View Entity에서는 왜 중심 개념이 아닌지 적습니다.

완료 조건: define view entity ... as select from ... { ... }의 각 부분을 말로 설명할 수 있으면 성공입니다.

8. 확인 퀴즈와 정답/해설 ✅

  1. define view entity에서 as select from 뒤에 오는 것은 무엇인가요?
  2. 신규 CDS 개발에서 옛 define view와 @AbapCatalog.sqlViewName 방식보다 define view entity를 우선하는 이유는 무엇인가요?
  3. CDS View Entity를 활성화한 뒤 ABAP 코드에서는 어떤 방식으로 읽을 수 있나요?
정답/해설 보기
  1. 원천 데이터 소스입니다. 테이블, View 또는 다른 CDS 엔티티처럼 이 View가 읽어 올 기반을 지정합니다.
  2. 최신 ABAP/CDS 개발의 권장 형태이고, 별도 SQL View 이름에 기대던 옛 방식보다 CDS 엔티티 자체를 중심으로 모델링하기 좋습니다.
  3. 일반 데이터 소스처럼 Open SQL의 SELECT 대상으로 사용할 수 있습니다. 다만 ABAP Cloud에서는 원천 객체의 사용 가능 여부도 함께 확인해야 합니다.

9. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • CDS View Entity는 코드(DDL)로 정의하는 현대 데이터 모델입니다.
  • define view entity ... as select from ... { key ..., ... } 구조.
  • 활성화하면 일반 테이블처럼 SELECT로 읽힙니다.
  • 신규는 옛 define view가 아닌 view entity로 만듭니다.
