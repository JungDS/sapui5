학습 목표

현대 SAP 데이터 모델의 핵심, CDS View Entity의 기본 구조를 배웁니다. 코드(소스)로 View를 정의하는 DDL Source가 무엇인지, Classic View와 무엇이 다른지 익힙니다.

1. 지난 시간 연결: 화면 클릭에서 "코드"로 📝

THEORY-12에서 Classic View(Database/Projection 등)를 SE11 화면에서 만들었습니다. THEORY-17 끝에서 "그 한계를 넘는 게 CDS"라고 예고했죠. 드디어 그 CDS로 들어갑니다.

가장 큰 차이: CDS는 화면 클릭이 아니라 텍스트 소스 코드(DDL)로 정의합니다. ADT(이클립스)에서 작성하며, 버전 관리·이관이 쉽고 표현력이 훨씬 강합니다.

2. 가장 단순한 CDS View Entity ✍️

@AccessControl.authorizationCheck: #NOT_REQUIRED
define view entity ZI_Flight
  as select from sflight
{
  key carrid,
  key connid,
  key fldate,
      price,
      currency
}
  • define view entity: CDS View를 선언하는 키워드(최신 문법). 이름은 보통 ZI_로 시작.
  • as select from: 원천 테이블/뷰. SQL의 SELECT와 비슷합니다.
  • key: 키 필드 지정(여러 개 가능).
  • { ... }: 노출할 필드 목록.
💡

"View Entity"라는 이름

옛 CDS는 define view였는데, 최신(ABAP Cloud)은 define view entity를 씁니다. 더 깔끔하고 자동 SQL View 생성이 없는 개선판이에요. 신규는 무조건 view entity로 만드세요.

3. CDS는 그냥 "테이블처럼" 읽힌다 🔍

한 번 활성화하면 ABAP에서 일반 테이블처럼 SELECT할 수 있습니다. 

SELECT * FROM zi_flight
  WHERE carrid = @lv_carrid
  INTO TABLE @DATA(lt).

JOIN·계산·집계를 CDS 안에 미리 정의해 두면, 쓰는 쪽은 이렇게 간단하게 읽기만 하면 됩니다(THEORY-17의 코드 푸시다운).

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: DDL 작성 → 활성화 → 테이블처럼 SELECT.
  • ❌ 오류 1: @AccessControl.authorizationCheck 헤더 누락 → 활성화 경고/오류(권한 검사 방식 명시 필요, M06에서 다룸).
  • ❌ 오류 2: 옛 define view로 신규 작성 → ABAP Cloud에서 비권장. view entity 사용.

5. 실무에서 조심할 점 🚨

⚠️

CDS는 "릴리즈된 표준"을 원천으로 우선 고려

ABAP Cloud에서는 아무 테이블이나 직접 읽을 수 없고, SAP가 공개(릴리즈)한 객체만 원천으로 쓸 수 있습니다(THEORY-21에서 다룸). 또 CDS 이름·필드 규칙(ZI_/ZC_, 카멜케이스)을 팀 표준에 맞춰야 나중에 RAP·Fiori로 확장할 때 깔끔합니다. 처음부터 명명 규칙을 지키세요.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • CDS View Entity는 코드(DDL)로 정의하는 현대 데이터 모델입니다.
  • define view entity ... as select from ... { key ..., ... } 구조.
  • 활성화하면 일반 테이블처럼 SELECT로 읽힙니다.
  • 신규는 옛 define view가 아닌 view entity로 만듭니다.
