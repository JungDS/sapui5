학습 목표

이번 Chapter에서 배운 Internal Table, APPEND, LOOP, READ 흐름을 연결해 미니 데이터 가공 프로그램을 만듭니다. 마지막에는 WRITE로 처리 결과를 확인합니다.

1. 이제 조각들을 하나의 흐름으로 묶어보자 🧭

지금까지는 Internal Table의 각 동작을 하나씩 따로 배웠습니다. Lesson 1에서는 왜 필요한지, Lesson 2에서는 선언, Lesson 3에서는 줄 추가, Lesson 4에서는 전체 읽기, Lesson 5에서는 한 줄 검색을 봤습니다.

실무 프로그램에서는 이 조각들이 따로 놀지 않습니다. 데이터를 담고, 조건에 맞게 계산하고, 필요한 값을 찾고, 결과를 출력하는 흐름으로 연결됩니다. 이번 Lesson은 그 연결 감각을 만드는 작은 마무리 실습입니다.

Internal Table 실력은 문법 하나를 아는 것보다, 읽기-검색-가공-출력을 연결할 때 생깁니다.

2. 미니 시나리오: 학생 점수표 만들기 📋

목표는 단순합니다. 학생 3명의 점수를 Internal Table에 담고, 전체 학생을 출력하면서 90점 이상인 학생 수를 계산합니다. 마지막으로 특정 학생 ID를 READ TABLE로 찾아 상세 메시지를 출력합니다.

  • 입력값: 코드 안에서 만든 학생 ID, 이름, 점수 3건
  • 처리: Internal Table에 담고 LOOP로 전체 출력, 조건에 따라 우수 학생 수 계산
  • 검색: READ TABLE로 특정 ID 찾기
  • 결과: 전체 목록, 우수 학생 수, 검색 결과 메시지 출력

실제 프로젝트에서는 데이터베이스에서 가져온 데이터로 비슷한 일을 합니다. 지금은 Open SQL로 확장하기 전, 메모리 안에서 가공 흐름만 연습합니다.

REPORT zinternal_table_process.

TYPES: BEGIN OF ty_student,
         id    TYPE char3,
         name  TYPE char20,
         score TYPE i,
       END OF ty_student.

DATA: lt_students  TYPE STANDARD TABLE OF ty_student,
      ls_student   TYPE ty_student,
      lv_high_cnt  TYPE i.

ls_student-id = 'A01'.
ls_student-name = '정훈영'.
ls_student-score = 90.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A02'.
ls_student-name = '홍길동'.
ls_student-score = 85.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A03'.
ls_student-name = '심청'.
ls_student-score = 95.
APPEND ls_student TO lt_students.

WRITE: / '학생 목록'.

LOOP AT lt_students INTO ls_student.
  WRITE: / ls_student-id, ls_student-name, ls_student-score.

  IF ls_student-score >= 90.
    lv_high_cnt = lv_high_cnt + 1.
  ENDIF.
ENDLOOP.

WRITE: / '90점 이상 학생 수:', lv_high_cnt.

CLEAR ls_student.
READ TABLE lt_students INTO ls_student WITH KEY id = 'A02'.
IF sy-subrc = 0.
  WRITE: / '검색 성공:', ls_student-name, ls_student-score.
ELSE.
  WRITE: / '검색 실패: 해당 학생 없음'.
ENDIF.

코드가 길어 보일 수 있지만 흐름은 단순합니다. 표를 만들고, 줄을 넣고, 전체를 돌며 계산하고, 한 줄을 검색해 결과를 출력합니다.

미니 데이터 가공 전체 흐름

1. Line Type 선언 id, name, score 칸을 가진 한 줄 모양 정의
2. APPEND 3회 정훈영, 홍길동, 심청을 lt_students에 추가
3. LOOP AT 각 줄을 ls_student로 읽으며 출력
4. 조건 계산 score가 90 이상이면 lv_high_cnt 증가
5. READ TABLE A02를 찾아 sy-subrc로 성공/실패 분기
idnamescoreLOOP 처리 결과
A01정훈영90우수 학생 수 +1
A02홍길동85목록 출력만 수행
A03심청95우수 학생 수 +1

최종적으로 90점 이상 학생 수는 2명이고, READ TABLE id = 'A02'는 홍길동 행을 찾습니다.

4. 처리 흐름을 말로 다시 읽기 🔁

  1. ty_student로 학생 한 줄의 모양을 정합니다.
  2. lt_students라는 Internal Table과 ls_student라는 Work Area를 만듭니다.
  3. 학생 3명을 Work Area에 채운 뒤 APPEND로 표에 넣습니다.
  4. LOOP AT으로 표 전체를 읽고, 각 학생을 출력합니다.
  5. 점수가 90 이상이면 lv_high_cnt를 1씩 증가시킵니다.
  6. READ TABLE로 ID가 A02인 학생을 찾아 검색 결과를 출력합니다.

초심자 단계에서는 코드를 손으로 따라가며 “지금 Work Area에는 어떤 학생이 들어 있지?”를 계속 물어보면 좋습니다. 디버거에서 lt_students, ls_student, lv_high_cnt를 보면서 실행하면 훨씬 선명해집니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 학생 3줄이 추가되고, LOOP가 3번 돌며, 90점 이상 학생 수가 2로 출력됩니다.
  • ✅ 검색 성공: A02가 있으므로 sy-subrc = 0이 되고 홍길동의 점수가 출력됩니다.
  • ❌ 검색 실패: 검색 ID를 A99로 바꾸면 실패 메시지가 출력됩니다.
  • ❌ APPEND 누락: 한 학생의 APPEND를 지우면 LOOP 출력 줄 수와 우수 학생 수가 달라집니다.
  • ❌ CLEAR 누락: Work Area를 일부 필드만 다시 채우는 코드에서는 이전 값이 섞일 수 있습니다.

미니 실습으로 기준 점수를 90에서 80으로 바꿔보세요. 그리고 검색 ID도 바꿔보며 정상/실패 메시지가 잘 나뉘는지 확인합니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

작은 예제의 성공을 운영 규모로 그대로 가져가면 위험합니다

3건짜리 Internal Table에서는 어떤 방식도 빨라 보입니다. 하지만 운영에서는 수천, 수만, 수백만 건이 될 수 있습니다. 데이터 양, 검색 방식, LOOP 안 처리 비용, 메모리 사용량을 함께 봐야 안정적인 프로그램이 됩니다.

또한 결과를 출력하기 전에는 검색 실패와 빈 테이블을 분리해 처리해야 합니다. “데이터가 없다”와 “프로그램이 잘못됐다”는 사용자에게 전혀 다른 의미이기 때문입니다.

7. 미니 실습: 점수표 프로그램 변형하기 🧪

✍️

실습 과제

  1. 예제 zinternal_table_process를 만들어 실행하고, 학생 목록·우수 학생 수(2명)·검색 결과(홍길동)가 모두 출력되는지 확인합니다.
  2. 우수 기준 점수를 90에서 80으로 바꾸고, 우수 학생 수가 어떻게 달라지는지 확인합니다.
  3. 검색 ID를 A99로 바꿔 실패 메시지가 출력되는지 확인합니다.
  4. 전체 점수 합계를 LOOP 안에서 누적해 평균 점수를 출력하는 기능을 추가해봅니다.

완료 조건: 기준 점수와 검색 ID를 바꿔도 “담기 → 반복 계산 → 검색 → 출력” 흐름이 흔들리지 않게 코드를 수정할 수 있으면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. 예제 그대로 실행하면 “90점 이상 학생 수”는 몇 명으로 출력되나요?
  2. 검색 ID를 A99로 바꾸면 어떤 일이 일어나나요?
  3. “검색 실패”와 “빈 테이블”을 사용자 메시지에서 구분해야 하는 이유는 무엇인가요?
정답/해설 보기
  1. 2명입니다. 정훈영(90), 심청(95)이 90점 이상이고 홍길동(85)은 포함되지 않습니다.
  2. sy-subrc가 0이 아니게 되어 “검색 실패: 해당 학생 없음”이 출력됩니다. 프로그램 오류가 아니라 의도된 실패 흐름입니다.
  3. 사용자에게 전혀 다른 의미이기 때문입니다. “조건에 맞는 데이터가 없음”과 “처리할 데이터 자체가 없음(또는 프로그램 문제)”을 구분해야 올바른 후속 조치가 가능합니다.

Chapter 6 마무리 핵심

  • Internal Table은 여러 줄 데이터를 Runtime Memory에서 다루는 작업용 표입니다.
  • Line Type, Work Area, STANDARD TABLE 선언 흐름을 먼저 잡으면 문법이 덜 복잡해집니다.
  • APPEND와 INSERT로 줄을 추가하고, LOOP AT으로 전체를 읽습니다.
  • READ TABLE과 SY-SUBRC로 특정 줄 검색의 성공/실패를 분리합니다.
  • 운영 데이터에서는 메모리, 반복 비용, 중복, 검색 성능을 함께 고려해야 합니다.
