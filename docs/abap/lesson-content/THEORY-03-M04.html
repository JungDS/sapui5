학습 목표

Chapter 3의 마지막 Lesson에서는 여러 입력칸을 읽기 좋게 묶는 Selection Screen Block을 맛봅니다. SELECTION-SCREEN BEGIN OF BLOCK, END OF BLOCK, FRAME TITLE이 코드와 화면에 각각 어떤 영향을 주는지 확인합니다.

1. Chapter 3 연결: 입력 화면을 읽기 좋게 정리한다

M01~M03에서는 PARAMETERS 입력칸을 만들고, 기본값과 필수값을 붙이고, 입력값을 WRITE로 출력했습니다. 입력칸이 한두 개면 나열해도 충분하지만, 실제 Report는 회사 코드, 기간, 상태, 담당자처럼 여러 조건을 받습니다.

Block은 관련 입력 필드를 하나의 Selection Screen 영역으로 묶어 주는 장치입니다. 값을 검증하거나 데이터 구조를 바꾸는 기능이 아니라, 사용자가 화면을 더 빨리 읽도록 돕는 시각적 구조입니다.

핵심 한 줄: Block은 메모리 구조가 아니라 화면 정리 도구다.

2. BEGIN과 END는 반드시 짝이다

Block은 시작과 끝이 있는 범위입니다. SELECTION-SCREEN BEGIN OF BLOCK b_cond로 시작했다면, 같은 이름으로 SELECTION-SCREEN END OF BLOCK b_cond를 써서 닫아야 합니다. 이름이 다르면 구문 오류가 납니다.

조각 역할 초급 기준
b_cond Block 이름 시작과 끝에서 같은 이름을 씁니다. 공식 문서 기준 최대 20자입니다.
WITH FRAME 테두리 표시 비어 있지 않은 Block 주위에 프레임을 그립니다.
TITLE text-001 프레임 제목 Text Symbol의 문구가 프레임 왼쪽 위에 표시됩니다.
사이의 PARAMETERS Block에 포함되는 화면 요소 화면에서 같은 프레임 안에 보입니다.

3. 코드가 화면에서 어떻게 보이는가

text-001에 “조회 조건”이라는 Text Symbol을 유지보수했다고 가정하면, P_CARR와 P_DATE는 같은 프레임 안에 보입니다. 중요한 점은 입력 변수들이 합쳐진 것이 아니라, 화면 배치만 함께 묶였다는 사실입니다.

코드 범위
  • BEGIN OF BLOCK b_cond가 묶음 시작입니다.
  • 사이에 있는 PARAMETERS가 프레임 안에 배치됩니다.
  • END OF BLOCK b_cond가 묶음 끝입니다.
화면 결과
  • 프레임 제목은 “조회 조건”처럼 사용자가 읽는 문구입니다.
  • P_CARR, P_DATE는 같은 상자 안에 보입니다.
  • p_carr, p_date 변수는 여전히 독립입니다.
WITH FRAME을 빼면 문법 오류인가요?

아닙니다. Block 범위 자체는 정의할 수 있지만 사용자가 볼 수 있는 사각형 테두리는 나타나지 않습니다. 이번 Lesson에서는 화면 정리 효과를 보기 위해 WITH FRAME TITLE 조합을 기준으로 익힙니다.

4. TITLE은 사용자에게 보이는 문구다

FRAME TITLE은 프레임 왼쪽 위에 표시되는 제목입니다. 실습에서는 보통 text-001 같은 Text Symbol을 연결합니다. 이렇게 하면 나중에 번역과 문구 관리를 코드와 분리하기 쉽습니다.

⚠️

Text Symbol을 비우면 제목도 비어 보인다

TITLE text-001을 적어도 SE38의 Text Elements에서 001 문구를 등록하고 활성화하지 않으면, 프레임 제목이 기대처럼 보이지 않을 수 있습니다.

기술 이름
  • b_cond는 ABAP 코드에서 쓰는 Block 이름입니다.
  • 시작과 끝을 맞추는 내부 식별자입니다.
  • 사용자에게 그대로 보이게 하려는 문구가 아닙니다.
화면 제목
  • text-001의 실제 문구는 “조회 조건”처럼 사용자가 읽습니다.
  • 짧고 업무 의미가 드러나는 제목이 좋습니다.
  • “b1”, “cond” 같은 내부 이름을 제목으로 쓰지 않습니다.

6. Block이 바꾸는 것과 바꾸지 않는 것

바꾸는 것 Selection Screen에서 관련 입력 필드가 하나의 프레임 안에 묶여 보입니다.
바꾸지 않는 것 p_carr, p_date 같은 PARAMETERS 변수는 여전히 각각 독립적인 값입니다.
검증 아님 Block으로 묶었다고 필수값, 존재 여부, 권한 검증이 자동으로 추가되지는 않습니다.
디자인의 시작 입력 화면을 읽기 좋게 만드는 가장 작은 구조화 방법입니다.
Block 안에 들어간 변수들이 Structure처럼 묶이나요?

아닙니다. Block은 화면 렌더링을 위한 묶음입니다. 프로그램 메모리에서는 p_carr, p_date가 각각의 PARAMETERS 변수로 남습니다.

8. 7분 미니 실습

  1. SE38에서 Z_PARAM_M04_BLOCK Report를 만들고 p_carr, p_date를 준비합니다.
  2. SELECTION-SCREEN BEGIN OF BLOCK b_cond WITH FRAME TITLE text-001.와 END OF BLOCK b_cond. 사이에 두 입력 필드를 넣습니다.
  3. text-001의 문구를 “조회 조건”으로 등록하고 활성화합니다.
  4. WITH FRAME이 있을 때와 없을 때 화면 차이를 비교합니다.
  5. END OF BLOCK b_wrong처럼 이름을 바꿔 구문 오류를 확인한 뒤 다시 고칩니다.
실습 완료 기준

BEGIN OF BLOCK과 END OF BLOCK의 이름을 맞춰 닫고, 프레임 제목이 사용자에게 보이는 문구라는 점을 설명할 수 있으면 성공입니다.

10. Chapter 3 마무리

📝

Chapter 3에서 잡은 네 가지

  • PARAMETERS는 입력칸과 변수를 함께 만듭니다.
  • DEFAULT는 처음 보이는 값, OBLIGATORY는 빈 값 실행 방지입니다.
  • 입력값은 같은 이름의 변수로 넘어가고 WRITE로 Output List에 출력됩니다.
  • SELECTION-SCREEN BEGIN OF BLOCK은 관련 입력칸을 프레임으로 묶어 화면을 읽기 좋게 만듭니다.
