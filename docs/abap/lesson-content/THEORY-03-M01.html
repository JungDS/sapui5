학습 목표

PARAMETERS가 어떻게 내부 변수와 UI(화면 입력칸)를 동시에 만드는지 그 이중(Dual) 구조를 이해하고, 화면 이벤트에 따른 올바른 검증 위치를 익힙니다.

1. PARAMETERS의 마법: 변수와 화면의 동시 생성

ABAP 초보자들이 리포트 프로그램(Executable Program)을 작성할 때 가장 신기해하는 부분은 화면을 그리는 툴 없이 코드 한 줄로 입력 화면이 만들어진다는 점입니다.

SE38에서 PARAMETERS pa_name TYPE sflight-carrid.이라고 선언하면 두 가지 마법이 동시에 일어납니다.

백엔드 (Memory)

프로그램 내부에 사용자가 입력할 값을 담아둘 데이터 컨테이너(변수)가 생성됩니다.

DATA 선언과 유사하게 값을 임시 저장하지만, 화면과 직접 연결된다는 차이가 있습니다.

프론트엔드 (UI)

시스템이 Screen 1000이라는 표준 선택 화면(Selection Screen)을 렌더링하고, 입력 필드를 자동으로 그려줍니다.

심화 팁: 기본 타입보다 DDIC 참조하기

초보자는 TYPE string이나 TYPE c LENGTH 3처럼 기본 타입을 자주 사용하지만, 실무에서는 TYPE sflight-carrid처럼 ABAP Dictionary의 Data Element나 테이블 필드를 참조해야 합니다. 이렇게 하면 필드 라벨(Field Label)과 검색 도움말(Search Help, F4) 기능을 공짜로 상속받아 사용자 편의성이 극대화됩니다.

2. 프로그램 실행 이벤트와 유효성 검증

PARAMETERS로 만들어진 화면은 단순히 입력만 받는 것이 아니라, 정해진 이벤트 흐름(Event Flow)에 따라 엄격하게 제어됩니다.

INITIALIZATION 화면 출력 전 동적 초기값 세팅
AT SELECTION-SCREEN 사용자 입력값 사전 유효성 검증
START-OF-SELECTION 검증 통과 후 메인 비즈니스 로직 실행
초보자의 흔한 오류: 검증 타이밍 놓치기

입력된 값을 검사하는 로직을 START-OF-SELECTION 안에 작성하면 큰일납니다. 에러 메시지를 띄우더라도 이미 입력 화면(Selection Screen) 단계를 벗어났기 때문에, 사용자가 곧바로 값을 수정하고 다시 실행할 수 없는 치명적 흐름 오류가 발생합니다. 유효성 검증과 에러(TYPE 'E') 처리는 반드시 AT SELECTION-SCREEN 블록 내에서 수행해야 합니다.

파라미터 입력 및 이벤트 흐름 시뮬레이터
실행(F8) 버튼을 누르면 SAP 내부 이벤트 흐름이 로그로 출력됩니다…
실무 주의사항: 범위 검색에는 쓰지 마세요!

PARAMETERS는 오직 '단일 값(단건)' 입력 전용입니다. 다중 값이나 "2026년 1월부터 12월까지"처럼 범위 조건을 받아야 할 때는 다음에 배울 SELECT-OPTIONS를 사용해야 합니다. 범위 요건에 PARAMETERS를 2개(시작, 끝) 선언하는 것은 대표적인 초보적 안티패턴입니다.
