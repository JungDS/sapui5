학습 목표

PARAMETERS가 어떻게 내부 변수와 UI(화면 입력칸)를 동시에 만드는지 그 이중(Dual) 구조를 이해하고 실무 옵션을 익힙니다.

1. PARAMETERS의 마법: 변수와 화면의 동시 생성

ABAP 초보자들이 리포트 프로그램(Executable Program)을 작성할 때 가장 신기해하는 부분은 화면을 그리는 툴 없이 코드 한 줄로 입력 화면이 만들어진다는 점입니다.

SE38에서 PARAMETERS pa_name TYPE string.이라고 선언하면 두 가지 마법이 동시에 일어납니다.

백엔드 (Memory)

프로그램 내부에 사용자가 입력할 값을 담아둘 데이터 컨테이너(변수)가 생성됩니다.

DATA 선언과 유사하게 값을 임시 저장하지만, 화면과 직접 연결된다는 차이가 있습니다.

프론트엔드 (UI)

시스템이 Screen 1000이라는 표준 선택 화면(Selection Screen)을 렌더링하고, 입력 필드를 자동으로 그려줍니다.

2. 직접 해보는 실습 시뮬레이션

아래 가상 Sandbox를 통해 단일 기본 입력을 받고, 실행 버튼(F8)을 눌렀을 때 어떻게 이벤트 흐름이 진행되는지 직접 조작해 보세요. (에러 발생 조건을 테스트해 볼 수 있습니다!)

T-Code: SE38 (ZPARAM_DEMO)
파라미터 입력 시뮬레이터
실행(F8) 버튼을 누르면 SAP 내부 이벤트 흐름이 로그로 출력됩니다…
실무 주의사항: 범위 검색에는 쓰지 마세요!

PARAMETERS는 오직 '단일 값(단건)' 입력 전용입니다. "2026년 1월부터 12월까지"처럼 범위를 받아야 할 때는 다음에 배울 SELECT-OPTIONS를 사용해야 합니다.

심화 팁: 기본 타입보다 DDIC 참조하기

초보자는 TYPE string이나 TYPE c LENGTH 20처럼 기본 타입을 자주 사용하지만, 실무에서는 TYPE sflight-carrid처럼 ABAP Dictionary의 Data Element나 테이블 필드를 참조하도록 권장합니다. 이렇게 하면 필드 라벨(Field Label)과 검색 도움말(Search Help) 기능을 공짜로 상속받을 수 있습니다.
