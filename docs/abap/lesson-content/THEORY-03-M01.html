학습 목표

지난 Chapter에서 ABAP 프로그램이 값을 선언하고 출력하는 방법을 배웠습니다. 이번에는 프로그램 실행 전에 사용자에게 값을 입력받는 PARAMETERS를 배웁니다. Selection Screen, Screen Input, Elementary Input이 무엇인지 아주 처음부터 잡아봅니다.

1. 지난 Chapter 연결: 코드 안 값에서 화면 입력값으로 🖥️

Chapter 2에서는 DATA gv_name TYPE string VALUE 'ABAP'.처럼 코드 안에 값을 직접 넣고 WRITE로 출력했습니다. 학습할 때는 이 방식이 간단하지만, 실제 프로그램이 매번 같은 값만 처리하면 쓸모가 많이 줄어듭니다.

사용자가 실행할 때마다 이름, 날짜, 회사 코드, 상태값을 직접 입력하고 싶을 수 있습니다. 이때 ABAP Report가 자동으로 보여주는 입력 화면이 Selection Screen입니다.

Selection Screen은 “프로그램 시작 전에 사용자에게 필요한 값을 묻는 첫 화면”입니다.

2. PARAMETERS는 한 칸짜리 입력 질문이다 ✍️

PARAMETERS는 Selection Screen에 입력 필드 하나를 만들어주는 문법입니다. 사용자가 그 칸에 값을 넣고 실행하면, ABAP 프로그램은 그 값을 변수처럼 사용할 수 있습니다.

ABAP
1
2
3
4
5 
REPORT zparam_basic.

PARAMETERS p_name TYPE string.

WRITE: / '입력한 이름:', p_name.

위 프로그램을 실행하면 바로 결과가 나오는 것이 아니라, 먼저 입력 화면이 나타납니다. 사용자가 p_name 칸에 값을 입력하고 실행하면, 그 값이 프로그램 안으로 들어오고 WRITE로 출력됩니다.

💡

DATA와 PARAMETERS의 차이

  • DATA: 프로그램 내부에서 쓰는 변수입니다. 화면 입력칸이 자동으로 생기지는 않습니다.
  • PARAMETERS: 변수 역할도 하면서 Selection Screen에 입력칸을 만들어줍니다.

3. Screen Input과 Elementary Input 감각 잡기 🧩

Screen Input은 사용자가 화면에서 직접 넣는 값입니다. PARAMETERS는 보통 한 번에 하나의 단순 값을 받습니다. 이런 단순 입력을 Elementary Input이라고 생각하면 쉽습니다.

  • p_name TYPE string: 이름 한 개 입력
  • p_age TYPE i: 나이 한 개 입력
  • p_carr TYPE c LENGTH 3: 항공사 코드 한 개 입력
  • p_date TYPE d: 날짜 한 개 입력

여기서 중요한 것은 “한 개”입니다. 지금 배우는 PARAMETERS는 범위 여러 개를 받는 도구가 아닙니다. 나중에 SELECT-OPTIONS를 배우면 여러 값과 범위를 입력받을 수 있지만, 이번 Chapter에서는 한 칸짜리 입력부터 정확히 익힙니다.

4. 최소 실습: 이름과 나이를 입력받아 출력하기 🧪

이제 입력값 2개를 받아 Output List에 출력해봅시다.

ABAP

REPORT zparam_profile.

PARAMETERS p_name TYPE string.
PARAMETERS p_age  TYPE i.

WRITE: / '이름:', p_name,
       / '나이:', p_age.
  • 프로그램 실행 → Selection Screen 표시
  • p_name에 이름 입력
  • p_age에 숫자 입력
  • 실행 → Output List에 입력값 출력

처음에는 화면 라벨이 변수명처럼 투박하게 보일 수 있습니다. 더 예쁜 화면 텍스트와 블록 구성은 뒤 Lesson에서 조금씩 다룹니다. 지금은 “사용자가 입력한 값이 프로그램으로 들어온다”는 흐름이 핵심입니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 사용자가 p_name과 p_age에 값을 입력하고 실행하면, 입력값이 그대로 출력됩니다.
  • ❌ 타입 오류: p_age TYPE i에 숫자가 아닌 문자를 넣으면 입력 단계에서 오류가 날 수 있습니다.
  • ❌ 빈 값 허용: 기본 PARAMETERS는 값을 꼭 넣으라고 강제하지 않습니다. 빈 값이 들어와도 프로그램이 실행될 수 있습니다.
  • ❌ 과도한 확장: 여러 값, 범위, 복잡한 검증은 이번 Lesson에서 다루지 않습니다. 지금은 한 칸 입력에 집중합니다.
입력 화면은 프로그램의 첫인상입니다. 사용자가 어떤 값을 넣어야 하는지 명확해야 좋은 프로그램이 됩니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

입력받았다고 바로 믿으면 안 됩니다

Selection Screen이 타입에 맞지 않는 값 일부를 막아주긴 하지만, 업무적으로 올바른 값인지까지 자동으로 보장하지는 않습니다. 예를 들어 존재하지 않는 항공사 코드, 권한이 없는 회사 코드, 미래 날짜 같은 검증은 별도로 고민해야 합니다. 이 깊은 검증은 이후 Lesson에서 확장합니다.

또한 회사마다 PARAMETERS 이름, 화면 텍스트, 기본값 처리 관행이 다를 수 있습니다. 고객사 스타일을 따르되, 표준 SAP 문법과 회사 관행을 섞어 외우지 않는 것이 좋습니다.

7. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Selection Screen은 프로그램 실행 전에 사용자에게 값을 묻는 입력 화면입니다.
  • PARAMETERS는 한 칸짜리 입력 필드를 만들고, 그 값을 프로그램에서 사용할 수 있게 합니다.
  • DATA는 내부 변수이고, PARAMETERS는 화면 입력칸까지 만들어주는 변수에 가깝습니다.
  • Elementary Input은 이름, 나이, 날짜처럼 단순 값 하나를 받는 입력입니다.
  • 입력 타입은 기본 오류를 줄여주지만, 업무 검증까지 모두 대신하지는 않습니다.

다음 Lesson DEFAULT / OBLIGATORY 사용에서는 입력칸에 기본값을 넣고, 꼭 입력해야 하는 필드로 만드는 방법을 배웁니다.
