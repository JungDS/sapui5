학습 목표

이번 Lesson에서는 PARAMETERS 문 한 줄이 왜 화면 입력칸과 프로그램 변수를 동시에 만드는지 이해합니다. Chapter 2의 DATA 문, WRITE 문과 연결해 Selection Screen의 첫 감각을 잡습니다.

1. 코드 안 값에서 실행 전 입력값으로

Chapter 2에서는 값을 코드 안에 직접 적었습니다. 예를 들어 DATA gv_name TYPE c.처럼 선언하면, 프로그램은 매번 코드가 정한 값을 기준으로 실행됩니다.

실제 Report는 실행할 때마다 사용자가 회사 코드, 날짜, 이름 같은 조건을 바꿔 넣어야 합니다. ABAP 실행 프로그램은 이런 값을 묻기 위해 표준 Selection Screen을 사용할 수 있고, 가장 작은 입력칸을 만드는 문장이 PARAMETERS입니다.

오늘의 핵심은 “입력 화면을 직접 그리는 법”이 아니라, PARAMETERS가 화면과 메모리를 어떻게 연결하는지 이해하는 것입니다.

2. PARAMETERS는 입력칸과 변수를 함께 만든다

PARAMETERS 문은 두 가지 일을 동시에 합니다. 첫째, Selection Screen에 사용자가 값을 넣을 Screen Input 필드를 만듭니다. 둘째, 프로그램 안에서 그 값을 읽을 수 있는 변수도 만듭니다.

한 줄 선언이 만드는 두 결과

선언PARAMETERS p_name(20) TYPE c.
화면Selection Screen에 P_NAME 입력칸이 생긴다.
메모리프로그램 안에서는 p_name 변수를 읽는다.
출력WRITE가 입력값을 List Output에 보여준다.

DATA와 PARAMETERS 비교

DATA: 내부 변수만 선언
  • 프로그램 메모리에만 존재합니다.
  • 사용자 입력칸이 자동으로 생기지 않습니다.
  • 계산 중간값, 출력용 변수처럼 내부 처리에 씁니다.
PARAMETERS: 입력칸 + 변수
  • Selection Screen 입력 필드를 만듭니다.
  • 사용자가 실행 전 값을 넣을 수 있습니다.
  • 입력된 값은 같은 이름의 변수처럼 읽습니다.

3. 최소 코드와 자동 생성 Screen 1000

실행 가능한 Report에 PARAMETERS를 선언하면 ABAP 런타임이 표준 Selection Screen을 준비합니다. 실행 프로그램의 표준 Selection Screen 번호는 Screen 1000입니다. 초급 단계에서는 “Report 실행 전에 자동으로 뜨는 입력 화면”이라고 잡으면 충분합니다.

아닙니다. 이 Lesson의 범위에서는 PARAMETERS 선언만으로 표준 Selection Screen의 입력 필드가 생성됩니다. Screen Painter는 일반 Dynpro 화면을 직접 설계할 때 나오는 별도 주제이며, Chapter 3의 기본 입력 흐름에서는 다루지 않습니다.

4. Elementary Input: 한 칸에 한 값

지금 배우는 Elementary Input은 이름 하나, 나이 하나, 날짜 하나처럼 단순 값 하나를 받는 입력입니다. 하나의 PARAMETERS 선언은 보통 한 입력칸을 만들고, 그 입력칸은 하나의 값만 담습니다.

처음에 쓰기 좋은 입력 예시

입력 목적 선언 예시 초급 판단
짧은 이름 PARAMETERS p_name(20) TYPE c. 문자 길이를 정해서 받는다.
숫자 PARAMETERS p_age TYPE i. 숫자가 아닌 값은 입력 단계에서 막힐 수 있다.
날짜 PARAMETERS p_date TYPE d. 내부 형식은 날짜 타입 규칙을 따른다.
⚠️

초급 단계에서 먼저 지킬 규칙

  • p_name, p_date처럼 Parameter 이름은 짧게 둡니다. Selection Screen 입력 필드 이름은 8자 제한을 넘기지 않는 습관이 안전합니다.
  • 처음에는 TYPE c, TYPE i, TYPE d 또는 Dictionary의 단순 Data Element처럼 화면 입력에 맞는 타입으로 시작합니다.
  • SELECT-OPTIONS는 여러 값과 범위를 받는 도구입니다. 이번 Lesson에서는 한 칸 입력에 집중합니다.

5. 5분 미니 실습: DATA로 바꾸면 무엇이 사라질까

아래 실습은 문법을 많이 외우는 것이 아니라, DATA와 PARAMETERS의 차이를 눈으로 확인하는 데 목적이 있습니다.

ABAP
1
2
3
4
5
6 
REPORT z_my_first_param.

PARAMETERS p_user(10) TYPE c.

START-OF-SELECTION.
  WRITE: / '사용자:', p_user.
  1. 프로그램을 활성화하고 실행합니다.
  2. Selection Screen에 생긴 P_USER 입력칸에 본인 이름을 넣습니다.
  3. 실행 후 Output List에 같은 값이 출력되는지 확인합니다.
  4. PARAMETERS 줄을 DATA p_user(10) TYPE c.로 바꿔 보고, 입력칸이 사라지는지 확인합니다.
왜 입력칸이 사라지나요?

DATA는 프로그램 안의 변수만 만들기 때문입니다. 사용자가 실행 전에 값을 넣을 화면 요소를 만들려면 PARAMETERS가 필요합니다. 즉, PARAMETERS는 내부 변수와 Selection Screen 입력 필드를 함께 선언하는 문장입니다.

8. 확인 퀴즈

  1. PARAMETERS p_name(20) TYPE c.를 선언하면 프로그램 안과 화면에 각각 무엇이 생기나요?
  2. DATA로 같은 이름의 변수를 선언하면 Selection Screen 입력칸이 자동으로 생기나요?
  3. 여러 값이나 범위를 입력받는 기능을 지금 바로 다루지 않는 이유는 무엇인가요?
정답/해설 보기
  1. 화면에는 P_NAME 입력칸이 생기고, 프로그램 안에서는 p_name 변수를 읽을 수 있습니다.
  2. 아니요. DATA는 내부 변수만 만들고 Selection Screen 입력 필드는 만들지 않습니다.
  3. 이번 범위는 한 칸에 한 값을 받는 기본 입력입니다. 여러 값과 범위는 SELECT-OPTIONS, Selection Table 같은 다음 개념이 필요합니다.

오늘의 기준 문장

PARAMETERS는 Selection Screen 입력칸을 만들고, 사용자가 넣은 값을 프로그램 안의 변수처럼 읽게 해 주는 선언입니다. DATA는 메모리만, PARAMETERS는 화면과 메모리를 함께 만든다고 구분하세요.
