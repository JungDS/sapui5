학습 목표

PARAMETERS가 내부 변수와 Selection Screen 입력칸을 동시에 만드는 구조를 이해하고, 단일 값 입력은 Elementary Input으로 처리한다는 기준을 익힙니다.

1. 지난 Chapter 연결: 이제 프로그램이 사용자에게 값을 묻는다

Chapter 2에서는 값 선언, 출력, 분기, 반복, 시스템 필드를 익혔습니다. 지금부터는 리포트가 실행될 때 사용자에게 조건을 입력받는 선택 화면을 다룹니다. Classic ABAP Report에서 가장 기본적인 입력 방식이 PARAMETERS입니다.

핵심 한 줄: PARAMETERS는 변수 하나와 화면 입력칸 하나를 동시에 만든다.

2. PARAMETERS의 이중 구조: 메모리 변수 + 화면 필드

SE38에서 리포트 코드를 작성하고 PARAMETERS p_carr TYPE sflight-carrid.를 선언하면, ABAP 런타임은 두 가지를 자동으로 준비합니다.

Memory
  • p_carr라는 전역 데이터 오브젝트 생성
  • 사용자가 입력한 단일 값을 저장
  • START-OF-SELECTION에서 일반 변수처럼 사용
Screen 1000
  • 표준 선택 화면에 입력 필드 자동 렌더링
  • DDIC 타입이면 필드 라벨과 도움말을 활용
  • 사용자는 값을 입력한 뒤 다시 F8로 실행
DATA p_carr ...를 또 선언해야 하나요?

아닙니다. PARAMETERS 자체가 데이터 오브젝트 선언입니다. 같은 이름으로 DATA를 다시 선언하면 중복 선언이 됩니다. 화면 입력값은 곧바로 p_carr 변수에 들어옵니다.

3. 기본 문법: 타입은 명시하고, 단일 값만 받는다

가장 작은 형태는 PARAMETERS p_name TYPE c LENGTH 10.입니다. 타입과 길이를 명시하지 않으면 초보자가 의도한 입력칸보다 훨씬 작은 필드가 만들어질 수 있으니, 처음부터 명확하게 적습니다.

REPORT z_param_basic.

PARAMETERS p_carr TYPE sflight-carrid.

START-OF-SELECTION.
  WRITE: / '입력 항공사:', p_carr.
⚠️

범위 조건은 PARAMETERS가 아닙니다

PARAMETERS는 단일 값 입력 전용입니다. “날짜 From~To”, “여러 회사코드”, “제외 조건”처럼 범위·다중값이 필요하면 뒤에서 배울 SELECT-OPTIONS를 사용합니다.

4. 이벤트 흐름: 입력 검증은 화면 단계에서 끝낸다

사용자가 선택 화면에서 값을 입력하고 F8을 누르면, ABAP 리포트는 입력값을 검증하는 AT SELECTION-SCREEN을 거친 뒤 실제 로직인 START-OF-SELECTION으로 들어갑니다.

INITIALIZATION선택 화면 출력 전 기본값 준비
Selection Screen사용자 입력
AT SELECTION-SCREEN입력값 검증, 오류 시 화면으로 복귀
START-OF-SELECTION검증 통과 후 메인 처리
왜 START-OF-SELECTION에서 검증하면 안 좋나요?

그 시점은 이미 선택 화면 처리를 통과한 뒤입니다. 사용자가 값을 바로 고쳐 재실행하는 흐름을 만들려면 AT SELECTION-SCREEN에서 오류 메시지를 내고 선택 화면에 머물게 해야 합니다.

5. 직접 해보기: Selection Screen 시뮬레이터

아래 sandbox는 PARAMETERS p_carr TYPE sflight-carrid.가 변수와 입력칸을 동시에 만들고, F8 실행 시 이벤트가 어떤 순서로 흐르는지 보여 줍니다. 항공사 코드를 비우거나 지원하지 않는 값으로 바꿔 검증 흐름을 확인하세요.

T-Code: SE38 (ZPARAM_DEMO)
PARAMETERS 입력 및 이벤트 흐름
실행(F8)을 누르면 Selection Screen 이벤트 흐름이 표시됩니다.

6. 실무에서 조심해야 할 점

🚨

단일 값인지, 범위 조건인지 먼저 결정하세요

요구사항이 “회사코드 하나”이면 PARAMETERS가 맞습니다. 하지만 기간, 복수 코드, 제외 조건처럼 범위가 필요하면 SELECT-OPTIONS를 고려해야 합니다. 입력 구조가 곧 SQL 조건과 사용자 경험을 결정합니다.

  • 타입 명시: TYPE c LENGTH 3 또는 DDIC 참조처럼 입력 길이와 의미를 분명히 둡니다.
  • 검증 위치: 값 검증은 AT SELECTION-SCREEN, 조회·가공은 START-OF-SELECTION에 둡니다.
  • 과확장 금지: DEFAULT, OBLIGATORY, 블록/라인 디자인은 다음 Lesson에서 깊게 다룹니다.

7. 공식 문서로 더 확인하기

SAP Help Portal: PARAMETERS선택 화면 파라미터와 데이터 오브젝트 선언 규칙을 확인합니다. SAP Help Portal: AT SELECTION-SCREEN선택 화면 입력값 검증 이벤트를 확인합니다. SAP Help Portal: START-OF-SELECTION검증 후 메인 처리 이벤트를 확인합니다. SAP Help Portal: SELECT-OPTIONS범위 입력은 PARAMETERS가 아니라 SELECT-OPTIONS 영역임을 확인합니다.

8. 확인 퀴즈

  1. PARAMETERS 한 줄이 동시에 만드는 두 가지는 무엇인가요?
  2. 입력값 검증은 어느 이벤트 블록에 두는 것이 맞나요?
  3. 검증이 통과한 뒤 메인 로직이 실행되는 이벤트는 무엇인가요?
  4. 범위나 다중값 입력이 필요하면 어떤 구문으로 확장하나요?
정답/해설 보기
  1. 메모리 데이터 오브젝트와 Selection Screen 입력 필드입니다.
  2. AT SELECTION-SCREEN입니다.
  3. START-OF-SELECTION입니다.
  4. SELECT-OPTIONS입니다.
