학습 목표

지난 Lesson에서 하나의 검색 방법을 가진 Elementary Search Help를 배웠습니다. 이번에는 여러 Search Help를 한곳에 묶는 Collective Search Help와, 값을 주고받는 Search Help Parameter의 기본 감각을 익힙니다.

1. 지난 시간 연결: 검색 방법이 하나만 있으면 부족할 때가 있다 🧭

Elementary Search Help는 하나의 방식으로 후보를 찾습니다. 예를 들어 항공사 코드를 코드 기준으로 검색하거나, 항공사 이름 기준으로 검색하는 식입니다. 그런데 사용자는 상황에 따라 다른 방식으로 찾고 싶어할 수 있습니다.

어떤 사용자는 코드를 알고 있고, 어떤 사용자는 이름 일부만 알고 있고, 어떤 사용자는 국가별로 보고 싶을 수 있습니다. 이때 여러 검색 방법을 하나의 F4 Help 안에 묶어주는 것이 Collective Search Help입니다.

Collective Search Help는 여러 개의 작은 검색 도움말을 모아둔 검색 메뉴판입니다.

2. Collective Search Help는 묶음, Elementary는 실제 검색 방법 📚

Collective Search Help 자체가 직접 모든 후보를 읽는다고 생각하면 헷갈립니다. 더 정확히는 여러 Elementary Search Help를 포함하는 상위 묶음입니다.

  • Elementary Search Help: 실제 후보를 읽는 하나의 검색 방법
  • Collective Search Help: 여러 Elementary Search Help를 모아 사용자에게 선택지를 제공
  • 사용자 경험: F4 팝업 안에서 여러 검색 경로를 선택할 수 있음
💡

예시

ZSH_CARRIER_ALL이라는 Collective Search Help 안에 “코드로 검색”, “이름으로 검색”, “국가로 검색” Elementary Search Help를 묶을 수 있습니다.

Collective는 메뉴판, Elementary가 실제 검색 방법

Collective: ZSH_CARRIER_ALL
탭 1코드로 검색
탭 2이름으로 검색
탭 3국가로 검색
Elementary 1: 코드로 검색
출처ZCARRIER
조건CARRID
Elementary 2: 이름으로 검색
출처ZCARRIER
조건CARRNAME
Elementary 3: 국가로 검색
출처ZCARRIER
조건COUNTRY

Collective Search Help는 직접 데이터를 읽지 않습니다. F4 팝업에서 탭으로 보이는 각 검색 방법(Elementary)이 실제 후보 조회를 담당합니다.

3. Search Help Parameter는 값을 주고받는 연결점 🔌

Search Help Parameter는 Search Help가 외부 입력칸과 값을 주고받는 통로입니다. 어떤 값은 검색 조건으로 들어오고, 어떤 값은 사용자가 선택한 뒤 입력칸으로 돌아갑니다.

  • Import 성격: 이미 입력된 값이 Search Help의 검색 조건으로 들어갈 수 있습니다.
  • Export 성격: 사용자가 선택한 값이 화면 입력 필드로 돌아갈 수 있습니다.
  • 표시 성격: 후보 목록에 보여줄 필드로 사용할 수 있습니다.

초심자 단계에서는 세부 체크박스를 모두 외우기보다, “Search Help Parameter는 F4 팝업과 원래 입력 화면 사이를 연결하는 입출구”라고 기억하면 좋습니다.

4. 최소 실습 흐름: 두 검색 방법 묶기 🧪

실제 구성은 시스템 화면에 따라 다르지만, 기본 흐름은 아래처럼 생각할 수 있습니다.

  1. 항공사 코드 기준 Elementary Search Help를 준비합니다.
  2. 항공사 이름 기준 Elementary Search Help를 준비합니다.
  3. Collective Search Help를 새로 만듭니다.
  4. 두 Elementary Search Help를 포함 Search Help로 추가합니다.
  5. 공통 Search Help Parameter를 맞춰 코드가 입력칸으로 돌아오게 합니다.
  6. F4 팝업에서 두 검색 방법이 보이는지 확인합니다.

이 Lesson의 목적은 “Collective는 여러 검색 방법을 묶는다”는 구조 이해입니다. 복잡한 Parameter 매핑과 고급 검색 조건은 실무에서 필요할 때 더 깊게 다룹니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: F4를 누르면 여러 검색 방법이 보이고, 사용자는 원하는 방식으로 후보를 찾아 선택합니다.
  • ✅ 반환 흐름: 선택한 항공사 코드가 원래 입력칸으로 돌아옵니다.
  • ❌ 파라미터 매핑 오류: 이름 필드를 돌려줘야 하는지 코드 필드를 돌려줘야 하는지 잘못 설정하면 입력칸에 엉뚱한 값이 들어갈 수 있습니다.
  • ❌ 검색 방법 과다: 너무 많은 Elementary Search Help를 넣으면 사용자가 오히려 어떤 탭을 써야 할지 헷갈립니다.
검색 방법은 많을수록 무조건 좋은 것이 아닙니다. 사용자가 실제로 찾는 방식을 기준으로 골라야 합니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

Collective Search Help는 정리 도구이지 만능 해결책이 아닙니다

여러 검색 도움말을 무작정 묶으면 화면은 복잡해지고 유지보수도 어려워집니다. 표준 Collective Search Help가 이미 있으면 먼저 분석하고, 새로 만들 때는 실제 사용자 검색 패턴을 기준으로 최소한의 검색 방법만 포함하세요.

또한 Search Help Parameter 매핑은 작은 설정 같아 보여도 입력값 품질에 직접 영향을 줍니다. 후보 목록에 보여줄 값과 최종 입력칸으로 반환할 값을 구분해서 확인해야 합니다. 특히 사용자가 팝업에서 행을 선택했는데 입력칸에 값이 돌아오지 않는 문제는, 반환해야 할 파라미터의 Export 설정 누락이 원인인 경우가 많습니다.

7. 미니 실습: 검색 메뉴판 구성하기 🧪

✍️

실습 과제

  1. 위 구조도를 가리고 Collective와 Elementary의 관계를 그림으로 직접 그려봅니다.
  2. “우리 회사 거래처 찾기” F4를 설계한다면 어떤 검색 방법 2~3개를 탭으로 넣을지 적어봅니다.
  3. 각 검색 방법에서 입력칸으로 돌아가야 할 공통 반환 값(예: 거래처 코드)을 정합니다.
  4. 검색 방법을 5개 이상 넣었을 때 사용자 입장에서 생기는 문제를 한 줄로 적어봅니다.

완료 조건: “Collective는 직접 데이터를 읽지 않고 Elementary에게 위임한다”를 구조도와 함께 설명할 수 있으면 성공입니다.

8. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: Search Help - Elementary/Collective를 포함한 Search Help의 공식 정의를 확인합니다.
  • SAP Help Portal: Input Help - F4 입력 도움말 전체 메커니즘에서 Search Help의 위치를 확인합니다.
  • SAP Help Portal: Check Table - Search Help 없이도 Check Table로 F4 후보가 만들어지는 경우를 비교합니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. Collective Search Help는 후보 데이터를 직접 읽어올까요?
  2. F4 팝업에서 행을 더블클릭했는데 입력칸에 값이 들어오지 않는다면 무엇부터 확인해야 하나요?
  3. 검색 방법(Elementary)은 많이 묶을수록 좋은 설계일까요?
정답/해설 보기
  1. 아니요. Collective는 여러 Elementary Search Help를 묶는 상위 메뉴판이고, 실제 후보 조회는 각 Elementary의 Selection Method가 담당합니다.
  2. Search Help Parameter의 Export(반환) 설정입니다. 반환할 필드가 Export로 지정되어야 선택값이 입력칸으로 돌아옵니다.
  3. 아니요. 검색 방법이 너무 많으면 사용자가 어떤 탭을 써야 할지 헷갈리고 유지보수도 어려워집니다. 실제 사용자 검색 패턴 기준으로 최소한만 넣습니다.

10. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Collective Search Help는 여러 Elementary Search Help를 묶는 상위 검색 도움말입니다.
  • Elementary Search Help는 실제 후보를 읽는 하나의 검색 방법입니다.
  • Search Help Parameter는 F4 팝업과 입력 화면 사이에서 값을 주고받는 연결점입니다.
  • 검색 방법을 너무 많이 넣으면 오히려 사용성이 떨어질 수 있습니다.
  • 후보 목록에 보여줄 값과 입력칸으로 반환할 값을 정확히 구분해야 합니다.
