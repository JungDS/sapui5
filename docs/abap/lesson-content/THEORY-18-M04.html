학습 목표

객체를 만들어야 쓰는 Instance Method와, 객체 없이 클래스 이름으로 바로 쓰는 Static Method의 차이를 배웁니다. 언제 무엇을 쓸지 감을 잡습니다.

1. 지난 시간 연결: 꼭 객체를 만들어야 할까? 🤔

지금까지는 NEW로 객체를 만든 뒤 ->로 메서드를 불렀습니다. 그런데 어떤 기능은 "특정 객체"와 무관합니다. 예를 들어 "두 숫자를 더하는 계산기 기능"은 어느 객체의 상태와도 상관없죠.

이런 기능은 객체를 만들지 않고 클래스 이름으로 바로 부르는 게 편합니다. 그것이 Static Method입니다.

2. Instance vs Static ✍️

CLASS zcl_calc DEFINITION PUBLIC.
  PUBLIC SECTION.
    METHODS add IMPORTING iv_a TYPE i iv_b TYPE i
                RETURNING VALUE(rv) TYPE i.          "인스턴스 메서드
    CLASS-METHODS add_static IMPORTING iv_a TYPE i iv_b TYPE i
                RETURNING VALUE(rv) TYPE i.          "스태틱 메서드
ENDCLASS.
" 인스턴스: 객체를 만들어 호출 (->)
DATA(lo) = NEW zcl_calc( ).
DATA(r1) = lo->add( iv_a = 1 iv_b = 2 ).

" 스태틱: 클래스 이름으로 바로 호출 (=>)
DATA(r2) = zcl_calc=>add_static( iv_a = 1 iv_b = 2 ).
  • Instance Method: METHODS로 선언, 객체->메서드로 호출. 객체의 상태(속성)를 다룹니다.
  • Static Method: CLASS-METHODS로 선언, 클래스=>메서드로 호출. 특정 객체와 무관한 기능입니다.

3. 화살표가 다르다: -> vs => ➡️

💡

기억법

  • 객체 -> 메서드 : 실물(객체)에게 시킴(인스턴스).
  • 클래스 => 메서드 : 설계도(클래스)에게 바로 시킴(스태틱).

속성도 마찬가지로 CLASS-DATA로 선언한 것은 모든 객체가 공유하는 스태틱 속성입니다.

4. 언제 무엇을? 🔍

  • ✅ Instance: 객체마다 다른 상태(이 항공편의 요금 등)를 다룰 때.
  • ✅ Static: 상태와 무관한 유틸리티(계산·변환·팩토리)나 클래스 전체가 공유하는 값일 때.
  • ❌ 오류: Static Method 안에서 인스턴스 속성(객체별 데이터)에 접근하려 함 → 불가. Static은 "특정 객체"가 없으니까요.

5. 실무에서 조심할 점 🚨

⚠️

Static을 남용하면 OO의 장점이 사라집니다

모든 걸 Static으로 만들면, 결국 옛날 Function Module 묶음과 다를 게 없어집니다. Static은 정말 상태가 필요 없는 유틸리티에만 쓰세요. 객체의 상태를 다루고 다형성·상속의 이점을 누리려면 Instance가 기본입니다. "이 기능이 특정 객체의 상태에 의존하는가?"가 판단 기준입니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Instance Method: 객체를 만들어 객체->로 호출, 객체 상태를 다룸.
  • Static Method: 클래스=>로 바로 호출, 객체와 무관한 기능.
  • 선언: METHODS vs CLASS-METHODS, 호출: -> vs =>.
  • Static 남용은 OO 장점을 없애니 유틸리티에만 절제해서.
