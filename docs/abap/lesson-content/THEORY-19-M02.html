학습 목표

SALV의 외형을 다루는 get_layout( )과, 사용자가 컬럼 배치를 저장·재사용하는 Variant 저장을 배웁니다. THEORY-15의 Grid ALV Variant와 같은 개념을 SALV 방식으로 익힙니다.

1. 지난 시간 연결: 사용자 레이아웃을 SALV에서도 💾

THEORY-15에서 Grid ALV의 Layout Variant(컬럼 배치 저장)를 배웠습니다. SALV에도 같은 기능이 있는데, 객체 메서드로 더 간단하게 켭니다. 그게 get_layout( )입니다.

DATA(lo_layout) = lo_alv->get_layout( ).

" 변형(레이아웃) 저장 키: 보통 프로그램 ID 기준
DATA(ls_key) = VALUE salv_s_layout_key( report = sy-repid ).
lo_layout->set_key( ls_key ).

" 저장 허용 범위 (THEORY-15의 I_SAVE와 동일 개념)
lo_layout->set_save_restriction(
  if_salv_c_layout=>restrict_none ).   "사용자/공용 모두 허용
  • set_key( ): "어느 프로그램의 레이아웃인지" 구분하는 키.
  • set_save_restriction( ): 저장 범위(없음/사용자만/공용만). Grid ALV의 I_SAVE에 대응.
💡

같은 개념, 다른 포장

Grid ALV는 DISVARIANT 구조 + I_SAVE 문자였고, SALV는 layout_key + restriction 상수예요. 모양만 다를 뿐 "사용자가 레이아웃을 저장해 재사용한다"는 본질은 똑같습니다.

3. 사용자 입장의 흐름 🔄

  • ① 표에서 컬럼 순서·정렬을 바꾼다.
  • ② 툴바의 레이아웃 저장(앞 Lesson의 Functions가 켜져 있어야 버튼이 보임)으로 이름 붙여 저장.
  • ③ 다음에 같은 이름으로 불러오면 그 배치가 복원됨.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: set_key + 저장 허용 → 사용자가 레이아웃을 저장·재사용.
  • ❌ 오류 1: 저장 제한을 가장 엄격하게 두고 "왜 저장이 안 되지?" → 허용 범위 확인.
  • ❌ 오류 2: Functions(툴바)를 안 켜서 레이아웃 저장 버튼 자체가 안 보임(앞 Lesson과 연결).

5. 실무에서 조심할 점 🚨

⚠️

공용 레이아웃은 모두에게 영향을 줍니다

THEORY-15에서와 같이, 공용(전체 공유) 레이아웃을 허용하면 한 사람의 변경이 모든 사용자에게 적용됩니다. 운영 표준으로 합의된 게 아니라면, 사용자별 저장 위주로 시작하는 것이 안전합니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • get_layout( )으로 SALV의 외형·Variant 저장을 제어합니다.
  • set_key(프로그램 구분) + set_save_restriction(저장 범위)을 설정합니다.
  • Grid ALV의 DISVARIANT/I_SAVE와 같은 개념의 다른 포장입니다.
  • 레이아웃 저장 버튼은 Functions(툴바)가 켜져 있어야 보입니다.
