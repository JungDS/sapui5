학습 목표

지난 Lesson에서 SELECT의 기본 구조를 봤습니다. 이번에는 WHERE 조건으로 조회 범위를 줄이고, Host Variable @를 사용해 PARAMETERS 입력값을 SQL 조건에 넣는 방법을 배웁니다.

1. 데이터베이스에서 필요한 것만 가져오기 🧭

Lesson 1의 예제는 테이블에서 국가 코드와 국가명을 읽어왔습니다. 하지만 실무에서는 “전체 다 가져와서 ABAP에서 고르자”보다, 데이터베이스에 요청할 때부터 조건을 걸어 필요한 데이터만 가져오는 것이 중요합니다.

WHERE는 조회 조건입니다. 사용자가 입력한 국가 코드만 조회하거나, 현재 로그온 언어의 텍스트만 조회하는 식으로 범위를 줄일 수 있습니다.

WHERE는 데이터베이스에 보내는 “필터 조건”입니다.

2. PARAMETERS 값을 WHERE에 넣기 🎛️

ABAP

PARAMETERS p_land1 TYPE t005t-land1 DEFAULT 'KR'.

SELECT FROM t005t
  FIELDS land1, landx
  WHERE spras = @sy-langu
    AND land1 = @p_land1
  INTO TABLE @DATA(lt_countries).

이 코드는 사용자가 입력한 국가 코드 p_land1와 현재 로그온 언어 sy-langu에 맞는 국가 텍스트만 조회합니다.

  • WHERE spras = @sy-langu: 현재 언어 텍스트만 가져옵니다.
  • AND land1 = @p_land1: 사용자가 입력한 국가 코드만 가져옵니다.
  • @: SQL 안에서 ABAP 변수라는 것을 표시합니다.

3. Host Variable @는 왜 필요할까? 🔌

Host Variable @는 ABAP SQL 안에서 ABAP 프로그램의 변수 값을 사용할 때 붙이는 표시입니다. SQL의 필드 이름과 ABAP 변수 이름을 구분해주는 역할을 합니다.

예를 들어 land1은 데이터베이스 테이블 필드이고, p_land1은 ABAP 프로그램의 Selection Screen 입력 변수입니다. @p_land1이라고 쓰면 “이건 DB 필드가 아니라 ABAP 변수 값이야”라고 알려주는 셈입니다.

💡

@는 출입증 같은 표시

SQL 영역 안으로 ABAP 변수가 들어갈 때 “저는 ABAP 쪽 변수입니다”라는 출입증을 붙이는 느낌입니다.

REPORT zsql_where_host.

PARAMETERS p_land1 TYPE t005t-land1 DEFAULT 'KR'.

SELECT FROM t005t
  FIELDS land1, landx
  WHERE spras = @sy-langu
    AND land1 = @p_land1
  INTO TABLE @DATA(lt_countries).

IF lt_countries IS INITIAL.
  WRITE: / '조회 결과가 없습니다.'.
ELSE.
  LOOP AT lt_countries INTO DATA(ls_country).
    WRITE: / ls_country-land1, ls_country-landx.
  ENDLOOP.
ENDIF.

실행할 때 p_land1 값을 KR, US, DE처럼 바꿔보세요. 시스템 데이터와 언어 설정에 따라 결과가 달라질 수 있습니다.

필터링은 DB 쪽에서 끝나고, 마지막 1줄만 Application Server로 배송되어 lt_countries에 담깁니다. @는 “이건 DB 칸이 아니라 내 프로그램 변수예요”라고 알려주는 표식입니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 입력값과 언어 조건에 맞는 줄이 조회되어 Internal Table에 담깁니다.
  • ✅ 빈 결과: 입력한 국가 코드가 없거나 해당 언어 텍스트가 없으면 결과가 비어 있을 수 있습니다.
  • ❌ @ 누락: 최신 ABAP SQL 문맥에서 ABAP 변수 앞의 @를 빼면 문법 오류가 날 수 있습니다.
  • ❌ 조건 누락: 언어 조건 없이 텍스트 테이블을 조회하면 여러 언어의 텍스트가 섞일 수 있습니다.
  • ❌ 입력 검증 없음: 사용자가 빈 값이나 예상 밖 값을 넣으면 조회 결과가 의도와 다를 수 있습니다.

미니 실습으로 WHERE spras = @sy-langu 줄을 주석 처리해보세요. 같은 국가 코드라도 여러 언어 줄이 나올 수 있음을 확인하면 WHERE의 힘이 보입니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

조건은 성능이자 의미입니다

WHERE 조건은 단순히 속도를 빠르게 하기 위한 장치가 아닙니다. “어떤 업무 범위의 데이터를 볼 것인가”를 정하는 의미의 경계이기도 합니다. 조건이 틀리면 빠르게 틀린 데이터를 가져올 수 있습니다.

실제 Report에서는 PARAMETERS에 DEFAULT를 넣는 것만으로 충분하지 않을 수 있습니다. 필수 입력, 값 도움말, 권한 검사는 별도 흐름에서 함께 설계해야 합니다.

7. 미니 실습: 필터 안경 갈아끼우기 🧪

✍️

실습 과제

  1. 예제 zsql_where_host를 실행해 KR 조회 결과를 확인합니다.
  2. p_land1에 US, DE, 존재하지 않는 코드(XX)를 차례로 넣어 결과 차이를 기록합니다.
  3. WHERE spras = @sy-langu 줄을 주석 처리하고, 같은 국가가 여러 언어 줄로 나오는 것을 확인합니다.
  4. 일부러 @를 하나 빼고 활성화해 어떤 문법 메시지가 나오는지 확인합니다.

완료 조건: 조건을 더할수록 결과 줄이 줄어드는 위 3단계 그림을 자신의 실행 결과로 재현하면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. 최신 ABAP SQL에서 WHERE 절에 프로그램 변수를 쓸 때 @를 붙이는 이유는 무엇인가요?
  2. WHERE 조건 필터링은 Application Server와 데이터베이스 중 어디에서 일어나는 것이 좋은가요?
  3. 조회 결과가 0건이면 프로그램 오류일까요?
정답/해설 보기
  1. DB 테이블의 컬럼 이름과 프로그램 변수(Host Variable)를 명확히 구분하기 위해서입니다. 최신(Strict Mode) 문맥에서는 생략하면 문법 오류입니다.
  2. 데이터베이스입니다. DB에서 거른 뒤 필요한 줄만 전송해야 네트워크와 메모리 비용이 줄어듭니다. 다 가져와서 ABAP에서 거르는 방식은 낭비입니다.
  3. 아니요. 조건에 맞는 데이터가 없으면 빈 결과가 돌아올 뿐이며, 빈 결과 안내는 프로그램이 설계해야 할 정상 흐름입니다.

10. 한눈에 정리 🏁

📝

WHERE와 @ 핵심

  • WHERE는 데이터베이스 조회 범위를 줄이는 조건입니다.
  • Host Variable @는 SQL 안에서 ABAP 변수를 사용할 때 붙입니다.
  • PARAMETERS 입력값을 WHERE 조건에 연결하면 사용자 입력 기반 조회가 됩니다.
  • 텍스트 테이블은 언어 조건을 함께 봐야 결과가 깔끔합니다.
  • 조건은 성능뿐 아니라 업무 의미를 결정합니다.
