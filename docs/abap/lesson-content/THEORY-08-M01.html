학습 목표

Chapter 6~07에서 Internal Table을 만들고 가공했습니다. 이번 Chapter에서는 그 데이터를 화면 표로 보기 좋게 보여주는 SALV와 CL_SALV_TABLE의 목적을 이해합니다. 단순 List Output과 무엇이 다른지도 감을 잡습니다.

1. 지난 Chapter 연결: 표를 만들었으면 보여줘야 한다 🧭

지금까지 우리는 Internal Table에 여러 줄 데이터를 담고, 수정하고, 삭제하고, 정렬하고, 검색했습니다. 그런데 프로그램이 아무리 데이터를 잘 가공해도 사용자가 결과를 보기 어렵다면 실무에서는 반쪽짜리입니다.

WRITE로도 출력할 수 있지만, 행과 열이 많은 데이터는 단순 줄 출력만으로 보기 불편합니다. 사용자는 보통 열 제목, 행 구분, 정렬 버튼, 엑셀 다운로드 같은 표 형태의 결과 화면을 기대합니다.

SALV는 Internal Table 데이터를 “표 화면”으로 빠르게 보여주는 간단한 ALV 도구입니다.

2. SALV는 무엇인가? 📊

SALV는 Simple ALV 계열로, ABAP 프로그램에서 Internal Table 데이터를 표 형태로 표시할 때 많이 쓰는 방식입니다. 복잡한 편집 화면을 만드는 도구라기보다, 조회 결과를 빠르게 보여주는 데 초점이 있습니다.

  • 데이터 원천: ABAP 프로그램 안의 Internal Table
  • 표시 결과: 행과 열이 있는 ALV 화면
  • 장점: 짧은 코드로 기본 표 화면을 만들 수 있습니다.
  • 주의: 기본 SALV는 데이터 편집용 Grid가 아니라 조회용 표시 도구에 가깝습니다.

처음에는 “Internal Table을 사용자 친화적인 표로 보여주는 포장지”라고 생각하면 됩니다.

3. CL_SALV_TABLE은 SALV 표 객체를 만드는 Class 🏛️

CL_SALV_TABLE은 SALV 표 화면을 만들고 표시할 때 사용하는 대표 Class입니다. Chapter 5에서 Class와 Method를 맛봤기 때문에, 이제 이 문장이 조금 덜 낯설 것입니다.

ABAP
1 
DATA lo_alv TYPE REF TO cl_salv_table.

위 코드는 SALV 표 객체를 가리킬 참조 변수 lo_alv를 선언합니다. 실제 객체 생성은 다음 Lesson에서 factory Method로 진행합니다.

💡

왜 Class가 나올까?

SALV는 단순 문법 하나가 아니라 화면 표시 기능을 가진 객체입니다. 그래서 Class와 Method 호출 형태로 사용합니다.

4. WRITE 출력과 SALV 출력의 느낌 차이 ✍️

ABAP
1
2
3 
LOOP AT lt_students INTO ls_student.
  WRITE: / ls_student-id, ls_student-name, ls_student-score.
ENDLOOP.

위 코드는 List Output으로 한 줄씩 값을 찍습니다. 간단하지만 열 정렬, 사용자 기능, 표 형태 시각화가 부족합니다.

ABAP
1
2
3
4
5 
cl_salv_table=>factory(
  IMPORTING r_salv_table = lo_alv
  CHANGING  t_table      = lt_students ).

lo_alv->display( ).

SALV는 Internal Table 전체를 표 화면으로 넘기고, SALV 객체가 표시를 담당합니다. 지금은 문법을 외우기보다 “Internal Table을 SALV에게 맡기면 표 화면이 나온다”는 흐름을 잡으세요.

같은 데이터, 다른 화면 — WRITE vs SALV

WRITE (List Output)
화면 모양고정폭 글자를 한 줄씩 찍은 목록
코드 부담줄/칸 배치를 개발자가 직접 관리
사용자 기능정렬·필터·엑셀 없음
어울림학습, 간단 로그/확인용
SALV (표 화면)
화면 모양열이 정렬된 격자무늬 표
코드 부담Internal Table을 넘기면 표는 SALV가 책임
사용자 기능정렬·필터 등 표준 기능 연결 가능
어울림업무 조회 리포트

데이터(lt_students)는 같습니다. 누가 화면 표시를 책임지느냐 — 개발자의 WRITE 반복문이냐, SALV 객체냐 — 가 달라질 뿐입니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: Internal Table에 표시할 데이터가 있고, SALV 객체가 정상 생성되면 표 화면이 표시됩니다.
  • ✅ 빈 데이터: Internal Table이 비어 있어도 타입에 필드가 있으면 빈 표 형태로 표시될 수 있습니다.
  • ❌ 데이터 준비 누락: Internal Table에 줄을 넣지 않고 표시하면 사용자는 “결과가 없다”고 느낍니다.
  • ❌ 예외 처리 누락: SALV 객체 생성 중 문제가 생길 수 있으므로 예외 흐름을 확인해야 합니다.

미니 실습으로 기존 학생 Internal Table 예제를 떠올리고, WRITE 출력과 SALV 출력이 어떤 UX 차이를 만들지 말로 비교해보세요.

6. 실무에서 조심해야 할 점 🚨

⚠️

SALV는 만능 화면 도구가 아닙니다

SALV는 조회 결과를 빠르게 보여주기 좋지만, 복잡한 편집, 셀 색상/스타일, 이벤트 처리, Layout/Variant 심화는 별도 주제로 다뤄야 합니다. 이번 Chapter에서는 “보여주기 1차”에 집중합니다.

고객사마다 SALV, Grid ALV, 커스텀 화면을 선택하는 기준이 다를 수 있습니다. 표준 동작과 프로젝트 관행을 구분해서 읽는 습관이 필요합니다.

7. 미니 실습: 두 출력 방식 비교 체험 🧪

✍️

실습 과제

  1. Chapter 6의 학생 Internal Table 예제를 가져와 WRITE LOOP로 출력해봅니다.
  2. 같은 테이블을 cl_salv_table=>factory( ... ) + display( )로 표 화면에 띄워봅니다.
  3. 두 화면을 캡처하거나 메모해, 열 정렬·머리글·전체 인상 차이를 3가지 적어봅니다.
  4. “화면 표시 책임이 누구에게 있는가?”를 기준으로 두 방식을 한 문장씩 정리합니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. SALV로 전체 화면 표를 띄우려면 Dynpro 화면과 Custom Container를 먼저 만들어야 할까요?
  2. SALV는 사용자가 셀을 직접 수정하는 편집 화면에도 가장 적합한 도구일까요?
  3. WRITE 출력과 비교했을 때 SALV가 개발자 대신 책임져주는 것은 무엇인가요?
정답/해설 보기
  1. 아니요. cl_salv_table=>factory를 호출하면 화면 설계 없이도 전체 화면 표가 만들어집니다. 화면+Container가 필수인 것은 Grid ALV(CL_GUI_ALV_GRID) 방식입니다.
  2. 아니요. SALV는 조회(Read-only) 표시에 최적화된 도구입니다. 셀 편집이 중심인 화면은 Grid ALV 등 다른 선택이 표준입니다.
  3. 표 화면의 구성과 표시입니다. 열 배치, 머리글, 격자 표시를 SALV 객체가 맡고, 개발자는 데이터(Internal Table)만 준비합니다.

10. 한눈에 정리 🏁

📝

SALV 첫 감각

  • SALV는 Internal Table 데이터를 표 형태로 보여주는 간단한 ALV 도구입니다.
  • CL_SALV_TABLE은 SALV 표 화면을 만들고 표시하는 대표 Class입니다.
  • List Output은 WRITE 기반 줄 출력이고, SALV는 표 화면에 가깝습니다.
  • SALV는 조회용 표시에는 편하지만 복잡한 편집 화면의 만능 도구는 아닙니다.
  • 이번 Chapter는 FACTORY로 만들고 DISPLAY로 보여주는 1차 범위에 집중합니다.
