학습 목표

화면마다 붙는 고유 번호인 Screen Number와, 화면 레이아웃을 마우스로 그리는 Screen Painter(SE51)를 배웁니다. 화면 한 장이 어떻게 만들어지는지 흐름을 잡습니다.

1. 지난 시간 연결: 화면마다 이름표가 필요하다 🔢

Module Pool 안에는 화면이 여러 장 있을 수 있습니다. 시작 화면, 상세 화면, 팝업 화면처럼요. 이 화면들을 구분하려면 고유 번호가 필요합니다. 그것이 Screen Number입니다.

보통 0100, 0200처럼 네 자리 숫자를 씁니다. 프로그램은 "이제 0100 화면을 띄워라"라고 번호로 화면을 호출합니다.

ABAP
1
2 
" 프로그램에서 화면 호출

CALL SCREEN 0100.

2. Screen Painter로 레이아웃 그리기 🎨

Screen Painter(트랜잭션 SE51, 또는 SE80 안에서)는 화면을 마우스로 그리는 도구입니다. 입력 칸, 라벨, 버튼을 끌어다 배치합니다.

💡

화면 한 장의 3요소

  • Attributes(속성): 화면 번호, 다음 화면 번호, 화면 타입(일반/팝업 등).
  • Layout(레이아웃): 입력 칸·버튼 등 요소 배치(Screen Painter로 그림).
  • Flow Logic(흐름 로직): PBO/PAI 모듈을 부르는 짧은 코드.

3. Flow Logic이 화면과 코드를 잇는다 ✍️

화면을 그리면 자동으로 짧은 Flow Logic이 생깁니다. 이것이 "화면을 보여주기 전에 무슨 모듈을, 입력 후에 무슨 모듈을 부를지" 정합니다.

ABAP
1
2
3
4
5 
PROCESS BEFORE OUTPUT.
  MODULE status_0100.       "PBO: 화면 꾸미기


PROCESS AFTER INPUT.
  MODULE user_command_0100. "PAI: 버튼 처리

여기서 MODULE status_0100, user_command_0100 같은 실제 ABAP 코드는 Module Pool 프로그램 본문에 작성합니다. Flow Logic은 "언제 무엇을 부를지"의 다리 역할만 합니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 화면 번호 → 레이아웃 → Flow Logic → 모듈 코드가 모두 짝이 맞으면 화면이 떠서 동작합니다.
  • ❌ 오류 1: Flow Logic에 적은 모듈(status_0100)을 본문에 안 만들면 활성화 오류.
  • ❌ 오류 2: 다음 화면 번호 설정을 잘못해 엉뚱한 화면으로 넘어가거나 무한 반복.

5. 실무에서 조심할 점 🚨

⚠️

화면 번호 규칙을 팀과 맞추세요

화면 번호는 자유지만, 보통 0100(메인), 0200(상세)처럼 규칙을 둡니다. 번호를 중구난방으로 쓰면 나중에 화면 흐름을 추적하기 어렵습니다. 또 화면·Flow Logic·모듈 코드가 흩어져 있으니, 처음 배울 때는 "이 셋이 한 세트"라는 점을 의식하며 만드는 게 좋습니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • 화면마다 Screen Number(예: 0100)가 붙고, CALL SCREEN으로 호출합니다.
  • Screen Painter(SE51)로 레이아웃을 마우스로 그립니다.
  • 화면 = 속성 + 레이아웃 + Flow Logic 세 요소로 구성됩니다.
  • Flow Logic은 PBO/PAI 모듈을 부르는 다리이고, 실제 코드는 본문에 작성합니다.
