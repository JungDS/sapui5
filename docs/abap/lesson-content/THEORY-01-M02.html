학습 목표

데이터의 가장 작은 부품인 Domain을 만들어 봅니다. 데이터 타입과 길이(Length), 그리고 입력값을 제한하는 고정값(Fixed Value)이 무엇인지, 왜 따로 떼어 관리하는지 익힙니다.

1. Domain은 데이터의 "재질" 명세서 🧱

앞 Lesson에서 SAP는 부품(Repository Object)을 하나씩 조립해 테이블을 만든다고 했습니다. 그 부품 중 가장 밑바닥에 있는 것이 바로 Domain(도메인)입니다.

Domain은 "이 값은 어떤 재질로 되어 있는가"만 정의합니다. 즉 기술적인 형태만 책임집니다.

  • 데이터 타입(Data Type): 문자인지(CHAR), 숫자인지(NUMC, INT4), 날짜인지(DATS) 등
  • 길이(Length): 몇 자리까지 담을 수 있는지 (예: 항공사 코드 CHAR 3)
  • 소수 자릿수(Decimals): 금액·수량이라면 소수점 이하 자리
Domain은 "이 값은 3자리 문자다"까지만 말합니다. 이게 '항공사 코드'인지 '국가 코드'인지 같은 의미(뜻)는 다음 Lesson의 Data Element가 책임집니다.

2. 최소 예제: 항공사 코드 Domain 만들기 ✍️

이클립스 기반 ADT(또는 SE11)에서 ZCARRID라는 Domain을 만든다고 생각해 봅시다.

💡

설정값은 단 세 줄이면 충분합니다

Data Type: CHAR · Length: 3 · (필요 시) Output Length: 3
이것만 채우고 활성화(Activate)하면, 시스템 어디서든 "3자리짜리 항공사 코드 재질"을 재사용할 수 있습니다.

같은 재질을 100개 필드에서 쓰더라도 Domain은 딱 하나만 있으면 됩니다. 나중에 "코드를 3자리에서 4자리로 늘리자"가 되면, 이 Domain 하나만 고치면 그것을 쓰는 모든 곳에 한 번에 반영됩니다. 이것이 DDIC가 추구하는 단일 진실 공급원(SSOT)의 힘입니다.

3. 고정값(Fixed Value)으로 입력을 단속하기 🚦

Domain에는 고정값(Fixed Value)이라는 강력한 기능이 있습니다. 들어올 수 있는 값의 목록을 미리 못 박아 두는 것입니다.

  • ✅ 정상 흐름: 성별 Domain에 M(남), F(여)만 고정값으로 등록 ➔ 프로그램이나 입력 화면에서 자동으로 이 둘만 허용 ➔ F4(입력 도움말) 목록에도 자동 표시
  • ❌ 오류 흐름: 사용자가 X를 입력 ➔ 시스템이 "허용되지 않은 값"이라며 거부
고정값은 "값의 종류가 적고 거의 안 변하는 것"(성별, 상태 플래그 Y/N 등)에 잘 맞습니다. 값이 많거나 자주 바뀌면(국가, 통화처럼) 고정값 대신 Value Table / Check Table을 쓰는데, 이건 THEORY-04에서 다룹니다.

4. 실무에서 주의할 점 🚨

⚠️

표준 Domain을 먼저 찾아보세요

금액(WERTV8), 수량(MENG13), 통화 코드(WAERS)처럼 SAP가 이미 완벽하게 만들어 둔 표준 Domain이 수두룩합니다. 나만의 ZWAERS를 새로 만들기 전에 표준이 있는지 검색하는 것이 기본기입니다.

또한 운영 중인 시스템에서 이미 데이터가 쌓인 Domain의 길이를 줄이거나 타입을 바꾸면 기존 데이터가 잘리거나 변환 오류가 날 수 있습니다. 길이를 늘리는 것은 비교적 안전하지만, 줄이거나 타입을 바꾸는 변경은 항상 조심해야 합니다.

5. 다음 단계로 🚀

Domain으로 데이터의 "재질(기술적 형태)"을 정의했습니다. 하지만 재질만으로는 이 값이 무슨 뜻인지, 화면에 어떤 이름표를 달지 알 수 없습니다.

그래서 다음 Lesson 'Data Element 기본 설계'에서는 Domain 위에 의미(Semantic)와 필드 라벨을 입혀, 실제로 테이블·화면에서 쓸 수 있는 부품으로 완성하는 과정을 살펴봅니다.
