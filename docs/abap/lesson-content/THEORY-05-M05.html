학습 목표

지난 Lesson에서 프로그램 안의 Local Class를 만들었습니다. 이번에는 시스템 전체에서 재사용할 수 있는 Global Class를 호출하는 기초를 배웁니다. SE24, Static Method, Instance Method의 차이를 처음 보는 사람 기준으로 정리합니다.

1. 지난 시간 연결: 내 프로그램 안 Class에서 공용 Class로 🌐

Local Class는 현재 프로그램 안에서만 쓰기 좋습니다. 하지만 여러 프로그램이 같은 기능을 써야 한다면 어떻게 할까요? 매번 Local Class를 복사하면 유지보수가 힘들어집니다.

이럴 때 Global Class를 사용합니다. Global Class는 Repository Object로 관리되며, 여러 프로그램에서 이름으로 호출할 수 있습니다. 전통적으로 SAP GUI에서는 SE24에서 Class Builder를 열어 확인하고 관리할 수 있습니다. ADT에서도 Class를 열고 편집할 수 있습니다.

Global Class는 시스템 공용 도구 상자이고, Local Class는 현재 프로그램 안의 개인 도구 상자에 가깝습니다.

2. Static Method: 객체 없이 바로 호출하기 ⚡

Static Method는 객체를 만들지 않고 Class 이름으로 바로 호출할 수 있는 Method입니다. 보통 상태를 오래 들고 있지 않는 계산, 변환, 유틸리티 기능에 어울립니다.

ABAP
1
2
3
4
5
6
7 
DATA gv_text TYPE string.

gv_text = zcl_demo_text=>build_greeting(
  iv_name = 'ABAP'
).

WRITE gv_text.

위 예제는 ZCL_DEMO_TEXT라는 커스텀 Global Class에 BUILD_GREETING Static Method가 있다고 가정한 코드입니다. => 기호는 Static Method나 Static Attribute에 접근할 때 사용합니다.

💡

Static은 “Class 이름으로 바로”

zcl_demo_text=>build_greeting( )처럼 Class 이름 뒤에 =>가 보이면 Static 호출이라고 먼저 감을 잡으면 됩니다.

3. Instance Method: 객체를 만들고 호출하기 🧍

Instance Method는 객체를 먼저 만든 뒤 호출하는 Method입니다. 객체마다 상태를 가질 수 있거나, 생성 과정을 거쳐야 하는 기능에 어울립니다.

ABAP
1
2
3
4
5
6
7 
DATA lo_checker TYPE REF TO zcl_demo_checker.

lo_checker = NEW zcl_demo_checker( ).

lo_checker->check_input(
  iv_value = 'KE'
).

여기서는 NEW zcl_demo_checker( )로 객체를 만들고, lo_checker->check_input( )으로 Instance Method를 호출합니다. -> 기호는 객체 참조를 통해 Method를 호출할 때 사용합니다.

Static은 Class 이름에 붙는 =>, Instance는 객체 변수에 붙는 ->로 첫 구분을 해보세요.

4. SE24에서 무엇을 확인할까? 🔎

SE24는 SAP GUI에서 Class Builder를 여는 전통적인 트랜잭션입니다. Global Class를 볼 때는 최소한 아래를 확인하면 좋습니다.

  • Method 이름: 어떤 기능을 제공하는지 확인합니다.
  • Static 여부: Class 이름으로 바로 부르는지, 객체 생성이 필요한지 확인합니다.
  • 파라미터: Importing, Exporting, Changing 값을 확인합니다.
  • 예외: 실패 상황을 어떻게 알려주는지 확인합니다.
  • 문서: 사용 목적과 주의사항을 확인합니다.

ADT를 사용하는 환경이라면 Class를 열어 Method 시그니처와 구현을 더 편하게 탐색할 수 있습니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ Static 정상 흐름: Static Method는 클래스명=>메서드명( )으로 호출합니다.
  • ✅ Instance 정상 흐름: 객체를 생성한 뒤 객체참조->메서드명( )으로 호출합니다.
  • ❌ 호출 기호 오류: Instance Method를 =>로 호출하거나 Static Method를 객체 없이 잘못 호출하면 오류가 납니다.
  • ❌ 객체 생성 누락: Instance Method는 참조 변수가 비어 있으면 호출할 수 없습니다.
  • ❌ 파라미터 누락: Method가 요구하는 필수 파라미터를 빠뜨리면 문법 오류가 납니다.

미니 실습에서는 SE24나 ADT에서 간단한 Global Class의 Method 목록을 열어보고, Static Method인지 Instance Method인지 먼저 구분해보세요. 코드를 치기 전 구조를 읽는 연습이 중요합니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

표준 Class도 릴리스 상태와 사용 목적을 확인하세요

표준 Global Class가 보인다고 해서 모든 프로젝트에서 자유롭게 써도 된다는 뜻은 아닙니다. 특히 ABAP Cloud나 Clean Core 기준에서는 Released API인지 확인해야 할 수 있습니다. 지금은 호출 문법을 배우는 단계지만, 실무에서는 사용 가능성과 안정성도 함께 봐야 합니다.

또한 Global Class는 재사용 범위가 넓기 때문에 이름, 패키지, 공개 Method 설계가 중요합니다. 작은 실험 코드를 무심코 Global Class로 만들면 시스템 전체에 오래 남는 부채가 될 수 있습니다.
