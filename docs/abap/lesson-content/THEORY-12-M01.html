학습 목표

코드 안에서 그때그때 쓰던 JOIN을, DDIC에 미리 만들어 두고 재사용하는 Database View를 배웁니다. 코드로 쓰는 Open SQL JOIN과 무엇이 같고 다른지 비교하는 것이 목표입니다.

1. 지난 시간 연결: 같은 JOIN을 매번 또 쓰는 게 번거롭다 🔁

앞 Chapter에서 우리는 SPFLI와 SCARR를 INNER JOIN으로 연결해 읽었습니다. 그런데 이 "항공편 + 항공사 이름" 조합을 여러 프로그램에서 똑같이 쓴다면, 매번 같은 JOIN 코드를 반복해서 적어야 합니다.

반복은 곧 실수와 유지보수 부담입니다. 그래서 SAP는 자주 쓰는 JOIN을 DDIC에 객체로 미리 정의해 두고, 마치 테이블 하나처럼 꺼내 쓰게 해줍니다. 이것이 Database View입니다.

2. Database View는 "미리 짜둔 JOIN" 🧩

DDIC View 중 가장 기본인 Database View는, 여러 테이블을 INNER JOIN으로 연결한 결과를 하나의 가상 테이블처럼 보여줍니다. 실제 데이터를 따로 저장하지는 않고, 조회할 때 원본 테이블에서 합쳐 보여줍니다.

💡

일상 비유: 자주 쓰는 레시피를 카드로 만들어 두기

매번 재료(테이블)를 어떻게 섞을지 떠올리는 대신, "항공편+항공사 카드"를 한 장 만들어 두는 거예요. 다음부터는 그 카드만 꺼내면 합쳐진 결과가 바로 나옵니다.

한 번 만들어 두면 ABAP에서는 SELECT ... FROM zv_flight_carr처럼 테이블 이름 자리에 View 이름을 넣어 쓰면 끝입니다.

3. Open SQL JOIN과 비교 ✍️

  • Open SQL JOIN: 코드 안에서 그때그때 정의. 상황마다 자유롭게 바꿀 수 있음(유연함).
  • Database View: DDIC에 한 번 정의해 재사용. 여러 프로그램이 같은 정의를 공유(일관성).
" View를 테이블처럼 사용
SELECT carrid, connid, carrname
  FROM zv_flight_carr      "← 미리 정의해 둔 Database View
  INTO TABLE @DATA(lt).
"이 JOIN을 여러 곳에서 똑같이 쓴다" → Database View가 어울립니다. "이번만, 이 화면에서만 특수하게 합친다" → 코드 JOIN이 편합니다.

4. 정상 흐름과 한계 🔍

  • ✅ 정상: 연결 테이블들이 Foreign Key 등으로 잘 묶여 있으면, View가 INNER JOIN 결과를 안정적으로 보여줍니다.
  • ❌ 한계 1 — 읽기 전용: Database View로는 데이터를 수정/저장할 수 없습니다. 조회 전용입니다.
  • ❌ 한계 2 — INNER JOIN만: Classic Database View는 기본적으로 INNER 성격이라, 짝 없는 행을 살리는 OUTER 같은 유연함은 떨어집니다.

5. 실무에서 조심할 점 🚨

⚠️

요즘은 CDS View가 대세입니다

Classic Database View는 오래된 시스템에서 여전히 보이지만, 최신 SAP(S/4HANA·ABAP Cloud)에서는 더 강력한 CDS View Entity로 대체되는 추세입니다. 지금은 "JOIN을 DDIC에 미리 정의해 재사용한다"는 개념을 잡는 것이 핵심이고, 이 개념은 나중에 CDS를 배울 때 그대로 이어집니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Database View는 여러 테이블의 JOIN을 DDIC에 미리 정의해 테이블처럼 쓰는 객체입니다.
  • 데이터를 따로 저장하지 않고, 조회 시 원본에서 합쳐 보여줍니다(읽기 전용).
  • 여러 곳에서 같은 JOIN을 쓰면 View가, 일회성·특수 결합이면 코드 JOIN이 어울립니다.
  • 최신 환경에서는 CDS View로 진화하지만, 핵심 개념은 동일합니다.

Database View가 "여러 테이블 합치기"였다면, 다음 Lesson Projection View 개념과 한계에서는 "한 테이블에서 필요한 칸만 골라 보여주는" 더 단순한 View를 배웁니다.
