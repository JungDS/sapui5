학습 목표

사용자가 입력 칸에서 F4를 눌렀을 때 뜨는 입력 도움말의 재료가 되는 Help View를 배웁니다. Search Help와 어떻게 연결되는지 흐름을 잡는 것이 목표입니다.

1. 지난 시간 연결: 입력 도움말도 데이터가 필요하다 🔎

THEORY-04에서 우리는 Search Help로 F4 입력 도움말을 만들 수 있다고 배웠습니다. 그런데 도움말에 보여줄 후보 목록이 여러 테이블에 흩어져 있다면 어떻게 할까요?

예를 들어 "고객 코드"를 고를 때, 코드만이 아니라 옆에 고객 이름·도시까지 같이 보여주면 훨씬 친절합니다. 이 정보들이 여러 테이블에 있다면, 그것을 합쳐주는 특별한 View가 필요합니다. 그것이 Help View입니다.

2. Help View는 "F4 목록을 위한 합치기" 🧷

Help View는 입력 도움말(F4)에 보여줄 후보 목록을 만들기 위해 여러 테이블을 연결하는 DDIC View입니다. 핵심 테이블을 중심으로 관련 텍스트 테이블 등을 묶어, 코드와 설명을 한 화면에 보여줄 수 있게 합니다.

💡

일상 비유: 연락처 검색창

전화번호만 저장돼 있어도, 검색창에는 이름·회사·사진이 같이 떠야 누구인지 알아보죠. Help View는 그렇게 "고를 때 보기 좋은 목록"을 만들기 위해 정보를 합쳐주는 역할이에요.

3. F4 → Search Help → Help View 흐름 ✍️

전체 그림을 한 줄로 이어보면 이렇습니다.

  • ① 사용자가 입력 칸에서 F4를 누른다.
  • ② 그 칸에 연결된 Search Help가 작동한다.
  • ③ Search Help는 후보 목록의 출처로 테이블이나 Help View를 사용한다.
  • ④ 합쳐진 목록(코드 + 이름 + 설명)이 팝업으로 떠서 사용자가 고른다.
즉 Help View는 혼자 쓰이지 않고, Search Help의 데이터 공급원으로 동작합니다. "보여줄 목록을 어디서 가져올까?"의 답 중 하나가 Help View인 셈입니다.

4. F4 도움말과 Help View의 데이터 공급 흐름 시각화 🗺️

사용자가 화면의 사원 입력 필드에서 F4 키를 눌렀을 때, Search Help가 작동하여 데이터 공급원인 Help View `ZV_EMP_HELP`를 통해 코드와 텍스트(부서명)를 합쳐 팝업 리스트를 띄우는 과정을 시각화해 보겠습니다.

F4 입력 도움말 동작 및 Help View 데이터 흐름

1. F4 입력 트리거사용자가 사원 입력 필드에서 F4 키를 누릅니다.
2. Search Help 기동필드에 매핑된 서치 헬프(Search Help) 객체가 활성화됩니다.
3. Help View 데이터 공급서치 헬프가 지정된 Selection Method인 뷰 `ZV_EMP_HELP`에서 원본 테이블(사원/부서)을 OUTER JOIN하여 데이터를 로드합니다.
4. F4 팝업 리스트 노출사용자는 아래와 같은 정합 정보 팝업창에서 원하는 사원을 선택합니다.
선택EMPID (사원번호)EMPNAME (사원명)DEPTNAME (부서명)
🔘E001정훈영개발팀 (Outer Join 매칭 ✅)
⚪E002홍길동영업팀 (Outer Join 매칭 ✅)
⚪E003아이유[부서 없음] (Outer Join으로 사원 유실 방지 ✅)

Help View는 짝이 맞는 정보만 묶는 INNER JOIN과 달리, 부서 마스터 테이블에 부서명 정보가 없더라도 사원(아이유) 데이터가 F4 팝업에서 유실되지 않도록 **OUTER JOIN**으로 관계를 결합해 보여줍니다.

5. 정상 흐름과 특별한 주의사항 🔍

  • ✅ OUTER JOIN 특화 구조: Classic Help View는 F4 도움말에서 부차적인 텍스트 설명(예: 부서명, 국가명 등)이 존재하지 않아도 핵심 코드(사원번호, 국가코드) 자체가 팝업창 목록에서 사라지지 않도록 기본적으로 `OUTER JOIN`을 활용해 데이터를 공급합니다.
  • ❌ 직접 쿼리 조회 불가: Help View는 일반 테이블이나 Database View처럼 ABAP 프로그램 내부의 **Open SQL `SELECT`문에서 직접 호출하여 쓸 수 없습니다.** 오직 Search Help의 데이터 소스 역할로만 한정되어 동작합니다.
  • ❌ 다중 결합 주의: 너무 많은 텍스트 테이블을 Help View에 조인해 두면 사용자가 F4를 누를 때 팝업창이 늦게 뜨는 성능 지연을 유발합니다.

6. 실무에서 조심할 점 🚨

⚠️

SQL에서 읽을 수 없는 View임을 명심하세요

초심자들이 흔히 저지르는 실수 중 하나가 `SELECT * FROM [Help View명]`과 같이 코딩을 작성하는 것입니다. Help View는 데이터베이스 물리 레벨에 존재하지 않으며, 오직 SAP GUI 프레젠테이션 레이어의 Search Help 화면 공급용 인터페이스로 캡슐화되어 있기 때문에 SQL 구문 작성 시 반드시 배제해야 합니다.

7. 미니 실습: Help View 구조 및 Search Help 연결 구조 확인 🧪

✍️

실습 과제

  1. 표준 SAP Dictionary에서 H_T001과 같은 대표적인 표준 Help View를 열어 테이블 조인 조건을 살펴봅니다.
  2. 뷰 구성 탭에서 핵심 회사 코드 테이블(`T001`)과 언어별 텍스트 테이블(`T001T`)이 어떤 Outer Join 관계로 묶여 있는지 확인합니다.
  3. 특정 Search Help를 생성할 때 Selection Method 칸에 이 Help View 이름을 입력하고 파라미터 매핑을 하는 모의 구조를 설계해 봅니다.

완료 조건: Help View가 Search Help의 데이터 공급 모델로 바인딩되는 구조와 일반 SELECT 쿼리에서 직접 쓸 수 없다는 제한사항을 설명할 수 있으면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. Help View를 Open SQL SELECT FROM [Help View명] 구문을 통해 프로그램 내에서 직접 조회할 수 있나요?
  2. Database View와 비교했을 때, Help View만이 가진 테이블 조인(JOIN) 규칙의 가장 큰 기술적 특징은 무엇인가요?
  3. 사용자가 화면 입력칸에서 도움말 팝업을 띄우기 위해 누르는 표준 단축키는 무엇인가요?
정답/해설 보기
  1. 아니요. 불가능합니다. Help View는 오직 Search Help의 데이터 출처(Selection Method)로만 사용하도록 제한된 특수 뷰 객체이므로 SQL에서 직접 조회 시 구문 오류가 발생합니다.
  2. 기본적으로 OUTER JOIN 구조를 활용해 데이터를 결합합니다. 텍스트 마스터에 매칭 정보가 유실되어도 기준 코드가 F4 창에서 빠지는 사고를 막아줍니다. (Database View는 INNER JOIN 위주)
  3. F4 키입니다. F4 도움말 창에 데이터를 엮어 뿌리는 용도로 Help View가 활성화됩니다.

10. 한눈에 정리 🏁

📝

Help View 핵심 요약

  • Help View는 F4 도움말의 다중 테이블 데이터(코드 + 설명) 공급을 위해 OUTER JOIN으로 엮은 특수 뷰입니다.
  • SQL 직접 조회가 불가능하며, 오직 Search Help의 Selection Method로만 사용됩니다.
  • 텍스트 테이블이 누락되더라도 핵심 코드가 F4 팝업 리스트에서 살아남도록 설계되었습니다.
  • 최신 SAP Fiori/ABAP Cloud 환경에서는 CDS의 Value Help Annotation으로 대체되는 고전적 아키텍처입니다.

여기까지는 "보여주기"용 View였습니다. 다음 Lesson Maintenance View와 Foreign Key 관계에서는 데이터를 화면에서 직접 입력·수정할 수 있게 해주는 View를 배웁니다.
