학습 목표

SELECT 결과를 받을 그릇을 그 자리에서 만드는 INTO TABLE @DATA( ) 인라인 타겟을 정리합니다. 결과 구조가 자동으로 딱 맞게 생성되는 편리함과 주의점을 익힙니다.

1. 지난 시간 연결: 결과 그릇을 미리 안 만들어도 된다 🥡

예전에는 SELECT 전에 결과를 담을 구조·테이블을 정확한 타입으로 미리 선언해야 했습니다. 컬럼을 바꾸면 선언도 같이 고쳐야 했죠. 번거롭고 실수가 잦았습니다.

THEORY-16에서 배운 인라인 선언을 SELECT에 적용한 것이 INTO TABLE @DATA( )입니다. 결과에 딱 맞는 그릇을 ABAP이 자동으로 만들어 줍니다.

2. 자동으로 맞춰지는 결과 타입 ✍️

ABAP
1
2
3
4
5 
SELECT carrid, connid, price
  FROM sflight
  INTO TABLE @DATA(lt_flights).
"→ lt_flights는 carrid/connid/price 3개 필드를 가진
"   Internal Table로 자동 생성됨
  • 구조 자동: SELECT한 필드 그대로 결과 구조가 만들어집니다.
  • 단건은 @DATA로: SELECT SINGLE ... INTO @DATA(ls)면 구조(한 줄)로 생성됩니다.
💡

필드를 바꿔도 안전

SELECT에서 컬럼을 추가/삭제하면 결과 타입도 자동으로 따라 바뀝니다. 별도 선언을 같이 고칠 필요가 없어, "선언과 SELECT가 어긋나는" 실수가 사라집니다.

3. 별칭(AS)으로 필드 이름 정리 🏷️

계산식이나 집계를 SELECT하면 필드 이름이 애매할 수 있습니다. AS로 이름을 주면 결과 구조의 필드 이름이 깔끔해집니다.

ABAP
1
2
3
4
5
6 
SELECT carrid,
       SUM( price ) AS total_price
  FROM sflight
  GROUP BY carrid
  INTO TABLE @DATA(lt).
"→ 결과 필드 이름: carrid, total_price

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: @DATA로 결과 그릇 자동 생성, 필드 이름은 AS로 정리.
  • ❌ 오류 1: 인라인 결과를 SELECT 블록 밖에서 쓰려다 "그런 변수 없다" → 범위 밖. 넓게 쓰려면 미리 선언.
  • ❌ 오류 2: 계산식에 AS를 안 줘서 결과 필드 이름이 이상하게 잡힘 → 이후 코드에서 참조가 불편.

5. 실무에서 조심할 점 🚨

⚠️

"자동"이라 타입이 안 보인다

@DATA는 편하지만, 결과 구조가 코드에 안 드러납니다. 다른 메서드에 넘기거나 인터페이스로 쓸 데이터라면, 명시적인 타입(DDIC 구조나 TYPES)으로 받는 편이 의도가 분명합니다. "이 데이터의 모양이 계약처럼 중요한가?"를 기준으로, 일회성이면 @DATA, 공유·전달용이면 명시 타입을 고르세요.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • INTO TABLE @DATA( )는 결과에 맞는 그릇을 자동 생성합니다.
  • SELECT 필드가 바뀌면 결과 타입도 자동으로 따라갑니다.
  • 계산·집계 필드는 AS로 이름을 정리합니다.
  • 공유·전달용 데이터는 명시 타입으로 받는 편이 명확합니다.
