지난 Lesson에서 Function Module을 호출했습니다. 이번에는 프로그램 안에 직접 Local Class를 만들고, CLASS DEFINITION, CLASS IMPLEMENTATION, Method Call의 가장 기본 구조를 익힙니다.

1. 지난 시간 연결: 기능을 더 구조적으로 묶는 방법 🧱

FORM은 프로그램 안의 코드 묶음이고, Function Module은 시스템에 등록된 재사용 기능입니다. 이제 한 단계 더 현대적인 방향으로 가봅니다. ABAP에서도 Class와 Method를 사용해 관련 기능과 데이터를 더 구조적으로 묶을 수 있습니다.

Local Class는 하나의 ABAP 프로그램 안에 정의하는 Class입니다. 다른 프로그램에서 공용으로 쓰기보다는, 현재 프로그램 안에서 로직을 정리하고 테스트하듯 나눠볼 때 유용합니다.

Local Class는 프로그램 안에 만드는 작은 도구 상자입니다. 그 안의 Method가 실제 작업 버튼입니다.

2. DEFINITION과 IMPLEMENTATION 나눠 보기 🧭

Class는 보통 두 부분으로 나누어 작성합니다.

  • CLASS DEFINITION: 이 Class가 어떤 Method를 공개하는지 선언합니다. 메뉴판에 가깝습니다.
  • CLASS IMPLEMENTATION: 선언한 Method가 실제로 무슨 일을 하는지 작성합니다. 주방 레시피에 가깝습니다.

처음에는 “왜 둘로 나누지?” 싶을 수 있습니다. 하지만 외부에서 볼 약속과 내부 구현을 분리하면, 큰 프로그램에서 구조를 파악하기 쉬워집니다.

REPORT zlocal_class_basic.

CLASS lcl_greeter DEFINITION.
  PUBLIC SECTION.
    METHODS say_hello IMPORTING iv_name TYPE string.
ENDCLASS.

CLASS lcl_greeter IMPLEMENTATION.
  METHOD say_hello.
    WRITE: / '안녕하세요,', iv_name.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lo_greeter) = NEW lcl_greeter( ).
  lo_greeter->say_hello( iv_name = 'ABAP' ).

코드가 길어 보이지만 조각으로 나누면 어렵지 않습니다. lcl_greeter라는 Local Class를 정의하고, say_hello Method를 만든 뒤, 실행 구간에서 객체를 생성해 Method를 호출합니다.

4. Method Call 문법 감각 잡기 📞

Method Call은 Method를 실행하는 문법입니다. 위 예제에서는 아래 줄이 Method 호출입니다.

ABAP
1 
lo_greeter->say_hello( iv_name = 'ABAP' ).
  • lo_greeter: 생성된 객체를 담은 참조 변수입니다.
  • ->: 객체의 Method를 호출할 때 쓰는 화살표입니다.
  • say_hello: 실행할 Method 이름입니다.
  • iv_name = 'ABAP': Method에 넘기는 입력 파라미터입니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: Class Definition에 Method를 선언하고, Implementation에서 같은 이름으로 구현한 뒤 객체를 생성해 호출합니다.
  • ❌ 선언/구현 불일치: Definition에는 say_hello가 있는데 Implementation에서 이름을 다르게 쓰면 오류가 납니다.
  • ❌ 객체 생성 누락: Instance Method를 호출하려면 먼저 NEW로 객체를 만들어야 합니다.
  • ❌ 파라미터 누락: Method가 필수 입력 파라미터를 요구하는데 호출 시 넘기지 않으면 오류가 납니다.

미니 실습으로 say_hello Method의 문구를 바꾸거나, 이름 파라미터를 다른 값으로 바꿔 실행해보세요. Class 구조는 그대로 두고 Method 동작만 바뀌는 느낌을 확인할 수 있습니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

Class를 쓴다고 자동으로 좋은 설계가 되지는 않습니다

Class와 Method는 강력하지만, 역할을 나누지 않고 아무 로직이나 한 Class에 몰아넣으면 FORM이 길어진 것과 크게 다르지 않습니다. Method 이름, 파라미터, 책임 범위를 작고 명확하게 잡는 것이 중요합니다.

또한 Local Class는 현재 프로그램 안에서만 쓰기 좋습니다. 여러 프로그램에서 재사용해야 한다면 다음 Lesson의 Global Class를 고려합니다.
