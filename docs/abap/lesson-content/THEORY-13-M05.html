학습 목표

검증을 통과한 값으로 실제 데이터를 조회·처리하는 START-OF-SELECTION 이벤트를 배웁니다. 리포트의 메인 로직이 여기에 들어간다는 점을 분명히 합니다.

1. 지난 시간 연결: 준비가 끝났으니 일을 시작 ▶️

여기까지 우리는 기본값을 채우고(INITIALIZATION), 화면을 꾸미고(OUTPUT), 입력을 검증(AT SELECTION-SCREEN)했습니다. 이제 모든 준비가 끝났습니다.

사용자가 실행을 눌렀고 검증도 통과했다면, 드디어 진짜 일을 할 차례입니다. 그 일이 일어나는 곳이 START-OF-SELECTION입니다. 리포트의 메인 로직은 대부분 여기에 들어갑니다.

  • 데이터 조회: 앞에서 배운 Open SQL로 DB에서 필요한 데이터를 가져옵니다.
  • 가공: 가져온 데이터를 내부 테이블에서 다듬습니다(합계, 매핑 등).
  • 다음 단계 준비: 출력할 결과를 정리해 둡니다.
💡

사실 START-OF-SELECTION은 "기본 이벤트"

리포트에서 이벤트 키워드를 아무것도 안 적고 그냥 로직을 쓰면, SAP가 그 코드를 자동으로 START-OF-SELECTION으로 간주합니다. 하지만 흐름을 분명히 하려면 명시적으로 적는 것이 좋습니다.

3. 조회와 출력을 나누는 습관 🧱

초보자는 START-OF-SELECTION에서 조회·계산·출력을 한 덩어리로 몰아 적기 쉽습니다. 하지만 깔끔한 리포트는 보통 이렇게 나눕니다.

  • START-OF-SELECTION: 데이터 조회와 가공(결과를 내부 테이블에 담기까지).
  • END-OF-SELECTION: 담아둔 결과를 화면/ALV로 출력(다음 Lesson).
"데이터를 만드는 단계"와 "보여주는 단계"를 나누면, 나중에 출력 방식을 바꾸기도 쉽고 디버깅도 편합니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 검증된 값으로 조회 → 결과를 내부 테이블에 적재 → 출력 단계로 전달.
  • ❌ 오류 1: 여기서 입력 검증을 또는 처음 하려다, 잘못된 값으로 이미 조회가 돌아 오류.
  • ❌ 오류 2: 조회 결과가 0건인데 빈 화면만 띄움 → "데이터 없음" 안내를 빠뜨려 사용자가 당황.

5. 실무에서 조심할 점 🚨

⚠️

여기가 성능의 핵심 구간입니다

대부분의 무거운 작업(대량 조회, 계산)이 START-OF-SELECTION에서 일어납니다. 그래서 THEORY-09에서 배운 "LOOP 안 SELECT 금지", THEORY-11의 "JOIN/FAE로 한 번에" 같은 원칙이 여기서 그대로 중요합니다. 리포트가 느리다면 십중팔구 이 구간을 점검해야 합니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • START-OF-SELECTION은 검증 후 실행되는 리포트의 메인 로직 자리입니다.
  • 주로 데이터 조회와 가공을 하고, 결과를 내부 테이블에 담습니다.
  • 조회(여기)와 출력(END-OF-SELECTION)을 나누면 코드가 깔끔합니다.
  • 성능의 핵심 구간이므로 SQL 안티패턴을 특히 주의합니다.

데이터를 다 만들었으니, 마지막으로 보여줄 차례입니다. 다음 Lesson END-OF-SELECTION 출력 마무리에서 결과를 화면에 내보내는 단계를 배웁니다.
