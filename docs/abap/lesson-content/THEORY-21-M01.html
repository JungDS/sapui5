학습 목표

현대 SAP 개발의 종착점, RAP(RESTful Application Programming Model)의 큰 그림을 잡습니다. CDS·OData·Fiori가 어떻게 한 흐름으로 이어지는지 이해합니다.

1. 지난 시간 연결: 데이터를 넘어 "업무 앱"으로 🚀

Chapter 20에서 CDS로 데이터를 읽는 모델을 만들었습니다. 하지만 진짜 업무 앱은 데이터를 생성·수정·삭제하고, 화면(Fiori)으로 사용자와 상호작용해야 합니다.

이 전체를 표준화된 방식으로 묶은 것이 RAP입니다. CDS 위에 트랜잭션 동작과 서비스를 얹어, Fiori 앱까지 한 번에 잇는 개발 모델이에요.

2. RAP의 4단 구조 🏗️

🔗

아래에서 위로 쌓는 흐름

  • ① 데이터 모델 (CDS): Interface View(ZI_) + Projection View(ZC_). Chapter 20에서 배운 것.
  • ② 동작 (Behavior Definition): 생성·수정·삭제, 검증·액션 등 "무엇을 할 수 있는가".
  • ③ 서비스 (Service Definition/Binding): 모델을 OData 서비스로 외부에 노출.
  • ④ 화면 (Fiori Elements): 서비스를 소비해 화면 자동 생성.

Chapter 1~20에서 쌓은 DDIC·OO·CDS 지식이 여기서 전부 합쳐집니다.

3. 왜 RAP인가 💡

  • ✅ 표준화: 생성·수정 같은 흔한 동작을 매번 새로 짜지 않고 정해진 틀로.
  • ✅ 적은 코드: 화면(Fiori Elements)은 CDS 주석으로 거의 자동 생성.
  • ✅ 클라우드 준비: ABAP Cloud·S/4HANA의 공식 권장 모델(Chapter 21의 Lesson 8에서 마무리).
비유하면 RAP는 "조립식 주택 키트"예요. 기초(CDS)·배관(Behavior)·전기(Service)·인테리어(Fiori)를 표준 규격으로 끼우면 집(업무 앱)이 빠르게 완성됩니다.

5. 실무에서 조심할 점 🚨

⚠️

RAP는 "전체 그림"을 먼저 잡아야 합니다

RAP는 CDS·Behavior·Service·Fiori가 톱니바퀴처럼 맞물립니다. 한 조각만 보고 시작하면 길을 잃기 쉽습니다. 이번 Chapter는 입문이므로 "각 단계가 무엇을 하고 어떻게 이어지는가"의 흐름을 잡는 데 집중하세요. 깊은 구현은 실무 프로젝트·Fiori 트랙에서 단계별로 익히면 됩니다. 지금은 "지도"를 머리에 그리는 것이 목표입니다.

8. 확인 퀴즈와 정답/해설 ✅

  1. RAP를 단순히 OData 서비스 생성 도구로만 보면 어떤 점을 놓치나요?
  2. Managed Scenario에서 “managed”라는 말은 무엇을 뜻하나요?
  3. 이번 Lesson에서 Draft와 Unmanaged 구현을 깊게 다루지 않는 이유는 무엇인가요?
정답/해설 보기
  1. 데이터 모델, 트랜잭션 동작, 서비스 노출, UI 소비까지 이어지는 전체 아키텍처라는 점을 놓칩니다.
  2. 기본 CRUD와 저장 흐름의 많은 부분을 RAP 프레임워크가 관리한다는 뜻입니다.
  3. 입문 단계에서는 전체 지도가 먼저 필요하기 때문입니다. Draft와 Unmanaged는 트랜잭션 흐름과 기존 코드 연계가 깊어 후속 실습에서 다루는 편이 안전합니다.

9. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • RAP는 CDS 위에 동작·서비스·화면을 얹어 업무 앱을 만드는 현대 개발 모델입니다.
  • 4단 구조: CDS(데이터) → Behavior(동작) → Service(노출) → Fiori(화면).
  • 흔한 동작은 표준 틀로, 화면은 주석으로 거의 자동 생성됩니다.
  • ABAP Cloud·S/4HANA의 공식 권장 모델입니다.
