학습 목표

CDS 필드·뷰에 의미를 입히는 Annotation(@주석)을 배웁니다. 화면 라벨·통화·수량 같은 의미(Semantics)를 코드로 부여하는 감각을 익힙니다.

1. 지난 시간 연결: 데이터에 "뜻"을 달자 🏷️

CDS로 데이터를 잘 합쳤어도, "이 숫자가 금액인지 수량인지", "화면에 무슨 라벨로 보일지" 같은 의미가 없으면 UI·OData가 제대로 동작하지 못합니다. 이 의미를 코드로 다는 것이 Annotation, @로 시작하는 주석입니다.

2. 자주 쓰는 Annotation ✍️

define view entity ZI_Flight
  as select from sflight
{
  key carrid,
      @EndUserText.label: '항공 요금'
      @Semantics.amount.currencyCode: 'Currency'   "금액임 + 통화 필드 지정
      price,
      @Semantics.currencyCode: true                "이 필드가 통화 코드
      currency
}
  • @EndUserText.label: 화면에 보일 라벨(DDIC 라벨처럼).
  • @Semantics.amount/quantity: "이 값은 금액/수량이고 통화/단위는 저 필드" 라고 알려줌 → 화면이 형식을 알아서 처리.
💡

비유: 상품 라벨

Annotation은 상품에 붙이는 라벨이에요. "이건 우유(종류), 1L(단위), 냉장보관(취급법)". 이 라벨 덕분에 매장(화면)이 알아서 냉장칸에 진열하고 단위를 표시하죠. 데이터에 의미를 달면 UI가 똑똑해집니다.

3. UI Annotation과 OData 🌐

Projection View(ZC_)에는 @UI 계열 주석으로 화면 배치까지 정할 수 있습니다(예: 목록 컬럼 순서, 폼 위치). 이 주석들이 OData·Fiori Elements로 전달되어 화면을 거의 코드 없이 자동 생성하게 해줍니다(Chapter 21과 Fiori 트랙에서 심화).

ABAP

@UI.lineItem: [{ position: 10 }]   "목록에서 10번째 컬럼
@UI.identification: [{ position: 10 }]

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 금액엔 통화 지정, 수량엔 단위 지정 → 화면이 형식·합계를 올바르게 처리.
  • ❌ 오류 1: 금액 필드에 통화 연결(currencyCode)을 빠뜨림 → 활성화 경고 또는 화면 형식 깨짐.
  • ❌ 오류 2: UI 주석을 데이터 기반 ZI_에 잔뜩 박음 → 재사용성 저하(다음 Lesson의 MDE로 분리하는 게 깔끔).

5. 실무에서 조심할 점 🚨

⚠️

금액·수량은 반드시 의미 주석을 짝지어라

SAP에서 금액은 항상 "값 + 통화", 수량은 "값 + 단위"가 한 쌍입니다. @Semantics.amount.currencyCode나 @Semantics.quantity.unitOfMeasure로 짝을 지정하지 않으면, 화면 합계나 통화 변환이 틀어집니다. 이건 단순 꾸밈이 아니라 데이터 정확성 문제이니 꼭 챙기세요.

6. 미니 실습: Annotation 역할 분류하기 🧪

이번 실습은 Annotation을 “CDS 위에 붙는 꾸밈”으로만 보지 않고, 데이터의 의미와 소비 방식을 전달하는 메타데이터로 분류하는 연습입니다.

✍️

실습 과제

  1. 예제에서 @EndUserText.label, @Semantics..., @UI...를 찾아 목적별로 나눕니다.
  2. 금액 필드와 통화 필드를 따로 두었을 때, 왜 Semantics Annotation이 필요한지 설명합니다.
  3. UI Annotation을 Interface View에 둘지 Projection View에 둘지 판단하고 이유를 적습니다.

완료 조건: Annotation이 실행 로직이 아니라 의미와 소비 힌트를 전달한다는 점을 설명할 수 있으면 성공입니다.

7. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: EndUserText.label - 사람이 읽는 라벨 Annotation의 공식 의미를 확인합니다.
  • SAP Help Portal: Semantics Annotations - 통화, 단위처럼 소비 측 의미를 표준화하는 Annotation을 확인합니다.
  • SAP Help Portal: ABAP Annotation Syntax - CDS Annotation 문법과 속성 표를 확인합니다.

8. 확인 퀴즈와 정답/해설 ✅

  1. @EndUserText.label은 주로 누구를 위한 정보인가요?
  2. Semantics Annotation을 생략해도 숫자는 보일 수 있는데, 왜 여전히 중요할까요?
  3. UI Annotation을 데이터 기반 View에 몰아넣으면 어떤 설계 문제가 생기나요?
정답/해설 보기
  1. 개발자와 소비 도구가 사람이 읽을 수 있는 이름을 이해하도록 돕는 정보입니다.
  2. 값의 의미가 사라질 수 있기 때문입니다. 예를 들어 금액 숫자만 있고 통화와 연결되지 않으면 소비 화면에서 정확한 의미를 알기 어렵습니다.
  3. 재사용 데이터 모델이 특정 화면 요구에 묶입니다. 화면별 요구는 Projection View나 Metadata Extension으로 분리하는 것이 안전합니다.

9. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Annotation(@)으로 CDS 필드·뷰에 의미를 입힙니다.
  • @EndUserText.label(라벨), @Semantics(금액/수량/통화·단위), @UI(화면 배치).
  • 의미 주석이 있어야 OData·Fiori 화면이 올바르게 동작합니다.
  • 금액·수량은 통화·단위 짝을 반드시 지정합니다.

그런데 UI 주석이 많아지면 View가 지저분해집니다. 다음 Lesson Metadata Extension 기초에서 주석을 별도 파일로 분리하는 법을 배웁니다.
