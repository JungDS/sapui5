학습 목표

지난 Lesson에서 만든 Transparent Table을 실제로 활성화하기 위해 필요한 Technical Settings를 배웁니다. Data Class, Size Category, Buffering을 처음 보는 사람도 이해할 수 있게 풀고, Data Browser로 Test Data를 확인하는 흐름까지 마무리합니다.

1. 지난 시간 연결: 설계도만으로는 창고가 지어지지 않는다 🏗️

이전 Lesson에서 우리는 Transparent Table의 필드와 Key Field, MANDT까지 배웠습니다. 이제 테이블 모양은 꽤 그럴듯합니다. 하지만 여기서 활성화를 누르면 시스템이 추가 정보를 요구할 수 있습니다. “이 테이블을 실제 데이터베이스의 어떤 성격으로 관리할까요?”라는 질문입니다.

테이블은 단순히 칸 목록만 있다고 완성되지 않습니다. 실제 DB에 만들어지는 객체이기 때문에 저장 영역, 예상 크기, 캐시 여부 같은 운영 설정이 필요합니다. 이 마지막 설정 묶음이 Technical Settings입니다.

Technical Settings는 테이블의 “물리적 운영 방식”을 알려주는 체크리스트입니다.

2. Data Class: 어떤 종류의 데이터를 담는 창고인가? 🗂️

Data Class는 테이블이 담을 데이터의 성격을 정합니다. 쉽게 말해 “이 창고는 어떤 물건을 주로 보관하나요?”에 답하는 칸입니다.

  • APPL0: 마스터 데이터 성격입니다. 고객, 자재, 공급업체처럼 기준 정보에 가깝습니다.
  • APPL1: 트랜잭션 데이터 성격입니다. 주문, 전표, 예약처럼 업무가 발생할 때 계속 쌓이는 데이터입니다.
  • APPL2: 조직이나 커스터마이징 성격의 데이터에 쓰이는 경우가 있습니다.

초보 단계에서는 값 이름을 모두 외우려고 애쓰기보다, “DB 관리자가 데이터 성격에 맞게 저장 영역과 운영 정책을 잡을 수 있도록 힌트를 주는 설정”이라고 이해하면 충분합니다. 실제 프로젝트에서는 회사 기준과 Basis/DB 운영 기준을 따릅니다.

3. Size Category: 얼마나 커질 창고인지 미리 말하기 📏

Size Category는 테이블에 앞으로 데이터가 어느 정도 쌓일지 시스템에 알려주는 설정입니다. 개발자가 “처음엔 작지만 나중에 수백만 건까지 갈 수 있어요”라고 말해주는 힌트에 가깝습니다.

  • 작은 코드성 테이블: 데이터가 몇십 건 또는 몇백 건이면 낮은 범주를 선택할 수 있습니다.
  • 거래 이력 테이블: 매일 계속 쌓이는 데이터라면 더 큰 범주를 고려합니다.
  • 불확실한 경우: 혼자 추측하지 말고 선배 개발자나 Basis 기준을 확인합니다.
💡

학습지 느낌으로 기억하기

Size Category는 “책장을 하나 살지, 창고형 랙을 살지” 미리 정하는 것과 비슷합니다. 지금 당장 비어 있어도, 앞으로 얼마나 쌓일지 생각해야 합니다.

4. Buffering: 자주 읽는 작은 데이터를 빠르게 보기 ⚡

Buffering은 테이블 데이터를 애플리케이션 서버 메모리에 올려두고 빠르게 읽는 설정입니다. 데이터베이스까지 매번 다녀오는 대신, 자주 쓰는 작은 정보를 가까운 곳에 복사해두는 느낌입니다.

하지만 Buffering은 무조건 켠다고 좋은 기능이 아닙니다. 데이터가 자주 바뀌는 테이블을 버퍼링하면 최신 데이터가 바로 반영되지 않는 것처럼 보일 수 있고, 운영 정책과 충돌할 수도 있습니다.

  • ✅ 어울리는 후보: 국가 코드, 고정 코드, 작은 설정 테이블처럼 작고 자주 읽고 거의 변하지 않는 데이터
  • ❌ 위험한 후보: 주문, 재고, 전표처럼 자주 바뀌고 최신성이 중요한 데이터
초심자 기준에서는 Buffering을 직접 판단하기보다, “성능과 최신성 사이의 선택”이라는 감각을 먼저 잡으면 됩니다.

5. 활성화 후 Data Browser로 눈으로 확인하기 🔎

Technical Settings까지 채우고 활성화가 성공하면, 테이블은 실제로 사용할 준비가 됩니다. 이제 “정말 테이블이 생겼나?”, “데이터가 들어가면 어떻게 보이나?”를 확인해야 합니다. 이때 쓰는 도구가 Data Browser입니다.

  • SAP GUI: 전통적으로 SE16 또는 SE16N에서 테이블 데이터를 조회합니다.
  • ADT: 테이블을 열고 Data Preview 기능을 사용해 데이터를 표 형태로 확인합니다.
🧪

미니 실습 흐름

  1. 개발 환경에서 방금 만든 테이블을 활성화합니다.
  2. Data Browser 또는 ADT Data Preview로 테이블을 엽니다.
  3. 허용된 방식으로 Test Data 한 줄을 입력하거나, 별도 테스트 프로그램으로 데이터를 넣습니다.
  4. 같은 Key Field 조합으로 한 줄을 더 넣으려 할 때 중복 오류가 나는지 확인합니다.

완료 조건: Technical Settings 값, 테스트 데이터 1건, 중복 키 오류 확인 결과를 각각 한 줄씩 기록하면 성공입니다.

여기서 “오류가 난다”는 것은 무조건 나쁜 일이 아닙니다. 같은 키로 두 줄이 들어가지 못하게 막는다면, 지난 Lesson에서 설계한 Key Field가 제대로 일하고 있다는 뜻입니다.

6. 운영 SE16N 직접 수정은 왜 금기일까? 🚨

개발 환경에서 테스트 데이터를 넣어보는 것과 운영 환경에서 실제 업무 데이터를 직접 수정하는 것은 완전히 다른 이야기입니다. 운영 시스템은 실제 회사 업무가 돌아가는 곳입니다. Data Browser로 데이터를 직접 바꾸면 프로그램이 원래 수행해야 하는 검증 로직을 우회할 수 있습니다.

⚠️

운영 데이터는 정식 화면과 프로그램을 통해 바꿉니다

SE16N 같은 도구로 운영 데이터를 직접 수정하면 권한 체크, 상태 체크, 후속 문서 생성, 변경 이력 기록 같은 중요한 절차가 빠질 수 있습니다. 겉보기에는 한 칸만 고친 것 같아도, SAP 업무 데이터의 연결 관계가 깨질 수 있습니다.

  • ✅ 개발/테스트 환경: 학습과 검증 목적으로 제한적으로 테스트 데이터를 넣고 확인할 수 있습니다.
  • ❌ 운영 환경: 직접 테이블 수정이 아니라, 승인된 트랜잭션·프로그램·마이그레이션 절차를 사용합니다.

7. 공식 문서로 더 확인하기 🔗

  • SAP Learning: Database Tables 생성 — Technical Settings가 테이블 생성 흐름에서 어떤 위치인지 확인합니다.
  • SAP Help Portal: Technical Settings — Data Class, Size Category, Buffering 같은 설정의 의미를 공식 도움말로 확인합니다.
  • SAP Help Portal: Buffering Permission — Buffering을 허용할지 말지 판단하는 기본 설정을 확인합니다.

8. 확인 퀴즈와 정답/해설 ✅

  1. Technical Settings는 필드의 업무 의미를 정하는 설정일까요, 테이블의 물리적 운영 방식을 정하는 설정일까요?
  2. Buffering은 주문·재고·전표처럼 자주 바뀌는 테이블에 항상 켜는 것이 좋을까요?
  3. 개발 환경에서 같은 키로 테스트 데이터를 두 번 넣었을 때 오류가 나면 무조건 실패일까요?
정답/해설 보기
  1. 테이블의 물리적 운영 방식을 정하는 설정입니다. 필드 의미는 Data Element 쪽에서 다룹니다.
  2. 아니요. NotebookLM의 BC430 기반 요약과 SAP Help의 Buffering 설명 모두, Buffering은 작고 자주 읽으며 변경이 적은 데이터에 신중히 쓰는 설정이라는 점을 강조합니다.
  3. 아니요. 같은 키를 막는 오류라면 Key Field가 중복을 제대로 막고 있다는 신호일 수 있습니다.

9. 한눈에 정리 🏁

📝

DDIC 1차 마무리 핵심

  • Technical Settings는 Transparent Table의 물리적 운영 방식을 정합니다.
  • Data Class는 데이터 성격, Size Category는 예상 데이터 규모를 나타냅니다.
  • Buffering은 작은 기준 데이터를 빠르게 읽게 도와주지만, 최신성이 중요한 데이터에는 조심해야 합니다.
  • Data Browser는 테이블 안의 실제 데이터를 확인하는 도구입니다.
  • 운영 시스템에서 SE16N으로 데이터를 직접 수정하는 것은 업무 로직을 우회할 수 있어 금기입니다.

여기까지 Domain → Data Element → Structure → Transparent Table → Technical Settings까지 DDIC 1차 조립 흐름을 한 바퀴 돌았습니다. 다음 Chapter ABAP 기본 문법과 WRITE 출력에서는 이제 이 데이터 정의를 바탕으로 ABAP 프로그램을 직접 실행하고 화면에 값을 출력해보는 단계로 넘어갑니다.
