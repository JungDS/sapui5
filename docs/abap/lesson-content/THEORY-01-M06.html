학습 목표

테이블을 활성화하기 위한 Technical Settings(기술 설정)를 익히고, 완성된 테이블에 데이터가 잘 들어갔는지 Data Browser로 확인하는 법을 배웁니다. DDIC 1차 Chapter를 마무리합니다.

1. Technical Settings — 테이블의 "보관 방식" 설정 ⚙️

Transparent Table을 활성화하려면 Technical Settings(기술 설정)를 반드시 채워야 합니다. 데이터의 "모양"이 아니라, "어떻게 보관·운영할지"를 정하는 곳입니다.

  • Data Class(데이터 클래스): 이 테이블을 DB의 어느 영역에 둘지. 보통 마스터/트랜잭션 데이터는 APPL0~APPL2.
  • Size Category(크기 범주): 예상 데이터 양(0~4 등). DB가 초기 공간을 잡는 힌트.
  • Buffering(버퍼링): 거의 안 바뀌는 설정성 테이블이라면 앱 서버 메모리에 캐싱해 조회 속도를 올림.
💡

활성화 성공 = 진짜 DB 테이블 생성

Technical Settings까지 채우고 활성화(Activate)가 통과되면, 비로소 실제 데이터베이스에 테이블이 생성되어 데이터를 넣을 수 있는 상태가 됩니다.

2. 데이터 확인하기 — Data Browser 🔎

테이블을 만들었으면, 데이터가 실제로 어떻게 들어가 있는지 눈으로 확인할 수 있어야 합니다. 이때 쓰는 도구가 Data Browser입니다.

  • SE16 / SE16N: SAP GUI에서 테이블 내용을 표 형태로 조회. 조건을 걸어 특정 행만 볼 수도 있음.
  • ADT(Eclipse): 테이블을 열고 Data Preview(F8)로 같은 내용을 확인.
  • SE11과의 차이: SE11은 테이블의 구조(설계도)를, Data Browser는 그 안에 담긴 실제 데이터(내용물)를 봅니다.

3. 테스트 데이터 한 줄 넣어보기 🧪

처음에는 테이블이 비어 있습니다. 학습 단계에서는 테스트 데이터(Test Data)를 직접 한두 줄 넣어 흐름을 확인하면 좋습니다.

  • ✅ 정상 흐름: SE16N에서 신규 입력 ➔ 키 값이 유일 ➔ 저장 성공 ➔ 다시 조회하면 그 행이 보임
  • ❌ 오류 흐름: 이미 있는 키와 똑같은 값으로 또 입력 ➔ "이미 존재하는 키"라며 거부 (앞 Lesson의 키 필드 규칙이 여기서 작동)

4. 실무에서 주의할 점 🚨

⚠️

운영 시스템에서 직접 데이터 입력 금지

SE16N으로 데이터를 직접 넣고 고치는 것은 개발/테스트 환경의 학습용입니다. 운영(Production)에서 표준 업무 테이블을 SE16N으로 직접 수정하면, 업무 로직·검증을 모두 건너뛰어 데이터 정합성이 깨집니다. 운영 데이터 변경은 반드시 정식 트랜잭션이나 프로그램을 통해야 합니다.

5. Chapter를 마무리하며 🏁

축하합니다! 이 Chapter에서 Domain → Data Element → Structure → Transparent Table → Technical Settings → 데이터 확인으로 이어지는 DDIC 상향식 조립 전 과정을 한 바퀴 돌았습니다. 데이터를 담는 "그릇"을 만드는 법을 익힌 것입니다.
