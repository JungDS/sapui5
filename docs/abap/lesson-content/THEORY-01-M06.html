학습 목표

이번 Lesson에서는 지난 시간의 Transparent Table을 실제 DB 저장 대상으로 마무리하기 전 확인하는 Technical Settings를 다룹니다. Data Class, Size Category, Buffering을 운영 힌트로 이해하고, SE16N Data Browser로 Test Data를 확인하는 흐름까지 닫습니다.

1. Technical Settings는 필드 뜻을 정하지 않는다

Transparent Table은 필드 목록과 Key만으로 끝나지 않습니다. 실제 데이터베이스에 만들어지는 저장 대상이므로 시스템은 “이 테이블을 어떤 물리 특성으로 만들고 접근할 것인가?”라는 정보를 더 필요로 합니다. 이 묶음이 Technical Settings입니다.

SAP Learning은 Technical Table Settings를 테이블과 별도로 활성화하고 전송할 수 있는 개발 객체로 설명합니다. 이 설정은 물리 DB 테이블의 속성과 ABAP SQL 접근 방식에 영향을 줍니다. 단, 어떤 설정이 실제 DB에 전달되는지는 사용하는 데이터베이스에 따라 달라집니다.

필드의 업무 의미는 Data Element 쪽에서 잡고, Technical Settings는 저장과 접근의 운영 힌트를 잡습니다.

2. 설정 네 칸을 한 화면에 놓고 보기

3. Data Class, Size Category, Buffering 판단

Data Class는 테이블이 담는 데이터의 성격을 나타냅니다. Size Category는 앞으로 어느 정도 커질지 알려주는 값입니다. Buffering은 table buffer를 사용할지 정하는 성능 옵션입니다.

대표 판단 예시

테이블 Data Class Size Category Buffering
소규모 상태 코드 APPL2 후보 낮은 범주 후보 읽기 많고 변경 적음
고객 마스터 APPL0 후보 중간 이상 신중 변경/동기화 영향 확인
주문 이력 APPL1 후보 증가량 기준 비후보 자주 바뀌고 최신성 중요

숫자 자체를 암기하지 말고, 데이터 성격과 예상 row 수, 읽기/변경 빈도를 근거로 선택합니다.

HANA에서는 Data Class가 의미 없다면 아무거나 골라도 될까?

아닙니다. 실제 물리 효과가 제한되더라도 설계 문서와 운영 기준으로 남습니다. 프로젝트 표준, Basis 기준, 교육 시스템 지시값을 우선 따릅니다.

4. 직접 해보기: SE11 설정 후 Data Browser로 확인

SE11에서 테이블 정의와 Technical Settings를 확인하고, 활성화 후 SE16N Data Browser로 테스트 row를 조회하는 흐름을 한 번에 시뮬레이션합니다. 같은 Key 조합을 다시 넣으면 중복 key 오류가 나야 합니다. Log Data Changes를 Enabled로 바꿔 실행하면, 테스트 데이터 변경을 감사 로그 관점에서 어떻게 볼지도 함께 확인할 수 있습니다.

T-Code: SE11 → SE16N
Technical Settings and Data Browser Simulator
버튼을 누르면 Technical Settings 활성화, Data Browser 조회, 중복 key 예상 로그가 출력됩니다.

5. Data Browser는 확인 도구이지 운영 수정 우회로가 아니다

Data Browser는 ABAP 프로그램을 직접 만들지 않고 테이블 데이터를 확인하는 도구입니다. 교육 client에서 내가 만든 Z 테이블에 Test Data를 넣고 key 동작을 보는 것은 학습에 도움이 됩니다. 하지만 운영 데이터를 직접 수정하는 것은 전혀 다른 문제입니다.

🚫

운영 데이터는 정식 경로로 바꿉니다

Data Browser 직접 수정은 권한 체크, 상태 체크, 후속 문서 생성, 변경 이력, application logic을 우회할 수 있습니다. 운영에서는 승인된 트랜잭션, 프로그램, 마이그레이션 절차를 사용합니다.

허용 범위 감각

상황 판단 이유
교육 client에서 내가 만든 Z 테이블에 테스트 row 입력 학습 범위 테이블 설계와 key 동작을 확인하기 위한 제한된 데이터입니다.
개발 서버에서 승인된 테스트 프로그램으로 sample data 생성 권장 재현 가능한 방식으로 데이터를 넣고 지울 수 있습니다.
운영 client에서 업무 테이블 직접 수정 금지 업무 검증과 변경 절차를 우회해 데이터 정합성을 깨뜨릴 수 있습니다.
Client-dependent 테이블에서는 무엇을 먼저 볼까?

Client-dependent 테이블이라면 MANDT 기준으로 현재 로그인 client의 데이터가 보이는지 확인합니다. 다른 client의 데이터와 섞어 이해하면 실습 결과를 잘못 판단할 수 있습니다.

7. 확인 퀴즈

  1. Technical Settings는 필드의 업무 의미를 정하는 설정인가요, 물리 DB 테이블과 접근 특성을 정하는 설정인가요?
  2. SAP HANA에서 Data Class는 물리 tablespace 선택에 강하게 영향을 준다고 말해도 될까요?
  3. Buffering은 주문, 재고, 전표처럼 자주 바뀌는 테이블에 항상 켜는 것이 좋을까요?
  4. 개발 환경의 Test Data 입력과 운영 데이터 직접 수정은 같은 수준의 작업인가요?
정답/해설 보기
  1. 물리 DB 테이블과 접근 특성을 정하는 설정입니다. 필드 의미는 Data Element 쪽에서 다룹니다.
  2. 아니요. SAP Learning은 Data Class가 SAP HANA에서는 효과가 없지만 필수값과 문서 정보로 남는다고 설명합니다.
  3. 아니요. Buffering은 작고 자주 읽으며 변경이 드문 데이터에 신중히 검토합니다.
  4. 아니요. 운영 데이터는 승인된 트랜잭션, 프로그램, 마이그레이션 절차로 변경해야 합니다.
