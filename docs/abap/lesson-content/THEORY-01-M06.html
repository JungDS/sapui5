학습 목표

투명 테이블을 최종적으로 활성화하기 위한 필수 코스, Technical Settings(기술 설정)를 이해합니다. 그리고 방금 뚝딱 만들어낸 내 테이블 창고에 데이터가 잘 들어갔는지 Data Browser를 통해 직접 눈으로 확인하는 재미를 느껴봅니다. DDIC 1차 Chapter의 화려한 마무리입니다!

1. 지난 시간 요약 & 테이블 완성의 마지막 고개 🤔

이전 Lesson에서 우리는 투명 테이블의 모양을 디자인하고 강력한 키(Key) 필드까지 세팅했습니다. "와! 이제 끝났다!" 하고 활성화(Activate) 버튼을 누르면...? 삐빅! ❌ 시스템이 "Technical Settings(기술 설정)를 먼저 채워주세요!"라며 통과시켜주지 않습니다.

테이블의 '모양'은 완벽하지만, 이 거대한 테이블 창고를 실제 데이터베이스의 어느 구역에, 얼마나 크게 지을지 아직 허가를 받지 않았기 때문입니다.

2. Technical Settings (기술 설정) — 내 창고, 어떻게 지을까? ⚙️

테이블 화면 위쪽의 Technical Settings 버튼을 누르면, 이 창고의 물리적인 운영 방침을 정할 수 있습니다. 가장 중요한 3가지는 다음과 같습니다.

  • Data Class (데이터 클래스): 이 창고를 지을 '동네(영역)'를 정합니다. 수시로 데이터가 쌓이는 트랜잭션 데이터인지(APPL1), 기준 정보인 마스터 데이터인지(APPL0) 등을 지정합니다. DB 관리자가 백업을 효율적으로 하기 위해 나눠놓은 구역이죠.
  • Size Category (크기 범주): "앞으로 이 창고에 데이터가 대략 몇 만 건 쌓일 것 같아요"라고 시스템에 힌트(0~4 등급)를 줍니다. 시스템은 이 등급을 보고 초기에 땅(공간)을 적당히 할당해 줍니다.
  • Buffering (버퍼링): 엄청나게 조회를 많이 하지만 내용은 1년에 한 번 바뀔까 말까 한 테이블(예: 국가 코드, 환율)이라면? 매번 DB 창고 깊숙이 가지 않고, 앱 서버의 임시 메모리(캐시)에 올려두고 빛의 속도로 읽게 해주는 설정입니다.
🎉

드디어 활성화 성공! = 진짜 DB 테이블 탄생

기술 설정까지 깔끔하게 채우고 다시 활성화(Activate)를 누르면, 비로소 실제 데이터베이스에 테이블이 쿵! 하고 지어집니다. 이제 진짜 데이터를 넣을 수 있는 상태가 된 것입니다.

3. 데이터의 민낯을 보다: Data Browser (SE16N) 🔎

창고를 지었으니, 그 안에 데이터가 잘 들어가 있는지 문을 열어봐야겠죠? 개발자들이 하루에도 수십 번씩 쓰는 도구가 바로 Data Browser입니다.

  • SAP GUI 사용자: 명령어 창에 SE16 또는 더 쓰기 편한 최신 버전인 SE16N을 입력하고 들어갑니다. 마치 엑셀 표처럼 데이터를 편하게 조회하고 검색할 수 있습니다.
  • ADT(Eclipse) 사용자: 테이블을 열어둔 상태에서 F8 (Data Preview) 키를 누르면 화면 아래에 즉석에서 데이터가 표출됩니다. 너무 편리하죠!
비교 포인트: SE11 화면은 테이블의 구조(설계도)를 보는 곳이고, Data Browser(SE16N/F8)는 그 안에 담긴 실제 내용물(데이터)을 보는 곳입니다! 완전 역할이 다릅니다.

4. 직접 데이터 넣어보기 (미니 실습) 🧪

처음 만든 테이블은 당연히 비어있습니다. 우리가 만든 게 잘 동작하는지 테스트 데이터를 한 줄 넣어볼까요? (개발 환경에서만 해보세요!) SE16N 화면 위쪽의 ➕(추가) 버튼을 누르면 직접 데이터를 타이핑해서 넣을 수 있습니다.

  • ✅ 정상 흐름: 빈칸을 채우고 [저장] ➔ 하단에 "저장되었습니다" 메시지 ➔ 다시 조회하면 방금 넣은 1줄이 예쁘게 보입니다.
  • ❌ 오류 흐름 (키 중복): 똑같은 키 값(예: 똑같은 편명과 날짜)으로 1줄을 더 넣으려고 시도해 보세요. 시스템이 "이미 존재하는 키입니다!"라며 단호하게 거부합니다. 이전 Lesson에서 배운 방패(Key Field)가 완벽하게 작동하는 순간입니다!

5. 실무에서 조심해야 할 점 🚨

초보 티를 벗기 위해 이 점은 꼭 새겨두세요.

⚠️

운영 서버(Production)에서 SE16N으로 데이터를 직접 고친다고요? 절대 금지!

개발이나 테스트 환경에서는 방금처럼 SE16N으로 편하게 데이터를 넣고 고쳐도(디버깅 목적) 괜찮습니다. 하지만 진짜 회사의 업무 데이터가 쌓이는 운영 서버에서 테이블 내용을 SE16N으로 직접 수정하는 것은 최악의 금기사항입니다.

왜냐하면 직접 데이터를 찔러넣으면 SAP 프로그램이 가지고 있는 '안전 검사(이 고객이 블랙리스트인지, 날짜가 꼬이지는 않았는지)'를 전부 무시해버려서 데이터가 엉망이 되기 때문입니다. 운영 데이터 수정은 반드시 정식 프로그램이나 트랜잭션 화면을 통해서만 이루어져야 합니다.

6. 한눈에 정리 🏁

📝

DDIC 1차 요약 완료!

  • 테이블을 활성화하려면 Technical Settings(기술 설정)에서 데이터 클래스와 사이즈 등 보관 방식을 반드시 정해줘야 합니다.
  • Data Browser(SE16N/ADT F8)를 이용하면 테이블에 실제로 들어있는 엑셀 같은 데이터를 눈으로 확인할 수 있습니다.
  • 테스트 환경에서는 SE16N으로 데이터를 직접 넣어보며 키(Key) 중복 검사가 잘 되는지 확인하는 습관을 들이세요.
  • 운영 환경에서 SE16N으로 데이터를 조작하는 것은 데이터 정합성을 파괴하는 매우 위험한 행동입니다.
