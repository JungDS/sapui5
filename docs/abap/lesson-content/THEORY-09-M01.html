학습 목표

Chapter 8에서는 Internal Table을 SALV로 보여줬습니다. 이번 Chapter에서는 데이터베이스에서 데이터를 읽어오는 ABAP SQL의 첫 문법을 배웁니다. 가장 기본이 되는 SELECT FROM과 FIELDS 구조를 읽을 수 있게 됩니다.

1. 지난 Chapter 연결: SALV에 넣을 실제 데이터가 필요하다 🧭

지금까지는 예제 데이터를 코드 안에서 직접 만들었습니다. 학생 이름과 점수를 APPEND로 넣고, 그 Internal Table을 SALV로 보여줬죠. 하지만 실무 Report는 대부분 데이터베이스에 저장된 실제 업무 데이터를 읽어옵니다.

이때 ABAP 프로그램이 데이터베이스에 “이 테이블에서 이 필드들을 읽어와줘”라고 요청하는 문법이 ABAP SQL입니다. Open SQL이라고도 부르며, ABAP에서 데이터베이스에 독립적인 방식으로 데이터를 조회하도록 도와줍니다.

ABAP SQL은 ABAP 프로그램과 데이터베이스 사이의 표준 조회 언어입니다.

2. SELECT FROM / FIELDS 구조 읽기 📚

ABAP
1
2
3 
SELECT FROM t005t
  FIELDS land1, landx
  INTO TABLE @DATA(lt_countries).

위 코드는 국가 텍스트 테이블 T005T에서 국가 코드 LAND1과 국가명 LANDX를 읽어 Internal Table lt_countries에 담는 예제입니다.

  • SELECT FROM t005t: 어느 데이터베이스 테이블에서 읽을지 지정합니다.
  • FIELDS land1, landx: 어떤 필드만 가져올지 지정합니다.
  • INTO TABLE: 조회 결과 여러 줄을 Internal Table에 담습니다.
  • @DATA(...): 조회 결과를 받을 ABAP 변수를 inline으로 선언합니다.

지금은 INTO TABLE과 @DATA를 자세히 외우기보다, “FROM은 어디서, FIELDS는 무엇을”이라는 감각을 먼저 잡으면 됩니다.

3. 왜 FIELDS를 명시할까? 🎯

데이터베이스 테이블에는 많은 필드가 있을 수 있습니다. 그런데 화면에 국가 코드와 국가명만 필요하다면 모든 필드를 가져올 이유가 없습니다. 그래서 FIELDS로 필요한 필드만 적습니다.

💡

초심자용 비유

편의점에서 물 한 병만 필요한데 매장 전체 물건을 카트에 담아오지 않는 것과 같습니다. 필요한 필드만 고르는 습관이 성능과 가독성에 좋습니다.

초심자 단계에서는 SELECT *보다 필요한 필드를 적는 방식을 기본으로 연습하세요. 조회 의도가 코드에 더 잘 드러납니다.

4. 최소 예제: 조회 후 WRITE로 확인하기 ✍️

ABAP

REPORT zsql_select_basic.

SELECT FROM t005t
  FIELDS land1, landx
  INTO TABLE @DATA(lt_countries).

LOOP AT lt_countries INTO DATA(ls_country).
  WRITE: / ls_country-land1, ls_country-landx.
ENDLOOP.

이 예제는 조회 결과를 Internal Table에 담고, LOOP로 한 줄씩 출력합니다. 데이터가 많으면 출력도 길어질 수 있으므로 실제 실습에서는 강사가 지정한 작은 테이블이나 조건을 함께 사용하는 것이 좋습니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 테이블과 필드명이 맞고 권한/환경이 허용되면 조회 결과가 Internal Table에 담깁니다.
  • ✅ 빈 결과: 조건이 없거나 데이터가 없으면 Internal Table이 비어 있을 수 있습니다. 빈 결과 자체가 항상 오류는 아닙니다.
  • ❌ 필드명 오타: landx를 잘못 적으면 문법 오류가 납니다.
  • ❌ 테이블 미존재: 실습 시스템에 해당 테이블이 없거나 접근할 수 없으면 활성화/실행에 실패할 수 있습니다.
  • ❌ 무조건 대량 조회: 조건 없이 큰 테이블을 조회하면 성능과 운영 안정성에 부담이 됩니다.

미니 실습으로 FIELDS land1, landx에 필드를 하나 더 추가해보세요. 그리고 결과 구조에 해당 필드가 생기는지 확인합니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

실행되는 SELECT와 좋은 SELECT는 다릅니다

조건 없이 큰 테이블을 조회하거나, 필요 없는 필드를 모두 가져오는 코드는 실습에서는 돌아가도 운영에서는 문제가 될 수 있습니다. 처음부터 필요한 필드와 조건을 생각하는 습관을 들이세요.

또한 Open SQL은 데이터를 읽어오는 문법이지 업무 권한 검사를 자동으로 완성해주는 도구가 아닙니다. 실제 업무 Report에서는 권한, 조건, 데이터 범위를 함께 설계해야 합니다.

7. 한눈에 정리 🏁

📝

SELECT 기본 구조 핵심

  • ABAP SQL은 ABAP에서 데이터베이스 데이터를 조회하는 표준 문법입니다.
  • SELECT FROM은 어떤 테이블에서 읽을지 지정합니다.
  • FIELDS는 가져올 필드 목록을 지정합니다.
  • 조회 결과는 Internal Table에 담아 LOOP나 SALV로 확인할 수 있습니다.
  • 필요한 필드와 조건만 조회하는 습관이 성능과 유지보수성에 좋습니다.
