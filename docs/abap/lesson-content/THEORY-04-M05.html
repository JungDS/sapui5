학습 목표

지금까지 DDIC에서 입력 도움말(Search Help)과 관계(Foreign Key)를 만들어 봤습니다. 이번 Lesson에서는 그렇게 만든 입력 도움말을 실제 프로그램의 PARAMETERS 입력 필드에 연결해, 우리가 만든 화면에서 F4가 동작하게 만드는 법을 배웁니다. 핵심은 “Data Element를 참조하면 F4가 공짜로 따라온다”는 상속 원리입니다.

1. 지난 Lesson 연결: 만든 F4를 내 화면에 붙이기 🔌

Chapter 4 내내 “잘못된 값을 막고(Foreign Key), 고를 수 있게 돕는(Search Help)” DDIC 장치를 만들었습니다. 그런데 이게 실제로 내가 짠 보고서 프로그램의 입력칸에서 동작하지 않으면 의미가 없죠.

좋은 소식은, 대부분의 경우 코드를 거의 안 써도 F4가 자동으로 붙는다는 것입니다. 비결은 PARAMETERS를 선언할 때 타입을 어떻게 주느냐에 있습니다.

“코드 한 줄 쳤는데 돋보기(F4) 버튼이 알아서 생기는 마법”의 정체는 DDIC 속성의 자동 상속입니다.

2. 자동 상속: Data Element를 참조하면 F4가 따라온다 ✨

PARAMETERS를 TYPE/LIKE로 DDIC 객체(Data Element나 테이블 필드)를 참조해 선언하면, 런타임이 그 필드에 맞는 입력 도움말(F4)을 자동으로 제공합니다. 기본 타입(TYPE c LENGTH 10)으로 선언하면 이런 상속이 일어나지 않습니다.

PARAMETERS p_id TYPE c LENGTH 3.

* 권장: Data Element 참조 — F4 / 선택 텍스트 / F1 문서가 자동으로 따라옴
PARAMETERS p_carr TYPE s_carr_id.
💡

Data Element 참조가 좋은 3가지 “일관성 상속”

  • 의미(Field Label): Data Element의 라벨이 화면의 선택 텍스트(Selection Text)로 자동 반영 → 전사 통일된 용어.
  • F4(Search Help): Data Element/Domain에 붙은 검색 도움말·고정값을 코딩 없이 그대로 상속.
  • F1(문서): 사용자가 F1을 누르면 Data Element에 작성된 표준 설명이 팝업으로 표시.

3. 시스템이 F4를 찾는 우선순위 계층 🪜

사용자가 F4를 누르면(내부적으로 PROCESS ON VALUE-REQUEST), 시스템은 정해진 우선순위를 따라 가장 적절한 도움말을 찾아 띄웁니다. 위에서부터 먼저 확인합니다.

F4 입력 도움말 탐색 순서 (위가 우선)

1. 화면 필드 직접 연결Screen Painter에서 그 필드에 직접 붙인 Search Help
2. Check TableForeign Key로 연결된 Check Table 기반 도움말
3. Data Element참조한 Data Element에 붙은 Search Help
4. Domain 고정값Domain의 Fixed Values → 드롭다운
5. 달력/시계타입이 날짜(DATS)·시간(TIMS)이면 기본 달력·시계

그래서 Foreign Key만 잘 걸어둬도(2번) 별도 Search Help 없이 F4가 동작하는 경우가 많습니다.

4. 특정 Search Help 강제 지정: MATCHCODE OBJECT 🎯

자동 상속이 훌륭하지만, 어떤 보고서에서는 “상속된 기본 F4 말고 이 검색 도움말을 띄워라”라고 강제하고 싶을 때가 있습니다. 이때 MATCHCODE OBJECT 구문으로 특정 Search Help를 명시합니다.

ABAP
1
2 
* 상속된 기본 F4를 무시하고, 지정한 Search Help(zsh_order)를 강제로 연결
PARAMETERS p_ord LIKE vbak-vbeln MATCHCODE OBJECT zsh_order.

이 방식은 Data Element나 테이블 구조 자체를 수정하지 않고, 특정 프로그램에서만 검색 경로를 덮어쓸 수 있어 실무에서 자주 쓰입니다.

5. Foreign Key의 Check Table이 주는 똑똑한 F4 🧠

지난 Lesson의 Check Table은 “잘못된 값을 막는 방패”였지만, F4를 누를 때는 “친절한 안내자”도 됩니다. 필드에 Check Table이 지정돼 있으면, F4 시 그 테이블의 키 값을 읽어 목록으로 보여줍니다.

  • 키 목록 표시: 예) CARRID에 Check Table SCARR이 있으면 항공사 코드 목록을 F4로 제공.
  • 텍스트 테이블 자동 결합: Check Table에 텍스트 테이블이 연결돼 있으면, 코드뿐 아니라 로그인 언어에 맞는 설명까지 자동으로 조인해 보여줍니다.
  • 더 풍부한 도움말: Check Table 자체에 별도 Search Help가 있으면, 키만 보여주는 수준을 넘어 여러 조건을 입력받는 팝업을 띄웁니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

“F4에서 골랐으니 올바른 값이다”는 착각

F4 팝업은 “이런 값들이 있어요”라고 보여주는 편의 기능일 뿐, 최종 검증의 문지기가 아닙니다. 사용자가 F4를 무시하고 키보드로 엉뚱한 값을 타이핑한 뒤 엔터를 치면, Foreign Key/Check Table 제약이나 별도 입력 검증이 없는 한 그 잘못된 값이 그대로 프로그램으로 들어옵니다. 편의(Search Help)와 검증(Input Check)은 분리해서 설계하세요.

ABAP Cloud / Fiori에서는 PARAMETERS와 MATCHCODE가 어떻게 되나?

SAP GUI 기반에서는 PARAMETERS와 MATCHCODE OBJECT가 화면 렌더링과 F4를 지배했습니다. 하지만 ABAP Cloud·S/4HANA Clean Core(RAP)에서는 화면을 그리는 PARAMETERS 명령 자체가 금지(obsolete)되었습니다. 대신 Fiori 화면을 위해 CDS View에서 값 도움말을 제공합니다. 필드에 Value Help를 주려면 MATCHCODE OBJECT가 아니라 CDS 프로젝션에서 @Consumption.valueHelpDefinition 어노테이션으로 다른 CDS View(Value Help Provider)와 연결합니다.

7. 미니 실습: 내 PARAMETERS에 F4 붙이기 🧪

✍️

실습 과제

  1. 항공사 코드를 입력받는 PARAMETERS를 TYPE c LENGTH 3으로 선언했을 때와, Data Element(s_carr_id)를 참조했을 때 화면이 어떻게 달라질지 적습니다(F4·선택텍스트·F1 관점).
  2. 이 필드에 Foreign Key/Check Table(SCARR)이 걸려 있다면, 별도 Search Help 없이도 F4가 동작하는 이유를 우선순위 계층으로 설명합니다.
  3. 특정 보고서에서만 다른 검색 도움말을 띄우려면 어떤 구문을 쓰는지 적습니다.
  4. “F4로 골랐으니 검증은 끝났다”가 왜 위험한지 한 줄로 적습니다.

완료 조건: “Data Element 참조 → F4·라벨·문서 자동 상속”과 “F4는 편의일 뿐 검증은 별도”를 설명할 수 있으면 성공입니다.

9. 확인 퀴즈 ✅

  1. PARAMETERS에 F4가 자동으로 붙게 하려면 타입을 어떻게 선언하는 것이 좋은가요?
  2. F4 탐색 우선순위에서 Check Table과 Data Element 중 어느 쪽을 먼저 확인하나요?
  3. 상속된 기본 F4 대신 특정 Search Help를 강제로 띄우는 구문은?
  4. F4 목록에서 값을 고르면 입력 검증이 끝난 것인가요?
정답/해설 보기
  1. Data Element를 참조(TYPE <data_element>)해 선언합니다. 의미·F4·F1이 함께 상속됩니다.
  2. Check Table을 먼저 확인합니다(2번 → 3번 순서). 화면 직접 연결(1번)이 가장 우선입니다.
  3. MATCHCODE OBJECT 구문입니다. DDIC 수정 없이 프로그램 단위로 덮어씁니다.
  4. 아니요. F4는 편의일 뿐입니다. 검증은 Foreign Key/Check Table·입력 검증 로직이 담당합니다.
