학습 목표

지난 Lesson까지 DDIC의 Search Help를 배웠습니다. 이번에는 ABAP PARAMETERS 입력칸이 Data Element와 DDIC 연결을 통해 어떻게 F4 Help를 얻는지 확인합니다.

1. 지난 시간 연결: Search Help를 만들었는데 어디에 보일까? 🧩

Search Help를 만들었다고 해서 모든 입력칸에 자동으로 뜨는 것은 아닙니다. F4 Help가 나타나려면 입력 필드가 DDIC 정보와 연결되어 있어야 합니다.

ABAP Report의 PARAMETERS도 타입을 어떻게 선언하느냐에 따라 DDIC의 도움을 받을 수 있습니다. 특히 Data Element를 타입으로 사용하면, 그 Data Element에 연결된 Search Help나 관련 DDIC 정보가 입력 도움말로 이어질 수 있습니다.

PARAMETERS가 DDIC 타입을 입으면, 단순 입력칸이 아니라 DDIC 지식을 아는 입력칸이 됩니다.

2. TYPE c LENGTH 3와 Data Element 타입의 차이 🔍

아래 두 선언은 화면에서 비슷한 입력칸처럼 보일 수 있지만, DDIC 정보 연결 면에서는 차이가 있습니다.

ABAP
1
2 
PARAMETERS p_raw  TYPE c LENGTH 3.
PARAMETERS p_carr TYPE zde_carrid.
  • p_raw TYPE c LENGTH 3: 그냥 3자리 문자 입력칸입니다. 업무 의미나 Search Help 연결 정보가 없습니다.
  • p_carr TYPE zde_carrid: Data Element를 타입으로 사용합니다. Data Element의 의미, 라벨, Search Help 연결을 활용할 수 있습니다.

여기서 zde_carrid는 예시 Data Element 이름입니다. 실제 프로젝트에서는 표준 Data Element나 고객사 네이밍 규칙에 맞는 Data Element를 사용합니다.

3. DDIC F4 Help 연결 흐름 🧭

PARAMETERS와 DDIC F4 Help가 이어지는 대표 흐름은 아래처럼 볼 수 있습니다.

  1. Domain이 데이터 타입과 길이를 정의합니다.
  2. Data Element가 의미와 라벨을 붙입니다.
  3. Data Element 또는 관련 DDIC 관계에 Search Help가 연결됩니다.
  4. ABAP PARAMETERS가 그 Data Element를 타입으로 사용합니다.
  5. 사용자가 입력칸에서 F4를 누르면 DDIC 기반 후보 목록이 나타납니다.
💡

왜 DDIC를 재사용하나요?

프로그램마다 F4 Help를 따로 만들면 유지보수가 힘듭니다. Data Element와 Search Help에 의미를 모아두면 여러 프로그램이 같은 입력 도움말을 재사용할 수 있습니다.

4. 최소 실습: Data Element 타입으로 PARAMETERS 선언하기 🧪

아래 예제는 직접 F4 로직을 코딩하지 않고, DDIC 타입을 통해 입력 도움말을 기대하는 흐름입니다.

ABAP
1
2
3
4
5 
REPORT zparam_ddic_f4.

PARAMETERS p_carr TYPE zde_carrid OBLIGATORY.

WRITE: / '선택한 항공사:', p_carr.

실습 포인트는 코드가 짧다는 점입니다. F4 후보 목록을 직접 SELECT해서 팝업으로 만드는 것이 아니라, DDIC에 이미 정의된 Data Element와 Search Help 관계를 활용합니다.

  • Data Element에 Search Help가 연결되어 있는지 확인합니다.
  • PARAMETERS가 해당 Data Element를 타입으로 사용하는지 확인합니다.
  • Selection Screen에서 F4를 눌러 후보 목록이 나오는지 확인합니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: PARAMETERS가 Search Help가 연결된 Data Element를 사용하고, F4 목록이 표시됩니다.
  • ✅ 재사용 흐름: 같은 Data Element를 다른 프로그램에서도 쓰면 동일한 의미와 입력 도움말을 활용할 수 있습니다.
  • ❌ 단순 타입 선언: TYPE c LENGTH 3처럼만 선언하면 DDIC 의미와 F4 연결이 부족할 수 있습니다.
  • ❌ 연결 누락: Data Element는 사용했지만 Search Help나 Foreign Key 관계가 없다면 기대한 F4가 안 보일 수 있습니다.
F4 Help가 안 뜰 때는 “프로그램 코드”만 보지 말고 Data Element, Domain, Foreign Key, Search Help 연결을 함께 봐야 합니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

F4 Help는 입력 편의이지 최종 업무 검증이 아닙니다

사용자가 F4에서 값을 골랐다고 해서 모든 업무 조건이 만족되는 것은 아닙니다. 선택한 값이 현재 사용자에게 허용되는지, 특정 기간에 사용할 수 있는지, 상태가 유효한지는 프로그램 검증이나 권한 체크가 필요할 수 있습니다.

또한 표준 Data Element를 쓸 수 있는데 새 Data Element를 만들면 F4 Help와 라벨 재사용 기회를 잃을 수 있습니다. 의미가 같다면 표준 재사용을 먼저 검토하세요.

7. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • PARAMETERS는 Data Element 타입을 사용해 DDIC 의미와 입력 도움말을 활용할 수 있습니다.
  • TYPE c LENGTH 3 같은 단순 타입은 업무 의미와 F4 연결이 부족할 수 있습니다.
  • Data Element에 Search Help나 관계가 연결되어 있으면 F4 Help로 이어질 수 있습니다.
  • F4 Help가 안 뜨면 코드뿐 아니라 DDIC 연결을 함께 확인해야 합니다.
  • F4 Help는 편의 기능이며 권한과 복잡한 업무 검증을 모두 대신하지는 않습니다.
