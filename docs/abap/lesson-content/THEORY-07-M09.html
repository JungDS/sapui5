학습 목표

Chapter 7의 마지막 Lesson입니다. Internal Table과 Work Area를 다룬 뒤 값을 비우거나 메모리를 정리할 때 쓰는 CLEAR, REFRESH, FREE, 그리고 Memory 관점을 정리합니다.

1. 데이터를 넣었으면 비우는 법도 알아야 한다 🧭

이번 Chapter에서는 Internal Table의 행을 바꾸고, 지우고, 정렬하고, 검색하고, 깊은 구조까지 살펴봤습니다. 그런데 프로그램이 계속 실행되는 동안 같은 변수와 Internal Table을 재사용하면 이전 값이 남아 다음 처리에 섞일 수 있습니다.

그래서 ABAP에서는 값을 초기화하거나 Internal Table 내용을 비우는 문법을 사용합니다. 대표적으로 CLEAR, REFRESH, FREE가 있습니다.

정리는 “예쁘게 마무리”가 아니라, 다음 처리에 이전 값이 섞이지 않게 하는 안전장치입니다.

2. CLEAR: 변수나 구조를 초기값으로 돌리기 🧽

CLEAR는 변수, Work Area, 구조, Internal Table 등을 초기 상태로 되돌립니다. 

CLEAR ls_student.

Work Area에 CLEAR를 쓰면 각 필드가 타입에 맞는 초기값으로 돌아갑니다. 문자 필드는 공백, 숫자 필드는 0에 가까운 초기 상태가 됩니다. 

CLEAR lt_students.

Header Line을 쓰지 않는 현대적인 Internal Table에서는 CLEAR lt_students로 테이블 내용을 비우는 용도로도 사용합니다. 초심자 단계에서는 “다음 작업 전에 깨끗하게 비운다”는 감각으로 보면 됩니다.

3. REFRESH와 FREE는 Internal Table 정리에서 만난다 🗑️

REFRESH는 예전 ABAP 코드에서 Internal Table의 내용을 비울 때 자주 보입니다. 

REFRESH lt_students.

새 코드에서는 CLEAR lt_students를 더 자연스럽게 쓰는 경우가 많지만, 기존 시스템에서는 REFRESH를 읽을 수 있어야 합니다.

FREE는 Internal Table 내용을 비우는 것에 더해, 할당된 메모리를 반환하는 의미까지 가집니다. 

FREE lt_students.

대량 데이터를 담았던 Internal Table을 더 이상 쓰지 않을 때는 FREE를 고려할 수 있습니다.

4. 전체 예제로 정리 흐름 보기 ✍️

REPORT zclear_refresh_free.

TYPES: BEGIN OF ty_student,
         id    TYPE char3,
         name  TYPE char20,
       END OF ty_student.

DATA: lt_students TYPE STANDARD TABLE OF ty_student,
      ls_student  TYPE ty_student,
      lv_count    TYPE i.

ls_student-id = 'A01'.
ls_student-name = 'Mina'.
APPEND ls_student TO lt_students.

lv_count = lines( lt_students ).
WRITE: / '비우기 전 줄 수:', lv_count.

CLEAR ls_student.
CLEAR lt_students.

lv_count = lines( lt_students ).
WRITE: / 'CLEAR 후 줄 수:', lv_count.

FREE lt_students.

실행하면 CLEAR 후 줄 수가 0이 됩니다. FREE는 이후 더 이상 해당 Internal Table을 쓰지 않을 때 메모리 정리 의도를 드러내는 역할을 합니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: CLEAR로 Work Area를 비우면 이전 필드 값이 다음 줄에 섞이지 않습니다.
  • ✅ 테이블 비우기: CLEAR 또는 REFRESH 후 Internal Table 줄 수가 0이 됩니다.
  • ✅ 메모리 반환 의도: FREE는 큰 Internal Table을 더 이상 쓰지 않을 때 메모리 정리 의미를 드러냅니다.
  • ❌ 초기화 누락: Work Area를 재사용하면서 일부 필드만 채우면 이전 값이 남을 수 있습니다.
  • ❌ 비운 뒤 사용: CLEAR/FREE 후에도 데이터가 남아 있다고 가정하면 출력이나 검색이 실패합니다.

미니 실습으로 CLEAR lt_students. 줄을 주석 처리해보세요. 줄 수 출력이 어떻게 달라지는지 보면 비우기 동작을 확실히 확인할 수 있습니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

REFRESH는 기존 코드 읽기용으로 자주 만납니다

REFRESH는 오래된 ABAP 코드에서 Internal Table을 비우는 용도로 자주 등장합니다. 신규 코드에서는 팀 기준에 따라 CLEAR나 FREE를 더 명확히 선택하는 경우가 많으니, 프로젝트 컨벤션을 확인하세요.

또한 FREE를 남발한다고 프로그램이 자동으로 빨라지는 것은 아닙니다. 대량 데이터 처리 후 더 이상 사용하지 않는 테이블처럼, 의도가 분명한 곳에 쓰는 것이 좋습니다.

Chapter 7 마무리 핵심

  • CLEAR는 변수, 구조, Internal Table을 초기 상태로 돌립니다.

  • FREE는 내용을 비우고 메모리 반환 의도까지 표현합니다.
  • Work Area 재사용 전 초기화는 이전 값 섞임을 막는 안전 습관입니다.
