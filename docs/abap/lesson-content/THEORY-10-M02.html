학습 목표

지난 Lesson에서 Range Table의 네 칸 구조를 배웠습니다. 이번에는 SELECT-OPTIONS 기본 문법을 사용해 Selection Screen에 범위 입력 필드를 만들고, 그 결과로 생성되는 Selection Table을 이해합니다.

1. PARAMETERS와 SELECT-OPTIONS의 차이 🧭

PARAMETERS는 한 값을 입력받는 데 좋습니다. 예를 들어 국가 코드 하나만 받는다면 PARAMETERS p_land1로 충분합니다.

하지만 사용자가 여러 국가 코드, 범위, 제외 조건을 입력해야 한다면 SELECT-OPTIONS가 필요합니다. SELECT-OPTIONS는 화면에는 입력 필드처럼 보이지만, 내부적으로는 Range Table 형태의 Selection Table을 만들어줍니다.

SELECT-OPTIONS는 사용자 입력을 Range Table 구조로 받아주는 Selection Screen 문법입니다.

2. 기본 문법 보기 ✍️

ABAP
1
2
3
4
5 
REPORT zselect_options_basic.

DATA gv_land1 TYPE t005t-land1.

SELECT-OPTIONS s_land1 FOR gv_land1.

이 코드를 실행하면 Selection Screen에 s_land1이라는 범위 입력 필드가 생깁니다. 사용자는 단일값, 범위, Multiple Selection 팝업을 통해 여러 조건을 넣을 수 있습니다.

  • gv_land1: SELECT-OPTIONS가 참조할 타입 기준입니다.
  • s_land1: 화면 입력 필드이자 내부 Selection Table입니다.
  • FOR gv_land1: 어떤 타입의 값을 받을지 정합니다.

3. s_land1은 사실 Range Table처럼 생겼다 📦

Selection Table은 SELECT-OPTIONS가 자동으로 만들어주는 Range Table입니다. 내부적으로는 SIGN, OPTION, LOW, HIGH 필드를 가진 여러 줄 조건표입니다.

ABAP
1
2
3
4
5
6 
LOOP AT s_land1 INTO DATA(ls_range).
  WRITE: / ls_range-sign,
           ls_range-option,
           ls_range-low,
           ls_range-high.
ENDLOOP.

사용자가 화면에서 입력한 조건이 실제로 어떤 Range Table 줄로 들어왔는지 확인할 수 있습니다. 디버거에서 s_land1을 펼쳐보는 것도 좋은 연습입니다.

REPORT zselect_options_check.

DATA gv_land1 TYPE t005t-land1.

SELECT-OPTIONS s_land1 FOR gv_land1.

START-OF-SELECTION.

  IF s_land1 IS INITIAL.
    WRITE: / '입력된 선택 조건이 없습니다.'.
  ELSE.
    LOOP AT s_land1 INTO DATA(ls_range).
      WRITE: / ls_range-sign,
               ls_range-option,
               ls_range-low,
               ls_range-high.
    ENDLOOP.
  ENDIF.

실행 후 단일값 KR을 넣어보고, Multiple Selection에서 여러 값을 넣어보세요. 출력되는 SIGN/OPTION/LOW/HIGH가 어떻게 달라지는지 보는 것이 핵심입니다.

화면 입력이 조건표 줄로 바뀌는 순간

1. 사용자가 화면에 입력
단일값 칸KR
범위 칸A ~ C
2. s_land1 내부 (Selection Table)
SIGNOPTIONLOWHIGH
IEQKR
IBTAC
3. 조회에서의 의미
"KR이거나, A부터 C 사이인 값"
활용WHERE land1 IN @s_land1

SELECT-OPTIONS는 입력칸을 그려줄 뿐 아니라, 입력 내용을 SIGN/OPTION/LOW/HIGH 줄로 자동 번역해 Selection Table에 담아줍니다. 개발자는 그 표를 IN 조건으로 넘기기만 하면 됩니다.

5. 정상 흐름과 오류 흐름으로 확인하기 ✅

  • ✅ 정상 흐름: 사용자가 입력한 선택 조건이 s_land1 Selection Table에 Range 행으로 들어갑니다.
  • ✅ 빈 입력: 아무 값도 입력하지 않으면 s_land1이 비어 있을 수 있습니다.
  • ❌ 타입 기준 누락: FOR 뒤에 타입 기준이 되는 데이터 객체가 필요합니다.
  • ❌ 이름 착각: s_land1은 단일 변수 하나가 아니라 여러 줄 조건표입니다.

미니 실습으로 Selection Screen에서 단일값과 범위를 각각 입력한 뒤, 출력되는 option과 high 값을 비교해보세요.

6. 실무에서 조심해야 할 점 🚨

⚠️

SELECT-OPTIONS는 사용자에게 강력한 조건 입력 권한을 줍니다

사용자는 여러 값, 범위, 제외 조건을 넣을 수 있습니다. 편리한 만큼 조회 범위가 넓어질 수 있으므로, 필수 조건 여부와 권한, 성능 기준을 함께 설계해야 합니다.

또한 고객사마다 SELECT-OPTIONS 이름 규칙이 있습니다. 보통 s_ 접두어를 많이 쓰지만 프로젝트 기준을 따르는 것이 좋습니다.

7. 미니 실습: 입력과 내부 표 대조하기 🧪

✍️

실습 과제

  1. 예제 zselect_options_check를 실행하고 단일값 KR만 입력해 출력 줄을 확인합니다.
  2. 범위(A~C)를 입력하고 OPTION이 BT로 바뀌는 것을 확인합니다.
  3. Multiple Selection에서 값을 2개 이상 입력해 Selection Table에 줄이 여러 개 생기는 것을 확인합니다.
  4. 아무것도 입력하지 않고 실행해 “선택 조건 없음” 분기가 동작하는지 확인합니다.

완료 조건: 화면 입력 각각이 어떤 SIGN/OPTION/LOW/HIGH 줄로 번역되는지 예측하고 출력으로 맞히면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. PARAMETERS와 SELECT-OPTIONS의 가장 큰 차이는 무엇인가요?
  2. SELECT-OPTIONS s_land1 FOR gv_land1.에서 FOR 뒤의 변수는 어떤 역할을 하나요?
  3. SELECT-OPTIONS는 ABAP Cloud 환경에서도 사용할 수 있을까요?
정답/해설 보기
  1. 받을 수 있는 조건의 형태입니다. PARAMETERS는 단일 값 한 칸, SELECT-OPTIONS는 단일값·범위·여러 줄 조건을 담는 Selection Table을 만듭니다.
  2. 조건의 타입 기준입니다. 참조한 변수의 타입(길이·형식)에 맞춰 입력칸과 Selection Table의 LOW/HIGH 타입이 정해집니다.
  3. 아니요. SELECT-OPTIONS는 GUI Selection Screen을 만드는 문법이라 ABAP Cloud에서는 사용할 수 없고, TYPE RANGE OF 데이터 객체와 Fiori 필터로 대체합니다.

10. 한눈에 정리 🏁

📝

SELECT-OPTIONS 핵심

  • SELECT-OPTIONS는 범위 입력이 가능한 Selection Screen 필드를 만듭니다.
  • 생성된 변수는 단일값이 아니라 Selection Table입니다.
  • Selection Table은 SIGN, OPTION, LOW, HIGH 구조를 가집니다.
  • 사용자가 입력한 조건은 여러 Range 행으로 저장될 수 있습니다.
  • 편리한 만큼 조회 범위와 성능을 함께 생각해야 합니다.
