학습 목표

셀마다 편집 가능/비활성 같은 Cell Style(상태)을 주는 법을 배웁니다. Cell Color와 똑같이 Deep Structure를 쓰되, 색상 대신 LVC_T_STYL을 품는 구조를 익힙니다.

1. 지난 시간 연결: 색이 아니라 "상태"를 칸마다 🎚️

앞 Lesson에서 셀에 색을 줬습니다. 비슷하게, 셀마다 "이 칸은 편집 가능, 저 칸은 잠금" 같은 상태를 줄 수도 있습니다. 예: 신규 행만 입력 가능, 기존 행은 읽기 전용.

이것이 Cell Style이고, 구조는 Cell Color와 판박이입니다(색상 테이블 → 스타일 테이블로 바뀔 뿐).

2. 출력 구조에 스타일 테이블 품기 ✍️

TYPES: BEGIN OF ty_row,
         carrid TYPE s_carr_id,
         price  TYPE s_price,
         cellstyles TYPE lvc_t_styl,   "★ 셀 스타일 정보(Deep Structure)
       END OF ty_row.
" 특정 셀을 편집 가능/불가로
APPEND VALUE lvc_s_styl(
  fieldname = 'PRICE'
  style     = cl_gui_alv_grid=>mc_style_enabled )   "편집 가능
  TO <fs>-cellstyles.

" Layout에 스타일 필드 이름 알려주기
gs_layout-stylefname = 'CELLSTYLES'.
  • style: mc_style_enabled(편집 가능) / mc_style_disabled(비활성) 등 상수.
  • stylefname: Layout에 "셀 스타일 정보가 이 필드"라고 알려줌. (색상은 ctab_fname, 스타일은 stylefname — 둘은 별개!)

3. 색상(ctab) vs 스타일(style) 비교 🔍

🔗

헷갈리지 않게 짝 맞추기

  • 색: 구조 필드 LVC_T_SCOL ↔ Layout ctab_fname
  • 상태: 구조 필드 LVC_T_STYL ↔ Layout stylefname

둘 다 Deep Structure지만 담는 테이블 타입과 Layout 연결 필드가 다릅니다. 한 행에 색·스타일을 동시에 줄 수도 있습니다(필드 2개 다 둠).

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 셀별 스타일 채우고 stylefname 연결 → 칸마다 편집/잠금이 정확히 적용.
  • ❌ 오류 1: 색상용 ctab_fname에 스타일 필드를 잘못 연결 → 동작 안 함(짝을 맞춰야 함).
  • ❌ 오류 2: 셀을 편집 가능으로 열었지만 변경값 처리(검증·저장) 로직이 없음 → 입력이 반영 안 됨(편집 처리는 PRACTICAL 트랙).

5. 실무에서 조심할 점 🚨

⚠️

편집 가능 셀은 "그다음"이 더 중요

Cell Style로 셀을 편집 가능하게 만드는 것은 시작일 뿐입니다. 사용자가 바꾼 값을 받아 검증하고 DB에 안전하게 반영하는 처리(DATA_CHANGED 이벤트, COMMIT/ROLLBACK)가 뒤따라야 합니다. 이는 실무 트랙(PRACTICAL)에서 본격적으로 다룹니다. 지금은 "셀 단위로 상태를 줄 수 있다"는 구조만 정확히 잡으세요.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Cell Style은 셀마다 편집 가능/비활성 같은 상태를 줍니다.
  • 출력 구조에 LVC_T_STYL을 품고(Deep Structure), Layout의 stylefname으로 연결합니다.
  • 색은 ctab_fname, 스타일은 stylefname — 짝을 정확히 맞춥니다.
  • 편집 가능 셀은 변경값 검증·저장 처리가 뒤따라야 의미가 있습니다.
