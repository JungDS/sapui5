학습 목표

유지보수 화면을 자동으로 만들어주는 Table Maintenance Generator(TMG)와, 그렇게 만든 화면을 실행하여 데이터를 관리하는 트랜잭션 SM30의 원리를 배웁니다. 개발자가 코드 한 줄 코딩하지 않고도 견고한 데이터 입력/수정 시스템을 구축하는 흐름을 익힙니다.

1. 지난 시간 연결: 화면 개발, 언제 다 하고 있어? 😫

이전 레슨에서 여러 테이블을 묶어 데이터 편집을 지원하는 Maintenance View를 배웠습니다. 하지만 뷰(View)만 껍데기로 존재할 뿐, 정작 사용자가 데이터를 입력하고 수정할 화면(Screen)이 없다면 무용지물이겠죠?

화면을 만들기 위해 입력 칸을 배치하고, 저장 버튼을 달고, 데이터베이스 UPDATE/INSERT SQL 로직을 일일이 ABAP 코딩하는 것은 매우 번거롭고 시간이 오래 걸리는 작업입니다.

이러한 반복적인 유지보수 화면 개발을 클릭 몇 번으로 자동 해결해 주는 SAP의 비밀 무기가 있습니다. 바로 화면 자동 공장인 TMG와 데이터 관리 실행기인 SM30입니다!

2. TMG는 무엇인가?: 코딩 없는 화면 제조 공장 🏭

Table Maintenance Generator(TMG)는 테이블이나 유지보수 뷰(Maintenance View)를 바탕으로 데이터를 조회, 추가, 수정, 삭제(CRUD)할 수 있는 유지보수 다이얼로그(Maintenance Dialog) 화면을 자동으로 '찍어내는' DDIC 유틸리티 도구입니다.

💡

일상 비유: 구글 설문지 폼 메이커

데이터베이스의 필드 정보만 주면, 입력 상자와 저장 버튼이 달린 화면을 알아서 조립해 주는 서비스와 비슷해요. 개발자는 설정값 몇 개만 지정해주면 되고, 실제 동작하는 복잡한 입력 폼 코드는 SAP가 뒤에서 전부 자동으로 빌드합니다.

TMG 생성 시 설정하는 핵심 4요소

TMG를 빌드할 때 SE11 화면에서 다음과 같은 중요한 설계 정보들을 입력해야 합니다:

설정 항목 (Technical Option) 설명 및 선택 기준 핵심 팁 & 가이드
Authorization Group
(권한 그룹)		 이 유지보수 화면을 실행하고 수정할 수 있는 권한을 통제합니다. 권한 검사가 불필요한 테스트용 테이블의 경우 임시 그룹인 &NC&를 부여합니다.
Function Group
(펑션 그룹)		 TMG가 자동으로 생성하는 화면(Screen)과 변수, 모듈 풀 코드가 물리적으로 담길 그릇(패키지)입니다. 보통 ZFG_HR, ZFG_SALES와 같이 관련 모듈별 펑션 그룹을 미리 선언해두고 매핑합니다.
Maintenance Type
(유지보수 화면 타입)		 화면 단계를 One Step으로 할지, Two Step으로 할지 정의합니다.
  • One Step: 한 화면(표 형태)에서 직접 줄을 추가하고 즉시 수정합니다.
  • Two Step: 리스트 화면과 개별 상세 보기(상세 입력 폼) 화면이 분리됩니다.
Screen Number
(화면 번호)		 자동 생성될 화면의 번호를 매깁니다. 보통 4자리 숫자를 사용합니다. 'Find Screen Number' 버튼을 클릭하면 SAP가 사용하지 않는 화면 번호(예: 0001)를 자동으로 추천해 줍니다.

3. SM30: TMG 화면을 켜는 공용 뷰어 🖥️

TMG로 화면을 찍어냈다면, 사용자는 어떻게 이 화면을 실행할까요? 바로 표준 트랜잭션 코드인 SM30을 이용합니다.

사용자는 SM30에 들어가 가공하고자 하는 테이블이나 유지보수 뷰 이름을 입력한 뒤 Maintain(유지보수) 버튼을 누르면, TMG가 자동으로 조립해둔 화면이 짠 하고 나타나게 됩니다.

4. TMG ↔ SM30 아키텍처 및 데이터 흐름 시각화 🗺️

테이블/뷰 구조를 가지고 TMG가 소스 코드를 생성하고, 사용자가 SM30을 통해 데이터를 수정하여 최종적으로 데이터베이스 테이블에 저장되는 일련의 아키텍처 흐름을 보여줍니다.

TMG 화면 빌드 및 SM30 실행 데이터 바인딩 아키텍처

5. 정상 흐름과 특별한 기능: 검증과 이벤트 🔍

  • ✅ Foreign Key 자동 검증: SM30에서 잘못된 외래키 값을 입력하면, 화면 하단에 에러 메시지가 뜨며 저장이 차단됩니다. 개발자가 별도로 코딩하지 않아도 데이터 정합성을 철저히 지킵니다.
  • ✅ TMG Event 제어: 데이터가 저장될 때 특정 시간 정보를 자동으로 넣거나, 저장 직전 커스텀 체크 로직을 실행하고 싶다면 TMG Event 기능을 통해 ABAP 소스 코드를 원하는 시점에 끼워 넣을 수 있습니다.
  • ❌ 구조 변경 시 재생성 필수: 테이블에 신규 필드가 추가되거나 데이터 타입이 바뀌면, 반드시 TMG를 Rebuild(재생성) 해주어야 합니다. 안 그러면 화면 구조와 데이터베이스의 씽크가 맞지 않아 덤프(Runtime Error)가 발생하게 됩니다.

6. 실무에서 조심할 점: 전송요청서(TR) 지옥 탈출하기 🚨

⚠️

두 종류의 TR(Workbench vs Customizing)을 반드시 구분하세요!

초보 개발자가 가장 많이 하는 실수 중 하나는, 화면은 열심히 만들어 놓고 운영 서버(PRD)에서 화면이 열리지 않거나 설정 데이터가 유실되어 에러가 발생하는 것입니다. TMG의 생명주기는 다음과 같은 이관 규칙을 따릅니다:

  1. Workbench Request (개발 TR): TMG를 돌려 생성된 화면 번호, Function Group 모듈 등의 프로그램 껍데기(개발 객체)가 여기에 담깁니다.
  2. Customizing Request (커스터마이징 TR): SM30을 켜서 입력한 실제 테이블 데이터(회사 코드 설정 값 등)가 저장될 때 발행되는 TR입니다.

즉, TMG 자체를 이관하는 것과 데이터를 이관하는 것은 완전히 다른 전송 요청서에 기록되므로, 릴리즈 시 두 요청서가 모두 운영 시스템에 온전히 반영되었는지 반드시 교차 검증해야 데이터 유실 참사를 막을 수 있습니다.

7. 미니 실습: TMG 생성 및 SM30 테스트 🧪

✍️

실습 과제: 정훈영 사원의 부서 관리 시스템 만들기

신입 사원인 정훈영 사원은 인사 시스템의 부서 마스터 정보를 직접 관리하기 위해 TMG를 적용하고 SM30 화면을 띄워 데이터를 관리하는 업무를 맡았습니다.

  1. SE11로 접속하여 지난 시간에 생성했던 ZDEPT_MAINT 유지보수 뷰를 엽니다.
  2. 상단 메뉴에서 Utilities -> Table Maintenance Generator를 클릭합니다.
  3. 아래 설정 값을 입력하고 화면 상단의 Create (종이 모양 아이콘) 버튼을 클릭합니다:
    • Authorization Group: &NC& (권한 그룹 없음)
    • Function Group: ZFG_HR (인사 전용 펑션 그룹)
    • Maintenance Type: One Step 선택
    • Maintenance Screens: 'Find Screen Number(s)'를 눌러 자동으로 0001 제안 받아 채우기
  4. 생성이 완료되면, 새 창을 열어 트랜잭션 코드 SM30을 실행합니다.
  5. Table/View 칸에 ZDEPT_MAINT를 입력하고, **Maintain** 버튼을 누릅니다.
  6. New Entries 버튼을 클릭하고 다음과 같이 데이터를 채운 뒤 저장해 봅니다:
    부서코드 (DEPTID) 부서명 (DEPTNAME) 예산 (BUDGET) 담당자
    D01 개발팀 50,000,000 정훈영 (주인공 ✅)
    D02 영업팀 30,000,000 홍길동 (조연 1)
    D03 기획팀 40,000,000 심청 (조연 2)

완료 조건: TMG를 통해 유지보수 화면을 성공적으로 생성하고, SM30에서 데이터를 에러 없이 입력하고 변경 내용이 원본 테이블들에 영구 보관되었는지 확인하면 합격입니다.

8. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: Table Maintenance Generator (TMG) - DDIC 테이블로부터 뷰 유지보수 다이얼로그를 생성하는 전체 아키텍처 및 내부 원리를 학습합니다.
  • SAP Help Portal: Table Maintenance Dialog Architecture - 생성된 유지보수 화면 다이얼로그의 PBO/PAI 화면 흐름과 모듈 풀 기술 사양을 확인합니다.
  • SAP Help Portal: Transaction SM30 Operations - SM30을 이용해 데이터를 입력하고 변경 내역을 수집하는 Standard Recording Routine 기능의 설정을 확인합니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. TMG로 유지보수 화면을 생성할 때, 자동으로 만들어지는 Screen(화면)과 다이얼로그 제어용 ABAP 소스 코드가 저장되어 분류되는 DDIC 그릇은 무엇인가요?
  2. 유지보수 화면 타입(Maintenance Type)을 지정할 때, 'One Step'과 'Two Step'의 시각적인 작동 원리 차이는 무엇인가요?
  3. 테이블의 데이터 구조(신규 필드 추가 등)를 수정한 뒤 TMG 화면을 다시 빌드(Rebuild)하지 않고 SM30을 켜서 데이터를 수정하려 할 때 발생하는 심각한 문제는 무엇인가요?
정답/해설 보기
  1. Function Group (펑션 그룹)입니다. TMG 생성 시 개발자가 지정한 펑션 그룹 내부에 Screen과 제어 모듈이 생성되어 포함됩니다.
  2. One Step은 단일 리스트 화면(Table Control)에서 조회와 CUD를 동시에 수행하고, Two Step은 요약 목록을 보여주는 리스트 화면과 단일 데이터 세부 필드들을 보여주는 상세 입력 화면(Detail Screen)이 분리되어 제공됩니다.
  3. 물리 데이터베이스 구조와 TMG 생성 화면(Screen 구조 및 내부 변수)의 씽크가 맞지 않아, 런타임 오류(Runtime Error / DUMP)가 발생하며 시스템이 강제 종료됩니다. 따라서 구조를 바꾸면 반드시 TMG를 다시 Rebuild해주어야 합니다.

10. 한눈에 정리 🏁

📝

유지보수 도구 핵심 요약

  • TMG(Table Maintenance Generator)는 테이블/뷰 정보를 토대로 코딩 없이 CRUD 화면을 자동으로 찍어내는 도구입니다.
  • SM30은 TMG로 만들어진 화면을 호출하여 실제 비즈니스 데이터를 타이핑해 관리하는 트랜잭션입니다.
  • One Step과 Two Step의 화면 타입을 필요에 맞춰 선택하여 설계할 수 있습니다.
  • 개발 껍데기(Workbench TR)와 비즈니스 데이터(Customizing TR)는 이관 요청서가 다르므로 운영 반영 시 둘 다 누락이 없도록 챙겨야 합니다.
