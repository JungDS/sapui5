학습 목표

DDIC 1차에서 데이터의 모양을 만들었다면, 이제 그 데이터를 다루는 ABAP Program의 첫 줄을 작성합니다. REPORT, Comment, Activation, Execution이 어떤 순서로 이어지는지 익혀봅니다.

1. 지난 Chapter 연결: 창고를 만들었으니 이제 움직여보자 🚀

Chapter 1에서는 Domain, Data Element, Structure, Transparent Table을 만들며 “데이터가 어떤 모양으로 존재하는가”를 배웠습니다. 그런데 데이터 창고만 있다고 업무가 자동으로 돌아가지는 않습니다. 누군가 데이터를 읽고, 계산하고, 화면에 보여주는 프로그램을 작성해야 합니다.

ABAP에서 가장 가볍게 시작할 수 있는 프로그램 형태가 REPORT Program입니다. 처음에는 복잡한 화면이나 버튼을 만들지 않고, 소스 코드를 실행해서 결과 목록을 보는 방식으로 연습합니다.

오늘의 목표는 “Hello ABAP”을 띄우기 전에, ABAP 프로그램이 어떤 최소 구조로 시작되는지 이해하는 것입니다.

2. REPORT는 프로그램의 이름표이자 시작 선언 🏷️

ABAP 프로그램 파일의 가장 위쪽에는 보통 REPORT 문이 옵니다. REPORT는 “이 소스는 실행 가능한 리포트 프로그램입니다”라고 시스템에 알려주는 첫 선언입니다.

💡

가장 작은 ABAP 프로그램

ABAP
1
2
3 
REPORT zhello_abap.

WRITE 'Hello ABAP!'.

zhello_abap은 프로그램 이름입니다. 실무에서는 고객 개발 객체에 보통 Z 또는 Y로 시작하는 이름을 붙입니다. 회사별 네이밍 규칙이 있으면 그 규칙을 따릅니다.

여기서 문장 끝의 마침표 .도 중요합니다. ABAP은 문장의 끝을 마침표로 구분합니다. 줄바꿈만 했다고 문장이 끝나는 것이 아닙니다. 초반에 가장 자주 만나는 오류가 바로 마침표 누락입니다.

3. Comment는 미래의 나에게 남기는 메모 📝

Comment는 프로그램 실행에는 영향을 주지 않는 설명입니다. 지금은 내가 코드를 썼으니 다 기억날 것 같지만, 한 달 뒤의 나는 생각보다 많은 걸 잊습니다. 주석은 그때의 나와 동료를 위한 작은 안내판입니다.

  • 전체 줄 주석: 줄 맨 앞에 *를 씁니다.
  • 인라인 주석: 코드 뒤에 큰따옴표 "를 쓰고 설명을 붙입니다.
ABAP
1
2
3
4 
REPORT zhello_abap.

* 첫 ABAP 출력 연습

WRITE 'Hello ABAP!'. " 화면에 문장을 출력한다

주석은 많을수록 좋은 것이 아닙니다. WRITE가 출력한다는 사실처럼 코드만 봐도 알 수 있는 내용은 짧게 두고, “왜 이렇게 했는지”, “주의할 업무 규칙이 무엇인지”를 남기는 쪽이 더 좋습니다.

4. 저장, 활성화, 실행은 서로 다르다 ⚙️

초심자가 헷갈리기 쉬운 부분입니다. 코드를 저장했다고 바로 실행 가능한 상태가 되는 것은 아닙니다. ABAP 개발에서는 저장 → 활성화 → 실행 흐름을 구분해서 봐야 합니다.

  • 저장: 내가 쓴 소스를 시스템에 보관합니다. 아직 문법 오류가 있을 수 있습니다.
  • Activation: 문법과 참조 객체를 검사해, 다른 사용자가 쓸 수 있는 활성 버전으로 만듭니다.
  • Execution: 활성화된 프로그램을 실제로 실행합니다. SAP GUI나 ADT에서 보통 F8 실행을 사용합니다.
⚠️

저장만 하고 실행하려 하면 막힐 수 있어요

문법 오류가 남아 있거나 활성화가 실패한 프로그램은 제대로 실행되지 않습니다. “분명 저장했는데 왜 안 되지?”라고 당황하기 전에 활성화 결과 메시지를 먼저 확인하세요.

5. 정상 흐름과 오류 흐름을 함께 보기 🔎

이제 첫 프로그램의 흐름을 정상 케이스와 오류 케이스로 나눠봅시다.

  • ✅ 정상 흐름: REPORT zhello_abap. 작성 → WRITE 'Hello ABAP!'. 작성 → 활성화 성공 → 실행 → 출력 목록에 문장이 표시됩니다.
  • ❌ 마침표 누락: WRITE 'Hello ABAP!'처럼 문장 끝 마침표를 빼면 문법 오류가 납니다.
  • ❌ 이름 규칙 오류: 고객 개발 프로그램인데 표준 SAP 네임스페이스처럼 이름을 만들면 생성이 막히거나 운용 규칙에 어긋날 수 있습니다.
ABAP 초반 실력은 거창한 로직보다 “오류 메시지를 읽고 어느 줄이 문제인지 찾는 습관”에서 자랍니다.

6. 실무에서 조심해야 할 점 🚨

회사마다 개발 객체 이름, 패키지, 전송 요청, 주석 스타일에 대한 관행이 있습니다. 하지만 고객사 관행을 SAP 표준 동작과 섞어서 외우면 나중에 헷갈립니다.

⚠️

“실행된다”와 “좋은 프로그램이다”는 다릅니다

첫 Lesson에서는 실행되는 코드가 목표지만, 실무에서는 권한, 오류 처리, 유지보수성, 네이밍, 전송 절차까지 함께 봅니다. 지금은 과하게 확장하지 않되, 실행 성공만 보고 끝내지 않는 태도를 기억해두세요.

7. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • REPORT는 실행 가능한 ABAP 리포트 프로그램의 시작 선언입니다.
  • ABAP 문장은 마침표 .로 끝납니다.
  • Comment는 코드의 이유와 주의점을 남기는 설명입니다.
  • 저장, Activation, Execution은 서로 다른 단계입니다.
  • 실행되는 코드보다 오류 메시지 확인과 유지보수성까지 보는 습관이 중요합니다.
