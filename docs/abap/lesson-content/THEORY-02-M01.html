학습 목표

이번 Lesson에서는 실행 가능한 가장 작은 ABAP Program을 직접 써 봅니다. REPORT 선언이 무엇을 뜻하는지, Comment(주석)는 어떻게 남기는지, 그리고 저장 → Activation(활성화) → Execution(실행)이 왜 서로 다른 단계인지를 초심자 기준으로 잡습니다.

1. 지난 Chapter 연결: 창고를 만들었으니 이제 움직여 보자

Chapter 1에서는 Domain, Data Element, Structure, Transparent Table을 만들며 “데이터가 어떤 모양으로 존재하는가”를 배웠습니다. 그런데 데이터 창고만 있다고 업무가 자동으로 돌아가지는 않습니다. 누군가 데이터를 읽고, 계산하고, 화면에 보여주는 프로그램을 작성해야 합니다.

ABAP에서 가장 가볍게 시작할 수 있는 형태가 REPORT 프로그램입니다. 복잡한 화면이나 버튼 없이, 소스 코드를 실행해서 결과 목록(Output List)을 보는 방식이라 첫 연습에 딱 맞습니다.

오늘의 목표는 “Hello ABAP”을 띄우는 것 자체가 아니라, ABAP 프로그램이 어떤 최소 구조로 시작되고 어떤 단계를 거쳐 실행되는지를 이해하는 것입니다.

2. ABAP 프로그램의 최소 구조: REPORT 한 줄에서 시작한다

실행 가능한 ABAP 프로그램의 첫 줄에는 보통 REPORT 문이 옵니다. REPORT는 “이 소스는 실행 가능한 리포트 프로그램입니다”라고 시스템에 알리는 시작 선언입니다. 그 아래에 실제로 일을 시키는 문장(예: WRITE)을 적습니다.

ABAP
1
2
3 
REPORT zhello_abap.

WRITE 'Hello ABAP!'.

WRITE 'Hello ABAP!'.

.
한 문장의 끝 표시

zhello_abap은 프로그램 이름입니다. 고객 개발 객체는 보통 Z 또는 Y로 시작하는 이름을 씁니다(회사 네이밍 규칙이 있으면 그 규칙 우선).

⚠️

문장의 끝은 줄바꿈이 아니라 마침표(.)

ABAP은 줄을 바꿨다고 문장이 끝나는 것이 아니라 마침표로 문장의 끝을 판단합니다. 한 문장을 여러 줄에 걸쳐 써도 되고, 마침표를 빠뜨리면 다음 문장까지 한 덩어리로 읽혀 문법 오류가 납니다. 초심자가 가장 자주 만나는 오류가 바로 마침표 누락입니다.

3. Comment(주석): 미래의 나와 동료에게 남기는 메모

Comment는 프로그램 실행에는 전혀 영향을 주지 않는 설명입니다. 지금은 내가 방금 썼으니 다 기억날 것 같지만, 한 달 뒤의 나는 생각보다 많은 걸 잊습니다. 주석은 그때의 나와 동료를 위한 작은 안내판입니다. ABAP에는 주석을 다는 방법이 두 가지 있습니다.

두 가지 주석 방식

전체 줄 주석 — 별표 *
  • 줄 맨 앞 첫 칸에 *를 둡니다.
  • 그 줄 전체가 주석이 됩니다.
  • 블록 설명, 작성 이유를 적을 때.
인라인 주석 — 큰따옴표 "
  • 코드 뒤에 "를 쓰고 설명을 붙입니다.
  • " 뒤부터 줄 끝까지 주석입니다.
  • 특정 한 줄을 짧게 보충할 때.

별표는 “줄 맨 앞”에 있을 때만 전체 줄 주석입니다. 코드 중간의 곱셈 기호 *와 혼동하지 마세요.

ABAP
1
2
3
4 
REPORT zhello_abap.

* 첫 ABAP 출력 연습 (전체 줄 주석)
WRITE 'Hello ABAP!'.   " 화면에 문장을 출력한다 (인라인 주석)

주석은 많을수록 좋은 것이 아닙니다. WRITE가 출력한다는 사실처럼 코드만 봐도 아는 내용은 짧게 두고, “왜 이렇게 했는지”, “어떤 업무 규칙 때문인지”를 남기는 쪽이 훨씬 가치 있습니다.

4. 저장 · 활성화 · 실행은 서로 다른 단계

초심자가 가장 헷갈리는 지점입니다. 코드를 저장했다고 바로 실행 가능한 상태가 되는 것은 아닙니다. ABAP 개발에서는 저장 → 활성화 → 실행을 구분해서 봐야 합니다.

첫 프로그램이 결과를 내기까지의 4단계

1. 작성REPORT·주석·WRITE를 에디터(SE38 또는 ADT)에 입력한다.
2. 저장Inactive 소스를 보관한다. 아직 문법 오류가 있을 수 있다.
3. 활성화문법·참조를 검사해 실행 기준이 되는 활성 버전을 만든다.
4. 실행 (F8)Active 활성 버전을 실행해 Output List를 본다.
왜 저장과 활성화를 굳이 나눌까?

저장은 “작업 중인 초안을 비활성 버전으로 보관”한 상태에 가깝습니다. 활성화는 문법과 참조 관계를 검사해 “이제 런타임이 믿고 실행해도 된다”는 기준 버전으로 올리는 단계입니다. 그래서 저장만 한 변경은 마지막으로 성공한 활성 버전의 동작에 영향을 주지 않습니다.

⚠️

“분명 저장했는데 왜 안 바뀌지?”

문법 오류가 남아 있거나 활성화가 실패한 프로그램은 옛 활성 버전대로 동작하거나 실행이 막힙니다. 당황하기 전에 활성화 결과 메시지를 먼저 확인하는 습관을 들이세요.

5. 정상 흐름과 오류 흐름을 함께 보기

ABAP 초반 실력은 거창한 로직보다 “오류 메시지를 읽고 어느 줄이 문제인지 찾는 습관”에서 자랍니다. 같은 첫 프로그램을 정상 케이스와 대표적인 오류 케이스로 나눠 봅시다.

정상 흐름 vs 자주 만나는 오류

작성REPORT + WRITE '...'. (마침표 포함)
활성화검사 통과
실행Output List에 Hello ABAP! 표시
작성WRITE 'Hello ABAP!' — 끝 마침표 누락
활성화실패 문법 검사에서 문장 끝을 못 찾음
고치기오류 줄에 마침표 추가 후 재활성화
작성고객 개발인데 표준 네임스페이스처럼 이름 지정
생성/저장막힘 네이밍·패키지 규칙 위반
고치기Z/Y 등 허용된 이름으로 재지정

오류는 실력 부족의 신호가 아니라 “어디를 고치면 되는지 알려주는 안내”입니다. 메시지의 줄 번호부터 확인하세요.

6. 미니 실습: 첫 프로그램 실행 기록 남기기

실제 SAP 시스템이 없어도, 또는 연습 시스템이 있다면 그 위에서, 아래 단계를 따라 입력값·결과·오류 케이스를 한 세트로 기록해 보세요.

✍️

실습 과제

  1. 프로그램 이름을 정합니다. 예: zhello_abap.
  2. REPORT 문과 WRITE 문을 작성합니다.
  3. 전체 줄 주석 1개와 인라인 주석 1개를 추가합니다.
  4. 일부러 마침표 하나를 빼고 활성화해, 어떤 오류 메시지가 나는지 적습니다. (오류 케이스 기록)
  5. 마침표를 고쳐 활성화하고 실행 결과(Output List)를 적습니다. (정상 결과 기록)

완료 조건: 저장·활성화·실행을 각각 다른 단계로 설명할 수 있고, 마침표 누락 오류를 스스로 찾아 고칠 수 있으면 성공입니다.

활성화가 막히는 대표 원인 보기
  • 문장 끝 마침표(.)를 빠뜨렸다.
  • 문자열 따옴표 '를 한쪽만 닫았다.
  • 고객 개발인데 이름이 네임스페이스·패키지 규칙에 맞지 않는다.

7. 실무에서 조심해야 할 점

🚨

“실행된다”와 “좋은 프로그램이다”는 다릅니다

첫 Lesson에서는 실행되는 코드가 목표지만, 실무에서는 권한, 오류 처리, 유지보수성, 네이밍, 전송(Transport) 절차까지 함께 봅니다. 지금은 과하게 확장하지 않되, 실행 성공만 보고 끝내지 않는 태도를 기억해 두세요.

  • 표준과 커스텀을 섞어 외우지 않기: SAP 표준 동작과 고객사 커스텀 관행(네이밍·패키지·주석 스타일)은 구분해 기록합니다.
  • 선행 지식·유지보수성까지 확인: 단순히 돌아가는 코드보다, 왜 그렇게 썼는지와 다음에 고치기 쉬운지를 함께 봅니다.
  • 지금은 과확장 금지: 변수·조건·반복·문자열은 이어지는 Lesson에서 깊게 다룹니다. 이 단계에서 미리 끌어오지 않습니다.

9. 확인 퀴즈

  1. ABAP에서 한 문장의 끝을 표시하는 기호는 무엇인가요?
  2. 전체 줄 주석과 인라인 주석은 각각 어떤 기호로 시작하나요?
  3. 저장만 하면 항상 최신 코드가 실행될까요? 그 이유는?
  4. REPORT 문은 어떤 역할을 하나요?
정답/해설 보기
  1. 마침표 .입니다. ABAP은 줄바꿈이 아니라 마침표로 문장 끝을 판단합니다.
  2. 전체 줄 주석은 줄 맨 앞의 별표 *, 인라인 주석은 코드 뒤의 큰따옴표 "입니다.
  3. 아니요. 저장은 비활성 버전 보관이고, 실행 기준이 되는 활성 버전은 활성화를 거쳐야 만들어집니다.
  4. 이 소스가 실행 가능한 리포트 프로그램임을 선언하는 시작 문입니다.
