학습 목표

이번 Lesson에서는 실행 가능한 가장 작은 ABAP Program을 직접 만들고 실행해 봅니다. 첫 줄 REPORT 선언이 무슨 뜻인지, 주석은 *와 " 중 무엇으로 어디에 다는지, 그리고 SE38·SE80에서 저장 → 활성화 → 실행(F8)이 왜 서로 다른 단계인지를 손으로 익힙니다.

1. 지난 Chapter 연결: 창고를 지었으니 이제 일꾼을 부른다

Chapter 1에서는 Domain·Data Element·Structure·Table을 만들며 “데이터가 어떤 모양으로 저장되는가”를 배웠습니다. 하지만 창고만 있다고 업무가 돌아가지는 않습니다. 데이터를 읽고, 계산하고, 화면에 보여 주는 프로그램이 있어야 합니다.

그 첫걸음이 바로 “실행 가능한 가장 작은 프로그램”을 직접 만들어 보는 것입니다. 이번 Lesson은 화면 가득한 문법이 아니라, 프로그램 한 개가 태어나서 실행되기까지의 흐름을 손에 익히는 데 집중합니다.

오늘의 핵심 한 줄: “REPORT로 시작해서, 저장하고, 활성화한 뒤에야 비로소 실행된다.”

2. 프로그램의 뼈대: 왜 첫 줄이 REPORT일까?

모든 실행 가능한 ABAP 프로그램은 문법적으로 반드시 REPORT <프로그램명>. 한 줄로 시작합니다. 이 선언은 시스템과 컴파일러에게 “이 프로그램은 데이터를 조회해 화면에 뿌리는 Executable Program(Type 1)이다”라고 알려 주는 역할을 합니다.

REPORT 한 줄이 만드는 프로그램의 두 구역

① REPORT 선언
REPORT z_hello_abap.
프로그램 타입을 도입
항상 맨 첫 줄
→
② 전역 선언부
DATA, TYPES …
변수·타입을 미리 선언
(다음 Lesson 주제)
→
③ 처리 블록
START-OF-SELECTION.
실제 로직이 실행되는 곳
WRITE 출력 등

오늘은 ①과 ③의 가장 작은 형태만 다룹니다. ②(DATA/TYPES)는 바로 다음 Lesson에서 자세히 배웁니다.

이름 규칙: 반드시 Z 또는 Y로 시작

SAP가 기본 제공하는 표준 프로그램과 우리가 만든 커스텀 프로그램을 시스템이 구분하려면, 고객이 만드는 모든 객체 이름은 Z 또는 Y로 시작해야 합니다(예: Z_HELLO_ABAP). 이 규칙을 어기면 시스템이 “표준 객체를 고치려는 것”으로 보고 생성을 막거나 접근 키를 요구합니다.

아래가 우리가 만들 “가장 작은 프로그램”입니다. 아직 외울 필요는 없습니다. 첫 줄이 REPORT이고, 문장 끝마다 마침표(.)가 찍힌다는 것만 눈에 담으세요.

ABAP
1
2
3
4 
REPORT z_hello_abap.

START-OF-SELECTION.
  WRITE 'Hello, ABAP!'.
문장은 무슨 규칙으로 끝나나요?

ABAP 문장(Statement)은 키워드로 시작해서 마침표(.)로 끝납니다 — 예외가 없습니다. 단어 사이는 최소 한 칸 띄우고, 한 문장이 여러 줄에 걸쳐도 됩니다. 마침표를 빠뜨리는 것이 초심자의 가장 흔한 구문 오류입니다.

3. 주석 두 가지: *(별표)와 "(큰따옴표)

주석(Comment)은 컴파일러가 무시하는 설명 글입니다. 코드를 설명하거나, 잠시 실행되지 않게 막아 둘 때 씁니다. ABAP에는 두 종류가 있고, 어디에 쓸 수 있는지가 다릅니다.

두 주석의 위치 규칙

* 전체 줄 주석
위치반드시 1열(맨 앞)
범위그 줄 전체가 주석
주의중간에 *를 쓰면 주석이 아님
" 인라인 주석
위치어느 열이든 가능
범위"부터 줄 끝까지
용도코드 오른쪽에 짧은 설명
ABAP
1
2
3
4
5 
REPORT z_hello_abap.

* 이 줄은 1열의 별표로 시작 → 줄 전체가 주석입니다
START-OF-SELECTION.
  WRITE 'Hello, ABAP!'.   " 코드 뒤의 큰따옴표 → 여기부터 줄 끝까지 주석

자주 하는 착각 바로잡기

착각
  • *를 줄 중간에 넣어도 주석이 될 것이다.
  • 주석은 한 종류뿐이다.
  • 주석도 실행에 영향을 준다.
사실
  • *는 1열일 때만 전체 줄 주석. 중간에 쓰면 구문 오류.
  • 줄 전체는 *, 코드 뒤 인라인은 ".
  • 컴파일러가 무시하므로 실행 결과는 그대로다.

4. 어디로 들어가서 만들까: SE38 · SE80 · SA38

프로그램을 만들고 실행하려면 먼저 어느 화면(T-code)으로 들어갈지를 알아야 합니다. SAP GUI 명령창(왼쪽 위 입력칸)에 트랜잭션 코드를 입력해 이동합니다. 같은 “프로그램”을 다루지만 입구마다 성격이 조금씩 다릅니다.

세 입구 비교 — 탭을 눌러 진입 경로를 확인하세요

SE38(ABAP Editor)는 소스 코드를 쓰고 바로 실행하는 가장 기본 진입점입니다. 첫 프로그램을 만들 때 가장 직관적입니다.

명령창/nSE38 입력
이름 입력Z_HELLO_ABAP → [Create]
속성Title·Type=Executable
코딩→실행저장·활성화 후 F8

SE80(Object Navigator)는 패키지를 중심으로 프로그램·클래스·화면을 트리 구조로 한눈에 관리하는 통합 워크벤치입니다. 객체가 많아질수록 진가가 드러납니다.

명령창/nSE80 입력
트리 탐색패키지/프로그램 선택
우클릭 CreateProgram 생성
같은 흐름저장·활성화·실행

SA38은 소스를 편집하지 않고 이름만으로 실행만 하는 화면입니다. 운영(PRD) 서버에서는 보통 SE38은 막고 SA38만 열어, 현업이 코드 수정 없이 리포트를 돌리게 합니다.

명령창/nSA38 입력
이름 입력실행할 프로그램명
F8편집 없이 실행만

이번 Lesson의 주인공은 SE38입니다. 위 칩 바에서 신규/복습 트랜잭션을 한 번 더 확인해 보세요.

/n은 무슨 뜻인가요?

명령창에서 /n은 “현재 작업을 닫고 새 트랜잭션으로 이동”을 뜻합니다. /nSE38이면 어디에 있든 SE38로 깔끔하게 넘어갑니다. /o를 쓰면 새 창(세션)으로 엽니다.

5. 저장 ≠ 활성화: 프로그램이 실행되기까지의 흐름

초심자가 가장 많이 헷갈리는 지점입니다. 저장(Save)은 작업 내용을 보관할 뿐이고, 활성화(Activation)를 해야 시스템이 실제로 실행할 수 있는 버전이 만들어집니다.

첫 프로그램이 실행되기까지 5단계

1. 작성에디터에 REPORT + WRITE
2. 저장Inactive Ctrl+S — 나에게만 보이는 버전
3. 검사Ctrl+F2 — “No syntax errors”
4. 활성화Active Ctrl+F3 — 실행 가능한 런타임
5. 실행F8 — 출력 리스트 확인

Save vs Activate, 무엇이 다른가

Save (저장)
  • 상태: Inactive(비활성) 버전
  • 지금 수정한 내가 보는 버전
  • 다른 사용자/시스템은 아직 못 씀
Activate (활성화)
  • 상태: Active(활성) 버전
  • 컴파일된 런타임 객체로 승격
  • 비로소 정상 호출·실행 가능
⚠️

저장만 하고 실행하면 “옛날 코드”가 돈다

코드를 고친 뒤 저장(Ctrl+S)만 하고 활성화 없이 F8을 누르면, 시스템은 방금 고친 코드가 아니라 마지막으로 활성화해 둔 예전 버전을 실행합니다. “분명히 고쳤는데 화면이 그대로”라면 십중팔구 활성화를 빠뜨린 것입니다. 꼭 Ctrl+F3로 활성화하세요.

6. 직접 해보기: SE38에서 첫 프로그램 만들고 실행하기

아래 sandbox는 실제 SAP 시스템이 없어도 SE38의 작업 순서를 그대로 눌러 보는 미니 실습입니다. 프로그램 이름과 제목을 바꿔 실행해 보세요. 이름을 일부러 Z/Y 없이 넣으면 네임스페이스 검증에서 막히는 것을 직접 확인할 수 있습니다.

T-Code: SE38 (ABAP Editor)
첫 ABAP 프로그램 생성 시뮬레이터
버튼을 누르면 SE38 진입부터 F8 실행까지의 흐름과 출력 결과가 단계별로 표시됩니다.
이름을 HELLO(Z 없이)로 바꾸면 왜 막히나요?

Z/Y로 시작하지 않으면 시스템은 “SAP 표준 객체를 만들려 한다”고 보고 생성을 거부하거나 접근 키를 요구합니다. 그래서 실습에서도 네임스페이스 검증을 통과하지 못하면 다음 단계로 넘어가지 않습니다. Z_ 접두사를 붙여 다시 실행해 보세요.

최신 환경(ADT/ABAP Cloud)에서는 입구가 다릅니다

지금 배우는 SE38·SE80은 Classic SAP GUI의 개발 방식입니다. 최신 ABAP Cloud 개발은 Eclipse 기반 ADT(ABAP Development Tools)를 쓰며, 프로그램은 패키지에서 우클릭 New → ABAP Program으로 만들고, 화면을 띄우는 대신 콘솔 앱 형태로 실행하기도 합니다. 지금은 Classic 흐름으로 원리를 익히되, 현장에 따라 도구가 달라진다는 점만 기억하세요. 또한 학습용 $TMP(로컬 객체)에 저장하면 나중에 다른 시스템으로 이송(Transport)되지 않으니, 팀 개발에서는 정식 패키지를 씁니다.

9. 확인 퀴즈

  1. 실행 가능한 ABAP 프로그램의 첫 줄은 항상 무엇으로 시작하나요?
  2. 전체 줄 주석 *는 반드시 몇 열에 와야 하나요? 인라인 주석 "는 어디에 올 수 있나요?
  3. 저장(Save)과 활성화(Activate) 중, 시스템이 실제로 실행할 수 있는 버전을 만드는 단계는 무엇인가요?
  4. 커스텀 프로그램 이름은 어떤 글자로 시작해야 하나요?
  5. SE38과 SA38의 가장 큰 차이는 무엇인가요?
정답/해설 보기
  1. REPORT <프로그램명>.입니다. 이 선언이 “실행 가능 프로그램(Type 1)”임을 시스템에 알립니다.
  2. *는 1열(맨 앞)일 때만 줄 전체 주석이 됩니다. "는 어느 열이든 올 수 있고, 그 지점부터 줄 끝까지가 주석입니다.
  3. 활성화(Activate)입니다. 저장은 비활성 버전 보관이고, 활성화해야 실행 가능한 런타임 버전이 됩니다.
  4. Z 또는 Y로 시작해야 합니다(고객 네임스페이스).
  5. SE38은 소스를 편집·실행하는 개발 입구이고, SA38은 편집 없이 이름만으로 실행만 하는 화면입니다.
