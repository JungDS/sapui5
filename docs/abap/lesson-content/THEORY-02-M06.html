학습 목표

ABAP 기본 문법 Chapter를 마무리하며 String, SY-DATUM, SY-UNAME, SY-SUBRC를 익힙니다. 문자열을 만들고, 시스템이 자동으로 채워주는 값을 읽고, 처리 성공 여부를 확인하는 감각을 잡습니다.

1. 지난 시간 연결: 반복과 조건만으로는 정보가 부족하다 🧭

지금까지 우리는 프로그램을 만들고, 값을 선언하고, 출력하고, 조건과 반복을 배웠습니다. 이제 프로그램은 꽤 움직일 수 있습니다. 하지만 실제 업무 프로그램은 “오늘 날짜가 무엇인지”, “누가 실행했는지”, “방금 찾기가 성공했는지” 같은 주변 정보도 자주 필요합니다.

SAP는 이런 기본 정보를 시스템 필드로 제공합니다. 시스템 필드는 프로그램이 직접 계산하지 않아도 SAP 런타임이 자동으로 채워주는 값입니다.

2. String: 길이가 유연한 문자열 다루기 💬

String은 길이가 고정되지 않은 문자열 타입입니다. 짧은 이름부터 긴 메시지까지 비교적 편하게 담을 수 있습니다.

ABAP

REPORT zstring_basic.

DATA gv_name    TYPE string VALUE 'ABAP'.
DATA gv_message TYPE string.

CONCATENATE 'Hello' gv_name INTO gv_message SEPARATED BY space.

WRITE gv_message.

CONCATENATE는 여러 문자열을 이어 붙입니다. SEPARATED BY space는 단어 사이에 공백을 넣겠다는 뜻입니다. 결과는 Hello ABAP처럼 보입니다.

초심자 체크: 고정 길이 코드에는 c LENGTH 3 같은 타입이 어울리고, 메시지처럼 길이가 유동적인 텍스트에는 string이 편합니다.

3. SY-DATUM과 SY-UNAME: 오늘 날짜와 실행 사용자 📅

SY-DATUM은 현재 시스템 날짜를 담고, SY-UNAME은 현재 프로그램을 실행한 사용자 ID를 담습니다.

ABAP
1
2
3
4 
REPORT zsystem_fields.

WRITE: / '오늘 날짜:', sy-datum,
       / '실행 사용자:', sy-uname.
  • sy-datum: 날짜 값입니다. 보통 내부적으로 YYYYMMDD 형태로 이해하면 됩니다.
  • sy-uname: 현재 로그인한 SAP 사용자 ID입니다.

이런 값은 로그, 출력 제목, 기본 입력값, 간단한 확인 메시지에서 자주 쓰입니다. 단, 사용자 이름을 보고 권한을 직접 판단하는 식의 코드는 위험할 수 있습니다. 권한 처리는 별도의 권한 체크 원칙을 따라야 합니다.

4. SY-SUBRC: 방금 실행한 명령의 성공 여부 확인 ✅

SY-SUBRC는 많은 ABAP 문장이 실행된 뒤 결과 코드를 담는 시스템 필드입니다. 보통 0이면 성공, 0이 아니면 실패나 다른 상태로 해석합니다.

ABAP

2
3

REPORT zsubrc_basic.

DATA gv_text TYPE string VALUE 'Hello ABAP'.

FIND 'ABAP' IN gv_text.

IF sy-subrc = 0.
  WRITE '문자열을 찾았어요'.
ELSE.
  WRITE '문자열을 찾지 못했어요'.
ENDIF.

위 예제에서 FIND가 문자열을 찾으면 sy-subrc가 0이 됩니다. 찾지 못하면 0이 아닌 값이 됩니다. 그래서 바로 다음 줄에서 IF sy-subrc = 0.으로 성공 여부를 확인합니다.

⚠️

SY-SUBRC는 바로 확인하세요

sy-subrc는 여러 문장이 실행되며 계속 바뀔 수 있습니다. 어떤 명령의 결과를 확인하려면 그 명령 바로 뒤에서 확인하는 습관이 중요합니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 문자열을 만들고 WRITE로 출력합니다. 날짜와 사용자도 시스템 필드로 출력됩니다.
  • ✅ 찾기 성공: FIND 'ABAP' IN gv_text.가 성공하면 sy-subrc = 0입니다.
  • ❌ 찾기 실패: 검색어가 없으면 sy-subrc가 0이 아니므로 실패 메시지를 출력합니다.
  • ❌ 늦은 확인: 중간에 다른 문장이 sy-subrc를 바꾸면 원래 확인하고 싶던 결과를 잃을 수 있습니다.

미니 실습으로 gv_text 값을 바꾸거나, FIND 검색어를 'UI5'로 바꿔보세요. 출력 메시지가 어떻게 달라지는지 보면 sy-subrc의 역할이 바로 느껴집니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

시스템 필드는 편하지만 과신하면 안 됩니다

sy-datum, sy-uname, sy-subrc는 자주 쓰이지만, 업무 판단을 전부 대신해주지는 않습니다. 날짜는 타임존과 업무 기준일을 고려해야 할 수 있고, 사용자 ID는 권한 체크를 대신하지 않습니다. sy-subrc도 어떤 문장이 어떤 값을 세팅하는지 문서와 문맥을 함께 봐야 합니다.

이번 단계에서는 시스템 필드를 “SAP가 자동으로 채워주는 기본 정보”로 이해하면 충분합니다. 더 깊은 날짜 처리, 권한, 데이터 조회 결과 처리는 이후 Lesson에서 자연스럽게 확장합니다.

7. 미니 실습: 시스템 필드 바로 확인하기 🧪

이번 실습은 Chapter 2 마무리용입니다. 문자열을 만들고, 현재 날짜와 사용자, 그리고 sy-subrc를 바로 확인하는 습관을 같이 연습합니다.

✍️

실습 과제

  1. sy-uname과 sy-datum을 이용해 실행자와 실행일을 출력합니다.
  2. CONCATENATE 또는 문자열 연결로 인사말을 만듭니다.
  3. FIND 'ABAP' IN gv_text. 뒤에서 바로 sy-subrc를 확인합니다.
  4. 검색어를 없는 단어로 바꾸고 결과 메시지가 달라지는지 확인합니다.

완료 조건: sy-subrc를 설정한 문장 바로 다음에서 확인해야 하는 이유를 설명할 수 있으면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. sy-datum과 sy-uname은 개발자가 직접 계산해 넣는 값인가요?
  2. 많은 ABAP 문장에서 sy-subrc = 0은 보통 어떤 의미인가요?
  3. FIND 뒤에 여러 문장을 실행한 다음 sy-subrc를 확인해도 항상 안전할까요?
정답/해설 보기
  1. 아니요. SAP 런타임이 자동으로 채워주는 시스템 필드입니다.
  2. 성공 또는 정상 처리를 뜻하는 경우가 많습니다. 다만 문장마다 의미가 다를 수 있으므로 문맥과 공식 문서를 함께 봐야 합니다.
  3. 안전하지 않습니다. 다른 문장이 sy-subrc를 다시 설정할 수 있으므로, 확인하려는 문장 바로 뒤에서 읽는 습관이 중요합니다.

10. 한눈에 정리 🏁

📝

Chapter 2 마무리 핵심

  • String은 길이가 유연한 문자열 타입입니다.
  • SY-DATUM은 현재 시스템 날짜를 담습니다.
  • SY-UNAME은 현재 실행 사용자의 ID를 담습니다.
  • SY-SUBRC는 많은 ABAP 문장의 실행 결과 코드를 담고, 보통 0이면 성공입니다.
  • sy-subrc는 다른 문장으로 바뀔 수 있으므로 확인할 명령 바로 뒤에서 봅니다.

이것으로 REPORT, 선언, WRITE, 조건, 반복, 시스템 필드까지 ABAP 기본 문법의 첫 바퀴를 돌았습니다. 다음 Chapter PARAMETERS 기반 Selection Screen 맛보기에서는 사용자가 화면에서 값을 입력하고, 그 값을 프로그램이 받아 출력하는 흐름으로 넘어갑니다.
