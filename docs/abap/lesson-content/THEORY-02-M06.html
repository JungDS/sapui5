학습 목표

이번 Lesson에서는 실무에서 매일 쓰는 세 가지를 익힙니다. 가변 길이 문자열 String 다루기, 오늘 날짜를 주는 SY-DATUM·로그인 사용자 SY-UNAME, 그리고 직전 실행 성공 여부를 알려 주는 SY-SUBRC입니다.

1. 지난 Lesson 연결: 이제 “현실의 값”을 다뤄 보자

값 선언·출력·분기·반복까지 ABAP의 뼈대를 익혔습니다. 이제 실제 업무에서 끊임없이 등장하는 재료들을 만질 차례입니다. 사람 이름·메시지 같은 문자열, 전표·로그에 꼭 들어가는 날짜와 사용자, 그리고 “방금 그 작업이 성공했나?”를 알려 주는 시스템 필드입니다.

시스템 필드(SY-...)는 “시스템이 늘 채워서 들고 있는 공용 변수”입니다. 내가 만들지 않아도 항상 값이 들어 있습니다.

2. 문자열: 고정 문자(C)와 가변 문자열(String)

문자 데이터는 길이가 고정된 C와, 내용에 따라 늘어나는 String이 있습니다. 이름·설명처럼 길이를 모르는 값은 STRING이 편합니다. 문자열을 합칠 때는 && 연산자나 문자열 템플릿(|...|)을 씁니다.

REPORT zstring_demo.

DATA lv_first TYPE string VALUE 'ABAP'.
DATA lv_last  TYPE string VALUE 'Developer'.
DATA lv_full  TYPE string.

lv_full = lv_first && ` ` && lv_last.   " 연결: ABAP Developer
WRITE / lv_full.

lv_full = |{ lv_first } { lv_last }|.    " 문자열 템플릿도 동일 결과
WRITE / lv_full.
작은따옴표 '...' 와 백틱 `...` 은 뭐가 다를까?

작은따옴표 리터럴('...')은 고정 문자(C) 취급이라 뒤쪽 공백이 잘릴 수 있고, 백틱 리터럴(`...`)은 문자열(string) 취급이라 공백이 보존됩니다. 그래서 단어 사이 공백을 넣을 때 백틱을 쓰면 안전합니다.

3. 시스템 필드: 시스템이 늘 채워 주는 값들

SY-로 시작하는 시스템 필드는 SAP가 자동으로 채워 둡니다. 그중 초심자가 가장 자주 만나는 셋을 봅니다.

자주 쓰는 시스템 필드 3종

SY-DATUM
값오늘 날짜 (YYYYMMDD)
쓰임전표일, 생성일 기록
SY-UNAME
값로그인 사용자 ID
쓰임생성자/변경자 기록
SY-SUBRC
값직전 문장 결과 코드
쓰임0=성공, ≠0=실패/없음

현재 시간이 필요하면 SY-UZEIT(HHMMSS), 로그인 클라이언트는 SY-MANDT를 씁니다. 모두 시스템이 자동으로 채워 주는 값입니다.

WRITE: / '오늘 날짜:', sy-datum,
       / '실행 사용자:', sy-uname.

4. SY-SUBRC: “방금 그 작업, 성공했어?”

SY-SUBRC는 직전 문장이 성공했는지를 담습니다. 보통 0이면 성공, 0이 아니면 실패나 “결과 없음”입니다. 조회·읽기 직후에는 거의 항상 이 값을 확인해야 합니다.

REPORT zsubrc_demo.

DATA lv_text TYPE string VALUE 'ABAP'.

FIND 'BA' IN lv_text.
IF sy-subrc = 0.
  WRITE / '찾았습니다.'.
ELSE.
  WRITE / '없습니다.'.
ENDIF.
⚠️

SY-SUBRC는 “직전 한 문장” 기준입니다

검사할 문장 바로 다음 줄에서 확인해야 합니다. 중간에 다른 문장이 끼면 sy-subrc가 그 문장의 결과로 덮어써집니다. “읽자마자 바로 검사”가 원칙입니다.

5. 정상 흐름과 오류/혼동 흐름을 함께 보기

자주 하는 실수 vs 안전한 작성

❌ 자주 하는 실수
  • 조회와 sy-subrc 검사 사이에 다른 문장을 끼움.
  • 단어 사이 공백을 '...'로 넣어 공백이 사라짐.
  • 날짜를 문자열처럼 자유 형식으로 가정함.
✅ 안전한 작성
  • 조회 바로 다음 줄에서 sy-subrc 확인.
  • 공백·연결은 백틱(` `)이나 템플릿(|...|).
  • sy-datum은 8자리 YYYYMMDD로 다룸.

시스템 필드는 “읽기 전용으로 활용”이 기본입니다. 직접 값을 덮어쓰지 않습니다.

6. 미니 실습: 처리 로그 한 줄 만들기

✍️

실습 과제

  1. 이름과 메시지를 string으로 선언하고 && 또는 |...|로 한 문장으로 합칩니다.
  2. sy-datum과 sy-uname을 함께 출력해 “언제·누가” 로그 한 줄을 만듭니다.
  3. FIND로 특정 글자를 찾고 sy-subrc로 찾음/못 찾음을 분기 출력합니다.
  4. 일부러 조회와 검사 사이에 WRITE를 끼워 sy-subrc가 바뀌는지 확인합니다. (혼동 케이스)
  5. 검사를 바로 다음 줄로 옮겨 올바르게 동작시킵니다. (정상 결과)

완료 조건: 시스템 필드의 역할을 설명하고, sy-subrc를 “직전 문장 바로 뒤”에서 확인하는 이유를 말할 수 있으면 성공입니다.

7. 실무에서 조심해야 할 점

🚨

시스템 필드는 “지금·여기”의 값이라 휘발적입니다

sy-subrc·sy-index처럼 자주 바뀌는 시스템 필드는 필요한 순간 즉시 읽어 별도 변수에 담아 두는 것이 안전합니다. 나중에 쓰려고 미뤄 두면 그사이 다른 문장이 값을 바꿔 버립니다.

  • 읽기 전용 사용: 시스템 필드를 직접 덮어쓰지 않습니다(예측 불가한 부작용).
  • 날짜·시간대: sy-datum은 서버 기준입니다. 사용자/시간대 차이가 중요한 업무는 그 점을 별도로 고려합니다.
  • 표준 vs 커스텀: 시스템 필드 동작은 SAP 표준입니다. 로그 양식·필드 구성은 회사 관행이므로 분리해 기록합니다.
Modern ABAP / Cloud에서는 문자열·시스템 값을 어떻게 다룰까?

문자열 결합은 Classic의 CONCATENATE a b INTO c SEPARATED BY space. 대신, 최신 환경에서는 && 연산자나 문자열 템플릿 |{ a } { b }|로 한 줄에 처리합니다. 또 ABAP Cloud에서는 sy-datum·sy-uname을 직접 쓰는 것이 점차 제한(Not Released)되어, 표준 API cl_abap_context_info=>get_system_date( )·get_user_technical_name( )로 값을 얻도록 권장합니다(타임존·일관성 관리 때문).

9. 확인 퀴즈

  1. 오늘 날짜와 로그인 사용자를 담는 시스템 필드는 각각 무엇인가요?
  2. SY-SUBRC가 0이면 무엇을 뜻하나요?
  3. SY-SUBRC는 왜 검사 대상 문장 “바로 다음 줄”에서 확인해야 하나요?
  4. 단어 사이 공백을 안전하게 넣으려면 '...'와 `...` 중 무엇이 나은가요?
정답/해설 보기
  1. 오늘 날짜는 SY-DATUM, 로그인 사용자는 SY-UNAME입니다.
  2. 직전 문장이 성공했다는 뜻입니다(0이 아니면 실패/결과 없음).
  3. 다음 문장이 실행되면 그 결과로 값이 덮어써지기 때문입니다.
  4. 백틱 `...`입니다. 문자열로 취급되어 공백이 보존됩니다.
