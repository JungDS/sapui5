지난 Lesson에서 SELECT-OPTIONS가 Selection Table을 만든다는 것을 배웠습니다. 이번에는 WHERE field IN @range 형태로 Range Table 조건을 Open SQL 조회에 연결합니다.

1. 입력 조건을 조회 조건으로 연결하기 🧭

SELECT-OPTIONS만 선언하면 사용자가 조건을 입력할 수는 있습니다. 하지만 그 조건을 Open SQL에 연결하지 않으면 실제 조회 범위에는 영향을 주지 않습니다.

사용자가 입력한 Range Table 조건을 데이터베이스 조회에 적용할 때 자주 쓰는 문법이 WHERE field IN @range입니다.

SELECT-OPTIONS는 조건을 받고, WHERE IN은 그 조건으로 데이터를 걸러냅니다.

DATA gv_land1 TYPE t005t-land1.

SELECT-OPTIONS s_land1 FOR gv_land1.

SELECT FROM t005t
  FIELDS land1, landx
  WHERE spras = @sy-langu
    AND land1 IN @s_land1
  INTO TABLE @DATA(lt_countries).

여기서 land1은 데이터베이스 필드이고, s_land1은 사용자가 입력한 Selection Table입니다. @s_land1처럼 @를 붙여 ABAP 쪽 Range Table을 SQL 조건으로 전달합니다.

  • field IN range: 필드 값이 Range Table 조건에 포함되는지 확인합니다.
  • @s_land1: ABAP Selection Table을 SQL로 넘깁니다.
  • spras 조건: 텍스트 테이블에서 현재 언어 텍스트만 가져오기 위한 조건입니다.

REPORT zsql_where_in_range.

DATA gv_land1 TYPE t005t-land1.

SELECT-OPTIONS s_land1 FOR gv_land1.

START-OF-SELECTION.

  SELECT FROM t005t
    FIELDS land1, landx
    WHERE spras = @sy-langu
      AND land1 IN @s_land1
    INTO TABLE @DATA(lt_countries).

  IF lt_countries IS INITIAL.
    WRITE: / '조회 결과가 없습니다.'.
  ELSE.
    LOOP AT lt_countries INTO DATA(ls_country).
      WRITE: / ls_country-land1, ls_country-landx.
    ENDLOOP.
  ENDIF.

Selection Screen에서 KR, US를 여러 값으로 넣으면 두 국가 텍스트가 조회됩니다. 범위를 넣으면 해당 범위의 국가 코드가 조회 조건에 들어갑니다.

5. 비어 있는 Range는 어떻게 처리될까? 🪧

⚠️

빈 Range Table = 전체 조회 허용!

Range Table이 비어 있으면, SQL의 IN 조건은 항상 참(True)으로 평가됩니다. 즉, 아무런 필터링을 하지 않고 테이블의 전체 데이터를 조회하게 됩니다.

이것은 사용자가 "아무런 제한을 두지 않고 전체를 보겠다"는 의도일 때는 편리하지만, 수천만 건이 넘는 대용량 테이블에서는 시스템 다운을 유발하는 치명적인 성능 문제를 일으킬 수 있습니다.

따라서 초심자 단계에서는 다음 두 질문을 습관처럼 해보세요.

  • 조건이 비어 있을 때 전체 조회를 허용해도 되는 테이블인가?
  • 너무 많은 데이터가 조회되어 성능 장애를 유발할 위험은 없는가?

6. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 사용자가 입력한 Selection Table 조건이 WHERE land1 IN @s_land1로 정상 필터링됩니다.
  • ✅ Multiple Selection 대응: 여러 값이나 범위를 복잡하게 입력해도 단 하나의 IN 조건으로 완벽하게 처리됩니다.
  • ❌ 호스트 변수 기호(@) 누락: Open SQL에서 ABAP 변수/Range Table을 넘길 때 @를 빠뜨리면 구문 오류가 발생합니다.
  • ❌ 타입 불일치: 비교 대상 DB 필드와 Range Table의 LOW/HIGH 타입이 서로 호환되지 않으면 런타임 에러가 발생할 수 있습니다.
  • ❌ 빈 조건으로 인한 메모리 폭발: 조건이 비어 있을 때 대량 조회가 발생하는 것을 방지하는 방어 코드가 없으면 시스템 성능이 극도로 저하됩니다.

7. 실무에서 조심해야 할 점 🚨

⚠️

IN 조건은 편리하지만 대량 조회를 경계하세요

SELECT-OPTIONS는 개발자가 쿼리를 여러 번 짤 필요 없이 다중 입력을 알아서 해결해 주어 매우 강력합니다. 하지만 운영 환경에서는 필수 검색 항목(OBLIGATORY)을 지정하거나, 최대 조회 기간을 강제하는 등 대용량 데이터 조회 방어 조치가 필수적입니다.

8. 미니 실습: 조건에 따른 조회 분기 테스트 🧪

✍️

실습 과제

  1. 예제 코드 zsql_where_in_range를 생성하고 활성화합니다.
  2. Selection Screen에서 국가 코드에 KR을 입력한 뒤 실행하여 한국 데이터가 정상 조회되는지 확인합니다.
  3. 조건창에 아무것도 입력하지 않고 실행했을 때 전체 국가 목록이 다 출력되는지 관찰합니다.
  4. 코드에서 WHERE land1 IN @s_land1 앞의 호스트 변수 기호 @를 일부러 지워보고 ADT가 어떤 구문 에러를 주는지 확인합니다.

완료 조건: 조건 입력값의 유무에 따라 SQL이 어떻게 전체 조회와 조건 조회를 넘나드는지 원리를 설명할 수 있으면 성공입니다.

10. 확인 퀴즈와 정답/해설 ✅

  1. Range Table이 비어 있는 상태에서 WHERE field IN @range가 실행되면 결과는 어떻게 되나요?
  2. Open SQL 구문에서 ABAP 변수나 Range Table명을 적을 때 왜 앞에 @ 기호를 붙여야 하나요?
  3. WHERE field IN @range 조건에서 field의 데이터 타입과 Range Table(range)의 LOW/HIGH 필드 타입은 어때야 하나요?
정답/해설 보기
  1. 해당 IN 조건이 항상 참(True)이 되어 전체 데이터를 조회하게 됩니다. 조건 필터링이 생략된 것과 같은 효과를 냅니다.
  2. 데이터베이스 지시어와 ABAP 프로그램의 호스트 변수를 구분하기 위해서입니다. @가 없으면 데이터베이스 테이블의 필드로 오인하여 구문 에러가 납니다.
  3. 두 필드의 데이터 타입은 서로 호환 가능(Compatible)해야 합니다. 타입이 아예 다르면 값을 비교할 수 없어 구문 에러나 런타임 에러가 발생합니다.

11. 한눈에 정리 🏁

📝

WHERE IN 핵심 정리

  • WHERE field IN @range는 Range Table의 다중 조건을 한번에 SQL 조건으로 바인딩합니다.
  • SELECT-OPTIONS로 생성된 Selection Table은 이 문법을 통해 SQL과 바로 연결됩니다.
  • ABAP 변수나 Range Table명 앞에는 반드시 호스트 변수 기호인 @를 붙여야 합니다.
  • 빈 Range Table은 전체 조회를 의미하므로 대량 조회 방어 대책이 필요합니다.
