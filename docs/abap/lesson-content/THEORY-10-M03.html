학습 목표

지난 Lesson에서 SELECT-OPTIONS가 Selection Table을 만든다는 것을 배웠습니다. 이번에는 WHERE field IN @range 형태로 Range Table 조건을 Open SQL 조회에 연결합니다.

1. 입력 조건을 조회 조건으로 연결하기 🧭

SELECT-OPTIONS만 선언하면 사용자가 조건을 입력할 수는 있습니다. 하지만 그 조건을 Open SQL에 연결하지 않으면 실제 조회 범위에는 영향을 주지 않습니다.

사용자가 입력한 Range Table 조건을 데이터베이스 조회에 적용할 때 자주 쓰는 문법이 WHERE field IN @range입니다.

SELECT-OPTIONS는 조건을 받고, WHERE IN은 그 조건으로 데이터를 걸러냅니다.

2. 기본 구조 보기 🔍

DATA gv_land1 TYPE t005t-land1.

SELECT-OPTIONS s_land1 FOR gv_land1.

SELECT FROM t005t
  FIELDS land1, landx
  WHERE spras = @sy-langu
    AND land1 IN @s_land1
  INTO TABLE @DATA(lt_countries).

여기서 land1은 데이터베이스 필드이고, s_land1은 사용자가 입력한 Selection Table입니다. @s_land1처럼 @를 붙여 ABAP 쪽 Range Table을 SQL 조건으로 전달합니다.

  • field IN range: 필드 값이 Range Table 조건에 포함되는지 확인합니다.
  • @s_land1: ABAP Selection Table을 SQL로 넘깁니다.
  • spras 조건: 텍스트 테이블에서 현재 언어 텍스트만 가져오기 위한 조건입니다.

3. 전체 예제로 조회하기 ✍️

REPORT zsql_where_in_range.

DATA gv_land1 TYPE t005t-land1.

SELECT-OPTIONS s_land1 FOR gv_land1.

START-OF-SELECTION.

  SELECT FROM t005t
    FIELDS land1, landx
    WHERE spras = @sy-langu
      AND land1 IN @s_land1
    INTO TABLE @DATA(lt_countries).

  IF lt_countries IS INITIAL.
    WRITE: / '조회 결과가 없습니다.'.
  ELSE.
    LOOP AT lt_countries INTO DATA(ls_country).
      WRITE: / ls_country-land1, ls_country-landx.
    ENDLOOP.
  ENDIF.

Selection Screen에서 KR, US를 여러 값으로 넣으면 두 국가 텍스트가 조회됩니다. 범위를 넣으면 해당 범위의 국가 코드가 조회 조건에 들어갑니다.

4. 비어 있는 Range는 어떻게 볼까? 🪧

SELECT-OPTIONS를 비워두면 “사용자가 특별히 제한하지 않았다”는 의미로 쓰이는 경우가 많습니다. 다만 빈 Range Table을 어떻게 처리할지에 대해서는 코드 위치와 문맥을 확인해야 합니다.

초심자 단계에서는 다음 두 질문을 습관처럼 해보세요.

  • 비어 있으면 전체 조회를 허용해도 되는가?
  • 너무 많은 데이터가 조회될 위험은 없는가?

필요한 경우 Selection Screen 검증에서 최소 한 조건을 요구하거나, 조회 전 사용자에게 안내할 수 있습니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 사용자가 입력한 Selection Table 조건이 WHERE land1 IN @s_land1로 적용됩니다.
  • ✅ Multiple Selection: 여러 값이나 범위를 입력해도 IN 조건 하나로 처리할 수 있습니다.
  • ❌ @ 누락: s_land1 앞의 @를 빼면 ABAP 변수 전달이 되지 않아 오류가 날 수 있습니다.
  • ❌ 타입 불일치: DB 필드와 Range Table의 LOW/HIGH 타입이 맞지 않으면 문제가 됩니다.
  • ❌ 무제한 조회: 조건이 비어 있거나 너무 넓으면 대량 조회 위험이 생깁니다.

미니 실습으로 Selection Screen에서 값 1개, 여러 값, 범위를 각각 넣고 조회 결과가 어떻게 달라지는지 비교해보세요.

6. 실무에서 조심해야 할 점 🚨

⚠️

IN 조건은 편하지만 조회 범위를 크게 만들 수 있습니다

SELECT-OPTIONS는 사용자가 많은 조건을 넣을 수 있어 편리하지만, 반대로 너무 넓은 범위를 허용할 수도 있습니다. 운영 Report에서는 필수 조건, 최대 범위, 권한 검사를 함께 고려해야 합니다.

이번 Lesson은 단일 필드 IN 조건에 집중합니다. 여러 테이블 JOIN과 복합 조건은 후속 Open SQL 심화에서 다룹니다.

7. 한눈에 정리 🏁

📝

WHERE IN 핵심

  • WHERE field IN @range는 필드 값을 Range Table 조건으로 필터링합니다.
  • SELECT-OPTIONS로 만든 Selection Table을 Open SQL 조건에 바로 연결할 수 있습니다.
  • @는 ABAP 쪽 Range Table을 SQL에 전달하는 표시입니다.
  • 타입이 맞아야 하고, 비어 있거나 넓은 조건은 대량 조회 위험을 만들 수 있습니다.
  • 조건 입력과 조회 조건은 한 세트로 검증해야 합니다.
