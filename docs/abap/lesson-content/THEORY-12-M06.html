학습 목표

지금까지 배운 Classic View들의 한계를 명확히 짚어보고, 현대 SAP 아키텍처의 중심인 CDS View Entity로의 전환 방향성(현대화)을 배웁니다. 다음 Chapter로 넘어가기 전 고전과 현대의 데이터 모델링의 큰 그림을 맞춥니다.

1. 지난 시간 연결: 왜 이렇게 뷰의 종류가 많았을까? 🤯

이번 Chapter 12를 공부하면서 우리는 무려 4가지나 되는 고전 뷰(Classic View)들을 섭렵했습니다:

  • Database View: 테이블 여러 개 합치기(INNER JOIN)
  • Projection View: 필요한 필드만 골라서 솎아내기
  • Help View: F4 입력 도움말에 줄 리스트 공급하기
  • Maintenance View: 엑셀처럼 여러 테이블 데이터 편집하기

학습하면서 "아니, 그냥 테이블 엮어서 조회하고 편집하고 도움말 띄우는 걸 굳이 4개 객체로 찢어서 관리해야 하나?" 하는 의문이 들었을 것입니다.

실제로 SAP도 똑같은 고민을 거쳤고, 그 결과 탄생한 현대 SAP 개발의 핵심 기술이 바로 모든 기능을 코드로 하나에 때려 넣은 CDS View Entity입니다.

2. Classic View의 한계: 왜 변화가 필요했는가? 🧱

고전 4대 뷰는 수십 년간 SAP 시스템의 중추적인 역할을 해왔지만, 현대적인 비즈니스 요구사항을 처리하기에는 다음과 같은 한계에 봉착했습니다.

Classic View 4종의 치명적인 한계점

한계 항목 고전 방식 (Classic View)의 문제점 비즈니스에 미치는 영향
객체의 파편화 조회용, 도움말용, 수정용 뷰를 각각 SE11에서 따로 생성하고 관리해야 합니다. 동일한 테이블 관계 정보를 여러 뷰에 중복 정의하게 되어 변경 시 관리 비용이 증가합니다.
표현력의 한계 단순 JOIN이나 필드 제한 외에, 계산식, CASE 문 분기, 집계 연산(SUM, AVG) 등이 불가능합니다. 단순 가공을 위해서도 반드시 ABAP 프로그램 단에서 LOOP를 돌며 수동 코딩을 추가해야 합니다.
GUI 종속 및 확장 실패 주로 SAP GUI 화면 전용으로 최적화되어 설계되었습니다. 최신 웹 환경(SAP Fiori)이나 모바일, 외부 클라우드 시스템에 OData 서비스로 직접 확장하기 어렵습니다.
성능 최적화 부재 전통적인 RDBMS 기반으로 설계되어 대용량 데이터를 가져올 때 병목이 생깁니다. SAP HANA DB의 인메모리 파워를 100% 이끌어내지 못하고 WAS(애플리케이션 서버)에 부하가 집중됩니다.

3. CDS View Entity: 현대 SAP 데이터 모델의 구원자 🌟

CDS View Entity는 데이터베이스 레벨에서 SQL을 기반으로 고성능 데이터 모델을 정의하는 차세대 뷰 구조입니다. Classic View 4종의 역할을 완벽하게 통합하고 확장합니다.

💡

비유: 여러 개의 전용 장비 vs 최신 올인원 스마트폰

예전에는 삐삐(Help View), MP3(Projection View), 내비게이션(Database View), 전자수첩(Maintenance View)을 주머니에 주렁주렁 들고 다녔다면, 이제는 고성능 스마트폰(CDS View Entity) 하나가 이 모든 기능을 부드럽고 완벽하게 수행하는 것과 같아요!

CDS View Entity가 제공하는 혁신적인 3대 강점

  • ✅ SQL 기반 텍스트 코딩: 마우스 클릭 노가다 대신 이클립스 ADT에서 익숙한 SQL DDL 코드로 뷰를 코딩합니다. Git과 같은 최신 형상 관리 시스템과의 호환성이 극대화됩니다.
  • ✅ Annotation (어노테이션) 메타데이터: 코드 상단에 @UI.lineItem 또는 @Search.defaultSearchElement와 같은 어노테이션을 달아두면, SAP Fiori 웹 화면 레이아웃 설정과 Search Help 검색 기능까지 뷰 코드 자체에서 제어할 수 있습니다.
  • ✅ Association (연관 관계)의 도입: 일반 JOIN처럼 무조건 데이터를 합치지 않고, 사용자가 화면에서 해당 텍스트를 클릭하거나 상세 정보를 펼칠 때에만 런타임에 동적으로 JOIN을 수행하여 시스템 성능을 엄청나게 절약합니다.

4. Classic View ↔ CDS View Entity 아키텍처 구조 비교 🗺️

파편화된 기존 고전 뷰 아키텍처와, 통합된 CDS View Entity가 데이터베이스에서 웹 프레젠테이션 레이어까지 관통하는 현대 아키텍처의 차이를 시각적으로 확인해 봅시다.

데이터 모델 아키텍처 패러다임 시프트

5. 정상 흐름과 실무 적용 방향성 🔍

  • ✅ 신규 개발 표준: S/4HANA 이상의 최신 시스템에서는 가상 데이터 모델(VDM)에 근거하여 모든 신규 조회용 뷰를 CDS View Entity로 설계하는 것이 표준 권장사항입니다.
  • ✅ 기존 자산의 존중: 비록 고전 뷰가 노후화되었다 하더라도, 기존 레거시 프로그램과 스탠다드 로직에서 튼튼하게 작동하고 있다면 무리하게 변환하기보다 영향도를 파악하며 부분적으로 현대화를 적용해야 합니다.
  • ❌ 버전 확인 필수: CDS View Entity는 SAP NetWeaver 7.50 이상, 특히 S/4HANA 데이터베이스(HANA DB) 환경에서 그 파워가 극대화됩니다. 구버전 ECC 시스템에서는 문법 및 기능 지원 범위가 좁으므로 반드시 로컬 시스템 버전을 선행 점검해야 합니다.

6. 실무에서 조심할 점: "코드 푸시다운"에 숨겨진 함정 🚨

⚠️

모든 연산을 DB로 내리는 것만이 정답은 아닙니다!

CDS View의 가장 큰 장점 중 하나는 연산 로직을 데이터베이스 단에서 빠르게 처리하고 결과만 받아오는 코드 푸시다운(Code Pushdown) 기술입니다. 그러나 다음과 같은 오류를 방지해야 합니다:

  • 과도한 문자열 가공: 문자열 파싱, 결합, 포맷팅 등은 DB보다 Application Server(WAS) 메모리에서 가공하는 것이 오히려 더 효율적인 경우가 많습니다.
  • 복잡한 비즈니스 정책: 수시로 바뀌는 비즈니스 예외 규정이나 분기 로직을 전부 CDS SQL 코드(CASE WHEN 등)로 단단하게 굳혀버리면, 나중에 화면 기획이나 정책이 바뀌었을 때 SQL 전체를 뜯어고쳐야 하는 유지보수 헬게이트가 열릴 수 있습니다.

따라서, 대용량 필터링과 원천 데이터 집계는 DB(CDS)에 밀어 넣고, 미세한 문자열 렌더링이나 비즈니스 의사결정은 ABAP 로직에서 처리하도록 역할을 적절히 배분하는 지혜가 필요합니다.

7. 미니 실습: CDS View Entity 가상 설계 🧪

✍️

실습 과제: 정훈영 사원의 부서 정보 CDS 모델링 기획

정훈영 사원은 인사 정보를 웹 브라우저(Fiori) 화면에 출력하기 위해, 기존에 만들어 둔 ZDEPT(부서 마스터) 테이블과 ZDEPTT(언어 설명) 테이블을 엮어 하나의 현대식 CDS View Entity로 전환하는 설계를 가상으로 구현해 보려 합니다.

  1. 이클립스 ADT에서 새 Data Definition을 생성하고 이름은 ZDEMO_CDS_DEPT로 선언합니다.
  2. 소스 코드 에디터에서 다음과 같이 테이블 관계(Association)와 필드 매핑 DDL을 타이핑합니다:

8. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: ABAP CDS Entities - 현대 SAP 아키텍처 내에서 CDS View Entity의 공식 스펙과 데이터 모델링 규격을 심도 있게 배웁니다.
  • SAP Help Portal: CDS Associations - 일반 JOIN 대비 런타임 성능을 획기적으로 올려주는 CDS Association의 동적 Join 매커니즘과 선언 규격을 확인합니다.
  • SAP Help Portal: CDS Annotations Reference - `@UI`나 `@Search` 등 UI 프레젠테이션 및 시맨틱스 정의를 위한 메타데이터 어노테이션 사용법을 배웁니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. Classic View 4종(Database/Projection/Help/Maintenance)과 달리 CDS View Entity는 어떤 방식으로 데이터 모델을 선언하나요?
  2. CDS View Entity에서 일반 SQL JOIN 방식 대신 사용하며, 데이터가 화면에 표시되거나 요청될 때 필요한 경우에만 런타임에 결합을 수행하는 동적 관계 설계 방식을 무엇이라고 하나요?
  3. CDS View Entity 코드 상단이나 필드 위에 `@` 기호를 붙여 비즈니스적 설명, 검색 속성, 혹은 SAP Fiori UI 레이아웃 화면 표시 방법을 명시해 주는 메타데이터를 무엇이라고 부르나요?
정답/해설 보기
  1. 이클립스 ADT 환경에서 텍스트 기반 소스 코드로 SQL DDL 문법을 사용해 선언합니다. 이를 통해 객체 파편화를 막고 코드로써 버전 관리가 가능해집니다.
  2. Association (연관 관계)입니다. 이를 이용하면 정적 JOIN에 비해 데이터베이스 쿼리 성능이 획기적으로 개선됩니다.
  3. Annotation (어노테이션)입니다. 어노테이션을 통해 데이터 모델 자체가 프레젠테이션 레이어(UI)에 힌트를 주어 화면 배치를 주도할 수 있게 됩니다.

10. 한눈에 정리 🏁

📝

Chapter 12 최종 요약 및 현대화 핵심

  • Classic View는 Database, Projection, Help, Maintenance 4가지로 쪼개져 관리의 파편화 문제가 존재했습니다.
  • CDS View Entity는 고전 4종 뷰의 조회, 필터링, 도움말 기능 등을 하나의 모델로 스마트하게 통합합니다.
  • SQL 기반의 코딩, 성능을 보존하는 Association, UI 배치를 제어하는 Annotation이 CDS의 3대 무기입니다.
  • 신규 현대화 개발의 중심은 CDS이지만, 레거시 시스템 유지보수를 위해 고전 뷰의 작동 원리를 파악하는 것은 필수입니다.
