학습 목표

변수를 미리 선언하지 않고 쓰는 그 순간에 만드는 인라인 선언(Inline Declaration)을 배웁니다. DATA( )와 @DATA( )로 코드를 얼마나 짧고 깔끔하게 만드는지 익힙니다.

1. 지난 시간 연결: 선언과 사용이 멀리 떨어져 있다 📏

지금까지 우리는 변수를 항상 위에서 DATA로 먼저 선언하고, 아래에서 사용했습니다. 코드가 길어지면 "이 변수 타입이 뭐였지?" 하고 위로 스크롤해야 합니다.

최신 ABAP(7.40+)에서는 쓰는 그 자리에서 변수를 선언할 수 있습니다. 이것이 인라인 선언입니다. 선언과 사용이 한 줄에 붙어 코드가 훨씬 읽기 쉬워집니다.

DATA lv_count TYPE i.

DATA(lv_count) = 10.        "타입은 10을 보고 자동 추론(i)
  • DATA( ): 괄호 안 이름으로 변수를 즉석에서 만듭니다.
  • 타입 추론: 오른쪽 값을 보고 타입을 자동으로 정합니다. 타입을 따로 안 적어도 됩니다.

3. SELECT에서 빛나는 @DATA( ) ✨

인라인 선언이 가장 유용한 곳이 Open SQL입니다. 결과를 담을 Internal Table을 미리 만들 필요 없이 @DATA( )로 그 자리에서 만듭니다.

SELECT carrid, connid, price
  FROM sflight
  INTO TABLE @DATA(lt_flights).   "lt_flights가 딱 맞는 타입으로 자동 생성
💡

LOOP·READ에서도

LOOP AT lt INTO DATA(ls)., READ TABLE lt INTO DATA(ls) INDEX 1.처럼 LOOP·READ의 작업 영역도 인라인으로 만들 수 있습니다. ASSIGNING FIELD-SYMBOL(<fs>)도 같은 방식입니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 처음 값이 대입되는 그 자리에서 DATA( )로 선언 → 타입 자동, 코드 간결.
  • ❌ 오류 1: 이미 선언된 변수를 또 DATA( )로 선언 → 중복 선언 오류. 인라인은 "처음 만드는 자리"에서만.
  • ❌ 주의: 인라인 변수는 선언된 블록 안에서만 유효합니다. 블록 밖에서 쓰려면 미리 선언하는 편이 낫습니다.

5. 실무에서 조심할 점 🚨

⚠️

편하지만 타입이 "숨는다"는 점

인라인 선언은 타입을 자동 추론하기 때문에, 코드만 봐서는 변수 타입이 한눈에 안 보일 수 있습니다. 의도와 다른 타입이 추론되면 미묘한 버그가 됩니다. 타입이 중요하거나 명확히 드러내야 하는 경우엔 DATA lv TYPE ...로 명시하는 것도 좋은 선택입니다. 또 구버전 시스템(7.40 미만)에서는 지원되지 않으니 시스템 버전을 확인하세요.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • 인라인 선언은 변수를 쓰는 그 자리에서 DATA( )로 만듭니다.
  • 오른쪽 값을 보고 타입을 자동 추론합니다.
  • SELECT의 @DATA( ), LOOP/READ의 INTO DATA( )에서 특히 유용합니다.
  • 타입이 숨으니, 명확성이 중요할 땐 명시 선언도 고려합니다.
