학습 목표

사용자가 버튼을 누르거나 Enter를 친 직후 실행되는 PAI(Process After Input)를 배웁니다. 어떤 버튼을 눌렀는지 알려주는 OK_CODE를 읽어 동작을 분기하는 방법을 익힙니다.

1. 지난 시간 연결: 사용자가 행동했다 🖱️

PBO로 띄운 화면에서 사용자가 값을 입력하고 버튼을 눌렀습니다. 이제 프로그램이 그 행동에 반응해야 합니다. "저장 버튼이면 저장, 뒤로 버튼이면 이전 화면"처럼요.

이 반응을 처리하는 단계가 PAI(Process After Input)입니다. 사용자의 행동 직후 실행됩니다.

2. OK_CODE로 "무슨 버튼인지" 알기 ✍️

버튼을 누르면 그 버튼의 Function Code가 OK_CODE(화면에 연결된 특수 필드, 또는 sy-ucomm)로 전달됩니다. PAI에서 이 값을 보고 분기합니다. 

PROCESS AFTER INPUT.
  MODULE user_command_0100.

MODULE user_command_0100 INPUT.
  CASE ok_code.
    WHEN 'SAVE'.
      PERFORM save_data.        "저장 처리
    WHEN 'BACK' OR 'EXIT'.
      LEAVE TO SCREEN 0.        "화면 종료
  ENDCASE.
  CLEAR ok_code.               "다음을 위해 비워줌
ENDMODULE.
💡

OK_CODE는 꼭 CLEAR

처리 후 ok_code를 비우지 않으면, 다음에 Enter만 쳐도 직전 버튼이 또 눌린 것처럼 동작할 수 있습니다. 처리 끝에 CLEAR ok_code를 습관처럼 넣으세요.

3. 화면을 떠나는 방법 🚪

  • LEAVE TO SCREEN 0: 현재 화면을 닫고 호출한 곳으로 돌아갑니다(종료).
  • LEAVE TO SCREEN 0200: 다른 화면으로 이동합니다.
  • 아무것도 안 하면: 같은 화면이 유지되며 다시 PBO → 화면 표시가 반복됩니다.
PBO(준비) ↔ PAI(반응)가 번갈아 도는 것이 Dynpro의 생명 주기입니다. 사용자가 종료를 누를 때까지 이 박자가 반복됩니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: OK_CODE를 읽어 CASE로 분기 → 알맞은 동작 실행 → CLEAR.
  • ❌ 오류 1: CLEAR 누락 → 직전 명령이 반복 실행되는 유령 동작.
  • ❌ 오류 2: 입력 검증 없이 바로 저장 → 잘못된 데이터가 들어감. PAI에서 검증 후 저장합니다.

5. 실무에서 조심할 점 🚨

⚠️

저장 전 검증과 트랜잭션을 기억하세요

PAI의 저장 처리에서는 입력값 검증(존재·권한·형식)을 거친 뒤 DB에 반영해야 합니다. 그리고 DB 변경은 THEORY 이후 실무 트랙에서 배울 COMMIT/ROLLBACK으로 마무리해야 정합성이 지켜집니다. 지금은 "PAI에서 검증 후 처리한다"는 흐름만 확실히 잡으세요.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • PAI는 사용자가 버튼·Enter로 행동한 직후 실행됩니다.
  • OK_CODE(또는 sy-ucomm)로 어떤 버튼인지 읽어 CASE로 분기합니다.
  • 처리 후 CLEAR ok_code로 유령 동작을 막습니다.
  • LEAVE TO SCREEN으로 화면을 종료·이동하며, PBO↔PAI가 반복됩니다.
