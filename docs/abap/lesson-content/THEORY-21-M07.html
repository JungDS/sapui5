학습 목표

RAP에서 업무 규칙을 더하는 3대 도구 — 검증 Validation, 자동 계산 Determination, 사용자 동작 Action — 의 역할을 개요로 배웁니다.

1. 지난 시간 연결: 표준 동작을 넘어 "업무 규칙" 📐

create/update/delete 같은 표준 동작과 서비스 노출까지 됐습니다. 하지만 실제 업무에는 "종료일은 시작일 이후여야 한다", "요금은 자동 계산", "승인 버튼" 같은 고유 규칙이 필요합니다. RAP는 이를 세 가지 도구로 표현합니다.

2. 세 도구의 역할 ✍️

  • Validation(검증): 저장 전에 데이터가 규칙에 맞는지 확인. 틀리면 저장 차단. (예: 종료일 ≥ 시작일). Chapter 21의 Lesson 5에서 본 흐름과 연결됩니다.
  • Determination(결정/자동계산): 특정 시점에 값을 자동으로 채움. (예: 생성 시 상태='신규', 변경 시 총액 자동 합산).
  • Action(액션): 표준 CRUD 외의 사용자 동작. (예: '승인', '취소' 버튼). 화면 버튼으로 노출됨.

3. 언제 무엇을? 🧭

💡

한 문장 구분법

  • 막아야 하면 → Validation ("이건 틀렸어, 저장 못 해").
  • 자동으로 채워야 하면 → Determination ("이건 내가 알아서 채울게").
  • 버튼이 필요하면 → Action ("사용자가 누르면 이걸 해").

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 검증은 Validation, 자동값은 Determination, 특수 동작은 Action — 역할대로 배치.
  • ❌ 오류 1: 자동 계산을 Validation에서 하려다 흐름이 꼬임(검증은 "막기"만, 값 변경은 Determination).
  • ❌ 오류 2: Determination이 무한히 서로를 트리거 → 루프. 트리거 조건을 명확히 설계.

5. 실무에서 조심할 점 🚨

⚠️

역할을 섞으면 디버깅 지옥

Validation·Determination·Action은 실행 시점과 목적이 다릅니다. "검증인데 값을 바꾼다", "결정인데 저장을 막는다"처럼 역할을 섞으면, 나중에 "왜 이 값이 이렇게 됐지?"를 추적하기가 매우 어렵습니다. 각 도구를 본래 역할대로만 쓰는 것이 RAP를 깔끔하게 유지하는 비결입니다. 이 셋의 깊은 구현은 실무·Fiori 트랙에서 단계별로 익힙니다.

6. 미니 실습: Validation, Determination, Action 분류하기 🧪

이번 실습은 업무 규칙을 모두 IF문 하나로 처리하지 않고, RAP가 제공하는 세 도구에 맞게 분류하는 연습입니다.

✍️

실습 과제

  1. “금액은 0보다 커야 한다”, “상태 기본값을 NEW로 넣는다”, “승인 버튼을 누르면 상태를 APPROVED로 바꾼다”를 세 도구 중 어디에 둘지 나눕니다.
  2. Validation이 값을 직접 고치면 왜 역할이 섞이는지 적습니다.
  3. on modify와 on save 같은 트리거 시점이 결과에 어떤 차이를 만들 수 있는지 적습니다.

완료 조건: Validation은 검사, Determination은 자동 보정/계산, Action은 사용자가 요청하는 업무 동작이라고 설명할 수 있으면 성공입니다.

7. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: Determination and Validation Modelling - Validation과 Determination 모델링 기준을 확인합니다.
  • SAP Help Portal: Validation Definition - Validation 정의와 트리거 조건을 확인합니다.
  • SAP Help Portal: Determine Actions - Action과 side effect 관련 모델링 흐름을 확인합니다.

8. 확인 퀴즈와 정답/해설 ✅

  1. 값이 잘못되었는지 확인하고 메시지를 돌려주는 기능은 무엇인가요?
  2. 저장 전 기본값이나 파생 값을 채우는 규칙은 어디에 어울리나요?
  3. 사용자가 버튼으로 “승인” 같은 업무 동작을 실행하게 하려면 무엇을 사용하나요?
정답/해설 보기
  1. Validation입니다. 값이 유효한지 판단하고 실패 정보를 돌려주는 역할입니다.
  2. Determination입니다. 조건에 따라 값을 계산하거나 채우는 데 어울립니다.
  3. Action입니다. 표준 CRUD를 넘어선 사용자 요청 업무 동작을 표현합니다.

9. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Validation: 저장 전 검증, 틀리면 차단("막기").
  • Determination: 특정 시점 값 자동 채움("자동 채우기").
  • Action: CRUD 외 사용자 동작, 화면 버튼("누르면 실행").
  • 역할을 섞지 말고 본래 목적대로만 사용합니다.

RAP의 핵심 도구를 모두 봤습니다. 마지막 Lesson ABAP Cloud와 Released API 원칙에서, 이 모든 것이 돌아가는 현대 환경의 원칙을 정리하며 Track 1을 완성합니다.
