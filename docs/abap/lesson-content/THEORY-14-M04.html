학습 목표

화면을 사용자에게 보여주기 직전에 실행되는 PBO(Process Before Output)의 역할을 배웁니다. 화면에 값을 채우고, 상태(메뉴/툴바)를 세팅하고, 칸을 꾸미는 작업이 여기서 일어남을 익힙니다.

1. 지난 시간 연결: 화면을 띄우기 전 마지막 준비 🎬

앞에서 화면(0100)과 부품(Input/Button)을 만들었습니다. 그런데 화면이 떡 하니 뜨기 전에, "어떤 값을 미리 채울지", "메뉴·버튼을 어떻게 보일지"를 정해야 합니다.

그 마지막 준비 단계가 PBO(Process Before Output)입니다. 리포트의 INITIALIZATION + AT SELECTION-SCREEN OUTPUT을 합친 듯한 역할이라고 보면 이해가 쉽습니다.

  MODULE status_0100.

MODULE status_0100 OUTPUT.
  SET PF-STATUS 'STAT_0100'.   "메뉴/툴바 세팅
  SET TITLEBAR  'TITLE_0100'.  "창 제목
  gv_name = '홍길동'.           "화면 칸에 보일 값 채우기
ENDMODULE.
  • 값 채우기: 화면 Input Field와 연결된 변수에 표시할 값을 넣습니다.
  • 상태 세팅: SET PF-STATUS, SET TITLEBAR로 메뉴·툴바·제목을 정합니다(다음 Lesson M06).
  • 화면 꾸미기: 필요하면 LOOP AT SCREEN으로 칸을 숨기거나 비활성화합니다(THEORY-13-M03과 동일 원리).

3. PBO는 "보여주기 직전마다" 실행 🔁

PBO는 화면이 처음 뜰 때뿐 아니라, 화면이 다시 그려질 때마다 실행됩니다. 사용자가 버튼을 눌러 PAI가 돈 뒤 같은 화면으로 돌아오면, 다시 PBO가 실행되어 화면을 갱신합니다.

💡

비유: 무대 전환마다 세팅

막이 오르기 직전마다 무대 장치를 세팅하는 것과 같아요. 한 번만이 아니라, 장면이 바뀔 때마다 PBO가 다시 무대를 준비합니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: PBO에서 값·상태·레이아웃을 세팅 → 깔끔히 준비된 화면이 사용자에게 표시.
  • ❌ 오류 1: SET PF-STATUS를 안 하면 메뉴·툴바가 비어 버튼이 안 보임.
  • ❌ 오류 2: PBO에서 무거운 조회를 매번 실행 → 화면 전환마다 느려짐. 무거운 작업은 꼭 필요할 때만.

5. 실무에서 조심할 점 🚨

⚠️

PBO는 자주 실행된다는 걸 기억하세요

화면이 갱신될 때마다 PBO가 돌기 때문에, 여기에 매번 DB 조회나 복잡한 계산을 넣으면 사용자가 버튼 한 번 누를 때마다 느려집니다. "값이 처음 한 번만 필요한가, 매번 필요한가"를 구분해, 불필요한 반복을 피하세요.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • PBO는 화면을 보여주기 직전 실행되는 준비 단계입니다.
  • 값 채우기, SET PF-STATUS / SET TITLEBAR, 화면 꾸미기를 합니다.
  • 화면이 다시 그려질 때마다 반복 실행됩니다.
  • 자주 실행되므로 무거운 로직은 넣지 않습니다.
