학습 목표

이미 떠 있는 표를 데이터 변경 후 다시 그리는 REFRESH_TABLE_DISPLAY를 배웁니다. 사용자의 스크롤·선택을 유지하며 갱신하는 Stable Refresh(IS_STABLE)를 익힙니다.

1. 지난 시간 연결: 데이터가 바뀌었다 🔄

SET_TABLE_FOR_FIRST_DISPLAY로 표를 띄웠습니다. 그런데 사용자가 버튼을 눌러 데이터를 다시 조회하거나 값을 바꾸면, 표를 새 데이터로 다시 그려야 합니다.

이때 first_display를 또 부르면 표가 통째로 리셋됩니다(M07 주의). 대신 REFRESH_TABLE_DISPLAY를 쓰면 같은 표를 그 자리에서 갱신합니다.

2. 기본 Refresh ✍️

" 출력 테이블(gt_outtab) 내용을 바꾼 뒤
go_grid->refresh_table_display( ).

출력 테이블의 내용을 갱신하고 이 메서드를 부르면, 표가 새 데이터로 다시 그려집니다. 그런데 그냥 호출하면 사용자가 보고 있던 스크롤 위치와 선택이 처음으로 돌아갈 수 있습니다. 표가 길면 꽤 불편하죠.

3. Stable Refresh로 위치 유지 🧷

IS_STABLE을 넘기면, 갱신 후에도 사용자의 행/열 위치를 그대로 유지합니다. "안정적인(stable)" 갱신이라는 뜻입니다. 

DATA gs_stable TYPE lvc_s_stbl.
gs_stable-row = 'X'.   "행 위치 유지
gs_stable-col = 'X'.   "열 위치 유지

go_grid->refresh_table_display(
  EXPORTING is_stable = gs_stable ).
💡

비유: 책갈피 끼우고 페이지 새로고침

그냥 새로고침이 "책을 덮었다 다시 첫 장부터 펴기"라면, Stable Refresh는 "책갈피를 끼워두고 그 페이지를 갱신"하는 것과 같아요. 사용자가 보던 자리를 잃지 않습니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 데이터 변경 → refresh(is_stable) → 같은 위치에서 새 값이 보임.
  • ❌ 오류 1: 데이터를 안 바꾸고 refresh만 호출 → 화면은 그대로(의미 없음). 테이블 내용을 먼저 갱신해야 합니다.
  • ❌ 오류 2: is_stable 없이 매번 refresh → 사용자가 스크롤할 때마다 맨 위로 튕겨 불편.

5. 실무에서 조심할 점 🚨

⚠️

"첫 표시는 first_display, 갱신은 refresh" 규칙

이 둘을 헷갈리면 표가 자꾸 리셋되거나(첫 표시를 반복) 갱신이 안 되는(refresh를 안 함) 문제가 생깁니다. 정리하면: 화면 진입 시 최초 1회 = first_display, 이후 데이터 변경 = refresh(is_stable). 컬럼 구성 자체가 바뀐 게 아니라면 거의 항상 refresh로 충분합니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • REFRESH_TABLE_DISPLAY는 떠 있는 표를 새 데이터로 다시 그립니다.
  • IS_STABLE(row/col)로 스크롤·선택 위치를 유지합니다.
  • refresh 전에 출력 테이블 내용을 먼저 갱신해야 합니다.
  • 규칙: 최초 1회 first_display, 이후 갱신 refresh(is_stable).

표를 띄우고 갱신하는 법까지 익혔습니다. 마지막으로, 중요한 값을 눈에 띄게 만드는 색상을 배웁니다. 다음 Lesson 컬럼 색상과 행 색상 기초에서 이 Chapter를 마무리합니다.
