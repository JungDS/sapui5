학습 목표

지난 Lesson들에서 잘못된 값을 막는 방법(Foreign Key/Check Table)을 배웠습니다. 이번에는 한 발 더 나아가, 사용자가 값을 외우지 않아도 되도록 고를 수 있는 목록을 띄워주는 Search Help(F4 Help)를 배웁니다. 그중 가장 기본 형태인 Elementary Search Help의 구성요소와 만드는 흐름을 잡습니다.

1. 지난 Lesson 연결: 막는 것에서 “고르게 해주는 것”으로 🤝

Foreign Key는 잘못된 값을 입력 단계에서 막아줬습니다. 하지만 사용자 입장에서는 “그럼 올바른 값이 뭔데?”가 궁금하죠. 항공사 코드 KE, LH, AA… 를 외우고 있어야 한다면 불편합니다.

Search Help는 바로 이 문제를 해결합니다. 입력 필드 옆 돋보기 아이콘을 누르거나 F4 키를 누르면, 고를 수 있는 값 목록(hit list)을 팝업으로 띄워줍니다. 막는 것(검증)과 고르게 하는 것(입력 도움말)은 짝꿍입니다.

Search Help는 DDIC에 저장되는 재사용 가능한 객체입니다. 한 번 잘 만들면 여러 화면에서 같은 입력 도움말을 공유할 수 있습니다.

2. F4를 누르면 무슨 일이 일어날까? 🔍

F4 Help 사용자 경험 흐름

1. 커서사용자가 입력 칸에 커서를 둔다
2. 호출F4 키 또는 필드 옆 돋보기 아이콘 클릭
3. 목록팝업에 유효 값 목록(hit list)이 표 형태로 표시
4. 선택원하는 행을 더블클릭
5. 채움자동 입력 선택값이 화면 칸에 채워짐

사용자는 값을 외울 필요 없이 “보고 고르기”만 하면 됩니다. 오타도 자연히 줄어듭니다.

3. Elementary Search Help의 3대 구성요소 ⚙️

Elementary Search Help는 단일 검색 경로를 제공하는 가장 기본 형태입니다. 내부적으로 세 개의 톱니바퀴가 맞물려 돌아갑니다.

세 톱니바퀴

① Selection Method
데이터를 어디서 읽나
Table / View 지정
F4 시 그 소스를 SELECT
→
② Parameter (인터페이스)
화면 ↔ Search Help 통신
IMPORT / EXPORT
LPos / SPos 위치
→
③ Dialog Behavior
팝업이 어떻게 뜨나
바로 목록 / 제한 후 목록
건수에 따라 자동

① 어디서 읽고 → ② 화면과 무엇을 주고받고 → ③ 어떤 모습으로 보여줄지. 이 셋이 Elementary Search Help의 뼈대입니다.

🔌

Search Help Parameter — 화면과 주고받는 4가지

  • IMPORT: 화면에 이미 입력된 값을 끌고 들어와 검색 조건(WHERE)으로 사용. 예: 국가에 KR을 친 뒤 도시 F4 → 한국 도시만 조회.
  • EXPORT: 팝업에서 더블클릭한 값을 화면의 어느 필드로 돌려줄지 결정.
  • LPos: 결과 목록(hit list)에서 이 필드가 몇 번째 열에 보일지.
  • SPos: 검색 전 조건 제한 창에서 몇 번째 줄에 보일지.

4. Dialog Behavior: 팝업이 뜨는 방식 3종 🪟

데이터 양에 맞춰 고르는 표시 방식

바로 목록 표시
조건 창 없이 곧장 결과
데이터 적을 때 유리
제한 후 목록
먼저 조건 필터 창 표시
데이터 많을 때 유리
건수에 따라 자동
일정 건수 이하면 바로
초과하면 제한 창

목록이 수십 건이면 바로 보여주고, 수만 건이면 먼저 좁히게 하는 식으로 사용자 경험을 맞춥니다.

5. 만드는 표준 절차 (SE11 기준) 🛠️

Elementary Search Help 최소 구현 흐름

1. 생성SE11 → Search Help 선택 → 이름(예: ZSH_AIRLINE) → Elementary
2. Selection Method읽어올 테이블/뷰 지정 (예: SCARR)
3. Parameter보여줄/검색할 필드 추가 (예: CARRID, CARRNAME)
4. 방향·위치IMPORT/EXPORT 체크 + LPos/SPos 지정
5. 활성화저장 → 활성화(Ctrl+F3) → 전역 사용 가능

활성화까지 해야 다른 화면·필드에서 이 Search Help를 호출할 수 있습니다.

6. 어떻게 “연결(Attach)”되나 — 우선순위 계층 🪜

만든 Search Help는 누군가 호출해 줘야 동작합니다. SAP는 F4를 누를 때 어디에 Search Help가 붙어 있는지 아래에서 위로 우선순위를 따라 찾습니다. 위로 갈수록 우선합니다.

연결 위치 4가지 (위가 우선)

화면 설계나 PROCESS ON VALUE-REQUEST에서 직접 연결. 우선순위 최상위지만 그 화면에서만 동작 → 실무 비권장.

DDIC 테이블 설계 시 특정 필드에 Search Help를 부여. 그 필드를 쓰는 곳에 적용됩니다.

Foreign Key를 걸면 Check Table의 키/Search Help를 바탕으로 F4가 자동 제공됩니다. 지난 Lesson과 연결되는 지점!

Data Element에 연결하면, 이 Data Element를 참조하는 전사 모든 화면 필드에 일관된 F4가 상속됩니다. 가장 권장.

실무에서는 Screen Field 직접 연결보다 Data Element 연결이 일관성·재사용 면에서 가장 좋습니다.

7. 실무에서 조심해야 할 점

⚠️

Search Help는 “입력 편의”지 “검증”이 아니다

F4 목록은 고르기 쉽게 도와줄 뿐, 사용자가 목록을 무시하고 키보드로 직접 잘못된 값을 칠 수도 있습니다. 잘못된 값을 실제로 막는 것은 여전히 Foreign Key/Check Table(또는 프로그램 검증)의 몫입니다. 입력 도움말과 검증은 함께 설계하세요.

  • 중복 만들지 말기: Foreign Key가 이미 자동 F4를 제공하는 필드에 굳이 똑같은 Search Help를 또 붙일 필요는 없습니다.
  • 연결 위치 선택: 한 화면 전용이 아니라면 Data Element 연결을 우선 고려해 재사용·일관성을 확보하세요.

8. 미니 실습: 항공사 F4 설계하기 🧪

✍️

실습 과제

  1. SCARR을 Selection Method로 하는 Elementary Search Help ZSH_AIRLINE을 설계한다고 가정하고, 보여줄 필드(CARRID, CARRNAME)를 정합니다.
  2. 두 필드의 IMPORT/EXPORT 체크와 LPos(목록 열 순서)를 종이에 적어봅니다.
  3. 데이터가 항공사 10개뿐이라면 Dialog Behavior를 어떤 것으로 고를지 이유와 함께 정합니다.
  4. 이 Search Help를 Data Element에 연결하면 Screen Field에 직접 연결할 때와 무엇이 달라지는지 한 줄로 적습니다.

완료 조건: “Selection Method=데이터 출처, Parameter=화면과의 주고받기, Dialog Behavior=표시 방식”을 자신의 말로 설명하고, F4가 검증이 아니라는 점을 구분하면 성공입니다.

10. 확인 퀴즈 ✅

  1. Selection Method는 무엇을 지정하는 곳인가요?
  2. IMPORT 파라미터와 EXPORT 파라미터의 차이는?
  3. Search Help를 가장 널리, 일관되게 적용하려면 어디에 연결하는 것이 좋은가요?
  4. F4 목록이 있으면 잘못된 값 입력이 완전히 차단될까요?
정답/해설 보기
  1. 데이터 출처(Transparent Table / View)를 지정합니다. F4 시 그 소스를 조회합니다.
  2. IMPORT는 화면 값을 검색 조건으로 끌어오고, EXPORT는 선택값을 화면 필드로 돌려줍니다.
  3. Data Element에 연결합니다. 그 Data Element를 쓰는 모든 화면에 F4가 상속됩니다.
  4. 아니요. F4는 입력 편의일 뿐, 차단은 Foreign Key/Check Table·프로그램 검증의 몫입니다.
