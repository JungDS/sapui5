학습 목표

지난 Lesson에서 기준표 관계와 실제 검증의 차이를 배웠습니다. 이번에는 사용자가 입력칸에서 F4를 눌렀을 때 후보 목록을 보여주는 Search Help를 배웁니다. 가장 기본 형태인 Elementary Search Help, F4 Help, Selection Method의 역할을 익힙니다.

1. 지난 시간 연결: 막는 것만큼 고르게 해주는 것도 중요하다 🔎

Foreign Key와 Check Table은 잘못된 값이 들어오는 것을 막는 데 도움을 줍니다. 그런데 사용자가 매번 코드를 외워서 입력해야 한다면 너무 불친절합니다. 항공사 코드가 KE인지 KAL인지 기억하지 못할 수 있잖아요.

이때 필요한 것이 F4 Help입니다. 사용자가 입력칸에서 F4를 누르면 가능한 값 목록이 뜨고, 그중 하나를 선택할 수 있습니다. 이 후보 목록을 설계하는 DDIC 객체가 Search Help입니다.

Search Help는 “정답을 외우게 하는 기능”이 아니라 “정답 후보를 고르게 도와주는 기능”입니다.

2. Elementary Search Help는 하나의 검색 방법 🧭

Elementary Search Help는 하나의 검색 방법을 가진 가장 기본적인 Search Help입니다. 예를 들어 항공사 목록을 보여주는 F4 Help를 만든다면, 항공사 기준표에서 코드와 이름을 읽어와 목록으로 보여줄 수 있습니다.

  • 어디서 찾을지: 어떤 테이블이나 뷰에서 후보를 읽을지 정합니다.
  • 무엇을 보여줄지: 코드, 이름, 국가 등 목록에 표시할 필드를 정합니다.
  • 무엇을 돌려줄지: 사용자가 선택했을 때 입력칸에 들어갈 값을 정합니다.

초심자 단계에서는 “Search Help = F4 팝업 후보 목록 설계도”라고 기억하면 충분합니다.

3. Selection Method: 후보를 가져올 출처 📚

Selection Method는 Search Help가 후보 데이터를 읽어올 테이블이나 뷰입니다. 항공사 코드를 고르는 Search Help라면 항공사 기준표가 Selection Method가 될 수 있습니다.

💡

예시 구성

  • Search Help: ZSH_CARRIER
  • Selection Method: ZCARRIER 기준표
  • 목록 표시 필드: CARRID, CARRNAME
  • 입력칸으로 반환할 필드: CARRID

여기서 중요한 것은 후보 목록이 갑자기 마법처럼 생기는 것이 아니라, 어떤 테이블이나 뷰를 읽어 만들어진다는 점입니다. 출처가 잘못되면 F4 목록도 잘못됩니다.

F4를 눌렀을 때 일어나는 일

1. F4 입력 사용자가 입력칸에서 F4를 누름
2. Search Help 호출 필드에 연결된 ZSH_CARRIER 동작
3. 후보 조회 Selection Method ZCARRIER에서 읽기
4. 목록 표시 코드와 이름을 팝업으로 보여줌
5. 값 반환 선택한 CARRID가 입력칸으로
CARRIDCARRNAME사용자 동작
AA아메리칸항공
KE대한항공더블클릭 → 입력칸에 KE 반환
LH루프트한자

팝업 목록에는 코드와 이름이 함께 보이지만, 입력칸으로 돌아가는 값은 반환 필드로 지정한 CARRID입니다.

4. 최소 실습 흐름: 항공사 F4 Help 만들기 🧪

실제 화면은 시스템 버전에 따라 조금 다를 수 있지만, 기본 흐름은 비슷합니다.

  1. DDIC에서 Elementary Search Help를 생성합니다.
  2. 짧은 설명을 적습니다. 예: 항공사 코드 검색 도움말
  3. Selection Method에 기준표를 지정합니다. 예: ZCARRIER
  4. Search Help Parameter에 코드와 이름 필드를 추가합니다.
  5. 목록에 보여줄 필드와 입력칸으로 반환할 필드를 구분합니다.
  6. 저장하고 활성화한 뒤 F4 동작을 확인합니다.

이 Lesson에서는 Search Help Parameter의 세부 옵션을 깊게 파고들지 않습니다. 다음 Lesson에서 Collective Search Help와 함께 파라미터 감각을 조금 더 연결합니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 사용자가 F4를 누르면 Selection Method에서 읽은 후보 목록이 뜨고, 선택한 코드가 입력칸으로 돌아옵니다.
  • ❌ 출처 오류: Selection Method가 잘못된 테이블이면 후보 목록이 비거나 엉뚱하게 보입니다.
  • ❌ 반환 필드 오류: 사용자가 이름을 선택했는데 입력칸에는 코드가 들어가야 하는 경우, 반환 필드 설정이 중요합니다.
  • ❌ 권한 착각: F4 목록에 보인다고 사용자가 그 값을 업무적으로 사용할 권한이 있다는 뜻은 아닙니다.
Search Help는 선택을 도와주는 기능이고, 업무 권한이나 모든 검증을 대신하는 기능은 아닙니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

F4 목록은 친절해야 하지만 너무 무거우면 안 됩니다

Search Help가 너무 큰 테이블을 아무 조건 없이 읽으면 F4 팝업이 느려질 수 있습니다. 표시 필드는 필요한 만큼만 두고, 실제 업무에서 사용자가 찾기 쉬운 기준을 생각해야 합니다. 성능과 사용성을 함께 봐야 좋은 입력 도움말입니다.

또한 표준 SAP 객체에 이미 좋은 Search Help가 연결되어 있다면 새로 만들기 전에 재사용 가능성을 먼저 확인하세요. 커스텀 Search Help는 표준으로 해결되지 않을 때 신중하게 만듭니다. 후보 데이터가 많은 경우에는 사용자가 조건을 먼저 입력한 뒤 조회하도록 Dialog 동작을 “값 제한이 있는 다이얼로그”로 설정하는 방법도 함께 검토합니다.

7. 미니 실습: 항공사 F4 흐름 설계하기 🧪

✍️

실습 과제

  1. 위 5단계 플로우를 가리고, F4를 눌렀을 때 일어나는 일을 순서대로 직접 적어봅니다.
  2. Search Help ZSH_CARRIER의 Selection Method, 목록 표시 필드, 반환 필드를 표로 정리합니다.
  3. “사용자가 이름(대한항공)을 더블클릭했는데 입력칸에 코드(KE)가 들어가는” 이유를 반환 필드 개념으로 설명합니다.
  4. 후보가 10만 건인 기준표라면 어떤 설정을 고민해야 할지 한 줄로 적어봅니다.

완료 조건: “Search Help = 후보 목록 설계도, Selection Method = 후보 출처, 반환 필드 = 입력칸으로 돌아갈 값”을 구분해 말할 수 있으면 성공입니다.

8. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: Search Help - Search Help의 공식 정의와 종류를 확인합니다.
  • SAP Help Portal: Input Help - F4 입력 도움말(Input Help)의 큰 개념을 확인합니다.
  • SAP Help Portal: DDIC Data Element - Search Help가 Data Element를 통해 필드와 연결되는 고리를 확인합니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. Search Help의 후보 목록은 어디에서 읽어오나요?
  2. F4 목록에 보이는 값이면 사용자가 업무적으로 항상 사용할 수 있는 값일까요?
  3. 사용자가 팝업에서 행을 선택했는데 입력칸에 엉뚱한 값이 들어간다면 어떤 설정을 의심해야 하나요?
정답/해설 보기
  1. Selection Method로 지정한 테이블이나 뷰에서 읽어옵니다. 출처가 잘못되면 목록도 잘못됩니다.
  2. 아니요. F4는 입력 편의 기능입니다. 권한, 기간, 상태 같은 업무 조건은 별도 검증이 필요합니다.
  3. 반환(Export) 필드 설정입니다. 목록에 보여줄 필드와 입력칸으로 돌려줄 필드를 구분해 매핑해야 합니다.

10. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • F4 Help는 사용자가 입력 가능한 후보를 고르게 돕는 기능입니다.
  • Search Help는 F4 후보 목록을 설계하는 DDIC 객체입니다.
  • Elementary Search Help는 하나의 검색 방법을 가진 기본 Search Help입니다.
  • Selection Method는 후보 데이터를 읽어올 테이블이나 뷰입니다.
  • Search Help는 입력 편의를 돕지만 권한과 모든 업무 검증을 대신하지는 않습니다.
