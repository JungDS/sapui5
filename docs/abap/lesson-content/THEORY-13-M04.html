학습 목표

사용자가 넣은 값이 올바른지 확인하고, 틀리면 다시 입력하게 돌려보내는 AT SELECTION-SCREEN 검증을 배웁니다. MESSAGE 문으로 오류를 알리고 입력을 다시 받는 흐름을 익힙니다.

1. 지난 시간 연결: 입력값을 믿지 마라 🚧

사용자는 실수합니다. 날짜를 거꾸로 넣거나, 존재하지 않는 회사코드를 적을 수 있죠. 잘못된 값으로 메인 로직(START-OF-SELECTION)이 돌면, 엉뚱한 결과가 나오거나 오류가 납니다.

그래서 메인 로직으로 넘어가기 전에 입력을 검사해야 합니다. 그 검사 타이밍이 AT SELECTION-SCREEN 이벤트입니다. 사용자가 실행(▶)을 누른 직후, START-OF-SELECTION보다 먼저 실행됩니다.

2. MESSAGE로 "다시 입력하세요" ✍️

ABAP

PARAMETERS: p_from TYPE sy-datum,
            p_to   TYPE sy-datum.

AT SELECTION-SCREEN.
  IF p_to < p_from.
    MESSAGE '종료일이 시작일보다 빠릅니다.' TYPE 'E'.
  ENDIF.

MESSAGE ... TYPE 'E'(Error)를 만나면, SAP는 오류 메시지를 띄우고 화면을 다시 보여줍니다. 사용자는 START-OF-SELECTION으로 넘어가지 못하고, 값을 고쳐 다시 실행해야 합니다.

💡

메시지 타입의 차이

  • E (Error): 화면으로 돌려보냄. 진행 불가.
  • W (Warning): 경고만, 다시 누르면 진행.
  • I (Information): 단순 안내 팝업.
  • S (Success): 다음 화면 하단에 가볍게 표시.

3. 특정 칸만 다시 입력하게 하기 🎯

어떤 칸이 틀렸는지 콕 짚어주면 더 친절합니다. AT SELECTION-SCREEN ON p_to처럼 특정 입력 칸에 대한 검증 블록을 두면, 오류 시 그 칸에 커서가 가서 사용자가 바로 고칠 수 있습니다.

  IF sy-subrc <> 0.

  ENDIF.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 검증 통과 → START-OF-SELECTION으로 진행.
  • ❌ 검증 실패: MESSAGE TYPE 'E' → 화면 재표시, 값 수정 요구.
  • ❌ 흔한 실수: 검증을 START-OF-SELECTION 안에 넣음 → 이미 메인 로직이라 화면으로 깔끔히 돌려보내기 어렵습니다. 검증은 AT SELECTION-SCREEN에서.

5. 실무에서 조심할 점 🚨

⚠️

검증은 "막는 것"이지 "처리하는 것"이 아닙니다

AT SELECTION-SCREEN에서는 입력이 올바른지 확인만 하고, 본격적인 데이터 처리·출력은 하지 않습니다. 여기서 대량 조회를 하거나 데이터를 변경하면, 검증이 여러 번 실행되며 꼬일 수 있습니다. "통과 기준만 검사"하는 가벼운 코드로 유지하세요.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • AT SELECTION-SCREEN은 메인 로직 전에 입력값을 검증합니다.
  • MESSAGE TYPE 'E'는 화면을 다시 보여주며 수정을 요구합니다.
  • ON 칸이름으로 특정 칸만 검증해 사용자를 정확히 안내합니다.
  • 검증은 가볍게 "막기"만, 처리·출력은 다음 단계에서 합니다.

입력이 안전해졌으니, 드디어 본론입니다. 다음 Lesson START-OF-SELECTION 조회 실행에서 검증된 값으로 실제 데이터를 조회하는 메인 로직을 배웁니다.
