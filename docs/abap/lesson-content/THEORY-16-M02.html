학습 목표

구조체와 Internal Table을 한 줄로 채우는 VALUE 생성자 표현식을 배웁니다. 여러 줄의 대입·APPEND를 깔끔한 한 덩어리로 바꾸는 감각을 익힙니다.

1. 지난 시간 연결: 값 채우기가 너무 길다 📝

구조체 하나에 값을 넣으려면 필드마다 한 줄씩 대입해야 했습니다. Internal Table에 여러 줄을 넣으려면 APPEND를 반복했죠. 줄 수가 금방 불어납니다.

최신 ABAP의 VALUE 표현식은 이 모든 걸 한 덩어리로 만들어 줍니다.

2. 구조체를 한 줄로 ✍️

" 예전 방식
DATA ls_flight TYPE ty_flight.
ls_flight-carrid = 'LH'.
ls_flight-connid = '0400'.
ls_flight-price  = 900.

" 최신 방식
DATA(ls_flight) = VALUE ty_flight(
  carrid = 'LH'
  connid = '0400'
  price  = 900 ).

VALUE 타입( 필드 = 값 ... ) 형태로, 구조체를 만들면서 바로 값을 채웁니다.

3. Internal Table도 한 덩어리로 📦

DATA(lt_flights) = VALUE ty_flights(
  ( carrid = 'LH' connid = '0400' price = 900 )
  ( carrid = 'AA' connid = '0017' price = 800 )
  ( carrid = 'UA' connid = '0941' price = 750 ) ).
  • 바깥 괄호: 테이블 전체.
  • 안쪽 ( ... ) 하나: 한 줄(행). 행 수만큼 반복합니다.
💡

공통 값은 묶어서

여러 행이 같은 값을 공유하면 VALUE ty_flights( carrid = 'LH' ( connid = '0400' ) ( connid = '0401' ) )처럼 공통 필드를 앞에 한 번만 적을 수 있습니다. 반복을 더 줄여주죠.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: VALUE로 구조·테이블을 선언과 동시에 채워 코드가 짧고 명확해집니다.
  • ❌ 오류 1: 타입을 안 주고 VALUE #( ... )를 쓰려면 문맥에서 타입이 추론돼야 합니다. 추론이 안 되면 타입을 명시해야 합니다.
  • ❌ 오류 2: 필드명을 틀리면 그 필드는 초기값으로 남습니다. 채웠다고 생각했는데 비어 있을 수 있어요.

5. 실무에서 조심할 점 🚨

⚠️

한 줄에 너무 많이 담지 마세요

VALUE는 강력해서 수십 줄짜리 테이블도 한 표현식에 담을 수 있습니다. 하지만 너무 길어지면 오히려 읽기 어려워집니다. 적당히 줄바꿈으로 정렬하고, 데이터가 정말 많으면 별도 테이블/파일에서 읽는 편이 낫습니다. "짧게"가 목적이 아니라 "읽기 쉽게"가 목적임을 기억하세요.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • VALUE 표현식은 구조체·테이블을 한 덩어리로 만들어 채웁니다.
  • 구조: VALUE 타입( 필드 = 값 ), 테이블: 안쪽 ( )가 한 행.
  • 문맥에서 타입이 추론되면 VALUE #( )로 더 짧게 쓸 수 있습니다.
  • 가독성을 위해 적당한 길이로 정렬해서 사용합니다.
