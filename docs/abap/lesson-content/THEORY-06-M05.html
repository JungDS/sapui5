학습 목표

지난 Lesson에서는 LOOP AT으로 전체 줄을 읽었습니다. 이번에는 READ TABLE, WITH KEY, SY-SUBRC를 사용해 Internal Table에서 원하는 한 줄을 찾는 기본 검색 흐름을 배웁니다.

1. 매번 전체를 돌 필요는 없다 🧭

LOOP AT은 Internal Table의 모든 줄을 처리할 때 좋습니다. 하지만 “학생 ID가 A02인 한 명만 찾고 싶다”처럼 목표가 분명할 때는 전체를 끝까지 도는 것보다 검색 문법을 쓰는 편이 읽기 쉽습니다.

ABAP에서 Internal Table의 특정 줄을 읽는 기본 문법이 READ TABLE입니다. 검색 조건은 보통 WITH KEY로 적고, 찾았는지 여부는 SY-SUBRC로 확인합니다.

READ TABLE은 “이 표에서 조건에 맞는 한 줄을 찾아서 Work Area에 담아줘”라는 요청입니다.

2. READ TABLE 기본 구조 🔍

ABAP

READ TABLE lt_students INTO ls_student WITH KEY id = 'A02'.

IF sy-subrc = 0.
  WRITE: / '찾음:', ls_student-name.
ELSE.
  WRITE: / '해당 ID 없음'.
ENDIF.
  • READ TABLE: Internal Table에서 한 줄을 읽습니다.
  • INTO ls_student: 찾은 줄을 Work Area에 담습니다.
  • WITH KEY: 어떤 필드 값으로 찾을지 조건을 적습니다.
  • SY-SUBRC: 직전 실행 결과를 숫자로 알려주는 시스템 필드입니다.

sy-subrc = 0이면 찾았다는 뜻입니다. 0이 아니면 조건에 맞는 줄을 찾지 못했거나, 해당 문장이 기대한 대로 성공하지 않았다는 신호로 읽습니다.

REPORT zread_table_basic.

TYPES: BEGIN OF ty_student,
         id    TYPE char3,
         name  TYPE char20,
         score TYPE i,
       END OF ty_student.

DATA: lt_students TYPE STANDARD TABLE OF ty_student,
      ls_student  TYPE ty_student.

ls_student-id = 'A01'.
ls_student-name = '정훈영'.
ls_student-score = 90.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A02'.
ls_student-name = '홍길동'.
ls_student-score = 85.
APPEND ls_student TO lt_students.

CLEAR ls_student.
READ TABLE lt_students INTO ls_student WITH KEY id = 'A02'.
IF sy-subrc = 0.
  WRITE: / '찾음:', ls_student-id, ls_student-name.
ELSE.
  WRITE: / 'A02를 찾지 못했습니다.'.
ENDIF.

여기서는 A02가 있으므로 성공 흐름으로 갑니다. 조건을 A99로 바꿔 실행하면 실패 흐름으로 가고, ELSE 메시지가 출력됩니다.

READ TABLE 뒤에는 Work Area 값을 바로 믿지 말고, 먼저 sy-subrc로 성공 여부를 확인합니다.

4. 찾은 뒤에는 반드시 결과를 확인하기 🚦

초심자가 자주 하는 실수는 READ TABLE을 한 뒤 바로 Work Area 값을 믿고 쓰는 것입니다. 검색에 실패하면 Work Area에 기대한 줄이 들어오지 않았을 수 있습니다. 그래서 READ TABLE 다음에는 거의 항상 sy-subrc를 확인하는 습관이 필요합니다.

ABAP

READ TABLE lt_students INTO ls_student WITH KEY id = 'A99'.

IF sy-subrc <> 0.
  WRITE: / '검색 실패: A99 없음'.
  RETURN.
ENDIF.

WRITE: / '검색 성공:', ls_student-name.

위 예제처럼 실패를 먼저 처리하고 빠져나오면, 아래쪽 코드는 “찾은 데이터가 있다”는 전제로 읽기 쉬워집니다. 이 방식은 나중에 오류 처리와 유지보수성에도 도움이 됩니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 조건에 맞는 줄을 찾으면 sy-subrc = 0이 되고, Work Area에 해당 줄이 담깁니다.
  • ❌ 검색 실패: 조건에 맞는 줄이 없으면 sy-subrc가 0이 아닙니다. 실패 메시지나 대체 처리가 필요합니다.
  • ❌ 키 필드 오타: WITH KEY student_id = 'A02'처럼 없는 필드를 쓰면 문법 오류가 납니다.
  • ❌ 중복 줄: 같은 키 값이 여러 줄이면 기본 READ TABLE은 기대와 다른 첫 번째 줄을 가져올 수 있습니다.
  • ❌ 성능 착각: STANDARD TABLE에서 무조건 빠른 검색이 보장되는 것은 아닙니다. 대량 데이터 검색은 테이블 종류와 키 설계가 중요합니다.

미니 실습으로 A02와 A99를 각각 검색해보세요. 성공 시 이름을 출력하고, 실패 시 “없음”을 출력하도록 만들면 검색 기본 흐름을 잡은 것입니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

READ TABLE 다음 sy-subrc 확인은 거의 반사 습관

검색 실패를 확인하지 않고 Work Area를 사용하면 이전 값이나 빈 값으로 잘못된 결과를 출력할 수 있습니다. 특히 금액, 수량, 승인 여부처럼 업무 영향이 큰 데이터는 실패 흐름을 반드시 분리해야 합니다.

또한 고객사 코드에는 READ TABLE ... BINARY SEARCH, 테이블 키를 활용한 최신 문법 등이 섞여 있을 수 있습니다. 이번 Lesson은 기본 검색 감각을 익히는 단계이므로, 성능 심화는 후속 Internal Table 응용에서 확장합니다.

7. 미니 실습: 성공과 실패를 모두 만나보기 🧪

✍️

실습 과제

  1. 학생 3명을 담은 Internal Table에서 READ TABLE ... WITH KEY id = 'A02'로 검색하고, 성공 시 이름을 출력합니다.
  2. 검색 ID를 A99로 바꿔 실행하고, sy-subrc 값을 직접 출력해 0이 아님을 확인합니다.
  3. 실패 시 “해당 학생 없음” 메시지가 나오도록 IF 분기를 완성합니다.
  4. READ TABLE 앞의 CLEAR ls_student.를 일부러 빼고, 검색 실패 후 Work Area에 이전 값이 남아 있는 문제를 관찰합니다.

완료 조건: 성공/실패 두 흐름이 서로 다른 메시지로 출력되고, “실패 시 Work Area를 그대로 믿으면 안 되는 이유”를 설명할 수 있으면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. READ TABLE이 조건에 맞는 줄을 찾지 못하면 sy-subrc는 어떻게 될까요?
  2. 검색 실패 직후 Work Area에는 무엇이 들어 있을까요?
  3. 전체 학생을 출력할 때와 특정 학생 한 명을 찾을 때, 각각 어떤 문장이 적합한가요?
정답/해설 보기
  1. 0이 아닌 값(보통 4)이 됩니다. 0이면 성공, 0이 아니면 실패 흐름으로 분리해 처리합니다.
  2. 이전에 들어 있던 값이 그대로 남아 있을 수 있습니다. 그래서 검색 전에 CLEAR하거나, 실패 시 Work Area를 사용하지 않아야 합니다.
  3. 전체 출력은 LOOP AT, 한 줄 검색은 READ TABLE이 적합합니다. 목적(전체 반복 vs 단건 조회)에 따라 문장을 고릅니다.

10. 한눈에 정리 🏁

📝

검색 기본 핵심

  • READ TABLE은 Internal Table에서 조건에 맞는 한 줄을 읽습니다.
  • WITH KEY는 어떤 필드 값으로 찾을지 적는 조건입니다.
  • SY-SUBRC가 0이면 성공, 0이 아니면 실패 흐름으로 봅니다.
  • READ TABLE 뒤에는 결과 확인 없이 Work Area를 바로 믿지 않습니다.
  • 중복과 대량 검색은 별도 키 설계와 성능 기준을 함께 봐야 합니다.
