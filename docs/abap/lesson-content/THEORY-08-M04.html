학습 목표

이번 Lesson에서는 Internal Table 데이터를 준비하고, SALV로 표시하는 Mini Report를 하나로 완성합니다. 데이터 준비와 화면 표시가 어떻게 이어지는지 확인합니다.

1. 이제 데이터와 화면을 연결한다 🧭

Lesson 1~Lesson 3에서는 SALV의 목적, FACTORY, DISPLAY, 기본 Functions를 나누어 봤습니다. 이제 이 조각들을 하나의 Report 흐름으로 묶어봅니다.

실무 Report의 기본 골격은 생각보다 단순합니다. 입력값을 받고, 데이터를 읽거나 만들고, Internal Table에 담고, 마지막에 ALV/SALV로 보여줍니다. 이번 예제는 데이터베이스 조회 전 단계이므로 코드 안에서 작은 데이터를 만들어 표시합니다.

SALV 미니 리포트는 “Internal Table을 준비한 뒤 표 화면으로 보여주는” 작은 완성 프로그램입니다.

REPORT zsalv_mini_report.

TYPES: BEGIN OF ty_student,
         id    TYPE char3,
         name  TYPE char20,
         score TYPE i,
       END OF ty_student.

DATA: lt_students  TYPE STANDARD TABLE OF ty_student,
      ls_student   TYPE ty_student,
      lo_alv       TYPE REF TO cl_salv_table,
      lo_functions TYPE REF TO cl_salv_functions_list,
      lx_msg       TYPE REF TO cx_salv_msg.

ls_student-id = 'A01'. ls_student-name = 'Mina'. ls_student-score = 90.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A02'. ls_student-name = 'Jun'. ls_student-score = 85.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A03'. ls_student-name = 'Sora'. ls_student-score = 95.
APPEND ls_student TO lt_students.

SORT lt_students BY score DESCENDING.

TRY.
    cl_salv_table=>factory(
      IMPORTING r_salv_table = lo_alv
      CHANGING  t_table      = lt_students ).

    lo_functions = lo_alv->get_functions( ).
    lo_functions->set_all( abap_true ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO lx_msg.
    MESSAGE lx_msg->get_text( ) TYPE 'E'.
ENDTRY.

코드는 길어 보이지만 실제 덩어리는 네 개입니다. 타입 선언, 데이터 채우기, 정렬, SALV 표시입니다.

3. 흐름을 말로 다시 읽기 🔁

  1. ty_student로 한 줄 구조를 정의합니다.
  2. lt_students Internal Table에 학생 3명을 담습니다.
  3. SORT로 점수 높은 순서로 정렬합니다.
  4. cl_salv_table=>factory로 SALV 객체를 만듭니다.
  5. get_functions와 set_all로 기본 기능을 켭니다.
  6. display로 화면 표를 표시합니다.

디버거로 확인할 때는 lt_students가 정렬된 상태인지, lo_alv가 FACTORY 후 비어 있지 않은지, DISPLAY가 실행되는지 차례로 보면 됩니다.

4. 빈 데이터도 사용자 경험이다 🪧

Internal Table이 비어 있으면 SALV 화면이 비어 보일 수 있습니다. 이것이 기술적으로는 오류가 아닐 수 있지만, 사용자 입장에서는 “왜 아무것도 안 나오지?”가 됩니다.

실제 Report에서는 SALV 표시 전에 데이터가 없는 경우를 안내하는 메시지를 넣는 것이 좋습니다. 초심자 단계에서는 “빈 결과도 설계 대상”이라는 감각을 가져가세요.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: Internal Table에 3줄이 들어가고, 점수 내림차순 정렬 후 SALV 화면이 표시됩니다.
  • ✅ 빈 데이터 안내: 데이터가 없으면 DISPLAY 전에 메시지를 보여주고 종료할 수 있습니다.
  • ❌ 정렬 위치 착각: SALV 표시 후 SORT해도 이미 표시된 화면에는 기대대로 반영되지 않을 수 있습니다.
  • ❌ 데이터 검증 생략: 점수나 이름이 잘못 들어가도 SALV는 그대로 보여줍니다.

미니 실습으로 SORT lt_students BY score DESCENDING.을 주석 처리해보세요. 화면 표시 순서가 APPEND 순서와 어떻게 달라지는지 비교합니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

SALV는 결과 표시이지 데이터 정답 보증이 아닙니다

SALV 화면이 예쁘게 떠도 데이터가 정확하다는 뜻은 아닙니다. 조회 조건, 권한, 가공 로직, 빈 결과 안내까지 Report 전체 흐름에서 검증해야 합니다.

이번 미니 리포트는 코드 안에서 데이터를 만들지만, 뒤 Open SQL Chapter에서는 데이터베이스에서 조회한 Internal Table을 SALV로 표시하는 흐름으로 자연스럽게 확장됩니다.

7. 한눈에 정리 🏁

📝

미니 리포트 핵심

  • Mini Report는 데이터 준비부터 화면 표시까지 연결한 작은 완성 프로그램입니다.
  • Internal Table을 채운 뒤 정렬, 검증, SALV 표시 순서로 구성할 수 있습니다.
  • FACTORY로 SALV 객체를 만들고 DISPLAY로 화면을 띄웁니다.
  • 빈 데이터는 오류가 아닐 수 있지만 사용자 안내가 필요합니다.
  • SALV 표시 전 데이터 품질과 건수를 먼저 확인합니다.
