학습 목표

지난 Lesson에서 Include/Exclude를 봤습니다. 이번에는 Range Table의 OPTION에 들어가는 대표 Selection Option인 EQ, BT, CP를 초심자 눈높이로 정리합니다.

1. OPTION은 비교 방법이다 🧭

Range Table 한 줄에서 SIGN이 포함/제외를 정한다면, OPTION은 어떻게 비교할지를 정합니다. 같은 LOW 값이라도 OPTION이 무엇이냐에 따라 의미가 달라집니다.

OPTION은 “같다”, “사이에 있다”, “패턴과 맞다” 같은 비교 방식을 나타냅니다.

2. EQ: 같은 값 하나 🎯

EQ는 Equal, 즉 같다는 뜻입니다. LOW에 적은 값과 정확히 같은 값을 선택합니다.

EQ 조건 예시

SIGN OPTION LOW 의미
I EQ KR KR만 포함

단일값 입력은 대부분 내부적으로 OPTION = 'EQ'로 표현됩니다.

3. BT: 시작값부터 끝값까지 📏

BT는 Between, 즉 LOW부터 HIGH까지의 범위를 뜻합니다.

BT 조건 예시

SIGN OPTION LOW HIGH 의미
I BT A C A부터 C까지 포함

BT에서는 HIGH가 중요합니다. 시작값만 있고 끝값이 없으면 범위 조건의 의미가 흐려집니다.

4. CP: 패턴과 맞는 값 🔎

CP는 Contains Pattern입니다. 문자 패턴과 맞는 값을 고를 때 사용합니다. Selection Option에서 *는 여러 글자, +는 한 글자 패턴처럼 쓰입니다.

CP 조건 예시

SIGN OPTION LOW 의미
I CP K* K로 시작하는 값 포함

4. EQ vs BT vs CP 매칭 비교 시각화 🗺️

사원 이름 검색 조건에서 세 옵션(EQ, BT, CP)이 사원 목록(정훈영, 이몽룡, 이병헌, 이효리, 이영지)을 어떻게 매칭하는지 비교하여 작동 원리를 쉽게 이해해 보겠습니다.

동일한 사원 풀에 대한 OPTION별 매칭 차이

1. 조건 사원 풀
  • 정훈영
  • 이몽룡
  • 이병헌
  • 이효리
  • 이영지
2. 옵션별 최종 매칭 결과
OPTIONLOWHIGH매칭되는 사원 목록
EQ (Equal)이병헌이병헌 (단 1명 ✅)
BT (Between)이몽룡이병헌이몽룡, 이병헌 (가나다 순 범위 ✅)
CP (Contains Pattern)이*이몽룡, 이병헌, 이효리, 이영지 ('이'씨 모두 ✅)

CP에서 *는 여러 글자(와일드카드)를 의미하며, 대소문자 구분 없이 문자 패턴 매칭을 수행합니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 업무 의도에 맞는 옵션 설계: 사번 단일 매칭에는 EQ, 기간이나 부서 코드 범위에는 BT, 부분명 검색에는 CP를 올바르게 연결하여 사용합니다.
  • ✅ BT의 LOW/HIGH 관계: 항상 LOW <= HIGH여야 정상 매칭이 이루어집니다.
  • ❌ BT 옵션의 HIGH 값 누락: Between 조건임에도 HIGH를 비워두면, 시스템과 DB 환경에 따라 조건 검색이 비정상적으로 흘러갑니다.
  • ❌ CP 패턴의 와일드카드 오용: 와일드카드(*)를 CP 옵션 없이 그냥 EQ에(예: LOW = '이*', OPTION = 'EQ') 전달하면, * 자체를 일반 문자로 인식해 '이*'라는 진짜 이름을 찾으므로 매칭에 실패합니다.
  • ❌ CP 패턴의 성능 경고: *이* 처럼 양쪽에 와일드카드를 붙여 전체 검색을 하면 DB 인덱스를 전혀 타지 못해 조회 속도가 매우 느려집니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

CP 패턴 조회를 무분별하게 남발하지 마세요

CP(Contains Pattern)는 뒤에서 데이터베이스 쿼리로 변환될 때 LIKE 연산자로 번역됩니다. 대량 테이블에서 특히 문자열 중간이나 끝을 검색하기 위해 와일드카드를 과도하게 쓰는 경우, 데이터베이스 전체 테이블 스캔(Table Scan)을 유발해 전체 시스템에 큰 부하를 줄 수 있습니다.

7. 미니 실습: CP 패턴의 와일드카드 문자 작성 🧪

✍️

실습 과제

  1. 와일드카드 *(0개 이상의 문자)와 +(정확히 1개의 문자)의 성질을 비교합니다.
  2. 이름이 '이'로 시작하고 뒤에 세 글자가 더 오는 패턴(총 네 글자, 예: '이몽룡이')을 +를 활용해 표현해 봅니다. (정답: 이+++)
  3. '이'로 시작하는 모든 글자 수 제한 없는 이름 패턴을 *로 표현해 봅니다. (정답: 이*)
  4. ADT에서 사원 테이블을 조회할 때 와일드카드 기호인 #을 사용하여 실제 별표(*)를 문자로 검색하려면 어떻게 해야 하는지 문법을 탐색해 봅니다.

완료 조건: CP 옵션에서 *와 +의 매칭 범위 차이점을 설명할 수 있으면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. CP(Contains Pattern) 비교 옵션에서 *와 +의 가장 핵심적인 차이는 무엇인가요?
  2. Between(BT)을 쓸 때, 실수로 LOW 값에 HIGH 값보다 큰 값(가나다 순 또는 숫자 크기 기준)을 넣으면 SQL 실행 시 오류가 나나요?
  3. OPTION = 'EQ'이고 LOW = '이*'인 조건표가 있다면, 이는 어떤 데이터를 조회하나요?
정답/해설 보기
  1. 자릿수 제한 유무입니다. *는 글자 수 제한 없이 0개 이상의 모든 문자를 의미하고, +는 자릿수 1개에 대응하는 임의의 1문자를 의미합니다.
  2. 문법 오류나 SQL 에러는 나지 않지만, '시작값 > 끝값'이 되어 항상 거짓(False)인 조건이 되므로 아무런 결과도 조회되지 않는 논리 버그가 발생합니다.
  3. 와일드카드 매칭이 아닌, 실제 이름이 별표를 포함해 '이*'로 정확히 등록된 데이터를 찾습니다. 와일드카드 패턴 검색을 수행하려면 반드시 OPTION = 'CP'여야 합니다.

10. 한눈에 정리 🏁

📝

OPTION 핵심 정리

  • Selection Option은 Range Table에서 데이터 비교 연산 유형을 결정합니다.
  • EQ (Equal)은 단일 매칭, BT (Between)는 범위 매칭, CP (Contains Pattern)는 와일드카드 패턴 매칭입니다.
  • BT 조건은 반드시 LOW <= HIGH를 만족하며 둘 다 채워져 있어야 합니다.
  • CP는 내부적으로 DB LIKE 문으로 변경되므로 대량 테이블 조회 시 인덱스 스캔 성능에 주의해야 합니다.
