학습 목표

사용자가 컬럼 배치·정렬·필터를 저장해 다시 불러 쓰는 Layout Variant를 배웁니다. 변형을 저장 방식으로 제어하는 DISVARIANT와 I_SAVE를 익힙니다.

1. 지난 시간 연결: 사용자마다 보고 싶은 모양이 다르다 👥

같은 표라도 어떤 사용자는 요금 컬럼을 앞에 두고 정렬해서 보고 싶고, 다른 사용자는 날짜순으로 보고 싶을 수 있습니다. 매번 손으로 바꾸는 건 번거롭죠.

ALV는 사용자가 바꾼 컬럼 순서·너비·정렬·필터를 이름 붙여 저장하고, 다음에 그대로 불러올 수 있게 해줍니다. 이 저장본이 Layout Variant(레이아웃 변형)입니다.

2. DISVARIANT와 I_SAVE ✍️

DATA gs_variant TYPE disvariant.

gs_variant-report = sy-repid.   "이 프로그램 기준으로 변형 관리


" 표시 메서드에 함께 넘김 (다음 Lesson M07)

"   is_variant = gs_variant

"   i_save     = 'A'
  • DISVARIANT: 변형 정보를 담는 구조. 보통 report에 프로그램 ID를 넣어 "어느 프로그램의 변형인지" 구분합니다.
  • i_save: 저장 허용 범위를 정합니다.
💡

I_SAVE 값의 뜻

  • ' '(공백): 저장 불가(조회만).
  • 'U': 사용자별(User-specific) 변형만.
  • 'X': 공용(전체 공유) 변형만.
  • 'A': 둘 다 허용(User + 공용).

3. 사용자 입장에서의 흐름 🔄

  • ① 표에서 컬럼 순서·정렬을 바꾼다.
  • ② 툴바의 "레이아웃 저장"으로 이름을 붙여 저장(예: 요금순).
  • ③ 다음에 같은 표를 열고 "레이아웃 불러오기"로 요금순 선택 → 그대로 복원.
개발자는 변형을 "허용"만 해주면 되고, 실제 저장·관리는 사용자가 화면에서 합니다. 작은 설정 하나로 사용자 편의가 크게 올라갑니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: DISVARIANT-report 지정 + i_save 적절히 설정 → 사용자가 변형을 저장·재사용.
  • ❌ 오류 1: i_save를 공백으로 두면 저장 버튼이 비활성 → "왜 저장이 안 되지?" 혼란.
  • ❌ 오류 2: report를 안 채우면 변형이 엉뚱한 기준으로 묶일 수 있습니다.

5. 실무에서 조심할 점 🚨

⚠️

공용 변형은 신중하게

i_save = 'X'(공용)는 모든 사용자에게 영향을 줍니다. 한 사람이 바꾼 공용 변형이 전체에 적용되어 혼란을 줄 수 있으니, 보통은 사용자별('U') 또는 둘 다('A')로 시작하고, 공용 변형은 운영 표준으로 합의된 경우에만 신중히 사용하세요.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Layout Variant는 사용자가 컬럼 배치·정렬을 저장해 재사용하는 기능입니다.
  • DISVARIANT의 report로 변형 기준을, I_SAVE로 저장 범위를 정합니다.
  • I_SAVE: ' '(불가)/'U'(사용자)/'X'(공용)/'A'(둘 다).
  • 개발자는 "허용"만, 저장·관리는 사용자가 화면에서 합니다.

준비물(데이터·Field Catalog·Layout·Variant)이 다 모였습니다. 이제 이걸 한 번에 화면에 띄울 차례입니다. 다음 Lesson SET_TABLE_FOR_FIRST_DISPLAY에서 표를 처음 표시하는 핵심 메서드를 배웁니다.
