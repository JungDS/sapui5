학습 목표

ABAP 리포트 프로그램이 실행될 때 거치는 이벤트의 전체 흐름을 잡습니다. LOAD-OF-PROGRAM → INITIALIZATION → 선택 화면 → START-OF-SELECTION으로 이어지는 전체 생명주기 지도를 그리는 것이 목표입니다.

1. 지난 시간 연결: 코드는 "위에서 아래로"가 아니다? 🔄

일반적인 프로그래밍 언어를 처음 배울 때는 "코드는 무조건 위에서 아래로 차례차례 실행된다"고 배웁니다. 하지만 ABAP의 리포트 프로그램(Executable Program)은 설계 철학이 완전히 다릅니다.

우리가 소스 코드를 아무리 엉망인 순서로 배치하더라도, SAP 런타임 시스템이 정해진 이벤트 순서(Lifecycle Event)에 따라 우리가 작성한 코드 블록들을 콕콕 집어다가 정해진 스케줄대로 실행시킵니다.

이 개념을 확실히 모르면, "분명 코드 맨 위에 변수 초기값을 적어놨는데 왜 화면이 뜬 다음에 적용되지?" 혹은 "왜 데이터베이스 조회가 엉뚱한 시점에 일어나서 덤프가 나지?" 하는 혼란에 빠지게 됩니다. 리포트 개발을 시작하기 전, 전체 이벤트 지도를 명확히 머리에 그려봅시다!

2. 리포트 이벤트 라이프사이클 시각화 🗺️

리포트 프로그램이 처음 호출되어 데이터베이스 결과 화면을 출력하기까지 거치는 전체 단계를 Mermaid 다이어그램을 활용해 시각화해 보겠습니다.

선택 화면(Selection Screen)이 나타나는 시점을 기준으로 화면 이전(준비 및 설정)과 화면 이후(검증 및 실행)로 로직이 나뉩니다.

3. 일상 비유로 흐름 외우기: 요리사 정훈영 사원의 하루 🍳

이 복잡한 영문 이벤트명들은 요리사의 주방 프로세스에 비유하면 아주 직관적으로 머리에 들어옵니다.

  • LOAD-OF-PROGRAM (주방 오픈): 주방에 출근해 불을 켜고 앞치마를 맵니다. 프로그램이 메모리에 적재되어 준비되는 순간입니다.
  • INITIALIZATION (주문서 초기화): 손님이 오기 전에 오늘 추천 메뉴판에 '정훈영 추천 파스타'라고 디폴트 값을 미리 적어놓는 단계입니다. (화면 기본값 세팅)
  • Selection Screen (주문 대기): 손님(사용자)이 메뉴판(선택 화면)을 훑어보고 원하는 옵션을 클릭합니다.
  • AT SELECTION-SCREEN (주문 검증): 손님이 "파스타 100인분 주세요"라고 주문했을 때, 요리사가 "죄송합니다, 저희 재료가 부족해요"라며 주문을 거부하는 단계입니다. (입력값 유효성 검증)
  • START-OF-SELECTION (조리 시작): 주문이 최종 통과되면 주방에서 가스불을 켜고 본격적으로 요리를 조리하기 시작합니다. (메인 DB 데이터 조회 및 가공)
  • END-OF-SELECTION (플레이팅): 조리가 완료된 음식을 예쁜 그릇에 담아 테이블에 서빙합니다. (데이터 출력 화면 노출)

4. 정상 흐름과 실무 적용 🔍

  • ✅ 기본값 처리는 무조건 INITIALIZATION: 프로그램이 실행되고 화면이 사용자 눈에 띄기 전에 작동하므로, 필드에 미리 오늘 날짜나 특정 부서 코드 등의 기본값을 안전하게 채워넣을 수 있습니다.
  • ✅ 비즈니스 로직은 START-OF-SELECTION: 입력값 검증이 모두 끝난 시점에 비로소 메인 쿼리(SELECT)를 날리므로, 잘못된 값으로 DB에 무거운 쿼리가 들어가는 비효율을 완벽히 방지합니다.
  • ❌ 이벤트 블록 혼동 오류: 만약 초기값 설정 로직을 실수로 START-OF-SELECTION에 적어버리면, 사용자가 화면에서 값을 직접 고치고 실행(F8)할 때마다 초기값으로 다시 덮어써 버리는 버그가 나게 됩니다.

5. 실무에서 조심할 점 🚨

⚠️

"어디에 쓰느냐"가 아니라 "어떤 블록에 쓰느냐"가 생명입니다

ABAP 컴파일러는 소스 코드의 물리적인 윗줄, 아랫줄 위치를 보고 순서를 판단하지 않습니다. INITIALIZATION 키워드가 코드 가장 밑바닥에 적혀 있더라도, START-OF-SELECTION보다 무조건 먼저 실행됩니다. 따라서 가독성을 위해 코드 구조는 반드시 실행 생명주기 순서대로 정렬해 주는 것이 협업의 기초적인 매너입니다.

  2. 다음과 같이 이벤트 순서를 고의로 거꾸로 섞어서 코딩한 후 활성화시킵니다:

7. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: Executable Program Events - Executable 리포트 프로그램의 전체 실행 생명주기 사양을 확인합니다.
  • SAP Help Portal: INITIALIZATION Event Block - 화면이 렌더링되기 직전 값을 초기화하는 구문의 상세 선언 법을 확인합니다.
  • SAP Help Portal: START-OF-SELECTION Block - 쿼리 및 메인 로직이 실행되기 전 세션 상태를 결정하는 규칙을 학습합니다.

8. 확인 퀴즈와 정답/해설 ✅

  1. ABAP 리포트 프로그램에서 소스 코드상의 작성 위치가 아닌, 실행 시점을 결정해 주는 고유의 블록 단위를 무엇이라고 부르나요?
  2. 리포트가 실행될 때 선택 화면(Selection Screen)이 로드되기 **전**에 작동하여 디폴트 입력값을 필드에 적재해 주는 이벤트는 무엇인가요?
  3. 손님이 식당에 100인분 요리를 주문할 때 재료 수량을 검증하는 것과 같이, 사용자가 화면에 입력한 값이 유효한지 검사하는 이벤트는 무엇인가요?
정답/해설 보기
  1. 이벤트 블록 (Event Block)입니다.
  2. INITIALIZATION 이벤트입니다.
  3. AT SELECTION-SCREEN 이벤트입니다. 이를 통해 잘못된 데이터를 걸러내고 에러를 화면에 즉각 표시할 수 있습니다.

9. 한눈에 정리 🏁

📝

이벤트 기초 핵심 요약

  • ABAP 리포트는 작성 순서가 아닌 정해진 약속(이벤트 라이프사이클)에 의해 움직입니다.
  • INITIALIZATION은 화면이 로드되기 전 기본값을 세팅하는 준비 단계입니다.
  • AT SELECTION-SCREEN은 입력된 값의 적합성을 체크하는 검증 필터입니다.
  • START-OF-SELECTION은 데이터베이스 조회(SELECT) 등 핵심 계산을 수행하는 요리 단계입니다.
