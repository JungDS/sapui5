학습 목표

THEORY-06에서 Internal Table에 줄을 넣고 읽고 검색했습니다. 이번에는 이미 들어 있는 행을 MODIFY로 바꾸는 방법을 배웁니다. 특히 INDEX와 TRANSPORTING을 사용해 “몇 번째 줄의 어떤 필드만 바꿀지”를 안전하게 지정합니다.

1. 지난 Chapter 연결: 이제 표를 고쳐야 한다 🧭

지난 Chapter에서는 Internal Table에 학생 점수 데이터를 넣고, LOOP로 읽고, READ TABLE로 검색했습니다. 하지만 실제 업무에서는 읽기만 하지 않습니다. 계산 결과를 반영하거나, 상태를 바꾸거나, 특정 필드만 다시 채워야 할 때가 많습니다.

예를 들어 학생의 점수가 재채점되어 85점에서 88점으로 바뀌었다면, Internal Table 안의 해당 줄도 바꿔야 합니다. 이때 쓰는 기본 문법이 MODIFY입니다.

MODIFY는 Internal Table에 이미 들어 있는 한 줄을 새 값으로 덮어쓰는 문법입니다.

2. MODIFY 기본 구조 보기 🔧

READ TABLE lt_students INTO ls_student WITH KEY id = 'A02'.

IF sy-subrc = 0.
  ls_student-score = 88.
  MODIFY lt_students FROM ls_student INDEX 2.
ENDIF.

위 코드는 A02 학생을 Work Area로 읽어온 뒤 점수를 바꾸고, Internal Table의 2번째 줄을 Work Area 값으로 변경합니다. 여기서 중요한 것은 MODIFY가 Internal Table 원본 줄을 바꾼다는 점입니다.

  • FROM ls_student: 바꿀 새 값이 들어 있는 Work Area입니다.
  • INDEX 2: Internal Table의 2번째 줄을 대상으로 합니다.
  • sy-subrc: MODIFY가 성공했는지 확인할 수 있는 반환 코드입니다.

3. TRANSPORTING으로 필요한 필드만 바꾸기 🎯

TRANSPORTING은 Work Area 전체가 아니라 지정한 필드만 Internal Table에 반영하고 싶을 때 사용합니다. 초심자에게는 “필드 단위 안전장치”라고 생각하면 좋습니다. 

ls_student-score = 88.
MODIFY lt_students FROM ls_student INDEX 2 TRANSPORTING score.

이 코드는 2번째 줄의 score 필드만 바꿉니다. Work Area에 다른 필드 값이 비어 있거나 오래된 값이어도, score만 반영되므로 원치 않는 필드 덮어쓰기를 줄일 수 있습니다.

💡

초심자용 판단 기준

한 필드만 바꿀 목적이라면 TRANSPORTING을 먼저 떠올리세요. “전체 줄을 다시 쓰는 게 맞나?”를 묻는 습관이 데이터 손상을 줄입니다.

4. 전체 예제로 점수 수정하기 ✍️

REPORT zmodify_itab_basic.

TYPES: BEGIN OF ty_student,
         id    TYPE char3,
         name  TYPE char20,
         score TYPE i,
       END OF ty_student.

DATA: lt_students TYPE STANDARD TABLE OF ty_student,
      ls_student  TYPE ty_student.

ls_student-id = 'A01'. ls_student-name = 'Mina'. ls_student-score = 90.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A02'. ls_student-name = 'Jun'. ls_student-score = 85.
APPEND ls_student TO lt_students.

READ TABLE lt_students INTO ls_student WITH KEY id = 'A02'.
IF sy-subrc = 0.
  ls_student-score = 88.
  MODIFY lt_students FROM ls_student INDEX 2 TRANSPORTING score.
ENDIF.

LOOP AT lt_students INTO ls_student.
  WRITE: / ls_student-id, ls_student-name, ls_student-score.
ENDLOOP.

실행하면 Jun의 점수가 85에서 88로 바뀐 상태로 출력됩니다. 디버거에서 MODIFY 전후의 lt_students를 보면 원본 Internal Table 행이 실제로 바뀌는 것을 확인할 수 있습니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: READ TABLE로 대상 줄을 찾고, 필요한 필드를 바꾼 뒤 MODIFY가 성공합니다.
  • ❌ 검색 실패: READ TABLE이 실패했는데도 MODIFY하면 엉뚱한 Work Area 값이 반영될 수 있습니다.
  • ❌ 잘못된 INDEX: 존재하지 않는 인덱스를 지정하면 MODIFY가 실패합니다. 결과는 sy-subrc로 확인합니다.
  • ❌ TRANSPORTING 누락: 일부 필드만 바꿀 생각이었는데 전체 Work Area를 반영하면 다른 필드까지 덮어쓸 수 있습니다.

미니 실습으로 A02를 A99로 바꿔 검색 실패 상황을 만들어보세요. 실패 시 MODIFY를 실행하지 않도록 조건을 유지하는 것이 핵심입니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

INDEX는 현재 순서에 의존합니다

Internal Table을 SORT하거나 DELETE한 뒤에는 같은 데이터가 더 이상 같은 INDEX에 있지 않을 수 있습니다. “2번째 줄”보다 “ID가 A02인 줄”이 업무적으로 더 정확한 기준인지 항상 확인해야 합니다.

운영 코드에서는 변경 전 검색 성공 여부, 변경 대상 기준, 변경할 필드 범위를 분명히 해야 합니다. 단순히 실행되는 코드보다 “무엇을 기준으로 어느 필드만 바꾸는가”가 더 중요합니다.

7. 한눈에 정리 🏁

📝

행 변경 핵심

  • MODIFY는 Internal Table의 기존 행을 변경합니다.
  • INDEX는 몇 번째 줄을 바꿀지 지정합니다.
  • TRANSPORTING은 지정한 필드만 반영하게 해줍니다.
  • READ TABLE 실패 여부를 확인한 뒤 변경해야 엉뚱한 값 반영을 막을 수 있습니다.
  • INDEX는 현재 정렬/삭제 상태에 따라 의미가 바뀔 수 있으므로 주의합니다.
