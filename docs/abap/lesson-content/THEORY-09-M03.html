학습 목표

지난 Lesson에서는 WHERE 조건으로 여러 줄 결과를 좁혔습니다. 이번에는 SELECT SINGLE로 Single Row를 조회하고, 결과를 SY-SUBRC로 확인하는 흐름을 배웁니다.

1. 한 줄만 필요할 때가 있다 🧭

모든 조회가 여러 줄 목록을 만들기 위한 것은 아닙니다. 사용자가 입력한 국가 코드에 대한 국가명 한 줄만 필요하거나, 특정 고객 번호의 기본 정보 한 건만 확인하면 되는 경우가 있습니다.

이런 단건 조회에서 자주 만나는 문법이 SELECT SINGLE입니다. 이름 그대로 조건에 맞는 한 줄을 읽어옵니다.

SELECT SINGLE은 “조건에 맞는 한 건을 읽어와서 구조 변수에 담아줘”라는 요청입니다.

2. SELECT SINGLE 기본 구조 🔍

SELECT SINGLE FROM t005t
  FIELDS land1, landx
  WHERE spras = @sy-langu
    AND land1 = @p_land1
  INTO @DATA(ls_country).

여러 줄을 받는 INTO TABLE과 달리, SELECT SINGLE은 한 줄 구조에 결과를 담습니다. 그래서 변수 이름도 lt_가 아니라 ls_처럼 한 줄 구조 느낌으로 읽으면 좋습니다.

  • SELECT SINGLE: 한 줄만 조회합니다.
  • INTO @DATA(ls_country): 결과 한 줄을 구조 변수에 담습니다.
  • sy-subrc = 0: 조회 성공을 뜻합니다.

3. 결과 확인은 바로 뒤에서 하기 🚦

SELECT SINGLE FROM t005t
  FIELDS land1, landx
  WHERE spras = @sy-langu
    AND land1 = @p_land1
  INTO @DATA(ls_country).

IF sy-subrc = 0.
  WRITE: / ls_country-land1, ls_country-landx.
ELSE.
  WRITE: / '해당 국가 텍스트를 찾지 못했습니다.'.
ENDIF.

SY-SUBRC는 직전 명령의 결과 상태를 알려주는 시스템 필드입니다. 다른 명령이 실행되면 값이 바뀔 수 있으므로, 확인하고 싶은 SELECT 바로 뒤에서 읽는 습관이 중요합니다.

4. 전체 예제로 단건 조회하기 ✍️

REPORT zsql_select_single.

PARAMETERS p_land1 TYPE t005t-land1 DEFAULT 'KR'.

SELECT SINGLE FROM t005t
  FIELDS land1, landx
  WHERE spras = @sy-langu
    AND land1 = @p_land1
  INTO @DATA(ls_country).

IF sy-subrc = 0.
  WRITE: / '국가 코드:', ls_country-land1.
  WRITE: / '국가명:',    ls_country-landx.
ELSE.
  WRITE: / '조회 결과가 없습니다.'.
ENDIF.

p_land1에 존재하는 국가 코드를 넣으면 성공 흐름으로, 존재하지 않는 코드를 넣으면 실패 흐름으로 갑니다. 이 성공/실패 분리가 단건 조회의 핵심입니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 조건에 맞는 한 줄이 있으면 구조 변수에 값이 담기고 sy-subrc = 0입니다.
  • ❌ 조회 실패: 조건에 맞는 줄이 없으면 sy-subrc가 0이 아니며 실패 메시지를 보여줘야 합니다.
  • ❌ 키 조건 부족: 여러 줄이 가능한 조건으로 SELECT SINGLE을 쓰면 어떤 한 줄인지 업무적으로 애매할 수 있습니다.
  • ❌ SY-SUBRC 늦게 확인: SELECT 후 다른 문장이 실행되면 sy-subrc 값이 바뀔 수 있습니다.

미니 실습으로 p_land1에 존재하지 않을 만한 값을 넣어 실패 흐름을 확인해보세요. 성공보다 실패 메시지를 제대로 보는 것이 더 중요할 때도 많습니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

SELECT SINGLE은 “아무거나 하나”가 되면 위험합니다

조건이 고유하지 않은데 SELECT SINGLE을 쓰면 업무적으로 어떤 한 줄을 가져오는지 애매해질 수 있습니다. 단건 조회는 가능한 한 키에 가까운 명확한 조건으로 작성해야 합니다.

또한 SELECT SINGLE은 한 줄만 가져오므로 목록 출력에는 맞지 않습니다. 여러 줄 결과가 필요하면 INTO TABLE로 Result Set을 받아야 합니다.

7. 한눈에 정리 🏁

📝

SELECT SINGLE 핵심

  • SELECT SINGLE은 조건에 맞는 한 줄을 조회합니다.
  • Single Row 결과는 Internal Table이 아니라 구조 변수에 담습니다.
  • SY-SUBRC로 조회 성공과 실패를 바로 확인합니다.
  • 조건이 고유하지 않으면 어떤 한 줄인지 애매해질 수 있습니다.
  • 목록이 필요하면 SELECT SINGLE이 아니라 INTO TABLE 조회를 사용합니다.
