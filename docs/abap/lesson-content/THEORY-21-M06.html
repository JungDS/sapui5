학습 목표

완성한 Business Object를 외부(Fiori 등)에 노출하는 Service Definition과 Service Binding을 배웁니다. CDS·동작이 OData 서비스가 되어 화면과 연결되는 마지막 다리를 익힙니다.

1. 지난 시간 연결: 다 만들었으니 "내보내자" 📡

데이터 모델(ZI_/ZC_)·동작(BDEF/BIL)을 만들었습니다. 그런데 Fiori 화면이나 외부 시스템이 이걸 쓰려면, 서비스로 노출해야 합니다. 그 노출 과정이 Service Definition + Service Binding입니다.

2. Service Definition: 무엇을 노출할지 ✍️

define service ZUI_Travel {
  expose ZC_Travel as Travel;
  // 필요하면 관련 뷰도 함께 노출
  expose ZC_Agency as Agency;
}
  • define service: "이 서비스로 어떤 뷰들을 내보낼지" 목록.
  • expose ... as ...: 노출할 Projection View와 외부에서 부를 이름.

3. Service Binding: 어떤 프로토콜로 🔌

Service Binding은 그 서비스를 어떤 방식(프로토콜)으로 외부에 열지 정합니다.

  • OData V4 - UI: Fiori Elements 화면용(가장 흔함).
  • OData V2 - UI: 구버전 UI5 호환용.
  • OData V4 - Web API: 시스템 간 연동용(화면 없는 API).
💡

비유: 가게 오픈과 간판

Service Definition이 "무슨 상품을 팔지(메뉴)" 정하는 것이라면, Service Binding은 "어느 출입문으로 손님을 받을지(배달앱? 매장?)" 정하는 거예요. Binding을 활성화(Publish)하면 비로소 손님(Fiori)이 들어올 수 있습니다.

4. 활성화하면 화면 미리보기까지 🔍

Service Binding을 활성화(Publish)하면, ADT에서 바로 Fiori Elements 미리보기로 목록·상세 화면을 코드 없이 확인할 수 있습니다. CDS의 @UI 주석이 화면으로 그대로 그려지는 것을 눈으로 보게 됩니다.

  • ✅ 정상: Definition(메뉴) + Binding(출입문) 활성화 → OData 서비스 가동 + 화면 미리보기.
  • ❌ 오류: Binding을 활성화(Publish)하지 않음 → 서비스가 안 열려 화면이 데이터를 못 가져옴.

5. 실무에서 조심할 점 🚨

⚠️

노출 = 외부 공개, 신중히

서비스로 노출하는 순간 그 데이터·동작이 외부에 열립니다. 어떤 Projection을 노출하는지(민감 필드 포함 여부), 어떤 권한이 걸려 있는지(BDEF authorization, CDS DCL)를 함께 점검하세요. 또 한 번 외부에 공개한 서비스의 구조를 함부로 바꾸면, 그걸 쓰는 화면·연동이 깨질 수 있으니 변경 관리가 중요합니다.

6. 미니 실습: What과 How 분리하기 🧪

이번 실습은 Service Definition과 Service Binding을 한 덩어리로 보지 않고, “무엇을 노출할지”와 “어떤 프로토콜로 노출할지”를 분리하는 연습입니다.

✍️

실습 과제

  1. 노출할 Projection View 1개를 고르고, Service Definition의 expose 후보로 적습니다.
  2. UI 서비스와 Web API 중 어떤 Binding Type이 어울릴지 시나리오별로 나눕니다.
  3. Service Definition만 만들고 Binding을 publish하지 않았을 때 소비자가 왜 바로 호출할 수 없는지 적습니다.

완료 조건: Service Definition은 범위, Service Binding은 프로토콜과 게시를 담당한다고 설명할 수 있으면 성공입니다.

8. 확인 퀴즈와 정답/해설 ✅

  1. Service Definition과 Service Binding의 가장 큰 차이는 무엇인가요?
  2. OData V4 UI 서비스와 Web API는 항상 같은 목적이라고 볼 수 있나요?
  3. Binding을 만들었는데 호출이 안 될 때 확인할 것은 무엇인가요?
정답/해설 보기
  1. Definition은 무엇을 노출할지, Binding은 어떤 프로토콜과 방식으로 노출할지를 정합니다.
  2. 아닙니다. UI 서비스는 Fiori UI 소비에 초점이 있고, Web API는 일반 외부 소비자 접근에 더 초점이 있습니다.
  3. Binding Type, publish 상태, 대상 Service Definition, 시스템별 게이트웨이/런타임 설정을 확인합니다.

9. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Service Definition은 "무엇을(어떤 뷰를) 노출할지" 정합니다.
  • Service Binding은 "어떤 프로토콜(OData V4 UI 등)로" 열지 정하고 Publish합니다.
  • 활성화하면 OData 서비스가 가동되고 Fiori 미리보기가 됩니다.
  • 노출은 외부 공개이므로 필드·권한·변경 관리를 신중히.
