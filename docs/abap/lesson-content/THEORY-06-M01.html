학습 목표

이번 Chapter에서는 ABAP에서 여러 줄 데이터를 다루는 핵심 도구인 Internal Table을 배웁니다. 왜 데이터베이스에서 바로바로 처리하지 않고, Application Server의 Runtime Memory에 데이터를 올려서 가공하는지 감을 잡습니다.

1. 지난 Chapter 연결: 모듈 안에서 다룰 데이터가 필요하다 🧭

Chapter 5에서는 코드를 FORM, Function Module, Class처럼 작은 기능 단위로 나누는 법을 봤습니다. 그런데 기능을 나누기만 해서는 부족합니다. 실제 업무 프로그램은 보통 한 건이 아니라 여러 건의 데이터를 읽고, 비교하고, 합치고, 출력합니다.

예를 들어 학생 1명의 이름을 출력하는 것은 변수 하나로 충분합니다. 하지만 학생 30명의 점수를 읽고 평균을 계산하려면, 한 줄짜리 변수만으로는 금방 답답해집니다. 이때 필요한 것이 프로그램 안의 임시 표, 즉 Internal Table입니다.

Internal Table은 ABAP 프로그램 안에서 여러 줄 데이터를 들고 다니는 “작업용 표”입니다.

2. Internal Table은 데이터베이스 테이블이 아니다 🧠

Internal Table은 이름에 Table이 들어가지만, DDIC의 Transparent Table처럼 데이터베이스에 영구 저장되는 표가 아닙니다. ABAP 프로그램이 실행되는 동안 메모리에 만들어졌다가, 프로그램이 끝나면 사라지는 임시 데이터 묶음입니다.

  • Transparent Table: 데이터베이스에 저장되는 실제 테이블입니다. 프로그램이 끝나도 데이터가 남습니다.
  • Internal Table: 프로그램 실행 중에만 존재하는 메모리 속 표입니다. 정렬, 반복, 검색, 계산에 자주 씁니다.
  • Work Area: Internal Table의 한 줄을 잠깐 담아 처리하는 한 줄짜리 작업 공간입니다.

초심자에게 가장 중요한 구분은 “저장소냐, 작업 공간이냐”입니다. Internal Table은 영구 저장소가 아니라 처리 중간에 쓰는 작업 공간입니다.

3. 어디에 만들어질까? Application Server와 Runtime Memory 🏗️

SAP 시스템은 보통 사용자가 보는 SAP GUI, 프로그램이 실행되는 Application Server, 데이터가 저장되는 Database Server로 나누어 생각할 수 있습니다. ABAP 프로그램은 주로 Application Server에서 실행되고, 실행 중 필요한 임시 데이터는 Runtime Memory에 올라갑니다.

💡

머릿속 그림

데이터베이스는 큰 창고, Application Server는 작업대, Runtime Memory는 작업대 위에 펼쳐둔 임시 종이라고 생각하면 쉽습니다. Internal Table은 그 임시 종이에 그린 표입니다.

그래서 Internal Table에 너무 많은 데이터를 무작정 담으면 메모리를 많이 쓰고, 전체 프로그램이 느려질 수 있습니다. “일단 다 가져오자”보다 “필요한 만큼 가져와 처리하자”가 실무에서 훨씬 안전합니다.

REPORT zinternal_table_intro.

TYPES: BEGIN OF ty_student,
         id   TYPE char3,
         name TYPE char20,
       END OF ty_student.

DATA: lt_students TYPE STANDARD TABLE OF ty_student,
      ls_student  TYPE ty_student.

ls_student-id = 'A01'.
ls_student-name = '정훈영'.
APPEND ls_student TO lt_students.

LOOP AT lt_students INTO ls_student.
  WRITE: / ls_student-id, ls_student-name.
ENDLOOP.

지금은 문법을 완벽히 외우지 않아도 됩니다. 큰 흐름만 먼저 보세요. 한 줄 모양을 정하고, 여러 줄을 담을 표를 만들고, 한 줄을 넣은 뒤, 반복해서 출력합니다.

APPEND는 Work Area의 현재 값을 Internal Table 끝에 한 줄로 복사합니다. LOOP는 그 표를 한 줄씩 Work Area로 다시 읽어옵니다.

  • ty_student: 한 줄이 어떤 칸으로 구성되는지 정합니다.
  • lt_students: 여러 학생 줄을 담는 Internal Table입니다.
  • ls_student: 한 학생 줄을 잠깐 담는 Work Area입니다.
  • APPEND: Work Area의 현재 값을 Internal Table 끝에 추가합니다.
  • LOOP AT: Internal Table의 줄을 하나씩 읽습니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: Work Area에 값이 들어가고, APPEND로 Internal Table에 한 줄이 추가됩니다. LOOP AT이 그 줄을 읽어 출력합니다.
  • ❌ 빈 테이블: APPEND를 하지 않으면 Internal Table에 줄이 없습니다. LOOP AT 안의 출력문도 실행되지 않습니다.
  • ❌ 필드 이름 오타: ls_student-nam처럼 구조에 없는 필드를 쓰면 문법 오류가 납니다.
  • ❌ 너무 많은 데이터: 조건 없이 대량 데이터를 전부 담으면 Runtime Memory 사용량이 커질 수 있습니다.

미니 실습으로 학생을 2명 더 추가해보세요. Output List에 3줄이 나오면 성공입니다. 일부러 APPEND 한 줄을 주석 처리하면 출력 줄 수가 어떻게 바뀌는지도 확인해보면 좋습니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

Internal Table은 편하지만 공짜는 아닙니다

Internal Table은 데이터베이스를 계속 왔다 갔다 하지 않고 메모리에서 빠르게 처리할 수 있게 도와줍니다. 하지만 필요한 조건 없이 너무 많이 담으면 성능과 메모리에 부담이 됩니다. 특히 운영 데이터는 “몇 건 정도 들어올지”를 늘 생각해야 합니다.

또한 고객사마다 Internal Table을 선언하는 스타일, 이름 규칙, 성능 기준이 다를 수 있습니다. 표준 ABAP 문법과 프로젝트 관행을 구분해서 읽는 습관을 들이면 현장 코드가 훨씬 덜 무섭습니다.

7. 한눈에 정리 🏁

📝

Internal Table 첫 감각

  • Internal Table은 프로그램 실행 중 메모리에 존재하는 임시 표입니다.
  • Transparent Table은 영구 저장소, Internal Table은 작업용 데이터 묶음입니다.
  • ABAP 프로그램은 Application Server에서 실행되고, Internal Table은 Runtime Memory를 사용합니다.
  • 여러 줄 데이터를 반복, 검색, 계산, 출력할 때 Internal Table이 필요합니다.
  • 편하다고 무조건 많이 담지 말고 필요한 데이터만 다루는 습관이 중요합니다.
