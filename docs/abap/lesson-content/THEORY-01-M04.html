학습 목표

이번 Lesson에서는 낱개 Data Element를 모아 한 줄짜리 데이터 모양을 만드는 Structure를 설계합니다. Component, Work Area, Reusable Type을 구분하고, SE11에서 Structure를 생성·활성화하는 흐름을 직접 시뮬레이션합니다.

1. Structure는 한 줄 데이터의 설계도다

지금까지는 Domain으로 재질을 정하고 Data Element로 의미와 라벨을 붙였습니다. 하지만 실제 업무 데이터는 필드 하나만으로 움직이지 않습니다. 주문 한 건에는 주문번호, 고객번호, 주문일, 상태가 함께 필요합니다.

Structure는 이렇게 함께 움직이는 Component를 정해진 순서로 묶은 Dictionary 타입입니다. SAP 공식 문서 기준으로 Structure는 다른 데이터 타입을 Component로 포함하는 structured type이며, ABAP 코드의 변수나 파라미터 타입으로 사용할 수 있습니다.

Structure는 데이터 저장소가 아니라 “한 줄 값이 어떤 칸을 가져야 하는가”를 정하는 재사용 가능한 타입입니다.

2. Structure 안에는 Component가 들어간다

Structure를 표의 한 행처럼 생각하면 쉽습니다. Structure 자체는 한 줄의 모양이고, 그 안의 각 칸이 Component입니다. Component type에는 Data Element를 자주 사용합니다. 그래야 기술 타입뿐 아니라 라벨과 의미 정보도 따라옵니다. SAP 공식 예시처럼 predefined Dictionary type이나 다른 Structure를 Component Type으로 쓰는 경우도 있지만, 이번 초급 실습에서는 앞 Lesson에서 만든 Data Element를 조립하는 흐름에 집중합니다. Domain 이름을 Component Type 자리에 직접 넣는 방식은 피합니다.

주문 한 줄 Structure 예시

Component Component Type 의미
ORDER_ID ZDE_ORDER_ID 주문 번호
CUSTOMER_ID ZDE_CUSTOMER_ID 고객 번호
ORDER_DATE ZDE_ORDER_DATE 주문일
STATUS ZDE_ORDER_STATUS 주문 상태

Component 이름은 Structure 안에서 보이는 칸 이름이고, Component Type은 그 칸이 어떤 Data Element나 타입을 참조하는지입니다.

4. Structure와 Transparent Table은 닮았지만 다르다

Structure와 Transparent Table은 모두 필드 목록처럼 보입니다. 하지만 Structure는 타입이고, Transparent Table은 데이터베이스 저장 대상입니다.

저장 여부로 구분하기

Structure
  • 한 줄 데이터 타입입니다.
  • ABAP 변수, 메서드 파라미터, Table Type row로 재사용합니다.
  • 영구 저장소 아님
Transparent Table
  • DB 테이블 정의입니다.
  • Key, Client, Technical Settings 같은 저장 관련 설계가 필요합니다.
  • 영구 저장 가능

SELECT * FROM 구조체라고 생각하면 안 됩니다. 조회 대상은 DB 테이블이고, Structure는 조회 결과를 담거나 전달하는 타입입니다.

5. Work Area와 Reusable Type을 구분한다

Structure 정의 자체는 설계도입니다. ABAP 프로그램에서 DATA gs_order TYPE zst_order_line.처럼 선언할 때 실제 메모리의 Work Area가 생깁니다.

Flat, Nested, Deep은 지금 어디까지 알면 될까?

이번 Lesson의 중심은 Component가 주로 Data Element 같은 elementary type을 참조하는 flat structure입니다. Component가 또 다른 Structure를 참조하면 nested, table type이나 reference 같은 깊은 Component를 포함하면 deep structure로 확장됩니다.

7. 확인 퀴즈

  1. Structure를 활성화하면 실제 DB 테이블이 자동으로 만들어질까요?
  2. Structure 안의 낱개 필드는 무엇이라고 부르나요?
  3. DATA gs_order TYPE zst_order_line.에서 타입과 변수는 각각 무엇인가요?
  4. Structure와 Transparent Table의 가장 큰 차이는 무엇인가요?
  5. Component type에 Data Element를 쓰면 어떤 장점이 있나요?
정답/해설 보기
  1. 아니요. Structure는 DB 저장소가 아니라 Dictionary 타입입니다.
  2. Component입니다. 각 Component는 Data Element나 직접 타입을 참조할 수 있습니다.
  3. zst_order_line은 타입, gs_order는 변수입니다. 변수는 프로그램 메모리에 생기는 Work Area입니다.
  4. 영구 저장 여부입니다. Structure는 한 줄 타입이고, Transparent Table은 DB 저장 대상입니다.
  5. 라벨과 의미 정보까지 재사용하기 쉽습니다. 기술 타입만 맞추는 것보다 화면과 문서 연결이 좋아집니다.

8. 한눈에 정리

Structure여러 Component를 묶어 한 줄 데이터 모양을 만드는 DDIC 타입입니다.
ComponentStructure 안의 낱개 칸이며 Data Element나 직접 타입을 참조합니다.
Work AreaStructure 타입으로 만든 실제 ABAP 메모리 변수입니다.
저장소 아님Structure는 DB 테이블이 아닙니다. 영구 저장은 Transparent Table의 역할입니다.
