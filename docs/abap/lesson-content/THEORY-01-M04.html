학습 목표

지금까지 만든 낱개 필드들을 하나로 예쁘게 묶어주는 Structure(구조체)를 만들어 봅니다. Structure 안에 들어가는 컴포넌트(Component)의 개념을 익히고, 왜 이 구조체가 강력한 재사용 가능한 타입(Reusable Type)으로 쓰이는지 완벽히 이해해 봅니다.

1. 지난 시간 요약 & 부품 꾸러미가 필요한 이유 🤔

이전 Lesson까지 우리는 도메인(Domain)과 데이터 엘리먼트(Data Element)를 결합하여 완벽한 '낱개 필드' 부품을 만들었습니다.

하지만 실무에서 데이터는 결코 혼자 돌아다니지 않아요! 예를 들어 '항공편 예약 한 건'을 생각해 볼까요? 거기에는 항공사 이름, 편명, 출발지, 도착지, 출발 날짜, 요금 등 여러 정보가 한 세트로 뭉쳐 다녀야만 비로소 완전한 데이터의 의미를 가집니다. 이렇게 낱개 부품들을 하나로 묶어줄 보따리가 필요해졌습니다.

2. Structure(구조체)란 무엇일까? 📦

이렇게 여러 개의 필드를 정해진 순서대로 묶어놓은 꾸러미를 SAP에서는 Structure(구조체)라고 부릅니다. 그리고 이 꾸러미 안에 쏙쏙 들어있는 각각의 낱개 필드를 컴포넌트(Component)라고 부르죠.

💡

Structure 조립 예시 (항공편 정보: ZSFLIGHT)

  • 1번 칸(컴포넌트): CARRID (항공사) - 타입: Data Element
  • 2번 칸(컴포넌트): CONNID (편명) - 타입: Data Element
  • 3번 칸(컴포넌트): FLDATE (날짜) - 타입: Data Element
  • 4번 칸(컴포넌트): PRICE (요금) - 타입: Data Element

이렇게 줄을 세워서 하나의 Structure로 저장(활성화)하면, 이제 어디서든 "ZSFLIGHT 세트 메뉴 하나 주세요!" 하고 한꺼번에 가져다 쓸 수 있게 됩니다.

3. Structure의 가장 큰 오해: "여기에 데이터가 저장되나요?" 🥣

초보 개발자들이 가장 많이 헷갈리고 실수하는 부분입니다. 꼭 기억하세요! Structure 자체는 데이터베이스에 데이터를 영구히 저장하지 않습니다.

그럼 뭐냐고요? Structure는 밥알을 영원히 보관하는 냉동고가 아니라, 밥을 먹기 위해 잠깐 담았다가 설거지하면 비워지는 '빈 그릇' 또는 "이 그릇은 4칸으로 나뉘어 있어"라고 알려주는 '설계도'일 뿐입니다.

프로그램에서의 역할: ABAP 코딩을 할 때 DATA: gs_flight TYPE zsflight. 라고 쓰면, 메모리(컴퓨터의 임시 작업 공간)에 딱 이 Structure 모양대로 작업 영역(Work Area)이 생깁니다. 프로그램이 실행되는 동안 여기에 데이터를 담고 꺼내며 볶고 지지고 하다가, 프로그램이 끝나면 그릇은 깨끗하게 비워집니다.

4. 글로벌 타입으로의 재사용(Reusable Type) ♻️

DDIC에 Structure를 한 번 예쁘게 만들어 두면, 이 구조체는 시스템 전체에서 쓸 수 있는 전역(Global) 타입이 되어 엄청난 재사용성을 자랑합니다.

  • ✅ 프로그램 변수: 방금 말했듯, 임시 작업 영역(Work Area)을 만들거나 나중에 배울 Internal Table(데이터 목록)의 한 줄 모양을 잡을 때 이 Structure 이름을 그대로 가져다 씁니다.
  • ✅ 모듈 간 대화: 다른 프로그램이나 함수(Function)에 "나한테 항공편 정보 세트 메뉴(ZSFLIGHT)로 데이터 넘겨줘!"라고 약속(인터페이스 파라미터)할 때 사용합니다. 서로 모양이 같으니 데이터가 찰떡같이 전달되죠.

5. 실무에서 조심해야 할 점 🚨

⚠️

순서가 깡패입니다! 컴포넌트 순서 주의

Structure 안의 컴포넌트들은 만들어진 순서가 매우 중요합니다. 만약 프로그램에서 서로 모양이 비슷한 두 Structure끼리 데이터를 통째로 복사(단순 = 대입)할 때, 순서가 조금이라도 어긋나 있으면 '이름' 칸에 '나이'가 들어가버리는 끔찍한 대참사가 일어납니다.

그래서 실무에서는 웬만하면 단순 대입보다는 이름이 같은 컴포넌트끼리만 안전하게 값을 옮겨주는 MOVE-CORRESPONDING 명령어를 즐겨 씁니다. (이건 나중에 코딩 시간에 자세히 배울 거예요!)

참고로, Structure 안에 또 다른 Structure를 통째로 집어넣는 복잡한 구조(Deep Structure)도 만들 수 있지만, 지금 당장 몰라도 됩니다! THEORY-07에서 따로 다룰 테니 안심하세요.

6. 한눈에 정리 🏁

📝

오늘의 요약

  • Structure(구조체)는 여러 개의 Data Element(필드)를 정해진 순서대로 하나로 묶은 꾸러미입니다.
  • Structure 안의 낱개 칸 하나하나를 컴포넌트(Component)라고 부릅니다.
  • 가장 중요! Structure는 데이터를 담아두는 빈 그릇(임시 작업 영역)이자 설계도일 뿐, DB에 데이터를 영원히 저장하지 않습니다.
  • 한 번 만들어둔 Structure는 시스템 전역에서 변수 선언, 함수 매개변수 등 다양한 곳에 재사용(Reusable) 됩니다.

자, 우리는 이제 여러 데이터를 예쁘게 담을 수 있는 훌륭한 그릇(Structure)까지 만들어냈습니다.

그런데, 이 그릇에 담긴 데이터를 영원히 보관하려면 어떻게 해야 할까요? 컴퓨터를 껐다 켜도 데이터가 날아가지 않도록, 진짜 데이터베이스에 데이터를 꽉꽉 채워 넣을 창고가 필요합니다. 다음 Lesson 'Transparent Table 기본 생성'에서 드디어 진짜 데이터를 저장하는 투명 테이블을 만들어보겠습니다!
