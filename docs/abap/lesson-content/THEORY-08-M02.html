학습 목표

지난 Lesson에서 SALV의 목적을 봤습니다. 이번에는 FACTORY Method로 SALV 객체를 만들고, Changing Table에 Internal Table을 넘긴 뒤 DISPLAY로 화면에 표시합니다.

1. SALV 출력은 세 단계로 보면 쉽다 🧭

SALV 문법이 처음에는 길어 보입니다. 하지만 흐름을 세 단계로 나누면 훨씬 쉽습니다.

  1. Internal Table에 보여줄 데이터를 준비합니다.
  2. cl_salv_table=>factory로 SALV 객체를 만듭니다.
  3. lo_alv->display( )로 화면에 보여줍니다.
데이터 준비 → SALV 객체 생성 → DISPLAY 실행, 이 순서만 먼저 잡으면 됩니다.

2. FACTORY Method는 표 객체를 만들어준다 🏭

FACTORY는 SALV 객체를 생성하는 Method입니다. 이름 그대로 “공장”처럼 필요한 표시 객체를 만들어 돌려줍니다.

ABAP
1
2
3 
cl_salv_table=>factory(
  IMPORTING r_salv_table = lo_alv
  CHANGING  t_table      = lt_students ).
  • cl_salv_table=>factory: Class의 Static Method 호출입니다.
  • r_salv_table = lo_alv: 생성된 SALV 객체를 lo_alv에 받습니다.
  • t_table = lt_students: 표시할 Internal Table을 넘깁니다.

여기서 CHANGING은 “이 테이블을 대상으로 SALV를 준비한다”는 느낌으로 보면 됩니다. 초심자 단계에서는 방향보다 역할을 먼저 잡으세요.

REPORT zsalv_factory_basic.

TYPES: BEGIN OF ty_student,
         id    TYPE char3,
         name  TYPE char20,
         score TYPE i,
       END OF ty_student.

DATA: lt_students TYPE STANDARD TABLE OF ty_student,
      ls_student  TYPE ty_student,
      lo_alv      TYPE REF TO cl_salv_table,
      lx_msg      TYPE REF TO cx_salv_msg.

ls_student-id = 'A01'. ls_student-name = 'Mina'. ls_student-score = 90.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A02'. ls_student-name = 'Jun'. ls_student-score = 85.
APPEND ls_student TO lt_students.

TRY.
    cl_salv_table=>factory(
      IMPORTING r_salv_table = lo_alv
      CHANGING  t_table      = lt_students ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO lx_msg.
    MESSAGE lx_msg->get_text( ) TYPE 'E'.
ENDTRY.

이 코드는 학생 2명을 Internal Table에 넣고 SALV로 표시합니다. TRY...CATCH는 SALV 객체 생성 중 발생할 수 있는 예외를 처리하기 위한 기본 안전장치입니다.

4. DISPLAY는 화면 표시의 마지막 버튼 ▶️

DISPLAY는 준비된 SALV 객체를 실제 화면에 표시합니다. FACTORY까지만 호출하고 DISPLAY를 호출하지 않으면 객체는 만들어졌지만 사용자는 화면을 보지 못합니다.

ABAP
1 
lo_alv->display( ).

이 한 줄은 “준비된 ALV 표를 지금 사용자에게 보여줘”라는 의미입니다. SALV 기본 사용에서는 사실상 마지막 실행 버튼입니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: Internal Table 준비, FACTORY 성공, DISPLAY 실행 순서로 SALV 화면이 열립니다.
  • ❌ DISPLAY 누락: FACTORY만 호출하면 화면이 표시되지 않습니다.
  • ❌ 참조 변수 미생성: FACTORY가 실패하면 lo_alv가 제대로 준비되지 않을 수 있습니다.
  • ❌ 예외 무시: SALV 관련 예외를 무시하면 사용자에게 원인을 설명하기 어렵습니다.

미니 실습으로 lo_alv->display( ). 줄을 주석 처리해보세요. 데이터와 객체 생성 코드가 있어도 화면이 안 뜬다는 점을 확인하면 DISPLAY 역할이 선명해집니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

표시 전에 데이터 품질을 먼저 확인하기

SALV는 Internal Table을 보기 좋게 보여줄 뿐, 데이터의 의미를 자동으로 검증하지 않습니다. 잘못 가공된 데이터도 예쁘게 보일 수 있으므로 DISPLAY 전에 건수와 주요 필드를 확인하는 습관이 필요합니다.

또한 SALV 예제는 간단하지만 실제 운영에서는 권한, 데이터 범위, 조회 조건, 빈 결과 메시지까지 함께 설계해야 합니다.

7. 한눈에 정리 🏁

📝

FACTORY 출력 핵심

  • FACTORY는 SALV 표 객체를 생성합니다.
  • Changing Table로 표시할 Internal Table을 넘깁니다.
  • DISPLAY는 준비된 SALV 화면을 실제로 보여줍니다.
  • 흐름은 데이터 준비 → FACTORY → DISPLAY입니다.
  • DISPLAY 전에 데이터 건수와 주요 값이 기대대로인지 확인합니다.
