학습 목표

ABAP에 이미 들고 있는 목록을 기준으로 DB를 조회하는 FOR ALL ENTRIES(줄여서 FAE)를 배웁니다. 강력하지만 함정이 많아서, 빈 테이블 체크와 중복 누락 위험이라는 두 함정을 반드시 기억해야 합니다.

1. 지난 시간 연결: JOIN으로 안 풀리는 경우 🧩

JOIN은 "DB 테이블끼리" 연결할 때 좋습니다. 그런데 실무에서는 이미 ABAP 내부 테이블에 들고 있는 목록을 기준으로 다른 테이블을 조회하고 싶을 때가 있습니다.

예를 들어, 화면에서 사용자가 고른 주문 번호 50개가 내부 테이블 lt_orders에 있고, 이 50개에 해당하는 상세 내역만 VBAP에서 가져오고 싶다고 해볼게요. 이럴 때 쓰는 것이 FOR ALL ENTRIES입니다.

2. FOR ALL ENTRIES 기본 모양 ✍️

ABAP
1
2
3
4
5
6 
" lt_orders 에 들고 있는 주문번호들로 상세를 조회
SELECT vbeln, posnr, matnr
  FROM vbap
  FOR ALL ENTRIES IN @lt_orders
  WHERE vbeln = @lt_orders-vbeln
  INTO TABLE @DATA(lt_items).

lt_orders의 각 줄에 들어 있는 vbeln 값으로 VBAP를 반복 조회한 뒤, 결과를 한 테이블로 합쳐 줍니다. ABAP이 알아서 효율적인 조회로 바꿔 실행합니다.

3. 함정 ① — 빈 테이블이면 "전체"가 조회된다 💣

🚨

가장 유명한 ABAP 사고

기준 테이블(lt_orders)이 비어 있으면, FOR ALL ENTRIES의 WHERE 조건이 통째로 사라져서 테이블 전체가 조회됩니다! 수백만 건이 한꺼번에 딸려와 시스템이 멈출 수 있습니다.

그래서 FAE를 쓰기 직전에 반드시 기준 테이블이 비었는지 확인합니다.

ABAP
1
2
3 
IF lt_orders IS NOT INITIAL.        "← 이 한 줄이 사고를 막는다
  SELECT ... FOR ALL ENTRIES IN @lt_orders ...
ENDIF.

4. 함정 ② — 중복이 자동으로 사라진다 🫥

FOR ALL ENTRIES 결과는 완전히 똑같은 행(모든 SELECT 필드 값이 동일)을 자동으로 하나로 합쳐 버립니다. 그래서 의도치 않게 건수가 줄 수 있습니다.

  • ✅ 해결: 결과의 키 필드를 SELECT에 포함시키면, 서로 다른 행이 같은 값으로 합쳐지는 일을 막을 수 있습니다.
  • ❌ 실수: 키를 빼고 일부 필드만 조회 → 원래 여러 건이던 것이 한 건으로 합쳐져 "데이터가 줄었다"는 혼란.
"FAE는 중복을 지운다"는 사실을 모르면, 건수가 맞지 않는 버그를 찾느라 한참 헤맵니다. 항상 키를 포함해서 조회하세요.

6. 실무에서 조심할 점 🚨

⚠️

FAE 체크리스트

  • ① 기준 테이블 비었는지 IF로 확인(가장 중요).
  • ② 결과 키 필드를 SELECT에 포함(중복 누락 방지).
  • ③ 기준 테이블이 지나치게 크면(수만 건+) 성능 저하 → 이럴 땐 JOIN이나 다른 방법 고려.
  • ④ FAE에는 ORDER BY를 함께 신뢰하기 어렵습니다. 정렬은 받은 뒤 SORT로 처리하는 편이 안전합니다.

7. 미니 실습: FOR ALL ENTRIES 함정 직접 경험하기 🧪

✍️

실습 과제

  1. 예제를 SE38에서 실행해 lt_orders에 주문번호를 채운 뒤 FAE 조회가 해당 건만 반환하는지 확인합니다.
  2. IF lt_orders IS NOT INITIAL 조건을 빼고 lt_orders를 비운 채 실행해봅니다. 전체 테이블이 조회되는 위험을 직접 경험합니다(데이터 양이 많으면 조심).
  3. 키 필드(vbeln, posnr)를 SELECT에서 빼고 matnr만 조회했을 때 결과 건수가 줄어드는 중복 제거 현상을 확인합니다.
  4. 정훈영이 고객 주문(홍길동·아이유·유재석 주문)을 먼저 조회한 뒤, FAE로 상세를 가져오는 흐름을 머릿속으로 그려봅니다.

완료 조건: "기준 테이블이 비면 전체 조회", "키 없으면 중복 제거" 두 함정을 직접 경험했으면 성공입니다.

8. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: SELECT … FOR ALL ENTRIES — FAE 문법, 빈 테이블 동작, 중복 제거 동작을 공식 설명으로 확인합니다.
  • SAP Help Portal: SELECT … JOIN — FAE 대신 JOIN을 써야 하는 경우와 비교합니다.
  • SAP Help Portal: SELECT 문 개요 — FAE가 SELECT 절에서 어떻게 위치하는지 전체 구조로 확인합니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. 정훈영이 lt_orders IS NOT INITIAL 체크를 빼먹고 FAE를 실행했는데, 마침 lt_orders가 비어 있었다면 어떤 일이 일어날까요?
  2. FAE 결과에서 중복 행이 자동으로 제거되는 문제를 막으려면 어떻게 해야 하나요?
  3. 기준 테이블에 건수가 10만 건 이상이라면 FAE를 써도 될까요?
정답/해설 보기
  1. 대상 테이블 전체가 조회됩니다. 기준 테이블이 비면 FAE의 WHERE 조건이 통째로 무시되어 수백만 건이 한꺼번에 ABAP으로 넘어올 수 있습니다. 이는 시스템이 멈추는 가장 유명한 ABAP 사고 중 하나입니다.
  2. 결과의 키 필드를 SELECT에 포함시킵니다. FAE는 SELECT에 나열한 모든 필드가 완전히 동일한 행을 자동으로 하나로 합칩니다. 키 필드를 포함하면 행마다 고유한 값이 생겨 중복 합산을 막을 수 있습니다.
  3. 신중하게 검토해야 합니다. FAE의 기준 테이블이 지나치게 크면(수만 건 이상) DB 서버에서 그만큼 많은 조건을 처리해야 해 오히려 JOIN보다 느릴 수 있습니다. 이 경우 JOIN이나 범위 조건(WHERE field IN @range) 등 다른 방법을 검토합니다.

10. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • FOR ALL ENTRIES는 ABAP 내부 테이블 목록을 기준으로 DB를 조회합니다.
  • ⚠️ 기준 테이블이 비면 전체가 조회되므로 IS NOT INITIAL 체크는 필수입니다.
  • 결과는 완전 중복 행이 자동 제거되므로 키 필드를 꼭 포함합니다.
  • 기준 테이블이 너무 크면 JOIN 등 다른 방법을 고려합니다.
