학습 목표

선택 화면이 뜨기 전에 입력 칸의 기본값을 채우는 INITIALIZATION 이벤트를 배웁니다. DDIC의 DEFAULT와 무엇이 다른지, 언제 이 이벤트를 쓰는지 익힙니다.

1. 지난 시간 연결: 화면이 뜨기 "전"을 잡아라 ⏮️

앞 Lesson에서 INITIALIZATION은 선택 화면이 뜨기 직전에 실행된다고 했습니다. 바로 이 타이밍이 기본값을 채우기에 딱 좋은 순간입니다.

사용자가 매번 같은 값을 입력하는 게 귀찮다면, "오늘 날짜", "이번 달 1일" 같은 값을 미리 채워두면 친절하겠죠. 그 일을 INITIALIZATION에서 합니다.

2. INITIALIZATION으로 기본값 채우기 ✍️

PARAMETERS: p_date TYPE sy-datum,
            p_bukrs TYPE bukrs.

INITIALIZATION.
  p_date  = sy-datum.        "오늘 날짜를 기본값으로
  p_bukrs = '1000'.          "회사코드 기본값

이렇게 하면 화면이 처음 뜰 때 날짜 칸에 오늘 날짜가, 회사코드 칸에 1000이 미리 채워져 나타납니다. 사용자는 그대로 실행하거나 필요할 때만 바꾸면 됩니다.

💡

SELECT-OPTIONS 기본값은 조금 다르게

PARAMETERS는 변수에 바로 대입하면 되지만, SELECT-OPTIONS는 Range 구조라 s_xxx-low, s_xxx-sign, s_xxx-option을 채우고 APPEND해야 합니다(THEORY-10에서 배운 Range 구조 그대로).

3. DDIC DEFAULT와 INITIALIZATION의 차이 🤔

"기본값이면 PARAMETERS에 DEFAULT로 적어도 되잖아요?"라는 질문이 자연스럽습니다. 맞습니다. 다만 쓰임이 다릅니다.

  • DEFAULT (선언부): 항상 고정된 값(예: DEFAULT 'X'). 단순하고 정적입니다.
  • INITIALIZATION (이벤트): 계산이 필요한 기본값(오늘 날짜, 이번 달 1일, 시스템 설정 조회 결과 등)에 적합합니다.
"고정된 값이면 DEFAULT, 실행 시점에 계산해야 하면 INITIALIZATION." 이렇게 나눠 기억하면 됩니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: INITIALIZATION에서 채운 값이 화면에 미리 표시되고, 사용자가 수정 가능합니다.
  • ❌ 오류 1 — 너무 늦게: START-OF-SELECTION에서 기본값을 넣으면 화면이 이미 지나가 적용 안 됩니다.
  • ❌ 오류 2 — 매번 덮어쓰기: INITIALIZATION은 보통 화면 진입마다 실행되므로, 사용자가 바꾼 값을 의도치 않게 되돌릴 수 있습니다(특히 화면 재표시 시). 무거운 로직은 피하세요.

5. 실무에서 조심할 점 🚨

⚠️

INITIALIZATION에 무거운 조회를 넣지 마세요

이 이벤트는 화면을 띄우기 위한 가벼운 준비 단계입니다. 여기서 대량 DB 조회나 복잡한 계산을 하면, 화면이 뜨기도 전에 사용자가 기다리게 됩니다. 무거운 작업은 사용자가 실행을 누른 뒤(START-OF-SELECTION)에 하세요. 기본값 세팅처럼 가벼운 것만 둡니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • INITIALIZATION은 선택 화면이 뜨기 전에 실행되어 기본값을 채웁니다.
  • 고정값은 DEFAULT, 계산이 필요한 값은 INITIALIZATION이 적합합니다.
  • SELECT-OPTIONS 기본값은 Range 구조를 채워 APPEND합니다.
  • 무거운 조회는 넣지 말고, 가벼운 기본값 세팅만 둡니다.
