학습 목표

여러 테이블을 묶어 한 화면에서 입력·수정할 수 있게 해주는 Maintenance View를 배웁니다. 이때 테이블들을 안전하게 묶어주는 Foreign Key 관계가 왜 중요한지 익힙니다.

1. 지난 시간 연결: 보기만 말고 "고치기"까지 ✏️

지금까지 배운 View들(Database/Projection/Help)은 모두 읽기 전용이었습니다. 데이터를 합치거나 솎아서 보여줄 뿐, 직접 수정하지는 못했죠.

그런데 설정 데이터(코드표, 매핑표 등)는 사용자가 화면에서 직접 추가·수정해야 할 때가 많습니다. 프로그램을 따로 만들지 않고도 표 형태로 데이터를 관리하게 해주는 것이 Maintenance View입니다.

2. Maintenance View는 "편집 가능한 표 화면" 🗂️

Maintenance View는 하나 이상의 테이블을 묶어, 엑셀처럼 줄을 추가·수정·삭제할 수 있는 유지보수 화면을 위한 View입니다. 관리자가 코드값을 직접 손볼 수 있게 해줍니다.

💡

일상 비유: 공유 엑셀 시트

개발자에게 매번 부탁하지 않고도, 담당자가 직접 코드표를 여닫으며 줄을 추가하는 공유 엑셀 같은 거예요. 단, 아무 값이나 못 넣게 규칙(Foreign Key)이 걸려 있죠.

3. Foreign Key가 데이터를 지킨다 🔐

여러 테이블을 묶어 편집하게 하려면, 테이블들 사이의 관계가 분명해야 합니다. 이때 Foreign Key(THEORY-04에서 배운 그 개념)가 테이블 관계를 정의합니다.

  • ✅ 정상: Foreign Key가 "이 코드는 저 마스터 테이블에 있는 값만 허용"이라고 막아줍니다. 잘못된 값 입력이 차단됩니다.
  • ❌ 관계 없음: 관계가 모호하면 Maintenance View를 만들 때 "어떻게 묶을지 모르겠다"는 오류가 나거나, 엉뚱한 데이터가 들어갈 수 있습니다.
그래서 Maintenance View는 Foreign Key 설계가 잘 되어 있을수록 안전하고 편리하게 동작합니다. 데이터 모델(THEORY-01·04)이 탄탄해야 화면도 튼튼한 셈이죠.

4. 정상 흐름과 주의 🔍

  • ✅ 정상: 관계가 분명한 테이블들을 묶어 유지보수 화면을 만들면, 담당자가 안전하게 코드표를 관리합니다.
  • ❌ 권한 주의: 편집 화면이므로 아무나 열면 위험합니다. 누가 무엇을 고칠 수 있는지 권한 관리가 필요합니다.

5. 실무에서 조심할 점 🚨

⚠️

"누구나 수정 가능"은 위험합니다

Maintenance View로 만든 화면은 데이터를 바로 바꿉니다. 운영 데이터에 연결된 표라면, 권한 그룹·변경 로그·전송(Transport) 관리를 함께 설계해야 합니다. 편하다고 아무 테이블에나 유지보수 화면을 열어두면, 검증 없이 데이터가 바뀌어 사고로 이어질 수 있습니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Maintenance View는 데이터를 화면에서 직접 입력·수정하게 해주는 편집용 View입니다.
  • Foreign Key 관계가 잘못된 값 입력을 막아 데이터를 지킵니다.
  • 데이터 모델(관계 설계)이 탄탄할수록 유지보수 화면도 안전합니다.
  • 편집 화면이므로 권한·변경관리를 반드시 함께 고려합니다.
