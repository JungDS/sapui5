학습 목표

SELECT 안에서 직접 조건 분기·형 변환·빈값 대체를 하는 SQL 표현식을 배웁니다. CASE, CAST, COALESCE를 익힙니다.

1. 지난 시간 연결: 가공을 ABAP 말고 DB에서 🏭

예전에는 데이터를 ABAP으로 다 가져온 뒤 LOOP 돌며 가공했습니다. 그런데 간단한 분기·변환은 DB가 조회하면서 바로 해주면 더 빠르고 코드도 짧습니다(코드 푸시다운).

Modern ABAP SQL은 SELECT 안에 표현식을 넣을 수 있게 해줍니다. 대표 3종을 봅니다.

2. CASE — 조건에 따라 다른 값 ✍️

CASE는 조건에 따라 다른 값을 컬럼으로 만들어 줍니다(ABAP의 IF/CASE를 SQL에서).

ABAP

SELECT carrid, price,
       CASE WHEN price >= 1000 THEN 'HIGH'
            WHEN price >= 500  THEN 'MID'
            ELSE 'LOW'
       END AS price_grade
  FROM sflight
  INTO TABLE @DATA(lt).
"→ 요금에 따라 HIGH/MID/LOW 등급 컬럼이 함께 생성

3. CAST와 COALESCE 🔧

  • CAST: 타입을 바꿉니다. 예: 숫자를 문자로, 길이를 조정.
    ABAP
    1 
    CAST( price AS CHAR( 20 ) ) AS price_text
  • COALESCE: 값이 NULL(없음)이면 대체값을 줍니다. 주로 OUTER JOIN 결과에서 유용.
    ABAP
    1 
    COALESCE( b~bookid, 0 ) AS bookid
💡

비유: 조회하면서 즉석 가공

마트에서 물건을 사 와 집에서 손질하는 대신(ABAP 가공), 매장에서 손질까지 끝내 받는 것(DB 표현식)과 같아요. 집(ABAP)이 한결 한가해집니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 간단한 분기·변환·빈값 처리를 DB에서 끝내고, ABAP은 결과만 받습니다.
  • ❌ 오류 1: 표현식 결과 컬럼에 AS 이름을 안 줘서 참조가 불편.
  • ❌ 오류 2 — 과욕: 복잡한 업무 로직까지 전부 SQL CASE로 욱여넣어 SELECT가 읽기 어려워짐. 복잡하면 CDS나 ABAP으로 나눕니다.

5. 실무에서 조심할 점 🚨

⚠️

"DB에서 할 일"과 "ABAP에서 할 일"의 균형

간단한 등급 분류·형 변환·빈값 대체는 DB 표현식이 효율적입니다. 하지만 여러 단계의 복잡한 비즈니스 규칙까지 SQL에 다 넣으면, SELECT가 거대해지고 디버깅이 어려워집니다. "한눈에 읽히는 수준"을 넘어서면, 그 로직은 CDS View(THEORY-20)나 ABAP 메서드로 분리하는 것이 좋습니다.

오늘의 핵심만 딱 잡기

  • SQL 표현식으로 SELECT 안에서 가공할 수 있습니다.
