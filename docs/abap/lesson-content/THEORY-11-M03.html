학습 목표

데이터를 그룹으로 묶어 요약하는 GROUP BY와, 그룹마다 계산을 해주는 집계 함수(SUM·COUNT·AVG)를 배웁니다. "항공사별 총 매출", "편명별 예약 건수" 같은 요약 리포트의 기초입니다.

1. 지난 시간 연결: 한 줄씩 말고 "묶어서" 보고 싶다 📊

지금까지는 데이터를 한 줄 한 줄 그대로 읽었습니다. 그런데 보고서를 만들다 보면 "전체 명세"가 아니라 요약된 숫자가 필요할 때가 많습니다.

"항공사별로 예약이 몇 건이지?", "이번 달 매출 합계는?" 같은 질문이죠. 예약 데이터 수십만 줄을 사람이 직접 세는 건 불가능합니다. 이때 DB에게 "그룹으로 묶어서 계산해줘"라고 시키는 것이 GROUP BY와 집계 함수입니다.

2. GROUP BY는 "같은 것끼리 한 바구니에" 🧺

GROUP BY는 지정한 필드 값이 같은 행끼리 한 그룹으로 묶습니다. 그리고 그 그룹마다 집계 함수로 숫자 하나를 뽑아냅니다.

💡

일상 비유: 빨래 분류

빨래 더미(전체 데이터)를 색깔별로 바구니에 나눠 담는 게 GROUP BY예요. 그다음 "흰 바구니에 몇 장?"(COUNT), "검은 바구니 무게 합?"(SUM)을 세는 게 집계 함수입니다.

3. 집계 함수 4종 ✍️

  • COUNT( * ): 그룹에 행이 몇 개인지 (건수)
  • SUM( 필드 ): 그룹 안 그 필드의 합계
  • AVG( 필드 ): 평균
  • MAX / MIN( 필드 ): 최댓값 / 최솟값

SELECT carrid,
       COUNT(*) AS cnt,
       SUM( loccuram ) AS total
  FROM sbook
  GROUP BY carrid
  INTO TABLE @DATA(lt_summary).

✨

학습 포인트 — 황금 규칙

집계 SELECT에서 가장 중요한 규칙: SELECT에 적는 일반 필드는 전부 GROUP BY에도 적어야 합니다. "묶는 기준이 아닌 일반 필드"를 그냥 꺼내려고 하면 오류가 납니다. 집계 함수로 감싼 필드는 예외입니다.

5. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: GROUP BY 기준 필드 + 집계 함수만 SELECT에 적으면 그룹별 요약이 깔끔하게 나옵니다.
  • ❌ 오류 1: GROUP BY에 없는 일반 필드를 SELECT에 적음 → "GROUP BY에 넣으라"는 오류.
  • ❌ 오류 2: 집계 결과를 받을 변수 타입이 너무 작아 합계가 넘침(오버플로). 합계용 필드는 충분히 큰 타입(예: 패킹 타입)으로 받습니다.

6. 실무에서 조심할 점 🚨

⚠️

집계는 DB에서, ABAP 루프로 직접 세지 마세요

초보자는 종종 전체 데이터를 ABAP으로 다 읽어온 뒤 LOOP 돌며 직접 합계를 냅니다. 데이터가 많으면 이건 아주 느리고 메모리도 많이 씁니다. 합계·건수·평균은 DB에게 GROUP BY로 시키는 것이 훨씬 빠릅니다. 필요한 요약값만 가볍게 받아오세요.

실습 과제

  1. SE38에서 예제를 실행해 lt_summary에 항공사별 건수(cnt)와 합계(total)가 들어오는지 디버거로 확인합니다.
  2. GROUP BY에서 carrid를 빼고 connid만 남겨 SELECT에 일반 필드를 추가해 보면서 오류 메시지를 관찰합니다.

  4. GROUP BY carrid, connid로 기준 필드를 두 개로 늘렸을 때 결과 행 수가 어떻게 달라지는지 관찰합니다.

완료 조건: "SELECT에 적은 일반 필드는 모두 GROUP BY에도 있어야 한다"는 황금 규칙을 직접 오류로 경험하고, 집계 함수 3종(COUNT/SUM/MAX)의 결과를 모두 확인했으면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. GROUP BY 없이 SELECT COUNT(*) FROM sbook을 실행하면 몇 개의 행이 반환될까요?
  2. SELECT carrid, connid, COUNT(*) FROM sbook GROUP BY carrid는 오류가 날까요? 이유는?
  3. ABAP에서 전체 데이터를 읽어 LOOP로 합계를 내는 것보다 GROUP BY가 왜 더 빠른가요?
정답/해설 보기
  1. 1행만 반환됩니다. GROUP BY 없이 집계 함수만 쓰면 전체 테이블이 하나의 그룹으로 처리되어, 총 건수 하나가 담긴 행 1개만 나옵니다.
  2. 오류가 납니다. connid는 GROUP BY에 없는 일반 필드인데 SELECT에 적었기 때문입니다. GROUP BY의 황금 규칙: SELECT에 쓰는 일반 필드(집계 함수 안에 없는 것)는 전부 GROUP BY에도 있어야 합니다.
  3. DB 서버가 데이터를 직접 처리하기 때문입니다. GROUP BY는 DB 안에서 그룹 묶기·계산을 완료하고 결과만 ABAP으로 보내므로, 수십만 건 전체를 네트워크로 전송해 ABAP에서 계산하는 것보다 훨씬 빠르고 메모리도 적게 씁니다.

10. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • GROUP BY는 같은 값끼리 묶고, 그룹마다 한 줄로 요약합니다.
  • COUNT/SUM/AVG/MAX/MIN으로 건수·합계·평균 등을 계산합니다.
  • 황금 규칙: SELECT의 일반 필드는 모두 GROUP BY에도 있어야 합니다.
  • 요약 계산은 ABAP 루프가 아니라 DB(GROUP BY)에게 맡기는 것이 빠릅니다.
