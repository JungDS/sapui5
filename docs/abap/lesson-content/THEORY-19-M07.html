학습 목표

데이터를 갱신할 때 사용자가 보던 스크롤·선택 위치를 지키는 Stable Refresh(IS_STABLE)를 한 번 더 깊이 정리합니다. 표시 제어 Chapter를 마무리합니다.

1. 지난 시간 연결: 색·스타일을 바꾼 뒤엔? 🔄

이번 Chapter에서 정렬·필터·색·스타일을 코드로 제어했습니다. 그런데 사용자가 표를 보다가 데이터가 바뀌어 다시 그려야 할 때, 보던 위치가 맨 위로 튕기면 짜증스럽죠. THEORY-15에서 살짝 봤던 refresh를 표시 상태 보존 관점에서 마무리합니다.

  • is_stable-row / col: 갱신 후에도 사용자의 스크롤·선택 위치를 그대로 둡니다.
  • SALV는? SALV는 lo_alv->refresh( ) 호출 시 내부적으로 표시 상태를 비교적 잘 유지합니다. Grid ALV는 is_stable을 명시해야 합니다.
💡

비유: 책갈피 유지

그냥 새로고침이 "책을 덮고 첫 장부터"라면, Stable Refresh는 "책갈피 끼운 그 페이지만 갱신"이에요. 사용자가 작업하던 흐름이 끊기지 않습니다.

3. 표시 상태를 지키는 다른 요소들 🧷

  • 정렬/필터: 사용자가 적용한 정렬·필터는 갱신 후에도 가능한 유지되도록 설계합니다.
  • 선택(selected rows): 작업 중 선택한 행이 갱신으로 풀리지 않게 신경 씁니다.
  • 레이아웃(Variant): 사용자가 저장/적용한 레이아웃은 그대로 보존됩니다(앞 Lesson).

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 데이터 변경 → is_stable refresh → 같은 위치에서 새 값 확인.
  • ❌ 오류 1: 갱신 때마다 first_display를 다시 호출(THEORY-15 주의) → 표가 통째로 리셋되어 위치·선택 다 사라짐.
  • ❌ 오류 2: is_stable 없이 refresh → 매번 맨 위로 튕겨 사용성 저하.

5. 실무에서 조심할 점 🚨

⚠️

"갱신은 refresh, 첫 표시만 first_display"

표시 제어를 아무리 잘해도, 갱신 방식이 틀리면 사용자 경험이 무너집니다. 화면 진입 시 최초 1회만 set_table_for_first_display, 이후 데이터 변경은 항상 refresh_table_display(is_stable). 이 원칙을 지키면 색·스타일·정렬·선택이 모두 자연스럽게 유지됩니다.
