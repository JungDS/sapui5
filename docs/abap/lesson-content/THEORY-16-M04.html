학습 목표

Internal Table에서 원하는 줄을 대괄호로 콕 집어 꺼내는 Table Expression(lt[ ... ])을 배웁니다. 줄을 못 찾았을 때의 예외와 안전하게 처리하는 법을 익힙니다.

1. 지난 시간 연결: READ TABLE을 더 짧게 ⚡

THEORY-06에서 READ TABLE ... WITH KEY ...로 줄을 검색했습니다. 잘 동작하지만 여러 줄을 쓰게 되죠. 최신 ABAP은 이걸 대괄호 한 번으로 줄여줍니다. 그것이 Table Expression입니다.

2. 대괄호로 줄 꺼내기 ✍️

ABAP
1
2
3
4
5 
" 인덱스로 꺼내기

DATA(ls_first) = lt_flights[ 1 ].           "첫 번째 줄


" 키(조건)로 꺼내기

DATA(ls_lh) = lt_flights[ carrid = 'LH' ].  "carrid가 LH인 줄
  • lt[ 1 ]: 인덱스(몇 번째 줄).
  • lt[ 필드 = 값 ]: 조건에 맞는 첫 줄.
💡

비유: 사물함 번호로 꺼내기

lt[ 1 ]은 "1번 사물함", lt[ carrid = 'LH' ]는 "이름표가 LH인 사물함"을 바로 여는 거예요. 한 줄로 끝나니 깔끔하죠.

3. 못 찾으면? 예외가 난다 ⚠️

조심할 점이 있습니다. 조건에 맞는 줄이 없으면 Table Expression은 CX_SY_ITAB_LINE_NOT_FOUND 예외를 던지며 프로그램이 멈춥니다. READ TABLE이 sy-subrc로 조용히 알려주던 것과 다릅니다.

ABAP
1
2
3
4
5
6
7
8 
" 안전하게: 없으면 빈 구조(OPTIONAL) 또는 기본값(DEFAULT)

DATA(ls) = VALUE #( lt_flights[ carrid = 'XX' ] OPTIONAL ).
"→ 못 찾아도 예외 없이 초기값 구조를 돌려줌


" 존재 여부만 확인

IF line_exists( lt_flights[ carrid = 'LH' ] ).
  ...
ENDIF.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 줄이 확실히 있을 때 lt[ ... ]로 바로 꺼냅니다.
  • ❌ 오류 1: 없을 수도 있는 줄을 그냥 lt[ ... ]로 꺼냄 → 예외로 덤프(프로그램 중단).
  • ✅ 해결: VALUE #( ... OPTIONAL ) 또는 line_exists( )로 안전하게 처리합니다.

5. 실무에서 조심할 점 🚨

⚠️

"있을 때"와 "없을 수도 있을 때"를 구분하세요

Table Expression이 깔끔하다고 무심코 쓰면, 데이터가 없는 순간 프로그램이 덤프됩니다. 운영에서 갑자기 멈추면 큰 사고죠. "이 줄이 항상 있다고 보장되는가?"를 먼저 생각하고, 보장되지 않으면 OPTIONAL·line_exists·READ TABLE 중 하나로 안전하게 처리하세요.

📝

오늘의 핵심만 딱 잡기

  • Table Expression lt[ ... ]로 줄을 인덱스·조건으로 바로 꺼냅니다.
  • 못 찾으면 예외(CX_SY_ITAB_LINE_NOT_FOUND)로 중단됩니다.
  • 안전책: VALUE #( ... OPTIONAL ), line_exists( ).
  • "항상 있는가"를 확인하고 없을 수 있으면 방어 코드를 둡니다.
