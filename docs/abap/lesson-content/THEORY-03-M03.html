학습 목표

지난 Lesson에서 DEFAULT와 OBLIGATORY로 입력칸을 더 친절하게 만들었습니다. 이번에는 PARAMETERS로 받은 값을 WRITE로 출력하며 Input Output 흐름을 완성합니다.

1. 지난 시간 연결: 입력만 받고 끝나면 아쉽다 🔄

이전 Lesson까지 우리는 Selection Screen에 입력칸을 만들고, 기본값과 필수값을 설정했습니다. 하지만 입력 화면에서 값만 받는다고 프로그램이 일을 끝낸 것은 아닙니다. 받은 값을 사용해서 계산하거나 조회하거나 출력해야 의미가 생깁니다.

이번 Lesson은 아주 단순하게 갑니다. 사용자가 입력한 값을 그대로 Output List에 출력합니다. 단순하지만 이 흐름은 앞으로 거의 모든 Report 프로그램의 기본 뼈대가 됩니다.

입력값을 받고, 프로그램이 그 값을 읽고, 결과를 보여준다. 이게 Report 프로그램의 가장 기본적인 대화입니다.

2. Input Output 흐름을 그림처럼 보기 🧭

Input Output은 말 그대로 입력과 출력의 흐름입니다. ABAP Report에서는 보통 아래 순서로 생각하면 쉽습니다.

  1. 입력 화면 표시: PARAMETERS가 Selection Screen에 입력칸을 만듭니다.
  2. 사용자 입력: 사용자가 값을 넣고 실행합니다.
  3. 프로그램 처리: ABAP 코드가 PARAMETERS 값을 변수처럼 사용합니다.
  4. 결과 출력: WRITE가 Output List에 값을 보여줍니다.

이 흐름을 머릿속에 잡아두면, 나중에 데이터베이스 조회나 ALV 출력이 들어와도 “입력 → 처리 → 출력”이라는 큰 길을 잃지 않습니다.

3. 최소 예제: 입력한 이름으로 인사하기 👋

ABAP

2
3

REPORT zparam_output.

PARAMETERS p_name TYPE string DEFAULT 'ABAP' OBLIGATORY.

WRITE: / '안녕하세요,', p_name,
       / 'ABAP 학습을 시작합니다!'.

이 프로그램을 실행하면 먼저 p_name 입력칸이 보입니다. 기본값은 ABAP이고 필수 입력이므로 비워둘 수 없습니다. 사용자가 값을 입력한 뒤 실행하면 Output List에 인사 문장이 출력됩니다.

🧪

미니 실습

p_name을 본인 이름, 팀 이름, 임의의 닉네임으로 바꿔 실행해보세요. 같은 코드인데 입력값에 따라 출력 결과가 달라지는 것이 핵심입니다.

4. 여러 입력값을 조합해 출력하기 🧩

PARAMETERS는 여러 개 선언할 수 있습니다. 예를 들어 항공사 코드와 조회 일수를 입력받아 간단한 안내 문장을 만들 수 있습니다.

ABAP
1
2
3
4

8 
REPORT zparam_summary.

PARAMETERS p_carr TYPE c LENGTH 3 DEFAULT 'KE' OBLIGATORY.
PARAMETERS p_days TYPE i DEFAULT 7.

WRITE: / '항공사 코드:', p_carr,
       / '조회 일수:', p_days,
       / '위 조건으로 조회를 시작합니다.'.

아직 실제 데이터베이스를 조회하지는 않습니다. 하지만 사용자가 어떤 조건을 넣었는지 먼저 출력해보는 것만으로도 입력값이 프로그램에 잘 들어왔는지 확인할 수 있습니다.

실무에서도 복잡한 처리를 만들기 전에 입력값을 먼저 확인하는 습관이 디버깅을 많이 도와줍니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: 사용자가 입력한 값이 PARAMETERS 변수에 들어오고, WRITE가 그 값을 출력합니다.
  • ✅ 기본값 흐름: 사용자가 값을 바꾸지 않으면 DEFAULT 값이 그대로 출력됩니다.
  • ❌ 필수값 누락: OBLIGATORY 필드를 비우면 프로그램 본문까지 가지 못하고 Selection Screen에서 막힙니다.
  • ❌ 타입 불일치: 숫자 입력칸에 문자를 넣으면 실행 전에 오류가 날 수 있습니다.
  • ❌ 출력 착각: WRITE로 조건을 출력했다고 실제 조회나 저장이 된 것은 아닙니다. 아직은 입력 확인 단계입니다.

입력값이 이상할 때는 먼저 Output List에 “내가 받은 값”을 찍어보세요. 생각보다 많은 오류가 입력값 오해에서 시작됩니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

출력 전에 민감한 입력값인지 생각하세요

학습 예제에서는 입력값을 그대로 WRITE로 출력해도 괜찮습니다. 하지만 실무에서는 사용자 ID, 개인 정보, 금액 조건, 내부 코드처럼 화면에 그대로 보여주면 안 되는 값이 있을 수 있습니다. 출력은 디버깅에 편하지만, 운영 화면에 남겨도 되는 정보인지 확인해야 합니다.

또한 WRITE는 입력값 확인에는 좋지만, 실무용 결과 목록은 ALV나 다른 UI 도구가 더 적합할 수 있습니다. 지금은 Selection Screen 입력값이 프로그램으로 넘어오는 흐름을 확인하는 데 집중합니다.

7. 미니 실습: 입력값을 읽기 좋은 출력으로 바꾸기 🧪

이번 실습은 입력값을 단순히 찍는 데서 한 걸음 더 나아가, 사용자가 읽기 좋은 출력 문장으로 바꾸는 연습입니다. Selection Screen 입력과 Output List 출력이 한 흐름으로 이어지는지 확인하세요.

✍️

실습 과제

  1. p_name, p_carr, p_days 입력 필드를 선언합니다.
  2. 사용자가 입력한 세 값을 WRITE로 한 줄씩 출력합니다.
  3. p_days가 0일 때와 7일 때 출력 메시지를 비교합니다.
  4. 출력 라벨을 변수명 그대로 쓰지 말고, 사용자가 이해할 수 있는 한국어 문장으로 바꿉니다.

완료 조건: Input Output 흐름을 “입력 화면 → 실행 → 프로그램 변수 → 출력 목록” 순서로 설명할 수 있으면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. PARAMETERS 값은 사용자가 실행 버튼을 누른 뒤 프로그램 안에서 어떻게 다룰 수 있나요?
  2. WRITE 출력에서 변수명만 그대로 보여주는 방식이 초심자나 현업 사용자에게 불친절한 이유는 무엇인가요?
  3. 입력값을 출력할 때 타입과 업무 의미를 함께 확인해야 하는 이유는 무엇인가요?
정답/해설 보기
  1. 일반 변수처럼 읽어서 사용할 수 있습니다. Selection Screen에서 받은 값이 프로그램 본문에서 p_name 같은 데이터 객체로 접근됩니다.
  2. 사용자는 내부 변수명보다 업무 문장을 이해합니다. p_carr보다 “항공사 코드”처럼 의미를 드러내는 라벨이 더 읽기 쉽습니다.
  3. 타입이 맞아도 업무적으로 맞는 값이라는 보장은 없기 때문입니다. 예를 들어 숫자 0은 타입상 가능해도 조회 기간으로 적절하지 않을 수 있습니다.

10. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • PARAMETERS 값은 사용자가 Selection Screen에서 입력한 뒤 프로그램에서 변수처럼 사용됩니다.
  • WRITE는 입력값이 잘 들어왔는지 Output List에서 확인하는 데 좋습니다.
  • Input Output 흐름은 입력 화면 → 사용자 입력 → 프로그램 처리 → 결과 출력 순서입니다.
  • DEFAULT 값은 사용자가 바꾸지 않으면 그대로 출력됩니다.
  • 실무에서는 민감한 값을 무심코 출력하지 않도록 주의합니다.
