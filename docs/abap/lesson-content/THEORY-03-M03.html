학습 목표

Selection Screen에서 입력한 값이 같은 이름의 PARAMETERS 변수로 전달되고, START-OF-SELECTION 이후 WRITE가 Output List에 결과를 쓰는 흐름을 완성합니다.

1. 지난 Lesson 연결: 입력값을 결과로 보여준다

M01에서는 입력칸을 만들었고, M02에서는 기본값과 필수 입력을 붙였습니다. 이제 사용자가 넣은 값이 실제 프로그램 변수로 넘어와 결과 화면에 출력되는지 확인해야 합니다. 초급 Report의 가장 작은 완성형은 “값을 묻고, 받은 값을 보여주는 것”입니다.

핵심 한 줄: Selection Screen 값 → PARAMETERS 변수 → WRITE Output List 순서로 읽습니다.

2. 화면, 메모리, 출력은 다른 단계다

이번 Lesson의 핵심은 Input Output 흐름입니다. 초보자가 자주 하는 오해는 WRITE가 Selection Screen 아래에 바로 글자를 추가한다고 생각하는 것입니다. 실제로는 Execute(F8) 후 메인 처리로 넘어가고, 결과는 별도 Output List 화면에 표시됩니다.

1. PARAMETERS입력 필드와 같은 이름의 전역 변수를 만듭니다.
2. Execute(F8)사용자 입력값이 프로그램 변수로 전달됩니다.
3. START-OF-SELECTION검증 이후 본 실행 로직이 시작됩니다.
4. WRITE현재 list에 변수값과 문자열을 출력합니다.
입력 화면과 출력 화면을 왜 나눠 봐야 하나요?

Selection Screen은 조건을 받는 화면이고, Output List는 실행 결과를 보여주는 화면입니다. 이 구분을 놓치면 “입력값이 어디서 변수로 바뀌었는지”, “왜 F8을 두 번 누르는지”를 이해하기 어렵습니다.

3. 가장 작은 입력과 출력 예제

아래 코드는 P_NAME 입력값을 받아 인사 문장으로 출력합니다. DEFAULT가 있으므로 처음에는 ABAP이 보이고, OBLIGATORY가 있으므로 이름을 비운 채 실행할 수 없습니다.

REPORT z_param_m03_hello.

PARAMETERS p_name TYPE c LENGTH 20 DEFAULT 'ABAP' OBLIGATORY.

START-OF-SELECTION.
  WRITE: / '안녕하세요,', p_name,
         / 'ABAP 학습을 시작합니다.'.

사용자가 ABAP을 JISU로 바꾸면 Output List도 안녕하세요, JISU로 바뀝니다. 같은 코드라도 입력값이 달라지면 결과가 달라집니다.

4. 여러 입력값도 같은 방식으로 읽는다

PARAMETERS를 여러 개 선언해도 흐름은 같습니다. 화면 필드마다 같은 이름의 프로그램 변수가 있고, WRITE는 그 변수들을 읽어 순서대로 list에 씁니다.

REPORT z_param_m03_io.

PARAMETERS p_name TYPE c LENGTH 20 DEFAULT 'ABAP' OBLIGATORY.
PARAMETERS p_carr TYPE c LENGTH 3  DEFAULT 'KE'.
PARAMETERS p_days TYPE i DEFAULT 7.

START-OF-SELECTION.
  WRITE: / '이름:', p_name,
         / '항공사:', p_carr,
         / '조회 일수:', p_days.

입력값과 출력값 매핑

Selection Screen 필드 프로그램 변수 WRITE 출력 예
P_NAME에 ABAP p_name = 'ABAP' 이름: ABAP
P_CARR에 KE p_carr = 'KE' 항공사: KE
P_DAYS에 7 p_days = 7 조회 일수: 7

5. 직접 해보기: 입력 → 변수 → Output List

SE38에서 Z_PARAM_M03_IO를 실행한 상황입니다. 값을 바꾼 뒤 실행해 Output List가 즉시 달라지는지 확인하세요. 필수 입력 모드를 끄면 빈 이름도 출력 단계로 넘어가는 차이를 볼 수 있습니다.

T-Code: SE38 (Z_PARAM_M03_IO)
Selection Screen 1000 - 입력값 출력 실습
실행(F8)을 누르면 화면값이 변수로 전달되고 Output List가 표시됩니다.

6. DEFAULT와 OBLIGATORY가 출력에 미치는 영향

DEFAULT 사용자가 값을 바꾸지 않으면 기본값이 그대로 변수에 들어가고, WRITE도 그 값을 출력합니다.
OBLIGATORY 필수값이 비어 있으면 Selection Screen에서 멈추므로, WRITE까지 가지 않습니다.
빈 값 출력 OBLIGATORY가 없으면 빈 값도 변수로 넘어와 공백처럼 출력될 수 있습니다.
START-OF-SELECTION을 꼭 적어야 하나요?

짧은 레거시 예제에서는 생략된 형태를 볼 수 있지만, 초급 학습에서는 선언부와 실행부를 명확히 나누기 위해 적는 습관이 좋습니다. 이후 검증 이벤트와 조회 로직이 붙으면 이 구분이 더 중요해집니다.

7. 실무에서 조심할 점

⚠️

입력값을 그대로 출력해도 되는지 확인

학습 예제에서는 입력값을 그대로 출력하지만, 실무에서는 개인정보, 내부 코드, 권한 관련 값처럼 화면에 그대로 보여주면 안 되는 값이 있을 수 있습니다. 운영 화면에 남겨도 되는 정보인지 먼저 판단해야 합니다.

SE38 실습에서는 코드 작성 후 F8로 프로그램을 실행하고, Selection Screen에서 값을 입력한 뒤 다시 F8을 눌러 Output List로 넘어갑니다. 결과를 확인한 뒤 이전 입력 화면으로 돌아가려면 Back(F3)을 사용합니다.

8. 7분 미니 실습

  1. SE38에서 Z_PARAM_M03_IO Report를 만들고 위 코드를 입력합니다.
  2. P_NAME, P_CARR, P_DAYS 값을 바꿔 실행합니다.
  3. Output List에서 세 줄의 출력이 입력값과 일치하는지 확인합니다.
  4. P_NAME을 비운 뒤 OBLIGATORY 때문에 WRITE까지 가지 않는지 확인합니다.
  5. OBLIGATORY를 잠시 제거하면 빈 이름이 공백으로 출력될 수 있음을 비교합니다.
확인 질문

P_NAME 화면 필드와 p_name 프로그램 변수는 어떻게 연결되나요? 답은 “PARAMETERS 선언 하나가 둘을 같은 입력 파라미터로 묶어 준다”입니다.

9. 공식 문서로 더 확인하기

SAP Help: PARAMETERS Selection parameter가 프로그램 data object와 selection screen input field에 연결되는 규칙을 확인합니다. SAP Help: START-OF-SELECTION 사용자가 실행한 뒤 본 처리 블록이 시작되는 위치를 확인합니다. SAP Help: WRITE WRITE가 data object 내용을 current list에 쓰는 기본 역할을 확인합니다.

10. 확인 퀴즈

  1. PARAMETERS p_carr TYPE c LENGTH 3.에서 사용자가 KE를 입력하면 본문에서는 어떤 이름으로 값을 읽나요?
  2. WRITE 출력은 Selection Screen 아래에 붙나요, 아니면 다른 결과 화면에 보이나요?
  3. OBLIGATORY가 없고 입력값이 비어 있으면 WRITE는 항상 오류를 내나요?
  4. START-OF-SELECTION을 명시하면 어떤 점이 좋아지나요?
정답/해설 보기
  1. p_carr 변수로 읽습니다. 화면 필드와 프로그램 변수는 같은 PARAMETERS 선언에서 나옵니다.
  2. 다른 결과 단계인 Output List에 보입니다. Selection Screen을 꾸미는 출력이 아닙니다.
  3. 아니요. 빈 값이 변수에 들어오면 공백처럼 출력될 수 있습니다. 빈 값 실행을 막으려면 OBLIGATORY가 필요합니다.
  4. 선언부와 실행부가 분리되어 이후 검증, 조회, 출력 로직을 읽고 유지보수하기 쉬워집니다.
