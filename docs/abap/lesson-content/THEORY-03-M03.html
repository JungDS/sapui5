학습 목표

이번 Lesson에서는 Selection Screen에서 입력한 값이 같은 이름의 PARAMETERS 변수에 담기고, WRITE 문으로 Output List에 출력되는 흐름을 완성합니다.

1. 입력만 받고 끝나면 프로그램이 아니다

M01에서는 입력칸을 만들었고, M02에서는 기본값과 필수값을 붙였습니다. 이제 사용자가 넣은 값을 프로그램이 실제로 읽고 결과 화면에 보여줘야 합니다. 초급 Report의 가장 작은 대화는 “값을 묻고, 받은 값을 보여주는 것”입니다.

화면 입력값은 Execute(F8)를 누른 뒤 같은 이름의 프로그램 변수로 넘어오고, WRITE는 그 값을 List Output에 씁니다.

2. 화면 → 메모리 → 출력

이번 Lesson의 핵심은 Input Output 흐름입니다. 복잡한 조회나 ALV를 몰라도, Report가 어떤 순서로 사용자와 대화하는지 먼저 잡아야 합니다.

PARAMETERS 값이 출력으로 가는 4단계

1. 입력칸 생성PARAMETERS p_name(20) TYPE c.가 Selection Screen 필드를 만든다.
2. 사용자 입력사용자가 P_NAME에 값을 넣고 Execute(F8)를 누른다.
3. 메모리 전달입력값이 프로그램 변수 p_name에 담긴다.
4. List OutputWRITE가 현재 List에 값을 출력한다.
WRITE는 Selection Screen 아래에 출력하나요?

아닙니다. Execute(F8) 후 프로그램 본문이 실행되면 입력 화면이 그대로 확장되는 것이 아니라, 결과를 보여주는 List Output 화면으로 전환됩니다. 그래서 입력 화면과 출력 화면을 서로 다른 단계로 보는 것이 중요합니다.

PARAMETERS p_name(20) TYPE c DEFAULT 'ABAP' OBLIGATORY.

  WRITE: / '안녕하세요,', p_name,
         / 'ABAP 학습을 시작합니다.'.

실행 후: List Output
List Z_DEMO_PARAM_M03_HELLO
Output List
안녕하세요, ABAP
ABAP 학습을 시작합니다.

사용자가 기본값 ABAP을 JISU로 바꾸면 출력도 안녕하세요, JISU로 바뀝니다. 같은 코드라도 입력값이 달라지면 결과가 달라집니다.

4. 여러 입력값도 같은 방식으로 읽는다

PARAMETERS를 여러 개 선언해도 흐름은 같습니다. 화면 필드마다 같은 이름의 프로그램 변수가 있고, WRITE는 그 변수들을 읽어 출력합니다.

REPORT z_demo_param_m03_summary.

PARAMETERS p_carr(3) TYPE c DEFAULT 'KE' OBLIGATORY.
PARAMETERS p_days    TYPE i DEFAULT 7.

START-OF-SELECTION.
  WRITE: / '항공사 코드:', p_carr,
         / '조회 일수:', p_days,
         / '위 조건으로 조회를 시작합니다.'.

입력값과 출력값 매핑

Selection Screen 필드 프로그램 변수 WRITE 출력 예
P_CARR에 KE p_carr = 'KE' 항공사 코드: KE
P_DAYS에 7 p_days = 7 조회 일수: 7
실무에서도 복잡한 조회를 만들기 전에 입력값을 출력해 보면, 내가 받은 값이 맞는지 빠르게 확인할 수 있습니다.

5. DEFAULT와 OBLIGATORY가 출력에 미치는 영향

DEFAULT 사용자가 값을 바꾸지 않으면 기본값이 그대로 변수에 들어가고, WRITE도 그 값을 출력합니다.
OBLIGATORY 필수값이 비어 있으면 Selection Screen에서 멈추므로, 해당 경우에는 WRITE까지 가지 않습니다.
빈 값 출력 OBLIGATORY가 없으면 빈 값도 프로그램 변수로 넘어올 수 있고, 출력에는 공백처럼 보일 수 있습니다.
결과 화면에서 뒤로 가면 입력값은 사라지나요?

일반적으로 같은 실행 흐름 안에서는 뒤로 돌아갔을 때 방금 입력한 값이 Selection Screen에 남아 있는 것을 볼 수 있습니다. 중요한 점은 화면이 바뀌어도 프로그램 실행 컨텍스트 안에서 입력값을 기준으로 출력이 만들어졌다는 사실입니다.

6. 이번 범위 밖으로 빼기

⚠️

출력은 확인용으로만 단순하게

이번 Lesson은 입력값이 프로그램 변수로 넘어왔는지 확인하는 단계입니다. WRITE 색상, 위치, 통화 서식, ALV, AT SELECTION-SCREEN 검증, SELECT-OPTIONS 범위 입력은 아직 다루지 않습니다.

또한 학습 예제에서는 입력값을 그대로 출력하지만, 실무에서는 개인정보나 내부 코드처럼 화면에 그대로 보여주면 안 되는 값이 있을 수 있습니다. 운영 화면에 남겨도 되는 정보인지 항상 확인해야 합니다.

7. 7분 미니 실습

  1. p_name(20) TYPE c DEFAULT 'ABAP' OBLIGATORY를 선언합니다.
  2. p_carr(3) TYPE c DEFAULT 'KE'와 p_days TYPE i DEFAULT 7을 추가합니다.
  3. 세 값을 WRITE로 한 줄씩 출력합니다.
  4. Selection Screen에서 값을 바꿔 실행하고, Output List가 바뀌는지 확인합니다.
  5. p_name을 비우고 실행해 WRITE까지 가지 않는지 확인합니다.
확인 질문

P_NAME이라는 화면 필드와 p_name이라는 프로그램 변수는 어떻게 연결되나요? 답은 “PARAMETERS 선언 하나가 둘을 같은 입력 파라미터로 묶어 준다”입니다.

8. 공식 문서로 더 확인하기

SAP Help: PARAMETERS Selection Screen 입력 파라미터 선언과 프로그램 데이터 객체 역할을 확인합니다. SAP Help: Selection Screens Overview Execute 후 Selection Screen 처리와 프로그램 실행 흐름을 확인합니다. SAP Help: The WRITE Statement WRITE가 data object를 current list에 쓰는 기본 역할을 확인합니다.

9. 확인 퀴즈

  1. PARAMETERS p_carr(3) TYPE c.에서 사용자가 KE를 입력하면 프로그램 본문에서는 어떤 이름으로 값을 읽나요?
  2. WRITE 출력은 Selection Screen 아래에 붙나요, 아니면 다른 결과 화면에 보이나요?
  3. OBLIGATORY가 없고 입력값이 비어 있으면 WRITE는 항상 오류를 내나요?
정답/해설 보기
  1. p_carr 변수로 읽습니다. 화면 필드의 기술 이름과 프로그램 변수 이름이 같은 선언에서 나옵니다.
  2. 다른 결과 단계인 List Output에 보입니다. Selection Screen을 꾸미는 출력이 아닙니다.
  3. 아니요. 빈 값이 변수에 들어오면 공백처럼 출력될 수 있습니다. 빈 값 실행을 막으려면 OBLIGATORY가 필요합니다.

오늘의 기준 문장

Selection Screen에서 입력한 값은 같은 이름의 PARAMETERS 변수에 담기고, WRITE는 그 값을 List Output에 씁니다. “화면 → 메모리 → 출력” 순서를 잃지 않으면 Report의 기본 흐름을 읽을 수 있습니다.
