학습 목표

지난 Lesson에서 Internal Table의 선언 골격을 만들었습니다. 이번에는 APPEND와 INSERT로 Table Row를 추가하는 방법을 배웁니다.

1. 빈 표에는 줄을 넣어야 한다 🧭

Internal Table을 선언했다는 것은 “표를 만들 준비가 됐다”는 뜻입니다. 하지만 선언만으로 데이터가 생기지는 않습니다. 엑셀 파일을 새로 만들었다고 자동으로 행이 채워지지 않는 것과 같습니다.

이제 해야 할 일은 Work Area에 한 줄 값을 채운 뒤, 그 값을 Internal Table에 넣는 것입니다. 가장 자주 쓰는 기본 문법이 APPEND와 INSERT입니다.

APPEND는 끝에 붙이기, INSERT는 원하는 위치에 끼워 넣기입니다.

2. APPEND: 표의 맨 뒤에 한 줄 붙이기 ➕

APPEND는 Work Area의 현재 값을 Internal Table 맨 뒤에 추가합니다. 처음 배울 때 가장 많이 쓰는 추가 문법입니다.

ABAP
1
2
3
4 
ls_student-id = 'A01'.
ls_student-name = 'Mina'.
ls_student-score = 90.
APPEND ls_student TO lt_students.

중요한 점은 APPEND가 Work Area 자체를 표에 연결해두는 것이 아니라, 그 순간의 값을 한 줄로 복사해 넣는다는 것입니다. 이후 Work Area 값을 바꿔도 이미 추가된 줄이 자동으로 바뀌지는 않습니다.

💡

Work Area는 도장판 같은 느낌

Work Area에 값을 채우고 APPEND를 하면 그 상태가 한 줄로 찍힙니다. 다음 줄을 넣으려면 Work Area 값을 다시 채운 뒤 또 APPEND합니다.

3. INSERT: 특정 위치에 한 줄 끼워 넣기 📌

INSERT는 Internal Table에 줄을 추가한다는 점에서는 APPEND와 비슷하지만, 특정 위치를 지정할 수 있습니다.

ABAP
1
2
3
4 
ls_student-id = 'A00'.
ls_student-name = 'Start'.
ls_student-score = 100.
INSERT ls_student INTO lt_students INDEX 1.

위 코드는 lt_students의 1번째 위치에 새 줄을 넣습니다. 기존 1번째 줄이 있었다면 뒤로 밀립니다. 순서가 중요한 표를 만들 때 유용하지만, 인덱스를 잘못 생각하면 예상과 다른 순서가 될 수 있습니다.

REPORT zappend_insert_basic.

TYPES: BEGIN OF ty_student,
         id    TYPE char3,
         name  TYPE char20,
         score TYPE i,
       END OF ty_student.

DATA: lt_students TYPE STANDARD TABLE OF ty_student,
      ls_student  TYPE ty_student.

ls_student-id = 'A01'.
ls_student-name = 'Mina'.
ls_student-score = 90.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A02'.
ls_student-name = 'Jun'.
ls_student-score = 85.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A00'.
ls_student-name = 'Start'.
ls_student-score = 100.
INSERT ls_student INTO lt_students INDEX 1.

결과적으로 Internal Table 안에는 A00, A01, A02 순서로 3줄이 들어갑니다. CLEAR는 Work Area를 비워 다음 줄 값을 깔끔하게 채우기 위한 안전 습관입니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: Work Area에 값을 채우고 APPEND하면 Internal Table 끝에 한 줄이 추가됩니다.
  • ✅ 순서 조정: INSERT ... INDEX 1을 쓰면 새 줄이 맨 앞에 들어갑니다.
  • ❌ Work Area 미초기화: 이전 줄의 필드 값이 남아 다음 줄에 섞일 수 있습니다. 특히 일부 필드만 다시 채울 때 조심합니다.
  • ❌ 잘못된 인덱스: 존재하지 않는 위치에 INSERT하려 하면 실행 시 오류나 예외 상황을 만날 수 있습니다.
  • ❌ 중복 의미 방치: STANDARD TABLE은 기본적으로 같은 값의 줄이 들어갈 수 있습니다. 중복을 막아야 한다면 별도 기준이 필요합니다.

미니 실습으로 같은 id를 가진 줄을 두 번 APPEND해보세요. 문법상 들어갈 수 있다는 것을 보고, “중복을 막는 것은 추가 로직이나 테이블 종류/키 설계가 필요하구나”까지 연결하면 좋습니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

추가 순서는 나중 출력과 검색에 영향을 줍니다

Internal Table에 어떤 순서로 줄을 넣었는지는 LOOP 출력 순서와 일부 검색 방식에 영향을 줄 수 있습니다. “어차피 표니까 들어가기만 하면 된다”가 아니라, 순서가 업무적으로 의미 있는지 먼저 생각해야 합니다.

또한 많은 데이터를 한 줄씩 추가하는 로직에서는 성능을 의식해야 합니다. 지금은 기본 문법을 익히는 단계라 단순 예제를 쓰지만, 대량 데이터 처리에서는 Open SQL 조회 방식과 Internal Table 종류, 키 설계까지 함께 봐야 합니다.

7. 한눈에 정리 🏁

📝

줄 추가 핵심

  • APPEND는 Internal Table의 맨 뒤에 한 줄을 추가합니다.
  • INSERT는 지정한 위치에 한 줄을 끼워 넣을 수 있습니다.
  • Table Row는 Internal Table에 들어가는 한 건의 데이터입니다.
  • Work Area를 재사용할 때는 이전 값이 남지 않도록 CLEAR를 고려합니다.
  • STANDARD TABLE은 중복을 자동으로 막아주지 않으므로 업무 기준을 따로 확인합니다.
