학습 목표

데이터를 실제로 저장하는 Transparent Table(투명 테이블)을 만들어 봅니다. 키 필드(Key Field)와, 거의 모든 SAP 테이블 맨 앞에 붙는 클라이언트 필드(MANDT)의 의미를 익힙니다.

1. 드디어 진짜 "저장 창고" 🏬

앞의 Structure가 데이터를 잠깐 담는 그릇이었다면, Transparent Table(투명 테이블)은 데이터가 영구히 쌓이는 진짜 창고입니다.

"투명(Transparent)"이라는 이름은, DDIC에 만든 테이블 하나가 실제 데이터베이스(SAP HANA 등)의 물리 테이블 1개와 1:1로 그대로 비친다는 뜻입니다. 개발자가 DDIC에서 디자인하고 활성화하면, 시스템이 알아서 똑같은 모양의 진짜 DB 테이블을 만들어 줍니다.

2. 키 필드(Key Field) — 행을 구분하는 기준 🔑

테이블의 각 행을 유일하게 구분하는 필드가 키 필드(Key Field)입니다. 체크박스로 Key 표시를 한 필드들의 조합은 테이블 안에서 중복될 수 없습니다.

💡

키 예시 (항공편 테이블)

MANDT + CARRID + CONNID + FLDATE 를 키로 잡으면 → "특정 클라이언트의, 특정 항공사의, 특정 편명의, 특정 날짜 항공편"은 딱 한 줄만 존재합니다.

키 필드는 테이블 정의에서 항상 맨 위(왼쪽)에 모여 있어야 합니다. 키가 잘못 설계되면 같은 데이터가 중복 저장되거나, 반대로 꼭 필요한 행이 덮어써지는 사고가 납니다.

3. 맨 앞의 MANDT — 회사를 칸막이로 나누는 클라이언트 🏢

대부분의 업무 테이블은 첫 번째 필드가 MANDT(클라이언트)입니다. 하나의 SAP 시스템 안에서 여러 회사/환경의 데이터를 칸막이로 분리하는 장치입니다.

  • ✅ 자동 분리: 100번 클라이언트로 로그인하면, Open SQL이 알아서 MANDT = 100 데이터만 보여줌 (개발자가 일일이 조건을 안 걸어도 됨)
  • 📌 이런 테이블을 Client-Dependent(클라이언트 종속) 테이블이라 부릅니다. 시스템 공통 설정처럼 MANDT가 없는 Client-Independent 테이블도 일부 있습니다.

그 외에 테이블에는 Delivery Class(이 테이블이 고객 데이터용인지, SAP 표준 설정용인지 구분)도 지정하는데, 보통 업무 데이터는 A(Application table)를 씁니다.

4. 실무에서 주의할 점 🚨

⚠️

운영 테이블의 키·필드 변경은 고위험

이미 데이터가 쌓인 테이블에서 키를 바꾸거나 필드 길이를 줄이면, 활성화 시 테이블 변환(Conversion)이 일어나며 데이터가 손상될 수 있습니다. 운영 시스템에서는 반드시 영향도를 검토하고, 가능하면 변경보다 신규 필드 추가(뒤에 붙이기)로 우회합니다.
