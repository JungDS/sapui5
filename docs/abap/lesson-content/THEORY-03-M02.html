학습 목표

이번 Lesson에서는 PARAMETERS 문에 붙는 DEFAULT 옵션과 OBLIGATORY 옵션을 구분합니다. DEFAULT는 처음 보이는 값이고, OBLIGATORY는 빈 값 실행을 막는 검증이라는 기준을 잡습니다.

1. 입력칸은 만들었지만 아직 불친절하다

M01에서 PARAMETERS가 Selection Screen 입력칸과 프로그램 변수를 동시에 만든다는 점을 배웠습니다. 그런데 입력칸만 있다고 좋은 화면은 아닙니다. 매번 같은 값을 다시 입력해야 하거나, 꼭 필요한 값을 비운 채 실행할 수 있으면 사용자는 쉽게 실수합니다.

이때 선택 화면을 조금 더 친절하고 안전하게 만드는 두 옵션이 DEFAULT와 OBLIGATORY입니다. 이름은 같이 나오지만 역할은 완전히 다릅니다.

두 옵션의 역할 분리

DEFAULT: 편의
  • Selection Screen에 처음 표시될 값을 넣습니다.
  • 사용자는 값을 그대로 써도 되고 바꿔도 됩니다.
  • 값을 지우는 행동까지 막지는 않습니다.
OBLIGATORY: 방어
  • 입력 필드를 필수 입력으로 만듭니다.
  • 빈 값으로 Execute(F8)를 누르면 화면에서 멈춥니다.
  • 값의 업무적 유효성까지 보장하지는 않습니다.

2. DEFAULT: 처음 보이는 시작값

DEFAULT는 입력칸에 미리 채워둘 시작값입니다. SAP 공식 문서에서도 DEFAULT가 없으면 타입의 Initial Value가 start value로 쓰인다고 설명합니다. 즉, DEFAULT는 “빈 출발점 대신 내가 정한 값으로 시작하자”는 뜻입니다.

ABAP

REPORT z_demo_param_m02_default.

PARAMETERS p_curr(3) TYPE c DEFAULT 'KRW'.

START-OF-SELECTION.
  WRITE: / '통화:', p_curr.
Program Z_DEMO_PARAM_M02_DEFAULT
DEFAULT만 사용한 Selection Screen
KRW
DEFAULT는 추천 시작값입니다. 사용자가 지우거나 다른 값으로 바꾸면 그 변경값이 프로그램으로 들어갑니다.

3. OBLIGATORY: 빈 값 실행 방지

OBLIGATORY는 입력 필드를 필수 입력으로 만듭니다. 사용자가 해당 칸을 비운 채 Execute(F8)를 누르면 Selection Screen에서 멈추고, 프로그램 본문으로 넘어가지 않습니다.

ABAP
1
2
3
4
5
6 
REPORT z_demo_param_m02_required.

PARAMETERS p_carr(3) TYPE c OBLIGATORY.

START-OF-SELECTION.
  WRITE: / '항공사:', p_carr.
Program Z_DEMO_PARAM_M02_REQUIRED
OBLIGATORY만 사용한 Selection Screen

stop 필수 입력값이 비어 있어 Selection Screen에서 실행이 막힙니다.

⚠️

필수 입력은 값 존재만 본다

OBLIGATORY는 비어 있는지를 확인하는 장치입니다. 존재하지 않는 항공사 코드 ZZZ가 실제 업무상 올바른지까지 확인하지는 않습니다. 그런 유효성 검증은 Dictionary 관계, Value Help, AT SELECTION-SCREEN 같은 후속 범위에서 다룹니다.

4. 세 조합을 화면 흐름으로 비교하기

초급 단계에서는 옵션을 문법으로 외우기보다 “화면에 처음 어떻게 보이고, Execute를 눌렀을 때 어디서 멈추는가”로 구분하는 편이 안전합니다.

DEFAULT / OBLIGATORY 조합별 판단표

선언 처음 보이는 값 사용자가 비우고 실행하면 판단
PARAMETERS p_a(3) TYPE c. 공백 그대로 실행될 수 있음 가장 기본형
... DEFAULT 'KRW'. KRW 그대로 실행될 수 있음 편의값 제공
... OBLIGATORY. 공백 Selection Screen에서 멈춤 빈 값 방어
... DEFAULT 'KRW' OBLIGATORY. KRW 지우면 Selection Screen에서 멈춤 편의 + 방어
DEFAULT가 있으면 OBLIGATORY는 필요 없나요?

필요할 수 있습니다. DEFAULT로 값이 처음 채워져도 사용자는 화면에서 그 값을 지울 수 있습니다. 빈 값으로 실행되면 안 되는 조건이라면 OBLIGATORY를 함께 둬야 합니다. DEFAULT는 편의, OBLIGATORY는 방어입니다.

5. 실무형 조합: 기본값은 주고, 지우면 막기

아래 예시는 자주 쓰는 통화는 KRW로 미리 보여주고, 조회 시작일은 반드시 입력하게 하는 형태입니다. 두 옵션이 같은 필드에 함께 붙을 수도 있고, 서로 다른 필드에 나뉘어 붙을 수도 있습니다.

REPORT z_demo_param_m02.

PARAMETERS p_curr(3) TYPE c DEFAULT 'KRW' OBLIGATORY.
PARAMETERS p_date    TYPE d OBLIGATORY.
PARAMETERS p_days    TYPE i DEFAULT 7.

START-OF-SELECTION.
  WRITE: / '통화:', p_curr,
         / '시작일:', p_date,
         / '조회 일수:', p_days.

실행 전후 흐름

1. 화면 표시P_CURR는 KRW, P_DAYS는 7로 보인다.
2. 사용자 수정필요하면 기본값을 바꾸거나 날짜를 입력한다.
3. 필수 검증P_CURR 또는 P_DATE가 비면 화면에서 멈춘다.
4. 프로그램 실행필수값이 있으면 START-OF-SELECTION 이후 로직으로 넘어간다.

6. 이번 범위 밖으로 빼기

INITIALIZATION 동적으로 기본값을 넣는 이벤트 흐름은 아직 다루지 않습니다.
AT SELECTION-SCREEN 존재 여부, 권한, 복합 조건 검증은 후속 검증 주제입니다.
Variant 사용자별 입력값 저장 기능은 별도 운영 주제로 분리합니다.
SELECT-OPTIONS 여러 값과 범위 입력은 이번 Chapter의 맛보기 범위를 넘깁니다.

7. 7분 미니 실습

  1. p_curr(3) TYPE c DEFAULT 'KRW' OBLIGATORY를 선언합니다.
  2. p_date TYPE d OBLIGATORY와 p_days TYPE i DEFAULT 7을 추가합니다.
  3. 기본값 그대로 실행해 Output List에 값이 출력되는지 확인합니다.
  4. KRW를 USD로 바꿔 실행하고 출력값이 바뀌는지 확인합니다.
  5. p_curr 또는 p_date를 비우고 실행해 Selection Screen에서 멈추는지 확인합니다.
실습 후 한 문장으로 정리하기

DEFAULT는 사용자가 바꿀 수 있는 시작값이고, OBLIGATORY는 비워 둔 채 실행하지 못하게 막는 필수 입력 검증입니다.

8. 공식 문서로 더 확인하기

SAP Help: PARAMETERS value_options DEFAULT가 start value와 어떻게 연결되는지 확인합니다. SAP Help: PARAMETERS screen_options OBLIGATORY가 required field와 Execute(F8) 흐름에 미치는 영향을 확인합니다. SAP Help: Selection Screens Overview Selection Screen 처리 흐름 안에서 입력값 검사가 일어나는 위치를 확인합니다.

9. 확인 퀴즈

  1. DEFAULT 'KRW'가 있는 입력칸에서 사용자는 값을 바꿀 수 있나요?
  2. OBLIGATORY는 ZZZ 같은 존재하지 않는 업무 코드까지 막아주나요?
  3. DEFAULT와 OBLIGATORY를 함께 쓰는 이유는 무엇인가요?
정답/해설 보기
  1. 네. DEFAULT는 처음 표시되는 값일 뿐이고, 사용자는 실행 전에 수정할 수 있습니다.
  2. 아니요. OBLIGATORY는 빈 값 여부만 막습니다. 값의 업무적 존재 여부는 별도 검증 범위입니다.
  3. 자주 쓰는 값을 미리 제안하면서도, 사용자가 그 값을 지워 빈 값으로 실행하는 실수를 막기 위해서입니다.

오늘의 기준 문장

DEFAULT는 Selection Screen에 처음 보여줄 시작값이고, OBLIGATORY는 값을 비운 채 실행하지 못하게 하는 필수 입력 검증입니다. 편의와 방어를 같은 기능으로 섞어 외우지 마세요.
