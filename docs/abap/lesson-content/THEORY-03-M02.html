학습 목표

지난 Lesson에서 PARAMETERS로 입력칸을 만들었습니다. 이번에는 입력칸에 미리 값을 채우는 DEFAULT, 반드시 입력하게 만드는 OBLIGATORY, 실행 시작 시점의 Initial Value 감각을 익힙니다.

1. 지난 시간 연결: 입력칸은 만들었지만 아직 불친절하다 🧭

이전 Lesson에서 PARAMETERS p_name TYPE string.처럼 입력칸을 만들었습니다. 그런데 매번 사용자가 같은 값을 입력해야 하거나, 꼭 필요한 값을 비워두고 실행해버리면 프로그램 사용성이 떨어집니다.

좋은 Selection Screen은 사용자에게 필요한 만큼 친절해야 합니다. 자주 쓰는 값은 미리 채워두고, 꼭 필요한 값은 비워두지 못하게 막아야 합니다. 이때 쓰는 옵션이 DEFAULT와 OBLIGATORY입니다.

2. DEFAULT: 자주 쓰는 값을 미리 채워두기 ✨

DEFAULT는 PARAMETERS 입력칸에 기본값을 넣어줍니다. 사용자는 필요하면 그대로 실행하고, 필요하면 다른 값으로 바꿀 수 있습니다.

ABAP
1
2
3
4
5 
REPORT zparam_default.

PARAMETERS p_carr TYPE c LENGTH 3 DEFAULT 'KE'.

WRITE: / '항공사 코드:', p_carr.

위 프로그램을 실행하면 Selection Screen의 p_carr 칸에 KE가 미리 들어 있습니다. 사용자가 대한항공 데이터를 자주 조회한다면 꽤 편하겠죠. 하지만 다른 항공사를 보고 싶으면 값을 바꾸면 됩니다.

DEFAULT는 “추천값”에 가깝습니다. 사용자가 바꿀 수 있는 기본 출발점입니다.

3. OBLIGATORY: 빈칸 실행을 막는 안전장치 🔒

OBLIGATORY는 입력 필드를 필수값으로 만듭니다. 사용자가 값을 비워두고 실행하려 하면 Selection Screen 단계에서 오류가 나고, 프로그램 본문으로 넘어가지 않습니다.

ABAP
1
2
3
4
5 
REPORT zparam_required.

PARAMETERS p_carr TYPE c LENGTH 3 OBLIGATORY.

WRITE: / '항공사 코드:', p_carr.

항공사 코드 없이 실행되면 의미가 없는 프로그램이라면 이렇게 필수 입력으로 만드는 것이 좋습니다. 사용자가 실수로 빈값 실행을 누르는 상황을 화면에서 먼저 막아줍니다.

⚠️

OBLIGATORY는 “값 존재”만 막아줍니다

필수 입력이라고 해서 그 값이 실제로 존재하는 항공사 코드인지까지 확인해주지는 않습니다. 빈칸은 막지만, 잘못된 코드 검증은 별도의 로직이나 DDIC 입력 도움말, Check Table 같은 후속 주제가 필요합니다.

4. Initial Value: 아무것도 넣지 않았을 때의 시작값 🌱

Initial Value는 변수가 처음 만들어졌을 때 갖는 기본 빈값입니다. 타입마다 느낌이 조금 다릅니다.

  • 문자 타입은 공백처럼 시작할 수 있습니다.
  • 정수 타입은 0으로 시작할 수 있습니다.
  • 날짜 타입은 빈 날짜 상태로 시작할 수 있습니다.

DEFAULT를 쓰면 이 시작값 대신 내가 지정한 값이 Selection Screen에 먼저 보입니다. OBLIGATORY를 쓰면 사용자가 빈 초기값 상태로 실행하지 못하게 막습니다.

💡

DEFAULT와 OBLIGATORY를 같이 쓰면?

PARAMETERS p_carr TYPE c LENGTH 3 DEFAULT 'KE' OBLIGATORY.처럼 둘을 함께 쓸 수 있습니다. 기본값은 미리 채워주고, 사용자가 지워버리면 실행을 막는 조합입니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

ABAP

REPORT zparam_options.

PARAMETERS p_carr TYPE c LENGTH 3 DEFAULT 'KE' OBLIGATORY.
PARAMETERS p_days TYPE i DEFAULT 7.

WRITE: / '항공사:', p_carr,
       / '조회 일수:', p_days.
  • ✅ 정상 흐름: 기본값 KE와 7이 미리 들어 있고, 사용자가 실행하면 그대로 출력됩니다.
  • ✅ 수정 흐름: 사용자가 p_carr를 AA로 바꾸면 변경된 값이 출력됩니다.
  • ❌ 빈 필수값: 사용자가 p_carr 값을 지우고 실행하면 필수 입력 오류가 납니다.
  • ❌ 타입 오류: p_days TYPE i에 문자를 넣으면 숫자 타입에 맞지 않아 오류가 날 수 있습니다.

미니 실습에서는 기본값 그대로 실행해보고, 값을 바꿔 실행해보고, 마지막으로 OBLIGATORY 필드를 비워 실행해보세요. 정상과 오류 흐름이 눈에 확 들어옵니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

기본값은 편하지만 잘못된 선입견을 줄 수 있습니다

DEFAULT가 들어 있으면 사용자는 그 값이 “권장값”이라고 느낄 수 있습니다. 테스트 편의를 위해 넣은 기본값이 운영 프로그램에 남아 있으면 잘못된 조회나 처리로 이어질 수 있습니다. 기본값은 업무적으로 안전하고 자주 쓰이는 값인지 확인해야 합니다.

또한 OBLIGATORY를 너무 많이 붙이면 사용자는 입력할 값이 많아져 피곤해집니다. 꼭 필요한 값만 필수로 만들고, 나머지는 기본값이나 선택 입력으로 두는 균형이 필요합니다.

7. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • DEFAULT는 Selection Screen 입력칸에 기본값을 미리 채워줍니다.
  • OBLIGATORY는 빈 값으로 실행하지 못하게 막는 필수 입력 옵션입니다.
  • Initial Value는 아무 값도 넣지 않았을 때 타입이 갖는 시작값입니다.
  • DEFAULT와 OBLIGATORY는 함께 사용할 수 있습니다.
  • 기본값과 필수값은 사용성을 높이지만, 업무적으로 안전한지 확인해야 합니다.

다음 Lesson PARAMETER 입력값을 WRITE로 출력에서는 사용자가 입력한 값을 프로그램이 받아 실제 출력 결과로 보여주는 흐름을 더 자연스럽게 연결해봅니다.
