학습 목표

PARAMETERS에 붙는 DEFAULT와 OBLIGATORY를 구분하고, Selection Screen에서 처음 보이는 값과 필수 입력 검증이 각각 언제 작동하는지 직접 확인합니다.

1. 지난 Lesson 연결: 입력칸에 성격을 붙인다

M01에서는 PARAMETERS p_carr TYPE sflight-carrid. 한 줄이 프로그램 변수와 화면 입력칸을 동시에 만든다는 점을 봤습니다. 이번에는 그 입력칸에 두 가지 성격을 붙입니다. 하나는 처음 보여줄 값이고, 다른 하나는 비워 둔 채 실행하지 못하게 막는 규칙입니다.

핵심 한 줄: DEFAULT는 편의, OBLIGATORY는 방어다.
DEFAULT
  • 선택 화면이 처음 뜰 때 입력칸에 start value를 채웁니다.
  • 사용자는 값을 그대로 쓰거나 다른 값으로 바꿀 수 있습니다.
  • 사용자가 값을 지우는 행동까지 막지는 않습니다.
OBLIGATORY
  • 입력 필드를 required field로 만듭니다.
  • 빈 값으로 Execute(F8)를 누르면 화면을 빠져나가지 못합니다.
  • 값이 업무적으로 존재하는지까지 보장하지는 않습니다.

2. DEFAULT: 처음 보이는 시작값

DEFAULT는 Selection Screen에 표시될 시작값을 선언문에 적는 옵션입니다. SAP 문서 기준으로도 DEFAULT를 지정하지 않으면 타입에 연결된 Initial Value가 start value로 쓰입니다. 그래서 DEFAULT 'KRW'는 “빈 출발 대신 KRW로 시작하자”는 의미입니다.

ABAP

  WRITE: / '통화:', p_curr.
⚠️

DEFAULT는 잠금이 아니다

DEFAULT로 값이 채워져도 사용자는 그 값을 바꾸거나 지울 수 있습니다. “처음 보이는 값”과 “반드시 있어야 하는 값”을 같은 기능으로 생각하면 안 됩니다.

3. OBLIGATORY: 빈 값 실행 방지

OBLIGATORY는 입력 필드를 필수 입력으로 만듭니다. 사용자가 해당 칸을 비운 채 Execute(F8)를 누르면 SAP GUI는 선택 화면에 머물게 하고, 프로그램의 본 처리로 넘어가지 않습니다.

ABAP
1
2
3
4
5
6 
REPORT z_demo_param_m02_required.

PARAMETERS p_user TYPE c LENGTH 10 OBLIGATORY.

START-OF-SELECTION.
  WRITE: / '사용자:', p_user.
OBLIGATORY가 있으면 업무 검증도 끝나나요?

아닙니다. OBLIGATORY는 값이 비었는지만 막습니다. 존재하지 않는 코드, 권한 없는 회사코드, 날짜 범위 오류 같은 업무 검증은 AT SELECTION-SCREEN, DDIC 값 도움말, 별도 체크 로직에서 다룹니다.

4. 조합별 화면 흐름

아래 표는 같은 입력칸에 옵션을 붙였을 때 처음 화면과 F8 실행 흐름이 어떻게 달라지는지 보여 줍니다. 판단 기준은 “처음 무엇이 보이는가”와 “비웠을 때 실행되는가”입니다.

DEFAULT / OBLIGATORY 조합 판단표

선언 처음 보이는 값 사용자가 비우고 F8 의미
PARAMETERS p_a TYPE c LENGTH 3. 공백 실행될 수 있음 기본 입력칸
... DEFAULT 'KRW'. KRW 실행될 수 있음 편의값 제공
... OBLIGATORY. 공백 Selection Screen에서 멈춤 빈 값 방어
... DEFAULT 'KRW' OBLIGATORY. KRW 지우면 Selection Screen에서 멈춤 편의 + 방어
DEFAULT가 있으면 OBLIGATORY는 필요 없나요?

필요할 수 있습니다. 사용자가 기본값을 지우고 실행할 수 있기 때문입니다. 비어 있으면 안 되는 입력이라면 DEFAULT와 OBLIGATORY를 함께 둡니다.

SE38에서 아래 리포트를 만든 상황이라고 가정합니다. P_CURR는 DEFAULT와 OBLIGATORY를 함께 갖고, P_USER는 필수 입력만 갖고, P_LIMIT은 기본값만 갖습니다. 값을 바꾸거나 지운 뒤 실행(F8)을 눌러 차이를 확인하세요.

6. DEFAULT와 INITIALIZATION 경계

DEFAULT는 선언문에 붙는 정적 시작값입니다. 반면 “오늘 날짜 기준 7일 전”, “사용자 권한에 맞는 기본 회사코드”, “테이블에서 마지막 사용 조건 조회”처럼 실행 시점 계산이 필요한 기본값은 INITIALIZATION 이벤트에서 다룹니다. 이번 Lesson에서는 DEFAULT와 OBLIGATORY의 화면 동작까지만 정확히 잡습니다.

DEFAULT 'KRW' 선언문에 보이는 정적 시작값입니다.
INITIALIZATION 동적으로 기본값을 계산하는 후속 주제입니다.
OBLIGATORY 빈 값으로 F8 실행하는 흐름을 막습니다.
업무 검증 존재 여부와 권한 검사는 별도 검증 로직의 책임입니다.

7. 화면 라벨: 변수명을 그대로 보여주지 않는다

SE38에서 PARAMETERS p_user ...만 작성하면 화면 라벨이 P_USER처럼 개발자 변수명으로 보일 수 있습니다. 실무 화면은 현업 사용자가 읽는 화면이므로 Selection Texts에서 “사용자”, “통화 코드”, “최대 건수”처럼 업무 용어로 바꿔야 합니다.

SE38리포트 소스 열기
GotoText Elements 메뉴 진입
Selection TextsP_USER에 “사용자” 라벨 입력
Activate텍스트 요소까지 활성화
라벨을 저장만 하면 충분한가요?

아닙니다. Text Elements도 Repository 객체의 일부라 활성화가 필요합니다. 저장 후 활성화하지 않으면 화면에 기대한 라벨이 반영되지 않을 수 있습니다.

8. 7분 미니 실습

  1. SE38에서 새 Report를 만들고 p_curr, p_user, p_limit를 선언합니다.
  2. p_curr에는 DEFAULT 'KRW' OBLIGATORY를 함께 붙입니다.
  3. p_user에는 OBLIGATORY만 붙여, 처음에는 빈 필수 입력칸으로 보이게 합니다.
  4. p_limit에는 DEFAULT 50만 붙여, 지워도 필수 검증이 걸리지 않는 차이를 확인합니다.
  5. Selection Texts에서 화면 라벨을 업무 용어로 바꾸고 활성화합니다.
실습 후 한 문장으로 정리하기

DEFAULT는 사용자가 바꿀 수 있는 시작값이고, OBLIGATORY는 값을 비운 채 실행하지 못하게 하는 필수 입력 검증입니다.

9. 공식 문서로 더 확인하기

SAP Help: PARAMETERS PARAMETERS가 데이터 오브젝트와 Selection Screen 입력 필드를 동시에 만드는 규칙을 확인합니다. SAP Help: PARAMETERS value_options DEFAULT와 start value, initial value 관계를 확인합니다. SAP Help: PARAMETERS screen_options OBLIGATORY가 required field와 Execute(F8) 흐름에 미치는 영향을 확인합니다. SAP Help: LOAD-OF-PROGRAM 선택 화면 전 기본값 준비와 INITIALIZATION의 위치를 후속 학습용으로 확인합니다.

10. 확인 퀴즈

  1. DEFAULT 'KRW'가 있는 입력칸에서 사용자는 값을 지울 수 있나요?
  2. OBLIGATORY는 존재하지 않는 업무 코드까지 자동으로 막아 주나요?
  3. DEFAULT와 OBLIGATORY를 함께 쓰는 이유는 무엇인가요?
  4. 화면 라벨이 P_USER처럼 보이면 SE38의 어느 영역을 확인해야 하나요?
정답/해설 보기
  1. 네. DEFAULT는 처음 보이는 값일 뿐이고 사용자는 실행 전에 수정하거나 지울 수 있습니다.
  2. 아니요. OBLIGATORY는 값의 존재 여부만 막습니다. 업무적 유효성은 별도 검증 범위입니다.
  3. 자주 쓰는 값을 미리 제안하면서, 사용자가 그 값을 지워 빈 값으로 실행하는 실수를 막기 위해서입니다.
  4. Goto → Text Elements → Selection Texts에서 파라미터 라벨을 유지보수합니다.
