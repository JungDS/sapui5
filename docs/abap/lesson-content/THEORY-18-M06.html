학습 목표

오류를 객체로 다루는 예외 클래스(Exception Class)를 배웁니다. TRY...CATCH로 오류를 잡고, RAISE EXCEPTION으로 오류를 알리는 흐름을 익힙니다.

1. 지난 시간 연결: 오류도 "객체"로 다룬다 ⚠️

예전에는 오류를 sy-subrc 값으로 확인했습니다. 잘 동작하지만, "무슨 오류가 왜 났는지" 같은 풍부한 정보를 담기 어려웠죠.

객체지향에서는 오류를 예외 클래스라는 객체로 다룹니다. 오류에 메시지·원인·맥락을 담아, 발생시키고(throw) 잡을(catch) 수 있습니다.

2. TRY...CATCH로 오류 잡기 ✍️

ABAP
1
2
3
4
5
6 
TRY.
    DATA(lv_result) = 10 / lv_divisor.   "0으로 나누면 오류

  CATCH cx_sy_zerodivide INTO DATA(lx_err).
    " 오류가 났을 때 할 일

    MESSAGE lx_err->get_text( ) TYPE 'I'.
ENDTRY.
  • TRY: "오류가 날 수 있는" 코드를 감쌉니다.
  • CATCH: 특정 예외(cx_sy_zerodivide)가 나면 여기로 와서 처리합니다.
  • lx_err->get_text( ): 예외 객체에서 오류 메시지를 꺼냅니다.
💡

비유: 안전망

TRY는 외줄타기 아래 안전망이에요. 떨어져도(오류) 망(CATCH)이 받아주니 공연(프로그램)이 안 멈춥니다. 망이 없으면 그대로 추락(덤프)하죠.

3. RAISE EXCEPTION으로 오류 알리기 📢

내가 만든 메서드에서 "이건 잘못됐어"를 알리려면 직접 예외를 발생시킵니다. 보통 나만의 예외 클래스(ZCX_)를 만들어 씁니다.

METHOD withdraw.
  IF iv_amount > mv_balance.
    RAISE EXCEPTION TYPE zcx_insufficient_fund.   "잔액 부족 예외 발생

  ENDIF.
  mv_balance = mv_balance - iv_amount.
ENDMETHOD.

호출한 쪽은 이 메서드를 TRY...CATCH zcx_insufficient_fund로 감싸 처리합니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 오류 가능 코드를 TRY로 감싸고, 예외를 CATCH로 처리해 프로그램이 안전하게 계속됩니다.
  • ❌ 오류 1 — 방치: 예외를 안 잡으면(CATCH 없음) 프로그램이 덤프됩니다.
  • ❌ 오류 2 — 삼키기: CATCH해 놓고 아무 처리도 안 하면(빈 CATCH), 오류가 조용히 묻혀 더 큰 문제가 됩니다.

5. 실무에서 조심할 점 🚨

⚠️

"빈 CATCH"는 가장 위험한 습관

오류를 잡아놓고 아무것도 안 하면, 문제가 발생했는데도 프로그램은 멀쩡한 척 진행합니다. 나중에 "왜 데이터가 이상하지?"의 원인을 찾기가 극도로 어려워집니다. 예외를 잡았으면 반드시 로그를 남기거나 사용자에게 알리거나 안전하게 복구해야 합니다. 잡는 것보다 "잡고 무엇을 하는가"가 더 중요합니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • 예외 클래스는 오류를 정보가 담긴 객체로 다룹니다.
  • TRY...CATCH로 오류를 잡아 안전하게 처리합니다.
  • RAISE EXCEPTION으로 내 메서드에서 오류를 알립니다.
  • 빈 CATCH(오류 삼키기)는 절대 금물 — 잡았으면 처리합니다.
