학습 목표

이번 Lesson에서는 값을 담는 그릇을 만듭니다. DATA로 변수를 선언하고, ABAP 기본 데이터 타입(i·c·d·p·string 등)을 고르고, TYPES로 나만의 타입을, CONSTANTS로 변하지 않는 값을 정의하는 법을 직접 선언해 보며 익힙니다.

1. 지난 Lesson 연결: 프로그램 뼈대 위에 데이터를 얹는다

앞 Lesson에서 REPORT로 시작하는 가장 작은 프로그램을 만들고, 저장 → 활성화 → 실행까지 해 봤습니다. 그때 “전역 선언부는 다음에”라고 비워 뒀던 자리를 이번에 채웁니다.

프로그램이 무언가를 계산하거나 보여 주려면, 값을 잠시 담아 둘 그릇(변수)이 필요합니다. 그릇마다 “무엇을 담을 수 있는지(숫자? 글자? 날짜?)”가 정해져 있는데, 그게 바로 데이터 타입입니다.

오늘의 핵심 한 줄: “DATA는 값을 담는 그릇, TYPES는 그릇의 설계도, CONSTANTS는 봉인된 그릇이다.”

2. DATA: 값을 담는 그릇 만들기

DATA 문은 실행 중에 값을 담아 둘 메모리 공간(데이터 오브젝트)을 만듭니다. 기본 문법은 아주 단순합니다.

ABAP
1
2
3
4
5 
DATA lv_count TYPE i.                 " 정수 그릇, 초기값 0
DATA lv_name  TYPE c LENGTH 10.       " 10글자 문자 그릇
DATA lv_price TYPE p LENGTH 8 DECIMALS 2. " 소수 2자리 금액

DATA lv_msg TYPE string VALUE '안녕'.  " VALUE로 초기값 지정

DATA 문 한 줄의 구성

DATA
“그릇을 만들어라”
→
이름
lv_count
변수 이름
→
TYPE
i
담을 값의 종류
→
VALUE
(선택)
초기값

VALUE를 생략하면 타입별 기본 초기값(숫자는 0, 문자는 공백)이 자동으로 들어갑니다.

변수 이름은 보통 lv_, gv_로 시작하던데요?

문법 규칙은 아니지만 현장 관습입니다. lv_=local variable(지역 변수), gv_=global variable(전역 변수), ls_/gs_=structure, lt_/gt_=internal table. 이름만 봐도 종류와 범위가 보이도록 붙이는 헝가리안 표기입니다.

3. 기본 타입 도감: 어떤 그릇을 고를까

ABAP에는 미리 정의된 기본(elementary) 타입이 있습니다. 길이를 적지 않으면 기본 길이가 적용되니 표를 눈에 익혀 두세요. 특히 c·n의 기본 길이가 1이라는 점이 초심자의 함정입니다.

자주 쓰는 ABAP 기본 데이터 타입

타입담는 것기본 길이초기값예
i정수(소수 없음)4 byte0수량, 카운터
p소수(Packed)8 (DECIMALS 필요)0금액, 단가
c고정 길이 문자1공백코드, 플래그
n숫자형 문자(연산 X)1'0'사번, 우편번호
string가변 길이 문자가변빈 값메시지, 긴 텍스트
d날짜8 (YYYYMMDD)'00000000'주문일
t시간6 (HHMMSS)'000000'처리 시각
x16진수 바이트1'00'바이너리

n은 숫자처럼 보여도 문자열입니다. 사번 '0007'처럼 앞의 0을 지켜야 하고 계산하지 않는 값에 씁니다. 진짜 계산은 i·p로 합니다.

✂️

길이 함정: TYPE c만 쓰면 1글자만 담긴다

DATA lv_x TYPE c.처럼 길이를 생략하면 CHAR 1이 됩니다. 여기에 'HELLO'를 넣으면 첫 글자 'H'만 남고 나머지는 잘립니다(truncation). 오류 메시지도 없이 조용히 잘리므로 더 위험합니다. 문자 변수는 꼭 LENGTH를 함께 지정하세요.

4. TYPES: 나만의 타입 설계도

TYPES는 메모리를 전혀 차지하지 않는 “설계도”를 만듭니다. 같은 모양의 데이터를 여러 곳에서 쓸 때, 매번 타입을 길게 적는 대신 한 번 정의해 두고 재사용합니다.

ABAP
1
2
3
4
5
6 
* 내 타입(설계도)을 한 번 정의
TYPES ty_amount TYPE p LENGTH 8 DECIMALS 2.

* 여러 변수에서 같은 설계도를 재사용
DATA lv_price TYPE ty_amount.
DATA lv_total TYPE ty_amount.

DATA vs TYPES — 무엇이 메모리를 쓰나

TYPES (설계도)
  • 값을 담지 못한다
  • 메모리를 안 쓴다
  • “어떤 모양인가”만 정의
DATA (실제 그릇)
  • 값을 담는다
  • 메모리를 점유
  • 설계도(TYPE)를 참조해 생성
SE11에서 만든 “전역 타입”과는 뭐가 다른가요?

TYPES는 프로그램 안에서만 쓰는 지역 타입입니다. 반면 SE11(ABAP Dictionary)에서 만든 Data Element 같은 전역 타입은 여러 프로그램·테이블이 공유합니다. DATA lv_carrid TYPE sflight-carrid.처럼 DDIC 필드를 직접 참조하면, 그 필드의 길이·의미를 그대로 물려받습니다.

5. CONSTANTS: 봉인된 값으로 매직 넘버 없애기

CONSTANTS는 실행 중에 절대 바뀌지 않는 값입니다. 선언할 때 VALUE로 값을 반드시 정해야 하고(필수), 그 뒤로는 변경할 수 없습니다.

ABAP
1
2 
CONSTANTS gc_vat_rate TYPE p LENGTH 3 DECIMALS 2 VALUE '0.10'.
CONSTANTS gc_airline TYPE c LENGTH 2 VALUE 'LH'.

왜 상수를 쓸까 — 매직 넘버 제거

❌ 매직 넘버
  • lv_tax = lv_amount * '0.10'.
  • 0.10이 무슨 값인지 불명확
  • 세율이 바뀌면 코드 전체를 뒤져 수정
✅ 상수 사용
  • lv_tax = lv_amount * gc_vat_rate.
  • 이름이 의미를 설명
  • 값은 선언 한 곳만 고치면 끝
⚠️

CONSTANTS에 VALUE를 빠뜨리면 구문 오류

CONSTANTS gc_x TYPE i.처럼 VALUE 없이 선언하면 즉시 구문 에러가 납니다(활성화 불가). 상수는 “정해진 값”이 본질이므로 값이 반드시 있어야 합니다. 반대로 DATA는 VALUE가 선택입니다.

6. 직접 해보기: 선언 키워드 시뮬레이터

아래 sandbox는 SE38 에디터에서 선언부를 작성하고 구문 검사와 실행 결과를 확인하는 실습입니다. 선언 종류를 바꾸며 DATA는 메모리, TYPES는 설계도, CONSTANTS는 잠긴 값이라는 차이를 눌러 확인하세요. 특히 CONSTANTS에서 VALUE를 비우거나, TYPES 이름을 런타임에 출력하려 하면 검증에서 막힙니다.

T-Code: SE38 (ABAP Editor)
DATA / CONSTANTS / TYPES 선언 검사
버튼을 누르면 선택한 선언 종류의 Blueprint/RAM/Runtime 차이가 단계별로 표시됩니다.
버그 헌트: TYPE c인데 SUCCESS가 S만 나오나요?

c와 n은 LENGTH를 생략하면 기본 길이 1입니다. 위 sandbox에서 타입을 c, LENGTH를 빈 값, VALUE를 SUCCESS로 두면 실제 ABAP에서는 앞 한 글자만 담기는 상황을 예상해야 합니다. 전체 값을 보존하려면 LENGTH 7처럼 길이를 지정하세요.

타입에 integer라고 적으면 왜 안 되나요?

ABAP 기본 타입의 이름은 한 글자 약어입니다. 정수는 i, 문자는 c, 날짜는 d입니다. integer·char 같은 풀네임은 ABAP 기본 타입이 아니라서 검증에서 막힙니다. 가변 길이 문자만 예외적으로 string이라고 풀어 씁니다.

7. 한 걸음 더: 인라인 선언(Modern ABAP)

최신 ABAP(7.40+)에서는 변수를 미리 선언하지 않고, 쓰는 자리에서 바로 만들 수 있습니다. 시스템이 오른쪽 값을 보고 타입을 스스로 추론합니다.

ABAP
1
2
3 
START-OF-SELECTION.
  DATA(lv_year) = sy-datum(4).   " 값을 보고 타입을 자동 추론
  WRITE lv_year.

인라인 선언은 선언부를 위아래로 오가는 수고를 줄여 줍니다. 다만 지금 단계에서는 DATA … TYPE … 형태를 먼저 충분히 익히는 것이 타입 감각을 잡는 데 도움이 됩니다.

9. 확인 퀴즈

  1. DATA와 TYPES 중 메모리를 차지하는 것은 무엇인가요?
  2. DATA lv_x TYPE c.에 'HELLO'를 넣으면 어떻게 되나요?
  3. 사번 '0007'처럼 앞의 0을 지켜야 하고 계산하지 않는 값에는 어떤 타입이 어울리나요?
  4. CONSTANTS 선언에서 빠뜨리면 구문 오류가 나는 필수 옵션은 무엇인가요?
  5. 금액·단가처럼 소수 계산이 필요한 값에는 어떤 타입을 쓰며, 무엇을 꼭 지정해야 하나요?
정답/해설 보기
  1. DATA입니다. TYPES는 설계도일 뿐 메모리를 쓰지 않습니다.
  2. 'H' 한 글자만 남고 잘립니다. 길이를 생략하면 CHAR 1이기 때문입니다. LENGTH를 지정해야 합니다.
  3. n(숫자형 문자)입니다. 숫자처럼 보이지만 문자열이라 앞의 0이 보존됩니다.
  4. VALUE입니다. 상수는 값이 본질이라 반드시 지정해야 합니다.
  5. p(packed)를 쓰고 DECIMALS(소수 자릿수)를 꼭 지정해야 합니다. 빠뜨리면 정수처럼 처리됩니다.

10. 한눈에 정리

DATA값을 담는 그릇(변수). 메모리를 점유하고 값을 바꿀 수 있습니다.
기본 타입i·p는 계산용 숫자, c·n·string은 문자, d·t는 날짜·시간. 길이 기본값에 주의.
TYPES메모리 없는 설계도. 같은 모양을 여러 곳에서 재사용합니다.
CONSTANTSVALUE가 필수인 봉인된 값. 매직 넘버를 없앱니다.
