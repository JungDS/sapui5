학습 목표

이번 Lesson에서는 프로그램 안에서 값을 다루는 세 가지 선언을 배웁니다. 값을 담는 변수 DATA, 바뀌지 않는 값 CONSTANTS, 그리고 값의 모양을 정의해 재사용하는 TYPES입니다. 가장 기본이 되는 Elementary Type도 함께 정리합니다.

1. 지난 Lesson 연결: 프로그램을 만들었으니 이제 값을 담아 보자

지난 Lesson에서 REPORT로 프로그램을 열고 WRITE로 한 줄을 출력해 봤습니다. 그런데 진짜 업무 프로그램은 고정된 문장만 찍지 않습니다. “주문 수량”, “단가”, “오늘 날짜” 같은 값을 어딘가에 담아 두고 계산하고 비교해야 합니다.

그 “담아 두는 자리”를 만드는 것이 변수 선언입니다. ABAP에서는 DATA, CONSTANTS, TYPES 세 가지로 값과 모양을 다룹니다. 오늘은 이 셋을 구분하는 감을 잡는 것이 목표입니다.

핵심 질문: “이건 바뀌는 값인가, 고정된 값인가, 아니면 값이 아니라 모양(틀)인가?”

2. 세 선언의 역할을 한눈에 구분하기

초심자가 가장 먼저 헷갈리는 지점이 “변수와 타입이 뭐가 다른가”입니다. 아래 3분류로 나눠 보면, 지금 내가 쓰는 것이 값인지 모양인지가 덜 헷갈립니다.

DATA · CONSTANTS · TYPES 3분류

DATA
무엇값을 담는 변수(상자)
바뀌나?실행 중 자유롭게 변경 가능
예주문 수량, 합계
CONSTANTS
무엇고정된 값(팻말)
바뀌나?한 번 정하면 변경 불가
예최대 재시도 3회, 원주율
TYPES
무엇값의 모양(틀) 정의
바뀌나?값이 아니라 정의 — 재사용
예“수량 타입”을 만들어 여러 변수가 사용

한 문장으로: DATA는 바뀌는 상자, CONSTANTS는 고정 팻말, TYPES는 상자를 찍는 틀입니다.

3. DATA와 CONSTANTS를 코드로 써 보기

변수는 DATA 이름 TYPE 타입. 형태로 선언합니다. 상수는 CONSTANTS 이름 TYPE 타입 VALUE 초기값.처럼 VALUE로 값을 반드시 지정합니다.

REPORT zdata_demo.

DATA lv_qty   TYPE i.                  " 주문 수량 (정수, 바뀔 수 있음)
DATA lv_name  TYPE string.             " 고객 이름 (가변 문자열)

CONSTANTS lc_max_retry TYPE i VALUE 3. " 최대 재시도 횟수 (고정)

lv_qty  = 10.
lv_name = 'ABAP'.

WRITE: / lv_name, lv_qty, lc_max_retry.
💡

대입과 선언은 다릅니다

DATA는 “자리를 만든다”, =는 “그 자리에 값을 넣는다”입니다. CONSTANTS는 선언과 동시에 VALUE로 값을 고정하므로, 뒤에서 lc_max_retry = 5.처럼 다시 넣으려 하면 문법 오류가 납니다.

4. Elementary Type: 더 못 쪼개는 기본 타입들

Elementary Type은 더 쪼갤 수 없는 단일 값 타입입니다. 처음에는 아래 7개만 알아도 충분합니다. 자주 쓰는 것부터 익히세요.

자주 쓰는 기본 타입 치트시트

타입의미특징
I정수수량, 카운터에 사용
P압축 소수(Packed)금액·단가 등 소수 계산. DECIMALS 지정
STRING가변 문자열길이 고정 없이 늘어남
C고정 길이 문자길이를 미리 지정(LENGTH)
N숫자형 문자우편번호·코드처럼 0으로 시작 보존
D날짜8자리 YYYYMMDD
T시간6자리 HHMMSS

금액에 I(정수)를 쓰면 소수점이 잘립니다. 단가·금액은 보통 P DECIMALS n을 씁니다.

C(고정 문자)와 STRING(가변 문자)은 뭐가 다를까?

C LENGTH 10은 항상 10칸을 차지하고 남는 칸은 공백으로 채웁니다. STRING은 담은 내용만큼만 길이를 가집니다. 길이가 정해진 코드값에는 C/N, 길이를 모르는 설명·이름에는 STRING이 잘 맞습니다.

5. TYPES: 모양을 한 번 정의해 재사용하기

같은 “수량” 개념을 여러 변수가 쓴다면, 매번 TYPE i를 반복하는 대신 TYPES로 “수량 타입”을 한 번 정의해 재사용할 수 있습니다. 규격이 바뀌면 정의 한 곳만 고치면 됩니다.

REPORT ztypes_demo.

TYPES ty_qty TYPE i.        " '수량'이라는 모양을 정의 (값 아님)

DATA lv_order_qty TYPE ty_qty.   " 정의한 타입을 재사용
DATA lv_stock_qty TYPE ty_qty.

lv_order_qty = 5.
lv_stock_qty = 20.

WRITE: / lv_order_qty, lv_stock_qty.

Chapter 1의 Data Element가 “DDIC에 만든 공용 타입”이라면, TYPES는 “이 프로그램 안에서 쓰는 지역 타입”에 가깝습니다.

6. 정상 흐름과 오류 흐름을 함께 보기

자주 만나는 선언 관련 오류

선언DATA lv_qty TYPE i.
대입lv_qty = 10.
활성화·실행OK 값 출력
선언CONSTANTS lc_max TYPE i VALUE 3.
재대입 시도lc_max = 5.
활성화실패 상수에는 값을 다시 넣을 수 없음
선언DATA lv_qty TYPE i.
대입lv_qty = 'ABC'. (문자→정수)
결과주의 변환 오류 또는 의도치 않은 값

정수 변수에 글자를 넣는 등 “모양이 안 맞는 값”을 넣으면 변환 규칙에 따라 오류가 나거나 엉뚱한 값이 됩니다. 타입을 맞추는 습관이 중요합니다.

7. 미니 실습: 세 선언을 직접 구분해 보기

✍️

실습 과제

  1. DATA로 정수 변수 1개, 문자열 변수 1개를 선언합니다.
  2. CONSTANTS로 “최대 횟수 3” 같은 고정값 1개를 선언합니다.
  3. TYPES로 타입 1개를 정의하고, 그 타입으로 변수 2개를 만듭니다.
  4. 상수에 값을 다시 대입해 보고 어떤 오류가 나는지 적습니다. (오류 케이스)
  5. 오류 줄을 지운 뒤 활성화·실행해 값을 출력합니다. (정상 결과)

완료 조건: “이건 DATA/CONSTANTS/TYPES 중 무엇이고 왜 그런가”를 각 줄에 대해 설명할 수 있으면 성공입니다.

변수 이름 접두어(lv_, lc_, ty_)는 꼭 써야 하나?

문법상 필수는 아니지만, 회사 코딩 가이드에서 변수는 lv_, 상수는 lc_, 타입은 ty_ 같은 접두어를 권하는 경우가 많습니다. 이름만 봐도 역할이 보이게 하는 관행입니다. 회사 규칙이 있으면 그 규칙을 따르세요.

8. 실무에서 조심해야 할 점

🚨

“돌아가는 선언”과 “맞는 선언”은 다릅니다

금액에 정수 타입을 쓰면 당장은 실행되지만 소수점이 잘려 잘못된 계산으로 이어집니다. 타입은 “값의 의미”에 맞게 고르는 것이 유지보수의 출발점입니다.

  • 의미에 맞는 타입: 금액·단가는 P DECIMALS, 코드값은 C/N, 설명은 STRING.
  • 표준 vs 커스텀: 접두어·네이밍은 회사 커스텀 관행이고, DATA/CONSTANTS/TYPES 동작은 SAP 표준입니다. 둘을 섞어 외우지 않습니다.
  • 과확장 금지: 구조체(Structure)·내부 테이블 같은 복합 타입은 뒤 Chapter에서 다룹니다. 지금은 기본 타입에 집중합니다.

10. 확인 퀴즈

  1. 실행 중에 값이 바뀔 수 있는 선언과, 한 번 정하면 못 바꾸는 선언은 각각 무엇인가요?
  2. TYPES로 만든 것은 “값”인가요, “모양”인가요?
  3. 금액 계산에 I(정수) 타입을 쓰면 어떤 문제가 생기나요?
  4. 고정 길이 문자 C와 가변 문자열 STRING의 차이는 무엇인가요?
정답/해설 보기
  1. 바뀌는 것은 DATA(변수), 못 바꾸는 것은 CONSTANTS(상수)입니다.
  2. “모양”입니다. TYPES는 값을 담지 않고 타입(틀)만 정의하며, DATA가 그 틀로 변수를 만듭니다.
  3. 소수점이 잘립니다. 금액·단가는 P DECIMALS n 같은 소수 타입을 써야 합니다.
  4. C는 길이가 고정되어 남는 칸을 공백으로 채우고, STRING은 담은 내용만큼만 길이를 가집니다.

11. 한눈에 정리

CONSTANTSVALUE로 고정한 값. 다시 대입할 수 없습니다.
TYPES값이 아니라 모양(틀)을 정의해 여러 변수가 재사용합니다.
Elementary TypeI·P·C·N·D·T·STRING. 의미에 맞는 타입을 고르는 게 핵심입니다.
