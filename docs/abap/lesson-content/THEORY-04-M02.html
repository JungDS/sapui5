학습 목표

지난 Lesson에서 Foreign Key와 Check Table을 배웠습니다. 이번에는 Domain에 적는 Value Table이 실제 Foreign Key 검증과 어떻게 다른지 확실히 구분합니다.

1. 지난 시간 연결: 기준표 이름을 적었다고 검증이 끝난 걸까? 🤔

Foreign Key를 배우고 나면 초심자가 자주 하는 질문이 있습니다. “Domain에도 Value Table이라는 칸이 있던데, 거기에 기준표를 적으면 끝 아닌가요?” 아주 좋은 질문입니다.

결론부터 말하면 Value Table을 적는 것만으로는 실제 입력 검증이 완성되지 않습니다. Value Table은 Foreign Key를 만들 때 참고할 수 있는 기본 후보에 가깝고, 실제 관계와 검증은 테이블 필드에 Foreign Key를 설정해야 의미가 생깁니다.

Value Table은 “이 Domain은 보통 이 기준표를 봐요”라는 힌트이고, Foreign Key는 “이 필드는 실제로 이 기준표를 검사해요”라는 연결입니다.

2. Value Table은 Domain 레벨의 추천 기준표 📌

Value Table은 Domain에 지정하는 기준 테이블입니다. 같은 Domain을 사용하는 여러 필드가 있을 때, “이 Domain의 값은 보통 이 테이블에서 관리한다”는 정보를 제공합니다.

  • 위치: Domain 설정 안에 존재합니다.
  • 역할: Foreign Key 제안이나 기본 후보로 쓰일 수 있습니다.
  • 한계: 이것만으로 모든 사용 필드에 검증이 자동 적용되는 것은 아닙니다.

일상으로 치면 Value Table은 “이 과목 참고서는 보통 이 책을 봅니다”라고 적어둔 안내 문구와 같습니다. 실제 시험 채점 기준이 되려면, 시험 문제와 그 참고서가 평가 기준으로 명확히 연결되어야 합니다.

3. Foreign Key는 Table Field 레벨의 실제 약속 🔗

Foreign Key는 특정 테이블 필드에 설정합니다. 예를 들어 ZBOOKING-CARRID 필드가 ZCARRIER-CARRID를 참조하도록 연결하는 것이 실제 Foreign Key입니다.

💡

차이를 한 줄로 비교

  • Value Table: Domain에 붙은 기준표 힌트
  • Foreign Key: 테이블 필드에 붙은 실제 검사 관계

그래서 같은 Domain을 쓰는 필드라도 어떤 테이블 필드에는 Foreign Key를 걸고, 어떤 필드에는 업무 의미상 다른 관계를 걸 수 있습니다. Domain은 재질의 공통 기준이고, Foreign Key는 실제 사용 위치의 관계입니다.

Value Table만 있을 때 vs Foreign Key까지 걸었을 때

Value Table만 지정 (검증 없음)
위치Domain ZCARRID
역할"보통 이 기준표를 봐요" 제안
입력 XXX막지 못함
Foreign Key까지 설정 (검증 동작)
위치테이블 필드 ZBOOKING-CARRID
역할"이 기준표로 실제 검사" 연결
입력 XXX화면 입력에서 차단

Value Table은 Foreign Key를 만들 때 시스템이 기준표를 제안해주는 출발점이고, 실제 입력 검증은 테이블 필드의 Foreign Key가 만들어져야 동작합니다.

4. 최소 예시로 다시 보기 🧪

항공사 코드 Domain ZCARRID가 있다고 해봅시다. 이 Domain의 Value Table에 ZCARRIER를 적을 수 있습니다.

  • Domain: ZCARRID, 타입 CHAR 3, Value Table ZCARRIER
  • 업무 테이블: ZBOOKING-CARRID 필드가 ZCARRID Domain을 간접 사용
  • 실제 검증: ZBOOKING-CARRID에 Foreign Key를 생성해 ZCARRIER와 매핑

여기서 핵심은 마지막 줄입니다. Value Table이 이미 적혀 있어도, 업무 테이블 필드에 Foreign Key를 실제로 설정해야 그 필드의 검증 관계가 분명해집니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: Domain에 Value Table이 있고, 테이블 필드에 Foreign Key도 생성되어 있습니다. 입력값이 Check Table에 있으면 통과합니다.
  • ❌ 오해 흐름: Domain에 Value Table만 적고 Foreign Key를 만들지 않았습니다. 개발자는 검증된다고 생각하지만 실제 필드 검증은 기대대로 동작하지 않을 수 있습니다.
  • ❌ 잘못된 기준표: Value Table 후보를 그대로 믿고 업무 의미가 다른 필드에 억지로 연결하면, 사용자가 올바른 값을 입력하지 못할 수 있습니다.
  • ❌ 표준 혼동: 표준 Domain에 적힌 Value Table을 고객사 커스텀 검증 규칙으로 착각하면 안 됩니다.
Value Table은 출발점이고, Foreign Key는 실제 연결입니다. 둘을 같은 것으로 외우면 DDIC 관계에서 자주 길을 잃습니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

“Domain에 Value Table 있네요”에서 멈추지 마세요

실무에서 입력 검증이나 F4 Help 문제를 볼 때는 Domain의 Value Table만 확인하면 부족합니다. 실제 테이블 필드에 Foreign Key가 있는지, Check Table과 필드 매핑이 맞는지, Data Element나 Search Help가 추가로 연결되어 있는지 함께 봐야 합니다.

또한 Value Table을 무조건 채워야 하는 것도 아닙니다. 값 목록이 고정값으로 충분한지, 별도 기준표가 필요한지, 표준 객체를 재사용할 수 있는지 먼저 판단해야 합니다.

7. 미니 실습: 힌트와 연결 구분하기 🧪

✍️

실습 과제

  1. 위 비교표를 가리고, Value Table과 Foreign Key의 차이를 "위치"와 "역할" 두 줄로 직접 적어봅니다.
  2. "Domain에 Value Table을 적었는데 왜 검증이 안 되죠?"라는 동료 질문에 답하는 한 문장을 만들어봅니다.
  3. 같은 Domain을 쓰는 두 필드 중 하나만 Foreign Key를 걸어야 하는 업무 상황을 하나 상상해봅니다.

완료 조건: “Value Table은 Domain 레벨의 제안, Foreign Key는 필드 레벨의 실제 검증”을 예시와 함께 설명할 수 있으면 성공입니다.

8. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: Value Table - Value Table이 Domain에 붙는 제안 정보라는 공식 정의를 확인합니다.
  • SAP Help Portal: Foreign Key - 실제 검증 관계인 Foreign Key의 공식 정의를 확인합니다.
  • SAP Help Portal: Check Table - Value Table이 Check Table로 "격상"되는 조건을 비교해봅니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. Domain에 Value Table을 지정하면 그 Domain을 쓰는 모든 필드에 입력 검증이 자동 적용될까요?
  2. Value Table과 Check Table 중, 실제로 입력값을 검사하는 시점에 기준이 되는 것은 무엇인가요?
  3. 입력 검증이나 F4 문제를 분석할 때 Domain의 Value Table만 확인하면 안 되는 이유는 무엇인가요?
정답/해설 보기
  1. 아니요. Value Table은 Foreign Key를 만들 때 기준표를 제안하는 정보일 뿐, 각 테이블 필드에 Foreign Key를 설정해야 검증이 동작합니다.
  2. Check Table입니다. Foreign Key 관계가 만들어지면 그 기준표가 Check Table이 되어 입력값 존재 여부를 검사합니다.
  3. 실제 동작은 필드의 Foreign Key, Check Table 매핑, Data Element/Search Help 연결이 함께 결정하기 때문입니다. Value Table은 그중 출발점 힌트일 뿐입니다.

10. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • Value Table은 Domain에 지정하는 기준표 후보입니다.
  • Foreign Key는 특정 테이블 필드에 설정하는 실제 검증 관계입니다.
  • Value Table만 있다고 입력 검증이 자동 완성되는 것은 아닙니다.
  • Foreign Key는 Check Table과 필드 매핑까지 맞아야 의미가 있습니다.
  • 입력 도움말 문제를 볼 때는 Value Table, Foreign Key, Search Help 연결을 함께 확인합니다.
