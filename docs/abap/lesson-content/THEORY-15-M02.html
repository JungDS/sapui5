학습 목표

Container 안에 담길 진짜 표 객체, CL_GUI_ALV_GRID를 만드는 법을 배웁니다. 표 객체가 어느 그릇에 담길지 알려주는 Parent Container의 의미를 익힙니다.

1. 지난 시간 연결: 액자 틀에 그림 넣기 🖼️

앞 Lesson에서 그릇(Container)을 만들어 화면 자리에 연결했습니다. 이제 그 안에 들어갈 표 객체를 만듭니다. 이것이 CL_GUI_ALV_GRID입니다. 우리가 흔히 말하는 "Grid ALV"의 실체죠.

2. Grid 객체를 만들며 그릇을 지정 ✍️

DATA: go_container TYPE REF TO cl_gui_custom_container,
      go_grid      TYPE REF TO cl_gui_alv_grid.

IF go_container IS INITIAL.
  CREATE OBJECT go_container
    EXPORTING container_name = 'CC_ALV'.

  CREATE OBJECT go_grid
    EXPORTING i_parent = go_container.   "이 표는 'go_container' 안에 담긴다

ENDIF.
  • i_parent = go_container: "이 표를 어느 그릇에 담을지" 지정합니다. 앞에서 만든 Container를 넘깁니다.
  • go_grid: 표 객체를 가리키는 손잡이. 앞으로 데이터를 표시·갱신할 때 이 손잡이를 씁니다.
🔗

3단 연결을 기억하세요

화면 Custom Control(빈 자리) → Container(그릇) → ALV Grid(표). 이 셋이 부모-자식으로 이어져야 화면에 표가 뜹니다.

3. 아직 표는 비어 있다 🫥

여기까지 했다고 표가 보이지는 않습니다. 표 객체라는 틀만 만들었을 뿐, "무슨 데이터를, 어떤 컬럼으로 보여줄지"는 아직 안 정했습니다. 그건 다음 Lesson들에서 차례로 준비합니다.

  • 출력할 Internal Table (M03)
  • 컬럼 설명서 Field Catalog (M04)
  • 표 외형 Layout (M05)
  • 그리고 표시 명령 SET_TABLE_FOR_FIRST_DISPLAY (M07)

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: Container 생성 → 그 직후 Grid 생성(i_parent 지정) → 표 틀 준비 완료.
  • ❌ 오류 1: Container 없이 Grid만 생성하거나, i_parent를 빠뜨림 → 표가 붙을 자리가 없어 오류.
  • ❌ 오류 2: Grid를 PBO마다 새로 생성 → 표가 중복 생성되어 깨짐. Container와 함께 처음 한 번만.

5. 실무에서 조심할 점 🚨

⚠️

Container와 Grid는 한 세트로 관리

Container와 Grid는 부모-자식 관계라, 생성·소멸을 함께 관리하는 것이 안전합니다. 둘 다 전역 참조로 들고, 처음 한 번만 같이 만든 뒤 화면이 닫힐 때 정리합니다. 참고로 요즘 신규 개발은 이런 GUI 객체 제어 대신 SALV(THEORY-08)나 Fiori를 쓰는 추세지만, Grid ALV는 세밀한 제어가 필요할 때와 기존 화면 유지보수에서 여전히 핵심입니다.

6. 한눈에 정리 🏁

오늘의 핵심만 딱 잡기

  • CL_GUI_ALV_GRID가 화면에 뜨는 표(Grid ALV)의 실체입니다.
  • 생성 시 i_parent로 담길 Container를 지정합니다.
  • 연결 구조: Custom Control → Container → ALV Grid.
  • 객체는 Container와 함께 처음 한 번만 생성·전역 관리합니다.
