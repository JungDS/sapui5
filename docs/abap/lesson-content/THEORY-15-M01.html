학습 목표

화면 안에 표(ALV)를 띄우기 위한 첫 단추, CL_GUI_CUSTOM_CONTAINER 객체를 만드는 법을 배웁니다. 화면의 Custom Control 자리와 코드의 Container Name이 어떻게 연결되는지 익힙니다.

1. 지난 시간 연결: 빈 자리에 표를 걸 차례 🖼️

앞 Chapter(THEORY-14)에서 화면에 Custom Control이라는 "빈 자리(액자 걸이 못)"를 만들 수 있다고 했습니다. 이제 그 자리에 진짜 표를 거는 작업을 시작합니다.

표를 걸려면 먼저 그 빈 자리에 대응하는 그릇(Container) 객체가 필요합니다. 가장 많이 쓰는 그릇이 CL_GUI_CUSTOM_CONTAINER입니다.

2. Container를 만들어 화면과 연결 ✍️

DATA: go_container TYPE REF TO cl_gui_custom_container.

" 화면(0100)의 PBO에서, 처음 한 번만
IF go_container IS INITIAL.
  CREATE OBJECT go_container
    EXPORTING container_name = 'CC_ALV'.   "화면에 그린 Custom Control 이름
ENDIF.
  • container_name: Screen Painter에서 Custom Control에 준 이름과 정확히 같아야 합니다(예: CC_ALV).
  • 참조 변수: go_container는 이 그릇을 가리키는 손잡이입니다. 이후 ALV를 담을 때 이 손잡이를 넘깁니다.
💡

비유: 못과 액자 틀

화면의 Custom Control이 "벽에 박은 못"이라면, CL_GUI_CUSTOM_CONTAINER는 그 못에 거는 "액자 틀"이에요. 틀까지 만들어야 그 안에 그림(ALV)을 넣을 수 있습니다.

3. 왜 "처음 한 번만" 만들까? 🔁

PBO는 화면이 갱신될 때마다 실행됩니다(THEORY-14-M04). 그런데 Container 같은 GUI 객체를 PBO마다 새로 만들면, 같은 못에 액자 틀을 자꾸 겹쳐 거는 셈이 되어 화면이 깨지거나 깜빡입니다.

  • ✅ 정상: IS INITIAL로 "아직 안 만들었나?" 확인 → 처음 한 번만 생성.
  • ❌ 오류: 매번 CREATE OBJECT → 객체 중복·메모리 낭비·화면 깜빡임.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 화면 Custom Control 이름 = 코드 container_name → 그릇이 그 자리에 정확히 자리잡음.
  • ❌ 이름 불일치: 화면에 CC_ALV인데 코드에 CONT라고 쓰면, 그릇이 붙을 자리를 못 찾아 오류가 납니다.

5. 실무에서 조심할 점 🚨

⚠️

객체는 전역 변수로 들고 재사용하세요

go_container 같은 GUI 객체 참조는 보통 프로그램 전역(또는 클래스 속성)으로 선언해, 화면이 살아있는 동안 계속 들고 있어야 합니다. 지역 변수로 만들면 PBO가 끝날 때 사라져 매번 다시 만들게 됩니다. "한 번 만들어 오래 들고 간다"가 GUI 객체의 기본 수명 관리입니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • CL_GUI_CUSTOM_CONTAINER는 화면 Custom Control 자리에 대응하는 그릇 객체입니다.
  • container_name은 화면의 Custom Control 이름과 정확히 일치해야 합니다.
  • PBO에서 IS INITIAL로 처음 한 번만 생성합니다.
  • 객체 참조는 전역으로 들고 재사용합니다.
