학습 목표

이번 Lesson에서는 값에 따라 실행 흐름을 갈라 주는 조건 분기를 배웁니다. 참/거짓으로 나누는 IF(와 ELSEIF·ELSE), 그리고 하나의 값을 여러 후보와 비교하는 CASE(와 WHEN)를 언제 어떻게 쓰는지 구분합니다.

1. 지난 Lesson 연결: 출력 전에 “언제 무엇을”을 정하자

지금까지 값을 선언하고(DATA) 출력하는(WRITE) 법을 배웠습니다. 하지만 실제 업무는 “항상 같은 동작”이 아닙니다. 재고가 부족하면 경고를, 충분하면 처리 완료를 보여 줘야 합니다. 이렇게 상황에 따라 다른 길로 흐르게 하는 것이 조건 분기입니다.

핵심 질문: “이건 참/거짓 조건으로 나뉘는가, 아니면 하나의 값이 여러 후보 중 하나인가?” — 답에 따라 IF와 CASE를 고릅니다.

2. IF: 조건이 참일 때만 실행한다

IF는 조건이 참일 때 블록을 실행합니다. 추가 조건은 ELSEIF, 나머지 경우는 ELSE로 처리하고 ENDIF로 닫습니다.

DATA lv_stock TYPE i VALUE 0.

IF lv_stock > 10.
  WRITE / '재고 충분'.
ELSEIF lv_stock > 0.
  WRITE / '재고 적음'.
ELSE.
  WRITE / '품절'.
ENDIF.
💡

위에서 아래로, 처음 참인 가지 하나만

IF/ELSEIF는 위에서부터 검사해 가장 먼저 참이 된 가지 하나만 실행하고 나머지는 건너뜁니다. 그래서 조건의 “순서”가 결과를 바꿉니다. 좁은 조건을 위로, 넓은 조건을 아래로 두는 감각이 필요합니다.

3. 비교·논리 연산자 빠르게 보기

조건에 자주 쓰는 연산자

구분연산자의미
비교= / <>같다 / 다르다
비교> < >= <=크다·작다 계열
논리AND / OR / NOT그리고 / 또는 / 부정
특수IS INITIAL값이 비어 있는지(초기값)
특수BETWEEN a AND b범위 안에 있는지

IS INITIAL은 “값이 채워졌는지” 확인할 때 자주 씁니다. 숫자 0, 빈 문자열 등은 초기값으로 간주됩니다.

빈 값 확인은 왜 = '' 대신 IS INITIAL일까?

문자 타입에서 lv_str = ''(완전한 빈 문자열)와 공백 한 칸 ' '은 다르게 취급될 수 있어, 비어 있는지 검사가 새는 경우가 있습니다. IF lv_str IS INITIAL.은 타입별 초기값(문자=공백, 숫자=0 등)을 일관되게 판정하므로 “비었는지” 확인에는 IS INITIAL이 안전합니다.

4. CASE: 하나의 값을 여러 후보와 맞춘다

어떤 값 하나를 여러 후보와 “같은가?”로 비교할 때는 CASE가 더 읽기 좋습니다. 각 후보는 WHEN, 어디에도 안 맞으면 WHEN OTHERS, 끝은 ENDCASE입니다.

REPORT zcase_demo.

DATA lv_grade TYPE c LENGTH 1 VALUE 'B'.

CASE lv_grade.
  WHEN 'A'.
    WRITE / '우수'.
  WHEN 'B'.
    WRITE / '양호'.
  WHEN 'C'.
    WRITE / '보통'.
  WHEN OTHERS.
    WRITE / '미분류'.
ENDCASE.

IF로 쓸까, CASE로 쓸까

범위·복합 조건stock > 10, a AND b
여러 변수 비교서로 다른 항목을 함께 판단
결론크기·범위·논리는 IF
한 값의 동등 비교grade = 'A' / 'B' / 'C'
후보가 여러 개값 목록이 길어질수록 유리
결론한 값의 여러 후보는 CASE

규칙: 크기·범위·복합 조건은 IF, 한 값의 동등 비교 여러 개는 CASE. CASE가 더 짧고 읽기 좋습니다.

Modern ABAP: 한 줄로 값을 고르는 COND / SWITCH

ABAP 7.40부터는 분기 결과를 변수에 담을 때 IF/CASE를 여러 줄로 쓰는 대신 생성자 표현식으로 한 줄에 처리할 수 있습니다. IF형은 COND #( WHEN ... THEN ... ELSE ... ), CASE형은 SWITCH #( var WHEN ... THEN ... )입니다. 지금은 흐름 제어 기본기를 위해 IF/CASE를 먼저 익히고, 이런 최신 축약형이 있다는 정도만 기억하세요.

5. 정상 흐름과 오류 흐름을 함께 보기

조건 분기에서 자주 하는 실수

❌ 자주 하는 실수
  • ENDIF/ENDCASE를 빠뜨려 활성화 실패.
  • WHEN OTHERS가 없어 예외 값이 조용히 무시됨.
  • 넓은 조건을 위에 둬서 좁은 가지가 영원히 실행 안 됨.
✅ 안전한 작성
  • 블록을 열면 닫는 키워드를 먼저 적어 둔다.
  • WHEN OTHERS로 “그 외” 경우를 항상 처리.
  • 좁고 구체적인 조건을 위로 배치.

분기 버그의 상당수는 “닫는 키워드 누락”과 “그 외 경우 미처리”에서 나옵니다.

6. 미니 실습: 재고 상태 판정기 만들기

✍️

실습 과제

  1. 재고 수량 변수를 선언합니다.
  2. IF/ELSEIF/ELSE로 “충분/적음/품절”을 출력합니다.
  3. 등급 문자(A/B/C) 변수를 만들고 CASE/WHEN/WHEN OTHERS로 등급명을 출력합니다.
  4. 일부러 ENDIF를 빼고 활성화해 어떤 오류가 나는지 적습니다. (오류 케이스)
  5. 고친 뒤 값을 바꿔 가며 각 가지가 실행되는지 확인합니다. (정상 결과)

완료 조건: 같은 문제를 IF와 CASE 중 무엇으로 푸는 게 좋은지 이유와 함께 고를 수 있으면 성공입니다.

버튼을 누르면 IF 평가 순서와 CASE 선택 결과가 출력 리스트처럼 표시됩니다.
한 가지만 비교하는데 IF를 길게 늘어놓아도 되나?

동작은 합니다. 다만 같은 값에 대한 동등 비교(grade = 'A', = 'B' …)가 3개 이상 이어지면 CASE가 훨씬 읽기 좋고 실수도 줄어듭니다. “돌아가는 코드”와 “읽기 좋은 코드”는 다릅니다.

7. 실무에서 조심해야 할 점

🚨

“그 외 경우”를 비워 두지 마세요

예상 못한 값이 들어오는 일은 실무에서 흔합니다. ELSE나 WHEN OTHERS로 “그 외” 경로를 항상 처리해 두면, 조용한 무시 대신 명확한 메시지로 문제를 빨리 발견할 수 있습니다.

  • 조건 순서: 좁은(구체적) 조건을 위로, 넓은 조건을 아래로 둡니다.
  • 표준 vs 커스텀: IF/CASE 동작은 SAP 표준입니다. 업무 판정 규칙(임계값 등)은 회사 정책이므로 분리해 기록합니다.
  • 과확장 금지: 반복(DO/WHILE)과 결합한 복잡한 흐름은 다음 Lesson에서 다룹니다.

9. 확인 퀴즈

  1. IF/ELSEIF에서 여러 조건이 동시에 참이면 어떤 가지가 실행되나요?
  2. 한 변수의 값을 여러 후보와 동등 비교할 때 더 적합한 문장은?
  3. CASE에서 어떤 후보에도 안 맞는 값을 처리하는 키워드는?
  4. 값이 비어 있는지(초기값) 확인하는 표현은?
정답/해설 보기
  1. 위에서부터 가장 먼저 참이 된 가지 하나만 실행됩니다.
  2. CASE입니다. 동등 비교 후보가 많을수록 읽기 좋습니다.
  3. WHEN OTHERS입니다.
  4. IS INITIAL입니다.

그 외 처리ELSE / WHEN OTHERS로 예외 값을 꼭 처리합니다.
