지난 Lesson에서 값을 화면에 출력했습니다. 이번에는 값에 따라 다른 흐름을 선택하는 IF, ELSEIF, CASE, WHEN을 배웁니다. 조건 분기를 처음 보는 사람도 “프로그램의 갈림길”로 이해할 수 있게 정리합니다.

1. 지난 시간 연결: 출력은 같아도 상황은 다르다 🚦

이전 Lesson에서는 WRITE로 값을 그대로 출력했습니다. 하지만 실제 프로그램은 항상 같은 문장만 출력하지 않습니다. 점수가 90점 이상이면 “A”, 80점 이상이면 “B”, 그 외에는 “다시 도전”처럼 상황에 따라 다른 결과를 보여줘야 합니다.

이런 갈림길을 만드는 문법이 조건 분기입니다. ABAP에서는 대표적으로 IF와 CASE를 사용합니다.

조건 분기는 프로그램에게 “이럴 땐 이 길로, 저럴 땐 저 길로 가자”라고 알려주는 표지판입니다.

2. IF: 조건을 위에서부터 검사하기 🧭

IF는 조건이 참인지 확인한 뒤, 참이면 해당 블록을 실행합니다. 여러 조건을 차례대로 검사할 때 ELSEIF를 사용하고, 아무 조건도 맞지 않을 때 ELSE를 사용합니다.

REPORT zif_basic.

DATA gv_score TYPE i VALUE 85.

IF gv_score >= 90.
  WRITE 'A 등급'.
ELSEIF gv_score >= 80.
  WRITE 'B 등급'.
ELSE.
  WRITE '다시 도전'.
ENDIF.

ABAP에서는 조건 비교에 =, <>, >=, <= 같은 연산자를 사용합니다. 다른 언어처럼 ==를 쓰지 않는다는 점도 기억해두세요.

3. CASE와 WHEN: 하나의 값으로 갈래 나누기 🗂️

CASE는 하나의 값을 기준으로 여러 경우를 나눌 때 읽기 좋습니다. 각 경우는 WHEN으로 작성합니다.

REPORT zcase_basic.

DATA gv_grade TYPE c LENGTH 1 VALUE 'B'.

CASE gv_grade.
  WHEN 'A'.
    WRITE '아주 좋아요'.
  WHEN 'B'.
    WRITE '좋아요'.
  WHEN OTHERS.
    WRITE '확인이 필요해요'.
ENDCASE.

IF가 다양한 조건식을 자유롭게 쓸 수 있는 갈림길이라면, CASE는 “이 값이 A냐, B냐, C냐”처럼 한 기준값을 여러 후보와 비교할 때 깔끔합니다.

4. IF와 CASE를 언제 고를까? 🤔

  • IF가 편한 경우: 점수 범위, 날짜 비교, 여러 조건 조합처럼 조건식이 다양할 때 좋습니다.
  • CASE가 편한 경우: 상태 코드, 등급, 메뉴 선택처럼 하나의 값이 어떤 후보인지 비교할 때 좋습니다.
  • 둘 다 가능한 경우: 팀에서 읽기 쉬운 쪽, 유지보수하기 쉬운 쪽을 선택합니다.
💡

초심자 선택 기준

“조건이 문장처럼 다양하다”면 IF, “하나의 코드값을 여러 후보와 비교한다”면 CASE로 시작해보세요. 정답 하나를 외우기보다 읽기 쉬운 흐름을 고르는 감각이 중요합니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: gv_score = 85이면 첫 조건 >= 90은 실패하고, 다음 조건 >= 80이 성공해 B 등급이 출력됩니다.
  • ❌ ENDIF 누락: IF를 열고 ENDIF.로 닫지 않으면 문법 오류가 납니다.
  • ❌ ENDCASE 누락: CASE도 ENDCASE.로 닫아야 합니다.
  • ❌ 조건 순서 실수: gv_score >= 80을 먼저 쓰고 그 아래에 gv_score >= 90을 쓰면, 95점도 80점 조건에서 먼저 잡혀버립니다.

미니 실습으로 점수 값을 95, 85, 70으로 바꿔 실행해보세요. 어떤 조건이 잡히는지 Output List로 확인하면 조건 순서가 훨씬 잘 보입니다.

조건이 길어지고 중첩이 깊어지면 “왜 이 조건이 먼저인지”를 나중에 알기 어려워집니다. 단순히 실행되는 코드보다, 조건 순서와 예외 케이스가 읽히는지 확인하세요. 권한, 상태값, 오류 처리처럼 중요한 판단은 특히 주석이나 구조로 의도를 남기는 것이 좋습니다.

7. 미니 실습: IF와 CASE 선택 이유 적기 🧪

이번 실습은 조건문을 “작동만 하게” 쓰는 것이 아니라, 왜 IF 또는 CASE를 골랐는지 설명하는 연습입니다.

✍️

실습 과제

  1. 점수 95, 85, 70을 넣어 IF 예제를 세 번 실행한다고 가정하고 결과를 적습니다.
  2. 등급 코드 A, B, X를 넣어 CASE 예제 결과를 적습니다.
  3. 점수 범위 판단에는 IF가 더 자연스러운 이유를 한 줄로 적습니다.
  4. 등급 코드 판단에는 CASE가 더 읽기 좋은 이유를 한 줄로 적습니다.

완료 조건: 같은 조건 분기라도 범위 비교는 IF, 단일 코드 비교는 CASE가 읽기 좋다는 차이를 설명할 수 있으면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. IF를 열었으면 어떤 키워드로 닫아야 하나요?
  2. 점수 범위처럼 >=, <, 여러 조건 조합이 필요한 경우 IF와 CASE 중 무엇이 더 자연스러울까요?
  3. gv_score >= 80을 gv_score >= 90보다 먼저 쓰면 95점은 어떤 조건에서 잡힐까요?
정답/해설 보기
  1. ENDIF.로 닫습니다. CASE는 ENDCASE.로 닫습니다.
  2. IF가 더 자연스럽습니다. CASE는 하나의 기준값을 여러 후보와 비교할 때 읽기 좋습니다.
  3. 80점 조건에서 먼저 잡힙니다. 조건문은 위에서 아래로 검사하므로 더 구체적인 조건을 먼저 두는 것이 보통 안전합니다.

10. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • IF는 조건이 참이면 해당 블록을 실행하는 갈림길입니다.
  • ELSEIF는 다음 조건을 이어서 검사할 때 사용합니다.
  • CASE / WHEN은 하나의 값이 어떤 후보인지 나눌 때 읽기 좋습니다.
  • IF는 ENDIF., CASE는 ENDCASE.로 닫습니다.
  • 조건 순서가 결과를 바꿀 수 있으므로 큰 범위와 작은 범위의 위치를 조심합니다.
