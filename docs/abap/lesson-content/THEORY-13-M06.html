학습 목표

조회·가공이 끝난 결과를 화면으로 내보내는 END-OF-SELECTION 단계를 배웁니다. 조회와 출력 단계를 나누는 이유와 실전 패턴을 익힙니다.

1. 지난 시간 연결: 만든 요리를 접시에 담기 🍽️

앞 Lesson의 START-OF-SELECTION에서 데이터를 조회하고 내부 테이블에 담았습니다. 이제 그 결과를 사용자가 볼 수 있게 화면에 내보내야 합니다.

이 마지막 출력 단계가 END-OF-SELECTION입니다. START-OF-SELECTION이 모두 끝난 뒤 자동으로 실행됩니다. 데이터가 완성된 시점이라 출력에 딱 좋은 타이밍이죠.

  IF gt_result IS INITIAL.
    MESSAGE '조회된 데이터가 없습니다.' TYPE 'S'.

  " 담아둔 결과를 ALV 등으로 출력

  cl_salv_table=>factory(
    IMPORTING r_salv_table = DATA(lo_alv)
    CHANGING  t_table      = gt_result ).
  lo_alv->display( ).
  • 빈 결과 처리: 데이터가 0건이면 안내 메시지를 띄웁니다(사용자 배려).
  • 출력: 결과 테이블을 SALV나 WRITE 등으로 화면에 보여줍니다(THEORY-08에서 배운 SALV).

3. 왜 조회와 출력을 나눌까? 🧩

  • ✅ 유지보수: "출력을 ALV에서 다른 방식으로 바꾸자"가 되어도 조회 코드는 그대로 둡니다.
  • ✅ 가독성: "데이터 만들기(START)"와 "보여주기(END)"가 분리돼 흐름이 한눈에 들어옵니다.
  • ✅ 재사용: 조회 로직을 다른 화면이나 백그라운드 작업에서 재사용하기 쉬워집니다.
💡

현대적 관점

요즘은 조회 로직을 클래스/메서드로 빼고(THEORY-18 OO), 화면은 ALV·Fiori가 담당하도록 더 잘게 나눕니다. 하지만 그 출발점은 바로 이 "조회 단계와 출력 단계를 나눈다"는 감각입니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: 결과가 있으면 출력, 없으면 안내 메시지 후 종료.
  • ❌ 오류 1: 빈 결과를 확인하지 않고 출력 → 빈 화면만 떠 사용자가 "오류인가?" 오해.
  • ❌ 오류 2: END-OF-SELECTION에서 또 조회를 함 → 흐름이 꼬이고 성능 저하. 출력에 집중합니다.

5. 실무에서 조심할 점 🚨

⚠️

"데이터 없음"도 정상 결과입니다

조회 결과가 0건인 것은 오류가 아니라 정상적인 경우일 수 있습니다. 그런데 안내 없이 빈 화면만 뜨면 사용자는 프로그램이 고장났다고 생각합니다. 항상 빈 결과를 점검해 친절히 안내하세요. 작은 배려가 사용 경험을 크게 바꿉니다.

6. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • END-OF-SELECTION은 조회·가공이 끝난 결과를 화면에 출력하는 단계입니다.
  • 빈 결과를 점검해 "데이터 없음"을 친절히 안내합니다.
  • 조회(START)와 출력(END)을 나누면 유지보수·가독성·재사용에 유리합니다.
  • 여기서는 출력에 집중하고, 추가 조회는 하지 않습니다.
