학습 목표

테이블 하나에서 필요한 칸만 골라 보여주는 Projection View를 배웁니다. 왜 굳이 일부 필드만 따로 보여주는지(필드 제한), 그리고 그 한계가 무엇인지 익힙니다.

1. 지난 시간 연결: 합치기 말고 "솎아내기" ✂️

앞 Lesson의 Database View는 여러 테이블을 합치는 데 초점이 있었습니다. 그런데 반대 상황도 있습니다. 테이블은 하나인데, 필드가 너무 많아서 그 중 몇 개만 깔끔하게 보여주고 싶은 경우죠.

예를 들어 자재 마스터 테이블에는 필드가 수백 개인데, 어떤 화면에서는 자재번호·자재명·단위 3개만 필요할 수 있습니다. 이때 쓰는 것이 Projection View입니다.

2. Projection View는 "한 테이블의 일부 칸만" 🪟

Projection View는 딱 한 개의 테이블을 바탕으로, 그 중 필요한 일부 필드만 골라 보여주는 View입니다. JOIN은 하지 않습니다.

💡

일상 비유: 명함에서 보여줄 정보만 추리기

개인정보가 잔뜩 든 신상카드(원본 테이블)에서, 외부에 보여줄 명함에는 이름·부서·전화번호만 추려 담는 것과 같아요. 원본은 그대로 두고, 보이는 창만 좁히는 거예요.

3. 왜 일부만 보여줄까? 🤔

  • ✅ 단순함: 수백 개 필드 대신 꼭 필요한 칸만 노출해 프로그램이 깔끔해집니다.
  • ✅ 의미 부여: "이 용도에는 이 필드들만 쓴다"는 약속을 View 이름으로 표현할 수 있습니다.
  • ✅ 변화 흡수: 원본 테이블에 필드가 늘어도, 이 View를 쓰는 코드는 영향을 덜 받습니다.

4. Projection View의 필드 솎아내기 시각화 🗺️

원본 테이블 `ZEMPLOYEE`(수많은 기술/관리용 필드가 섞여 있음)에서 사용자가 명함용 필수 필드(사원번호, 이름, 전화번호)만 솎아내어 Projection View `ZV_EMP_MINI`를 구성하는 구조를 시각화해 보겠습니다.

민감한 급여 정보나 불필요한 시스템 관리 필드는 감추고, 필요한 필드만 콤팩트하게 노출합니다.

Database View와 달리 Projection View는 물리 데이터베이스 레벨에 View 객체를 생성하지 않고, ABAP 런타임 단계에서 SQL을 변환하여 데이터를 걸러내 줍니다.

5. 한계와 독특한 기능 분명히 알기 🔍

  • ❌ JOIN 완전 불가: 오직 단 하나의 기본 테이블만 바라볼 수 있습니다. 여러 테이블을 엮어 필드를 구성하려면 Database View를 사용해야 합니다.
  • ❌ 가공/계산 필드 추가 불가: 필드 순서를 바꾸거나 솎아내는 것 외에, 필드 값을 연산(예: 연봉 * 1.1)하거나 가공하여 새로운 가상 필드를 만들 수 없습니다.
  • ✅ 수정 및 쓰기 지원 (Write-Enabled): 데이터베이스 뷰와 다르게, Projection View는 **데이터 삽입(INSERT) 및 변경(UPDATE/DELETE)이 가능**합니다! 단, 뷰에 기본 테이블의 **모든 Key 필드가 반드시 포함**되어 있어야만 데이터 쓰기 규칙을 충족합니다.

6. 실무에서 조심할 점 🚨

⚠️

모든 Key 필드가 포함되지 않으면 쓰기 런타임 에러가 발생합니다

Projection View를 통해 데이터를 업데이트할 때, 기본 테이블의 Key 필드가 하나라도 뷰에서 빠져 있다면 런타임에 어떤 레코드를 갱신해야 할지 식별할 수 없어 오류가 발생합니다. 데이터를 직접 수정할 목적의 Projection View라면 반드시 Key 필드 구성을 꼼꼼하게 설계 단계에서 확보해야 합니다.

7. 미니 실습: Projection View 조회 및 데이터 쓰기 🧪

✍️

실습 과제

  1. 표준 테이블 `SPFLI`(항공편)를 솎아내어 만든 표준 Projection View SPFLIP의 구조를 ADT 사전에서 확인해 봅니다.
  2. Projection View SPFLIP에서 제공하는 필드 목록이 원본 테이블 `SPFLI`에 비해 어떻게 단순화되었는지 비교합니다.
  3. 기본 키인 CARRID와 CONNID가 포함된 가상의 사원 Projection View에 INSERT 구문을 작성해 보며, 뷰를 통해서도 원본 테이블로 데이터 쓰기가 직접 전송되는 원리를 이해합니다.

완료 조건: Projection View의 쓰기 가능 조건(모든 Key 필드 포함)을 파악하고 조회 코드를 정상 구현하면 성공입니다.

8. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: Write Access to Projection Views - 뷰를 통해 기본 테이블에 값을 기록할 때 충족해야 하는 키 설계 규칙을 학습합니다.
  • SAP Help Portal: SELECT from View - Projection View를 조회(Read)하는 쿼리 문법의 표준 사양을 확인합니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. Database View와 달리, Projection View를 사용할 때 데이터를 직접 수정(INSERT/UPDATE)하는 것이 가능한가요?
  2. Projection View에서 2개 이상의 테이블을 결합(JOIN)하여 뷰를 생성할 수 있나요?
  3. Projection View를 통해 기본 테이블에 데이터를 쓰기(Write)할 때 뷰에 반드시 포함되어 있어야 하는 필드 군은 무엇인가요?
정답/해설 보기
  1. 네, 가능합니다. Database View는 조회(Read-Only)만 되지만, Projection View는 쓰기 및 갱신 처리가 지원됩니다.
  2. 아니요. 불가능합니다. Projection View는 단일 테이블(Single Table)의 필드 수직 제한만 지원하므로 JOIN 기능을 쓸 수 없습니다.
  3. 기본 테이블의 모든 Key 필드가 반드시 포함되어 있어야 합니다. Key 필드가 누락되면 데이터의 식별이 불가능하여 수정 작업 수행 시 오류가 납니다.

10. 한눈에 정리 🏁

📝

Projection View 핵심 요약

  • Projection View는 단일 테이블의 필요한 필드들만 수직으로 솎아내어 심플하게 관리하는 DDIC 구조입니다.
  • 복수 테이블 JOIN이나 필드 값의 연산/가공은 지원되지 않습니다.
  • 쓰기 작업(CUD)을 완벽히 지원하지만, 기본 테이블의 모든 Key 필드를 포함해야만 런타임 에러가 나지 않습니다.
  • 현대적인 SAP Cloud 환경에서는 CDS View 등을 통해 필드를 솎아내어 API로 제공하는 아키텍처가 중심이 되고 있습니다.
