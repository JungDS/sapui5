학습 목표

지난 Lesson에서 SELECT SINGLE로 한 줄을 조회했습니다. 이번에는 여러 줄 Result Set을 INTO TABLE로 Internal Table에 적재하는 흐름을 배웁니다.

1. 목록 조회는 Internal Table로 받는다 🧭

SELECT SINGLE은 한 줄 조회에 적합합니다. 하지만 Report 화면이나 SALV에 표시할 데이터는 보통 여러 줄입니다. 데이터베이스에서 여러 줄을 가져오면 ABAP 프로그램 안에서는 Internal Table에 담아 다룹니다.

이때 사용하는 문법이 INTO TABLE입니다. 데이터베이스의 조회 결과 묶음, 즉 Result Set이 ABAP Internal Table로 들어옵니다.

INTO TABLE은 데이터베이스 조회 결과 여러 줄을 ABAP Internal Table로 옮기는 통로입니다.

2. INTO TABLE 기본 구조 📥

ABAP
1
2
3
4 
SELECT FROM t005t
  FIELDS land1, landx
  WHERE spras = @sy-langu
  INTO TABLE @DATA(lt_countries).

lt_countries는 조회된 여러 줄을 담는 Internal Table입니다. 조회 결과가 0건이면 빈 Internal Table이 되고, 여러 건이면 그만큼 줄이 들어갑니다.

  • Result Set: 데이터베이스가 SELECT에 대해 돌려준 결과 묶음입니다.
  • INTO TABLE: 그 결과 묶음을 Internal Table에 담습니다.
  • @DATA(lt_countries): 결과를 받을 Internal Table을 inline 선언합니다.

한 줄 그릇 vs 여러 줄 그릇 — INTO와 INTO TABLE

INTO @ls_country (Structure)
그릇한 줄짜리 구조(Work Area)
어울림SELECT SINGLE 단건 조회
여러 건 결과담을 수 없음
INTO TABLE @lt_countries (Internal Table)
그릇여러 줄을 담는 Internal Table
어울림목록 조회 (Result Set 전체)
여러 건 결과한 번에 적재

결과가 몇 줄인지에 따라 그릇이 달라집니다. 단건은 INTO + 구조, 목록은 INTO TABLE + Internal Table — 이 짝을 바꿔 끼우면 문법 오류이거나 의도와 다른 동작이 됩니다.

3. 조회 후 건수 확인하기 🔢

ABAP
1
2 
DATA(lv_count) = lines( lt_countries ).
WRITE: / '조회 건수:', lv_count.

Open SQL 조회 후에는 “몇 건이 들어왔는지”를 먼저 확인하는 습관이 좋습니다. 특히 SALV로 바로 넘기기 전에 건수를 확인하면 빈 결과와 대량 결과를 구분할 수 있습니다.

💡

건수는 첫 번째 진단 신호

0건이면 조건이 너무 좁거나 데이터가 없을 수 있고, 너무 많으면 조건이 너무 넓을 수 있습니다. 건수는 조회 로직을 점검하는 첫 단서입니다.

REPORT zsql_into_table.

DATA: lo_alv TYPE REF TO cl_salv_table,
      lx_msg TYPE REF TO cx_salv_msg.

SELECT FROM t005t
  FIELDS land1, landx
  WHERE spras = @sy-langu
  INTO TABLE @DATA(lt_countries).

IF lt_countries IS INITIAL.
  WRITE: / '조회 결과가 없습니다.'.
  RETURN.
ENDIF.

TRY.
    cl_salv_table=>factory(
      IMPORTING r_salv_table = lo_alv
      CHANGING  t_table      = lt_countries ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO lx_msg.
    MESSAGE lx_msg->get_text( ) TYPE 'E'.
ENDTRY.

이 예제는 Open SQL 조회 결과를 Internal Table에 담고, 그 Internal Table을 SALV로 표시합니다. Chapter 8과 Open SQL이 연결되는 지점입니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: SELECT 결과 여러 줄이 Internal Table에 담기고, LOOP나 SALV로 표시할 수 있습니다.
  • ✅ 빈 결과: 조건에 맞는 데이터가 없으면 Internal Table이 비어 있습니다. 사용자 안내가 필요합니다.
  • ❌ 대량 결과: 조건이 너무 넓으면 많은 줄이 메모리에 올라와 성능 문제가 될 수 있습니다.
  • ❌ 타입 불일치: 명시적 Target Table을 쓸 때 FIELDS와 Target 구조가 맞지 않으면 오류가 날 수 있습니다.

미니 실습으로 조회 후 lines( lt_countries )를 출력해보세요. 조건을 바꿨을 때 건수가 어떻게 달라지는지 보는 것이 목표입니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

INTO TABLE은 메모리에 올리는 작업입니다

데이터베이스 결과를 Internal Table에 담는다는 것은 Application Server 메모리에 데이터를 올린다는 뜻입니다. 조건 없는 대량 조회는 데이터베이스와 애플리케이션 서버 모두에 부담이 될 수 있습니다.

운영 Report에서는 조회 조건, 최대 데이터 범위, 빈 결과 안내, 권한 확인을 함께 설계해야 합니다. 단순히 “표시된다”에서 멈추면 안 됩니다.

7. 미니 실습: 조회 → 건수 확인 → SALV 🧪

✍️

실습 과제

  1. 국가 텍스트를 INTO TABLE로 조회하고 lines( )로 건수를 출력합니다.
  2. 건수가 0이면 안내 메시지, 1건 이상이면 SALV로 표시하는 분기를 완성합니다.
  3. WHERE 조건을 좁혀(특정 국가) 건수가 달라지는 것을 확인합니다.
  4. INTO TABLE을 INTO로 잘못 바꿔보고 어떤 문법 메시지가 나는지 확인 후 복원합니다.

완료 조건: 조회 건수에 따라 다른 화면(메시지/SALV)이 나오는 작은 리포트가 완성되면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. 여러 건의 조회 결과를 받으려면 INTO와 INTO TABLE 중 무엇을 쓰나요?
  2. INTO TABLE 조회 직후 결과가 있는지 확인하는 두 가지 방법은 무엇인가요?
  3. “일단 조건 없이 다 가져와서 메모리에서 처리하자”가 위험한 이유는 무엇인가요?
정답/해설 보기
  1. INTO TABLE입니다. 대상이 Internal Table이어야 하며, 한 줄짜리 구조에는 여러 건을 담을 수 없습니다.
  2. sy-subrc 확인과 lines( itab ) 또는 IS INITIAL 검사입니다. 건수는 조회 로직 점검의 첫 단서입니다.
  3. 대량 데이터가 그대로 네트워크를 타고 와 Runtime Memory를 차지하기 때문입니다. 필터링은 가능한 한 DB(WHERE)에서 끝내야 합니다.

10. 한눈에 정리 🏁

📝

INTO TABLE 핵심

  • Result Set은 SELECT가 돌려준 조회 결과 묶음입니다.
  • INTO TABLE은 여러 줄 결과를 Internal Table에 담습니다.
  • 조회 후 건수를 확인하면 빈 결과와 대량 결과를 빨리 알아차릴 수 있습니다.
  • Internal Table에 담은 결과는 LOOP나 SALV로 처리할 수 있습니다.
  • 대량 조회는 메모리와 성능 관점에서 조심해야 합니다.
