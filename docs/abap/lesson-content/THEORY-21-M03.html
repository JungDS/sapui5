학습 목표

RAP의 화면용 소비층 Projection View(ZC_)를 설계하는 법을 배웁니다. Interface 위에 UI 주석을 입혀 Fiori 화면으로 이어지는 층을 익힙니다.

1. 지난 시간 연결: 기반 위에 "화면용 창" 🪟

앞에서 만든 ZI_Travel(데이터 기반)을 직접 화면에 노출하지 않습니다. 그 위에 화면/서비스용 투영인 Projection View(ZC_)를 둡니다. Chapter 20의 2계층 패턴을 RAP에서 그대로 씁니다.

  • as projection on: Interface View를 투영. 필요한 필드만 골라 노출.
  • 화면 관점: 사용자에게 보일 필드/이름을 여기서 결정(관리 필드 등은 숨김).
💡

ZI_는 안 바뀌고 ZC_만 화면별로

같은 ZI_Travel을 바탕으로, 관리자용 ZC_와 고객용 ZC_를 따로 만들 수 있어요. 데이터 기반(ZI_)은 공유하고 화면 창(ZC_)만 다르게 — 재사용과 유연성을 동시에 얻습니다.

3. UI 주석은 여기 또는 MDE에 🎨

화면 배치(@UI.lineItem 등)는 Projection View 또는 별도 MDE(Chapter 20의 Lesson 5)에 둡니다. 이 주석들이 Fiori Elements로 전달되어, 목록·폼 화면이 코드 거의 없이 생성됩니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: ZI_(기반) → ZC_(투영) → UI 주석 → Fiori 화면 자동화.
  • ❌ 오류 1: ZC_에 무거운 JOIN·계산을 또 넣음 → 계층 책임 붕괴. 데이터 로직은 ZI_에.
  • ❌ 오류 2: ZC_와 ZI_의 루트 지정(root)이 어긋나면 Behavior 연결이 꼬임.

5. 실무에서 조심할 점 🚨

⚠️

Projection은 "노출 통제"의 자리

Projection View는 "사용자에게 무엇을 보여줄지" 통제하는 곳입니다. 민감 필드(원가·내부 메모 등)를 실수로 노출하지 않도록 ZC_에서 필드를 의식적으로 골라야 합니다. ZI_에 다 있다고 ZC_에 그대로 올리지 말고, "이 화면에 정말 필요한가?"를 한 번 더 거르세요.

6. 미니 실습: 소비 화면에 맞게 Projection 줄이기 🧪

이번 실습은 ZC_ View를 “복사본”이 아니라 소비 목적에 맞춘 창으로 설계하는 연습입니다.

✍️

실습 과제

  1. 목록 화면, 상세 화면, API 소비자에게 필요한 필드를 각각 나눠봅니다.
  2. ZI_에는 있지만 ZC_에서 숨겨도 되는 기술 필드를 2개 가정합니다.
  3. UI Annotation을 ZC_ 본문에 둘지 Metadata Extension으로 뺄지 판단 기준을 적습니다.

완료 조건: Projection View가 소비 목적에 맞춰 필드와 메타데이터를 조정하는 계층임을 설명할 수 있으면 성공입니다.

7. 공식 문서로 더 확인하기 🔗

  • SAP Learning: RAP Architecture - BO Projection과 서비스 노출 흐름을 확인합니다.
  • SAP Help Portal: Metadata Extensions - UI 메타데이터를 분리하는 방식을 확인합니다.
  • SAP Help Portal: Projecting Managed BO - Managed BO를 non-draft 서비스로 노출할 때의 projection 흐름을 확인합니다.

8. 확인 퀴즈와 정답/해설 ✅

  1. Projection View에 무거운 JOIN과 계산을 계속 추가하면 어떤 계층 문제가 생기나요?
  2. ZC_ View가 소비자별로 달라질 수 있는 이유는 무엇인가요?
  3. UI Annotation을 Metadata Extension으로 분리하면 어떤 이점이 있나요?
정답/해설 보기
  1. Projection이 소비 계층이 아니라 또 다른 데이터 기반 계층처럼 변합니다. 재사용 로직은 ZI_/하위 계층에 두는 것이 좋습니다.
  2. 화면, API, 역할별로 필요한 필드와 메타데이터가 다르기 때문입니다.
  3. 데이터 모델과 화면 표시 메타데이터를 분리해 변경 영향을 줄일 수 있습니다.

9. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • RAP의 Projection View(ZC_)는 Interface 위의 화면/서비스용 소비층입니다.
  • as projection on으로 필요한 필드만 골라 노출합니다.
  • UI 주석(또는 MDE)이 Fiori 화면을 거의 자동 생성합니다.
  • 민감 필드 노출 통제를 ZC_에서 신경 씁니다.
