학습 목표

Chapter 10의 마무리입니다. SELECT-OPTIONS 화면이 아니라 코드에서 직접 APPEND Range를 만들어 Range Line을 추가하고, LOW/HIGH 값을 채우는 기초를 배웁니다.

1. 화면 입력 없이 조건표를 만들 수도 있다 🧭

지금까지는 사용자가 SELECT-OPTIONS 화면에서 조건을 입력한다고 생각했습니다. 하지만 프로그램 안에서 조건을 직접 만들어야 할 때도 있습니다.

예를 들어 기본 조회 대상 국가를 코드로 정하거나, 다른 로직에서 계산된 값들을 Range Table로 만들어 Open SQL에 넘길 수 있습니다.

Selection Table은 화면에서 만들어질 수도 있고, ABAP 코드로 직접 만들어질 수도 있습니다.

2. RANGE OF로 조건표 선언하기 📦

ABAP
1 
DATA r_land1 TYPE RANGE OF t005t-land1.

이 선언은 T005T-LAND1 타입에 맞는 Range Table을 만듭니다. 내부 행은 SIGN, OPTION, LOW, HIGH 구조를 가집니다.

이름은 예제상 r_land1로 두었습니다. 프로젝트에 따라 lr_, rt_, range_ 같은 접두어를 사용할 수 있습니다.

3. APPEND VALUE로 Range Line 추가하기 ✍️

ABAP
1
2
3 
APPEND VALUE #( sign = 'I' option = 'EQ' low = 'KR' ) TO r_land1.
APPEND VALUE #( sign = 'I' option = 'EQ' low = 'US' ) TO r_land1.
APPEND VALUE #( sign = 'I' option = 'BT' low = 'A' high = 'C' ) TO r_land1.

각 APPEND VALUE #( ... )는 Range Table에 조건 한 줄을 추가합니다. EQ는 HIGH가 필요 없고, BT는 LOW와 HIGH가 함께 필요합니다.

💡

Range Line 읽는 법

sign = 'I' option = 'BT' low = 'A' high = 'C'는 “A부터 C까지 포함”이라고 말로 읽으면 됩니다.

REPORT zrange_manual_basic.

DATA r_land1 TYPE RANGE OF t005t-land1.

APPEND VALUE #( sign = 'I' option = 'EQ' low = 'KR' ) TO r_land1.
APPEND VALUE #( sign = 'I' option = 'EQ' low = 'US' ) TO r_land1.

SELECT FROM t005t
  FIELDS land1, landx
  WHERE spras = @sy-langu
    AND land1 IN @r_land1
  INTO TABLE @DATA(lt_countries).

LOOP AT lt_countries INTO DATA(ls_country).
  WRITE: / ls_country-land1, ls_country-landx.
ENDLOOP.

5. 코드 조작과 Range Table 메모리 상태 시각화 🗺️

ABAP 프로그램에서 직접 RANGE OF를 선언하고 APPEND VALUE 명령을 통해 Range Table에 값을 채워 나갈 때, 프로그램 메모리 내부에서 어떤 변화가 일어나는지 정훈영 사원의 시나리오로 시각화해 보겠습니다.

r_empid (사원 Range Table) 메모리 로드 상태

1. ABAP 명령 수행 단계 
DATA r_empid TYPE RANGE OF zemployee-empid.

APPEND VALUE #( sign = 'I'
                option = 'EQ'
                low = 'E001' ) TO r_empid.

APPEND VALUE #( sign = 'I'
                option = 'EQ'
                low = 'E003' ) TO r_empid.
2. r_empid 내부 메모리 상태 (Internal Table)
SIGNOPTIONLOWHIGH비고
IEQE001 (정훈영)E001 포함
IEQE003 (아이유)E003 포함
데이터베이스 조회 쿼리 매핑SQL 실행 시 WHERE empid IN ('E001', 'E003') 연산과 동일하게 동작합니다.

직접 만든 Range Table도 결국 Standard Internal Table 구조이므로 LOOP AT이나 APPEND 등의 테이블 명령을 완벽히 지원합니다.

6. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 동일한 유형의 Range 선언: 비교할 DB 테이블의 실제 필드 타입을 참조하여 TYPE RANGE OF [테이블명-필드명]으로 정확히 대응하는 Range Table을 생성합니다.
  • ✅ 값의 명시적 선언: APPEND VALUE #( ... ) 구문을 통해 라인 구조를 명확히 선언하고 추가합니다.
  • ❌ 초기화(CLEAR) 누락: 여러 쿼리에 하나의 Range Table을 재사용할 때, 이전 조건들을 CLEAR하지 않고 APPEND하면 과거 조건들이 누적되어 엉뚱한 조회 결과를 유발합니다.
  • ❌ BT 옵션의 HIGH 값 공백: Between 연산자를 쓰면서 HIGH를 비워두면, 데이터가 정상적으로 필터링되지 않거나 원치 않는 조건 에러가 발생합니다.
  • ❌ 빈 Range Table 무검증: 아무 조건도 APPEND하지 않은 상태로 SQL을 날릴 경우, 무조건 전체 데이터를 조회하게 되어 대규모 테이블에서 성능 다운을 초래합니다.

7. 실무에서 조심해야 할 점 🚨

⚠️

직접 조작하는 Range Table은 사용하기 전 초기화 습관이 필수적입니다

실무 로직을 짜다 보면, 반복문 내부에서 특정 키로 Range Table을 계속 빌드해야 할 때가 많습니다. 이때 루프가 시작되는 시점에 CLEAR r_table 또는 FREE r_table을 선언해 주지 않으면, 이전 루프의 조건 데이터가 그대로 남아 있어 치명적인 정보 유출이나 데이터 연산 버그를 초래하게 됩니다.

8. 미니 실습: Range Table 직접 조작과 쿼리 테스트 🧪

✍️

실습 과제

  1. 예제 프로그램 zrange_manual_basic을 복사하여 zrange_manual_practice를 생성합니다.
  2. 국가 코드 Range Table r_land1에 US만 포함(Include)하고 KR은 제외(Exclude)하도록 APPEND VALUE 코드를 직접 수정해 봅니다.
  3. 결과 출력 루프 전에 CLEAR r_land1를 넣어보고 실행했을 때 전체 국가 데이터가 쏟아져 나오는 현상을 확인합니다.
  4. 동일한 유형의 Range Table을 2개 이상 만들어 각각의 조건이 AND 또는 OR 조건으로 SQL에 어떻게 엮이는지 연습 쿼리를 구성해 봅니다.

완료 조건: Range Table을 선언하고, 데이터를 직접 추가 및 조회하여 정상 필터링을 검증해 내면 성공입니다.

10. 확인 퀴즈와 정답/해설 ✅

  1. DATA r_empid TYPE RANGE OF zemployee-empid.로 선언된 Range Table은 실제로 어떤 구조를 갖게 되나요?
  2. 코드에서 Range Table을 빌드하여 SQL에 활용할 때, 루프 내에서 Range Table 데이터를 사용하기 직전에 반드시 수행해야 하는 안전 규칙은 무엇인가요?
  3. Range Table에 어떤 데이터도 들어있지 않은(Initial) 상태로 Open SQL WHERE field IN @r_table을 사용하면 조회 결과가 어떻게 되나요?
정답/해설 보기
  1. SIGN, OPTION, LOW, HIGH 필드를 컬럼으로 갖는 Standard Internal Table 구조를 가지게 됩니다.
  2. CLEAR r_empid 혹은 FREE r_empid를 통해 이전 연산 내역을 깨끗하게 비워야(초기화) 합니다.
  3. 조건이 항상 참(True)으로 평가되어, 필터 조건 없이 대상 테이블의 전체 데이터가 리턴됩니다.

11. 한눈에 정리 🏁

📝

Chapter 10 최종 정리

  • Range Table은 화면뿐 아니라 ABAP 코드에서도 직접 선언하여 다중 조건을 정의할 수 있습니다.
  • RANGE OF를 통해 대상 필드의 스펙과 정확히 호환되는 Range 구조를 빌드합니다.
  • Range Table에 줄을 추가할 때는 APPEND VALUE #( ... ) 구문을 사용합니다.
  • 사용 직전에는 항상 CLEAR를 생활화해야 정보 누출이나 오작동 버그를 예방할 수 있습니다.
