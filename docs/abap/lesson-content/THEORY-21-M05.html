학습 목표

Behavior Definition에서 "선언"한 동작의 실제 로직을 담는 Behavior Implementation(BIL)을 배웁니다. 검증·계산 같은 커스텀 로직이 들어가는 자리를 익힙니다.

1. 지난 시간 연결: 선언했으니 이제 "구현" 🛠️

앞 Lesson의 BDEF는 "무엇을 할 수 있는가"를 선언했습니다. managed라면 표준 생성·수정·삭제·저장은 RAP가 자동으로 해줍니다. 하지만 "요금을 자동 계산", "날짜를 검증" 같은 업무 고유 로직은 우리가 직접 구현(BIL)해야 합니다.

2. Behavior Pool 클래스 ✍️

CLASS lhc_travel DEFINITION INHERITING FROM cl_abap_behavior_handler.
  PRIVATE SECTION.
    METHODS validate_dates FOR VALIDATE ON SAVE
      IMPORTING keys FOR Travel~validateDates.
ENDCLASS.

CLASS lhc_travel IMPLEMENTATION.
  METHOD validate_dates.
    " 키로 해당 건들을 읽어 검증
    READ ENTITIES OF zi_travel IN LOCAL MODE
      ENTITY Travel FIELDS ( begin_date end_date ) WITH CORRESPONDING #( keys )
      RESULT DATA(travels).

    LOOP AT travels INTO DATA(travel).
      IF travel-end_date < travel-begin_date.
        APPEND VALUE #( %tky = travel-%tky ) TO failed-travel.
        " 메시지도 함께 보고
      ENDIF.
    ENDLOOP.
  ENDMETHOD.
ENDCLASS.

3. RAP의 작업 방식: 키로 읽고 결과 보고 🔁

  • READ ENTITIES: 전달받은 키로 해당 건들을 RAP 방식으로 읽음(직접 SELECT 대신).
  • failed / reported: 실패한 건과 메시지를 RAP에 "보고"하면, RAP가 알아서 저장을 막고 사용자에게 알림.
💡

비유: 품질 검사관

구현 메서드는 생산 라인의 품질 검사관이에요. RAP가 "이 건들 검사해줘"라며 키를 넘기면, 검사관은 읽어보고 불량(failed)을 보고합니다. 합격/불합격 판정만 하고, 라인 정지(저장 차단)는 RAP가 처리하죠.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: READ ENTITIES로 읽고, 검증 후 failed/reported로 보고 → RAP가 저장 통제.
  • ❌ 오류 1: 구현 안에서 직접 SELECT/UPDATE를 함 → RAP 트랜잭션 흐름과 충돌. READ/MODIFY ENTITIES를 써야 함.
  • ❌ 오류 2: 실패를 failed에 안 담음 → 잘못된 데이터가 그대로 저장됨.

5. 실무에서 조심할 점 🚨

⚠️

RAP 안에서는 "RAP 방식"으로

Behavior 구현 안에서는 일반 Open SQL로 직접 DB를 건드리면 안 됩니다. 반드시 READ ENTITIES / MODIFY ENTITIES 같은 RAP 전용 구문을 써야 트랜잭션·잠금·버퍼가 올바르게 동작합니다. 처음엔 낯설지만, "RAP의 세계에서는 RAP의 언어로 말한다"고 생각하면 됩니다. 직접 SELECT/UPDATE 유혹을 참는 것이 핵심입니다.

6. 미니 실습: Behavior Pool 호출 흐름 구분하기 🧪

이번 실습은 Behavior Implementation을 일반 ABAP 클래스처럼 직접 호출하는 습관과 RAP 프레임워크를 통한 호출 흐름을 구분하는 데 목적이 있습니다.

✍️

실습 과제

  1. BDEF에서 선언한 Validation, Determination, Action이 어느 구현 메서드와 이어질지 화살표로 그립니다.
  2. Behavior Implementation 메서드를 외부 프로그램에서 직접 호출하지 않는 이유를 적습니다.
  3. EML의 READ ENTITIES, MODIFY ENTITIES가 어느 위치에서 등장하는지 표시합니다.

완료 조건: Behavior Pool은 RAP 프레임워크가 호출하는 구현 장소이며, 외부 소비자는 EML이나 서비스 경로를 사용한다는 점을 설명할 수 있으면 성공입니다.

8. 확인 퀴즈와 정답/해설 ✅

  1. Behavior Pool 클래스는 일반 Utility 클래스처럼 외부에서 마음대로 호출해도 되나요?
  2. EML은 RAP에서 어떤 역할을 하나요?
  3. FAILED, REPORTED 같은 응답 구조는 왜 중요한가요?
정답/해설 보기
  1. 아닙니다. Behavior Pool은 RAP 프레임워크가 Business Object 동작을 실행하기 위해 호출하는 구현 장소입니다.
  2. Business Object 인스턴스를 타입 안전하게 읽고 변경하는 ABAP 언어 기능입니다.
  3. 처리 실패와 메시지를 프레임워크와 UI로 돌려주는 표준 통로이기 때문입니다.

  • RAP 안에서는 직접 SELECT/UPDATE 대신 RAP 전용 구문을 씁니다.
