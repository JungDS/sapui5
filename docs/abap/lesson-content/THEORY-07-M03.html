학습 목표

지난 Lesson에서 필요 없는 행을 삭제했습니다. 이번에는 SORT로 Internal Table의 순서를 바꾸고, ASCENDING과 DESCENDING으로 정렬 방향을 지정합니다.

1. 같은 데이터도 순서가 바뀌면 읽기 쉬워진다 🧭

Internal Table에는 여러 줄이 들어 있습니다. 이 줄들이 입력된 순서 그대로 있어도 되지만, 출력이나 검색을 위해 특정 기준으로 정렬해야 할 때가 많습니다.

예를 들어 학생 목록을 이름순으로 보여주거나, 점수가 높은 순서대로 보여주면 사용자가 훨씬 빠르게 이해할 수 있습니다. 정렬은 데이터 자체의 값을 새로 만드는 것이 아니라, 줄의 순서를 바꾸는 작업입니다.

SORT는 Internal Table의 줄 순서를 지정한 필드 기준으로 재배치하는 문법입니다.

2. SORT 기본 구조 보기 📚

ABAP
1 
SORT lt_students BY name ASCENDING.

위 코드는 lt_students를 이름 오름차순으로 정렬합니다. 오름차순은 작은 값에서 큰 값, A에서 Z, 낮은 숫자에서 높은 숫자로 가는 방향입니다.

ABAP
1 
SORT lt_students BY score DESCENDING.

이 코드는 점수가 높은 학생이 먼저 오도록 내림차순 정렬합니다. 랭킹이나 우선순위 목록에서는 DESCENDING이 자주 등장합니다.

  • ASCENDING: 낮은 값에서 높은 값으로 정렬합니다.
  • DESCENDING: 높은 값에서 낮은 값으로 정렬합니다.
  • BY 필드명: 어떤 칸을 기준으로 줄 순서를 바꿀지 정합니다.

3. 여러 기준으로 정렬하기 🎛️

정렬 기준은 하나만 쓸 수도 있고 여러 개를 이어 쓸 수도 있습니다. 예를 들어 점수가 높은 순서로 먼저 정렬하고, 점수가 같으면 이름순으로 정렬할 수 있습니다.

ABAP
1 
SORT lt_students BY score DESCENDING name ASCENDING.

이 코드는 먼저 score를 내림차순으로 봅니다. 점수가 같을 때는 name을 오름차순으로 정렬합니다. 실무 출력 목록에서는 이런 다중 기준 정렬이 매우 흔합니다.

💡

정렬 기준을 말로 읽기

SORT lt_students BY score DESCENDING name ASCENDING.은 “점수 높은 순, 점수가 같으면 이름 빠른 순”이라고 말로 바꿔 읽으면 됩니다.

REPORT zsort_itab_basic.

TYPES: BEGIN OF ty_student,
         id    TYPE char3,
         name  TYPE char20,
         score TYPE i,
       END OF ty_student.

DATA: lt_students TYPE STANDARD TABLE OF ty_student,
      ls_student  TYPE ty_student.

ls_student-id = 'A01'. ls_student-name = 'Mina'. ls_student-score = 90.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A02'. ls_student-name = 'Jun'. ls_student-score = 85.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A03'. ls_student-name = 'Sora'. ls_student-score = 95.
APPEND ls_student TO lt_students.

SORT lt_students BY score DESCENDING.

LOOP AT lt_students INTO ls_student.
  WRITE: / ls_student-id, ls_student-name, ls_student-score.
ENDLOOP.

실행하면 95점인 Sora가 먼저 출력되고, 그 다음 Mina, Jun 순서로 출력됩니다. APPEND한 순서와 출력 순서가 달라졌다면 SORT가 적용된 것입니다.

SORT lt_students BY score DESCENDING 실행 전과 후

실행 전 (APPEND한 순서)
순번idnamescore
1A01Mina90
2A02Jun85
3A03Sora95
실행 후 (점수 내림차순)
순번idnamescore

2A01Mina90

데이터 내용은 그대로지만 줄의 순서(그리고 각 줄의 INDEX)가 완전히 바뀌었습니다. SORT 후에는 “3번째 줄”의 의미가 이전과 다릅니다.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: SORT 후 LOOP를 돌면 정렬된 순서로 출력됩니다.
  • ✅ 동점 처리: 첫 번째 기준 값이 같으면 두 번째 기준으로 순서가 정해집니다.
  • ❌ 필드명 오타: BY scroe처럼 없는 필드를 쓰면 문법 오류가 납니다.
  • ❌ 정렬 전후 INDEX 혼동: SORT 후에는 기존 1번째 줄이 그대로 1번째가 아닐 수 있습니다.
  • ❌ 검색 전 정렬 누락: 다음 Lesson의 BINARY SEARCH는 정렬이 전제입니다. 정렬 기준을 놓치면 결과를 믿기 어렵습니다.

미니 실습으로 score DESCENDING을 name ASCENDING으로 바꿔보세요. 출력 순서가 이름 기준으로 바뀌면 정렬 기준을 제대로 이해한 것입니다.

6. 실무에서 조심해야 할 점 🚨

⚠️

SORT는 원본 Internal Table 순서를 바꿉니다

SORT는 복사본을 만드는 것이 아니라 해당 Internal Table 자체의 순서를 바꿉니다. 정렬 전 순서가 이후 로직에 필요하다면 별도 테이블을 쓰거나 정렬 위치를 신중히 잡아야 합니다.

또한 출력용 정렬과 검색용 정렬은 목적이 다를 수 있습니다. 화면에서 예쁘게 보이기 위한 정렬인지, 빠른 검색을 위한 정렬인지 구분해서 읽어야 합니다.

7. 미니 실습: 정렬 기준 바꿔보기 🧪

✍️

실습 과제

  1. 예제 zsort_itab_basic을 실행해 점수 내림차순 출력(Sora→Mina→Jun)을 확인합니다.
  2. SORT lt_students BY score ASCENDING.으로 바꿔 오름차순 결과를 비교합니다.
  3. SORT lt_students BY name.으로 이름 기준 정렬도 실행해봅니다.
  4. 같은 점수(90)를 가진 학생을 한 명 더 추가하고, SORT ... BY score DESCENDING name.처럼 두 번째 기준을 줘서 동점자 순서를 통제해봅니다.

완료 조건: 정렬 기준을 바꿀 때마다 출력 순서가 어떻게 달라지는지 예측한 뒤 실행 결과로 맞히면 성공입니다.

9. 확인 퀴즈와 정답/해설 ✅

  1. SORT를 실행하면 줄의 데이터 내용도 바뀌나요?
  2. 정렬 방향을 지정하지 않으면 기본은 오름차순일까요, 내림차순일까요?
  3. SORT 후에 “2번째 줄”을 INDEX로 접근하는 코드는 왜 다시 점검해야 하나요?
정답/해설 보기
  1. 아니요. 줄의 내용은 그대로이고 순서만 재배치됩니다. 다만 각 줄의 INDEX는 바뀝니다.
  2. 오름차순(ASCENDING)이 기본입니다. 내림차순이 필요하면 DESCENDING을 명시합니다.
  3. 정렬 전과 후의 INDEX가 다르기 때문입니다. 정렬 전 2번째였던 줄이 정렬 후 다른 위치로 이동할 수 있으므로, INDEX 의존 코드는 정렬 시점과 함께 봐야 합니다.
