학습 목표

지금까지는 LOOP AT ... INTO로 행을 Work Area에 복사해 읽었습니다. 이번에는 FIELD-SYMBOLS와 ASSIGNING을 사용해 Internal Table 행에 Reference-like Access로 접근하는 기초를 배웁니다.

1. INTO는 복사, ASSIGNING은 원본 행 접근 🧭

Chapter 6에서는 LOOP AT lt_students INTO ls_student.를 사용했습니다. 이 방식은 현재 행의 값을 Work Area로 복사해서 읽습니다. 읽기에는 안전하고 이해하기 쉽습니다.

하지만 Internal Table의 원본 행을 바로 바꾸고 싶거나, 큰 구조를 매번 복사하는 비용을 줄이고 싶을 때는 Field Symbol을 사용합니다. Field Symbol은 값을 담는 상자라기보다, 현재 행을 가리키는 이름표에 가깝습니다.

Field Symbol은 데이터 자체를 복사해 담는 변수가 아니라, 어떤 데이터 위치를 가리키는 별명처럼 동작합니다.

2. FIELD-SYMBOLS 선언과 ASSIGNING 구조 🔗

ABAP
1

FIELD-SYMBOLS <fs_student> TYPE ty_student.

LOOP AT lt_students ASSIGNING <fs_student>.
  <fs_student>-score = <fs_student>-score + 1.
ENDLOOP.
  • FIELD-SYMBOLS: Field Symbol 이름과 타입을 선언합니다.
  • ASSIGNING: LOOP가 현재 행을 Field Symbol에 연결합니다.
  • <fs_student>: 현재 Internal Table 행을 가리키는 별명입니다.

위 코드는 각 학생 점수에 1점을 더합니다. INTO처럼 복사본을 바꾸는 것이 아니라, Field Symbol이 가리키는 원본 행을 직접 바꾸므로 별도 MODIFY 없이 점수가 변경됩니다.

REPORT zfield_symbol_basic.

TYPES: BEGIN OF ty_student,
         id    TYPE char3,
         name  TYPE char20,
         score TYPE i,
       END OF ty_student.

DATA: lt_students TYPE STANDARD TABLE OF ty_student,
      ls_student  TYPE ty_student.

FIELD-SYMBOLS <fs_student> TYPE ty_student.

ls_student-id = 'A01'. ls_student-name = 'Mina'. ls_student-score = 90.
APPEND ls_student TO lt_students.

CLEAR ls_student.
ls_student-id = 'A02'. ls_student-name = 'Jun'. ls_student-score = 85.
APPEND ls_student TO lt_students.

LOOP AT lt_students ASSIGNING <fs_student>.
  <fs_student>-score = <fs_student>-score + 1.
ENDLOOP.

LOOP AT lt_students INTO ls_student.
  WRITE: / ls_student-id, ls_student-name, ls_student-score.
ENDLOOP.

실행하면 두 학생의 점수가 각각 1점씩 올라간 상태로 출력됩니다. 첫 번째 LOOP에서 Field Symbol로 원본 행을 직접 바꿨기 때문입니다.

4. Reference-like Access는 강력하지만 조심스럽다 ⚡

Reference-like Access는 실제 데이터 위치를 가리키는 방식에 가깝습니다. 그래서 큰 데이터를 복사하지 않고 다룰 수 있고, 원본 행 변경도 간단해집니다.

하지만 그만큼 실수도 바로 원본에 반영됩니다. 읽기만 하려던 코드에서 Field Symbol 값을 바꾸면 Internal Table이 실제로 바뀝니다. 그래서 Field Symbol을 볼 때는 “이 코드는 원본을 바꿀 수 있나?”를 먼저 확인해야 합니다.

⚠️

할당되지 않은 Field Symbol 접근 금지

Field Symbol이 어떤 데이터에도 연결되어 있지 않은 상태에서 값을 읽거나 쓰면 런타임 오류가 날 수 있습니다. LOOP ASSIGNING 안처럼 연결이 보장되는 범위에서 사용하는 습관을 들이세요.

5. 정상 흐름과 오류 흐름으로 확인하기 🔎

  • ✅ 정상 흐름: LOOP ASSIGNING 안에서 Field Symbol은 현재 행을 가리키고, 필드 변경이 원본 행에 반영됩니다.
  • ✅ 복사 감소: 큰 행을 매번 Work Area로 복사하지 않아도 됩니다.
  • ❌ 의도치 않은 변경: 읽기만 할 생각이었는데 Field Symbol 필드를 바꾸면 원본 Internal Table이 바뀝니다.
  • ❌ 미할당 접근: 연결되지 않은 Field Symbol을 사용하면 런타임 오류가 날 수 있습니다.
  • ❌ 가독성 저하: Field Symbol을 과하게 쓰면 데이터가 어디서 바뀌는지 추적하기 어려울 수 있습니다.

미니 실습으로 + 1을 + 5로 바꿔보세요. 두 번째 LOOP 출력에서 원본 점수가 바뀐 것을 확인하면 ASSIGNING의 감각을 잡은 것입니다.

6. 실무에서 조심해야 할 점 🚨

Field Symbol은 성능과 편의성 때문에 현장 코드에서 자주 보입니다. 특히 큰 Internal Table을 LOOP로 돌며 값을 수정할 때 많이 사용합니다. 하지만 초심자에게는 데이터 변경 위치가 덜 명확하게 느껴질 수 있으므로, 처음에는 INTO와 ASSIGNING의 차이를 코드 리뷰에서 꼭 확인하세요.

또한 Field Symbol 이름은 보통 꺾쇠 형태(<fs_student>)로 작성합니다. HTML 본문이나 문서에 쓸 때는 꺾쇠가 태그처럼 해석되지 않도록 이스케이프해야 한다는 점도 기억해두면 좋습니다.

7. 한눈에 정리 🏁

📝

Field Symbol 핵심

  • FIELD-SYMBOLS는 데이터 위치를 가리키는 별명 같은 도구입니다.
  • ASSIGNING은 LOOP의 현재 행을 Field Symbol에 연결합니다.
  • INTO는 복사, ASSIGNING은 원본 행 접근에 가깝습니다.
  • Field Symbol로 필드를 바꾸면 Internal Table 원본 행이 바뀝니다.
  • 미할당 Field Symbol 접근은 런타임 오류가 될 수 있어 주의합니다.
