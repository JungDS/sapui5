학습 목표

CDS를 계층으로 나누는 핵심 패턴 — 재사용 기반인 Interface View(ZI_)와 화면용인 Projection View(ZC_)의 구분을 배웁니다. 왜 한 덩어리로 안 만들고 나누는지 익힙니다.

1. 지난 시간 연결: View 하나로 다 하면 안 될까? 🤔

앞에서 만든 ZI_Flight 하나로 모든 화면·프로그램이 쓰면 될 것 같지만, 문제가 생깁니다. 화면용 꾸밈(UI 주석)과 순수 데이터 모델이 한 곳에 섞이면, 재사용하기도 어렵고 화면마다 요구가 충돌합니다.

그래서 CDS는 보통 2계층으로 나눕니다: 데이터 기반(Interface) + 소비용(Projection).

2. 두 계층의 역할 ✍️

  • Interface View (ZI_): 순수 데이터 모델. JOIN·계산·Association을 담는 재사용 가능한 기반. 여러 곳에서 공유.
  • Projection View (ZC_): 특정 화면/서비스를 위한 소비용 층. Interface에서 필요한 필드만 골라 UI 주석을 입힘.

비유: 원자재 창고 vs 매장 진열

Interface View(ZI_)는 가공·결합을 끝낸 원자재 창고예요. Projection View(ZC_)는 그 중 이 매장(화면)에 맞게 진열한 매대입니다. 창고 하나로 여러 매장을 꾸밀 수 있죠.

3. 왜 나누면 좋은가 🔑

  • ✅ 재사용: 같은 ZI_를 여러 ZC_(화면별)가 공유 → 데이터 로직 한 번만.
  • ✅ 안정성: 화면 요구가 바뀌어도 ZC_만 손대고 ZI_(데이터 기반)는 보호.
  • ✅ RAP 연결: 이 ZI_/ZC_ 2계층이 Chapter 21의 RAP 구조로 그대로 이어집니다.

4. 정상 흐름과 오류 흐름 🔍

  • ✅ 정상: ZI_(기반) → ZC_(투영)로 계층화 → 재사용·확장 용이.
  • ❌ 오류 1: Projection에 무거운 JOIN·계산을 또 넣음 → 계층 의미가 무너짐. 무거운 로직은 Interface에.
  • ❌ 오류 2: UI 주석을 Interface View에 박음 → 재사용성 저하. UI는 Projection 또는 이번 Chapter의 Lesson 5에서 다루는 MDE에 둡니다.

5. 실무에서 조심할 점 🚨

⚠️

계층 책임을 섞지 마세요

"Interface = 데이터·재사용, Projection = 화면·소비"라는 책임 분리가 CDS 설계의 핵심입니다. 귀찮다고 한 View에 다 몰아넣으면, 처음엔 빨라도 화면이 늘수록 유지보수가 급격히 어려워집니다. 작은 프로젝트라도 이 2계층 습관을 들이면 나중에 RAP·Fiori 확장이 훨씬 수월합니다.

6. 미니 실습: ZI_와 ZC_ 책임 나누기 🧪

이번 실습은 View 이름 규칙보다 더 중요한 책임 분리를 연습합니다. 같은 필드라도 어디에 두어야 오래 안전한지 판단해보세요.

✍️

실습 과제

  1. 항공편 목록 화면을 만든다고 가정하고, 데이터 결합·계산·UI 표시 주석을 각각 ZI_와 ZC_ 중 어디에 둘지 표로 나눕니다.
  2. Interface View 하나를 여러 Projection View가 공유하는 예를 2개 적습니다.
  3. UI 요구사항이 바뀌었을 때 ZI_와 ZC_ 중 어느 쪽을 먼저 의심해야 하는지 이유와 함께 정리합니다.

완료 조건: “ZI_는 재사용 데이터 기반, ZC_는 소비 목적에 맞춘 투영”이라고 예를 들어 설명할 수 있으면 성공입니다.

7. 공식 문서로 더 확인하기 🔗

  • SAP Help Portal: DEFINE VIEW ENTITY - View Entity와 projection 구문의 공식 문법 범위를 확인합니다.
  • SAP Learning: RAP Architecture - RAP에서 데이터 모델, projection, service가 어떻게 이어지는지 확인합니다.

8. 확인 퀴즈와 정답/해설 ✅

  1. Interface View에 UI 전용 주석을 많이 넣으면 어떤 문제가 생기나요?
  2. Projection View가 Interface View를 그대로 복사한 두 번째 원본이 되면 왜 위험한가요?
  3. RAP에서 ZI_와 ZC_를 나누는 습관이 중요한 이유는 무엇인가요?
정답/해설 보기
  1. 재사용성이 떨어집니다. 여러 소비자가 공유해야 하는 기반 View가 특정 화면 요구에 묶이기 때문입니다.
  2. 데이터 로직이 중복됩니다. 원천 의미가 두 군데로 갈라지면 수정 시 누락과 불일치가 생깁니다.
  3. RAP는 데이터 모델, projection, service를 계층으로 쌓기 때문입니다. 초반에 책임을 나누면 이후 Behavior와 Service 연결이 안정적입니다.

9. 한눈에 정리 🏁

📝

오늘의 핵심만 딱 잡기

  • CDS는 보통 Interface View(ZI_) + Projection View(ZC_) 2계층입니다.
  • ZI_ = 재사용 데이터 기반(JOIN·계산), ZC_ = 화면용 소비층(필드 선택·UI).
  • as projection on으로 Interface를 투영합니다.
  • 이 2계층이 RAP 구조로 그대로 이어집니다.
