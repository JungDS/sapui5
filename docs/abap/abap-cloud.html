ABAP Cloud App Development 정리

ABAP Cloud는 단순히 ABAP 문법이 새로워진 것이 아니라, Clean Core를 지키면서 공개 API, CDS, RAP, 확장 포인트를 중심으로 개발하는 방향이다. 이 문서는 초급자가 Classic ABAP 경험을 ABAP Cloud 관점으로 어떻게 재정렬해야 하는지 설명한다.

Stage 7 ABAP 개발 ABAP Cloud
01 · 방향

ABAP Cloud는 수정 가능한 코드보다 유지 가능한 확장을 우선합니다

Classic ABAP에서는 표준 테이블을 직접 읽고, Enhancement나 User Exit로 표준 흐름 안에 코드를 넣고, 필요한 경우 내부 구현에 가까운 객체를 참조하는 일이 많았다. ABAP Cloud 관점에서는 이런 방식이 업그레이드와 SaaS 운영에 부담을 만들 수 있다고 본다.

그래서 ABAP Cloud 개발자는 먼저 공개된 API와 Released Object를 확인하고, 데이터 모델은 CDS로 표현하며, 비즈니스 객체의 동작은 RAP Behavior로 선언한다. 핵심 질문은 "어떻게든 접근할 수 있는가"가 아니라 "업그레이드 후에도 깨지지 않는 공식 확장 방식인가"이다.

초급 학습 기준 ABAP Cloud를 처음 공부할 때는 문법보다 개발 원칙을 먼저 잡는 것이 좋다. 공개 API, Clean Core, CDS, RAP, Service Binding이라는 단어가 같은 방향을 가리킨다는 점을 이해한다.
02 · 비교

Classic 개발 습관을 Cloud 개발 기준으로 바꿔 읽습니다

관점 Classic ABAP에서 자주 보던 방식 ABAP Cloud에서 우선하는 방식
데이터 접근 테이블 직접 조회와 내부 테이블 처리 Released CDS View, 공개 API, CDS 기반 모델링
서비스 개발 Gateway SEGW와 DPC_EXT 수동 구현 RAP BO, Service Definition, Service Binding
확장 User Exit, BAdI, Enhancement 중심 Released Extension Point와 Key User/Developer Extensibility
UI Report, ALV, Freestyle UI5 직접 구현 Fiori Elements, Annotation, OData V4 서비스 소비
안정성 내부 구현을 알고 있으면 우회 가능 업그레이드 가능한 계약 기반 개발
03 · 구성요소

ABAP Cloud 학습은 네 개의 블록으로 나누면 선명합니다

Released Objects

사용해도 되는 API, CDS View, Class, Interface를 먼저 확인한다. 접근 가능 여부보다 released 여부가 중요하다.

CDS Data Model

업무 데이터를 SQL 결과가 아니라 의미 있는 모델로 표현한다. Association과 Annotation이 서비스 품질을 좌우한다.

RAP Behavior

생성, 수정, 삭제, Validation, Determination, Action을 비즈니스 객체의 동작으로 선언하고 구현한다.

Service Exposure

Service Definition과 Binding을 통해 OData V4 서비스로 노출하고 Fiori Elements 또는 외부 소비자가 사용하게 한다.

04 · 읽는 법

ABAP Cloud 예제를 볼 때는 객체의 허용 여부부터 확인합니다

초급자는 예제 코드를 보면 먼저 문법을 따라 치려고 한다. ABAP Cloud에서는 한 단계 앞에서 "이 객체가 Cloud 개발에서 사용할 수 있는가"를 확인해야 한다. 같은 SELECT 문이라도 대상이 내부 테이블인지, 공개된 CDS View인지에 따라 운영 안정성이 달라진다.

읽기 관점 예시
" 나쁜 예라고 단정하기보다, 먼저 released 여부를 확인한다.
SELECT * FROM some_table INTO TABLE @DATA(lt_rows).

" Cloud 친화적으로는 공개된 API/CDS View를 우선 검토한다.
SELECT FROM I_SomeReleasedView
  FIELDS KeyField, BusinessField
  INTO TABLE @DATA(lt_rows).

실제 시스템에서는 ADT의 API State, ABAP Language Version, released contract 정보를 함께 확인한다. 초급 단계에서는 "테이블명만 알면 끝"이라는 생각을 내려놓고, 공식 사용 계약을 찾는 습관을 만든다.

05 · 체크리스트

ABAP Cloud 문서를 읽은 뒤 다음 질문에 답할 수 있어야 합니다

  • Clean Core가 왜 표준 수정 금지 이상의 의미를 갖는지 설명할 수 있다.
  • Released Object와 단순히 접근 가능한 Object의 차이를 구분할 수 있다.
  • CDS, RAP, Service Binding이 하나의 개발 흐름으로 연결되는 이유를 말할 수 있다.
  • Classic Gateway와 RAP Service Binding의 역할 차이를 비교할 수 있다.
  • Fiori Elements가 Annotation과 OData 메타데이터를 기반으로 동작한다는 점을 이해한다.
주의 ABAP Cloud는 모든 Classic ABAP 지식을 버리는 영역이 아니다. Open SQL, Internal Table, Class, Exception, Transaction 이해는 여전히 필요하다. 다만 어떤 객체와 확장 방식을 선택할지의 기준이 더 엄격해진다.
