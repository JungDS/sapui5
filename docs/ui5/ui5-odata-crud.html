SAPUI5 OData Model과 CRUD 입문

SAPUI5에서 은 화면과 SAP 또는 RAP 서비스를 연결하는 핵심 모델이다. 이 문서는 과 의 차이, 방식, 호출 흐름을 초급자 관점으로 정리한다.

Stage 7 Docs ODataModel CRUD
01 · 모델 구분

과 은 목적이 다릅니다

은 브라우저 안에 있는 임시 JSON 데이터를 화면에 할 때 적합하다. 반면 은 서버의 , Entity, Function, Action을 화면과 연결한다. 실무 앱에서는 화면 상태는 에 두고, 업무 데이터는 로 읽고 저장하는 경우가 많다.

모델주요 용도주의점
화면 상태, 임시 입력값, 필터 조건서버와 자동 동기화되지 않는다.
SAP 서비스 데이터 조회와 변경서비스 메타데이터와 Key 구조를 정확히 이해해야 한다.
02 · 바인딩

목록과 상세는 방식이 다릅니다

목록은 여러 건을 보여주기 때문에 Aggregation Binding을 사용하고, 상세 화면은 하나의 Entity를 보여주기 때문에 Element Binding을 사용한다. 

<Table items="{/SalesOrderSet}">
  <columns>
    <Column><Text text="Sales Order" /></Column>
  </columns>
  <items>
    <ColumnListItem press=".onItemPress" type="Navigation">
      <cells>
        <Text text="{SalesOrder}" />
      </cells>
    </ColumnListItem>
  </items>
</Table>

상세 화면에서는 Route에서 받은 Key로 경로를 만들고 bindElement를 호출한다. 이때 Key Predicate 형식이 서비스 메타데이터와 맞아야 한다.

03 · 조회

조회는 바인딩을 우선 사용하고 필요한 경우 read를 사용합니다

SAPUI5에서는 화면에 보여줄 데이터는 가능한 바인딩으로 처리한다. Controller에서 직접 read를 호출하는 방식은 특수한 계산이나 별도 후처리가 필요할 때 사용한다. 

const oModel = this.getView().getModel();
oModel.read("/SalesOrderSet", {
  success: function (oData) {
    // oData.results에 조회 결과가 들어온다.
  },
  error: function (oError) {
    // MessageManager 또는 MessageBox로 사용자 메시지를 처리한다.
  }
});
04 · 변경

는 사용자 행동과 서버 변경을 연결합니다

생성, 수정, 삭제는 사용자가 화면에서 수행한 행동을 서버의 변경 요청으로 바꾸는 작업이다. 실무에서는 변경 전 입력값 검증, Busy 처리, 성공 메시지, 오류 메시지 처리가 함께 필요하다. 

const oModel = this.getView().getModel();

oModel.create("/SalesOrderSet", {
  Customer: "100000",
  Currency: "KRW"
}, {
  success: function () {
    sap.m.MessageToast.show("생성되었습니다.");
  },
  error: function () {
    sap.m.MessageBox.error("생성 중 오류가 발생했습니다.");
  }
});
주의 OData V2에서는 변경 요청이 Batch로 묶일 수 있다. 즉시 서버에 보내야 하는지, 사용자가 저장 버튼을 눌렀을 때 한 번에 보낼지 프로젝트 정책을 확인한다.
05 · 메시지

서버 오류는 사용자가 이해할 수 있는 메시지로 연결해야 합니다

CRUD 실패는 단순 기술 오류가 아니라 사용자가 수정해야 할 입력 오류일 수 있다. Gateway 또는 RAP에서 반환한 메시지를 UI5 MessageManager와 연결하면 필드 오류, MessagePopover, 저장 실패 안내를 일관되게 처리할 수 있다.

06 · 완료 체크

ODataModel 기본기를 다음 항목으로 확인합니다

  1. 과 의 목적 차이를 설명한다.
  2. 목록 바인딩과 상세 바인딩의 차이를 설명한다.
  3. OData Entity Key로 상세 경로를 만드는 방식을 설명한다.
  4. Create, Update, Delete 요청에서 성공/오류 처리가 필요한 이유를 설명한다.
  5. 서버 메시지를 UI 메시지로 연결해야 하는 이유를 설명한다.
