Fiori Elements 입문

Fiori Elements는 화면을 직접 코딩하기보다 OData 메타데이터와 Annotation을 기반으로 List Report, Object Page 같은 표준 Fiori 화면을 구성하는 개발 방식이다.

Stage 7 Docs Fiori Elements Annotation
01 · 개념

Fiori Elements는 화면을 코드보다 메타데이터로 만듭니다

Freestyle SAPUI5는 개발자가 View와 Controller를 직접 작성해 화면을 세밀하게 제어한다. Fiori Elements는 CDS Annotation, OData Metadata, Template을 조합해 표준 화면을 생성한다. 그래서 반복적인 List, Filter, Object Page 구현을 줄이고 표준 UX를 빠르게 맞출 수 있다.

구분Freestyle SAPUI5Fiori Elements
화면 구현XML View와 Controller 중심Template과 Annotation 중심
자유도높음표준 패턴 안에서 확장
적합한 앱특수 UX, 복잡한 상호작용List Report, Object Page, Analytical Page
02 · 흐름

RAP 서비스에서 Fiori Elements 화면까지 이어집니다

1
CDS Interface View

ZI_*에서 데이터 구조와 Association을 정의한다.

2
CDS Projection View

ZC_*에서 소비 목적의 필드와 UI Annotation을 정리한다.

3
Service Binding

OData V4 서비스로 publish한다.

4
Fiori Elements App

서비스 메타데이터를 기반으로 List Report와 Object Page를 생성한다.

03 · Annotation

Annotation은 화면에 무엇을 어떻게 보여줄지 설명합니다

@UI.headerInfo: {
  typeName: 'Sales Order',
  typeNamePlural: 'Sales Orders',
  title: { value: 'SalesOrder' }
}
@UI.lineItem: [
  { position: 10, value: SalesOrder },
  { position: 20, value: Customer },
  { position: 30, value: GrossAmount }
]
define root view entity ZC_JHY_SalesOrder
  as projection on ZI_JHY_SalesOrder
{
  key SalesOrder,
      Customer,
      GrossAmount,
      Currency
}

초급자는 Annotation을 "화면 속성"으로만 외우기보다, 메타데이터를 읽는 템플릿에게 의도를 전달하는 언어로 이해해야 한다.

04 · 한계

Fiori Elements는 UI5를 전혀 몰라도 되는 기술이 아닙니다

Fiori Elements를 사용하면 표준 화면 구현량은 줄어들지만, UI5의 모델, 라우팅, 메시지, 확장 포인트를 이해해야 문제를 해결할 수 있다. Annotation이 맞는데 화면이 기대와 다르면 OData Metadata, Service Binding, 브라우저 네트워크, UI5 런타임을 함께 확인해야 한다.
