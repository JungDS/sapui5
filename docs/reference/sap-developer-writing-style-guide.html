SAP Developer Learning Library 문체 기준

본문, 실습, 체크리스트, 강사용 메모의 문체를 상황에 맞게 구분해 전체 학습자료의 읽기 흐름을 통일한다.

본문 평서형 실습 지시형 강사용 메모 존칭형
01 · 원칙

문체는 문서의 기능에 맞춘다

개념 설명은 기술 서적처럼 간결한 평서형을 사용한다. 실습 절차와 체크리스트는 학습자의 행동을 이끄는 지시형을 사용한다. 강사용 메모는 수업 진행자에게 전달하는 안내이므로 존칭형을 유지한다.

개념 설명

평서형을 사용한다. 예: UI5는 입력값을 Model에 반영하기 전에 타입과 제약조건을 검증한다.

실습 / 체크리스트

지시형을 사용한다. 예: Input에 abc를 입력한다. MessageModel에 Error가 생성되는지 확인한다.

강사용 메모

존칭형을 사용한다. 예: 이 단계에서는 학생에게 화면 값과 Model 값의 차이를 먼저 질문하는 것이 좋다.

02 · 예시

같은 내용을 상황별로 다르게 표현한다

상황 권장 표현 사용 위치
개념 설명 Input은 사용자가 값을 입력하는 UI Control이다. 본문, 개념 카드, 표 설명
절차 안내 Input에 abc를 입력한다. Model 값이 변경되지 않는지 확인한다. 실습, 따라하기, 체크리스트
주의사항 화면 값과 Model 값을 같은 것으로 오해하기 쉽다. 주의 박스, 팁 박스
강사용 메모 이 단계에서는 먼저 질문을 던지는 것이 좋다. 강사용 주석, 수업 운영 팁
03 · 적용 기준

v3 문서 수정 기준

  1. 본문의 “한다/된다/있다” 표현은 원칙적으로 “한다/된다/있다”로 정리한다.
  2. 실습 문장은 “입력한다”, “실행한다”, “확인한다”처럼 행동 중심으로 쓴다.
  3. 초심자에게 어려운 단어는 처럼 용어 팝업으로 연결한다.
  4. 강사용 메모와 수업 진행 팁은 존칭형을 유지한다.
04 · 필수 규칙

모든 주요 콘텐츠 블록에는 data-prose를 반드시 부여한다

  1. section.section-card, .hero, .index-card, .note, .warning, .teacher-note에는 data-prose를 부여한다.
  2. 문체 검수는 문장 위치가 아니라 data-prose 값을 기준으로 수행한다.
  3. data-prose가 누락된 주요 콘텐츠 블록은 검수 실패로 본다.
  4. 허용 값은 concept, structure, practice, checklist, warning, teacher, reference, summary이다.
