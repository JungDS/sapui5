오류 찾기 미션

일부러 틀린 코드를 제시하고 버그를 찾게 합니다. 문제 줄 번호나 키워드를 입력해 채점하고, 해설로 원인을 확인합니다. 안티패턴·성능·화면 제어처럼 "실수가 잦은" 주제에 효과적입니다.

원본: Chapter 13 Lesson 1/3 (이벤트·화면 제어 실수)버그 진단 + 해설

실제 적용 예시 3

같은 수단을 세 가지 ABAP 버그에 적용

예시 1은 Chapter 13 Lesson 1의 "기본값을 잘못된 이벤트에 둔 버그"를 찾는 미션입니다.

예시 1 · Report Event (Chapter 13 Lesson 1 원본)

왜 사용자 입력이 무시될까?

ABAP
1
2
3
4
PARAMETERS p_year TYPE c LENGTH 4.
START-OF-SELECTION.
  p_year = '2026'.
  SELECT * FROM zemp WHERE gyear = @p_year INTO TABLE @gt.
버그가 있는 줄 번호를 입력하세요.
해설 보기

3번 줄. 기본값 세팅은 INITIALIZATION에 두어야 합니다. START-OF-SELECTION은 F8 실행마다 돌아 사용자가 바꾼 연도를 매번 '2026'으로 덮어씁니다.

AI 작성 메모: "현상(입력 무시) → 버그 줄 찾기 → 해설" 3단 구성으로 진단 사고를 훈련시킨다.

  SELECT SINGLE carrname FROM scarr WHERE carrid = @ls_f-carrid INTO @DATA(lv_n).

버그가 있는 줄 번호를 입력하세요.
해설 보기

2번 줄. 루프 안 SELECT는 안티패턴입니다. INNER JOIN이나 FOR ALL ENTRIES로 한 번에 가져오세요.

AI 작성 메모: 성능 버그는 "느린 이유"를 묻고, 해설에 대안(JOIN/FAE)을 함께 제시한다.

예시 3 · Selection Screen 화면 제어

왜 칸이 안 숨겨질까?

ABAP
AT SELECTION-SCREEN OUTPUT.
  LOOP AT SCREEN.
    IF screen-name = 'P_DETAIL'.
      screen-active = '0'.
      " ??? 무언가 빠졌다
    ENDIF.
  ENDLOOP.
빠진 구문을 입력하세요.
해설 보기

MODIFY SCREEN.이 빠졌습니다. screen-active를 바꿔도 이 구문이 없으면 실제 화면에 반영되지 않습니다(가장 흔한 실수).

AI 작성 메모: "빠진 줄 찾기"형 버그는 키워드 입력으로 받아, 학습자가 정확한 구문을 떠올리게 한다.
