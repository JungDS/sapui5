예시 1 · Report Event (Chapter 13 통합)

사원 조회 리포트 완성하기

이벤트 라이프사이클 전 단계를 하나의 리포트에 통합합니다.

🎯 목표

  • 이벤트 6단계를 모두 사용하는 사원 조회 리포트

📋 요구사항

  • 기준년도 기본값(오늘 연도)
  • 상세 옵션 체크 시에만 추가 필드 표시
  • 회사코드 존재 검증
  • SALV로 결과 출력, 0건 안내

🪜 단계

  • INITIALIZATION: 기본값
  • AT SELECTION-SCREEN OUTPUT: 화면 제어
  • AT SELECTION-SCREEN: 검증
  • START-OF-SELECTION: 조회
  • END-OF-SELECTION: 출력

🏁 완료 조건

  • 잘못된 입력은 화면 복귀
  • 0건이면 안내 메시지
  • 정상 입력 시 ALV 표시
AI 작성 메모: 캡스톤은 "목표/요구/단계/완료"를 보드로 분리해 학습자가 작업 범위를 스스로 관리하게 한다.

예시 2 · Open SQL + ALV

항공편 매출 요약 리포트

🎯 목표

  • 항공사별 매출 합계를 표로 출력

📋 요구사항

  • 기간(s_date) 입력
  • JOIN으로 항공사명 표시
  • GROUP BY로 매출 합계

🪜 단계

  • 선택 화면 설계
  • JOIN + 집계 SELECT
  • SALV 출력

🏁 완료 조건

  • LOOP 안 SELECT 없음
  • 합계가 정확
  • 0건 안내 처리
AI 작성 메모: SQL+ALV 통합 과제는 "성능 원칙 준수"를 완료 조건에 명시해 안티패턴을 차단한다.

예시 3 · OO ABAP

조회 로직 클래스로 분리하기

🎯 목표

  • 조회 로직을 클래스 메서드로 캡슐화

📋 요구사항

  • lcl_flight_reader 클래스
  • get_flights( ) 메서드
  • 리포트는 클래스를 호출만

🪜 단계

  • DEFINITION/IMPLEMENTATION 작성
  • NEW로 인스턴스화
  • 결과를 ALV로 출력

🏁 완료 조건

  • 조회와 출력이 분리됨
  • 클래스만 바꿔도 화면 영향 없음
AI 작성 메모: OO 캡스톤은 "관심사 분리(조회 vs 출력)"를 완료 조건으로 두어 설계 감각을 기른다.
