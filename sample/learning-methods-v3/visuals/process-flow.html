프로세스 플로우

런타임 처리나 업무 절차를 번호가 매겨진 단계 카드로 보여줍니다. 카드는 화면 폭에 맞춰 1~여러 열로 자동 배치되어 가로 스크롤 없이 흐름을 한눈에 담습니다.

원본: Chapter 13 Lesson 3~5 (단계 플로우)단계 카드

실제 적용 예시 3

같은 수단을 세 가지 ABAP 절차에 적용

예시 1은 Chapter 13 Lesson 4의 입력 검증 게이트 4단계 플로우를 이식했습니다.

예시 1 · Report Event (Chapter 13 Lesson 4 원본)

입력 검증 게이트 (검문소)

실행(F8) 이후 메인 로직으로 가기 전 검문소

1. 사용자가 실행선택 화면 값이 ABAP 변수로 넘어옵니다.
2. AT SELECTION-SCREEN날짜 역전·회사코드 존재 등 입력 조건을 검사합니다.
3A. 실패MESSAGE E 화면 복귀, 재입력.
3B. 성공통과 START-OF-SELECTION으로 진행.

정훈영 사원이 날짜를 거꾸로 넣으면 여기서 막고, 정상일 때만 조회 단계로 보냅니다.

AI 작성 메모: 분기가 있는 절차는 3A/3B처럼 같은 단계 번호에 성공/실패 카드를 나란히 둔다.

예시 2 · Open SQL

START-OF-SELECTION 처리 흐름

검증된 입력이 결과 테이블이 되기까지

1. 선택 조건p_carrid, s_date가 검증된 상태로 전달.
2. Open SQL필요한 필드만 골라 DB에서 읽기.
3. 내부 테이블gt_result에 담아 후속 처리 준비.
4. 출력 단계로조회·가공을 끝내고 END-OF-SELECTION으로.
AI 작성 메모: "입력 → 처리 → 산출"의 데이터 변환 흐름은 단계 카드로 그리면 책임 분리가 분명해진다.

예시 3 · ALV

SALV 출력 4단계

조회 결과를 ALV로 띄우는 절차

1. 데이터 조회SELECT ... INTO TABLE @lt
2. factory 생성cl_salv_table=>factory로 ALV 객체 생성.
3. 기능 활성화get_functions( ) + set_all( )로 툴바 켜기.
4. displaydisplay( )로 화면 출력.
AI 작성 메모: API 호출 순서는 각 카드에 실제 메서드명을 코드로 박아 실습 시 그대로 옮겨 쓰게 한다.
