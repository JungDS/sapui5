디버그 시작 후 Next Step (F6)을 누르면 현재 실행 줄이 하이라이트되고, 모니터 패널의 변수와 콘솔 출력이 갱신됩니다. 런타임이 코드를 어떤 순서로 점프하는지 브라우저에서 그대로 모사합니다.

원본: Chapter 13 Lesson 1 (이벤트 실행 순서 디버거) 현재 줄 하이라이트 변수 모니터 + 콘솔

실제 적용 예시 3

같은 수단을 세 가지 런타임 흐름에 적용

예시 1은 Chapter 13 Lesson 1의 이벤트 순서 디버거를 그대로 이식했습니다. 코드가 거꾸로 적혀 있어도 실행 순서는 정해진 순위를 따릅니다.

예시 1 · Report Event (Chapter 13 Lesson 1 원본)

이벤트 블록 실행 순서 추적

INITIALIZATION이 코드 맨 아래에 있어도 1순위로 점프하는 것을 Next Step으로 관찰하세요.

REPORT zreport_event_demo.START-OF-SELECTION. WRITE: / '[3] START-OF-SELECTION'.END-OF-SELECTION. WRITE: / '[4] END-OF-SELECTION'.INITIALIZATION. WRITE: / '[1] INITIALIZATION'.
⚙️ ABAP Debugger Monitor
현재 호출 이벤트-
SY-SUBRC-
디버깅 대기 중입니다. [디버그 시작]을 누르세요.
AI 작성 메모: "줄 번호 순서 ≠ 실행 순서"를 글로 백 번 설명하는 것보다, Next Step으로 점프를 직접 보여주는 편이 강력하다.

예시 2 · Internal Table

LOOP AT 반복과 sy-tabix 추적

반복마다 현재 행 인덱스(sy-tabix)가 어떻게 증가하는지 Next Step으로 따라가세요.

LOOP AT lt_emp INTO ls_emp. WRITE: / sy-tabix, ls_emp-name.ENDLOOP.
⚙️ Loop Monitor
SY-TABIX (현재 행)-
ls_emp-name-
디버깅 대기 중입니다.
AI 작성 메모: 루프/검색처럼 "포인터가 움직이는" 주제는 모니터에 sy-tabix·sy-subrc를 띄워 상태 변화를 눈으로 잡게 한다.

예시 3 · Selection Screen 검증

검증 실패 후 화면 복귀 추적

종료일이 시작일보다 빠를 때 MESSAGE 'E'가 흐름을 멈추고 화면으로 돌려보내는 과정을 추적합니다.

AT SELECTION-SCREEN. IF p_to < p_from.  MESSAGE 'E: 종료일 오류' TYPE 'E'. ENDIF.START-OF-SELECTION. SELECT ... (실행 안 됨)
⚙️ Validation Monitor
현재 이벤트-
검증 결과-
디버깅 대기 중입니다.
AI 작성 메모: 검증 실패 경로는 "메인 로직이 실행되지 않는다"는 사실을 디버거로 보여줄 때 가장 명확하다(6번 줄에 끝내 도달하지 않음).
