예상 로그 비교

정상 실행 로그와 오류 실행 로그를 나란히 보여줍니다. 어느 단계까지 진행되고 어디서 멈추는지 비교하면, 런타임 흐름의 차이를 글보다 빠르게 이해합니다.

원본 주제: Chapter 13 Lesson 4 (검증 통과/실패)정상 vs 오류 로그

실제 적용 예시 3

같은 수단을 세 가지 흐름에 적용

예시 1은 Chapter 13 Lesson 4의 검증 성공/실패 로그를 비교한 것입니다.

예시 1 · Report Event (Chapter 13 Lesson 4 주제)

입력 검증 성공 vs 실패

✅ 정상 (검증 통과)
AT SELECTION-SCREEN: OK
START-OF-SELECTION: SELECT 3 rows
END-OF-SELECTION: ALV 출력
❌ 오류 (검증 실패)
AT SELECTION-SCREEN: p_to < p_from
MESSAGE E: 종료일 오류 → 화면 복귀
START-OF-SELECTION: (실행 안 됨)

오류 로그는 START-OF-SELECTION 줄에 끝내 도달하지 않습니다. 이것이 "검증이 메인 로직을 막는다"의 증거입니다.

AI 작성 메모: 두 로그의 마지막 줄 차이("실행됨" vs "실행 안 됨")가 핵심이므로 그 줄을 끝에 배치한다.

예시 2 · Open SQL

조회 결과 있음 vs 0건

✅ 결과 있음
SELECT ... : sy-subrc = 0
건수: 3
END: ALV 3행 출력
⚠️ 0건 (정상일 수 있음)
SELECT ... : sy-subrc = 4
건수: 0
END: '데이터 없음' 안내 메시지

0건은 덤프가 아닙니다. sy-subrc=4를 확인해 안내로 분기하는 흐름을 비교합니다.

AI 작성 메모: "오류처럼 보이지만 정상"인 케이스(0건)는 로그로 보여줘 오해를 푼다.

예시 3 · 권한 검사

권한 통과 vs 거부

✅ 권한 있음
AUTHORITY-CHECK: sy-subrc = 0
조회 진행
ALV 출력
❌ 권한 없음
AUTHORITY-CHECK: sy-subrc = 4
MESSAGE E: 권한 없음
조회: (실행 안 됨)
AI 작성 메모: 권한 로그는 "검사 결과 → 분기 → 실행/차단"의 3줄 구조로 두 경로를 대비시킨다.
