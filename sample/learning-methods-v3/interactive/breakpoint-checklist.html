Breakpoint 체크리스트

"어디에 breakpoint를 걸고 무엇을 봐야 하는지"를 표와 체크리스트로 안내합니다. 디버깅을 처음 배우는 학습자가 막연함 없이 멈출 지점과 확인할 변수를 정합니다.

원본 주제: Chapter 13 (이벤트 실행 순서)멈출 위치 + 확인 변수

실제 적용 예시 3

같은 수단을 세 가지 디버깅 상황에 적용

예시 1은 Chapter 13 이벤트 흐름을 디버깅할 때 걸 breakpoint를 정리한 것입니다.

예시 1 · Report Event (Chapter 13 주제)

이벤트 순서 디버깅

Breakpoint 위치확인할 것
INITIALIZATION 첫 줄화면 표시 전에 멈추는지, 기본값이 채워지는지
AT SELECTION-SCREEN입력값(p_year)이 넘어왔는지, 검증 분기
START-OF-SELECTION검증 통과 후에야 도달하는지, sy-subrc
AI 작성 메모: "어디서 멈추고 무엇을 보는가"를 쌍으로 적으면 디버깅이 추측이 아니라 절차가 된다.

예시 2 · Internal Table

LOOP / READ 디버깅

Breakpoint 위치확인할 것
LOOP AT 내부 첫 줄sy-tabix 증가, Work Area 값
READ TABLE 직후sy-subrc(0/4), 찾은 행 내용
AI 작성 메모: 루프/검색은 시스템 필드(sy-tabix/sy-subrc)를 "watch"에 올리도록 안내한다.

예시 3 · Open SQL

SELECT 결과 디버깅

Breakpoint 위치확인할 것
SELECT 직후sy-subrc(0/4), 결과 테이블 건수
WHERE 변수 사용 직전호스트 변수 값이 의도대로인지
AI 작성 메모: SQL 디버깅은 "조건 변수 값"과 "결과 건수"를 멈춰서 확인하게 하는 것이 핵심.
