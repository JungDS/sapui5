01. 큰 그림

Gateway는 SAP 데이터를 HTTP API로 노출하는 관문이다

Gateway OData V2 개발은 SAP 내부의 데이터와 로직을 외부 소비자가 호출할 수 있는 HTTP API로 만드는 작업입니다.

학습 포인트 초급자가 먼저 이해해야 할 기준을 정리합니다.
실무 관점 화면보다 API 단독 검증을 우선합니다.
02. 핵심 용어

Entity Type과 Entity Set을 구분해야 한다

Entity Type은 한 건의 구조이고 Entity Set은 그 구조를 가진 데이터 집합입니다.

학습 포인트 초급자가 먼저 이해해야 할 기준을 정리합니다.

GET_ENTITYSET, GET_ENTITY, CREATE_ENTITY, UPDATE_ENTITY, DELETE_ENTITY를 HTTP Method와 함께 연결해 이해합니다.

04. GET_ENTITYSET

목록 조회는 필터와 반환 테이블을 중심으로 구현한다

처음에는 단순 SELECT로 응답 구조를 확인하고, 이후 $filter, $top, $skip, 정렬, 페이징을 단계적으로 추가합니다.

05. GET_ENTITY

단건 조회는 Key 값을 정확히 읽는 것이 핵심이다

GET_ENTITY는 URL에 포함된 Key를 기준으로 한 건을 조회합니다.

학습 포인트 초급자가 먼저 이해해야 할 기준을 정리합니다.

06. CUD 구현 관점

생성, 수정, 삭제는 요청 Body와 Key 처리 기준이 다르다

CREATE_ENTITY는 Body를 읽고, UPDATE_ENTITY와 DELETE_ENTITY는 URL Key 기준으로 대상 데이터를 찾습니다.
