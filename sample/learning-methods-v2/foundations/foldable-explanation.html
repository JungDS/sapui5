예시 2 · DDIC

Foreign Key 보충 해설

본문엔 핵심만 두고, 자주 나오는 오해는 접이식 보충으로 분리합니다.

"DDIC Foreign Key가 DB 물리 제약인가요?" 펼치기

아닙니다. DDIC Foreign Key는 Application Server 레벨의 논리 검증입니다. 화면 입력이나 ABAP 검증 시 동작하며, 배치나 직접 INSERT로는 우회될 수 있습니다. 물리적 무결성이 꼭 필요하면 DB 제약을 별도로 검토하세요.

"Value Table이 곧 검증인가요?" 펼치기

Value Table은 Domain 레벨의 후보 목록일 뿐, 실제 검증은 Foreign Key 관계가 담당합니다. 둘을 혼동하지 마세요.

AI 작성 메모: 본문을 무겁게 만들 보충/예외는 접이식으로 빼면 초보자는 핵심만, 심화 학습자는 펼쳐 본다.

예시 3 · RAP / CDS

RAP 고급 팁 접기

validation과 determination의 차이 펼치기

validation은 "저장해도 되는지" 검증해 실패 시 막고, determination은 "값을 자동으로 채우거나 파생"합니다. 둘 다 트리거 시점을 지정하지만 책임이 다릅니다.

Public API와 Released API의 차이 펼치기

Public이라고 모두 안정 계약은 아닙니다. ABAP Cloud/Clean Core에서는 Released 상태(C1 contract)인 API만 사용해야 업그레이드 안정성이 보장됩니다.

AI 작성 메모: 용어 구분이 미묘한 RAP 주제는 "A vs B" 형태의 접이식 한 쌍으로 정리하면 오개념이 줄어든다.
