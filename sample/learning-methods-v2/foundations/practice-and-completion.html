미니 실습과 완료 조건

"직접 해볼 과제"와 "어디까지 하면 성공인지(완료 조건)"를 한 세트로 제시합니다. 완료 조건이 있으면 학습자가 스스로 도달 여부를 판단할 수 있어 학습이 닫힙니다.

예시 1은 Chapter 13 Lesson 1의 "이벤트 실행 순서 추적기" 실습 + 완료 조건을 이식했습니다.

예시 1 · Report Event (Chapter 13 Lesson 1 원본)

이벤트 실행 순서 추적기 만들기

✍️

실습 과제

정훈영 사원이 "코드 작성 순서와 무관하게 이벤트가 정해진 순서로 실행된다"를 증명하는 추적 리포트를 설계합니다. INITIALIZATION·START-OF-SELECTION·END-OF-SELECTION을 일부러 뒤섞어 적고 각 블록에 WRITE 로그를 둡니다.

🏁

완료 조건

  • 실행 로그에 INITIALIZATION이 소스 위치보다 먼저 찍힌다.
  • START-OF-SELECTION → END-OF-SELECTION 순서를 말로 설명할 수 있다.
AI 작성 메모: 완료 조건은 "관찰 가능한 결과(로그 순서)" + "설명 가능 여부"로 적으면 자기 채점이 쉽다.

예시 2 · Open SQL

날짜 범위 조회 리포트 만들기

✍️

실습 과제

SFLIGHT에서 항공사와 출발일 범위를 입력받아 조회하는 리포트를 작성합니다. 필요한 컬럼만 SELECT하고 결과를 내부 테이블에 담습니다.

🏁

완료 조건

  • 조건에 맞는 행만 결과 테이블에 담긴다.
  • 조회 결과 0건일 때 빈 화면 대신 안내 메시지가 나온다.
  • WHERE 절의 호스트 변수에 @를 빠뜨리지 않았다.
AI 작성 메모: SQL 실습 완료 조건에는 "빈 결과 처리"와 "Strict 모드 @"처럼 자주 놓치는 항목을 명시한다.

예시 3 · ALV

SALV로 결과 출력하기

✍️

실습 과제

조회한 내부 테이블을 cl_salv_table=>factory( )로 생성해 화면에 출력합니다. 정렬·필터·합계 등 표준 툴바를 켭니다.

🏁

완료 조건

  • factory → display 순서로 ALV가 뜬다.
  • get_functions( ) + set_all( )로 툴바가 활성화된다.
  • 결과 0건일 때 ALV 대신 안내 메시지로 분기한다.
AI 작성 메모: API 실습은 "호출 순서"와 "기본적으로 꺼져 있는 기능을 켜는 단계"를 완료 조건으로 넣어야 빈 화면 함정을 피한다.
