콜아웃 패턴

학습 목표, 팁, 실무 주의를 본문과 구분되는 색 박스로 고정해 시선을 잡습니다. tip(초록)·warn(빨강)·기본(파랑) 세 종류를 일관되게 쓰면 학습자가 "여기는 꼭 봐야 하는 곳"임을 색만으로 인지합니다.

원본: Chapter 13 Lesson 1~6 (학습 목표/실무 주의)tip / warn / 기본

실제 적용 예시 3

같은 수단을 세 가지 ABAP 주제에 적용

예시 1은 Chapter 13에서 실제로 쓰인 콜아웃 묶음(학습 목표 + 실무 주의)을 이식했습니다.

예시 1 · Report Event (Chapter 13 원본)

이벤트 Lesson의 콜아웃 3종

🎯

학습 목표

리포트가 실행될 때 거치는 이벤트의 전체 흐름(LOAD-OF-PROGRAM → INITIALIZATION → 선택 화면 → START-OF-SELECTION)을 지도처럼 그립니다.

⚠️

"어디에 쓰느냐"가 아니라 "어떤 블록에 쓰느냐"

컴파일러는 물리적 줄 위치가 아니라 이벤트 블록으로 순서를 정합니다. INITIALIZATION은 코드 맨 아래에 있어도 START-OF-SELECTION보다 먼저 실행됩니다.

💡

SELECT-OPTIONS 기본값은 조금 다르게

PARAMETERS는 변수에 바로 대입하지만, SELECT-OPTIONS는 Range 구조(low/sign/option)를 채우고 APPEND해야 합니다.

AI 작성 메모: 모든 Lesson 도입부는 tip(목표), 본론 끝은 warn(실무 주의)로 고정하면 학습자가 구조를 예측한다.

예시 2 · Open SQL

SELECT 성능 Lesson의 콜아웃

🎯

학습 목표

필요한 필드만 골라 한 번에 조회하는 습관을 들입니다.

⚠️

LOOP 안에서 SELECT 금지

반복마다 DB를 왕복하면 건수만큼 비용이 곱해집니다. JOIN이나 FOR ALL ENTRIES로 한 번에 가져오세요.

💡

빈 결과는 오류가 아니다

조건에 맞는 행이 0건이면 sy-subrc = 4입니다. 덤프가 아니라 "조용한" 결과이므로 반드시 확인하세요.

AI 작성 메모: 성능 주제는 warn 콜아웃에 "금지 패턴"을 명시하면 코드 리뷰 기준으로도 재활용된다.

예시 3 · OO ABAP

클래스 입문 Lesson의 콜아웃

🎯

학습 목표

DEFINITION(설계도)과 IMPLEMENTATION(구현)을 구분하고, 인스턴스를 만들어 메서드를 호출합니다.

⚠️

Static과 Instance를 혼동하지 마세요

클래스 자체에 붙은 것은 =>로, 객체에 붙은 것은 ->로 접근합니다. 호출 연산자가 곧 소속을 말해줍니다.

💡

신규 개발은 Subroutine 대신 클래스

FORM/PERFORM은 구식(obsolete)입니다. 새 모듈화는 Local/Global Class를 우선 검토하세요.

AI 작성 메모: 오개념이 강한 주제(Static vs Instance)는 warn 콜아웃으로 "헷갈리는 지점"을 콕 집는다.
