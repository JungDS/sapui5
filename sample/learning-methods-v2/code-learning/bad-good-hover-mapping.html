Bad/Good Practice Hover Mapping

왼쪽 안티패턴 코드와 오른쪽 권장 코드를 나란히 두고, 어느 한 줄에 마우스를 올리면 양쪽의 대응 줄이 함께 강조되며 아래에 상세 해설이 나타납니다. "무엇이 왜 잘못됐는지"를 한 줄 단위로 비교합니다.

원본: Chapter 13 Lesson 1 (기본값 위치 버그) hover 연동 강조 실시간 해설

실제 적용 예시 3

같은 수단을 세 가지 ABAP 안티패턴에 적용

예시 1은 Chapter 13 Lesson 1의 "잘못된 이벤트 블록에 기본값 세팅" 비교를 그대로 이식했습니다. 각 줄에 마우스를 올려보세요.

예시 1 · Report Event (Chapter 13 Lesson 1 원본)

기본값을 어느 이벤트 블록에 둘 것인가

START-OF-SELECTION에 기본값을 넣으면 매 실행마다 사용자 입력을 덮어쓰는 버그가 납니다. INITIALIZATION에 두는 것이 정답입니다.

💻 실무 코드 비교 분석기 (Hover Mapping)

❌ Bad Practice (버그 유발)

PARAMETERS p_year TYPE c LENGTH 4.

START-OF-SELECTION.
  p_year = '2026'.
  SELECT * FROM zemp WHERE gyear = p_year.

✅ Good Practice (권장)

PARAMETERS p_year TYPE c LENGTH 4.

INITIALIZATION.
  p_year = '2026'.

START-OF-SELECTION.
  SELECT * FROM zemp WHERE gyear = p_year.
양쪽 코드의 강조 줄에 마우스를 올리면 비교 설명이 여기에 표시됩니다.
AI 작성 메모: 안티패턴 Lesson에서 Hover Mapping은 "어느 줄이 어느 줄과 대응되는가"를 손으로 짚어주므로, 단순 Before/After 표보다 인과관계가 또렷하다.

예시 2 · Open SQL

LOOP 안 SELECT vs JOIN 한 번

반복문 안에서 SELECT를 돌리면 DB 왕복이 폭증합니다. 한 번의 JOIN으로 대체하는 것이 정석입니다.

💻 성능 안티패턴 비교

❌ Bad Practice (N+1 쿼리)

LOOP AT lt_flight INTO DATA(ls_f).
  SELECT SINGLE carrname FROM scarr WHERE carrid = @ls_f-carrid INTO @DATA(lv_name).
ENDLOOP.

✅ Good Practice (단일 JOIN)

SELECT f~carrid, c~carrname, f~fldate
  FROM sflight AS f INNER JOIN scarr AS c ON f~carrid = c~carrid INTO TABLE @DATA(lt_join).
강조 줄에 마우스를 올리면 비교 설명이 표시됩니다.
AI 작성 메모: 성능 주제는 "반복 줄 ↔ 단일 조회 줄"을 직접 연결해 보여주면 비용 차이를 직관적으로 이해시킬 수 있다.

예시 3 · Internal Table

LOOP 중 DELETE vs DELETE WHERE

루프를 돌며 행을 지우면 인덱스가 밀려 일부 행을 건너뜁니다. 집합 연산인 DELETE ... WHERE가 안전합니다.

💻 인덱스 시프트 안티패턴 비교

❌ Bad Practice (행 건너뜀)

LOOP AT lt_emp INTO DATA(ls_e).
  IF ls_e-dept = 'OLD'. DELETE lt_emp INDEX sy-tabix. ENDIF.
ENDLOOP.

✅ Good Practice (집합 삭제)

DELETE lt_emp WHERE dept = 'OLD'.
" 모든 'OLD' 부서 행이 정확히 제거됩니다.
강조 줄에 마우스를 올리면 비교 설명이 표시됩니다.
AI 작성 메모: "순회 중 구조 변경"처럼 눈에 안 보이는 버그는 Bad/Good를 줄 단위로 연결해야 위험 지점이 분명해진다.
