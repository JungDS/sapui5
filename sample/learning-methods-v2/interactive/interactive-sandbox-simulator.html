상호작용 · 가상 SAP GUI Sandbox

가상 Sandbox 시뮬레이터

학습자가 직접 값을 입력하고 실행(F8)을 누르면, SAP 엔진이 이벤트 순서대로 동작하는 과정을 로그로 보여주고 가상 DB 조회 결과까지 ALV 표로 렌더링합니다. 잘못된 입력은 검증 단계에서 막혀 에러 모달이 뜹니다.

원본: Chapter 13 Lesson 1 (Selection Screen Sandbox) 입력 → 검증 → 조회 → 출력 JSON 시나리오 구동

실제 적용 예시 3

같은 수단을 세 가지 ABAP 주제에 적용

예시 1은 Chapter 13 Lesson 1의 사원 정보 조회 Sandbox를 그대로 이식했습니다. 사원번호를 비우거나 4자리 숫자가 아닌 값을 넣어 검증 에러를 유도해 보세요.

예시 1 · Report Event (Chapter 13 Lesson 1 원본)

사원 정보 통합 조회 Sandbox

기준년도와 사원번호를 입력하고 실행하면 INITIALIZATION → AT SELECTION-SCREEN → START-OF-SELECTION → END-OF-SELECTION 순으로 로그가 쌓이고, 가상 DB에서 일치하는 사원이 ALV로 출력됩니다.

💡 사원번호 예시: 1000(정훈영), 2000(김지현), 4000(박서우)은 2026년 / 3000(이민수)은 2025년 데이터입니다.

T-Code: SE38 (ZREPORT_EVENT_DEMO)
사원 정보 통합 조회 프로그램 (Selection Screen)
실행(F8) 버튼을 누르면 SAP 내부 이벤트 흐름이 로그로 출력됩니다…
AI 작성 메모: Sandbox는 "입력값에 따라 결과가 달라진다"를 직접 만지게 할 때만 쓴다. 검증 실패 경로(빈 값/형식 오류)를 반드시 넣어야 학습 가치가 산다.

예시 2 · Open SQL

항공편 WHERE 필터 Sandbox

항공사 코드와 최소 가격을 입력하면 WHERE 조건이 적용된 결과셋이 달라집니다. 항공사 코드를 비우면 전체에서 가격 조건만 적용됩니다.

💡 항공사 코드: AA, LH, UA / 가격은 숫자(예: 500)

T-Code: SE38 (ZFLIGHT_QUERY)
항공편 조회 (SFLIGHT)
실행(F8)을 누르면 SELECT 쿼리 흐름이 출력됩니다…
AI 작성 메모: 빈 입력을 "필터 제외"로 처리하면 학습자가 WHERE 조건의 누적 효과를 직접 실험할 수 있다.

예시 3 · Selection Screen 권한 검증

회사코드 권한 체크 Sandbox

회사코드를 입력하면 AT SELECTION-SCREEN에서 존재 여부를 검증하고, 등록된 코드만 조회로 진행합니다. 미등록 코드는 에러로 막힙니다.

💡 등록된 회사코드: 1000, 2000, 3000

T-Code: SE38 (ZCOMPANY_CHECK)
회사코드 검증 조회 (T001)
실행(F8)을 누르면 권한/존재 검증 흐름이 출력됩니다…
AI 작성 메모: 존재/권한 검증은 "DB에 있으면 통과, 없으면 화면 복귀" 패턴이 핵심. 빈 결과를 에러 메시지로 안내하는 것까지 시뮬레이션하면 실무 감각이 붙는다.
