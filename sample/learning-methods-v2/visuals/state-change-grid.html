상태 변화 그리드

연산 실행 전과 후의 내부 테이블 상태를 두 표로 나란히 보여줍니다. 어느 행이 추가/삭제/변경됐는지 색으로 강조해, 추상적인 "테이블이 바뀐다"를 구체적인 행 변화로 만듭니다.

Internal Table 적용전/후 표 대비

실제 적용 예시 3

같은 수단을 세 가지 내부 테이블 연산에 적용

정훈영 사원 데이터로 연산 전/후 상태 변화를 추적합니다.

예시 1 · Internal Table — APPEND

APPEND 전/후

APPEND 전
#이름
1정훈영
2김지현
APPEND 후
#이름
1정훈영
2김지현
3박서우 (추가됨)

APPEND는 맨 뒤에 행을 붙입니다. 새 행(3번)이 노란색으로 강조됩니다.

AI 작성 메모: 추가/변경된 행만 viz-highlight-row로 강조하면 "무엇이 달라졌는지" 시선이 바로 간다.

예시 2 · Internal Table — SORT

SORT BY name 전/후

SORT 전 (입력 순)
이름
정훈영
김지현
박서우
SORT 후 (가나다순)
이름
김지현
박서우
정훈영

정렬은 행 내용이 아니라 순서를 바꿉니다. BINARY SEARCH 전에는 이 정렬이 반드시 선행돼야 합니다.

AI 작성 메모: 순서만 바뀌는 연산은 같은 데이터의 배치 변화를 두 표로 보여줘 "내용 보존 + 순서 변경"을 분명히 한다.

조건에 맞는 모든 행이 한 번에 제거됩니다. LOOP 중 DELETE와 달리 인덱스 밀림이 없습니다.

AI 작성 메모: 삭제 결과는 빈 상태(viz-empty)로 "사라졌음"을 시각화하면 변화가 체감된다.
