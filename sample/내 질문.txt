# 핵심 신규 요구: 수단별 디자인 시안 3개 이상 + 선택 기록
- 각 샘플 페이지 상단에 "디자인 시안(Design Variants)" 섹션을 추가한다.
- 해당 페이지의 "수단 그 자체"를 주제로, 서로 명확히 다른 디자인 시안을 최소 3개(A/B/C…) 제시한다.
  - 예: 콜아웃 패턴 → (A) 좌측 컬러바 카드형, (B) 아이콘 배지 + 둥근 박스형, (C) 미니멀 라인형.
  - 예: 프로세스 플로우 → (A) 가로 단계 카드, (B) 세로 타임라인, (C) 번호 원형 노드 연결형.
  - 시안끼리는 "색만 다른" 수준이 아니라 레이아웃/구성 방식이 실제로 달라야 한다.
  - 각 시안에는 짧은 설명(언제 적합한지)을 붙인다.
- 각 페이지는 "시안 선택 UI"를 제공한다(라디오/버튼). 선택 시:
  - localStorage에 page-id별 선택을 저장하고, 화면에 현재 선택을 표시한다.
  - "선택 내보내기" 버튼으로 현재 페이지 선택(JSON 한 줄)을 클립보드로 복사할 수 있게 한다.
- 선택 결과의 단일 기록 파일 sample/learning-methods-v3/design-choices.json 을 만든다.
  - 스키마 예:
    {
      "version": "v3",
      "updated": "YYYY-MM-DD",
      "choices": {
        "foundations/callout-patterns": { "chosen": null, "options": ["A","B","C"], "note": "" },
        ... 38개 페이지 전부 ...
      }
    }
  - 초기값 chosen은 null. 사용자가 시안을 고르면 이 파일에 chosen을 기록한다(사용자가 직접 수정하거나, 페이지의 "선택 내보내기"로 복사해 붙여넣는 흐름).
  - 이후 단계에서 AI가 이 파일을 읽어 chosen 시안의 디자인을 본 페이지의 정식 디자인으로 반영할 수 있도록, 시안 식별자와 디자인 의도를 README에 설명한다.
- design-choices.json의 모든 page-id가 실제 v3 HTML 파일 경로와 1:1로 일치해야 한다(누락/오타 0건).

# 공통 소스 재점검(전 페이지)
- 38개 페이지 각각의 소스를 다시 읽고 오작동 가능성을 점검한다. 최소 다음을 확인:
  - HTML에서 < > & 등 특수문자가 코드 블록 안에서 올바르게 이스케이프(&lt; &gt; &amp;)되어 텍스트가 깨지지 않는지.
  - getElementById/중복 id 충돌(특히 아코디언 data-tour-id, 디버거/sandbox/탭 패널 id)이 페이지 내에서 유일한지.
  - 위젯 JS가 멀티 인스턴스에서 각각 독립 동작하는지(한 인스턴스 조작이 다른 인스턴스에 영향 X).
  - JSON 구동 위젯(sandbox-config, debugger-steps, decision-config)의 JSON이 파싱 가능한지, 라벨 누락("[undefined]") 같은 결함이 없는지.
  - 줄 번호(line-numbers) 개수와 실제 코드 줄 수가 일치하는지.
  - mermaid 페이지는 CDN 로드 후 SVG가 렌더링되는지.
