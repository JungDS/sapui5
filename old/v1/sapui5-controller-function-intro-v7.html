이 자료를 읽기 전에

JavaScript를 처음 배우면 함수 문법이 여러 가지로 보여서 헷갈릴 수 있습니다. 특히 UI5 Controller에서는 아래 세 가지 모양을 자주 보게 됩니다.

?
용어를 클릭해보세요.
문서 중간의 파란색 점선 용어를 클릭하면 간단한 설명 팝업이 열리고, 팝업 안에서 더 자세한 학습 페이지로 이동할 수 있습니다.
a: function () { ... }

a() { ... }

() => { ... }

세 문법은 모두 함수를 다루는 방법이지만, UI5에서는 아무 곳에나 같은 방식으로 쓰면 안 됩니다. 특히 this가 Controller를 가리키는지 여부가 매우 중요합니다.

먼저 기억할 기준 UI5 Controller를 처음 작성할 때는 Controller 메서드는 function, 그 안의 콜백은 화살표 함수라는 기준으로 시작하면 안전합니다.

1장. 함수가 뭔가요?

함수는 실행할 코드를 하나의 이름으로 묶어둔 것입니다. 일반 JavaScript에서는 같은 코드를 여러 번 사용하기 위해 함수를 만들기도 합니다. 

function sayHello() {
  console.log("안녕하세요");
}

sayHello();

위 코드는 sayHello라는 이름의 함수를 만들고, 나중에 sayHello()라고 호출해서 실행하는 예입니다.

UI5에서는 “재사용”보다 “기능 블록”이 더 중요합니다

UI5 Controller에서 함수는 단순히 자주 쓰는 코드를 보관하는 용도만은 아닙니다. 오히려 화면에서 어떤 일이 발생했을 때 실행할 기능을 미리 구현해두는 블록에 가깝습니다. 

onSave: function () {
  // 저장 버튼을 눌렀을 때 실행할 기능
}

이 함수는 “자주 쓰려고 보관한 코드”라기보다, “저장 버튼을 눌렀을 때 무엇을 할지 정해둔 기능 블록”입니다.

UI5식으로 이해하기 UI5 Controller에서 함수는 화면 동작을 처리하는 기능 단위입니다. 조회, 저장, 삭제, 취소 같은 화면 행동이 각각 함수로 구현됩니다.

함수와 메서드는 무엇이 다른가요?

초급 단계에서는 다음처럼 이해하면 충분합니다.

함수 독립적으로 실행할 수 있는 코드 묶음입니다.
메서드 객체나 클래스 안에 들어있는 함수입니다. 
// 일반 함수
function sayHello() {
  console.log("안녕하세요");
}

// 객체 안에 들어있는 함수: 메서드라고 부를 수 있음
const person = {
  sayHello: function () {
    console.log("안녕하세요");
  }
};

UI5 Controller 안에 작성하는 함수도 JavaScript 문법상 함수입니다. 하지만 Controller라는 객체 안에 들어있기 때문에 보통 Controller 메서드라고 부릅니다. 

return Controller.extend("my.app.controller.Main", {
  onInit: function () {
    // Controller 메서드
  }
});

2장. UI5에서는 함수가 어디에 쓰이나요?

UI5를 처음 배우면 View와 Controller가 나뉘어 있는 구조가 어색할 수 있습니다. 하지만 이 구조를 이해하면 Controller 함수의 역할이 훨씬 명확해집니다.

View와 Controller의 역할

구분 역할 쉽게 말하면
View 화면에 무엇을 보여줄지 담당 버튼, 입력필드, 테이블 같은 화면 구성
Controller 사용자가 행동했을 때 무엇을 할지 담당 버튼 클릭, 조회, 저장, 오류 처리 같은 동작

버튼 클릭과 Controller 함수 연결

XMLView에서 버튼에 press=".onSearch"를 작성하면, 사용자가 버튼을 눌렀을 때 Controller의 onSearch 함수가 실행됩니다. 

<Button text="조회" press=".onSearch" />
onSearch: function () {
  console.log("조회 버튼을 눌렀습니다.");
}
1
사용자가 화면의 조회 버튼을 누릅니다.
2
UI5가 XMLView의 press=".onSearch" 설정을 확인합니다.
3
Controller 안에서 onSearch라는 이름의 함수를 찾습니다.
4
onSearch 함수 안에 작성한 코드가 실행됩니다.

Controller 함수의 대표적인 예

함수 예시 실행 시점 역할
onInit 화면이 처음 열릴 때 초기 모델 생성, 기본값 설정, 초기 데이터 준비
onSearch 조회 버튼 클릭 검색 조건을 읽고 데이터 조회 실행
onSave 저장 버튼 클릭 입력값 검증 후 저장 처리
onDelete 삭제 버튼 클릭 선택한 행이나 데이터를 삭제
_loadData 다른 함수 내부에서 호출 데이터 조회를 실제로 수행하는 보조 함수
_handleError 오류 발생 시 호출 오류 메시지 정리 및 사용자 안내

함수 이름에는 의도가 담깁니다

함수 이름은 단순한 이름표가 아닙니다. 이 함수가 어떤 상황에서 실행되는지 알려주는 중요한 힌트입니다.

on을 붙이는 이유

UI5 Controller에서 이벤트 처리 함수는 보통 on으로 시작합니다. 

onSearch: function () {}
onSave: function () {}
onDelete: function () {}
onCancel: function () {}

on은 “어떤 일이 발생했을 때”라는 느낌으로 이해하면 좋습니다. onSearch는 “조회가 발생했을 때 실행되는 함수”, onSave는 “저장이 발생했을 때 실행되는 함수”라는 의미를 줍니다.

중요 on은 JavaScript가 강제로 요구하는 문법은 아닙니다. 하지만 UI5에서 이벤트 핸들러 이름을 읽기 쉽게 만드는 중요한 관례입니다.

_를 붙이는 이유

Controller 내부에서만 사용할 보조 함수는 보통 _로 시작하는 이름을 사용합니다. 

onSearch: function () {
  this._loadData();
},

_loadData: function () {
  // 실제 데이터 조회 처리
}

_loadData처럼 앞에 _가 붙은 함수는 “화면 이벤트에서 직접 호출하는 함수라기보다, Controller 내부에서 도와주는 함수”라는 의미를 줍니다.

이름을 잘 짓는 이유 이름만 보고도 “이 함수가 이벤트 처리용인지”, “내부 보조 기능인지”, “어떤 업무 동작을 담당하는지” 알 수 있어야 합니다.

3장. 첫 번째 문법: a: function () { ... }

UI5 Controller를 처음 배울 때 가장 먼저 익히면 좋은 함수 문법입니다. 

onSearch: function () {
  console.log("조회 버튼을 눌렀습니다.");
}
부분 의미
onSearch 함수 이름입니다. 조회 버튼과 연결될 수 있습니다.
function () 함수를 정의한다는 뜻입니다.
{ ... } 실제로 실행할 코드를 작성하는 영역입니다.

UI5 Controller의 라이프사이클 함수나 이벤트 핸들러는 이 방식으로 작성하면 안정적입니다. 

return Controller.extend("my.app.controller.Main", {
  onInit: function () {
    // 화면이 처음 열릴 때 실행
  },

  onSearch: function () {
    // 조회 버튼을 눌렀을 때 실행
  },

  onSave: function () {
    // 저장 버튼을 눌렀을 때 실행
  }
});
초급자 권장 UI5 Controller의 주요 메서드는 우선 a: function () { ... } 형태로 작성하세요. 특히 this.getView(), this.byId()를 사용할 때 이 기준이 안전합니다.

4장. 두 번째 문법: a() { ... }

이 문법은 객체 안의 함수를 더 짧게 작성하는 최신 JavaScript 문법입니다. 

onSearch() {
  console.log("조회 버튼을 눌렀습니다.");
}

아래 두 코드는 비슷한 역할을 합니다.

// 전통적인 UI5 스타일
onSearch: function () {
  console.log("조회 버튼을 눌렀습니다.");
}

// 짧게 쓰는 최신 JavaScript 스타일
onSearch() {
  console.log("조회 버튼을 눌렀습니다.");
}

최신 JavaScript 문법에 익숙한 개발자라면 a() {} 형태도 사용할 수 있습니다. 다만 UI5를 처음 배우는 학생에게는 a: function () {} 형태가 더 명확합니다.

입문 단계 기준 a() {}도 사용할 수 있지만, UI5 교육에서는 먼저 a: function () {}을 기본 형태로 익히는 것이 좋습니다. 하나의 기준을 먼저 잡아야 Controller 구조가 덜 헷갈립니다.

5장. 세 번째 문법: () => { ... }

이 문법은 화살표 함수라고 부릅니다. UI5 Controller의 메인 함수보다는, 함수 안에서 잠깐 사용하는 콜백 함수에 자주 사용합니다.

배열 [ ]이란?

배열은 여러 값을 순서대로 담아두는 상자입니다. JavaScript에서는 [ ] 기호로 배열을 만듭니다. 

const numbers = [10, 20, 30];
순서 값
첫 번째 10
두 번째 20
세 번째 30

UI5에서도 테이블 데이터, 조회 결과 목록, 선택한 행 목록 등을 다룰 때 배열을 자주 사용합니다.

forEach란?

forEach는 배열 안에 들어있는 값을 하나씩 꺼내서 처리할 때 사용하는 기능입니다. 

const numbers = [10, 20, 30];

numbers.forEach(function (number) {
  console.log(number);
});

위 코드는 다음과 비슷한 의미입니다.

console.log(10);
console.log(20);
console.log(30);
1
numbers 배열 안에는 10, 20, 30이 들어 있습니다.
2
forEach가 값을 하나씩 꺼냅니다.
3
꺼낸 값이 number라는 이름으로 함수에 전달됩니다.
4
함수 안의 console.log(number)가 실행됩니다.

콜백 함수란?

일반적인 코드는 보통 위에서 아래로 실행됩니다. 

console.log("1번");
console.log("2번");
console.log("3번");

실행 결과도 순서대로입니다.

1번
2번
3번

그런데 콜백 함수는 조금 다르게 생각해야 합니다. 

numbers.forEach(function (number) {
  console.log(number);
});

여기서 아래 함수는 우리가 직접 함수이름() 형태로 호출하는 함수가 아닙니다. 

function (number) {
  console.log(number);
}

이 함수는 forEach에게 전달됩니다. 그리고 forEach가 배열 값을 하나씩 꺼낼 때마다 이 함수를 대신 실행합니다.

콜백 함수 쉽게 이해하기 콜백 함수는 “지금 바로 내가 직접 실행하는 함수”라기보다, 다른 기능에게 맡겨두고 필요한 순간에 그 기능이 대신 실행해주는 함수입니다.
처음에 어려운 이유 콜백 함수는 코드가 위에서 아래로만 실행되는 것처럼 보이지 않습니다. 어떤 기능이 나중에 함수를 다시 불러주는 구조이기 때문에 처음에는 헷갈릴 수 있습니다.

화살표 함수는 콜백에서 자주 사용됩니다

기존 방식은 다음과 같습니다.

numbers.forEach(function (number) {
  console.log(number);
});

화살표 함수 방식은 다음과 같습니다.

numbers.forEach((number) => {
  console.log(number);
});

화살표 함수는 짧고 읽기 좋아서 forEach, map, filter, Promise, OData callback 같은 곳에서 자주 사용됩니다. 특히 UI5 Controller 안에서 콜백을 작성할 때 this 문제를 줄이는 데 도움이 됩니다.

주의 화살표 함수가 항상 더 좋은 것은 아닙니다. UI5 Controller의 주요 메서드 자체를 화살표 함수로 작성하는 것은 피하는 것이 좋습니다.

6장. UI5에서 가장 중요한 this

UI5 Controller를 배울 때 this는 반드시 이해해야 하는 개념입니다. 가장 중요한 문장은 이것입니다.

반드시 기억하기 this는 항상 Controller가 아닙니다.

this는 상황에 따라 달라집니다

UI5 Controller 메서드 안에서는 보통 this가 Controller를 가리킵니다. 

onSearch: function () {
  this.getView();
  this.byId("idInput");
}

그래서 this.getView(), this.byId(), this.getOwnerComponent() 같은 코드를 사용할 수 있습니다.

하지만 모든 함수 안에서 this가 항상 Controller라는 뜻은 아닙니다. this는 “어떤 상황에서 실행되었는가”에 따라 달라질 수 있습니다.

콜백 함수에서는 this가 Controller가 아닐 수 있습니다

onSearch: function () {
  const numbers = [10, 20, 30];

  numbers.forEach(function (number) {
    this.byId("idInput"); // 오류가 날 수 있음
  });
}

바깥쪽 onSearch 안의 this는 Controller일 수 있습니다. 하지만 forEach 안에 전달한 일반 함수의 this는 Controller가 아닐 수 있습니다.

실무에서 자주 나는 오류 콜백 함수 안에서 this.byId(...), this.getView()를 사용했는데 this가 Controller가 아니라서 오류가 발생하는 경우가 많습니다.

해결 방법 1: .bind(this)

일반 함수 뒤에 .bind(this)를 붙이면, 함수 안의 this를 바깥쪽 Controller의 this로 고정할 수 있습니다. 

onSearch: function () {
  const numbers = [10, 20, 30];

  numbers.forEach(function (number) {
    this.byId("idInput");
  }.bind(this));
}

.bind(this)는 “이 함수 안에서 사용할 this는 바깥쪽의 this로 고정해줘”라는 의미로 이해하면 됩니다.

해결 방법 2: 화살표 함수

화살표 함수는 자기만의 this를 새로 만들지 않고, 바깥쪽 this를 그대로 사용합니다. 

onSearch: function () {
  const numbers = [10, 20, 30];

  numbers.forEach((number) => {
    this.byId("idInput");
  });
}

위 예제에서 화살표 함수 안의 this는 바깥쪽 onSearch의 this를 그대로 사용합니다. 따라서 이 경우 this는 Controller를 가리킵니다.

.bind(this)와 화살표 함수 비교

방식 예시 특징
function () {}.bind(this) 일반 함수 뒤에 .bind(this) 사용 this를 직접 고정합니다. 오래된 UI5 코드에서 자주 볼 수 있습니다.
() => {} 화살표 함수 사용 바깥쪽 this를 그대로 사용합니다. 새로 작성하는 콜백에서 간단하고 읽기 쉽습니다.
실무 감각 새로 작성하는 콜백에서는 화살표 함수가 더 간단합니다. 하지만 기존 UI5 프로젝트를 읽을 때는 .bind(this)도 자주 보이므로 의미를 알아두어야 합니다.

Controller 메서드 자체를 화살표 함수로 만들지 마세요

// 권장하지 않음
onSearch: () => {
  this.getView();
}

Controller 메서드 자체를 화살표 함수로 만들면 this가 Controller를 가리키지 않을 수 있습니다.

가장 안전한 패턴 Controller 메서드는 function으로 작성하고, 그 안의 콜백은 화살표 함수로 작성합니다. 
onSearch: function () {
  const numbers = [10, 20, 30];

  numbers.forEach((number) => {
    this.byId("idInput");
  });
}

7장. UI5 Controller 함수 작성 기준 다시 정리하기

이제 중요한 내용을 다시 정리해보겠습니다. 이 장은 외우기 위한 요약이라기보다, 실습 전에 다시 확인하는 기준표에 가깝습니다.

1. Controller의 주요 함수는 function으로 작성합니다

onInit: function () {
  this.getView();
},

onSearch: function () {
  this.byId("idInput");
}

UI5가 직접 호출하는 Controller 메서드는 function 방식으로 작성하는 것이 안전합니다. 화면 초기화, 버튼 클릭, 저장, 삭제 같은 기능은 이 기준으로 작성하세요.

2. 내부 콜백은 화살표 함수를 자주 사용합니다

onSearch: function () {
  const items = [1, 2, 3];

  items.forEach((item) => {
    console.log(item);
    this.byId("idInput");
  });
}

콜백 안에서 Controller의 this를 사용해야 한다면 화살표 함수가 편리합니다.

3. 오래된 코드에서는 .bind(this)도 볼 수 있습니다

onSearch: function () {
  const items = [1, 2, 3];

  items.forEach(function (item) {
    console.log(item);
    this.byId("idInput");
  }.bind(this));
}

.bind(this)는 화살표 함수가 널리 쓰이기 전부터 사용하던 방식입니다. 새로 작성하는 코드에서는 화살표 함수가 더 간단하지만, 기존 프로젝트를 읽기 위해서는 알아두는 것이 좋습니다.

4. a() {} 문법은 나중에 익혀도 됩니다

onSearch() {
  this.getView();
}

이 문법도 사용할 수 있습니다. 다만 UI5를 처음 배우는 단계에서는 onSearch: function () {} 형태를 먼저 익히는 것이 좋습니다.

최종 권장 패턴

return Controller.extend("my.app.controller.Main", {
  onInit: function () {
    this._setViewModel();
  },

  onSearch: function () {
    const items = [1, 2, 3];

    items.forEach((item) => {
      console.log(item);
      this.byId("idInput");
    });
  },

  _setViewModel: function () {
    // Controller 내부에서 사용하는 보조 함수
  }
});
학생용 최종 문장 UI5 Controller를 처음 작성할 때는 Controller 메서드는 function, 그 안의 콜백은 () => {}로 시작하세요.

실습 전 체크리스트

  • View는 화면 모양을 담당하고, Controller는 화면 동작을 담당한다.
  • Controller 함수는 화면에서 발생하는 일을 처리하는 기능 블록이다.
  • on으로 시작하는 함수는 이벤트 처리 함수로 이해하면 좋다.
  • _로 시작하는 함수는 Controller 내부 보조 함수로 이해하면 좋다.
  • this는 항상 Controller가 아니다.
  • 콜백 함수 안에서 this를 사용할 때는 특히 조심한다.
  • 새로 작성하는 콜백에서는 화살표 함수가 간단하고 읽기 쉽다.
