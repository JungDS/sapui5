초급 디딤돌부터 백엔드 동기화, 그리고 Fragment 예외 처리까지

눈에 보이는 화면 값 vs 메모리의 Model 값

UI5 입문자가 자만하기 가장 좋은 순간은 "Input 상자에 타이핑했으니 바인딩된 변수도 즉시 바뀐다"고 믿을 때입니다. 화면에 적힌 글자는 검증을 통과하기 전까지는 실제 데이터 금고(Model)에 들어가지 못합니다.

Input 화면 값 (외면)

20

사용자가 타이핑 중인 가변 후보 상태.

Model 실제 값 (내면)

20

유효성 필터를 완벽히 통과한 확정 상태.

💡 핵심 패러다임 오류가 터졌을 때 화면에 빨간 선이 그어지는 현상은, 모델에 에러 데이터가 주입되었다는 뜻이 아닙니다. 반대로 "위험한 데이터라 모델 내부로 진입하지 못하게 프론트엔드가 문을 걸어 잠그고 입구를 통제한 상태"입니다.

체험형 가상 런타임 시뮬레이터

조건: Integer (정수 형태), 최소: 1, 최대: 120 제약 조건이 걸려있는 상태를 가상으로 만져봅니다.

나이 입력 필드 (정수형, 1 ~ 120)

현재 깨끗한 상태입니다. 정상 값 20이 모델과 동기화되어 있습니다.
처음 보는 UI5 필수 용어집 (클릭하여 펼치기)

• parseValue (해석 단계): 화면에 입력된 문자열을 컴퓨터 자료형(정수, 날짜 등)으로 해석하는 첫 번째 검문소입니다. 문자 입력 시 parseError가 터집니다.

• validateValue (검증 단계): 해석은 완료되었으나 비즈니스 규칙(Constraints: 최소/최대값)을 충족하는지 따지는 두 번째 검문소입니다. 범위를 넘어서면 validationError가 유발됩니다.

• Messaging (메시징 모듈): 위 검문소에서 적발된 에러 리포트들을 모아서 관리하고, 에러가 난 입력창에 경고 테두리를 매핑해 주는 UI5 전담 비서 모듈입니다.

실무 가드(Guard) 코드 장착하기

화면에 에러 테두리가 선명하게 켜져 있음에도, 아무 처리 없이 '저장' 버튼을 누르면 모델의 예전 정상 데이터가 백엔드로 전송되는 대참사가 일어납니다. 프론트엔드 단에서 통신 페이로드 송신을 원천 격리하는 인터셉터 코드를 심어야 합니다.

Main.controller.js (방어벽 설계 패턴)
sap.ui.define([
    "sap/ui/core/mvc/Controller",
    "sap/ui/core/Messaging",
    "sap/m/MessageBox"
], function (Controller, Messaging, MessageBox) {
    "use strict";

    return Controller.extend("demo.controller.Main", {
        onInit: function () {
            this.getView().setModel(Messaging.getMessageModel(), "message");
        },

        onSave: function () {
            var aMessages = Messaging.getMessageModel().getData();
            
            // 에러 장부 스캔 루프 개시
            var bHasError = aMessages.some(function (oMsg) {
                return oMsg.getType() === "Error";
            });

            if (bHasError) {
                MessageBox.error("미해결된 입력 오류가 존재합니다. 가드(Guard) 작동.");
                return; // 프로세스 전송 즉시 차단
            }

            MessageBox.success("안전지대 확인. 트랜잭션을 백엔드로 Submit 합니다.");
        }
    });
});

💡 시니어 벨류: handleValidation이 먹통이 되는 유일한 순간

현업 프로젝트 도중 주니어들이 사수 자리에 가장 많이 뛰어오는 지점이 있습니다. "사수님, manifest에 분명 설정을 켰는데 팝업창 입력 검증은 테두리가 안 쳐집니다!"

Fragment 팝업의 맹점 원인 분석
XML View와 달리 sap.m.Dialog나 Fragment로 띄우는 팝업 컴포넌트들은 UI5 프레임워크가 관리하는 메인 라이프사이클 컨텍스트 밖에 독립적으로 생성됩니다. 때문에 글로벌 선언형 옵션인 "handleValidation": true의 감시망을 유유히 벗어납니다.

이를 해결하려면 팝업을 동적으로 인스턴스화하는 컨트롤러 시점에 감시 비서(Messaging)를 수동으로 강제 바인딩해 줘야 합니다.

Main.controller.js (Fragment 수동 계약 패턴)
onOpenDialog: function () {
    var oView = this.getView();

    if (!this._pDialog) {
        this._pDialog = Fragment.load({
            id: oView.getId(),
            name: "demo.view.DetailDialog",
            controller: this
        }).then(function (oDialog) {
            oView.addDependent(oDialog);

            // [핵심] 독립된 팝업 오브젝트에 감시 체계를 수동으로 연결해 줍니다.
            Messaging.registerObject(oDialog, true); 
            return oDialog;
        });
    }
    this._pDialog.then(function(oDialog) { oDialog.open(); });
}

초보 개발자 지뢰밭 집중 분해 수첩

단순한 이론을 넘어 현업 부서에서 매일 발생하는 진짜 지뢰들을 선별했습니다.

지뢰 01

[취소]나 [초기화] 버튼을 눌러 데이터를 밀어버렸는데 빨간 선이 남는 현상

초보자들은 화면을 리셋할 때 oModel.setData({})를 호출합니다. 데이터 청소는 깔끔하게 끝나지만, 화면의 밸리데이션 테두리는 지워지지 않고 지저분하게 남아있습니다.

이유: UI5 프레임워크 사상에서 데이터 금고를 비우는 행위와 에러 비서(Messaging)가 들고 있는 장부를 찢어버리는 행위는 별개의 트랙입니다.

🛠 해결 코드: 초기화 함수 끝자락에 장부 전역 소거 API 코드를 동시 호출 처리하십시오.

Clear Handler 예시
onResetForm: function() {
    this.getView().getModel("view").setData({ Age: 20 }); // 모델 청소
    Messaging.removeAllMessages(); // [해결책] 중앙 에러 장부 소거 (테두리 즉시 증발)
}
지뢰 02

백엔드 서버 에러가 났을 때 테크니컬 네임으로 표시되는 가독성 문제

OData/RAP 아키텍처 상 백엔드 검증 로직에서 에러를 던지면, 팝오버 창에 필드 기술명인 [SeatsOcc] 값이 잘못되었습니다라고 흉측하게 뜨곤 합니다. 화면 Label에는 "예약석 수"라고 예쁘게 적혀있는데 말이죠.

해결 아키텍처: SAP 메타데이터 동기화 원리
ABAP 백엔드 설계 시 SE11 Dictionary 레벨이나 RAP의 데이터 엘리먼트 텍스트 룰에 한글 라벨(sap:label 속성)을 정확히 바인딩해 두면, UI5의 ODataMetaModel 분석기가 에러 발생 시 target 명칭을 실시간 분석하여 화면에 떠 있는 인간 친화적 Label 텍스트와 에러 문구를 자동으로 결합해 줍니다. 백엔드 테크니컬 컴플라이언스를 준수해야 하는 실무적 당위성입니다.
지뢰 03

서버 에러 페이로드는 수신되었으나 특정 Input 인터페이스와 연동 실패

브라우저 Network 탭에는 분명 400 에러와 리포트 내용이 잡히는데, 정작 화면의 해당 입력창에는 빨간 테두리가 매핑되지 않는 기이한 현상입니다.

🛠 디버깅 콘솔 추적 마스터 기법: 백엔드가 응답으로 보낸 "target": "/FlightSet(Carrid='AA')/SeatsOcc" 문자열 주소와 프론트엔드 UI 컨트롤의 바인딩 결합 정보 주소가 대소문자나 키값 하나까지 정확히 일치해야 자동 바인딩이 수행됩니다. 불일치가 의심될 때 브라우저 콘솔창(F12 -> Console)에 아래 마법의 한 줄 코드를 입력해 절대 경로를 정밀 대조하세요.

// 타겟 입력 컨트롤의 프론트엔드 실시간 결합 경로 추출법
