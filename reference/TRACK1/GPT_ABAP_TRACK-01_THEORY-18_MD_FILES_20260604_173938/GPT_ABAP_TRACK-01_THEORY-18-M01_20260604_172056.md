## 3. Global Class란 무엇인가?

### 3.1 쉬운 정의

Global Class는 SAP Repository에 독립 객체로 저장되는 ABAP Class이다.  
한 프로그램 안에서만 쓰는 임시 Class가 아니라, 여러 프로그램과 다른 Class에서 재사용할 수 있는 전역 객체이다.

예를 들어 다음과 같은 요구사항이 있다고 하자.

```text
사용자 상태를 조회한다.
상태 코드에 따라 설명을 반환한다.
사용자 목록을 출력한다.
```

이 로직을 Report 안에 전부 작성할 수도 있다.  
하지만 여러 프로그램에서 동일 로직이 필요하다면, Global Class로 분리하는 것이 유지보수에 유리하다.

```text
ZCL_JHY_USER_SERVICE
  ├─ 사용자 조회
  ├─ 사용자 상태 설명 반환
  └─ 사용자 목록 출력용 데이터 구성
```

### 3.2 SAP Repository Object로서의 의미

Global Class는 단순 코드 조각이 아니라 Repository Object이다.  
따라서 다음 관리 흐름을 가진다.

| 항목 | 의미 |
|---|---|
| Object Name | 예: `ZCL_JHY_OO_INTRO` |
| Package | 개발 객체가 소속되는 패키지 |
| Transport Request | 시스템 간 이송 대상 |
| Activation | 실행 가능한 활성 버전 생성 |
| Where-Used List | 다른 객체에서의 사용 위치 확인 |
| Version Management | 변경 이력 관리 |

즉, Global Class는 ABAP 개발에서 **재사용·운영·이송·영향분석**의 단위가 된다.

## 4. Local Class와 Global Class의 차이

ABAP에는 Local Class와 Global Class가 모두 존재한다.

| 구분 | Local Class | Global Class |
|---|---|---|
| 저장 위치 | 특정 프로그램 내부 | SAP Repository |
| 재사용 범위 | 해당 프로그램 내부 중심 | 여러 프로그램/클래스에서 재사용 가능 |
| 생성 도구 | ABAP Editor / ADT 코드 내부 | SE24 / ADT Class 생성 |
| Transport 관리 | 포함 프로그램과 함께 관리 | 독립 객체로 관리 |
| Where-Used 분석 | 제한적 | Repository 수준 분석 가능 |
| 실무 사용 | 프로그램 내부 보조 로직 | 공통 로직, 서비스, 유틸리티, 모델 객체 |

초급자는 다음 기준으로 판단하면 된다.

```text
한 프로그램 안에서만 쓰면 Local Class로 충분할 수 있다.
여러 객체에서 재사용하거나 독립적으로 관리해야 하면 Global Class를 검토한다.
```

## 5. Global Class의 기본 구조

Global Class는 크게 두 영역으로 이해할 수 있다.

```abap
CLASS zcl_jhy_oo_intro DEFINITION.
  "무엇을 제공할지 선언하는 영역
ENDCLASS.

CLASS zcl_jhy_oo_intro IMPLEMENTATION.
  "선언한 Method의 실제 로직을 작성하는 영역
ENDCLASS.
```

### 5.1 Definition 영역

Definition 영역은 Class의 외형과 계약을 정의한다.

여기에는 다음이 포함될 수 있다.

| 구성 요소 | 설명 |
|---|---|
| PUBLIC SECTION | 외부에서 접근 가능한 구성 요소 |
| PROTECTED SECTION | 상속 관계에서 접근 가능한 구성 요소 |
| PRIVATE SECTION | Class 내부에서만 접근 가능한 구성 요소 |
| METHODS | 객체가 수행할 동작 |
| CLASS-METHODS | Class 자체에 소속된 정적 동작 |
| DATA | Instance Attribute |
| CLASS-DATA | Static Attribute |
| INTERFACES | 구현할 Interface |

이번 모듈에서는 구조만 이해하고, Visibility와 Attribute/Method의 상세 설계는 다음 모듈에서 학습한다.

### 5.2 Implementation 영역

Implementation 영역은 Definition에서 선언한 Method의 실제 코드를 작성하는 곳이다.

예:

```abap
METHOD get_text.
  rv_text = 'Hello Global Class'.
ENDMETHOD.
```

초급자는 다음 관계를 기억하면 된다.

```text
Definition = 무엇이 있는지 선언
Implementation = 어떻게 동작하는지 구현
```

## 7. ADT에서 Global Class 생성하기

S/4HANA 개발에서는 Eclipse 기반 ADT를 자주 사용한다.  
특히 최신 ABAP 개발, CDS, RAP 학습으로 이어지려면 ADT 기반 Class 생성에 익숙해지는 것이 좋다.

### 7.1 생성 흐름

```text
1. Eclipse ADT 실행
2. ABAP Project 접속
3. Package 선택
4. New → ABAP Class 선택
5. Name 입력: ZCL_JHY_OO_INTRO
6. Description 입력: OO ABAP Intro Class
7. Superclass 또는 Interface는 기본값 또는 필요 시 선택
8. Finish
9. Definition / Implementation 코드 작성
10. Activate
11. Run As → ABAP Application 또는 ClassRun 실행
```

### 7.2 ADT ClassRun 실습의 장점

초급자에게 ADT의 `IF_OO_ADT_CLASSRUN` 방식은 유용하다.

이유는 다음과 같다.

| 장점 | 설명 |
|---|---|
| Report 없이 Class 자체 실행 가능 | OO 흐름을 중심으로 학습할 수 있다. |
| 출력 객체 제공 | `out->write( )`로 결과 확인 가능 |
| RAP/Modern ABAP 전환에 유리 | 후속 S/4HANA 개발 흐름과 연결된다. |
| 테스트가 간단함 | 작은 예제를 빠르게 실행할 수 있다. |

## 8. 실습: ADT 실행 가능한 Global Class 만들기

### 8.1 실습 목표

`ZCL_JHY_OO_INTRO` Global Class를 만들고, ADT에서 실행해 문자열을 출력한다.

### 8.2 Class 정의 예시

ADT에서 다음 형태의 Class를 작성한다.

```abap
CLASS zcl_jhy_oo_intro DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC.

  PUBLIC SECTION.
    INTERFACES if_oo_adt_classrun.

  PROTECTED SECTION.
  PRIVATE SECTION.

ENDCLASS.



CLASS zcl_jhy_oo_intro IMPLEMENTATION.

  METHOD if_oo_adt_classrun~main.

    out->write( 'Hello, Global Class.' ).
    out->write( 'This is the first OO ABAP class.' ).

  ENDMETHOD.

ENDCLASS.
```

### 8.3 코드 설명

| 코드 | 설명 |
|---|---|
| `CLASS ... DEFINITION` | Class의 외형을 정의한다. |
| `PUBLIC` | Repository에서 공개 Class로 정의한다. |
| `FINAL` | 상속을 허용하지 않는 Class로 정의한다. 상속은 후속 모듈에서 별도 학습한다. |
| `CREATE PUBLIC` | 외부에서 객체 생성을 허용한다. |
| `INTERFACES if_oo_adt_classrun` | ADT에서 실행 가능한 ClassRun Interface를 구현한다. |
| `METHOD if_oo_adt_classrun~main` | ClassRun 실행 시 호출되는 Method를 구현한다. |
| `out->write( )` | ADT Console에 값을 출력한다. |

이번 모듈에서 중요한 점은 `IF_OO_ADT_CLASSRUN` 자체를 깊게 이해하는 것이 아니다.  
중요한 것은 **Global Class가 정의 영역과 구현 영역을 가지며, 활성화 후 실행 가능한 Repository Object가 된다는 점**이다.

## 9. SE24 실습 대안

SAP GUI 중심 수업에서는 SE24로 Class를 생성한 후 Method를 정의할 수 있다.  
다만 `IF_OO_ADT_CLASSRUN` 실행은 ADT에서 더 자연스럽다.


예시 Method 개념:

```abap
METHOD get_message.

ENDMETHOD.
```

이 방식은 `THEORY-18-M02`에서 Method, Parameter, Visibility를 더 구체적으로 다룰 때 확장한다.

## 10. Global Class 생성 시 중요한 속성

### 10.1 Class Description

Description은 단순한 주석이 아니다.  
Repository Browser, ADT 검색, SE24 목록에서 객체의 목적을 파악하는 데 사용된다.

좋은 예:

```text
OO ABAP Intro Class for Training
```

나쁜 예:

```text
test
abc
class1
```

### 10.2 Package

교육용 객체는 `$TMP` Local Object로 저장할 수 있다.  
하지만 실무에서는 반드시 프로젝트 Package를 사용한다.

| 선택 | 의미 |
|---|---|
| `$TMP` | Local Object. Transport 대상 아님 |
| `Z...` Package | Transport Request와 연결되어 시스템 간 이송 가능 |

실무 기준으로는 다음을 항상 확인한다.

```text
이 Class는 개발 서버에서만 쓰는가?
품질/운영 시스템으로 이송되어야 하는가?
어떤 Package의 책임 영역에 속하는가?
```

### 10.3 Transport Request

Global Class를 Package에 저장하면 일반적으로 Transport Request가 필요하다.  
이는 Class가 다른 시스템으로 이동할 수 있는 개발 객체이기 때문이다.

초급자는 다음 정도로 이해하면 충분하다.

```text
Package에 저장하는 Repository Object는 Transport 관리 대상이 될 수 있다.
$TMP는 로컬 학습용이며 운영 이송 대상이 아니다.
```

### 10.4 Activation

Class를 저장만 해서는 다른 객체에서 안정적으로 사용할 수 없다.  
반드시 Syntax Check와 Activation을 수행해야 한다.

정상 흐름:

```text
Class 생성
→ 코드 작성
→ Syntax Check
→ Activate
→ 실행 또는 참조 테스트
```

## 11. Class 구조를 읽는 방법

초급자가 처음 Class 코드를 보면 길고 낯설게 느껴진다.  
하지만 다음 순서로 읽으면 된다.

```text
1. Class 이름을 확인한다.
2. PUBLIC / FINAL / CREATE PUBLIC 속성을 확인한다.
3. PUBLIC SECTION에 외부 공개 요소가 무엇인지 본다.
4. 구현한 Interface가 있는지 확인한다.
5. METHODS 선언을 확인한다.
6. IMPLEMENTATION에서 Method 실제 로직을 확인한다.
```

예제 Class를 기준으로 읽으면 다음과 같다.

```text
ZCL_JHY_OO_INTRO라는 Global Class가 있다.
상속은 일단 막아 둔 FINAL Class이다.
외부에서 객체 생성이 가능한 CREATE PUBLIC Class이다.
ADT ClassRun Interface를 구현한다.
실행 시 MAIN Method가 호출된다.
MAIN Method는 문자열 두 줄을 출력한다.
```

## 12. 정상 흐름과 오류 흐름

### 12.1 정상 흐름

```text
Class 이름 결정
→ SE24 또는 ADT에서 Class 생성
→ Description 입력
→ Package 선택
→ Public Section 구조 확인
→ 필요한 Interface 또는 Method 선언
→ Implementation 작성
→ Syntax Check
→ Activate
→ 실행 또는 호출 테스트
```

### 12.2 오류 흐름 1: 이름 규칙 위반

#### 증상

```text
Object name is not in customer namespace
```

#### 원인

고객 개발 객체인데 `Z` 또는 `Y` 네임스페이스를 사용하지 않았을 수 있다.

#### 해결

```text
ZCL_JHY_OO_INTRO
YCL_JHY_OO_INTRO
```

처럼 고객 네임스페이스를 사용한다.

---

### 12.3 오류 흐름 2: Interface Method 미구현

#### 증상

`IF_OO_ADT_CLASSRUN`을 선언했지만 `IF_OO_ADT_CLASSRUN~MAIN` Method를 구현하지 않았다.

#### 원인

Interface는 구현 계약이다.  
Interface에 정의된 Method를 Class에서 구현해야 한다.

#### 해결

다음 Method를 Implementation에 작성한다.

```abap
METHOD if_oo_adt_classrun~main.
  out->write( 'Hello, Global Class.' ).
ENDMETHOD.
```

---

### 12.4 오류 흐름 3: Syntax Check 실패

#### 증상

Activate가 실패하고 구문 오류가 표시된다.

#### 원인 예시

- 마침표 누락
- `ENDMETHOD` 누락
- Interface Method 이름 오타
- 작은따옴표 누락
- Definition과 Implementation의 Method 이름 불일치

#### 해결

오류 메시지를 더블클릭해 위치로 이동하고 수정한다.

---

### 12.5 오류 흐름 4: 활성화하지 않고 실행

#### 증상

변경한 코드가 실행되지 않거나, 실행 가능한 객체로 인식되지 않는다.

#### 원인

저장만 하고 Activate하지 않았다.

#### 해결

```text
Ctrl + F3
또는 Activate 버튼
```

으로 Class를 활성화한다.

---

### 12.6 오류 흐름 5: ADT 실행 메뉴가 보이지 않음

#### 증상

Class에서 Run As 실행 메뉴가 기대와 다르다.

#### 가능한 원인

- `IF_OO_ADT_CLASSRUN`을 구현하지 않았다.
- `MAIN` Method가 올바르게 구현되지 않았다.
- Class가 활성화되지 않았다.
- ADT 프로젝트 또는 시스템 릴리스 설정이 다르다.

#### 해결

다음을 확인한다.

```text
1. INTERFACES if_oo_adt_classrun 선언 여부
2. METHOD if_oo_adt_classrun~main 구현 여부
3. Class Activate 여부
4. ADT에서 Class를 다시 열고 실행
```

## 13. 실무 적용 기준

### 13.1 Global Class를 만드는 것이 좋은 경우

| 상황 | 이유 |
|---|---|
| 여러 프로그램에서 같은 로직을 재사용 | 중복 제거 |
| 업무 기능 단위가 명확함 | Service Class로 분리 가능 |
| 테스트 가능한 구조가 필요 | Method 단위 테스트 가능 |
| 상태와 동작을 함께 관리 | OO 설계 장점 활용 |
| 후속 RAP/CDS Service 로직으로 확장 | 현대 S/4HANA 개발과 연결 |

### 13.2 Global Class가 과한 경우

| 상황 | 판단 |
|---|---|
| 한 줄짜리 일회성 변환 | Local Method 또는 간단한 표현식으로 충분할 수 있음 |
| 특정 Report 안에서만 쓰는 보조 로직 | Local Class가 더 적절할 수 있음 |
| 재사용 가능성이 전혀 없음 | Repository Object 남발이 될 수 있음 |
| 교육용 단발 실습 | `$TMP` Local Object로 충분 |

### 13.3 실무 질문

Global Class를 만들기 전에 다음을 질문한다.

```text
이 로직은 여러 곳에서 재사용되는가?
객체 이름만 보고 책임을 알 수 있는가?
Class가 너무 많은 책임을 갖고 있지는 않은가?
Method 단위로 테스트 가능한가?
Package와 Transport 책임이 명확한가?
```

## 14. 초급자 안티패턴

### 14.1 모든 로직을 하나의 Class에 몰아넣기

나쁜 예:

```text
ZCL_JHY_ALL_PROCESS
```

이 Class가 조회, 계산, 출력, 저장, 메시지 처리, 권한 처리까지 모두 담당하면 유지보수가 어렵다.

좋은 방향:

```text
ZCL_JHY_USER_READER
ZCL_JHY_USER_VALIDATOR
ZCL_JHY_USER_REPORT_APP
```

단, 초급 단계에서는 과도하게 세분화하지 말고 “책임을 이름으로 설명할 수 있는가”부터 확인한다.

### 14.2 의미 없는 Class 이름 사용

나쁜 예:

```text
ZCL_TEST
ZCL_TEMP
ZCL_001
```

좋은 예:

```text
ZCL_JHY_OO_INTRO
ZCL_JHY_USER_SERVICE
ZCL_JHY_FLIGHT_READER
```

### 14.3 Public으로 전부 공개하기

초급자는 모든 Method와 Attribute를 Public에 두기 쉽다.  
하지만 외부에서 사용할 필요가 없는 요소는 공개하지 않는 것이 좋다.

이 내용은 다음 모듈인 `THEORY-18-M02 Attribute / Method / Visibility`에서 더 자세히 다룬다.

### 14.4 활성화 없이 테스트하기

ABAP Repository Object는 활성화가 중요하다.  
특히 Global Class는 다른 객체가 참조할 수 있으므로 Syntax Check와 Activate를 습관화해야 한다.

## 15. 실습 과제

### 15.1 기본 과제

다음 Class를 생성한다.

```text
Class Name: ZCL_JHY_OO_INTRO
Description: OO ABAP Intro Class for Training
Type: Global Class
Creation: Public
Final: Yes
Interface: IF_OO_ADT_CLASSRUN
```

구현할 출력:

```text
Hello, Global Class.
This is the first OO ABAP class.
```

### 15.2 제출 기록 양식

| 항목 | 기록 |
|---|---|
| Class 이름 | ZCL_JHY_OO_INTRO |
| 생성 도구 | SE24 / ADT |
| Package | $TMP 또는 프로젝트 Package |
| Interface | IF_OO_ADT_CLASSRUN |
| Activate 결과 | 성공 / 실패 |
| 실행 결과 | 출력 메시지 |
| 오류 메시지 | 발생 시 원문 기록 |
| 해결 방법 | 어떤 부분을 수정했는지 기록 |

### 15.3 확장 과제

다음 변경을 시도한다.

```text
1. 출력 메시지를 본인 이름 또는 교육명으로 변경한다.
2. Class Description을 더 명확하게 수정한다.
3. Syntax Error를 일부러 만들고 오류 메시지를 기록한다.
4. 오류를 수정한 뒤 다시 Activate한다.
```

주의: 실습 오류는 교육용 시스템에서만 수행한다.

## 16. 디버깅과 검증 포인트

Global Class를 처음 만들 때는 다음을 확인한다.

| 검증 항목 | 확인 방법 |
|---|---|
| Class 존재 여부 | SE24 또는 ADT 검색 |
| 활성화 여부 | Object 상태 확인 |
| Interface 구현 여부 | Definition 영역의 `INTERFACES` 확인 |
| Method 구현 여부 | Implementation 영역의 Method 확인 |
| 실행 가능 여부 | ADT Run As 또는 테스트 호출 |
| 출력 결과 | Console 또는 실행 결과 확인 |
| 오류 메시지 | Syntax Check 결과 확인 |

디버깅은 후속 모듈에서 더 자세히 다룰 수 있으나, 이 단계에서는 Breakpoint를 `MAIN` Method 안에 두고 실행 흐름이 진입하는지 확인해보면 좋다.

## 17. 평가 문제

### 17.1 객관식

#### Q1. Global Class에 대한 설명으로 가장 적절한 것은?

A. 특정 Report 안에서만 존재하는 임시 Class이다.  
B. SAP Repository에 저장되어 여러 객체에서 재사용할 수 있는 Class이다.  
C. 데이터베이스 테이블을 직접 저장하는 객체이다.  
D. Selection Screen의 입력 필드를 정의하는 객체이다.

정답: B

#### Q2. Definition 영역의 주된 역할은?

A. 실제 SQL 실행 결과를 저장한다.  
B. Class의 외형과 공개/비공개 구성 요소를 선언한다.  
C. Transport Request를 생성한다.  
D. 데이터베이스 인덱스를 생성한다.

정답: B

#### Q3. `IF_OO_ADT_CLASSRUN`을 사용하는 주된 이유는?

A. DDIC Table을 자동 생성하기 위해서  
B. ADT에서 Class를 간단히 실행하고 결과를 확인하기 위해서  
C. SAP GUI 메뉴를 변경하기 위해서  
D. Transport Request를 자동 릴리즈하기 위해서

정답: B

---

### 17.2 단답형

#### Q1. Local Class와 Global Class의 차이를 설명하시오.

모범 답안:  
Local Class는 특정 프로그램 내부에 정의되어 주로 해당 프로그램 안에서 사용된다. Global Class는 SAP Repository에 독립 객체로 저장되며 여러 프로그램이나 다른 Class에서 재사용할 수 있고, Package와 Transport 관리 대상이 될 수 있다.

#### Q2. Definition과 Implementation의 차이를 설명하시오.

모범 답안:  
Definition은 Class가 어떤 Attribute, Method, Interface, Visibility 구조를 가지는지 선언하는 영역이다. Implementation은 선언한 Method의 실제 실행 로직을 작성하는 영역이다.

#### Q3. Global Class를 만든 후 Activate가 필요한 이유는?

모범 답안:  
저장된 소스가 실제 런타임에서 사용할 수 있는 활성 버전으로 반영되어야 다른 객체에서 참조하거나 실행할 수 있기 때문이다.

## 18. 강사용 설명 포인트

강의 시 다음 흐름으로 설명하면 초급자의 이해가 빠르다.

```text
기존 Report 중심 개발
→ 로직 중복 문제
→ 재사용 가능한 단위 필요
→ Global Class 등장
→ Definition / Implementation 구조
→ SE24와 ADT 생성 흐름
→ ClassRun으로 실행 확인
```

강조할 메시지:

```text
OO ABAP은 문법을 외우는 과정이 아니라,
로직의 책임을 이름 있는 객체로 분리하는 사고방식이다.
```

또한 초급 과정에서는 상속, 인터페이스, 다형성을 한꺼번에 깊게 설명하지 않는다.  
이번 모듈에서는 “Class라는 Repository Object를 만들고 구조를 읽을 수 있다”가 목표이다.

## 19. 핵심 요약

```text
Global Class는 SAP Repository에 저장되는 재사용 가능한 ABAP Class이다.
SE24와 ADT에서 생성할 수 있다.
Class는 Definition 영역과 Implementation 영역으로 나뉜다.
Definition은 외형과 계약을 선언하고, Implementation은 실제 로직을 작성한다.
IF_OO_ADT_CLASSRUN을 구현하면 ADT에서 간단히 Class를 실행할 수 있다.
저장 후에는 반드시 Syntax Check와 Activate를 수행해야 한다.
Global Class는 Package, Transport, Where-Used, Version 관리 대상이 될 수 있다.
```
