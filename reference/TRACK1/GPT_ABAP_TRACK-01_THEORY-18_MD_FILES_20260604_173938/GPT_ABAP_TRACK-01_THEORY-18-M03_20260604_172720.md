## 0. 이 문서의 학습 범위

이 문서는 `THEORY-18-M03 — Constructor와 객체 초기화`만 다룬다.

이번 모듈의 핵심은 **객체가 생성되는 순간 필요한 초기 상태를 어떻게 안전하게 보장할 것인가**이다. 앞선 모듈에서 Attribute, Method, Public/Protected/Private Visibility를 배웠다면, 이제 그 Attribute들이 언제 어떤 값으로 채워지는지 이해해야 한다.

OO ABAP에서 객체는 단순히 Class 이름으로 선언한다고 바로 사용할 수 있는 것이 아니다. Reference Variable을 선언하고, 실제 Instance를 생성해야 하며, 생성 과정에서 Constructor가 실행되어 객체의 초기 상태를 만든다.

이번 모듈에서는 다음을 깊게 다룬다.

| 주제 | 학습 범위 |
|---|---|
| Constructor | 객체 생성 시 자동으로 실행되는 초기화 Method |
| CREATE OBJECT | 전통적인 객체 생성 구문 |
| NEW | 최신 ABAP에서 자주 사용하는 Constructor Expression |
| 객체 초기화 | Attribute를 유효한 기본 상태로 만드는 설계 행위 |
| 초기화 오류 | 필수 입력 누락, 잘못된 값, Reference 미생성 오류 |
| 실무 기준 | Constructor에 무엇을 넣고 무엇을 넣지 말아야 하는지 판단 |

아직 다음 주제들은 깊게 다루지 않는다.

| 후속 모듈 | 이 문서에서의 처리 수준 |
|---|---|

| Inheritance / Redefinition | Superclass Constructor 호출 흐름은 맛보기 수준으로만 언급 |
| Dependency Injection | 실무 설계 관점에서 개념만 소개하고 심화는 후속 OO 설계로 위임 |

## 3. Constructor란 무엇인가?

### 3.1 쉬운 정의

Constructor는 객체가 생성될 때 자동으로 실행되는 특수 Method이다.

일반 Method는 개발자가 명시적으로 호출해야 실행된다.

```abap
lo_user->set_name( 'KIM' ).
```

반면 Constructor는 객체 생성 구문이 실행될 때 자동으로 호출된다.

```abap
CREATE OBJECT lo_user.
```

또는 최신 문법에서는 다음처럼 객체를 생성할 수 있다.

```abap
lo_user = NEW zcl_gpt_user( ).
```

두 경우 모두 Class에 `constructor` Method가 정의되어 있으면 객체 생성 시점에 Constructor가 실행된다.

### 3.2 왜 Constructor가 필요한가?

객체에는 Attribute가 있다. Attribute는 객체가 기억하는 상태이다.

예를 들어 사용자 객체가 다음 Attribute를 가진다고 하자.

| Attribute | 의미 |
|---|---|
| `mv_user_id` | 사용자 ID |
| `mv_user_name` | 사용자명 |
| `mv_status` | 상태 |

이 객체는 최소한 사용자 ID가 있어야 의미가 있을 수 있다. 사용자 ID 없이 사용자 객체를 만들면, 이후 Method가 정상적으로 동작하기 어렵다.

Constructor는 이런 문제를 방지한다.

```text
객체가 만들어지는 순간 필수 상태를 받는다.
받은 값을 검증한다.
Private Attribute에 저장한다.
객체가 유효한 상태로 출발하도록 보장한다.
```

## 4. Reference Variable과 Instance 생성

OO ABAP 초급자가 가장 먼저 구분해야 할 것은 **참조 변수 선언**과 **객체 생성**이다.

### 4.1 Reference Variable 선언

다음 코드는 Reference Variable을 선언한다.

```abap
DATA lo_user TYPE REF TO zcl_gpt_user.
```

이 시점에는 아직 객체가 만들어지지 않았다. `LO_USER`는 객체를 담는 변수가 아니라, 객체를 가리킬 수 있는 Reference Variable이다.

비유하면 다음과 같다.

```text
DATA lo_user TYPE REF TO zcl_gpt_user.
= 자동차 키를 둘 자리만 만든 상태
= 실제 자동차는 아직 없음
```

### 4.2 객체 생성

객체를 실제로 만들려면 생성 구문이 필요하다.

```abap
CREATE OBJECT lo_user.
```

또는 다음처럼 쓸 수 있다.

```abap
lo_user = NEW zcl_gpt_user( ).
```

이때 실제 Instance가 메모리에 생성되고, Constructor가 있으면 Constructor가 실행된다.

### 4.3 생성하지 않은 객체 사용 오류

객체를 만들지 않고 Instance Method를 호출하면 오류가 발생한다.

```abap
DATA lo_user TYPE REF TO zcl_gpt_user.

lo_user->display( ). " 객체 생성 전 호출: 오류 가능
```

이런 상황은 흔히 Null Reference 또는 Initial Reference 관련 Runtime Error로 이어질 수 있다.

초급자는 다음 순서를 습관화해야 한다.

```text
1. Reference Variable 선언
2. 객체 생성
3. Method 호출
```

## 5. Constructor의 선언과 구현

### 5.1 Class Definition 예시

다음은 Constructor를 가진 간단한 Class 예시이다.

```abap
CLASS zcl_gpt_user DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC.

  PUBLIC SECTION.
    METHODS constructor
      IMPORTING
        iv_user_id   TYPE string
        iv_user_name TYPE string.

    METHODS get_display_text
      RETURNING VALUE(rv_text) TYPE string.

  PRIVATE SECTION.
    DATA mv_user_id   TYPE string.
    DATA mv_user_name TYPE string.
ENDCLASS.
```

여기서 중요한 점은 다음이다.

| 코드 | 의미 |
|---|---|
| `METHODS constructor` | Constructor 선언 |
| `IMPORTING` | 객체 생성 시 전달받을 값 |
| `mv_user_id` | Constructor에서 초기화할 Private Attribute |
| `CREATE PUBLIC` | 외부에서 이 Class의 객체를 생성할 수 있음 |

### 5.2 Class Implementation 예시

```abap
CLASS zcl_gpt_user IMPLEMENTATION.

  METHOD constructor.
    mv_user_id   = iv_user_id.
    mv_user_name = iv_user_name.
  ENDMETHOD.

  METHOD get_display_text.
    rv_text = |{ mv_user_id } - { mv_user_name }|.
  ENDMETHOD.

ENDCLASS.
```

Constructor는 일반 Method처럼 `METHOD constructor.`와 `ENDMETHOD.` 사이에 구현한다. 다만 일반 Method와 달리 객체 생성 시점에 자동 호출된다.

## 6. CREATE OBJECT 기본 사용법

### 6.1 Parameter가 없는 Constructor

Constructor가 없거나 Parameter가 없는 Constructor라면 다음처럼 생성할 수 있다.

```abap
DATA lo_user TYPE REF TO zcl_gpt_user.

CREATE OBJECT lo_user.
```

### 6.2 Parameter가 있는 Constructor

Constructor에 Importing Parameter가 있으면 객체 생성 시 값을 전달해야 한다.

```abap
DATA lo_user TYPE REF TO zcl_gpt_user.

CREATE OBJECT lo_user
  EXPORTING
    iv_user_id   = 'U0001'
    iv_user_name = 'Kim Developer'.
```

여기서 `EXPORTING`은 객체 생성 구문에서 Constructor의 Importing Parameter로 값을 넘긴다는 의미이다.

초급자가 헷갈릴 수 있는 부분은 다음이다.

```text
Constructor Method 입장에서는 IMPORTING
CREATE OBJECT 호출 입장에서는 EXPORTING
```

즉, 호출하는 쪽에서 값을 내보내고, Constructor는 그 값을 받아온다.

### 6.3 CREATE OBJECT의 실무적 의미

`CREATE OBJECT`는 전통적인 ABAP Objects 객체 생성 구문이다. 기존 프로젝트, 오래된 코드, SAP GUI 중심의 Class 학습 자료에서 자주 볼 수 있다.

따라서 최신 문법 `NEW`를 사용하더라도, `CREATE OBJECT`를 읽을 줄 알아야 한다.

## 7. NEW Constructor Expression

### 7.1 기본 형태

최신 ABAP에서는 `NEW`를 사용해 객체를 더 간결하게 생성할 수 있다.

```abap
DATA(lo_user) = NEW zcl_gpt_user(
  iv_user_id   = 'U0001'
  iv_user_name = 'Kim Developer'
).
```

이 코드는 Reference Variable 선언과 객체 생성을 한 번에 처리한다.

### 7.2 기존 방식과 비교

| 구분 | CREATE OBJECT | NEW |
|---|---|---|
| 스타일 | 전통적 구문 | 표현식 기반 최신 구문 |
| 선언 | 보통 별도 DATA 선언 | 인라인 선언과 함께 자주 사용 |
| 가독성 | 오래된 코드에서 익숙함 | 짧고 명확함 |
| 학습 필요성 | 기존 코드 이해에 필수 | 현대 ABAP 작성에 유용 |

예를 비교하면 다음과 같다.

```abap
DATA lo_user TYPE REF TO zcl_gpt_user.

CREATE OBJECT lo_user
  EXPORTING
    iv_user_id   = 'U0001'
    iv_user_name = 'Kim Developer'.
```

```abap
DATA(lo_user) = NEW zcl_gpt_user(
  iv_user_id   = 'U0001'
  iv_user_name = 'Kim Developer'
).
```

두 코드는 핵심적으로 같은 목적을 가진다.

```text
ZCL_GPT_USER 객체를 만들고 Constructor에 초기값을 전달한다.
```

### 7.3 초급자에게 권장하는 학습 순서

초급자는 다음 순서를 추천한다.

```text
1. DATA ... TYPE REF TO ... 로 Reference Variable을 먼저 이해한다.
2. CREATE OBJECT로 객체 생성 흐름을 명확히 익힌다.
3. NEW로 같은 내용을 간결하게 작성해 본다.
4. 기존 코드에서는 CREATE OBJECT를 읽고, 신규 코드에서는 NEW를 점진적으로 사용한다.
```

## 8. Constructor에서 초기화해야 하는 것

Constructor에는 객체가 정상적으로 출발하기 위해 반드시 필요한 초기 상태를 넣는 것이 좋다.

### 8.1 좋은 초기화 대상

| 대상 | 예시 | 이유 |
|---|---|---|
| 필수 식별자 | 사용자 ID, 주문번호, 항공사 코드 | 객체의 정체성을 결정 |
| 기본 상태 | Active, New, Initial | 객체의 기본 동작 기준 |
| 설정값 | 최대 처리 건수, 표시 옵션 | 객체 동작의 초기 규칙 |
| 의존 객체 Reference | Logger, Validator | 객체가 책임을 수행하는 데 필요 |

### 8.2 예시: 필수 사용자 ID 초기화

```abap
METHOD constructor.
  IF iv_user_id IS INITIAL.
    RAISE EXCEPTION TYPE cx_sy_illegal_argument.
  ENDIF.

  mv_user_id   = iv_user_id.
  mv_user_name = iv_user_name.
  mv_status    = 'A'.
ENDMETHOD.
```

이 예시는 사용자 ID가 없으면 객체를 만들지 않겠다는 의도를 가진다. 실제 프로젝트에서는 전용 Exception Class를 만들 수 있지만, Exception Class 심화는 `THEORY-18-M06`에서 다룬다.

### 8.3 Constructor에 넣지 않는 것이 좋은 것

Constructor에 모든 로직을 넣는 것은 좋지 않다.

| 피해야 할 처리 | 이유 |
|---|---|
| 대량 DB 조회 | 객체 생성 자체가 느려짐 |
| 장시간 외부 RFC/OData 호출 | 생성 실패와 성능 문제가 커짐 |
| 복잡한 업무 처리 전체 | Constructor 책임이 과도해짐 |
| 사용자 화면 출력 | 객체 생성과 UI 처리가 섞임 |
| 불필요한 COMMIT WORK | 트랜잭션 제어가 예측 불가해짐 |

Constructor는 객체를 “사용 가능한 초기 상태”로 만드는 데 집중해야 한다. 복잡한 업무 실행은 별도 Public Method로 분리하는 것이 더 명확하다.

## 9. 객체 초기화 설계 기준

### 9.1 필수값과 선택값 구분

Constructor Parameter를 설계할 때는 필수값과 선택값을 구분해야 한다.

예를 들어 사용자 객체에서 `USER_ID`는 필수이고, `USER_NAME`은 나중에 조회할 수 있다고 가정할 수 있다.

```abap
METHODS constructor
  IMPORTING
    iv_user_id   TYPE string
    iv_user_name TYPE string OPTIONAL.
```

이때 설계자는 다음을 판단해야 한다.

```text
USER_ID 없이 객체가 의미 있는가?
USER_NAME 없이도 객체가 생성될 수 있는가?
초기 생성 시 STATUS는 외부에서 받는가, 내부 기본값으로 정하는가?
```

### 9.2 기본값을 어디서 정할 것인가?

상태 기본값을 `A`로 정한다고 하자.

방법 1: Constructor 내부에서 기본값 지정

```abap
METHOD constructor.
  mv_user_id = iv_user_id.
  mv_status  = 'A'.
ENDMETHOD.
```

방법 2: Parameter 기본값 사용

```abap
METHODS constructor
  IMPORTING
    iv_user_id TYPE string
    iv_status  TYPE c DEFAULT 'A'.
```

두 방식 모두 가능하지만, 실무에서는 기본값의 의미와 변경 가능성을 고려해야 한다.

| 기준 | Constructor 내부 기본값 | Parameter 기본값 |
|---|---|---|
| 외부 호출 단순성 | 좋음 | 좋음 |
| 기본값 노출 | 구현부를 봐야 함 | Signature에서 보임 |
| 변경 영향 | 구현 변경 | 호출부 의도와 연결 |
| 교육용 이해 | 내부 대입이 쉬움 | Signature 학습에 좋음 |

초급 과정에서는 둘 다 경험하되, “기본값도 설계 결정”이라는 점을 기억해야 한다.

## 10. Constructor와 Visibility

Constructor도 Visibility의 영향을 받는다.

### 10.1 Public Constructor

가장 일반적인 형태는 Public Constructor이다.

```abap
CLASS zcl_gpt_user DEFINITION
  PUBLIC
  CREATE PUBLIC.

  PUBLIC SECTION.
    METHODS constructor.
ENDCLASS.
```

이 경우 외부 프로그램에서 객체를 생성할 수 있다.

```abap
DATA(lo_user) = NEW zcl_gpt_user( ).
```

### 10.2 Private Constructor

Constructor를 Private으로 두거나 Class 생성 속성을 제한하면 외부에서 직접 객체를 만들 수 없다.

이런 설계는 Factory Method나 Singleton Pattern에서 사용할 수 있지만, 초급 단계에서는 개념만 이해한다.

```text
외부에서 아무나 객체를 만들지 못하게 제한하고,
정해진 생성 Method를 통해서만 객체를 만들게 하는 설계가 가능하다.
```

다만 이 주제는 OO 설계 심화에 해당하므로 이번 모듈에서는 Public Constructor를 기준으로 실습한다.

```text
2. Constructor에서 오류 메시지 또는 Exception 설계를 명확히 한다.
3. 예외 처리는 후속 Exception Class 모듈에서 체계적으로 다룬다.
```

### 11.5 오류 흐름 4: Constructor에 과도한 로직 포함

## 13. 실습: 사용자 객체 Constructor 만들기

### 13.1 실습 목표

Global Class `ZCL_GPT_USER`에 Constructor를 만들고, 객체 생성 시 사용자 ID와 사용자명을 초기화한다.

### 13.2 Class Definition

```abap
CLASS zcl_gpt_user DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC.

  PUBLIC SECTION.
    METHODS constructor
      IMPORTING
        iv_user_id   TYPE string
        iv_user_name TYPE string.

    METHODS get_display_text
      RETURNING VALUE(rv_text) TYPE string.

  PRIVATE SECTION.
    DATA mv_user_id   TYPE string.
    DATA mv_user_name TYPE string.
    DATA mv_status    TYPE c LENGTH 1.
ENDCLASS.
```

### 13.3 Class Implementation

```abap
CLASS zcl_gpt_user IMPLEMENTATION.

  METHOD constructor.
    IF iv_user_id IS INITIAL.
      RAISE EXCEPTION TYPE cx_sy_illegal_argument.
    ENDIF.

    mv_user_id   = iv_user_id.
    mv_user_name = iv_user_name.
    mv_status    = 'A'.
  ENDMETHOD.

  METHOD get_display_text.
    rv_text = |User: { mv_user_id }, Name: { mv_user_name }, Status: { mv_status }|.
  ENDMETHOD.

ENDCLASS.
```

### 13.4 테스트 Report — CREATE OBJECT 방식

```abap
REPORT zgpt_test_constructor_01.

DATA lo_user TYPE REF TO zcl_gpt_user.
DATA lv_text TYPE string.

CREATE OBJECT lo_user
  EXPORTING
    iv_user_id   = 'U0001'
    iv_user_name = 'Kim Developer'.

lv_text = lo_user->get_display_text( ).

WRITE: / lv_text.
```

### 13.5 테스트 Report — NEW 방식

```abap
REPORT zgpt_test_constructor_02.

DATA(lo_user) = NEW zcl_gpt_user(
  iv_user_id   = 'U0002'
  iv_user_name = 'Lee Consultant'
).

DATA(lv_text) = lo_user->get_display_text( ).

WRITE: / lv_text.
```

### 13.6 기대 결과

```text
User: U0001, Name: Kim Developer, Status: A
```

또는

```text
User: U0002, Name: Lee Consultant, Status: A
```

결과에서 중요한 것은 `STATUS` 값을 호출부에서 넘기지 않았는데도 `A`로 설정되었다는 점이다. 이 값은 Constructor 내부에서 초기화되었다.

## 14. Constructor 설계의 실무 원칙

### 14.1 Constructor는 객체의 유효성을 보장해야 한다

객체가 생성된 직후부터 최소한의 유효한 상태여야 한다.

나쁜 예:

```abap
DATA(lo_user) = NEW zcl_gpt_user( ).
lo_user->set_user_id( 'U0001' ).
lo_user->set_user_name( 'Kim Developer' ).
```

이 방식은 Setter를 호출하기 전까지 객체가 불완전한 상태일 수 있다.

좋은 예:

```abap
DATA(lo_user) = NEW zcl_gpt_user(
  iv_user_id   = 'U0001'
  iv_user_name = 'Kim Developer'
).
```

객체 생성과 동시에 필수값을 전달하므로 더 안전하다.

### 14.2 Constructor Parameter는 너무 많지 않게 한다

Constructor Parameter가 너무 많으면 객체 생성이 복잡해진다.

나쁜 예:

```abap
DATA(lo_user) = NEW zcl_gpt_user(
  iv_user_id      = 'U0001'
  iv_user_name    = 'Kim'
  iv_status       = 'A'
  iv_department   = 'IT'
  iv_phone        = '010...'
  iv_email        = 'a@b.com'
  iv_created_by   = sy-uname
  iv_created_on   = sy-datum
  iv_changed_by   = sy-uname
  iv_changed_on   = sy-datum
).
```

Parameter가 많다면 별도 Structure를 사용하거나, 필수값만 Constructor로 받고 나머지는 Method로 설정하는 방식을 검토한다.

### 14.3 Constructor에 DB 접근을 넣을 때는 신중히 판단한다

실무에서 Constructor가 DB에서 데이터를 읽어 객체를 완성하는 경우도 있다. 하지만 초급 단계에서는 다음을 원칙으로 둔다.

```text
Constructor에서 DB 접근은 가능하지만 기본값처럼 사용하지 않는다.
객체 생성이 예상보다 느려질 수 있다.
테스트와 오류 처리가 어려워질 수 있다.
```

예를 들어 사용자 ID를 넘기면 Constructor가 DB에서 사용자명을 읽어오는 설계가 가능하다. 하지만 이 경우 객체 생성과 데이터 조회 책임이 섞일 수 있으므로 Service Method나 Factory Method로 분리하는 것이 더 적절할 수 있다.

### 14.4 Constructor에서 화면 출력을 하지 않는다

나쁜 예:

```abap
METHOD constructor.
  WRITE: / 'Object created'.
ENDMETHOD.
```

Constructor는 객체 초기화가 목적이다. 화면 출력은 별도 Method나 호출 프로그램에서 처리하는 것이 좋다.

## 15. CREATE PUBLIC과 객체 생성 권한

Class Definition의 `CREATE PUBLIC`은 외부에서 객체를 생성할 수 있음을 의미한다.

```abap
CLASS zcl_gpt_user DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC.
```

초급 단계에서는 대부분 `CREATE PUBLIC`으로 실습한다.

하지만 실무에서는 다음과 같은 설계도 가능하다.

| 생성 제어 | 의미 | 사용 예 |
|---|---|---|
| CREATE PUBLIC | 외부에서 자유롭게 생성 가능 | 일반 Service, Helper Class |
| CREATE PROTECTED | 상속 관계에서 제한적으로 생성 | 상속 설계 |
| CREATE PRIVATE | Class 내부에서만 생성 | Singleton, Factory Pattern |

이번 모듈에서는 `CREATE PUBLIC` 중심으로 이해한다. `CREATE PRIVATE`과 Factory Pattern은 후속 OO 설계 심화에서 다루는 것이 적절하다.

## 16. Constructor와 Static Constructor 맛보기

ABAP Objects에는 Instance Constructor와 Static Constructor가 있다.

| 구분 | 실행 시점 | 목적 |
|---|---|---|
| Instance Constructor | 객체 Instance가 생성될 때 | 개별 객체 상태 초기화 |
| Static Constructor | Class가 처음 사용될 때 | Class 공통 상태 초기화 |

이번 모듈에서 다루는 Constructor는 Instance Constructor이다.

```abap
METHODS constructor.
```

Static Constructor는 다음처럼 선언한다.

```abap
CLASS-METHODS class_constructor.
```

하지만 Static Method와 Static Attribute는 다음 모듈 `THEORY-18-M04`에서 더 자세히 다루므로, 여기서는 차이만 기억한다.

```text
constructor는 객체마다 실행된다.
class_constructor는 Class 차원에서 실행된다.
```

## 17. 후속 주제와의 연결

Constructor는 OO ABAP의 여러 후속 개념과 연결된다.

| 후속 주제 | Constructor와의 연결 |
|---|---|
| Static Method / Instance Method | 객체가 필요한 Method와 필요 없는 Method를 구분한다. |
| Interface | 객체 생성 후 Interface Reference로 사용할 수 있다. |
| Exception Class | Constructor에서 잘못된 초기값을 Exception으로 처리할 수 있다. |
| Inheritance | Subclass 생성 시 Superclass Constructor 관계를 이해해야 한다. |
| ALV / Gateway / RAP | Service 객체, Handler 객체, Model 객체 초기화에 활용된다. |

실무 ABAP에서는 다음과 같은 객체를 만들 때 Constructor 설계가 중요하다.

```text
ALV 출력 Service 객체
Open SQL 조회 Repository 객체
Gateway Data Provider 보조 Class
RAP Behavior 구현 보조 Class
검증 Validator 객체
메시지 Collector 객체
```

## 19. 실무 안티패턴

### 19.1 빈 객체를 만든 뒤 Setter로 모두 채우기

```abap
DATA(lo_user) = NEW zcl_gpt_user( ).
lo_user->set_user_id( 'U0001' ).
lo_user->set_user_name( 'Kim' ).
lo_user->set_status( 'A' ).
```

객체가 한동안 불완전한 상태로 존재할 수 있다. 필수값은 Constructor로 받는 것이 더 안전하다.

### 19.2 Constructor에서 모든 업무를 실행하기

```abap
METHOD constructor.
  SELECT * FROM zt_big_table INTO TABLE mt_data.
  me->calculate_all( ).
  me->save_result( ).
ENDMETHOD.
```

객체 생성 자체가 업무 실행이 되어버린다. 테스트, 재사용, 성능 측면에서 좋지 않다.

### 19.3 Constructor Parameter 이름을 불명확하게 짓기

나쁜 예:

```abap
METHODS constructor
  IMPORTING
    iv_a TYPE string
    iv_b TYPE string.
```

좋은 예:

```abap
METHODS constructor
  IMPORTING
    iv_user_id   TYPE string
    iv_user_name TYPE string.
```

### 19.4 Public Attribute를 Constructor 대신 직접 변경하게 하기

나쁜 예:

```abap
DATA(lo_user) = NEW zcl_gpt_user( ).
lo_user->mv_user_id = 'U0001'.
```

Attribute를 Public으로 열어두면 객체 상태 보호가 어려워진다. Private Attribute와 Constructor / Public Method를 통해 제어하는 것이 좋다.

### 20.2 서술형

#### Q1. Reference Variable 선언과 객체 생성의 차이를 설명하시오.

모범 답안: Reference Variable 선언은 객체를 가리킬 수 있는 변수를 만드는 것이며, 실제 객체가 생성되는 것은 아니다. 객체 생성은 `CREATE OBJECT` 또는 `NEW`를 통해 메모리에 Instance를 만들고 Reference Variable이 그 Instance를 가리키게 하는 과정이다.

#### Q2. Constructor Parameter를 사용하는 이유를 설명하시오.

모범 답안: 객체가 생성되는 순간 필요한 초기값을 전달하여 객체가 유효한 상태로 시작하도록 하기 위해 사용한다. 필수값을 Constructor에서 받으면 불완전한 객체 생성을 줄이고, 초기화 책임을 명확히 할 수 있다.

#### Q3. `CREATE OBJECT`와 `NEW`의 차이를 설명하시오.

모범 답안: 둘 다 객체를 생성하는 방식이다. `CREATE OBJECT`는 전통적인 ABAP Objects 생성 구문이고, `NEW`는 표현식 기반의 현대 ABAP 생성 방식이다. `NEW`는 인라인 선언과 함께 간결하게 사용할 수 있지만, 기존 코드 이해를 위해 `CREATE OBJECT`도 알아야 한다.

| [ ] | `CREATE OBJECT`로 Parameter 있는 Constructor를 호출할 수 있다. |

| [ ] | Constructor에서 Private Attribute를 초기화할 수 있다. |
| [ ] | 객체 생성 전 Instance Method 호출 오류를 설명할 수 있다. |
| [ ] | Constructor에 넣어도 되는 로직과 피해야 할 로직을 구분할 수 있다. |
| [ ] | Debugger로 Constructor 진입을 확인할 수 있다. |

## 22. 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
Constructor는 객체 생성 시 자동 실행되는 초기화 Method이다.
Reference Variable 선언만으로는 객체가 생성되지 않는다.
CREATE OBJECT와 NEW는 객체를 생성하는 두 가지 대표 방식이다.
Constructor Parameter를 통해 필수 초기값을 객체에 전달할 수 있다.
Constructor는 객체를 유효한 초기 상태로 만드는 데 집중해야 한다.
무거운 DB 조회, 화면 출력, 트랜잭션 제어를 Constructor에 남발하지 않는다.
```

OO ABAP 실무에서 Constructor를 잘 설계하면 객체가 불완전한 상태로 사용되는 위험을 줄이고, Class의 책임과 사용법을 더 명확하게 만들 수 있다.
