## 3. F4 Help란 무엇인가?

F4 Help는 사용자가 입력 필드에서 가능한 값을 선택할 수 있도록 돕는 SAP의 표준 입력 도움말이다.

예를 들어 항공사 코드 입력 필드가 있다고 하자.

```abap
PARAMETERS p_carrid TYPE scarr-carrid.
```

사용자는 `AA`, `LH`, `SQ` 같은 코드를 외워서 입력할 수도 있지만, 실무 화면에서는 가능한 값을 선택할 수 있어야 한다. 이때 F4 Help를 제공하면 사용자는 값 목록과 설명을 보고 선택할 수 있다.

F4 Help의 역할은 다음과 같다.

| 역할 | 설명 |
|---|---|
| 입력 편의성 | 사용자가 가능한 값을 목록에서 선택할 수 있다. |
| 오류 감소 | 존재하지 않는 코드를 입력할 가능성을 줄인다. |
| 의미 제공 | 코드뿐 아니라 설명 필드를 함께 보여줄 수 있다. |
| 표준화 | 여러 화면에서 동일한 입력 도움말을 재사용할 수 있다. |

초급자는 다음처럼 이해하면 된다.

```text
F4 Help = 사용자가 값을 고를 수 있도록 보여주는 입력 도움말 화면
Search Help = 그 F4 Help를 정의하는 ABAP Dictionary 객체
Help View = Search Help가 보여줄 데이터를 준비하는 조회 기반 중 하나
```

## 4. Search Help란 무엇인가?

Search Help는 ABAP Dictionary에서 F4 Help의 동작을 정의하는 객체이다.

Search Help는 다음 질문에 답한다.

```text
어떤 데이터 소스에서 값을 가져올 것인가?
어떤 필드를 검색 조건으로 받을 것인가?
어떤 필드를 결과 목록에 보여줄 것인가?
선택한 값 중 어떤 값을 화면 필드로 돌려줄 것인가?
```

Search Help의 대표 구성 요소는 다음과 같다.

| 구성 요소 | 의미 |
|---|---|
| Selection Method | Search Help가 데이터를 읽을 기반 테이블 또는 View |
| Search Help Parameter | 입력/출력/표시/반환에 사용할 필드 |
| Import Parameter | F4 호출 시 현재 화면 값을 검색 조건으로 받을 수 있는 필드 |
| Export Parameter | 사용자가 선택한 값을 화면 필드로 돌려줄 수 있는 필드 |
| LPos | 결과 리스트에서 필드가 표시되는 위치 |
| SPos | 검색 조건 화면에서 필드가 표시되는 위치 |
| Dialog Type | F4 Help가 어떤 방식으로 표시될지 결정하는 옵션 |

이번 모듈에서는 `Selection Method`에 Help View를 연결하는 흐름을 중심으로 학습한다.

## 5. Help View란 무엇인가?

Help View는 Search Help에서 사용할 수 있는 DDIC View의 한 유형이다. 특히 여러 테이블의 필드를 조합하여 사용자가 선택할 값 목록을 구성하고자 할 때 유용하다.

예를 들어 연결편(Connection) F4 Help를 만들고 싶다고 하자. 단순히 `SPFLI-CONNID`만 보여주면 사용자는 숫자 코드만 보게 된다.

```text
0017
0400
2402
```

하지만 사용자가 실제로 선택하려면 다음 정보가 함께 보이는 편이 좋다.

| 항공사 | 연결편 | 출발 도시 | 도착 도시 |
|---|---|---|---|
| AA | 0017 | NEW YORK | SAN FRANCISCO |
| LH | 0400 | FRANKFURT | NEW YORK |

이 경우 `SPFLI` 자체만으로도 어느 정도 정보를 보여줄 수 있지만, 항공사 이름까지 포함하려면 `SCARR`와 연결하고 싶을 수 있다. 이런 식으로 F4 Help에 필요한 표시 필드를 조합하기 위한 DDIC 기반 조회 객체로 Help View를 사용할 수 있다.

초급자 관점에서는 다음처럼 정리할 수 있다.

```text
Help View = F4 Help 목록을 만들기 위해 필요한 테이블 조인/필드 구성을 DDIC 객체로 준비한 것
```

## 6. Help View와 Database View의 차이

Help View와 Database View는 모두 Classic DDIC View 계열이지만 목적이 다르다.

| 구분 | Database View | Help View |
|---|---|---|
| 주 목적 | ABAP SQL 조회용 재사용 View | Search Help의 Selection Method로 사용 |
| 사용 위치 | SELECT FROM view | F4 Help / Search Help |
| 설계 중심 | 조회 재사용, JOIN 캡슐화 | 입력 도움말에 필요한 표시/검색/반환 필드 구성 |
| 결과 소비자 | ABAP 프로그램, 조회 로직 | 사용자 입력 필드의 F4 Help |
| 현대적 대체 흐름 | CDS View Entity | CDS Value Help / UI Annotation / RAP Value Help |

핵심 차이는 “누가 이 View를 소비하는가”이다.

```text
Database View는 주로 프로그램이 소비한다.
Help View는 주로 Search Help가 소비한다.
```

[추정] 시스템과 릴리스에 따라 Help View 생성 화면, 허용 가능한 Join/조건 설정, 권장 사용 방식이 다소 다르게 보일 수 있다. 하지만 교육상 핵심은 “F4 Help의 데이터 기반으로 View를 준비한다”는 점이다.

## 7. 실습 시나리오 개요

이번 실습에서는 항공편 연결 정보를 선택하는 F4 Help를 만든다.

학습용 표준 테이블은 다음을 사용한다.

| 테이블 | 의미 |
|---|---|
| `SCARR` | 항공사 마스터 |
| `SPFLI` | 항공사별 연결편 정보 |

실습 목표는 다음과 같다.

```text
1. SCARR와 SPFLI를 조합한 Help View를 만든다.
2. 이 Help View를 Elementary Search Help의 Selection Method로 사용한다.
3. Search Help에서 항공사, 연결편, 출발/도착 도시를 표시한다.
4. ABAP PARAMETERS에서 F4 Help가 동작하는지 확인한다.
```

생성할 객체 예시는 다음과 같다.

| 객체 | 예시 이름 | 목적 |
|---|---|---|
| Help View | `ZHV_JHY_CONN` | 연결편 F4 Help의 데이터 기반 |
| Elementary Search Help | `ZSH_JHY_CONN` | F4 Help 정의 |
| Test Report | `ZR_JHY_TEST_SH_CONN` | PARAMETERS에서 F4 확인 |

> [추정] 교육 시스템에 SAP Flight Model 테이블(`SCARR`, `SPFLI`)이 없거나 데이터가 비어 있을 수 있다. 이 경우 교육용 Z 테이블 또는 시스템에 존재하는 표준 마스터 테이블로 대체한다.

## 8. Help View 설계

### 8.1 Help View의 기본 설계

Help View `ZHV_JHY_CONN`은 다음 필드를 제공한다고 가정한다.

| View Field | Source Field | 의미 | F4 표시 여부 |
|---|---|---|---|
| CARRID | SPFLI-CARRID | 항공사 코드 | 표시/반환 후보 |
| CARRNAME | SCARR-CARRNAME | 항공사 이름 | 표시 |
| CONNID | SPFLI-CONNID | 연결편 번호 | 반환 후보 |
| CITYFROM | SPFLI-CITYFROM | 출발 도시 | 표시/검색 |
| CITYTO | SPFLI-CITYTO | 도착 도시 | 표시/검색 |

Join 조건은 다음과 같다.

```text
SCARR-CARRID = SPFLI-CARRID
```

이 조건은 항공사 마스터와 연결편 정보를 항공사 코드 기준으로 연결한다.

### 8.2 왜 Help View를 사용하는가?

Search Help의 Selection Method는 단일 테이블만 사용할 수도 있고, View를 사용할 수도 있다.  
단일 테이블만으로 충분하면 굳이 Help View를 만들 필요가 없다. 하지만 다음 상황에서는 View가 유용하다.

| 상황 | Help View 사용 이유 |
|---|---|
| 코드와 설명이 서로 다른 테이블에 있음 | F4 목록에 함께 보여주기 위해 |
| 사용자가 선택할 값에 부가 설명이 필요함 | 결과 리스트의 의미를 높이기 위해 |
| Search Help에서 재사용할 조회 기반이 필요함 | Selection Method를 안정적으로 관리하기 위해 |
| CDS 이전 Classic DDIC 방식 이해가 필요함 | 현대 방식과 비교 기준을 만들기 위해 |

## 9. SE11에서 Help View 생성 절차

SAP GUI 800 기준의 일반 흐름은 다음과 같다.

```text

2. View 선택
3. View Name에 ZHV_JHY_CONN 입력
4. Create 선택
5. View Type에서 Help View 선택
6. Short Description 입력
7. Tables/Join Conditions 설정
8. View Fields 선택
9. Selection Conditions 필요 시 설정
10. Save
11. Activate
```

### 9.1 View Type 선택

Create 단계에서 `Help View`를 선택한다.

```text
View Name: ZHV_JHY_CONN
View Type: Help View
Short Description: Help View for Flight Connection F4
```

### 9.2 기본 테이블 입력

예시로 다음 테이블을 사용한다.

```text
Primary Table: SPFLI
Secondary Table: SCARR
Join Condition: SPFLI-CARRID = SCARR-CARRID
```

실제 SE11 화면의 표현은 시스템 설정과 릴리스에 따라 다를 수 있다. 중요한 것은 두 테이블이 `CARRID` 기준으로 연결되어야 한다는 점이다.

### 9.3 View Fields 선택

다음 필드를 View Field로 포함한다.

| Source | Field |
|---|---|
| SPFLI | CARRID |
| SCARR | CARRNAME |
| SPFLI | CONNID |
| SPFLI | CITYFROM |
| SPFLI | CITYTO |

### 9.4 활성화

Help View를 저장한 뒤 반드시 Activate한다.

Search Help는 Selection Method로 활성 객체를 참조해야 하므로 Help View가 비활성 상태이면 이후 Search Help 활성화 또는 F4 실행에서 문제가 발생할 수 있다.

## 11. Import / Export / LPos / SPos 이해

### 11.1 Import Parameter

Import Parameter는 F4 Help가 호출될 때 현재 입력 화면의 값을 Search Help 검색 조건으로 넘겨받을 수 있는 필드이다.

예를 들어 사용자가 항공사 코드 `LH`를 이미 입력한 상태에서 연결편 F4를 누르면, F4 목록을 `LH` 기준으로 좁히고 싶을 수 있다. 이때 `CARRID`를 Import Parameter로 설정할 수 있다.

초급자 설명:

```text
Import = 화면에 이미 입력된 값을 F4 검색 조건으로 가져오는 통로
```

### 11.2 Export Parameter

Export Parameter는 사용자가 F4 목록에서 한 줄을 선택했을 때, 그 값을 입력 화면으로 돌려줄 수 있는 필드이다.

예를 들어 연결편 번호를 선택하는 Search Help라면 `CONNID`가 Export 대상이 될 수 있다.

초급자 설명:

```text
Export = F4에서 선택한 값을 화면 필드로 되돌려주는 통로
```

### 11.3 LPos

LPos는 F4 결과 리스트에서 해당 필드가 표시되는 위치이다.

| LPos | 표시 필드 예 |
|---:|---|
| 1 | CARRID |
| 2 | CONNID |
| 3 | CARRNAME |
| 4 | CITYFROM |
| 5 | CITYTO |

LPos가 비어 있으면 결과 목록에 표시되지 않을 수 있다.

### 11.4 SPos

SPos는 F4 검색 조건 팝업에서 해당 필드가 검색 조건으로 표시되는 위치이다.

| SPos | 검색 조건 예 |
|---:|---|
| 1 | CARRID |
| 2 | CONNID |
| 3 | CITYFROM |
| 4 | CITYTO |

SPos는 사용자가 F4 목록을 열기 전에 조건을 입력해 범위를 좁힐 때 유용하다.

## 12. Search Help 연결 방식

Search Help를 실제 입력 필드에 연결하는 방식은 크게 두 가지로 볼 수 있다.

### 12.1 Data Element에 연결

Data Element에 Search Help를 연결하면 해당 Data Element를 사용하는 여러 필드에서 F4 Help를 재사용할 수 있다.

예시 흐름:

```text
SE11
→ Data Element ZDE_JHY_CONNID
→ Further Characteristics 또는 Search Help 관련 탭
→ Search Help ZSH_JHY_CONN 연결
→ Activate
```

장점:

| 장점 | 설명 |
|---|---|
| 재사용성 | 여러 화면과 테이블 필드에서 같은 F4 Help 사용 가능 |
| 중앙 관리 | Data Element 중심으로 의미와 입력 도움말 관리 |
| 유지보수성 | F4 Help 변경 시 여러 사용처에 반영 가능 |

주의점:

```text
Data Element에 연결하면 영향 범위가 넓어진다.
이미 여러 객체에서 사용 중인 Data Element라면 변경 영향 분석이 필요하다.
```

### 12.2 ABAP PARAMETERS에 직접 연결

교육용으로는 ABAP Report의 PARAMETERS에 직접 Search Help를 지정해 테스트할 수 있다.

```abap
REPORT zr_jhy_test_sh_conn.

PARAMETERS p_connid TYPE spfli-connid MATCHCODE OBJECT zsh_jhy_conn.

START-OF-SELECTION.
  WRITE: / 'Selected Connection:', p_connid.
```

이 방식은 실습 확인에 적합하다.

| 장점 | 설명 |
|---|---|
| 빠른 테스트 | Data Element 변경 없이 F4 Help 확인 가능 |
| 영향 범위 제한 | 해당 프로그램의 Parameter에만 적용 |
| 교육용 적합 | Search Help 동작을 빠르게 검증 가능 |

단점은 재사용성이 낮다는 점이다.

## 14. 정상 흐름과 오류 흐름

### 14.1 정상 흐름

```text
Help View 생성
→ Join 조건 설정
→ View Fields 선택
→ Help View Activate
→ Elementary Search Help 생성
→ Selection Method에 Help View 지정
→ Parameter / LPos / SPos / Import / Export 설정
→ Search Help Activate
→ PARAMETERS 또는 Data Element에 연결
→ F4 테스트
```

### 14.2 오류 흐름 1: F4 Help가 뜨지 않음

가능한 원인:

| 원인 | 확인 방법 |
|---|---|
| Search Help를 입력 필드에 연결하지 않음 | Parameter의 MATCHCODE OBJECT 또는 Data Element 연결 확인 |
| Search Help가 비활성 상태 | SE11에서 Search Help 활성 상태 확인 |
| 권한 문제 | 다른 사용자/개발자 권한과 비교 |
| 프로그램이 이전 버전으로 실행됨 | 프로그램 Activate 후 다시 실행 |

해결 순서:

```text
1. Search Help 객체 활성화 확인
2. Parameter 또는 Data Element 연결 확인
3. 프로그램 Syntax Check 및 Activate
4. 새 세션에서 다시 실행
```

### 14.3 오류 흐름 2: F4 목록이 비어 있음

가능한 원인:

| 원인 | 설명 |
|---|---|
| Help View 조회 결과가 없음 | Join 조건이 잘못되었거나 데이터가 없음 |
| 기본 테이블 데이터가 없음 | SCARR/SPFLI 데이터 확인 필요 |
| Selection Condition이 과도함 | View 또는 Search Help 조건이 너무 제한적 |
| Import 값이 잘못 전달됨 | 화면 입력값이 검색 조건으로 들어가 목록을 제한 |

해결:

```text
1. SE11에서 Help View 데이터 조회 가능 여부 확인
2. 기본 테이블 SCARR/SPFLI 데이터 존재 여부 확인
3. Join 조건 확인
4. Search Help의 Import Parameter 설정 임시 해제 후 테스트
5. Selection Condition 확인
```

### 14.4 오류 흐름 3: 값이 화면으로 반환되지 않음

가능한 원인:

| 원인 | 설명 |
|---|---|
| Export Parameter 미설정 | 선택한 값을 반환할 필드가 지정되지 않음 |
| Parameter 이름 매핑 문제 | Search Help Parameter와 화면 필드 연결이 맞지 않음 |
| 반환 필드가 LPos에는 있으나 Export가 아님 | 표시만 되고 반환되지 않음 |
| MATCHCODE OBJECT 테스트 방식의 한계 | 다중 필드 반환 테스트는 별도 화면 필드 연결이 필요할 수 있음 |

해결:

```text
1. 반환해야 하는 필드에 Export 체크
2. Search Help Parameter 이름 확인
3. 단일 반환 필드부터 테스트
4. Data Element 연결 방식과 Parameter 직접 연결 방식을 분리해 점검
```

### 14.5 오류 흐름 4: 활성화 오류

가능한 원인:

| 원인 | 설명 |
|---|---|
| Help View가 비활성 | Search Help에서 Selection Method로 사용 불가 |
| View Field 누락 | Search Help Parameter가 Selection Method에 없는 필드를 참조 |
| Join 조건 오류 | Help View 자체 활성화 실패 |
| 객체 이름 오류 | Z/Y 네임스페이스 또는 오타 문제 |

해결:

```text
1. Help View 먼저 Activate
2. Help View Field 목록 확인
3. Search Help Parameter와 View Field 이름 일치 확인
4. Search Help Activate
```

## 15. 실무 적용 기준

### 15.1 Help View를 사용할 만한 경우

| 상황 | 설명 |
|---|---|
| F4 목록에 여러 테이블의 설명 필드를 함께 보여주고 싶음 | 코드와 설명 테이블을 조인 |
| Search Help의 Selection Method를 명확한 DDIC 객체로 분리하고 싶음 | 유지보수성 향상 |
| Classic SAP GUI 중심 개발에서 F4 Help를 구성해야 함 | 기존 DDIC 방식과 잘 맞음 |
| CDS 이전의 Classic View 체계를 교육해야 함 | 학습 선후수상 의미 있음 |

### 15.2 Help View를 피하거나 대안을 검토할 경우

| 상황 | 검토 대안 |
|---|---|
| S/4HANA 신규 개발에서 CDS 기반 UI를 개발 | CDS View Entity + Value Help Annotation |
| 복잡한 동적 검색 로직이 필요 | Search Help Exit 검토 |
| Fiori Elements/RAP 화면의 Value Help 필요 | RAP Value Help / CDS Association |
| 단순 코드 테이블 한 개만 필요 | 테이블 또는 Database View를 Selection Method로 사용 가능 |

> 실무에서는 “Help View를 만들 수 있다”와 “Help View가 최선이다”를 구분해야 한다.  
> Classic SAP GUI와 SE11 중심 실습에서는 유용하지만, 신규 S/4HANA 확장 개발에서는 CDS 기반 Value Help와 비교해 판단해야 한다.

### 15.3 성능 관점

F4 Help는 사용자가 자주 호출할 수 있으므로 성능이 중요하다.

점검할 항목:

| 항목 | 설명 |
|---|---|
| Selection Method 데이터량 | 너무 큰 테이블을 제한 없이 보여주지 않는다. |
| 검색 조건 | SPos와 Import Parameter를 활용해 범위를 줄인다. |
| Join 조건 | 불필요하게 많은 테이블을 연결하지 않는다. |
| 결과 필드 | 사용자에게 필요한 필드만 표시한다. |
| 권한/데이터 보안 | 민감한 필드를 F4 목록에 노출하지 않는다. |

### 15.4 운영 안정성 관점

F4 Help는 단순 편의 기능처럼 보이지만, 운영 화면에서는 사용자의 입력 정확도와 직결된다.

주의할 점:

```text
검색 결과가 너무 많으면 사용성이 떨어진다.
설명 필드가 없으면 사용자가 잘못 선택할 가능성이 높아진다.
반환 필드가 잘못 설정되면 잘못된 값이 화면에 들어간다.
Data Element에 연결하면 영향 범위가 넓어진다.
운영 중 사용되는 Search Help를 변경할 때는 사용처를 확인해야 한다.
```

## 16. Help View와 Check Table / Foreign Key의 차이

초급자는 F4 Help, Foreign Key, Check Table을 자주 혼동한다.

| 구분 | 목적 | 대표 객체 |
|---|---|---|
| Foreign Key | 입력값의 유효성 검증 관계 | Check Table |
| Search Help | 사용자가 값을 찾고 선택하게 도움 | Elementary / Collective Search Help |
| Help View | Search Help가 사용할 조회 기반 | Help View |
| Fixed Value | 작은 코드값의 허용 범위 정의 | Domain Value Range |

핵심 구분은 다음이다.

```text
Foreign Key는 검증 관계이다.
Search Help는 값 찾기 UI이다.
Help View는 F4 목록을 만들기 위한 데이터 기반이다.
```

F4 Help가 있다고 해서 반드시 DB 수준의 Foreign Key 검증이 되는 것은 아니다.  
반대로 Foreign Key가 있다고 해서 항상 사용자가 원하는 형태의 풍부한 F4 목록이 자동으로 제공되는 것도 아니다.

## 17. 강사용 설명 포인트

강의에서는 다음 메시지를 강조하면 좋다.

### 17.1 F4 Help는 “값 선택 UI”이다

초급자는 Search Help를 데이터 검증과 혼동할 수 있다. 다음 문장을 반복하면 좋다.

```text
F4 Help는 사용자가 값을 찾도록 돕는 기능이다.
입력값 검증은 Foreign Key, Domain Fixed Value, 프로그램 검증 등과 구분해서 이해해야 한다.
```

### 17.2 Help View는 “Search Help용 조회 기반”이다

Database View와 혼동하지 않도록 다음 비교를 사용한다.

```text
Database View → ABAP SQL에서 조회하려고 만든 View
Help View → F4 Help 목록을 만들려고 만든 View
```

### 17.3 Classic 방식과 Modern 방식의 연결

이 모듈은 CDS Value Help를 바로 다루지 않는다. 그러나 후속 CDS/RAP 학습을 위해 다음 연결 문장을 제공한다.

```text
Classic Search Help는 SAP GUI 중심 입력 도움말의 대표 방식이다.
CDS/RAP에서는 Value Help Annotation과 Association을 통해 비슷한 목적을 더 선언적으로 구현한다.
```

## 20. 평가 문제

### 20.1 객관식

#### Q1. Help View의 가장 적절한 설명은?

A. DB 데이터를 직접 수정하기 위한 유지보수 화면이다.  
B. Search Help에서 사용할 수 있는 Classic DDIC View 유형이다.  
C. ABAP Report의 이벤트 블록이다.  
D. CDS View Entity의 필수 구성 요소이다.

**정답:** B

#### Q2. Search Help에서 Selection Method의 역할은?

A. F4 Help가 데이터를 읽을 기반 테이블 또는 View를 지정한다.  
B. ABAP 프로그램의 실행 순서를 지정한다.  
C. 화면 버튼의 색상을 지정한다.  
D. Transport Request를 자동 생성한다.

**정답:** A

#### Q3. 사용자가 F4 목록에서 선택한 값을 화면 필드로 돌려주려면 어떤 설정이 중요한다?

A. SPos  
B. Export Parameter  
C. Comment  
D. Package Description

**정답:** B

#### Q4. F4 목록에는 표시되지만 검색 조건 화면에는 보이지 않도록 하려면 일반적으로 어떤 설정을 사용할 수 있는가?

A. LPos는 지정하고 SPos는 비워둔다.  
B. SPos만 지정하고 LPos는 비워둔다.  
C. 모든 Parameter를 Export로만 둔다.  
D. Search Help를 비활성화한다.

**정답:** A

### 20.2 서술형

#### Q1. Help View와 Database View의 목적 차이를 설명하시오.

**모범 답안:**  
Database View는 주로 ABAP SQL에서 재사용 가능한 조회 기반으로 사용하기 위한 DDIC View이고, Help View는 Search Help에서 F4 Help 목록을 구성하기 위한 Selection Method로 사용하는 View이다. 즉, Database View의 주요 소비자는 프로그램 조회 로직이고, Help View의 주요 소비자는 입력 도움말이다.

#### Q2. Foreign Key와 Search Help의 차이를 설명하시오.

**모범 답안:**  
Foreign Key는 입력값이 유효한지 검증하기 위한 테이블 관계이고, Search Help는 사용자가 값을 찾고 선택할 수 있도록 제공하는 입력 도움말 정의이다. F4 Help가 있다고 해서 반드시 검증이 되는 것은 아니며, 검증과 값 선택 UI는 역할을 구분해야 한다.

#### Q3. F4 목록이 비어 있을 때 점검할 항목을 세 가지 이상 쓰시오.

**모범 답안:**  
Help View의 Join 조건이 올바른지, 기본 테이블에 데이터가 존재하는지, Search Help의 Import Parameter가 과도하게 결과를 제한하고 있지 않은지, Selection Condition이 지나치게 제한적인지, Help View와 Search Help가 활성화되어 있는지 확인한다.

## 22. 후속 모듈 연결

이번 모듈에서는 Help View를 Search Help와 연결하여 F4 Help를 구성했다.  
다음 모듈 `THEORY-12-M04 — Maintenance View와 Foreign Key 관계`에서는 데이터 조회/선택 도움말을 넘어, 여러 테이블 관계를 유지보수 View 관점에서 어떻게 다룰 수 있는지 학습한다.

연결 흐름은 다음과 같다.

```text
THEORY-12-M01 Database View와 Open SQL JOIN 비교
→ THEORY-12-M02 Projection View 개념과 한계
→ THEORY-12-M03 Help View와 Search Help 연결
→ THEORY-12-M04 Maintenance View와 Foreign Key 관계
→ THEORY-12-M05 Table Maintenance Generator / SM30
→ THEORY-12-M06 Classic View와 CDS View Entity 비교 준비
```

이번 모듈의 핵심은 다음 문장으로 정리된다.

```text
Help View는 F4 Help 목록을 만들기 위해 Search Help의 Selection Method로 사용할 수 있는 Classic DDIC View이다.
```

## 23. 웹페이지 생성용 주요 용어 후보

향후 이 MD를 HTML 학습자료로 변환할 때 팝업 설명을 붙이기 좋은 용어는 다음과 같다.

| 용어 | 팝업 설명 요약 |
|---|---|
| Help View | Search Help에서 F4 목록의 조회 기반으로 사용할 수 있는 Classic DDIC View |
| Search Help | SAP 입력 필드의 F4 Help를 정의하는 ABAP Dictionary 객체 |
| F4 Help | 사용자가 가능한 값을 검색하고 선택할 수 있는 입력 도움말 UI |
| Selection Method | Search Help가 데이터를 읽는 테이블 또는 View |
| Import Parameter | 화면의 기존 값을 F4 검색 조건으로 전달하는 Parameter |
| Export Parameter | F4에서 선택한 값을 화면 필드로 반환하는 Parameter |
| LPos | F4 결과 리스트에서 필드가 표시되는 위치 |
| SPos | F4 검색 조건 화면에서 필드가 표시되는 위치 |
| Foreign Key | 입력값 검증을 위한 테이블 간 관계 |
| CDS Value Help | CDS/RAP 기반 현대적 값 도움말 구현 방식 |
