## 2. 선행 지식

CDS View Entity는 초급자가 바로 접하면 어렵게 느낄 수 있다.

| 선행 학습 | CDS View Entity와의 연결 |
|---|---|
| DDIC Transparent Table | CDS View Entity의 기본 데이터 소스가 될 수 있다. |
| Open SQL | CDS 결과를 ABAP SQL에서 조회할 수 있다. |

## 3. CDS View Entity란 무엇인가?

### 3.1 쉬운 정의

CDS View Entity는 ABAP Development Tools에서 작성하는 CDS 기반 Repository Object이다.  
데이터베이스 테이블, 기존 CDS View, 다른 CDS View Entity 등을 데이터 소스로 사용하여 재사용 가능한 조회 모델을 정의한다.

예를 들어 항공편 연결 정보를 조회하는 로직이 여러 프로그램에서 반복된다고 가정하자.

```abap
SELECT carrid,
       connid,
       cityfrom,
       cityto
  FROM spfli
  INTO TABLE @DATA(lt_connection).
```

이 조회 구조를 여러 프로그램에서 계속 반복하면 다음 문제가 생긴다.

- 필드 목록이 프로그램마다 달라질 수 있다.
- alias와 의미 부여가 일관되지 않을 수 있다.
- 나중에 JOIN이나 annotation을 붙이기 어렵다.
- UI, OData, RAP, 분석 모델로 확장하기 어렵다.

CDS View Entity는 이런 조회 구조를 하나의 Repository Object로 정의한다.

```abap
@EndUserText.label: 'Flight Connection Basic'
@AccessControl.authorizationCheck: #NOT_REQUIRED
define view entity ZI_JHY_FlightConnectionBasic
  as select from spfli
{
  key carrid    as CarrierId,
  key connid    as ConnectionId,
      countryfr as DepartureCountry,
      cityfrom   as DepartureCity,
      countryto as ArrivalCountry,
      cityto     as ArrivalCity
}
```

이제 ABAP 프로그램은 `SPFLI`를 직접 조회하지 않고, 위 CDS View Entity를 조회할 수 있다.

```abap
SELECT *
  FROM ZI_JHY_FlightConnectionBasic
  INTO TABLE @DATA(lt_connection).
```

## 4. Classic CDS View와 CDS View Entity의 차이

초급 과정에서 반드시 구분해야 할 점이 있다.  
예전 CDS 학습 자료에는 `define view`와 `@AbapCatalog.sqlViewName`이 자주 등장한다.  
하지만 최신 S/4HANA 기준 학습에서는 **CDS View Entity**를 우선 학습하는 것이 적절하다.

### 4.1 Classic CDS View 예시

```abap
@AbapCatalog.sqlViewName: 'ZVFLIGHT01'
@EndUserText.label: 'Classic CDS View'
define view ZC_ClassicFlight
  as select from spfli
{
  key carrid,
  key connid,
      cityfrom,
      cityto
}
```

Classic CDS View에서는 DDIC SQL View 이름이 별도로 필요했다.

### 4.2 CDS View Entity 예시

```abap
@EndUserText.label: 'Flight Connection Basic'
@AccessControl.authorizationCheck: #NOT_REQUIRED
define view entity ZI_JHY_FlightConnectionBasic
  as select from spfli
{
  key carrid   as CarrierId,
  key connid   as ConnectionId,
      cityfrom  as DepartureCity,
      cityto    as ArrivalCity
}
```

CDS View Entity에서는 `@AbapCatalog.sqlViewName`을 사용하지 않는다.  
Repository Object 자체가 View Entity로 정의되며, 별도의 DDIC SQL View 이름을 만들지 않는 방식으로 이해하면 된다.

### 4.3 비교표

| 구분 | Classic CDS View | CDS View Entity |
|---|---|---|
| 기본 선언 | `define view` | `define view entity` |
| SQL View Name | `@AbapCatalog.sqlViewName` 필요 | 사용하지 않음 |
| 최신 학습 권장성 | 기존 시스템 이해용 | 신규 학습과 최신 개발 흐름에 적합 |
| ADT 개발 | 가능 | 가능 |
| RAP/CDS 확장 흐름 | 제한적으로 사용 | 현대 ABAP 모델링의 기본 흐름 |

> 주의: 실제 프로젝트에서는 시스템 릴리스, 기존 자산, 고객사 표준에 따라 Classic CDS View가 아직 존재할 수 있다.  
> 하지만 신규 학습과 S/4HANA 중심 설계에서는 CDS View Entity 구조를 먼저 익히는 것이 바람직하다.

## 5. CDS View Entity의 기본 골격

CDS View Entity는 다음 구조를 가진다.

```abap
@Annotation: value
define view entity ViewEntityName
  as select from DataSource
{
  key field1 as Alias1,
      field2 as Alias2,
      field3 as Alias3
}
```

각 부분의 의미는 다음과 같다.

| 구문 | 의미 |
|---|---|
| `@Annotation` | View 또는 Element에 의미와 메타데이터를 부여한다. |
| `define view entity` | CDS View Entity를 정의한다. |
| `ViewEntityName` | CDS View Entity의 Repository Object 이름이다. |
| `as select from` | 조회할 데이터 소스를 지정한다. |
| `{ ... }` | 결과로 노출할 element 목록을 정의한다. |
| `key` | CDS 결과 모델에서 중요한 식별 element를 표시한다. |
| `as Alias` | 외부에 노출할 element 이름을 지정한다. |

## 6. 이름 규칙

교육용 CDS 이름은 다음 규칙을 사용한다.

| 객체 성격 | Prefix | 예시 |
|---|---|---|
| Interface View | `ZI_` | `ZI_JHY_FlightConnectionBasic` |
| Projection / Consumption View | `ZC_` | `ZC_JHY_FlightConnectionBasic` |

이번 모듈에서는 CDS View Entity의 기본 구조를 익히기 위해 `ZI_*` 이름을 사용한다.  
`ZI_*`와 `ZC_*`의 계층 구분은 다음 모듈 `THEORY-20-M02`에서 본격적으로 다룬다.

> 이번 모듈에서는 “CDS View Entity 문법을 읽고 활성화하는 능력”이 핵심이다.  
> `ZI_*` / `ZC_*` 아키텍처 설계 논쟁은 다음 모듈로 넘긴다.

## 7. 실습 예제: 항공편 연결 기본 View Entity

### 7.1 실습 목표

표준 교육 테이블 `SPFLI`를 기반으로 간단한 CDS View Entity를 생성한다.

> [추정] 일부 교육 시스템에는 `SCARR`, `SPFLI`, `SFLIGHT` 같은 항공 예제 테이블이 없을 수 있다.

## 8. 예제 코드 상세 해설

### 8.1 `@EndUserText.label`

```abap
@EndUserText.label: 'Flight Connection Basic'
```

이 annotation은 CDS 객체의 사람이 읽을 수 있는 설명을 제공한다.  
ADT, Repository 검색, 메타데이터 확인 시 의미 파악에 도움이 된다.

초급자는 다음처럼 이해하면 된다.

```text
ABAP Dictionary의 Short Description과 비슷하게
객체의 목적을 설명하는 메타데이터이다.
```

### 8.2 `@AccessControl.authorizationCheck`

```abap
@AccessControl.authorizationCheck: #NOT_REQUIRED
```

이 annotation은 CDS Access Control, 즉 DCL과 관련된 권한 체크 동작을 지정한다.  
이번 모듈에서는 실습 단순화를 위해 `#NOT_REQUIRED`를 사용한다.

중요한 점은 다음이다.

```text
운영용 CDS에서 권한 체크를 무시하라는 뜻으로 외우면 안 된다.
이번 실습에서는 DCL을 아직 배우지 않았기 때문에
기본 구조 학습을 위해 단순화한 설정이다.
```

DCL과 권한 설계는 `THEORY-20-M06`에서 다룬다.

### 8.3 `define view entity`

```abap
define view entity ZI_JHY_FlightConnectionBasic
```

이 구문은 새로운 CDS View Entity를 정의한다.

| 항목 | 설명 |
|---|---|
| `define` | 객체를 정의한다는 의미 |
| `view entity` | CDS View Entity 유형 |
| `ZI_JHY_FlightConnectionBasic` | 생성할 View Entity 이름 |

### 8.4 `as select from`

```abap
as select from spfli
```

이 구문은 CDS View Entity의 데이터 소스를 지정한다.

여기서는 `SPFLI` 테이블을 데이터 소스로 사용한다.

| 구성 | 의미 |
|---|---|
| `as select from` | 이 데이터 소스로부터 조회 모델을 만든다 |
| `spfli` | 원천 테이블 또는 View 이름 |

이번 모듈에서는 단일 데이터 소스만 사용한다.  
JOIN, Association, Path Expression은 후속 모듈에서 다룬다.

### 8.5 Element List

```abap
{
  key carrid    as CarrierId,
  key connid    as ConnectionId,
      countryfr as DepartureCountry,
      cityfrom   as DepartureCity
}
```

중괄호 안에는 이 View Entity가 외부에 노출할 element를 정의한다.

| 원천 필드 | Alias | 설명 |
|---|---|---|
| `carrid` | `CarrierId` | 항공사 코드 |

## 9. `key`의 의미

CDS에서 `key`는 결과 모델의 중요한 식별 element를 표시한다.

```abap
key carrid as CarrierId,
key connid as ConnectionId,
```

초급자가 주의해야 할 점은 다음이다.

```text
CDS의 key는 데이터베이스 테이블의 Primary Key와 완전히 같은 의미로 단순화하면 안 된다.
```

원천 테이블의 Key를 그대로 반영하는 경우도 많지만, CDS View Entity의 key는 View 결과 모델에서 어떤 element가 식별 역할을 하는지를 표현하는 의미가 강하다.

예를 들어 `SPFLI`에서는 `CARRID`, `CONNID` 조합이 항공 연결을 식별한다.  
따라서 View Entity에서도 `CarrierId`, `ConnectionId`를 key로 지정한다.

### 9.1 잘못된 예

```abap
{
  key carrid    as CarrierId,
  key connid    as ConnectionId,
  key cityfrom  as DepartureCity,
  key cityto    as ArrivalCity
}
```

모든 필드를 key로 지정하는 것은 일반적으로 좋지 않다.  
key는 결과 한 건을 식별하는 핵심 element를 중심으로 최소화해야 한다.

### 9.2 초급자 판단 기준

| 질문 | 판단 |
|---|---|
| 이 필드가 한 건을 식별하는 데 꼭 필요한가? | 필요하면 key 후보 |
| 값이 설명성 속성인가? | 보통 key 아님 |
| 값이 변경될 가능성이 큰가? | key로 부적합할 수 있음 |
| 원천 테이블의 key와 연결되는가? | 우선 검토 대상 |

## 10. Alias 설계

CDS View Entity는 원천 필드명을 그대로 노출할 수도 있고, alias를 통해 의미 있는 이름으로 바꿀 수도 있다.

### 10.1 원천 필드명 그대로 사용

```abap
{
  key carrid,
  key connid,
      cityfrom,
      cityto
}
```

이 방식은 단순하지만 외부에서 의미가 덜 명확할 수 있다.

### 10.2 의미 있는 Alias 사용

```abap
{
  key carrid  as CarrierId,
  key connid  as ConnectionId,
      cityfrom as DepartureCity,
      cityto   as ArrivalCity
}
```

이 방식은 외부 소비자 입장에서 의미가 명확하다.

### 10.3 실무적 권장

CDS는 단순 SQL View가 아니라 의미 모델링 계층으로 사용되는 경우가 많다.  
따라서 element 이름은 단순 약어보다 의미를 드러내는 방식이 좋다.

| 원천 필드 | 비권장 노출 | 권장 Alias |
|---|---|---|
| `carrid` | `carrid` | `CarrierId` |
| `connid` | `connid` | `ConnectionId` |
| `cityfrom` | `cityfrom` | `DepartureCity` |
| `cityto` | `cityto` | `ArrivalCity` |

단, 실제 프로젝트에서는 기존 VDM naming rule, 고객사 네이밍 규칙, RAP BO 설계 기준을 따라야 한다.

## 11. ADT에서 CDS View Entity 생성 절차

CDS View Entity는 일반적으로 SAP GUI SE11이 아니라 Eclipse ADT에서 생성한다.

### 11.1 생성 절차

```text
1. Eclipse ADT 실행
2. ABAP Project 접속
3. Package 선택
4. New → Other 선택
5. ABAP Repository Object 선택
6. Core Data Services → Data Definition 선택
7. Name 입력: ZI_JHY_FlightConnectionBasic
8. Description 입력
9. Template 선택 또는 빈 소스 생성
10. CDS 코드 작성
11. Save
12. Activate
13. Data Preview 실행
```

### 11.2 Package 선택

교육용이라면 `$TMP` Local Object를 사용할 수 있다.  
실무 프로젝트에서는 반드시 프로젝트 Package와 Transport Request 정책을 따른다.

### 11.3 Data Definition 이름과 View Entity 이름

일반적으로 Data Definition 객체명과 `define view entity` 이름은 동일하게 맞추는 것이 학습과 유지보수에 유리하다.

```text
Data Definition: ZI_JHY_FlightConnectionBasic
View Entity:     ZI_JHY_FlightConnectionBasic
```

## 12. Data Preview로 확인하기

CDS View Entity를 활성화한 뒤에는 ADT에서 Data Preview로 결과를 확인할 수 있다.

```text
CDS Source 열기
→ View Entity 이름 선택
→ Open With
→ Data Preview
```

또는 Project Explorer에서 해당 CDS 객체를 선택한 뒤 Data Preview를 실행할 수 있다.

Data Preview에서는 다음을 확인한다.

| 확인 항목 | 설명 |
|---|---|
| 결과 행 수 | 원천 테이블에 데이터가 있는지 확인 |
| element 이름 | Alias가 의도대로 노출되는지 확인 |
| key element | `CarrierId`, `ConnectionId`가 key로 보이는지 확인 |
| 데이터 타입 | 원천 필드 타입이 정상 전달되는지 확인 |
| 권한 오류 | DCL/권한 관련 메시지가 있는지 확인 |

> Data Preview 결과가 비어 있다고 해서 CDS 문법이 틀린 것은 아니다.  
> 원천 테이블에 데이터가 없거나 현재 Client에 데이터가 없을 수도 있다.

## 13. ABAP SQL에서 CDS View Entity 조회하기

활성화된 CDS View Entity는 ABAP SQL의 데이터 소스로 사용할 수 있다.

```abap
REPORT zjhy_select_cds_entity.

SELECT CarrierId,
       ConnectionId,
       DepartureCity,
       ArrivalCity
  FROM ZI_JHY_FlightConnectionBasic
  INTO TABLE @DATA(lt_connection).

IF sy-subrc = 0.
  LOOP AT lt_connection INTO DATA(ls_connection).
    WRITE: / ls_connection-CarrierId,
             ls_connection-ConnectionId,
             ls_connection-DepartureCity,
             ls_connection-ArrivalCity.
  ENDLOOP.
ELSE.
  WRITE: / 'No connection data found.'.
ENDIF.
```

초급자는 이 예제에서 다음만 이해하면 된다.

```text
CDS View Entity는 ABAP SQL의 FROM 절에서 조회할 수 있다.
CDS element 이름은 ABAP SQL의 필드 이름처럼 사용할 수 있다.
```

ABAP SQL의 상세한 성능, WHERE 조건, JOIN, Aggregation은 이미 앞선 Open SQL Section에서 학습했거나 후속 심화에서 다시 다룬다.

## 14. 활성화 오류와 해결 방법

### 14.1 원천 테이블이 존재하지 않음

#### 증상

```text
Data source SPFLI does not exist
```

#### 원인

- 시스템에 `SPFLI` 테이블이 없음
- 테이블 이름 오타
- 해당 객체 접근 권한 부족

#### 해결

- SE11 또는 ADT에서 `SPFLI` 존재 여부 확인
- 교육 시스템에 맞는 다른 테이블로 대체
- 권한 문제인 경우 관리자 또는 강사에게 확인

### 14.2 필드명이 존재하지 않음

#### 증상

```text
Element CARRIDX is unknown
```

#### 원인

- 원천 테이블에 없는 필드명을 사용
- 철자 오류
- 대체 테이블 사용 중 필드명이 다름

#### 해결

- 원천 테이블의 필드 목록 확인
- ADT Content Assist 사용
- 필드명을 정확히 수정

### 14.3 Alias 중복

#### 증상

```text
Element name is not unique
```

#### 원인

두 개 이상의 element가 같은 alias를 사용했다.

#### 잘못된 예

```abap
{
  carrid as Id,
  connid as Id
}
```

#### 해결

각 element alias를 유일하게 만든다.

```abap
{
  carrid as CarrierId,
  connid as ConnectionId
}
```

### 14.4 Semicolon 또는 comma 오류

CDS element list에서는 각 element 사이에 comma가 필요하다.

잘못된 예:

```abap
{
  key carrid as CarrierId
  key connid as ConnectionId
}
```

올바른 예:

```abap
{
  key carrid as CarrierId,
  key connid as ConnectionId
}
```

### 14.5 권한 또는 DCL 관련 메시지

실습에서 `@AccessControl.authorizationCheck: #NOT_REQUIRED`를 사용하지 않거나, 시스템 정책이 다르면 Data Preview 시 권한 관련 메시지를 볼 수 있다.

초급 단계에서는 다음 원칙만 기억한다.

```text
CDS는 권한 제어와 연결될 수 있다.
운영용 View에서 권한을 무시하면 안 된다.
DCL과 Authorization은 THEORY-20-M06에서 별도로 다룬다.
```

## 15. CDS View Entity 작성 시 실무 주의점

### 15.1 원천 테이블을 무분별하게 직접 노출하지 않는다

CDS View Entity는 단순히 테이블을 그대로 외부에 공개하기 위한 도구가 아니다.  
특히 RAP, OData, Fiori, 분석 모델로 이어지는 경우에는 View 계층 설계가 중요하다.

이번 모듈에서는 단일 View를 만들지만, 실무에서는 일반적으로 다음 계층을 고려한다.

```text
DB Table
→ Basic / Interface View
→ Projection / Consumption View
→ Service / UI / API
```

이 계층 구분은 다음 모듈에서 다룬다.

### 15.2 Alias는 API 계약처럼 생각한다

CDS element 이름은 이후 ABAP SQL, OData, Fiori, RAP에서 사용될 수 있다.  
따라서 한 번 외부에 노출한 element 이름은 변경하기 어렵다.

나쁜 예:

```text
F1
F2
TXT
CD
```

좋은 예:

```text
CarrierId
ConnectionId
DepartureCity
ArrivalCity
```

### 15.3 `key`를 기계적으로 복사하지 않는다

원천 테이블의 key를 그대로 사용하는 것이 적절한 경우도 있지만, 모든 상황에서 자동 정답은 아니다.  
CDS 결과 모델이 어떤 단위의 데이터를 표현하는지 먼저 판단해야 한다.

### 15.4 Annotation을 장식으로 생각하지 않는다

Annotation은 CDS의 의미를 확장하는 핵심 장치이다.  
이번 모듈에서는 최소 annotation만 사용하지만, 후속 모듈에서는 UI, OData, 검색, 권한, 메타데이터 분리와 연결된다.

### 15.5 복잡한 로직을 한 View에 몰아넣지 않는다

초급자가 CDS를 배우면 모든 JOIN, CASE, 계산식을 하나의 View에 몰아넣는 실수를 할 수 있다.  
실무에서는 View 계층, 재사용성, 성능, 권한, 테스트 가능성을 고려해야 한다.

## 18. 평가 문제

### 18.1 객관식

#### Q1. CDS View Entity를 정의하는 기본 구문은 무엇인가?

A. `define table entity`  
B. `define view entity`  
C. `create database table`  
D. `select view from entity`

**정답:** B

#### Q2. CDS View Entity에서 데이터 소스를 지정하는 구문은?

A. `as select from`  
B. `into table`  
C. `start-of-selection`  
D. `write from`

**정답:** A

#### Q3. CDS View Entity에서 `@AbapCatalog.sqlViewName`에 대한 설명으로 적절한 것은?

A. View Entity에서 반드시 필요하다.  
B. View Entity에서는 사용하지 않는 것이 기본이다.  
C. 모든 ABAP 프로그램에 반드시 필요하다.  
D. Data Preview를 실행하기 위한 트랜잭션 코드이다.

**정답:** B

### 18.2 서술형

#### Q1. CDS View Entity를 사용하는 이유를 설명하시오.

**모범 답안:**  
CDS View Entity는 테이블이나 다른 CDS 위에 재사용 가능한 조회 모델을 정의한다. 프로그램마다 반복되는 SELECT 구조를 중앙화하고, element 이름, key, annotation, 후속 서비스 노출, RAP/Fiori 확장에 필요한 의미 모델을 제공할 수 있다.

#### Q2. `as select from spfli`의 의미를 설명하시오.

**모범 답안:**  
`SPFLI` 테이블을 데이터 소스로 사용하여 CDS View Entity의 결과 element를 정의한다는 의미이다.

#### Q3. CDS의 `key`를 DB Primary Key와 동일하게만 이해하면 안 되는 이유를 설명하시오.

**모범 답안:**  
CDS의 `key`는 View 결과 모델에서 식별 역할을 하는 element를 표시한다. 원천 테이블의 Primary Key와 일치할 수 있지만, CDS 모델의 목적, 집계 여부, Projection 여부, 소비 계층에 따라 의미가 달라질 수 있으므로 단순히 DB Primary Key와 동일하다고만 보면 안 된다.
