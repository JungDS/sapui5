## 3. SET_TABLE_FOR_FIRST_DISPLAY란 무엇인가?

`SET_TABLE_FOR_FIRST_DISPLAY`는 `CL_GUI_ALV_GRID` 클래스의 대표 메서드이다.  
이 메서드는 Grid ALV에 출력 대상 데이터와 출력 메타데이터를 전달하여 최초 화면 표시를 수행한다.

초급자 관점에서 다음처럼 이해하면 쉽다.

```text
CL_GUI_ALV_GRID 객체 = ALV 표를 표시할 화면 컴포넌트
IT_OUTTAB = 화면에 보여줄 실제 데이터
IT_FIELDCATALOG = 각 컬럼을 어떻게 보여줄지에 대한 설명서
SET_TABLE_FOR_FIRST_DISPLAY = 데이터와 설명서를 Grid에 연결해 최초 표시하는 호출
```

즉, Grid 객체만 생성했다고 ALV가 자동으로 나타나는 것은 아니다.  
Grid 객체에 어떤 데이터를 어떤 컬럼 구조로 표시할지 알려주는 단계가 필요하며, 이 역할을 하는 메서드가 `SET_TABLE_FOR_FIRST_DISPLAY`이다.

## 4. 메서드 호출의 기본 구조

대표적인 호출 형태는 다음과 같다.

```abap
go_grid->set_table_for_first_display(
  EXPORTING
    is_layout       = gs_layout
    is_variant      = gs_variant
    i_save          = 'A'
  CHANGING
    it_outtab       = gt_data
    it_fieldcatalog = gt_fieldcat
  EXCEPTIONS
    invalid_parameter_combination = 1
    program_error                 = 2
    too_many_lines                = 3
    OTHERS                        = 4 ).
```

초급 단계에서 가장 중요하게 볼 파라미터는 다음이다.

| 파라미터 | 방향 | 의미 |
|---|---|---|
| `IT_OUTTAB` | CHANGING | ALV에 표시할 Internal Table |
| `IT_FIELDCATALOG` | CHANGING | ALV 컬럼 정의 |
| `IS_LAYOUT` | EXPORTING | ALV 표시 레이아웃 설정 |
| `IS_VARIANT` | EXPORTING | Layout Variant 설정 |
| `I_SAVE` | EXPORTING | Variant 저장 허용 범위 |

`IT_OUTTAB`과 `IT_FIELDCATALOG`는 `CHANGING` 파라미터이다.  
초급자는 이 점 때문에 “왜 출력용 데이터인데 CHANGING인가?”라고 느낄 수 있다. ALV Grid 내부에서 표시 준비 과정 중 테이블 참조와 메타데이터 처리에 관여하기 때문에 메서드 시그니처상 `CHANGING`으로 정의되어 있다. 실무에서는 이 파라미터에 넘기는 Internal Table과 Field Catalog가 호출 시점에 정상 구성되어 있어야 한다는 점이 더 중요하다.

---

## 5. IT_OUTTAB의 역할

`IT_OUTTAB`은 Grid ALV에 표시할 실제 데이터 Internal Table이다.

예를 들어 항공사 데이터를 표시한다면 다음과 같은 Internal Table이 필요하다.

```abap
TYPES: BEGIN OF ty_sflight_alv,
         carrid   TYPE sflight-carrid,
         connid   TYPE sflight-connid,
         fldate   TYPE sflight-fldate,
         price    TYPE sflight-price,
         currency TYPE sflight-currency,
       END OF ty_sflight_alv.

DATA gt_data TYPE STANDARD TABLE OF ty_sflight_alv.
```

데이터는 보통 `SELECT` 결과 또는 가공 결과로 채운다.

```abap
SELECT carrid,
       connid,
       fldate,
       price,
       currency
  FROM sflight
  INTO TABLE @gt_data
  UP TO 100 ROWS.
```

> [추정] 교육 시스템에 `SFLIGHT` 데모 데이터가 없거나 권한이 제한된 경우, 같은 구조의 Internal Table을 직접 `APPEND VALUE #( ... )` 방식으로 채워도 실습 목적은 달성할 수 있다.

### 5.1 IT_OUTTAB 점검 기준

`SET_TABLE_FOR_FIRST_DISPLAY` 호출 전에 다음을 확인한다.

| 점검 항목 | 확인 방법 |
|---|---|
| Internal Table이 선언되었는가 | `GT_DATA` 존재 여부 확인 |
| Line Type이 Field Catalog와 맞는가 | Field Catalog의 `FIELDNAME`과 구조 필드명 비교 |
| 데이터가 들어 있는가 | `LINES( gt_data )` 또는 디버거 확인 |
| 너무 많은 데이터가 아닌가 | 초급 실습은 `UP TO 100 ROWS` 권장 |
| DB 조회 실패를 처리했는가 | `SY-SUBRC`, `LINES( )` 확인 |

데이터가 0건이어도 ALV Grid 자체는 표시될 수 있다.  
하지만 초급자 실습에서는 데이터가 없으면 “ALV가 안 뜬다”고 오해하기 쉬우므로, 먼저 데이터 건수를 확인하는 습관이 필요하다.

## 6. IT_FIELDCATALOG의 역할

`IT_FIELDCATALOG`는 ALV 컬럼 정의 테이블이다.  
Grid ALV는 출력 데이터만 보고도 일부 컬럼을 추론할 수 있지만, 실무에서는 Field Catalog를 명시적으로 구성하는 것이 일반적이다.

대표 선언은 다음과 같다.

```abap
DATA gt_fieldcat TYPE lvc_t_fcat.
DATA gs_fieldcat TYPE lvc_s_fcat.
```

예시는 다음과 같다.

```abap
CLEAR gs_fieldcat.
gs_fieldcat-fieldname = 'CARRID'.
gs_fieldcat-coltext   = '항공사'.
gs_fieldcat-outputlen = 10.
APPEND gs_fieldcat TO gt_fieldcat.

CLEAR gs_fieldcat.
gs_fieldcat-fieldname = 'CONNID'.
gs_fieldcat-coltext   = '연결번호'.
gs_fieldcat-outputlen = 10.
APPEND gs_fieldcat TO gt_fieldcat.

CLEAR gs_fieldcat.
gs_fieldcat-fieldname = 'FLDATE'.
gs_fieldcat-coltext   = '비행일자'.
gs_fieldcat-outputlen = 12.
APPEND gs_fieldcat TO gt_fieldcat.
```

### 6.1 Field Catalog와 IT_OUTTAB의 연결

가장 중요한 규칙은 다음이다.

```text
Field Catalog의 FIELDNAME은 IT_OUTTAB Line Type의 필드명과 일치해야 한다.
```

예를 들어 `GT_DATA`의 필드가 `CARRID`인데 Field Catalog에 `CARRIER_ID`라고 적으면 해당 컬럼이 정상 표시되지 않거나 예기치 않은 결과가 발생할 수 있다.

### 6.2 실무 점검 포인트

| 오류 유형 | 원인 | 해결 |
|---|---|---|
| 컬럼이 안 보임 | `FIELDNAME` 오타 | Internal Table 필드명과 비교 |
| 컬럼 제목이 이상함 | `COLTEXT` 누락 | Field Catalog 라벨 설정 |
| 금액/수량 표시가 어색함 | 통화/단위 참조 부족 | `CFIELDNAME`, `QFIELDNAME` 검토 |
| 정렬/합계가 의도와 다름 | 필드 속성 누락 | `DO_SUM`, `KEY`, `NO_OUT` 등 검토 |
| 컬럼 순서가 다름 | Field Catalog 순서 또는 `COL_POS` | 순서 명시 |

이번 모듈에서는 `SET_TABLE_FOR_FIRST_DISPLAY`에 전달하는 기본 흐름이 핵심이므로, Field Catalog 심화 속성은 후속 모듈에서 필요한 만큼 확장한다.

## 7. Layout과 Variant 연결

앞선 모듈에서 준비한 Layout과 Variant는 `SET_TABLE_FOR_FIRST_DISPLAY` 호출 시 함께 전달된다.

### 7.1 Layout 예시

```abap
DATA gs_layout TYPE lvc_s_layo.

gs_layout-zebra      = abap_true.
gs_layout-cwidth_opt = abap_true.
gs_layout-sel_mode   = 'A'.
```

`IS_LAYOUT = gs_layout`로 전달하면 Grid가 Zebra 패턴, 컬럼폭 최적화, 선택 모드 등을 반영해 표시한다.

### 7.2 Variant 예시

```abap
DATA gs_variant TYPE disvariant.

gs_variant-report = sy-repid.
```

그리고 다음과 같이 전달한다.

```abap
is_variant = gs_variant
i_save     = 'A'
```

실무에서 Variant를 안정적으로 사용하려면 `GS_VARIANT-REPORT`를 명확히 설정해야 한다.  
보통 현재 Report 기준으로 `SY-REPID`를 사용한다.

## 8. 최초 표시와 Refresh의 차이

초급자가 가장 많이 하는 실수 중 하나는 데이터를 갱신할 때마다 `SET_TABLE_FOR_FIRST_DISPLAY`를 다시 호출하는 것이다.

원칙은 다음과 같다.

```text
최초 1회 표시: SET_TABLE_FOR_FIRST_DISPLAY
이후 데이터 변경 반영: REFRESH_TABLE_DISPLAY
```

### 8.1 최초 표시

화면이 처음 열리고 Grid 객체가 생성된 뒤, 데이터와 Field Catalog를 연결하는 시점이다.

```abap
IF go_grid IS INITIAL.
  "Container와 Grid 생성
  "Field Catalog 구성
  "SET_TABLE_FOR_FIRST_DISPLAY 호출
ENDIF.
```

### 8.2 이후 Refresh

이미 Grid가 생성되어 표시된 상태에서 Internal Table 데이터만 변경되었다면 Refresh를 사용한다.

```abap
go_grid->refresh_table_display( ).
```

Stable Refresh는 다음 모듈에서 더 자세히 다룬다.

> 이 모듈에서는 `SET_TABLE_FOR_FIRST_DISPLAY`는 “처음 보여줄 때”, `REFRESH_TABLE_DISPLAY`는 “이미 보여준 뒤 다시 그릴 때”라는 구분만 확실히 잡는다.

## 9. PBO에서의 표준 흐름

Grid ALV는 Classic Dynpro 화면 위에서 동작한다.  
따라서 보통 PBO(Process Before Output) 모듈에서 객체 생성과 최초 Display 호출을 수행한다.

```abap
MODULE status_0100 OUTPUT.
  SET PF-STATUS 'S100'.
  SET TITLEBAR 'T100'.

  IF go_container IS INITIAL.
    PERFORM create_alv_objects.
    PERFORM get_data.
    PERFORM build_fieldcat.
    PERFORM build_layout.
    PERFORM build_variant.
    PERFORM display_alv.
  ENDIF.
ENDMODULE.
```

이 흐름의 핵심은 `GO_CONTAINER IS INITIAL` 조건이다.  
PBO는 화면이 다시 그려질 때마다 반복 실행될 수 있으므로, 객체 생성과 최초 Display를 매번 실행하면 안 된다.

## 10. 최소 전체 예제

아래 예제는 Screen 0100에 Custom Control `CC_ALV`가 만들어져 있다고 가정한다.

### 10.1 전역 선언

```abap
REPORT zgrid_alv_first_display.

TYPES: BEGIN OF ty_sflight_alv,
         carrid   TYPE sflight-carrid,
         connid   TYPE sflight-connid,
         fldate   TYPE sflight-fldate,
         price    TYPE sflight-price,
         currency TYPE sflight-currency,
       END OF ty_sflight_alv.

DATA gt_data     TYPE STANDARD TABLE OF ty_sflight_alv.
DATA gt_fieldcat TYPE lvc_t_fcat.
DATA gs_fieldcat TYPE lvc_s_fcat.
DATA gs_layout   TYPE lvc_s_layo.
DATA gs_variant  TYPE disvariant.

DATA go_container TYPE REF TO cl_gui_custom_container.
DATA go_grid      TYPE REF TO cl_gui_alv_grid.
```

### 10.2 START-OF-SELECTION

```abap
START-OF-SELECTION.
  CALL SCREEN 0100.
```

### 10.3 PBO / PAI

```abap
MODULE status_0100 OUTPUT.
  SET PF-STATUS 'S100'.
  SET TITLEBAR 'T100'.

  IF go_container IS INITIAL.
    PERFORM create_alv_objects.
    PERFORM get_data.
    PERFORM build_fieldcat.
    PERFORM build_layout.
    PERFORM build_variant.
    PERFORM display_alv.
  ENDIF.
ENDMODULE.

MODULE user_command_0100 INPUT.
  CASE sy-ucomm.
    WHEN 'BACK' OR 'EXIT' OR 'CANC'.
      LEAVE TO SCREEN 0.
  ENDCASE.
ENDMODULE.
```

### 10.4 Container와 Grid 생성

```abap
FORM create_alv_objects.
  CREATE OBJECT go_container
    EXPORTING
      container_name = 'CC_ALV'.

  CREATE OBJECT go_grid
    EXPORTING
      i_parent = go_container.
ENDFORM.
```

### 10.5 데이터 조회

```abap
FORM get_data.
  SELECT carrid,
         connid,
         fldate,
         price,
         currency
    FROM sflight
    INTO TABLE @gt_data
    UP TO 100 ROWS.

  IF gt_data IS INITIAL.
    MESSAGE '조회된 데이터가 없습니다.' TYPE 'S'.
  ENDIF.
ENDFORM.
```

### 10.6 Field Catalog 구성

```abap
FORM build_fieldcat.
  CLEAR gt_fieldcat.

  CLEAR gs_fieldcat.
  gs_fieldcat-fieldname = 'CARRID'.
  gs_fieldcat-coltext   = '항공사'.
  gs_fieldcat-outputlen = 10.
  APPEND gs_fieldcat TO gt_fieldcat.

  CLEAR gs_fieldcat.
  gs_fieldcat-fieldname = 'CONNID'.
  gs_fieldcat-coltext   = '연결번호'.
  gs_fieldcat-outputlen = 10.
  APPEND gs_fieldcat TO gt_fieldcat.

  CLEAR gs_fieldcat.
  gs_fieldcat-fieldname = 'FLDATE'.
  gs_fieldcat-coltext   = '비행일자'.
  gs_fieldcat-outputlen = 12.
  APPEND gs_fieldcat TO gt_fieldcat.

  CLEAR gs_fieldcat.
  gs_fieldcat-fieldname = 'PRICE'.
  gs_fieldcat-coltext   = '가격'.
  gs_fieldcat-outputlen = 15.
  APPEND gs_fieldcat TO gt_fieldcat.

  CLEAR gs_fieldcat.
  gs_fieldcat-fieldname = 'CURRENCY'.
  gs_fieldcat-coltext   = '통화'.
  gs_fieldcat-outputlen = 5.
  APPEND gs_fieldcat TO gt_fieldcat.
ENDFORM.
```

### 10.7 Layout 구성

```abap
FORM build_layout.
  CLEAR gs_layout.

  gs_layout-zebra      = abap_true.
  gs_layout-cwidth_opt = abap_true.
  gs_layout-sel_mode   = 'A'.
ENDFORM.
```

### 10.8 Variant 구성

```abap
FORM build_variant.
  CLEAR gs_variant.

  gs_variant-report = sy-repid.
ENDFORM.
```

### 10.9 최초 Display

```abap
FORM display_alv.
  go_grid->set_table_for_first_display(
    EXPORTING
      is_layout       = gs_layout
      is_variant      = gs_variant
      i_save          = 'A'
    CHANGING
      it_outtab       = gt_data
      it_fieldcatalog = gt_fieldcat
    EXCEPTIONS
      invalid_parameter_combination = 1
      program_error                 = 2
      too_many_lines                = 3
      OTHERS                        = 4 ).

  IF sy-subrc <> 0.
    MESSAGE 'ALV 최초 출력 중 오류가 발생했습니다.' TYPE 'E'.
  ENDIF.
ENDFORM.
```

### 11.2 실습 목표

`SET_TABLE_FOR_FIRST_DISPLAY`를 사용해 `GT_DATA`를 Grid ALV로 최초 표시한다.

### 11.3 실습 순서

```text
1. Screen 0100에 Custom Control CC_ALV가 있는지 확인한다.
2. PBO에서 Container와 Grid 객체를 생성한다.
3. 출력용 Internal Table GT_DATA를 채운다.
4. Field Catalog GT_FIELDCAT를 구성한다.
5. Layout GS_LAYOUT을 구성한다.
6. Variant GS_VARIANT를 구성한다.
7. SET_TABLE_FOR_FIRST_DISPLAY를 호출한다.
8. 화면에 ALV Grid가 표시되는지 확인한다.
9. 컬럼 제목과 데이터가 의도대로 보이는지 확인한다.
10. 오류 발생 시 SY-SUBRC와 Field Catalog를 우선 확인한다.
```

## 12. 정상 흐름과 오류 흐름

### 12.1 정상 흐름

```text
Screen 0100 호출
→ PBO 실행
→ Custom Container 생성
→ ALV Grid 생성
→ 데이터 조회
→ Field Catalog 구성
→ Layout/Variant 구성
→ SET_TABLE_FOR_FIRST_DISPLAY 호출
→ Grid ALV 화면 표시
```

### 12.2 오류 흐름 1: Custom Control 이름 불일치

증상:

```text
화면에서 Control Framework 관련 오류 발생
```

가능한 원인:

```text
Screen Painter의 Custom Control 이름은 CC_ALV인데
CREATE OBJECT에서 container_name = 'CCALV'처럼 다르게 입력
```

해결:

```text
Screen Painter의 Custom Control Name과 container_name 문자열을 정확히 일치시킨다.
```

### 12.3 오류 흐름 2: Grid 객체가 생성되지 않음

증상:

```text
GO_GRID가 INITIAL 상태
SET_TABLE_FOR_FIRST_DISPLAY 호출 시 덤프 또는 오류
```

원인:

```text
CREATE OBJECT go_grid가 실패했거나 호출되지 않음
```

해결:

```text
PBO 흐름에서 create_alv_objects가 먼저 호출되는지 확인한다.
GO_CONTAINER가 정상 생성되었는지 디버깅한다.
```

### 12.4 오류 흐름 3: Field Catalog 필드명 오타

증상:

```text
특정 컬럼이 표시되지 않거나 값이 비어 보임
```

원인:

```text
GT_FIELDCAT-FIELDNAME과 GT_DATA의 실제 필드명이 불일치
```

해결:

```text
디버거에서 GT_DATA Line Type과 GT_FIELDCAT-FIELDNAME 값을 비교한다.
FIELDNAME은 일반적으로 대문자 필드명으로 맞춘다.
```

### 12.5 오류 흐름 4: SET_TABLE_FOR_FIRST_DISPLAY 반복 호출

증상:

```text
화면 깜빡임
사용자 변경 Layout 초기화
Variant 적용 혼선
성능 저하
```

원인:

```text
PBO가 실행될 때마다 SET_TABLE_FOR_FIRST_DISPLAY를 호출
```

해결:

```text
IF go_container IS INITIAL.
  "최초 1회 생성 및 display
ENDIF.
```

이후 데이터 변경에는 `REFRESH_TABLE_DISPLAY`를 사용한다.

### 12.6 오류 흐름 5: 데이터 0건

증상:

```text
Grid는 표시되지만 데이터가 비어 있음
```

원인:

```text
SELECT 결과가 없음
권한 또는 Client 차이
조회 조건이 너무 제한적
```

해결:

```text
LINES( gt_data ) 확인
SELECT 조건 완화
SE16N 또는 ADT Data Preview로 원천 테이블 확인
```

## 13. 디버깅 포인트

`SET_TABLE_FOR_FIRST_DISPLAY` 오류를 추적할 때는 다음 순서로 본다.

| 순서 | 확인 대상 | 확인 내용 |
|---:|---|---|
| 1 | `GO_CONTAINER` | 객체가 생성되었는가 |
| 2 | `GO_GRID` | Grid 객체가 생성되었는가 |
| 3 | `GT_DATA` | 데이터가 들어 있는가 |
| 4 | `GT_FIELDCAT` | Field Catalog가 비어 있지 않은가 |
| 5 | `FIELDNAME` | 출력 구조 필드명과 일치하는가 |
| 6 | `GS_LAYOUT` | 잘못된 레이아웃 값은 없는가 |
| 7 | `GS_VARIANT` | `REPORT` 값이 설정되었는가 |
| 8 | `SY-SUBRC` | 메서드 호출 결과가 0인가 |
| 9 | PBO 조건 | 최초 호출 조건이 올바른가 |

디버거에서 가장 먼저 확인할 항목은 다음 두 가지이다.

```text
GT_DATA[]가 비어 있지 않은가?
GT_FIELDCAT[]의 FIELDNAME이 GT_DATA의 필드명과 일치하는가?
```

## 14. 실무 적용 기준

### 14.1 최초 Display 메서드는 화면 초기화 지점에 둔다

실무 Grid ALV 프로그램에서는 PBO에서 객체 생성과 최초 Display를 처리하는 경우가 많다.  
단, PBO는 여러 번 실행될 수 있으므로 반드시 최초 1회만 실행되도록 제어한다.

```abap
IF go_grid IS INITIAL.
  "Create and first display
ENDIF.
```

### 14.2 데이터 조회와 ALV 출력 책임을 분리한다

좋지 않은 예:

```abap
FORM display_alv.
  SELECT ...
  BUILD FIELDCAT ...
  SET_TABLE_FOR_FIRST_DISPLAY ...
ENDFORM.
```

권장 예:

```text
GET_DATA
BUILD_FIELDCAT
BUILD_LAYOUT
BUILD_VARIANT
DISPLAY_ALV
```

절차를 분리하면 오류 원인을 추적하기 쉽고, 이후 Refresh나 조건 재조회 기능을 추가하기도 쉽다.

### 14.3 화면 표시용 데이터는 별도 타입으로 준비한다

DB 테이블 전체를 그대로 출력하기보다, ALV 출력 목적에 맞는 구조를 준비하는 것이 좋다.

```text
DB 조회 구조
→ 업무 계산/텍스트 보강
→ ALV 출력 구조
```

특히 금액/수량/상태 텍스트/색상 필드가 추가되면 출력 구조를 별도로 설계하는 편이 유지보수에 유리하다.

### 14.4 예외 처리를 생략하지 않는다

초급 예제에서 `EXCEPTIONS`를 생략하면 화면에 아무것도 표시되지 않을 때 원인 추적이 어렵다.  
최소한 `SY-SUBRC`를 확인하고 메시지를 출력하는 습관이 필요하다.

## 15. 안티패턴과 개선

| 안티패턴 | 문제 | 개선 |
|---|---|---|
| PBO마다 최초 Display 호출 | 화면 재초기화, 성능 저하 | 최초 1회만 호출 |
| Field Catalog 없이 감으로 출력 | 컬럼 제어 어려움 | `LVC_T_FCAT` 구성 |
| 데이터 조회와 화면 출력을 한 FORM에 몰아넣음 | 오류 추적 어려움 | 책임별 FORM 분리 |
| `SY-SUBRC` 미확인 | 오류 원인 파악 어려움 | 메서드 호출 후 결과 확인 |
| Variant의 `REPORT` 미설정 | Variant 저장/조회 불안정 | `GS_VARIANT-REPORT = SY-REPID` |
| 너무 많은 데이터 즉시 조회 | 성능 저하 | 조건 또는 Row 제한 사용 |

## 16. 평가 문제

### 16.1 객관식

#### Q1. `SET_TABLE_FOR_FIRST_DISPLAY`의 주된 목적은 무엇인가?

A. Internal Table의 데이터를 DB에 저장한다.  
B. Grid ALV에 출력 데이터와 Field Catalog를 연결하여 최초 표시한다.  
C. Selection Screen 필드를 생성한다.  
D. ALV Variant만 삭제한다.

**정답:** B

#### Q2. `IT_OUTTAB`에 전달하는 것은 무엇인가?

A. ALV에 표시할 실제 데이터 Internal Table  
B. GUI Status 이름  
C. Screen 번호  
D. Function Code 목록

**정답:** A

#### Q3. `SET_TABLE_FOR_FIRST_DISPLAY`를 반복 호출하는 대신 데이터 변경 후 사용하는 메서드는?

A. `CREATE_OBJECT`  
B. `FREE`  
C. `REFRESH_TABLE_DISPLAY`  
D. `CALL SCREEN`

**정답:** C

### 16.2 서술형

#### Q1. `IT_OUTTAB`과 `IT_FIELDCATALOG`의 차이를 설명하시오.

**모범 답안:**  
`IT_OUTTAB`은 ALV에 표시할 실제 데이터 Internal Table이고, `IT_FIELDCATALOG`는 그 데이터를 어떤 컬럼명, 제목, 길이, 속성으로 표시할지 정의하는 컬럼 메타데이터이다.

#### Q2. PBO에서 `GO_CONTAINER IS INITIAL` 조건을 사용하는 이유는 무엇인가?

**모범 답안:**  
PBO는 화면이 다시 그려질 때마다 여러 번 실행될 수 있다. Container와 Grid 생성, `SET_TABLE_FOR_FIRST_DISPLAY` 호출은 최초 1회만 수행해야 화면 재초기화와 성능 문제를 피할 수 있기 때문이다.

#### Q3. Field Catalog의 `FIELDNAME` 오타가 발생하면 어떤 문제가 생길 수 있는가?

**모범 답안:**  
ALV가 출력 데이터의 실제 필드와 Field Catalog를 연결하지 못해 컬럼이 표시되지 않거나 값이 비어 보일 수 있다. 디버거에서 `GT_DATA`의 필드명과 `GT_FIELDCAT-FIELDNAME`을 비교해야 한다.

## 18. 후속 모듈 연결

다음 모듈은 `THEORY-15-M08 — Refresh와 Stable Refresh 기초`이다.

이번 모듈이 최초 표시를 다뤘다면, 다음 모듈은 이미 표시된 ALV의 데이터를 다시 그리는 방법을 다룬다.

```text
M07: SET_TABLE_FOR_FIRST_DISPLAY
     최초 데이터 바인딩과 화면 표시

M08: REFRESH_TABLE_DISPLAY
     데이터 변경 후 Grid 갱신

M09: 컬럼 색상과 행 색상 기초
     기본 색상 표현
```

중요한 구분은 다음이다.

```text
처음 표시할 때: SET_TABLE_FOR_FIRST_DISPLAY
이미 표시된 뒤 갱신할 때: REFRESH_TABLE_DISPLAY
```

## 19. 핵심 요약

```text
SET_TABLE_FOR_FIRST_DISPLAY는 Grid ALV 최초 표시의 핵심 메서드이다.
IT_OUTTAB은 실제 출력 데이터이고, IT_FIELDCATALOG는 컬럼 표시 설명서이다.
IS_LAYOUT과 IS_VARIANT는 앞선 모듈에서 만든 표시 옵션을 연결한다.
PBO는 여러 번 실행될 수 있으므로 최초 Display는 1회만 호출해야 한다.
데이터 갱신은 다음 모듈의 REFRESH_TABLE_DISPLAY로 처리한다.
오류가 발생하면 Container, Grid, Data, Field Catalog, SY-SUBRC 순서로 확인한다.
```
