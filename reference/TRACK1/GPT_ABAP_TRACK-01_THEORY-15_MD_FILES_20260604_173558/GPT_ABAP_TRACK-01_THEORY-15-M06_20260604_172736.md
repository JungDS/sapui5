## 1. 이 문서의 목적

이 문서는 `CL_GUI_ALV_GRID`에서 **Layout Variant**를 기본 설정하는 방법을 다룬다.  
이전 모듈에서 Custom Container, ALV Grid 객체, 출력용 Internal Table, Field Catalog, Layout 기본 설정을 준비했다면, 이번 모듈에서는 사용자가 자신의 ALV 표시 상태를 저장하고 다시 불러올 수 있는 **Variant 구조**를 이해한다.

## 2. 선수 지식

이 모듈은 `THEORY-15 Grid ALV 기초` 중간 단계에 해당한다.  
다음 내용을 이미 알고 있어야 한다.

| 선수 개념 | 필요 이유 |
|---|---|
| `CL_GUI_CUSTOM_CONTAINER` | Grid ALV가 표시될 화면 영역을 준비해야 한다. |
| `CL_GUI_ALV_GRID` | Variant는 ALV Grid 표시 메서드와 함께 전달된다. |
| 출력용 Internal Table | ALV에 표시할 데이터가 필요하다. |
| `LVC_T_FCAT` Field Catalog | 컬럼 표시 정보가 있어야 Variant가 컬럼 상태를 저장할 수 있다. |
| `LVC_S_LAYO` Layout | 기본 표시 속성과 Variant의 역할을 구분해야 한다. |
| `SET_TABLE_FOR_FIRST_DISPLAY` | Variant 관련 파라미터는 이 메서드 호출 시 함께 사용된다. |

> Layout은 개발자가 정하는 기본 화면 속성이고, Variant는 사용자가 저장해 다시 불러올 수 있는 화면 표시 상태이다.

## 3. ALV Layout Variant란 무엇인가?

### 3.1 기본 정의

ALV Layout Variant는 ALV Grid 화면의 표시 상태를 저장하는 기능이다.  
사용자는 ALV 화면에서 컬럼 순서, 숨김 컬럼, 정렬, 필터, 합계, 컬럼 폭 등을 조정한 뒤 Variant로 저장할 수 있다.

예를 들어 영업오더 리스트 ALV에서 사용자마다 보고 싶은 컬럼이 다를 수 있다.

| 사용자 | 관심 컬럼 |
|---|---|
| 영업 담당자 | 고객, 주문번호, 주문일자, 금액 |
| 물류 담당자 | 플랜트, 납품일, 출고상태 |
| 회계 담당자 | 금액, 통화, 청구상태 |

같은 ALV 프로그램이라도 사용자는 각자의 업무 관점으로 레이아웃을 다르게 보고 싶어 한다.  
Variant는 이 차이를 저장하고 재사용할 수 있게 해준다.

### 3.2 Variant에 저장될 수 있는 대표 항목

시스템 설정과 ALV 기능 사용 범위에 따라 차이가 있지만, 일반적으로 다음과 같은 표시 상태가 Variant에 반영될 수 있다.

| 항목 | 설명 |
|---|---|
| 컬럼 순서 | 사용자가 컬럼 위치를 변경한 상태 |
| 컬럼 숨김 | 특정 컬럼을 보이지 않게 한 상태 |
| 컬럼 폭 | 컬럼 너비 조정 상태 |
| 정렬 | 특정 컬럼 기준 오름차순/내림차순 |
| 필터 | 특정 조건으로 데이터 표시 제한 |
| 합계/소계 | 숫자 컬럼의 집계 표시 |
| Grouping 관련 표시 | ALV 기능 범위에 따라 그룹성 표시 |

이번 모듈에서는 Variant의 세부 사용자 조작법보다 ABAP 코드에서 Variant 사용을 가능하게 하는 기본 설정에 집중한다.

## 4. Layout과 Variant의 차이

`LVC_S_LAYO` Layout과 Variant는 모두 ALV 표시와 관련되어 있어 초급자가 혼동하기 쉽다.

| 구분 | Layout (`LVC_S_LAYO`) | Variant (`DISVARIANT`) |
|---|---|---|
| 주체 | 개발자 | 사용자 또는 개발자 기본값 |
| 목적 | ALV 기본 표시 속성 제어 | 사용자가 저장한 화면 상태 재사용 |
| 예시 | Zebra, Column Width Optimize, Row Color Field | 컬럼 순서, 숨김, 정렬, 필터 저장 |
| 전달 위치 | `IS_LAYOUT` | `IS_VARIANT` |
| 저장 허용 제어 | 직접 담당하지 않음 | `I_SAVE`와 함께 사용 |
| 대표 구조 | `LVC_S_LAYO` | `DISVARIANT` |

예를 들어 개발자는 Zebra 표시를 기본으로 켜고 싶을 수 있다.

```abap
gs_layout-zebra = abap_true.
```

반면 사용자는 자신의 화면에서 `STATUS` 컬럼을 왼쪽으로 옮기고, `CREATED_ON` 기준으로 내림차순 정렬한 상태를 저장하고 싶을 수 있다.  
이 사용자 설정은 Layout 자체가 아니라 Variant 기능과 관련된다.

## 5. 핵심 객체: DISVARIANT

### 5.1 DISVARIANT의 역할

`DISVARIANT`는 ALV Layout Variant를 식별하기 위한 정보를 담는 구조이다.  
Grid ALV에서는 `SET_TABLE_FOR_FIRST_DISPLAY` 호출 시 `IS_VARIANT` 파라미터에 전달할 수 있다.

대표적으로 중요한 필드는 다음과 같다.

| 필드 | 의미 |
|---|---|
| `REPORT` | Variant를 연결할 프로그램 이름 |
| `HANDLE` | 하나의 프로그램 안에서 여러 ALV를 구분할 때 사용하는 핸들 |
| `VARIANT` | 특정 Variant 이름을 지정할 때 사용 |
| `USERNAME` | 사용자 관련 Variant 식별에 사용될 수 있는 필드 |

초급 단계에서는 가장 먼저 `REPORT` 필드를 정확히 이해해야 한다.

### 5.2 REPORT 필드

`gs_variant-report`에는 일반적으로 현재 프로그램 이름을 넣는다.

```abap
gs_variant-report = sy-repid.
```

이 값은 Variant가 어떤 프로그램에 속하는지 식별하는 기준이 된다.  
즉, 같은 이름의 Variant라도 프로그램이 다르면 서로 다른 Variant로 취급될 수 있다.

실무에서 가장 기본적인 형태는 다음과 같다.

```abap
DATA gs_variant TYPE disvariant.

gs_variant-report = sy-repid.
```

### 5.3 HANDLE 필드

한 프로그램 안에 ALV Grid가 하나만 있다면 `HANDLE`을 생략해도 되는 경우가 많다.  
하지만 한 화면에 여러 Grid ALV가 있거나, 하나의 프로그램 안에서 여러 ALV 표시 영역을 사용하는 경우에는 `HANDLE`을 통해 구분하는 것이 좋다.

예시:

```abap
gs_variant-report = sy-repid.
gs_variant-handle = 'GRID1'.
```

다른 Grid에는 다음처럼 별도 Handle을 줄 수 있다.

```abap
gs_variant_2-report = sy-repid.
gs_variant_2-handle = 'GRID2'.
```

초급 과정에서는 하나의 Grid만 사용하므로 `REPORT = SY-REPID`를 기본으로 익히고, `HANDLE`은 다중 Grid 상황에서 필요하다는 정도로 이해하면 충분하다.

## 6. 핵심 파라미터: I_SAVE

### 6.1 I_SAVE의 역할

`I_SAVE`는 사용자가 ALV Layout Variant를 저장할 수 있는 범위를 제어하는 파라미터이다.  
`SET_TABLE_FOR_FIRST_DISPLAY` 호출 시 함께 전달한다.

대표적으로 다음 값이 사용된다.

| 값 | 의미 |
|---|---|
| Space | Variant 저장 불가 |
| `U` | User-specific Variant 저장 허용 |
| `X` | Global Variant 저장 허용 |
| `A` | User-specific 및 Global Variant 모두 허용 |

> 실제 시스템의 권한과 설정에 따라 사용자가 저장할 수 있는 범위는 달라질 수 있다. 초급자는 `I_SAVE`가 저장 가능 여부와 저장 범위를 제어한다는 점을 먼저 이해한다.

### 6.2 User-specific Variant

User-specific Variant는 특정 사용자에게만 적용되는 Variant이다.

예를 들어 사용자 A가 `MY_LAYOUT`이라는 Variant를 저장해도, 사용자 B에게는 보이지 않거나 별도 Variant로 관리될 수 있다.  
개인별 업무 화면을 저장하는 목적에는 User-specific Variant가 적합하다.

일반적으로 다음처럼 설정한다.

```abap
i_save = 'U'
```

### 6.3 Global Variant

Global Variant는 여러 사용자가 함께 사용할 수 있는 Variant이다.  
운영 리포트에서 “표준 레이아웃”처럼 배포하려는 경우 사용될 수 있다.

```abap
i_save = 'X'
```

다만 Global Variant는 모든 사용자가 마음대로 저장하거나 변경하면 혼란이 커질 수 있으므로 권한과 운영 규칙이 중요하다.

### 6.4 둘 다 허용

사용자별 Variant와 Global Variant를 모두 허용하려면 다음 값을 사용할 수 있다.

```abap
i_save = 'A'
```

교육용 예제에서는 Variant 기능을 폭넓게 경험하기 위해 `A`를 사용할 수 있지만, 실무에서는 권한과 운영 정책에 맞게 결정한다.

## 7. SET_TABLE_FOR_FIRST_DISPLAY에서 Variant 연결

Variant 설정은 단독으로 동작하지 않고, ALV Grid 최초 표시 메서드와 함께 사용된다.

기본 형태는 다음과 같다.

```abap
CALL METHOD go_grid->set_table_for_first_display
  EXPORTING
    is_variant      = gs_variant
    i_save          = 'A'
    is_layout       = gs_layout
  CHANGING
    it_outtab       = gt_output
    it_fieldcatalog = gt_fcat.
```

여기서 핵심은 다음이다.

| 파라미터 | 의미 |
|---|---|
| `IS_VARIANT` | Variant 식별 정보 |
| `I_SAVE` | Variant 저장 허용 범위 |
| `IS_LAYOUT` | 개발자가 지정하는 기본 Layout |
| `IT_OUTTAB` | 출력 데이터 |
| `IT_FIELDCATALOG` | 컬럼 정의 |

### 7.1 가장 작은 Variant 예제

```abap
DATA gs_variant TYPE disvariant.

gs_variant-report = sy-repid.

CALL METHOD go_grid->set_table_for_first_display
  EXPORTING
    is_variant      = gs_variant
    i_save          = 'A'
    is_layout       = gs_layout
  CHANGING
    it_outtab       = gt_output
    it_fieldcatalog = gt_fcat.
```

이 예제는 가장 기본적인 Variant 활성화 형태이다.  
사용자는 ALV 화면에서 레이아웃을 조정하고 저장할 수 있다.

## 8. 전체 예제 흐름

아래 예제는 이 모듈의 핵심만 보여주기 위한 최소 구조이다.

## 9. 기본 Variant 지정

사용자가 특정 Variant를 기본으로 불러오게 하고 싶다면 `DISVARIANT-VARIANT` 필드를 사용할 수 있다.

```abap
gs_variant-report  = sy-repid.
gs_variant-variant = '/STANDARD'.
```

다만 초급 실습에서는 이 설정을 무리하게 적용하지 않는 것이 좋다.  
Variant 이름이 실제로 존재하지 않거나, 권한 또는 저장 범위가 맞지 않으면 예상과 다르게 동작할 수 있다.

먼저 다음 순서로 학습한다.

```text
1. REPORT만 설정한다.
2. I_SAVE로 저장 가능하게 한다.
3. ALV 화면에서 사용자가 직접 Variant를 저장해본다.
4. 저장한 Variant가 다시 조회되는지 확인한다.
5. 필요할 때 기본 Variant 지정으로 확장한다.
```

## 10. Variant 저장 실습

### 10.1 실습 목표

ALV Grid 화면에서 사용자가 Layout Variant를 저장하고 다시 불러오는 흐름을 확인한다.

### 10.2 선행 조건

다음이 준비되어 있어야 한다.

| 객체/구성 | 상태 |
|---|---|
| Screen 0100 | Custom Control 영역 존재 |
| Custom Control 이름 | 예: `CC_ALV` |
| `CL_GUI_CUSTOM_CONTAINER` 객체 | 생성 완료 |
| `CL_GUI_ALV_GRID` 객체 | 생성 완료 |
| 출력용 Internal Table | 데이터 존재 |
| Field Catalog | 최소 컬럼 구성 완료 |
| Layout | 기본 설정 완료 |
| Variant | `REPORT = SY-REPID` 설정 완료 |
| `I_SAVE` | `U`, `X`, `A` 중 하나 설정 |

### 10.3 실습 절차

1. ALV 프로그램 실행
2. Grid ALV 화면 확인
3. 컬럼 순서 변경
4. 특정 컬럼 숨김
5. 정렬 또는 필터 적용
6. Layout 저장 버튼 또는 메뉴 실행
7. Variant 이름 입력
8. 저장
9. 프로그램 재실행
10. 저장한 Variant가 목록에 나타나는지 확인
11. Variant 적용 후 화면 상태 확인

### 10.4 실습 기록 양식

| 기록 항목 | 예시 |
|---|---|
| 프로그램명 | `ZALV_GRID_VARIANT_01` |
| `GS_VARIANT-REPORT` 값 | `SY-REPID` |
| `I_SAVE` 값 | `A` |
| 저장 Variant 이름 | `JHY_TEST` |
| 변경한 화면 상태 | 컬럼 순서, 숨김 컬럼, 정렬 |
| 재실행 후 적용 여부 | 성공 / 실패 |
| 오류 또는 특이사항 | 권한 오류, 저장 버튼 미표시 등 |

## 11. 정상 흐름과 오류 흐름

### 11.1 정상 흐름

정상적인 Variant 설정 흐름은 다음과 같다.

```text
1. DISVARIANT 구조 선언
2. REPORT 필드에 SY-REPID 설정
3. SET_TABLE_FOR_FIRST_DISPLAY에서 IS_VARIANT 전달
4. I_SAVE에 저장 허용 값 전달
5. ALV 화면 실행
6. 사용자가 Layout 변경
7. Variant 저장
8. 프로그램 재실행
9. Variant 재사용 확인
```

### 11.2 오류 흐름 1: `GS_VARIANT-REPORT` 누락

#### 현상

Variant 저장 또는 조회가 예상대로 동작하지 않는다.

#### 원인

`DISVARIANT-REPORT`가 비어 있으면 Variant가 어떤 프로그램에 속하는지 명확하지 않다.

#### 해결

다음 코드를 추가한다.

```abap
gs_variant-report = sy-repid.
```

### 11.3 오류 흐름 2: `I_SAVE` 미설정

#### 현상

사용자가 Variant를 저장할 수 없거나 저장 버튼이 기대와 다르게 보인다.

#### 원인

`I_SAVE`에 저장 허용 값이 전달되지 않았다.

#### 해결

교육용으로는 다음처럼 설정한다.

```abap
i_save = 'A'
```

실무에서는 운영 기준에 따라 `U`, `X`, `A` 중 선택한다.

### 11.4 오류 흐름 3: Global Variant 저장 권한 부족

#### 현상

Global Variant 저장을 시도했지만 권한 오류가 발생한다.

#### 원인

Global Variant 저장은 시스템 권한과 운영 정책의 영향을 받을 수 있다.

#### 해결

- 개인 Variant로 저장한다.
- 권한 담당자에게 필요한 권한을 확인한다.
- 운영 리포트에서는 공용 Variant 관리 기준을 별도로 둔다.

### 11.5 오류 흐름 4: Field Catalog 변경으로 기존 Variant가 깨짐

#### 현상

기존 Variant 적용 시 컬럼이 사라지거나, 예상과 다른 화면이 표시된다.

#### 원인

Variant는 컬럼명과 표시 상태를 기준으로 저장된다.  
프로그램 변경으로 Field Catalog의 `FIELDNAME`이 바뀌거나 컬럼이 삭제되면 기존 Variant와 불일치가 생길 수 있다.

#### 해결

- 운영 중인 ALV의 Field Catalog 변경은 신중히 수행한다.
- 컬럼명을 불필요하게 변경하지 않는다.
- 변경 시 기존 Variant 영향 여부를 테스트한다.
- 필요한 경우 사용자에게 Variant 재저장을 안내한다.

## 12. 실무 설계 기준

### 12.1 Variant는 사용자 생산성과 직접 연결된다

실무 사용자는 ALV 리포트에서 매번 같은 화면 조정을 반복하고 싶어 하지 않는다.  
Variant 저장이 가능하면 사용자별 업무 화면을 빠르게 복원할 수 있다.

따라서 운영용 ALV 리포트에서는 Variant 제공 여부가 사용성에 큰 영향을 준다.

### 12.2 Global Variant는 운영 규칙이 필요하다

Global Variant는 여러 사용자가 함께 사용할 수 있어 편리하지만, 아무나 만들고 변경하면 Variant 목록이 혼란스러워진다.

실무에서는 다음 기준을 정하는 것이 좋다.

| 기준 | 예시 |
|---|---|
| Global Variant 생성 권한 | Key User 또는 운영 담당자 |
| 이름 규칙 | `/STD_SALES`, `/STD_MONTHLY` |
| 설명 규칙 | 업무 목적이 드러나는 설명 사용 |
| 변경 절차 | 운영 반영 전 테스트 |
| 삭제 기준 | 미사용 Variant 정리 |

### 12.3 Field Catalog와 Variant는 함께 관리해야 한다

Variant는 Field Catalog의 컬럼 구조와 밀접하게 연결된다.  
따라서 Field Catalog를 변경할 때는 기존 Variant 영향을 고려해야 한다.

위험한 변경 예시는 다음과 같다.

```text
FIELDNAME 변경
컬럼 삭제
동일 FIELDNAME에 의미가 다른 값 매핑
Output Table 구조의 필드명 변경
```

상대적으로 안전한 변경은 다음과 같다.

```text
COLTEXT 보완
OUTPUTLEN 조정
새 컬럼 추가
기본 정렬이나 Layout 일부 보완
```

단, 새 컬럼 추가도 기존 Variant에서는 숨겨지거나 예상 위치와 다를 수 있으므로 테스트가 필요하다.

## 13. 권한과 운영 안정성

Variant 저장은 단순 화면 설정처럼 보이지만 운영 시스템에서는 권한과 연결될 수 있다.

### 13.1 권한 관점

| 상황 | 검토 |
|---|---|
| 개인 Variant 저장 | 일반 사용자에게 허용되는 경우가 많음 |
| Global Variant 저장 | 권한 제한 가능 |
| 공용 Variant 변경/삭제 | 운영 기준 필요 |
| 민감 컬럼 숨김/표시 | 권한 제어와 혼동하지 말아야 함 |

중요한 점은 Variant가 보안 기능이 아니라는 것이다.  
사용자가 컬럼을 숨겨도 데이터 권한이 제어되는 것은 아니다.  
보안은 Authorization Object, Open SQL 조건, CDS DCL 등 별도 권한 체계로 설계해야 한다.

### 13.2 운영 안정성 관점

Variant 설정은 프로그램 로직을 직접 바꾸지는 않는다.  
하지만 사용자가 보는 화면과 업무 처리 방식에 영향을 준다.

예를 들어 사용자가 중요한 상태 컬럼을 숨긴 Variant를 사용하면 업무 판단을 놓칠 수 있다.  
따라서 운영 리포트의 기본 Variant는 업무상 필요한 핵심 컬럼이 보이도록 관리하는 것이 좋다.

---

## 14. 성능 관점

Variant 자체가 대량 데이터 조회 성능을 개선하는 기능은 아니다.  
정렬, 필터, 합계 등 표시 기능은 사용자 경험에 영향을 주지만, DB 조회 성능 문제를 해결하지 않는다.

성능 문제는 주로 다음 영역에서 다룬다.

| 영역 | 예시 |
|---|---|
| Open SQL | WHERE 조건, JOIN, 집계 |
| Internal Table | 정렬, 검색, Key 사용 |
| ALV 출력 | 불필요한 컬럼, 대량 데이터 표시 |
| DB 설계 | 인덱스, 테이블 구조 |

Variant는 사용자가 화면 표시를 편하게 조정하는 기능이지, 근본적인 데이터 조회 성능 튜닝 도구가 아니다.

## 16. 미니 실습 과제

### 16.1 기본 과제

기존 Grid ALV 프로그램에 다음 코드를 추가한다.

```abap
DATA gs_variant TYPE disvariant.

gs_variant-report = sy-repid.

CALL METHOD go_grid->set_table_for_first_display
  EXPORTING
    is_layout       = gs_layout
    is_variant      = gs_variant
    i_save          = 'A'
  CHANGING
    it_outtab       = gt_output
    it_fieldcatalog = gt_fcat.
```

실행 후 다음을 확인한다.

1. ALV 화면에서 컬럼 순서를 변경한다.
2. 특정 컬럼을 숨긴다.
3. Variant를 저장한다.
4. 프로그램을 다시 실행한다.
5. 저장한 Variant를 다시 적용한다.

### 16.2 오류 케이스 과제

다음 두 가지를 의도적으로 테스트한다.

| 테스트 | 기대 관찰 |
|---|---|
| `GS_VARIANT-REPORT`를 주석 처리 | Variant 저장/조회가 정상적이지 않을 수 있음 |
| `I_SAVE`를 제거 | 저장 기능이 제한되거나 표시되지 않을 수 있음 |

테스트 후 다음을 기록한다.

## 17. 자가 진단 문제

### Q1. `DISVARIANT`의 가장 중요한 기본 필드는 무엇인가?

A. `REPORT`  
B. `ZEBRA`  
C. `CWIDTH_OPT`  
D. `FIELDNAME`

**정답:** A

### Q2. `I_SAVE = 'U'`의 의미로 가장 적절한 것은?

A. Variant 저장 불가  
B. 사용자별 Variant 저장 허용  
C. Global Variant만 저장 허용  
D. Field Catalog 자동 생성

**정답:** B

### Q3. Layout과 Variant의 차이를 설명하시오.

**모범 답안:**  
Layout은 개발자가 지정하는 ALV 기본 표시 속성이고, Variant는 사용자가 ALV 화면에서 조정한 컬럼 순서, 숨김, 정렬, 필터 등의 표시 상태를 저장해 재사용하는 기능이다.

### Q4. Field Catalog의 `FIELDNAME` 변경이 기존 Variant에 영향을 줄 수 있는 이유는?

**모범 답안:**  
Variant는 ALV 컬럼의 식별 정보를 기준으로 저장된다. Field Catalog의 `FIELDNAME`이 바뀌면 기존 Variant가 저장한 컬럼 상태와 새 컬럼 구조가 맞지 않아 예상과 다른 화면이 표시될 수 있다.

### Q5. Variant로 컬럼을 숨기면 권한 제어가 되는가?

**모범 답안:**  
아니다. Variant는 화면 표시 상태를 저장하는 기능이지 보안 기능이 아니다. 데이터 권한은 별도의 Authorization 설계로 제어해야 한다.

## 19. 핵심 요약

```text
ALV Layout Variant는 사용자의 화면 표시 상태를 저장하고 재사용하는 기능이다.
DISVARIANT는 Variant를 식별하기 위한 구조이며, REPORT 필드가 중요하다.
I_SAVE는 Variant 저장 허용 범위를 제어한다.
대표 값은 U, X, A이며 각각 개인/공용/모두 허용 의미로 이해할 수 있다.
Variant는 사용성 기능이지 권한 제어 기능이 아니다.
Field Catalog 변경은 기존 Variant에 영향을 줄 수 있으므로 운영 리포트에서는 주의해야 한다.
```
