## 1. 이 문서의 목적

이 문서는 `THEORY-15-M05 — Layout 기본 설정`을 독립적으로 학습할 수 있도록 구성한 고품질 MD 원본이다.  
이전 모듈에서 `CL_GUI_CUSTOM_CONTAINER`, `CL_GUI_ALV_GRID`, 출력용 Internal Table, Field Catalog의 기본 구조를 확보했다면, 이번 모듈에서는 Grid ALV의 **표시 동작과 사용자 경험을 제어하는 Layout 구조체**를 학습한다.

Grid ALV에서 Layout은 단순한 “예쁘게 보이기” 옵션이 아니다.  
운영 현장에서 사용자가 데이터를 빠르게 읽고, 행을 구분하고, 컬럼 폭을 적절히 맞추고, 행 색상이나 선택 모드를 이해하는 데 영향을 주는 중요한 표시 제어 영역이다.

이번 모듈의 중심 구조체는 다음이다.

```abap
TYPE lvc_s_layo
```

특히 초급 단계에서는 다음 세 가지를 반드시 이해해야 한다.

```text
ZEBRA      : 행 배경을 교차 표시하여 가독성을 높인다.
CWIDTH_OPT : 컬럼 폭을 데이터와 헤더 기준으로 자동 최적화한다.
INFO_FNAME : 행 색상 정보를 담은 필드명을 지정한다.
```

다만 `INFO_FNAME`은 실제 행 색상 구현과 연결되므로, 이번 모듈에서는 Layout 필드의 의미와 기본 연결 방식까지만 다루고, 색상 제어의 세부 구현은 `THEORY-15-M09 컬럼 색상과 행 색상 기초`와 연결한다.

## 2. 선수 지식

이 문서를 이해하려면 다음 내용을 알고 있어야 한다.

| 선수 지식 | 필요한 이유 |
|---|---|
| Dynpro Screen 100 생성 | Grid ALV는 화면 컨테이너 위에 표시되기 때문이다. |
| Custom Control | `CL_GUI_CUSTOM_CONTAINER`가 화면 영역과 연결되기 때문이다. |
| `CL_GUI_ALV_GRID` | 실제 Grid ALV 객체가 Layout을 받아 표시를 제어한다. |
| 출력용 Internal Table | Layout은 출력 데이터의 표시 방식에 영향을 준다. |
| Field Catalog | Field Catalog는 컬럼 단위 속성, Layout은 Grid 전체 표시 속성에 가깝다. |

초급자는 다음 구분을 먼저 기억하면 좋다.

```text
Field Catalog = 컬럼 하나하나의 속성
Layout        = Grid 전체의 표시 방식과 사용자 경험
```

## 3. Layout이란 무엇인가?

Grid ALV에서 Layout은 ALV 화면 전체의 표시 속성을 담는 설정 구조체이다.  
SAP 표준 타입으로는 보통 `LVC_S_LAYO`를 사용한다.

```abap
DATA gs_layout TYPE lvc_s_layo.
```

이 구조체에 값을 채운 뒤 `SET_TABLE_FOR_FIRST_DISPLAY` 호출 시 전달한다.

```abap
go_grid->set_table_for_first_display(
  EXPORTING
    is_layout       = gs_layout
  CHANGING
    it_outtab       = gt_output
    it_fieldcatalog = gt_fcat
).
```

Layout은 다음과 같은 질문에 답한다.

```text
행을 줄무늬로 보여줄 것인가?
컬럼 폭을 자동으로 맞출 것인가?
행 색상 필드는 무엇인가?
선택 방식은 어떻게 할 것인가?
합계/소계 또는 기타 표시 옵션을 어떻게 둘 것인가?
```

이번 모듈은 초급 단계이므로 `ZEBRA`, `CWIDTH_OPT`, `INFO_FNAME`을 중심으로 진행한다.

## 4. Field Catalog와 Layout의 역할 분리

Grid ALV를 처음 배우면 Field Catalog와 Layout이 모두 화면 표시와 관련되어 혼동될 수 있다.  
실무에서는 두 개념을 다음처럼 분리해 이해하는 것이 좋다.

| 구분 | Field Catalog | Layout |
|---|---|---|
| 대표 타입 | `LVC_T_FCAT`, `LVC_S_FCAT` | `LVC_S_LAYO` |
| 주 대상 | 컬럼 단위 | Grid 전체 또는 행 표시 |
| 예시 속성 | `FIELDNAME`, `COLTEXT`, `OUTPUTLEN`, `KEY`, `NO_OUT` | `ZEBRA`, `CWIDTH_OPT`, `INFO_FNAME`, 선택 모드 |
| 책임 | 각 필드를 어떻게 보여줄지 | 전체 리스트를 어떤 방식으로 보여줄지 |
| 이전/현재 모듈 | THEORY-15-M04 | THEORY-15-M05 |

예를 들어 `CARRID` 컬럼의 제목을 “항공사”로 바꾸는 것은 Field Catalog의 책임이다.  
반면 전체 ALV를 줄무늬 행으로 표시하는 것은 Layout의 책임이다.

## 5. `LVC_S_LAYO` 기본 선언

Layout은 보통 전역 데이터로 선언한다.  
Dynpro 기반 Grid ALV에서는 PBO에서 화면 객체를 생성하고 최초 표시를 수행하는 경우가 많으므로, 화면 처리 흐름 전체에서 접근하기 쉽게 전역으로 두는 편이 교육상 이해하기 쉽다.

```abap
DATA: gs_layout TYPE lvc_s_layo.
```

기본 설정 예시는 다음과 같다.

```abap
CLEAR gs_layout.

gs_layout-zebra      = abap_true.
gs_layout-cwidth_opt = abap_true.
```

구형 예제나 일부 시스템에서는 `abap_true` 대신 `'X'`를 사용하는 코드도 많다.

```abap
gs_layout-zebra      = 'X'.
gs_layout-cwidth_opt = 'X'.
```

S/4HANA 기준의 현대적 ABAP 설명에서는 `abap_true`를 선호할 수 있지만, Classic Dynpro/Grid ALV 예제에서는 `'X'`도 여전히 많이 보인다.  
교육자료에서는 두 방식을 모두 읽을 수 있게 안내하는 것이 좋다.

## 6. `ZEBRA` — 줄무늬 행 표시

### 6.1 의미

`ZEBRA`는 ALV 행을 교차 색상으로 표시하여 가독성을 높이는 Layout 옵션이다.

```abap
gs_layout-zebra = abap_true.
```

또는

```abap
gs_layout-zebra = 'X'.
```

이 옵션을 켜면 사용자는 행이 많은 리스트에서 현재 행을 시각적으로 더 쉽게 따라갈 수 있다.

### 6.2 언제 유용한가?

`ZEBRA`는 특히 다음 상황에서 유용하다.

| 상황 | 효과 |
|---|---|
| 행 수가 많은 리스트 | 눈으로 행을 따라가기 쉬워진다. |
| 컬럼 수가 많은 리스트 | 가로 이동 시 행 위치를 놓칠 가능성이 줄어든다. |
| 교육용 ALV 예제 | Layout 효과가 즉시 보이므로 학습 이해가 쉽다. |
| 단순 조회성 리포트 | 사용자 경험을 빠르게 개선할 수 있다. |

### 6.3 주의점

`ZEBRA`는 데이터 의미를 표현하는 기능이 아니다.  
즉, “오류 행”, “성공 행”, “주의 행” 같은 업무 상태를 나타내려면 `INFO_FNAME` 기반 행 색상이나 Cell Color 제어를 사용해야 한다.

초급자는 다음처럼 구분한다.

```text
ZEBRA      = 단순 가독성 개선
INFO_FNAME = 행별 의미 있는 색상 제어
```

## 7. `CWIDTH_OPT` — 컬럼 폭 자동 최적화

### 7.1 의미

`CWIDTH_OPT`는 Grid ALV가 컬럼 폭을 자동으로 조정하도록 지시하는 Layout 옵션이다.

```abap
gs_layout-cwidth_opt = abap_true.
```

또는

```abap
gs_layout-cwidth_opt = 'X'.
```

이 설정을 적용하면 Field Catalog의 `OUTPUTLEN`을 세밀하게 지정하지 않아도, ALV가 데이터와 헤더를 참고하여 컬럼 폭을 적절히 맞추려고 한다.

### 7.2 언제 유용한가?

| 상황 | 효과 |
|---|---|
| 초급 실습 | 컬럼 폭 조정에 시간을 덜 쓰고 ALV 구조 학습에 집중 가능 |
| 조회 컬럼이 많지 않은 경우 | 자동 폭 조정만으로 충분히 보기 좋다 |
| 데이터 길이가 일정하지 않은 경우 | 긴 값이 잘리는 문제를 줄일 수 있다 |
| 데모 프로그램 | 빠르게 보기 좋은 결과를 만들 수 있다 |

### 7.3 Field Catalog `OUTPUTLEN`과의 관계

`CWIDTH_OPT`와 Field Catalog의 `OUTPUTLEN`은 모두 컬럼 폭과 관련된다.  
차이는 다음과 같다.

| 구분 | 설명 |
|---|---|
| `OUTPUTLEN` | 특정 컬럼의 출력 길이를 Field Catalog에서 직접 지정 |
| `CWIDTH_OPT` | 전체 Grid에 대해 컬럼 폭 자동 최적화를 요청 |

실무에서는 둘을 함께 고려한다.  
예를 들어 특정 컬럼은 반드시 짧게 유지해야 한다면 Field Catalog에서 별도 제어를 할 수 있고, 나머지는 자동 최적화를 사용할 수 있다.

### 7.4 주의점

자동 최적화가 항상 완벽한 것은 아니다.

| 주의사항 | 설명 |
|---|---|
| 긴 텍스트 컬럼 | 지나치게 넓어질 수 있다. |
| 데이터 건수 많음 | 시스템/화면 상황에 따라 표시 계산 비용이 커질 수 있다. |
| 사용자가 직접 조정한 폭 | Variant와 함께 쓰면 사용자 저장 설정과 상호작용할 수 있다. |
| 출력 목적 | 인쇄/엑셀 다운로드까지 고려하면 별도 폭 설계가 필요할 수 있다. |

초급 과정에서는 `CWIDTH_OPT = abap_true`를 기본값처럼 사용해도 되지만, 실무에서는 화면 목적에 맞는 폭 정책을 검토해야 한다.

## 8. `INFO_FNAME` — 행 색상 필드명 지정

### 8.1 의미

`INFO_FNAME`은 출력 Internal Table 안에 있는 **행 색상 정보 필드명**을 Layout에 알려주는 속성이다.

예를 들어 출력 구조에 다음 필드가 있다고 가정한다.

```abap
TYPES: BEGIN OF ty_output,
         carrid     TYPE s_carr_id,
         carrname   TYPE s_carrname,
         currcode   TYPE s_currcode,
         row_color  TYPE c LENGTH 4,
       END OF ty_output.
```

이때 Layout에 다음처럼 지정할 수 있다.

```abap
gs_layout-info_fname = 'ROW_COLOR'.
```

그러면 ALV는 출력 테이블의 `ROW_COLOR` 값을 행 색상 제어 정보로 해석할 수 있다.

### 8.2 중요한 전제

`INFO_FNAME`은 단독으로 색상을 만들어내는 마법 옵션이 아니다.  
출력 Internal Table에 해당 필드가 실제로 있어야 하며, 그 필드에 ALV가 이해할 수 있는 색상 코드가 채워져 있어야 한다.

즉, 최소 흐름은 다음과 같다.

```text
1. 출력 구조에 행 색상 필드를 추가한다.
2. Layout의 INFO_FNAME에 해당 필드명을 지정한다.
3. 출력 데이터 생성 시 행별 색상 값을 채운다.
4. SET_TABLE_FOR_FIRST_DISPLAY에 Layout과 출력 테이블을 전달한다.
```

이번 모듈에서는 개념과 기본 연결만 다룬다.  
색상 코드의 세부 규칙과 업무 상태별 행/셀 색상 구현은 `THEORY-15-M09`에서 더 자세히 다룬다.

### 8.3 초급자에게 필요한 이해 수준

이번 단계에서는 다음 정도를 기억하면 충분하다.

```text
INFO_FNAME은 “행 색상 정보를 어느 필드에서 읽을지” 알려주는 Layout 속성이다.
```

## 9. Layout 설정의 기본 구현 흐름

Grid ALV에서 Layout은 보통 다음 흐름으로 사용한다.

```text
1. 출력 Internal Table 준비
2. Field Catalog 준비
3. Layout 구조체 선언
4. Layout 값 설정
5. SET_TABLE_FOR_FIRST_DISPLAY 호출 시 IS_LAYOUT으로 전달
```

ABAP 코드 흐름은 다음과 같다.

```abap
DATA: go_container TYPE REF TO cl_gui_custom_container,
      go_grid      TYPE REF TO cl_gui_alv_grid,
      gt_output    TYPE STANDARD TABLE OF ty_output,
      gt_fcat      TYPE lvc_t_fcat,
      gs_layout    TYPE lvc_s_layo.

CLEAR gs_layout.
gs_layout-zebra      = abap_true.
gs_layout-cwidth_opt = abap_true.

go_grid->set_table_for_first_display(
  EXPORTING
    is_layout       = gs_layout
  CHANGING
    it_outtab       = gt_output
    it_fieldcatalog = gt_fcat
).
```

핵심은 `IS_LAYOUT = GS_LAYOUT`이다.  
Layout을 아무리 채워도 `SET_TABLE_FOR_FIRST_DISPLAY`에 전달하지 않으면 Grid에 반영되지 않는다.

### 10.4 Layout 설정 FORM 예시

```abap
FORM set_layout.

```

구형 시스템 또는 교육 환경에서 `abap_true`가 익숙하지 않은 학습자에게는 다음 형태도 함께 설명할 수 있다.

```abap

  CLEAR gs_layout.

  gs_layout-zebra      = 'X'.
  gs_layout-cwidth_opt = 'X'.

ENDFORM.
```

### 10.5 PBO 흐름에 연결

PBO 모듈에서 ALV를 최초 생성할 때 Layout 설정을 호출한다.

```abap
MODULE status_0100 OUTPUT.

  SET PF-STATUS 'S100'.

  IF go_container IS INITIAL.

    PERFORM create_container.
    PERFORM create_grid.
    PERFORM get_data.
    PERFORM build_field_catalog.
    PERFORM set_layout.
    PERFORM display_alv.

  ENDIF.

ENDMODULE.
```

### 10.6 Display 호출 예시

```abap
FORM display_alv.

  go_grid->set_table_for_first_display(
    EXPORTING
      is_layout       = gs_layout
    CHANGING
      it_outtab       = gt_output
      it_fieldcatalog = gt_fcat
  ).

ENDFORM.
```

### 10.7 결과 확인

실행 후 다음을 확인한다.

| 확인 항목 | 기대 결과 |
|---|---|
| 행 줄무늬 | 행 배경이 교차 표시된다. |
| 컬럼 폭 | 컬럼 폭이 데이터와 헤더에 맞게 조정된다. |
| 오류 없음 | 화면 진입 시 Dump 없이 Grid가 표시된다. |
| Field Catalog 유지 | 컬럼 제목과 필드 순서가 기존대로 표시된다. |

## 11. 전체 예제 코드 조각

아래 코드는 Layout 부분만 강조한 교육용 조각이다.  
전체 프로그램에는 Screen 100, Custom Control, PBO/PAI 모듈, 데이터 조회, Field Catalog 생성 코드가 함께 필요하다.

```abap
DATA: go_container TYPE REF TO cl_gui_custom_container,
      go_grid      TYPE REF TO cl_gui_alv_grid,
      gt_fcat      TYPE lvc_t_fcat,
      gs_layout    TYPE lvc_s_layo.

FORM set_layout.

  CLEAR gs_layout.

  "행 줄무늬 표시
  gs_layout-zebra = abap_true.

  "컬럼 폭 자동 최적화
  gs_layout-cwidth_opt = abap_true.

ENDFORM.

FORM display_alv.

  go_grid->set_table_for_first_display(
    EXPORTING
      is_layout       = gs_layout
    CHANGING
      it_outtab       = gt_output
      it_fieldcatalog = gt_fcat
  ).

ENDFORM.
```

## 12. 정상 흐름과 오류 흐름

### 12.1 정상 흐름

```text
출력 데이터 준비
→ Field Catalog 준비
→ Layout CLEAR
→ ZEBRA / CWIDTH_OPT 설정
→ SET_TABLE_FOR_FIRST_DISPLAY에 IS_LAYOUT 전달
→ Grid 화면 표시
→ 줄무늬와 컬럼 폭 확인
```

### 12.2 오류 흐름 1: Layout을 설정했지만 반영되지 않음

#### 증상

`gs_layout-zebra = abap_true`를 설정했는데 화면에 변화가 없다.

#### 원인 후보

| 원인 | 설명 |
|---|---|
| `IS_LAYOUT` 전달 누락 | `SET_TABLE_FOR_FIRST_DISPLAY` 호출에 Layout을 넘기지 않음 |
| 다른 Layout 변수를 전달 | 설정한 변수와 전달한 변수가 다름 |
| Display 호출 순서 문제 | Layout 설정 전에 Display를 먼저 호출 |
| Refresh만 수행 | 최초 표시 Layout 변경은 Refresh만으로 기대대로 반영되지 않을 수 있음 |

#### 해결

다음 순서를 확인한다.

```abap
PERFORM set_layout.
PERFORM display_alv.
```

그리고 Display 호출에서 다음 인자를 확인한다.

```abap
EXPORTING
  is_layout = gs_layout
```

### 12.3 오류 흐름 2: 컬럼 폭이 기대와 다름

#### 증상

`CWIDTH_OPT`를 설정했지만 특정 컬럼이 너무 넓거나 좁다.

#### 원인 후보

| 원인 | 설명 |
|---|---|
| 데이터 값이 매우 김 | 자동 최적화가 긴 값을 기준으로 폭을 잡을 수 있음 |
| Field Catalog의 `OUTPUTLEN` 설정 | 컬럼 폭 관련 개별 설정과 상호작용 가능 |
| Variant 적용 | 사용자 저장 Variant가 폭 설정에 영향을 줄 수 있음 |
| 헤더 텍스트 길이 | 컬럼 제목이 길면 폭이 넓어질 수 있음 |

#### 해결

특정 컬럼은 Field Catalog에서 `OUTPUTLEN`을 조정하고, 전체는 `CWIDTH_OPT`로 보조한다.

### 12.4 오류 흐름 3: `INFO_FNAME` 지정 후 Dump 또는 색상 미표시

#### 증상

`INFO_FNAME`을 지정했지만 색상이 보이지 않거나 오류가 발생한다.

#### 원인 후보

| 원인 | 설명 |
|---|---|
| 출력 구조에 필드 없음 | `INFO_FNAME`에 지정한 필드가 `GT_OUTPUT` 구조에 없음 |
| 필드명 오타 | 대문자 필드명 불일치 |
| 색상 코드 미입력 | 필드는 있지만 값이 비어 있음 |
| 색상 필드 타입 부적절 | ALV가 기대하는 형식과 다름 |

#### 해결

이번 모듈에서는 `INFO_FNAME`을 개념 수준으로만 확인한다.  
실제 행 색상 구현은 `THEORY-15-M09`에서 색상 필드와 값 형식을 함께 다룬다.

## 13. 디버깅 및 검증 포인트

Layout 설정 문제는 대부분 “값을 설정했는가”보다 “올바른 시점에 올바른 변수로 전달했는가”에서 발생한다.

### 13.1 Breakpoint 위치

다음 위치에 Breakpoint를 설정한다.

| 위치 | 확인할 내용 |
|---|---|
| `FORM set_layout` | `gs_layout-zebra`, `gs_layout-cwidth_opt` 값 |
| `FORM display_alv` | `is_layout = gs_layout` 전달 여부 |
| `SET_TABLE_FOR_FIRST_DISPLAY` 호출 직전 | 출력 데이터, Field Catalog, Layout이 모두 준비되었는지 |
| PBO Module | 최초 1회 생성 조건이 정상인지 |

### 13.2 확인할 변수

| 변수 | 기대 값 |
|---|---|
| `GS_LAYOUT-ZEBRA` | `X` 또는 `ABAP_TRUE` |
| `GS_LAYOUT-CWIDTH_OPT` | `X` 또는 `ABAP_TRUE` |
| `GT_FCAT` | 출력 컬럼 정보 존재 |
| `GT_OUTPUT` | 출력 데이터 존재 |
| `GO_GRID` | Bound 상태 |

객체 참조 변수는 다음 조건을 확인한다.

```abap
IF go_grid IS BOUND.
  "Grid 객체 정상 생성
ENDIF.
```

## 14. 실무 적용 기준

### 14.1 조회성 ALV의 기본 Layout 권장

단순 조회성 Grid ALV에서는 다음 설정을 기본값으로 둘 수 있다.

```abap
gs_layout-zebra      = abap_true.
gs_layout-cwidth_opt = abap_true.
```

이 두 옵션은 사용자 가독성을 빠르게 개선한다.

### 14.2 대량 컬럼/대량 데이터 ALV에서는 신중하게 적용

컬럼 수가 많거나 데이터가 매우 많으면 자동 폭 최적화가 항상 좋은 결과를 내지 않을 수 있다.  
이 경우 중요한 컬럼만 Field Catalog에서 폭을 직접 제어하고, 불필요한 컬럼은 숨기거나 Variant로 관리하는 방식이 낫다.

### 14.3 색상은 업무 의미가 있을 때만 사용

행 색상과 컬럼 색상은 강력한 시각적 신호다.  
따라서 단순히 화면을 화려하게 만들기 위해 남발하면 사용자가 오히려 혼란스러울 수 있다.

적절한 예:

| 색상 사용 목적 | 예 |
|---|---|
| 오류 상태 | 실패 행 강조 |
| 경고 상태 | 재고 부족, 납기 지연 |
| 성공 상태 | 처리 완료 |
| 중요 상태 | 승인 대기, 차단 |

부적절한 예:

```text
모든 컬럼을 각기 다른 색으로 표시
의미 없는 행 색상 반복
ZEBRA와 업무 색상을 동시에 과도하게 사용
```

### 14.4 Layout 설정은 한 곳에서 관리

실무 프로그램에서는 Layout 설정 코드를 여기저기 흩어놓지 않는 것이 좋다.

권장:

```abap
FORM set_layout.
  CLEAR gs_layout.
  gs_layout-zebra      = abap_true.
  gs_layout-cwidth_opt = abap_true.
ENDFORM.
```

비권장:

```abap
"여러 FORM과 PBO 곳곳에서 gs_layout 값을 변경
```

Layout 설정이 흩어지면 화면 표시 문제를 추적하기 어려워진다.

## 15. 강의 진행 가이드

### 15.1 설명 순서

강의자는 다음 순서로 설명하면 좋다.

```text
1. Field Catalog와 Layout의 역할 차이 복습

3. ZEBRA 설정 후 화면 비교
4. CWIDTH_OPT 설정 전후 비교

```

시연 시 가장 효과적인 방식은 같은 프로그램을 두 번 실행해 비교하는 것이다.

| 실행 | 설정 | 관찰 포인트 |
|---|---|---|
| 1차 | Layout 미설정 | 컬럼 폭과 행 표시 기본 상태 |
| 2차 | `ZEBRA`, `CWIDTH_OPT` 설정 | 가독성 변화와 폭 최적화 확인 |

## 18. 안티패턴과 개선 예

### 18.1 안티패턴: Layout을 설정하고 전달하지 않음

```abap
gs_layout-zebra = abap_true.

go_grid->set_table_for_first_display(
  CHANGING
    it_outtab       = gt_output
    it_fieldcatalog = gt_fcat
).
```

문제는 `IS_LAYOUT`이 빠져 있다는 점이다.

개선:

```abap
go_grid->set_table_for_first_display(
  EXPORTING
    is_layout       = gs_layout
  CHANGING
    it_outtab       = gt_output
    it_fieldcatalog = gt_fcat
).
```

### 18.2 안티패턴: Field Catalog와 Layout 책임 혼동

```abap
"Field Catalog에서 처리해야 할 컬럼 제목 변경을 Layout에서 찾으려고 함
```

개선:

```text
컬럼 제목, 출력 길이, 숨김 여부 → Field Catalog
줄무늬, 자동 폭, 행 색상 필드명 → Layout
```

### 18.3 안티패턴: 색상을 의미 없이 남발

문제:

```text
모든 행과 컬럼에 색상을 적용하여 업무 의미가 흐려짐
```

개선:

```text
오류, 경고, 성공, 중요 상태처럼 사용자가 판단해야 하는 정보에만 색상을 사용한다.
```

## 19. 다음 모듈과의 연결

이번 모듈은 ALV의 기본 표시 품질을 개선하는 Layout 설정을 다루었다.

다음 모듈 `THEORY-15-M06 — Variant 기본 설정`에서는 사용자가 ALV 화면에서 컬럼 순서, 정렬, 필터, 폭 등을 저장하고 다시 불러오는 Layout Variant를 학습한다.

연결 관계는 다음과 같다.

```text
THEORY-15-M04 Field Catalog 기초
  → 컬럼 단위 표시 속성

THEORY-15-M05 Layout 기본 설정
  → Grid 전체 표시 속성

THEORY-15-M06 Variant 기본 설정
  → 사용자별/공통 Layout 저장과 재사용
```

즉, 이번 모듈에서 만든 Layout은 개발자가 프로그램에서 기본으로 제공하는 표시 정책이고, 다음 모듈의 Variant는 사용자가 자신의 화면 설정을 저장하고 재사용하는 영역이다.

## 20. 핵심 요약

```text
LVC_S_LAYO는 Grid ALV의 전체 표시 옵션을 담는 Layout 구조체이다.
ZEBRA는 행 줄무늬 표시로 가독성을 높인다.
CWIDTH_OPT는 컬럼 폭 자동 최적화 옵션이다.
INFO_FNAME은 출력 테이블의 행 색상 정보 필드명을 지정한다.
Layout은 SET_TABLE_FOR_FIRST_DISPLAY 호출 시 IS_LAYOUT으로 전달해야 반영된다.
Field Catalog는 컬럼 단위, Layout은 Grid 전체 표시 속성이라는 책임 분리가 중요하다.
```
