## 3. CL_GUI_ALV_GRID란 무엇인가?

`CL_GUI_ALV_GRID`는 SAP GUI 화면에서 데이터를 표 형태로 보여주는 Grid ALV Control 클래스이다.  
Classic Report의 `WRITE` 출력이나 `REUSE_ALV_GRID_DISPLAY` 함수 기반 ALV보다 객체 지향적이고 화면 제어 능력이 높다.

Grid ALV는 다음 기능의 기반이 된다.

| 기능 | 설명 |
|---|---|
| 컬럼 기반 출력 | Internal Table 데이터를 행/열 형태로 표시한다. |
| Field Catalog 제어 | 컬럼명, 길이, 편집 가능 여부, 색상 등 세부 속성을 제어한다. |
| Layout 제어 | Zebra, 선택 모드, 컬럼 최적화 등 화면 속성을 설정한다. |
| Variant | 사용자가 레이아웃 변형을 저장하고 재사용할 수 있다. |
| Refresh | 데이터 변경 후 Grid를 다시 표시할 수 있다. |
| Event Handling | Double Click, Toolbar, User Command 등 이벤트를 처리할 수 있다. |
| Edit 가능 Grid | 설정에 따라 셀 입력/변경을 처리할 수 있다. |

다만 이번 모듈에서는 **Grid 객체 생성**에만 집중한다.

## 4. Custom Container와 ALV Grid의 관계

Grid ALV를 이해하려면 두 객체의 역할을 분리해야 한다.

| 객체 | 역할 | 비유 |
|---|---|---|
| `CL_GUI_CUSTOM_CONTAINER` | Dynpro 화면의 Custom Control 영역과 ABAP 객체를 연결 | TV를 놓을 벽면/공간 |
| `CL_GUI_ALV_GRID` | 실제 데이터를 표 형태로 보여주는 ALV Grid Control | 그 공간에 놓는 TV |

즉, `CL_GUI_ALV_GRID`는 단독으로 화면에 떠 있는 객체가 아니다.  
화면의 어느 영역에 표시할지 알아야 하며, 그 역할을 `i_parent`에 전달하는 Container가 담당한다.

일반적인 생성 순서는 다음과 같다.

```abap
CREATE OBJECT go_container
  EXPORTING
    container_name = 'CC_ALV'.

CREATE OBJECT go_grid
  EXPORTING
    i_parent = go_container.
```

여기서 `CC_ALV`는 Screen Painter에서 배치한 Custom Control의 이름이다.  
`go_container`는 해당 화면 영역과 연결된 ABAP 객체이고, `go_grid`는 그 Container 안에 표시되는 Grid 객체이다.

## 5. 왜 PBO에서 생성하는가?

Grid ALV는 화면이 표시될 때 준비되어야 한다.  
Classic Dynpro의 화면 표시 전 이벤트는 PBO(Process Before Output)이다.

따라서 보통 다음 흐름을 사용한다.

```text
CALL SCREEN 0100
→ Screen 0100 PBO 실행
→ STATUS_0100 모듈에서 PF-STATUS 설정
→ CREATE_ALV_0100 모듈에서 Container/Grid 생성
→ 화면 표시
→ 사용자 액션 발생
→ PAI 실행
```

PBO에서 객체를 생성하는 이유는 다음과 같다.

| 이유 | 설명 |
|---|---|
| 화면 영역이 준비된 시점 | PBO는 화면 표시 직전이므로 Control 준비에 적합하다. |
| 사용자에게 표시되기 전 생성 가능 | 화면이 나타날 때 Grid가 함께 보이도록 할 수 있다. |
| 후속 Refresh와 분리 가능 | 최초 생성과 데이터 갱신 로직을 구분할 수 있다. |
| SAP GUI Control Framework 흐름과 맞음 | Custom Control 기반 화면 제어의 표준적인 구현 흐름이다. |

---

## 6. 객체를 1회만 생성해야 하는 이유

PBO는 화면이 처음 뜰 때만 실행되는 것이 아니다.  
사용자가 Enter를 누르거나 버튼을 클릭하거나 화면이 다시 그려질 때 반복 실행될 수 있다.

따라서 PBO 안에서 무조건 `CREATE OBJECT`를 수행하면 같은 화면에 Control 객체가 반복 생성될 수 있다.  
이는 화면 이상, 리소스 낭비, 예측하기 어려운 동작으로 이어질 수 있다.

그래서 보통 다음처럼 참조 변수가 초기 상태인지 확인한다.

```abap
IF go_grid IS INITIAL.
  CREATE OBJECT go_container
    EXPORTING
      container_name = 'CC_ALV'.

  CREATE OBJECT go_grid
    EXPORTING
      i_parent = go_container.
ENDIF.
```

핵심은 다음이다.

```text
PBO는 반복 실행된다.
Grid 객체 생성은 최초 1회만 수행한다.
이미 생성된 Grid는 재사용한다.
데이터 변경 시에는 새로 생성하지 말고 Refresh를 검토한다.
```

## 7. 최소 프로그램 구조

아래 코드는 이번 모듈의 핵심만 보여주는 최소 구조이다.  
실제 실행을 위해서는 Screen 0100과 Custom Control `CC_ALV`가 Screen Painter에 존재해야 한다.

```abap
REPORT zgpt_grid_alv_m02.

DATA: go_container TYPE REF TO cl_gui_custom_container,
      go_grid      TYPE REF TO cl_gui_alv_grid.

START-OF-SELECTION.
  CALL SCREEN 0100.

MODULE status_0100 OUTPUT.
  SET PF-STATUS 'S0100'.
  SET TITLEBAR 'T0100'.
ENDMODULE.

MODULE create_alv_0100 OUTPUT.
  IF go_grid IS INITIAL.
    CREATE OBJECT go_container
      EXPORTING
        container_name = 'CC_ALV'.

    CREATE OBJECT go_grid
      EXPORTING
        i_parent = go_container.
  ENDIF.
ENDMODULE.

MODULE user_command_0100 INPUT.
  CASE sy-ucomm.
    WHEN 'BACK' OR 'EXIT' OR 'CANCEL'.
      LEAVE TO SCREEN 0.
  ENDCASE.
ENDMODULE.
```

이 코드는 아직 데이터를 표시하지 않는다.  
Grid 객체만 생성하므로 화면에는 빈 Grid 영역이 보이거나, 시스템/상태에 따라 아직 의미 있는 데이터가 없는 Control처럼 보일 수 있다. 실제 데이터 출력은 `SET_TABLE_FOR_FIRST_DISPLAY`를 호출해야 가능하다.

## 8. Screen 0100에 필요한 설정

위 프로그램이 동작하려면 Screen Painter에서 다음이 준비되어야 한다.

| 항목 | 예시 | 설명 |
|---|---|---|
| Screen Number | 0100 | ALV를 표시할 Dynpro 화면 |
| Custom Control Name | CC_ALV | Container가 연결할 화면 영역 이름 |
| PBO Module | STATUS_0100 | PF-STATUS와 Title 설정 |
| PBO Module | CREATE_ALV_0100 | Container/Grid 생성 |
| PAI Module | USER_COMMAND_0100 | BACK/EXIT/CANCEL 처리 |
| PF-STATUS | S0100 | 뒤로가기, 종료, 취소 버튼 포함 |
| Titlebar | T0100 | 화면 제목 |

Screen Flow Logic 예시는 다음과 같다.

```abap
PROCESS BEFORE OUTPUT.
  MODULE status_0100.
  MODULE create_alv_0100.

PROCESS AFTER INPUT.
  MODULE user_command_0100.
```

초급자가 가장 자주 실수하는 부분은 Screen Painter의 Custom Control 이름과 ABAP 코드의 `container_name`을 다르게 입력하는 것이다.

```abap
container_name = 'CC_ALV'
```

위 이름은 Screen Painter에 배치한 Custom Control 이름과 정확히 일치해야 한다.

## 9. 전역 참조 변수가 필요한 이유

`go_container`와 `go_grid`는 일반적으로 전역으로 선언한다.

```abap
DATA: go_container TYPE REF TO cl_gui_custom_container,
      go_grid      TYPE REF TO cl_gui_alv_grid.
```

그 이유는 다음과 같다.

| 이유 | 설명 |
|---|---|
| PBO 반복 호출 대응 | 객체가 이미 생성되었는지 확인해야 한다. |
| 후속 메서드 호출 | `set_table_for_first_display`, `refresh_table_display` 등을 호출해야 한다. |
| 객체 생명주기 유지 | Local 변수로만 만들면 화면 제어 흐름에서 참조 유지가 어렵다. |
| PAI/Event 처리 연결 | 사용자 액션이나 이벤트 처리 시 Grid 객체가 필요할 수 있다. |

나쁜 예는 다음과 같다.

```abap
MODULE create_alv_0100 OUTPUT.
  DATA lo_grid TYPE REF TO cl_gui_alv_grid.

  CREATE OBJECT lo_grid
    EXPORTING
      i_parent = go_container.
ENDMODULE.
```

이렇게 지역 변수로만 Grid 객체를 만들면 후속 처리에서 해당 Grid를 안정적으로 다시 참조하기 어렵다.  
교육 단계에서는 반드시 전역 참조 변수로 관리하는 습관을 들이는 것이 좋다.

## 10. 정상 흐름과 오류 흐름

### 10.1 정상 흐름

```text
Screen 0100 생성
→ Custom Control CC_ALV 배치
→ go_container 전역 선언
→ go_grid 전역 선언
→ PBO에서 go_grid IS INITIAL 확인
→ Container 생성
→ Grid 생성
→ 화면 표시
```

### 10.2 오류 흐름 1 — Container를 만들지 않고 Grid 생성

잘못된 예:

```abap
CREATE OBJECT go_grid
  EXPORTING
    i_parent = go_container.
```

이 시점에 `go_container`가 아직 초기 상태라면 Grid가 올라갈 Parent가 없다.

해결:

```abap
CREATE OBJECT go_container
  EXPORTING
    container_name = 'CC_ALV'.

CREATE OBJECT go_grid
  EXPORTING
    i_parent = go_container.
```

### 10.3 오류 흐름 2 — Custom Control 이름 불일치

Screen Painter의 Control 이름은 `CC_GRID`인데 코드에는 다음처럼 되어 있을 수 있다.

```abap
container_name = 'CC_ALV'
```

이 경우 Container 생성 시 화면 Control을 찾지 못하거나 정상 연결되지 않는다.

해결:

```text
Screen Painter의 Custom Control 이름과 ABAP 코드의 container_name 값을 일치시킨다.
```

### 10.4 오류 흐름 3 — PBO마다 객체 반복 생성

잘못된 예:

```abap
MODULE create_alv_0100 OUTPUT.
  CREATE OBJECT go_container
    EXPORTING
      container_name = 'CC_ALV'.

  CREATE OBJECT go_grid
    EXPORTING
      i_parent = go_container.
ENDMODULE.
```

문제점:

```text
PBO가 반복될 때마다 Container와 Grid를 계속 생성한다.
```

해결:

```abap
IF go_grid IS INITIAL.
  " 최초 1회만 생성
ENDIF.
```

### 10.5 오류 흐름 4 — PF-STATUS가 없어 화면을 빠져나갈 수 없음

Grid 객체는 생성되었지만 BACK/EXIT/CANCEL 처리가 없으면 화면 종료가 불편해진다.

해결:

```abap
MODULE user_command_0100 INPUT.
  CASE sy-ucomm.
    WHEN 'BACK' OR 'EXIT' OR 'CANCEL'.
      LEAVE TO SCREEN 0.
  ENDCASE.
ENDMODULE.
```

## 11. 실무 구현 패턴

실무에서는 Grid 생성 로직을 하나의 FORM 또는 Method로 분리하는 경우가 많다.

초급 Report 예제에서는 다음처럼 FORM으로 나눌 수 있다.

```abap
FORM create_grid.
  IF go_grid IS INITIAL.
    CREATE OBJECT go_container
      EXPORTING
        container_name = 'CC_ALV'.

    CREATE OBJECT go_grid
      EXPORTING
        i_parent = go_container.
  ENDIF.
ENDFORM.
```

PBO에서는 다음처럼 호출한다.

```abap
MODULE create_alv_0100 OUTPUT.
  PERFORM create_grid.
ENDMODULE.
```

OO 기반 실무 프로그램에서는 화면 Controller 클래스 또는 Application 클래스의 Method로 분리할 수 있다.

```abap
METHOD create_grid.
  IF mo_grid IS INITIAL.
    CREATE OBJECT mo_container
      EXPORTING
        container_name = 'CC_ALV'.

    CREATE OBJECT mo_grid
      EXPORTING
        i_parent = mo_container.
  ENDIF.
ENDMETHOD.
```

다만 초급 단계에서는 FORM 기반 구조를 먼저 이해한 뒤 OO로 확장하는 편이 좋다.

## 12. CL_GUI_ALV_GRID 생성 후 바로 데이터를 표시하지 않는 이유

`CL_GUI_ALV_GRID` 객체를 생성하는 것과 데이터를 표시하는 것은 별개의 단계이다.

| 단계 | 대표 메서드/구문 | 역할 |
|---|---|---|
| Container 생성 | `CREATE OBJECT cl_gui_custom_container` | 화면 영역과 ABAP 객체 연결 |
| Grid 생성 | `CREATE OBJECT cl_gui_alv_grid` | Grid Control 인스턴스 생성 |
| 데이터 최초 표시 | `set_table_for_first_display` | Internal Table 데이터를 Grid에 연결 |
| 데이터 갱신 표시 | `refresh_table_display` | 이미 표시된 Grid를 새로고침 |

이번 모듈은 두 번째 단계까지 다룬다.

```text
이번 모듈: Grid 객체 생성
다음 모듈: 출력용 Internal Table 준비
후속 모듈: SET_TABLE_FOR_FIRST_DISPLAY로 데이터 표시
```

```abap
REPORT zgpt_grid_alv_m02.

DATA: go_container TYPE REF TO cl_gui_custom_container,
      go_grid      TYPE REF TO cl_gui_alv_grid.

START-OF-SELECTION.
  CALL SCREEN 0100.

MODULE status_0100 OUTPUT.
  SET PF-STATUS 'S0100'.
  SET TITLEBAR 'T0100'.
ENDMODULE.

MODULE create_alv_0100 OUTPUT.
  IF go_grid IS INITIAL.
    CREATE OBJECT go_container
      EXPORTING
        container_name = 'CC_ALV'.

    CREATE OBJECT go_grid
      EXPORTING
        i_parent = go_container.
  ENDIF.
ENDMODULE.

MODULE user_command_0100 INPUT.
  CASE sy-ucomm.
    WHEN 'BACK' OR 'EXIT' OR 'CANCEL'.
      LEAVE TO SCREEN 0.
  ENDCASE.
ENDMODULE.
```

### 13.3 오류 케이스 실습

다음 오류를 일부러 만들어보고 결과를 기록한다.

| 오류 케이스 | 변경 내용 | 예상 결과 |
|---|---|---|
| Control 이름 불일치 | Screen은 `CC_ALV`, 코드는 `CC_GRID` | Container 연결 오류 가능 |
| Container 미생성 | Grid 생성만 수행 | Parent 객체 없음 |
| `IS INITIAL` 조건 제거 | PBO마다 객체 생성 | 반복 생성 문제 가능 |
| PAI 종료 처리 누락 | BACK 처리 없음 | 화면 종료 불편 |

## 14. 디버깅 포인트

Grid 생성 문제를 확인할 때는 다음 지점을 본다.

| 지점 | 확인 내용 |
|---|---|
| `go_container IS INITIAL` | Container 생성 전/후 상태 |
| `go_grid IS INITIAL` | Grid 생성 전/후 상태 |
| `container_name` 값 | Screen Painter의 Custom Control 이름과 일치하는가 |
| PBO 호출 횟수 | 화면 액션 시 PBO가 반복되는가 |
| `sy-ucomm` | BACK/EXIT/CANCEL 처리 값이 들어오는가 |

디버깅 흐름 예시는 다음과 같다.

```text
1. CREATE_ALV_0100 모듈에 Breakpoint 설정
2. CALL SCREEN 0100 실행
3. go_grid 초기 상태 확인
4. Container 생성 후 go_container 참조 확인
5. Grid 생성 후 go_grid 참조 확인
6. Enter 또는 버튼 클릭 후 PBO 재진입 여부 확인
7. IS INITIAL 조건 때문에 재생성되지 않는지 확인
```

## 15. 성능과 운영 관점의 주의사항

### 15.1 객체 반복 생성 방지

Grid 객체를 반복 생성하면 화면 리소스와 SAP GUI Control Framework 처리에 불필요한 부담이 생긴다.  
성능 관점에서 최초 1회 생성 후 재사용하는 패턴이 기본이다.

### 15.2 데이터 갱신과 객체 재생성 분리

데이터가 바뀌었다고 Grid 객체를 새로 만들 필요는 없다.  
후속 모듈에서 배우는 `refresh_table_display`를 사용하여 표시 데이터를 갱신하는 것이 일반적이다.

### 15.3 화면 종료 처리

Control 기반 화면은 화면 종료 시점에 객체 정리까지 고려해야 한다.  
초급 단계에서는 `LEAVE TO SCREEN 0` 정도로 충분하지만, 복잡한 화면에서는 `FREE` 처리와 이벤트 해제까지 검토할 수 있다.

### 15.4 권한 관점

Grid 생성 자체는 조회 권한을 의미하지 않는다.  
실제 데이터를 조회하여 표시할 때는 테이블 권한, 트랜잭션 권한, 프로그램 권한을 함께 고려해야 한다.

## 16. 초급자 오해 정리

| 오해 | 정리 |
|---|---|
| Grid 객체만 만들면 데이터가 자동 표시된다 | 아니다. `set_table_for_first_display`가 필요하다. |
| Container와 Grid는 같은 객체다 | 아니다. Container는 자리, Grid는 표시 Control이다. |
| PBO는 한 번만 실행된다 | 아니다. 화면이 다시 그려질 때 반복될 수 있다. |
| 매번 Grid를 새로 만들면 최신 데이터가 보인다 | 아니다. Refresh와 객체 재생성은 분리해야 한다. |
| Local 변수로 Grid를 만들어도 충분하다 | 후속 처리와 생명주기 관리를 위해 전역 참조가 필요하다. |

## 17. 자가 점검 문제

### Q1. `CL_GUI_ALV_GRID`의 역할은 무엇인가?

**정답 예시:**  
Internal Table 데이터를 SAP GUI 화면에서 Grid 형태로 표시하기 위한 ALV Control 클래스이다.

### Q2. `i_parent = go_container`가 필요한 이유는 무엇인가?

**정답 예시:**  
Grid Control이 어느 화면 영역 안에 표시될지 알아야 하기 때문이다. `go_container`는 Screen Painter의 Custom Control 영역과 연결된 Parent Container 역할을 한다.

### Q3. PBO에서 `IF go_grid IS INITIAL` 조건을 사용하는 이유는 무엇인가?

**정답 예시:**  
PBO는 여러 번 실행될 수 있으므로 Grid 객체를 최초 1회만 생성하고 이후에는 재사용하기 위해서이다.

### Q4. Grid 객체를 생성했는데 데이터가 보이지 않는 이유는 무엇일 수 있는가?

**정답 예시:**  
Grid 객체 생성은 표시 Control만 만든 것이며, 실제 Internal Table 데이터를 연결하려면 `set_table_for_first_display`를 호출해야 한다.

### Q5. Screen Painter의 Custom Control 이름과 `container_name`이 다르면 어떤 문제가 생기는가?

**정답 예시:**  
ABAP Container 객체가 실제 화면 영역을 찾지 못해 Container 생성 또는 Grid 표시가 실패할 수 있다.

## 18. 강사용 설명 포인트

강의에서는 다음 비유가 효과적이다.

```text
Screen 0100 = 교실
Custom Control = 칠판을 놓을 자리
CL_GUI_CUSTOM_CONTAINER = 칠판 자리와 ABAP 객체를 연결하는 받침대
CL_GUI_ALV_GRID = 실제 칠판
Internal Table = 칠판에 적을 내용
SET_TABLE_FOR_FIRST_DISPLAY = 내용을 칠판에 쓰는 행위
```

초급자에게는 Grid ALV를 처음부터 Field Catalog와 Layout까지 한 번에 설명하면 부담이 크다.  
따라서 이번 모듈에서는 “Grid 객체 생성은 아직 데이터 표시가 아니다”라는 점을 명확히 분리해야 한다.

추천 질문:

```text
Container 없이 Grid를 만들 수 있을까요?
PBO가 두 번 실행되면 CREATE OBJECT도 두 번 실행되어야 할까요?
Grid 객체와 Internal Table 데이터 연결은 같은 단계일까요?
```

## 19. 후속 모듈 연결

이번 모듈에서는 Grid ALV 객체를 생성했다.  
다음 모듈 `THEORY-15-M03 — 출력용 Internal Table 준비`에서는 Grid에 표시할 데이터를 담는 Internal Table을 준비한다.

연결 흐름은 다음과 같다.

```text
THEORY-15-M01 CL_GUI_CUSTOM_CONTAINER 생성
  → 화면 영역과 Container 준비

THEORY-15-M02 CL_GUI_ALV_GRID 생성
  → Grid Control 객체 생성

THEORY-15-M03 출력용 Internal Table 준비
  → Grid에 표시할 데이터 구조와 데이터 준비

THEORY-15-M04 Field Catalog 기초
  → Grid 컬럼 표시 속성 제어

THEORY-15-M07 SET_TABLE_FOR_FIRST_DISPLAY
  → 준비한 데이터와 설정을 Grid에 최초 표시
```

이번 모듈의 결과물은 `GO_GRID` 객체이다.  
이 객체는 이후 모든 Grid ALV 처리의 중심이 된다.

## 20. 핵심 요약

```text
CL_GUI_ALV_GRID는 SAP GUI 화면에 표 형태 데이터를 표시하는 Grid ALV Control 클래스이다.
Grid는 단독으로 표시되지 않고 Parent Container가 필요하다.
Custom Container는 화면 영역이고 Grid는 실제 표 Control이다.
PBO는 반복 실행될 수 있으므로 Grid 객체는 최초 1회만 생성해야 한다.
Grid 생성과 데이터 표시는 다른 단계이다.
실제 데이터 표시는 SET_TABLE_FOR_FIRST_DISPLAY에서 수행한다.
```
