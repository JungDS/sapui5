## 3. Grid ALV에서 색상이 필요한 이유

Grid ALV는 단순히 데이터를 표 형태로 보여주는 도구가 아니다. 실무에서는 사용자가 수백 건, 수천 건의 데이터를 빠르게 판단해야 한다. 이때 색상은 다음과 같은 역할을 한다.

| 목적 | 예시 |
|---|---|
| 중요 컬럼 강조 | 금액, 상태, 오류 메시지 컬럼을 눈에 띄게 표시 |
| 위험 데이터 표시 | 결재 지연, 재고 부족, 오류 상태 행 강조 |
| 정상/주의/오류 구분 | 초록/노랑/빨강 계열로 상태 구분 |
| 사용자 탐색 지원 | 대량 리스트에서 우선 확인 대상 식별 |
| 업무 판단 속도 향상 | 조건에 따라 시각적 우선순위 제공 |

예를 들어 구매요청 목록에서 상태가 `ERROR`인 행을 붉은색으로 표시하면, 사용자는 오류 데이터를 즉시 확인할 수 있다. 금액 컬럼을 강조하면 어떤 숫자를 기준으로 판단해야 하는지 쉽게 알 수 있다.

하지만 색상은 편의 기능이므로 과도하게 사용하면 오히려 화면을 복잡하게 만든다. 따라서 색상은 “업무적으로 판단이 빨라지는 지점”에만 제한적으로 사용해야 한다.

## 4. 컬럼 색상과 행 색상의 차이

Grid ALV에서 이번 모듈이 다루는 색상은 크게 두 가지이다.

| 구분 | 제어 위치 | 적용 단위 | 대표 속성 |
|---|---|---|---|
| 컬럼 색상 | Field Catalog | 특정 컬럼 전체 | `LVC_S_FCAT-EMPHASIZE` |
| 행 색상 | Layout + Output Table | 특정 데이터 행 전체 | `LVC_S_LAYO-INFO_FNAME` |

### 4.1 컬럼 색상

컬럼 색상은 특정 필드 전체를 강조한다.

예를 들어 `STATUS` 컬럼 전체를 강조하면 모든 행에서 `STATUS` 컬럼이 눈에 띄게 표시된다.

```text
STATUS 컬럼은 업무 판단의 핵심이므로 항상 강조한다.
```

### 4.2 행 색상

행 색상은 데이터 조건에 따라 특정 행 전체를 강조한다.

예를 들어 상태값이 `E`인 행은 붉은색, `W`인 행은 노란색으로 표시할 수 있다.

```text
STATUS = 'E' → 행 전체 빨강 계열
STATUS = 'W' → 행 전체 노랑 계열
STATUS = 'S' → 행 전체 초록 계열
```

초급자 관점에서는 다음처럼 구분하면 된다.

```text
컬럼 색상 = 어느 필드가 중요한가?
행 색상 = 어느 데이터 행이 중요한가?
```

## 5. ALV 색상 코드의 기본 구조

`CL_GUI_ALV_GRID`의 LVC 기반 ALV에서는 색상 코드가 보통 `Cxyz` 형태로 사용된다.

```text
Cxyz
```

| 자리 | 의미 | 예시 |
|---|---|---|
| C | Color 코드 시작 문자 | C |
| x | 색상 번호 | 0~7 범위 |
| y | 강조 여부 | 0 또는 1 |
| z | 반전 여부 | 0 또는 1 |

예를 들어 다음과 같은 값이 사용될 수 있다.

| 코드 | 의미 예시 |
|---|---|
| `C500` | 기본 색상 5, 일반 표시 |
| `C510` | 색상 5, 강조 표시 |
| `C600` | 기본 색상 6, 일반 표시 |
| `C610` | 색상 6, 강조 표시 |
| `C710` | 색상 7, 강조 표시 |

> [추정] 색상 번호별 실제 화면 색상은 SAP GUI 테마, SAP GUI 버전, 사용자 접근성 설정에 따라 다르게 보일 수 있다. 따라서 실무에서는 “빨강/노랑/초록이 반드시 이 색상 번호다”처럼 고정 암기하기보다, 시스템에서 실제 렌더링 결과를 확인해야 한다.

초급 교육에서는 다음 정도로 활용하면 충분하다.

```text
정상: C510
주의: C310 또는 C610
오류: C610 또는 시스템에서 오류처럼 보이는 색상 코드
강조: C710
```

실제 프로젝트에서는 화면 테마와 사용자 가독성을 기준으로 색상 코드를 검증해야 한다.

## 6. 컬럼 색상: Field Catalog의 EMPHASIZE

### 6.1 EMPHASIZE의 위치

컬럼 색상은 Field Catalog의 개별 행에 설정한다.

```abap
DATA lt_fcat TYPE lvc_t_fcat.
DATA ls_fcat TYPE lvc_s_fcat.

ls_fcat-fieldname = 'STATUS'.
ls_fcat-coltext   = '상태'.
ls_fcat-outputlen = 10.
ls_fcat-emphasize = 'C610'.
APPEND ls_fcat TO lt_fcat.
```

여기서 중요한 것은 `EMPHASIZE`가 **컬럼 정의 정보**라는 점이다. 즉, 데이터 행마다 다르게 적용되는 값이 아니라 해당 Field Catalog 항목이 가리키는 컬럼 전체에 적용된다.

### 6.2 EMPHASIZE를 사용할 때의 판단 기준

| 사용하면 좋은 경우 | 설명 |
|---|---|
| 상태 컬럼 | 업무 판단의 기준이 되는 필드 |
| 금액 컬럼 | 사용자가 우선 확인해야 하는 숫자 필드 |
| 오류 메시지 컬럼 | 조치 대상 파악에 필요한 필드 |
| 승인 여부 컬럼 | 결재/승인 프로세스의 핵심 필드 |

### 6.3 EMPHASIZE를 남발하면 안 되는 이유

컬럼 색상을 너무 많이 적용하면 사용자는 무엇이 중요한지 알기 어려워진다.

나쁜 예:

```text
모든 컬럼에 다른 색상을 적용한다.
색상 기준 없이 개발자 취향으로 컬럼을 칠한다.
업무 중요도와 무관하게 보기 좋게만 꾸민다.
```

좋은 예:

```text
상태 컬럼과 금액 컬럼만 강조한다.
오류 판단에 필요한 컬럼만 색상 처리한다.
색상 기준을 문서화한다.
```

## 7. 행 색상: Layout의 INFO_FNAME

### 7.1 INFO_FNAME의 핵심 구조

행 색상은 Layout의 `INFO_FNAME`에 “행 색상 정보를 담고 있는 필드명”을 지정해서 적용한다.

예를 들어 Output Internal Table에 `ROWCOLOR` 필드가 있다고 하자.

```abap
TYPES: BEGIN OF ty_output,
         carrid   TYPE s_carr_id,
         connid   TYPE s_conn_id,
         status   TYPE c LENGTH 1,
         message  TYPE c LENGTH 40,
         rowcolor TYPE c LENGTH 4,
       END OF ty_output.
```

그 다음 Layout에 다음처럼 지정한다.

```abap
DATA gs_layout TYPE lvc_s_layo.

gs_layout-info_fname = 'ROWCOLOR'.
```

그리고 Internal Table의 각 행에 색상 코드를 넣는다.

```abap
CASE ls_output-status.
  WHEN 'S'.
    ls_output-rowcolor = 'C510'.
  WHEN 'W'.
    ls_output-rowcolor = 'C310'.
  WHEN 'E'.
    ls_output-rowcolor = 'C610'.
ENDCASE.
```

이 구조가 핵심이다.

```text
Output Table에 색상 필드 추가
→ 각 행에 색상 코드 입력
→ Layout의 INFO_FNAME에 색상 필드명 지정
→ SET_TABLE_FOR_FIRST_DISPLAY 호출 시 Layout 전달
```

### 7.2 INFO_FNAME의 값은 필드명이다

초급자가 자주 하는 실수는 `INFO_FNAME`에 색상 코드 자체를 넣는 것이다.

잘못된 예:

```abap
gs_layout-info_fname = 'C610'. " 잘못된 방식
```

올바른 예:

```abap
gs_layout-info_fname = 'ROWCOLOR'. " 색상 코드를 담은 필드명
```

즉, `INFO_FNAME`에는 `C610`이 아니라 `ROWCOLOR` 같은 필드명이 들어가야 한다.

## 8. 실습 시나리오

### 8.1 업무 가정

항공편 처리 결과를 Grid ALV로 표시한다. 상태에 따라 행 색상을 다르게 적용하고, 상태 컬럼은 컬럼 색상으로 강조한다.

| 상태 | 의미 | 행 색상 기준 |
|---|---|---|
| S | Success | 정상 색상 |
| W | Warning | 주의 색상 |
| E | Error | 오류 색상 |

### 8.2 Output Structure

```abap
TYPES: BEGIN OF ty_output,
         carrid   TYPE s_carr_id,
         connid   TYPE s_conn_id,
         fldate   TYPE s_date,
         status   TYPE c LENGTH 1,
         message  TYPE c LENGTH 50,
         rowcolor TYPE c LENGTH 4,
       END OF ty_output.

DATA gt_output TYPE STANDARD TABLE OF ty_output.
DATA gs_output TYPE ty_output.
```

`ROWCOLOR`는 화면에 보여주기 위한 업무 데이터가 아니라 행 색상을 제어하기 위한 기술 필드이다.

### 8.3 테스트 데이터 준비

```abap
CLEAR gs_output.
gs_output-carrid   = 'AA'.
gs_output-connid   = '0017'.
gs_output-fldate   = sy-datum.
gs_output-status   = 'S'.
gs_output-message  = '정상 처리'.
gs_output-rowcolor = 'C510'.
APPEND gs_output TO gt_output.

CLEAR gs_output.
gs_output-carrid   = 'LH'.
gs_output-connid   = '0400'.
gs_output-fldate   = sy-datum.
gs_output-status   = 'W'.
gs_output-message  = '확인 필요'.
gs_output-rowcolor = 'C310'.
APPEND gs_output TO gt_output.

CLEAR gs_output.
gs_output-carrid   = 'KR'.
gs_output-connid   = '0900'.
gs_output-fldate   = sy-datum.
gs_output-status   = 'E'.
gs_output-message  = '오류 발생'.
gs_output-rowcolor = 'C610'.
APPEND gs_output TO gt_output.
```

### 8.4 Field Catalog 구성

```abap
DATA gt_fcat TYPE lvc_t_fcat.
DATA gs_fcat TYPE lvc_s_fcat.

CLEAR gs_fcat.
gs_fcat-fieldname = 'CARRID'.
gs_fcat-coltext   = '항공사'.
gs_fcat-outputlen = 10.
APPEND gs_fcat TO gt_fcat.

CLEAR gs_fcat.
gs_fcat-fieldname = 'CONNID'.
gs_fcat-coltext   = '연결번호'.
gs_fcat-outputlen = 10.
APPEND gs_fcat TO gt_fcat.

CLEAR gs_fcat.
gs_fcat-fieldname = 'FLDATE'.
gs_fcat-coltext   = '비행일자'.
gs_fcat-outputlen = 12.
APPEND gs_fcat TO gt_fcat.

CLEAR gs_fcat.
gs_fcat-fieldname = 'STATUS'.
gs_fcat-coltext   = '상태'.
gs_fcat-outputlen = 8.
gs_fcat-emphasize = 'C710'.
APPEND gs_fcat TO gt_fcat.

CLEAR gs_fcat.
gs_fcat-fieldname = 'MESSAGE'.
gs_fcat-coltext   = '메시지'.
gs_fcat-outputlen = 40.
APPEND gs_fcat TO gt_fcat.
```

`ROWCOLOR` 필드는 표시용 컬럼으로 만들지 않아도 된다. Layout의 `INFO_FNAME`이 해당 필드를 참조하면 행 색상 제어에 사용할 수 있다.

### 8.5 Layout 설정

```abap
DATA gs_layout TYPE lvc_s_layo.

gs_layout-zebra      = abap_true.
gs_layout-cwidth_opt = abap_true.
gs_layout-info_fname = 'ROWCOLOR'.
```

여기서 `INFO_FNAME`은 Output Internal Table의 필드명과 정확히 일치해야 한다.

## 9. SET_TABLE_FOR_FIRST_DISPLAY와 연결

색상 설정은 최종적으로 `SET_TABLE_FOR_FIRST_DISPLAY`에 전달되어야 화면에 반영된다.

```abap
CALL METHOD go_grid->set_table_for_first_display
  EXPORTING
    is_layout       = gs_layout
  CHANGING
    it_outtab       = gt_output
    it_fieldcatalog = gt_fcat.
```

이 호출 시점에 다음 데이터가 준비되어 있어야 한다.

| 객체 | 준비 내용 |
|---|---|
| `GT_OUTPUT` | `ROWCOLOR` 필드에 행별 색상 코드가 들어 있어야 함 |
| `GT_FCAT` | 컬럼 강조가 필요한 필드에 `EMPHASIZE` 설정 |
| `GS_LAYOUT` | `INFO_FNAME = 'ROWCOLOR'` 설정 |
| `GO_GRID` | `CL_GUI_ALV_GRID` 객체 생성 완료 |

## 10. 데이터 변경 후 색상 갱신

이전 모듈에서 학습한 것처럼 ALV 데이터가 변경되면 Refresh가 필요하다. 행 색상도 Output Table의 데이터 일부이므로 변경 후 화면을 갱신해야 한다.

```abap
LOOP AT gt_output INTO gs_output.
  IF gs_output-status = 'E'.
    gs_output-rowcolor = 'C610'.
  ELSEIF gs_output-status = 'W'.
    gs_output-rowcolor = 'C310'.
  ELSE.
    gs_output-rowcolor = 'C510'.
  ENDIF.

  MODIFY gt_output FROM gs_output.
ENDLOOP.

DATA ls_stable TYPE lvc_s_stbl.
ls_stable-row = abap_true.
ls_stable-col = abap_true.

CALL METHOD go_grid->refresh_table_display
  EXPORTING
    is_stable = ls_stable.
```

Stable Refresh를 사용하면 스크롤 위치와 컬럼 위치를 가능한 유지하면서 색상 변경 결과를 반영할 수 있다.

## 11. 정상 흐름

컬럼 색상과 행 색상의 정상 적용 흐름은 다음과 같다.

```text
1. Output Structure에 ROWCOLOR 필드 추가
2. Output Internal Table 데이터 구성
3. 각 행의 상태값에 따라 ROWCOLOR에 색상 코드 입력
4. Field Catalog에서 강조할 컬럼에 EMPHASIZE 설정
5. Layout에서 INFO_FNAME = 'ROWCOLOR' 설정
6. SET_TABLE_FOR_FIRST_DISPLAY 호출
7. 화면에서 컬럼 강조와 행 색상 확인
8. 데이터 변경 시 ROWCOLOR 재계산 후 REFRESH_TABLE_DISPLAY 호출
```

## 12. 오류 흐름과 해결 방법

### 12.1 행 색상이 전혀 적용되지 않음

| 점검 항목 | 설명 |
|---|---|
| `GS_LAYOUT-INFO_FNAME` | 색상 필드명이 정확히 들어갔는지 확인 |
| Output Table 필드 | `ROWCOLOR` 필드가 실제 구조에 있는지 확인 |
| 필드명 대소문자 | 일반적으로 대문자 필드명 사용 권장 |
| 색상 코드 값 | `C610` 같은 4자리 코드가 들어 있는지 확인 |
| Layout 전달 여부 | `SET_TABLE_FOR_FIRST_DISPLAY`에 `IS_LAYOUT`을 전달했는지 확인 |

잘못된 예:

```abap
gs_layout-info_fname = 'ROW_COLOR'.
```

실제 필드명이 `ROWCOLOR`라면 적용되지 않는다.

올바른 예:

```abap
gs_layout-info_fname = 'ROWCOLOR'.
```

### 12.2 컬럼 색상이 적용되지 않음

| 점검 항목 | 설명 |
|---|---|
| `FIELDNAME` | Field Catalog의 필드명이 Output Table 필드명과 일치하는지 확인 |
| `EMPHASIZE` | `C710` 같은 값이 설정되어 있는지 확인 |
| Field Catalog 전달 | `IT_FIELDCATALOG`가 실제 호출에 전달되는지 확인 |
| 재생성 로직 | Field Catalog가 나중에 초기화되지 않는지 확인 |

### 12.3 색상 필드가 ALV 컬럼으로 표시됨

`ROWCOLOR`는 기술 제어 필드이므로 화면에 표시할 필요가 없다. Field Catalog에 `ROWCOLOR`를 포함했다면 숨김 처리하거나 Field Catalog에서 제외한다.

```abap
CLEAR gs_fcat.
gs_fcat-fieldname = 'ROWCOLOR'.
gs_fcat-no_out    = abap_true.
APPEND gs_fcat TO gt_fcat.
```

또는 표시용 Field Catalog에 아예 넣지 않는다.

### 12.4 색상 코드가 업무 의미와 다르게 보임

색상 번호의 실제 표현은 SAP GUI 테마와 사용자 설정에 따라 달라질 수 있다. 따라서 실습에서는 코드가 적용되는지 확인하고, 실무에서는 사용자 환경에서 실제 가독성을 검증해야 한다.

## 13. 실무 적용 기준

### 13.1 색상은 업무 기준으로 사용한다

색상은 개발자 취향이 아니라 업무 기준에 따라 적용해야 한다.

좋은 기준:

| 조건 | 색상 목적 |
|---|---|
| 승인 지연 | 조치 필요 표시 |
| 오류 상태 | 즉시 확인 대상 표시 |
| 마감 임박 | 우선 처리 대상 표시 |
| 금액 초과 | 검토 필요 표시 |

나쁜 기준:

```text
보기 예쁘게 만들기 위해 색상을 많이 사용한다.
모든 컬럼과 모든 행에 색상을 적용한다.
사용자에게 색상 의미를 설명하지 않는다.
```

### 13.2 색상 의미를 문서화한다

실무 리포트에서는 색상 의미를 문서화하거나 화면 상단 설명, 버튼 도움말, 사용자 매뉴얼에 남기는 것이 좋다.

예:

| 색상 | 의미 |
|---|---|
| 초록 계열 | 정상 |
| 노랑 계열 | 확인 필요 |
| 빨강 계열 | 오류 또는 즉시 조치 필요 |

### 13.3 접근성을 고려한다

색상만으로 의미를 전달하면 색약, 테마 차이, 인쇄 환경에서 문제가 생길 수 있다. 따라서 색상과 함께 상태 텍스트나 아이콘을 같이 제공하는 것이 좋다.

```text
색상 + STATUS 텍스트 + MESSAGE 컬럼
```

이 조합이 단순 색상보다 더 안전하다.

### 13.4 성능 관점

행 색상 필드 하나를 추가하는 것 자체는 일반적으로 큰 성능 문제를 만들지 않는다. 다만 대량 데이터에서 색상 계산을 위해 복잡한 DB 조회나 반복 로직을 과도하게 넣으면 성능 문제가 생길 수 있다.

성능 관점의 권장 사항은 다음이다.

| 권장 | 설명 |
|---|---|
| 색상 조건은 단순하게 유지 | 상태값, 금액 기준 등 명확한 조건 사용 |
| 반복문 안 DB 조회 금지 | 색상 계산 중 `SELECT SINGLE` 반복은 피함 |
| 계산 결과 재사용 | 이미 가진 상태값으로 색상 결정 |
| Refresh 범위 고려 | 필요할 때만 Refresh 수행 |

## 14. 후속 THEORY-19와의 경계

이번 모듈에서는 행 전체 색상까지만 다룬다. 셀 단위 색상이나 스타일은 Deep Structure가 필요하다.

| 구분 | 현재 모듈 | 후속 THEORY-19 |
|---|---|---|
| 컬럼 전체 색상 | 다룸 | 복습 가능 |
| 행 전체 색상 | 다룸 | 복습 가능 |
| 셀 단위 색상 | 다루지 않음 | 다룸 |
| 셀 단위 스타일 | 다루지 않음 | 다룸 |
| `LVC_T_SCOL` | 개념 언급만 | 실제 구현 |
| `LVC_T_STYL` | 개념 언급만 | 실제 구현 |
| Deep Structure | 다루지 않음 | 실제 적용 |

이번 모듈에서 과도하게 셀 색상까지 구현하려고 하면 학습 순서가 흐려진다. 따라서 현재 단계에서는 `EMPHASIZE`, `INFO_FNAME`, Row Color만 확실히 익힌다.

## 15. 미니 실습

### 15.1 실습 목표

Grid ALV에 다음 두 가지 색상 기능을 적용한다.

```text
1. STATUS 컬럼을 EMPHASIZE로 강조한다.
2. STATUS 값에 따라 행 전체 색상을 다르게 표시한다.
```

### 15.2 입력 데이터

| CARRID | CONNID | STATUS | MESSAGE |
|---|---|---|---|
| AA | 0017 | S | 정상 처리 |
| LH | 0400 | W | 확인 필요 |
| KR | 0900 | E | 오류 발생 |

### 15.3 구현 조건

| 항목 | 조건 |
|---|---|
| Output Table | `ROWCOLOR TYPE C LENGTH 4` 필드 포함 |
| 컬럼 색상 | `STATUS` Field Catalog에 `EMPHASIZE` 설정 |
| 행 색상 | Layout에 `INFO_FNAME = 'ROWCOLOR'` 설정 |
| 오류 행 | `ROWCOLOR = 'C610'` |
| 주의 행 | `ROWCOLOR = 'C310'` |
| 정상 행 | `ROWCOLOR = 'C510'` |

### 15.4 결과 확인

실습 후 다음을 확인한다.

| 확인 항목 | 완료 |
|---|---|
| ALV가 정상 출력되는가 |  |
| STATUS 컬럼이 강조되는가 |  |
| 상태값에 따라 행 색상이 달라지는가 |  |
| ROWCOLOR 필드가 불필요하게 표시되지 않는가 |  |
| Refresh 후에도 색상이 유지되는가 |  |

## 17. 평가 문제

### 17.1 객관식

#### Q1. Grid ALV에서 컬럼 전체를 강조할 때 주로 사용하는 Field Catalog 속성은 무엇인가?

A. `INFO_FNAME`  
B. `EMPHASIZE`  
C. `CWIDTH_OPT`  
D. `I_SAVE`

정답: B

#### Q2. 행 색상을 적용하기 위해 Layout에서 지정하는 속성은 무엇인가?

A. `INFO_FNAME`  
B. `FIELDNAME`  
C. `OUTPUTLEN`  
D. `VARIANT`

정답: A

#### Q3. `INFO_FNAME`에 들어가야 하는 값으로 올바른 것은?

A. `C610`  
B. `C710`  
C. `ROWCOLOR`  
D. `STATUS = E`

정답: C

### 17.2 서술형

#### Q1. 컬럼 색상과 행 색상의 차이를 설명하시오.

모범 답안:  
컬럼 색상은 Field Catalog의 `EMPHASIZE`를 사용하여 특정 컬럼 전체를 강조하는 방식이다. 행 색상은 Output Internal Table에 색상 필드를 두고, Layout의 `INFO_FNAME`에 해당 필드명을 지정하여 행별 조건에 따라 행 전체 색상을 다르게 표시하는 방식이다.

#### Q2. 행 색상이 적용되지 않을 때 확인해야 할 항목을 세 가지 이상 쓰시오.

모범 답안:  
Output Structure에 `ROWCOLOR` 필드가 존재하는지, `GT_OUTPUT` 각 행의 `ROWCOLOR` 값이 `C610` 같은 형식으로 들어 있는지, `GS_LAYOUT-INFO_FNAME`이 실제 필드명과 일치하는지, `SET_TABLE_FOR_FIRST_DISPLAY`에 Layout이 전달되었는지 확인한다.

#### Q3. 색상만으로 업무 상태를 표현하면 안 되는 이유를 설명하시오.

모범 답안:  
SAP GUI 테마, 사용자 접근성 설정, 색약 여부, 인쇄 환경에 따라 색상 인지가 달라질 수 있기 때문이다. 따라서 색상과 함께 상태 코드, 상태 텍스트, 메시지 컬럼 등을 제공하는 것이 더 안전하다.

## 18. 초급자 핵심 요약

이번 모듈에서 반드시 기억할 내용은 다음이다.

```text
컬럼 색상은 Field Catalog의 EMPHASIZE로 설정한다.
행 색상은 Layout의 INFO_FNAME으로 색상 필드명을 연결한다.
INFO_FNAME에는 색상 코드가 아니라 색상 코드를 담은 필드명이 들어간다.

색상 코드는 일반적으로 Cxyz 형식을 사용한다.
셀 단위 색상과 스타일은 Deep Structure가 필요하므로 후속 THEORY-19에서 다룬다.
```
