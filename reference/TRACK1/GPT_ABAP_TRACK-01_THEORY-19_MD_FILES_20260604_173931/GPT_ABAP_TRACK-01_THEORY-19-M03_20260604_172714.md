## 3. Grid ALV 컬럼 제어의 핵심: Field Catalog

Grid ALV는 Internal Table의 데이터를 그대로 보여주는 도구가 아니다. Grid ALV는 출력 테이블의 각 필드를 **컬럼**으로 해석하고, 각 컬럼을 어떻게 보여줄지 결정하기 위해 Field Catalog를 사용한다.

Field Catalog는 쉽게 말해 다음과 같은 컬럼 설명서이다.

```text
이 필드는 어떤 이름의 컬럼인가?
컬럼 헤더는 무엇으로 보여줄 것인가?
몇 자리로 보여줄 것인가?
숨길 것인가?
합계를 낼 것인가?
왼쪽/오른쪽/가운데 정렬할 것인가?
핫스팟으로 보여줄 것인가?
통화키 또는 단위 필드와 연결할 것인가?
표시용 변환 규칙을 적용할 것인가?
```

Grid ALV에서 사용하는 대표 타입은 다음과 같다.

| 타입 | 의미 |
|---|---|
| `LVC_T_FCAT` | Field Catalog Internal Table |
| `LVC_S_FCAT` | Field Catalog 한 줄 구조 |
| `LVC_S_LAYO` | Grid ALV 전체 Layout 설정 |
| `LVC_T_SORT` | 정렬 조건 테이블 |
| `LVC_T_FILT` | 필터 조건 테이블 |

이번 문서에서는 `LVC_T_FCAT`, `LVC_S_FCAT`을 중심으로 한다.

## 4. Field Catalog 자동 생성과 수동 제어

Grid ALV에서는 Field Catalog를 전부 직접 만들 수도 있고, DDIC 구조를 기준으로 자동 생성할 수도 있다.

### 4.1 자동 생성

`SET_TABLE_FOR_FIRST_DISPLAY` 호출 시 `I_STRUCTURE_NAME`에 DDIC Structure나 Transparent Table 이름을 전달하면 Grid ALV가 DDIC 메타데이터를 바탕으로 Field Catalog를 생성할 수 있다.

예시:

```abap
CALL METHOD go_grid->set_table_for_first_display
  EXPORTING
    i_structure_name = 'SFLIGHT'
    is_layout        = gs_layout
  CHANGING
    it_outtab        = gt_sflight.
```

자동 생성의 장점은 다음과 같다.

| 장점 | 설명 |
|---|---|
| 빠른 구현 | DDIC 라벨과 타입 정보를 자동 활용할 수 있다. |
| 표준 일관성 | Data Element의 Field Label을 재사용한다. |
| 오류 감소 | 필드 타입을 직접 잘못 입력할 가능성이 줄어든다. |

하지만 자동 생성만으로는 실무 요구를 모두 충족하기 어렵다. 예를 들어 특정 컬럼만 숨기거나, 컬럼 헤더를 업무 화면에 맞게 바꾸거나, 금액/수량 단위를 명확히 연결해야 할 수 있다.

### 4.2 수동 제어

수동 제어는 Field Catalog를 직접 구성하거나, 자동 생성된 Field Catalog를 받아 일부 속성만 변경하는 방식이다.

일반적으로 실무에서는 다음 방식이 안정적이다.

```text
DDIC 구조를 기준으로 기본 Field Catalog를 만든다.
→ 필요한 컬럼만 LOOP로 찾아 속성을 보정한다.
→ 보정된 Field Catalog를 SET_TABLE_FOR_FIRST_DISPLAY에 전달한다.
```

즉, 모든 것을 처음부터 직접 쓰기보다 **표준 메타데이터를 활용하되 필요한 부분만 명시적으로 수정**하는 방식이 좋다.

## 5. 주요 Field Catalog 속성

`LVC_S_FCAT`에는 많은 필드가 있지만, 초급·중급 실무에서 자주 쓰는 항목부터 익히는 것이 좋다.

| 속성 | 의미 | 대표 사용 |
|---|---|---|
| `FIELDNAME` | 출력 테이블의 필드명 | 컬럼 식별 |
| `COLTEXT` | 컬럼 헤더 텍스트 | 업무 친화적 제목 |
| `SCRTEXT_S` | 짧은 필드 라벨 | 좁은 컬럼 헤더 |
| `SCRTEXT_M` | 중간 필드 라벨 | 일반 헤더 |
| `SCRTEXT_L` | 긴 필드 라벨 | 상세 헤더 |
| `OUTPUTLEN` | 출력 길이 | 컬럼 폭 조정 |
| `NO_OUT` | 기본 숨김 | Variant에서 표시 가능 |
| `TECH` | 기술 필드 숨김 | 사용자에게 거의 노출하지 않음 |
| `KEY` | Key 컬럼 표시 | 주요 식별 필드 강조 |
| `HOTSPOT` | 클릭 가능한 컬럼 | Drilldown/상세 이동 |
| `JUST` | 정렬 | L/C/R 정렬 |
| `EMPHASIZE` | 컬럼 강조 색상 | 컬럼 단위 강조 |
| `DO_SUM` | 합계 가능 | 금액/수량 합계 |
| `CFIELDNAME` | 통화키 필드명 | 금액 필드와 통화 연결 |
| `QFIELDNAME` | 단위 필드명 | 수량 필드와 단위 연결 |
| `EDIT_MASK` | 표시 마스크 | 날짜/코드/번호 표시 보정 |
| `REF_TABLE` | 참조 테이블 | DDIC 참조 보정 |
| `REF_FIELD` | 참조 필드 | DDIC 참조 보정 |

초급자는 먼저 다음 여섯 가지를 확실히 익히면 좋다.

```text
FIELDNAME
COLTEXT
OUTPUTLEN
NO_OUT
KEY
EDIT_MASK
```

## 7. Field Catalog 구성 예제

아래 예제는 Grid ALV 컬럼 제어를 학습하기 위한 교육용 코드이다.

```abap
FORM build_field_catalog.

  DATA ls_fcat TYPE lvc_s_fcat.

  CLEAR gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'CARRID'.
  ls_fcat-coltext   = '항공사'.
  ls_fcat-key       = abap_true.
  ls_fcat-outputlen = 8.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'CONNID'.
  ls_fcat-coltext   = '연결번호'.
  ls_fcat-key       = abap_true.
  ls_fcat-outputlen = 10.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'FLDATE'.
  ls_fcat-coltext   = '비행일자'.
  ls_fcat-outputlen = 12.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname  = 'PRICE'.
  ls_fcat-coltext    = '운임'.
  ls_fcat-outputlen  = 15.
  ls_fcat-do_sum     = abap_true.
  ls_fcat-cfieldname = 'CURRENCY'.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'CURRENCY'.
  ls_fcat-coltext   = '통화'.
  ls_fcat-outputlen = 5.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'PLANETYPE'.
  ls_fcat-coltext   = '항공기 유형'.
  ls_fcat-no_out    = abap_true.
  APPEND ls_fcat TO gt_fcat.

ENDFORM.
```

이 예제에서 중요한 포인트는 다음이다.

| 코드 | 의미 |
|---|---|
| `FIELDNAME` | 출력 Internal Table의 실제 필드명과 일치해야 한다. |
| `COLTEXT` | 사용자가 보는 컬럼 제목을 지정한다. |
| `KEY` | 주요 식별 필드로 표시한다. |
| `OUTPUTLEN` | 화면상의 컬럼 폭을 조정한다. |
| `DO_SUM` | 금액/수량 필드 합계 가능성을 부여한다. |
| `CFIELDNAME` | 금액 필드가 참조할 통화키 필드를 지정한다. |
| `NO_OUT` | 기본 출력에서는 숨기되 사용자가 Variant 등에서 표시할 수 있다. |

## 8. SET_TABLE_FOR_FIRST_DISPLAY와 연결

Field Catalog를 만든 뒤 Grid ALV 출력 시 전달한다.

```abap
FORM display_alv.

  IF go_container IS INITIAL.
    CREATE OBJECT go_container
      EXPORTING
        container_name = 'CC_ALV'.

    CREATE OBJECT go_grid
      EXPORTING
        i_parent = go_container.

    PERFORM build_field_catalog.

    gs_layout-zebra      = abap_true.
    gs_layout-cwidth_opt = abap_true.

    CALL METHOD go_grid->set_table_for_first_display
      EXPORTING
        is_layout       = gs_layout
      CHANGING
        it_outtab       = gt_sflight
        it_fieldcatalog = gt_fcat.
  ELSE.
    CALL METHOD go_grid->refresh_table_display.
  ENDIF.

ENDFORM.
```

여기서 `IT_FIELDCATALOG`에 `GT_FCAT`을 전달하면 Grid ALV가 해당 설정을 기준으로 컬럼을 표시한다.

주의할 점은 다음이다.

```text
Field Catalog의 FIELDNAME은 GT_SFLIGHT의 필드명과 정확히 일치해야 한다.
대소문자는 보통 대문자로 맞추는 것이 안전하다.
존재하지 않는 필드를 FIELDNAME에 넣으면 컬럼 제어가 의도대로 적용되지 않는다.
```

## 9. 자동 Field Catalog 보정 방식

수동으로 모든 Field Catalog를 작성하면 코드가 길어진다. 실무에서는 Function Module `LVC_FIELDCATALOG_MERGE`를 사용하거나 DDIC 구조 기반 자동 생성을 활용한 뒤 일부 필드만 조정하는 경우가 많다.

예시:

```abap
CALL FUNCTION 'LVC_FIELDCATALOG_MERGE'
  EXPORTING
    i_structure_name = 'SFLIGHT'
  CHANGING
    ct_fieldcat      = gt_fcat
  EXCEPTIONS
    inconsistent_interface = 1
    program_error          = 2
    OTHERS                 = 3.

IF sy-subrc <> 0.
  MESSAGE 'Field Catalog 생성 중 오류가 발생했습니다.' TYPE 'E'.
ENDIF.

LOOP AT gt_fcat ASSIGNING FIELD-SYMBOL(<fs_fcat>).
  CASE <fs_fcat>-fieldname.
    WHEN 'CARRID'.
      <fs_fcat>-coltext   = '항공사'.
      <fs_fcat>-key       = abap_true.
      <fs_fcat>-outputlen = 8.

    WHEN 'CONNID'.
      <fs_fcat>-coltext   = '연결번호'.
      <fs_fcat>-key       = abap_true.
      <fs_fcat>-outputlen = 10.

    WHEN 'PRICE'.
      <fs_fcat>-coltext    = '운임'.
      <fs_fcat>-do_sum     = abap_true.
      <fs_fcat>-cfieldname = 'CURRENCY'.

    WHEN 'PLANETYPE'.
      <fs_fcat>-no_out = abap_true.
  ENDCASE.
ENDLOOP.
```

이 방식의 장점은 다음이다.

| 장점 | 설명 |
|---|---|
| DDIC 기반 유지 | 기본 타입, 라벨, 참조 정보를 활용한다. |
| 코드량 감소 | 모든 필드를 직접 작성하지 않아도 된다. |
| 실무 변경에 유리 | 특정 필드만 찾아서 보정할 수 있다. |
| 오류 감소 | 필드 누락 가능성이 줄어든다. |

> [추정] `LVC_FIELDCATALOG_MERGE` 사용 가능 여부와 권장 방식은 시스템 릴리스, 프로젝트 표준, 개발 환경에 따라 다를 수 있다. 교육 과정에서는 동작 원리 이해를 위해 사용하고, 실무에서는 프로젝트 표준을 우선한다.

## 10. 컬럼 헤더 제어

Grid ALV의 컬럼 헤더는 사용자 경험에 큰 영향을 준다. Data Element의 Field Label을 그대로 쓰면 표준성과 일관성은 좋지만, 특정 업무 화면에서는 더 명확한 표현이 필요할 수 있다.

대표 속성은 다음과 같다.

| 속성 | 설명 |
|---|---|
| `COLTEXT` | 일반 컬럼 헤더 텍스트 |
| `SCRTEXT_S` | 짧은 라벨 |
| `SCRTEXT_M` | 중간 라벨 |
| `SCRTEXT_L` | 긴 라벨 |
| `REPTEXT` | 리포트 출력용 텍스트 성격 |

예시:

```abap
<fs_fcat>-coltext   = '판매금액'.
<fs_fcat>-scrtext_s = '금액'.
<fs_fcat>-scrtext_m = '판매금액'.
<fs_fcat>-scrtext_l = '총 판매금액'.
```

실무 기준은 다음이다.

| 상황 | 권장 |
|---|---|
| 표준 테이블 필드 의미가 충분히 명확함 | Data Element 라벨 유지 |
| 사용자 화면에서 더 쉬운 표현이 필요함 | `COLTEXT` 보정 |
| 다국어 화면이 중요함 | Text Symbol, Data Element, 번역 전략 검토 |
| 교육용 단순 화면 | 한글 `COLTEXT` 사용 가능 |

초급 과정에서는 한글 `COLTEXT`로 가독성을 높여도 된다. 그러나 실무에서는 다국어, 번역, 표준 라벨 재사용 기준까지 고려해야 한다.

---

## 11. 컬럼 폭 제어

컬럼 폭은 `OUTPUTLEN`과 Layout의 `CWIDTH_OPT`가 함께 영향을 준다.

```abap
<fs_fcat>-outputlen = 15.
gs_layout-cwidth_opt = abap_true.
```

| 설정 | 의미 |
|---|---|
| `OUTPUTLEN` | 해당 컬럼의 기본 출력 길이 |
| `CWIDTH_OPT` | Grid가 내용에 따라 컬럼 폭을 최적화하도록 지시 |

주의할 점은 다음이다.

```text
CWIDTH_OPT가 켜져 있으면 OUTPUTLEN이 항상 절대적으로 고정되는 것은 아니다.
사용자 Variant가 적용되면 저장된 컬럼 폭이 우선될 수 있다.
너무 작은 OUTPUTLEN은 값 식별을 어렵게 한다.
너무 큰 OUTPUTLEN은 화면 공간을 낭비한다.
```

실무에서는 화면의 주요 업무 흐름을 기준으로 컬럼 폭을 결정한다.

| 컬럼 유형 | 권장 관점 |
|---|---|
| 코드 필드 | 코드가 잘리지 않을 정도로 짧게 |
| 이름/설명 필드 | 실제 업무 확인이 가능하도록 충분히 |
| 금액/수량 필드 | 숫자와 단위가 함께 읽히도록 |
| 긴 텍스트 | 필요 시 상세 화면으로 분리 검토 |

---

## 12. 컬럼 숨김: NO_OUT과 TECH

Grid ALV에서 컬럼을 숨기는 대표 속성은 `NO_OUT`과 `TECH`이다.

| 속성 | 의미 | 사용자 표시 가능성 |
|---|---|---|
| `NO_OUT` | 기본 화면에서 숨김 | 사용자가 Layout/Variant에서 다시 표시 가능 |
| `TECH` | 기술 필드로 숨김 | 일반 사용자에게 거의 노출하지 않는 용도 |

예시:

```abap
WHEN 'PLANETYPE'.
  <fs_fcat>-no_out = abap_true.

WHEN 'INTERNAL_GUID'.
  <fs_fcat>-tech = abap_true.
```

### 12.1 NO_OUT이 적합한 경우

| 상황 | 설명 |
|---|---|
| 기본 화면에는 필요 없지만 분석 시 유용 | 보조 코드, 상세 속성 |
| 특정 사용자만 가끔 확인 | 선택 표시 가능 |
| Variant로 조정 허용 | 사용자의 개인화 가능 |

### 12.2 TECH가 적합한 경우

| 상황 | 설명 |
|---|---|
| 내부 처리용 GUID | 사용자에게 의미 없음 |
| 이벤트 처리용 Hidden Key | 클릭/상세 이동에만 필요 |
| 시스템 기술 필드 | 업무 화면 노출 부적합 |

주의할 점은 `TECH` 필드에 업무상 필요한 값을 숨겨버리면 사용자가 화면에서 문제를 분석하기 어려워질 수 있다는 것이다.

---

## 13. Key 컬럼 제어

`KEY` 속성은 컬럼을 주요 식별 필드로 표시하는 데 사용된다.

```abap
<fs_fcat>-key = abap_true.
```

Key 컬럼은 보통 왼쪽에 고정되거나 강조되어 보일 수 있으며, 사용자가 행의 식별 기준을 빠르게 이해하도록 돕는다.

예를 들어 `SFLIGHT`에서는 다음 필드가 업무상 식별성이 높다.

| 필드 | 이유 |
|---|---|
| `CARRID` | 항공사 코드 |
| `CONNID` | 연결 번호 |
| `FLDATE` | 비행일자 |

실무에서 Key 컬럼을 지정할 때는 다음을 고려한다.

```text
DB Primary Key와 화면상 Key 컬럼이 항상 완전히 같아야 하는 것은 아니다.
사용자가 행을 식별하는 데 필요한 필드를 중심으로 지정한다.
너무 많은 컬럼을 Key로 지정하면 화면이 복잡해진다.
```

---

## 14. 정렬과 정렬 표시의 구분

컬럼 제어에서 `KEY`를 지정한다고 해서 반드시 데이터가 정렬되는 것은 아니다. Key 표시는 행 식별을 위한 표시 속성이고, 실제 정렬은 Sort Table이나 사용자 정렬 기능으로 처리한다.

정렬은 보통 `LVC_T_SORT`를 사용한다.

```abap
DATA gt_sort TYPE lvc_t_sort.
DATA gs_sort TYPE lvc_s_sort.

CLEAR gs_sort.
gs_sort-fieldname = 'CARRID'.
gs_sort-up        = abap_true.
APPEND gs_sort TO gt_sort.

CLEAR gs_sort.
gs_sort-fieldname = 'CONNID'.
gs_sort-up        = abap_true.
APPEND gs_sort TO gt_sort.
```

`SET_TABLE_FOR_FIRST_DISPLAY` 호출 시 정렬 테이블을 함께 전달할 수 있다.

```abap
CALL METHOD go_grid->set_table_for_first_display
  EXPORTING
    is_layout       = gs_layout
  CHANGING
    it_outtab       = gt_sflight
    it_fieldcatalog = gt_fcat
    it_sort         = gt_sort.
```

이번 모듈의 중심은 컬럼 속성이므로 Sort 심화는 별도 주제로 확장하지 않는다. 다만 `KEY`와 `SORT`를 혼동하지 않는 것이 중요하다.

---

## 15. 정렬 방향: JUST

`JUST`는 컬럼 값의 표시 정렬을 제어한다.

| 값 | 의미 |
|---|---|
| `L` | Left |
| `C` | Center |
| `R` | Right |

예시:

```abap
<fs_fcat>-just = 'R'.
```

실무 일반 기준은 다음과 같다.

| 데이터 유형 | 권장 정렬 |
|---|---|
| 코드 | 왼쪽 또는 가운데 |
| 설명 텍스트 | 왼쪽 |
| 금액 | 오른쪽 |
| 수량 | 오른쪽 |
| 날짜 | 시스템/프로젝트 기준에 따름 |

숫자처럼 보이는 코드와 실제 계산 대상 숫자는 구분해야 한다. 예를 들어 `CONNID`가 숫자 형태라고 해서 항상 계산용 숫자는 아니다.

## 16. 금액/수량 컬럼과 단위 연결

ALV에서 금액과 수량은 단순 숫자 컬럼으로 보면 안 된다. 금액에는 통화가 필요하고, 수량에는 단위가 필요하다.

### 16.1 통화키 연결

금액 필드는 `CFIELDNAME`으로 통화키 필드를 연결할 수 있다.

```abap
WHEN 'PRICE'.
  <fs_fcat>-cfieldname = 'CURRENCY'.
```

이 설정은 `PRICE` 값이 어떤 통화 기준인지 ALV가 이해하도록 돕는다.

### 16.2 단위 필드 연결

수량 필드는 `QFIELDNAME`으로 단위 필드를 연결할 수 있다.

```abap
WHEN 'WEIGHT'.
  <fs_fcat>-qfieldname = 'UNIT'.
```

### 16.3 실무 주의

| 주의점 | 설명 |
|---|---|
| 금액만 단독 표시 금지 | 통화가 없으면 값 의미가 불명확하다. |
| 수량만 단독 표시 금지 | 단위가 없으면 수량 의미가 불명확하다. |
| 합계 시 단위 혼합 주의 | 서로 다른 통화/단위의 합계는 의미가 없을 수 있다. |
| DDIC 참조 우선 | 가능하면 DDIC에서 통화/단위 참조를 올바르게 설계한다. |

Grid ALV 컬럼 제어는 DDIC 설계를 보완할 수 있지만, 잘못된 데이터 모델을 완전히 해결해주지는 않는다.

---

## 17. 합계 컬럼: DO_SUM

`DO_SUM`은 금액이나 수량 컬럼에 합계 기능을 부여하는 데 사용한다.

```abap
<fs_fcat>-do_sum = abap_true.
```

합계가 적합한 컬럼은 다음과 같다.

| 적합 | 부적합 |
|---|---|
| 금액 | 코드 |
| 수량 | 상태값 |
| 건수 | 이름 |
| 점수 | 날짜 |

주의할 점은 통화나 단위가 섞인 데이터의 합계이다. 예를 들어 USD와 KRW가 섞인 금액을 단순 합계로 보여주면 업무적으로 의미가 없다. 이런 경우 통화별 합계, 환산 기준, 그룹핑 기준을 별도로 설계해야 한다.

## 18. Edit Mask의 목적

`EDIT_MASK`는 출력 값을 특정 형식으로 보이게 하는 표시용 마스크이다.

예를 들어 내부적으로는 숫자나 문자열로 저장되어 있지만, 화면에서는 하이픈이나 구분 기호가 포함된 형태로 보여주고 싶을 때 검토할 수 있다.

```text
내부 값: 20260604
표시 값: 2026-06-04
```

또는 코드/번호를 사용자 친화적 형식으로 표시하고 싶을 수 있다.

`EDIT_MASK`는 “값 자체를 변경하는 것”이 아니라 “표시 형식을 보정하는 것”으로 이해해야 한다.

---

## 19. Edit Mask 사용 예시

교육용 예시로, 사업자번호처럼 고정 길이 문자열을 표시한다고 가정한다.

```abap
WHEN 'BIZ_NO'.
  <fs_fcat>-edit_mask = '___-__-_____'.
```

또는 코드 표시 형식을 보정할 수 있다.

```abap
WHEN 'DOC_NO'.
  <fs_fcat>-edit_mask = '____-____-____'.
```

> [추정] 실제 `EDIT_MASK`의 해석과 적용 가능성은 필드 타입, Conversion Exit, 시스템 설정, ALV 표시 방식에 따라 차이가 있을 수 있다. 운영 화면에서는 반드시 실제 데이터로 검증해야 한다.

### 19.1 Edit Mask와 Conversion Exit

SAP 표준 필드에는 Conversion Exit가 적용되는 경우가 많다. 예를 들어 자재번호, 고객번호, ALPHA 변환 등은 내부 값과 외부 표시 값이 다를 수 있다.

따라서 실무에서는 다음 순서로 판단하는 것이 좋다.

```text
1. DDIC Data Element에 적절한 Conversion Exit가 있는가?
2. 표준 표시 방식이 이미 충분한가?
3. 화면 요구사항 때문에 추가 표시 마스크가 필요한가?
4. 마스크 적용 후 정렬/필터/다운로드 결과가 문제없는가?
```

Edit Mask를 남발하면 표시와 실제 값 사이의 차이가 커져 사용자 혼란이 생길 수 있다.

## 20. 핫스팟 컬럼

`HOTSPOT`은 컬럼 값을 클릭 가능한 형태로 표시할 때 사용한다.

```abap
WHEN 'CARRID'.
  <fs_fcat>-hotspot = abap_true.
```

핫스팟은 보통 다음 기능과 연결된다.

| 기능 | 설명 |
|---|---|
| 상세 화면 이동 | 선택 행의 상세 정보 표시 |
| 트랜잭션 호출 | 관련 표준 트랜잭션으로 이동 |
| 팝업 표시 | 추가 설명 표시 |
| Drilldown | 하위 목록 조회 |

다만 Hotspot 이벤트 처리 자체는 ALV 이벤트 주제에 속한다. 이번 모듈에서는 컬럼을 클릭 가능하게 표시하는 속성만 이해한다.

## 21. 컬럼 강조: EMPHASIZE

`EMPHASIZE`는 컬럼 단위 강조에 사용한다.

```abap
WHEN 'PRICE'.
  <fs_fcat>-emphasize = 'C300'.
```

이 속성은 컬럼 전체를 강조하는 방식이다. 특정 셀만 조건부로 색칠하고 싶다면 Cell Color 구조가 필요하며, 이는 다음 모듈에서 다룬다.

| 요구사항 | 적합한 방식 |
|---|---|
| 특정 컬럼 전체 강조 | `EMPHASIZE` |
| 특정 행 전체 강조 | `INFO_FNAME` |
| 특정 셀만 조건부 강조 | `CTAB_FNAME`, `LVC_T_SCOL` |

이번 모듈에서는 컬럼 전체 강조까지만 다룬다.

## 22. 출력 후 Field Catalog 변경

ALV를 이미 출력한 뒤에도 Frontend Field Catalog를 가져와 변경할 수 있다.

대표 흐름은 다음과 같다.

```abap
DATA lt_fcat TYPE lvc_t_fcat.

CALL METHOD go_grid->get_frontend_fieldcatalog
  IMPORTING
    et_fieldcatalog = lt_fcat.

LOOP AT lt_fcat ASSIGNING FIELD-SYMBOL(<fs_fcat>).
  IF <fs_fcat>-fieldname = 'PLANETYPE'.
    <fs_fcat>-no_out = abap_false.
  ENDIF.
ENDLOOP.

CALL METHOD go_grid->set_frontend_fieldcatalog
  EXPORTING
    it_fieldcatalog = lt_fcat.

CALL METHOD go_grid->refresh_table_display.
```

이 방식은 사용자의 화면 상태에 영향을 줄 수 있으므로 신중해야 한다.

### 22.1 초기 Field Catalog와 Frontend Field Catalog

| 구분 | 의미 |
|---|---|
| 초기 Field Catalog | 최초 ALV 출력 시 전달하는 컬럼 설정 |
| Frontend Field Catalog | 현재 화면에 적용된 컬럼 설정 |

실무에서는 가능하면 초기 출력 전에 Field Catalog를 충분히 준비하는 것이 좋다. 출력 후 동적 변경은 버튼 이벤트, 사용자 액션, 조건부 화면 전환 등 명확한 이유가 있을 때 사용한다.

## 23. Variant와 컬럼 제어 충돌

ALV Layout Variant는 사용자가 컬럼 순서, 폭, 숨김 여부, 정렬 등을 저장하는 기능이다. Field Catalog에서 컬럼 속성을 설정해도 사용자 Variant가 적용되면 화면 결과가 달라질 수 있다.

예를 들어 개발자가 `PLANETYPE`을 숨기도록 `NO_OUT`을 설정했지만, 사용자의 Variant가 해당 컬럼을 표시하도록 저장되어 있다면 예상과 다른 화면이 나올 수 있다.

실무 기준은 다음과 같다.

| 상황 | 권장 대응 |
|---|---|
| 기본 화면 표준화가 중요 | 기본 Variant 관리 |
| 사용자 개인화 허용 | Variant 적용 가능성 문서화 |
| 기술 필드 노출 금지 | `TECH` 또는 출력 데이터 구조 분리 검토 |
| 화면 변경 후 사용자 불만 발생 | Variant 초기화/재저장 안내 |

컬럼 제어 문제처럼 보이지만 실제 원인이 Variant인 경우가 많다.

## 24. 자주 발생하는 오류

### 24.1 FIELDNAME 오타

#### 증상

컬럼 속성을 바꿨는데 화면에 반영되지 않는다.

#### 원인

`FIELDNAME`이 출력 Internal Table 필드명과 일치하지 않는다.

#### 해결

출력 구조 필드명을 확인하고 대문자로 정확히 맞춘다.

```abap
잘못된 예: 'carrid'
권장 예: 'CARRID'
```

### 24.2 Field Catalog에 없는 필드 출력 기대

#### 증상

Internal Table에는 필드가 있는데 ALV에 보이지 않는다.

#### 원인

수동 Field Catalog 방식에서 해당 필드를 추가하지 않았다.

#### 해결

Field Catalog에 해당 `FIELDNAME`을 추가하거나 자동 생성 후 보정 방식을 사용한다.

### 24.3 통화/단위 연결 누락

#### 증상

금액이나 수량이 의미 없이 숫자로만 보인다.

#### 원인

`CFIELDNAME`, `QFIELDNAME` 또는 DDIC 참조가 누락되었다.

#### 해결

금액 필드에는 통화키 필드, 수량 필드에는 단위 필드를 연결한다.

### 24.4 NO_OUT과 TECH 혼동

#### 증상

사용자가 Layout에서 컬럼을 다시 표시할 수 없거나, 반대로 숨겨야 할 필드를 표시할 수 있다.

#### 원인

`NO_OUT`과 `TECH`의 목적을 혼동했다.

#### 해결

기본 숨김은 `NO_OUT`, 사용자에게 노출하지 않을 기술 필드는 `TECH`를 검토한다.

### 24.5 Variant 때문에 변경 사항이 안 보임

#### 증상

Field Catalog를 수정했는데 특정 사용자에게만 화면이 다르게 보인다.

#### 원인

사용자 개인 Variant 또는 기본 Variant가 컬럼 속성을 덮어쓰고 있다.

#### 해결

Variant 적용 여부를 확인하고, 필요 시 Variant를 삭제/재저장하거나 기본 Layout 정책을 정리한다.

## 25. 실무 설계 기준

### 25.1 컬럼 제어는 사용자 업무 흐름 기준으로 한다

컬럼을 예쁘게 만드는 것보다 중요한 것은 사용자가 업무 판단을 빠르게 할 수 있게 하는 것이다.

다음 질문을 기준으로 설계한다.

```text
사용자가 행을 식별하는 데 필요한 컬럼은 무엇인가?
가장 먼저 봐야 하는 컬럼은 무엇인가?
기본 화면에서 숨겨도 되는 보조 컬럼은 무엇인가?
금액/수량 컬럼의 단위는 명확한가?
사용자가 Variant로 조정해도 되는 영역인가?
```

### 25.2 DDIC 설계를 우선한다

Field Catalog에서 많은 것을 보정할 수 있지만, 가장 좋은 방식은 DDIC에서 필드 의미와 타입을 올바르게 설계하는 것이다.

| DDIC 설계 | ALV 효과 |
|---|---|
| Data Element Field Label | 기본 컬럼 라벨로 활용 가능 |
| Domain Fixed Value | 값 의미 파악에 도움 |
| Currency/Quantity Reference | 금액/수량 표시 안정성 향상 |
| Conversion Exit | 내부/외부 값 표시 일관성 확보 |

ALV Field Catalog는 DDIC 설계의 대체물이 아니라 화면 요구사항에 맞춘 보완 수단이다.

### 25.3 기술 필드는 최소 노출한다

GUID, 내부 상태값, 처리용 플래그는 사용자에게 노출할 필요가 없을 수 있다. 그러나 이벤트 처리나 상세 조회에 필요할 수 있으므로 출력 Internal Table에는 보관하되 화면에서는 숨길 수 있다.

```text
출력 구조에는 포함
→ Field Catalog에서 TECH 또는 NO_OUT 처리
→ 이벤트 처리 시 내부 값 활용
```

### 25.4 컬럼 수를 줄인다

ALV에 너무 많은 컬럼을 기본 표시하면 사용자가 핵심 정보를 놓친다. 기본 화면은 핵심 컬럼 중심으로 구성하고, 보조 컬럼은 Variant로 열 수 있게 하는 것이 좋다.

## 28. 평가 문제

### 28.1 객관식

#### Q1. Grid ALV에서 컬럼 표시 속성을 제어하는 핵심 데이터 구조는 무엇인가?

A. `LVC_S_LAYO`  
B. `LVC_T_FCAT`  
C. `BAPIRET2`  
D. `BDCDATA`  

정답: B

#### Q2. 기본 화면에서는 숨기지만 사용자가 Layout에서 다시 표시할 수 있게 하고 싶을 때 주로 사용하는 속성은?

A. `NO_OUT`  
B. `TECH`  
C. `DO_SUM`  
D. `CFIELDNAME`  

정답: A

#### Q3. 금액 필드와 통화키 필드를 연결하는 Field Catalog 속성은?

A. `QFIELDNAME`  
B. `CFIELDNAME`  
C. `HOTSPOT`  
D. `OUTPUTLEN`  

정답: B

#### Q4. 특정 셀만 조건부로 색상을 바꾸고 싶을 때 이번 모듈의 `EMPHASIZE`만으로 충분한가?

A. 충분하다.  
B. 충분하지 않다. Cell Color 구조가 필요하며 후속 모듈에서 다룬다.  
C. `OUTPUTLEN`을 늘리면 된다.  
D. `KEY`를 체크하면 된다.  

정답: B

### 28.2 서술형

#### Q1. `NO_OUT`과 `TECH`의 차이를 설명하시오.

모범 답안:  
`NO_OUT`은 기본 화면에서 컬럼을 숨기지만 사용자가 Layout/Variant에서 다시 표시할 수 있는 성격이다. `TECH`는 내부 처리용 기술 필드처럼 일반 사용자에게 노출하지 않는 컬럼에 사용하는 숨김 성격이다.

#### Q2. Field Catalog를 수정했는데 특정 사용자 화면에서만 반영되지 않는 이유를 설명하시오.

모범 답안:  
사용자 개인 Layout Variant 또는 기본 Variant가 컬럼 순서, 폭, 숨김 여부 등을 저장하고 있어 개발자가 설정한 Field Catalog 결과를 덮어쓸 수 있다. 따라서 Variant 적용 여부를 확인하고 필요 시 초기화 또는 재저장이 필요하다.

#### Q3. 금액 컬럼에 `CFIELDNAME`을 설정해야 하는 이유를 설명하시오.

모범 답안:  
금액은 통화 없이 숫자만으로는 의미가 불명확하다. `CFIELDNAME`을 통해 금액 필드가 참조할 통화키 필드를 지정하면 ALV가 금액과 통화를 함께 이해하고 표시할 수 있다.

## 29. 핵심 요약

이번 모듈의 핵심은 다음과 같다.

```text
Grid ALV 컬럼 제어의 중심은 Field Catalog이다.
LVC_T_FCAT은 컬럼 설정 테이블이고 LVC_S_FCAT은 한 컬럼의 설정 구조이다.
COLTEXT, OUTPUTLEN, NO_OUT, TECH, KEY, HOTSPOT, DO_SUM, CFIELDNAME, QFIELDNAME, EDIT_MASK는 실무에서 자주 쓰인다.
금액과 수량은 통화키/단위 필드와 함께 표시해야 의미가 명확하다.
NO_OUT과 TECH는 목적이 다르므로 구분해서 사용해야 한다.
Variant는 Field Catalog 결과에 영향을 줄 수 있다.
특정 셀 색상이나 스타일 제어는 후속 Deep Structure 기반 모듈에서 다룬다.
```
