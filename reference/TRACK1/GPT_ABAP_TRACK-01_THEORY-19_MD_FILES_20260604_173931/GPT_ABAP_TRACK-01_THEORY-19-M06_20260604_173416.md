## 3. 색상 표시 제어의 실무 목적

ALV 색상은 장식이 아니다.  
업무 리포트에서 색상은 다음 목적을 가진다.

| 목적 | 예시 |
|---|---|
| 위험 신호 표시 | 납기 초과, 마이너스 재고, 결재 지연 |
| 주의 필요 항목 표시 | 상태 보류, 예외 승인 필요, 임계값 초과 |
| 주요 컬럼 강조 | 금액, 상태, 차이, 승인 여부 |
| 사용자의 탐색 부담 감소 | 많은 행 중 중요한 행을 빠르게 찾도록 지원 |
| 후속 조치 대상 구분 | 처리 필요, 재검토 필요, 완료 |

색상은 업무 판단을 돕는 신호여야 한다.  
“예쁘게 보이기 위해” 색을 많이 넣는 것은 실무 리포트 품질을 떨어뜨린다.

## 4. 세 가지 색상 제어 방식 한눈에 보기

### 4.1 Row Color

Row Color는 한 행 전체를 강조한다.

예를 들어 판매오더 리스트에서 `STATUS = 'E'`인 행 전체를 빨간색 계열로 표시할 수 있다.

```text
행 전체가 문제인 경우 → Row Color
```

대표 설정은 Layout의 `INFO_FNAME`이다.

```abap
gs_layout-info_fname = 'ROW_COLOR'.
```

여기서 `ROW_COLOR`는 출력 Internal Table의 필드명이다.  
해당 필드에 ALV 색상 코드가 들어가면 Grid ALV가 그 값을 읽어 행 전체 색상으로 적용한다.

### 4.2 Column Color

Column Color는 특정 컬럼 전체를 강조한다.

예를 들어 금액 컬럼 `AMOUNT`를 항상 강조하고 싶다면 Field Catalog의 `EMPHASIZE`를 사용한다.

```abap
gs_fcat-fieldname = 'AMOUNT'.
gs_fcat-emphasize = 'C510'.
```

```text
컬럼 자체가 중요한 경우 → Column Color
```

Column Color는 데이터 값마다 달라지는 것이 아니라, 해당 컬럼의 역할 때문에 강조할 때 적합하다.

### 4.3 Cell Color

Cell Color는 특정 행의 특정 컬럼, 즉 특정 셀만 강조한다.

예를 들어 전체 행이 아니라 `AMOUNT_DIFF` 값이 음수인 셀만 빨간색으로 표시할 수 있다.

```text
특정 값 하나가 문제인 경우 → Cell Color
```

대표 설정은 Layout의 `CTAB_FNAME`이다.

```abap
gs_layout-ctab_fname = 'CELL_COLOR'.
```

여기서 `CELL_COLOR`는 출력 Internal Table의 Deep Component이며, 타입은 보통 `LVC_T_SCOL`이다.

## 5. 선택 기준: 어떤 색상 방식을 써야 하는가?

실무에서 가장 중요한 판단 기준은 “강조 대상이 무엇인가?”이다.

| 강조 대상 | 선택 방식 | 대표 설정 |
|---|---|---|
| 행 전체의 업무 상태 | Row Color | `INFO_FNAME` |
| 컬럼의 역할 또는 중요도 | Column Color | `EMPHASIZE` |
| 특정 셀의 예외값 | Cell Color | `CTAB_FNAME` |
| 행 전체 상태 + 특정 셀 예외 | Row Color + Cell Color | `INFO_FNAME` + `CTAB_FNAME` |
| 컬럼 기본 강조 + 특정 셀 예외 | Column Color + Cell Color | `EMPHASIZE` + `CTAB_FNAME` |

단, 여러 색상 제어를 동시에 사용할 때는 가독성 규칙을 반드시 정해야 한다.

> 실무 권장 원칙:  
> 한 화면에서 색상의 의미는 최대한 단순해야 한다.  
> 사용자가 색상표를 보지 않고도 직관적으로 이해할 수 있어야 한다.

## 6. Row Color 선택 기준

### 6.1 Row Color가 적합한 경우

Row Color는 한 행 전체가 같은 의미를 가질 때 적합하다.

| 상황 | Row Color 적합 여부 | 이유 |
|---|---|---|
| 주문 전체가 취소됨 | 적합 | 행 전체 상태가 취소이므로 전체 강조 가능 |
| 결재 문서 전체가 반려됨 | 적합 | 문서 한 건 전체가 문제 상태 |
| 재고 항목 전체가 Block됨 | 적합 | 해당 행 전체가 처리 제한 대상 |
| 특정 금액 셀만 음수 | 부적합 | 행 전체가 아니라 특정 셀만 문제 |
| 특정 컬럼을 항상 중요하게 보여야 함 | 부적합 | 행이 아니라 컬럼 역할의 문제 |

### 6.2 Row Color 구현 구조

Row Color를 적용하려면 출력 Internal Table에 색상 코드용 필드를 둔다.

```abap
TYPES: BEGIN OF ty_output,
         carrid    TYPE s_carr_id,
         connid    TYPE s_conn_id,
         seatsocc  TYPE s_seatsocc,
         seatsmax  TYPE s_seatsmax,
         status    TYPE c LENGTH 1,
         row_color TYPE c LENGTH 4,
       END OF ty_output.
```

그리고 Layout에서 이 필드명을 지정한다.

```abap
DATA gs_layout TYPE lvc_s_layo.

gs_layout-info_fname = 'ROW_COLOR'.
```

이후 데이터 조건에 따라 `ROW_COLOR` 값을 채운다.

```abap
LOOP AT gt_output ASSIGNING FIELD-SYMBOL(<ls_output>).
  IF <ls_output>-status = 'E'.
    <ls_output>-row_color = 'C610'.
  ELSEIF <ls_output>-status = 'W'.
    <ls_output>-row_color = 'C310'.
  ENDIF.
ENDLOOP.
```

색상 코드의 세부 의미는 시스템 테마와 ALV 동작에 따라 시각적으로 다르게 느껴질 수 있다.  
따라서 교육과 실무에서는 실제 SAP GUI 화면에서 색상 결과를 확인해야 한다.

### 6.3 Row Color 사용 시 주의점

Row Color는 강력한 시각 효과를 가진다.  
많은 행이 한꺼번에 색칠되면 오히려 사용자가 중요한 정보를 찾기 어려워진다.

나쁜 예:

```text
전체 1,000건 중 800건에 Row Color 적용
```

좋은 예:

```text
예외 상태 20건에만 Row Color 적용
```

## 7. Column Color 선택 기준

### 7.1 Column Color가 적합한 경우

Column Color는 데이터 값과 관계없이 특정 컬럼의 역할이 중요할 때 사용한다.

| 상황 | Column Color 적합 여부 | 이유 |
|---|---|---|
| 금액 컬럼을 항상 강조 | 적합 | 컬럼 자체가 핵심 지표 |
| 차이 금액 컬럼을 강조 | 적합 | 리포트 분석의 핵심 컬럼 |
| 상태 컬럼을 강조 | 경우에 따라 적합 | 상태 컬럼을 빠르게 찾게 함 |
| 오류가 있는 행 전체를 강조 | 부적합 | 컬럼이 아니라 행 상태의 문제 |
| 특정 셀만 오류 표시 | 부적합 | 컬럼 전체 강조는 과도함 |

### 7.2 Column Color 구현 구조

Column Color는 Field Catalog에서 설정한다.

```abap
DATA gs_fcat TYPE lvc_s_fcat.

gs_fcat-fieldname = 'AMOUNT_DIFF'.
gs_fcat-coltext   = '차이 금액'.
gs_fcat-emphasize = 'C510'.
APPEND gs_fcat TO gt_fcat.
```

`EMPHASIZE`는 해당 컬럼을 강조 표시하는 속성이다.  
간단하게는 `X`를 넣어 강조할 수도 있고, 색상 코드를 사용하여 특정 색 계열을 지정할 수도 있다.

```abap
gs_fcat-emphasize = 'X'.     " 기본 강조
gs_fcat-emphasize = 'C510'.  " 색상 코드 기반 강조
```

### 7.3 Column Color 사용 시 주의점

Column Color는 리포트의 “읽는 경로”를 설계하는 데 유용하다.  
하지만 컬럼이 너무 많이 강조되면 강조의 의미가 사라진다.

권장 기준:

```text
한 ALV에서 Column Color는 1~3개 핵심 컬럼에만 사용한다.
```

예를 들어 재고 분석 리포트라면 다음 컬럼 정도가 강조 대상이 될 수 있다.

| 컬럼 | 강조 이유 |
|---|---|
| CURRENT_STOCK | 현재 재고 |
| SAFETY_STOCK | 안전 재고 |
| SHORTAGE_QTY | 부족 수량 |

## 8. Cell Color 선택 기준

### 8.1 Cell Color가 적합한 경우

Cell Color는 가장 세밀한 표시 제어 방식이다.  
특정 값이나 특정 조건이 중요한 경우 사용한다.

| 상황 | Cell Color 적합 여부 | 이유 |
|---|---|---|
| 금액 차이가 음수인 셀만 표시 | 적합 | 특정 값만 예외 |
| 납기일이 오늘 이전인 셀만 표시 | 적합 | 특정 날짜 값만 문제 |
| 상태가 오류인 행 전체 표시 | 경우에 따라 부적합 | 행 전체 상태라면 Row Color가 더 명확 |
| 모든 금액 컬럼을 강조 | 부적합 | Column Color가 더 단순 |
| 특정 셀을 입력 가능/불가능으로 구분 | Cell Style 영역 | 색상보다 Style 제어가 적합할 수 있음 |

### 8.2 Cell Color 구현 구조

Cell Color는 출력 Internal Table에 Deep Component를 추가하고, Layout에 해당 필드명을 지정한다.

```abap
TYPES: BEGIN OF ty_output,
         carrid     TYPE s_carr_id,
         connid     TYPE s_conn_id,
         seatsocc   TYPE s_seatsocc,
         seatsmax   TYPE s_seatsmax,
         status     TYPE c LENGTH 1,
         cell_color TYPE lvc_t_scol,
       END OF ty_output.
```

Layout 설정:

```abap
DATA gs_layout TYPE lvc_s_layo.

gs_layout-ctab_fname = 'CELL_COLOR'.
```

조건에 따라 Cell Color 정보를 채운다.

```abap
DATA ls_scol TYPE lvc_s_scol.

LOOP AT gt_output ASSIGNING FIELD-SYMBOL(<ls_output>).

  IF <ls_output>-seatsocc >= <ls_output>-seatsmax.

    CLEAR ls_scol.
    ls_scol-fname     = 'SEATSOCC'.
    ls_scol-color-col = 6.
    ls_scol-color-int = 1.
    ls_scol-color-inv = 0.
    APPEND ls_scol TO <ls_output>-cell_color.

  ENDIF.

ENDLOOP.
```

`LVC_S_SCOL-FNAME`에는 색상을 적용할 필드명을 넣는다.  
이 필드명이 Field Catalog의 `FIELDNAME`과 맞지 않으면 색상이 적용되지 않는다.

## 9. 세 방식의 비교

### 9.1 목적 기준 비교

| 기준 | Row Color | Column Color | Cell Color |
|---|---|---|---|
| 강조 범위 | 행 전체 | 컬럼 전체 | 특정 셀 |
| 대표 설정 | `INFO_FNAME` | `EMPHASIZE` | `CTAB_FNAME` |
| 데이터별 변화 | 행마다 다름 | 보통 고정 | 셀마다 다름 |
| 구현 난이도 | 중 | 하 | 상 |
| 유지보수 난이도 | 중 | 하 | 상 |
| 가독성 영향 | 큼 | 중 | 작지만 정밀 |
| 남용 위험 | 높음 | 중 | 높음 |
| 실무 추천 | 행 상태 표현 | 핵심 컬럼 강조 | 예외값 표현 |

### 9.2 기술 기준 비교

| 기술 요소 | Row Color | Column Color | Cell Color |
|---|---|---|---|
| Layout 설정 필요 | `INFO_FNAME` | 보통 불필요 | `CTAB_FNAME` |
| Field Catalog 설정 | 일반적으로 필수 아님 | `EMPHASIZE` | 대상 필드명 일치 필요 |
| Output Table 추가 필드 | Char4 색상 필드 | 불필요 | `LVC_T_SCOL` Deep Component |
| Deep Structure 필요 | 아니오 | 아니오 | 예 |
| 조건별 동적 처리 | 가능 | 제한적 | 가능 |

## 10. 중복 적용 시 판단 기준

실무에서는 Row Color, Column Color, Cell Color가 동시에 요구될 수 있다.  
예를 들어 다음 요구사항을 보자.

```text
오류 상태인 주문 행은 빨간색으로 표시한다.
금액 컬럼은 항상 강조한다.
금액 차이가 음수인 셀은 별도로 강조한다.
```

이 경우 세 방식이 모두 등장한다.

| 요구사항 | 적용 방식 |
|---|---|
| 오류 상태인 주문 행 | Row Color |
| 금액 컬럼 항상 강조 | Column Color |
| 금액 차이 음수 셀 | Cell Color |

하지만 색이 겹치면 사용자가 어떤 의미인지 혼란스러울 수 있다.

### 10.1 권장 우선순위

일반적으로 실무 설계 관점에서는 다음 우선순위를 권장한다.

```text
1. Cell Color: 가장 구체적인 예외
2. Row Color: 행 전체 상태
3. Column Color: 기본 컬럼 강조
```

이 우선순위는 “화면상 실제 렌더링 우선순위”라기보다 “업무 설계 우선순위”이다.  
실제 표시 결과는 SAP GUI 테마, ALV 속성, 중복 설정 방식에 따라 다르게 보일 수 있으므로 반드시 화면에서 검증한다.

### 10.2 중복 적용 회피 원칙

다음 원칙을 적용하면 혼란이 줄어든다.

| 원칙 | 설명 |
|---|---|
| 한 색상에는 한 의미만 부여 | 빨간색이 오류인지 마감인지 혼동되면 안 됨 |
| 행 색상과 셀 색상 의미를 분리 | 행은 상태, 셀은 값 예외처럼 구분 |
| 컬럼 색상은 약하게 사용 | 핵심 컬럼 안내 정도로만 사용 |
| 색상 설명을 제공 | 범례 또는 문서화 필요 |
| Variant와 함께 검증 | 사용자별 Layout 변경 후에도 의미가 유지되는지 확인 |

## 11. 실습 시나리오

### 11.1 업무 요구사항

항공편 좌석 현황 ALV를 만든다고 가정한다.  
출력 필드는 다음과 같다.

| 필드 | 의미 |
|---|---|
| CARRID | 항공사 |
| CONNID | 연결 번호 |
| FLDATE | 비행일 |
| SEATSMAX | 최대 좌석 |
| SEATSOCC | 예약 좌석 |
| OCC_RATE | 점유율 |
| STATUS | 상태 |

업무 규칙은 다음과 같다.

```text
1. 예약 좌석이 최대 좌석 이상이면 행 전체를 오류 색상으로 표시한다.
2. 점유율 컬럼은 항상 강조한다.
3. 점유율이 90% 이상인 셀은 별도 색상으로 표시한다.
```

### 11.2 선택 방식

| 규칙 | 선택 방식 | 이유 |
|---|---|---|
| 예약 좌석이 최대 좌석 이상 | Row Color | 행 전체가 주의 대상 |
| 점유율 컬럼 항상 강조 | Column Color | 컬럼 자체가 핵심 분석 지표 |
| 점유율 90% 이상 | Cell Color | 특정 셀 값의 예외 상황 |

## 12. 예제 코드 구조

아래 코드는 전체 프로그램을 완성하기 위한 뼈대이다.  
실제 시스템의 데이터 존재 여부와 ALV Container 구성 방식에 따라 조정이 필요하다.

### 12.1 출력 타입 정의

```abap
TYPES: BEGIN OF ty_output,
         carrid     TYPE sflight-carrid,
         connid     TYPE sflight-connid,
         fldate     TYPE sflight-fldate,
         seatsmax   TYPE sflight-seatsmax,
         seatsocc   TYPE sflight-seatsocc,
         occ_rate   TYPE p LENGTH 5 DECIMALS 2,
         status     TYPE c LENGTH 1,
         row_color  TYPE c LENGTH 4,
         cell_color TYPE lvc_t_scol,
       END OF ty_output.

DATA gt_output TYPE STANDARD TABLE OF ty_output.
DATA gs_layout TYPE lvc_s_layo.
DATA gt_fcat   TYPE lvc_t_fcat.
```

### 12.2 Layout 설정

```abap
gs_layout-zebra      = abap_true.
gs_layout-cwidth_opt = abap_true.
gs_layout-info_fname = 'ROW_COLOR'.
gs_layout-ctab_fname = 'CELL_COLOR'.
```

여기서 핵심은 다음 두 줄이다.

```abap
gs_layout-info_fname = 'ROW_COLOR'.
gs_layout-ctab_fname = 'CELL_COLOR'.
```

`INFO_FNAME`은 Row Color용 필드명을 지정한다.  
`CTAB_FNAME`은 Cell Color용 Deep Component명을 지정한다.

### 12.3 Column Color 설정

Field Catalog에서 `OCC_RATE` 컬럼을 강조한다.

```abap
DATA gs_fcat TYPE lvc_s_fcat.

CLEAR gs_fcat.
gs_fcat-fieldname = 'OCC_RATE'.
gs_fcat-coltext   = '점유율'.
gs_fcat-outputlen = 10.
gs_fcat-emphasize = 'C510'.
APPEND gs_fcat TO gt_fcat.
```

실무에서는 전체 Field Catalog를 구성한 뒤 특정 컬럼만 찾아 `EMPHASIZE`를 부여하는 방식도 자주 사용한다.

```abap
LOOP AT gt_fcat ASSIGNING FIELD-SYMBOL(<ls_fcat>).
  IF <ls_fcat>-fieldname = 'OCC_RATE'.
    <ls_fcat>-emphasize = 'C510'.
  ENDIF.
ENDLOOP.
```

### 12.4 Row Color와 Cell Color 채우기

```abap
DATA ls_scol TYPE lvc_s_scol.

LOOP AT gt_output ASSIGNING FIELD-SYMBOL(<ls_output>).

  " Row Color: 행 전체 상태
  IF <ls_output>-seatsocc >= <ls_output>-seatsmax.
    <ls_output>-status    = 'E'.
    <ls_output>-row_color = 'C610'.
  ELSEIF <ls_output>-occ_rate >= 90.
    <ls_output>-status    = 'W'.
    <ls_output>-row_color = 'C310'.
  ELSE.
    <ls_output>-status = 'N'.
    CLEAR <ls_output>-row_color.
  ENDIF.

  " Cell Color: 특정 셀 예외
  IF <ls_output>-occ_rate >= 90.
    CLEAR ls_scol.
    ls_scol-fname     = 'OCC_RATE'.
    ls_scol-color-col = 6.
    ls_scol-color-int = 1.
    ls_scol-color-inv = 0.
    APPEND ls_scol TO <ls_output>-cell_color.
  ENDIF.

ENDLOOP.
```

이 예제는 Row Color와 Cell Color를 함께 사용한다.  
다만 같은 의미를 두 번 반복해서 표현하면 화면이 복잡해질 수 있으므로, 실무에서는 둘 중 하나만 선택하는 것도 검토한다.

## 13. 실제 선택 의사결정 예시

### 13.1 예시 1: 결재 상태 리포트

요구사항:

```text
반려된 결재 문서는 행 전체를 빨간색으로 표시한다.
승인 대기 문서는 노란색으로 표시한다.
```

권장 방식:

```text
Row Color
```

이유:

결재 문서 한 건 전체가 상태를 가진다.  
특정 셀만 문제가 아니라 문서 행 전체가 업무상 주의 대상이다.

### 13.2 예시 2: 재고 부족 리포트

요구사항:

```text
현재고 컬럼과 안전재고 컬럼을 눈에 잘 보이게 한다.
부족 수량이 0보다 작은 셀은 빨간색으로 표시한다.
```

권장 방식:

```text
Column Color + Cell Color
```

이유:

현재고와 안전재고는 컬럼 역할상 중요하므로 Column Color가 적합하다.  
부족 수량의 특정 값이 예외이므로 Cell Color가 적합하다.

### 13.3 예시 3: 매출 실적 리포트

요구사항:

```text
목표 달성률이 100% 미만인 영업사원을 강조한다.
달성률 셀만 색상으로 표시한다.
```

권장 방식:

```text
Cell Color
```

이유:

영업사원 행 전체를 문제로 볼 수도 있지만, 사용자가 보고 싶은 핵심은 달성률 값이다.  
따라서 해당 셀만 강조하는 편이 더 정밀하다.

### 13.4 예시 4: 마감 처리 상태 리포트

요구사항:

```text
마감 완료 행은 회색 느낌으로 표시한다.
오류 행은 빨간색으로 표시한다.
```

권장 방식:

```text
Row Color
```

이유:

마감 완료와 오류는 행 전체 상태이다.  
행 전체 색상이 사용자의 업무 처리 대상을 빠르게 구분하게 한다.

## 14. 오류 상황과 점검 포인트

### 14.1 Row Color가 적용되지 않음

| 점검 항목 | 설명 |
|---|---|
| `INFO_FNAME` 값 | Layout에 지정한 필드명이 Output Table 필드명과 정확히 일치하는지 확인 |
| 색상 필드 타입 | 보통 `C LENGTH 4` 형태인지 확인 |
| 색상 코드 값 | `C610` 같은 유효한 형식인지 확인 |
| ALV Refresh | 데이터 변경 후 Refresh가 필요한지 확인 |
| 필드명 대소문자 | ABAP 필드명 기준으로 정확히 입력했는지 확인 |

### 14.2 Column Color가 적용되지 않음

| 점검 항목 | 설명 |
|---|---|
| Field Catalog 대상 | 해당 필드의 `FIELDNAME`이 정확한지 확인 |
| `EMPHASIZE` 설정 | 강조 값이 실제 Field Catalog에 반영되었는지 확인 |
| Field Catalog 재생성 | 설정 후 다시 덮어쓰는 로직이 없는지 확인 |
| Variant 영향 | 사용자 Variant가 컬럼을 숨기거나 순서를 바꾸는지 확인 |

### 14.3 Cell Color가 적용되지 않음

| 점검 항목 | 설명 |
|---|---|
| `CTAB_FNAME` 값 | Layout에 지정한 Deep Component명이 정확한지 확인 |
| Deep Component 타입 | `LVC_T_SCOL` 타입인지 확인 |
| `FNAME` 값 | 색상을 적용할 컬럼명이 정확한지 확인 |
| 데이터별 Cell Table | 각 행의 `CELL_COLOR`에 값이 들어갔는지 디버깅 |
| 대상 필드 표시 여부 | 컬럼이 Field Catalog에서 숨김 처리되지 않았는지 확인 |

### 14.4 색상이 너무 많아 가독성이 낮음

| 원인 | 해결 |
|---|---|
| 모든 행에 색상 적용 | 예외 행에만 적용 |
| 모든 컬럼 강조 | 핵심 컬럼 1~3개만 강조 |
| Row/Cell/Column 색상 중복 | 우선순위와 의미를 정리 |
| 색상 의미 불명확 | 범례 또는 문서화 추가 |
| 사용자 Variant와 충돌 | Variant별 화면 검증 |

## 15. 유지보수 가능한 설계 방식

### 15.1 색상 결정 로직을 분리한다

색상 결정 로직을 ALV 출력 직전에 여기저기 흩뿌리면 유지보수가 어렵다.  
가능하면 별도 FORM, Method, Class로 분리한다.

예:

```abap
FORM set_display_colors
  CHANGING ct_output TYPE STANDARD TABLE.

  LOOP AT ct_output ASSIGNING FIELD-SYMBOL(<ls_output>).
    PERFORM set_row_color  CHANGING <ls_output>.
    PERFORM set_cell_color CHANGING <ls_output>.
  ENDLOOP.

ENDFORM.
```

OO 방식에서는 다음처럼 분리할 수 있다.

```abap
CLASS zcl_alv_color_policy DEFINITION.
  PUBLIC SECTION.
    METHODS apply_colors
      CHANGING ct_output TYPE STANDARD TABLE.
ENDCLASS.
```

초급 과정에서는 FORM으로 시작해도 되지만, 실무에서는 색상 정책을 별도 메서드로 분리하는 편이 좋다.

### 15.2 색상 의미를 상수화한다

색상 코드가 프로그램 곳곳에 직접 쓰이면 의미를 알기 어렵다.

나쁜 예:

```abap
<ls_output>-row_color = 'C610'.
```

개선 예:

```abap
CONSTANTS:
  gc_color_error TYPE c LENGTH 4 VALUE 'C610',
  gc_color_warn  TYPE c LENGTH 4 VALUE 'C310',
  gc_color_info  TYPE c LENGTH 4 VALUE 'C510'.

<ls_output>-row_color = gc_color_error.
```

상수명은 “무슨 색인가”보다 “무슨 의미인가”를 드러내는 편이 좋다.

| 나쁜 상수명 | 좋은 상수명 |
|---|---|
| `gc_red` | `gc_color_error` |
| `gc_yellow` | `gc_color_warning` |
| `gc_blue` | `gc_color_info` |

### 15.3 색상 의미를 문서화한다

ALV 리포트에 색상 의미가 많다면 사용자는 혼란스러울 수 있다.  
다음 중 하나로 설명을 제공하는 것이 좋다.

- 화면 상단 설명 텍스트
- 리포트 문서
- 사용자 매뉴얼
- ALV Header 영역
- Status bar 메시지
- 교육 자료 또는 운영 가이드

## 16. 성능 관점

색상 제어는 화면 표시 기능이지만, 데이터 건수가 많으면 성능에 영향을 줄 수 있다.

### 16.1 Row Color 성능

Row Color는 각 행의 Char4 필드 하나를 채우는 방식이므로 비교적 단순하다.  
대량 데이터에서도 구현 부담은 낮은 편이다.

### 16.2 Column Color 성능

Column Color는 Field Catalog 수준에서 설정되므로 가장 단순하다.  
대량 데이터여도 행마다 별도 색상 테이블을 채우지 않는다.

### 16.3 Cell Color 성능

Cell Color는 각 행마다 `LVC_T_SCOL` 내부 테이블을 가질 수 있다.  
대량 데이터에서 많은 셀에 색상을 넣으면 메모리와 처리량이 증가한다.

주의 예:

```text
10,000행 × 20컬럼 전체에 Cell Color 적용
```

이 방식은 Cell Color의 장점을 잃고, 화면 표시와 데이터 준비 모두 부담을 키울 수 있다.  
특정 예외 셀에만 사용하는 것이 좋다.

## 17. 권한과 운영 관점

ALV 색상은 권한 자체를 대체하지 않는다.

예를 들어 특정 사용자가 금액을 보면 안 되는 경우, 컬럼을 회색으로 표시하는 것만으로는 보안이 되지 않는다.  
권한이 필요한 정보는 애초에 조회하지 않거나, 필드 출력 자체를 제어해야 한다.

```text
색상 = 시각적 안내
권한 = 데이터 접근 통제
```

실무에서 민감 데이터가 있는 ALV는 다음을 함께 검토해야 한다.

| 관점 | 설명 |
|---|---|
| 조회 권한 | 사용자가 데이터를 볼 수 있는가 |
| 컬럼 숨김 | 민감 컬럼을 숨겨야 하는가 |
| 마스킹 | 일부 값만 표시해야 하는가 |
| 로그 | 누가 조회했는지 기록해야 하는가 |
| 색상 | 예외나 상태를 안내하는 보조 수단 |

## 18. 실습 과제

### 18.1 기본 실습

다음 요구사항을 만족하는 Grid ALV를 구현한다.

```text
1. SFLIGHT 또는 교육용 Internal Table 데이터를 사용한다.
2. 좌석 점유율을 계산한다.
3. 좌석이 가득 찬 항공편은 행 전체를 강조한다.
4. 점유율 컬럼은 항상 강조한다.
5. 점유율 90% 이상인 셀은 별도 색상으로 강조한다.
```

### 18.2 구현 체크리스트

| 항목 | 완료 |
|---|---|
| Output Table에 `ROW_COLOR` 필드를 추가했다. |  |
| Output Table에 `CELL_COLOR TYPE LVC_T_SCOL`을 추가했다. |  |
| Layout에 `INFO_FNAME`을 지정했다. |  |
| Layout에 `CTAB_FNAME`을 지정했다. |  |
| Field Catalog에서 핵심 컬럼에 `EMPHASIZE`를 지정했다. |  |
| Row Color 조건이 업무 규칙과 맞다. |  |
| Cell Color 조건이 업무 규칙과 맞다. |  |
| 색상 과다 사용 여부를 검토했다. |  |
| 사용자 Variant 적용 후에도 화면을 확인했다. |  |

### 18.3 오류 케이스 기록

실습 중 반드시 오류 케이스 하나를 기록한다.

예:

| 오류 | 원인 | 해결 |
|---|---|---|
| Cell Color가 표시되지 않음 | `CTAB_FNAME`에 잘못된 필드명 입력 | Layout의 필드명을 `CELL_COLOR`로 수정 |
| Row Color가 표시되지 않음 | `ROW_COLOR` 필드 타입이 부적절 | `TYPE C LENGTH 4`로 수정 |
| Column Color가 사라짐 | Field Catalog 재생성 시 `EMPHASIZE` 초기화 | Field Catalog 생성 후 마지막 단계에서 강조 설정 |

## 19. 강사용 설명 포인트

강의에서는 다음 순서로 설명하면 학습자가 혼동을 줄일 수 있다.

```text
1. 먼저 업무 요구사항을 보여준다.
2. 강조 대상이 행인지, 컬럼인지, 셀인지 묻는다.
3. Row/Column/Cell Color의 선택 기준을 표로 정리한다.
4. 가장 단순한 Column Color부터 보여준다.
5. Row Color를 추가한다.
6. 마지막으로 Cell Color를 추가한다.
7. 중복 적용 시 화면이 복잡해지는 문제를 토론한다.
```

초급자에게 바로 `LVC_T_SCOL` 구조부터 설명하면 어렵게 느껴질 수 있다.  
따라서 “왜 셀 단위 제어가 필요한가?”를 먼저 설명한 뒤 Deep Structure를 연결하는 것이 좋다.

### 20.1 객관식

#### Q1. 행 전체가 오류 상태임을 표시할 때 가장 적합한 방식은?

A. `CTAB_FNAME`

### 20.2 단답형

#### Q1. Row Color와 Cell Color의 차이를 설명하시오.

모범 답안:  
Row Color는 한 행 전체의 상태를 표현할 때 사용하고, Cell Color는 특정 행의 특정 컬럼 값만 예외적으로 강조할 때 사용한다.

#### Q2. Column Color가 적합한 업무 요구사항 예를 하나 쓰시오.

모범 답안:  
금액 차이 컬럼, 점유율 컬럼, 위험 점수 컬럼처럼 리포트 분석에서 항상 중요한 컬럼을 강조할 때 적합하다.

#### Q3. Cell Color를 대량으로 남용하면 어떤 문제가 생길 수 있는가?

모범 답안:  
각 행마다 색상 테이블을 채워야 하므로 메모리와 처리량이 증가할 수 있고, 화면 전체가 지나치게 복잡해져 사용자가 중요한 정보를 파악하기 어려워질 수 있다.

## 21. 실무 리뷰 기준

완성된 ALV 리포트는 다음 기준으로 리뷰한다.

| 리뷰 항목 | 질문 |
|---|---|
| 업무 의미 | 색상은 명확한 업무 의미를 가지는가 |
| 일관성 | 같은 색상은 같은 의미로 사용되는가 |
| 단순성 | 너무 많은 색상이 사용되지 않았는가 |
| 기술 적합성 | Row/Column/Cell 방식 선택이 적절한가 |
| 유지보수성 | 색상 결정 로직이 분리되어 있는가 |
| 성능 | 대량 데이터에서 Cell Color를 과도하게 쓰지 않는가 |
| 검증 | Variant, Refresh, Scroll 이후에도 표시가 유지되는가 |

마지막 항목은 다음 모듈인 `THEORY-19-M07 Stable Refresh와 표시 상태 보존`과 연결된다.

---

## 22. 후속 모듈 연결

이번 모듈에서는 Row, Column, Cell 단위 색상 제어 기준을 다루었다.  
다음 모듈에서는 ALV 데이터 변경 또는 Refresh 이후 사용자의 표시 상태를 어떻게 보존할지 학습한다.

연결 흐름은 다음과 같다.

```text
THEORY-19-M04 Deep Structure 기반 Cell Color
 → THEORY-19-M05 Deep Structure 기반 Cell Style
 → THEORY-19-M06 Row/Column/Cell Color 선택 기준
 → THEORY-19-M07 Stable Refresh와 표시 상태 보존
```

색상 제어가 잘 되어 있어도 Refresh 후 스크롤 위치, 선택 행, 컬럼 위치가 매번 초기화되면 사용성이 떨어진다.  
따라서 색상 정책 다음에는 Stable Refresh와 표시 상태 보존을 반드시 연결해서 이해해야 한다.

## 23. 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
Row Color는 행 전체 상태를 강조할 때 사용한다.
Column Color는 컬럼 자체의 중요도를 강조할 때 사용한다.
Cell Color는 특정 셀의 예외값을 강조할 때 사용한다.
INFO_FNAME은 Row Color용 필드명을 지정한다.
EMPHASIZE는 Field Catalog에서 컬럼 강조를 지정한다.
CTAB_FNAME은 Cell Color용 Deep Component명을 지정한다.
색상은 장식이 아니라 업무 판단을 돕는 UI 신호이다.
색상 과다 사용은 가독성과 유지보수성을 떨어뜨린다.
```
