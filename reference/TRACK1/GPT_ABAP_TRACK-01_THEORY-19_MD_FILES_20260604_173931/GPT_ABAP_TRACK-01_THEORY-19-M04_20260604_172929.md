## 0. 이 문서의 학습 범위

이 문서는 `THEORY-19-M04 — Deep Structure 기반 Cell Color`만 다룬다.

이번 모듈의 핵심은 **Grid ALV에서 특정 Cell 단위로 색상을 제어하는 방법**이다.  
초급·중급 단계에서 ALV 색상 제어를 배울 때 가장 많이 혼동하는 부분은 다음 세 가지이다.

```text
Row Color  = 행 전체 색상
Column Color = 열 전체 색상
Cell Color = 특정 행의 특정 컬럼 색상
```

이번 모듈은 이 중 **Cell Color**만 집중한다.  
특히 Grid ALV의 `LVC_S_LAYO-CTAB_FNAME`과 출력 Internal Table의 Deep Component인 `LVC_T_SCOL`을 연결하는 구조를 학습한다.

---

## 1. 선수 지식

이 모듈은 `THEORY-19` 중간 단계에 해당한다. 학습자는 다음 내용을 이미 알고 있어야 한다.

| 선수 지식 | 필요한 이유 |
|---|---|
| Internal Table | 출력 데이터와 Cell Color 정보를 같은 Row 단위로 보관하기 위해 필요하다. |
| Structure / Deep Structure | 출력 구조 안에 색상 테이블 필드인 `LVC_T_SCOL`을 포함하기 위해 필요하다. |
| Grid ALV 기본 출력 | `CL_GUI_ALV_GRID`와 `SET_TABLE_FOR_FIRST_DISPLAY` 흐름을 알아야 한다. |
| Field Catalog | ALV 컬럼 속성을 제어하는 기본 구조를 이해해야 한다. |
| Layout | `LVC_S_LAYO`의 역할을 알아야 `CTAB_FNAME`을 이해할 수 있다. |
| Refresh | 색상 변경 후 화면 반영 시점과 표시 상태 보존을 이해하기 위해 필요하다. |

이번 모듈은 SALV가 아니라 **Classic Grid ALV** 기준으로 설명한다.  
SALV는 단순 조회용 구현에는 편리하지만, Cell 단위 색상 제어와 같은 세밀한 표시 제어에서는 Grid ALV의 Field Catalog, Layout, Deep Structure 패턴을 이해하는 것이 중요하다.

---

## 2. Cell Color가 필요한 이유

ALV는 단순히 데이터를 표 형태로 출력하는 도구가 아니다.  
실무에서는 데이터의 상태, 위험도, 승인 여부, 오류 여부를 시각적으로 강조해야 하는 경우가 많다.

예를 들어 다음과 같은 요구사항이 있을 수 있다.

| 업무 요구사항 | Cell Color 적용 예 |
|---|---|
| 금액이 기준치를 초과하면 금액 Cell만 빨간색 표시 | `AMOUNT` 컬럼의 특정 행만 강조 |
| 상태가 오류이면 상태 Cell만 빨간색 표시 | `STATUS` 컬럼만 강조 |
| 납기 지연이면 납기일 Cell만 노란색 표시 | `DELIV_DATE` 컬럼만 강조 |
| 처리 완료이면 결과 Cell만 초록색 표시 | `RESULT` 컬럼만 강조 |
| 여러 조건에 따라 서로 다른 컬럼을 다르게 강조 | 한 Row 안에서도 컬럼별 색상 분리 |

행 전체 색상으로 처리하면 사용자가 “어떤 값 때문에 강조되었는지” 바로 알기 어렵다.  
Cell Color는 정확히 문제가 되는 값 또는 주목해야 할 값만 강조할 수 있다는 장점이 있다.

## 3. Grid ALV Cell Color의 핵심 구조

Grid ALV에서 Cell Color를 사용하려면 다음 세 가지가 연결되어야 한다.

```text
1. 출력 Internal Table의 Row 구조 안에 색상 정보 필드가 있어야 한다.
2. 그 색상 정보 필드는 LVC_T_SCOL 타입이어야 한다.
3. Layout의 CTAB_FNAME에 색상 정보 필드명을 지정해야 한다.
```

구조적으로 표현하면 다음과 같다.

```text
GT_OUTTAB
 ├─ CARRID
 ├─ CONNID
 ├─ PRICE
 ├─ CURRENCY
 ├─ STATUS
 └─ CELL_COLOR   TYPE LVC_T_SCOL
          ├─ FNAME = 'PRICE'
          └─ COLOR = 색상 구조
```

`CELL_COLOR`는 화면에 표시할 일반 컬럼이 아니라, ALV Grid에게 “이 행의 어떤 컬럼을 어떤 색으로 칠할지” 알려주는 제어용 내부 테이블이다.

---

## 4. 핵심 타입: LVC_T_SCOL과 LVC_S_SCOL

Cell Color를 이해하려면 두 타입을 알아야 한다.

| 타입 | 의미 |
|---|---|
| `LVC_S_SCOL` | Cell 색상 한 건을 담는 Structure |
| `LVC_T_SCOL` | `LVC_S_SCOL`의 Internal Table 타입 |

즉, 한 Row에 여러 Cell 색상을 지정하려면 `LVC_T_SCOL`이 필요하다.

예를 들어 한 행에서 `PRICE`, `STATUS` 두 Cell을 각각 강조하려면 다음처럼 색상 정보가 두 건 들어간다.

```text
CELL_COLOR[1] → FNAME = 'PRICE'
CELL_COLOR[2] → FNAME = 'STATUS'
```

---

## 5. LVC_S_SCOL의 주요 구성

`LVC_S_SCOL`에서 초급자가 반드시 이해해야 할 필드는 다음이다.

| 필드 | 의미 |
|---|---|
| `FNAME` | 색상을 적용할 ALV 컬럼명 |
| `COLOR-COL` | 색상 번호 |
| `COLOR-INT` | 강조 여부 |
| `COLOR-INV` | 반전 표시 여부 |
| `NOKEYCOL` | Key 컬럼 색상 처리 관련 보조 설정 |

실무에서 가장 많이 사용하는 조합은 다음이다.

```abap
ls_scol-fname     = 'PRICE'.
ls_scol-color-col = 6.
ls_scol-color-int = 1.
ls_scol-color-inv = 0.
APPEND ls_scol TO ls_out-cell_color.
```

여기서 중요한 것은 `FNAME`에 지정하는 값이 **출력 Internal Table의 필드명 및 Field Catalog의 FIELDNAME과 일치해야 한다**는 점이다.

---

## 6. 색상 번호의 기본 감각

Grid ALV의 색상 번호는 시스템 테마, GUI 설정, 프론트엔드 환경에 따라 보이는 느낌이 달라질 수 있다.  
그래도 교육용으로는 일반적으로 다음과 같은 감각으로 설명할 수 있다.

| `COLOR-COL` | 일반적 의미 |
|---:|---|
| 1 | 회색 계열 또는 기본 강조 |
| 2 | 파란색 계열 |
| 3 | 노란색 계열 |
| 4 | 파란/청록 계열 |
| 5 | 초록색 계열 |
| 6 | 빨간색 계열 |
| 7 | 주황/갈색 계열 |

> [추정] 정확한 색상 표현은 SAP GUI 테마와 사용자 환경에 따라 다르게 보일 수 있다. 따라서 교육에서는 숫자 자체보다 “상태별 색상 정책을 일관되게 설계하는 것”이 더 중요하다.

실무에서는 다음처럼 정책화하는 것이 좋다.

| 상태 | 권장 색상 정책 |
|---|---|
| 정상 | 기본색 또는 초록 계열 |
| 경고 | 노란색 또는 주황 계열 |
| 오류 | 빨간색 계열 |
| 선택/강조 | 파란색 계열 |
| 비활성 | 회색 계열 |

## 7. Layout의 CTAB_FNAME

Cell Color를 실제 ALV에 반영하려면 `LVC_S_LAYO-CTAB_FNAME`에 출력 구조 안의 색상 필드명을 넣어야 한다.

예:

```abap
gs_layout-ctab_fname = 'CELL_COLOR'.
```

이 설정은 ALV Grid에게 다음을 알려준다.

```text
각 Row의 CELL_COLOR 필드 안에 Cell 색상 정보가 들어 있다.
그 정보를 읽어서 Cell 단위 색상을 적용하라.
```

`CTAB_FNAME`을 설정하지 않으면 출력 Internal Table 안에 `LVC_T_SCOL` 필드를 넣고 데이터를 채워도 화면에 색상이 나타나지 않는다.

초급자가 자주 하는 실수:

```text
LVC_T_SCOL 필드는 만들었지만 CTAB_FNAME을 설정하지 않음
```

결과:

```text
프로그램은 오류 없이 실행될 수 있지만 색상이 표시되지 않는다.
```

---

## 8. 출력 Structure 설계

Cell Color를 사용하려면 출력 Structure에 Deep Component를 포함해야 한다.

예:

```abap
TYPES: BEGIN OF ty_out,
         carrid     TYPE sflight-carrid,
         connid     TYPE sflight-connid,
         fldate     TYPE sflight-fldate,
         price      TYPE sflight-price,
         currency   TYPE sflight-currency,
         status     TYPE char1,
         cell_color TYPE lvc_t_scol,
       END OF ty_out.
```

여기서 `CELL_COLOR`는 화면에 일반 컬럼으로 보여주기 위한 필드가 아니다.  
ALV 제어용 필드이다.

따라서 Field Catalog에서 `CELL_COLOR`가 일반 컬럼으로 나오지 않도록 주의해야 한다.  
일반적으로 Field Catalog를 명시적으로 구성하면서 출력 대상 컬럼만 넣거나, 자동 생성 후 불필요한 Deep Component가 표시되지 않도록 점검한다.

---

## 9. 최소 구현 흐름

Deep Structure 기반 Cell Color의 최소 구현 흐름은 다음과 같다.

```text
1. 출력용 Structure에 CELL_COLOR TYPE LVC_T_SCOL 필드 추가
2. 출력 데이터 Internal Table 생성
3. 각 Row 조건에 따라 LVC_S_SCOL 생성
4. FNAME에 색상을 적용할 컬럼명 입력
5. COLOR-COL / INT / INV 설정
6. Row의 CELL_COLOR Internal Table에 APPEND
7. Layout-CTAB_FNAME = 'CELL_COLOR' 설정
8. SET_TABLE_FOR_FIRST_DISPLAY 호출
```

이 중 하나라도 빠지면 색상이 표시되지 않거나 기대와 다르게 동작할 수 있다.

## 11. 예제 코드: 출력 타입과 전역 데이터

아래 예제는 Cell Color 구조를 이해하기 위한 핵심 코드 중심이다.

```abap
TYPES: BEGIN OF ty_out,
         carrid     TYPE sflight-carrid,
         connid     TYPE sflight-connid,
         fldate     TYPE sflight-fldate,
         price      TYPE sflight-price,
         currency   TYPE sflight-currency,
         status     TYPE char1,
         cell_color TYPE lvc_t_scol,
       END OF ty_out.

DATA: gt_outtab TYPE STANDARD TABLE OF ty_out,
      gs_layout TYPE lvc_s_layo,
      gt_fcat   TYPE lvc_t_fcat.

DATA: go_container TYPE REF TO cl_gui_custom_container,
      go_grid      TYPE REF TO cl_gui_alv_grid.
```

핵심은 `TY_OUT` 안에 `CELL_COLOR TYPE LVC_T_SCOL`이 포함되어 있다는 점이다.

이 구조는 Deep Structure이다.  
왜냐하면 Structure 안에 다시 Internal Table 타입 필드가 포함되어 있기 때문이다.

## 12. 예제 코드: 데이터 조회와 상태값 구성

```abap
FORM get_data.

  SELECT carrid,
         connid,
         fldate,
         price,
         currency
    FROM sflight
    INTO CORRESPONDING FIELDS OF TABLE @gt_outtab
    UP TO 50 ROWS.

  LOOP AT gt_outtab ASSIGNING FIELD-SYMBOL(<ls_out>).

    IF <ls_out>-price > 1000.
      <ls_out>-status = 'E'.
    ELSEIF <ls_out>-price > 500.
      <ls_out>-status = 'W'.
    ELSE.
      <ls_out>-status = 'S'.
    ENDIF.

  ENDLOOP.

ENDFORM.
```

이 예제에서 `STATUS`는 교육용으로 계산한 상태값이다.

| 조건 | STATUS |
|---|---|
| PRICE > 1000 | E |
| PRICE > 500 | W |
| 그 외 | S |

실무에서는 DB 값, 검증 결과, 업무 상태, 메시지 상태 등을 기준으로 색상 정책을 적용할 수 있다.

## 13. 예제 코드: Cell Color 설정

색상 제어 로직은 별도 FORM 또는 Method로 분리하는 것이 좋다.

```abap
FORM set_cell_color.

  DATA ls_scol TYPE lvc_s_scol.

  LOOP AT gt_outtab ASSIGNING FIELD-SYMBOL(<ls_out>).

    CLEAR <ls_out>-cell_color.

    IF <ls_out>-price > 1000.
      CLEAR ls_scol.
      ls_scol-fname     = 'PRICE'.
      ls_scol-color-col = 6.
      ls_scol-color-int = 1.
      ls_scol-color-inv = 0.
      APPEND ls_scol TO <ls_out>-cell_color.
    ENDIF.

    CASE <ls_out>-status.
      WHEN 'E'.
        CLEAR ls_scol.
        ls_scol-fname     = 'STATUS'.
        ls_scol-color-col = 6.
        ls_scol-color-int = 1.
        ls_scol-color-inv = 0.
        APPEND ls_scol TO <ls_out>-cell_color.

      WHEN 'W'.
        CLEAR ls_scol.
        ls_scol-fname     = 'STATUS'.
        ls_scol-color-col = 3.
        ls_scol-color-int = 1.
        ls_scol-color-inv = 0.
        APPEND ls_scol TO <ls_out>-cell_color.

      WHEN 'S'.
        CLEAR ls_scol.
        ls_scol-fname     = 'STATUS'.
        ls_scol-color-col = 5.
        ls_scol-color-int = 1.
        ls_scol-color-inv = 0.
        APPEND ls_scol TO <ls_out>-cell_color.
    ENDCASE.

  ENDLOOP.

ENDFORM.
```

이 로직에서 중요한 포인트는 다음이다.

| 코드 | 의미 |
|---|---|
| `CLEAR <ls_out>-cell_color` | Row별 기존 색상 정보를 초기화 |
| `ls_scol-fname = 'PRICE'` | PRICE Cell에 색상 적용 |
| `ls_scol-color-col = 6` | 빨간색 계열 적용 |
| `APPEND ls_scol TO <ls_out>-cell_color` | 해당 Row의 Cell Color 테이블에 색상 정보 추가 |

## 14. 예제 코드: Layout 설정

Cell Color를 ALV에 반영하려면 Layout 설정이 반드시 필요하다.

```abap
FORM set_layout.

  CLEAR gs_layout.

  gs_layout-zebra      = abap_true.
  gs_layout-cwidth_opt = abap_true.
  gs_layout-ctab_fname = 'CELL_COLOR'.

ENDFORM.
```

여기서 가장 중요한 줄은 다음이다.

```abap
gs_layout-ctab_fname = 'CELL_COLOR'.
```

`CELL_COLOR`는 출력 Structure의 필드명과 정확히 일치해야 한다.

실무에서는 필드명을 상수로 정의해 오타 위험을 줄이는 것이 좋다.

```abap
CONSTANTS gc_ctab_fname TYPE lvc_fname VALUE 'CELL_COLOR'.

gs_layout-ctab_fname = gc_ctab_fname.
```

## 15. 예제 코드: Field Catalog 구성

Field Catalog는 출력 대상 컬럼만 명시적으로 구성하는 편이 초급 실습에서는 안전하다.

```abap
FORM build_fieldcatalog.

  DATA ls_fcat TYPE lvc_s_fcat.

  CLEAR gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'CARRID'.
  ls_fcat-coltext   = '항공사'.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'CONNID'.
  ls_fcat-coltext   = '연결번호'.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'FLDATE'.
  ls_fcat-coltext   = '비행일자'.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'PRICE'.
  ls_fcat-coltext   = '가격'.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'CURRENCY'.
  ls_fcat-coltext   = '통화'.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'STATUS'.
  ls_fcat-coltext   = '상태'.
  APPEND ls_fcat TO gt_fcat.

ENDFORM.
```

`CELL_COLOR`는 출력 컬럼으로 넣지 않는다.  
이 필드는 ALV 내부 제어용 필드이기 때문이다.

## 18. 정상 동작 확인 기준

Cell Color가 정상 적용되었는지 확인하려면 다음을 점검한다.

| 확인 항목 | 기대 결과 |
|---|---|
| PRICE > 1000 | PRICE Cell이 빨간색 계열로 표시 |
| STATUS = E | STATUS Cell이 빨간색 계열로 표시 |
| STATUS = W | STATUS Cell이 노란색 계열로 표시 |
| STATUS = S | STATUS Cell이 초록색 계열로 표시 |
| 다른 Cell | 기본 색상 유지 |
| Row 전체 | 색상이 불필요하게 전체 행에 번지지 않음 |

Cell Color는 “특정 Cell만 강조”되어야 한다.  
만약 행 전체가 색상으로 보인다면 Row Color 설정과 혼동했을 가능성이 있다.

## 19. 자주 발생하는 오류와 원인

### 19.1 색상이 전혀 표시되지 않음

가능한 원인:

| 원인 | 설명 |
|---|---|
| `CTAB_FNAME` 누락 | Layout에 색상 필드명을 지정하지 않음 |
| 필드명 오타 | `CELL_COLOR`와 `CTAB_FNAME` 값이 다름 |
| `LVC_T_SCOL` 필드 없음 | 출력 Structure에 색상 테이블이 없음 |
| 색상 데이터 미생성 | `CELL_COLOR`에 아무 항목도 Append하지 않음 |
| Refresh 누락 | 데이터 변경 후 화면 갱신을 하지 않음 |

점검 순서:

```text
1. 출력 Structure에 CELL_COLOR TYPE LVC_T_SCOL이 있는가?
2. GS_LAYOUT-CTAB_FNAME = 'CELL_COLOR'가 설정되었는가?
3. CELL_COLOR 내부에 LVC_S_SCOL 데이터가 들어갔는가?
4. FNAME 값이 실제 컬럼명과 일치하는가?
5. SET_TABLE_FOR_FIRST_DISPLAY 또는 REFRESH가 정상 호출되었는가?
```

### 19.2 특정 컬럼만 색상이 안 나옴

가능한 원인:

```text
FNAME에 지정한 컬럼명이 Field Catalog의 FIELDNAME과 일치하지 않음
```

예:

```abap
ls_scol-fname = 'AMOUNT'.  " 실제 컬럼은 PRICE
```

해결:

```abap
ls_scol-fname = 'PRICE'.
```

### 19.3 색상이 이전 상태로 남아 있음

가능한 원인:

```text
Row별 CELL_COLOR를 CLEAR하지 않고 계속 APPEND만 수행
```

해결:

```abap
CLEAR <ls_out>-cell_color.
```

조건 재계산 전에 기존 색상 정보를 초기화해야 한다.

### 19.4 CELL_COLOR 컬럼이 화면에 보임

가능한 원인:

```text
Field Catalog 자동 생성 과정에서 Deep Component 처리 방식이 기대와 다름
```

해결:

- Field Catalog를 명시적으로 구성한다.
- 출력 대상 컬럼만 Field Catalog에 추가한다.
- `CELL_COLOR`는 일반 출력 컬럼으로 넣지 않는다.

### 19.5 색상이 너무 강하거나 알아보기 어려움

가능한 원인:

```text
COLOR-INT 또는 COLOR-INV 설정이 과도함
```

해결:

테마와 사용자 환경을 고려해 색상 정책을 조정한다.  
교육용에서는 `COLOR-INT = 1`, `COLOR-INV = 0`을 기준으로 시작하고, 필요할 때 비교 실습을 한다.

## 20. 실무 설계 기준

### 20.1 색상은 의미가 있어야 한다

ALV 색상은 예쁘게 보이기 위한 장식이 아니다.  
사용자가 빠르게 판단할 수 있도록 하는 업무 신호이다.

좋은 예:

| 색상 | 의미 |
|---|---|
| 빨간색 | 오류, 중단, 초과, 실패 |
| 노란색 | 경고, 확인 필요 |
| 초록색 | 정상, 완료, 성공 |
| 파란색 | 선택, 정보, 참조 |

나쁜 예:

```text
개발자가 보기 좋다고 임의로 여러 색상을 섞음
상태 의미 없이 컬럼마다 색상을 다르게 지정
오류와 성공에 같은 색상 사용
사용자 교육 없이 색상 의미만으로 판단하게 함
```

### 20.2 색상 정책은 문서화해야 한다

실무 ALV에서는 색상 의미를 프로그램 주석, 설계서, 사용자 가이드에 남기는 것이 좋다.

예:

```text
빨간색: 처리 불가 오류
노란색: 사용자 확인 필요
초록색: 처리 완료
```

### 20.3 색상만으로 상태를 전달하지 않는다

접근성과 운영 안정성을 위해 색상만으로 모든 의미를 전달하면 안 된다.  
상태 컬럼, 메시지 컬럼, 아이콘 컬럼 등을 함께 제공하는 것이 좋다.

예:

| STATUS | MESSAGE | 색상 |
|---|---|---|
| E | 금액이 한도를 초과했습니다. | 빨간색 |
| W | 납기일 확인이 필요합니다. | 노란색 |
| S | 정상 처리 가능 | 초록색 |

색상을 보지 못하는 사용자나 프린트 출력 상황에서도 의미가 전달되어야 한다.

### 20.4 대량 데이터에서는 색상 계산 비용을 고려한다

Cell Color 정보는 Row마다 Deep Component에 들어간다.  
대량 데이터에서 많은 Cell 색상을 계산하면 메모리와 처리 시간이 증가할 수 있다.

실무 기준:

```text
정말 필요한 Cell만 색상 적용
대량 전체 데이터보다 조회 조건으로 범위 제한
색상 계산 로직은 단순하게 유지
반복문 안에서 불필요한 DB 조회 금지
```

## 21. Row Color, Column Color와의 차이

이 모듈은 Cell Color에 집중하지만, 실무에서는 다른 색상 제어 방식과 비교할 수 있어야 한다.

| 방식 | 적용 범위 | 대표 설정 |
|---|---|---|
| Row Color | 행 전체 | `INFO_FNAME` |
| Column Color | 열 전체 | Field Catalog `EMPHASIZE` |
| Cell Color | 특정 행의 특정 컬럼 | `CTAB_FNAME` + `LVC_T_SCOL` |

선택 기준은 다음과 같다.

```text
행 전체 상태를 강조한다면 Row Color
특정 컬럼 자체가 중요하다면 Column Color
특정 값만 조건부로 강조한다면 Cell Color
```

이번 모듈의 핵심은 세 번째이다.

## 22. 리팩토링 관점

초급 예제에서는 FORM으로 작성했지만, 실무에서는 색상 정책을 별도 Method로 분리하는 것이 좋다.

예:

```abap
METHOD set_cell_color.
  LOOP AT mt_outtab ASSIGNING FIELD-SYMBOL(<ls_out>).
    CLEAR <ls_out>-cell_color.
    me->append_price_color( CHANGING cs_out = <ls_out> ).
    me->append_status_color( CHANGING cs_out = <ls_out> ).
  ENDLOOP.
ENDMETHOD.
```

장점:

| 장점 | 설명 |
|---|---|
| 가독성 | 색상 조건이 한 곳에 모인다. |
| 유지보수성 | 상태 정책 변경 시 수정 범위가 줄어든다. |
| 테스트 용이성 | 색상 결정 로직만 따로 확인할 수 있다. |
| 확장성 | 후속 Cell Style, Row Color와 조합하기 쉽다. |

## 24. 평가 문제

### 24.1 객관식

#### Q1. Grid ALV Cell Color를 적용하기 위해 Layout에서 사용하는 필드는?

A. `INFO_FNAME`  
B. `STYLEFNAME`  
C. `CTAB_FNAME`  
D. `EMPHASIZE`

**정답:** C

#### Q2. Cell Color 정보를 Row별로 담기 위해 출력 Structure에 포함해야 하는 타입은?

A. `LVC_T_FCAT`  
B. `LVC_T_SCOL`  
C. `LVC_S_LAYO`  
D. `SLIS_T_FIELDCAT_ALV`

**정답:** B

#### Q3. `LVC_S_SCOL-FNAME`에는 무엇을 지정해야 하는가?

A. 프로그램명  
B. 화면 번호  
C. 색상을 적용할 컬럼명  
D. 패키지명

**정답:** C

### 24.2 단답형

#### Q1. Cell Color와 Row Color의 차이를 설명하시오.

**모범 답안:**  
Row Color는 행 전체에 색상을 적용하고, Cell Color는 특정 행의 특정 컬럼에만 색상을 적용한다. Cell Color는 `LVC_T_SCOL`과 `CTAB_FNAME`을 사용하고, Row Color는 보통 `INFO_FNAME`을 사용한다.

#### Q2. `CTAB_FNAME`을 설정하지 않으면 어떤 문제가 발생하는가?

**모범 답안:**  
출력 Internal Table 안에 색상 정보가 있어도 ALV Grid가 어떤 필드에서 Cell Color 정보를 읽어야 하는지 알 수 없으므로 색상이 표시되지 않는다.

#### Q3. 색상 계산 전에 `CLEAR <ls_out>-cell_color`가 필요한 이유는 무엇인가?

**모범 답안:**  
기존 색상 정보가 남아 있으면 조건이 바뀐 뒤에도 이전 색상이 계속 표시될 수 있기 때문이다. Row별로 색상 정보를 다시 계산하기 전에 초기화해야 한다.

## 26. 핵심 요약

```text
Grid ALV의 Cell Color는 특정 행의 특정 컬럼만 조건부로 강조하는 기능이다.
출력 Structure 안에 LVC_T_SCOL 타입의 Deep Component가 필요하다.
Layout의 CTAB_FNAME에는 색상 정보 필드명을 지정한다.
LVC_S_SCOL-FNAME에는 색상을 적용할 컬럼명을 지정한다.
색상 정보는 Row별로 CELL_COLOR Internal Table에 APPEND한다.
조건 재계산 전에는 기존 Cell Color 정보를 CLEAR해야 한다.
색상은 장식이 아니라 업무 판단을 돕는 시각적 신호여야 한다.
```
