## 1. 이 문서의 목적

이 문서는 `CL_GUI_ALV_GRID` 기반 Grid ALV에서 **행 단위 데이터 내부에 Deep Structure 필드를 두고, 특정 Cell의 Style을 제어하는 방식**을 학습하기 위한 자료이다.

앞선 모듈에서는 `LVC_T_SCOL`과 `CTAB_FNAME`을 이용해 Cell Color를 제어했다.  
이번 모듈에서는 색상보다 더 행위 중심적인 제어인 **Cell Style**을 다룬다.

Cell Style은 다음과 같은 요구사항에서 사용된다.

```text
특정 조건의 셀만 편집 가능하게 한다.
특정 조건의 셀만 편집 불가능하게 한다.
특정 셀을 버튼처럼 표시한다.
특정 셀의 입력 가능 상태를 데이터 조건에 따라 다르게 제어한다.
```

Grid ALV에서 Style 제어는 단순 표시 꾸미기가 아니다.  
특히 Editable Grid, 승인/반려 처리, 예외 수정 화면, 데이터 검증 전후 상태 제어에서 실무적으로 중요하다.

이 모듈은 Section 19의 고급 ALV 표시 제어 주제이다. 다음 개념을 이미 알고 있어야 한다.

| 선수 개념 | 필요한 이유 |

| Editable Grid 기초 | Cell Style은 편집 가능/불가능 제어와 자주 함께 사용된다. |

## 4. Cell Style이란 무엇인가?

### 4.1 기본 정의

Cell Style은 Grid ALV에서 특정 셀의 표시 또는 동작 방식을 제어하는 속성이다.

Color가 “어떻게 보일 것인가”에 가깝다면, Style은 “어떻게 동작할 것인가”에 더 가깝다.

| 구분 | Cell Color | Cell Style |
|---|---|---|
| 대표 타입 | `LVC_T_SCOL` | `LVC_T_STYL` |
| Layout 연결 필드 | `CTAB_FNAME` | `STYLEFNAME` |
| 주요 목적 | 색상 표시 | 편집 가능/불가능, 버튼, 입력 제어 등 |
| 성격 | 시각적 강조 | UI 동작 제어 |
| 대표 사용처 | 상태 강조, 오류 강조, 금액 차이 표시 | 특정 셀만 수정 가능, 승인 버튼형 셀, 조건부 입력 제어 |

### 4.2 왜 Deep Structure가 필요한가?

Cell Style은 행마다, 그리고 셀마다 다를 수 있다.  
따라서 단순히 Field Catalog에 한 번 설정하는 방식으로는 부족하다.

예를 들어 다음 요구사항을 보자.

```text
STATUS = 'A'인 행은 PRICE 셀을 수정할 수 없게 한다.
STATUS = 'E'인 행은 PRICE 셀만 수정 가능하게 한다.
STATUS = 'B'인 행은 ACTION 셀을 버튼처럼 표시한다.
```

이 경우 행마다 Style 규칙이 다르다.  
그래서 출력 Internal Table의 각 행에 “이 행에서 어떤 셀에 어떤 스타일을 적용할지” 담을 수 있는 Deep 필드를 둔다.

예시 구조는 다음과 같다.

```abap
TYPES: BEGIN OF ty_alv,
         carrid     TYPE sflight-carrid,
         connid     TYPE sflight-connid,
         fldate     TYPE sflight-fldate,
         price      TYPE sflight-price,
         currency   TYPE sflight-currency,
         status     TYPE c LENGTH 1,
         cell_style TYPE lvc_t_styl,
       END OF ty_alv.
```

여기서 `CELL_STYLE`은 단순 필드가 아니라 Internal Table 타입 필드이다.  
즉, 각 출력 행이 자기 자신만의 Style Table을 가지고 있는 구조이다.

## 5. 핵심 타입과 필드

### 5.1 `LVC_T_STYL`

`LVC_T_STYL`은 Cell Style 정보를 여러 건 담는 Table Type이다.  
각 라인은 일반적으로 특정 필드명과 스타일 값을 가진다.

개념적으로는 다음과 같이 이해하면 된다.

| 구성 | 의미 |
|---|---|
| `FIELDNAME` | Style을 적용할 ALV 필드명 |
| `STYLE` | 적용할 Cell Style 값 |
| 추가 Style 필드 | 시스템/릴리스에 따라 보조 Style 값이 존재할 수 있음 |

초급자는 `FIELDNAME`과 `STYLE`의 관계를 먼저 이해하면 된다.

```text
FIELDNAME = 어느 컬럼의 셀인가?
STYLE     = 그 셀에 어떤 동작 스타일을 줄 것인가?
```

### 5.2 `LVC_S_LAYO-STYLEFNAME`

`STYLEFNAME`은 Grid ALV Layout 구조 `LVC_S_LAYO`의 필드이다.  
이 필드에는 출력 Internal Table 안에서 Cell Style 정보를 담고 있는 컴포넌트명을 지정한다.

예:

```abap
DATA gs_layout TYPE lvc_s_layo.

gs_layout-stylefname = 'CELL_STYLE'.
```

이 설정은 Grid ALV에게 다음을 알려준다.

```text
출력 Internal Table의 각 행에는 CELL_STYLE이라는 Deep 필드가 있다.
각 행을 그릴 때 CELL_STYLE 내부의 Style 정보를 읽어서 셀별 스타일을 적용하라.
```

### 5.3 `CL_GUI_ALV_GRID` Style 상수

Cell Style 값은 보통 `CL_GUI_ALV_GRID` 클래스의 상수를 사용한다.

대표적으로 다음과 같은 상수를 접하게 된다.

| 상수 예시 | 일반적 용도 |
|---|---|
| `CL_GUI_ALV_GRID=>MC_STYLE_ENABLED` | 셀 입력 가능 |
| `CL_GUI_ALV_GRID=>MC_STYLE_DISABLED` | 셀 입력 불가능 |
| `CL_GUI_ALV_GRID=>MC_STYLE_BUTTON` | 버튼 스타일 |
| `CL_GUI_ALV_GRID=>MC_STYLE_HOTSPOT` | Hotspot 성격 표시 |

> [추정] 사용 가능한 Style 상수와 동작 세부는 SAP 릴리스, GUI 패치, Grid 설정, Field Catalog 설정에 따라 체감이 달라질 수 있다. 실무에서는 시스템에서 제공되는 `CL_GUI_ALV_GRID` 상수와 SAP GUI 동작을 기준으로 확인한다.

## 6. Cell Style 적용 전체 흐름

Cell Style은 다음 순서로 적용한다.

```text
1. 출력용 Row Type에 Deep 필드 추가
2. ALV 출력 데이터 구성
3. 각 행의 조건에 따라 LVC_T_STYL 값 채우기
4. Field Catalog에서 기본 표시/편집 속성 설정
5. Layout의 STYLEFNAME에 Deep 필드명 지정
6. SET_TABLE_FOR_FIRST_DISPLAY 호출
7. 화면에서 셀별 Style 적용 확인
```

핵심은 3번과 5번이다.

```text
각 행에 Style 정보를 넣는다.
Grid Layout에 그 Style 정보가 어디 있는지 알려준다.
```

## 7. 최소 구현 예제

아래 예제는 Cell Style 적용 흐름을 설명하기 위한 최소 구조이다.  
실제 화면 컨테이너 생성, PBO/PAI, 전체 Event 처리는 앞선 Grid ALV 기본 모듈에서 다룬 내용을 전제로 한다.

### 7.1 출력 Row Type 정의

```abap
TYPES: BEGIN OF ty_alv,
         carrid     TYPE sflight-carrid,
         connid     TYPE sflight-connid,
         fldate     TYPE sflight-fldate,
         price      TYPE sflight-price,
         currency   TYPE sflight-currency,
         status     TYPE c LENGTH 1,
         cell_style TYPE lvc_t_styl,
       END OF ty_alv.

DATA gt_alv TYPE STANDARD TABLE OF ty_alv.
```

`CELL_STYLE`은 화면에 보여줄 업무 필드가 아니라 Grid ALV가 내부적으로 읽을 제어 필드이다.

---

### 7.2 테스트 데이터 구성

```abap
DATA ls_alv TYPE ty_alv.

CLEAR ls_alv.
ls_alv-carrid   = 'AA'.
ls_alv-connid   = '0017'.
ls_alv-fldate   = sy-datum.
ls_alv-price    = '100.00'.
ls_alv-currency = 'USD'.
ls_alv-status   = 'A'.
APPEND ls_alv TO gt_alv.

CLEAR ls_alv.
ls_alv-carrid   = 'LH'.
ls_alv-connid   = '0400'.
ls_alv-fldate   = sy-datum.
ls_alv-price    = '200.00'.
ls_alv-currency = 'EUR'.
ls_alv-status   = 'E'.
APPEND ls_alv TO gt_alv.
```

실무에서는 DB 조회 결과를 기반으로 `GT_ALV`를 구성하지만, 학습 단계에서는 테스트 데이터를 직접 구성해도 된다.

---

### 7.3 조건별 Style 구성

```abap
FORM set_cell_style.

  FIELD-SYMBOLS <ls_alv> TYPE ty_alv.

  LOOP AT gt_alv ASSIGNING <ls_alv>.

    CLEAR <ls_alv>-cell_style.

    DATA(ls_style) = VALUE lvc_s_styl( ).

    CASE <ls_alv>-status.

      WHEN 'A'.
        "정상 상태: PRICE 수정 불가
        ls_style-fieldname = 'PRICE'.
        ls_style-style     = cl_gui_alv_grid=>mc_style_disabled.
        APPEND ls_style TO <ls_alv>-cell_style.

      WHEN 'E'.
        "오류 상태: PRICE 수정 가능
        ls_style-fieldname = 'PRICE'.
        ls_style-style     = cl_gui_alv_grid=>mc_style_enabled.
        APPEND ls_style TO <ls_alv>-cell_style.

      WHEN OTHERS.
        "별도 스타일 없음

    ENDCASE.

  ENDLOOP.

ENDFORM.
```

이 예제에서 중요한 점은 `FIELDNAME = 'PRICE'`이다.  
Field Catalog의 필드명과 정확히 일치해야 한다.

---

### 7.4 Layout에 `STYLEFNAME` 지정

```abap
DATA gs_layout TYPE lvc_s_layo.

gs_layout-stylefname = 'CELL_STYLE'.
```

이 설정이 누락되면 각 행에 `CELL_STYLE` 데이터를 채워도 Grid ALV가 읽지 않는다.  
즉, 화면에는 아무 효과가 나타나지 않는다.

---

### 7.5 Field Catalog의 편집 설정

Cell Style이 편집 가능/불가능 제어에 사용될 경우 Field Catalog의 기본 `EDIT` 설정도 함께 이해해야 한다.

예:

```abap
DATA gt_fcat TYPE lvc_t_fcat.
DATA ls_fcat TYPE lvc_s_fcat.

CLEAR ls_fcat.
ls_fcat-fieldname = 'PRICE'.
ls_fcat-coltext   = 'Price'.
ls_fcat-edit      = abap_true.
APPEND ls_fcat TO gt_fcat.
```

`PRICE` 컬럼이 전체적으로 편집 대상이 될 수 있어야, Cell Style로 행별 enable/disable을 제어하는 흐름이 명확해진다.

실무에서 자주 쓰는 패턴은 다음이다.

```text
Field Catalog: 해당 컬럼은 편집 가능 후보로 설정
Cell Style   : 행/셀 조건에 따라 특정 셀만 Enabled 또는 Disabled
```

---

### 7.6 Grid 호출 흐름

```abap
CALL METHOD go_grid->set_table_for_first_display
  EXPORTING
    is_layout       = gs_layout
  CHANGING
    it_outtab       = gt_alv
    it_fieldcatalog = gt_fcat.
```

이때 `GT_ALV` 안의 각 행에는 이미 `CELL_STYLE` 값이 채워져 있어야 한다.  
그리고 `GS_LAYOUT-STYLEFNAME`에는 `CELL_STYLE`이 지정되어 있어야 한다.

## 8. Cell Style과 Field Catalog의 관계

Cell Style을 제대로 이해하려면 Field Catalog와의 관계를 구분해야 한다.

| 구분 | Field Catalog | Cell Style |
|---|---|---|
| 적용 단위 | 컬럼 전체 | 특정 행의 특정 셀 |
| 설정 위치 | `LVC_T_FCAT` | 출력 Internal Table의 Deep 필드 |
| 대표 필드 | `EDIT`, `HOTSPOT`, `EMPHASIZE` 등 | `FIELDNAME`, `STYLE` |
| 동적 조건 처리 | 제한적 | 행별 조건 처리에 적합 |
| 유지보수 포인트 | 컬럼 설계 | 데이터 조건 기반 UI 제어 |

예를 들어 `PRICE` 컬럼 전체를 편집 가능하게 하려면 Field Catalog에서 `EDIT = 'X'`를 설정한다.  
그 후 특정 행의 `PRICE`만 편집 불가능하게 만들려면 Cell Style에서 `MC_STYLE_DISABLED`를 적용한다.

```text
컬럼 수준 기본값: Field Catalog
셀 수준 예외값: Cell Style
```

## 9. Style 적용 패턴

### 9.1 특정 셀만 수정 불가

```abap
ls_style-fieldname = 'PRICE'.
ls_style-style     = cl_gui_alv_grid=>mc_style_disabled.
APPEND ls_style TO <ls_alv>-cell_style.
```

사용 예:

```text
승인 완료된 행의 금액 필드 수정 불가
전표 생성 완료된 행의 수량 필드 수정 불가
마감 기간의 입력 필드 수정 불가
```

### 9.2 특정 셀만 수정 가능

```abap
ls_style-fieldname = 'PRICE'.
ls_style-style     = cl_gui_alv_grid=>mc_style_enabled.
APPEND ls_style TO <ls_alv>-cell_style.
```

사용 예:

```text
오류 상태 행만 수정 가능
검증 실패 필드만 재입력 가능
승인 대기 상태의 코멘트 필드만 입력 가능
```

### 9.3 버튼 스타일

```abap
ls_style-fieldname = 'ACTION'.
ls_style-style     = cl_gui_alv_grid=>mc_style_button.
APPEND ls_style TO <ls_alv>-cell_style.
```

사용 예:

```text
행별 상세보기 버튼
행별 승인/반려 버튼
행별 재처리 버튼
```

버튼 스타일은 일반 표시만으로 끝나지 않는다.  
실제로 버튼 클릭을 처리하려면 Grid Event 처리까지 연결해야 한다.  
이 부분은 ALV Event 심화 또는 화면 처리 모듈과 연결된다.

## 10. 실무 시나리오 예시

### 10.1 승인 상태별 입력 제어

업무 요구사항:

```text
승인 완료 행은 모든 입력 필드를 수정할 수 없다.
반려 행은 사유 필드만 수정할 수 있다.
신규 행은 금액과 수량을 수정할 수 있다.
```

설계 방식:

| 상태 | PRICE | QUANTITY | REASON |
|---|---|---|---|
| A 승인 완료 | Disabled | Disabled | Disabled |
| R 반려 | Disabled | Disabled | Enabled |
| N 신규 | Enabled | Enabled | Enabled |

이런 요구사항은 Field Catalog만으로 처리하기 어렵다.  
행마다 상태가 다르기 때문이다.  
따라서 Deep Structure 기반 Cell Style이 적합하다.

### 10.2 오류 필드만 수정 가능

검증 결과 오류가 발생한 필드만 수정 가능하게 만들 수 있다.

```text
금액 오류 → PRICE만 Enabled
통화 오류 → CURRENCY만 Enabled
일자 오류 → FLDATE만 Enabled
```

이 방식은 사용자에게 “어디를 고쳐야 하는지”를 명확히 알려준다.  
색상 제어와 함께 사용하면 더 효과적이다.

```text
Cell Color: 오류 위치를 빨간색 또는 강조색으로 표시
Cell Style: 오류 위치만 입력 가능하게 제어
```

## 11. Cell Color와 Cell Style 조합

Cell Color와 Cell Style은 함께 사용할 수 있다.  
단, 서로 다른 Deep 필드를 사용한다.

예:

```abap
TYPES: BEGIN OF ty_alv,
         carrid     TYPE sflight-carrid,
         connid     TYPE sflight-connid,
         price      TYPE sflight-price,
         status     TYPE c LENGTH 1,
         cell_color TYPE lvc_t_scol,
         cell_style TYPE lvc_t_styl,
       END OF ty_alv.
```

Layout 설정:

```abap
gs_layout-ctab_fname = 'CELL_COLOR'.
gs_layout-stylefname = 'CELL_STYLE'.
```

이 구조를 사용하면 한 셀에 대해 다음을 동시에 제어할 수 있다.

```text
색상으로 오류 강조
Style로 수정 가능 상태 제어
```

다만 실무에서는 너무 많은 표시 제어를 동시에 적용하면 화면이 복잡해진다.  
색상, 아이콘, 스타일, 메시지를 함께 설계할 때는 사용자 경험을 고려해야 한다.

## 12. 자주 발생하는 오류와 해결

### 12.1 `STYLEFNAME` 누락

#### 증상

Internal Table의 `CELL_STYLE`에 값을 채웠지만 화면에 아무 변화가 없다.

#### 원인

`GS_LAYOUT-STYLEFNAME`을 지정하지 않았다.

#### 해결

```abap
gs_layout-stylefname = 'CELL_STYLE'.
```

### 12.2 Deep 필드명 오타

#### 증상

Style이 적용되지 않는다.

#### 원인

출력 Row Type에는 `CELL_STYLE`인데 Layout에는 `CELLSTYL` 또는 `CELLSTYLE`로 입력했다.

#### 해결

Row Type 필드명과 `STYLEFNAME` 값을 정확히 일치시킨다.

```text
Row Type 필드명: CELL_STYLE
STYLEFNAME    : CELL_STYLE
```

### 12.3 `FIELDNAME` 오타

#### 증상

특정 컬럼에 Style이 적용되지 않는다.

#### 원인

`LVC_S_STYL-FIELDNAME`에 Field Catalog와 다른 이름을 입력했다.

잘못된 예:

```abap
ls_style-fieldname = 'AMOUNT'.
```

실제 Field Catalog 필드명이 `PRICE`라면 아무 효과가 없다.

#### 해결

Field Catalog의 `FIELDNAME`과 동일하게 입력한다.

```abap
ls_style-fieldname = 'PRICE'.
```

### 12.4 Field Catalog `EDIT` 설정 누락

#### 증상

`MC_STYLE_ENABLED`를 적용했는데 셀이 편집되지 않는다.

#### 원인

해당 컬럼이 전체적으로 편집 가능한 후보가 아니거나 Grid 편집 모드가 준비되지 않았다.

#### 해결

Field Catalog와 Grid 편집 설정을 함께 확인한다.

```abap
ls_fcat-fieldname = 'PRICE'.
ls_fcat-edit      = abap_true.
```

### 12.5 행 데이터 변경 후 Style 재계산 누락

#### 증상

상태값을 바꿨는데 Cell Style이 이전 상태로 남아 있다.

#### 원인

Style 정보는 자동으로 다시 계산되지 않는다.  
데이터 상태가 바뀌면 `CELL_STYLE`도 다시 채워야 한다.

#### 해결

상태 변경 후 Style 구성 Form/Method를 다시 호출한다.

```text
데이터 변경
→ Style 재계산
→ Grid Refresh
```

### 12.6 Refresh 후 표시 상태 불안정

#### 증상

Style 적용 후 Refresh하면 스크롤 위치나 선택 상태가 흔들린다.

#### 원인

Grid Refresh 시 Stable 설정을 사용하지 않았거나, Refresh 타이밍이 부적절하다.

#### 해결

다음 모듈 `THEORY-19-M07`에서 다룰 `IS_STABLE` 기반 Refresh를 적용한다.

## 13. 성능과 유지보수 관점

### 13.1 성능 관점

Cell Style은 각 행에 Deep Internal Table을 가지는 구조이다.  
데이터가 수천, 수만 건으로 커지면 Style 정보 생성 비용도 커질 수 있다.

주의할 점은 다음이다.

| 항목 | 설명 |
|---|---|
| 전체 셀에 무조건 Style 생성 | 불필요한 메모리 사용 증가 |
| 조건 없는 반복 Style 삽입 | 성능 저하와 코드 복잡도 증가 |
| 대량 ALV에서 과도한 UI 제어 | 사용자 경험과 성능 모두 악화 가능 |
| Style 재계산 빈도 | 이벤트마다 전체 재계산하면 부담 증가 |

권장 원칙:

```text
기본 상태는 Field Catalog로 처리한다.
예외 셀만 Cell Style로 제어한다.
대량 데이터에서는 Style 적용 범위와 조건을 제한한다.
```

### 13.2 유지보수 관점

Cell Style 로직이 ALV 생성 코드 곳곳에 흩어져 있으면 유지보수가 어렵다.

권장 구조는 다음과 같다.

```text
GET_DATA
BUILD_FIELDCATALOG
BUILD_LAYOUT
APPLY_CELL_STYLE
DISPLAY_ALV
REFRESH_ALV
```

Style 적용 로직은 별도 Form 또는 Method로 분리하는 것이 좋다.

예:

```abap
METHOD apply_cell_style.
  LOOP AT mt_alv ASSIGNING FIELD-SYMBOL(<ls_alv>).
    CLEAR <ls_alv>-cell_style.
    me->set_price_style( CHANGING cs_alv = <ls_alv> ).
    me->set_reason_style( CHANGING cs_alv = <ls_alv> ).
  ENDLOOP.
ENDMETHOD.
```

## 14. 실습 과제

### 14.1 기본 과제

다음 조건을 만족하는 Grid ALV를 구현한다.

```text
1. 출력 필드: CARRID, CONNID, FLDATE, PRICE, CURRENCY, STATUS
2. STATUS = 'A'이면 PRICE 셀을 Disabled 처리한다.
3. STATUS = 'E'이면 PRICE 셀을 Enabled 처리한다.
4. STATUS = 'B'이면 PRICE 셀을 Disabled 처리하고 CURRENCY 셀도 Disabled 처리한다.
5. STYLEFNAME을 이용하여 행별 Deep Style을 적용한다.
```

### 14.2 권장 Row Type

```abap
TYPES: BEGIN OF ty_alv,
         carrid     TYPE sflight-carrid,
         connid     TYPE sflight-connid,
         fldate     TYPE sflight-fldate,
         price      TYPE sflight-price,
         currency   TYPE sflight-currency,
         status     TYPE c LENGTH 1,
         cell_style TYPE lvc_t_styl,
       END OF ty_alv.
```

### 14.3 검증 포인트

| 검증 항목 | 확인 방법 |
|---|---|
| `CELL_STYLE`이 Row Type에 있는가? | ABAP Type 정의 확인 |
| `STYLEFNAME`이 지정되었는가? | `GS_LAYOUT-STYLEFNAME` 확인 |
| `PRICE` Field Catalog가 편집 가능 후보인가? | `GT_FCAT` 확인 |
| 상태별 Style이 다르게 생성되는가? | Debugging으로 `CELL_STYLE` 확인 |
| 화면에서 셀별 편집 가능 여부가 다른가? | Grid ALV 실행 후 확인 |

### 14.4 오류 케이스 기록

실습 중 최소 하나의 오류를 일부러 만들어 확인한다.

권장 오류:

```text
STYLEFNAME을 일부러 잘못 입력한다.
예: CELL_STYLE → CELLSTYL
```

기록할 내용:

| 항목 | 기록 |
|---|---|
| 오류 재현 조건 | `STYLEFNAME` 오타 |
| 기대 결과 | Cell Style 적용 |
| 실제 결과 | Style 미적용 |
| 원인 | Layout에서 Deep 필드명을 찾지 못함 |
| 해결 | 정확한 Deep 필드명으로 수정 |

## 15. 디버깅 포인트

Cell Style이 적용되지 않을 때는 화면만 보지 말고 다음 순서로 디버깅한다.

```text
1. GT_ALV에 데이터가 있는가?
2. 각 행의 CELL_STYLE에 값이 들어 있는가?
3. CELL_STYLE 안의 FIELDNAME이 Field Catalog와 일치하는가?
4. STYLE 값이 원하는 상수로 들어갔는가?
5. GS_LAYOUT-STYLEFNAME이 정확한가?
6. SET_TABLE_FOR_FIRST_DISPLAY 호출 시 Layout이 전달되었는가?
7. Field Catalog의 EDIT 설정과 충돌하지 않는가?
8. Refresh 이후 Style 재계산이 필요한 상황인가?
```

ABAP Debugger에서 특히 확인할 변수는 다음이다.

| 변수 | 확인 내용 |
|---|---|
| `GT_ALV` | 출력 데이터 전체 |
| `GT_ALV-CELL_STYLE` | 행별 Style Table |
| `GS_LAYOUT-STYLEFNAME` | Deep 필드명 |
| `GT_FCAT` | 컬럼 편집 가능 여부 |
| `LS_STYLE-FIELDNAME` | 적용 대상 컬럼명 |
| `LS_STYLE-STYLE` | 적용 Style 상수 값 |

## 16. 실무 적용 기준

Cell Style은 강력하지만 남용하면 유지보수가 어려워진다.

### 16.1 사용을 권장하는 경우

| 상황 | 이유 |
|---|---|
| 상태별로 특정 셀만 수정 가능해야 함 | 행별 조건 제어가 필요 |
| 오류 필드만 재입력 가능해야 함 | 사용자 입력 오류 수정 UX 개선 |
| 행별 버튼 또는 액션 셀이 필요 | 업무 처리 단축 |
| Field Catalog만으로 표현 불가 | 셀 단위 예외 제어 필요 |

### 16.2 사용을 신중히 해야 하는 경우

| 상황 | 이유 |
|---|---|
| 단순 색상 강조만 필요 | `LVC_T_SCOL`이 더 적합 |
| 컬럼 전체가 편집 가능/불가능 | Field Catalog만으로 충분 |
| 데이터 건수가 매우 많음 | Deep Style 생성 비용 증가 |
| 조건이 복잡하고 자주 바뀜 | 유지보수 난이도 증가 |
| Web/Fiori 전환 예정 화면 | Classic ALV UI 로직에 과도하게 의존 가능 |

### 16.3 Clean Code 관점

다음과 같은 코드는 피한다.

```abap
LOOP AT gt_alv ASSIGNING <ls_alv>.
  IF <ls_alv>-status = 'A'.
    "수십 줄의 Style 코드
  ELSEIF <ls_alv>-status = 'B'.
    "수십 줄의 Style 코드
  ELSEIF <ls_alv>-status = 'E'.
    "수십 줄의 Style 코드
  ENDIF.
ENDLOOP.
```

권장 방식은 조건별 메서드나 Form으로 분리하는 것이다.

```text
APPLY_CELL_STYLE
  SET_PRICE_STYLE
  SET_CURRENCY_STYLE
  SET_ACTION_STYLE
```

## 17. 평가 문제

### Q1. `LVC_T_STYL`의 목적은 무엇인가?

**정답 예시:**  
Grid ALV에서 특정 행의 특정 셀에 적용할 Style 정보를 담기 위한 Table Type이다. 출력 Internal Table의 Deep 필드로 포함하여 셀 단위 동작 제어에 사용한다.

### Q2. `STYLEFNAME`에는 무엇을 입력해야 하는가?

**정답 예시:**  
출력 Internal Table Row Type 안에 존재하는 Deep Style 필드명을 입력해야 한다. 예를 들어 Row Type에 `CELL_STYLE TYPE LVC_T_STYL`이 있다면 `GS_LAYOUT-STYLEFNAME = 'CELL_STYLE'`로 지정한다.

### Q3. Field Catalog의 `EDIT`와 Cell Style의 관계를 설명하시오.

**정답 예시:**  
Field Catalog의 `EDIT`는 컬럼 전체의 기본 편집 가능 여부를 설정하고, Cell Style은 특정 행의 특정 셀에 대해 예외적으로 Enabled 또는 Disabled 같은 스타일을 적용한다. 셀별 편집 제어를 하려면 Field Catalog와 Cell Style을 함께 고려해야 한다.

### Q4. Cell Style이 적용되지 않을 때 가장 먼저 확인할 세 가지는?

**정답 예시:**  

1. `GS_LAYOUT-STYLEFNAME`이 정확히 지정되었는지 확인한다.
2. 출력 Internal Table의 각 행에 `CELL_STYLE` 값이 들어 있는지 확인한다.
3. `LVC_S_STYL-FIELDNAME`이 Field Catalog의 필드명과 일치하는지 확인한다.

### Q5. Cell Color와 Cell Style의 차이는 무엇인가?

**정답 예시:**  
Cell Color는 주로 셀의 색상 표시를 제어하고, Cell Style은 셀의 편집 가능 여부, 버튼 스타일, Hotspot 등 UI 동작을 제어한다. Cell Color는 `LVC_T_SCOL`과 `CTAB_FNAME`, Cell Style은 `LVC_T_STYL`과 `STYLEFNAME`을 사용한다.

## 18. 핵심 요약

```text
Cell Style은 Grid ALV에서 셀 단위 UI 동작을 제어하는 기능이다.
LVC_T_STYL은 각 행의 특정 필드에 적용할 Style 목록을 담는다.
출력 Row Type에는 LVC_T_STYL 타입의 Deep 필드를 포함해야 한다.
LVC_S_LAYO-STYLEFNAME에는 해당 Deep 필드명을 지정한다.
Field Catalog는 컬럼 기본값, Cell Style은 셀 단위 예외 제어에 적합하다.
Style이 적용되지 않으면 STYLEFNAME, FIELDNAME, Deep 필드 데이터, Field Catalog 설정을 확인한다.
```
