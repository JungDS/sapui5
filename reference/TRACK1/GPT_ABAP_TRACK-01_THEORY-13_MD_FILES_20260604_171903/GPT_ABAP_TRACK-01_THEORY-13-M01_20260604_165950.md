## 1. 이 모듈의 위치

이 문서는 `THEORY-13-M01 — ABAP Report Event 전체 흐름`만 다룬다.

Track 1 앞부분에서 학습자는 이미 다음 내용을 경험했다.

```text
DDIC 기본 객체 생성
→ ABAP 기본 문법과 WRITE 출력
→ PARAMETERS 기반 Selection Screen 맛보기
→ Open SQL 기본 조회
→ Internal Table 처리
→ SALV 1차 출력
```

이번 Section에서는 그동안 조각처럼 배운 내용을 **Classic ABAP Report의 이벤트 흐름**으로 다시 연결한다.

초급 학습자는 보통 ABAP Report를 다음처럼 단순하게 생각한다.

```abap
REPORT zsample.

PARAMETERS p_carrid TYPE s_carr_id.

SELECT *
  FROM sflight
  INTO TABLE @DATA(lt_flight)
  WHERE carrid = @p_carrid.

LOOP AT lt_flight INTO DATA(ls_flight).
  WRITE: / ls_flight-carrid, ls_flight-connid, ls_flight-fldate.
ENDLOOP.
```

이 코드는 실행될 수 있지만, 실무 Report는 단순히 위에서 아래로만 흐르지 않는다. ABAP Report에는 표준 이벤트 블록이 있고, 각 이벤트는 실행 시점과 책임이 다르다.

이번 모듈에서는 다음 세 이벤트를 중심으로 전체 흐름을 잡는다.

```text
LOAD-OF-PROGRAM
INITIALIZATION
START-OF-SELECTION
```

다만 Section 전체 흐름을 이해하기 위해 다음 이벤트도 간단히 연결해서 언급한다.

```text
AT SELECTION-SCREEN OUTPUT
AT SELECTION-SCREEN
END-OF-SELECTION
```

상세한 동적 화면 제어, 입력 검증, 조회 실행, 출력 마무리는 M02~M07에서 각각 분리해 학습한다.

7. 후속 모듈에서 다룰 Selection Screen 심화 이벤트와 연결 관계를 설명할 수 있다.

## 4. ABAP Report Event란 무엇인가?

ABAP Report Event는 Executable Program이 실행되는 동안 SAP Runtime이 특정 시점에 자동으로 호출하는 처리 블록이다.

예를 들어 프로그램이 실행될 때 다음 일이 순서대로 일어난다고 생각할 수 있다.

```text
프로그램이 메모리에 로드된다.
선택 화면의 기본값이 준비된다.
선택 화면이 사용자에게 표시된다.
사용자가 값을 입력하고 실행한다.
입력값이 검증된다.
주요 조회/처리 로직이 실행된다.
결과가 출력된다.
```

이 각 시점에 대응하는 ABAP 이벤트가 있다.

| 실행 시점 | 대표 이벤트 |
|---|---|
| 프로그램 로드 시점 | `LOAD-OF-PROGRAM` |
| 선택 화면 기본값 설정 시점 | `INITIALIZATION` |
| 선택 화면 출력 직전 | `AT SELECTION-SCREEN OUTPUT` |
| 선택 화면 입력값 검증 | `AT SELECTION-SCREEN` |
| 주요 비즈니스 처리 시작 | `START-OF-SELECTION` |
| 출력 마무리 단계 | `END-OF-SELECTION` |

이벤트는 개발자가 직접 `CALL`하는 서브루틴이 아니다. ABAP Runtime이 프로그램 실행 흐름 중 정해진 시점에 해당 이벤트 블록을 수행한다.

## 5. 왜 이벤트 흐름을 배워야 하는가?

초급자 단계에서는 `REPORT`, `PARAMETERS`, `SELECT`, `WRITE`를 순서대로 쓰면 프로그램이 동작하는 것처럼 보인다. 그러나 실무 Report는 다음 요구사항을 자주 가진다.

```text
선택 화면에 기본값을 넣어야 한다.
사용자 권한에 따라 화면 필드를 숨기거나 비활성화해야 한다.
필수 입력값을 검증해야 한다.
존재하지 않는 코드가 입력되면 메시지를 보여줘야 한다.
조회 전 권한을 확인해야 한다.
조회 결과가 없으면 적절한 메시지를 보여줘야 한다.
조회 후 출력 형식을 정리해야 한다.
```

이 요구사항을 모두 `START-OF-SELECTION`에 몰아넣으면 프로그램은 동작할 수 있지만 구조가 무너진다.

나쁜 구조의 예는 다음과 같다.

```abap
START-OF-SELECTION.
  " 기본값 처리
  " 화면 제어
  " 입력값 검증
  " 권한 체크
  " 데이터 조회
  " 결과 출력
  " 마무리 메시지
```

이렇게 작성하면 실행 시점이 맞지 않는 로직이 생긴다. 예를 들어 화면이 이미 표시된 뒤에 기본값을 넣으려 하거나, 입력 검증을 조회 이후에 수행하는 문제가 생길 수 있다.

따라서 Report Event를 배우는 목적은 다음이다.

```text
각 로직을 실행 시점에 맞는 위치에 배치하기 위해서이다.
```

## 6. Report Event 전체 흐름 개요

Classic ABAP Report의 대표 흐름은 다음과 같이 이해할 수 있다.

```text
1. Program Load
   └─ LOAD-OF-PROGRAM

2. Selection Screen 준비
   └─ INITIALIZATION

3. Selection Screen 표시 직전
   └─ AT SELECTION-SCREEN OUTPUT

4. 사용자 입력 및 실행
   └─ AT SELECTION-SCREEN

5. 주요 처리 로직 실행
   └─ START-OF-SELECTION

6. 처리 결과 마무리
   └─ END-OF-SELECTION
```

이번 M01에서는 전체 지도를 먼저 잡고, 후속 모듈에서 각 이벤트를 깊게 다룬다.

## 7. LOAD-OF-PROGRAM

### 7.1 목적

`LOAD-OF-PROGRAM`은 프로그램이 메모리에 로드될 때 실행되는 이벤트이다.

초급자에게는 다소 추상적으로 느껴질 수 있다. 실무 초급 Report에서 반드시 자주 사용하는 이벤트는 아니지만, Report 전체 실행 흐름을 이해할 때 중요하다.

간단히 말하면 다음과 같다.

```text
LOAD-OF-PROGRAM = 프로그램이 실행 준비를 위해 메모리에 올라오는 시점
```

### 7.2 특징

| 항목 | 설명 |
|---|---|
| 실행 시점 | 프로그램 로드 시점 |
| 사용자 입력 전 여부 | 입력 전 |
| Selection Screen 표시 전 여부 | 표시 전 |
| 주요 용도 | 전역 초기 준비, 프로그램 로드 시점 처리 |
| 초급 사용 빈도 | 낮음 |

### 7.3 초급 예시

```abap
REPORT zjhy_report_event_flow.

LOAD-OF-PROGRAM.
  WRITE: / '1. LOAD-OF-PROGRAM executed'.
```

그러나 실제 Report에서 `LOAD-OF-PROGRAM`에 `WRITE`를 넣는 방식은 교육용 확인에는 사용할 수 있어도 실무적으로 권장되는 패턴은 아니다. 이벤트 실행 순서를 보기 위한 예시로만 이해한다.

### 7.4 실무 주의점

`LOAD-OF-PROGRAM`은 사용자가 Selection Screen에서 입력한 값을 아직 다룰 수 있는 시점이 아니다. 따라서 입력값 기반 조회나 검증을 여기에 넣으면 안 된다.

부적절한 예:

```abap
LOAD-OF-PROGRAM.
  " 사용자가 아직 입력하지 않은 p_carrid로 조회하려는 구조는 부적절하다.
  SELECT * FROM sflight INTO TABLE @DATA(lt_flight)
    WHERE carrid = @p_carrid.
```

적절한 판단:

```text
사용자 입력값이 필요한 로직은 START-OF-SELECTION 또는 AT SELECTION-SCREEN 계열로 보낸다.
```

## 8. INITIALIZATION

### 8.1 목적

`INITIALIZATION`은 Selection Screen이 처음 표시되기 전에 기본값을 설정하는 데 자주 사용하는 이벤트이다.

초급자는 다음처럼 기억하면 된다.

```text
INITIALIZATION = 선택 화면이 나타나기 전에 기본값을 넣는 시점
```

### 8.2 특징

| 항목 | 설명 |
|---|---|
| 실행 시점 | Selection Screen 최초 표시 전 |
| 주요 용도 | PARAMETERS / SELECT-OPTIONS 기본값 설정 |
| 사용자 입력 전 여부 | 입력 전 |
| 화면 동적 제어 | 주로 `AT SELECTION-SCREEN OUTPUT`에서 수행 |
| 입력값 검증 | 주로 `AT SELECTION-SCREEN`에서 수행 |

### 8.3 초급 예시

```abap
REPORT zjhy_report_event_flow.

PARAMETERS p_carrid TYPE s_carr_id.

INITIALIZATION.
  p_carrid = 'AA'.
```

이 프로그램을 실행하면 Selection Screen의 `P_CARRID` 입력 필드에 기본값 `AA`가 들어간 상태로 표시된다.

### 8.4 DEFAULT와 INITIALIZATION의 관계

PARAMETERS에는 `DEFAULT` 옵션도 있다.

```abap
PARAMETERS p_carrid TYPE s_carr_id DEFAULT 'AA'.
```

그렇다면 `INITIALIZATION`은 언제 쓰는가?

| 방식 | 적합한 상황 |
|---|---|
| `DEFAULT` | 고정 기본값이 단순할 때 |
| `INITIALIZATION` | 시스템 날짜, 사용자, 조건 계산 등 동적 기본값이 필요할 때 |

예:

```abap
PARAMETERS p_date TYPE sy-datum.

INITIALIZATION.
  p_date = sy-datum.
```

### 8.5 실무 주의점

`INITIALIZATION`에서 입력값 검증을 하려고 하면 안 된다. 이 시점은 사용자가 아직 값을 입력하기 전이기 때문이다.

부적절한 예:

```abap
INITIALIZATION.
  IF p_carrid IS INITIAL.
    MESSAGE '항공사 코드를 입력하세요.' TYPE 'E'.
  ENDIF.
```

입력값 검증은 후속 모듈에서 다룰 `AT SELECTION-SCREEN`에서 처리하는 것이 적절하다.

## 9. START-OF-SELECTION

### 9.1 목적

`START-OF-SELECTION`은 사용자가 Selection Screen에서 Execute를 누른 뒤 주요 처리 로직이 시작되는 이벤트이다.

초급자는 다음처럼 기억하면 된다.

```text
START-OF-SELECTION = 사용자가 실행한 뒤 실제 조회와 처리를 시작하는 시점
```

### 9.2 특징

| 항목 | 설명 |
|---|---|
| 실행 시점 | Selection Screen 입력 후 실행 단계 |
| 주요 용도 | 데이터 조회, 주요 계산, 결과 준비 |
| Open SQL 위치 | 일반적으로 이 이벤트에서 수행 |
| 입력값 기본 검증 | `AT SELECTION-SCREEN`이 더 적합 |
| 출력 | 간단한 WRITE 출력 가능 |

### 9.3 초급 예시

```abap
REPORT zjhy_report_event_flow.

PARAMETERS p_carrid TYPE s_carr_id DEFAULT 'AA'.

START-OF-SELECTION.
  SELECT carrid,
         connid,
         fldate,
         price,
         currency
    FROM sflight
    WHERE carrid = @p_carrid
    INTO TABLE @DATA(lt_flight).

  IF sy-subrc <> 0.
    WRITE: / 'No data found.'.
    RETURN.
  ENDIF.

  LOOP AT lt_flight INTO DATA(ls_flight).
    WRITE: / ls_flight-carrid,
             ls_flight-connid,
             ls_flight-fldate,
             ls_flight-price,
             ls_flight-currency.
  ENDLOOP.
```

이 예제는 `START-OF-SELECTION`의 가장 기본적인 역할을 보여준다.

```text
사용자 입력값을 기준으로 DB 조회
→ 조회 결과 확인
→ 결과 출력
```

## 10. 전체 이벤트 흐름 예제

아래 예제는 이벤트 흐름을 관찰하기 위한 교육용 코드이다.

```abap
REPORT zjhy_event_flow_demo.

PARAMETERS: p_carrid TYPE s_carr_id,
            p_date   TYPE sy-datum.

LOAD-OF-PROGRAM.
  " 프로그램이 로드될 때 실행된다.
  " 실무 초급 Report에서는 사용 빈도가 높지 않다.

INITIALIZATION.
  p_carrid = 'AA'.
  p_date   = sy-datum.

AT SELECTION-SCREEN OUTPUT.
  " 선택 화면 표시 직전에 화면 속성을 조정할 수 있다.
  " 상세 내용은 THEORY-13-M03에서 다룬다.

AT SELECTION-SCREEN.
  " 사용자가 입력하고 실행할 때 입력값을 검증할 수 있다.
  " 상세 내용은 THEORY-13-M04에서 다룬다.

START-OF-SELECTION.
  SELECT carrid,
         connid,
         fldate,
         price,
         currency
    FROM sflight
    WHERE carrid = @p_carrid
      AND fldate >= @p_date
    INTO TABLE @DATA(lt_flight).

  IF sy-subrc <> 0.
    WRITE: / 'No flight data found.'.
    RETURN.
  ENDIF.

  LOOP AT lt_flight INTO DATA(ls_flight).
    WRITE: / ls_flight-carrid,
             ls_flight-connid,
             ls_flight-fldate,
             ls_flight-price,
             ls_flight-currency.
  ENDLOOP.

END-OF-SELECTION.
  " 출력 마무리 단계로 이해할 수 있다.
  " 상세 내용은 THEORY-13-M06에서 다룬다.
```

이 코드를 통해 학습자가 봐야 할 핵심은 문법 자체보다 “로직이 어느 이벤트에 위치하는가”이다.

## 11. 이벤트별 책임 분리

이벤트를 잘 쓰려면 각 이벤트의 책임을 분리해야 한다.

| 이벤트 | 넣기 좋은 로직 | 피해야 할 로직 |
|---|---|---|
| `LOAD-OF-PROGRAM` | 프로그램 로드 시점의 전역 초기 준비 | 사용자 입력값 기반 조회 |
| `INITIALIZATION` | 기본값 설정 | 사용자 입력값 검증 |
| `AT SELECTION-SCREEN OUTPUT` | 화면 필드 활성/비활성, 표시 제어 | DB 대량 조회 |
| `AT SELECTION-SCREEN` | 입력값 검증, 존재 여부 검증 | 결과 출력 전체 처리 |
| `START-OF-SELECTION` | 주요 조회, 계산, 처리 | 화면 필드 속성 제어 |
| `END-OF-SELECTION` | 출력 마무리, 후처리 | 기본 입력값 설정 |

초급 단계에서는 최소한 다음만 지켜도 구조가 좋아진다.

```text
기본값은 INITIALIZATION
입력 검증은 AT SELECTION-SCREEN
주요 조회는 START-OF-SELECTION
출력 마무리는 END-OF-SELECTION
```

## 12. 이벤트 흐름을 그림으로 이해하기

```text
프로그램 실행
   │
   ▼
LOAD-OF-PROGRAM
   │
   ▼
INITIALIZATION
   │
   ▼
Selection Screen 준비
   │
   ▼
AT SELECTION-SCREEN OUTPUT
   │
   ▼
사용자 입력 / Execute
   │
   ▼
AT SELECTION-SCREEN
   │
   ▼
START-OF-SELECTION
   │
   ▼
END-OF-SELECTION
   │
   ▼
List Output 또는 후속 출력
```

이 흐름을 머릿속에 넣으면 이후 Selection Screen 심화 모듈을 훨씬 쉽게 이해할 수 있다.

## 13. 실무 안티패턴

### 13.1 모든 로직을 START-OF-SELECTION에 몰아넣기

초급자에게 가장 흔한 패턴이다.

```abap
START-OF-SELECTION.
  " 기본값 설정
  " 입력값 검증
  " 화면 제어
  " 권한 체크
  " 조회
  " 출력
```

문제는 실행 시점이 서로 다른 로직이 한곳에 섞인다는 점이다. 화면 제어는 이미 늦었고, 기본값 설정도 사용자의 입력 이후에는 의미가 달라진다.

### 13.2 INITIALIZATION에서 사용자 입력 검증하기

`INITIALIZATION`은 사용자 입력 전 이벤트이다. 따라서 입력값 검증 위치로 적합하지 않다.

### 13.3 AT SELECTION-SCREEN OUTPUT에서 DB 대량 조회하기

화면 표시 직전 이벤트는 화면 속성을 조정하는 용도로 사용해야 한다. 이곳에 DB 대량 조회를 넣으면 화면 표시가 느려지고, 사용자가 값을 바꿀 때마다 불필요하게 반복될 수 있다.

### 13.4 이벤트 순서를 코드 위치 순서로만 이해하기

ABAP 이벤트 블록은 단순한 텍스트 위치가 아니라 Runtime 이벤트 흐름과 연결된다. 교육 초반에는 코드 위치도 정리하는 것이 좋지만, 핵심은 실행 시점이다.

## 14. 실습: 이벤트 흐름 관찰 프로그램 만들기

### 14.1 실습 목표

간단한 Report를 만들고, 각 이벤트가 어떤 순서로 실행되는지 관찰한다.

### 14.2 프로그램명

```text
ZJHY_EVENT_FLOW_DEMO
```

### 14.3 실습 코드

```abap
REPORT zjhy_event_flow_demo.

PARAMETERS: p_name TYPE c LENGTH 20 DEFAULT 'ABAP',
            p_date TYPE sy-datum.

INITIALIZATION.
  p_date = sy-datum.

START-OF-SELECTION.
  WRITE: / 'START-OF-SELECTION'.
  WRITE: / 'Name:', p_name.
  WRITE: / 'Date:', p_date.

END-OF-SELECTION.
  WRITE: / 'END-OF-SELECTION'.
```

초급 단계에서는 `LOAD-OF-PROGRAM`의 출력 여부를 환경에 따라 혼동할 수 있으므로, 첫 실습에서는 `INITIALIZATION`, `START-OF-SELECTION`, `END-OF-SELECTION` 중심으로 확인해도 충분하다.

### 14.4 실습 절차

```text
1. SE38 또는 ADT에서 Executable Program 생성
2. 위 코드 입력
3. Syntax Check
4. Activate
5. Execute
6. Selection Screen에서 기본값 확인
7. Execute
8. List Output 확인
```

### 14.5 관찰 포인트

| 관찰 항목 | 확인 내용 |
|---|---|
| `p_date` 기본값 | Selection Screen 표시 전에 오늘 날짜가 들어가는가? |
| `START-OF-SELECTION` 출력 | 사용자가 Execute한 뒤 표시되는가? |
| `END-OF-SELECTION` 출력 | 주요 처리 뒤 출력되는가? |
| 값 변경 | Selection Screen에서 값을 바꾸면 출력 결과가 바뀌는가? |

## 15. 디버깅으로 이벤트 흐름 확인하기

이벤트 흐름은 디버깅으로 보면 더 명확하다.

### 15.1 디버깅 절차

```text
1. INITIALIZATION 라인에 Breakpoint 설정
2. START-OF-SELECTION 라인에 Breakpoint 설정
3. END-OF-SELECTION 라인에 Breakpoint 설정
4. 프로그램 실행
5. Debugger에서 멈추는 순서 확인
```

### 15.2 확인할 시스템 필드

| 시스템 필드 | 확인 목적 |
|---|---|
| `SY-REPID` | 현재 프로그램명 |
| `SY-DATUM` | 현재 날짜 기본값 |
| `SY-UNAME` | 현재 사용자 |
| `SY-UCOMM` | 사용자의 화면 기능 코드 확인에 활용 가능 |
| `SY-SUBRC` | 후속 조회/검증 로직에서 결과 코드 확인 |

이번 모듈에서는 시스템 필드를 깊게 다루지 않는다. 다만 후속 검증 로직에서 `SY-SUBRC`가 중요하게 사용된다는 점을 연결해 둔다.

## 16. 오류 상황과 해결

### 16.1 이벤트 이름 오타

#### 증상

Syntax Error가 발생한다.

#### 예시

```abap
START-OF-SELECTIONS.
  WRITE 'Hello'.
```

#### 해결

정확한 이벤트 이름을 사용한다.

```abap
START-OF-SELECTION.
```

### 16.2 이벤트 블록 안에 실행문 위치 오류

ABAP에서는 선언부와 실행문 위치를 구분해야 한다. 초급자는 `DATA` 선언과 이벤트 블록, 실행문 배치를 혼동할 수 있다.

권장 방식:

```abap
REPORT zjhy_event_demo.

PARAMETERS p_name TYPE c LENGTH 20.

DATA gv_text TYPE string.

INITIALIZATION.
  p_name = 'ABAP'.

START-OF-SELECTION.
  gv_text = |Hello { p_name }|.
  WRITE gv_text.
```

### 16.3 기본값이 기대대로 보이지 않음

#### 가능한 원인

| 원인 | 설명 |
|---|---|
| `DEFAULT`와 `INITIALIZATION` 값이 충돌 | 나중에 실행되는 기본값 설정이 우선될 수 있다. |
| Variant 사용 | 저장된 Selection Variant가 기본값을 덮을 수 있다. |
| 필드명 오타 | 다른 Parameter에 값을 넣었을 수 있다. |

### 16.4 입력 검증을 잘못된 이벤트에 배치

입력 검증을 `INITIALIZATION`에 넣으면 사용자가 입력하기 전에 검증이 발생한다. 입력 검증은 후속 모듈의 `AT SELECTION-SCREEN`에서 다룬다.

## 17. 강사용 설명 포인트

강의에서는 다음 순서로 설명하면 학습자 이해가 빠르다.

1. 먼저 단순 Report를 보여준다.
2. `PARAMETERS`가 있으면 Selection Screen이 먼저 표시됨을 보여준다.
3. `INITIALIZATION`으로 기본값이 들어가는 것을 보여준다.
4. 사용자가 Execute를 누른 뒤 `START-OF-SELECTION`이 실행됨을 보여준다.
5. 입력 검증과 화면 제어는 별도 이벤트로 분리해야 함을 예고한다.

강사가 강조할 핵심 문장은 다음이다.

```text
ABAP Report는 작성한 코드의 위아래 순서만 보는 것이 아니라, Runtime이 호출하는 이벤트 흐름으로 이해해야 한다.
```

## 18. 평가 문제

### 18.1 객관식

#### Q1. `INITIALIZATION` 이벤트의 대표적인 용도는 무엇인가?

A. 데이터베이스 대량 조회  
B. Selection Screen 기본값 설정  
C. ALV Grid 이벤트 처리  
D. 프로그램 종료 후 로그 삭제  

정답: B

#### Q2. 사용자가 Selection Screen에서 Execute를 누른 뒤 주요 조회 로직을 배치하기 가장 적절한 이벤트는?

A. `LOAD-OF-PROGRAM`  
B. `INITIALIZATION`  
C. `START-OF-SELECTION`  
D. `TOP-OF-PAGE`  

정답: C

#### Q3. 다음 중 사용자 입력값 검증을 본격적으로 다룰 후속 이벤트는?

A. `AT SELECTION-SCREEN`  
B. `INITIALIZATION`  
C. `LOAD-OF-PROGRAM`  
D. `REPORT`  

정답: A

### 18.2 서술형

#### Q1. ABAP Report Event를 배우는 이유를 설명하시오.

모범 답안:

ABAP Report는 선택 화면 준비, 사용자 입력, 입력값 검증, 조회 실행, 출력 마무리처럼 실행 시점이 나뉘어 있다. 이벤트를 이해하면 기본값 설정, 검증, 조회, 출력 로직을 적절한 위치에 배치할 수 있어 프로그램 구조와 유지보수성이 좋아진다.

#### Q2. `INITIALIZATION`과 `START-OF-SELECTION`의 차이를 설명하시오.

모범 답안:

`INITIALIZATION`은 Selection Screen이 표시되기 전에 기본값을 설정하는 시점이고, `START-OF-SELECTION`은 사용자가 실행한 후 주요 조회나 처리 로직을 수행하는 시점이다.

#### Q3. 모든 로직을 `START-OF-SELECTION`에 몰아넣으면 왜 좋지 않은가?

모범 답안:

기본값 설정, 화면 제어, 입력 검증, 데이터 조회는 각각 적절한 실행 시점이 다르다. 모든 로직을 `START-OF-SELECTION`에 넣으면 화면 표시 전 처리나 입력 검증 같은 로직이 늦게 실행되거나 의미가 불명확해져 유지보수가 어려워진다.

## 20. 핵심 요약

```text
ABAP Report Event는 SAP Runtime이 특정 시점에 호출하는 처리 블록이다.
LOAD-OF-PROGRAM은 프로그램 로드 시점 이벤트이다.
INITIALIZATION은 Selection Screen 표시 전 기본값 설정에 적합하다.
START-OF-SELECTION은 사용자 실행 후 주요 조회와 처리 로직에 적합하다.
입력 검증은 AT SELECTION-SCREEN에서 다루는 것이 적절하다.

```
