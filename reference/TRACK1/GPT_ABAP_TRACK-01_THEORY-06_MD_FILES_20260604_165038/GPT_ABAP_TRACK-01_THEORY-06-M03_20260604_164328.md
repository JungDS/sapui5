## 1. 이 문서의 목적

이 문서는 ABAP 초급자가 Internal Table에 데이터를 추가하는 기본 구문인 **APPEND**와 **INSERT**를 이해하도록 돕는다.

앞선 모듈에서 학습자는 다음을 배웠다.

```text
Line Type
Work Area
STANDARD TABLE 선언
```

이번 모듈에서는 선언된 Internal Table에 실제 행을 추가한다.

```text
Work Area에 한 줄 데이터를 채운다.
→ APPEND로 마지막 줄에 추가한다.
→ INSERT로 원하는 위치에 추가한다.
→ Internal Table의 행 수와 순서를 확인한다.
```

---

## 2. 선수 지식

| 선수 지식 | 필요한 이유 |
|---|---|
| TYPES | Internal Table의 Line Type을 정의한다. |
| DATA | Work Area와 Internal Table을 선언한다. |
| Standard Table | APPEND/INSERT 동작을 가장 단순하게 확인할 수 있다. |
| WRITE | 추가된 데이터를 화면에 출력해 검증한다. |
| CLEAR | Work Area 재사용 시 이전 값을 제거한다. |

---

## 3. APPEND란 무엇인가?

`APPEND`는 Internal Table의 **마지막 줄에 새로운 행을 추가**하는 구문이다.

기본 형태는 다음과 같다.

```abap
APPEND ls_student TO lt_student.
```

의미는 다음이다.

```text
ls_student Work Area에 들어 있는 현재 값을
lt_student Internal Table의 마지막 줄로 추가한다.
```

APPEND는 Standard Table에서 초급자가 가장 먼저 익혀야 하는 행 추가 방식이다.

---

## 4. APPEND 기본 예제

```abap
REPORT zgpt_itab_append_01.

TYPES: BEGIN OF ty_student,
         student_id TYPE c LENGTH 5,
         name       TYPE c LENGTH 20,
         score      TYPE i,
       END OF ty_student.

DATA: lt_student TYPE STANDARD TABLE OF ty_student,
      ls_student TYPE ty_student.

ls_student-student_id = 'S0001'.
ls_student-name       = 'Kim'.
ls_student-score      = 90.
APPEND ls_student TO lt_student.

CLEAR ls_student.

ls_student-student_id = 'S0002'.
ls_student-name       = 'Lee'.
ls_student-score      = 85.
APPEND ls_student TO lt_student.

WRITE: / 'Rows appended successfully.'.
```

이 예제에서 `APPEND`는 두 번 실행되며, `lt_student`에는 두 줄이 들어간다.

---

## 5. Work Area와 APPEND의 관계

초급자가 반드시 이해해야 하는 점은 다음이다.

```text
APPEND는 Work Area 자체를 테이블에 연결하는 것이 아니라,
APPEND 시점의 Work Area 값을 한 줄로 복사해서 Internal Table에 넣는다.
```

즉, `APPEND` 이후에 Work Area를 변경해도 이미 추가된 Internal Table의 기존 행이 자동으로 바뀌지는 않는다.

### 5.1 예시

```abap
ls_student-student_id = 'S0001'.
ls_student-name       = 'Kim'.
ls_student-score      = 90.
APPEND ls_student TO lt_student.

ls_student-name = 'Changed'.
```

위 코드에서 `APPEND` 후 Work Area의 `name`을 변경해도, 이미 추가된 첫 번째 행의 값이 항상 같이 바뀌는 개념은 아니다.  
Internal Table에는 APPEND 시점의 값이 들어간다.

---

## 6. CLEAR가 필요한 이유

Work Area를 반복해서 사용할 때는 `CLEAR`를 사용하는 것이 안전하다.

```abap
APPEND ls_student TO lt_student.
CLEAR ls_student.
```

`CLEAR`는 Work Area의 필드를 초기값으로 되돌린다.

### 6.1 CLEAR를 하지 않았을 때의 문제

```abap
ls_student-student_id = 'S0001'.
ls_student-name       = 'Kim'.
ls_student-score      = 90.
APPEND ls_student TO lt_student.

ls_student-student_id = 'S0002'.
APPEND ls_student TO lt_student.
```

위 코드는 두 번째 행에 `name = Kim`, `score = 90`이 그대로 남을 수 있다.  
왜냐하면 두 번째 입력 전에 `name`, `score`를 초기화하거나 다시 세팅하지 않았기 때문이다.

초급 학습에서는 다음 패턴을 권장한다.

```abap
값 세팅
APPEND
CLEAR
```

## 7. APPEND 후 행 수 확인

Internal Table에 몇 건이 들어갔는지 확인하려면 `DESCRIBE TABLE` 또는 `lines( )`를 사용할 수 있다.

초급 Classic ABAP 흐름에서는 다음처럼 확인할 수 있다.

```abap
DATA gv_lines TYPE i.

DESCRIBE TABLE lt_student LINES gv_lines.
WRITE: / 'Row count:', gv_lines.
```

S/4HANA 기반의 비교적 최신 ABAP 문법에서는 다음처럼도 쓸 수 있다.

```abap
WRITE: / 'Row count:', lines( lt_student ).
```

다만 현재 Section은 Internal Table 기초이므로, 문법 설명은 Classic 형태를 중심으로 이해해도 충분하다.

## 8. INSERT란 무엇인가?

`INSERT`는 Internal Table에 행을 추가하는 또 다른 구문이다.  
Standard Table에서는 특정 위치(Index)에 행을 넣는 예제를 통해 차이를 이해하는 것이 좋다.

기본 형태는 다음과 같다.

```abap
INSERT ls_student INTO lt_student INDEX 1.
```

의미는 다음이다.

```text
ls_student 값을 lt_student의 1번째 위치에 삽입한다.
기존 1번째 행과 그 뒤의 행들은 뒤로 밀린다.
```

---

## 9. APPEND와 INSERT의 차이

| 구분 | APPEND | INSERT |
|---|---|---|
| 기본 목적 | 마지막 줄에 추가 | 특정 위치 또는 키 기준으로 삽입 |
| 초급 사용 형태 | `APPEND wa TO itab` | `INSERT wa INTO itab INDEX n` |
| 행 순서 영향 | 항상 뒤에 붙음 | 지정 위치에 들어가며 기존 행이 밀림 |
| 사용 난이도 | 낮음 | APPEND보다 주의 필요 |
| 주요 실습 대상 | Standard Table | Standard Table의 Index 삽입 |

초급자는 우선 이렇게 기억하면 된다.

```text
APPEND = 끝에 추가
INSERT = 지정 위치에 삽입
```

---

## 10. INSERT 기본 예제

```abap
REPORT zgpt_itab_insert_01.

TYPES: BEGIN OF ty_student,
         student_id TYPE c LENGTH 5,
         name       TYPE c LENGTH 20,
         score      TYPE i,
       END OF ty_student.

DATA: lt_student TYPE STANDARD TABLE OF ty_student,
      ls_student TYPE ty_student.

ls_student-student_id = 'S0001'.
ls_student-name       = 'Kim'.
ls_student-score      = 90.
APPEND ls_student TO lt_student.
CLEAR ls_student.

ls_student-student_id = 'S0002'.
ls_student-name       = 'Lee'.
ls_student-score      = 85.
APPEND ls_student TO lt_student.
CLEAR ls_student.

ls_student-student_id = 'S0000'.
ls_student-name       = 'Park'.
ls_student-score      = 95.
INSERT ls_student INTO lt_student INDEX 1.

WRITE: / 'Insert completed.'.
```

실행 후 Internal Table의 논리적 순서는 다음과 같다.

| Index | STUDENT_ID | NAME | SCORE |
|---:|---|---|---:|
| 1 | S0000 | Park | 95 |
| 2 | S0001 | Kim | 90 |
| 3 | S0002 | Lee | 85 |

## 11. 전체 데이터를 출력해서 검증하기

APPEND와 INSERT 결과를 확인하려면 `LOOP AT`으로 출력할 수 있다.  
`LOOP AT`은 다음 모듈에서 자세히 다루지만, 이번 모듈에서는 검증용으로 최소한만 사용한다.

```abap
LOOP AT lt_student INTO ls_student.
  WRITE: / ls_student-student_id,
           ls_student-name,
           ls_student-score.
ENDLOOP.
```

이 코드는 Internal Table의 첫 줄부터 마지막 줄까지 읽으며 화면에 출력한다.

## 12. 종합 실습 코드

다음 코드는 APPEND와 INSERT의 차이를 한 번에 확인하는 실습이다.

```abap
REPORT zgpt_itab_append_insert.

TYPES: BEGIN OF ty_student,
         student_id TYPE c LENGTH 5,
         name       TYPE c LENGTH 20,
         score      TYPE i,
       END OF ty_student.

DATA: lt_student TYPE STANDARD TABLE OF ty_student,
      ls_student TYPE ty_student,
      gv_lines   TYPE i.

"1. 첫 번째 학생을 마지막 줄에 추가
ls_student-student_id = 'S0001'.
ls_student-name       = 'Kim'.
ls_student-score      = 90.
APPEND ls_student TO lt_student.
CLEAR ls_student.

"2. 두 번째 학생을 마지막 줄에 추가
ls_student-student_id = 'S0002'.
ls_student-name       = 'Lee'.
ls_student-score      = 85.
APPEND ls_student TO lt_student.
CLEAR ls_student.

"3. 세 번째 학생을 첫 번째 위치에 삽입
ls_student-student_id = 'S0000'.
ls_student-name       = 'Park'.
ls_student-score      = 95.
INSERT ls_student INTO lt_student INDEX 1.
CLEAR ls_student.

DESCRIBE TABLE lt_student LINES gv_lines.
WRITE: / 'Total rows:', gv_lines.
WRITE: / '------------------------------'.

LOOP AT lt_student INTO ls_student.
  WRITE: / ls_student-student_id,
           ls_student-name,
           ls_student-score.
ENDLOOP.
```

예상 출력 순서는 다음과 같다.

```text
Total rows: 3
------------------------------
S0000 Park 95
S0001 Kim  90
S0002 Lee  85
```

시스템의 출력 폭이나 타입 표시 방식에 따라 공백은 다르게 보일 수 있다.

## 13. INSERT INDEX 사용 시 주의점

### 13.1 Index는 행 위치이다

`INDEX 1`은 첫 번째 위치를 의미한다.

```abap
INSERT ls_student INTO lt_student INDEX 1.
```

`INDEX 2`는 두 번째 위치를 의미한다.

```abap
INSERT ls_student INTO lt_student INDEX 2.
```

### 13.2 비어 있는 테이블에 INDEX 1은 가능

Internal Table이 비어 있어도 첫 번째 위치에 삽입할 수 있다.

```abap
INSERT ls_student INTO lt_student INDEX 1.
```

### 13.3 범위를 벗어난 Index는 오류 또는 실패 원인이 될 수 있음

예를 들어 현재 2건만 있는 테이블에 너무 큰 Index로 삽입하려 하면 문제가 발생할 수 있다.

```abap
INSERT ls_student INTO lt_student INDEX 99.
```

초급자는 `INSERT` 후 `sy-subrc` 또는 결과 행 수를 확인하는 습관을 들이면 좋다.  
다만 `sy-subrc`의 세부 동작은 구문과 테이블 종류에 따라 달라질 수 있으므로, 이번 모듈에서는 “삽입 후 결과를 반드시 검증한다”는 원칙을 먼저 익힌다.

## 14. APPEND와 INSERT의 실무 사용 기준

실무에서 Standard Table에 데이터를 모을 때는 `APPEND`를 가장 자주 사용한다.

### 14.1 APPEND가 적합한 경우

| 상황 | 이유 |
|---|---|
| SELECT 결과를 후처리하며 한 줄씩 추가 | 입력 순서대로 누적하면 충분 |
| 파일 업로드 데이터를 순서대로 담음 | 업로드 순서 유지 |
| ALV 출력 데이터를 구성 | 일반적으로 마지막에 추가하는 흐름이 자연스러움 |
| 임시 결과 목록 생성 | 복잡한 위치 삽입 필요 없음 |

### 14.2 INSERT가 적합한 경우

| 상황 | 이유 |
|---|---|
| 특정 행 앞에 데이터를 넣어야 함 | Index 위치 삽입 필요 |
| Header 성격의 행을 맨 앞에 추가 | 기존 행을 뒤로 밀어야 함 |
| 정렬 또는 Key 기반 테이블 심화 학습 | Sorted/Hashed Table에서 별도 의미 학습 필요 |

초급 실무 감각은 다음이다.

```text
대부분의 단순 누적은 APPEND로 충분하다.
위치를 의도적으로 제어해야 할 때 INSERT를 검토한다.
```

## 15. 자주 발생하는 오류와 안티패턴

### 15.1 Work Area 초기화 누락

#### 문제 코드

```abap
ls_student-student_id = 'S0001'.
ls_student-name       = 'Kim'.
ls_student-score      = 90.
APPEND ls_student TO lt_student.

ls_student-student_id = 'S0002'.
APPEND ls_student TO lt_student.
```

#### 문제점

두 번째 행에 `name`과 `score`가 이전 값으로 남을 수 있다.

#### 개선 코드

```abap
APPEND ls_student TO lt_student.
CLEAR ls_student.
```

그리고 다음 행의 모든 필드를 명시적으로 세팅한다.

---

### 15.2 APPEND 대상과 Work Area 타입 불일치

#### 문제 상황

`lt_student`의 Line Type은 `ty_student`인데, 다른 구조의 Work Area를 APPEND하려는 경우 Syntax Error가 발생한다.

#### 해결

Internal Table과 Work Area의 타입을 일치시킨다.

```abap
DATA: lt_student TYPE STANDARD TABLE OF ty_student,
      ls_student TYPE ty_student.
```

---

### 15.3 INSERT를 APPEND처럼 오해

`INSERT ... INDEX 1`은 마지막 줄에 추가하는 것이 아니라 첫 번째 위치에 삽입한다.  
기존 데이터의 순서가 달라질 수 있으므로 의도적으로 사용할 때만 선택한다.

---

### 15.4 행 추가 후 검증하지 않음

초급자는 APPEND나 INSERT를 작성하고도 실제로 행이 몇 건 들어갔는지 확인하지 않는 경우가 많다.

권장 검증:

```abap
DESCRIBE TABLE lt_student LINES gv_lines.
WRITE: / 'Rows:', gv_lines.
```

또는 `LOOP AT`으로 결과를 출력한다.

## 16. 디버깅 관점

APPEND와 INSERT를 학습할 때는 디버깅이 매우 효과적이다.

### 16.1 확인할 변수

| 변수 | 확인 내용 |
|---|---|
| `ls_student` | APPEND 직전 Work Area 값 |
| `lt_student` | APPEND 후 Internal Table 행 |
| `gv_lines` | 행 수 |
| `sy-tabix` | LOOP 중 현재 Index. 다음 모듈에서 더 중요 |
| `sy-subrc` | 일부 테이블 처리 결과 확인. 후속 모듈에서 더 중요 |

### 16.2 디버깅 절차

```text
1. APPEND 직전 Breakpoint 설정
2. ls_student 값 확인
3. APPEND 실행
4. lt_student에 한 줄이 추가되었는지 확인
5. CLEAR 실행 후 ls_student 초기화 확인
6. INSERT 실행 후 행 순서 확인
```

디버깅으로 확인하면 “Work Area 값이 복사되어 Internal Table 행이 된다”는 개념이 명확해진다.

## 17. 미니 실습 과제

### 17.1 기본 과제

다음 조건을 만족하는 프로그램을 작성한다.

```text
Line Type: ty_product
Fields:
  product_id   TYPE c LENGTH 10
  product_name TYPE c LENGTH 40
  price        TYPE p LENGTH 8 DECIMALS 2

Internal Table: lt_product
Work Area: ls_product
```

처리 조건:

```text
1. APPEND로 P001, P002 두 상품을 추가한다.
2. INSERT INDEX 1로 P000 상품을 첫 번째 위치에 추가한다.
3. 최종 행 수를 출력한다.
4. LOOP AT으로 전체 상품 목록을 출력한다.
```

### 17.2 예시 코드

```abap
REPORT zgpt_itab_product_append.

TYPES: BEGIN OF ty_product,
         product_id   TYPE c LENGTH 10,
         product_name TYPE c LENGTH 40,
         price        TYPE p LENGTH 8 DECIMALS 2,
       END OF ty_product.

DATA: lt_product TYPE STANDARD TABLE OF ty_product,
      ls_product TYPE ty_product,
      gv_lines   TYPE i.

ls_product-product_id   = 'P001'.
ls_product-product_name = 'Keyboard'.
ls_product-price        = '50000'.
APPEND ls_product TO lt_product.
CLEAR ls_product.

ls_product-product_id   = 'P002'.
ls_product-product_name = 'Mouse'.
ls_product-price        = '25000'.
APPEND ls_product TO lt_product.
CLEAR ls_product.

ls_product-product_id   = 'P000'.
ls_product-product_name = 'Monitor'.
ls_product-price        = '200000'.
INSERT ls_product INTO lt_product INDEX 1.
CLEAR ls_product.

DESCRIBE TABLE lt_product LINES gv_lines.
WRITE: / 'Product count:', gv_lines.

LOOP AT lt_product INTO ls_product.
  WRITE: / ls_product-product_id,
           ls_product-product_name,
           ls_product-price.
ENDLOOP.
```

## 18. 평가 문제

### 18.1 객관식

#### Q1. APPEND의 기본 동작으로 가장 적절한 것은?

A. Internal Table의 모든 행을 삭제한다.  
B. Work Area 값을 Internal Table 마지막 줄에 추가한다.  
C. Internal Table을 데이터베이스에 저장한다.  
D. 특정 Key를 기준으로 한 줄을 검색한다.

정답: B

#### Q2. `INSERT ls_data INTO lt_data INDEX 1.`의 의미는?

A. 마지막 줄에 추가한다.  
B. 첫 번째 위치에 삽입한다.  
C. 첫 번째 행을 삭제한다.  
D. 첫 번째 행을 읽는다.

정답: B

#### Q3. APPEND 후 Work Area를 CLEAR하는 이유로 가장 적절한 것은?

A. Internal Table의 모든 데이터가 삭제되기 때문이다.  
B. 다음 행 입력 시 이전 필드 값이 남는 것을 방지하기 위해서이다.  
C. 프로그램을 자동으로 활성화하기 위해서이다.  
D. 데이터베이스 Commit을 수행하기 위해서이다.

정답: B

### 18.2 서술형

#### Q1. APPEND와 INSERT의 차이를 설명하시오.

모범 답안:  
APPEND는 Work Area 값을 Internal Table의 마지막 줄에 추가한다. INSERT는 지정한 위치나 조건에 따라 행을 삽입할 수 있으며, Standard Table에서는 `INDEX`를 사용해 특정 위치에 넣는 방식으로 이해할 수 있다.

#### Q2. Work Area 초기화를 하지 않으면 어떤 문제가 발생할 수 있는가?

모범 답안:  
이전 행에서 사용한 필드 값이 다음 행에 그대로 남아 의도하지 않은 데이터가 추가될 수 있다. 따라서 Work Area를 재사용할 때는 모든 필드를 다시 세팅하거나 `CLEAR`를 사용해야 한다.

#### Q3. APPEND 후 결과를 검증하는 방법을 두 가지 쓰시오.

모범 답안:  
`DESCRIBE TABLE ... LINES ...`로 행 수를 확인하거나, `LOOP AT`으로 전체 데이터를 출력하여 확인할 수 있다.

## 19. 실무 관점 요약

APPEND와 INSERT는 Internal Table을 실제로 “채우는” 첫 번째 단계이다.  
실무에서는 조회 결과를 가공하거나, 파일 업로드 데이터를 담거나, ALV 출력 데이터를 만들 때 매우 자주 사용한다.

다만 초급자는 다음 세 가지를 특히 주의해야 한다.

```text
Work Area 값을 완성한 뒤 APPEND한다.
APPEND 후에는 Work Area 초기화 여부를 확인한다.
INSERT는 행 순서를 바꾸므로 의도적으로 사용한다.
```

## 20. 핵심 요약

```text
APPEND는 Internal Table의 마지막 줄에 데이터를 추가한다.
INSERT INDEX는 Standard Table의 특정 위치에 데이터를 삽입한다.
APPEND와 INSERT는 Work Area의 현재 값을 한 줄로 넣는 방식이다.
Work Area를 반복 사용할 때는 CLEAR를 통해 이전 값 잔존을 방지한다.
행 추가 후에는 DESCRIBE TABLE이나 LOOP AT으로 결과를 검증한다.
```
