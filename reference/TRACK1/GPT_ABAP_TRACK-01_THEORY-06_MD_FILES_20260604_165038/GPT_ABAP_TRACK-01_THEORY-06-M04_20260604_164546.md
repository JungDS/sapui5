## 1. 이 문서의 목적

이 문서는 ABAP 초급자가 Internal Table에 들어 있는 여러 행을 **처음부터 끝까지 순차적으로 읽는 방법**을 이해하도록 돕는다.

앞선 모듈에서 학습자는 다음을 배웠다.

```text
THEORY-06-M01  Internal Table이 필요한 이유
THEORY-06-M02  Line Type / Work Area / STANDARD TABLE 선언
THEORY-06-M03  APPEND와 INSERT 기초
```

이번 모듈에서는 이미 Internal Table에 들어 있는 데이터를 `LOOP AT`으로 한 줄씩 읽는다.

```text
Internal Table에 여러 행을 준비한다.
→ LOOP AT으로 첫 번째 행부터 마지막 행까지 반복한다.
→ INTO로 현재 행을 Work Area에 복사한다.
→ Work Area의 값을 WRITE로 출력한다.
→ 반복이 끝난 뒤 결과를 검증한다.
```

초급자가 반드시 이해해야 할 핵심은 다음 문장이다.

> `LOOP AT ... INTO ...`는 Internal Table의 각 행을 차례대로 Work Area에 복사하여 반복 처리하는 구문이다.

---

## 2. 선수 지식

| 선수 지식 | 필요한 이유 |
|---|---|
| Internal Table | 여러 행 데이터를 메모리에 보관하는 대상이다. |
| Line Type | Internal Table 한 줄의 구조를 정의한다. |
| Work Area | LOOP에서 현재 행을 담는 변수로 사용된다. |
| APPEND | 반복 처리할 테스트 데이터를 미리 넣기 위해 필요하다. |
| WRITE | 반복해서 읽은 값을 화면에 출력해 확인한다. |
| SY-SUBRC | 이번 모듈의 핵심은 아니지만 후속 READ TABLE 학습에서 중요하다. |

이번 모듈은 `READ TABLE`처럼 특정 한 건을 검색하는 주제가 아니다.  
전체 데이터를 순차적으로 읽는 기본 흐름에 집중한다.

---

## 3. LOOP AT이란 무엇인가?

`LOOP AT`은 Internal Table의 데이터를 **행 단위로 반복 처리**하는 ABAP 구문이다.

가장 기본적인 형태는 다음과 같다.

```abap
LOOP AT lt_student INTO ls_student.
  WRITE: / ls_student-id,
           ls_student-name,
           ls_student-score.
ENDLOOP.
```

이 구문은 다음 의미를 가진다.

```text
lt_student Internal Table의 첫 번째 행을 ls_student에 복사한다.
반복문 안의 코드를 실행한다.
두 번째 행을 ls_student에 복사한다.
반복문 안의 코드를 실행한다.
...
마지막 행까지 처리하면 LOOP를 종료한다.
```

초급자는 `LOOP AT`을 다음처럼 이해하면 좋다.

```text
Internal Table = 여러 줄이 있는 엑셀 표
Work Area      = 현재 읽고 있는 한 줄
LOOP AT        = 표의 첫 줄부터 마지막 줄까지 한 줄씩 읽는 작업
```

## 4. LOOP AT의 기본 구조

`LOOP AT`의 기본 구조는 다음과 같다.

```abap
LOOP AT <internal_table> INTO <work_area>.
  " 현재 행에 대한 처리
ENDLOOP.
```

각 요소의 의미는 다음과 같다.

| 요소 | 의미 |
|---|---|
| `LOOP AT` | Internal Table 반복 시작 |
| `<internal_table>` | 반복할 Internal Table |
| `INTO` | 현재 행을 Work Area에 복사한다는 의미 |
| `<work_area>` | 현재 행 값을 담을 변수 |
| `ENDLOOP` | 반복 종료 |

예를 들어 다음 코드를 보자.

```abap
LOOP AT lt_student INTO ls_student.
  WRITE: / ls_student-name.
ENDLOOP.
```

이 코드는 `LT_STUDENT`에 들어 있는 모든 학생을 한 명씩 읽고, 각 학생의 이름을 출력한다.

---

## 5. INTO의 의미

`INTO`는 현재 Internal Table 행의 값을 Work Area로 **복사**한다.

```text
Internal Table의 현재 행
        ↓ 복사
Work Area
```

즉, 다음 구문에서 `LS_STUDENT`는 반복이 진행될 때마다 현재 행의 값으로 바뀐다.

```abap
LOOP AT lt_student INTO ls_student.
  WRITE: / ls_student-id, ls_student-name.
ENDLOOP.
```

### 5.1 Work Area는 매 반복마다 바뀐다

예를 들어 Internal Table에 다음 데이터가 있다고 하자.

| 순서 | ID | NAME | SCORE |
|---:|---:|---|---:|
| 1 | 1 | Kim | 90 |
| 2 | 2 | Lee | 85 |
| 3 | 3 | Park | 95 |

LOOP가 실행되면 Work Area는 다음처럼 변한다.

| 반복 횟수 | `ls_student-id` | `ls_student-name` | `ls_student-score` |
|---:|---:|---|---:|
| 1회차 | 1 | Kim | 90 |
| 2회차 | 2 | Lee | 85 |
| 3회차 | 3 | Park | 95 |

따라서 LOOP 안에서는 Work Area만 보면 현재 처리 중인 행의 값을 알 수 있다.

### 5.2 INTO는 원본 행을 직접 수정하지 않는다

초급자가 가장 많이 하는 오해 중 하나는 다음이다.

```text
LOOP AT ... INTO ... 안에서 Work Area 값을 바꾸면 Internal Table 원본도 자동으로 바뀐다.
```

이것은 올바른 이해가 아니다.

`INTO`는 현재 행을 Work Area에 **복사**한다.  
따라서 Work Area 값을 바꾸는 것만으로 Internal Table 원본 행이 자동 변경되는 것은 아니다.

```abap
LOOP AT lt_student INTO ls_student.
  ls_student-score = ls_student-score + 10.
ENDLOOP.
```

위 코드는 `LS_STUDENT` 값만 변경한다.  
Internal Table의 실제 행을 변경하려면 후속 모듈에서 `MODIFY`, `ASSIGNING`, Field Symbol 같은 별도 주제를 학습해야 한다.

이번 모듈에서는 “읽기와 출력”에 집중한다.

## 6. 기본 예제: 전체 학생 출력

다음 예제는 학생 Internal Table을 만들고 전체 데이터를 출력한다.

```abap
REPORT zgpt_itab_loop_01.

TYPES: BEGIN OF ty_student,
         id    TYPE i,
         name  TYPE c LENGTH 20,
         score TYPE i,
       END OF ty_student.

DATA: lt_student TYPE STANDARD TABLE OF ty_student,
      ls_student TYPE ty_student.

ls_student-id    = 1.
ls_student-name  = 'Kim'.
ls_student-score = 90.
APPEND ls_student TO lt_student.

CLEAR ls_student.
ls_student-id    = 2.
ls_student-name  = 'Lee'.
ls_student-score = 85.
APPEND ls_student TO lt_student.

CLEAR ls_student.
ls_student-id    = 3.
ls_student-name  = 'Park'.
ls_student-score = 95.
APPEND ls_student TO lt_student.

WRITE: / 'ID', 10 'NAME', 35 'SCORE'.
ULINE.

LOOP AT lt_student INTO ls_student.
  WRITE: / ls_student-id,
           10 ls_student-name,
           35 ls_student-score.
ENDLOOP.
```

### 6.1 예상 출력

```text
ID        NAME                         SCORE
------------------------------------------------
1         Kim                          90
2         Lee                          85
3         Park                         95
```

### 6.2 코드 흐름

| 순서 | 설명 |
|---:|---|
| 1 | `TY_STUDENT` Line Type을 정의한다. |
| 2 | `LT_STUDENT` Internal Table을 선언한다. |
| 3 | `LS_STUDENT` Work Area를 선언한다. |
| 4 | Work Area에 학생 한 명의 값을 채운다. |
| 5 | `APPEND`로 Internal Table에 행을 추가한다. |
| 6 | `LOOP AT`으로 모든 행을 반복한다. |
| 7 | 매 반복마다 Work Area 값을 출력한다. |

## 7. LOOP AT과 SY-TABIX

`LOOP AT` 안에서는 시스템 필드 `SY-TABIX`를 통해 현재 처리 중인 행의 인덱스를 확인할 수 있다.

```abap
LOOP AT lt_student INTO ls_student.
  WRITE: / 'Index:', sy-tabix,
           'ID:', ls_student-id,
           'Name:', ls_student-name.
ENDLOOP.
```

예상 출력은 다음과 같다.

```text
Index: 1 ID: 1 Name: Kim
Index: 2 ID: 2 Name: Lee
Index: 3 ID: 3 Name: Park
```

초급 단계에서 `SY-TABIX`는 다음 정도로 이해하면 충분하다.

| 시스템 필드 | 의미 |
|---|---|
| `SY-TABIX` | 현재 Internal Table 반복에서 처리 중인 행 번호 |

다만 실무에서는 `SY-TABIX`에 지나치게 의존하는 코드는 유지보수성이 떨어질 수 있다.  
특히 정렬, 삭제, 필터링, 중첩 LOOP가 들어가면 인덱스 기반 사고가 오류를 만들 수 있다.

이번 모듈에서는 출력 확인용으로만 가볍게 사용한다.

## 8. WHERE 조건을 사용한 LOOP AT 기초

`LOOP AT`에는 조건을 붙여 특정 행만 반복할 수 있다.

```abap
LOOP AT lt_student INTO ls_student WHERE score >= 90.
  WRITE: / ls_student-id,
           ls_student-name,
           ls_student-score.
ENDLOOP.
```

이 코드는 점수가 90점 이상인 학생만 출력한다.

예상 출력:

```text
1 Kim 90
3 Park 95
```

### 8.1 WHERE는 이번 모듈에서 맛보기만 다룬다

`WHERE` 조건은 매우 유용하지만, 이 단계에서 복잡한 조건식을 과도하게 다루지는 않는다.  
이후 `READ TABLE`, Open SQL, Internal Table 응용에서 조건 처리와 검색을 더 자세히 다룬다.

초급자는 다음 정도만 기억한다.

```text
LOOP AT은 전체 행을 반복할 수 있다.
필요하면 WHERE로 일부 행만 반복할 수도 있다.
```

## 9. 빈 Internal Table을 LOOP하면 어떻게 되는가?

Internal Table이 비어 있으면 `LOOP AT` 내부 코드는 실행되지 않는다.

```abap
REPORT zgpt_itab_loop_empty.

TYPES: BEGIN OF ty_student,
         id    TYPE i,
         name  TYPE c LENGTH 20,
       END OF ty_student.

DATA: lt_student TYPE STANDARD TABLE OF ty_student,
      ls_student TYPE ty_student.

WRITE: / 'Before LOOP'.

LOOP AT lt_student INTO ls_student.
  WRITE: / ls_student-id, ls_student-name.
ENDLOOP.

WRITE: / 'After LOOP'.
```

예상 출력:

```text
Before LOOP
After LOOP
```

`LT_STUDENT`가 비어 있기 때문에 LOOP 안의 WRITE는 한 번도 실행되지 않는다.

### 9.1 빈 테이블을 구분하고 싶을 때

초급 단계에서는 `lines( )` 함수를 사용해 행 수를 확인할 수 있다.

```abap
IF lines( lt_student ) = 0.
  WRITE: / 'No student data.'.
ENDIF.
```

또는 LOOP 전에 다음처럼 안내 메시지를 출력할 수 있다.

```abap
IF lt_student IS INITIAL.
  WRITE: / 'Internal table is empty.'.
ENDIF.
```

## 10. LOOP 안에서 IF 사용하기

LOOP는 단순히 출력만 하는 데 그치지 않고, 각 행마다 조건 판단을 수행할 수 있다.

```abap
LOOP AT lt_student INTO ls_student.
  IF ls_student-score >= 90.
    WRITE: / ls_student-name, 'Pass with high score'.
  ELSE.
    WRITE: / ls_student-name, 'Need review'.
  ENDIF.
ENDLOOP.
```

이 구조는 ABAP에서 매우 자주 사용된다.

```text
Internal Table 전체 반복
→ 현재 행의 값 확인
→ 조건에 따라 다른 처리
→ 결과 출력 또는 가공
```

### 10.1 IF와 LOOP의 결합 흐름

| 단계 | 설명 |
|---:|---|
| 1 | LOOP가 현재 학생 한 명을 Work Area에 담는다. |
| 2 | IF가 현재 학생의 점수를 확인한다. |
| 3 | 조건에 맞는 메시지를 출력한다. |
| 4 | 다음 학생으로 넘어간다. |

이 흐름은 후속 모듈의 “Internal Table 기반 미니 데이터 가공”으로 자연스럽게 연결된다.

## 11. 실무에서 LOOP AT을 읽는 방식

실무 ABAP 코드를 읽을 때 `LOOP AT`을 만나면 다음 질문을 해야 한다.

```text
어떤 Internal Table을 반복하고 있는가?
한 줄의 구조는 무엇인가?
현재 행은 어떤 Work Area에 담기는가?
LOOP 안에서 출력만 하는가, 값을 변경하는가?
WHERE 조건이 있는가?
중첩 LOOP가 있는가?
LOOP 안에서 DB SELECT를 수행하는가?
```

초급 단계에서는 특히 마지막 두 질문이 중요하다.

### 11.1 중첩 LOOP 주의

다음과 같은 구조는 데이터가 많아질수록 성능 문제가 발생할 수 있다.

```abap
LOOP AT lt_header INTO ls_header.
  LOOP AT lt_item INTO ls_item.
    " 처리 로직
  ENDLOOP.
ENDLOOP.
```

현재 모듈에서는 성능 튜닝을 다루지 않지만, 실무에서는 중첩 LOOP가 데이터 건수에 따라 매우 느려질 수 있다는 감각을 가져야 한다.

### 11.2 LOOP 안의 SELECT 주의

다음과 같은 코드는 실무에서 자주 문제가 된다.

```abap
LOOP AT lt_student INTO ls_student.
  SELECT SINGLE *
    FROM zt_score
    WHERE id = @ls_student-id
    INTO @DATA(ls_score).
ENDLOOP.
```

이 구조는 Internal Table 행 수만큼 DB를 반복 호출할 수 있다.  
이 문제는 후속 Open SQL, JOIN, FOR ALL ENTRIES, CDS 학습과 연결된다.

이번 모듈에서는 다음 원칙만 기억한다.

> LOOP는 메모리 데이터를 반복하는 구문이고, LOOP 안에서 DB 접근을 반복하면 성능 문제가 커질 수 있다.

## 12. 정상 흐름과 오류 흐름

### 12.1 정상 흐름

```text
Line Type 정의
→ Internal Table 선언
→ Work Area 선언
→ APPEND로 데이터 준비
→ LOOP AT ... INTO ... 실행
→ Work Area 필드 출력
→ ENDLOOP로 반복 종료
```

### 12.2 오류 흐름 1: Work Area 타입 불일치

#### 상황

```abap
DATA ls_other TYPE c LENGTH 10.

LOOP AT lt_student INTO ls_other.
  WRITE: / ls_other.
ENDLOOP.
```

#### 문제

Internal Table의 한 줄 구조와 Work Area 타입이 맞지 않는다.

#### 해결

Internal Table Line Type과 같은 타입의 Work Area를 사용한다.

```abap
DATA ls_student TYPE ty_student.

LOOP AT lt_student INTO ls_student.
  WRITE: / ls_student-id, ls_student-name.
ENDLOOP.
```

### 12.3 오류 흐름 2: ENDLOOP 누락

#### 상황

```abap
LOOP AT lt_student INTO ls_student.
  WRITE: / ls_student-name.
```

#### 문제

`LOOP AT`은 반드시 `ENDLOOP`으로 닫아야 한다.

#### 해결

```abap
LOOP AT lt_student INTO ls_student.
  WRITE: / ls_student-name.
ENDLOOP.
```

### 12.4 오류 흐름 3: Work Area 값을 변경했는데 원본이 바뀐다고 오해

#### 상황

```abap
LOOP AT lt_student INTO ls_student.
  ls_student-score = 100.
ENDLOOP.
```

#### 문제

`INTO`는 행을 Work Area에 복사하므로, Work Area 값을 바꾸는 것만으로 Internal Table 원본이 자동 변경되지 않는다.

#### 해결

이번 모듈에서는 원본 변경을 다루지 않는다.  
후속 학습에서 `MODIFY`, `ASSIGNING`, Field Symbol을 학습할 때 원본 변경 방식을 다룬다.

### 12.5 오류 흐름 4: 빈 테이블인데 출력이 없어서 오류로 착각

#### 상황

LOOP 안의 WRITE가 실행되지 않는다.

#### 원인

Internal Table에 데이터가 없을 수 있다.

#### 해결

LOOP 전에 행 수를 확인한다.

```abap
IF lt_student IS INITIAL.
  WRITE: / 'No data found.'.
ENDIF.
```

### 12.6 오류 흐름 5: LOOP 안에서 불필요하게 CLEAR 사용

#### 상황

```abap
LOOP AT lt_student INTO ls_student.
  CLEAR ls_student.
  WRITE: / ls_student-name.
ENDLOOP.
```

#### 문제

현재 행을 Work Area에 복사한 직후 `CLEAR`하면 출력할 값이 사라진다.

#### 해결

LOOP 안에서 현재 행 값을 사용해야 한다면 불필요하게 Work Area를 초기화하지 않는다.

## 13. 디버깅 관찰 포인트

`LOOP AT`은 디버깅으로 관찰하면 매우 이해하기 쉽다.

### 13.1 디버깅 절차

```text
1. LOOP AT 구문에 Breakpoint 설정
2. 프로그램 실행
3. LT_STUDENT 행 수 확인
4. 첫 번째 반복에서 LS_STUDENT 값 확인
5. F5 또는 F6로 다음 반복 진행
6. 반복마다 LS_STUDENT 값이 바뀌는지 확인
7. SY-TABIX 값 확인
8. ENDLOOP 이후 흐름 확인
```

### 13.2 꼭 확인할 변수

| 변수 | 확인할 내용 |
|---|---|
| `LT_STUDENT` | 전체 Internal Table 데이터 |
| `LS_STUDENT` | 현재 반복 중인 한 줄 데이터 |
| `SY-TABIX` | 현재 반복 중인 행 번호 |
| `SY-SUBRC` | LOOP 자체보다 후속 READ TABLE에서 더 중요함 |

초급자는 디버깅 중 `LS_STUDENT`가 반복마다 바뀌는 장면을 반드시 확인해야 한다.  
이 장면을 보면 Work Area의 역할이 명확해진다.

## 14. 실습 과제

### 14.1 기본 실습

다음 조건을 만족하는 프로그램을 작성한다.

```text
프로그램명: ZGPT_ITAB_LOOP_BASIC
```

|---|---|---|
| ID | I | 학생 ID |

요구사항:

```text

3. APPEND로 세 건의 데이터를 추가한다.
4. LOOP AT ... INTO ... 로 전체 데이터를 출력한다.
5. 출력 시 SY-TABIX도 함께 출력한다.
```

### 14.2 확장 실습

기본 실습을 확장하여 점수가 90점 이상인 학생만 출력한다.

요구사항:

```text
1. LOOP AT ... WHERE score >= 90 사용
2. 출력 결과에 'High Score' 문구 추가
3. 전체 건수와 조건 출력 건수를 비교
```

조건 출력 건수를 세려면 간단한 카운터 변수를 사용할 수 있다.

```abap
DATA gv_high_count TYPE i.

LOOP AT lt_student INTO ls_student WHERE score >= 90.
  gv_high_count = gv_high_count + 1.
  WRITE: / ls_student-name, ls_student-score, 'High Score'.
ENDLOOP.

WRITE: / 'High score count:', gv_high_count.
```

## 15. 미니 종합 예제

```abap
REPORT zgpt_itab_loop_m04.

TYPES: BEGIN OF ty_student,
         id    TYPE i,
         name  TYPE c LENGTH 20,
         score TYPE i,
       END OF ty_student.

DATA: lt_student    TYPE STANDARD TABLE OF ty_student,
      ls_student    TYPE ty_student,
      gv_high_count TYPE i.

ls_student-id    = 1.
ls_student-name  = 'Kim'.
ls_student-score = 90.
APPEND ls_student TO lt_student.

CLEAR ls_student.
ls_student-id    = 2.
ls_student-name  = 'Lee'.
ls_student-score = 85.
APPEND ls_student TO lt_student.

CLEAR ls_student.
ls_student-id    = 3.
ls_student-name  = 'Park'.
ls_student-score = 95.
APPEND ls_student TO lt_student.

WRITE: / '=== All Students ==='.
LOOP AT lt_student INTO ls_student.
  WRITE: / sy-tabix,
           ls_student-id,
           ls_student-name,
           ls_student-score.
ENDLOOP.

SKIP.
WRITE: / '=== High Score Students ==='.
LOOP AT lt_student INTO ls_student WHERE score >= 90.
  gv_high_count = gv_high_count + 1.
  WRITE: / ls_student-name,
           ls_student-score,
           'High Score'.
ENDLOOP.

SKIP.
WRITE: / 'Total count     :', lines( lt_student ),
       / 'High score count:', gv_high_count.
```

### 15.1 예상 결과

```text
=== All Students ===
1 1 Kim 90
2 2 Lee 85
3 3 Park 95

=== High Score Students ===
Kim 90 High Score
Park 95 High Score

Total count     : 3
High score count: 2
```

## 16. 강사용 설명 포인트

강의에서는 다음 순서로 설명하면 학습자가 쉽게 따라온다.

1. Internal Table은 여러 줄 데이터이다.
2. Work Area는 현재 한 줄이다.
3. LOOP AT은 여러 줄을 한 줄씩 읽는 반복문이다.
4. INTO는 현재 행을 Work Area에 복사한다.
5. LOOP 안에서는 Work Area 필드를 기준으로 출력·판단한다.
6. 빈 Internal Table이면 LOOP 안은 실행되지 않는다.
7. Work Area 값을 바꾼다고 원본 Internal Table이 자동 변경되지는 않는다.

특히 다음 질문을 던지면 좋다.

```text
LOOP 2회차에서 LS_STUDENT에는 어떤 값이 들어 있을까요?
INTO는 복사일까요, 참조일까요?
LOOP 안에서 LS_STUDENT를 CLEAR하면 어떤 일이 생길까요?
LT_STUDENT가 비어 있으면 LOOP 안의 WRITE는 실행될까요?
```

## 17. 평가 문제

### 17.1 객관식

#### Q1. `LOOP AT lt_student INTO ls_student.`의 의미로 가장 적절한 것은?

A. `LT_STUDENT`의 모든 행을 삭제한다.  
B. `LT_STUDENT`의 각 행을 차례로 `LS_STUDENT`에 복사하며 반복한다.  
C. `LS_STUDENT`를 DB 테이블에 저장한다.  
D. `LT_STUDENT`의 첫 번째 행만 읽는다.

정답: B

#### Q2. `INTO` 방식에 대한 설명으로 올바른 것은?

A. 현재 행을 Work Area에 복사한다.  
B. Internal Table 원본 행을 직접 참조한다.  
C. 반복문을 종료한다.  
D. 데이터베이스에서 데이터를 조회한다.

정답: A

#### Q3. Internal Table이 비어 있을 때 `LOOP AT` 내부 코드는 어떻게 되는가?

A. 한 번 실행된다.  
B. 무한 반복된다.  
C. 실행되지 않는다.  
D. 항상 Dump가 발생한다.

정답: C

### 17.2 단답형

#### Q1. Work Area의 역할을 설명하시오.

모범 답안:  
Work Area는 Internal Table의 현재 행을 담는 변수이다. `LOOP AT ... INTO ...`에서는 반복이 진행될 때마다 현재 행의 값이 Work Area에 복사된다.

#### Q2. `LOOP AT ... INTO ...` 안에서 Work Area 값을 변경하면 Internal Table 원본이 자동 변경되지 않는 이유는 무엇인가?

모범 답안:  
`INTO`는 현재 행을 Work Area로 복사하는 방식이기 때문이다. 복사본인 Work Area 값을 변경하는 것만으로 Internal Table의 원본 행이 자동 변경되지는 않는다.

#### Q3. LOOP 전에 `IF lt_student IS INITIAL.`을 사용할 수 있는 이유는 무엇인가?

모범 답안:  
Internal Table에 행이 하나도 없는지 확인하여, 빈 테이블일 때 별도의 안내 메시지를 출력하거나 후속 처리를 분기할 수 있기 때문이다.

## 19. 핵심 요약

```text
LOOP AT은 Internal Table의 여러 행을 순차적으로 반복 처리하는 기본 구문이다.
INTO는 현재 행을 Work Area에 복사한다.
Work Area는 반복마다 현재 행의 값으로 바뀐다.
Internal Table이 비어 있으면 LOOP 내부 코드는 실행되지 않는다.
WHERE 조건을 붙이면 일부 행만 반복할 수 있다.
INTO 방식에서 Work Area 값을 바꾼다고 원본 Internal Table이 자동 변경되지는 않는다.
```

초급자는 이번 모듈에서 다음 문장을 반드시 기억해야 한다.

> Internal Table 전체 데이터를 처리할 때는 `LOOP AT`, 현재 한 줄을 다룰 때는 Work Area를 본다.

## 20. 다음 모듈 연결

다음 모듈은 `THEORY-06-M05 — READ TABLE 기본 검색`이다.

이번 모듈은 전체 데이터를 순차적으로 읽는 방법을 다루었다.

```text
LOOP AT
→ 전체 행을 처음부터 끝까지 읽는다.
```

다음 모듈에서는 특정 조건에 맞는 한 건을 찾는 방법을 다룬다.

```text
READ TABLE
→ Internal Table 안에서 특정 Key를 가진 한 줄을 찾는다.
```

따라서 두 구문의 차이를 다음처럼 기억하면 좋다.

| 구문 | 목적 |
|---|---|
| `LOOP AT` | 전체 또는 조건에 맞는 여러 행 반복 처리 |
| `READ TABLE` | 특정 조건의 단건 검색 |
