## 1. 이 문서의 목적

이 문서는 ABAP 초급자가 지금까지 배운 Internal Table 기초 문법을 조합하여 **작은 데이터 가공 프로그램**을 직접 구성할 수 있도록 돕는다.

앞선 모듈에서는 다음을 순서대로 학습했다.

```text
M01 Internal Table이 필요한 이유
M02 Line Type / Work Area / Standard Table 선언
M03 APPEND와 INSERT 기초
M04 LOOP AT으로 전체 데이터 읽기
M05 READ TABLE 기본 검색
M06 Internal Table 기반 미니 데이터 가공
```

이번 모듈은 Section 06의 마무리 단계이다. 단일 구문만 보는 것이 아니라, Internal Table에 데이터를 넣고, 반복 처리하고, 조건에 따라 값을 계산하고, 특정 데이터를 검색한 뒤, 최종 결과를 `WRITE`로 출력하는 흐름을 하나의 작은 프로그램으로 연결한다.

초급자가 반드시 기억해야 할 핵심 문장은 다음이다.

> Internal Table 가공은 “메모리에 올린 여러 행을 반복·검색·계산하여 의미 있는 결과로 바꾸는 과정”이다.

## 2. 선수 지식

| 선수 지식 | 필요한 이유 |
|---|---|
| Internal Table | 여러 행 데이터를 메모리에서 다루는 기본 대상이다. |
| Line Type | Internal Table 한 줄의 구조를 정의한다. |
| Work Area | 한 행을 임시로 담고 처리하는 변수이다. |
| APPEND / INSERT | 테스트 데이터를 Internal Table에 넣기 위해 필요하다. |
| LOOP AT | 전체 데이터를 순회하며 합계, 건수, 조건 판정을 수행한다. |
| READ TABLE | 특정 조건에 맞는 한 행을 검색한다. |
| SY-SUBRC | `READ TABLE` 등 처리 결과의 성공/실패를 판단한다. |
| WRITE | 가공 결과를 List Output으로 확인한다. |

이번 모듈은 새로운 문법을 많이 추가하는 단계가 아니라, 이미 배운 구문을 조합하는 단계이다.

```text
선언
→ 데이터 입력
→ 전체 반복
→ 조건 처리
→ 단건 검색
→ 결과 출력
```

---

## 3. 미니 데이터 가공이란 무엇인가?

Internal Table 기반 데이터 가공은 업무 데이터를 프로그램 내부 메모리에서 처리하는 과정이다.

예를 들어 학생 점수 데이터가 있다고 하자.

| ID | 이름 | 점수 |
|---|---|---:|
| S001 | Kim Beginner | 90 |
| S002 | Lee Trainee | 75 |
| S003 | Park Junior | 82 |
| S004 | Choi Basic | 58 |

이 데이터를 그대로 출력할 수도 있지만, 실무 프로그램에서는 보통 다음과 같은 처리를 한다.

```text
전체 학생 수를 계산한다.
전체 점수 합계를 구한다.
평균 점수를 계산한다.
합격자 수와 불합격자 수를 구분한다.
특정 학생 ID를 검색한다.
최종 결과를 출력한다.
```

이런 흐름이 Internal Table 기반 미니 데이터 가공이다.

## 4. 이번 모듈의 전체 처리 흐름

이번 모듈에서 만들 프로그램의 흐름은 다음과 같다.

```text
1. 학생 데이터 Line Type을 정의한다.
2. Internal Table과 Work Area를 선언한다.
3. APPEND로 테스트 데이터를 입력한다.
4. LOOP AT으로 전체 데이터를 순회한다.
5. 합계, 건수, 합격/불합격 수를 계산한다.
6. READ TABLE로 특정 학생을 검색한다.
7. WRITE로 원본 데이터와 가공 결과를 출력한다.
8. SY-SUBRC로 검색 성공/실패를 분기한다.
```

초급자는 이 흐름을 “작은 Report 프로그램의 기본 골격”으로 이해하면 된다.

```text
점수 60점 이상: PASS
점수 60점 미만: FAIL
```

## 6. 전체 예제 코드

아래 코드는 이번 모듈의 핵심 실습 코드이다. SAP GUI 800의 ABAP Editor 또는 ADT에서 Report 프로그램으로 작성해 실행할 수 있다.

```abap
REPORT zgpt_itab_mini_process.

TYPES: BEGIN OF ty_student,
         id    TYPE c LENGTH 4,
         name  TYPE c LENGTH 20,
         score TYPE i,
       END OF ty_student.

DATA: lt_student TYPE STANDARD TABLE OF ty_student,
      ls_student TYPE ty_student.

DATA: gv_count      TYPE i,
      gv_total      TYPE i,
      gv_average    TYPE p LENGTH 5 DECIMALS 2,
      gv_pass_count TYPE i,
      gv_fail_count TYPE i.

"------------------------------------------------------------
" 1. 테스트 데이터 입력
"------------------------------------------------------------
CLEAR ls_student.
ls_student-id    = 'S001'.
ls_student-name  = 'Kim Beginner'.
ls_student-score = 90.
APPEND ls_student TO lt_student.

CLEAR ls_student.
ls_student-id    = 'S002'.
ls_student-name  = 'Lee Trainee'.
ls_student-score = 75.
APPEND ls_student TO lt_student.

CLEAR ls_student.
ls_student-id    = 'S003'.
ls_student-name  = 'Park Junior'.
ls_student-score = 82.
APPEND ls_student TO lt_student.

CLEAR ls_student.
ls_student-id    = 'S004'.
ls_student-name  = 'Choi Basic'.
ls_student-score = 58.
APPEND ls_student TO lt_student.

"------------------------------------------------------------
" 2. 전체 목록 출력 및 데이터 가공
"------------------------------------------------------------
WRITE: / 'Student List'.
WRITE: / '--------------------------------'.

LOOP AT lt_student INTO ls_student.
  gv_count = gv_count + 1.
  gv_total = gv_total + ls_student-score.

  IF ls_student-score >= 60.
    gv_pass_count = gv_pass_count + 1.
    WRITE: / ls_student-id, ls_student-name, ls_student-score, 'PASS'.
  ELSE.
    gv_fail_count = gv_fail_count + 1.
    WRITE: / ls_student-id, ls_student-name, ls_student-score, 'FAIL'.
  ENDIF.
ENDLOOP.

"------------------------------------------------------------
" 3. 평균 계산
"------------------------------------------------------------
IF gv_count > 0.
  gv_average = gv_total / gv_count.
ENDIF.

WRITE: / '--------------------------------'.
WRITE: / 'Count      :', gv_count.
WRITE: / 'Total Score:', gv_total.
WRITE: / 'Average    :', gv_average.
WRITE: / 'Pass Count :', gv_pass_count.
WRITE: / 'Fail Count :', gv_fail_count.

"------------------------------------------------------------
" 4. 특정 학생 검색
"------------------------------------------------------------
CLEAR ls_student.
READ TABLE lt_student INTO ls_student WITH KEY id = 'S003'.

IF sy-subrc = 0.
  WRITE: / '--------------------------------'.
  WRITE: / 'Search Result'.
  WRITE: / 'ID   :', ls_student-id.
  WRITE: / 'Name :', ls_student-name.
  WRITE: / 'Score:', ls_student-score.
ELSE.
  WRITE: / 'Student not found.'.
ENDIF.
```

## 7. 코드 구조 해설

### 7.1 Line Type 정의

```abap
TYPES: BEGIN OF ty_student,
         id    TYPE c LENGTH 4,
         name  TYPE c LENGTH 20,
         score TYPE i,
       END OF ty_student.
```

이 구문은 학생 데이터 한 줄의 구조를 정의한다.

| 필드 | 타입 | 의미 |
|---|---|---|
| ID | C LENGTH 4 | 학생 ID |
| NAME | C LENGTH 20 | 학생 이름 |
| SCORE | I | 점수 |

초급 단계에서는 로컬 `TYPES`를 사용하지만, 실무에서는 DDIC Structure나 Data Element 기반 타입을 사용하는 경우도 많다.

### 7.2 Internal Table과 Work Area 선언

```abap
DATA: lt_student TYPE STANDARD TABLE OF ty_student,
      ls_student TYPE ty_student.
```

| 변수 | 역할 |
|---|---|
| LT_STUDENT | 여러 학생 데이터를 담는 Internal Table |
| LS_STUDENT | 한 명의 학생 데이터를 임시로 담는 Work Area |

초급자는 다음 구분을 명확히 해야 한다.

```text
LT_ = 여러 줄
LS_ = 한 줄
```

### 7.3 집계용 변수 선언

```abap
DATA: gv_count      TYPE i,
      gv_total      TYPE i,
      gv_average    TYPE p LENGTH 5 DECIMALS 2,
      gv_pass_count TYPE i,
      gv_fail_count TYPE i.
```

이 변수들은 Internal Table 자체에 저장되는 값이 아니라, 반복 처리 중 계산 결과를 담기 위한 보조 변수이다.

| 변수 | 의미 |
|---|---|
| GV_COUNT | 전체 건수 |
| GV_TOTAL | 점수 합계 |
| GV_AVERAGE | 평균 점수 |
| GV_PASS_COUNT | 합격자 수 |
| GV_FAIL_COUNT | 불합격자 수 |

## 8. 데이터 입력 흐름

테스트 데이터를 넣는 기본 패턴은 다음과 같다.

```abap
CLEAR ls_student.
ls_student-id    = 'S001'.
ls_student-name  = 'Kim Beginner'.
ls_student-score = 90.
APPEND ls_student TO lt_student.
```

이 코드는 다음 흐름으로 동작한다.

```text
1. Work Area를 초기화한다.
2. Work Area의 각 필드에 값을 넣는다.
3. APPEND로 Work Area 내용을 Internal Table 마지막 행에 추가한다.
```

초급자가 자주 하는 실수는 `CLEAR`를 생략하고 이전 값이 남은 상태로 다음 행을 만드는 것이다. 이번 예제에서는 모든 필드에 값을 다시 넣고 있지만, 실무 습관으로는 새 행을 만들기 전에 Work Area를 초기화하는 것이 안전하다.

## 9. LOOP AT으로 전체 데이터 가공하기

가장 중요한 가공 구간은 다음이다.

```abap
LOOP AT lt_student INTO ls_student.
  gv_count = gv_count + 1.
  gv_total = gv_total + ls_student-score.

  IF ls_student-score >= 60.
    gv_pass_count = gv_pass_count + 1.
    WRITE: / ls_student-id, ls_student-name, ls_student-score, 'PASS'.
  ELSE.
    gv_fail_count = gv_fail_count + 1.
    WRITE: / ls_student-id, ls_student-name, ls_student-score, 'FAIL'.
  ENDIF.
ENDLOOP.
```

이 구문은 다음을 동시에 수행한다.

| 처리 | 설명 |
|---|---|
| 전체 순회 | Internal Table의 모든 행을 한 줄씩 읽는다. |
| 건수 계산 | 한 줄 읽을 때마다 `GV_COUNT`를 1 증가시킨다. |
| 합계 계산 | 각 학생의 점수를 `GV_TOTAL`에 더한다. |
| 조건 판정 | 점수가 60 이상인지 판단한다. |
| 합격/불합격 카운트 | 조건에 따라 다른 카운터를 증가시킨다. |
| 목록 출력 | 각 행의 처리 결과를 `WRITE`로 출력한다. |

이처럼 `LOOP AT`은 단순 출력뿐 아니라 집계, 조건 분기, 파생 결과 생성의 중심 구문이다.

## 10. 평균 계산 시 주의점

평균은 다음처럼 계산한다.

```abap
IF gv_count > 0.
  gv_average = gv_total / gv_count.
ENDIF.
```

여기서 `IF gv_count > 0` 조건이 중요하다.

만약 Internal Table이 비어 있고 `GV_COUNT = 0`인데 나눗셈을 수행하면 0으로 나누는 오류가 발생할 수 있다. 따라서 평균 계산 전에는 반드시 건수가 0보다 큰지 확인한다.

### 10.1 안전한 계산 습관

```text
합계 계산 전 초기값 확인
건수 계산 후 0 여부 확인
나눗셈 전 분모가 0인지 확인
결과 타입이 소수점을 담을 수 있는지 확인
```

### 10.2 평균 타입을 Packed Number로 둔 이유

```abap
gv_average TYPE p LENGTH 5 DECIMALS 2
```

평균은 소수점이 발생할 수 있으므로 정수 타입 `I`만으로는 충분하지 않다. `P DECIMALS 2`를 사용하면 소수 둘째 자리까지 표현할 수 있다.

## 11. READ TABLE로 특정 데이터 검색하기

Section 06의 M05에서 배운 `READ TABLE`은 이번 미니 프로그램에서도 활용된다.

```abap
CLEAR ls_student.
READ TABLE lt_student INTO ls_student WITH KEY id = 'S003'.

IF sy-subrc = 0.
  WRITE: / 'Search Result'.
  WRITE: / 'ID   :', ls_student-id.
  WRITE: / 'Name :', ls_student-name.
  WRITE: / 'Score:', ls_student-score.
ELSE.
  WRITE: / 'Student not found.'.
ENDIF.
```

이 코드는 다음 의미이다.

```text
LT_STUDENT에서 ID가 S003인 학생을 찾는다.
찾으면 LS_STUDENT에 해당 행을 복사한다.
SY-SUBRC가 0이면 검색 성공이다.
SY-SUBRC가 0이 아니면 검색 실패로 처리한다.
```

### 11.1 검색 성공 흐름

```text
READ TABLE 성공
→ SY-SUBRC = 0
→ Work Area에 검색 결과 존재
→ 결과 출력
```

### 11.2 검색 실패 흐름

```text
READ TABLE 실패
→ SY-SUBRC <> 0
→ Work Area 결과를 신뢰하지 않음
→ 실패 메시지 출력
```

`READ TABLE` 전에 `CLEAR ls_student`를 수행하는 이유는 검색 실패 시 이전 값이 Work Area에 남아 있어도 잘못 출력하지 않기 위함이다.

## 13. 정상 흐름과 오류 흐름

### 13.1 정상 흐름

```text
Line Type 정의
→ Internal Table / Work Area 선언
→ 테스트 데이터 입력
→ LOOP AT 전체 처리
→ 건수·합계·평균 계산
→ READ TABLE 단건 검색
→ SY-SUBRC 확인
→ WRITE 결과 출력
```

### 13.2 오류 흐름 1: Internal Table이 비어 있음

#### 증상

```text
목록 출력이 되지 않는다.
Count가 0이다.
Average가 계산되지 않는다.
```

#### 원인

`APPEND`가 수행되지 않았거나, 데이터를 넣기 전에 Internal Table을 초기화했을 수 있다.

#### 해결

```text
APPEND 수행 여부 확인
디버깅으로 LT_STUDENT 행 수 확인
LINES( lt_student ) 또는 LOOP 진입 여부 확인
```

### 13.3 오류 흐름 2: 평균 계산 오류

#### 증상

0으로 나누기 오류 또는 예상과 다른 평균이 나온다.

#### 원인

건수 0 확인 없이 나눗셈을 수행했거나, 평균 변수 타입이 정수라 소수점이 손실될 수 있다.

#### 해결

```abap
IF gv_count > 0.
  gv_average = gv_total / gv_count.
ENDIF.
```

그리고 평균 변수는 소수 표현이 가능한 타입을 사용한다.

### 13.4 오류 흐름 3: READ TABLE 검색 실패

#### 증상

`Student not found.`가 출력된다.

#### 원인

검색 조건의 ID가 Internal Table에 존재하지 않는다.

#### 해결

```text
Internal Table 입력 데이터 확인
WITH KEY 값 오타 확인
대소문자 및 길이 확인
SY-SUBRC 값 확인
```

### 13.5 오류 흐름 4: Work Area 초기화 누락

#### 증상

검색 실패했는데도 이전 학생 정보가 출력되는 것처럼 보인다.

#### 원인

`READ TABLE` 실패 후 `SY-SUBRC`를 확인하지 않고 Work Area 값을 사용했을 가능성이 있다.

#### 해결

```text
READ TABLE 후 반드시 SY-SUBRC 확인
검색 전 Work Area CLEAR
검색 실패 시 Work Area 값 사용 금지
```

## 14. 디버깅 관찰 포인트

이번 모듈은 디버깅 연습에 매우 좋다. 다음 지점에 Breakpoint를 걸고 값을 관찰한다.

| 위치 | 관찰 대상 |
|---|---|
| APPEND 직후 | `LT_STUDENT` 행 수 증가 여부 |
| LOOP AT 내부 | `LS_STUDENT` 값이 행마다 바뀌는지 |
| 합계 계산 직후 | `GV_TOTAL` 누적 값 |
| IF 조건 내부 | 합격/불합격 분기 여부 |
| 평균 계산 전 | `GV_COUNT`, `GV_TOTAL` 값 |
| READ TABLE 직후 | `SY-SUBRC`, `LS_STUDENT` 값 |

디버깅 시 초급자가 꼭 봐야 하는 것은 다음이다.

```text
Internal Table은 여러 행을 가진다.
LOOP AT은 한 번에 한 행씩 Work Area로 복사한다.
Work Area 값은 반복마다 바뀐다.
누적 변수는 반복이 진행될수록 값이 쌓인다.
READ TABLE 결과는 SY-SUBRC로 판단해야 한다.
```

## 15. 실무 적용 기준

이번 예제는 교육용이지만 실무 프로그램의 기본 축소판이다.

실무에서는 보통 다음 흐름이 자주 등장한다.

```text
DB에서 SELECT로 데이터 조회
→ Internal Table에 저장
→ LOOP AT으로 업무 조건 처리
→ READ TABLE로 보조 데이터 검색
→ 계산 결과 생성
→ ALV, 화면, 파일, 인터페이스로 출력
```

이번 모듈에서는 아직 DB 조회나 ALV를 깊게 다루지 않는다. 하지만 Internal Table 가공 흐름은 이후 거의 모든 ABAP 실무 주제의 기반이 된다.

### 15.1 실무에서 주의할 점

| 주의점 | 설명 |
|---|---|
| 데이터량 | Internal Table이 너무 커지면 메모리와 성능 문제가 생길 수 있다. |
| 중첩 LOOP | 큰 테이블끼리 중첩 반복하면 성능 문제가 커질 수 있다. |
| READ TABLE 반복 사용 | Standard Table에서 반복 검색이 많으면 성능 저하가 발생할 수 있다. |
| SY-SUBRC 확인 | 검색 실패를 정상 데이터처럼 처리하면 오류가 숨어든다. |
| 타입 일관성 | 계산 변수 타입이 부적절하면 값 손실이 생길 수 있다. |

### 15.2 이 단계에서 과도하게 확장하지 않을 내용

다음 내용은 중요하지만 후속 Section에서 다루는 것이 적절하다.

```text
SORTED TABLE / HASHED TABLE 성능 비교
BINARY SEARCH
FIELD-SYMBOLS
LOOP AT ASSIGNING
GROUP BY LOOP
REDUCE / VALUE / FOR 표현식
Open SQL 집계
ALV 표시 제어
```

이번 모듈의 목표는 가장 기본적인 Internal Table 가공 흐름을 안정적으로 익히는 것이다.

## 16. Clean ABAP 관점의 초급 조언

초급 단계에서도 유지보수성을 고려한 습관을 만들면 좋다.

| 기준 | 권장 |
|---|---|
| 변수명 | `lt_student`, `ls_student`, `gv_total`처럼 역할이 보이는 이름 사용 |
| 주석 | 처리 블록의 목적을 설명하되, 코드 그대로 반복 설명하지 않음 |
| 조건 | 합격 기준 같은 값은 의미 있게 표현 |
| 출력 | 계산 결과와 원본 목록을 구분해서 출력 |
| 오류 처리 | 검색 실패, 빈 테이블, 0 나눗셈을 고려 |

예를 들어 다음 주석은 의미가 적다.

```abap
" 점수를 더한다
```

더 나은 주석은 다음과 같다.

```abap
" 전체 평균 계산을 위해 점수를 누적한다.
```

주석은 “무엇을 하는가”보다 “왜 하는가”를 설명할 때 더 가치가 있다.

## 18. 평가 문제

### 18.1 객관식

#### Q1. Internal Table 기반 미니 데이터 가공에 가장 적절한 설명은?

A. DB 테이블을 직접 생성하는 작업이다.  
B. 메모리에 있는 여러 행을 반복·검색·계산하여 결과를 만드는 작업이다.  
C. 화면 레이아웃을 디자인하는 작업이다.  
D. Transport Request를 생성하는 작업이다.

**정답:** B

#### Q2. 평균을 계산하기 전에 `GV_COUNT > 0`을 확인하는 주된 이유는?

A. 출력 색상을 바꾸기 위해서이다.  
B. Work Area를 초기화하기 위해서이다.  
C. 0으로 나누는 오류를 방지하기 위해서이다.  
D. Internal Table을 정렬하기 위해서이다.

**정답:** C

#### Q3. `READ TABLE` 후 반드시 확인해야 하는 시스템 필드는?

A. SY-DATUM  
B. SY-UNAME  
C. SY-SUBRC  
D. SY-INDEX

**정답:** C

### 18.2 단답형

#### Q1. LOOP AT과 READ TABLE의 차이를 설명하시오.

**모범 답안:**  
`LOOP AT`은 Internal Table의 여러 행을 순차적으로 반복 처리하는 구문이고, `READ TABLE`은 조건에 맞는 한 행을 검색하는 구문이다.

#### Q2. Work Area를 CLEAR하는 이유를 설명하시오.

**모범 답안:**  
이전 행의 값이 남아 다음 처리에 영향을 주는 것을 방지하기 위해서이다. 특히 `READ TABLE` 실패 시 이전 값이 남아 있을 수 있으므로 검색 전 초기화하고, 검색 후에는 `SY-SUBRC`를 확인해야 한다.

#### Q3. Internal Table 가공 결과를 WRITE로 출력하는 목적은 무엇인가?

**모범 답안:**  
초급 학습 단계에서 계산 결과와 처리 흐름을 눈으로 확인하기 위한 목적이다. 실무에서는 이후 ALV, 화면, 파일, 인터페이스 등 다양한 출력 대상으로 확장될 수 있다.

## 19. Section 06 종합 정리

THEORY-06은 Internal Table의 가장 기본적인 흐름을 학습하는 Section이다.

```text
Internal Table이 왜 필요한지 이해한다.
Line Type과 Work Area를 선언한다.
APPEND와 INSERT로 데이터를 입력한다.
LOOP AT으로 전체 데이터를 처리한다.
READ TABLE로 특정 데이터를 검색한다.
Loop, Read, Write Result를 조합하여 작은 데이터 가공 프로그램을 만든다.
```

이 Section을 마치면 학습자는 ABAP에서 가장 많이 사용하는 메모리 데이터 처리 방식의 기초를 갖추게 된다.

## 21. 핵심 요약

```text
Internal Table 가공은 여러 행 데이터를 메모리에서 처리하는 ABAP의 핵심 기술이다.

READ TABLE 후에는 SY-SUBRC를 확인해야 한다.
검색 실패 시 Work Area 값을 그대로 믿으면 안 된다.
```
