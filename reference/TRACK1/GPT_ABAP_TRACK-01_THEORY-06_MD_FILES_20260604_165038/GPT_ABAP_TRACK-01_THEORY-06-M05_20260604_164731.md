## 1. 이 문서의 목적

이 문서는 ABAP 초급자가 Internal Table에서 **특정 한 건을 검색하는 기본 방법**을 이해하도록 돕는다.

앞선 모듈에서는 Internal Table에 여러 행을 넣고, `LOOP AT`으로 전체 행을 순차적으로 읽는 방법을 배웠다. 이번 모듈에서는 전체 행을 모두 읽는 것이 아니라, 특정 조건에 맞는 한 줄을 찾는 방법을 학습한다.

```text
Internal Table에 여러 행을 준비한다.
→ 검색할 조건을 정한다.
→ READ TABLE ... WITH KEY로 한 건을 찾는다.
→ 찾은 경우 Work Area에 결과가 들어온다.
→ SY-SUBRC로 성공/실패를 판단한다.
→ 결과를 WRITE로 확인한다.
```

초급자가 반드시 기억해야 할 핵심 문장은 다음이다.

> `READ TABLE ... WITH KEY ... INTO ...`는 Internal Table에서 조건에 맞는 한 행을 찾아 Work Area에 복사하는 기본 구문이다.

---

## 2. 선수 지식

| 선수 지식 | 필요한 이유 |
|---|---|
| Internal Table | 검색 대상이 되는 메모리 테이블이다. |
| Line Type | 검색 결과 한 줄의 구조를 이해하기 위해 필요하다. |
| Work Area | 검색 성공 시 한 행이 복사되는 대상이다. |
| APPEND / INSERT | 검색할 테스트 데이터를 준비하기 위해 필요하다. |
| LOOP AT | 전체 반복과 단건 검색의 차이를 비교하기 위해 필요하다. |
| SY-SUBRC | READ TABLE 성공/실패 판단의 핵심 시스템 필드이다. |

이번 모듈은 `Internal Table 전체 순회`가 아니라 `Internal Table 단건 검색`에 초점을 둔다.

```text
LOOP AT     = 여러 행을 차례대로 처리
READ TABLE  = 조건에 맞는 한 행을 검색
```

---

## 3. READ TABLE이란 무엇인가?

`READ TABLE`은 Internal Table에서 특정 행을 읽는 ABAP 구문이다. 가장 기본적인 형태는 다음과 같다.

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S001'.
```

이 구문은 다음 의미를 가진다.

```text
lt_student Internal Table에서
id 필드 값이 'S001'인 행을 찾는다.
찾으면 해당 행을 ls_student Work Area에 복사한다.
검색 성공 여부는 sy-subrc에 기록된다.
```

기본 구조를 분해하면 다음과 같다.

| 구문 요소 | 의미 |
|---|---|
| READ TABLE | Internal Table에서 한 행을 읽겠다는 명령 |
| lt_student | 검색 대상 Internal Table |
| INTO ls_student | 검색 결과를 담을 Work Area |
| WITH KEY id = 'S001' | 검색 조건 |
| sy-subrc | 검색 성공/실패 결과 확인용 시스템 필드 |

---

## 4. 왜 READ TABLE이 필요한가?

Internal Table에 데이터가 10건, 100건, 1,000건 들어 있을 때 매번 `LOOP AT`으로 전체를 돌면서 원하는 값을 찾을 수도 있다. 하지만 단순히 한 건을 찾는 목적이라면 `READ TABLE`이 더 명확하다.

### 4.1 LOOP AT으로 찾는 방식

```abap
LOOP AT lt_student INTO ls_student.
  IF ls_student-id = 'S001'.
    WRITE: / ls_student-name.
    EXIT.
  ENDIF.
ENDLOOP.
```

위 방식은 동작할 수 있다. 하지만 “한 건 검색”이라는 의도가 코드에 직접적으로 드러나지 않는다.

### 4.2 READ TABLE로 찾는 방식

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S001'.

IF sy-subrc = 0.
  WRITE: / ls_student-name.
ENDIF.
```

이 방식은 Internal Table에서 특정 Key 조건으로 한 건을 찾는다는 의도가 분명하다.

| 방식 | 적합한 상황 |
|---|---|
| LOOP AT | 전체 행을 순차 처리해야 할 때 |
| READ TABLE | 특정 조건에 맞는 한 행을 찾을 때 |

## 5. 기본 예제 데이터 준비

이번 모듈에서는 학생 점수 데이터를 예제로 사용한다.

```abap
REPORT zgpt_itab_read_basic.

TYPES: BEGIN OF ty_student,
         id    TYPE c LENGTH 4,
         name  TYPE c LENGTH 20,
         score TYPE i,
       END OF ty_student.

DATA: lt_student TYPE STANDARD TABLE OF ty_student,
      ls_student TYPE ty_student.

CLEAR ls_student.
ls_student-id    = 'S001'.
ls_student-name  = 'Kim Beginner'.
ls_student-score = 90.
APPEND ls_student TO lt_student.

CLEAR ls_student.
ls_student-id    = 'S002'.
ls_student-name  = 'Lee Trainee'.
ls_student-score = 75.
APPEND ls_student TO lt_student.

CLEAR ls_student.
ls_student-id    = 'S003'.
ls_student-name  = 'Park Junior'.
ls_student-score = 82.
APPEND ls_student TO lt_student.
```

위 코드는 다음 구조를 가진 Internal Table을 만든다.

| ID | Name | Score |
|---|---|---:|
| S001 | Kim Beginner | 90 |
| S002 | Lee Trainee | 75 |
| S003 | Park Junior | 82 |

## 6. READ TABLE WITH KEY 기본 문법

### 6.1 가장 기본 형태

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S002'.
```

의미는 다음과 같다.

```text
lt_student에서 id가 S002인 행을 찾는다.
찾으면 ls_student에 그 행이 복사된다.
```

### 6.2 검색 성공 처리

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S002'.

IF sy-subrc = 0.
  WRITE: / '검색 성공:', ls_student-id, ls_student-name, ls_student-score.
ELSE.
  WRITE: / '검색 실패'.
ENDIF.
```

검색 결과는 `sy-subrc`로 판단한다.

| sy-subrc | 의미 |
|---:|---|
| 0 | 검색 성공 |
| 4 | 조건에 맞는 행을 찾지 못함 |

초급 단계에서는 다음만 기억하면 충분하다.

```text
READ TABLE 후에는 반드시 sy-subrc를 확인한다.
sy-subrc = 0이면 찾았다.
sy-subrc <> 0이면 찾지 못했다.
```

---

## 7. SY-SUBRC의 역할

`SY-SUBRC`는 ABAP에서 여러 명령의 실행 결과를 알려주는 시스템 필드이다. `READ TABLE`에서도 매우 중요하다.

### 7.1 성공 케이스

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S001'.

IF sy-subrc = 0.
  WRITE: / 'Found:', ls_student-name.
ENDIF.
```

`S001` 데이터가 존재하면 `sy-subrc`는 0이 된다.

### 7.2 실패 케이스

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S999'.

IF sy-subrc <> 0.
  WRITE: / 'Student not found.'.
ENDIF.
```

`S999`가 Internal Table에 없으면 `sy-subrc`는 0이 아니다. 일반적인 미검색 상황에서는 4를 기대할 수 있다.

### 7.3 왜 반드시 확인해야 하는가?

`READ TABLE` 실패 후에도 Work Area에는 이전 값이 남아 있을 수 있다. 그래서 `sy-subrc`를 확인하지 않고 Work Area를 바로 사용하면 잘못된 결과를 출력할 수 있다.

나쁜 예:

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S999'.
WRITE: / ls_student-name.
```

좋은 예:

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S999'.

IF sy-subrc = 0.
  WRITE: / ls_student-name.
ELSE.
  WRITE: / 'No matching student.'.
ENDIF.
```

> 실무 기준: `READ TABLE` 직후에는 가능하면 바로 `sy-subrc`를 판단한다. 중간에 다른 구문이 들어오면 `sy-subrc` 값이 다른 명령에 의해 바뀔 수 있다.

## 9. READ TABLE과 Work Area의 관계

`READ TABLE ... INTO ls_student`는 조건에 맞는 행을 Work Area에 복사한다.

```text
Internal Table 한 행
→ Work Area로 복사
→ Work Area의 필드를 사용
```

그림으로 표현하면 다음과 같다.

```text
lt_student
+------+---------------+-------+
| S001 | Kim Beginner  | 90    |
| S002 | Lee Trainee   | 75    |  ← READ TABLE 성공
| S003 | Park Junior   | 82    |
+------+---------------+-------+
              ↓
ls_student
+------+---------------+-------+
| S002 | Lee Trainee   | 75    |
+------+---------------+-------+
```

중요한 점은 `READ TABLE`이 Internal Table의 행을 직접 화면에 출력하는 것이 아니라, 먼저 Work Area로 가져온 뒤 Work Area를 사용하는 방식이라는 점이다.

## 10. WITH KEY의 의미

`WITH KEY`는 어떤 조건으로 행을 찾을지 지정한다.

### 10.1 단일 필드 검색

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S001'.
```

`id` 하나만 조건으로 검색한다.

### 10.2 여러 필드 검색

Line Type에 학급과 학생 ID가 함께 있다면 여러 조건을 사용할 수 있다.

```abap
READ TABLE lt_student INTO ls_student
     WITH KEY class = 'A'
              id    = 'S001'.
```

의미는 다음과 같다.

```text
class가 A이고 id가 S001인 행을 찾는다.
```

여러 필드를 조건으로 사용할 때는 “모든 조건이 일치하는 행”을 찾는다고 이해하면 된다.

### 10.3 존재하지 않는 필드를 KEY로 사용할 수 없음

다음은 잘못된 예이다.

```abap
READ TABLE lt_student INTO ls_student WITH KEY grade = 'A'.
```

Line Type에 `grade` 필드가 없다면 문법 오류가 발생한다.

## 11. 중복 데이터가 있을 때의 동작

`STANDARD TABLE`에 같은 조건을 만족하는 행이 여러 개 있으면, 기본적인 `READ TABLE ... WITH KEY`는 조건에 맞는 첫 번째 행을 읽는 것으로 이해한다.

예를 들어 다음 데이터가 있다고 하자.

| ID | Name | Score |
|---|---|---:|
| S001 | Kim Beginner | 90 |
| S002 | Lee Trainee | 75 |
| S002 | Lee Duplicate | 88 |

다음 구문을 실행하면:

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S002'.
```

일반적으로 먼저 발견된 `S002` 행이 읽힌다.

초급 단계에서는 이 상황을 통해 다음 원칙을 배워야 한다.

```text
READ TABLE로 한 건을 명확히 찾고 싶다면 검색 조건이 유일한지 먼저 생각한다.
```

실무에서는 중복 가능성이 있는 조건으로 단건 검색을 하면 버그가 될 수 있다.

## 12. READ TABLE INDEX 기초

`READ TABLE`은 조건뿐 아니라 행 번호로도 읽을 수 있다.

```abap
READ TABLE lt_student INTO ls_student INDEX 1.
```

이 구문은 Internal Table의 첫 번째 행을 읽는다.

| 구문 | 의미 |
|---|---|
| `READ TABLE ... INDEX 1` | 첫 번째 행 읽기 |
| `READ TABLE ... INDEX 2` | 두 번째 행 읽기 |
| `READ TABLE ... INDEX 999` | 해당 순번이 없으면 실패 |

하지만 초급 실무 관점에서는 `INDEX`보다 `WITH KEY`가 더 의미 있는 검색인 경우가 많다.

| 방식 | 특징 |
|---|---|
| INDEX | 몇 번째 행인지 알고 있을 때 사용 |
| WITH KEY | 특정 업무 조건으로 찾을 때 사용 |

이번 모듈의 핵심은 `WITH KEY`이다. `INDEX`는 보조 개념으로만 이해한다.

## 13. READ TABLE과 SY-TABIX

`READ TABLE`이 성공하면 `sy-tabix`에는 검색된 행의 인덱스가 들어올 수 있다. 특히 `STANDARD TABLE`에서 위치 확인용으로 사용할 수 있다.

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S002'.

IF sy-subrc = 0.
  WRITE: / 'Found at index:', sy-tabix.
ENDIF.
```

초급자는 `sy-tabix`를 다음처럼 이해하면 된다.

```text
sy-tabix = 현재 Internal Table에서 처리 중이거나 찾은 행의 위치를 나타내는 시스템 필드
```

다만 이번 모듈의 핵심 검증 필드는 `sy-subrc`이다. `sy-tabix`는 위치를 확인하는 보조 정보로만 다룬다.

## 14. READ TABLE 사용 시 흔한 실수

### 14.1 sy-subrc를 확인하지 않음

가장 흔한 실수이다.

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S999'.
WRITE: / ls_student-name.
```

검색 실패 후에도 Work Area에는 이전 값이 남아 있을 수 있으므로 반드시 `sy-subrc`를 확인한다.

### 14.2 검색 조건이 유일하지 않음

```abap
READ TABLE lt_student INTO ls_student WITH KEY score = 80.
```

점수가 같은 학생이 여러 명이면 어떤 행이 읽히는지 업무적으로 애매할 수 있다.

### 14.3 필드명을 잘못 입력함

```abap
READ TABLE lt_student INTO ls_student WITH KEY student_id = 'S001'.
```

Line Type에 `student_id`가 없고 `id`만 있다면 문법 오류가 발생한다.

### 14.4 READ TABLE 직후 다른 구문을 먼저 실행함

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S001'.
WRITE: / 'Search executed'.

IF sy-subrc = 0.
  WRITE: / ls_student-name.
ENDIF.
```

`WRITE`가 항상 `sy-subrc`를 변경한다고 단정할 수는 없지만, 실무 습관으로는 `READ TABLE` 직후 곧바로 `sy-subrc`를 확인하는 것이 안전하다.

좋은 습관:

```abap
READ TABLE lt_student INTO ls_student WITH KEY id = 'S001'.
IF sy-subrc = 0.
  WRITE: / ls_student-name.
ENDIF.
```

### 14.5 전체 처리와 단건 검색을 혼동함

모든 학생의 점수를 출력해야 하는데 `READ TABLE`을 쓰면 한 건만 나온다. 전체 처리는 `LOOP AT`이 적합하다.

## 15. 정상 흐름과 오류 흐름

### 15.1 정상 흐름

```text
1. Internal Table 선언
2. Work Area 선언
3. 테스트 데이터 APPEND
4. READ TABLE ... WITH KEY 실행
5. sy-subrc = 0 확인
6. Work Area 값 사용
7. 결과 출력
```

### 15.2 실패 흐름

```text
1. READ TABLE ... WITH KEY 실행
2. 조건에 맞는 행 없음
3. sy-subrc <> 0
4. Work Area를 사용하지 않음
5. 사용자에게 미검색 메시지 출력
```

### 15.3 디버깅 포인트

디버깅 시 다음을 확인한다.

| 확인 항목 | 설명 |
|---|---|
| lt_student 내용 | 검색 대상 데이터가 실제로 들어 있는가? |
| 검색 조건 | `id = 'S002'` 값이 정확한가? |
| sy-subrc | READ TABLE 직후 0인지 4인지 확인 |
| ls_student | 검색 성공 시 의도한 행이 들어왔는가? |
| sy-tabix | 몇 번째 행이 검색되었는가? |

## 16. 실무 적용 기준

### 16.1 READ TABLE이 적합한 경우

| 상황 | 설명 |
|---|---|
| 특정 ID 한 건을 찾을 때 | 예: 사용자 ID, 자재 번호, 문서 번호 |
| 전체 반복 중 보조 테이블에서 매칭 데이터를 찾을 때 | 예: 주문 데이터 처리 중 고객명 조회 |
| 메모리에 이미 올려둔 데이터에서 빠르게 참조할 때 | DB 재조회 대신 Internal Table 검색 |
| 검색 실패 여부에 따라 분기해야 할 때 | `sy-subrc` 기준 분기 |

### 16.2 READ TABLE만으로 부족한 경우

| 상황 | 더 적합한 방식 |
|---|---|
| 조건에 맞는 모든 행을 처리해야 함 | `LOOP AT ... WHERE` 또는 필터링 로직 |
| 대량 데이터에서 반복 검색이 많음 | Sorted/Hashed Table, 적절한 Key 설계 검토 |
| DB에 아직 있는 데이터를 검색해야 함 | Open SQL SELECT 필요 |
| 복잡한 집계가 필요함 | LOOP, COLLECT, Open SQL 집계 등 후속 주제 |

### 16.3 성능 관점의 기본 감각

`STANDARD TABLE`에서 `READ TABLE ... WITH KEY`는 기본적으로 순차 검색에 가까운 방식으로 이해할 수 있다. 데이터가 적으면 문제가 되지 않지만, 데이터가 많고 반복 검색이 많으면 성능 문제가 생길 수 있다.

초급 단계에서는 다음 정도만 기억한다.

```text
데이터가 적고 단순 검색이면 STANDARD TABLE + READ TABLE로 충분하다.
데이터가 많고 검색이 반복되면 Table Type과 Key 설계를 다시 생각해야 한다.
```

`SORTED TABLE`, `HASHED TABLE`, `BINARY SEARCH`, Secondary Key 등은 후속 심화 주제에서 다루는 것이 적절하다.

## 18. 확장 실습

### 18.1 여러 필드 조건 검색

Line Type에 `class` 필드를 추가하고 다음 조건으로 검색해본다.

```abap
READ TABLE lt_student INTO ls_student
     WITH KEY class = 'A'
              id    = 'S001'.
```

확인할 점:

```text
class만 같은 데이터가 여러 건 있을 때와
class + id 조합이 유일할 때의 차이를 이해한다.
```

### 18.2 INDEX 검색 실습

다음 구문을 실행하고 결과를 비교한다.

```abap
READ TABLE lt_student INTO ls_student INDEX 1.
READ TABLE lt_student INTO ls_student INDEX 2.
READ TABLE lt_student INTO ls_student INDEX 999.
```

확인할 점:

```text
존재하는 인덱스는 sy-subrc = 0이다.
존재하지 않는 인덱스는 sy-subrc <> 0이다.
INDEX 검색은 업무 조건 검색과 의미가 다르다.
```

## 19. 평가 문제

### 19.1 객관식

#### Q1. `READ TABLE`의 기본 목적은 무엇인가?

A. Internal Table의 모든 행을 삭제한다.  
B. Internal Table에서 조건에 맞는 한 행을 읽는다.  
C. 데이터베이스 테이블을 생성한다.  
D. Selection Screen을 만든다.

정답: B

#### Q2. `READ TABLE` 후 검색 성공 여부를 확인하는 대표 시스템 필드는 무엇인가?

A. SY-DATUM  
B. SY-UNAME  
C. SY-SUBRC  
D. SY-INDEX

정답: C

#### Q3. 다음 중 좋은 습관은 무엇인가?

A. READ TABLE 후 sy-subrc를 확인하지 않고 Work Area를 바로 사용한다.  
B. 검색 조건이 유일한지 생각하지 않는다.  
C. READ TABLE 직후 sy-subrc를 확인한다.  
D. 모든 전체 출력 로직을 READ TABLE 하나로 처리한다.

정답: C

### 19.2 단답형

#### Q1. `READ TABLE lt_student INTO ls_student WITH KEY id = 'S001'.`의 의미를 설명하시오.

모범 답안:

```text
lt_student Internal Table에서 id 필드 값이 S001인 행을 찾아 ls_student Work Area에 복사한다.
```

#### Q2. 검색 실패 시 Work Area를 바로 사용하면 안 되는 이유를 설명하시오.

모범 답안:

```text
검색 실패 후에도 Work Area에 이전 값이 남아 있을 수 있으므로, sy-subrc를 확인하지 않고 사용하면 잘못된 데이터를 출력할 수 있다.
```

#### Q3. LOOP AT과 READ TABLE의 차이를 설명하시오.

모범 답안:

```text
LOOP AT은 Internal Table의 여러 행을 순차적으로 처리하는 반복 구문이고, READ TABLE은 특정 조건 또는 인덱스에 맞는 한 행을 검색하는 구문이다.
```

## 20. 강사용 설명 포인트

강의 시 다음 흐름으로 설명하면 초급자가 이해하기 쉽다.

```text
1. LOOP AT은 전체를 읽는 것이다.
2. READ TABLE은 한 건을 찾는 것이다.
3. 찾은 결과는 Work Area에 들어간다.
4. 성공 여부는 sy-subrc로 판단한다.
5. sy-subrc 확인 없이 Work Area를 쓰면 위험하다.
```

특히 `sy-subrc`는 이후 Open SQL, AUTHORITY-CHECK, Function Module 호출 등에서도 반복적으로 등장하므로, 이번 모듈에서 습관을 잡아야 한다.

강의 중 추천 질문:

```text
READ TABLE이 실패했는데 Work Area에는 어떤 값이 남아 있을까요?
점수가 80점인 학생이 여러 명이면 READ TABLE은 어떤 행을 가져올까요?
전체 학생을 출력해야 한다면 READ TABLE과 LOOP AT 중 무엇이 적합할까요?
```

## 21. 초급자 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
READ TABLE은 Internal Table에서 한 행을 찾는 구문이다.
WITH KEY는 검색 조건을 지정한다.
INTO는 검색 결과를 Work Area에 복사한다.
READ TABLE 후에는 반드시 sy-subrc를 확인한다.
sy-subrc = 0이면 검색 성공이다.
sy-subrc <> 0이면 검색 실패이며 Work Area를 사용하지 않는 것이 안전하다.
LOOP AT은 전체 처리, READ TABLE은 단건 검색에 적합하다.
```
