## 0. 이 문서의 학습 범위

이 문서는 `THEORY-08-M04 — Internal Table → SALV 미니 리포트`만 다룬다.

앞선 모듈에서 학습자는 `CL_SALV_TABLE=>FACTORY`를 호출하고, `get_functions( )->set_all( )`을 통해 기본 기능을 표시한 뒤 `display( )`로 SALV 화면을 실행하는 최소 흐름을 배웠다. 이번 모듈에서는 그 조각들을 하나의 **실행 가능한 미니 리포트**로 연결한다.

이번 모듈의 핵심은 다음 문장으로 요약할 수 있다.

```text
Open SQL로 데이터를 Internal Table에 담고,
그 Internal Table을 CL_SALV_TABLE로 화면에 출력하는 가장 작은 조회성 리포트를 만든다.
```

이번 모듈에서 다루는 범위는 다음과 같다.

```text
REPORT 기본 구조
→ Selection 조건 최소 적용
→ Open SQL로 표준 테이블 조회
→ 조회 결과를 Internal Table에 저장
→ SALV 객체 생성
→ 기본 Function 활성화
→ DISPLAY 실행
→ 오류/빈 데이터/권한/실무 주의점 점검
```

다음 항목은 이번 모듈에서 깊게 다루지 않는다.

| 제외 항목 | 이유 |
|---|---|
| SALV 컬럼 속성 상세 제어 | 후속 SALV/ALV 심화 범위 |
| Sort, Filter, Layout Variant 상세 | `THEORY-08-M05`에서 범위 분리 관점으로 정리하고, 심화는 뒤에서 다룸 |
| Field Catalog 직접 구성 | Grid ALV 기초 Section의 핵심 내용 |
| Editable ALV | SALV 1차의 목적이 아님 |
| 대량 데이터 성능 튜닝 | Open SQL, Internal Table, ALV 심화에서 단계적으로 다룸 |

## 1. 학습 목표

학습자는 이 모듈을 마친 뒤 다음을 설명하고 수행할 수 있어야 한다.

1. Internal Table이 SALV 출력의 입력 데이터 역할을 한다는 점을 설명할 수 있다.

6. 기본 Function 표시 후 `display( )`를 호출하는 순서를 구현할 수 있다.
7. 초급 조회성 리포트에서 SALV가 적합한 상황을 판단할 수 있다.
8. 후속 Grid ALV, SALV 심화, Report Event 학습과의 연결 지점을 설명할 수 있다.

## 2. 선수 지식

이 모듈은 다음 선수 지식을 전제로 한다.

| 선수 지식 | 필요한 이유 |
|---|---|
| Internal Table | SALV는 일반적으로 Internal Table 데이터를 화면에 표시한다. |
| Open SQL 기본 조회 | DB 테이블에서 데이터를 읽어 Internal Table에 담아야 한다. |
| `SELECT ... INTO TABLE` | 조회 결과를 Internal Table로 받는 핵심 구문이다. |
| Reference Variable | `lo_alv`는 SALV 객체 참조 변수이다. |
| Static Method Call | `CL_SALV_TABLE=>FACTORY`는 클래스의 정적 메서드 호출이다. |
| TRY...CATCH | SALV 생성 과정에서 발생 가능한 예외를 처리한다. |
| WRITE 기본 출력 | SALV와 전통적 리스트 출력의 차이를 비교하는 데 필요하다. |

초급자는 다음 흐름을 머릿속에 그리면 된다.

```text
DB Table
  ↓ SELECT
Internal Table
  ↓ FACTORY
SALV Object
  ↓ DISPLAY
ALV 화면
```

## 3. 미니 리포트란 무엇인가?

여기서 말하는 미니 리포트는 복잡한 화면 제어, 이벤트, 사용자 커맨드 처리 없이 다음만 수행하는 간단한 조회 프로그램이다.

```text
1. 조건을 입력받는다.
2. 데이터를 조회한다.
3. 조회 결과를 표 형태로 보여준다.
```

초급 단계에서는 이 정도 흐름만으로도 실무 리포트의 기본 구조를 경험할 수 있다.

예를 들어 항공사 마스터 정보를 조회하는 리포트를 생각해보자.

```text
사용자 입력: 항공사 코드
조회 대상: SCARR
출력 방식: SALV
```

이 경우 프로그램의 큰 흐름은 다음과 같다.

```text
PARAMETERS p_carrid TYPE scarr-carrid.
SELECT ... FROM scarr INTO TABLE lt_scarr WHERE carrid = p_carrid.
CL_SALV_TABLE=>FACTORY( ... ).
lo_alv->display( ).
```

이번 모듈의 목적은 이 흐름을 단순 복사 코드가 아니라, 각 줄의 책임을 이해하면서 작성하는 것이다.

## 4. SALV 미니 리포트의 표준 구조

SALV 미니 리포트는 보통 다음 구조를 가진다.

| 단계 | 역할 |
|---:|---|
| 1 | REPORT 선언 |
| 2 | Selection Parameter 선언 |
| 3 | Internal Table 선언 또는 Inline Declaration |
| 4 | Open SQL로 데이터 조회 |
| 5 | 조회 결과 없음 처리 |
| 6 | SALV 객체 생성 |
| 7 | 기본 Function 설정 |
| 8 | 화면 출력 |
| 9 | 예외 처리 |

초급 교육에서는 이 구조를 다음처럼 분해해서 이해하는 것이 좋다.

```text
데이터 준비 영역
→ 화면 출력 준비 영역
→ 오류 처리 영역
```

### 4.1 데이터 준비 영역

```abap
SELECT carrid,
       carrname,
       currcode,
       url
  FROM scarr
  WHERE carrid = @p_carrid
  INTO TABLE @DATA(lt_scarr).
```

이 영역은 DB에서 데이터를 읽어 Internal Table에 담는다.

### 4.2 화면 출력 준비 영역

```abap
cl_salv_table=>factory(
  IMPORTING
    r_salv_table = DATA(lo_alv)
  CHANGING
    t_table      = lt_scarr ).
```

이 영역은 Internal Table을 SALV 객체로 감싼다.

### 4.3 화면 실행 영역

```abap
lo_alv->get_functions( )->set_all( abap_true ).
lo_alv->display( ).
```

이 영역은 사용자가 볼 수 있는 ALV 화면을 실행한다.

## 5. 실습 시나리오

### 5.1 업무 요구사항

교육용으로 다음 요구사항을 구현한다.

```text
항공사 코드가 입력되면 SCARR에서 항공사 정보를 조회한다.
조회 결과는 WRITE가 아니라 SALV로 출력한다.
사용자가 기본 Function을 사용할 수 있도록 Function 버튼을 표시한다.
조회 결과가 없으면 메시지를 출력하고 SALV를 실행하지 않는다.
SALV 생성 중 오류가 발생하면 오류 메시지를 출력한다.
```

### 5.2 사용 테이블

이번 실습에서는 SAP 교육 시스템에서 자주 사용되는 표준 항공사 테이블 `SCARR`를 기준으로 설명한다.

| 필드 | 의미 |
|---|---|
| CARRID | 항공사 코드 |
| CARRNAME | 항공사명 |
| CURRCODE | 통화 코드 |
| URL | 항공사 URL |

[추정] 교육 시스템에 따라 `SCARR` 데이터가 없거나 일부 항공사 코드가 다를 수 있다. 데이터가 없는 경우 `SE16N` 또는 ADT Data Preview로 먼저 실제 데이터를 확인한다.

## 6. 전체 예제 코드

다음 예제는 이번 모듈의 기준 코드이다.

```abap
REPORT zjhy_salv_mini_report.

PARAMETERS p_carrid TYPE scarr-carrid.

START-OF-SELECTION.

  SELECT carrid,
         carrname,
         currcode,
         url
    FROM scarr
    WHERE carrid = @p_carrid
    INTO TABLE @DATA(lt_scarr).

  IF lt_scarr IS INITIAL.
    MESSAGE '조회된 항공사 데이터가 없습니다.' TYPE 'S' DISPLAY LIKE 'E'.
    RETURN.
  ENDIF.

  TRY.
      cl_salv_table=>factory(
        IMPORTING
          r_salv_table = DATA(lo_alv)
        CHANGING
          t_table      = lt_scarr ).

      lo_alv->get_functions( )->set_all( abap_true ).

      lo_alv->display( ).

    CATCH cx_salv_msg INTO DATA(lx_salv).
      MESSAGE lx_salv->get_text( ) TYPE 'S' DISPLAY LIKE 'E'.
  ENDTRY.
```

이 코드는 짧지만 초급 학습자가 이해해야 할 핵심 요소를 모두 포함한다.

| 코드 요소 | 역할 |
|---|---|
| `REPORT` | 실행 가능한 Classic ABAP Report 선언 |
| `PARAMETERS` | 사용자 입력값 수신 |
| `START-OF-SELECTION` | 조회 로직 시작 이벤트 |
| `SELECT ... INTO TABLE` | DB 조회 결과를 Internal Table에 저장 |
| `IF lt_scarr IS INITIAL` | 조회 결과 없음 처리 |
| `CL_SALV_TABLE=>FACTORY` | SALV 객체 생성 |
| `get_functions( )->set_all( )` | 기본 Function 표시 |
| `display( )` | SALV 화면 실행 |
| `CATCH cx_salv_msg` | SALV 생성 오류 처리 |

## 7. 코드 상세 해설

### 7.1 REPORT 선언

```abap
REPORT zjhy_salv_mini_report.
```

`REPORT`는 Classic ABAP에서 실행 가능한 리포트 프로그램을 선언한다. 초급자는 `REPORT`를 “이 프로그램은 실행 가능한 ABAP Report이다”라고 시스템에 알려주는 첫 줄로 이해하면 된다.

실무 명명에서는 고객 개발 객체에 `Z` 또는 `Y` 네임스페이스를 사용한다.

```text
ZJHY_SALV_MINI_REPORT
```

이름만 보고 “SALV 미니 리포트”라는 목적이 드러나므로 교육용 예제로 적절하다.

### 7.2 PARAMETERS 선언

```abap
PARAMETERS p_carrid TYPE scarr-carrid.
```

`PARAMETERS`는 Selection Screen에 단일 입력 필드를 만든다. 여기서는 항공사 코드 하나를 입력받는다.

`TYPE scarr-carrid`를 사용했기 때문에 입력 필드는 표준 테이블 필드의 DDIC 속성을 참고한다. 즉, 길이와 타입이 표준 필드와 맞게 구성된다.

### 7.3 START-OF-SELECTION

```abap
START-OF-SELECTION.
```

`START-OF-SELECTION`은 Report에서 본격적인 데이터 처리 로직이 실행되는 이벤트이다. 초급 과정에서는 다음 정도로 이해하면 된다.

```text
입력 화면 처리가 끝난 뒤 실제 조회와 출력이 시작되는 지점
```

이벤트 구조는 Report Event Section에서 더 자세히 다룬다. 이번 모듈에서는 미니 리포트 흐름을 명확히 구분하기 위해 사용한다.

### 7.4 Open SQL 조회

```abap
SELECT carrid,
       carrname,
       currcode,
       url
  FROM scarr
  WHERE carrid = @p_carrid
  INTO TABLE @DATA(lt_scarr).
```

이 구문은 `SCARR` 테이블에서 사용자가 입력한 항공사 코드에 해당하는 데이터를 조회한다.

중요 포인트는 다음이다.

| 요소 | 설명 |
|---|---|
| 필드 목록 지정 | 필요한 필드만 명시적으로 조회한다. |
| `WHERE` | 입력값 기준으로 조회 범위를 제한한다. |
| `@p_carrid` | Host Variable 표시이다. |
| `INTO TABLE` | 결과를 Internal Table로 받는다. |
| `@DATA(lt_scarr)` | 조회 결과 Internal Table을 인라인 선언한다. |

초급자는 `SELECT *`보다 필요한 필드를 명시하는 습관을 먼저 익히는 것이 좋다.

### 7.5 조회 결과 없음 처리

```abap
IF lt_scarr IS INITIAL.
  MESSAGE '조회된 항공사 데이터가 없습니다.' TYPE 'S' DISPLAY LIKE 'E'.
  RETURN.
ENDIF.
```

`lt_scarr IS INITIAL`은 Internal Table에 데이터가 없는지 확인한다.

조회 결과가 없는데도 SALV를 실행하면 빈 화면이 표시된다. 빈 화면도 기술적으로는 오류가 아니지만, 사용자 입장에서는 “프로그램이 제대로 동작했는지” 헷갈릴 수 있다. 그래서 초급 리포트에서는 조회 결과 없음 메시지를 명확히 보여주는 것이 좋다.

`RETURN`은 이후 SALV 생성 로직을 실행하지 않고 현재 처리 흐름을 종료한다.

### 7.6 SALV 객체 생성

```abap
cl_salv_table=>factory(
  IMPORTING
    r_salv_table = DATA(lo_alv)
  CHANGING
    t_table      = lt_scarr ).
```

이 구문은 Internal Table `lt_scarr`를 기준으로 SALV 객체 `lo_alv`를 생성한다.

| 파라미터 | 역할 |
|---|---|
| `r_salv_table` | 생성된 SALV 객체 참조를 반환한다. |
| `t_table` | SALV가 표시할 Internal Table이다. |

초급자가 특히 기억해야 할 점은 `t_table`이 `CHANGING` 파라미터라는 점이다. SALV는 전달받은 Internal Table의 구조를 분석하여 컬럼을 구성한다.

### 7.7 기본 Function 활성화

```abap
lo_alv->get_functions( )->set_all( abap_true ).
```

이 구문은 SALV 화면의 기본 기능 버튼을 표시한다.

초급 리포트에서는 사용자가 최소한 다음과 같은 기능을 사용할 수 있도록 하는 것이 좋다.

```text
정렬
필터
엑스포트
프린트
기본 표시 기능
```

단, 이번 모듈에서는 기능 버튼을 “표시”하는 수준까지만 다룬다. 개별 기능을 세밀하게 제어하는 방법은 후속 심화 과정에서 다룬다.

### 7.8 DISPLAY 실행

```abap
lo_alv->display( ).
```

`display( )`는 SALV 화면을 실제로 보여주는 메서드이다. 이 호출이 없으면 SALV 객체를 생성해도 화면에 표시되지 않는다.

초급자가 자주 하는 실수는 다음이다.

```text
FACTORY 호출까지는 했지만 display( )를 호출하지 않음
```

이 경우 프로그램은 오류 없이 끝날 수 있지만 화면에 아무것도 보이지 않는다.

### 7.9 예외 처리

```abap
CATCH cx_salv_msg INTO DATA(lx_salv).
  MESSAGE lx_salv->get_text( ) TYPE 'S' DISPLAY LIKE 'E'.
```

SALV 생성 과정에서 예외가 발생할 수 있다. 초급 실습에서는 `CX_SALV_MSG`를 잡고 메시지를 출력하는 방식으로 충분하다.

실무에서는 단순 메시지 출력 외에도 로그 기록, 후속 처리 중단, 사용자 안내 메시지 정교화 등을 고려할 수 있다.

## 9. 오류 상황과 점검 방법

### 9.1 조회 결과가 없는 경우

#### 증상

```text
조회된 항공사 데이터가 없습니다.
```

#### 가능한 원인

| 원인 | 설명 |
|---|---|
| 존재하지 않는 CARRID 입력 | `SCARR`에 해당 코드가 없음 |
| 대소문자 문제 | 코드값은 일반적으로 대문자 기준 |
| 교육 시스템 데이터 누락 | 샘플 데이터가 없을 수 있음 |
| WHERE 조건이 너무 제한적 | 입력값이 정확히 맞지 않음 |

#### 해결

```text
SE16N에서 SCARR 데이터를 먼저 확인한다.
존재하는 CARRID를 입력한다.
WHERE 조건을 임시로 제거하고 전체 조회를 테스트한다.
```

### 9.2 SALV 화면이 표시되지 않는 경우

#### 가능한 원인

| 원인 | 설명 |
|---|---|
| `display( )` 호출 누락 | SALV 객체만 만들고 화면 실행을 하지 않음 |
| 조회 결과 없음 | RETURN으로 SALV 생성 전 종료 |
| 예외 발생 | `CX_SALV_MSG`가 발생했을 수 있음 |
| 프로그램 미활성화 | 이전 버전이 실행될 수 있음 |

#### 해결

```text
display( ) 호출 여부 확인
lt_scarr 데이터 존재 여부 디버깅
CATCH 메시지 확인
프로그램 Activate 후 재실행
```

### 9.3 Syntax Error가 발생하는 경우

#### 가능한 원인

| 원인 | 설명 |
|---|---|
| `@` 누락 | 최신 Open SQL에서 Host Variable 표기가 필요함 |
| 괄호 또는 마침표 누락 | ABAP 문장 종료 누락 |
| 변수명 오타 | `lt_scarr`, `lo_alv` 이름 불일치 |
| 릴리스 차이 | 일부 문법이 낮은 릴리스에서 지원되지 않을 수 있음 |

#### 해결

초급자는 에러 메시지를 복사하지 말고 먼저 더블클릭하여 오류 위치를 확인한다. ABAP Editor나 ADT는 대부분 오류 라인을 알려주므로, 해당 줄의 문장 종료와 변수명을 먼저 점검한다.

### 9.4 Function 버튼이 보이지 않는 경우

#### 가능한 원인

| 원인 | 설명 |
|---|---|
| `set_all( )` 호출 누락 | 기본 Function을 활성화하지 않음 |
| 호출 순서 문제 | display 전 설정해야 함 |
| 화면/GUI 차이 | 시스템 환경에 따라 아이콘 표시가 다를 수 있음 |

#### 해결

다음 코드가 `display( )` 전에 있는지 확인한다.

```abap
lo_alv->get_functions( )->set_all( abap_true ).
```

## 11. WRITE 출력과 SALV 출력의 비교

같은 데이터를 `WRITE`로 출력하면 다음처럼 작성할 수 있다.

```abap
LOOP AT lt_scarr INTO DATA(ls_scarr).
  WRITE: / ls_scarr-carrid,
           ls_scarr-carrname,
           ls_scarr-currcode.
ENDLOOP.
```

이 방식은 이해하기 쉽지만, 사용자 기능이 거의 없다. 반면 SALV는 Internal Table을 전달하는 것만으로도 표 형태의 출력과 기본 기능을 제공한다.

| 구분 | WRITE | SALV |
|---|---|---|
| 구현 난이도 | 낮음 | 낮음~중간 |
| 표 형태 출력 | 직접 정렬 필요 | 자동 구성 |
| 정렬/필터 기능 | 직접 구현 필요 | 기본 Function 가능 |
| 사용자 편의성 | 낮음 | 높음 |
| 실무 조회 리포트 적합성 | 단순 테스트용 | 조회성 리포트에 적합 |

초급자는 다음 기준으로 이해하면 된다.

```text
WRITE는 문법 학습과 단순 출력에 좋다.
SALV는 Internal Table 결과를 사용자 친화적인 표로 보여주기에 좋다.
```

## 12. 실무 적용 기준

### 12.1 SALV가 적합한 경우

| 상황 | 이유 |
|---|---|
| 단순 조회성 리포트 | 빠르게 표 형태 출력 가능 |
| Internal Table 결과 확인 | 개발/검증 단계에서 유용 |
| 사용자가 정렬/필터/엑스포트를 원함 | 기본 Function 제공 가능 |
| Editable 기능이 필요 없음 | SALV 1차 범위와 맞음 |
| 복잡한 셀 제어가 필요 없음 | 최소 코드로 충분 |

### 12.2 SALV가 부적합하거나 한계가 있는 경우

| 상황 | 이유 |
|---|---|
| 사용자가 화면에서 데이터를 직접 수정해야 함 | Editable Grid ALV가 더 적합 |
| 셀 단위 색상/스타일 제어가 많음 | Grid ALV 또는 심화 ALV 필요 |
| 복잡한 사용자 커맨드 처리 필요 | 이벤트 설계 필요 |
| 대량 데이터 페이징/성능 제어 필요 | 조회 조건, SQL, ALV 설계 재검토 필요 |
| 저장 가능한 Layout Variant를 체계적으로 관리해야 함 | 심화 범위에서 다룰 주제 |

이번 모듈에서는 SALV의 한계를 세부 구현으로 해결하려고 하지 않는다. 중요한 것은 Simple SALV 1차의 적정 사용 범위를 이해하는 것이다.

## 13. 코드 개선 방향

기준 코드는 학습용으로 단순하다. 실무에서는 다음 개선을 고려할 수 있다.

### 13.1 입력값 필수 처리

```abap
PARAMETERS p_carrid TYPE scarr-carrid OBLIGATORY.
```

항공사 코드를 반드시 입력하도록 하려면 `OBLIGATORY`를 사용할 수 있다. 다만 Selection Screen 심화 검증은 후속 과정에서 더 자세히 다룬다.

### 13.2 전체 조회 허용

실무에서는 입력값이 비어 있으면 전체 조회를 허용할 수도 있다.

```abap
IF p_carrid IS INITIAL.
  SELECT carrid, carrname, currcode, url
    FROM scarr
    INTO TABLE @DATA(lt_scarr).
ELSE.
  SELECT carrid, carrname, currcode, url
    FROM scarr
    WHERE carrid = @p_carrid
    INTO TABLE @lt_scarr.
ENDIF.
```

하지만 초급 과정에서는 변수를 사전에 선언해야 하는 구조와 인라인 선언의 범위 차이가 섞일 수 있으므로, 먼저 단일 조건 조회를 기준으로 익히는 것이 좋다.

### 13.3 메시지 텍스트 관리

실무에서는 하드코딩된 메시지 대신 Message Class를 사용할 수 있다. 하지만 초급 단계에서는 메시지 클래스까지 확장하면 범위가 넓어지므로 단순 메시지로 충분하다.

### 15.2 서술형

#### Q1. SALV 미니 리포트의 기본 흐름을 순서대로 설명하시오.

**모범 답안:**  
Selection Parameter로 조건을 입력받고, Open SQL로 데이터를 조회하여 Internal Table에 담은 뒤, `CL_SALV_TABLE=>FACTORY`로 SALV 객체를 생성한다. 이후 기본 Function을 표시하고 `display( )`를 호출하여 화면에 출력한다.

#### Q2. `display( )` 호출을 누락하면 어떤 현상이 발생할 수 있는가?

**모범 답안:**  
SALV 객체 생성까지는 수행되지만 실제 화면 출력이 실행되지 않으므로 사용자는 결과 화면을 보지 못한다. 프로그램이 오류 없이 종료되는 것처럼 보일 수 있어 초급자가 원인을 혼동할 수 있다.

#### Q3. `lt_scarr IS INITIAL`을 확인하는 이유를 설명하시오.

**모범 답안:**  
조회 결과가 없는 경우 빈 SALV 화면을 보여주는 대신 사용자에게 데이터가 없음을 명확히 안내하고, 불필요한 SALV 생성 및 화면 실행을 피하기 위해서이다.

SALV는 SELECT를 대신하지 않는다.

## 17. 실무 안티패턴

### 17.1 `SELECT *` 남용

학습 초기에는 편해 보이지만, 실무에서는 필요한 필드만 명시하는 습관이 중요하다.

```abap
SELECT * FROM scarr INTO TABLE @DATA(lt_scarr). "초급 실습에서는 가능하지만 습관화는 비권장
```

권장 형태는 다음과 같다.

```abap
SELECT carrid, carrname, currcode, url
  FROM scarr
  INTO TABLE @DATA(lt_scarr).
```

### 17.2 조회 결과 없음 처리 누락

데이터가 없을 때 빈 화면만 보여주면 사용자는 조건이 잘못된 것인지, 프로그램 오류인지 판단하기 어렵다.

### 17.3 예외 처리 누락

SALV 예제에서 `TRY...CATCH`를 생략하면 코드는 짧아지지만, 오류 상황을 학습하기 어렵다.

### 17.4 SALV로 모든 ALV 요구사항을 해결하려고 함

SALV는 빠르고 간단한 조회성 리포트에 적합하다. 하지만 Editable, 복잡한 이벤트, 셀 단위 제어가 필요하면 Grid ALV나 다른 UI 기술을 검토해야 한다.

## 19. 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
SALV 미니 리포트는 Open SQL 조회 결과를 Internal Table에 담고,

```

반드시 기억할 문장은 다음과 같다.

```text
SELECT는 데이터를 준비하고,
Internal Table은 결과를 담고,
SALV는 그 결과를 사용자에게 보여준다.
```

초급자가 이번 모듈을 제대로 이해했다면 다음 코드를 보고 전체 흐름을 설명할 수 있어야 한다.

```abap
cl_salv_table=>factory(
  IMPORTING r_salv_table = DATA(lo_alv)
  CHANGING  t_table      = lt_scarr ).

lo_alv->get_functions( )->set_all( abap_true ).
lo_alv->display( ).
```
