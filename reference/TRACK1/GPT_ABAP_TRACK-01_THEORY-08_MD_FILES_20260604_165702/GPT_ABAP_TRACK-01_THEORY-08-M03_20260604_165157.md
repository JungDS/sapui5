## 0. 이 문서의 학습 범위

이 문서는 `THEORY-08-M03 — 기본 Function 표시와 Display 실행`만 다룬다.

앞선 모듈에서 학습자는 `CL_SALV_TABLE=>FACTORY`를 이용하여 Internal Table을 SALV 객체로 변환하고, `DISPLAY`로 화면에 출력하는 최소 흐름을 익혔다. 이번 모듈에서는 그 결과 화면이 단순히 “보이는 것”에서 끝나지 않고, 사용자가 기본 기능을 사용할 수 있도록 **Functions Basic**을 표시하는 방법을 학습한다.

→ 기본 Function 표시

## 3. DISPLAY의 역할

### 3.1 DISPLAY는 최종 출력 실행 메서드이다

SALV 객체를 생성했다고 해서 화면이 바로 표시되지는 않는다.

일반 흐름은 다음과 같다.

```abap
cl_salv_table=>factory(
  IMPORTING
    r_salv_table = DATA(lo_alv)
  CHANGING
    t_table      = lt_flight ).

lo_alv->display( ).
```

`FACTORY`는 SALV 객체를 준비하는 단계이고, `display( )`는 준비된 SALV 객체를 실제 화면에 표시하는 단계이다.

따라서 초급자는 다음 순서를 명확히 구분해야 한다.

```text
FACTORY = SALV 객체 생성
DISPLAY = SALV 화면 출력
```

### 3.2 DISPLAY 전에 설정을 끝내야 한다

SALV 화면의 기능 버튼, 컬럼 속성, 제목, 표시 옵션은 일반적으로 `display( )` 호출 전에 설정한다.  
`display( )`가 호출되면 화면 표시가 시작되므로, 그 뒤의 설정 코드는 사용자가 화면을 닫은 이후에 실행될 수 있다.

나쁜 예는 다음과 같다.

```abap
lo_alv->display( ).
lo_alv->get_functions( )->set_all( abap_true ). "의도한 시점에 반영되지 않을 수 있음
```

좋은 예는 다음과 같다.

```abap
lo_alv->get_functions( )->set_all( abap_true ).
lo_alv->display( ).
```

핵심은 다음이다.

```text
표시 전 설정
→ display( )
```

## 4. SALV 기본 Function이란 무엇인가?

SALV의 Function은 사용자가 출력 화면에서 사용할 수 있는 기본 조작 기능을 의미한다.

예를 들면 다음과 같은 기능이다.

| 기능 유형 | 초급자 관점의 의미 |
|---|---|
| Sort | 화면에서 데이터를 정렬한다. |
| Filter | 조건에 맞는 데이터만 표시한다. |
| Find | 화면 내 값을 검색한다. |
| Export | 결과를 스프레드시트 등으로 내보낼 수 있다. |
| Print | 리스트를 출력한다. |
| Layout 관련 기능 | 표시 형식을 조정한다. 단, 상세는 후속 범위이다. |

[추정] 실제 표시되는 버튼 구성은 SAP GUI 버전, 권한, 시스템 설정, SALV 표시 모드, 프로그램 실행 환경에 따라 약간 달라질 수 있다.

이번 모듈에서는 각각의 기능을 깊게 커스터마이징하지 않는다.  
목표는 **기본 기능이 화면에 표시되도록 설정하는 것**이다.

## 5. get_functions( )와 set_all( )

### 5.1 get_functions( )의 역할

`get_functions( )`는 SALV 테이블 객체에서 기능 관리 객체를 가져오는 메서드이다.

```abap
DATA(lo_functions) = lo_alv->get_functions( ).
```

또는 다음처럼 한 줄로 사용할 수도 있다.

```abap
lo_alv->get_functions( )->set_all( abap_true ).
```

초급 교육에서는 처음에는 분리해서 쓰는 편이 이해하기 쉽다.

```abap
DATA(lo_functions) = lo_alv->get_functions( ).
lo_functions->set_all( abap_true ).
```

### 5.2 set_all( )의 역할

`set_all( )`은 SALV의 기본 Function을 전체적으로 활성화하는 데 사용한다.

```abap
lo_functions->set_all( abap_true ).
```

의미는 다음과 같다.

```text
SALV 화면에서 사용할 수 있는 표준 기본 기능들을 표시한다.
```

일부 구버전 또는 시스템 스타일에서는 다음 상수를 사용하는 예도 볼 수 있다.

```abap
lo_functions->set_all( if_salv_c_bool_sap=>true ).
```

S/4HANA 기반 현대 ABAP 문맥에서는 `abap_true`를 사용하는 예제가 이해하기 쉽다.

## 6. 최소 예제 코드

### 6.1 표준 테이블 조회 후 SALV 출력

다음 예제는 `SFLIGHT` 표준 교육 테이블을 조회하여 SALV로 표시하고, 기본 Function을 활성화한다.

```abap
REPORT zgpt_salv_functions_basic.

SELECT carrid,
       connid,
       fldate,
       price,
       currency
  FROM sflight
  INTO TABLE @DATA(lt_flight)
  UP TO 30 ROWS.

IF lt_flight IS INITIAL.
  WRITE: / 'No flight data found.'.
  RETURN.
ENDIF.

TRY.
    cl_salv_table=>factory(
      IMPORTING
        r_salv_table = DATA(lo_alv)
      CHANGING
        t_table      = lt_flight ).

    DATA(lo_functions) = lo_alv->get_functions( ).
    lo_functions->set_all( abap_true ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO DATA(lx_salv).
    WRITE: / 'SALV display error:',
             lx_salv->get_text( ).
ENDTRY.
```

### 6.2 코드 흐름 해석

| 코드 | 의미 |
|---|---|
| `SELECT ... INTO TABLE` | DB에서 데이터를 읽어 Internal Table에 저장 |
| `IF lt_flight IS INITIAL` | 조회 결과가 없는 경우 메시지 출력 |
| `cl_salv_table=>factory` | SALV 객체 생성 |
| `r_salv_table = DATA(lo_alv)` | 생성된 SALV 객체 참조를 받음 |
| `t_table = lt_flight` | 출력 대상 Internal Table 전달 |
| `get_functions( )` | 기능 관리 객체 획득 |
| `set_all( abap_true )` | 기본 Function 표시 |
| `display( )` | SALV 화면 실행 |
| `CATCH cx_salv_msg` | SALV 생성/표시 관련 예외 처리 |

초급자는 이 코드에서 다음 한 줄의 위치를 반드시 기억해야 한다.

```abap
lo_functions->set_all( abap_true ).
```

이 코드는 `display( )`보다 먼저 호출되어야 한다.

## 7. DATA(lo_functions)를 분리해서 쓰는 이유

다음 두 코드는 기능적으로 비슷한 흐름을 가진다.

### 7.1 한 줄 작성

```abap
lo_alv->get_functions( )->set_all( abap_true ).
```

### 7.2 분리 작성

```abap
DATA(lo_functions) = lo_alv->get_functions( ).
lo_functions->set_all( abap_true ).
```

초급 교육에서는 분리 작성이 더 좋다.

| 이유 | 설명 |
|---|---|
| 디버깅이 쉽다 | `lo_functions`가 정상 생성되었는지 확인 가능 |
| 객체 흐름 이해 | SALV 객체와 Function 객체를 구분할 수 있음 |
| 후속 확장 가능 | 나중에 특정 기능만 제어할 때 구조가 자연스럽다 |
| 가독성 | 한 줄 체이닝보다 초급자가 읽기 쉽다 |

실무에서는 팀 컨벤션과 코드 복잡도에 따라 선택한다.

## 8. DISPLAY 실행 위치와 프로그램 흐름

### 8.1 display( )는 사용자 화면 표시를 시작한다

`display( )`는 단순한 계산 메서드가 아니라, SAP GUI에 출력 화면을 표시하는 메서드이다.  
따라서 사용자가 ALV 화면을 보고 뒤로가기 또는 종료를 하기 전까지 프로그램 흐름이 화면 표시 상태에 머문다고 이해하면 된다.

예제:

```abap
WRITE: / 'Before SALV'.

lo_alv->display( ).

WRITE: / 'After SALV'.
```

이 코드를 실행하면 `display( )` 호출 이후 SALV 화면이 표시된다.  
그 이후의 `WRITE` 결과는 사용자가 ALV 화면을 빠져나온 뒤의 리스트 처리 흐름과 연결될 수 있으므로, 초급 단계에서는 `display( )` 이후에 중요한 출력 로직을 배치하지 않는 편이 좋다.

### 8.2 권장 구조

Simple SALV 리포트의 기본 구조는 다음과 같다.

```text
1. 데이터 조회
2. 데이터 존재 여부 확인
3. SALV 객체 생성
4. Function/표시 속성 설정
5. DISPLAY 호출
6. 예외 처리
```

## 9. 빈 Internal Table 처리

SALV는 빈 Internal Table도 표시할 수 있지만, 초급 교육에서는 데이터가 없는 상황을 명시적으로 처리하는 편이 좋다.

```abap
IF lt_flight IS INITIAL.
  MESSAGE 'No data found.' TYPE 'S' DISPLAY LIKE 'E'.
  RETURN.
ENDIF.
```

또는 단순히 다음처럼 출력할 수도 있다.

```abap
IF lt_flight IS INITIAL.
  WRITE: / 'No data found.'.
  RETURN.
ENDIF.
```

### 9.1 왜 빈 테이블을 먼저 확인하는가?

| 이유 | 설명 |
|---|---|
| 사용자 경험 | 빈 ALV 화면보다 명확한 메시지가 이해하기 쉽다. |
| 디버깅 | 데이터 조회 문제인지 SALV 표시 문제인지 구분 가능 |
| 교육 효과 | SELECT 결과 확인 습관을 만든다. |
| 실무 안정성 | 조회 조건이 잘못된 경우 빠르게 파악 가능 |

## 10. TRY...CATCH 처리

`CL_SALV_TABLE=>FACTORY`는 예외를 발생시킬 수 있다.  
따라서 최소 예제에서도 `TRY...CATCH`를 사용하는 것이 좋다.

```abap
TRY.
    cl_salv_table=>factory(
      IMPORTING
        r_salv_table = DATA(lo_alv)
      CHANGING
        t_table      = lt_flight ).

    lo_alv->get_functions( )->set_all( abap_true ).
    lo_alv->display( ).

  CATCH cx_salv_msg INTO DATA(lx_salv).
    WRITE: / lx_salv->get_text( ).
ENDTRY.
```

### 10.1 초급자에게 TRY...CATCH를 보여주는 이유

| 이유 | 설명 |
|---|---|
| 객체 기반 API 이해 | SALV는 클래스 기반 API이다. |
| 오류 흐름 분리 | 정상 표시와 오류 처리를 구분한다. |
| 실무 습관 | 예외를 무시하지 않는 습관을 만든다. |
| 디버깅 도움 | 오류 메시지를 화면에 표시할 수 있다. |

## 11. 실습: 기본 Function이 표시되는 SALV 만들기

### 11.1 실습 목표

`SFLIGHT` 데이터를 조회하여 SALV로 출력하고, 기본 Function 버튼을 표시한다.

### 11.2 실습 코드

```abap
REPORT zgpt_salv_m03_basic_func.

SELECT carrid,
       connid,
       fldate,
       price,
       currency
  FROM sflight
  INTO TABLE @DATA(lt_flight)
  UP TO 50 ROWS.

IF lt_flight IS INITIAL.
  WRITE: / 'No data found in SFLIGHT.'.
  RETURN.
ENDIF.

TRY.
    cl_salv_table=>factory(
      IMPORTING
        r_salv_table = DATA(lo_alv)
      CHANGING
        t_table      = lt_flight ).

    DATA(lo_functions) = lo_alv->get_functions( ).
    lo_functions->set_all( abap_true ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO DATA(lx_salv).
    WRITE: / 'SALV error:', lx_salv->get_text( ).
ENDTRY.
```

### 11.3 실행 결과 확인

실행 후 다음을 확인한다.

| 확인 항목 | 확인 내용 |
|---|---|
| 데이터 표시 | `SFLIGHT` 조회 결과가 리스트 형태로 보이는가 |
| Function 표시 | 화면 상단에 기본 기능 버튼이 보이는가 |
| 정렬/필터 가능 여부 | 사용자 조작으로 기본 정렬 또는 필터 기능을 사용할 수 있는가 |
| 예외 없음 | `CX_SALV_MSG` 오류 메시지가 출력되지 않는가 |
| 빈 데이터 처리 | 조회 결과가 없을 때 명확한 메시지가 표시되는가 |

## 12. 오류 상황과 점검 방법

### 12.1 Function 버튼이 보이지 않는다

가능한 원인:

| 원인 | 점검 |
|---|---|
| `set_all( )` 호출 누락 | `lo_functions->set_all( abap_true )`가 있는지 확인 |
| `display( )` 이후에 설정 | Function 설정이 `display( )`보다 먼저 있는지 확인 |
| 다른 화면 모드/권한 영향 | 시스템/GUI 환경 차이 확인 |
| 예제 코드 일부 누락 | `get_functions( )` 호출 여부 확인 |

### 12.2 ALV 화면이 나타나지 않는다

가능한 원인:

| 원인 | 점검 |
|---|---|
| `display( )` 호출 누락 | `lo_alv->display( )`가 있는지 확인 |
| `FACTORY` 예외 발생 | `CATCH cx_salv_msg` 메시지 확인 |
| 프로그램이 중간에 RETURN | 빈 테이블 처리 조건 확인 |
| Syntax Error | 활성화 전 문법 오류 확인 |

### 12.3 데이터가 없다

가능한 원인:

| 원인 | 점검 |
|---|---|
| SFLIGHT 데이터 없음 | 교육 시스템에 데모 데이터가 있는지 확인 |
| WHERE 조건 과도 | 조건을 줄이고 다시 조회 |
| 다른 Client | 현재 로그인 Client의 데이터 확인 |
| 권한 부족 | 데이터 조회 권한 확인 |

### 12.4 프로그램은 실행되지만 기대한 기능이 없다

초급자는 다음 순서로 확인한다.

```text
1. SELECT 결과가 있는가?
2. FACTORY가 정상 수행되었는가?
3. get_functions( )를 호출했는가?
4. set_all( abap_true )를 호출했는가?
5. display( )가 마지막 표시 단계에 있는가?
```

## 13. 실무 적용 기준

### 13.1 SALV를 사용하기 좋은 경우

| 상황 | 이유 |
|---|---|
| 조회성 리포트 | 빠르게 리스트 화면을 만들 수 있다. |
| Internal Table 결과 확인 | 데이터 가공 결과를 즉시 시각화할 수 있다. |
| 교육용/분석용 프로그램 | Grid ALV보다 코드가 간단하다. |
| 편집이 필요 없는 리스트 | Simple SALV의 목적과 잘 맞는다. |
| 빠른 PoC | 짧은 시간에 결과 화면을 만들 수 있다. |

### 13.2 SALV만으로 부족한 경우

| 상황 | 이유 |
|---|---|
| 사용자가 셀을 직접 수정해야 함 | SALV 1차 범위가 아님 |
| 셀 색상/스타일 제어가 중요함 | Grid ALV 심화로 가야 함 |
| 이벤트 처리가 복잡함 | OO ALV/Grid ALV 검토 필요 |
| Field Catalog를 세밀하게 제어해야 함 | Grid ALV가 더 적합할 수 있음 |
| Layout Variant를 본격적으로 관리해야 함 | 후속 심화 범위 |

초급 단계에서는 다음 기준을 기억한다.

```text
빠르게 보여주는 조회성 리스트 → SALV
복잡한 제어와 편집 중심 화면 → Grid ALV 또는 별도 UI 검토
```

## 14. 성능과 운영 관점의 주의사항

### 14.1 SALV가 성능 문제를 자동으로 해결하지 않는다

SALV는 출력 도구이다.  
데이터를 얼마나 가져올지, 어떤 조건으로 조회할지는 개발자가 결정한다.

나쁜 예:

```abap
SELECT *
  FROM sflight
  INTO TABLE @DATA(lt_flight).
```

실습에서는 허용될 수 있지만, 실무에서는 조건 없이 대량 데이터를 가져오면 성능 문제가 생길 수 있다.

좋은 습관:

```abap
SELECT carrid,
       connid,
       fldate,
       price,
       currency
  FROM sflight
  WHERE carrid = 'AA'
  INTO TABLE @DATA(lt_flight)
  UP TO 100 ROWS.
```

### 14.2 필요한 필드만 조회한다

`SELECT *`는 초급 예제에서는 편하지만, 실무에서는 필요한 필드만 명시하는 습관이 좋다.

| 방식 | 평가 |
|---|---|
| `SELECT *` | 빠른 테스트에는 편하지만 실무에서는 주의 |
| 필드 명시 | 의도가 명확하고 불필요한 데이터 이동을 줄임 |

### 14.3 사용자에게 보여줄 데이터량을 제한한다

SALV가 리스트를 예쁘게 보여줘도 수십만 건을 한 번에 표시하면 사용자와 시스템 모두에게 부담이 된다.  
초급 예제에서는 `UP TO 50 ROWS`처럼 제한을 두는 것이 안전하다.

## 15. 디버깅 포인트

실습 중 문제가 생기면 다음 지점에 Breakpoint를 걸어 확인한다.

| 위치 | 확인할 내용 |
|---|---|
| SELECT 직후 | `lt_flight`에 데이터가 들어왔는가 |

| display 직전 | 화면 표시 전 모든 설정이 완료되었는가 |
| CATCH 블록 | `lx_salv->get_text( )` 메시지가 무엇인가 |

ABAP Debugger에서 참조 변수를 확인할 때는 `lo_alv IS BOUND` 여부를 보는 습관이 좋다.

## 16. 초급자 오해 정리

### 오해 1. `FACTORY`를 호출하면 화면이 자동으로 뜬다

아니다.  
`FACTORY`는 SALV 객체를 생성하는 단계이고, 화면 출력은 `display( )`가 담당한다.

### 오해 2. `display( )` 뒤에 기능을 설정해도 된다

일반적으로 권장하지 않는다.  
표시 전 설정을 마친 뒤 `display( )`를 호출해야 한다.

### 오해 3. `set_all( )`은 데이터를 조회하는 기능이다

아니다.  
`set_all( )`은 SALV 화면의 기본 Function을 표시하는 기능이다. 데이터 조회는 Open SQL이 담당한다.

### 오해 4. SALV를 쓰면 대량 데이터도 자동으로 안전하다

아니다.  
SALV는 출력 도구일 뿐이다. 조회 조건과 데이터량 제어는 개발자가 책임져야 한다.

### 오해 5. SALV 1차에서 모든 ALV 기능을 다 배워야 한다

아니다.  
이번 Section은 Simple SALV 1차이다. Sort/Filter/Layout/Variant 심화, Grid ALV Field Catalog, Cell Style 등은 후속 과정에서 다룬다.

## 18. 평가 문제

### 18.1 객관식

#### Q1. SALV에서 실제 화면 표시를 수행하는 메서드는 무엇인가?

A. `factory( )`  
B. `get_functions( )`  
C. `set_all( )`  
D. `display( )`

정답: D

#### Q2. 기본 Function을 전체적으로 표시하기 위해 사용하는 메서드는?

A. `set_all( )`  
B. `display( )`  
C. `append( )`  
D. `select( )`

정답: A

#### Q3. 다음 중 권장되는 호출 순서는?

A. `display( )` → `set_all( )`  
B. `set_all( )` → `display( )`  
C. `display( )` → `factory( )`  
D. `set_all( )` → `select( )`

정답: B

### 18.2 단답형

#### Q1. `get_functions( )`의 목적을 설명하시오.

모범 답안:  
SALV 테이블 객체에서 화면 Function을 관리하는 객체를 가져오기 위한 메서드이다. 이 객체를 통해 기본 기능 표시 여부를 설정할 수 있다.

#### Q2. `display( )`를 호출하기 전에 Function을 설정해야 하는 이유는 무엇인가?

모범 답안:  
`display( )`는 SALV 화면을 실제로 표시하는 단계이므로, 화면에 반영할 기능과 표시 속성은 일반적으로 표시 전에 설정해야 한다.

#### Q3. SALV가 성능을 자동으로 해결하지 않는 이유는 무엇인가?

모범 답안:  
SALV는 조회 결과를 표시하는 출력 도구일 뿐이다. 어떤 데이터를 얼마나 조회할지는 Open SQL과 개발자의 조회 조건 설계에 달려 있다.
