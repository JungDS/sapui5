## 2. 선수 지식

SALV를 배우기 전에 다음 개념이 필요하다.

| 선수 개념 | 필요한 이유 |
|---|---|
| Internal Table | SALV는 일반적으로 Internal Table 데이터를 출력한다. |
| Structure / Line Type | Internal Table 한 줄의 필드 구조가 ALV 컬럼이 된다. |
| SELECT INTO TABLE | DB 데이터를 Internal Table에 담은 뒤 SALV로 보여줄 수 있다. |
| TRY...CATCH | SALV 객체 생성 시 예외 처리를 이해해야 한다. |
| Class / Static Method 기초 | `CL_SALV_TABLE=>FACTORY`는 클래스 메서드 호출 형태이다. |

이 Section은 초급자에게 ALV를 처음 보여주는 위치이다.  
따라서 OO ABAP을 완전히 깊게 이해하지 않아도 된다. 다만 `CL_SALV_TABLE`이 “클래스”이고, `FACTORY` 메서드가 “SALV 객체를 만들어 주는 메서드”라는 감각은 필요하다.

## 3. 왜 WRITE 출력만으로는 부족한가?

ABAP을 처음 배울 때는 `WRITE` 구문으로 결과를 출력한다.

```abap
WRITE: / 'Carrier:', lv_carrid,
       / 'Connection:', lv_connid.
```

`WRITE`는 초급 문법을 이해하기에는 좋다.  
하지만 실무 데이터는 보통 여러 행과 여러 컬럼을 가진다.

예를 들어 항공편 데이터를 조회하면 다음과 같은 정보가 필요할 수 있다.

| 항공사 | 연결번호 | 비행일자 | 가격 | 통화 |
|---|---|---|---:|---|
| AA | 0017 | 2026-06-04 | 422.00 | USD |
| LH | 0400 | 2026-06-05 | 399.00 | EUR |

이런 데이터를 `WRITE`로 직접 정렬해 출력하려면 개발자가 직접 간격, 줄바꿈, 제목, 컬럼 폭을 관리해야 한다. 데이터가 많아지면 가독성이 떨어지고, 사용자 입장에서도 정렬이나 필터 같은 기본적인 리스트 조작을 하기 어렵다.

SALV는 이 문제를 해결한다.

```text
Internal Table에 데이터가 있다.
→ SALV가 이를 표 형태로 보여준다.
→ 사용자는 결과를 더 쉽게 확인한다.
```

## 4. SALV란 무엇인가?

SALV는 SAP List Viewer 계열의 객체 기반 리스트 출력 도구로 이해할 수 있다.  
초급 과정에서는 다음처럼 정의하면 충분하다.

```text
SALV = Internal Table 데이터를 빠르게 표 형태로 출력하기 위한 표준 ABAP 리스트 출력 도구
```

SALV를 사용하면 개발자는 필드별 `WRITE`를 직접 작성하지 않고도 Internal Table의 구조를 기준으로 리스트 화면을 만들 수 있다.

### 4.1 SALV의 핵심 특징

| 특징 | 설명 |
|---|---|
| Internal Table 기반 | 출력 대상은 일반적으로 Internal Table이다. |
| 빠른 구현 | 최소 코드로 표 형태 출력이 가능하다. |
| 객체 기반 | `CL_SALV_TABLE` 클래스를 사용한다. |
| 조회 중심 | 초급 단계에서는 데이터 표시용으로 이해한다. |
| 표준 UI 제공 | 기본 리스트 화면과 일부 표준 기능을 제공한다. |

### 4.2 SALV를 배우는 이유

초급자에게 SALV를 일찍 학습시키면 다음 장점이 있다.

| 장점 | 설명 |
|---|---|
| 데이터 처리 결과 확인 | Internal Table 가공 결과를 쉽게 확인할 수 있다. |
| 실무 감각 형성 | `WRITE`보다 실제 업무 리포트에 가까운 결과를 볼 수 있다. |
| 후속 ALV 학습 기반 | Grid ALV, Field Catalog, Layout, Variant 학습의 전 단계가 된다. |
| 동기부여 | 표준 SAP 화면처럼 보이는 결과를 빠르게 경험할 수 있다. |

## 5. CL_SALV_TABLE이란 무엇인가?

`CL_SALV_TABLE`은 단순 테이블 형태의 SALV 출력을 만들 때 사용하는 대표 클래스이다.

초급자 관점에서는 다음처럼 이해하면 된다.

```text
CL_SALV_TABLE = Internal Table을 받아서 ALV 형태로 표시해 주는 표준 클래스
```

이 클래스는 일반적으로 다음 흐름으로 사용한다.

```text
Internal Table 준비
→ CL_SALV_TABLE=>FACTORY 호출
→ SALV 객체 반환
→ DISPLAY 호출
```

ABAP 코드 흐름은 다음과 유사하다.

```abap
DATA lo_alv TYPE REF TO cl_salv_table.

cl_salv_table=>factory(
  IMPORTING
    r_salv_table = lo_alv
  CHANGING
    t_table      = lt_data ).

lo_alv->display( ).
```

여기서 중요한 것은 `lt_data`이다.  
SALV가 출력할 실제 데이터는 `lt_data`라는 Internal Table에 들어 있다.

## 6. SALV의 가장 기본 실행 흐름

SALV 1차 학습의 기본 흐름은 다음 네 단계로 정리할 수 있다.

```text
1. 출력할 데이터 구조를 정한다.
2. Internal Table에 데이터를 담는다.
3. CL_SALV_TABLE=>FACTORY로 SALV 객체를 만든다.
4. DISPLAY로 화면에 출력한다.
```

### 6.1 단계별 의미

| 단계 | 의미 |
|---|---|
| 데이터 구조 정의 | ALV 컬럼 구조를 결정한다. |
| Internal Table 채우기 | 실제 출력할 행 데이터를 준비한다. |
| FACTORY 호출 | SALV 출력 객체를 생성한다. |
| DISPLAY 호출 | 생성된 SALV를 화면에 표시한다. |

### 6.2 초급자가 가장 먼저 기억할 코드 패턴

```abap
DATA lo_alv TYPE REF TO cl_salv_table.

TRY.
    cl_salv_table=>factory(
      IMPORTING
        r_salv_table = lo_alv
      CHANGING
        t_table      = lt_data ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO DATA(lx_salv).
    MESSAGE lx_salv->get_text( ) TYPE 'E'.
ENDTRY.
```

이 패턴은 향후 여러 SALV 예제에서 반복해서 사용된다.

## 7. 최소 예제: 직접 만든 Internal Table 출력

다음 예제는 데이터베이스 조회 없이 Internal Table을 직접 채운 뒤 SALV로 출력하는 가장 단순한 예제이다.

```abap
REPORT zsalv_basic_01.

TYPES: BEGIN OF ty_student,
         student_id TYPE c LENGTH 8,
         name       TYPE c LENGTH 30,
         score      TYPE i,
       END OF ty_student.

DATA lt_student TYPE STANDARD TABLE OF ty_student.

lt_student = VALUE #(
  ( student_id = 'S0000001' name = 'Kim Beginner' score = 85 )
  ( student_id = 'S0000002' name = 'Lee Junior'   score = 92 )
  ( student_id = 'S0000003' name = 'Park ABAP'    score = 78 )
).

DATA lo_alv TYPE REF TO cl_salv_table.

TRY.
    cl_salv_table=>factory(
      IMPORTING
        r_salv_table = lo_alv
      CHANGING
        t_table      = lt_student ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO DATA(lx_salv).
    MESSAGE lx_salv->get_text( ) TYPE 'E'.
ENDTRY.
```

이 예제에서 SALV의 컬럼은 `TY_STUDENT`의 필드에서 만들어진다.

| 필드 | SALV 컬럼 |
|---|---|
| STUDENT_ID | 학생 ID 컬럼 |
| NAME | 이름 컬럼 |
| SCORE | 점수 컬럼 |

즉, SALV 화면의 기본 컬럼 구조는 Internal Table의 Line Type에 의해 결정된다.

## 8. 최소 예제: SELECT 결과를 SALV로 출력

실무에서는 데이터베이스에서 조회한 결과를 Internal Table에 담고, 그 결과를 SALV로 보여주는 경우가 많다.

다음은 SFLIGHT 표준 교육 테이블을 사용하는 예제이다.

```abap
REPORT zsalv_basic_02.

SELECT carrid,
       connid,
       fldate,
       price,
       currency
  FROM sflight
  INTO TABLE @DATA(lt_flight)
  UP TO 30 ROWS.

IF lt_flight IS INITIAL.
  MESSAGE '조회된 항공편 데이터가 없습니다.' TYPE 'S' DISPLAY LIKE 'E'.
  RETURN.
ENDIF.

DATA lo_alv TYPE REF TO cl_salv_table.

TRY.
    cl_salv_table=>factory(
      IMPORTING
        r_salv_table = lo_alv
      CHANGING
        t_table      = lt_flight ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO DATA(lx_salv).
    MESSAGE lx_salv->get_text( ) TYPE 'E'.
ENDTRY.
```

### 8.1 예제 흐름 해석

```text
SELECT로 SFLIGHT 데이터를 조회한다.
→ 결과가 LT_FLIGHT Internal Table에 들어간다.
→ LT_FLIGHT가 비어 있으면 메시지를 출력하고 종료한다.
→ LT_FLIGHT를 SALV FACTORY에 넘긴다.
→ DISPLAY로 리스트를 보여준다.
```

### 8.2 중요한 초급 포인트

이 예제에서 SALV는 DB에서 직접 데이터를 가져오지 않는다.  
데이터 조회는 `SELECT`가 수행하고, SALV는 이미 채워진 Internal Table을 표시한다.

```text
SELECT = 데이터 조회
Internal Table = 조회 결과 보관
SALV = 조회 결과 표시
```

이 역할 분리를 반드시 이해해야 한다.

## 9. SALV와 WRITE 출력 비교

| 비교 항목 | WRITE | SALV |
|---|---|---|
| 출력 방식 | 개발자가 직접 줄 단위 출력 | Internal Table 기반 표 출력 |
| 컬럼 관리 | 직접 간격 조정 필요 | 기본 컬럼 자동 생성 |
| 실무 리포트 느낌 | 낮음 | 높음 |
| 대량 데이터 가독성 | 낮음 | 상대적으로 좋음 |
| 구현 난이도 | 문법은 단순하지만 표 출력은 번거로움 | 기본 패턴만 익히면 빠름 |
| 후속 확장 | 제한적 | 기능, 컬럼, 레이아웃 확장 가능 |

`WRITE`는 문법 학습에 적합하고, SALV는 데이터 결과 확인과 리포트 형태 출력에 적합하다.

초급 과정에서는 둘 중 하나만 배우는 것이 아니라, 다음처럼 역할을 나누어 이해하는 것이 좋다.

```text
WRITE = ABAP 실행 흐름과 기본 출력 학습
SALV = Internal Table 결과를 실무형 리스트로 확인
```

## 10. SALV와 Grid ALV의 관계

ABAP에는 ALV와 관련된 여러 방식이 있다.

초급자는 다음 정도로 구분하면 충분하다.

| 구분 | 대표 객체/방식 | 초급자 해석 |
|---|---|---|
| WRITE List | `WRITE` | 가장 기본 출력 |
| SALV | `CL_SALV_TABLE` | 가장 간단한 표 형태 ALV 출력 |
| Grid ALV | `CL_GUI_ALV_GRID` | 더 세밀한 제어가 가능한 ALV |
| Function Module ALV | `REUSE_ALV_GRID_DISPLAY` 등 | Classic ALV 방식 |

이 Section에서는 `CL_SALV_TABLE`만 다룬다.  
Grid ALV는 이후 Screen Programming과 함께 별도 Section에서 다루는 것이 적절하다. 이유는 Grid ALV가 Container, Field Catalog, Layout, Event 등 더 많은 개념을 필요로 하기 때문이다.

## 11. CL_SALV_TABLE 기본 객체 구조

SALV를 이해하기 위해 가장 먼저 알아야 할 객체는 다음이다.

```abap
DATA lo_alv TYPE REF TO cl_salv_table.
```

이 선언은 “SALV Table 객체를 가리킬 참조 변수”를 만든다는 의미이다.

### 11.1 객체 참조 변수

`LO_ALV`는 SALV 화면 그 자체라기보다는 SALV 객체를 가리키는 변수이다.

```text
LO_ALV
  → CL_SALV_TABLE 객체
      → LT_DATA를 기반으로 출력 준비
      → DISPLAY 메서드로 화면 출력
```

### 11.2 FACTORY 메서드

`FACTORY`는 SALV 객체를 생성하는 대표 메서드이다.

```abap
cl_salv_table=>factory(
  IMPORTING
    r_salv_table = lo_alv
  CHANGING
    t_table      = lt_data ).
```

초급자가 집중해야 할 파라미터는 두 가지이다.

| 파라미터 | 방향 | 의미 |
|---|---|---|
| `R_SALV_TABLE` | IMPORTING | 생성된 SALV 객체를 받는다. |
| `T_TABLE` | CHANGING | 출력할 Internal Table을 넘긴다. |

`CHANGING`이라는 용어 때문에 초급자는 “SALV가 내 Internal Table 데이터를 바꾸는가?”라고 오해할 수 있다.  
기본 표시 목적에서는 데이터를 직접 변경하는 흐름으로 이해하기보다, SALV가 출력 대상 Internal Table을 참조하여 표시 객체를 구성한다고 이해하면 된다.

## 12. 예외 처리: CX_SALV_MSG

SALV 객체 생성 중 문제가 발생하면 `CX_SALV_MSG` 예외가 발생할 수 있다.  
따라서 기본 예제에서는 `TRY...CATCH`를 함께 사용한다.

```abap
TRY.
    cl_salv_table=>factory(
      IMPORTING
        r_salv_table = lo_alv
      CHANGING
        t_table      = lt_data ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO DATA(lx_salv).
    MESSAGE lx_salv->get_text( ) TYPE 'E'.
ENDTRY.
```

### 12.1 왜 예외 처리를 넣는가?

실습 중에는 예외가 자주 발생하지 않을 수도 있다.  
하지만 실무 코드에서는 표준 클래스 호출이 실패할 가능성을 고려해야 한다.

| 관점 | 설명 |
|---|---|
| 안정성 | 오류 발생 시 명확한 메시지를 보여준다. |
| 디버깅 | 예외 객체에서 원인을 추적할 수 있다. |
| 습관 | 표준 클래스 사용 시 예외 처리를 자연스럽게 익힌다. |

초급자는 처음부터 모든 예외 클래스를 깊게 외울 필요는 없다.  
다만 `CL_SALV_TABLE=>FACTORY` 주변에는 `TRY...CATCH CX_SALV_MSG` 패턴을 함께 쓰는 것이 좋다.

## 13. SALV 1차에서 다루지 않는 것

이번 Section은 SALV를 “가장 단순한 결과 출력 도구”로 사용하는 단계이다.  
따라서 다음 주제는 의도적으로 뒤로 미룬다.

| 주제 | 뒤로 미루는 이유 |
|---|---|
| 정렬 Sort | Internal Table 처리와 SALV 기본 표시 후 심화로 다루는 것이 적절하다. |
| 필터 Filter | 사용성 기능이지만 기본 출력 개념 이후가 적절하다. |
| Layout Variant | 사용자별 저장/불러오기 개념이 들어간다. |
| Column Text 변경 | Column 객체 이해가 필요하다. |
| Hotspot / Event | 이벤트 처리와 OO 개념이 필요하다. |
| Cell Color / Style | Deep Structure와 표시 제어 심화가 필요하다. |
| Editable ALV | SALV 기본 목적과 다르며 Grid ALV 쪽 개념이 필요하다. |

이번 모듈에서 중요한 것은 다음이다.

```text
Internal Table 결과를 SALV로 즉시 볼 수 있다.
CL_SALV_TABLE이 그 역할을 한다.
FACTORY와 DISPLAY가 기본 패턴이다.
```

## 14. 실무에서 SALV를 사용하는 상황

SALV는 다음과 같은 상황에서 유용하다.

| 상황 | 설명 |
|---|---|
| 조회 결과 확인용 리포트 | SELECT 결과를 빠르게 표로 보여준다. |
| 교육용 실습 리포트 | Internal Table 처리 결과를 확인하기 좋다. |
| 간단한 운영 보조 리포트 | 복잡한 화면 제어가 필요 없을 때 적합하다. |
| 디버깅 보조 출력 | 가공 결과를 화면으로 빠르게 확인할 수 있다. |

반면 다음과 같은 경우에는 SALV만으로 부족할 수 있다.

| 상황 | 이유 |
|---|---|
| 셀 단위 색상 제어 | 심화 ALV 제어 필요 |
| Editable Grid | Grid ALV 또는 다른 UI 기술 검토 |
| 복잡한 사용자 이벤트 | Event Handling 학습 필요 |
| 화면 안의 Container 배치 | Screen Programming과 Grid ALV 필요 |
| 저장 가능한 Layout Variant 심화 | 추가 SALV/ALV 기능 이해 필요 |

## 15. 실습: SALV 목적 확인 미니 리포트

### 15.1 실습 목표

Internal Table에 직접 데이터를 넣고 `CL_SALV_TABLE`로 출력한다.

### 15.2 실습 코드

```abap
REPORT zsalv_purpose_m01.

TYPES: BEGIN OF ty_result,
         item_no TYPE i,
         title   TYPE c LENGTH 30,
         status  TYPE c LENGTH 1,
       END OF ty_result.

DATA lt_result TYPE STANDARD TABLE OF ty_result.

lt_result = VALUE #(
  ( item_no = 1 title = 'Read internal table' status = 'S' )
  ( item_no = 2 title = 'Process data'        status = 'S' )
  ( item_no = 3 title = 'Display SALV'        status = 'S' )
).

DATA lo_alv TYPE REF TO cl_salv_table.

TRY.
    cl_salv_table=>factory(
      IMPORTING
        r_salv_table = lo_alv
      CHANGING
        t_table      = lt_result ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO DATA(lx_msg).
    MESSAGE lx_msg->get_text( ) TYPE 'E'.
ENDTRY.
```

### 15.3 실습에서 확인할 것

| 확인 항목 | 설명 |
|---|---|
| 프로그램이 활성화되는가 | Syntax Error 없이 Activate되는지 확인한다. |
| SALV 화면이 표시되는가 | `DISPLAY` 호출 후 표 형태 리스트가 나오는지 확인한다. |
| 컬럼이 자동 생성되는가 | `ITEM_NO`, `TITLE`, `STATUS` 필드가 컬럼으로 보이는지 확인한다. |
| 데이터가 3행 표시되는가 | Internal Table에 입력한 행 수와 화면 출력 행 수를 비교한다. |

## 16. 오류 상황과 해결

### 16.1 `CL_SALV_TABLE`을 찾을 수 없음

| 항목 | 내용 |
|---|---|
| 증상 | 클래스 이름 관련 Syntax Error |
| 원인 | 클래스명 오타 또는 시스템 릴리스/권한 문제 가능성 |
| 해결 | `CL_SALV_TABLE` 철자 확인, 개발 시스템에서 클래스 존재 여부 확인 |

### 16.2 `T_TABLE`에 Internal Table이 아닌 변수를 전달함

| 항목 | 내용 |
|---|---|
| 증상 | FACTORY 호출 시 타입 관련 오류 |
| 원인 | `T_TABLE`에는 출력 대상 Internal Table을 전달해야 한다. |
| 해결 | `DATA lt_data TYPE STANDARD TABLE OF ...` 형태로 Internal Table을 준비한다. |

### 16.3 `LO_ALV` 선언 누락

| 항목 | 내용 |
|---|---|
| 증상 | `LO_ALV` is unknown 같은 오류 |
| 원인 | SALV 객체 참조 변수를 선언하지 않았다. |
| 해결 | `DATA lo_alv TYPE REF TO cl_salv_table.` 선언을 추가한다. |

### 16.4 Internal Table이 비어 있음

| 항목 | 내용 |
|---|---|
| 증상 | SALV 화면은 뜨지만 데이터가 보이지 않음 |
| 원인 | 출력 대상 Internal Table에 데이터가 없다. |
| 해결 | `IF lt_data IS INITIAL.` 체크를 넣거나, 데이터 입력/SELECT 결과를 확인한다. |

### 16.5 예외 처리 누락

| 항목 | 내용 |
|---|---|
| 증상 | 문법 또는 ATC 관점에서 안정성 부족 |
| 원인 | `FACTORY` 호출의 예외 상황을 고려하지 않음 |
| 해결 | `TRY...CATCH cx_salv_msg` 패턴을 사용한다. |

## 17. 강사용 설명 포인트

강의에서는 다음 메시지를 강조하는 것이 좋다.

### 17.1 SALV는 “데이터 처리 결과를 보여주는 도구”이다

학습자는 SALV를 처음 보면 화면 기능 자체에 관심을 갖기 쉽다.  
하지만 이 Section의 목적은 ALV 기능을 깊게 파는 것이 아니라, Internal Table 처리 결과를 실무형 리스트로 확인하는 것이다.

```text
데이터 처리 = Internal Table
결과 확인 = SALV
```

### 17.2 SALV는 DB를 직접 조회하지 않는다

초급자가 오해하기 쉬운 부분이다.  
SALV는 SELECT를 대신하지 않는다.

```text
SELECT로 가져오고,
Internal Table에 담고,
SALV로 보여준다.
```

### 17.3 심화 기능은 뒤로 미룬다

첫 시간부터 Sort, Layout, Column, Event를 모두 보여주면 학습 부담이 커진다.  
이번 단계에서는 FACTORY와 DISPLAY만 확실히 익히면 충분하다.

## 18. 평가 문제

### 18.1 객관식

#### Q1. SALV의 가장 기본적인 목적은 무엇인가?

A. 데이터베이스 테이블을 생성하는 것  
B. Internal Table 데이터를 표 형태로 출력하는 것  
C. 사용자의 비밀번호를 관리하는 것  
D. Transport Request를 생성하는 것  

**정답:** B

#### Q2. `CL_SALV_TABLE=>FACTORY`에 전달하는 `T_TABLE`의 일반적인 대상은 무엇인가?

A. Transparent Table 이름  
B. Internal Table  
C. Function Module 이름  
D. Screen Number  

**정답:** B

#### Q3. SALV 기본 출력 마지막에 호출하는 대표 메서드는 무엇인가?

A. SAVE  
B. ACTIVATE  
C. DISPLAY  
D. COMMIT  

**정답:** C

### 18.2 서술형

#### Q1. WRITE 출력과 SALV 출력의 차이를 설명하시오.

**모범 답안:**  
`WRITE`는 개발자가 직접 줄 단위로 출력 내용을 작성하는 기본 리스트 출력 방식이다. SALV는 Internal Table 데이터를 기반으로 표 형태의 리스트 화면을 제공하여 여러 행과 여러 컬럼의 데이터를 더 쉽게 확인할 수 있게 한다.

#### Q2. SALV가 SELECT를 대신하지 않는다는 말의 의미를 설명하시오.

**모범 답안:**  
SALV는 데이터 조회 도구가 아니라 표시 도구이다. 데이터베이스 조회는 Open SQL의 `SELECT`가 수행하고, 조회 결과는 Internal Table에 저장된다. SALV는 그 Internal Table을 받아 화면에 출력한다.

#### Q3. `CL_SALV_TABLE`의 역할을 설명하시오.

**모범 답안:**  
`CL_SALV_TABLE`은 Internal Table 데이터를 단순 ALV 리스트 형태로 표시하기 위해 사용하는 표준 클래스이다. `FACTORY` 메서드로 SALV 객체를 생성하고, 생성된 객체의 `DISPLAY` 메서드를 호출하여 화면에 출력한다.

## 20. 핵심 요약

```text
SALV는 Internal Table 결과를 표 형태로 출력하는 표준 도구이다.
CL_SALV_TABLE은 단순 SALV Table 출력을 위한 대표 클래스이다.
기본 흐름은 Internal Table 준비 → FACTORY → DISPLAY이다.

```
