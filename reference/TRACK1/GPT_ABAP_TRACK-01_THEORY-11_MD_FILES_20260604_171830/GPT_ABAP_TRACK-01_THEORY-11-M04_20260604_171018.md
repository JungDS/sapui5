이번 모듈의 핵심 키워드는 다음 두 가지이다.

| 키워드 | 의미 |
|---|---|
| `HAVING` | `GROUP BY`로 묶인 집계 결과에 조건을 적용하는 SQL 절 |
| Aggregate Filter | 집계 함수 결과(`COUNT`, `SUM`, `AVG` 등)를 기준으로 그룹을 걸러내는 조건 |

이번 모듈은 그 다음 단계로, **집계 결과 중에서 원하는 그룹만 남기는 방법**을 학습한다.

> 핵심 문장:  
> **`WHERE`는 집계 전 원본 행을 거르고, `HAVING`은 집계 후 그룹 결과를 거른다.**

## 1. 왜 HAVING이 필요한가?

실무에서는 단순히 전체 그룹별 요약을 보는 것보다, 특정 조건을 만족하는 요약 결과만 필요한 경우가 많다.

예를 들면 다음과 같다.

```text
항공편 수가 10건 이상인 항공사만 조회
예약 건수가 100건 이상인 고객만 조회
매출 합계가 1억 이상인 제품군만 조회
평균 단가가 500 이상인 자재 그룹만 조회
좌석 점유 합계가 일정 기준 이상인 항공 연결만 조회
```

이 조건들은 대부분 원본 행 하나에 대한 조건이 아니다.  
여러 행을 그룹으로 묶고, 그 그룹의 집계 결과를 계산한 뒤에야 판단할 수 있다.

예를 들어 “항공사별 항공편 수가 10건 이상”이라는 조건은 다음 흐름이 필요하다.

```text
SFLIGHT 원본 행 조회
→ CARRID별로 그룹화
→ 각 CARRID의 항공편 수 계산
→ 계산된 항공편 수가 10 이상인 그룹만 남김
```

이 마지막 단계에서 사용하는 구문이 `HAVING`이다.

이번 문서의 예제는 SAP 교육 시스템에서 자주 사용하는 Flight Model 테이블을 기준으로 설명한다.

| 테이블 | 의미 | 주요 필드 예시 |

| `SBOOK` | 예약 정보 | `CARRID`, `CONNID`, `FLDATE`, `BOOKID`, `CUSTOMID` |

## 3. WHERE와 HAVING의 차이

`HAVING`을 이해하려면 먼저 `WHERE`와의 차이를 정확히 구분해야 한다.

| 구분 | `WHERE` | `HAVING` |
|---|---|---|
| 적용 시점 | 그룹화 전 | 그룹화 후 |
| 적용 대상 | 원본 행 | 그룹 결과 |
| 집계 함수 조건 | 일반적으로 사용 불가 | 사용 가능 |
| 예시 | `WHERE carrid = 'AA'` | `HAVING COUNT( * ) >= 10` |
| 목적 | 조회 대상 원본 데이터 줄이기 | 집계 결과 그룹 필터링 |

초급자에게 가장 중요한 차이는 다음이다.

```text
WHERE는 개별 행을 대상으로 묻는다.
HAVING은 그룹 결과를 대상으로 묻는다.
```

### 3.1 WHERE 예시

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  WHERE carrid = 'AA'
  GROUP BY carrid
  INTO TABLE @DATA(lt_result).
```

이 예제에서 `WHERE carrid = 'AA'`는 그룹화 전에 원본 행을 줄인다.  
즉, `SFLIGHT` 중 항공사 코드가 `AA`인 행만 가져온 뒤, 그 행들을 `CARRID` 기준으로 그룹화한다.

### 3.2 HAVING 예시

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  HAVING COUNT( * ) >= 10
  INTO TABLE @DATA(lt_result).
```

이 예제는 모든 항공사를 `CARRID`별로 그룹화한 뒤, 항공편 수가 10건 이상인 그룹만 결과로 남긴다.

## 4. SQL 처리 순서 감각

실제 데이터베이스 옵티마이저는 내부적으로 최적화를 수행하지만, 초급자는 논리적 처리 순서를 다음처럼 이해하면 좋다.

```text
FROM / JOIN
→ WHERE
→ GROUP BY
→ HAVING
→ SELECT 결과 구성
→ ORDER BY
```

이 순서를 기준으로 `WHERE`와 `HAVING`의 차이가 자연스럽게 이해된다.

| 단계 | 설명 |
|---|---|
| FROM / JOIN | 어떤 테이블에서 데이터를 읽을지 결정 |
| WHERE | 그룹화 전 원본 행 필터링 |
| GROUP BY | 남은 행을 기준 필드별로 묶음 |
| HAVING | 묶인 그룹의 집계 결과를 기준으로 필터링 |
| SELECT | 표시할 컬럼과 집계값 구성 |
| ORDER BY | 최종 결과 정렬 |

> 실무 감각:  
> 성능을 위해서는 가능한 원본 행을 `WHERE`에서 먼저 줄이고, 그룹 결과에만 필요한 조건을 `HAVING`에 둔다.

## 5. HAVING의 기본 구조

`HAVING`은 `GROUP BY`와 함께 사용하는 것이 일반적이다.

기본 구조는 다음과 같다.

```abap
SELECT group_field,
       aggregate_function( field ) AS alias_name
  FROM database_table
  WHERE row_condition
  GROUP BY group_field
  HAVING aggregate_function( field ) aggregate_condition
  INTO TABLE @DATA(result_table).
```

예를 들어 항공사별 항공편 수가 5건 이상인 항공사만 조회하려면 다음처럼 작성한다.

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  HAVING COUNT( * ) >= 5
  INTO TABLE @DATA(lt_flight_count).
```

이때 결과는 다음과 같은 형태가 된다.

| CARRID | FLIGHT_COUNT |
|---|---:|
| AA | 12 |
| LH | 28 |
| UA | 15 |

항공편 수가 5건 미만인 항공사는 결과에서 제외된다.

---

## 6. HAVING에서 사용할 수 있는 조건

`HAVING`에는 그룹 결과를 기준으로 조건을 작성한다. 일반적으로 다음과 같은 조건이 사용된다.

| 조건 유형 | 예시 | 의미 |
|---|---|---|
| 건수 조건 | `HAVING COUNT( * ) >= 10` | 그룹 건수가 10건 이상 |
| 합계 조건 | `HAVING SUM( seatsocc ) > 500` | 좌석 점유 합계가 500 초과 |
| 평균 조건 | `HAVING AVG( price ) >= 300` | 평균 가격이 300 이상 |
| 그룹 필드 조건 | `HAVING carrid <> 'AA'` | 그룹 필드 기준 조건 |

다만 그룹 필드에 대한 단순 조건은 가능한 경우 `WHERE`에서 처리하는 것이 일반적으로 더 적절하다.

예를 들어 다음 두 쿼리를 비교해보자.

### 6.1 비권장에 가까운 예

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  HAVING carrid = 'AA'
  INTO TABLE @DATA(lt_result).
```

### 6.2 더 권장되는 예

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  WHERE carrid = 'AA'
  GROUP BY carrid
  INTO TABLE @DATA(lt_result).
```

`CARRID = 'AA'`는 원본 행 단계에서 판단할 수 있는 조건이므로 `WHERE`에 두는 편이 자연스럽다.  
`HAVING`은 집계 후에야 알 수 있는 조건에 집중하는 것이 좋다.

## 7. 실습 1 — 항공편 수가 많은 항공사만 조회

### 7.1 요구사항

`SFLIGHT`에서 항공사별 항공편 수를 계산하고, 항공편 수가 10건 이상인 항공사만 출력한다.

### 7.2 예제 코드

```abap
REPORT zgpt_sql_having_01.

SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  HAVING COUNT( * ) >= 10
  INTO TABLE @DATA(lt_result).

IF sy-subrc = 0.
  LOOP AT lt_result INTO DATA(ls_result).
    WRITE: / ls_result-carrid,
             ls_result-flight_count.
  ENDLOOP.
ELSE.
  WRITE: / 'No airline has 10 or more flights.'.
ENDIF.
```

### 7.3 코드 해설

| 코드 | 설명 |
|---|---|
| `COUNT( * )` | 그룹별 행 수를 계산한다. |
| `GROUP BY carrid` | 항공사별로 그룹을 만든다. |
| `HAVING COUNT( * ) >= 10` | 항공편 수가 10건 이상인 그룹만 남긴다. |
| `INTO TABLE @DATA(lt_result)` | 결과 구조를 인라인으로 생성해 내부 테이블에 담는다. |

### 7.4 검증 포인트

실행 결과가 없을 경우 다음을 확인한다.

```text
SFLIGHT에 데이터가 있는가?
항공사별 데이터가 10건 이상 존재하는가?
HAVING 기준값을 1 또는 2로 낮추면 결과가 나오는가?
```

## 8. 실습 2 — 통화별 가격 합계 기준 필터링

### 8.1 요구사항

`SFLIGHT`에서 항공사와 통화별 가격 합계를 계산하고, 합계가 10000 이상인 그룹만 조회한다.

금액 합계를 다룰 때는 통화를 반드시 함께 고려해야 한다.  
서로 다른 통화의 금액을 단순 합산하면 업무적으로 잘못된 결과가 될 수 있다.

### 8.2 예제 코드

```abap
REPORT zgpt_sql_having_02.

SELECT carrid,
       currency,
       SUM( price ) AS total_price
  FROM sflight
  GROUP BY carrid,
           currency
  HAVING SUM( price ) >= 10000
  INTO TABLE @DATA(lt_result).

IF sy-subrc = 0.
  LOOP AT lt_result INTO DATA(ls_result).
    WRITE: / ls_result-carrid,
             ls_result-currency,
             ls_result-total_price.
  ENDLOOP.
ELSE.
  WRITE: / 'No result found.'.
ENDIF.
```

### 8.3 왜 CURRENCY를 GROUP BY에 넣는가?

`PRICE`는 금액 필드이고 `CURRENCY`는 통화 필드이다.  
금액은 통화가 다르면 직접 비교하거나 합산하면 안 된다.

잘못된 예는 다음과 같다.

```abap
SELECT carrid,
       SUM( price ) AS total_price
  FROM sflight
  GROUP BY carrid
  HAVING SUM( price ) >= 10000
  INTO TABLE @DATA(lt_wrong).
```

이 코드는 항공사별 가격을 합산하지만 통화를 구분하지 않는다.  
예제 데이터가 모두 같은 통화라면 우연히 문제가 없어 보일 수 있지만, 실무에서는 잘못된 설계가 될 수 있다.

권장 방식은 다음처럼 통화 기준을 함께 그룹화하는 것이다.

```text
CARRID + CURRENCY 기준으로 GROUP BY
```

## 9. 실습 3 — WHERE와 HAVING 함께 사용

### 9.1 요구사항

현재일 이후 항공편만 대상으로 항공사별 항공편 수를 계산하고, 그중 3건 이상인 항공사만 조회한다.

### 9.2 예제 코드

```abap
REPORT zgpt_sql_having_03.

SELECT carrid,
       COUNT( * ) AS future_flight_count
  FROM sflight
  WHERE fldate >= @sy-datum
  GROUP BY carrid
  HAVING COUNT( * ) >= 3
  INTO TABLE @DATA(lt_result).

LOOP AT lt_result INTO DATA(ls_result).
  WRITE: / ls_result-carrid,
           ls_result-future_flight_count.
ENDLOOP.
```

### 9.3 처리 흐름

이 쿼리는 다음 순서로 이해하면 된다.

```text
SFLIGHT에서 현재일 이후 항공편만 남긴다.       → WHERE
남은 항공편을 CARRID별로 묶는다.              → GROUP BY
항공편 수가 3건 이상인 그룹만 남긴다.          → HAVING
결과를 ABAP 내부 테이블로 가져온다.            → INTO TABLE
```

이 예제는 `WHERE`와 `HAVING`을 함께 사용하는 전형적인 패턴이다.

## 10. 실습 4 — JOIN 결과에 HAVING 적용

### 10.1 요구사항

`SCARR`와 `SFLIGHT`를 조인하여 항공사명 기준으로 항공편 수를 계산하고, 항공편 수가 5건 이상인 항공사만 출력한다.

### 10.2 예제 코드

```abap
REPORT zgpt_sql_having_04.

SELECT c~carrid,
       c~carrname,
       COUNT( * ) AS flight_count
  FROM scarr AS c
  INNER JOIN sflight AS f
    ON f~carrid = c~carrid
  GROUP BY c~carrid,
           c~carrname
  HAVING COUNT( * ) >= 5
  INTO TABLE @DATA(lt_result).

LOOP AT lt_result INTO DATA(ls_result).
  WRITE: / ls_result-carrid,
           ls_result-carrname,
           ls_result-flight_count.
ENDLOOP.
```

### 10.3 GROUP BY 기준

SELECT 목록에 집계 함수가 아닌 필드가 있다면, 해당 필드는 `GROUP BY`에 포함되어야 한다.

이 예제에서는 다음 두 필드가 일반 필드이다.

```text
c~carrid
c~carrname
```

따라서 `GROUP BY`에도 두 필드를 모두 포함한다.

```abap
GROUP BY c~carrid,
         c~carrname
```

`COUNT( * )`는 집계 함수이므로 `GROUP BY`에 넣지 않는다.

## 11. HAVING과 별칭 Alias

ABAP Open SQL에서 집계 결과에 `AS`로 별칭을 부여할 수 있다.

```abap
COUNT( * ) AS flight_count
```

이 별칭은 결과 내부 테이블의 컴포넌트 이름으로 매우 유용하다.

```abap
ls_result-flight_count
```

다만 초급 학습 단계에서는 `HAVING` 조건에 별칭을 사용할 수 있다고 가정하기보다, 집계 표현식을 직접 반복해서 작성하는 방식으로 익히는 것이 안전하다.

권장 학습 예:

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  HAVING COUNT( * ) >= 10
  INTO TABLE @DATA(lt_result).
```

이렇게 작성하면 `HAVING`이 집계 함수 결과를 필터링한다는 의미가 명확하다.

## 12. HAVING 없이 ABAP에서 필터링하는 방식과 비교

### 12.1 ABAP에서 필터링하는 방식

다음 방식은 DB에서 전체 집계 결과를 가져온 뒤 ABAP에서 조건을 적용한다.

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  INTO TABLE @DATA(lt_result).

DELETE lt_result WHERE flight_count < 10.
```

이 방식도 소량 데이터에서는 동작한다.  
하지만 불필요한 그룹 결과까지 ABAP 서버로 가져온 뒤 삭제한다.

### 12.2 HAVING을 사용하는 방식

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  HAVING COUNT( * ) >= 10
  INTO TABLE @DATA(lt_result).
```

이 방식은 DB에서 조건을 적용한 뒤 필요한 그룹만 ABAP으로 전달한다.

### 12.3 선택 기준

| 방식 | 적합한 경우 | 주의 |
|---|---|---|
| ABAP 필터링 | 후속 로직이 매우 복잡하고 SQL로 표현하기 어려움 | 데이터 전송량 증가 가능 |
| `HAVING` 필터링 | 집계 결과 조건이 SQL로 명확히 표현 가능 | SQL 문법과 집계 기준 이해 필요 |

S/4HANA 환경에서는 가능한 조건을 DB에서 처리하는 것이 일반적으로 더 바람직하다.  
다만 모든 업무 규칙을 무조건 SQL에 밀어 넣는 것도 좋은 설계는 아니다. 조건의 명확성, 성능, 유지보수성을 함께 판단해야 한다.

## 13. 자주 발생하는 오류와 해결

### 13.1 WHERE에 집계 함수를 쓰려고 함

잘못된 예:

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  WHERE COUNT( * ) >= 10
  GROUP BY carrid
  INTO TABLE @DATA(lt_result).
```

문제:

```text
WHERE는 그룹화 전 개별 행을 필터링하는 절이다.
COUNT( * )는 그룹화 후에 계산되는 집계 결과이다.
```

해결:

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  HAVING COUNT( * ) >= 10
  INTO TABLE @DATA(lt_result).
```

---

### 13.2 GROUP BY 없이 HAVING을 사용하려고 함

집계 전체 결과에 조건을 적용하는 특수한 경우도 있지만, 초급 단계에서는 `HAVING`을 `GROUP BY`와 함께 사용하는 패턴으로 먼저 익히는 것이 좋다.

권장 학습 패턴:

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  HAVING COUNT( * ) >= 10
  INTO TABLE @DATA(lt_result).
```

---

### 13.3 SELECT 필드와 GROUP BY 불일치

잘못된 예:

```abap
SELECT carrid,
       connid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  HAVING COUNT( * ) >= 10
  INTO TABLE @DATA(lt_result).
```

문제:

`CONNID`는 집계 함수가 아닌 일반 필드인데 `GROUP BY`에 포함되어 있지 않다.

해결:

```abap
SELECT carrid,
       connid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid,
           connid
  HAVING COUNT( * ) >= 10
  INTO TABLE @DATA(lt_result).
```

또는 `CONNID`가 결과에 필요 없다면 SELECT 목록에서 제거한다.

---

### 13.4 금액/수량 필터에서 단위와 통화를 무시함

잘못된 예:

```abap
SELECT carrid,
       SUM( price ) AS total_price
  FROM sflight
  GROUP BY carrid
  HAVING SUM( price ) >= 10000
  INTO TABLE @DATA(lt_result).
```

문제:

`PRICE`는 금액이므로 `CURRENCY` 없이 합산·비교하면 업무 의미가 불명확하다.

해결:

```abap
SELECT carrid,
       currency,
       SUM( price ) AS total_price
  FROM sflight
  GROUP BY carrid,
           currency
  HAVING SUM( price ) >= 10000
  INTO TABLE @DATA(lt_result).
```

---

### 13.5 HAVING 기준값을 너무 높게 둠

증상:

```text
문법은 맞는데 결과가 없다.
```

가능한 원인:

```text
데이터가 적어서 COUNT/SUM/AVG 조건을 만족하는 그룹이 없음
```

해결:

```text
1. HAVING 조건을 잠시 제거하고 전체 그룹 결과를 확인한다.
2. 기준값을 낮춰서 결과가 나오는지 확인한다.
3. 실제 테이블에 테스트 데이터가 충분한지 확인한다.
```

## 14. 성능 관점

### 14.1 WHERE를 먼저 활용한다

`HAVING`은 집계 결과를 필터링하지만, 가능한 원본 행 조건은 `WHERE`에서 먼저 적용하는 것이 좋다.

예를 들어 특정 기간만 조회한다면 다음처럼 작성한다.

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  WHERE fldate BETWEEN @p_from AND @p_to
  GROUP BY carrid
  HAVING COUNT( * ) >= 10
  INTO TABLE @DATA(lt_result).
```

이 방식은 전체 데이터를 그룹화하는 것이 아니라, 기간 조건으로 줄어든 데이터만 그룹화한다.

### 14.2 HAVING은 결과 전송량을 줄인다

`HAVING`을 사용하면 기준에 맞는 그룹만 ABAP 서버로 전달된다.  
집계 결과 그룹이 많을수록 효과가 있을 수 있다.

```text
전체 그룹 10,000개
→ HAVING 조건 만족 그룹 120개
→ ABAP 서버로 120개만 전송
```

### 14.3 그래도 무조건 HAVING이 정답은 아니다

다음 경우에는 ABAP 후처리가 더 명확할 수 있다.

| 상황 | 설명 |
|---|---|
| 조건이 업무 함수나 복잡한 ABAP 로직에 의존 | SQL로 표현하기 어려울 수 있음 |
| 후속 계산이 여러 단계 | SQL이 너무 복잡해져 유지보수성이 떨어질 수 있음 |
| 데이터량이 매우 작음 | 성능 차이가 의미 없을 수 있음 |
| 가독성이 크게 저하됨 | 실무 유지보수 관점에서 분리 고려 |

실무에서는 성능과 가독성, 테스트 가능성을 함께 판단한다.

## 15. 권한과 운영 관점

`HAVING` 자체가 별도 권한을 요구하는 것은 아니다.  
그러나 조회 대상 테이블에 대한 권한, 프로그램 실행 권한, 데이터 접근 정책은 여전히 중요하다.

운영 관점에서 특히 주의할 점은 다음이다.

| 관점 | 주의사항 |
|---|---|
| 대량 데이터 | WHERE 조건 없이 전체 테이블을 집계하면 부하가 커질 수 있다. |
| 운영 시간 | 대량 집계 리포트는 실행 시간과 시스템 부하를 고려해야 한다. |
| 권한 | 집계 결과라도 민감 정보가 포함될 수 있다. |
| 감사 | 집계 결과가 의사결정에 쓰이면 기준 조건을 명확히 남겨야 한다. |

집계 결과는 상세 데이터보다 덜 민감해 보일 수 있지만, 매출 합계, 고객 수, 재고 수량 같은 정보는 충분히 중요한 업무 정보다.

## 16. 디버깅과 검증 방법

집계 쿼리는 일반 상세 조회보다 검증이 어렵다.  
따라서 다음 순서로 검증하는 습관이 필요하다.

### 16.1 검증 순서

```text
1. WHERE 조건만 적용한 원본 데이터 건수 확인
2. GROUP BY만 적용한 전체 그룹 결과 확인
3. HAVING 조건을 추가한 결과 확인
4. 기준값을 낮추거나 높여 결과 변화를 확인
5. 필요 시 SE16N 또는 ADT Data Preview로 원본 데이터 샘플 확인
```

### 16.2 비교 검증 예

먼저 전체 그룹 결과를 확인한다.

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  INTO TABLE @DATA(lt_all_groups).
```

그 다음 `HAVING`을 추가한다.

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  HAVING COUNT( * ) >= 10
  INTO TABLE @DATA(lt_filtered_groups).
```

두 결과의 건수를 비교하면 `HAVING`이 어떤 그룹을 제외했는지 확인할 수 있다.

## 17. 실무 안티패턴

### 17.1 집계 조건을 ABAP에서만 처리

```abap
SELECT carrid,
       COUNT( * ) AS flight_count
  FROM sflight
  GROUP BY carrid
  INTO TABLE @DATA(lt_result).

DELETE lt_result WHERE flight_count < 10.
```

소량 데이터에서는 문제가 없어 보일 수 있지만, 대량 데이터에서는 불필요한 결과 전송과 후처리가 발생한다.

### 17.2 WHERE와 HAVING을 혼동

```abap
WHERE COUNT( * ) >= 10
```

이런 식으로 집계 조건을 `WHERE`에 넣으려는 시도는 초급자가 자주 하는 오류다.

### 17.3 HAVING으로 모든 조건을 처리

```abap
GROUP BY carrid
HAVING carrid = 'AA' AND COUNT( * ) >= 10
```

`CARRID = 'AA'`는 원본 행 조건이므로 `WHERE`에 두는 것이 더 적절하다.

### 17.4 통화와 단위를 무시한 집계 조건

```abap
HAVING SUM( price ) >= 10000
```

금액 필드라면 통화 기준을 함께 고려해야 한다.

### 17.5 결과가 없는 것을 오류로만 판단

`HAVING` 조건이 너무 강하면 정상적으로 결과가 없을 수 있다.  
이 경우 문법 오류가 아니라 데이터 조건 불일치일 수 있다.

## 18. 실습 과제

### 18.1 기본 과제

`SFLIGHT`에서 항공사별 항공편 수를 계산하고, 항공편 수가 5건 이상인 항공사만 출력한다.

필수 조건:

```text
GROUP BY carrid 사용
COUNT( * ) 사용
HAVING COUNT( * ) >= 5 사용
결과가 없으면 기준값을 낮춰 재실행
```

### 18.2 응용 과제

`SFLIGHT`에서 항공사와 통화별 가격 합계를 계산하고, 합계가 특정 기준 이상인 그룹만 출력한다.

필수 조건:

```text
GROUP BY carrid, currency 사용
SUM( price ) 사용
HAVING SUM( price ) >= 기준값 사용
통화별로 결과를 분리해서 해석
```

### 18.3 심화 맛보기 과제

`SCARR`와 `SFLIGHT`를 조인하여 항공사명 기준 항공편 수를 계산하고, 일정 건수 이상인 항공사만 출력한다.

필수 조건:

```text
INNER JOIN 사용
Alias 사용
GROUP BY에 일반 SELECT 필드 포함
HAVING으로 집계 조건 적용
```

## 20. 자가 진단 문제

### 20.1 객관식

#### Q1. `HAVING`의 가장 적절한 설명은?

A. 원본 행을 그룹화 전에 필터링한다.  
B. 집계 결과 그룹을 기준으로 필터링한다.  
C. 결과를 정렬한다.  
D. 테이블을 조인한다.

정답: B

#### Q2. 항공사별 항공편 수가 10건 이상인 항공사만 조회할 때 적절한 조건은?

A. `WHERE COUNT( * ) >= 10`  
B. `HAVING COUNT( * ) >= 10`  
C. `ORDER BY COUNT( * ) >= 10`  
D. `GROUP BY COUNT( * ) >= 10`

정답: B

#### Q3. `WHERE`에 두는 것이 더 적절한 조건은?

A. `COUNT( * ) >= 10`  
B. `SUM( price ) >= 10000`  
C. `carrid = 'AA'`  
D. `AVG( price ) > 500`

정답: C

### 20.2 서술형

#### Q1. `WHERE`와 `HAVING`의 차이를 설명하시오.

모범 답안:  
`WHERE`는 그룹화 전에 원본 행을 필터링하는 조건이고, `HAVING`은 `GROUP BY`로 묶인 후 계산된 집계 결과 그룹을 필터링하는 조건이다.

#### Q2. 금액 합계에 `HAVING SUM( price ) >= 10000`을 사용할 때 `currency`를 함께 고려해야 하는 이유를 설명하시오.

모범 답안:  
금액은 통화에 따라 의미가 달라지므로 서로 다른 통화를 단순 합산하거나 비교하면 업무적으로 잘못된 결과가 될 수 있다. 따라서 `CURRENCY`를 `GROUP BY`에 포함해 통화별로 합계를 분리해야 한다.

#### Q3. `HAVING` 조건을 적용했더니 결과가 없을 때 확인할 사항을 쓰시오.

모범 답안:  
원본 데이터가 존재하는지, `WHERE` 조건이 너무 제한적인지, `GROUP BY`만 적용했을 때 전체 그룹 결과가 있는지, `HAVING` 기준값이 너무 높은지 확인한다.

## 21. 강사용 설명 포인트

강의에서는 다음 순서로 설명하면 이해가 쉽다.

```text
1. 상세 데이터 전체 조회
2. GROUP BY로 항공사별 묶기
3. COUNT로 항공사별 건수 계산
4. HAVING으로 건수 기준 필터링
5. WHERE와 HAVING의 처리 시점 비교
```

특히 다음 문장을 반복해서 강조한다.

```text
WHERE는 원본 데이터 조건이다.
HAVING은 집계 결과 조건이다.
```

학습자가 이 차이를 이해하면 이후 `ORDER BY`, `JOIN / FAE / ABAP 처리 선택 기준`, CDS View의 집계 모델링도 훨씬 쉽게 받아들일 수 있다.

## 22. 후속 모듈과의 연결

이번 모듈에서는 집계 결과에 조건을 적용하는 `HAVING`을 학습했다.

다음 모듈 `THEORY-11-M05 — ORDER BY 정렬 조회`에서는 조회 결과를 사용자가 보기 좋은 순서로 정렬하는 방법을 다룬다.

연결 흐름은 다음과 같다.

```text
THEORY-11-M03 GROUP BY와 Aggregate
→ THEORY-11-M04 HAVING과 집계 조건
→ THEORY-11-M05 ORDER BY 정렬 조회
```

실무 조회 프로그램에서는 보통 다음 구성이 함께 등장한다.

```text
WHERE      원본 행 조건
GROUP BY   집계 기준
HAVING     집계 결과 조건
ORDER BY   최종 결과 정렬
```

따라서 이번 모듈은 집계 조회의 필터링을 완성하는 단계이고, 다음 모듈은 결과 표현 품질을 높이는 단계다.

## 23. 핵심 요약

```text
HAVING은 GROUP BY 이후 집계 결과를 필터링하는 조건이다.
WHERE는 원본 행 조건이고, HAVING은 그룹 결과 조건이다.
COUNT, SUM, AVG 같은 Aggregate 결과 조건은 HAVING에 작성한다.
원본 행에서 판단 가능한 조건은 가능한 WHERE에 둔다.
금액과 수량을 집계할 때는 통화와 단위를 함께 고려한다.
HAVING 결과가 없을 때는 기준값, 원본 데이터, WHERE 조건, GROUP BY 결과를 순서대로 확인한다.
```
