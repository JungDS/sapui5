## 2. 선행 지식

이 모듈은 다음 지식 위에 놓인다.

| 선행 지식 | 필요한 이유 |
|---|---|
| `PARAMETERS` | 단일 입력값 조건과 Range 조건의 차이를 이해하기 위해 필요 |
| `SELECT-OPTIONS` | 사용자가 범위, 복수값, 제외값을 입력하는 Selection Screen 필드이기 때문 |
| Range Table 구조 | `SIGN`, `OPTION`, `LOW`, `HIGH`를 이해해야 `WHERE IN`의 의미를 해석할 수 있음 |
| Open SQL 기본 조회 | `SELECT ... FROM ... WHERE ... INTO TABLE` 흐름이 필요 |
| Internal Table | 조회 결과를 `INTO TABLE`로 받는 구조를 이해해야 함 |

이 문서에서는 Open SQL의 모든 세부 문법을 깊게 다루지는 않는다.  
핵심은 Selection Screen 조건을 DB 조회 조건으로 안전하게 연결하는 것이다.

## 3. 왜 `WHERE field IN @range`가 필요한가?

실무 Report는 대부분 사용자가 입력한 조건을 기준으로 데이터를 조회한다.

예를 들어 항공편 데이터를 조회한다고 가정한다.

```text
항공사 코드: AA
연결 번호: 0017
비행일자: 2026.06.01 ~ 2026.06.30
```

단일 값만 입력받는다면 `PARAMETERS`와 `=` 조건으로도 충분하다.

```abap
PARAMETERS p_carrid TYPE s_carr_id.

SELECT *
  FROM sflight
  WHERE carrid = @p_carrid
  INTO TABLE @DATA(lt_sflight).
```

하지만 실무에서는 사용자가 다음과 같은 복잡한 조건을 입력할 수 있어야 한다.

```text
AA 또는 LH 항공사만 조회
AA는 제외하고 조회
AA부터 LH까지 범위로 조회
특정 항공사 여러 개 선택
비어 있으면 전체 조회
```

이런 조건을 단순 `PARAMETERS`만으로 처리하려면 코드가 복잡해진다.  
`SELECT-OPTIONS`와 Range Table을 사용하면 사용자가 입력한 조건을 표준 구조로 관리하고, Open SQL에 직접 전달할 수 있다.

```abap
SELECT-OPTIONS s_carrid FOR sflight-carrid.

SELECT *
  FROM sflight
  WHERE carrid IN @s_carrid
  INTO TABLE @DATA(lt_sflight).
```

이 한 줄이 이번 모듈의 핵심이다.

## 4. 기본 문법

### 4.1 SELECT-OPTIONS를 사용하는 기본 예

```abap
REPORT zgpt_so_where_in_01.

TABLES sflight.

SELECT-OPTIONS s_carrid FOR sflight-carrid.

START-OF-SELECTION.

  SELECT carrid,
         connid,
         fldate,
         price,
         currency
    FROM sflight
    WHERE carrid IN @s_carrid
    INTO TABLE @DATA(lt_flight).

  LOOP AT lt_flight INTO DATA(ls_flight).
    WRITE: / ls_flight-carrid,
             ls_flight-connid,
             ls_flight-fldate,
             ls_flight-price,
             ls_flight-currency.
  ENDLOOP.
```

이 예제에서 핵심은 다음이다.

| 코드 | 의미 |
|---|---|
| `SELECT-OPTIONS s_carrid FOR sflight-carrid` | 항공사 코드 조건 입력 필드를 만든다. |
| `WHERE carrid IN @s_carrid` | 입력된 항공사 조건을 DB 조회 조건에 연결한다. |
| `@s_carrid` | ABAP 변수 또는 Internal Table을 SQL 문 안에서 사용한다는 표시이다. |

### 4.2 Host Variable Escape `@`

최신 Open SQL에서는 ABAP 변수, Work Area, Internal Table 같은 Host Variable 앞에 `@`를 붙인다.

```abap
WHERE carrid = @p_carrid
WHERE carrid IN @s_carrid
INTO TABLE @DATA(lt_flight)
```

`@`는 SQL 구문 안에서 “이것은 DB 컬럼명이 아니라 ABAP 프로그램 쪽 변수다”라는 의미를 명확히 한다.

초급자는 다음처럼 이해하면 된다.

```text
@가 붙으면 ABAP 프로그램 안의 값이다.
@가 없으면 SQL의 필드명, 테이블명, 키워드로 해석될 수 있다.
```

## 5. Range Table 구조 복습

`SELECT-OPTIONS`는 내부적으로 Range Table 구조를 가진다.

대표 구조는 다음과 같다.

| Field | 의미 | 예시 |
|---|---|---|
| SIGN | 포함/제외 | `I`, `E` |
| OPTION | 비교 연산 | `EQ`, `BT`, `CP`, `GE`, `LE` 등 |
| LOW | 하한값 또는 단일값 | `AA` |
| HIGH | 상한값 | `LH` |

예를 들어 사용자가 항공사 코드 `AA`와 `LH`를 각각 선택했다면 내부적으로는 다음과 비슷한 구조가 된다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | EQ | AA |  |
| I | EQ | LH |  |

사용자가 `AA`부터 `LH`까지 범위를 입력했다면 다음과 비슷하다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | BT | AA | LH |

사용자가 `AA`를 제외했다면 다음과 비슷하다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| E | EQ | AA |  |

Open SQL의 `WHERE carrid IN @s_carrid`는 이런 Range Table을 해석하여 조건으로 반영한다.

## 6. SELECT-OPTIONS와 WHERE IN의 연결 흐름

Selection Screen과 Open SQL의 연결 흐름은 다음과 같다.

```text
1. 개발자가 SELECT-OPTIONS를 선언한다.
2. SAP Runtime이 Selection Screen을 생성한다.
3. 사용자가 조건을 입력한다.
4. 입력값이 Range Table 형태로 프로그램에 전달된다.
5. Open SQL에서 WHERE field IN @range_table로 조건을 전달한다.
6. DB에서 조건에 맞는 데이터가 조회된다.
7. 조회 결과가 Internal Table에 담긴다.
```

이 흐름을 코드로 보면 다음과 같다.

```abap
SELECT-OPTIONS s_carrid FOR sflight-carrid.

START-OF-SELECTION.

  SELECT *
    FROM sflight
    WHERE carrid IN @s_carrid
    INTO TABLE @DATA(lt_sflight).
```

초급자는 이 패턴을 하나의 기본 공식처럼 익혀도 된다.

```abap
SELECT-OPTIONS s_xxx FOR dbtab-field.

SELECT ...
  FROM dbtab
  WHERE field IN @s_xxx
  INTO TABLE @DATA(lt_result).
```

## 7. PARAMETERS와 SELECT-OPTIONS의 비교

### 7.1 PARAMETERS 방식

```abap
PARAMETERS p_carrid TYPE s_carr_id.

SELECT *
  FROM sflight
  WHERE carrid = @p_carrid
  INTO TABLE @DATA(lt_sflight).
```

이 방식은 단일 값 조건에 적합하다.

| 장점 | 단점 |
|---|---|
| 단순하다 | 복수값 입력이 어렵다 |
| 코드가 직관적이다 | 범위 조건을 직접 구현해야 한다 |
| 초급자가 이해하기 쉽다 | Include/Exclude 조건 처리에 한계가 있다 |

### 7.2 SELECT-OPTIONS 방식

```abap
SELECT-OPTIONS s_carrid FOR sflight-carrid.

SELECT *
  FROM sflight
  WHERE carrid IN @s_carrid
  INTO TABLE @DATA(lt_sflight).
```

이 방식은 복수값, 범위, 제외 조건에 적합하다.

| 장점 | 단점 |
|---|---|
| 복수값 처리 가능 | Range Table 개념을 알아야 한다 |
| 범위 조건 처리 가능 | 비어 있을 때 동작을 주의해야 한다 |
| Include/Exclude 가능 | 복잡한 조건은 사용자가 오해할 수 있다 |
| 실무 Report에서 매우 자주 사용 | 성능과 선택 조건 설계가 중요하다 |

## 8. 비어 있는 Range Table의 의미

### 8.1 가장 중요한 주의점

초급자가 반드시 알아야 할 점은 다음이다.

```text
Range Table이 비어 있을 때 WHERE field IN @range 조건은 기대와 다르게 동작할 수 있으므로 반드시 의도적으로 처리해야 한다.
```

일반적인 실무 감각에서는 다음 두 가지 의도가 있을 수 있다.

| 사용자의 의도 | 의미 |
|---|---|
| 조건을 입력하지 않으면 전체 조회 | Range가 비어 있으면 WHERE 조건을 생략해야 함 |
| 조건을 반드시 입력해야 함 | Selection Screen에서 OBLIGATORY 또는 검증 필요 |

`SELECT-OPTIONS`는 아무 조건도 입력하지 않을 수 있다.  
이때 개발자가 전체 조회를 허용할지, 오류로 막을지 설계해야 한다.

### 8.2 전체 조회를 허용하는 경우

사용자가 조건을 입력하지 않으면 전체 데이터를 조회해도 되는 보고서라면 다음처럼 작성할 수 있다.

```abap
SELECT-OPTIONS s_carrid FOR sflight-carrid.

START-OF-SELECTION.

  IF s_carrid IS INITIAL.
    SELECT carrid,
           connid,
           fldate
      FROM sflight
      INTO TABLE @DATA(lt_sflight).
  ELSE.
    SELECT carrid,
           connid,
           fldate
      FROM sflight
      WHERE carrid IN @s_carrid
      INTO TABLE @lt_sflight.
  ENDIF.
```

하지만 위 코드는 `lt_sflight` 선언 위치 때문에 초급자에게 혼란을 줄 수 있다.  
더 명확하게 하려면 타입을 먼저 정의하는 방식도 가능하다.

```abap
DATA lt_sflight TYPE STANDARD TABLE OF sflight.

IF s_carrid IS INITIAL.
  SELECT *
    FROM sflight
    INTO TABLE @lt_sflight.
ELSE.
  SELECT *
    FROM sflight
    WHERE carrid IN @s_carrid
    INTO TABLE @lt_sflight.
ENDIF.
```

### 8.3 조건 입력을 필수로 하는 경우

조건 없이 전체 조회되면 데이터량이 너무 많거나 성능 문제가 생긴다면 입력을 강제한다.

```abap
SELECT-OPTIONS s_carrid FOR sflight-carrid OBLIGATORY.

START-OF-SELECTION.

  SELECT *
    FROM sflight
    WHERE carrid IN @s_carrid
    INTO TABLE @DATA(lt_sflight).
```

`OBLIGATORY`는 사용자가 최소 입력을 하도록 돕는다.  
다만 실무에서는 `OBLIGATORY`만으로 충분하지 않을 수 있다.  
예를 들어 너무 넓은 범위를 입력하는 경우는 별도 검증이 필요할 수 있다.

## 9. 직접 만든 Range Table 사용

`SELECT-OPTIONS` 없이 직접 Range Table을 만들어 `WHERE IN`에 사용할 수도 있다.

### 9.1 TYPE RANGE OF 사용

```abap
REPORT zgpt_range_where_in_02.

DATA lr_carrid TYPE RANGE OF sflight-carrid.

APPEND VALUE #( sign   = 'I'
                option = 'EQ'
                low    = 'AA' ) TO lr_carrid.

APPEND VALUE #( sign   = 'I'
                option = 'EQ'
                low    = 'LH' ) TO lr_carrid.

SELECT carrid,
       connid,
       fldate
  FROM sflight
  WHERE carrid IN @lr_carrid
  INTO TABLE @DATA(lt_sflight).

LOOP AT lt_sflight INTO DATA(ls_sflight).
  WRITE: / ls_sflight-carrid,
           ls_sflight-connid,
           ls_sflight-fldate.
ENDLOOP.
```

이 코드의 의미는 다음과 같다.

```text
AA 또는 LH 항공사의 항공편을 조회한다.
```

### 9.2 VALUE 문으로 Range Table 생성

Modern ABAP 문법을 사용하면 다음처럼 Range Table을 더 간결하게 만들 수 있다.

```abap
DATA(lr_carrid) = VALUE RANGE OF sflight-carrid(
  ( sign = 'I' option = 'EQ' low = 'AA' )
  ( sign = 'I' option = 'EQ' low = 'LH' )
).

SELECT carrid,
       connid,
       fldate
  FROM sflight
  WHERE carrid IN @lr_carrid
  INTO TABLE @DATA(lt_sflight).
```

이 문법은 간결하지만, 초급자에게는 내부 구조가 보이지 않을 수 있다.  
처음 학습할 때는 `APPEND VALUE #(...)` 방식과 `VALUE RANGE OF ...` 방식을 함께 비교해보는 것이 좋다.

## 10. BETWEEN 조건과 Range Table

Range Table의 `OPTION = 'BT'`는 Between 조건이다.

```abap
DATA(lr_connid) = VALUE RANGE OF sflight-connid(
  ( sign = 'I' option = 'BT' low = '0010' high = '0099' )
).

SELECT carrid,
       connid,
       fldate
  FROM sflight
  WHERE connid IN @lr_connid
  INTO TABLE @DATA(lt_sflight).
```

이 조건은 개념적으로 다음과 유사하다.

```sql
WHERE connid BETWEEN '0010' AND '0099'
```

초급자가 주의할 점은 `LOW`와 `HIGH`의 값 타입이 DB 필드 타입과 맞아야 한다는 것이다.  
예를 들어 `connid`가 문자 기반 숫자 형식이라면 앞자리 0을 포함한 값 체계를 유지해야 한다.

## 11. Include와 Exclude 조건

Range Table의 `SIGN`은 포함과 제외를 나타낸다.

| SIGN | 의미 |
|---|---|
| I | Include |
| E | Exclude |

### 11.1 Include 조건

```abap
DATA(lr_carrid) = VALUE RANGE OF sflight-carrid(
  ( sign = 'I' option = 'EQ' low = 'AA' )
  ( sign = 'I' option = 'EQ' low = 'LH' )
).
```

의미:

```text
AA 또는 LH 포함
```

### 11.2 Exclude 조건

```abap
DATA(lr_carrid) = VALUE RANGE OF sflight-carrid(
  ( sign = 'E' option = 'EQ' low = 'AA' )
).
```

의미:

```text
AA 제외
```

단, Exclude 조건은 초급자가 오해하기 쉽다.  
특히 Include 조건과 Exclude 조건이 섞이면 실제 조회 결과를 직관적으로 예측하기 어려울 수 있다.

실무 Report에서는 사용자가 복잡한 Include/Exclude 조건을 입력할 수 있으므로, 중요 데이터 조회에서는 조건 해석 결과를 사용자에게 명확히 보여주거나 입력 제한을 검토할 수 있다.

## 12. 여러 SELECT-OPTIONS 조건 조합

실무에서는 하나의 Selection Screen에 여러 조건이 있다.

```abap
TABLES sflight.

SELECT-OPTIONS s_carrid FOR sflight-carrid.
SELECT-OPTIONS s_connid FOR sflight-connid.
SELECT-OPTIONS s_fldate FOR sflight-fldate.

START-OF-SELECTION.

  SELECT carrid,
         connid,
         fldate,
         price,
         currency
    FROM sflight
    WHERE carrid IN @s_carrid
      AND connid IN @s_connid
      AND fldate IN @s_fldate
    INTO TABLE @DATA(lt_flight).
```

이 코드는 다음 조건을 모두 만족하는 데이터를 조회한다.

```text
항공사 코드 조건
AND 연결 번호 조건
AND 비행일자 조건
```

초급자가 이해해야 할 점은 다음이다.

```text
SELECT-OPTIONS 여러 개를 WHERE에 연결하면 일반적으로 AND 조건으로 결합한다.
각 SELECT-OPTIONS 내부에서는 사용자가 입력한 여러 행이 Range 조건으로 해석된다.
```

---

## 13. WHERE IN과 성능 감각

### 13.1 WHERE 조건은 DB로 내려간다

Open SQL의 `WHERE` 조건은 데이터베이스에서 데이터를 줄이는 역할을 한다.  
따라서 가능한 한 조건을 DB 조회 단계에 넣는 것이 중요하다.

나쁜 방식:

```abap
SELECT *
  FROM sflight
  INTO TABLE @DATA(lt_sflight).

DELETE lt_sflight WHERE carrid NOT IN s_carrid.
```

좋은 방식:

```abap
SELECT *
  FROM sflight
  WHERE carrid IN @s_carrid
  INTO TABLE @DATA(lt_sflight).
```

첫 번째 방식은 DB에서 모든 데이터를 가져온 뒤 ABAP 메모리에서 지운다.  
두 번째 방식은 DB에서 필요한 데이터만 가져온다.

실무에서는 두 번째 방식이 일반적으로 더 바람직하다.

### 13.2 조건 필드와 인덱스

`WHERE` 조건에 사용한 필드가 테이블의 Key 또는 Index와 잘 맞으면 조회 성능에 도움이 될 수 있다.

예를 들어 `SFLIGHT`는 학습용 표준 테이블이지만, 실제 업무 테이블에서는 다음을 고려해야 한다.

| 고려 항목 | 설명 |
|---|---|
| Key 필드 조건 | Primary Key 또는 주요 Index와 맞는 조건은 유리할 수 있다. |
| 너무 넓은 범위 | Range가 넓으면 조건 효과가 작아질 수 있다. |
| Exclude 조건 | DB 최적화 측면에서 Include보다 해석이 복잡할 수 있다. |
| 대량 IN 조건 | Range Table에 너무 많은 행이 있으면 성능 검토가 필요하다. |

초급 단계에서는 다음 원칙을 기억한다.

```text
가능하면 DB에서 줄이고 가져온다.
조건 없이 전체 데이터를 가져온 뒤 ABAP에서 지우는 방식은 피한다.
```

## 14. `FOR ALL ENTRIES`와 혼동하지 않기

초급자는 `WHERE field IN @range`와 `FOR ALL ENTRIES`를 혼동하기 쉽다.

| 구분 | WHERE field IN @range | FOR ALL ENTRIES |
|---|---|---|
| 주 목적 | Range 조건으로 필터링 | Internal Table의 여러 키를 기준으로 조회 |
| 데이터 구조 | Range Table | 일반 Internal Table |
| 대표 구조 | SIGN/OPTION/LOW/HIGH | 업무 필드 구조 |
| 사용 예 | Selection Screen 조건 | 선행 조회 결과 기반 후속 조회 |
| 초급 학습 위치 | SELECT-OPTIONS와 Range Table | Open SQL 응용 또는 성능 주제 |

이번 모듈에서는 `FOR ALL ENTRIES`를 다루지 않는다.  
핵심은 Range Table을 SQL 조건으로 연결하는 것이다.

## 15. 실습: 항공사 조건으로 SFLIGHT 조회

### 15.1 실습 목표

사용자가 입력한 항공사 코드 조건을 기준으로 `SFLIGHT` 데이터를 조회한다.

### 15.2 실습 코드

```abap
REPORT zgpt_so_where_in_flight.

TABLES sflight.

SELECT-OPTIONS s_carrid FOR sflight-carrid.

START-OF-SELECTION.

  SELECT carrid,
         connid,
         fldate,
         price,
         currency
    FROM sflight
    WHERE carrid IN @s_carrid
    INTO TABLE @DATA(lt_flight).

  IF lt_flight IS INITIAL.
    WRITE: / '조회된 데이터가 없습니다.'.
    RETURN.
  ENDIF.

  WRITE: / '조회 건수:', lines( lt_flight ).

  ULINE.

  LOOP AT lt_flight INTO DATA(ls_flight).
    WRITE: / ls_flight-carrid,
             ls_flight-connid,
             ls_flight-fldate,
             ls_flight-price,
             ls_flight-currency.
  ENDLOOP.
```

### 15.3 실행 테스트

다음 조건으로 실행해본다.

| 테스트 | 입력 조건 | 기대 결과 |
|---|---|---|
| 1 | `AA` 단일값 | AA 항공사 데이터 조회 |
| 2 | `AA`, `LH` 복수값 | AA 또는 LH 데이터 조회 |
| 3 | `AA` 제외 | AA를 제외한 데이터 조회 |
| 4 | 비어 있음 | 시스템/코드 동작 확인 |
| 5 | 존재하지 않는 항공사 코드 | 조회 결과 없음 |

### 15.4 실습 기록 양식

| 항목 | 기록 |
|---|---|
| 입력한 `s_carrid` 조건 |  |
| 조회 건수 |  |
| `s_carrid` 내부 행 수 |  |
| 조회 결과가 없는 경우 메시지 |  |
| 예상과 다른 결과가 나온 경우 원인 |  |

## 16. 디버깅 포인트

Range Table을 제대로 이해하려면 디버깅이 매우 중요하다.

### 16.1 확인할 변수

디버거에서 다음을 확인한다.

| 변수 | 확인 내용 |
|---|---|
| `s_carrid[]` | 전체 Range Table 행 |
| `s_carrid-sign` | Include/Exclude 여부 |
| `s_carrid-option` | EQ, BT 등 조건 |
| `s_carrid-low` | 단일값 또는 하한값 |
| `s_carrid-high` | 상한값 |
| `lt_flight` | 조회 결과 Internal Table |

### 16.2 추천 디버깅 흐름

```text
1. Selection Screen에서 여러 조건 입력
2. START-OF-SELECTION에 Breakpoint 설정
3. s_carrid[] 내부 행 확인
4. SIGN/OPTION/LOW/HIGH 값 확인
5. SELECT 실행 후 lt_flight 건수 확인
6. 조건과 조회 결과가 일치하는지 비교
```

이 과정을 통해 학습자는 `SELECT-OPTIONS`가 단순 화면 필드가 아니라 Range Table이라는 점을 체감할 수 있다.

## 17. 자주 발생하는 오류

### 17.1 `@` 누락

오류 예:

```abap
WHERE carrid IN s_carrid
```

수정:

```abap
WHERE carrid IN @s_carrid
```

최신 Open SQL 문법에서는 Host Variable 앞에 `@`를 붙이는 습관을 들인다.

### 17.2 필드 타입 불일치

오류 또는 문제 상황:

```abap
DATA lr_wrong TYPE RANGE OF char40.

SELECT *
  FROM sflight
  WHERE carrid IN @lr_wrong
  INTO TABLE @DATA(lt_sflight).
```

가능하면 Range Table 타입은 대상 필드 타입을 기준으로 선언한다.

권장:

```abap
DATA lr_carrid TYPE RANGE OF sflight-carrid.
```

### 17.3 Range Table이 비었는데 전체 조회됨

상황:

```abap
SELECT *
  FROM 큰_테이블
  WHERE field IN @s_field
  INTO TABLE @DATA(lt_data).
```

사용자가 조건을 비워두면 데이터가 너무 많이 조회될 수 있다.  
실무에서는 `OBLIGATORY`, 날짜 조건 필수화, 최대 조회 건수 제한 등을 검토한다.

### 17.4 Exclude 조건 오해

사용자가 `E EQ AA`를 입력하면 AA가 제외된다.  
하지만 Include와 Exclude가 섞이면 결과가 복잡해질 수 있다.

해결 방법:

- 복잡한 입력 조건은 디버거로 Range Table을 확인한다.
- 사용자에게 입력 조건 가이드를 제공한다.
- 필요한 경우 Selection Screen 검증 로직으로 제한한다.

### 17.5 `SELECT-OPTIONS` 이름과 DB 필드 이름 혼동

예:

```abap
SELECT-OPTIONS s_carrid FOR sflight-carrid.

SELECT *
  FROM sflight
  WHERE s_carrid IN @s_carrid
  INTO TABLE @DATA(lt_sflight).
```

위 코드는 잘못된 사고방식이다.  
`WHERE` 왼쪽에는 DB 필드가 와야 한다.

올바른 예:

```abap
WHERE carrid IN @s_carrid
```

## 18. 실무 패턴

### 18.1 필수 조건과 선택 조건 분리

대량 테이블에서는 모든 조건을 선택 사항으로 두면 위험하다.

예:

```abap
SELECT-OPTIONS s_bukrs FOR bkpf-bukrs OBLIGATORY.
SELECT-OPTIONS s_budat FOR bkpf-budat OBLIGATORY.
SELECT-OPTIONS s_belnr FOR bkpf-belnr.
```

이 설계는 회사코드와 전기일은 필수로 하고, 문서번호는 선택 조건으로 둔다.

### 18.2 날짜 조건은 필수로 검토

실무 대량 테이블에서는 날짜 조건이 매우 중요하다.  
예를 들어 전표, 판매오더, 이력, 로그 테이블은 날짜 범위 없이 조회하면 성능 문제가 생길 수 있다.

```abap
SELECT-OPTIONS s_fldate FOR sflight-fldate OBLIGATORY.
```

### 18.3 최대 조회 건수 제한

교육용 Report에서는 생략할 수 있지만, 실무에서는 조회 건수 제한 또는 사전 검증을 고려한다.

```abap
SELECT *
  FROM sflight
  WHERE carrid IN @s_carrid
  UP TO 100 ROWS
  INTO TABLE @DATA(lt_sflight).
```

단, `UP TO n ROWS`는 사용 목적을 명확히 해야 한다.  
업무 결과를 완전하게 보여줘야 하는 프로그램에서 임의로 잘라내면 안 된다.

### 18.4 Selection Screen 입력 조건 로그

중요한 배치나 대량 조회 프로그램에서는 사용자가 어떤 조건으로 실행했는지 로그로 남기는 경우도 있다.

예:

```text
실행자
실행일시
입력 회사코드
입력 날짜 범위
조회 건수
처리 건수
오류 건수
```

이 주제는 Track 2의 실무 응용, 배치, 로그 설계에서 더 깊게 다룰 수 있다.

## 19. Clean Code 관점

`WHERE field IN @range`는 매우 간결하지만, 무조건 한 줄로 끝내는 것이 항상 좋은 코드는 아니다.

### 19.1 좋은 코드의 특징

| 기준 | 설명 |
|---|---|
| 조건 의도가 명확함 | 어떤 필드가 어떤 Range와 연결되는지 쉽게 보임 |
| 타입이 일치함 | `TYPE RANGE OF dbtab-field` 또는 `SELECT-OPTIONS FOR dbtab-field` 사용 |
| 비어 있는 조건 처리 | 전체 조회 허용/차단이 명확함 |
| 대량 조회 방어 | 필수 조건 또는 날짜 조건 고려 |
| 후속 처리 분리 | 조회, 검증, 출력 로직이 너무 뒤섞이지 않음 |

### 19.2 나쁜 코드 예

```abap
SELECT *
  FROM zbig_table
  INTO TABLE @DATA(lt_data).

DELETE lt_data WHERE bukrs NOT IN s_bukrs.
DELETE lt_data WHERE budat NOT IN s_budat.
```

문제:

- DB에서 전체 데이터를 가져온다.
- ABAP 메모리에서 뒤늦게 필터링한다.
- 대량 데이터에서 성능 문제가 크다.
- 프로그램 의도가 불명확하다.

개선:

```abap
SELECT *
  FROM zbig_table
  WHERE bukrs IN @s_bukrs
    AND budat IN @s_budat
  INTO TABLE @DATA(lt_data).
```

## 21. 평가 문제

### 21.1 객관식

#### Q1. `WHERE carrid IN @s_carrid`에서 `@s_carrid`의 의미로 가장 적절한 것은?

A. DB 테이블 이름  
B. ABAP 프로그램의 Range Table 또는 SELECT-OPTIONS 변수  
C. SAP Client 번호  
D. 화면 제목  

정답: B

#### Q2. Range Table의 기본 구성 필드가 아닌 것은?

A. SIGN  
B. OPTION  
C. LOW  
D. INDEX  

정답: D

#### Q3. 대량 테이블 조회에서 가장 바람직한 방식은?

A. 전체 데이터를 가져온 뒤 Internal Table에서 삭제한다.  
B. DB 조회 조건 없이 항상 전체 조회한다.  
C. 가능한 조건을 Open SQL의 WHERE에 반영한다.  
D. WHERE 조건은 화면 출력 후 적용한다.  

정답: C

### 21.2 단답형

#### Q1. Host Variable Escape `@`의 목적은 무엇인가?

모범 답안:  
Open SQL 문장 안에서 ABAP 프로그램의 변수나 Internal Table을 명확히 구분하기 위해 사용한다.

#### Q2. `SELECT-OPTIONS`가 `WHERE IN`에 바로 사용될 수 있는 이유는 무엇인가?

모범 답안:  
`SELECT-OPTIONS`는 내부적으로 `SIGN`, `OPTION`, `LOW`, `HIGH`를 가진 Range Table 구조이기 때문에 Open SQL의 `IN @range` 조건에 사용할 수 있다.

#### Q3. Range Table이 비어 있을 때 실무에서 주의해야 하는 점은 무엇인가?

모범 답안:  
조건 없이 전체 조회가 발생하거나, 의도와 다른 결과가 나올 수 있으므로 전체 조회를 허용할지 입력을 필수화할지 명확히 설계해야 한다.

## 22. 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
SELECT-OPTIONS는 Range Table 구조를 가진다.
Range Table은 SIGN, OPTION, LOW, HIGH로 조건을 표현한다.
Open SQL에서는 WHERE field IN @range_table 형식으로 조건을 전달한다.
@는 ABAP 변수임을 표시하는 Host Variable Escape이다.
조건 없이 전체 조회되는 상황은 반드시 의도적으로 설계해야 한다.
가능하면 DB 조회 단계에서 조건을 적용하고, ABAP 메모리에서 뒤늦게 필터링하는 방식은 피한다.
```

초급자는 다음 패턴을 반드시 익힌다.

```abap
SELECT-OPTIONS s_field FOR dbtab-field.

SELECT ...
  FROM dbtab
  WHERE field IN @s_field
  INTO TABLE @DATA(lt_result).
```
