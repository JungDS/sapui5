## 3. Selection Table과 Range Table의 관계

### 3.1 Range Table

Range Table은 특정 필드에 대한 조건 집합을 담는 Internal Table이다.

예를 들어 항공사 코드 `SFLIGHT-CARRID`에 대한 Range Table은 다음처럼 선언할 수 있다.

```abap
DATA lt_carrid_range TYPE RANGE OF sflight-carrid.
```

이 선언은 내부적으로 다음 구조의 행을 여러 개 가질 수 있는 테이블을 만든다.

| 필드 | 의미 |
|---|---|
| `SIGN` | 포함 또는 제외. `I` 또는 `E` |
| `OPTION` | 비교 방식. `EQ`, `BT`, `CP` 등 |
| `LOW` | 단일값 또는 범위 시작값 |
| `HIGH` | 범위 종료값 |

### 3.2 Selection Table

`SELECT-OPTIONS`를 선언하면 Selection Screen에 입력 필드가 생기고, ABAP 프로그램 내부에는 같은 구조의 Selection Table이 만들어진다.

```abap
TABLES sflight.

SELECT-OPTIONS s_carrid FOR sflight-carrid.
```

여기서 `s_carrid`는 화면 입력 필드처럼 보이지만, ABAP 코드에서는 조건 행을 가진 Selection Table처럼 다룰 수 있다.

즉 다음 두 개념은 형태가 매우 유사하다.

| 구분 | 생성 방식 | 주요 사용 |
|---|---|---|
| Range Table | `DATA ... TYPE RANGE OF ...` | 코드에서 조건 집합 구성 |
| Selection Table | `SELECT-OPTIONS ... FOR ...` | Selection Screen 입력 조건 수신 |

초급자는 다음 문장을 기억하면 된다.

```text
SELECT-OPTIONS는 화면이 있는 Range Table이라고 이해해도 좋다.
```

단, 이 표현은 학습용 비유이다. 실제 표준 동작에서는 Selection Screen의 화면 처리, 사용자 입력, 이벤트 흐름이 함께 연결된다.

## 4. Range Line 직접 추가하기

### 4.1 가장 기본적인 APPEND 방식

다음 코드는 항공사 코드 `AA`만 조회하는 조건을 Range Table에 직접 추가한다.

```abap
DATA lt_carrid_range TYPE RANGE OF sflight-carrid.

APPEND VALUE #( sign   = 'I'
                option = 'EQ'
                low    = 'AA' ) TO lt_carrid_range.
```

이 코드는 다음 조건 행을 만든다.

| SIGN | OPTION | LOW | HIGH | 의미 |
|---|---|---|---|---|
| I | EQ | AA |  | AA를 포함 |

이후 Open SQL에서 다음처럼 사용할 수 있다.

```abap
SELECT carrid,
       connid,
       fldate,
       price,
       currency
  FROM sflight
  WHERE carrid IN @lt_carrid_range
  INTO TABLE @DATA(lt_flights).
```

### 4.2 여러 값을 APPEND하기

여러 항공사 코드를 포함하려면 조건 행을 여러 개 추가한다.

```abap
DATA lt_carrid_range TYPE RANGE OF sflight-carrid.

APPEND VALUE #( sign = 'I' option = 'EQ' low = 'AA' ) TO lt_carrid_range.
APPEND VALUE #( sign = 'I' option = 'EQ' low = 'LH' ) TO lt_carrid_range.
APPEND VALUE #( sign = 'I' option = 'EQ' low = 'UA' ) TO lt_carrid_range.
```

조건의 의미는 다음과 같다.

```text
CARRID = 'AA'
또는 CARRID = 'LH'
또는 CARRID = 'UA'
```

Open SQL에서는 다음처럼 연결된다.

```abap
WHERE carrid IN @lt_carrid_range
```

초급자는 `IN`이 단일값 하나가 아니라 조건 집합 전체를 받는다는 점을 이해해야 한다.

## 5. VALUE 문법으로 Range Table 한 번에 만들기

### 5.1 기본 문법

`APPEND`를 여러 번 쓰는 대신 `VALUE #( ... )`로 Range Table 전체를 한 번에 만들 수 있다.

```abap
DATA lt_carrid_range TYPE RANGE OF sflight-carrid.

lt_carrid_range = VALUE #(
  ( sign = 'I' option = 'EQ' low = 'AA' )
  ( sign = 'I' option = 'EQ' low = 'LH' )
  ( sign = 'I' option = 'EQ' low = 'UA' )
).
```

이 방식은 조건이 명확하고 고정되어 있을 때 가독성이 좋다.

### 5.2 APPEND 방식과 VALUE 방식 비교

| 구분 | APPEND 방식 | VALUE 방식 |
|---|---|---|
| 특징 | 한 줄씩 추가 | 한 번에 전체 구성 |
| 장점 | 조건을 단계적으로 추가하기 좋음 | 코드가 간결하고 구조가 잘 보임 |
| 단점 | 줄 수가 많아질 수 있음 | 조건이 동적으로 복잡하면 읽기 어려울 수 있음 |
| 추천 상황 | 반복문 안에서 조건 추가 | 고정 기본 조건 구성 |

### 5.3 실무적 판단

조건이 프로그램 실행 중 동적으로 결정된다면 `APPEND`가 편하다. 반대로 시작 시점에 명확한 기본 조건을 선언적으로 만들고 싶다면 `VALUE`가 좋다.

```text
조건을 하나씩 계산해서 넣는다 → APPEND
조건 목록이 이미 정해져 있다 → VALUE
```

## 6. BT 조건 직접 만들기

`BT`는 Between 조건이다. `LOW`와 `HIGH`를 함께 사용한다.

```abap
DATA lt_date_range TYPE RANGE OF sflight-fldate.

APPEND VALUE #( sign   = 'I'
                option = 'BT'
                low    = '20260101'
                high   = '20261231' ) TO lt_date_range.
```

조건 의미는 다음과 같다.

```text
FLDATE가 2026-01-01부터 2026-12-31 사이인 데이터
```

Open SQL에서는 다음처럼 사용한다.

```abap
SELECT carrid,
       connid,
       fldate
  FROM sflight
  WHERE fldate IN @lt_date_range
  INTO TABLE @DATA(lt_flight_dates).
```

### 6.1 BT에서 자주 하는 실수

| 실수 | 문제 |
|---|---|
| `HIGH`를 비워둠 | 범위 종료값이 없어 조건이 의도와 다를 수 있다. |
| `LOW > HIGH` | 시작값이 종료값보다 커서 결과가 없거나 비정상적 조건이 된다. |
| 날짜를 문자처럼 임의 입력 | DATS 형식 `YYYYMMDD`를 지켜야 한다. |
| 숫자와 문자 타입 혼동 | 대상 필드 타입과 Range Table 타입을 맞춰야 한다. |

초급자는 `BT`를 사용할 때 다음을 습관화해야 한다.

```text
BT는 LOW와 HIGH를 함께 확인한다.
LOW가 시작값이고 HIGH가 종료값이다.
```

## 7. CP 조건 직접 만들기

`CP`는 Contains Pattern 조건이다. 패턴을 이용해 문자열 조건을 만든다.

```abap
DATA lt_carrid_range TYPE RANGE OF sflight-carrid.

APPEND VALUE #( sign   = 'I'
                option = 'CP'
                low    = 'A*' ) TO lt_carrid_range.
```

조건 의미는 다음과 같다.

```text
A로 시작하는 항공사 코드 포함
```

ABAP Selection Option의 `CP` 패턴에서 자주 보는 문자는 다음이다.

| 패턴 | 의미 |
|---|---|
| `*` | 임의 길이 문자열 |
| `+` | 한 글자 |

예를 들어 다음과 같이 해석할 수 있다.

| LOW | 의미 |
|---|---|
| `A*` | A로 시작하는 값 |
| `+A` | 두 글자 중 두 번째가 A인 값 |
| `*A*` | A를 포함하는 값 |

> 주의: ABAP Selection Option의 `CP` 패턴과 SQL `LIKE`의 `%`, `_` 패턴을 혼동하지 않는다. `SELECT-OPTIONS`와 Range Table 학습 단계에서는 `CP`의 `*`, `+`를 기준으로 이해한다.

## 8. Exclude 조건 직접 만들기

`SIGN = 'E'`는 제외 조건을 의미한다.

```abap
DATA lt_carrid_range TYPE RANGE OF sflight-carrid.

APPEND VALUE #( sign   = 'I'
                option = 'CP'
                low    = '*' ) TO lt_carrid_range.

APPEND VALUE #( sign   = 'E'
                option = 'EQ'
                low    = 'AA' ) TO lt_carrid_range.
```

위 조건은 학습용으로 다음과 같이 해석할 수 있다.

```text
전체를 포함하되 AA는 제외한다.
```

다만 실무 코드에서는 전체 포함을 위해 `CP '*'`를 무조건 쓰는 방식보다, 실제 필요한 포함 조건을 명확히 구성하는 것이 좋다.

### 8.1 Include와 Exclude를 섞을 때의 주의

Include와 Exclude를 섞으면 조건 해석이 어려워질 수 있다.

| 조합 | 위험 |
|---|---|
| Include 여러 줄 + Exclude 여러 줄 | 사용자가 결과를 예측하기 어려울 수 있다. |
| 넓은 Include + 좁은 Exclude | 의도는 명확할 수 있으나 설명이 필요하다. |
| Exclude만 존재 | 프로그램 결과가 직관적이지 않을 수 있다. |

초급자는 다음 원칙을 기억한다.

```text
직접 만든 Range 조건은 나중에 읽는 개발자도 이해할 수 있어야 한다.
```

## 9. SELECT-OPTIONS에 기본 조건 넣기

`SELECT-OPTIONS`로 생성된 Selection Table도 ABAP 코드에서 직접 조건 행을 추가할 수 있다.

### 9.1 기본 예제

```abap
REPORT zgpt_so_default.

TABLES sflight.

SELECT-OPTIONS s_carrid FOR sflight-carrid.

INITIALIZATION.
  APPEND VALUE #( sign   = 'I'
                  option = 'EQ'
                  low    = 'AA' ) TO s_carrid.

START-OF-SELECTION.
  SELECT carrid,
         connid,
         fldate
    FROM sflight
    WHERE carrid IN @s_carrid
    INTO TABLE @DATA(lt_flights).

  WRITE: / '조회 건수:', lines( lt_flights ).
```

이 예제는 Selection Screen이 표시되기 전에 `s_carrid`에 기본 조건 `AA`를 넣는다.

### 9.2 왜 INITIALIZATION을 사용하는가?

`INITIALIZATION`은 Selection Screen이 처음 표시되기 전에 기본값을 세팅하는 데 자주 사용된다.

초급 학습에서는 다음 정도로 이해하면 된다.

```text
PARAMETERS나 SELECT-OPTIONS의 기본값을 프로그램에서 미리 넣고 싶을 때 INITIALIZATION을 사용할 수 있다.
```

Report Event 전체 체계는 후속 Section에서 더 자세히 다루므로, 여기서는 `SELECT-OPTIONS` 기본 조건을 넣는 예제로만 이해한다.

### 9.3 DEFAULT와 직접 APPEND의 차이

단일 기본값만 넣는다면 `DEFAULT`가 더 단순하다.

```abap
SELECT-OPTIONS s_carrid FOR sflight-carrid DEFAULT 'AA'.
```

복수 조건이나 복잡한 조건을 넣으려면 직접 APPEND가 유리하다.

```abap
INITIALIZATION.
  APPEND VALUE #( sign = 'I' option = 'EQ' low = 'AA' ) TO s_carrid.
  APPEND VALUE #( sign = 'I' option = 'EQ' low = 'LH' ) TO s_carrid.
  APPEND VALUE #( sign = 'E' option = 'EQ' low = 'ZZ' ) TO s_carrid.
```

| 방식 | 적합한 상황 |
|---|---|
| `DEFAULT` | 단순한 기본 단일값 |
| 직접 APPEND | 여러 조건, Exclude, Between, Pattern 조건 |

## 10. Selection Table 초기화

### 10.1 CLEAR와 REFRESH

Selection Table 또는 Range Table을 비우고 다시 구성해야 할 때가 있다.

일반적인 Internal Table 초기화 관점에서는 다음처럼 사용할 수 있다.

```abap
CLEAR lt_carrid_range.
```

또는 전통적인 코드에서는 다음과 같은 형태도 볼 수 있다.

```abap
REFRESH lt_carrid_range.
```

초급자에게는 다음 원칙을 권장한다.

```text
새로운 ABAP 코드에서는 Internal Table 전체를 비울 때 CLEAR itab을 우선적으로 이해한다.
기존 코드에서 REFRESH를 만나면 테이블 본문 초기화 의미로 읽는다.
```

### 10.2 SELECT-OPTIONS 초기화 예

```abap
INITIALIZATION.
  CLEAR s_carrid.

  APPEND VALUE #( sign = 'I' option = 'EQ' low = 'AA' ) TO s_carrid.
  APPEND VALUE #( sign = 'I' option = 'EQ' low = 'LH' ) TO s_carrid.
```

단, 실제 Selection Screen 이벤트 흐름에서 사용자가 입력한 값을 언제 지우는지는 매우 신중해야 한다. 사용자가 이미 입력한 조건을 프로그램이 지워버리면 사용자는 프로그램이 자신의 입력을 무시한다고 느낄 수 있다.

## 11. Selection Table에서 조건 삭제하기

### 11.1 특정 조건 삭제

Range Table에서 특정 조건을 삭제할 수 있다.

```abap
DELETE lt_carrid_range
  WHERE sign   = 'E'
    AND option = 'EQ'
    AND low    = 'ZZ'.
```

이 코드는 `ZZ`를 제외하는 조건 행을 삭제한다.

### 11.2 잘못된 조건 삭제 예

예를 들어 `BT`인데 `HIGH`가 비어 있는 조건은 오류 가능성이 크다.

```abap
DELETE lt_date_range
  WHERE option = 'BT'
    AND high   IS INITIAL.
```

이런 검증은 사용자 입력값을 정리하거나, 프로그램이 직접 만든 조건을 보정할 때 사용할 수 있다.

### 11.3 삭제 시 주의점

삭제는 조건 결과를 직접 바꾸는 행위이다. 따라서 실무 코드에서는 삭제 이유를 명확히 남기는 것이 좋다.

```abap
" Remove invalid BT range rows without HIGH value.
DELETE lt_date_range
  WHERE option = 'BT'
    AND high   IS INITIAL.
```

Clean Code 관점에서는 “왜 삭제하는가”가 보이도록 주석 또는 메서드명을 사용한다.

## 12. LOOP AT으로 Range Line 확인하기

직접 조작한 Range Table이 의도대로 구성되었는지 확인하려면 `LOOP AT`으로 내부 행을 출력할 수 있다.

```abap
LOOP AT lt_carrid_range INTO DATA(ls_range).
  WRITE: / ls_range-sign,
           ls_range-option,
           ls_range-low,
           ls_range-high.
ENDLOOP.
```

Selection Table도 같은 방식으로 확인할 수 있다.

```abap
LOOP AT s_carrid INTO DATA(ls_carrid).
  WRITE: / ls_carrid-sign,
           ls_carrid-option,
           ls_carrid-low,
           ls_carrid-high.
ENDLOOP.
```

초급자에게 이 확인은 매우 중요하다. Selection Screen에서 입력한 내용이 실제 내부 테이블에서 어떻게 보이는지 확인하면 `SELECT-OPTIONS`의 동작이 훨씬 명확해진다.

## 13. 직접 조작한 조건으로 Open SQL 조회하기

다음은 직접 만든 Range Table을 실제 조회에 연결하는 전체 예제이다.

```abap
REPORT zgpt_range_direct_01.

DATA lt_carrid_range TYPE RANGE OF sflight-carrid.

lt_carrid_range = VALUE #(
  ( sign = 'I' option = 'EQ' low = 'AA' )
  ( sign = 'I' option = 'EQ' low = 'LH' )
  ( sign = 'E' option = 'EQ' low = 'ZZ' )
).

SELECT carrid,
       connid,
       fldate,
       price,
       currency
  FROM sflight
  WHERE carrid IN @lt_carrid_range
  INTO TABLE @DATA(lt_flights).

IF sy-subrc = 0.
  WRITE: / '조회 건수:', lines( lt_flights ).
ELSE.
  WRITE: / '조건에 맞는 데이터가 없습니다.'.
ENDIF.
```

이 프로그램의 핵심은 다음이다.

```text
Range Table을 코드에서 직접 만든다.
WHERE field IN @range_table로 조회 조건에 연결한다.
조회 결과를 확인한다.
```

## 14. 실무 패턴 1: 사용자 조건에 기본 제한 추가

실무 프로그램에서는 사용자가 입력한 조건에 프로그램이 추가 제한을 더해야 할 때가 있다.

예를 들어 사용자가 항공사 코드를 입력하더라도, 프로그램 정책상 특정 항공사는 제외해야 한다고 가정한다.

```abap
SELECT-OPTIONS s_carrid FOR sflight-carrid.

START-OF-SELECTION.
  APPEND VALUE #( sign   = 'E'
                  option = 'EQ'
                  low    = 'ZZ' ) TO s_carrid.

  SELECT carrid,
         connid,
         fldate
    FROM sflight
    WHERE carrid IN @s_carrid
    INTO TABLE @DATA(lt_flights).
```

이 패턴은 유용하지만 주의가 필요하다. 사용자가 입력하지 않은 조건을 프로그램이 추가하기 때문이다.

실무에서는 다음을 고려해야 한다.

| 고려 항목 | 설명 |
|---|---|
| 사용자 인지 | 프로그램이 추가 제한을 적용한다는 점을 알 수 있는가? |
| 권한 | 제외 조건이 권한 통제 목적이라면 별도 권한 체크가 필요한가? |
| 감사 | 조회 조건이 변경되는 이유를 추적할 수 있는가? |
| 유지보수 | 하드코딩된 제외값이 나중에 문제가 되지 않는가? |

---

## 15. 실무 패턴 2: 기본 조회 기간 설정

날짜 Range Table에 기본 기간을 설정할 수 있다.

```abap
TABLES sflight.

SELECT-OPTIONS s_fldate FOR sflight-fldate.

INITIALIZATION.
  APPEND VALUE #( sign   = 'I'
                  option = 'BT'
                  low    = sy-datum
                  high   = sy-datum + 30 ) TO s_fldate.
```

이 예제는 오늘부터 30일 후까지의 기본 조회 기간을 설정한다.

> [추정] 실제 업무에서는 `sy-datum + 30` 같은 단순 계산보다 공장 달력, 영업일, 회계기간, 타임존 등을 고려해야 할 수 있다. 이 모듈에서는 Range Table 조작 문법 이해를 위해 단순 날짜 계산으로 제한한다.

## 16. 실무 패턴 3: 내부 계산 결과를 Range Table로 변환

프로그램에서 어떤 조건 목록을 계산한 뒤 이를 Range Table로 변환해야 할 수 있다.

예를 들어 허용 항공사 목록이 Internal Table에 있다고 가정한다.

```abap
DATA lt_allowed_carrid TYPE STANDARD TABLE OF sflight-carrid WITH EMPTY KEY.
DATA lt_carrid_range   TYPE RANGE OF sflight-carrid.

lt_allowed_carrid = VALUE #( ( 'AA' ) ( 'LH' ) ( 'UA' ) ).

LOOP AT lt_allowed_carrid INTO DATA(lv_carrid).
  APPEND VALUE #( sign   = 'I'
                  option = 'EQ'
                  low    = lv_carrid ) TO lt_carrid_range.
ENDLOOP.
```

이후 다음처럼 조회에 사용한다.

```abap
SELECT carrid,
       connid,
       fldate
  FROM sflight
  WHERE carrid IN @lt_carrid_range
  INTO TABLE @DATA(lt_flights).
```

이 패턴은 실무에서 자주 사용된다. 예를 들어 권한 기준, 설정 테이블 기준, 사용자 프로필 기준으로 조회 대상 목록을 만든 뒤 Range Table로 변환할 수 있다.

## 17. 실무 패턴 4: Range Table을 메서드 파라미터로 전달

Range Table은 메서드나 함수에 파라미터로 전달할 수 있다.

```abap
CLASS lcl_flight_reader DEFINITION.
  PUBLIC SECTION.
    METHODS get_flights
      IMPORTING it_carrid_range TYPE RANGE OF sflight-carrid
      RETURNING VALUE(rt_flight) TYPE STANDARD TABLE OF sflight.
ENDCLASS.

CLASS lcl_flight_reader IMPLEMENTATION.
  METHOD get_flights.
    SELECT *
      FROM sflight
      WHERE carrid IN @it_carrid_range
      INTO TABLE @rt_flight.
  ENDMETHOD.
ENDCLASS.
```

호출부는 다음처럼 작성할 수 있다.

```abap
DATA lt_carrid_range TYPE RANGE OF sflight-carrid.

lt_carrid_range = VALUE #(
  ( sign = 'I' option = 'EQ' low = 'AA' )
  ( sign = 'I' option = 'EQ' low = 'LH' )
).

DATA(lo_reader) = NEW lcl_flight_reader( ).
DATA(lt_flights) = lo_reader->get_flights( lt_carrid_range ).
```

이 예제는 OO ABAP 심화가 아니라, Range Table이 프로그램 내부 조건 전달 구조로도 사용될 수 있다는 감각을 주기 위한 것이다.

## 18. 직접 조작 시 자주 발생하는 오류

### 18.1 SIGN 값 오류

```abap
APPEND VALUE #( sign = 'X' option = 'EQ' low = 'AA' ) TO lt_carrid_range.
```

`SIGN`에는 일반적으로 `I` 또는 `E`를 사용한다. `X`는 올바른 포함/제외 의미가 아니다.

해결:

```abap
APPEND VALUE #( sign = 'I' option = 'EQ' low = 'AA' ) TO lt_carrid_range.
```

### 18.2 OPTION 값 오류

```abap
APPEND VALUE #( sign = 'I' option = 'XX' low = 'AA' ) TO lt_carrid_range.
```

`OPTION`에는 `EQ`, `BT`, `CP` 등 Selection Option에서 허용되는 비교 연산을 사용해야 한다.

### 18.3 BT에서 HIGH 누락

```abap
APPEND VALUE #( sign = 'I' option = 'BT' low = 'AA' ) TO lt_carrid_range.
```

`BT`는 범위 조건이므로 `HIGH`가 필요하다.

수정:

```abap
APPEND VALUE #( sign   = 'I'
                option = 'BT'
                low    = 'AA'
                high   = 'LH' ) TO lt_carrid_range.
```

### 18.4 대상 필드와 Range 타입 불일치

항공사 코드 Range Table을 날짜 필드에 사용하면 의미가 맞지 않는다.

나쁜 예:

```abap
DATA lt_carrid_range TYPE RANGE OF sflight-carrid.

SELECT *
  FROM sflight
  WHERE fldate IN @lt_carrid_range
  INTO TABLE @DATA(lt_result).
```

좋은 예:

```abap
DATA lt_date_range TYPE RANGE OF sflight-fldate.

SELECT *
  FROM sflight
  WHERE fldate IN @lt_date_range
  INTO TABLE @DATA(lt_result).
```

### 18.5 사용자의 입력 조건을 무조건 덮어씀

```abap
START-OF-SELECTION.
  CLEAR s_carrid.
  APPEND VALUE #( sign = 'I' option = 'EQ' low = 'AA' ) TO s_carrid.
```

이 코드는 사용자가 입력한 조건을 실행 시점에 지워버릴 수 있다. 이런 처리는 사용자 경험과 결과 신뢰성 측면에서 위험하다.

해결 방향:

```text
기본값은 INITIALIZATION에서 제공한다.
사용자 입력을 변경해야 한다면 명확한 이유가 있어야 한다.
필요하면 메시지나 문서로 조건 보정 규칙을 안내한다.
```

## 19. 검증용 출력 예제

Range Table을 직접 조작할 때는 내부 조건을 확인하는 디버깅 습관이 중요하다. 다음 예제는 조건 행을 리스트로 출력한다.

```abap
FORM display_range USING it_range TYPE RANGE OF sflight-carrid.

  LOOP AT it_range INTO DATA(ls_range).
    WRITE: / 'SIGN:',   ls_range-sign,
             'OPTION:', ls_range-option,
             'LOW:',    ls_range-low,
             'HIGH:',   ls_range-high.
  ENDLOOP.

ENDFORM.
```

초급 과정에서는 `FORM` 자체를 깊게 설명하지 않아도 된다. 핵심은 Range Table 안의 조건 행을 눈으로 확인하는 것이다.

더 단순하게는 다음처럼 직접 `LOOP AT`을 써도 된다.

```abap
LOOP AT lt_carrid_range INTO DATA(ls_range).
  WRITE: / ls_range-sign, ls_range-option, ls_range-low, ls_range-high.
ENDLOOP.
```

## 20. 디버깅 포인트

Range Table 직접 조작을 디버깅할 때는 다음 지점을 확인한다.

| 확인 위치 | 확인 내용 |
|---|---|
| APPEND 직후 | 조건 행이 실제로 추가되었는가 |
| SELECT 직전 | Range Table의 최종 조건 집합이 의도와 같은가 |
| SELECT 직후 | `sy-subrc`, 조회 건수, 결과 데이터가 의도와 같은가 |
| 사용자 입력 후 | Selection Table에 사용자의 입력이 어떤 행으로 들어왔는가 |
| 조건 삭제 후 | 삭제 대상만 정확히 제거되었는가 |

디버거에서는 Range Table을 펼쳐 각 행의 `SIGN`, `OPTION`, `LOW`, `HIGH` 값을 직접 확인한다.

## 21. 실무 주의사항

### 21.1 하드코딩을 남발하지 않는다

다음 코드는 교육용으로는 이해하기 쉽지만 실무에서는 주의가 필요하다.

```abap
APPEND VALUE #( sign = 'I' option = 'EQ' low = 'AA' ) TO lt_carrid_range.
```

업무 코드에서 특정 값을 직접 박아 넣는 것은 변경에 취약하다. 실무에서는 설정 테이블, 상수, Customizing, 권한 객체, 사용자 입력 등을 검토해야 한다.

### 21.2 조건 보정 로직은 명시적으로 작성한다

사용자 입력 조건을 프로그램이 변경한다면 코드에서 의도가 드러나야 한다.

나쁜 예:

```abap
DELETE s_carrid WHERE low = 'ZZ'.
```

좋은 예:

```abap
" Exclude blocked carrier code from user selection.
DELETE s_carrid WHERE low = 'ZZ'.
```

더 좋은 구조는 별도 메서드로 의미를 표현하는 것이다.

```abap
" [예시] OO ABAP 후속 학습에서 더 자연스럽게 다룰 구조
remove_blocked_carrier_codes( CHANGING ct_carrid_range = s_carrid[] ).
```

### 21.3 권한 처리를 Range Table만으로 대체하지 않는다

Range Table을 이용해 조회 조건을 제한할 수는 있다. 하지만 이것이 곧 권한 체크를 대체하는 것은 아니다.

```text
조회 조건 제한 ≠ 권한 검증 완료
```

권한이 중요한 프로그램에서는 표준 권한 객체, `AUTHORITY-CHECK`, 역할/프로파일, 애플리케이션 권한 설계를 별도로 검토해야 한다.

### 21.4 너무 복잡한 Range Table은 분리해서 만든다

Include, Exclude, EQ, BT, CP가 복잡하게 섞이면 조건을 읽기 어려워진다. 이럴 때는 다음 방식이 좋다.

```text
1. 기본 포함 조건 생성
2. 제외 조건 추가
3. 잘못된 조건 제거
4. 최종 조건 검증
5. SELECT 실행
```

단계를 나누면 디버깅과 유지보수가 쉬워진다.

## 22. 미니 실습

### 22.1 실습 목표

항공사 코드 Range Table을 직접 만들고, `SFLIGHT`를 조회한 뒤 조건 행과 조회 건수를 출력한다.

### 22.2 실습 코드

```abap
REPORT zgpt_range_direct_lab.

DATA lt_carrid_range TYPE RANGE OF sflight-carrid.

lt_carrid_range = VALUE #(
  ( sign = 'I' option = 'EQ' low = 'AA' )
  ( sign = 'I' option = 'EQ' low = 'LH' )
  ( sign = 'E' option = 'EQ' low = 'ZZ' )
).

WRITE: / '--- Range Conditions ---'.
LOOP AT lt_carrid_range INTO DATA(ls_range).
  WRITE: / ls_range-sign,
           ls_range-option,
           ls_range-low,
           ls_range-high.
ENDLOOP.

SELECT carrid,
       connid,
       fldate,
       price,
       currency
  FROM sflight
  WHERE carrid IN @lt_carrid_range
  INTO TABLE @DATA(lt_flights).

WRITE: / '--- Result ---'.
WRITE: / 'Rows:', lines( lt_flights ).

LOOP AT lt_flights INTO DATA(ls_flight) FROM 1 TO 10.
  WRITE: / ls_flight-carrid,
           ls_flight-connid,
           ls_flight-fldate,
           ls_flight-price,
           ls_flight-currency.
ENDLOOP.
```

### 22.3 실습 확인 항목

| 확인 항목 | 설명 |
|---|---|
| Range 조건 출력 | `AA`, `LH`, `ZZ 제외` 조건이 보이는가 |
| 조회 건수 | 조건에 맞는 데이터가 조회되는가 |
| `sy-subrc` | SELECT 후 결과 존재 여부를 확인할 수 있는가 |
| 결과 상위 10건 | 너무 많은 출력이 발생하지 않도록 제한했는가 |

### 25.2 서술형

#### Q1. Range Table을 직접 구성하는 대표적인 두 가지 방법을 설명하시오.

모범 답안:

```text
첫 번째는 APPEND VALUE #( ... ) TO range_table을 사용해 조건 행을 하나씩 추가하는 방식이다.
두 번째는 range_table = VALUE #( ( ... ) ( ... ) ) 형태로 조건 집합 전체를 한 번에 구성하는 방식이다.
```

#### Q2. `SELECT-OPTIONS`에 기본 조건을 직접 넣을 때 `INITIALIZATION`을 사용할 수 있는 이유를 설명하시오.

모범 답안:

```text
INITIALIZATION은 Selection Screen이 처음 표시되기 전에 기본값을 세팅하는 데 사용할 수 있는 이벤트이다. 따라서 SELECT-OPTIONS의 Selection Table에 기본 조건 행을 미리 추가해 사용자에게 초기 조건을 제공할 수 있다.
```

#### Q3. 사용자가 입력한 Selection Table을 프로그램에서 변경할 때 주의할 점을 설명하시오.

모범 답안:

```text
사용자가 입력한 조건을 프로그램이 임의로 삭제하거나 추가하면 조회 결과가 사용자의 기대와 달라질 수 있다. 따라서 변경 이유가 명확해야 하며, 권한이나 업무 정책 때문이라면 별도 권한 체크와 안내, 유지보수 가능한 구조를 함께 고려해야 한다.
```

## 26. 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
Selection Table과 Range Table은 SIGN, OPTION, LOW, HIGH 구조를 공유한다.
Range Line은 하나의 조건 행이다.
APPEND VALUE #( ... ) TO range_table로 조건을 직접 추가할 수 있다.
VALUE #( ( ... ) ( ... ) )로 조건 집합을 한 번에 만들 수 있다.
BT는 LOW와 HIGH를 함께 사용한다.
CP는 패턴 조건이며 * 와 + 패턴을 사용할 수 있다.
직접 조작한 Range Table은 WHERE field IN @range_table로 Open SQL에 연결할 수 있다.
사용자 입력 조건을 변경할 때는 의도와 영향이 명확해야 한다.
```

## 27. 다음 Section 연결

이 모듈을 끝으로 `THEORY-10 — SELECT-OPTIONS와 Range Table` Section이 마무리된다.

다음 단계에서는 ABAP Report Event를 학습한다. `SELECT-OPTIONS`는 Selection Screen과 Report Event 흐름 속에서 더욱 자연스럽게 이해된다.

후속 학습 연결은 다음과 같다.

| 후속 주제 | 연결 방식 |
|---|---|
| Report Event | `INITIALIZATION`, `AT SELECTION-SCREEN`, `START-OF-SELECTION` 흐름 이해 |
| Open SQL 심화 | Range Table 조건을 WHERE 조건에 안정적으로 연결 |
| Internal Table 응용 | 조건 목록을 Internal Table에서 Range Table로 변환 |
| SALV / ALV | Range 조건으로 조회한 데이터를 화면에 표시 |
| OO ABAP | Range Table을 메서드 파라미터로 전달 |
| 실무 리포트 | 사용자 입력, 기본 조건, 권한 조건, 조회 조건을 분리 설계 |

## 28. 강사용 설명 포인트

강의에서는 다음 순서로 설명하면 좋다.

```text
1. SELECT-OPTIONS가 화면 입력처럼 보이지만 내부적으로는 조건 테이블이라는 점을 복습한다.
2. Range Line 하나가 조건 하나라는 점을 표로 보여준다.
3. APPEND VALUE 예제로 EQ 조건을 직접 만든다.
4. BT와 CP 조건을 각각 LOW/HIGH 관점에서 비교한다.
5. 직접 만든 Range Table을 WHERE IN에 연결한다.
6. 사용자의 입력 조건을 변경하는 것은 실무적으로 민감하다는 점을 강조한다.
```

특히 초급자는 “화면에서 입력한 조건”과 “코드에서 직접 추가한 조건”을 같은 Selection Table 안에서 함께 볼 수 있어야 한다. 디버거에서 `s_carrid`를 펼쳐 `SIGN`, `OPTION`, `LOW`, `HIGH`를 확인하는 시연이 효과적이다.
