## 3. SELECT-OPTIONS란 무엇인가?

`SELECT-OPTIONS`는 ABAP Report에서 Selection Screen 입력 필드를 선언하는 문법이다.  
사용자는 화면에서 값을 입력하고, ABAP 프로그램은 그 값을 Selection Table 형태로 받는다.

가장 기본 문법은 다음과 같다.

```abap
DATA gv_carrid TYPE sflight-carrid.

SELECT-OPTIONS s_carrid FOR gv_carrid.
```

이 선언의 의미는 다음과 같다.

```text
gv_carrid와 같은 타입을 기준으로
s_carrid라는 Selection Screen 입력 조건을 만든다.
```

프로그램 실행 시 사용자는 Selection Screen에서 항공사 코드 조건을 입력할 수 있다.  
실행 후 `s_carrid` 내부에는 사용자가 입력한 조건이 Selection Table 형태로 저장된다.

## 4. SELECT-OPTIONS의 기본 구조

`SELECT-OPTIONS`는 단순 변수를 하나 만드는 문법이 아니다.  
선언 결과로 Selection Table이 생성된다.

Selection Table은 Range Table과 같은 기본 구조를 가진다.

| 필드 | 의미 | 예시 |
|---|---|---|
| SIGN | 포함/제외 여부 | `I`, `E` |
| OPTION | 비교 옵션 | `EQ`, `BT`, `CP` |
| LOW | 단일값 또는 범위 시작값 | `AA` |
| HIGH | 범위 종료값 | `LH` |

예를 들어 사용자가 `AA`를 단일값으로 입력하면 내부적으로 다음과 비슷한 한 줄이 만들어진다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | EQ | AA |  |

사용자가 `AA`부터 `LH`까지 범위를 입력하면 다음과 비슷한 한 줄이 만들어질 수 있다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | BT | AA | LH |

초급자는 이 구조를 반드시 기억해야 한다.  
`SELECT-OPTIONS`를 이해한다는 것은 결국 Selection Screen 입력값이 Selection Table의 행으로 변환된다는 것을 이해하는 것이다.

## 5. PARAMETERS와 SELECT-OPTIONS의 차이

`PARAMETERS`와 `SELECT-OPTIONS`는 모두 Selection Screen에 입력 필드를 만든다.  
하지만 목적과 내부 구조가 다르다.

| 구분 | PARAMETERS | SELECT-OPTIONS |
|---|---|---|
| 기본 목적 | 단일 값 입력 | 조건 범위 입력 |
| 내부 형태 | 단일 변수 | Selection Table |
| 여러 값 입력 | 기본적으로 불가 | 가능 |
| 범위 입력 | 기본적으로 불가 | 가능 |
| Include/Exclude | 직접 구현 필요 | Selection Table 구조로 표현 가능 |
| 대표 사용 예 | 회사코드 하나, 실행 모드 하나 | 날짜 범위, 고객 범위, 자재 여러 개 |

예를 들어 회사코드 하나만 입력받는다면 `PARAMETERS`가 더 단순할 수 있다.

```abap
PARAMETERS p_bukrs TYPE bukrs.
```

반면 여러 회사코드 또는 회사코드 범위를 입력받아 조회해야 한다면 `SELECT-OPTIONS`가 적합하다.

```abap
DATA gv_bukrs TYPE bukrs.
SELECT-OPTIONS s_bukrs FOR gv_bukrs.
```

실무에서는 조회 조건 대부분이 단일값만 요구하지 않는다.  
날짜, 고객, 자재, 플랜트, 판매오더, 구매오더처럼 여러 값을 입력하거나 범위를 지정해야 하는 경우가 많다. 이런 경우 `SELECT-OPTIONS`가 매우 자주 사용된다.

## 6. 기본 문법 상세

### 6.1 기본 형식

```abap
SELECT-OPTIONS s_name FOR data_object.
```

각 부분의 의미는 다음과 같다.

| 부분 | 의미 |
|---|---|
| `SELECT-OPTIONS` | Selection Screen에 범위 입력 조건을 선언하는 키워드 |
| `s_name` | 생성할 Selection Option 이름 |
| `FOR` | 기준 데이터 객체를 지정하는 키워드 |
| `data_object` | 타입 기준이 되는 변수 또는 Dictionary Field |

### 6.2 이름 규칙

교육용 Naming Convention은 다음처럼 정리할 수 있다.

| 객체 | Prefix 예시 | 예 |
|---|---|---|
| Parameter | `p_` | `p_carrid` |
| Select-Option | `s_` | `s_carrid` |
| Global Variable | `gv_` | `gv_carrid` |
| Internal Table | `gt_` | `gt_flight` |
| Work Area / Structure | `gs_` | `gs_flight` |

`SELECT-OPTIONS` 이름은 보통 `s_`로 시작하면 읽기 쉽다.

```abap
SELECT-OPTIONS s_carrid FOR gv_carrid.
SELECT-OPTIONS s_fldate FOR gv_fldate.
SELECT-OPTIONS s_connid FOR gv_connid.
```

### 6.3 FOR 뒤에는 타입 기준이 필요하다

`FOR` 뒤에는 아무 이름이나 쓸 수 없다.  
`SELECT-OPTIONS`가 어떤 타입과 길이의 입력 필드를 만들어야 하는지 알 수 있도록 기준 객체가 필요하다.

예:

```abap
DATA gv_carrid TYPE sflight-carrid.
SELECT-OPTIONS s_carrid FOR gv_carrid.
```

여기서 `gv_carrid`는 실제로 값을 저장하기 위한 업무 변수라기보다, `s_carrid`의 타입 기준 역할을 한다.

## 7. 기본 예제 1: 단순 SELECT-OPTIONS 선언

다음 예제는 항공사 코드 조건을 입력받고, 내부 Selection Table 내용을 그대로 출력한다.

```abap
REPORT zgpt_t10_m02_01.

DATA gv_carrid TYPE sflight-carrid.

SELECT-OPTIONS s_carrid FOR gv_carrid.

START-OF-SELECTION.

  WRITE: / 'SIGN', 10 'OPTION', 25 'LOW', 45 'HIGH'.
  ULINE.

  LOOP AT s_carrid INTO DATA(ls_carrid).
    WRITE: / ls_carrid-sign,
             10 ls_carrid-option,
             25 ls_carrid-low,
             45 ls_carrid-high.
  ENDLOOP.
```

실행 후 Selection Screen에서 `AA`를 입력하고 실행하면, 프로그램은 내부적으로 `s_carrid` Selection Table에 들어간 값을 출력한다.

초급자가 이 예제에서 확인해야 할 점은 다음이다.

```text
화면에서 AA를 입력했다.
→ 프로그램 내부에서는 s_carrid의 한 줄로 저장된다.
→ 그 한 줄에는 SIGN, OPTION, LOW, HIGH가 있다.
```

## 8. 기본 예제 2: 날짜 조건 선언

날짜 조건도 같은 방식으로 만들 수 있다.

```abap
REPORT zgpt_t10_m02_02.

DATA gv_fldate TYPE sflight-fldate.

SELECT-OPTIONS s_fldate FOR gv_fldate.

START-OF-SELECTION.

  LOOP AT s_fldate INTO DATA(ls_fldate).
    WRITE: / 'SIGN   =', ls_fldate-sign,
           / 'OPTION =', ls_fldate-option,
           / 'LOW    =', ls_fldate-low,
           / 'HIGH   =', ls_fldate-high.
    SKIP.
  ENDLOOP.
```

날짜 필드는 화면에서 날짜 입력 형식이 적용될 수 있다.  
이는 `FOR gv_fldate`가 날짜 타입을 기준으로 하기 때문이다.

즉, `SELECT-OPTIONS`의 입력 필드 타입은 `FOR` 뒤의 기준 객체 타입에 의해 결정된다.

## 9. DEFAULT 사용

`SELECT-OPTIONS`에도 기본값을 줄 수 있다.

```abap
DATA gv_carrid TYPE sflight-carrid.

SELECT-OPTIONS s_carrid FOR gv_carrid DEFAULT 'AA'.
```

이 경우 Selection Screen이 처음 표시될 때 `AA`가 기본값으로 들어간다.

기본값은 교육용 예제나 자주 사용하는 조회 조건을 제시할 때 유용하다.  
하지만 실무 프로그램에서 기본값을 넣을 때는 주의해야 한다.

| 관점 | 주의 사항 |
|---|---|
| 사용자 경험 | 기본값 때문에 사용자가 조건을 놓칠 수 있다. |
| 조회 범위 | 기본값이 너무 좁으면 데이터가 안 보일 수 있다. |
| 운영 영향 | 기본값이 너무 넓으면 대량 조회가 발생할 수 있다. |
| 업무 의미 | 특정 회사코드, 플랜트 등을 하드코딩하면 재사용성이 떨어질 수 있다. |

## 10. NO INTERVALS

`NO INTERVALS`는 범위 입력의 High 필드를 제한할 때 사용한다.

```abap
DATA gv_carrid TYPE sflight-carrid.

SELECT-OPTIONS s_carrid FOR gv_carrid NO INTERVALS.
```

이 문법을 사용하면 기본 화면에서 단일값 입력 중심으로 보이게 할 수 있다.  
단, Selection Table 구조 자체가 사라지는 것은 아니다. 여전히 내부적으로는 `SIGN`, `OPTION`, `LOW`, `HIGH` 구조를 가진 Selection Table이다.

초급자가 기억할 점은 다음이다.

```text
NO INTERVALS는 화면 입력 방식을 제한하는 옵션이지,
SELECT-OPTIONS를 PARAMETERS로 바꾸는 옵션이 아니다.
```

## 11. NO-EXTENSION

`NO-EXTENSION`은 Multiple Selection 확장 버튼을 제한할 때 사용한다.

```abap
DATA gv_carrid TYPE sflight-carrid.

SELECT-OPTIONS s_carrid FOR gv_carrid NO-EXTENSION.
```

Multiple Selection 기능을 통해 사용자는 여러 값을 복잡하게 입력할 수 있다.  
하지만 초급 실습이나 단순 조회 프로그램에서는 너무 복잡한 입력을 허용하지 않는 편이 더 명확할 수 있다.

`NO-EXTENSION`을 사용하면 사용자가 여러 줄 조건을 입력하는 기능을 제한할 수 있다.

| 옵션 | 의미 |
|---|---|
| `NO INTERVALS` | 범위 입력을 제한 |
| `NO-EXTENSION` | Multiple Selection 확장을 제한 |

이 두 옵션은 자주 함께 사용될 수 있다.

```abap
SELECT-OPTIONS s_carrid FOR gv_carrid NO INTERVALS NO-EXTENSION.
```

다만 이 경우에도 내부 객체는 Selection Table이다.  
따라서 프로그램에서는 여전히 `LOOP AT s_carrid` 같은 방식으로 다룰 수 있다.

## 12. SELECT-OPTIONS와 Selection Table의 관계

`SELECT-OPTIONS` 선언을 하면 ABAP은 이름이 같은 Selection Table을 만든다.

```abap
SELECT-OPTIONS s_carrid FOR gv_carrid.
```

이후 프로그램에서는 `s_carrid`를 Selection Table처럼 사용할 수 있다.

```abap
LOOP AT s_carrid INTO DATA(ls_carrid).
  WRITE: / ls_carrid-sign,
           ls_carrid-option,
           ls_carrid-low,
           ls_carrid-high.
ENDLOOP.
```

초급 단계에서는 다음 관계를 명확히 이해해야 한다.

```text
SELECT-OPTIONS는 화면 필드를 만드는 문법이다.
동시에 프로그램 내부에서 사용할 Selection Table도 만든다.
```

즉, `SELECT-OPTIONS`는 화면과 내부 데이터 구조를 연결하는 선언문이다.

## 13. 기본 입력 패턴과 내부 변환

### 13.1 단일값 입력

화면에서 `AA`만 입력하면 다음과 같은 Selection Table Row로 이해할 수 있다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | EQ | AA |  |

### 13.2 범위 입력

화면에서 `AA`부터 `LH`까지 입력하면 다음과 같은 Row로 이해할 수 있다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | BT | AA | LH |

### 13.3 여러 값 입력

Multiple Selection에서 여러 값을 입력하면 여러 Row가 생긴다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | EQ | AA |  |
| I | EQ | LH |  |
| I | EQ | UA |  |

여러 값과 Include/Exclude의 자세한 해석은 `THEORY-10-M04`에서 다룬다.  
이번 모듈에서는 “입력값이 여러 Row로 저장될 수 있다”는 점만 이해하면 된다.

## 14. 실습: SELECT-OPTIONS 입력값 확인 프로그램

### 14.1 실습 목표

Selection Screen에서 항공사 코드 조건을 입력하고, 프로그램 내부 Selection Table 구조를 확인한다.

### 14.2 실습 코드

```abap
REPORT zgpt_t10_m02_lab.

DATA gv_carrid TYPE sflight-carrid.

SELECT-OPTIONS s_carrid FOR gv_carrid.

START-OF-SELECTION.

  IF s_carrid[] IS INITIAL.
    WRITE: / '입력된 조건이 없습니다.'.
    RETURN.
  ENDIF.

  WRITE: / '입력된 SELECT-OPTIONS 조건'.
  ULINE.
  WRITE: / 'SIGN', 10 'OPTION', 25 'LOW', 45 'HIGH'.
  ULINE.

  LOOP AT s_carrid INTO DATA(ls_carrid).
    WRITE: / ls_carrid-sign,
             10 ls_carrid-option,
             25 ls_carrid-low,
             45 ls_carrid-high.
  ENDLOOP.
```

### 14.3 실습 방법

1. `SE38` 또는 ADT에서 프로그램을 생성한다.
2. 위 코드를 입력한다.
3. Syntax Check를 수행한다.
4. Activate한다.
5. 실행한다.
6. Selection Screen에서 `AA`를 입력한다.
7. 결과 화면에서 `SIGN`, `OPTION`, `LOW`, `HIGH` 값을 확인한다.
8. 다시 실행하여 범위값을 입력해 본다.
9. Multiple Selection을 눌러 여러 값을 입력해 본다.

### 14.4 실습 기록 양식

| 입력 방식 | 예상 SIGN | 예상 OPTION | LOW | HIGH | 실제 결과 |
|---|---|---|---|---|---|
| 단일값 `AA` | I | EQ | AA |  |  |
| 범위 `AA` ~ `LH` | I | BT | AA | LH |  |
| 여러 값 `AA`, `LH` | I | EQ | AA/LH |  |  |

## 15. 자주 발생하는 오류

### 15.1 FOR 뒤 기준 객체를 선언하지 않음

#### 오류 예

```abap
SELECT-OPTIONS s_carrid FOR gv_carrid.
```

하지만 위쪽에 `gv_carrid`가 선언되어 있지 않으면 오류가 발생한다.

#### 해결

```abap
DATA gv_carrid TYPE sflight-carrid.
SELECT-OPTIONS s_carrid FOR gv_carrid.
```

### 15.2 SELECT-OPTIONS를 실행 블록 안에 선언하려고 함

#### 오류 예

```abap
START-OF-SELECTION.
  SELECT-OPTIONS s_carrid FOR gv_carrid.
```

`SELECT-OPTIONS`는 Selection Screen 선언부에 작성하는 문법이다.  
일반 실행 로직 안에 작성하는 문장이 아니다.

#### 해결

```abap
DATA gv_carrid TYPE sflight-carrid.
SELECT-OPTIONS s_carrid FOR gv_carrid.

START-OF-SELECTION.
  " 실행 로직 작성
```

### 15.3 PARAMETERS처럼 단일 변수로 착각함

#### 잘못된 사고

```text
s_carrid는 사용자가 입력한 단일 항공사 코드 값이다.
```

#### 올바른 사고

```text
s_carrid는 Selection Table이다.
사용자가 단일값을 입력해도 내부적으로는 한 줄짜리 Selection Table로 이해해야 한다.
```

### 15.4 Header Line과 Body를 혼동함

Classic ABAP의 `SELECT-OPTIONS`는 초급자가 보기에는 단일 객체처럼 보인다.  
하지만 실제 사용 시에는 Selection Table의 Body와 Work Area 성격을 구분해서 이해해야 한다.

초급 단계에서는 다음 방식으로 안전하게 확인한다.

```abap
LOOP AT s_carrid INTO DATA(ls_carrid).
  " ls_carrid-sign, ls_carrid-option, ls_carrid-low, ls_carrid-high 확인
ENDLOOP.
```

그리고 전체 테이블이 비어 있는지 확인할 때는 다음처럼 Body를 명시하는 습관을 들인다.

```abap
IF s_carrid[] IS INITIAL.
  WRITE: / '입력된 조건이 없습니다.'.
ENDIF.
```

## 16. 실무 적용 기준

### 16.1 SELECT-OPTIONS가 적합한 경우

| 상황 | 이유 |
|---|---|
| 날짜 범위 조회 | 시작일과 종료일을 입력받기 좋다. |
| 고객 여러 건 조회 | Multiple Selection으로 여러 고객을 입력할 수 있다. |
| 자재 번호 범위 조회 | 번호 범위를 입력받을 수 있다. |
| 플랜트/회사코드 복수 선택 | 조직 조건을 유연하게 받을 수 있다. |
| 상태값 조건 조회 | 하나 또는 여러 상태값을 받을 수 있다. |

### 16.2 PARAMETERS가 더 적합한 경우

| 상황 | 이유 |
|---|---|
| 실행 모드 하나 선택 | 단일값이면 더 단순하다. |
| 체크박스 입력 | `PARAMETERS ... AS CHECKBOX`가 적합하다. |
| 라디오 버튼 그룹 | `PARAMETERS ... RADIOBUTTON GROUP`이 적합하다. |
| 반드시 하나의 값만 필요한 경우 | Range 구조가 불필요할 수 있다. |

### 16.3 조회 프로그램에서의 일반적인 사용

실무 조회 프로그램에서는 다음 조합이 자주 등장한다.

```abap
DATA gv_carrid TYPE sflight-carrid.
DATA gv_fldate TYPE sflight-fldate.

SELECT-OPTIONS s_carrid FOR gv_carrid.
SELECT-OPTIONS s_fldate FOR gv_fldate.

START-OF-SELECTION.
  SELECT carrid,
         connid,
         fldate
    FROM sflight
    WHERE carrid IN @s_carrid
      AND fldate IN @s_fldate
    INTO TABLE @DATA(lt_flight).
```

이번 모듈에서는 `WHERE ... IN`을 문법 예고 수준으로만 본다.  
정식 활용은 다음 모듈인 `THEORY-10-M03`에서 다룬다.

## 17. 강사용 설명 포인트

강의에서는 다음 순서로 설명하는 것이 좋다.

```text
1. PARAMETERS 복습: 단일값 입력
2. 업무 요구 제시: 여러 값과 범위가 필요함
3. SELECT-OPTIONS 등장
4. 화면에서 입력한 값이 Selection Table로 들어감
5. SIGN/OPTION/LOW/HIGH 구조 확인
6. SQL WHERE IN은 다음 모듈에서 연결
```

초급자에게 가장 중요한 설명은 다음이다.

```text
SELECT-OPTIONS는 화면 필드처럼 보이지만,
프로그램 내부에서는 Range Table과 같은 구조의 Selection Table이다.
```

이 문장을 이해하면 이후 `WHERE field IN @s_field`, Multiple Selection, Include/Exclude, Selection Table 직접 조작이 훨씬 쉬워진다.

## 18. 자가 진단 문제

### Q1. `SELECT-OPTIONS`의 기본 문법을 작성하시오.

모범 답안:

```abap
DATA gv_carrid TYPE sflight-carrid.
SELECT-OPTIONS s_carrid FOR gv_carrid.
```

### Q2. `PARAMETERS`와 `SELECT-OPTIONS`의 가장 큰 차이는 무엇인가?

모범 답안:

```text
PARAMETERS는 보통 단일 값을 입력받는 단일 변수이고,
SELECT-OPTIONS는 여러 조건을 담을 수 있는 Selection Table을 만든다.
```

### Q3. `SELECT-OPTIONS s_carrid FOR gv_carrid.`에서 `FOR gv_carrid`의 역할은 무엇인가?

모범 답안:

```text
s_carrid가 어떤 타입과 길이의 입력 필드를 가져야 하는지 결정하는 기준 객체 역할을 한다.
```

### Q4. 사용자가 단일값 `AA`를 입력했을 때 Selection Table은 어떤 형태로 이해할 수 있는가?

모범 답안:

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | EQ | AA |  |

### Q5. `NO INTERVALS`와 `NO-EXTENSION`의 차이는 무엇인가?

모범 답안:

```text
NO INTERVALS는 범위 입력을 제한하고,
NO-EXTENSION은 Multiple Selection 확장을 제한한다.
둘 다 내부 Selection Table 구조 자체를 없애는 것은 아니다.
```

## 20. 핵심 요약

```text
SELECT-OPTIONS는 Selection Screen에 범위 조건 입력 필드를 만든다.
SELECT-OPTIONS는 내부적으로 Selection Table을 만든다.
Selection Table은 SIGN, OPTION, LOW, HIGH 구조를 가진다.
FOR 뒤의 기준 객체가 입력 필드의 타입과 길이를 결정한다.
PARAMETERS는 단일값 중심이고, SELECT-OPTIONS는 복수 조건과 범위 조건에 적합하다.
NO INTERVALS와 NO-EXTENSION은 화면 입력 방식을 제한하지만 내부 구조를 없애지는 않는다.
```
