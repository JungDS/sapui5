## 1. 이 문서의 목적

이 문서는 `SELECT-OPTIONS`를 사용하는 ABAP Report에서 사용자가 **Multiple Selection** 팝업을 통해 여러 조건을 입력하고, 그 조건이 내부적으로 `SIGN`, `OPTION`, `LOW`, `HIGH` 구조의 Selection Table에 어떻게 반영되는지 이해하도록 돕기 위한 학습 문서이다.

앞선 모듈에서 학습한 흐름은 다음과 같다.

```text
THEORY-10-M01  Range Table 구조
THEORY-10-M02  SELECT-OPTIONS 기본 문법
THEORY-10-M03  WHERE field IN @range 사용
THEORY-10-M04  Multiple Selection과 Include/Exclude
```

이번 모듈의 핵심은 단순히 “여러 값을 입력할 수 있다”가 아니다.  
실무에서 중요한 것은 다음이다.

```text
사용자가 Selection Screen에서 여러 조건을 입력한다.
→ SAP GUI는 이를 Selection Table의 여러 Row로 변환한다.
→ 각 Row에는 Include/Exclude와 조건 Option이 저장된다.
→ ABAP Open SQL의 WHERE field IN @range가 이 조건 묶음을 해석한다.
→ 잘못된 Exclude 조건이나 과도한 Multiple Selection은 결과와 성능에 영향을 줄 수 있다.
```

초급자는 이번 문서를 통해 `SELECT-OPTIONS`의 화면 기능과 내부 데이터 구조가 분리되어 있지 않고, 같은 개념의 두 표현이라는 점을 이해해야 한다.

## 4. Multiple Selection이란 무엇인가?

### 4.1 기본 정의

`SELECT-OPTIONS`로 생성된 Selection Screen 필드는 기본적으로 하나의 시작값과 종료값 입력 영역을 가진다.  
하지만 사용자가 여러 개의 값을 한 번에 입력해야 하는 경우가 많다.

예를 들어 항공사 코드 `CARRID`를 기준으로 데이터를 조회한다고 하자.

```abap
SELECT-OPTIONS s_carrid FOR scarr-carrid.
```

사용자는 다음처럼 여러 조건을 입력하고 싶을 수 있다.

```text
AA 항공사 포함
LH 항공사 포함
UA 항공사 포함
하지만 XX 항공사는 제외
또는 A로 시작하는 항공사 포함
```

이런 복수 조건을 입력하기 위한 표준 화면 기능이 Multiple Selection이다.

### 4.2 SAP GUI에서의 위치

SAP GUI 800 기준으로 `SELECT-OPTIONS` 필드 오른쪽에는 일반적으로 Multiple Selection 버튼이 표시된다.  
사용자가 이 버튼을 누르면 여러 탭 또는 입력 영역을 가진 팝업이 열린다.

대표적으로 다음 유형의 입력 영역을 볼 수 있다.

| 영역 | 의미 |
|---|---|
| Single Values | 특정 값들을 포함한다. |
| Ranges | From-To 범위를 포함한다. |
| Exclude Single Values | 특정 값들을 제외한다. |
| Exclude Ranges | 특정 범위를 제외한다. |

시스템 언어, SAP GUI 설정, 릴리스에 따라 화면 문구는 약간 다르게 보일 수 있다.  
하지만 개념은 동일하다.

```text
포함할 값/범위
제외할 값/범위
```

## 5. Selection Table 구조 복습

`SELECT-OPTIONS`로 생성된 변수는 단일 값이 아니라 Selection Table이다.

예를 들어 다음 선언이 있다고 하자.

```abap
TABLES scarr.

SELECT-OPTIONS s_carrid FOR scarr-carrid.
```

`s_carrid`는 내부적으로 다음 구조를 가진 여러 Row의 테이블처럼 동작한다.

| Field | 의미 | 예시 |
|---|---|---|
| SIGN | Include 또는 Exclude | I, E |
| OPTION | 비교 연산자 | EQ, BT, CP 등 |
| LOW | 시작값 또는 단일값 | AA |
| HIGH | 종료값 | LH |

### 5.1 SIGN

`SIGN`은 조건을 포함할지 제외할지 결정한다.

| SIGN | 의미 | 설명 |
|---|---|---|
| I | Include | 조건에 맞는 값을 포함한다. |
| E | Exclude | 조건에 맞는 값을 제외한다. |

### 5.2 OPTION

`OPTION`은 비교 방식이다.

| OPTION | 의미 | 예시 |
|---|---|---|
| EQ | Equal | `LOW = 'AA'` |
| BT | Between | `LOW = 'AA', HIGH = 'LH'` |
| CP | Contains Pattern | `LOW = 'A*'` |
| NE | Not Equal | `LOW = 'AA'` |
| GE | Greater or Equal | `LOW = '1000'` |
| LE | Less or Equal | `LOW = '9999'` |

이번 모듈에서는 Multiple Selection과 Include/Exclude를 중심으로 보기 때문에 `EQ`, `BT`를 중심으로 설명한다.  
`EQ`, `BT`, `CP` 등 옵션 자체의 세부 의미는 다음 모듈에서 더 체계적으로 다룬다.

## 6. Multiple Selection 화면과 내부 Row 매핑

Multiple Selection 화면의 각 입력 유형은 Selection Table Row로 변환된다.

### 6.1 Single Values

사용자가 Single Values 영역에 다음 값을 입력했다고 하자.

```text
AA
LH
UA
```

내부 Selection Table은 다음처럼 구성된다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | EQ | AA |  |
| I | EQ | LH |  |
| I | EQ | UA |  |

해석은 다음과 같다.

```text
CARRID가 AA인 데이터 포함
또는 CARRID가 LH인 데이터 포함
또는 CARRID가 UA인 데이터 포함
```

Open SQL에서는 다음 감각으로 이해할 수 있다.

```text
WHERE carrid IN ('AA', 'LH', 'UA')
```

단, 실제 ABAP에서는 Selection Table 구조를 `IN @s_carrid`로 전달한다.

```abap
SELECT carrid, carrname
  FROM scarr
  WHERE carrid IN @s_carrid
  INTO TABLE @DATA(lt_scarr).
```

### 6.2 Ranges

사용자가 Ranges 영역에 다음 범위를 입력했다고 하자.

| From | To |
|---|---|
| AA | LH |

내부 구조는 다음과 같다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | BT | AA | LH |

해석은 다음과 같다.

```text
CARRID가 AA부터 LH 사이인 데이터를 포함한다.
```

문자 필드의 Between은 문자 정렬 기준의 범위이므로, 초급자는 숫자 범위처럼만 생각하면 안 된다.  
예를 들어 문자 코드의 범위 조건은 코드 체계와 정렬 순서를 함께 이해해야 한다.

### 6.3 Exclude Single Values

사용자가 Exclude Single Values 영역에 다음 값을 입력했다고 하자.

```text
XX
```

내부 구조는 다음과 같다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| E | EQ | XX |  |

해석은 다음과 같다.

```text
CARRID가 XX인 데이터는 제외한다.
```

### 6.4 Exclude Ranges

사용자가 Exclude Ranges 영역에 다음 값을 입력했다고 하자.

| From | To |
|---|---|
| Q0 | Q9 |

내부 구조는 다음과 같다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| E | BT | Q0 | Q9 |

해석은 다음과 같다.

```text
CARRID가 Q0부터 Q9 사이인 데이터는 제외한다.
```

## 7. Include와 Exclude가 함께 있을 때의 해석

Multiple Selection에서 가장 중요한 부분은 Include와 Exclude가 함께 있을 때의 해석이다.

예를 들어 사용자가 다음 조건을 입력했다고 하자.

### Include Single Values

```text
AA
LH
UA
```

### Exclude Single Values

```text
LH
```

내부 Selection Table은 다음과 같다.

| Row | SIGN | OPTION | LOW | HIGH | 의미 |
|---:|---|---|---|---|---|
| 1 | I | EQ | AA |  | AA 포함 |
| 2 | I | EQ | LH |  | LH 포함 |
| 3 | I | EQ | UA |  | UA 포함 |
| 4 | E | EQ | LH |  | LH 제외 |

최종 결과는 다음처럼 이해할 수 있다.

```text
AA, LH, UA 중에서 LH를 제외한다.
→ 결과: AA, UA
```

즉, Exclude 조건은 단순히 별도 조건으로 존재하는 것이 아니라, Include 조건으로 만들어진 후보에서 특정 값을 빼는 효과를 낸다.

> 실무 주의: Include와 Exclude가 복잡하게 섞이면 사용자가 기대한 결과와 실제 결과가 달라질 수 있다. 특히 범위 조건과 제외 조건이 함께 사용될 때는 디버깅 또는 입력값 출력으로 반드시 확인하는 습관이 필요하다.

## 8. Include 조건이 없는 Exclude만 있는 경우

초급자가 헷갈리기 쉬운 상황이 있다.

사용자가 Include에는 아무것도 넣지 않고 Exclude만 입력하는 경우이다.

예를 들어 다음과 같이 입력했다고 하자.

| SIGN | OPTION | LOW |
|---|---|---|
| E | EQ | LH |

직관적으로는 다음처럼 이해할 수 있다.

```text
LH를 제외한 전체
```

그러나 실제 결과와 SQL 변환 방식은 필드 타입, DB, Open SQL 처리, 조건 조합 방식에 따라 학습자가 단순히 추정해서는 안 된다.  
초급 교육에서는 다음 기준으로 지도하는 것이 안전하다.

```text
Exclude만 입력하는 방식은 초급 실습에서 권장하지 않는다.
명확한 Include 범위를 먼저 설정하고, 그 안에서 Exclude를 사용하는 방식으로 학습한다.
```

실무에서도 “전체에서 일부 제외” 조건은 데이터량이 매우 커질 수 있으므로 주의해야 한다.  
예를 들어 고객 전체에서 특정 고객만 제외하고 조회하는 조건은 의도치 않게 대량 데이터를 조회할 수 있다.

## 9. 실습 프로그램: Multiple Selection 내부 구조 확인

### 9.1 실습 목표

사용자가 Multiple Selection에 값을 입력했을 때, Selection Table 내부 구조가 어떻게 채워지는지 직접 출력한다.

### 9.2 예제 프로그램

```abap
REPORT zgpt_so_multiple_01.

TABLES scarr.

SELECT-OPTIONS s_carrid FOR scarr-carrid.

START-OF-SELECTION.

  WRITE: / 'Selection Table Contents'.
  ULINE.

  IF s_carrid[] IS INITIAL.
    WRITE: / 'No selection condition entered.'.
    RETURN.
  ENDIF.

  LOOP AT s_carrid INTO DATA(ls_carrid).
    WRITE: / 'SIGN   =', ls_carrid-sign,
           / 'OPTION =', ls_carrid-option,
           / 'LOW    =', ls_carrid-low,
           / 'HIGH   =', ls_carrid-high.
    ULINE.
  ENDLOOP.
```

### 9.3 실행 절차

1. 프로그램을 생성한다.
2. Syntax Check를 수행한다.
3. Activate한다.
4. 실행한다.
5. `s_carrid` 오른쪽의 Multiple Selection 버튼을 누른다.
6. Single Values에 `AA`, `LH`, `UA`를 입력한다.
7. Exclude Single Values에 `LH`를 입력한다.
8. 실행한다.
9. 출력된 `SIGN`, `OPTION`, `LOW`, `HIGH`를 확인한다.

### 9.4 예상 출력

실제 출력 형태는 시스템 설정에 따라 다를 수 있지만, 의미상 다음과 같은 Row를 확인할 수 있다.

```text
SIGN   = I
OPTION = EQ
LOW    = AA
HIGH   =

SIGN   = I
OPTION = EQ
LOW    = LH
HIGH   =

SIGN   = I
OPTION = EQ
LOW    = UA
HIGH   =

SIGN   = E
OPTION = EQ
LOW    = LH
HIGH   =
```

이 출력 결과를 보면 Multiple Selection 화면 입력이 Selection Table의 여러 Row로 변환되었다는 사실을 확인할 수 있다.

## 10. Open SQL과 연결하기

Multiple Selection을 실제 조회 조건으로 사용하는 기본 패턴은 다음과 같다.

```abap
REPORT zgpt_so_multiple_02.

TABLES scarr.

SELECT-OPTIONS s_carrid FOR scarr-carrid.

START-OF-SELECTION.

  SELECT carrid,
         carrname,
         currcode
    FROM scarr
    WHERE carrid IN @s_carrid
    INTO TABLE @DATA(lt_scarr).

  IF sy-subrc <> 0.
    WRITE: / 'No data found.'.
    RETURN.
  ENDIF.

  LOOP AT lt_scarr INTO DATA(ls_scarr).
    WRITE: / ls_scarr-carrid,
             ls_scarr-carrname,
             ls_scarr-currcode.
  ENDLOOP.
```

이 프로그램에서 사용자가 Multiple Selection에 입력한 조건은 `WHERE carrid IN @s_carrid`에 그대로 전달된다.

초급자는 다음을 반드시 연결해서 이해해야 한다.

| 화면 입력 | 내부 구조 | SQL 조건 |
|---|---|---|
| Single Values | `I/EQ/LOW` 여러 Row | `IN` 조건 |
| Ranges | `I/BT/LOW/HIGH` | Between 성격 조건 |
| Exclude Single Values | `E/EQ/LOW` | 제외 조건 |
| Exclude Ranges | `E/BT/LOW/HIGH` | 제외 범위 조건 |

## 11. Include/Exclude 조건을 직접 구성해보기

Multiple Selection 팝업 없이 ABAP 코드로 Selection Table을 직접 구성할 수도 있다.  
다만 이 모듈의 주제는 화면 입력이므로, 여기서는 이해 보조용 예제로만 다룬다.

```abap
REPORT zgpt_so_multiple_03.

TYPES ty_carrid_range TYPE RANGE OF scarr-carrid.

DATA rt_carrid TYPE ty_carrid_range.

APPEND VALUE #( sign = 'I' option = 'EQ' low = 'AA' ) TO rt_carrid.
APPEND VALUE #( sign = 'I' option = 'EQ' low = 'LH' ) TO rt_carrid.
APPEND VALUE #( sign = 'I' option = 'EQ' low = 'UA' ) TO rt_carrid.
APPEND VALUE #( sign = 'E' option = 'EQ' low = 'LH' ) TO rt_carrid.

SELECT carrid,
       carrname
  FROM scarr
  WHERE carrid IN @rt_carrid
  INTO TABLE @DATA(lt_scarr).

LOOP AT lt_scarr INTO DATA(ls_scarr).
  WRITE: / ls_scarr-carrid, ls_scarr-carrname.
ENDLOOP.
```

이 예제는 사용자가 Multiple Selection 화면에서 입력한 것과 유사한 Selection Table을 코드로 만든 것이다.  
후속 모듈에서 Selection Table 직접 조작을 더 자세히 다룬다.

## 12. 실무에서 Multiple Selection이 자주 쓰이는 경우

Multiple Selection은 실무 Report에서 매우 자주 사용된다.

| 업무 상황 | 예시 |
|---|---|
| 여러 회사코드 조회 | `BUKRS` 여러 개 입력 |
| 여러 플랜트 조회 | `WERKS` 여러 개 입력 |
| 여러 자재 조회 | `MATNR` 여러 개 입력 |
| 여러 고객 조회 | `KUNNR` 여러 개 입력 |
| 특정 문서번호 범위 조회 | `BELNR` From-To 입력 |
| 특정 상태 제외 | 완료 또는 취소 상태 제외 |
| 테스트 데이터 일부 제외 | 특정 코드만 제외하고 조회 |

예를 들어 재고 조회 Report에서 플랜트를 여러 개 입력하고 싶다면 다음과 같은 Selection Screen을 만들 수 있다.

```abap
TABLES marc.
SELECT-OPTIONS s_werks FOR marc-werks.
```

사용자는 Multiple Selection을 통해 `1000`, `1100`, `1200`을 한 번에 입력할 수 있다.

## 13. Include/Exclude 사용 시 실무 주의점

### 13.1 Exclude는 사용자의 의도를 흐릴 수 있다

Include 조건은 비교적 직관적이다.

```text
AA, LH, UA를 조회한다.
```

하지만 Exclude 조건은 결과를 이해하기 어렵게 만들 수 있다.

```text
AA부터 ZZ까지 조회하되, LH와 Q0~Q9는 제외한다.
```

조건이 복잡해지면 결과가 맞는지 검증하기 어려워진다.

### 13.2 Exclude만 사용하면 대량 조회 위험이 있다

사용자가 “특정 값만 빼고 전체 조회” 형태로 입력하면, 결과적으로 매우 많은 데이터가 조회될 수 있다.

예를 들어 판매오더 테이블에서 특정 주문 유형만 제외하고 전체를 조회하면 성능 문제가 발생할 수 있다.

```text
전체 데이터 - 일부 제외 = 여전히 매우 큰 데이터
```

따라서 실무 Report에서는 필수 조건, 기간 조건, 조직 조건 등을 함께 요구하는 것이 안전하다.

### 13.3 범위 조건은 코드 체계를 이해해야 한다

문자 필드에서 `BT` 범위 조건은 단순 숫자 범위와 다르다.

예를 들어 `CARRID`가 문자 코드라면 `AA ~ LH`는 문자 정렬 기준 범위이다.  
사용자가 기대한 항공사 집합과 실제 문자열 범위가 다를 수 있다.

### 13.4 패턴 조건은 더 신중해야 한다

`CP` 같은 패턴 조건은 강력하지만 결과가 넓어질 수 있다.

```text
A*  → A로 시작하는 모든 값
*1  → 1로 끝나는 모든 값
```

패턴 조건은 후속 모듈에서 상세히 다루지만, Multiple Selection에서도 입력될 수 있음을 기억해야 한다.

## 14. 디버깅 관점

Multiple Selection 결과를 이해하려면 Debugging이 매우 유용하다.

### 14.1 확인 위치

프로그램에서 다음 위치에 Breakpoint를 걸 수 있다.

```abap
START-OF-SELECTION.
```

또는 Selection Table을 LOOP하기 직전에 Breakpoint를 걸어도 된다.

```abap
BREAK-POINT.

LOOP AT s_carrid INTO DATA(ls_carrid).
  " 확인
ENDLOOP.
```

### 14.2 디버거에서 확인할 항목

| 확인 항목 | 의미 |
|---|---|
| `s_carrid[]` | Selection Table 전체 Row |
| `s_carrid-sign` | Include/Exclude 여부 |
| `s_carrid-option` | EQ, BT 등 비교 방식 |
| `s_carrid-low` | 단일값 또는 시작값 |
| `s_carrid-high` | 종료값 |

디버거에서 이 값을 확인하면 화면에서 입력한 Multiple Selection 조건이 내부적으로 어떻게 변환되었는지 명확히 볼 수 있다.

## 15. 입력값 검증과 Multiple Selection

Multiple Selection을 제공한다고 해서 모든 입력을 무조건 허용해야 하는 것은 아니다.  
실무 Report에서는 입력값 검증이 필요할 수 있다.

예를 들어 다음과 같은 정책을 둘 수 있다.

```text
Exclude 조건은 허용하지 않는다.
범위 조건은 허용하지 않는다.
최대 입력 Row 수를 제한한다.
필수 조직 조건이 없으면 실행하지 않는다.
```

### 15.1 Exclude 조건 제한 예시

```abap
LOOP AT s_carrid INTO DATA(ls_carrid).
  IF ls_carrid-sign = 'E'.
    MESSAGE 'Exclude condition is not allowed.' TYPE 'E'.
  ENDIF.
ENDLOOP.
```

이 코드는 단순 예제이다.  
실제 메시지 클래스, 다국어 메시지, 사용자 경험은 프로젝트 기준에 맞게 설계해야 한다.

### 15.2 입력 Row 수 제한 예시

```abap
IF lines( s_carrid[] ) > 100.
  MESSAGE 'Too many selection conditions.' TYPE 'E'.
ENDIF.
```

대량 조건 입력은 SQL 변환, DB Optimizer, 네트워크, 결과 데이터량에 영향을 줄 수 있으므로 실무에서는 제한이 필요할 수 있다.

## 16. 성능 관점

Multiple Selection 자체가 나쁜 것은 아니다.  
오히려 SAP Report에서 매우 자연스럽고 표준적인 입력 방식이다.

하지만 다음 조건이 겹치면 성능 문제가 발생할 수 있다.

| 위험 조건 | 설명 |
|---|---|
| 너무 많은 Single Values | IN 조건이 지나치게 길어질 수 있다. |
| Include 없이 Exclude만 사용 | 전체 데이터 조회에 가까워질 수 있다. |
| 날짜 조건 없이 대량 테이블 조회 | 결과 범위가 너무 넓다. |
| Index와 맞지 않는 필드 조건 | DB에서 효율적으로 찾기 어렵다. |
| CP 패턴 남발 | 조건 선택도가 낮아질 수 있다. |

실무 Report에서는 Multiple Selection을 제공하더라도, 다음과 같은 기본 방어 장치를 고려한다.

```text
필수 기간 조건 지정
필수 조직 조건 지정
최대 입력 Row 제한
Exclude 사용 제한 또는 경고
조회 전 예상 조건 출력
권한 조건과 함께 적용
```

## 17. 실습 과제

### 17.1 기본 과제

다음 프로그램을 작성한다.

```abap
REPORT zgpt_so_multiple_lab.

TABLES scarr.

SELECT-OPTIONS s_carrid FOR scarr-carrid.

START-OF-SELECTION.

  WRITE: / 'Input Conditions'.
  ULINE.

  LOOP AT s_carrid INTO DATA(ls_carrid).
    WRITE: / ls_carrid-sign,
             ls_carrid-option,
             ls_carrid-low,
             ls_carrid-high.
  ENDLOOP.
```

다음 조건을 Multiple Selection으로 입력하고 출력 결과를 기록한다.

| 입력 유형 | 입력값 |
|---|---|
| Single Values | AA, LH, UA |
| Ranges | AA ~ UA |
| Exclude Single Values | LH |
| Exclude Ranges | Q0 ~ Q9 |

### 17.2 응용 과제

다음 조건을 만족하는 조회 프로그램을 작성한다.

```text
SCARR에서 사용자가 입력한 CARRID 조건에 맞는 항공사만 조회한다.
Multiple Selection으로 Include/Exclude 조건을 입력할 수 있다.
입력된 Selection Table 내용을 먼저 출력한다.
그 다음 조회 결과를 출력한다.
```

예상 구조는 다음과 같다.

```abap
REPORT zgpt_so_multiple_query.

TABLES scarr.
SELECT-OPTIONS s_carrid FOR scarr-carrid.

START-OF-SELECTION.

  PERFORM display_selection.
  PERFORM select_data.

FORM display_selection.
  LOOP AT s_carrid INTO DATA(ls_cond).
    WRITE: / ls_cond-sign, ls_cond-option, ls_cond-low, ls_cond-high.
  ENDLOOP.
ENDFORM.

FORM select_data.
  SELECT carrid, carrname, currcode
    FROM scarr
    WHERE carrid IN @s_carrid
    INTO TABLE @DATA(lt_scarr).

  LOOP AT lt_scarr INTO DATA(ls_scarr).
    WRITE: / ls_scarr-carrid, ls_scarr-carrname, ls_scarr-currcode.
  ENDLOOP.
ENDFORM.
```

> 위 예제는 초급 학습용으로 `FORM`을 사용했다. 실무 신규 개발에서는 OO 방식 또는 프로젝트 표준을 우선한다.

## 18. 자주 하는 실수

### 18.1 `s_carrid`와 `s_carrid[]` 혼동

`SELECT-OPTIONS` 변수는 Header Line을 가진 Selection Table처럼 동작하는 역사적 문법 맥락이 있다.  
초급자는 전체 테이블을 다룰 때 `s_carrid[]`를 명확히 의식하는 것이 좋다.

```abap
IF s_carrid[] IS INITIAL.
  WRITE: / 'No condition.'.
ENDIF.
```

### 18.2 LOW만 보고 조건을 판단함

Multiple Selection에서는 `LOW`만 보면 안 된다.

반드시 다음 네 필드를 함께 봐야 한다.

```text
SIGN
OPTION
LOW
HIGH
```

예를 들어 `LOW = 'AA'`라도 다음 조건은 서로 다르다.

| SIGN | OPTION | LOW | HIGH | 의미 |
|---|---|---|---|---|
| I | EQ | AA |  | AA 포함 |
| E | EQ | AA |  | AA 제외 |
| I | BT | AA | LH | AA~LH 포함 |

### 18.3 Exclude 조건을 무시함

개발자가 직접 Selection Table을 LOOP하면서 Include만 처리하고 Exclude를 무시하면, 사용자가 입력한 조건과 다른 결과가 나올 수 있다.

Open SQL의 `WHERE field IN @range`는 Selection Table 의미를 처리하지만, 개발자가 직접 IF 조건을 만들 때는 `SIGN`, `OPTION`을 정확히 해석해야 한다.

### 18.4 빈 Selection Table 처리 누락

`s_carrid[]`가 비어 있을 때 `WHERE carrid IN @s_carrid`가 어떻게 동작하는지에 대해 초급자가 임의로 추정하면 위험하다.  
교육에서는 다음 방식처럼 입력값이 비어 있으면 명확히 처리하는 습관을 들이는 것이 좋다.

```abap
IF s_carrid[] IS INITIAL.
  MESSAGE 'Please enter at least one carrier.' TYPE 'S' DISPLAY LIKE 'E'.
  RETURN.
ENDIF.
```

실무에서는 업무 요구사항에 따라 “조건 없으면 전체 조회 허용” 또는 “조건 필수”를 명확히 정해야 한다.

## 19. 평가 문제

### 19.1 객관식

#### Q1. Multiple Selection의 주요 목적은 무엇인가?

A. 프로그램 이름을 여러 개 입력하기 위한 기능이다.  
B. SELECT-OPTIONS 필드에 여러 값, 범위, 제외 조건을 입력하기 위한 기능이다.  
C. Internal Table을 정렬하기 위한 기능이다.  
D. ALV Layout Variant를 저장하기 위한 기능이다.

**정답:** B

#### Q2. Selection Table에서 Exclude 조건을 나타내는 SIGN 값은 무엇인가?

A. I  
B. E  
C. X  
D. N

**정답:** B

#### Q3. Multiple Selection의 Ranges 입력은 일반적으로 어떤 OPTION으로 저장되는가?

A. EQ  
B. BT  
C. CP  
D. NE

**정답:** B

### 19.2 서술형

#### Q1. Include와 Exclude가 함께 있을 때 결과를 해석하는 기본 관점을 설명하시오.

**모범 답안:**  
Include 조건은 조회 후보를 만들고, Exclude 조건은 그 후보에서 특정 값이나 범위를 제외하는 조건으로 이해할 수 있다. 따라서 Include와 Exclude가 함께 있을 때는 Selection Table의 모든 Row를 `SIGN`, `OPTION`, `LOW`, `HIGH` 기준으로 함께 확인해야 한다.

#### Q2. Multiple Selection에서 `LOW`만 확인하면 안 되는 이유를 설명하시오.

**모범 답안:**  
같은 `LOW` 값이라도 `SIGN`이 `I`인지 `E`인지, `OPTION`이 `EQ`인지 `BT`인지에 따라 의미가 완전히 달라진다. 따라서 Selection Table 조건은 `SIGN`, `OPTION`, `LOW`, `HIGH`를 함께 확인해야 한다.

#### Q3. Exclude 조건만 입력하는 방식이 실무에서 위험할 수 있는 이유를 설명하시오.

**모범 답안:**  
Exclude만 입력하면 특정 값을 제외한 전체 데이터 조회에 가까워질 수 있다. 대량 테이블에서는 조회 범위가 과도하게 넓어져 성능 문제가 발생할 수 있으므로, 기간 조건이나 조직 조건 같은 Include 조건과 함께 사용하거나 제한해야 한다.

## 21. 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
Multiple Selection은 SELECT-OPTIONS의 복수 조건 입력 기능이다.
입력 결과는 Selection Table의 여러 Row로 저장된다.
Include 조건은 SIGN = 'I'로 저장된다.
Exclude 조건은 SIGN = 'E'로 저장된다.
Single Values는 주로 OPTION = 'EQ'로 표현된다.
Ranges는 주로 OPTION = 'BT'로 표현된다.
LOW만 확인하지 말고 SIGN, OPTION, LOW, HIGH를 함께 확인해야 한다.
Exclude 조건과 대량 조건은 실무에서 성능과 결과 정확성 측면의 검토가 필요하다.
```
