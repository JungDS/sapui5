## 0. 이 문서의 학습 범위

이 문서는 `THEORY-10-M05 — EQ / BT / CP 옵션 이해`만 다룬다.

이번 모듈의 핵심 키워드는 다음 네 가지이다.

| 키워드 | 의미 |
|---|---|
| `EQ` | Equal. LOW와 같은 값을 선택한다. |
| `BT` | Between. LOW부터 HIGH까지의 범위를 선택한다. |
| `CP` | Contains Pattern. 패턴 조건에 맞는 값을 선택한다. |
| Selection Option | `SIGN`, `OPTION`, `LOW`, `HIGH`로 구성된 조건 한 줄 또는 조건 집합 |

앞선 모듈에서 학습자는 Range Table 구조, `SELECT-OPTIONS` 기본 문법, `WHERE field IN @range`, Multiple Selection과 Include/Exclude를 경험했다. 이번 모듈에서는 그중에서도 실무에서 가장 자주 만나는 `OPTION` 값인 `EQ`, `BT`, `CP`를 분리해서 깊게 이해한다.

초급자가 가장 많이 하는 실수는 다음과 같다.

```text
EQ는 단일값, BT는 범위, CP는 패턴이라는 사실은 외웠지만,
LOW와 HIGH를 언제 쓰는지,
SIGN = I/E와 결합되면 결과가 어떻게 달라지는지,
CP의 * 와 + 패턴이 SQL LIKE의 % 와 _ 와 다르다는 점을 놓친다.
```

이 문서의 목표는 단순 암기가 아니라, `SELECT-OPTIONS` 화면에서 사용자가 입력한 조건이 실제 Range Table 내부에서 어떻게 표현되고, ABAP Open SQL 조건으로 어떻게 사용되는지까지 연결해서 이해하는 것이다.

## 1. 학습 목표

학습자는 이 모듈을 마친 뒤 다음을 설명하고 구현할 수 있어야 한다.

## 3. Selection Option의 네 가지 필드 복습

Selection Option은 일반적으로 다음 네 필드로 구성된다.

| 필드 | 의미 | 대표 값 |
|---|---|---|
| `SIGN` | 포함 또는 제외 | `I`, `E` |
| `OPTION` | 비교 방식 | `EQ`, `BT`, `CP`, `NE`, `GE`, `LE` 등 |
| `LOW` | 단일값 또는 범위 시작값 | `'AA'`, `'20260101'` |
| `HIGH` | 범위 종료값 | `'LH'`, `'20261231'` |

초급 단계에서 가장 자주 다루는 조합은 다음이다.

| SIGN | OPTION | LOW | HIGH | 의미 |
|---|---|---|---|---|
| I | EQ | AA |  | AA를 포함 |
| E | EQ | AA |  | AA를 제외 |
| I | BT | AA | LH | AA부터 LH까지 포함 |
| E | BT | AA | LH | AA부터 LH까지 제외 |
| I | CP | A* |  | A로 시작하는 값 포함 |
| E | CP | A* |  | A로 시작하는 값 제외 |

## 4. OPTION = EQ

### 4.1 EQ의 의미

`EQ`는 Equal의 약자이다. `LOW`에 입력한 값과 정확히 같은 데이터를 선택한다.

```text
SIGN = I
OPTION = EQ
LOW = AA
```

위 조건은 다음 의미이다.

```text
CARRID가 AA인 데이터 포함
```

Open SQL 조건으로 감각을 바꾸면 다음과 유사하다.

```sql
WHERE carrid = 'AA'
```

ABAP Range Table로 직접 작성하면 다음과 같다.

```abap
DATA lt_carrid TYPE RANGE OF sflight-carrid.

APPEND VALUE #( sign   = 'I'
                option = 'EQ'
                low    = 'AA' ) TO lt_carrid.

SELECT carrid, connid, fldate
  FROM sflight
  WHERE carrid IN @lt_carrid
  INTO TABLE @DATA(lt_flight).
```

### 4.2 SELECT-OPTIONS 화면에서의 EQ

다음과 같이 선언했다고 하자.

```abap
SELECT-OPTIONS s_carrid FOR sflight-carrid.
```

Selection Screen에서 단일값 `AA`를 입력하면 내부적으로는 보통 다음과 같은 조건 행으로 이해할 수 있다.

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | EQ | AA |  |

사용자 입장에서는 단순히 입력 필드에 `AA`를 넣었지만, ABAP 내부에서는 Selection Table 형식으로 관리된다.

### 4.3 EQ의 실무 사용처

`EQ`는 다음 상황에서 가장 자연스럽다.

| 상황 | 예시 |
|---|---|
| 특정 회사코드만 조회 | `BUKRS = '1000'` |
| 특정 항공사만 조회 | `CARRID = 'AA'` |
| 특정 고객 번호만 조회 | `KUNNR = '0000001000'` |
| 특정 상태만 조회 | `STATUS = 'A'` |

### 4.4 EQ에서 HIGH는 사용하지 않는다

`EQ`는 단일값 조건이다. 따라서 `HIGH`는 비워둔다.

나쁜 예:

```abap
APPEND VALUE #( sign   = 'I'
                option = 'EQ'
                low    = 'AA'
                high   = 'LH' ) TO lt_carrid.
```

위 코드는 의미가 불명확하다. `EQ`는 `LOW`만 기준으로 하는 단일값 조건이므로 `HIGH`를 채우지 않는 것이 맞다.

좋은 예:

```abap
APPEND VALUE #( sign   = 'I'
                option = 'EQ'
                low    = 'AA' ) TO lt_carrid.
```

## 5. EQ와 SIGN 조합

`EQ`는 `SIGN`과 결합되면 의미가 달라진다.

| SIGN | OPTION | LOW | 의미 |
|---|---|---|---|
| I | EQ | AA | AA 포함 |
| E | EQ | AA | AA 제외 |

예를 들어 다음 Range Table은 `AA`를 제외한다.

```abap
DATA lt_carrid TYPE RANGE OF sflight-carrid.

APPEND VALUE #( sign   = 'E'
                option = 'EQ'
                low    = 'AA' ) TO lt_carrid.
```

이를 사람의 말로 풀면 다음과 같다.

```text
AA가 아닌 항공사를 조회한다.
```

단, 실무에서는 `SIGN = E` 조건이 많아질수록 결과 해석이 어려워질 수 있다. 특히 Include 조건과 Exclude 조건이 함께 섞이면 조회 결과를 예측하기 어려워지므로, 조건 설계를 명확히 기록해야 한다.

## 6. OPTION = BT

### 6.1 BT의 의미

`BT`는 Between의 약자이다. `LOW`부터 `HIGH`까지의 범위를 선택한다.

```text
SIGN = I
OPTION = BT
LOW = 20260101
HIGH = 20261231
```

위 조건은 다음 의미이다.

```text
2026년 1월 1일부터 2026년 12월 31일까지 포함
```

Open SQL 조건 감각으로 보면 다음과 유사하다.

```sql
WHERE fldate BETWEEN '20260101' AND '20261231'
```

ABAP Range Table로 직접 작성하면 다음과 같다.

```abap
DATA lt_date TYPE RANGE OF sflight-fldate.

APPEND VALUE #( sign   = 'I'
                option = 'BT'
                low    = '20260101'
                high   = '20261231' ) TO lt_date.

SELECT carrid, connid, fldate
  FROM sflight
  WHERE fldate IN @lt_date
  INTO TABLE @DATA(lt_flight).
```

### 6.2 BT에서는 LOW와 HIGH가 모두 중요하다

`BT`는 범위 조건이므로 `LOW`와 `HIGH`를 함께 사용한다.

| 필드 | 의미 |
|---|---|
| LOW | 범위 시작값 |
| HIGH | 범위 종료값 |

예를 들어 금액 범위를 조회한다면 다음과 같다.

| SIGN | OPTION | LOW | HIGH | 의미 |
|---|---|---:|---:|---|
| I | BT | 1000 | 5000 | 1000 이상 5000 이하 |

### 6.3 BT는 양 끝값을 포함한다

초급자가 자주 놓치는 점은 `BT`가 양 끝값을 포함한다는 것이다.

```text
LOW <= field <= HIGH
```

예를 들어 다음 조건은 `20260101`과 `20260131`도 포함한다.

```abap
APPEND VALUE #( sign   = 'I'
                option = 'BT'
                low    = '20260101'
                high   = '20260131' ) TO lt_date.
```

### 6.4 BT의 실무 사용처

| 상황 | 예시 |
|---|---|
| 전기일 범위 | `BUDAT` 20260101 ~ 20260131 |
| 생성일 범위 | `ERDAT` 시작일 ~ 종료일 |
| 금액 범위 | 1000 ~ 5000 |
| 문서번호 범위 | 0000001000 ~ 0000001999 |
| 항공편 날짜 범위 | `SFLIGHT-FLDATE` |

### 6.5 BT에서 LOW > HIGH가 되면 안 된다

다음은 잘못된 예이다.

```abap
APPEND VALUE #( sign   = 'I'
                option = 'BT'
                low    = '20261231'
                high   = '20260101' ) TO lt_date.
```

범위 시작값이 종료값보다 크면 조건 의미가 깨진다. Selection Screen에서는 사용자가 잘못 입력할 수도 있으므로, 실무 프로그램에서는 필요 시 입력 검증을 고려한다.

```abap
IF s_fldate-low IS NOT INITIAL
   AND s_fldate-high IS NOT INITIAL
   AND s_fldate-low > s_fldate-high.
  MESSAGE '시작일은 종료일보다 클 수 없습니다.' TYPE 'E'.
ENDIF.
```

위 코드는 개념 예시이다. 실제 `SELECT-OPTIONS`는 여러 줄이 있을 수 있으므로, 모든 조건 행을 반복 검증해야 할 수 있다.

## 7. BT와 SIGN 조합

`BT`도 `SIGN`과 결합되면 의미가 달라진다.

| SIGN | OPTION | LOW | HIGH | 의미 |
|---|---|---|---|---|
| I | BT | 20260101 | 20260131 | 해당 기간 포함 |
| E | BT | 20260101 | 20260131 | 해당 기간 제외 |

예를 들어 다음 조건은 2026년 1월 데이터를 제외한다.

```abap
APPEND VALUE #( sign   = 'E'
                option = 'BT'
                low    = '20260101'
                high   = '20260131' ) TO lt_date.
```

실무에서는 Exclude Between 조건이 들어가면 결과를 설명하기 어려워질 수 있다. 예를 들어 “전체 기간 중 특정 휴무 기간 제외” 같은 요구사항에는 적합하지만, 일반 조회 조건에서는 사용자에게 결과 의미를 명확히 안내해야 한다.

## 8. OPTION = CP

### 8.1 CP의 의미

`CP`는 Contains Pattern의 약자이다. 값이 특정 패턴에 맞는지 검사한다.

```text
SIGN = I
OPTION = CP
LOW = A*
```

위 조건은 다음 의미이다.

```text
A로 시작하는 값 포함
```

ABAP Range Table로 직접 작성하면 다음과 같다.

```abap
DATA lt_carrid TYPE RANGE OF sflight-carrid.

APPEND VALUE #( sign   = 'I'
                option = 'CP'
                low    = 'A*' ) TO lt_carrid.

SELECT carrid, connid, fldate
  FROM sflight
  WHERE carrid IN @lt_carrid
  INTO TABLE @DATA(lt_flight).
```

### 8.2 CP의 패턴 문자

ABAP의 `CP` 패턴에서는 일반적으로 다음 문자를 사용한다.

| 패턴 | 의미 | 예시 |
|---|---|---|
| `*` | 임의의 문자열 | `A*` = A로 시작 |
| `+` | 임의의 한 문자 | `A+` = A 뒤에 한 문자 |

예시:

| 조건 | 의미 | 매칭 예 |
|---|---|---|
| `A*` | A로 시작 | A, AA, AB, A123 |
| `*A` | A로 끝남 | A, AA, BA |
| `*A*` | 중간에 A 포함 | A, BA, ABC |
| `A+` | A 뒤에 한 글자 | AA, AB |
| `++` | 두 글자 | AA, LH, 01 |

초급자에게 가장 중요한 주의점은 다음이다.

```text
CP의 패턴 문자는 ABAP 스타일의 * 와 + 이다.
SQL LIKE의 % 와 _ 와 혼동하지 않는다.
```

### 8.3 CP의 실무 사용처

`CP`는 사용자가 정확한 값을 모르고 일부 패턴으로 검색하고 싶을 때 사용한다.

| 상황 | 예시 |
|---|---|
| 이름이 K로 시작 | `K*` |
| 코드에 TEST 포함 | `*TEST*` |
| 항공사 코드가 A로 시작 | `A*` |
| 문서번호 앞자리가 45 | `45*` |
| 특정 Prefix를 가진 Z 객체 | `ZSD_*` |

### 8.4 CP에서 HIGH는 사용하지 않는다

`CP`는 패턴 조건이므로 일반적으로 `LOW`에 패턴을 넣고 `HIGH`는 비운다.

좋은 예:

```abap
APPEND VALUE #( sign   = 'I'
                option = 'CP'
                low    = 'A*' ) TO lt_carrid.
```

나쁜 예:

```abap
APPEND VALUE #( sign   = 'I'
                option = 'CP'
                low    = 'A*'
                high   = 'L*' ) TO lt_carrid.
```

패턴 조건에서 `HIGH`를 채우면 읽는 사람에게 혼란을 준다. 범위를 표현하려면 `BT`, 패턴을 표현하려면 `CP`를 사용한다.

## 9. CP와 SIGN 조합

| SIGN | OPTION | LOW | 의미 |
|---|---|---|---|
| I | CP | A* | A로 시작하는 값 포함 |
| E | CP | A* | A로 시작하는 값 제외 |

예를 들어 다음 조건은 A로 시작하는 항공사 코드를 제외한다.

```abap
APPEND VALUE #( sign   = 'E'
                option = 'CP'
                low    = 'A*' ) TO lt_carrid.
```

사람의 말로 풀면 다음과 같다.

```text
CARRID가 A로 시작하지 않는 데이터 조회
```

`CP`와 Exclude 조건이 결합되면 결과 해석이 매우 중요하다. 예를 들어 `E CP '*TEST*'`는 “TEST가 포함된 값을 제외”한다. 테스트 데이터, 임시 코드, 특정 Prefix 제외 같은 요구사항에서 유용할 수 있다.

## 10. EQ, BT, CP 비교

### 10.1 핵심 비교표

| OPTION | 이름 | LOW 사용 | HIGH 사용 | 대표 의미 |
|---|---|---|---|---|
| EQ | Equal | 사용 | 미사용 | 단일값과 같음 |
| BT | Between | 사용 | 사용 | 시작값부터 종료값까지 |
| CP | Contains Pattern | 사용 | 미사용 | 패턴에 맞음 |

### 10.2 예시 비교

| 요구사항 | 적절한 OPTION | 예시 |
|---|---|---|
| 항공사 AA만 조회 | EQ | `I EQ AA` |
| 날짜 2026년 1월 조회 | BT | `I BT 20260101 20260131` |
| A로 시작하는 항공사 조회 | CP | `I CP A*` |
| AA 제외 | EQ + E | `E EQ AA` |
| 1월 제외 | BT + E | `E BT 20260101 20260131` |
| TEST 포함 코드 제외 | CP + E | `E CP *TEST*` |

## 11. SELECT-OPTIONS에서 사용자가 입력한 조건 읽기

다음 Selection Screen을 가정한다.

```abap
TABLES sflight.

SELECT-OPTIONS s_carrid FOR sflight-carrid.
SELECT-OPTIONS s_fldate FOR sflight-fldate.
```

사용자가 다음 조건을 입력했다고 하자.

```text
항공사: AA
날짜: 2026.01.01 ~ 2026.01.31
```

내부적으로는 다음과 같은 Selection Table 형태로 이해할 수 있다.

### 11.1 S_CARRID

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | EQ | AA |  |

### 11.2 S_FLDATE

| SIGN | OPTION | LOW | HIGH |
|---|---|---|---|
| I | BT | 20260101 | 20260131 |

이 조건을 Open SQL에 그대로 연결하면 다음과 같다.

```abap
SELECT carrid, connid, fldate, price, currency
  FROM sflight
  WHERE carrid IN @s_carrid
    AND fldate IN @s_fldate
  INTO TABLE @DATA(lt_flight).
```

핵심은 다음이다.

```text
SELECT-OPTIONS는 화면 입력 필드인 동시에 Range Table이다.
Open SQL의 IN 조건은 그 Range Table을 조건 집합으로 해석한다.
```

## 12. Multiple Selection 화면과 OPTION

`SELECT-OPTIONS`의 Multiple Selection 버튼을 누르면 단일값, 범위, 제외값, 패턴 등을 여러 줄로 입력할 수 있다.

예를 들어 사용자가 다음 요구사항을 입력한다고 하자.

```text
AA와 LH는 포함한다.
AZ는 제외한다.
A로 시작하는 코드는 포함한다.
```

이를 Selection Table로 표현하면 다음처럼 될 수 있다.

| SIGN | OPTION | LOW | HIGH | 의미 |
|---|---|---|---|---|
| I | EQ | AA |  | AA 포함 |
| I | EQ | LH |  | LH 포함 |
| E | EQ | AZ |  | AZ 제외 |
| I | CP | A* |  | A로 시작 포함 |

이 조합은 초급자에게 다소 복잡하다. 특히 `I CP A*`와 `E EQ AZ`가 함께 있으면, A로 시작하는 전체 코드 중 AZ는 제외하는 식으로 해석할 수 있다.

실무 프로그램에서는 이런 조건을 직접 해석하기보다 `WHERE field IN @s_field`에 맡기는 편이 안전하고 간결하다. 다만 사용자의 조회 조건이 복잡해질수록 결과 설명과 테스트 케이스가 중요해진다.

## 13. 조건 조합을 ABAP으로 직접 만들기

화면 입력 없이 Range Table을 직접 구성할 수도 있다.

### 13.1 EQ 조건 직접 구성

```abap
DATA lt_carrid TYPE RANGE OF sflight-carrid.

lt_carrid = VALUE #(
  ( sign = 'I' option = 'EQ' low = 'AA' )
  ( sign = 'I' option = 'EQ' low = 'LH' )
).
```

### 13.2 BT 조건 직접 구성

```abap
DATA lt_date TYPE RANGE OF sflight-fldate.

lt_date = VALUE #(
  ( sign = 'I' option = 'BT' low = '20260101' high = '20260131' )
).
```

### 13.3 CP 조건 직접 구성

```abap
DATA lt_carrid TYPE RANGE OF sflight-carrid.

lt_carrid = VALUE #(
  ( sign = 'I' option = 'CP' low = 'A*' )
).
```

### 13.4 Include와 Exclude 조합

```abap
DATA lt_carrid TYPE RANGE OF sflight-carrid.

lt_carrid = VALUE #(
  ( sign = 'I' option = 'CP' low = 'A*' )
  ( sign = 'E' option = 'EQ' low = 'AZ' )
).
```

의미:

```text
A로 시작하는 항공사 코드를 포함하되, AZ는 제외한다.
```

## 14. 초급자가 자주 하는 실수

### 14.1 EQ에 HIGH를 넣는 실수

잘못된 예:

```abap
( sign = 'I' option = 'EQ' low = 'AA' high = 'LH' )
```

문제:

```text
EQ는 단일값 비교이므로 HIGH가 필요 없다.
```

수정:

```abap
( sign = 'I' option = 'EQ' low = 'AA' )
```

### 14.2 BT에 HIGH를 비우는 실수

잘못된 예:

```abap
( sign = 'I' option = 'BT' low = '20260101' )
```

문제:

```text
BT는 범위 조건이므로 HIGH가 필요하다.
```

수정:

```abap
( sign = 'I' option = 'BT' low = '20260101' high = '20260131' )
```

### 14.3 CP에서 SQL LIKE 패턴을 쓰는 실수

잘못된 예:

```abap
( sign = 'I' option = 'CP' low = 'A%' )
```

문제:

```text
CP는 ABAP 스타일 패턴을 사용한다. %가 아니라 *를 사용한다.
```

수정:

```abap
( sign = 'I' option = 'CP' low = 'A*' )
```

### 14.4 CP를 써야 할 곳에 EQ를 쓰는 실수

요구사항:

```text
A로 시작하는 항공사 전체 조회
```

잘못된 예:

```abap
( sign = 'I' option = 'EQ' low = 'A*' )
```

문제:

```text
EQ는 문자 그대로 A*와 같은 값을 찾는다.
패턴 검색이 아니다.
```

수정:

```abap
( sign = 'I' option = 'CP' low = 'A*' )
```

### 14.5 Include/Exclude 조건을 설명하지 않는 실수

실무에서 다음 조건은 결과가 직관적이지 않을 수 있다.

```abap
lt_carrid = VALUE #(
  ( sign = 'I' option = 'CP' low = 'A*' )
  ( sign = 'E' option = 'EQ' low = 'AA' )
).
```

이 조건은 다음처럼 문서화해야 한다.

```text
A로 시작하는 항공사 중 AA는 제외한다.
```

복잡한 조건은 주석 또는 테스트 케이스를 함께 남기는 것이 유지보수에 좋다.

## 15. 실습: EQ / BT / CP 옵션 비교 프로그램

### 15.1 실습 목표

`SFLIGHT` 표준 테이블을 기준으로 `SELECT-OPTIONS` 조건을 입력하고, `EQ`, `BT`, `CP` 옵션의 차이를 확인한다.

### 15.2 실습 코드

```abap
REPORT zgpt_range_option_demo.

TABLES sflight.

SELECT-OPTIONS s_carrid FOR sflight-carrid.
SELECT-OPTIONS s_fldate FOR sflight-fldate.

START-OF-SELECTION.

  SELECT carrid,
         connid,
         fldate,
         price,
         currency
    FROM sflight
    WHERE carrid IN @s_carrid
      AND fldate IN @s_fldate
    INTO TABLE @DATA(lt_flight).

  WRITE: / '조회 건수:', lines( lt_flight ).
  ULINE.

  LOOP AT lt_flight INTO DATA(ls_flight).
    WRITE: / ls_flight-carrid,
             ls_flight-connid,
             ls_flight-fldate,
             ls_flight-price,
             ls_flight-currency.
  ENDLOOP.
```

### 15.3 실습 케이스 1 — EQ

입력:

```text
S_CARRID = AA
```

기대:

```text
CARRID가 AA인 항공편만 조회된다.
```

### 15.4 실습 케이스 2 — BT

입력:

```text
S_FLDATE = 20260101 ~ 20261231
```

기대:

```text
해당 날짜 범위에 포함되는 항공편만 조회된다.
```

### 15.5 실습 케이스 3 — CP

Multiple Selection에서 패턴 조건 입력:

```text
S_CARRID CP A*
```

기대:

```text
A로 시작하는 항공사 코드가 조회된다.
```

### 15.6 실습 케이스 4 — Exclude

Multiple Selection에서 다음 조건 입력:

```text
Include Pattern: A*
Exclude Single Value: AA
```

기대:

```text
A로 시작하는 항공사 중 AA는 제외된다.
```

## 16. 디버깅 관찰 포인트

`SELECT-OPTIONS`가 실제로 어떤 Range Table 구조를 가지는지 확인하려면 디버깅이 가장 좋다.

### 16.1 Breakpoint 위치

다음 위치에 Breakpoint를 둔다.

```abap
START-OF-SELECTION.
```

또는 `SELECT` 문 직전에 둔다.

### 16.2 확인할 변수

디버거에서 다음을 확인한다.

```text
S_CARRID[]
S_FLDATE[]
```

### 16.3 확인할 필드

| 필드 | 확인 내용 |
|---|---|
| SIGN | I 또는 E인지 확인 |
| OPTION | EQ, BT, CP 중 무엇인지 확인 |
| LOW | 사용자가 입력한 시작값 또는 단일값 |
| HIGH | BT일 때 종료값 |

디버깅을 통해 “Selection Screen 입력값이 내부 Range Table로 변환된다”는 사실을 눈으로 확인하는 것이 중요하다.

## 17. DDIC와의 연결

`SELECT-OPTIONS`는 보통 Dictionary Field를 기준으로 선언된다.

```abap
SELECT-OPTIONS s_carrid FOR sflight-carrid.
```

이 경우 `SFLIGHT-CARRID`의 Data Element, Domain, Search Help, Field Label 등이 Selection Screen에 영향을 줄 수 있다.

| DDIC 요소 | Selection Screen에 주는 영향 |
|---|---|
| Data Element | 필드 의미와 라벨 |
| Domain | 기술 타입과 길이 |
| Search Help | F4 Help |
| Fixed Value | 입력 가능한 값 힌트 또는 F4 후보 |

따라서 `EQ`, `BT`, `CP`는 단순 문법이 아니라 DDIC 타입과 연결된 입력 조건이다.

예를 들어 날짜 필드에 `BT`를 사용하면 시작일과 종료일 범위 입력이 자연스럽다. 반면 상태 코드처럼 값이 제한된 필드에는 `EQ`나 Multiple Selection이 더 자주 쓰일 수 있다.

## 18. 실무 설계 기준

### 18.1 사용자가 원하는 조건 유형을 먼저 파악한다

Selection Screen을 설계하기 전에 다음을 먼저 정리한다.

| 질문 | 예시 판단 |
|---|---|
| 사용자는 단일값만 입력하는가? | `PARAMETERS` 또는 `SELECT-OPTIONS` 단일 EQ |
| 여러 값을 입력해야 하는가? | `SELECT-OPTIONS` |
| 범위 입력이 필요한가? | `BT` 가능성이 높음 |
| 패턴 검색이 필요한가? | `CP` 허용 여부 검토 |
| 제외 조건이 필요한가? | Multiple Selection과 `SIGN = E` 고려 |

### 18.2 CP를 무조건 허용하지 않는다

`CP`는 편리하지만 성능과 결과 예측 측면에서 주의가 필요하다.

특히 다음 패턴은 많은 데이터를 조회할 가능성이 있다.

```text
*TEST*
*A*
*
```

앞에 `*`가 붙는 패턴은 DB 인덱스를 효율적으로 활용하기 어려운 형태가 될 수 있다. 초급 과정에서는 성능 심화까지 들어가지는 않지만, 실무에서는 무분별한 패턴 검색을 조심해야 한다.

### 18.3 BT는 날짜와 번호 범위에서 유용하다

`BT`는 날짜, 번호, 금액처럼 순서가 있는 값에서 자연스럽다.

| 필드 유형 | BT 적합도 |
|---|---|
| 날짜 | 높음 |
| 문서번호 | 상황에 따라 높음 |
| 금액 | 높음 |
| 상태 코드 | 낮음 |
| 이름 | 보통 낮음 |

상태 코드처럼 의미 중심의 코드값에는 `BT`보다 `EQ` 또는 Multiple Selection이 더 적합한 경우가 많다.

### 18.4 Selection 조건은 테스트 케이스로 검증한다

조회 조건은 코드만 보고 끝내면 안 된다. 다음 테스트 케이스를 반드시 준비한다.

```text
단일값 EQ
범위 BT
패턴 CP
Include 여러 개
Exclude 하나 이상
조건 미입력
존재하지 않는 값
LOW > HIGH 같은 비정상 입력
```

## 19. 입력 검증 관점

Selection Screen에서는 사용자가 다양한 조건을 입력할 수 있다. 실무 프로그램에서는 필요한 경우 `AT SELECTION-SCREEN` 이벤트에서 입력값을 검증한다.

### 19.1 BT 범위 검증 예시

```abap
AT SELECTION-SCREEN.

  LOOP AT s_fldate ASSIGNING FIELD-SYMBOL(<ls_date>).
    IF <ls_date>-option = 'BT'
       AND <ls_date>-low IS NOT INITIAL
       AND <ls_date>-high IS NOT INITIAL
       AND <ls_date>-low > <ls_date>-high.
      MESSAGE '시작일은 종료일보다 클 수 없습니다.' TYPE 'E'.
    ENDIF.
  ENDLOOP.
```

### 19.2 CP 사용 제한 예시

특정 필드에서는 패턴 검색을 허용하지 않을 수도 있다.

```abap
AT SELECTION-SCREEN.

  LOOP AT s_carrid ASSIGNING FIELD-SYMBOL(<ls_carrid>).
    IF <ls_carrid>-option = 'CP'.
      MESSAGE '항공사 코드는 패턴 검색을 허용하지 않습니다.' TYPE 'E'.
    ENDIF.
  ENDLOOP.
```

위 코드는 교육용 예시이다. 실제 프로그램에서는 업무 요구사항과 사용자 편의성, 성능 기준을 함께 고려한다.

## 22. 강사용 설명 포인트

강의에서는 `EQ`, `BT`, `CP`를 단순 옵션 목록으로 설명하지 말고, 반드시 Selection Table 행으로 시각화해야 한다.

추천 설명 순서:

```text
1. 사용자가 화면에 값을 입력한다.
2. ABAP은 그 값을 Selection Table 행으로 관리한다.
3. 각 행은 SIGN / OPTION / LOW / HIGH를 가진다.
4. OPTION 값이 비교 방식을 결정한다.
5. WHERE field IN @range는 이 조건 집합을 SQL 조건으로 사용한다.
```

강의 중 반드시 보여줄 디버깅 포인트:

```text
S_CARRID[] 내부 테이블
S_FLDATE[] 내부 테이블
Multiple Selection 입력 후 생성되는 여러 행
CP 입력 시 LOW에 들어가는 패턴 문자열
Exclude 조건 입력 시 SIGN = E
```

## 23. 핵심 요약

```text
EQ는 LOW와 같은 단일값을 선택한다.
BT는 LOW부터 HIGH까지의 범위를 선택한다.
CP는 LOW에 입력한 패턴과 맞는 값을 선택한다.
EQ와 CP는 일반적으로 HIGH를 사용하지 않는다.
BT는 LOW와 HIGH를 모두 사용한다.
SIGN = I는 포함, SIGN = E는 제외를 의미한다.
CP는 ABAP 스타일 패턴인 * 와 + 를 사용한다.
SQL LIKE의 % 와 _ 와 혼동하지 않는다.
SELECT-OPTIONS는 화면 입력이면서 동시에 Range Table이다.
```
