## 1. 왜 WHERE 조건이 필요한가?

ABAP SQL에서 조건 없이 테이블을 조회하면 테이블의 모든 행을 읽으려고 한다.

```abap
SELECT FROM sflight
       FIELDS carrid,
              connid,
              fldate,
              price
       INTO TABLE @DATA(lt_flight).
```

교육용 테이블에 데이터가 적을 때는 문제가 없어 보일 수 있다. 하지만 실무 운영 테이블은 수십만, 수백만, 수천만 건의 데이터를 가질 수 있다. 조건 없는 조회는 다음 문제를 만들 수 있다.

| 문제 | 설명 |
|---|---|
| 성능 저하 | 불필요하게 많은 데이터를 DB에서 읽는다. |
| 네트워크 부하 | DB에서 Application Server로 전송되는 데이터량이 커진다. |
| 메모리 사용 증가 | 조회 결과가 Internal Table에 대량 적재될 수 있다. |
| 사용자 대기 시간 증가 | Report 실행 시간이 길어진다. |
| 운영 안정성 저하 | 동시 사용자 환경에서 시스템 부하를 키울 수 있다. |

따라서 실무 ABAP에서는 가능한 한 업무적으로 필요한 조건을 명확히 지정해야 한다.

```text
Open SQL 기본 원칙: 필요한 필드만, 필요한 조건으로, 필요한 데이터만 조회한다.
```

## 2. WHERE 조건의 기본 구조

WHERE는 조회 대상 행을 제한하는 조건절이다.

기본 구조는 다음과 같다.

```abap
SELECT FROM table_name
       FIELDS field1,
              field2
       WHERE field1 = 조건값
       INTO TABLE @DATA(lt_result).
```

예를 들어 항공사 코드가 `AA`인 데이터만 조회하려면 다음과 같이 작성한다.

```abap
SELECT FROM scarr
       FIELDS carrid,
              carrname,
              currcode
       WHERE carrid = 'AA'
       INTO TABLE @DATA(lt_scarr).
```

이 코드는 `SCARR` 전체를 조회하지 않고 `CARRID = 'AA'`에 해당하는 행만 조회한다.

---

## 3. Literal 조건과 변수 조건

WHERE 조건에는 고정값을 직접 쓸 수도 있고, ABAP 변수 값을 사용할 수도 있다.

### 3.1 Literal 조건

```abap
SELECT FROM scarr
       FIELDS carrid,
              carrname
       WHERE carrid = 'AA'
       INTO TABLE @DATA(lt_scarr).
```

여기서 `'AA'`는 코드에 직접 작성된 고정값이다.

Literal 조건은 초급 실습에는 간단하지만, 실무 프로그램에서는 사용자가 입력한 값이나 프로그램에서 계산한 값으로 조회하는 경우가 많다.

### 3.2 ABAP 변수 조건

ABAP 변수 값을 SQL 조건에 넣을 때는 Host Variable 표기를 사용한다.

```abap
DATA lv_carrid TYPE scarr-carrid VALUE 'AA'.

SELECT FROM scarr
       FIELDS carrid,
              carrname
       WHERE carrid = @lv_carrid
       INTO TABLE @DATA(lt_scarr).
```

여기서 `@lv_carrid`가 Host Variable이다.

---

## 4. Host Variable @란 무엇인가?

Host Variable은 SQL 문 안에서 사용하는 ABAP 변수이다. 최신 ABAP SQL 문법에서는 ABAP 변수 앞에 `@`를 붙여 SQL의 컬럼명과 ABAP 변수를 명확히 구분한다.

```abap
WHERE carrid = @lv_carrid
```

이 문장을 해석하면 다음과 같다.

| 부분 | 의미 |
|---|---|
| `carrid` | DB 테이블 `SCARR`의 필드 |
| `=` | 비교 연산자 |
| `@lv_carrid` | ABAP 프로그램 안의 변수 `lv_carrid` 값 |

즉, 왼쪽은 DB 필드이고 오른쪽은 ABAP 변수이다.

### 4.1 왜 @가 필요한가?

ABAP SQL 문 안에는 DB 필드명과 ABAP 변수명이 함께 등장할 수 있다. `@`는 “이 이름은 DB 필드가 아니라 ABAP 변수다”라고 명시하는 표기이다.

초급자는 다음처럼 기억하면 된다.

```text
SQL 안에서 ABAP 변수나 파라미터를 사용할 때는 앞에 @를 붙인다.
```

### 4.2 @가 붙는 대표 위치

| 위치 | 예시 | 의미 |
|---|---|---|
| WHERE 조건 | `WHERE carrid = @lv_carrid` | ABAP 변수 값을 조건으로 사용 |
| INTO 대상 | `INTO TABLE @DATA(lt_scarr)` | ABAP 변수를 결과 대상으로 사용 |
| 계산식/비교값 | `WHERE price >= @lv_min_price` | ABAP 변수와 DB 값 비교 |

이번 모듈에서는 WHERE 조건과 `PARAMETERS` 입력값 연결에 집중한다.

## 5. PARAMETERS와 WHERE 연결

앞선 Selection Screen 기초에서 `PARAMETERS`를 학습했다. `PARAMETERS`는 사용자가 실행 화면에서 값을 입력할 수 있게 한다.

예를 들어 항공사 코드를 입력받는 파라미터를 만들 수 있다.

```abap
PARAMETERS p_carrid TYPE scarr-carrid.
```

이 입력값을 SQL WHERE 조건에 연결하면 사용자가 입력한 항공사만 조회할 수 있다.

```abap
REPORT zjhy_sql_where_01.

PARAMETERS p_carrid TYPE scarr-carrid.

SELECT FROM scarr
       FIELDS carrid,
              carrname,
              currcode
       WHERE carrid = @p_carrid
       INTO TABLE @DATA(lt_scarr).

IF sy-subrc = 0.
  LOOP AT lt_scarr INTO DATA(ls_scarr).
    WRITE: / ls_scarr-carrid,
             ls_scarr-carrname,
             ls_scarr-currcode.
  ENDLOOP.
ELSE.
  WRITE: / 'No carrier found for:', p_carrid.
ENDIF.
```

### 5.1 코드 해석

| 코드 | 설명 |
|---|---|
| `PARAMETERS p_carrid TYPE scarr-carrid.` | 항공사 코드를 입력받는 Selection Screen 필드 생성 |
| `WHERE carrid = @p_carrid` | 입력받은 항공사 코드와 같은 데이터만 조회 |
| `INTO TABLE @DATA(lt_scarr)` | 조회 결과를 Internal Table로 받음 |
| `sy-subrc = 0` | 조회 결과가 있는지 확인 |
| `WRITE` | 조회 결과 또는 메시지 출력 |

초급자에게 가장 중요한 부분은 다음이다.

```text
PARAMETERS는 ABAP 변수이고, SQL WHERE 안에서 사용할 때 @p_carrid처럼 @를 붙인다.
```

## 6. WHERE에서 자주 쓰는 비교 연산자

WHERE 조건에서는 다양한 비교 연산자를 사용할 수 있다. 초급 단계에서는 다음을 먼저 익히면 충분하다.

| 연산자 | 의미 | 예시 |
|---|---|---|
| `=` | 같다 | `WHERE carrid = @p_carrid` |
| `<>` | 같지 않다 | `WHERE carrid <> 'AA'` |
| `>` | 크다 | `WHERE price > @lv_price` |
| `<` | 작다 | `WHERE price < @lv_price` |
| `>=` | 크거나 같다 | `WHERE price >= @lv_min` |
| `<=` | 작거나 같다 | `WHERE price <= @lv_max` |

예제:

```abap
PARAMETERS p_price TYPE sflight-price.

SELECT FROM sflight
       FIELDS carrid,
              connid,
              fldate,
              price,
              currency
       WHERE price >= @p_price
       INTO TABLE @DATA(lt_flight).
```

이 예제는 입력한 금액 이상인 항공편 데이터를 조회한다.

> [추정] `SFLIGHT` 데이터와 통화/금액 값은 교육 시스템의 샘플 데이터 상태에 따라 다를 수 있다.

## 7. AND와 OR

WHERE 조건은 여러 개를 조합할 수 있다.

### 7.1 AND

AND는 모든 조건을 만족해야 한다.

```abap
PARAMETERS: p_carrid TYPE sflight-carrid,
            p_connid TYPE sflight-connid.

SELECT FROM sflight
       FIELDS carrid,
              connid,
              fldate,
              price
       WHERE carrid = @p_carrid
         AND connid = @p_connid
       INTO TABLE @DATA(lt_flight).
```

해석:

```text
항공사 코드가 p_carrid와 같고,
노선 번호가 p_connid와 같은 데이터만 조회한다.
```

### 7.2 OR

OR는 조건 중 하나라도 만족하면 조회된다.

```abap
SELECT FROM scarr
       FIELDS carrid,
              carrname
       WHERE carrid = 'AA'
          OR carrid = 'LH'
       INTO TABLE @DATA(lt_scarr).
```

해석:

```text
항공사 코드가 AA이거나 LH인 데이터를 조회한다.
```

### 7.3 괄호 사용

AND와 OR를 함께 사용할 때는 조건 우선순위를 명확히 하기 위해 괄호를 사용하는 것이 좋다.

```abap
SELECT FROM sflight
       FIELDS carrid,
              connid,
              fldate,
              price
       WHERE ( carrid = 'AA' OR carrid = 'LH' )
         AND price >= @p_price
       INTO TABLE @DATA(lt_flight).
```

실무에서는 조건이 조금만 복잡해져도 괄호를 사용해 의도를 명확히 하는 것이 유지보수에 좋다.

## 8. BETWEEN과 LIKE 기초

이번 모듈은 WHERE 기본 조건을 다루므로 `BETWEEN`과 `LIKE`도 맛보기 수준으로만 정리한다.

### 8.1 BETWEEN

BETWEEN은 범위 조건을 표현한다.

```abap
PARAMETERS: p_from TYPE sflight-fldate,
            p_to   TYPE sflight-fldate.

SELECT FROM sflight
       FIELDS carrid,
              connid,
              fldate
       WHERE fldate BETWEEN @p_from AND @p_to
       INTO TABLE @DATA(lt_flight).
```

### 8.2 LIKE

LIKE는 패턴 조건을 표현한다.

```abap
PARAMETERS p_name TYPE scarr-carrname.

SELECT FROM scarr
       FIELDS carrid,
              carrname
       WHERE carrname LIKE @p_name
       INTO TABLE @DATA(lt_scarr).
```

실습 시 `p_name`에 `%Air%` 같은 패턴을 입력하면 이름에 `Air`가 포함된 항공사를 찾는 방식으로 사용할 수 있다.

> 주의: 사용자 입력값으로 LIKE 패턴을 사용할 때는 검색 범위가 넓어질 수 있으므로 운영 대량 테이블에서는 성능을 고려해야 한다.

## 9. Host Variable @를 빠뜨렸을 때의 오류

최신 ABAP SQL 문법에서 ABAP 변수를 SQL 문 안에 사용할 때 `@`를 빠뜨리면 Syntax Error가 발생할 수 있다.

잘못된 예:

```abap
DATA lv_carrid TYPE scarr-carrid VALUE 'AA'.

SELECT FROM scarr
       FIELDS carrid,
              carrname
       WHERE carrid = lv_carrid
       INTO TABLE @DATA(lt_scarr).
```

좋은 예:

```abap
DATA lv_carrid TYPE scarr-carrid VALUE 'AA'.

SELECT FROM scarr
       FIELDS carrid,
              carrname
       WHERE carrid = @lv_carrid
       INTO TABLE @DATA(lt_scarr).
```

초급자 규칙은 단순하다.

```text
WHERE 조건에서 ABAP 변수 또는 PARAMETERS를 쓸 때는 @를 붙인다.
```

## 10. 필드명과 변수명이 같을 때

ABAP 변수명과 DB 필드명이 비슷하거나 같으면 혼동이 생길 수 있다.

예를 들어 다음과 같은 변수명을 만들었다고 하자.

```abap
DATA carrid TYPE scarr-carrid VALUE 'AA'.
```

그리고 SQL에서 다음처럼 쓰면 혼동이 커진다.

```abap
WHERE carrid = @carrid
```

문법적으로는 왼쪽 `carrid`가 DB 필드이고 오른쪽 `@carrid`가 ABAP 변수임을 구분할 수 있다. 하지만 가독성은 좋지 않다.

따라서 실무에서는 변수명 Prefix를 사용하는 것이 좋다.

| 변수 유형 | 예시 |
|---|---|
| Local Variable | `lv_carrid` |
| Parameter | `p_carrid` |
| Internal Table | `lt_scarr` |
| Work Area / Structure | `ls_scarr` |

좋은 예:

```abap
DATA lv_carrid TYPE scarr-carrid VALUE 'AA'.

SELECT FROM scarr
       FIELDS carrid,
              carrname
       WHERE carrid = @lv_carrid
       INTO TABLE @DATA(lt_scarr).
```

## 11. 데이터 타입 일치의 중요성

WHERE 조건의 비교 대상은 타입이 맞아야 한다.

예를 들어 `SCARR-CARRID`는 항공사 코드 타입이다. 이 필드를 비교할 파라미터는 같은 Dictionary 타입을 사용하는 것이 좋다.

권장:

```abap
PARAMETERS p_carrid TYPE scarr-carrid.
```

비권장:

```abap
PARAMETERS p_carrid TYPE c LENGTH 10.
```

비권장 방식이 항상 문법 오류를 만드는 것은 아니지만, 불필요한 길이 차이, 값 형식 차이, 입력 도움말 연결 문제, 의미 불일치를 만들 수 있다.

실무에서는 가능하면 DDIC 필드 또는 Data Element를 참조해 타입을 선언한다.

```text
PARAMETERS p_carrid TYPE scarr-carrid.
```

이 방식은 다음 장점이 있다.

| 장점 | 설명 |
|---|---|
| 타입 일관성 | 테이블 필드와 입력값 타입이 일치 |
| 유지보수성 | 필드 길이 변경 시 영향 추적이 쉬움 |
| 입력 의미 | 해당 필드의 업무 의미를 코드에서 드러냄 |
| F4 Help 연결 가능성 | Data Element/Search Help 기반 연결 가능 |

## 12. 실습 1: 항공사 코드 조건 조회

### 12.1 실습 목표

Selection Screen에서 항공사 코드를 입력받아 `SCARR`에서 해당 항공사 정보를 조회한다.

### 12.2 실습 코드

```abap
REPORT zjhy_sql_where_carrier.

PARAMETERS p_carrid TYPE scarr-carrid OBLIGATORY.

SELECT FROM scarr
       FIELDS carrid,
              carrname,
              currcode,
              url
       WHERE carrid = @p_carrid
       INTO TABLE @DATA(lt_scarr).

IF sy-subrc = 0.
  LOOP AT lt_scarr INTO DATA(ls_scarr).
    WRITE: / 'Carrier ID  :', ls_scarr-carrid,
           / 'Carrier Name:', ls_scarr-carrname,
           / 'Currency    :', ls_scarr-currcode,
           / 'URL         :', ls_scarr-url.
  ENDLOOP.
ELSE.
  WRITE: / 'No carrier found for input:', p_carrid.
ENDIF.
```

### 12.3 실습 포인트

| 포인트 | 설명 |
|---|---|
| `OBLIGATORY` | 입력값을 필수로 만든다. |
| `TYPE scarr-carrid` | 테이블 필드와 같은 타입을 사용한다. |
| `WHERE carrid = @p_carrid` | 입력값을 조회 조건으로 사용한다. |
| `sy-subrc` | 조회 결과 존재 여부를 확인한다. |

## 13. 실습 2: 항공편 가격 조건 조회

### 13.1 실습 목표

입력한 항공사 코드와 최소 가격 조건을 기준으로 `SFLIGHT` 데이터를 조회한다.

### 13.2 실습 코드

```abap
REPORT zjhy_sql_where_flight.

PARAMETERS: p_carrid TYPE sflight-carrid OBLIGATORY,
            p_price  TYPE sflight-price.

SELECT FROM sflight
       FIELDS carrid,
              connid,
              fldate,
              price,
              currency
       WHERE carrid = @p_carrid
         AND price  >= @p_price
       INTO TABLE @DATA(lt_flight).

IF sy-subrc = 0.
  LOOP AT lt_flight INTO DATA(ls_flight).
    WRITE: / ls_flight-carrid,
             ls_flight-connid,
             ls_flight-fldate,
             ls_flight-price,
             ls_flight-currency.
  ENDLOOP.
ELSE.
  WRITE: / 'No flight data found.'.
ENDIF.
```

### 13.3 실습 시 주의점

`p_price`에 초기값이 들어가면 가격 조건이 사실상 전체 범위처럼 동작할 수 있다. 실제 프로그램에서는 입력값 검증이나 기본값 정책을 별도로 고려해야 한다.

입력값 검증 이벤트는 Selection Screen 심화에서 다루므로, 이번 모듈에서는 WHERE 조건 연결에 집중한다.

## 14. 정상 흐름과 오류 흐름

### 14.1 정상 흐름

```text
PARAMETERS로 입력값 선언
→ SELECT FROM으로 조회 대상 지정
→ FIELDS로 필요한 필드 지정
→ WHERE에서 DB 필드와 @파라미터 비교
→ INTO TABLE로 결과 수신
→ sy-subrc 또는 lines( )로 결과 확인
→ LOOP/WRITE로 출력
```

### 14.2 오류 흐름 1: @ 누락

| 항목 | 내용 |
|---|---|
| 증상 | Syntax Error 발생 가능 |
| 원인 | SQL 문 안의 ABAP 변수에 `@`를 붙이지 않음 |
| 해결 | `@p_carrid`, `@lv_carrid`처럼 Host Variable 표기 사용 |

### 14.3 오류 흐름 2: 필드 타입 불일치

| 항목 | 내용 |
|---|---|
| 증상 | 조회 결과 없음 또는 형식 변환 혼란 |
| 원인 | WHERE 비교 대상의 타입/길이가 부적절 |
| 해결 | `TYPE table-field` 또는 적절한 Data Element 사용 |

### 14.4 오류 흐름 3: 조건이 너무 제한적임

| 항목 | 내용 |
|---|---|
| 증상 | 조회 결과가 없음 |
| 원인 | 입력한 조건과 일치하는 데이터가 없음 |
| 해결 | SE16N에서 데이터 존재 여부 확인, 조건을 하나씩 줄여 테스트 |

### 14.5 오류 흐름 4: 조건이 너무 넓음

| 항목 | 내용 |
|---|---|
| 증상 | 대량 데이터 조회, 실행 지연 |
| 원인 | WHERE 조건이 없거나 너무 넓음 |
| 해결 | Key 또는 선택도 높은 필드를 조건에 포함 |

## 15. 성능 관점의 기본 감각

WHERE 조건은 성능과 직접 연결된다.

초급자는 아직 Index, Execution Plan, ST05 SQL Trace를 깊게 배우지 않았지만, 다음 감각은 가져야 한다.

```text
WHERE 조건이 구체적일수록 DB가 필요한 데이터를 더 적게 읽을 가능성이 높다.
```

그러나 모든 WHERE 조건이 항상 빠른 것은 아니다. 실무에서는 테이블 Key, Secondary Index, 데이터 분포, 조건 필드의 선택도, DB 최적화 방식이 함께 영향을 준다.

이번 모듈에서는 다음 기준만 기억한다.

| 좋은 습관 | 이유 |
|---|---|
| Key 필드를 조건에 활용 | 데이터 식별 기준이 명확함 |
| 필요한 조건을 누락하지 않음 | 전체 조회 방지 |
| 사용자 입력값을 그대로 대량 LIKE 검색에 쓰지 않음 | 검색 범위가 과도하게 넓어질 수 있음 |
| 조건 없는 운영 테이블 조회를 피함 | 성능 리스크 감소 |

---

## 16. 보안과 안정성 관점

정적 ABAP SQL에서 Host Variable을 사용하는 것은 ABAP 변수와 SQL 표현을 명확히 구분하는 데 도움이 된다.

다만 초급자가 오해하면 안 되는 점이 있다.

```text
@를 붙였다고 모든 보안 문제가 자동으로 해결되는 것은 아니다.
```

실무에서는 다음도 함께 고려해야 한다.

| 관점 | 설명 |
|---|---|
| 권한 | 사용자가 조회해도 되는 데이터인지 확인 필요 |
| 입력 검증 | 비정상 입력값 처리 필요 |
| 동적 SQL | 동적 WHERE 문자열 조립은 별도 주의 필요 |
| 대량 조회 제한 | 사용자가 넓은 조건으로 전체 데이터를 조회하지 않게 설계 |

이번 모듈은 정적 SQL과 Host Variable 기초에 집중한다. 권한 객체, 동적 SQL, 보안 검증은 후속 실무 과정에서 다룬다.

## 17. 실무 코딩 스타일 권장

### 17.1 파라미터 이름은 의미 있게 작성한다

좋은 예:

```abap
PARAMETERS p_carrid TYPE scarr-carrid.
```

나쁜 예:

```abap
PARAMETERS p1 TYPE c LENGTH 3.
```

### 17.2 필드와 변수는 구분되게 작성한다

```abap
DATA lv_carrid TYPE scarr-carrid.

SELECT FROM scarr
       FIELDS carrid,
              carrname
       WHERE carrid = @lv_carrid
       INTO TABLE @DATA(lt_scarr).
```

### 17.3 조건은 읽기 쉽게 정렬한다

```abap
WHERE carrid = @p_carrid
  AND connid = @p_connid
  AND fldate BETWEEN @p_from AND @p_to
```

한 줄에 모든 조건을 몰아넣는 것보다, 조건별로 줄을 나누면 유지보수성이 좋아진다.

## 18. 자가 진단 문제

### Q1. WHERE 조건의 목적은 무엇인가?

정답: 조회 대상 테이블에서 필요한 행만 선택하기 위해 사용한다.

### Q2. `@p_carrid`에서 `@`의 의미는 무엇인가?

정답: SQL 문 안에서 `p_carrid`가 DB 필드가 아니라 ABAP 프로그램의 Host Variable임을 나타낸다.

### Q3. `PARAMETERS p_carrid TYPE scarr-carrid.`처럼 선언하는 장점은 무엇인가?

정답: 테이블 필드와 같은 타입을 사용하므로 길이와 의미가 일치하고, 유지보수성과 입력 의미가 좋아진다.

### Q4. AND와 OR의 차이는 무엇인가?

정답: AND는 모든 조건이 참이어야 하고, OR는 조건 중 하나 이상이 참이면 된다.

### Q5. WHERE 조건이 너무 넓으면 어떤 문제가 생길 수 있는가?

정답: 대량 데이터 조회로 인해 성능 저하, 메모리 사용 증가, 사용자 대기 시간 증가가 발생할 수 있다.

M04: INTO TABLE로 Internal Table 적재

## 21. 핵심 요약

```text
WHERE는 조회할 행을 제한하는 조건절이다.
ABAP 변수나 PARAMETERS를 SQL 문 안에서 사용할 때는 @를 붙인다.
@는 DB 필드와 ABAP Host Variable을 구분하기 위한 표기이다.
PARAMETERS 입력값은 WHERE 조건과 연결해 사용자 기반 조회를 만들 수 있다.
조건 없는 전체 조회는 교육용 실습에서는 가능하지만 실무 운영 테이블에서는 주의해야 한다.
WHERE 조건은 성능, 안정성, 유지보수성과 직접 연결된다.
```
