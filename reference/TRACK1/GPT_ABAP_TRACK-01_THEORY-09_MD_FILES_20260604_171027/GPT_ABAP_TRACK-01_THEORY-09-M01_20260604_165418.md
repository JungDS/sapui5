## 0. 이 문서의 학습 범위

이 문서는 `THEORY-09-M01 — SELECT FROM / FIELDS 기본 구조`만 다룬다.

이번 모듈의 핵심은 ABAP 프로그램에서 데이터베이스 테이블을 조회하는 가장 기본적인 문장을 이해하는 것이다. 아직 `WHERE` 조건, `SELECT SINGLE`, Internal Table 적재 심화, 반복 SELECT 성능 문제는 깊게 다루지 않는다. 이 내용들은 같은 Section의 후속 모듈에서 순서대로 학습한다.

이번 모듈에서 다루는 최소 흐름은 다음과 같다.

```text
ABAP Dictionary의 Transparent Table을 이해한다.
→ ABAP SQL의 SELECT 문이 테이블을 조회한다는 점을 이해한다.
→ FROM으로 조회 대상을 지정한다.
→ FIELDS로 가져올 컬럼을 지정한다.
→ INTO 또는 INTO TABLE로 결과를 받을 수 있음을 이해한다.
→ 결과를 WRITE 또는 LOOP로 간단히 확인한다.
```

## 1. Open SQL과 ABAP SQL의 기본 개념

SAP ABAP에서 데이터베이스를 조회할 때 사용하는 SQL을 전통적으로 Open SQL이라고 불렀고, 최신 문서에서는 ABAP SQL이라는 명칭을 함께 사용한다. 초급자는 다음처럼 이해하면 된다.

```text
ABAP SQL = ABAP 프로그램 안에서 SAP 데이터베이스 테이블을 조회·처리하기 위한 표준 SQL 계층
```

중요한 점은 ABAP 개발자가 물리 DB가 HANA인지, 다른 DB인지에 직접 종속된 SQL을 매번 작성하지 않는다는 것이다. ABAP SQL은 SAP 시스템이 제공하는 데이터 접근 계층이며, ABAP Dictionary에 정의된 테이블과 필드를 기준으로 동작한다.

### 1.1 왜 ABAP SQL을 먼저 배워야 하는가?

실무 ABAP 프로그램은 대부분 데이터를 조회하고, 가공하고, 출력한다.

| 프로그램 유형 | 데이터 조회 필요성 |
|---|---|
| Report Program | 테이블 데이터를 조회해 리스트 출력 |
| ALV Program | 조회 결과를 Internal Table에 담고 ALV 출력 |
| Interface Program | 송수신 대상 데이터를 DB에서 읽거나 저장 |
| Batch Program | 대량 데이터를 조회해 처리 |
| CDS/RAP 기반 개발 | 하위 테이블과 데이터 모델 이해 필요 |

즉, ABAP SQL은 ABAP 실무의 핵심 기초이다.

## 2. SELECT 기본 구조

가장 기본적인 ABAP SQL 조회 구조는 다음과 같다.

```abap
SELECT FROM table_name
       FIELDS field1, field2, field3
       INTO TABLE @DATA(lt_result).
```

구성 요소를 나누면 다음과 같다.

| 구문 | 의미 |
|---|---|
| `SELECT` | 데이터 조회를 시작하는 명령 |
| `FROM` | 어떤 DB 테이블에서 조회할지 지정 |
| `FIELDS` | 어떤 필드를 가져올지 지정 |
| `INTO TABLE` | 조회 결과 여러 건을 Internal Table에 담음 |
| `@DATA(...)` | 조회 결과를 받을 ABAP 변수를 인라인 선언 |

초급자는 우선 다음 문장만 기억하면 된다.

```text
SELECT는 데이터를 읽는 문장이고, FROM은 테이블, FIELDS는 컬럼, INTO는 결과를 받을 ABAP 변수이다.
```

## 3. 예제 테이블: SCARR

초급 Open SQL 실습에서는 SAP 교육 시스템에 자주 존재하는 항공사 예제 테이블을 사용할 수 있다.

| 테이블 | 설명 |
|---|---|
| `SCARR` | 항공사 기본 정보 |
| `SPFLI` | 항공 노선 정보 |
| `SFLIGHT` | 항공편 정보 |

이번 모듈에서는 가장 단순한 `SCARR`를 기준으로 설명한다.

대표 필드는 다음과 같다.

| 필드 | 의미 |
|---|---|
| `CARRID` | 항공사 코드 |
| `CARRNAME` | 항공사명 |
| `CURRCODE` | 통화 코드 |
| `URL` | 항공사 URL |

> [추정] 교육 시스템의 샘플 데이터 존재 여부는 시스템 설정에 따라 다를 수 있다. `SCARR` 데이터가 없거나 다른 샘플 테이블을 사용하는 경우, 강사가 지정한 표준 교육용 테이블로 대체한다.

## 4. 최소 조회 예제

다음 예제는 `SCARR`에서 항공사 코드와 항공사명을 조회한다.

```abap
REPORT zjhy_open_sql_01.

SELECT FROM scarr
       FIELDS carrid,
              carrname
       INTO TABLE @DATA(lt_carrier).

LOOP AT lt_carrier INTO DATA(ls_carrier).
  WRITE: / ls_carrier-carrid,
           ls_carrier-carrname.
ENDLOOP.
```

### 4.1 코드 해석

| 코드 | 설명 |
|---|---|
| `REPORT zjhy_open_sql_01.` | 실행 가능한 Report Program 선언 |
| `SELECT FROM scarr` | `SCARR` 테이블에서 조회 |
| `FIELDS carrid, carrname` | 항공사 코드와 항공사명만 가져옴 |
| `INTO TABLE @DATA(lt_carrier)` | 결과 여러 건을 Internal Table로 받음 |
| `LOOP AT lt_carrier` | 조회 결과를 한 줄씩 반복 |
| `WRITE` | 조회 결과를 리스트로 출력 |

이번 단계에서는 Internal Table의 상세 문법을 완전히 이해하지 않아도 된다. 중요한 것은 `SELECT` 결과가 ABAP 변수에 담기고, 그 값을 출력할 수 있다는 흐름이다.

## 5. FIELDS 구문의 의미

`FIELDS`는 테이블에서 어떤 필드를 가져올지 지정한다.

예를 들어 다음 구문은 `SCARR`에서 세 필드만 가져온다.

```abap
SELECT FROM scarr
       FIELDS carrid,
              carrname,
              currcode
       INTO TABLE @DATA(lt_carrier).
```

### 5.1 필요한 필드만 선택해야 하는 이유

초급자는 처음에 `SELECT *`를 자주 사용한다. 하지만 실무에서는 필요한 필드만 명시하는 습관이 중요하다.

| 방식 | 설명 | 실무 관점 |
|---|---|---|
| `SELECT *` | 모든 필드를 가져옴 | 초급 실습 외에는 신중히 사용 |
| `FIELDS carrid, carrname` | 필요한 필드만 가져옴 | 권장 |

필요한 필드만 가져오면 다음 장점이 있다.

1. 코드 의도가 명확하다.
2. 불필요한 데이터 전송을 줄일 수 있다.
3. 결과 구조가 단순해진다.
4. 후속 유지보수자가 어떤 데이터를 쓰는지 바로 알 수 있다.

### 5.2 `SELECT *`가 항상 금지는 아니다

`SELECT *`가 문법적으로 항상 잘못된 것은 아니다. 예를 들어 매우 작은 커스터마이징 테이블 전체 필드가 필요한 경우 사용할 수 있다. 하지만 초급 학습 단계에서는 먼저 필드를 명시하는 습관을 들이는 것이 좋다.

```text
기본 습관: SELECT *보다 FIELDS로 필요한 필드만 지정한다.
```

## 6. FROM 구문의 의미

`FROM`은 조회 대상 테이블을 지정한다.

```abap
SELECT FROM scarr
       FIELDS carrid,
              carrname
       INTO TABLE @DATA(lt_carrier).
```

여기서 `scarr`가 조회 대상이다.

ABAP SQL의 `FROM`에는 일반적으로 다음과 같은 대상이 올 수 있다.

| 대상 | 설명 | 초급 학습 여부 |
|---|---|---|
| Transparent Table | 실제 DB 테이블 | 이번 모듈 핵심 |
| DDIC View | Dictionary View | 후속 DDIC View에서 학습 |
| CDS View Entity | 최신 ABAP 데이터 모델 | 후속 CDS Section에서 학습 |
| Join Source | 여러 테이블 결합 | Open SQL 2차에서 학습 |

이번 모듈에서는 Transparent Table 한 개를 조회하는 기본 구조에 집중한다.

## 7. INTO와 INTO TABLE의 기본 감각

SELECT 결과는 ABAP 프로그램 안의 변수로 받아야 사용할 수 있다.

여러 건을 받을 때는 일반적으로 Internal Table에 담는다.

```abap
SELECT FROM scarr
       FIELDS carrid,
              carrname
       INTO TABLE @DATA(lt_carrier).
```

단건 조회는 후속 모듈 `THEORY-09-M03 SELECT SINGLE과 단건 조회`에서 자세히 다룬다. 이번 모듈에서는 다음 정도만 이해한다.

| 구문 | 의미 |
|---|---|
| `INTO TABLE` | 여러 건을 Internal Table에 담음 |
| `INTO` | 한 건 또는 특정 구조에 담음 |

초급자에게는 `INTO TABLE @DATA(...)`가 조회 결과를 바로 확인하기 쉬운 방식이다.

## 8. 최신 문법과 구문 위치

ABAP SQL에는 전통적인 구문과 최신 형태의 구문이 함께 존재한다.

### 8.1 최신 형태 예

```abap
SELECT FROM scarr
       FIELDS carrid,
              carrname
       INTO TABLE @DATA(lt_carrier).
```

### 8.2 전통적인 형태 예

```abap
SELECT carrid,
       carrname
  FROM scarr
  INTO TABLE @DATA(lt_carrier).
```

둘 다 시스템 릴리스와 문법 지원 범위에 따라 사용할 수 있다. S/4HANA 기반 학습에서는 최신 ABAP SQL 형태를 익히되, 현장에서 기존 코드를 읽을 수 있도록 전통적인 형태도 함께 인식하는 것이 좋다.

> [추정] 일부 구형 교육 시스템에서는 `SELECT FROM ... FIELDS ...` 형태가 제한될 수 있다. 이 경우 강사는 전통적인 `SELECT field1 field2 FROM table INTO TABLE ...` 형태로 대체할 수 있다.

## 9. 실습: 항공사 목록 조회

### 9.1 실습 목표

`SCARR` 테이블에서 항공사 코드와 항공사명을 조회하여 출력한다.

### 9.2 실습 코드

```abap
REPORT zjhy_sql_select_fields.

SELECT FROM scarr
       FIELDS carrid,
              carrname
       INTO TABLE @DATA(lt_scarr).

IF sy-subrc = 0.
  LOOP AT lt_scarr INTO DATA(ls_scarr).
    WRITE: / ls_scarr-carrid,
             ls_scarr-carrname.
  ENDLOOP.
ELSE.
  WRITE: / 'No carrier data found.'.
ENDIF.
```

| 확인 항목 | 설명 |

| 결과 출력 | 항공사 코드와 이름이 출력되는지 확인 |

## 10. 오류 상황과 해결

### 10.1 테이블명이 잘못된 경우

```abap
SELECT FROM zzz_unknown
       FIELDS carrid
       INTO TABLE @DATA(lt_result).
```

가능한 오류:

```text
테이블 또는 뷰가 존재하지 않음
```

해결:

1. SE11에서 테이블 존재 여부 확인
2. 철자 확인
3. 권한 또는 패키지 접근 이슈 확인

### 10.2 필드명이 잘못된 경우

```abap
SELECT FROM scarr
       FIELDS carrier_id
       INTO TABLE @DATA(lt_result).
```

`SCARR`에 `CARRIER_ID`라는 필드가 없다면 Syntax Error가 발생한다.

해결:

1. SE11에서 `SCARR` 필드 목록 확인
2. 실제 필드명 `CARRID` 사용
3. 대소문자는 일반적으로 크게 문제되지 않지만, 표준 필드명을 정확히 쓰는 습관 유지

### 10.3 INTO 누락

ABAP SQL 조회 결과를 받을 대상이 없으면 문장이 완성되지 않는다.

```abap
SELECT FROM scarr
       FIELDS carrid,
              carrname.
```

해결:

```abap
SELECT FROM scarr
       FIELDS carrid,
              carrname
       INTO TABLE @DATA(lt_scarr).
```

### 10.4 조회 결과가 없는 경우

테이블에는 데이터가 없을 수도 있다. 이 경우 프로그램은 문법적으로 정상이어도 출력이 없을 수 있다.

확인 방법:

1. SE16N에서 `SCARR` 데이터 존재 여부 확인
2. 현재 Client 확인
3. WHERE 조건이 있는 경우 조건 제거 후 확인

WHERE 조건은 다음 모듈에서 다룬다.

## 11. 실무 관점의 기본 원칙

### 11.1 조회 대상은 명확히 한다

테이블명을 정확히 알고 조회해야 한다. 실무에서는 표준 테이블을 무작정 조회하기보다 데이터 모델과 업무 흐름을 먼저 확인해야 한다.

### 11.2 필요한 필드만 조회한다

필요한 필드만 명시하는 습관은 성능과 가독성 모두에 도움이 된다.

### 11.3 조건 없는 전체 조회는 주의한다

이번 모듈에서는 단순 학습을 위해 조건 없는 조회를 사용한다. 하지만 운영 테이블에서 조건 없이 전체 데이터를 조회하면 성능 문제가 발생할 수 있다.

```text
교육용 소량 테이블: 조건 없는 조회 가능
운영 대량 테이블: WHERE 조건 없는 전체 조회 주의
```

### 11.4 표준 SAP 동작과 고객사 관행을 구분한다

고객사에서는 성능 가이드, ATC 규칙, 네이밍 규칙, 조회 제한 기준이 별도로 있을 수 있다. 이 모듈은 표준 문법과 기본 흐름을 학습하는 단계이며, 실제 프로젝트에서는 고객사 개발 표준을 함께 따라야 한다.

## 12. 자가 진단 문제

### Q1. `FROM`의 역할은 무엇인가?

정답: 조회할 데이터 소스, 즉 테이블이나 뷰를 지정한다.

### Q2. `FIELDS`의 역할은 무엇인가?

정답: 조회 대상 테이블에서 가져올 필드를 지정한다.

### Q3. `SELECT *`보다 필요한 필드를 명시하는 것이 좋은 이유는?

정답: 코드 의도가 명확해지고 불필요한 데이터 전송을 줄일 수 있으며, 결과 구조가 단순해져 유지보수성이 좋아진다.

### Q4. 조회 결과를 ABAP 프로그램에서 사용하려면 어떤 구문이 필요한가?

정답: `INTO` 또는 `INTO TABLE`로 결과를 받을 대상이 필요하다.

## 13. 후속 모듈 연결

이번 모듈은 Open SQL의 가장 기본 구조를 다루었다.

다음 모듈 `THEORY-09-M02 — WHERE 조건과 Host Variable @ 기초`에서는 전체 테이블을 조회하지 않고 필요한 데이터만 선택하기 위해 WHERE 조건을 사용한다. 또한 ABAP 변수 값을 SQL 문 안에 안전하게 넣기 위해 `@` Host Variable 표기를 학습한다.

```text
M01: SELECT FROM / FIELDS 기본 구조
M02: WHERE 조건과 Host Variable @ 기초
M03: SELECT SINGLE과 단건 조회
M04: INTO TABLE로 Internal Table 적재
M05: 명시적 Target Table 선언 방식
M06: 반복 SELECT 안티패턴 맛보기
```
