## 3. String Template이란 무엇인가?

String Template은 문자열 안에 변수, 식, 함수 호출, 포맷 옵션을 직접 삽입하여 문자열을 생성하는 ABAP 문법이다.

기본 형태는 다음과 같다.

```abap
DATA(lv_text) = |Hello ABAP|.
```

변수를 넣을 때는 중괄호를 사용한다.

```abap
DATA(lv_name) = 'ABAP'.
DATA(lv_text) = |Hello { lv_name }|.
WRITE lv_text.
```

실행 결과는 다음과 같다.

```text
Hello ABAP
```

초급자 관점에서 String Template은 다음처럼 이해하면 된다.

```text
문자열 안에 변수와 계산 결과를 자연스럽게 끼워 넣는 Modern ABAP 문법
```

## 4. 왜 String Template을 사용하는가?

### 4.1 전통 방식의 불편함

전통 ABAP에서는 문자열 조립에 `CONCATENATE`를 많이 사용했다.

```abap
DATA: lv_name TYPE string VALUE 'Kim',
      lv_age  TYPE i VALUE 30,
      lv_text TYPE string.

CONCATENATE 'Name:' lv_name 'Age:' lv_age
       INTO lv_text SEPARATED BY space.

WRITE lv_text.
```

이 방식은 동작하지만 다음 문제가 있다.

| 문제 | 설명 |
|---|---|
| 읽기 어려움 | 최종 문자열 모양을 한눈에 보기 어렵다. |
| 공백 처리 번거로움 | `SEPARATED BY space` 또는 별도 공백 문자열이 필요하다. |
| 변수와 텍스트가 분리됨 | 문자열의 의미 흐름이 끊긴다. |
| 포맷 처리 추가 필요 | 날짜, 숫자, ALPHA 변환 등은 별도 처리가 필요할 수 있다. |

### 4.2 String Template 방식

같은 로직을 String Template로 작성하면 다음과 같다.

```abap
DATA(lv_name) = 'Kim'.
DATA(lv_age)  = 30.

DATA(lv_text) = |Name: { lv_name } Age: { lv_age }|.

WRITE lv_text.
```

문자열의 최종 형태가 코드에서 바로 보인다.

```text
Name: Kim Age: 30
```

이것이 String Template의 가장 큰 장점이다.

## 5. 기본 문법

### 5.1 문자열 리터럴

String Template은 `|`로 시작하고 `|`로 끝난다.

```abap
DATA(lv_message) = |SAP ABAP Modern Syntax|.
```

문자열 안의 공백은 템플릿에 작성한 대로 반영된다.

```abap
DATA(lv_message) = |A B C|.
```

결과:

```text
A B C
```

### 5.2 변수 삽입

변수는 `{`와 `}` 안에 넣는다.

```abap
DATA(lv_carrid) = 'AA'.
DATA(lv_text)   = |Carrier ID = { lv_carrid }|.
```

결과:

```text
Carrier ID = AA
```

### 5.3 계산식 삽입

String Template 안에는 단순 변수뿐 아니라 계산식도 넣을 수 있다.

```abap
DATA(lv_qty)   = 3.
DATA(lv_price) = 100.

DATA(lv_text) = |Total = { lv_qty * lv_price }|.
```

결과:

```text
Total = 300
```

다만 실무에서는 너무 복잡한 계산식을 템플릿 안에 직접 넣지 않는 것이 좋다. 복잡한 계산은 별도 변수로 분리하는 편이 읽기 쉽다.

---

## 6. String Template의 가장 중요한 가치: 의도 표현

String Template을 쓰는 이유는 단순히 코드 줄 수를 줄이기 위해서가 아니다. 핵심은 **의도를 더 잘 보이게 만드는 것**이다.

### 6.1 나쁜 예

```abap
DATA(lv_text) = |{ lv_user }{ lv_status }{ lv_date }|.
```

이 코드는 짧지만 읽기 어렵다. 각 값이 무엇을 의미하는지, 어디에 공백이나 구분자가 있는지 알기 어렵다.

### 6.2 좋은 예

```abap
DATA(lv_text) = |User={ lv_user }, Status={ lv_status }, Date={ lv_date }|.
```

이 코드는 최종 문자열의 의미가 명확하다.

실무 기준은 다음이다.

```text
String Template은 짧게 쓰는 문법이 아니라, 결과 문자열의 의도를 명확하게 보이게 하는 문법이다.
```

## 7. 내장 함수와 String Template

String Template은 내장 함수와 함께 사용할 때 실무 가치가 커진다.

대표적인 문자열 관련 내장 함수는 다음과 같다.

| 함수 | 목적 | 예시 |
|---|---|---|
| `strlen( )` | 문자열 길이 반환 | `strlen( lv_text )` |
| `to_upper( )` | 대문자 변환 | `to_upper( lv_text )` |
| `to_lower( )` | 소문자 변환 | `to_lower( lv_text )` |
| `substring( )` | 문자열 일부 추출 | `substring( val = lv_text off = 0 len = 3 )` |
| `condense( )` | 불필요한 공백 정리 | `condense( val = lv_text )` |
| `replace( )` | 문자열 치환 | `replace( val = lv_text sub = '-' with = '' )` |
| `contains( )` | 특정 문자열 포함 여부 확인 | `contains( val = lv_text sub = 'SAP' )` |

> [추정] 시스템의 ABAP Release에 따라 일부 함수나 선택 파라미터 사용 가능 범위가 다를 수 있다. 교육 시스템에서는 Syntax Check와 F1 Help로 실제 지원 여부를 확인하는 것이 좋다.

## 8. 내장 함수 예제

### 8.1 `strlen( )`

문자열 길이를 확인한다.

```abap
REPORT zgpt_string_func_01.

DATA(lv_name) = 'SAP ABAP'.
DATA(lv_text) = |Text="{ lv_name }", Length={ strlen( lv_name ) }|.

WRITE lv_text.
```

예상 출력:

```text
Text="SAP ABAP", Length=8
```

### 8.2 `to_upper( )`, `to_lower( )`

문자열의 대소문자를 변환한다.

```abap
REPORT zgpt_string_func_02.

DATA(lv_code) = 'abap'.

WRITE: / |Original: { lv_code }|,
       / |Upper   : { to_upper( lv_code ) }|,
       / |Lower   : { to_lower( lv_code ) }|.
```

예상 출력:

```text
Original: abap
Upper   : ABAP
Lower   : abap
```

### 8.3 `substring( )`

문자열 일부를 추출한다.

```abap
REPORT zgpt_string_func_03.

DATA(lv_code) = 'S4HANA2026'.

DATA(lv_prefix) = substring( val = lv_code off = 0 len = 6 ).

WRITE |Prefix={ lv_prefix }|.
```

예상 출력:

```text
Prefix=S4HANA
```

ABAP의 offset은 일반적으로 0부터 시작한다. 따라서 `off = 0`은 첫 번째 문자부터 시작한다.

### 8.4 `condense( )`

불필요한 공백을 정리한다.

```abap
REPORT zgpt_string_func_04.

DATA(lv_raw) = `  SAP    ABAP    Syntax  `.
DATA(lv_out) = condense( val = lv_raw ).

WRITE: / |Raw      : [{ lv_raw }]|,
       / |Condense : [{ lv_out }]|.
```

예상 출력:

```text
Raw      : [  SAP    ABAP    Syntax  ]
Condense : [SAP ABAP Syntax]
```

### 8.5 `replace( )`

문자열 일부를 다른 값으로 바꾼다.

```abap
REPORT zgpt_string_func_05.

DATA(lv_date_text) = '2026-06-04'.
DATA(lv_clean)     = replace( val = lv_date_text sub = '-' with = '' occ = 0 ).

WRITE |Clean Date={ lv_clean }|.
```

예상 출력:

```text
Clean Date=20260604
```

`occ = 0`은 모든 발생 항목을 대상으로 한다는 의미로 사용된다.

## 9. String Template 안에서 함수 호출하기

String Template 안에서는 함수 호출 결과를 바로 넣을 수 있다.

```abap
REPORT zgpt_string_template_func.

DATA(lv_user) = 'kim'.
DATA(lv_role) = 'developer'.

DATA(lv_message) = |User={ to_upper( lv_user ) }, Role={ to_upper( lv_role ) }|.

WRITE lv_message.
```

예상 출력:

```text
User=KIM, Role=DEVELOPER
```

이 방식은 간단한 변환에는 유용하다. 하지만 함수 호출이 많아지면 한 줄이 너무 길어질 수 있다.

### 9.1 과도한 사용 예

```abap
DATA(lv_text) = |{ replace( val = to_upper( condense( val = lv_raw ) ) sub = '-' with = '_' occ = 0 ) }|.
```

이 코드는 Modern ABAP이지만 읽기 어렵다.

### 9.2 개선 예

```abap
DATA(lv_clean) = condense( val = lv_raw ).
DATA(lv_upper) = to_upper( lv_clean ).
DATA(lv_text)  = replace( val = lv_upper sub = '-' with = '_' occ = 0 ).

WRITE |Result={ lv_text }|.
```

또는 의미 있는 중간 변수명을 더 명확하게 줄 수 있다.

```abap
DATA(lv_normalized_text) = condense( val = lv_raw ).
DATA(lv_output_code)     = to_upper( lv_normalized_text ).

WRITE |Output Code={ lv_output_code }|.
```

핵심은 다음이다.

```text
String Template 안에는 간단한 표현식만 넣는다.
복잡한 변환은 의미 있는 중간 변수로 분리한다.
```

## 10. 날짜와 시간 출력

### 10.1 기본 날짜 출력

ABAP의 `DATS` 타입은 내부적으로 `YYYYMMDD` 형태를 가진다. 화면에 어떤 형식으로 표시되는지는 사용자 설정, 출력 방식, 변환 옵션에 따라 달라질 수 있다.

간단한 예제:

```abap
REPORT zgpt_date_template_01.

DATA(lv_date) = sy-datum.
DATA(lv_time) = sy-uzeit.

WRITE: / |System Date={ lv_date }|,
       / |System Time={ lv_time }|.
```

초급 단계에서는 다음을 기억한다.

```text
날짜와 시간은 단순 문자열이 아니라 SAP 타입과 사용자 포맷 영향을 고려해야 한다.
```

### 10.2 명시적 문자열 조립이 필요한 경우

업무 인터페이스나 파일명에는 `YYYYMMDD` 같은 고정 형식이 필요할 수 있다. 이 경우에는 내부 날짜 값을 그대로 쓰거나 별도 변환 규칙을 명확히 해야 한다.

```abap
DATA(lv_file_name) = |USER_EXPORT_{ sy-datum }_{ sy-uzeit }.txt|.
```

예상 형태:

```text
USER_EXPORT_20260604_153000.txt
```

단, 실제 파일명으로 사용할 때는 시스템별 허용 문자, 시간대, 중복 방지 규칙을 추가로 고려해야 한다.

## 11. 숫자와 금액 출력

String Template에서 숫자를 바로 넣을 수 있다.

```abap
REPORT zgpt_number_template_01.

DATA(lv_qty)   = 3.
DATA(lv_price) = 1500.
DATA(lv_total) = lv_qty * lv_price.

WRITE |Qty={ lv_qty }, Price={ lv_price }, Total={ lv_total }|.
```

예상 출력:

```text
Qty=3, Price=1500, Total=4500
```

하지만 실무에서는 금액과 수량을 단순 숫자로 출력하면 충분하지 않은 경우가 많다.

| 항목 | 고려 사항 |
|---|---|
| 금액 | 통화키, 소수점, 사용자 포맷 |
| 수량 | 단위, 소수점, 반올림 |
| 비율 | 소수점 자리수, % 표기 |
| 파일 인터페이스 | 고정 길이, 소수점 문자, 천 단위 구분자 여부 |

따라서 금액·수량 출력은 단순 String Template 사용보다 업무 포맷 기준을 먼저 확인해야 한다.

## 12. ALPHA 변환과 코드 출력 감각

SAP에서는 고객번호, 자재번호, 문서번호처럼 내부 형식과 외부 표시 형식이 다른 값이 많다. 예를 들어 내부적으로는 앞에 0이 채워진 값이 사용될 수 있다.

String Template에는 변환 루틴과 함께 사용할 수 있는 포맷 옵션이 존재한다. 대표적으로 ALPHA 변환은 초급자가 자주 접하는 주제이다.

예시 개념:

```abap
DATA(lv_customer) = '12345'.
DATA(lv_text) = |Customer={ lv_customer ALPHA = IN }|.
```

또는 표시용으로 외부 형식이 필요할 수 있다.

```abap
DATA(lv_customer_out) = |{ lv_customer ALPHA = OUT }|.
```

> [추정] 실습 시스템의 ABAP Release와 필드 타입에 따라 ALPHA 포맷 옵션 사용 가능 여부와 결과가 다를 수 있다. 실무에서는 대상 필드의 Data Element, Conversion Exit, 도메인 설정을 함께 확인해야 한다.

초급자에게 중요한 메시지는 다음이다.

```text
문서번호나 고객번호는 단순 문자열처럼 보이지만, SAP에서는 내부/외부 표현 변환이 중요할 수 있다.
```

## 14. `WRITE ... TO` 대체 감각

전통 ABAP에서는 값을 문자열로 변환하기 위해 `WRITE ... TO`를 사용했다.

```abap
DATA: lv_date TYPE d VALUE sy-datum,
      lv_text TYPE string.

WRITE lv_date TO lv_text.
WRITE lv_text.
```

Modern ABAP에서는 단순 변환 목적이라면 String Template으로 더 간결하게 표현할 수 있다.

```abap
DATA(lv_text) = |{ sy-datum }|.
WRITE lv_text.
```

다만 `WRITE ... TO`가 항상 나쁜 것은 아니다. 특정 포맷, 길이, 출력 옵션, 레거시 호환이 필요한 경우에는 여전히 사용될 수 있다.

실무 판단 기준은 다음이다.

| 상황 | 권장 판단 |
|---|---|
| 단순 메시지 문자열 조립 | String Template 권장 |
| 복잡한 출력 포맷 제어 | 별도 변수 또는 검증된 변환 로직 사용 |
| 기존 코드 유지보수 | 무리한 일괄 변경 금지 |
| 표준 출력 동작 의존 | Syntax Check와 결과 비교 필수 |

## 15. Internal Table과 String Template

Internal Table 데이터를 출력하거나 로그 메시지로 만들 때 String Template은 매우 유용하다.

### 15.1 테스트 데이터 생성

```abap
REPORT zgpt_template_itab_01.

TYPES: BEGIN OF ty_user,
         user_id   TYPE c LENGTH 10,
         user_name TYPE c LENGTH 30,
         status    TYPE c LENGTH 1,
       END OF ty_user.

DATA(lt_user) = VALUE STANDARD TABLE OF ty_user(
  ( user_id = 'U0001' user_name = 'Kim'  status = 'A' )
  ( user_id = 'U0002' user_name = 'Lee'  status = 'I' )
  ( user_id = 'U0003' user_name = 'Park' status = 'B' ) ).

LOOP AT lt_user INTO DATA(ls_user).
  WRITE: / |User={ ls_user-user_id }, Name={ ls_user-user_name }, Status={ ls_user-status }|.
ENDLOOP.
```

예상 출력:

```text
User=U0001, Name=Kim, Status=A
User=U0002, Name=Lee, Status=I
User=U0003, Name=Park, Status=B
```

### 15.2 상태 텍스트 변환과 조합

```abap
LOOP AT lt_user INTO DATA(ls_user).
  DATA(lv_status_text) = SWITCH string( ls_user-status
    WHEN 'A' THEN 'Active'
    WHEN 'I' THEN 'Inactive'
    WHEN 'B' THEN 'Blocked'
    ELSE 'Unknown' ).

  WRITE: / |User={ ls_user-user_id }, Status={ lv_status_text }|.
ENDLOOP.
```

`SWITCH`는 별도 모듈에서 더 자세히 다룰 수 있으므로, 여기서는 문자열 메시지와 조합할 수 있다는 정도만 이해한다.

## 17. String Template 사용 시 주의할 점

### 17.1 너무 긴 한 줄 금지

나쁜 예:

```abap
DATA(lv_text) = |User={ lv_user_id }, Name={ lv_name }, Status={ lv_status }, Created={ lv_created_on }, Changed={ lv_changed_on }, Count={ lines( lt_item ) }|.
```

한 줄이 너무 길면 읽기 어렵다.

개선 예:

```abap
DATA(lv_user_summary) = |User={ lv_user_id }, Name={ lv_name }, Status={ lv_status }|.
DATA(lv_audit_info)   = |Created={ lv_created_on }, Changed={ lv_changed_on }|.
DATA(lv_count_info)   = |Count={ lines( lt_item ) }|.
```

### 17.2 복잡한 비즈니스 로직을 템플릿 안에 넣지 않는다

나쁜 예:

```abap
DATA(lv_text) = |{ COND string( WHEN lv_amount > 1000000 AND lv_status = 'A' THEN 'High Active' ELSE 'Normal' ) }|.
```

이 정도 로직은 별도 변수로 분리하는 것이 좋다.

```abap
DATA(lv_category) = COND string(
  WHEN lv_amount > 1000000 AND lv_status = 'A' THEN 'High Active'
  ELSE 'Normal' ).

DATA(lv_text) = |Category={ lv_category }|.
```

### 17.3 다국어 메시지에는 Text Element 검토

String Template은 편리하지만, 사용자에게 보여주는 문장을 코드에 직접 하드코딩하면 다국어 처리와 유지보수에 불리할 수 있다.

실무에서는 다음을 구분해야 한다.

| 용도 | 권장 방식 |
|---|---|
| 임시 디버깅 출력 | String Template 직접 사용 가능 |
| 로그성 내부 메시지 | 상황에 따라 사용 가능 |
| 사용자 화면 메시지 | Text Element, Message Class 검토 |
| 다국어 필수 문구 | 하드코딩 금지 |

### 17.4 타입 변환 결과 확인

String Template은 많은 값을 자동으로 문자열화하지만, 그 결과가 항상 업무적으로 원하는 표시 형식이라는 뜻은 아니다.

특히 다음 항목은 결과를 직접 확인해야 한다.

```text
날짜
시간
금액
수량
문서번호
고객번호
단위
통화
```

## 18. 정상 흐름과 오류 흐름

### 18.1 정상 흐름

```text
문자열에 넣을 변수 준비
→ String Template 작성
→ 필요한 경우 내장 함수로 간단 변환
→ WRITE 또는 로그 변수에 저장
→ 결과 문자열 확인
```

### 18.2 오류 흐름 1: 중괄호 문법 오류

잘못된 예:

```abap
DATA(lv_text) = |User={ lv_user |.
```

문제:

```text
중괄호가 닫히지 않음
```

해결:

```abap
DATA(lv_text) = |User={ lv_user }|.
```

### 18.3 오류 흐름 2: 너무 복잡한 표현식

잘못된 예:

```abap
DATA(lv_text) = |{ substring( val = replace( val = to_upper( lv_raw ) sub = '-' with = '_' occ = 0 ) off = 0 len = 10 ) }|.
```

문제:

```text
코드가 동작하더라도 유지보수자가 의도를 파악하기 어렵다.
```

해결:

```abap
DATA(lv_upper)    = to_upper( lv_raw ).
DATA(lv_replaced) = replace( val = lv_upper sub = '-' with = '_' occ = 0 ).
DATA(lv_prefix)   = substring( val = lv_replaced off = 0 len = 10 ).

DATA(lv_text) = |Prefix={ lv_prefix }|.
```

### 18.4 오류 흐름 3: 타입 포맷 오해

상황:

```abap
DATA(lv_text) = |Date={ sy-datum }|.
```

문제:

```text
사용자가 기대한 날짜 형식과 실제 출력 형식이 다를 수 있다.
```

해결:

```text
출력 결과를 확인하고, 필요한 경우 명시적 포맷 또는 별도 변환 규칙을 적용한다.
```

## 19. 실습: Legacy 문자열 조립 리팩터링

### 19.1 실습 목표

전통적인 `CONCATENATE` 중심 코드를 String Template 기반 코드로 변환한다.

### 19.2 Legacy 코드

```abap
REPORT zgpt_legacy_string.

DATA: lv_user_id TYPE c LENGTH 10 VALUE 'U0001',
      lv_status  TYPE c LENGTH 1  VALUE 'A',
      lv_text    TYPE string.

CONCATENATE 'User' lv_user_id 'has status' lv_status
       INTO lv_text SEPARATED BY space.

WRITE lv_text.
```

### 19.3 Modern ABAP 코드

```abap
REPORT zgpt_modern_string.

DATA(lv_user_id) = 'U0001'.
DATA(lv_status)  = 'A'.

DATA(lv_text) = |User { lv_user_id } has status { lv_status }|.

WRITE lv_text.
```

### 19.4 의미 개선 버전

상태 코드만 보여주면 사용자가 의미를 모를 수 있다. 상태 텍스트를 추가하면 더 좋다.

```abap
DATA(lv_status_text) = SWITCH string( lv_status
  WHEN 'A' THEN 'Active'
  WHEN 'I' THEN 'Inactive'
  WHEN 'B' THEN 'Blocked'
  ELSE 'Unknown' ).

DATA(lv_text) = |User={ lv_user_id }, Status={ lv_status_text }|.

WRITE lv_text.
```

실무 리팩터링은 단순히 문법을 바꾸는 것이 아니라, 결과 문자열의 의미를 더 명확하게 만드는 방향이어야 한다.

## 20. 미니 프로젝트: 항공편 조회 메시지 만들기

### 20.1 목표

표준 교육 테이블 `SFLIGHT` 또는 유사한 항공편 데이터를 조회한 뒤 조회 결과 요약 메시지를 String Template으로 만든다.

### 20.2 예제 코드

```abap
REPORT zgpt_flight_template.

PARAMETERS p_carrid TYPE s_carr_id DEFAULT 'AA'.

SELECT carrid,
       connid,
       fldate,
       price,
       currency
  FROM sflight
  WHERE carrid = @p_carrid
  INTO TABLE @DATA(lt_flight).

DATA(lv_summary) = |Carrier={ p_carrid }, Rows={ lines( lt_flight ) }|.

WRITE: / lv_summary.

LOOP AT lt_flight INTO DATA(ls_flight) FROM 1 TO 5.
  WRITE: / |{ ls_flight-carrid }-{ ls_flight-connid } Date={ ls_flight-fldate } Price={ ls_flight-price } { ls_flight-currency }|.
ENDLOOP.
```

### 20.3 검토 포인트

| 검토 항목 | 설명 |
|---|---|
| 조회 조건 | `p_carrid`가 WHERE 조건에 사용되는가 |
| 요약 메시지 | 조회 건수를 `lines( )`로 표시하는가 |
| 상세 메시지 | 항공편별 정보가 읽기 쉽게 표시되는가 |
| 과도한 출력 방지 | 처음 5건만 출력하는가 |
| 포맷 확인 | 날짜와 금액 표시가 기대와 맞는가 |

> [추정] 시스템에 Flight Model 샘플 데이터가 없을 수 있다. 이 경우 강사가 제공한 Z 테이블 또는 사용 가능한 표준/교육용 테이블로 대체한다.

## 21. Clean ABAP 관점

String Template은 Clean ABAP 스타일과도 잘 맞는다. 핵심은 **읽기 쉬운 의도 표현**이다.

### 21.1 권장 패턴

```abap
DATA(lv_message) = |Order { lv_order_id } was created successfully.|.
```

### 21.2 비권장 패턴

```abap
DATA(lv_message) = |{ lv_order_id }{ lv_status }{ lv_date }{ lv_time }|.
```

### 21.3 판단 기준

| 질문 | 설명 |
|---|---|
| 최종 문자열 모양이 한눈에 보이는가? | String Template 사용의 핵심 기준이다. |
| 템플릿 안의 표현식이 너무 복잡하지 않은가? | 복잡하면 변수로 분리한다. |
| 사용자 문구를 하드코딩하고 있지 않은가? | 다국어가 필요하면 Text Element/Message Class를 검토한다. |
| 포맷이 업무 기준과 맞는가? | 날짜, 금액, 수량은 반드시 확인한다. |

## 22. 자가 진단 문제

### 22.1 객관식

#### Q1. String Template의 기본 구분자로 올바른 것은?

A. `'...'`  
B. `"..."`  
C. `|...|`  
D. `[ ... ]`

정답: C

#### Q2. String Template 안에 변수를 삽입할 때 사용하는 기호는?

A. `{ }`  
B. `( )`  
C. `[ ]`  
D. `< >`

정답: A

#### Q3. 다음 중 String Template 사용 시 적절한 실무 기준은?

A. 모든 비즈니스 로직을 한 줄 템플릿 안에 넣는다.  
B. 최종 문자열의 의미가 잘 보이도록 사용한다.  
C. 다국어 문구도 무조건 코드에 직접 작성한다.  
D. 날짜와 금액 포맷은 확인하지 않아도 된다.

정답: B

### 22.2 단답형

#### Q1. `CONCATENATE`보다 String Template이 유리한 점을 한 가지 쓰시오.

모범 답안:  
최종 문자열의 형태가 코드에서 바로 보여 가독성이 좋고, 변수와 텍스트를 자연스럽게 조합할 수 있다.

#### Q2. 복잡한 함수 호출을 String Template 안에 직접 넣지 않는 것이 좋은 이유는?

모범 답안:  
한 줄이 지나치게 길어지고 의도 파악이 어려워져 유지보수성이 떨어지기 때문이다. 복잡한 변환은 중간 변수로 분리하는 것이 좋다.

#### Q3. 사용자에게 표시되는 문장을 String Template에 하드코딩할 때 주의할 점은?

모범 답안:  
다국어 처리와 유지보수 문제가 생길 수 있으므로 Text Element나 Message Class 사용을 검토해야 한다.

## 24. 강사용 설명 포인트

강의 시에는 다음 순서로 설명하면 이해가 빠르다.

1. `CONCATENATE` 방식의 불편함을 먼저 보여준다.
2. 같은 결과를 String Template으로 바꿔 보여준다.
3. “짧아졌다”보다 “결과 문자열이 보인다”를 강조한다.
4. 내장 함수와 조합해 실제 문자열 정리 예제를 보여준다.
5. 날짜, 금액, ALPHA 변환은 결과 확인이 필요하다고 강조한다.
6. 사용자 메시지 하드코딩과 다국어 이슈를 분리해서 설명한다.
7. 과도하게 복잡한 한 줄 코드를 금지한다.

초급자에게 특히 중요한 문장은 다음이다.

```text
Modern ABAP은 짧게 쓰는 문법이 아니라, 의도를 명확하게 표현하기 위한 문법이다.
```

## 25. 후속 모듈 연결

이번 모듈에서 학습한 String Template은 리팩터링에서 매우 자주 사용된다.

| Legacy 패턴 | Modern ABAP 전환 |
|---|---|
| `CONCATENATE` | String Template |
| `WRITE ... TO` 단순 변환 | String Template |
| 보조 문자열 변수 남발 | 의미 있는 템플릿 변수 |
| 복잡한 메시지 조립 | 템플릿 + 중간 변수 분리 |

후속 모듈에서는 Inline Declaration, VALUE, CORRESPONDING, Table Expression, String Template을 종합하여 Legacy 코드를 더 읽기 쉬운 형태로 바꾸는 연습을 한다.

## 26. 핵심 요약

```text
String Template은 |...|로 작성한다.
변수나 표현식은 { ... } 안에 넣는다.
CONCATENATE보다 최종 문자열 모양을 읽기 쉽다.
내장 함수와 조합하면 문자열 정리, 변환, 요약 메시지 작성이 편해진다.
복잡한 로직을 템플릿 안에 몰아넣으면 오히려 가독성이 떨어진다.
사용자 문구는 다국어와 Message Class/Text Element를 고려해야 한다.
날짜, 금액, 수량, ALPHA 변환은 출력 결과를 반드시 확인해야 한다.
```
