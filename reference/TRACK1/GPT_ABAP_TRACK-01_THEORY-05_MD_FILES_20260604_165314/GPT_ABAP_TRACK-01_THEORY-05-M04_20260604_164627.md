## 3. Local Class란 무엇인가?

### 3.1 쉬운 정의

Local Class는 하나의 ABAP 프로그램, Include, Function Group, Global Class 내부 등 특정 개발 객체 안에 정의되는 클래스이다.

Report 프로그램 기준으로 설명하면, Local Class는 해당 Report 안에 함께 작성된다.

```abap
REPORT z_example_local_class.

CLASS lcl_calculator DEFINITION.
  PUBLIC SECTION.
    METHODS add
      IMPORTING iv_a TYPE i
                iv_b TYPE i
      RETURNING VALUE(rv_result) TYPE i.
ENDCLASS.

CLASS lcl_calculator IMPLEMENTATION.
  METHOD add.
    rv_result = iv_a + iv_b.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA lo_calc TYPE REF TO lcl_calculator.
  CREATE OBJECT lo_calc.

  DATA(lv_result) = lo_calc->add(
    iv_a = 10
    iv_b = 20 ).

  WRITE: / lv_result.
```

이 예제에서 `lcl_calculator`가 Local Class이고, `add`가 Method이다.

### 3.2 왜 Local Class를 배우는가?

초급 ABAP 학습자는 보통 다음 순서로 모듈화를 경험한다.

```text
긴 Report를 작성한다.
→ 중복 코드가 생긴다.
→ FORM으로 분리한다.
→ Function Module을 호출한다.
→ Class와 Method로 구조화한다.
```

Local Class는 객체지향 ABAP으로 넘어가는 첫 번째 실습 단계로 적합하다.  
Global Class를 만들기 전에 하나의 Report 안에서 클래스 문법을 작게 실험할 수 있기 때문이다.

## 4. Local Class와 Global Class의 차이

이번 모듈은 Local Class를 다루지만, Global Class와의 차이를 최소한 알고 있어야 한다.

| 구분 | Local Class | Global Class |
|---|---|---|
| 정의 위치 | 특정 프로그램 내부 | ABAP Repository 객체 |
| 대표 생성 도구 | ABAP Editor / ADT 코드 안 | SE24 또는 ADT Class 생성 |
| 재사용 범위 | 해당 프로그램 내부 중심 | 여러 프로그램에서 재사용 가능 |
| 학습 난이도 | 비교적 낮음 | 더 체계적 설계 필요 |
| 이번 모듈 범위 | 다룸 | 다음 모듈에서 기초 호출 중심으로 다룸 |

초급자는 다음 기준으로 이해하면 된다.

```text
Local Class = 한 프로그램 안에서 코드를 구조화하기 위한 클래스
Global Class = 여러 프로그램에서 재사용하기 위해 Repository에 등록하는 클래스
```

이번 문서에서는 Global Class 생성 방식은 자세히 다루지 않는다.  
다음 모듈 `THEORY-05-M05 — Global Class 호출 기초`에서 별도 학습한다.

## 5. CLASS DEFINITION

### 5.1 역할

`CLASS ... DEFINITION`은 클래스의 외형을 선언하는 영역이다.

여기에는 다음이 들어갈 수 있다.

| 요소 | 의미 |
|---|---|
| 클래스 이름 | 클래스 식별자 |
| Visibility Section | `PUBLIC`, `PROTECTED`, `PRIVATE` 영역 |
| Method 선언 | 어떤 메서드가 있는지 정의 |
| Attribute 선언 | 클래스 또는 객체가 가지는 데이터 선언 |
| Event / Interface 등 | 고급 객체지향 요소 |

초급 단계에서는 `PUBLIC SECTION`과 `METHODS`만 먼저 익혀도 충분하다.

### 5.2 최소 예제

```abap
CLASS lcl_status_helper DEFINITION.
  PUBLIC SECTION.
    METHODS get_status_text
      IMPORTING iv_status TYPE c LENGTH 1
      RETURNING VALUE(rv_text) TYPE string.
ENDCLASS.
```

이 코드는 다음 의미이다.

| 코드 | 의미 |
|---|---|
| `CLASS lcl_status_helper DEFINITION.` | `lcl_status_helper`라는 Local Class의 선언 시작 |
| `PUBLIC SECTION.` | 외부에서 접근 가능한 영역 시작 |
| `METHODS get_status_text` | `get_status_text`라는 Instance Method 선언 |
| `IMPORTING iv_status` | 호출자가 상태값을 넘겨준다 |
| `RETURNING VALUE(rv_text)` | 메서드가 문자열 결과를 반환한다 |
| `ENDCLASS.` | 클래스 선언 종료 |

### 5.3 Local Class 이름 관례

Local Class는 보통 `lcl_` Prefix를 사용한다.

| Prefix | 의미 | 예시 |
|---|---|---|
| `lcl_` | Local Class | `lcl_status_helper` |
| `lo_` | Local Object Reference | `lo_helper` |
| `lr_` | Local Reference | `lr_data` |
| `lv_` | Local Variable | `lv_status` |
| `lt_` | Local Internal Table | `lt_user` |
| `ls_` | Local Structure | `ls_user` |

이름만 보고도 객체의 성격을 이해할 수 있도록 일관된 규칙을 사용하는 것이 좋다.

## 6. CLASS IMPLEMENTATION

### 6.1 역할

`CLASS ... IMPLEMENTATION`은 `CLASS DEFINITION`에서 선언한 Method의 실제 처리 로직을 작성하는 영역이다.

선언만 있고 구현이 없으면 사용할 수 없다.

```abap
CLASS lcl_status_helper IMPLEMENTATION.
  METHOD get_status_text.
    CASE iv_status.
      WHEN 'A'.
        rv_text = 'Active'.
      WHEN 'I'.
        rv_text = 'Inactive'.
      WHEN 'B'.
        rv_text = 'Blocked'.
      WHEN OTHERS.
        rv_text = 'Unknown'.
    ENDCASE.
  ENDMETHOD.
ENDCLASS.
```

### 6.2 선언과 구현의 연결

`DEFINITION`에서 선언한 Method 이름과 `IMPLEMENTATION`에서 구현한 Method 이름은 일치해야 한다.

```abap
" 선언
METHODS get_status_text.

" 구현
METHOD get_status_text.
  ...
ENDMETHOD.
```

이름이 다르면 문법 오류가 발생한다.

```abap
" 선언은 get_status_text인데
METHODS get_status_text.

" 구현은 get_text로 작성한 경우
METHOD get_text.
  ...
ENDMETHOD.
```

이런 경우 시스템은 선언되지 않은 Method를 구현했거나, 선언된 Method를 구현하지 않았다고 판단한다.

## 7. Method란 무엇인가?

### 7.1 쉬운 정의

Method는 Class 안에 정의된 처리 블록이다.

절차적 ABAP의 `FORM`과 비교하면 다음과 같다.

| 구분 | FORM | Method |
|---|---|---|
| 소속 | Report 또는 Include 중심 | Class 내부 |
| 호출 방식 | `PERFORM form_name` | `object->method( )` 또는 `class=>method( )` |
| 데이터 결합 | 전역 변수 의존이 쉬움 | Attribute와 함께 구조화 가능 |
| 객체지향 확장 | 제한적 | OO ABAP의 기본 단위 |
| 현대적 권장 방향 | Legacy 코드에서 여전히 존재 | 신규 구조화 코드에서 중요 |

Method는 단순히 FORM의 새 문법이 아니다.  
Method는 Class라는 구조 안에 포함되어 객체의 책임을 표현하는 단위이다.

### 7.2 Method 파라미터

초급 단계에서는 다음 세 가지를 먼저 이해하면 된다.

| 파라미터 | 의미 |
|---|---|
| `IMPORTING` | 호출자가 Method에 입력값을 넘김 |
| `EXPORTING` | Method가 호출자에게 출력값을 넘김 |
| `RETURNING` | Method가 하나의 결과값을 함수처럼 반환 |

이번 모듈에서는 초급자에게 가장 직관적인 `IMPORTING + RETURNING` 패턴을 중심으로 학습한다.

## 8. Instance Method 호출

### 8.1 Instance Method란?

Instance Method는 객체 인스턴스를 생성한 뒤 호출하는 Method이다.

흐름은 다음과 같다.

```text
Class Type을 기준으로 참조 변수 선언
→ 객체 생성
→ 참조 변수를 통해 Method 호출
```

### 8.2 CREATE OBJECT 방식

Classic ABAP에서 자주 보는 방식이다.

```abap
DATA lo_helper TYPE REF TO lcl_status_helper.
CREATE OBJECT lo_helper.

DATA(lv_text) = lo_helper->get_status_text( iv_status = 'A' ).
```

여기서 중요한 문법은 `->`이다.

```text
lo_helper->get_status_text( )
```

`->`는 객체 참조 변수를 통해 Instance Method나 Instance Attribute에 접근할 때 사용한다.

### 8.3 NEW 방식

Modern ABAP 문법에서는 다음처럼 쓸 수도 있다.

```abap
DATA(lo_helper) = NEW lcl_status_helper( ).

DATA(lv_text) = lo_helper->get_status_text( iv_status = 'A' ).
```

이번 과정은 초급자가 Classic ABAP 흐름도 이해해야 하므로 `CREATE OBJECT`와 `NEW`를 함께 보여준다.  
다만 Modern ABAP 문법의 세부 규칙은 후속 Section에서 더 자세히 다룬다.

## 9. Static Method 호출

### 9.1 Static Method란?

Static Method는 객체를 생성하지 않고 클래스 이름으로 직접 호출할 수 있는 Method이다.

```abap
CLASS lcl_math DEFINITION.
  PUBLIC SECTION.
    CLASS-METHODS add
      IMPORTING iv_a TYPE i
                iv_b TYPE i
      RETURNING VALUE(rv_result) TYPE i.
ENDCLASS.

CLASS lcl_math IMPLEMENTATION.
  METHOD add.
    rv_result = iv_a + iv_b.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lv_result) = lcl_math=>add(
    iv_a = 10
    iv_b = 20 ).

  WRITE: / lv_result.
```

여기서 중요한 문법은 `=>`이다.

```text
lcl_math=>add( )
```

`=>`는 클래스 이름을 통해 Static Method나 Static Attribute에 접근할 때 사용한다.

### 9.2 Instance Method와 Static Method 비교

| 구분 | Instance Method | Static Method |
|---|---|---|
| 선언 | `METHODS` | `CLASS-METHODS` |
| 호출 전 객체 생성 | 필요 | 불필요 |
| 호출 연산자 | `->` | `=>` |
| 상태 보관 | 객체 Attribute와 연결 가능 | 클래스 수준 처리 중심 |
| 예시 | 사용자 객체의 상태 변경 | 단순 계산, 변환, 유틸리티 |

초급자는 다음처럼 기억하면 된다.

```text
객체를 만들어서 호출하면 ->
클래스 이름으로 바로 호출하면 =>
```

## 10. Local Class 작성 위치

ABAP Report에서 Local Class는 보통 실행 블록보다 앞에 정의한다.

권장 흐름은 다음과 같다.

```abap
REPORT z_example.

CLASS lcl_demo DEFINITION.
  ...
ENDCLASS.

CLASS lcl_demo IMPLEMENTATION.
  ...
ENDCLASS.

START-OF-SELECTION.
  ...
```

초급자는 일단 다음 순서를 지키는 것이 좋다.

```text
1. REPORT 선언
2. Local Class DEFINITION
3. Local Class IMPLEMENTATION
4. START-OF-SELECTION 또는 실행 로직
```

[추정] 시스템 설정, Include 구조, 개발 스타일에 따라 Local Class 위치는 다양하게 구성될 수 있지만, 초급 교육에서는 위 순서가 가장 읽기 쉽고 오류를 줄이기 좋다.

## 11. 전체 최소 예제 1 — 상태 텍스트 변환

다음 예제는 상태 코드 `A`, `I`, `B`를 사람이 읽을 수 있는 텍스트로 변환한다.

```abap
REPORT zjhy_local_class_01.

CLASS lcl_status_helper DEFINITION.
  PUBLIC SECTION.
    METHODS get_status_text
      IMPORTING iv_status TYPE c LENGTH 1
      RETURNING VALUE(rv_text) TYPE string.
ENDCLASS.

CLASS lcl_status_helper IMPLEMENTATION.
  METHOD get_status_text.
    CASE iv_status.
      WHEN 'A'.
        rv_text = 'Active'.
      WHEN 'I'.
        rv_text = 'Inactive'.
      WHEN 'B'.
        rv_text = 'Blocked'.
      WHEN OTHERS.
        rv_text = 'Unknown'.
    ENDCASE.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA lo_helper TYPE REF TO lcl_status_helper.
  DATA lv_text   TYPE string.

  CREATE OBJECT lo_helper.

  lv_text = lo_helper->get_status_text( iv_status = 'A' ).

  WRITE: / 'Status Text:', lv_text.
```

### 11.1 실행 흐름

```text
프로그램 실행
→ START-OF-SELECTION 진입
→ lo_helper 참조 변수 선언
→ CREATE OBJECT로 객체 생성
→ lo_helper->get_status_text( ) 호출
→ CASE 분기 실행
→ rv_text 반환
→ WRITE 출력
```

### 11.2 출력 예시

```text
Status Text: Active
```

## 12. 전체 최소 예제 2 — Static Method 계산

단순 계산이나 변환처럼 객체 상태가 필요 없는 경우 Static Method를 사용할 수 있다.

```abap
REPORT zjhy_local_class_02.

CLASS lcl_math DEFINITION.
  PUBLIC SECTION.
    CLASS-METHODS add
      IMPORTING iv_a TYPE i
                iv_b TYPE i
      RETURNING VALUE(rv_result) TYPE i.
ENDCLASS.

CLASS lcl_math IMPLEMENTATION.
  METHOD add.
    rv_result = iv_a + iv_b.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lv_result) = lcl_math=>add(
    iv_a = 10
    iv_b = 20 ).

  WRITE: / 'Result:', lv_result.
```

### 12.1 실행 흐름

```text
프로그램 실행
→ START-OF-SELECTION 진입
→ lcl_math=>add( ) 호출
→ Method 내부에서 덧셈 수행
→ 결과 반환
→ WRITE 출력
```

### 12.2 출력 예시

```text
Result: 30
```

## 13. Instance Attribute 기초

Class는 Method만 가질 수 있는 것이 아니라 Attribute도 가질 수 있다.  
Attribute는 클래스나 객체가 보유하는 데이터이다.

```abap
CLASS lcl_counter DEFINITION.
  PUBLIC SECTION.
    METHODS increase.
    METHODS get_count RETURNING VALUE(rv_count) TYPE i.

  PRIVATE SECTION.
    DATA mv_count TYPE i.
ENDCLASS.

CLASS lcl_counter IMPLEMENTATION.
  METHOD increase.
    mv_count = mv_count + 1.
  ENDMETHOD.

  METHOD get_count.
    rv_count = mv_count.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lo_counter) = NEW lcl_counter( ).

  lo_counter->increase( ).
  lo_counter->increase( ).

  WRITE: / lo_counter->get_count( ).
```

이 예제에서 `mv_count`는 객체 내부에서 유지되는 값이다.

### 13.1 PRIVATE SECTION의 의미

`PRIVATE SECTION`에 선언한 Attribute는 클래스 외부에서 직접 접근할 수 없다.

```abap
PRIVATE SECTION.
  DATA mv_count TYPE i.
```

외부에서는 Method를 통해 접근해야 한다.

```abap
lo_counter->increase( ).
lo_counter->get_count( ).
```

초급자는 여기서 객체지향의 중요한 감각을 얻을 수 있다.

```text
데이터를 아무 곳에서나 직접 바꾸지 않고,
정해진 Method를 통해 다루도록 구조화한다.
```

## 14. Visibility Section

ABAP Class에는 Visibility Section이 있다.

| Section | 의미 | 초급자 이해 |
|---|---|---|
| PUBLIC SECTION | 외부에서 접근 가능 | 호출자가 사용할 Method를 둔다 |
| PROTECTED SECTION | 상속 관계에서 접근 가능 | 이번 모듈에서는 깊게 다루지 않음 |
| PRIVATE SECTION | 클래스 내부에서만 접근 가능 | 내부 변수와 내부 보조 Method를 둔다 |

이번 모듈에서는 `PUBLIC SECTION`과 `PRIVATE SECTION`만 기본적으로 이해하면 충분하다.

### 14.1 권장 설계 감각

| 항목 | 권장 위치 |
|---|---|
| 외부에서 호출할 Method | PUBLIC SECTION |
| 내부 상태 Attribute | PRIVATE SECTION |
| 내부 보조 Method | PRIVATE SECTION |

모든 것을 `PUBLIC SECTION`에 두면 외부에서 무분별하게 접근할 수 있어 유지보수가 어려워진다.  
초급 단계부터 “외부에 공개할 것과 내부에 숨길 것”을 구분하는 습관이 중요하다.

## 15. FORM과 Local Class 비교

### 15.1 FORM으로 작성한 예

```abap
FORM get_status_text USING    iv_status TYPE c
                     CHANGING cv_text   TYPE string.
  CASE iv_status.
    WHEN 'A'.
      cv_text = 'Active'.
    WHEN 'I'.
      cv_text = 'Inactive'.
    WHEN 'B'.
      cv_text = 'Blocked'.
    WHEN OTHERS.
      cv_text = 'Unknown'.
  ENDCASE.
ENDFORM.
```

호출:

```abap
DATA lv_text TYPE string.
PERFORM get_status_text USING 'A' CHANGING lv_text.
```

### 15.2 Local Class Method로 작성한 예

```abap
CLASS lcl_status_helper DEFINITION.
  PUBLIC SECTION.
    METHODS get_status_text
      IMPORTING iv_status TYPE c LENGTH 1
      RETURNING VALUE(rv_text) TYPE string.
ENDCLASS.
```

호출:

```abap
DATA(lo_helper) = NEW lcl_status_helper( ).
DATA(lv_text) = lo_helper->get_status_text( iv_status = 'A' ).
```

### 15.3 비교

| 관점 | FORM | Local Class Method |
|---|---|---|
| 문법 난이도 | 낮음 | 약간 높음 |
| 구조화 수준 | 절차적 분리 | 책임 단위 분리 |
| 데이터 은닉 | 약함 | `PRIVATE SECTION` 활용 가능 |
| 테스트 가능성 | 제한적 | 더 확장 가능 |
| OO ABAP 연결 | 약함 | 강함 |

초급 교육에서는 FORM도 여전히 중요하다.  
기존 고객사 ABAP 프로그램에는 FORM이 많이 존재하기 때문이다.  
다만 신규 설계와 객체지향 확장 관점에서는 Local Class와 Method를 이해해야 한다.

## 16. Function Module과 Local Class 비교

| 관점 | Function Module | Local Class |
|---|---|---|
| 위치 | Function Group / Repository | 프로그램 내부 |
| 호출 방식 | `CALL FUNCTION` | `object->method( )`, `class=>method( )` |
| 재사용 범위 | 여러 프로그램에서 재사용 가능 | 해당 프로그램 중심 |
| 인터페이스 확인 | SE37 | 코드의 CLASS DEFINITION |
| 상태 관리 | Function Group 전역 데이터 가능 | 객체 Attribute 가능 |
| 현대적 설계 연결 | BAPI/RFC 등에서 여전히 중요 | OO ABAP의 기초 |

이번 모듈은 Function Module을 대체하라는 의미가 아니다.  
각 구조가 어디에 적합한지 구분할 수 있도록 하는 것이 목표이다.

## 17. 정상 흐름과 오류 흐름

### 17.1 정상 흐름

```text
1. CLASS DEFINITION 작성
2. PUBLIC SECTION에 Method 선언
3. CLASS IMPLEMENTATION 작성
4. 선언한 Method 구현
5. START-OF-SELECTION에서 객체 생성
6. Method 호출
7. 반환값 또는 변경값 확인
8. WRITE로 결과 출력
```

### 17.2 오류 흐름 1 — Method 선언 누락

#### 상황

`CLASS IMPLEMENTATION`에 Method 구현을 작성했지만 `CLASS DEFINITION`에 선언하지 않았다.

#### 예

```abap
CLASS lcl_demo DEFINITION.
  PUBLIC SECTION.
ENDCLASS.

CLASS lcl_demo IMPLEMENTATION.
  METHOD run.
    WRITE: / 'Hello'.
  ENDMETHOD.
ENDCLASS.
```

#### 문제

`run` Method가 Definition에 선언되어 있지 않다.

#### 해결

```abap
CLASS lcl_demo DEFINITION.
  PUBLIC SECTION.
    METHODS run.
ENDCLASS.
```

### 17.3 오류 흐름 2 — 객체 생성 전 Instance Method 호출

#### 상황

참조 변수만 선언하고 객체를 생성하지 않은 상태에서 Instance Method를 호출한다.

```abap
DATA lo_helper TYPE REF TO lcl_status_helper.
DATA(lv_text) = lo_helper->get_status_text( iv_status = 'A' ).
```

#### 문제

`lo_helper`가 실제 객체를 가리키지 않는다.  
이 상태에서 Method를 호출하면 런타임 오류가 발생할 수 있다.

#### 해결

```abap
CREATE OBJECT lo_helper.
DATA(lv_text) = lo_helper->get_status_text( iv_status = 'A' ).
```

또는:

```abap
DATA(lo_helper) = NEW lcl_status_helper( ).
DATA(lv_text) = lo_helper->get_status_text( iv_status = 'A' ).
```

### 17.4 오류 흐름 3 — `->`와 `=>` 혼동

#### 상황

Static Method를 `->`로 호출하거나 Instance Method를 `=>`로 호출한다.

```abap
" 잘못된 예
DATA(lv_result) = lcl_math->add( iv_a = 1 iv_b = 2 ).
```

#### 해결

| Method 종류 | 올바른 호출 |
|---|---|
| Instance Method | `lo_object->method( )` |
| Static Method | `lcl_class=>method( )` |

### 17.5 오류 흐름 4 — 파라미터 이름 오타

#### 상황

Method 선언은 `iv_status`인데 호출 시 `iv_stat`로 입력한다.

```abap
DATA(lv_text) = lo_helper->get_status_text( iv_stat = 'A' ).
```

#### 문제

호출 구문의 실제 파라미터 이름이 Method 선언과 일치하지 않는다.

#### 해결

```abap
DATA(lv_text) = lo_helper->get_status_text( iv_status = 'A' ).
```

### 17.6 오류 흐름 5 — 반환값 타입 불일치

#### 상황

Method의 `RETURNING` 타입과 받는 변수의 기대 타입이 맞지 않는다.

```abap
DATA lv_result TYPE i.
lv_result = lo_helper->get_status_text( iv_status = 'A' ).
```

#### 문제

`get_status_text`는 문자열을 반환하는데 정수형 변수에 대입하려 한다.

#### 해결

반환값 타입에 맞는 변수를 사용한다.

```abap
DATA lv_text TYPE string.
lv_text = lo_helper->get_status_text( iv_status = 'A' ).
```

## 18. 디버깅 포인트

Local Class Method를 학습할 때는 다음 위치에 Breakpoint를 두면 좋다.

| 위치 | 확인할 내용 |
|---|---|
| `CREATE OBJECT` 다음 줄 | 참조 변수가 객체를 가리키는지 확인 |
| Method 호출 줄 | 실제 파라미터 값 확인 |
| `METHOD ...` 첫 줄 | Method 진입 여부 확인 |
| `CASE` 또는 `IF` 내부 | 분기 흐름 확인 |
| `RETURNING` 값 설정 줄 | 반환값이 채워지는지 확인 |
| 호출 후 다음 줄 | 호출자가 반환값을 받았는지 확인 |

초급자는 디버깅 중 다음 질문을 하면서 확인하면 좋다.

```text
객체가 생성되었는가?
Method에 실제로 진입했는가?
입력 파라미터 값이 예상과 같은가?
반환값이 Method 내부에서 채워졌는가?
호출자 변수에 반환값이 들어왔는가?
```

## 19. 실무 적용 기준

### 19.1 Local Class를 사용하면 좋은 경우

| 상황 | 이유 |
|---|---|
| 하나의 Report 안에 로직이 길어짐 | 책임별로 Method를 나눌 수 있다. |
| FORM이 너무 많아져 흐름이 불명확함 | Class 단위로 관련 로직을 묶을 수 있다. |
| 내부 상태를 안전하게 관리하고 싶음 | PRIVATE Attribute를 사용할 수 있다. |
| Global Class로 빼기 전 작은 설계를 검증하고 싶음 | Local Class로 빠르게 구조화 가능하다. |
| Unit Test나 OO 확장으로 이어질 가능성이 있음 | OO ABAP 학습 기반이 된다. |

### 19.2 Local Class를 남발하면 안 되는 경우

| 상황 | 이유 |
|---|---|
| 여러 프로그램에서 재사용해야 함 | Global Class가 더 적합하다. |
| 아주 짧고 일회성인 로직 | 오히려 구조가 과도해질 수 있다. |
| 표준 API나 BAPI 호출이 필요한 경우 | Function Module/BAPI 호출이 필요할 수 있다. |
| 도메인 객체 수준의 장기 재사용 설계 | Global Class, Interface 설계를 검토해야 한다. |

### 19.3 Clean ABAP 관점의 초급 원칙

이 모듈은 초급 단계이지만, 다음 원칙은 바로 적용할 수 있다.

```text
Method는 한 가지 일을 하게 만든다.
Method 이름은 동작을 설명하게 만든다.
전역 변수에 과도하게 의존하지 않는다.
외부에 공개할 필요가 없는 데이터는 PRIVATE에 둔다.
호출부에서 의미가 드러나도록 파라미터 이름을 명확히 사용한다.
```

예를 들어 `run`, `process`, `do_it` 같은 이름은 너무 넓을 수 있다.  
반면 `get_status_text`, `calculate_total`, `validate_status`는 동작이 더 명확하다.

## 20. 미니 실습

### 20.1 실습 목표

Local Class를 사용하여 상태 코드를 상태 텍스트로 변환하는 프로그램을 작성한다.

### 20.2 실습 요구사항

```text
Program Name: ZJHY_LOCAL_CLASS_STATUS
Local Class: LCL_STATUS_HELPER
Method: GET_STATUS_TEXT
Input: 상태 코드 A/I/B/기타
Output: 상태 텍스트 Active/Inactive/Blocked/Unknown
```

### 20.3 실습 코드

```abap
REPORT zjhy_local_class_status.

      WHEN 'I'.

      WHEN 'B'.
        rv_text = 'Blocked'.
      WHEN OTHERS.
        rv_text = 'Unknown'.
    ENDCASE.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lo_helper) = NEW lcl_status_helper( ).

  WRITE: / 'A:', lo_helper->get_status_text( iv_status = 'A' ),
         / 'I:', lo_helper->get_status_text( iv_status = 'I' ),
         / 'B:', lo_helper->get_status_text( iv_status = 'B' ),
         / 'X:', lo_helper->get_status_text( iv_status = 'X' ).
```

```text

I: Inactive
B: Blocked
X: Unknown
```

### 20.5 오류 케이스 기록

학습자는 일부러 다음 오류를 만들어보고 메시지를 기록한다.

| 오류 실험 | 예상 결과 |
|---|---|
| `CREATE OBJECT` 또는 `NEW` 없이 Instance Method 호출 | 참조 변수 초기 상태 관련 오류 가능 |

| `RETURNING` 타입과 받는 변수 타입 불일치 | 타입 변환 또는 문법/런타임 이슈 확인 |

## 21. 강사용 설명 포인트

### 21.1 “클래스 = 어려운 것”이라는 심리 장벽을 낮춘다

초급자에게 객체지향을 처음 설명하면 상속, 다형성, 인터페이스부터 떠올려 어렵게 느낄 수 있다.  
이번 모듈에서는 다음 메시지를 강조하는 것이 좋다.

```text
Local Class는 우선 코드를 정리하기 위한 그릇으로 이해하면 된다.
Method는 클래스 안에 들어 있는 처리 단위이다.
처음에는 FORM보다 조금 더 구조화된 방법이라고 받아들여도 충분하다.
```

### 21.2 FORM을 부정하지 않는다

기존 SAP 고객사 시스템에는 FORM 기반 Report가 많다.  
따라서 FORM을 무조건 나쁘다고 설명하기보다, 다음처럼 균형 있게 설명한다.

```text
FORM은 기존 코드 이해에 반드시 필요하다.
Local Class는 신규 구조화와 OO 확장을 위해 필요하다.
둘의 목적과 한계를 구분하는 것이 중요하다.
```

### 21.3 `->`와 `=>`를 반드시 구분시킨다

초급자 오류의 상당수는 Instance Method와 Static Method 호출 연산자 혼동에서 발생한다.

```text
객체 참조 변수로 호출하면 ->
클래스 이름으로 호출하면 =>
```

이 규칙을 예제와 함께 반복하는 것이 좋다.

### 21.4 다음 모듈과 연결한다

이번 모듈은 Local Class를 Report 안에 정의했다.  
다음 모듈에서는 Repository에 등록된 Global Class를 호출하는 기초로 넘어간다.

```text
Local Class
  → 프로그램 내부 구조화

Global Class
  → Repository 객체 기반 재사용
```

## 23. 평가 문제

### 23.1 객관식

#### Q1. Local Class에 대한 설명으로 가장 적절한 것은?

A. 반드시 SE24에서만 생성할 수 있는 Repository 객체이다.  
B. 특정 프로그램 내부에 정의하여 사용할 수 있는 클래스이다.  
C. 데이터베이스 테이블을 생성하는 DDIC 객체이다.  
D. Function Module을 그룹화하는 Function Group이다.

**정답:** B

#### Q2. Instance Method 호출에 사용하는 연산자는?

A. `=>`  
B. `->`  
C. `:=`  
D. `&&`

**정답:** B

#### Q3. Static Method 선언에 사용하는 구문은?

A. `METHODS`  
B. `CLASS-METHODS`  
C. `FORM`  
D. `CALL FUNCTION`

**정답:** B

#### Q4. `CLASS IMPLEMENTATION`의 역할은 무엇인가?

A. 테이블 필드를 정의한다.  
B. Method의 실제 처리 로직을 작성한다.  
C. Selection Screen 입력 필드를 만든다.  
D. Transport Request를 생성한다.

**정답:** B

### 23.2 단답형

#### Q1. `CLASS DEFINITION`과 `CLASS IMPLEMENTATION`의 차이를 설명하시오.

**모범 답안:**  
`CLASS DEFINITION`은 클래스의 외형, Method, Attribute, 공개 영역 등을 선언하는 부분이다. `CLASS IMPLEMENTATION`은 Definition에서 선언한 Method의 실제 처리 로직을 작성하는 부분이다.

#### Q2. `lo_helper->get_status_text( )`에서 `->`의 의미를 설명하시오.

**모범 답안:**  
`->`는 객체 참조 변수를 통해 Instance Method 또는 Instance Attribute에 접근할 때 사용하는 연산자이다. `lo_helper`가 실제 객체를 가리키고 있어야 Method를 호출할 수 있다.

#### Q3. Local Class를 사용하는 장점을 두 가지 쓰시오.

**모범 답안:**  
관련 로직을 Class와 Method 단위로 구조화할 수 있고, `PRIVATE SECTION`을 통해 내부 데이터를 외부에서 직접 변경하지 못하게 할 수 있다. 또한 OO ABAP과 Global Class 학습으로 자연스럽게 이어질 수 있다.

## 25. 핵심 요약

이번 모듈에서 반드시 기억할 내용은 다음이다.

```text
Local Class는 특정 ABAP 프로그램 내부에서 사용하는 클래스이다.
CLASS DEFINITION은 클래스의 외형을 선언한다.
CLASS IMPLEMENTATION은 Method의 실제 로직을 구현한다.
METHODS는 Instance Method를 선언한다.
CLASS-METHODS는 Static Method를 선언한다.

Static Method는 class=>method( )로 호출한다.
PUBLIC과 PRIVATE을 구분하면 코드의 책임과 접근 범위를 더 명확히 만들 수 있다.
```
