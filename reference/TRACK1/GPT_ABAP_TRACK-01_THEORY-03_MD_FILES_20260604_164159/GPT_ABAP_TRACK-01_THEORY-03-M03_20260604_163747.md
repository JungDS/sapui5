이번 모듈은 Selection Screen 학습의 아주 초기 단계이다.  
앞선 모듈에서 `PARAMETERS` 기본 선언과 `DEFAULT`, `OBLIGATORY`를 학습했다면, 이번에는 사용자가 입력한 값을 실제 Report 출력 리스트에 표시하는 흐름을 경험한다.

이 모듈에서는 다음을 다룬다.

```text
PARAMETERS로 입력 필드 선언

→ 실행 시점에 Parameter 변수에 값 전달
→ WRITE 문으로 결과 리스트 출력
→ 입력값/출력값/오류 케이스 확인
```

이 단계에서는 `SELECT-OPTIONS`, `AT SELECTION-SCREEN`, 복잡한 F4 Help, Dynamic Screen Modification은 다루지 않는다.  
이 주제들은 후속 Section에서 더 적절한 순서로 다룬다.

## 3. PARAMETERS와 WRITE의 역할

### 3.1 PARAMETERS의 역할

`PARAMETERS`는 Report 프로그램에 단일 입력 필드를 만든다.

예를 들어 다음 문장은 Selection Screen에 이름 입력 필드를 만든다.

```abap
PARAMETERS p_name TYPE c LENGTH 20.
```

이때 `p_name`은 단순히 화면 필드만 의미하지 않는다.  
프로그램 안에서는 변수처럼 사용할 수 있다.

즉, 사용자가 Selection Screen에서 `KIM`을 입력하면 프로그램 실행 시점에 `p_name` 값은 `KIM`이 된다.

### 3.2 WRITE의 역할

`WRITE`는 ABAP List 화면에 값을 출력한다.

예를 들어 다음 문장은 프로그램 결과 화면에 입력된 이름을 출력한다.

```abap
WRITE: / '입력한 이름:', p_name.
```

여기서 `/`는 새 줄 출력을 의미한다.

### 3.3 입력과 출력의 연결

이번 모듈의 핵심 흐름은 다음이다.

```text
Selection Screen
  p_name = 'KIM'
        ↓
ABAP Runtime
  p_name 변수에 값 보관
        ↓
WRITE Output List
  입력한 이름: KIM
```

## 4. 가장 작은 예제

다음은 `PARAMETERS` 입력값을 `WRITE`로 출력하는 가장 작은 수준의 예제이다.

```abap
REPORT zjhy_t03_m03_basic.

PARAMETERS p_name TYPE c LENGTH 20.

START-OF-SELECTION.
  WRITE: / '입력한 이름:', p_name.
```

이 프로그램을 실행하면 다음 흐름이 발생한다.

```text
1. 프로그램 실행
2. Selection Screen 표시
3. 사용자가 p_name에 값을 입력
4. 실행 버튼 선택
5. START-OF-SELECTION 블록 실행
6. WRITE 문으로 입력값 출력
```

---

## 5. START-OF-SELECTION은 왜 사용하는가?

ABAP Report는 여러 이벤트 블록을 가질 수 있다.  
초급 단계에서는 모든 이벤트를 깊게 다루지 않고, `START-OF-SELECTION`만 기본 흐름으로 사용한다.

```abap
START-OF-SELECTION.
  WRITE: / p_name.
```

`START-OF-SELECTION`은 사용자가 Selection Screen에서 입력을 마치고 실행했을 때 실제 주요 처리가 시작되는 대표적인 처리 블록이다.

이번 단계에서 기억할 기준은 다음이다.

```text
PARAMETERS 선언부 = 입력 필드 정의
START-OF-SELECTION = 입력 후 실행할 본 처리
WRITE = 결과 리스트 출력
```

[추정] 아주 단순한 Report에서는 `START-OF-SELECTION` 없이도 `WRITE`가 동작하는 예제를 볼 수 있다. 그러나 교육용 문서에서는 입력 선언부와 처리부를 명확히 분리하기 위해 `START-OF-SELECTION`을 사용하는 방식을 권장한다.

## 6. 실행 화면 흐름

### 6.1 프로그램 코드

```abap
REPORT zjhy_t03_m03_flow.

PARAMETERS p_carrid TYPE c LENGTH 3 DEFAULT 'AA'.

START-OF-SELECTION.
  WRITE: / '항공사 코드:', p_carrid.
```

### 6.2 실행 전 Selection Screen

사용자가 프로그램을 실행하면 다음과 같은 입력 필드가 표시된다.

```text
항공사 코드 [AA ]
```

여기서 `AA`는 `DEFAULT 'AA'` 때문에 기본으로 표시된다.

### 6.3 사용자가 값을 변경한 경우

사용자가 `LH`를 입력하고 실행하면 결과는 다음과 같다.

```text
항공사 코드: LH
```

### 6.4 핵심 포인트

입력 필드의 현재 값이 프로그램 실행 시점에 Parameter 변수 값이 된다.

```text
화면 입력값 LH
→ p_carrid = 'LH'
→ WRITE 출력 LH
```

## 8. 실습 예제 2: 숫자 입력 후 계산 결과 출력

### 8.1 요구사항

수량과 단가를 입력받아 금액을 계산한 뒤 출력한다.

### 8.2 코드

```abap
REPORT zjhy_t03_m03_calc.

PARAMETERS p_qty   TYPE i DEFAULT 1.
PARAMETERS p_price TYPE p LENGTH 8 DECIMALS 2 DEFAULT '1000.00'.

DATA gv_amount TYPE p LENGTH 10 DECIMALS 2.

START-OF-SELECTION.
  gv_amount = p_qty * p_price.

  WRITE: / '수량:', p_qty,
         / '단가:', p_price,
         / '금액:', gv_amount.
```

### 8.3 예상 결과

입력값:

```text
p_qty   = 3
p_price = 1500.00
```

출력:

```text
수량: 3
단가: 1500.00
금액: 4500.00
```

### 8.4 학습 포인트

이 예제는 단순히 입력값을 그대로 출력하는 것에서 한 단계 확장한다.  
사용자가 입력한 값을 계산에 사용한 뒤 출력한다.

```text
입력값
→ 프로그램 내부 계산
→ WRITE 결과 출력
```

초급자는 여기서 `PARAMETERS`가 단순 화면 표시용이 아니라 프로그램 로직의 입력값이라는 점을 이해해야 한다.

## 9. 실습 예제 3: 상태 코드 입력 후 설명 출력

### 9.1 요구사항

상태 코드 `A`, `I`, `B`를 입력받아 설명을 출력한다.

| 코드 | 의미 |
|---|---|
| A | Active |
| I | Inactive |
| B | Blocked |

### 9.2 코드

```abap
REPORT zjhy_t03_m03_status.

PARAMETERS p_status TYPE c LENGTH 1 DEFAULT 'A'.

START-OF-SELECTION.

  WRITE: / '입력 상태 코드:', p_status.

  IF p_status = 'A'.
    WRITE: / '상태 설명: Active'.
  ELSEIF p_status = 'I'.
    WRITE: / '상태 설명: Inactive'.
  ELSEIF p_status = 'B'.
    WRITE: / '상태 설명: Blocked'.
  ELSE.
    WRITE: / '상태 설명: 알 수 없는 코드'.
  ENDIF.
```

### 9.3 예상 결과

입력값:

```text
p_status = I
```

출력:

```text
입력 상태 코드: I
상태 설명: Inactive
```

### 9.4 학습 포인트

이 예제는 입력값에 따라 출력이 달라지는 흐름을 보여준다.

다만 이 모듈의 중심은 조건문 자체가 아니다.  
조건문은 이미 `THEORY-02`에서 학습한 내용을 사용하여 `PARAMETERS` 입력값을 처리하는 보조 수단이다.

## 10. PARAMETERS 선언 위치와 처리부 위치

ABAP Report에서는 보통 선언부와 처리부를 구분하여 작성한다.

```abap
REPORT zjhy_t03_m03_layout.

" 1. Selection Screen 입력 필드 선언
PARAMETERS p_name TYPE c LENGTH 20.

" 2. 일반 변수 선언
DATA gv_message TYPE string.

" 3. 실행 처리부
START-OF-SELECTION.
  gv_message = |Hello, { p_name }|.
  WRITE: / gv_message.
```

### 10.1 권장 구조

초급 단계에서는 다음 순서를 권장한다.

```text
REPORT 문
→ PARAMETERS 선언
→ DATA 선언
→ START-OF-SELECTION
→ 처리 로직
→ WRITE 출력
```

### 10.2 왜 구조를 나누는가?

구조를 나누면 코드 읽기가 쉬워진다.

| 영역 | 역할 |
|---|---|
| REPORT | 프로그램 이름 선언 |
| PARAMETERS | 사용자 입력 정의 |
| DATA | 내부 처리 변수 정의 |
| START-OF-SELECTION | 실행 처리 시작 |
| WRITE | 결과 출력 |

실무에서는 코드가 길어지기 때문에 처음부터 선언부와 처리부를 구분하는 습관이 중요하다.

## 11. WRITE 출력 기본 패턴

### 11.1 새 줄 출력

```abap
WRITE: / '이름:', p_name.
```

`/`는 새 줄을 의미한다.

### 11.2 여러 줄 출력

```abap
WRITE: / '입력값 확인',
       / '이름:', p_name,
       / '상태:', p_status.
```

### 11.3 빈 줄 출력

```abap
WRITE: /.
WRITE: / '다음 출력 영역'.
```

### 11.4 제목과 구분선 출력

```abap
WRITE: / '--- 입력값 확인 ---'.
WRITE: / '이름:', p_name.
WRITE: / '상태:', p_status.
```

초급 단계에서는 복잡한 List Formatting보다, 입력값을 명확히 보여주는 단순한 출력 형식을 우선한다.

## 12. 문자형 입력값 출력 시 주의점

### 12.1 길이 제한

```abap
PARAMETERS p_name TYPE c LENGTH 10.
```

이 경우 10자리까지만 안정적으로 저장된다.  
너무 긴 값을 입력하면 필드 길이 제한에 따라 잘리거나 입력 자체가 제한될 수 있다.

초급자는 다음을 기억한다.

```text
PARAMETERS의 TYPE과 LENGTH는 화면 입력 가능 길이와 프로그램 내부 값 크기에 영향을 준다.
```

### 12.2 대소문자

문자형 Parameter는 타입, 화면 속성, 도메인 설정에 따라 대소문자 처리 방식이 달라질 수 있다.

예를 들어 코드성 값은 대문자 중심으로 처리하는 것이 일반적이다.

```abap
PARAMETERS p_code TYPE c LENGTH 3 DEFAULT 'ABC'.
```

[추정] 시스템 설정 또는 참조한 DDIC 타입의 Lowercase 설정에 따라 입력값의 대소문자 처리 체감이 달라질 수 있으므로, 교육 실습에서는 코드값을 대문자로 입력하는 방식을 권장한다.

---

## 13. 숫자형 입력값 출력 시 주의점

숫자형 Parameter는 문자형과 다르게 입력값의 형식이 맞지 않으면 오류가 발생할 수 있다.

```abap
PARAMETERS p_count TYPE i.
```

여기에 문자를 입력하면 숫자 타입에 맞지 않는 입력이므로 오류가 발생한다.

### 13.1 실습 오류 케이스

입력값:

```text
p_count = ABC
```

예상:

```text
숫자 필드에 문자 입력으로 인한 오류 또는 입력 거부
```

### 13.2 해결

숫자 필드에는 숫자만 입력한다.

```text
p_count = 10
```

초급자는 타입이 단순 문법이 아니라 사용자 입력 검증과도 연결된다는 점을 이해해야 한다.

---

## 14. 빈 값 입력과 OBLIGATORY

`OBLIGATORY`가 없는 Parameter는 공백으로 실행될 수 있다.

```abap
PARAMETERS p_name TYPE c LENGTH 20.

START-OF-SELECTION.
  WRITE: / '이름:', p_name.
```

이 경우 사용자가 아무것도 입력하지 않으면 결과는 다음처럼 의미가 부족할 수 있다.

```text
이름:
```

반면 다음처럼 작성하면 공백 실행을 방지할 수 있다.

```abap
PARAMETERS p_name TYPE c LENGTH 20 OBLIGATORY.
```

이번 모듈의 핵심은 출력이지만, 입력값이 비어 있을 때 출력 결과가 어떻게 달라지는지도 반드시 확인해야 한다.

## 15. DDIC 타입과 PARAMETERS

`PARAMETERS`는 ABAP 기본 타입뿐 아니라 DDIC Data Element를 참조할 수 있다.

예를 들어 앞선 DDIC 모듈에서 사용자 상태 Data Element를 만들었다고 가정한다.

```abap
PARAMETERS p_status TYPE zde_jhy_status.
```

이 방식의 장점은 다음과 같다.

| 장점 | 설명 |
|---|---|
| 의미 재사용 | Data Element의 업무 의미를 입력 필드에 연결 |
| 기술 속성 재사용 | Domain의 타입/길이를 함께 사용 |
| 라벨 활용 | Selection Screen에서 DDIC 기반 텍스트 활용 가능 |
| 검증 연결 가능성 | Domain Fixed Value 등과 연계 가능 |

다만 이번 모듈에서는 DDIC 심화 검증보다 “입력값을 받아 출력한다”는 기본 흐름을 우선한다.

---

## 16. 실무 관점: 입력값 Echo 출력의 의미

초급 실습에서는 입력값을 그대로 출력하는 예제가 단순해 보일 수 있다.  
하지만 실무적으로는 매우 중요한 디버깅 습관과 연결된다.

### 16.1 입력값 확인 출력

프로그램 개발 초기에 Selection Screen 입력값이 의도대로 전달되는지 확인하기 위해 다음과 같은 출력 또는 디버깅을 사용할 수 있다.

```abap
WRITE: / '입력 회사코드:', p_bukrs,
       / '입력 기준일:', p_date.
```

### 16.2 왜 필요한가?

| 이유 | 설명 |
|---|---|
| 입력값 검증 | 사용자가 어떤 값을 입력했는지 확인 |
| 디버깅 전 단계 | 간단한 출력으로 흐름 확인 |
| 테스트 기록 | 실습에서 입력/출력 결과를 남기기 쉬움 |
| 후속 SQL 연결 | WHERE 조건에 들어갈 값 확인 가능 |

후속 Open SQL 학습에서는 Parameter 입력값이 `WHERE` 조건에 사용된다.

```abap
SELECT ...
  FROM ...
  WHERE carrid = @p_carrid.
```

따라서 지금 단계에서 입력값을 정확히 출력하는 습관이 중요하다.

---

## 17. 표준 동작 흐름 정리

PARAMETERS 입력값을 WRITE로 출력하는 표준 흐름은 다음과 같이 정리할 수 있다.

```text
1. 개발자가 PARAMETERS를 선언한다.
2. ABAP Runtime이 Selection Screen을 생성한다.
3. 사용자가 값을 입력한다.
4. 사용자가 Execute를 누른다.
5. Runtime이 입력값을 Parameter 변수에 전달한다.
6. START-OF-SELECTION 처리 블록이 실행된다.
7. WRITE 문이 ABAP List에 값을 출력한다.
```

이 흐름은 아주 기본적이지만, 이후 거의 모든 Report 프로그램의 출발점이 된다.

## 18. 오류 상황과 점검 방법

### 18.1 입력값이 출력되지 않음

| 항목 | 내용 |
|---|---|
| 증상 | 실행했는데 입력값이 보이지 않음 |
| 가능한 원인 | `WRITE` 문에서 다른 변수명을 사용 |
| 해결 | Parameter 이름과 출력 변수명이 같은지 확인 |

예:

```abap
PARAMETERS p_name TYPE c LENGTH 20.

START-OF-SELECTION.
  WRITE: / p_nam. "오타
```

### 18.2 프로그램이 Syntax Error 발생

| 항목 | 내용 |
|---|---|
| 증상 | Activate 또는 Syntax Check 실패 |
| 가능한 원인 | 마침표 누락, 변수명 오타, 타입 선언 오류 |
| 해결 | 에러 메시지 더블클릭 후 해당 라인 수정 |

ABAP 문장은 마침표(`.`)로 끝난다.

```abap
WRITE: / '이름:', p_name.
```

### 18.3 숫자 필드에 문자 입력

| 항목 | 내용 |
|---|---|
| 증상 | 입력 화면에서 오류 발생 또는 실행 불가 |
| 원인 | 숫자 타입 Parameter에 문자 입력 |
| 해결 | 입력 타입에 맞는 값 입력 또는 타입 설계 변경 |

### 18.4 공백 값 출력

| 항목 | 내용 |
|---|---|
| 증상 | 결과 화면에 값이 비어 있음 |
| 원인 | 사용자가 아무것도 입력하지 않음 |
| 해결 | `OBLIGATORY` 사용 또는 기본값 설정 |

### 18.5 너무 긴 값 입력

| 항목 | 내용 |
|---|---|
| 증상 | 입력값이 잘리거나 제한됨 |
| 원인 | Parameter 길이가 부족 |
| 해결 | 적절한 LENGTH 또는 DDIC 타입 사용 |

## 19. 실습 과제

### 19.1 기본 과제

다음 요구사항을 만족하는 Report를 작성한다.

```text
프로그램명: ZJHY_T03_M03_EX01
입력값:
  p_name   이름, 문자 20자리, 필수
  p_status 상태, 문자 1자리, 기본값 A

출력값:
  입력한 이름
  입력한 상태 코드
```

예상 코드:

```abap
REPORT zjhy_t03_m03_ex01.

PARAMETERS p_name   TYPE c LENGTH 20 OBLIGATORY.
PARAMETERS p_status TYPE c LENGTH 1 DEFAULT 'A'.

START-OF-SELECTION.
  WRITE: / '--- 입력값 확인 ---',
         / '이름:', p_name,
         / '상태:', p_status.
```

### 19.2 확장 과제

상태 코드에 따라 설명을 함께 출력한다.

```abap
REPORT zjhy_t03_m03_ex02.

PARAMETERS p_name   TYPE c LENGTH 20 OBLIGATORY.
PARAMETERS p_status TYPE c LENGTH 1 DEFAULT 'A'.

START-OF-SELECTION.
  WRITE: / '--- 입력값 확인 ---',
         / '이름:', p_name,
         / '상태 코드:', p_status.

  IF p_status = 'A'.
    WRITE: / '상태 설명: Active'.
  ELSEIF p_status = 'I'.
    WRITE: / '상태 설명: Inactive'.
  ELSEIF p_status = 'B'.
    WRITE: / '상태 설명: Blocked'.
  ELSE.
    WRITE: / '상태 설명: 알 수 없는 코드'.
  ENDIF.
```

### 19.3 오류 케이스 과제

다음 오류를 일부러 만들어 보고 원인을 기록한다.

| 오류 케이스 | 예상 원인 | 해결 방법 |
|---|---|---|
| `WRITE` 문 마침표 제거 | ABAP 문장 종료 누락 | 마침표 추가 |
| `p_name` 대신 `p_nam` 출력 | 변수명 오타 | 선언된 이름으로 수정 |
| 숫자 Parameter에 문자 입력 | 타입 불일치 | 숫자 입력 또는 타입 변경 |
| `OBLIGATORY` 제거 후 공백 실행 | 필수 입력 검증 없음 | `OBLIGATORY` 사용 |

## 22. 평가 문제

### 22.1 객관식

#### Q1. `PARAMETERS`의 역할로 가장 적절한 것은?

A. 결과 리스트에 값을 출력한다.  
B. Selection Screen에 입력 필드를 만든다.  
C. 데이터베이스 테이블을 생성한다.  
D. 프로그램을 백그라운드로 실행한다.

**정답:** B

#### Q2. `WRITE` 문의 역할로 가장 적절한 것은?

A. 사용자의 입력값을 강제로 검증한다.  
B. ABAP List 화면에 값을 출력한다.  
C. Data Element를 생성한다.  
D. Selection Screen 블록을 만든다.

**정답:** B

#### Q3. 사용자가 Selection Screen에서 입력을 마치고 실행했을 때 주요 처리 로직을 배치하기에 적절한 블록은?

A. `START-OF-SELECTION`  
B. `ENDCASE`  
C. `ENDDO`  
D. `TABLES`

**정답:** A

### 22.2 단답형

#### Q1. 다음 코드의 출력 결과를 쓰시오.

```abap
REPORT ztest.

PARAMETERS p_text TYPE c LENGTH 10 DEFAULT 'SAP'.

START-OF-SELECTION.
  WRITE: / '입력:', p_text.
```

사용자가 값을 변경하지 않고 실행했다고 가정한다.

**모범 답안:**  

```text
입력: SAP
```

#### Q2. `WRITE: / '이름:', p_name.`에서 `/`의 의미는 무엇인가?

**모범 답안:**  
새 줄에 출력하라는 의미이다.

#### Q3. `PARAMETERS` 입력값을 출력하는 실습이 후속 Open SQL 학습과 연결되는 이유는 무엇인가?

**모범 답안:**  
후속 Open SQL에서는 사용자가 입력한 Parameter 값이 `WHERE` 조건 등 조회 조건으로 사용된다. 따라서 입력값이 프로그램에 제대로 전달되는지 확인하고 출력하는 흐름을 이해해야 한다.

## 23. 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
PARAMETERS는 사용자 입력 필드를 만든다.
사용자가 입력한 값은 프로그램 변수처럼 사용할 수 있다.
WRITE는 ABAP List 화면에 값을 출력한다.
START-OF-SELECTION은 Selection Screen 입력 후 주요 처리 로직을 실행하는 대표 블록이다.
입력값을 출력해보는 것은 Report 프로그램의 기본 검증 방법이다.
```

초급자는 이번 모듈을 통해 다음 구조를 자연스럽게 읽을 수 있어야 한다.

```abap
REPORT zexample.

PARAMETERS p_value TYPE c LENGTH 20.

START-OF-SELECTION.
  WRITE: / p_value.
```

## 24. 다음 모듈 연결

다음 모듈은 `THEORY-03-M04 — Selection Screen Block 기초 맛보기`이다.

이번 모듈에서는 단일 또는 여러 Parameter 입력값을 받아 출력했다.  
다음 모듈에서는 입력 필드를 화면상에서 더 보기 좋게 묶는 기초 방법을 학습한다.

연결 흐름은 다음과 같다.

```text
THEORY-03-M01 PARAMETERS 기본 선언
 → THEORY-03-M02 DEFAULT / OBLIGATORY 사용
 → THEORY-03-M03 PARAMETER 입력값을 WRITE로 출력
 → THEORY-03-M04 Selection Screen Block 기초 맛보기
```

중요한 점은 다음 모듈에서도 여전히 복잡한 Selection Screen 이벤트는 다루지 않는다는 것이다.  
이번 Section의 목적은 “초급자가 단일 입력값을 받아 출력하는 흐름을 경험하는 것”이다.
