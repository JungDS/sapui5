## 3. 문자열이란 무엇인가?

문자열은 프로그램에서 문자 데이터를 표현하는 값이다.

ABAP에서는 초급 단계에서 다음 두 가지 문자 타입을 자주 만난다.

| 타입 | 성격 | 예시 |
|---|---|---|
| `c` | 고정 길이 문자 타입 | `TYPE c LENGTH 10` |
| `string` | 가변 길이 문자열 타입 | `TYPE string` |

### 3.1 고정 길이 문자 타입 `c`

`TYPE c LENGTH n`은 길이가 정해진 문자 타입이다.

```abap
DATA gv_code TYPE c LENGTH 5.

gv_code = 'AB'.
WRITE: / gv_code.
```

`gv_code`는 길이가 5인 문자 필드이다. 값은 `AB`이지만 내부적으로는 남는 길이에 공백이 포함될 수 있다.

초급자는 다음을 기억한다.

```text
TYPE c LENGTH n은 정해진 길이를 가진 문자 필드이다.
짧은 값을 넣으면 남는 부분은 공백처럼 취급될 수 있다.
```

### 3.2 가변 길이 문자열 타입 `string`

`TYPE string`은 길이가 고정되지 않은 문자열 타입이다.

```abap
DATA gv_text TYPE string.

gv_text = 'Hello ABAP'.
WRITE: / gv_text.
```

`string`은 설명문, 메시지, 조합된 텍스트처럼 길이가 유동적인 값에 편리하다.

---

## 4. `c`와 `string`의 차이

초급 과정에서는 다음 비교표를 기준으로 이해한다.

| 구분 | `c` | `string` |
|---|---|---|
| 길이 | 고정 길이 | 가변 길이 |
| 선언 | `TYPE c LENGTH 10` | `TYPE string` |
| 공백 처리 | 남는 길이에 공백 영향 가능 | 실제 문자열 길이 중심 |
| DDIC 필드와의 친화성 | 높음 | 용도에 따라 사용 |
| 초급 사용 예 | 코드, 상태값, 고정 필드 | 메시지, 설명문, 결합 문자열 |

예를 들어 상태 코드처럼 길이가 명확한 값은 `c LENGTH 1`이 적합할 수 있다.

```abap
DATA gv_status TYPE c LENGTH 1 VALUE 'A'.
```

반대로 사용자에게 출력할 메시지는 `string`이 편리하다.

```abap
DATA gv_message TYPE string.

gv_message = '사용자 상태가 정상입니다.'.
```

## 5. 문자열 값 할당과 출력

### 5.1 기본 값 할당

```abap
REPORT zjhy_string_basic_01.

DATA gv_name TYPE string.
DATA gv_role TYPE c LENGTH 10.

gv_name = 'Kim Developer'.
gv_role = 'ABAP'.

WRITE: / 'Name:', gv_name,
       / 'Role:', gv_role.
```

이 예제는 문자열과 고정 길이 문자 필드를 각각 선언하고 출력한다.

### 5.2 VALUE를 이용한 초기값 선언

변수를 선언하면서 초기값을 줄 수도 있다.

```abap
REPORT zjhy_string_basic_02.

DATA gv_name TYPE string VALUE 'Kim Developer'.
DATA gv_status TYPE c LENGTH 1 VALUE 'A'.

WRITE: / 'Name  :', gv_name,
       / 'Status:', gv_status.
```

초급자는 `DATA` 선언 시 `VALUE`를 사용하면 프로그램 시작 시점의 기본값을 줄 수 있다는 점을 이해하면 된다.

## 6. 문자열 연결

여러 문자값을 하나의 출력 문장으로 만들고 싶을 때 문자열 연결이 필요하다.

### 6.1 `CONCATENATE` 기본

Classic ABAP에서 오래전부터 사용해온 문자열 연결 구문은 `CONCATENATE`이다.

```abap
REPORT zjhy_concat_01.

DATA gv_first TYPE string VALUE 'Hello'.
DATA gv_second TYPE string VALUE 'ABAP'.
DATA gv_result TYPE string.

CONCATENATE gv_first gv_second INTO gv_result SEPARATED BY space.

WRITE: / gv_result.
```

출력 예시는 다음과 같다.

```text
Hello ABAP
```

### 6.2 공백 없이 연결

```abap
CONCATENATE gv_first gv_second INTO gv_result.
```

이 경우 공백 없이 붙을 수 있다.

```text
HelloABAP
```

초급자는 문자열 연결 시 `SEPARATED BY space` 여부를 의식해야 한다.

### 6.3 문자열 템플릿 맛보기

최신 ABAP 문법에서는 문자열 템플릿을 사용할 수 있다.

```abap
DATA gv_name TYPE string VALUE 'Kim'.
DATA gv_text TYPE string.

gv_text = |Hello { gv_name }|.

WRITE: / gv_text.
```

다만 이 모듈은 Classic 기본 문법 흐름이므로 문자열 템플릿은 “이런 방식도 있다”는 맛보기 수준으로만 다룬다.  
Modern ABAP Syntax Section에서 더 체계적으로 학습한다.

## 7. 문자열 길이와 공백 주의

문자 타입을 사용할 때 초급자가 자주 만나는 문제는 공백과 길이이다.

```abap
REPORT zjhy_string_space_01.

DATA gv_code TYPE c LENGTH 5 VALUE 'AB'.
DATA gv_text TYPE string.

CONCATENATE '[' gv_code ']' INTO gv_text.

WRITE: / gv_text.
```

고정 길이 문자 필드의 남는 공백 때문에 기대와 다른 결과가 나올 수 있다.

초급 단계에서는 다음 원칙을 기억한다.

| 상황 | 권장 판단 |
|---|---|
| 코드, 상태, 고정 자리 값 | `TYPE c LENGTH n` 또는 DDIC 타입 |
| 설명, 메시지, 조합 텍스트 | `TYPE string` |
| 공백이 결과에 영향을 주는 경우 | 출력 전 공백 처리 확인 |

문자열 공백 제거 함수와 세부 문자열 함수는 후속 Modern ABAP 또는 문자열 심화에서 더 깊게 다룬다.

## 8. 날짜 기초: `sy-datum`

### 8.1 `sy-datum`이란?

`sy-datum`은 현재 ABAP 프로그램 실행 시점의 시스템 날짜를 나타내는 시스템 필드이다.

```abap
REPORT zjhy_date_basic_01.

WRITE: / 'Today:', sy-datum.
```

일반적으로 내부 값은 `YYYYMMDD` 형태로 이해할 수 있다.

예:

```text
20260604
```

화면 표시 형식은 사용자 설정, 시스템 설정, 출력 방식에 따라 다르게 보일 수 있다.

### 8.2 날짜를 변수에 담기

```abap
REPORT zjhy_date_basic_02.

DATA gv_today TYPE d.

gv_today = sy-datum.

WRITE: / 'System Date:', gv_today.
```

`TYPE d`는 ABAP 날짜 타입이다.

초급자는 다음을 기억한다.

```text
날짜는 단순 문자열처럼 보이지만, ABAP에는 날짜 타입 d가 있다.
sy-datum은 현재 시스템 날짜를 담고 있다.
```

### 8.3 날짜 계산 맛보기

ABAP 날짜 타입은 간단한 일수 계산이 가능하다.

```abap
REPORT zjhy_date_basic_03.

DATA gv_today    TYPE d.
DATA gv_tomorrow TYPE d.

gv_today = sy-datum.
gv_tomorrow = gv_today + 1.

WRITE: / 'Today   :', gv_today,
       / 'Tomorrow:', gv_tomorrow.
```

이 예제는 “날짜 + 1”이 다음 날을 의미한다는 감각을 주기 위한 최소 예제이다.  
월말, 연말, 공장 달력, 영업일 계산 같은 실무 날짜 계산은 훨씬 복잡하며 후속 과정에서 다룬다.

## 9. 현재 사용자: `sy-uname`

### 9.1 `sy-uname`이란?

`sy-uname`은 현재 ABAP 프로그램을 실행한 SAP 사용자 ID를 나타내는 시스템 필드이다.

```abap
REPORT zjhy_uname_basic_01.

WRITE: / 'Current User:', sy-uname.
```

예를 들어 사용자가 `JHY`라는 SAP 사용자로 로그인했다면 다음처럼 출력될 수 있다.

```text
Current User: JHY
```

### 9.2 생성자 필드에 사용하는 예

업무 테이블에는 `CREATED_BY`, `CHANGED_BY` 같은 필드가 자주 있다. 이때 `sy-uname`은 생성자 또는 변경자 기본값으로 사용될 수 있다.

```abap
REPORT zjhy_uname_basic_02.

DATA gv_created_by TYPE syuname.

gv_created_by = sy-uname.

WRITE: / 'Created By:', gv_created_by.
```

초급자는 다음을 기억한다.

```text
sy-uname은 현재 로그인 사용자 ID이다.
생성자/변경자 기록의 기본 재료로 자주 사용된다.
```

다만 실제 업무 프로그램에서는 단순히 `sy-uname`만 저장하는 것으로 충분하지 않을 수 있다.  
생성일, 생성시간, 변경일, 변경시간, 권한, 로그 정책 등과 함께 고려해야 한다.

## 10. 처리 결과: `sy-subrc`

### 10.1 `sy-subrc`란?

`sy-subrc`는 많은 ABAP 문장이 실행된 뒤 처리 결과를 숫자로 알려주는 시스템 필드이다.

가장 기본적인 해석은 다음과 같다.

| 값 | 초급자 해석 |
|---:|---|
| 0 | 성공 또는 조건에 맞는 결과 있음 |
| 4 | 실패, 찾지 못함, 조건에 맞는 결과 없음 등 |
| 기타 값 | 문장에 따라 다른 의미 가능 |

중요한 점은 `sy-subrc`의 의미가 **직전 실행 문장에 따라 달라진다**는 것이다.  
따라서 모든 상황에서 `0 = 성공`, `4 = 실패`라고만 외우면 위험하다. 초급 단계에서는 “문장별로 의미를 확인해야 한다”는 태도가 중요하다.

### 10.2 `sy-subrc` 확인 패턴

```abap
IF sy-subrc = 0.
  WRITE: / '처리 성공'.
ELSE.
  WRITE: / '처리 실패 또는 데이터 없음'.
ENDIF.
```

이 패턴은 ABAP에서 매우 자주 등장한다.  
특히 데이터 조회, 테이블 읽기, 검색, 메시지 처리 등에서 후속 로직을 제어하는 데 사용된다.

---

## 11. `sy-subrc`는 즉시 확인해야 한다

`sy-subrc`에서 가장 중요한 실무 주의점은 다음이다.

```text
sy-subrc는 직전 ABAP 문장의 결과이다.
중간에 다른 문장을 실행하면 값이 바뀔 수 있다.
```

예를 들어 다음 코드는 위험한 습관을 보여준다.

```abap
READ TABLE lt_user INTO ls_user WITH KEY user_id = 'U0001'.

WRITE: / 'Read completed'.

IF sy-subrc = 0.
  WRITE: / 'User found'.
ENDIF.
```

이 예제는 초급 설명용이다. `WRITE`가 항상 `sy-subrc`를 바꾼다고 단정하려는 목적은 아니다.  
핵심은 `READ TABLE` 결과를 확인하려면 그 직후에 확인하는 습관이 필요하다는 점이다.

더 좋은 패턴은 다음이다.

```abap
READ TABLE lt_user INTO ls_user WITH KEY user_id = 'U0001'.

IF sy-subrc = 0.
  WRITE: / 'User found'.
ELSE.
  WRITE: / 'User not found'.
ENDIF.
```

## 12. `sy-subrc`를 활용한 미니 예제

Internal Table의 상세 학습은 후속 Section에서 다루지만, `sy-subrc`를 이해하기 위한 최소 예제를 확인한다.

```abap
REPORT zjhy_subrc_basic_01.

TYPES: BEGIN OF ty_user,
         user_id   TYPE c LENGTH 5,
         user_name TYPE string,
       END OF ty_user.

DATA lt_user TYPE STANDARD TABLE OF ty_user.
DATA ls_user TYPE ty_user.

ls_user-user_id = 'U0001'.
ls_user-user_name = 'Kim'.
APPEND ls_user TO lt_user.

CLEAR ls_user.

READ TABLE lt_user INTO ls_user WITH KEY user_id = 'U0001'.

IF sy-subrc = 0.
  WRITE: / 'Found:', ls_user-user_id, ls_user-user_name.
ELSE.
  WRITE: / 'Not found'.
ENDIF.
```

이 예제의 핵심은 Internal Table 문법 전체가 아니라 다음이다.

```text
READ TABLE을 수행한다.
그 직후 sy-subrc를 확인한다.
0이면 찾은 경우, 아니면 찾지 못한 경우로 분기한다.
```

Internal Table은 `THEORY-06` 이후에서 더 체계적으로 학습한다.

## 13. 문자열, 날짜, 시스템 필드를 함께 사용하는 예제

이번 모듈의 핵심 요소를 한 번에 묶으면 다음과 같다.

```abap
REPORT zjhy_system_fields_01.

DATA gv_user    TYPE syuname.
DATA gv_today   TYPE d.
DATA gv_message TYPE string.

gv_user  = sy-uname.
gv_today = sy-datum.

CONCATENATE 'User' gv_user 'executed this report on' gv_today
       INTO gv_message
       SEPARATED BY space.

WRITE: / gv_message.
```

이 프로그램은 다음을 수행한다.

| 단계 | 설명 |
|---:|---|
| 1 | 현재 사용자 ID를 `sy-uname`에서 읽는다. |
| 2 | 현재 날짜를 `sy-datum`에서 읽는다. |
| 3 | 문자열을 조합한다. |
| 4 | 결과 메시지를 출력한다. |

## 14. 정상 흐름과 오류 흐름

### 14.1 정상 흐름

```text
DATA로 변수 선언
→ 문자열 또는 시스템 필드 값 할당
→ WRITE로 출력
→ 처리 결과가 필요한 문장 직후 sy-subrc 확인
→ IF/ELSE로 후속 처리 분기
```

### 14.2 오류 흐름 1: 문자열 길이 부족

#### 상황

```abap
DATA gv_name TYPE c LENGTH 5.

gv_name = 'ABCDEFG'.
WRITE: / gv_name.
```

#### 문제

고정 길이 문자 필드에 길이보다 긴 값을 넣으면 값이 잘리거나 기대와 다른 결과가 나올 수 있다.

#### 해결

- 고정 길이 필드가 필요한지 검토한다.
- 설명문이나 긴 메시지는 `TYPE string`을 사용한다.
- DDIC 필드 길이를 기준으로 변수를 선언한다.

### 14.3 오류 흐름 2: `sy-subrc`를 늦게 확인

#### 상황

처리 결과를 확인해야 하는 문장과 `IF sy-subrc` 사이에 다른 로직이 들어간다.

#### 문제

`sy-subrc`가 더 이상 원하는 문장의 결과를 의미하지 않을 수 있다.

#### 해결

처리 결과가 필요한 문장 바로 다음에 확인한다.

```abap
READ TABLE lt_user INTO ls_user WITH KEY user_id = 'U0001'.
IF sy-subrc = 0.
  " 성공 처리
ELSE.
  " 실패 처리
ENDIF.
```

### 14.4 오류 흐름 3: `sy-datum`을 문자처럼만 취급

#### 상황

날짜를 단순 문자로만 다루어 출력 형식과 내부 형식을 혼동한다.

#### 문제

사용자 표시 형식, 내부 저장 형식, 실제 날짜 계산을 혼동할 수 있다.

#### 해결

- 날짜 타입 `d`의 의미를 이해한다.
- 단순 출력과 날짜 계산을 구분한다.
- 복잡한 날짜 계산은 표준 함수/클래스 또는 업무 기준을 확인한다.

### 14.5 오류 흐름 4: `sy-uname`을 권한 검증으로 오해

#### 상황

현재 사용자가 누구인지 알기 위해 `sy-uname`을 사용한 뒤, 이를 곧 권한이 있다는 의미로 해석한다.

#### 문제

`sy-uname`은 사용자 ID일 뿐 권한 검증 결과가 아니다.

#### 해결

권한 확인은 별도의 권한 체크 로직과 권한 객체를 사용해야 한다.  
이 내용은 보안/권한 관련 후속 과정에서 다룬다.

## 15. 실무 적용 기준

### 15.1 문자열 타입 선택 기준

| 상황 | 권장 타입 |
|---|---|
| 상태 코드, 구분자, 고정 길이 코드 | `c LENGTH n` 또는 DDIC 타입 |
| 사용자 출력 메시지 | `string` |
| DB 테이블 필드와 동일하게 맞춰야 하는 값 | DDIC Data Element 참조 |
| 긴 설명 또는 조합 텍스트 | `string` |

### 15.2 시스템 필드 사용 기준

| 시스템 필드 | 사용 예 | 주의점 |
|---|---|---|
| `sy-datum` | 생성일, 실행일 출력 | 시간대와 업무 기준일은 별도 검토 필요 |
| `sy-uname` | 생성자, 변경자 기록 | 권한 검증과 혼동 금지 |
| `sy-subrc` | 직전 처리 결과 확인 | 반드시 해당 문장 직후 확인 |
| `sy-index` | 반복 횟수 확인 | DO/WHILE 등 반복 맥락에서 의미 있음 |

### 15.3 실무에서 더 권장되는 방향

초급 단계에서는 시스템 필드를 직접 읽는 방식이 학습에 좋다.  
그러나 실무 프로그램에서는 다음 관점도 고려해야 한다.

```text
현재 날짜가 서버 날짜인지, 사용자 로컬 날짜인지 확인한다.
현재 사용자가 실제 처리 권한을 가진 사용자인지 별도 검증한다.
처리 결과는 sy-subrc 외에도 예외, 메시지, 반환 구조로 표현될 수 있다.
```

특히 S/4HANA와 ABAP Cloud, RAP 영역으로 갈수록 시스템 정보 접근 방식이 더 명시적이고 객체지향적으로 바뀔 수 있다.  
이 모듈에서는 Classic ABAP 기본 감각을 먼저 학습한다.

## 16. 미니 실습

### 16.1 실습 목표

현재 사용자, 현재 날짜, 상태 코드, 처리 결과 메시지를 출력하는 작은 ABAP Report를 작성한다.

### 16.2 실습 프로그램

```abap
REPORT zjhy_basic_system_info.

DATA gv_user    TYPE syuname.
DATA gv_today   TYPE d.
DATA gv_status  TYPE c LENGTH 1 VALUE 'A'.
DATA gv_message TYPE string.

gv_user  = sy-uname.
gv_today = sy-datum.

IF gv_status = 'A'.
  gv_message = 'Active user process'.
ELSEIF gv_status = 'I'.
  gv_message = 'Inactive user process'.
ELSE.
  gv_message = 'Unknown status'.
ENDIF.

WRITE: / 'Current User:', gv_user,
       / 'Current Date:', gv_today,
       / 'Status      :', gv_status,
       / 'Message     :', gv_message.
```

### 16.3 실습 변경 과제

위 프로그램을 다음과 같이 변경한다.

1. `gv_status` 값을 `I`로 변경하고 출력 결과를 비교한다.
2. `gv_status` 값을 `X`로 변경하고 `Unknown status`가 출력되는지 확인한다.
3. `gv_message`를 `CONCATENATE`로 조합해 사용자명과 날짜를 포함한다.
4. 날짜에 7일을 더한 `gv_next_week` 변수를 출력한다.
5. Syntax Error를 일부러 하나 만들고 활성화 오류 메시지를 기록한다.

## 17. 강사용 설명 포인트

강사는 이번 모듈에서 다음 사항을 강조하면 좋다.

### 17.1 문자열은 단순하지만 실무 오류가 많다

문자열은 초급자에게 쉬워 보이지만, 실제로는 길이, 공백, 대소문자, 인코딩, 출력 형식, 변환 문제와 연결된다.  
초급 단계에서는 특히 `c`와 `string`의 차이를 체감시키는 것이 좋다.

### 17.2 시스템 필드는 편리하지만 문맥이 중요하다

`sy-datum`, `sy-uname`, `sy-subrc`는 매우 편리하지만 의미를 과도하게 일반화하면 안 된다.

```text
sy-datum = 현재 날짜이지만, 업무 기준일과 항상 같지는 않을 수 있다.
sy-uname = 현재 사용자이지만, 권한 검증 결과는 아니다.
sy-subrc = 직전 문장 결과이지만, 문장마다 해석이 다를 수 있다.
```

### 17.3 `sy-subrc`는 “즉시 확인” 습관을 만든다

초급자에게 가장 먼저 잡아주어야 하는 습관은 다음이다.

```text
결과 확인이 필요한 문장 바로 다음 줄에서 sy-subrc를 확인한다.
```

이 습관은 이후 `READ TABLE`, `SELECT SINGLE`, `CALL FUNCTION`, `AUTHORITY-CHECK` 등 많은 영역에서 도움이 된다.

## 18. 평가 문제

### 18.1 객관식

#### Q1. `TYPE c LENGTH 10`에 대한 설명으로 가장 적절한 것은?

A. 가변 길이 문자열이다.  
B. 고정 길이 문자 필드이다.  
C. 날짜 타입이다.  
D. 정수 타입이다.

**정답:** B

#### Q2. 현재 SAP 로그인 사용자 ID를 나타내는 시스템 필드는?

A. `sy-datum`  
B. `sy-index`  
C. `sy-uname`  
D. `sy-subrc`

**정답:** C

#### Q3. `sy-subrc`에 대한 설명으로 가장 적절한 것은?

A. 프로그램 전체의 최종 결과만 저장한다.  
B. 항상 현재 날짜를 저장한다.  
C. 많은 ABAP 문장의 직전 처리 결과를 나타낸다.  
D. 현재 반복 횟수만 저장한다.

**정답:** C

#### Q4. `sy-subrc` 사용 습관으로 가장 적절한 것은?

A. 프로그램 맨 마지막에 한 번만 확인한다.  
B. 결과 확인이 필요한 문장 직후 확인한다.  
C. 확인하지 않아도 ABAP이 자동 처리한다.  
D. `WRITE` 문 앞에서만 확인한다.

**정답:** B

### 18.2 단답형

#### Q1. `TYPE c`와 `TYPE string`의 차이를 간단히 설명하시오.

**모범 답안:**  
`TYPE c LENGTH n`은 길이가 고정된 문자 필드이고, `TYPE string`은 길이가 가변적인 문자열 타입이다. 코드나 상태값처럼 길이가 정해진 값은 `c`, 메시지나 설명처럼 길이가 유동적인 값은 `string`이 적합할 수 있다.

#### Q2. `sy-datum`과 `sy-uname`의 의미를 설명하시오.

**모범 답안:**  
`sy-datum`은 현재 시스템 날짜를 나타내는 시스템 필드이고, `sy-uname`은 현재 ABAP 프로그램을 실행한 SAP 로그인 사용자 ID를 나타내는 시스템 필드이다.

#### Q3. `sy-subrc`를 늦게 확인하면 왜 문제가 될 수 있는가?

**모범 답안:**  
`sy-subrc`는 직전 ABAP 문장의 처리 결과를 담기 때문에, 결과를 확인해야 하는 문장과 `sy-subrc` 확인 사이에 다른 문장이 실행되면 원래 확인하려던 결과가 아니게 될 수 있다.

## 19. 실무형 리뷰 문제

다음 코드를 보고 문제점을 설명하시오.

```abap
READ TABLE lt_user INTO ls_user WITH KEY user_id = 'U0001'.

WRITE: / '조회 완료'.

IF sy-subrc = 0.
  WRITE: / '사용자를 찾았습니다.'.
ENDIF.
```

### 모범 해설

`READ TABLE`의 결과를 확인하려면 `READ TABLE` 직후 `sy-subrc`를 확인하는 습관이 필요하다.  
중간에 다른 문장이 들어가면 `sy-subrc`가 의도한 문장의 결과를 나타내는지 불명확해질 수 있다.

개선 예시는 다음과 같다.

```abap
READ TABLE lt_user INTO ls_user WITH KEY user_id = 'U0001'.

IF sy-subrc = 0.
  WRITE: / '사용자를 찾았습니다.'.
ELSE.
  WRITE: / '사용자를 찾지 못했습니다.'.
ENDIF.
```

## 21. 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
문자열은 고정 길이 c와 가변 길이 string의 차이를 이해해야 한다.
sy-datum은 현재 시스템 날짜를 나타낸다.
```

```text
REPORT 구조를 만들고,
DATA로 값을 담고,
WRITE로 출력하고,
IF/CASE로 분기하고,
DO/WHILE로 반복하고,
문자열·날짜·시스템 필드로 실제 실행 문맥을 표현한다.
```
