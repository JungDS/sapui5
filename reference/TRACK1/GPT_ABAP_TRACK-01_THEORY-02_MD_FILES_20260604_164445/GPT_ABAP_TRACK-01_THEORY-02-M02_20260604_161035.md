## 3. ABAP에서 선언이 중요한 이유

프로그램은 데이터를 처리한다.  
데이터를 처리하려면 값을 담을 공간과, 그 값이 어떤 형식인지에 대한 약속이 필요하다.

예를 들어 다음과 같은 값을 프로그램에서 다룬다고 하자.

| 값 | 의미 | 필요한 타입 |
|---|---|---|
| `KIM` | 사용자명 | 문자 |
| `30` | 나이 | 정수 |
| `1500.50` | 금액 | 소수점 숫자 |
| `20260604` | 날짜 | 날짜 |
| `A` | 상태 코드 | 한 자리 문자 |

ABAP에서는 이런 값을 다루기 위해 변수를 선언한다.

```abap
DATA gv_name TYPE c LENGTH 20.
DATA gv_age  TYPE i.
```

이 선언은 다음 의미를 가진다.

```text
GV_NAME이라는 이름의 문자 20자리 변수를 만든다.
GV_AGE라는 이름의 정수 변수를 만든다.
```

즉, 선언은 프로그램이 데이터를 안전하게 다루기 위한 출발점이다.

## 4. DATA 선언

### 4.1 DATA의 기본 의미

`DATA`는 ABAP 프로그램 안에서 변수를 선언하는 키워드이다.  
변수는 프로그램 실행 중 값이 바뀔 수 있는 저장 공간이다.

기본 형태는 다음과 같다.

```abap
DATA 변수명 TYPE 타입.
```

예시:

```abap
DATA gv_name TYPE c LENGTH 20.
DATA gv_age  TYPE i.
```

여기서 각 요소의 의미는 다음과 같다.

| 요소 | 의미 |
|---|---|
| DATA | 변수를 선언한다는 키워드 |
| GV_NAME | 변수명 |
| TYPE | 어떤 타입인지 지정 |
| C | Character 타입 |
| LENGTH 20 | 20자리 문자 길이 |
| 마침표 `.` | ABAP 문장의 끝 |

ABAP 문장은 마침표로 끝난다.  
초급자가 자주 하는 실수 중 하나가 마침표 누락이다.

## 5. ABAP 변수 네이밍 기본

ABAP에서 변수명은 시스템적으로 반드시 `GV_`, `LV_` 같은 Prefix를 요구하지는 않는다.  
하지만 실무에서는 가독성을 위해 네이밍 규칙을 사용하는 경우가 많다.

| Prefix | 일반적 의미 | 예시 |
|---|---|---|
| GV_ | Global Variable | `gv_count` |
| LV_ | Local Variable | `lv_count` |
| GS_ | Global Structure | `gs_user` |
| LS_ | Local Structure | `ls_user` |
| GT_ | Global Internal Table | `gt_user` |
| LT_ | Local Internal Table | `lt_user` |
| GC_ | Global Constant | `gc_status_active` |
| LC_ | Local Constant | `lc_status_active` |
| TY_ | Local Type | `ty_user` |

이번 초급 모듈에서는 단순성을 위해 `gv_`, `lv_`, `gc_`, `ty_` 형태를 사용한다.

> [추정] 실제 프로젝트에서는 고객사 또는 개발팀 Naming Convention이 있을 수 있으므로, 실무에서는 해당 규칙을 우선한다.

## 6. Elementary Type 개요

Elementary Type은 더 이상 내부 필드로 나뉘지 않는 가장 기초적인 데이터 타입이다.

초급 과정에서 먼저 알아야 할 대표 타입은 다음과 같다.

| 타입 | 이름 | 용도 | 예시 |
|---|---|---|---|
| C | Character | 고정 길이 문자 | 이름, 코드 |
| N | Numeric Text | 숫자로 이루어진 문자 | 문서번호, 순번 |
| I | Integer | 정수 계산 | 개수, 반복 횟수 |
| P | Packed Number | 소수점 숫자, 금액/수량 | 금액, 비율 |
| F | Floating Point | 부동소수점 | 과학 계산 |
| D | Date | 날짜 | `20260604` |
| T | Time | 시간 | `153000` |
| STRING | Variable-length String | 가변 길이 문자열 | 긴 설명 |
| X | Hexadecimal Byte | 바이트 | 바이너리 데이터 |
| XSTRING | Variable-length Byte String | 가변 바이트 문자열 | 파일/바이너리 |

초급 ABAP 학습에서는 `C`, `N`, `I`, `P`, `D`, `T`, `STRING`을 먼저 익히면 충분하다.

---

## 7. Character Type: C

### 7.1 기본 선언

`C` 타입은 고정 길이 문자 타입이다.

```abap
DATA gv_name TYPE c LENGTH 20.
```

`LENGTH 20`은 최대 20자리 고정 길이 문자를 의미한다.  
고정 길이 타입이므로 값이 짧으면 남는 공간은 공백으로 채워진다.

### 7.2 예제

```abap
REPORT zedu_data_c_type.

DATA gv_name TYPE c LENGTH 20.

gv_name = 'SAP'.
WRITE gv_name.
```

이 프로그램에서 `GV_NAME`은 20자리 공간을 가진다.  
화면에는 `SAP`가 보이지만 내부적으로는 뒤쪽에 공백이 있을 수 있다.

### 7.3 실무 사용 예

| 사용 대상 | 이유 |
|---|---|
| 상태 코드 | 길이가 고정된 코드값 |
| 회사 코드 | SAP 표준에서 고정 길이 코드가 많음 |
| 사용자명 일부 | 고정 길이 필드가 필요한 경우 |
| 단순 코드 | `A`, `I`, `B` 같은 값 |

문자열 길이가 유동적이고 길이가 길 수 있는 설명성 데이터라면 `STRING`도 고려할 수 있다.  
다만 DB Table Field나 DDIC 객체와 연결될 때는 고정 길이 타입을 쓰는 경우도 많다.

---

## 8. Numeric Text Type: N

### 8.1 기본 의미

`N` 타입은 숫자처럼 보이지만 실제 성격은 문자에 가깝다.  
숫자 계산용이라기보다, 숫자로 구성된 고정 길이 코드를 표현할 때 사용한다.

```abap
DATA gv_docno TYPE n LENGTH 10.
```

### 8.2 예제

```abap
REPORT zedu_data_n_type.

DATA gv_docno TYPE n LENGTH 10.

gv_docno = '12345'.

WRITE gv_docno.
```

`N` 타입은 앞쪽 0을 포함한 고정 길이 식별자에 적합하다.

예:

```text
0000001234
2026060001
```

### 8.3 `N`과 `I`의 차이

| 구분 | N | I |
|---|---|---|
| 성격 | 숫자 문자 | 정수 |
| 계산 목적 | 부적합 | 적합 |
| 앞자리 0 | 유지 의미 있음 | 숫자값으로 처리 |
| 예시 | 문서번호, 순번 코드 | 수량 카운트, 반복 횟수 |

초급자는 다음처럼 기억하면 된다.

```text
계산할 숫자면 I 또는 P.
번호처럼 보존할 값이면 N.
```

## 9. Integer Type: I

### 9.1 기본 선언

`I` 타입은 정수 계산에 사용하는 타입이다.

```abap
DATA gv_count TYPE i.
```

### 9.2 예제

```abap
REPORT zedu_data_i_type.

DATA gv_count TYPE i.

gv_count = 10.
gv_count = gv_count + 5.

WRITE gv_count.
```

결과는 `15`이다.

### 9.3 사용 예

| 사용 대상 | 이유 |
|---|---|
| 반복 횟수 | 정수 계산 |
| 총 건수 | 정수 카운트 |
| Index | 위치 번호 |
| 단순 수량 | 소수점이 필요 없는 경우 |

금액, 비율, 소수점 수량에는 `I`를 사용하지 않는다.

## 10. Packed Number Type: P

### 10.1 기본 의미

`P` 타입은 Packed Number이며, 소수점이 필요한 숫자에 자주 사용된다.  
ABAP에서 금액, 수량, 비율 같은 값을 다룰 때 초급자가 반드시 이해해야 하는 타입이다.

```abap
DATA gv_amount TYPE p LENGTH 8 DECIMALS 2.
```

### 10.2 LENGTH와 DECIMALS

| 속성 | 의미 |
|---|---|
| LENGTH | 내부 저장 길이 |
| DECIMALS | 소수 자릿수 |

예:

```abap
DATA gv_rate TYPE p LENGTH 5 DECIMALS 2.
```

이 변수는 소수점 2자리 숫자를 다루는 데 사용된다.

### 10.3 예제

```abap
REPORT zedu_data_p_type.

DATA gv_price TYPE p LENGTH 8 DECIMALS 2.
DATA gv_qty   TYPE i.
DATA gv_total TYPE p LENGTH 10 DECIMALS 2.

gv_price = '1500.50'.
gv_qty   = 3.
gv_total = gv_price * gv_qty.

WRITE gv_total.
```

이 예제는 가격과 수량을 곱해 총액을 계산한다.

### 10.4 실무 주의

금액과 수량은 단순히 `P` 타입으로만 선언해서 끝나는 것이 아니다.  
실제 DB 테이블에서는 통화키, 단위 필드와 함께 설계해야 하는 경우가 많다.

이번 모듈에서는 ABAP 변수 선언 관점에서 `P`를 이해하고, 통화/수량 필드의 DDIC 설계는 후속 DDIC 심화에서 다시 연결한다.

## 11. Date Type: D

### 11.1 기본 의미

`D` 타입은 날짜를 표현한다.

```abap
DATA gv_date TYPE d.
```

ABAP 내부 날짜 형식은 보통 `YYYYMMDD` 형태로 이해하면 된다.

예:

```text
20260604
```

### 11.2 예제

```abap
REPORT zedu_data_d_type.

DATA gv_today TYPE d.

gv_today = sy-datum.

WRITE gv_today.
```

`SY-DATUM`은 현재 시스템 날짜를 나타내는 시스템 필드이다.  
시스템 필드는 `THEORY-02-M06`에서 더 자세히 다룬다. 여기서는 날짜 타입 예시로만 사용한다.

### 11.3 주의

날짜를 문자처럼 보관할 수도 있지만, 날짜 의미가 있는 값은 날짜 타입을 사용하는 것이 좋다.  
날짜 타입을 사용하면 날짜 계산과 검증 측면에서 더 명확한 프로그램을 작성할 수 있다.

## 12. Time Type: T

### 12.1 기본 의미

`T` 타입은 시간을 표현한다.

```abap
DATA gv_time TYPE t.
```

ABAP 내부 시간 형식은 보통 `HHMMSS` 형태로 이해하면 된다.

예:

```text
153000
```

### 12.2 예제

```abap
REPORT zedu_data_t_type.

DATA gv_time TYPE t.

gv_time = sy-uzeit.

WRITE gv_time.
```

`SY-UZEIT`는 현재 시스템 시간을 의미한다.  
이 역시 시스템 필드 상세 학습은 후속 모듈에서 다룬다.

## 13. STRING Type

### 13.1 기본 의미

`STRING`은 가변 길이 문자열 타입이다.

```abap
DATA gv_text TYPE string.
```

`C LENGTH n`과 달리, `STRING`은 길이가 고정되어 있지 않다.

### 13.2 예제

```abap
REPORT zedu_data_string_type.

DATA gv_text TYPE string.

gv_text = 'ABAP variable-length string example'.

WRITE gv_text.
```

### 13.3 C와 STRING 비교

| 구분 | C | STRING |
|---|---|---|
| 길이 | 고정 길이 | 가변 길이 |
| 선언 | `TYPE c LENGTH 20` | `TYPE string` |
| 용도 | 코드, 고정 필드 | 긴 텍스트, 동적 문자열 |
| 공백 처리 | 고정 길이에 따른 공백 고려 | 상대적으로 유연 |

초급 단계에서는 고정 코드값은 `C`, 설명성 긴 문장은 `STRING`으로 이해하면 좋다.

---

## 14. VALUE 옵션

### 14.1 기본 의미

`VALUE`는 선언과 동시에 초기값을 지정하는 옵션이다.

```abap
DATA gv_name TYPE c LENGTH 20 VALUE 'SAP'.
```

이 문장은 다음 두 문장과 유사한 효과를 가진다.

```abap
DATA gv_name TYPE c LENGTH 20.
gv_name = 'SAP'.
```

### 14.2 예제

```abap
REPORT zedu_data_value.

DATA gv_name  TYPE c LENGTH 20 VALUE 'SAP'.
DATA gv_count TYPE i VALUE 10.

WRITE: / gv_name,
       / gv_count.
```

### 14.3 실무 주의

초기값이 명확한 경우에는 `VALUE`를 사용하면 코드가 간결해진다.  
하지만 업무 로직 중 계산되거나 사용자 입력으로 바뀌는 값은 무리하게 선언부에서 초기화하지 않아도 된다.

## 15. CONSTANTS 선언

### 15.1 CONSTANTS의 의미

`CONSTANTS`는 실행 중 값이 바뀌면 안 되는 상수를 선언한다.

```abap
CONSTANTS gc_status_active TYPE c LENGTH 1 VALUE 'A'.
```

이 선언은 다음 의미를 가진다.

```text
GC_STATUS_ACTIVE는 한 자리 문자 상수이고 값은 A이다.
프로그램 실행 중 다른 값으로 변경할 수 없다.
```

### 15.2 왜 상수를 사용하는가?

상수를 사용하는 이유는 다음과 같다.

| 이유 | 설명 |
|---|---|
| 의미 부여 | `'A'`보다 `gc_status_active`가 의미를 더 잘 표현한다. |
| 중복 제거 | 같은 리터럴 값을 여러 곳에 반복하지 않는다. |
| 변경 용이성 | 값이 바뀌면 상수 선언부만 수정하면 된다. |
| 오류 감소 | 오타로 인한 조건 오류를 줄일 수 있다. |
| 가독성 | 조건문의 업무 의미가 명확해진다. |

### 15.3 상수 사용 전후 비교

나쁜 예:

```abap
IF gv_status = 'A'.
  WRITE 'Active'.
ENDIF.
```

좋은 예:

```abap
CONSTANTS gc_status_active TYPE c LENGTH 1 VALUE 'A'.

IF gv_status = gc_status_active.
  WRITE 'Active'.
ENDIF.
```

문자 `'A'` 자체는 업무 의미가 드러나지 않는다.  
상수를 사용하면 `'A'`가 활성 상태라는 의미를 코드에 드러낼 수 있다.

### 15.4 상수 변경 오류

다음 코드는 문법적으로 문제가 된다.

```abap
CONSTANTS gc_status_active TYPE c LENGTH 1 VALUE 'A'.

gc_status_active = 'I'.
```

상수는 선언 이후 값을 바꿀 수 없다.  
이런 코드는 Syntax Check 또는 Activation 단계에서 오류가 발생한다.

## 16. TYPES 선언

### 16.1 TYPES의 의미

`TYPES`는 값을 저장하지 않는다.  
새로운 타입 이름을 정의한다.

```abap
TYPES ty_status TYPE c LENGTH 1.
```

이 선언은 `TY_STATUS`라는 타입 별칭을 만든다.  
이후 변수 선언에서 사용할 수 있다.

```abap
DATA gv_status TYPE ty_status.
```

초급자가 자주 혼동하는 점은 다음이다.

```text
DATA는 변수 생성.
TYPES는 타입 정의.
```

`TYPES` 자체로는 값이 담기지 않는다.

### 16.2 예제

```abap
REPORT zedu_types_basic.

TYPES ty_status TYPE c LENGTH 1.

DATA gv_status TYPE ty_status.

gv_status = 'A'.

WRITE gv_status.
```

### 16.3 TYPES를 사용하는 이유

| 이유 | 설명 |
|---|---|
| 반복 선언 감소 | 같은 타입을 여러 변수에 재사용 |
| 의미 부여 | `c LENGTH 1`보다 `ty_status`가 의미 있음 |
| 구조화 준비 | Structure와 Internal Table 타입 정의로 확장 |
| 유지보수성 | 타입 길이 변경 시 한 곳에서 수정 가능 |

### 16.4 실무 주의

로컬 `TYPES`는 해당 프로그램 안에서만 유효하다.  
여러 프로그램에서 공통으로 써야 하는 타입이라면 DDIC Data Element, Structure, Table Type 등을 검토한다.

## 17. TYPE과 LIKE

### 17.1 TYPE

`TYPE`은 명시한 타입을 기준으로 변수를 선언한다.

```abap
DATA gv_count TYPE i.
DATA gv_name  TYPE c LENGTH 20.
DATA gv_date  TYPE d.
```

또는 DDIC Data Element를 참조할 수도 있다.

```abap
DATA gv_carrid TYPE s_carr_id.
```

### 17.2 LIKE

`LIKE`는 이미 존재하는 변수, 구조 필드, 테이블 필드와 같은 속성을 가지도록 선언한다.

```abap
DATA gv_carrid LIKE scarr-carrid.
```

이는 `SCARR-CARRID` 필드의 타입 속성을 참고해 변수를 선언한다는 의미이다.

### 17.3 TYPE과 LIKE의 기본 판단

| 구분 | 사용 기준 |
|---|---|
| TYPE | 타입 이름이 명확할 때 |
| LIKE | 기존 변수나 테이블 필드와 같은 타입을 맞추고 싶을 때 |

초급자에게는 다음 기준이 안전하다.

```text
DDIC Data Element를 알고 있으면 TYPE을 사용한다.
표준 테이블 필드와 정확히 맞추고 싶으면 LIKE table-field를 사용할 수 있다.
```

### 17.4 예제

```abap
REPORT zedu_type_like.

DATA gv_carrid_1 TYPE s_carr_id.
DATA gv_carrid_2 LIKE scarr-carrid.

gv_carrid_1 = 'AA'.
gv_carrid_2 = 'LH'.

WRITE: / gv_carrid_1,
       / gv_carrid_2.
```

이 예제에서 `S_CARR_ID`와 `SCARR-CARRID`는 시스템에 존재하는 항공사 ID 관련 타입/필드이다.  
실습 시스템에 따라 항공 예제 테이블이 없을 수 있으므로, 그런 경우 시스템에 존재하는 다른 표준 테이블 필드 또는 교육용 Z 객체로 대체한다.

---

## 18. DDIC 타입을 참조하는 이유

앞선 `THEORY-01`에서는 Domain, Data Element, Structure, Transparent Table을 학습했다.  
ABAP 변수 선언에서 DDIC 타입을 참조하면 데이터 의미와 기술 속성을 일관되게 맞출 수 있다.

예를 들어 사용자 ID를 프로그램에서 선언한다고 하자.

나쁜 예:

```abap
DATA gv_user_id TYPE c LENGTH 10.
```

좋은 예:

```abap
DATA gv_user_id TYPE zde_jhy_user_id.
```

또는 테이블 필드를 기준으로 선언할 수도 있다.

```abap
DATA gv_user_id LIKE zt_jhy_user-user_id.
```

### 18.1 장점

| 장점 | 설명 |
|---|---|
| 길이 일관성 | 테이블 필드와 프로그램 변수 길이가 맞는다. |
| 의미 일관성 | Data Element의 업무 의미를 따라간다. |
| 유지보수성 | DDIC 변경 시 영향 분석이 쉬워진다. |
| 오류 감소 | 잘못된 길이 또는 타입 선언을 줄인다. |

### 18.2 실무 원칙

실무에서 DB 테이블 필드와 비교하거나 SELECT 조건으로 사용할 변수는 가능하면 관련 DDIC 타입을 참조하는 것이 안전하다.

예:

```abap
DATA gv_carrid TYPE s_carr_id.

SELECT SINGLE carrname
  FROM scarr
  WHERE carrid = @gv_carrid
  INTO @DATA(gv_carrname).
```

Open SQL은 후속 Section에서 자세히 다루므로, 여기서는 “타입을 맞추는 것이 중요하다”는 정도만 이해한다.

## 19. 선언 위치

초급 Classic Report에서는 보통 프로그램 상단에 선언부를 둔다.

```abap
REPORT zedu_declaration_position.

DATA gv_name TYPE c LENGTH 20.

gv_name = 'SAP'.

WRITE gv_name.
```

하지만 ABAP은 블록과 컨텍스트에 따라 선언 위치가 달라질 수 있다.  
후속 모듈에서 Procedure, Method, Inline Declaration을 배우면 선언 위치의 의미가 더 중요해진다.

이번 단계에서는 다음 습관을 권장한다.

```text
초급 Report에서는 필요한 변수를 프로그램 상단에 명확히 선언한다.
변수명과 타입을 읽기 쉽게 작성한다.
초기값이 필요한 경우 VALUE를 사용한다.
상태값과 고정 코드는 CONSTANTS로 분리한다.
```

## 20. 한 줄 선언과 체인 선언

ABAP에서는 같은 키워드로 여러 변수를 선언할 수 있다.

### 20.1 개별 선언

```abap
DATA gv_name TYPE c LENGTH 20.
DATA gv_age  TYPE i.
DATA gv_city TYPE c LENGTH 20.
```

### 20.2 체인 선언

```abap
DATA: gv_name TYPE c LENGTH 20,
      gv_age  TYPE i,
      gv_city TYPE c LENGTH 20.
```

둘 다 가능하다.  
초급자는 처음에는 개별 선언으로 익힌 뒤, 가독성이 익숙해지면 체인 선언을 사용해도 된다.

### 20.3 체인 선언 주의

체인 선언에서는 쉼표와 마침표 위치가 중요하다.

잘못된 예:

```abap
DATA: gv_name TYPE c LENGTH 20.
      gv_age  TYPE i.
```

올바른 예:

```abap
DATA: gv_name TYPE c LENGTH 20,
      gv_age  TYPE i.
```

첫 줄 뒤에는 쉼표가 필요하고, 마지막 선언 뒤에 마침표를 찍는다.

## 21. 완성 예제: 선언문 종합

다음 예제는 이번 모듈의 핵심을 한 프로그램에 모은 것이다.

```abap
REPORT zedu_data_constants_types.

TYPES ty_status TYPE c LENGTH 1.

CONSTANTS gc_status_active   TYPE ty_status VALUE 'A'.
CONSTANTS gc_status_inactive TYPE ty_status VALUE 'I'.

DATA gv_user_name TYPE c LENGTH 30 VALUE 'Kim Beginner'.
DATA gv_age       TYPE i VALUE 30.
DATA gv_status    TYPE ty_status VALUE gc_status_active.
DATA gv_amount    TYPE p LENGTH 8 DECIMALS 2 VALUE '1500.50'.
DATA gv_today     TYPE d.

gv_today = sy-datum.

WRITE: / 'User Name:', gv_user_name,
       / 'Age      :', gv_age,
       / 'Status   :', gv_status,
       / 'Amount   :', gv_amount,
       / 'Today    :', gv_today.
```

이 예제에서 확인해야 할 것은 다음이다.

| 코드 | 학습 포인트 |
|---|---|
| `TYPES ty_status` | 로컬 타입 정의 |
| `CONSTANTS gc_status_active` | 고정 코드값 상수화 |
| `DATA gv_user_name` | 문자 변수 |
| `DATA gv_age` | 정수 변수 |
| `DATA gv_amount` | 소수점 숫자 |
| `VALUE` | 초기값 |
| `sy-datum` | 시스템 날짜 사용 예고 |

## 22. 오류 상황과 해결

### 22.1 마침표 누락

잘못된 예:

```abap
DATA gv_name TYPE c LENGTH 20
WRITE gv_name.
```

문제:

```text
ABAP 문장은 마침표로 끝나야 한다.
```

해결:

```abap
DATA gv_name TYPE c LENGTH 20.
WRITE gv_name.
```

### 22.2 타입 길이 누락

잘못된 예:

```abap
DATA gv_name TYPE c.
```

상황에 따라 기본 길이가 적용될 수 있지만, 초급 학습에서는 문자 타입 길이를 명확히 쓰는 습관이 좋다.

권장:

```abap
DATA gv_name TYPE c LENGTH 20.
```

### 22.3 상수값 변경 시도

잘못된 예:

```abap
CONSTANTS gc_status TYPE c LENGTH 1 VALUE 'A'.

gc_status = 'I'.
```

문제:

```text
CONSTANTS로 선언한 값은 변경할 수 없다.
```

해결:

변경이 필요한 값이라면 `DATA`를 사용한다.

```abap
DATA gv_status TYPE c LENGTH 1 VALUE 'A'.

gv_status = 'I'.
```

### 22.4 TYPES를 변수처럼 사용

잘못된 예:

```abap
TYPES ty_status TYPE c LENGTH 1.

ty_status = 'A'.
```

문제:

```text
TYPES는 타입 이름을 정의할 뿐 변수 저장 공간을 만들지 않는다.
```

해결:

`TYPES`로 정의한 타입을 기준으로 `DATA` 변수를 선언한다.

```abap
TYPES ty_status TYPE c LENGTH 1.

DATA gv_status TYPE ty_status.

gv_status = 'A'.
```

### 22.5 숫자 타입과 문자 타입 혼동

잘못된 설계 예:

```abap
DATA gv_docno TYPE i.
gv_docno = 00001234.
```

문서번호처럼 앞자리 0이 중요한 값은 정수로 선언하면 의미가 깨질 수 있다.

권장:

```abap
DATA gv_docno TYPE n LENGTH 10.
gv_docno = '0000001234'.
```

### 22.6 소수점 계산에 I 사용

잘못된 예:

```abap
DATA gv_price TYPE i.
gv_price = '1500.50'.
```

문제:

정수 타입은 소수점 처리에 적합하지 않다.

권장:

```abap
DATA gv_price TYPE p LENGTH 8 DECIMALS 2.
gv_price = '1500.50'.
```

## 23. 실무 적용 기준

### 23.1 직접 타입 선언과 DDIC 타입 참조

직접 타입 선언:

```abap
DATA gv_carrid TYPE c LENGTH 3.
```

DDIC 타입 참조:

```abap
DATA gv_carrid TYPE s_carr_id.
```

실무에서는 DB 필드와 연계되는 값일수록 DDIC 타입 참조가 안전하다.

| 상황 | 권장 방식 |
|---|---|
| 화면/테이블 필드와 연결 | DDIC Data Element 참조 |
| DB Table Field와 비교 | Table Field 기준 LIKE 또는 Data Element TYPE |
| 프로그램 내부 계산용 정수 | `TYPE i` |
| 단순 임시 문자열 | `TYPE string` 또는 `TYPE c LENGTH n` |
| 고정 업무 코드 | `CONSTANTS` 사용 |

### 23.2 하드코딩 줄이기

조건문에 직접 리터럴을 반복하는 코드는 유지보수성이 떨어진다.

비권장:

```abap
IF gv_status = 'A'.
  WRITE 'Active'.
ELSEIF gv_status = 'I'.
  WRITE 'Inactive'.
ENDIF.
```

권장:

```abap
CONSTANTS gc_status_active   TYPE c LENGTH 1 VALUE 'A'.
CONSTANTS gc_status_inactive TYPE c LENGTH 1 VALUE 'I'.

IF gv_status = gc_status_active.
  WRITE 'Active'.
ELSEIF gv_status = gc_status_inactive.
  WRITE 'Inactive'.
ENDIF.
```

### 23.3 불필요한 전역 변수 줄이기

초급 Report에서는 학습 편의를 위해 상단에 변수를 모아 선언한다.  
하지만 실무 프로그램에서는 변수의 사용 범위를 좁히는 것이 중요하다.  
이 내용은 FORM, Method, OO ABAP, Modern ABAP Inline Declaration에서 더 자세히 다룬다.

이번 모듈에서는 다음 정도만 기억한다.

```text
필요한 변수만 선언한다.
변수명은 의미 있게 작성한다.
고정값은 상수로 분리한다.
DDIC 필드와 연결되는 값은 DDIC 타입을 참조한다.
```

## 24. 실습: 사용자 상태 출력 프로그램

### 24.1 실습 목표

`DATA`, `CONSTANTS`, `TYPES`를 사용하여 사용자 상태를 출력하는 간단한 Report를 작성한다.

### 24.2 프로그램명

```text
ZEDU_T02_M02_DECL
```

### 24.3 요구사항

1. 상태 타입 `TY_STATUS`를 정의한다.
2. 활성 상태 상수 `GC_STATUS_ACTIVE`를 선언한다.
3. 비활성 상태 상수 `GC_STATUS_INACTIVE`를 선언한다.
4. 사용자명 변수 `GV_USER_NAME`을 선언한다.
5. 상태 변수 `GV_STATUS`를 선언한다.
6. 나이 변수 `GV_AGE`를 선언한다.
7. 금액 변수 `GV_AMOUNT`를 선언한다.
8. 결과를 `WRITE`로 간단히 출력한다.

### 24.4 예제 코드

```abap
REPORT zedu_t02_m02_decl.

TYPES ty_status TYPE c LENGTH 1.

CONSTANTS gc_status_active   TYPE ty_status VALUE 'A'.
CONSTANTS gc_status_inactive TYPE ty_status VALUE 'I'.

DATA gv_user_name TYPE c LENGTH 30 VALUE 'Kim Beginner'.
DATA gv_status    TYPE ty_status VALUE gc_status_active.
DATA gv_age       TYPE i VALUE 30.
DATA gv_amount    TYPE p LENGTH 8 DECIMALS 2 VALUE '1200.50'.

WRITE: / 'User Name:', gv_user_name,
       / 'Status   :', gv_status,
       / 'Age      :', gv_age,
       / 'Amount   :', gv_amount.
```

### 24.5 확인 포인트

| 확인 항목 | 기대 결과 |
|---|---|
| Syntax Check | 오류 없음 |
| Activation | 성공 |
| Execution | 사용자명, 상태, 나이, 금액 출력 |
| Constant 변경 시도 | 오류 발생 |
| TYPES 직접 대입 시도 | 오류 발생 |

### 24.6 오류 케이스 기록

학습자는 다음 오류 케이스 중 하나를 일부러 만들어보고 메시지를 기록한다.

| 오류 실험 | 예상 결과 |
|---|---|
| `GC_STATUS_ACTIVE = 'I'.` 추가 | 상수 변경 불가 오류 |
| `TY_STATUS = 'A'.` 추가 | 타입을 변수처럼 사용할 수 없음 |
| 마침표 삭제 | 문법 오류 |
| `GV_AMOUNT TYPE i`로 변경 후 소수점 값 대입 | 타입 부적합 또는 값 처리 문제 |

---

## 25. 디버깅 관찰 포인트

이번 단계에서 디버깅을 깊게 다루지는 않지만, 선언된 변수 값이 어떻게 들어가는지 관찰하면 좋다.

관찰 순서:

```text
1. 프로그램 실행 전 Breakpoint 설정
2. DATA 선언 이후 초기값 확인
3. VALUE로 지정된 값 확인
4. GV_STATUS 값이 GC_STATUS_ACTIVE와 같은지 확인
5. GV_AMOUNT의 소수점 값 확인
```

디버깅에서 확인할 질문:

| 질문 | 관찰 대상 |
|---|---|
| `GV_USER_NAME`의 값은 무엇인가? | 문자 변수 |
| `GV_STATUS`는 어떤 값인가? | 타입과 상수 관계 |
| `GC_STATUS_ACTIVE`는 변경 가능한가? | 상수 |
| `GV_AMOUNT`는 소수점이 유지되는가? | Packed Number |
| 선언만 하고 값이 없는 변수는 어떤 초기값인가? | Initial Value |

---

## 26. 강사용 설명 포인트

강의에서는 다음 순서로 설명하면 좋다.

```text
1. 프로그램은 데이터를 처리한다.
2. 데이터를 처리하려면 변수 선언이 필요하다.
3. DATA는 값이 바뀌는 변수이다.
4. CONSTANTS는 값이 바뀌면 안 되는 상수이다.
5. TYPES는 값을 저장하지 않고 타입 이름을 만든다.
6. 타입은 직접 지정할 수도 있고 DDIC를 참조할 수도 있다.
7. DB 필드와 연결되는 값은 DDIC 타입 참조가 실무적으로 안전하다.
```

초급자에게 특히 강조할 문장은 다음이다.

```text
TYPES는 변수 선언이 아니다.
CONSTANTS는 DATA처럼 보이지만 값을 바꿀 수 없다.
문서번호와 계산 숫자는 타입이 다르다.
금액과 수량은 소수점 타입을 신중하게 사용해야 한다.
```

## 27. 평가 문제

### 27.1 객관식

#### Q1. `DATA` 선언의 목적은 무엇인가?

A. 프로그램 주석을 작성한다.  
B. 실행 중 값을 담을 변수를 선언한다.  
C. 화면 제목을 정의한다.  
D. 데이터베이스 테이블을 생성한다.

**정답:** B

#### Q2. `CONSTANTS`에 대한 설명으로 올바른 것은?

A. 실행 중 값을 계속 변경하는 변수이다.  
B. 타입 이름만 정의하고 저장 공간은 만들지 않는다.  
C. 선언 후 값이 바뀌면 안 되는 상수이다.  
D. 반드시 데이터베이스 테이블 필드와 연결되어야 한다.

**정답:** C

#### Q3. `TYPES`에 대한 설명으로 올바른 것은?

A. 값을 저장하는 변수이다.  
B. 실행 가능한 프로그램 이름이다.  
C. 새로운 타입 이름을 정의한다.  
D. 화면에 결과를 출력한다.

**정답:** C

#### Q4. 소수점 2자리 금액 계산에 가장 적합한 초급 타입 선언은?

A. `TYPE i`  
B. `TYPE c LENGTH 10`  
C. `TYPE p LENGTH 8 DECIMALS 2`  
D. `TYPE n LENGTH 10`

**정답:** C

#### Q5. 문서번호 `0000001234`처럼 앞자리 0이 의미 있는 값에 더 적합한 타입은?

A. `I`  
B. `N LENGTH 10`  
C. `F`  
D. `D`

**정답:** B

### 27.2 단답형

#### Q1. `DATA`, `CONSTANTS`, `TYPES`의 차이를 설명하시오.

**모범 답안:**  
`DATA`는 실행 중 값이 바뀔 수 있는 변수를 선언한다. `CONSTANTS`는 선언 후 값이 바뀌면 안 되는 상수를 선언한다. `TYPES`는 값을 저장하지 않고 재사용 가능한 타입 이름을 정의한다.

#### Q2. `TYPE`과 `LIKE`의 차이를 설명하시오.

**모범 답안:**  
`TYPE`은 명시한 타입 이름을 기준으로 변수를 선언한다. `LIKE`는 이미 존재하는 변수나 테이블 필드와 같은 속성을 가지도록 변수를 선언한다.

#### Q3. 하드코딩된 문자 `'A'` 대신 상수를 사용하는 이유를 설명하시오.

**모범 답안:**  
상수명을 통해 값의 업무 의미를 드러낼 수 있고, 같은 값을 여러 곳에 반복하지 않아 유지보수성이 좋아지며, 오타로 인한 조건 오류를 줄일 수 있다.

## 29. 후속 모듈 연결

이번 모듈에서는 값을 담고 처리하기 위한 선언문을 배웠다.  
다음 모듈인 `THEORY-02-M03 — WRITE 기본 출력`에서는 선언한 값을 화면에 출력하는 방법을 더 자세히 다룬다.

연결 흐름은 다음과 같다.

```text
THEORY-02-M01
ABAP Program 기본 구조와 주석
  ↓
THEORY-02-M02
DATA / CONSTANTS / TYPES 선언
  ↓
THEORY-02-M03
WRITE 기본 출력
```

이후 모듈에서는 선언한 변수를 조건문, 반복문, 문자열 처리, 시스템 필드와 함께 사용한다.

```text
선언한 변수
→ WRITE로 출력
→ IF/CASE로 조건 판단
→ DO/WHILE로 반복
→ 문자열/날짜/시스템 필드와 결합
```

## 30. 핵심 요약

이번 모듈의 핵심 문장은 다음과 같다.

```text
DATA는 값을 담는 변수이다.
CONSTANTS는 변경하면 안 되는 고정값이다.
TYPES는 값을 담지 않고 타입 이름을 정의한다.
Elementary Type은 ABAP 데이터 처리의 가장 기본 단위이다.
DDIC와 연결되는 값은 가능하면 DDIC 타입을 참조하는 것이 실무적으로 안전하다.
```

초급자는 선언문을 단순 암기하지 말고, 다음 질문을 항상 함께 생각해야 한다.

```text
이 값은 바뀌는가?
이 값은 고정 코드인가?
이 값은 계산용 숫자인가, 번호성 문자값인가?
소수점이 필요한가?
DB 필드와 타입을 맞춰야 하는가?
```

이 질문에 답할 수 있으면 ABAP 변수 선언의 기본 방향을 잡을 수 있다.
