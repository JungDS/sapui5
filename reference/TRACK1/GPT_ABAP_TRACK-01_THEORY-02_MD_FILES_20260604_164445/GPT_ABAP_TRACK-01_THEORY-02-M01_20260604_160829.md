## 2. ABAP Program이란 무엇인가?

ABAP Program은 SAP 시스템 안에서 실행되는 개발 객체이다.  
초급 단계에서는 “ABAP으로 작성한 실행 가능한 코드 단위”라고 이해하면 된다.

ABAP 프로그램은 여러 종류가 있지만, 초급자가 가장 먼저 배우는 것은 보통 **Executable Program**, 즉 Report Program이다.

### 2.1 Report Program의 기본 개념

Report Program은 전통적으로 다음 흐름을 가진다.

```text
사용자가 프로그램 실행
→ 프로그램이 필요한 데이터 처리
→ 결과를 리스트 화면 또는 다른 출력 방식으로 표시
```

가장 단순한 Report는 데이터베이스를 읽지 않고도 실행될 수 있다.  
예를 들어 화면에 문장 하나만 출력하는 프로그램도 완전한 Report Program이다.

```abap
REPORT zjy_theory_02_m01_hello.

WRITE: / 'Hello, ABAP'.
```

이 예제는 짧지만 중요한 요소를 모두 포함한다.

| 요소 | 의미 |
|---|---|
| `REPORT` | 프로그램 시작부에서 Report Program을 정의 |
| 프로그램명 | Repository에 저장되는 ABAP 프로그램 이름 |
| `WRITE` | 리스트 화면에 텍스트를 출력 |
| 마침표 `.` | ABAP 문장의 끝 |

## 3. ABAP Report Program의 최소 구조

가장 작은 Report Program은 다음과 같은 형태를 가진다.

```abap
REPORT zjy_theory_02_m01_min.

WRITE: / 'My first ABAP program'.
```

이 프로그램은 두 개의 핵심 문장으로 구성된다.

```text
REPORT 문장
WRITE 문장
```

### 3.1 REPORT 문장

`REPORT` 문장은 프로그램의 기본 속성을 선언하는 문장이다.

```abap
REPORT zjy_theory_02_m01_min.
```

초급 단계에서는 다음 원칙을 기억한다.

| 원칙 | 설명 |
|---|---|
| 보통 첫 번째 실행 문장으로 작성 | 프로그램의 정체성을 선언한다. |
| 프로그램명과 일치해야 함 | Repository 객체명과 동일한 이름을 사용한다. |
| 마침표로 끝남 | ABAP 문장은 마침표 `.`로 종료된다. |
| 고객 개발 프로그램은 `Z` 또는 `Y`로 시작 | 표준 네임스페이스와 구분한다. |

### 3.2 WRITE 문장

`WRITE`는 리스트 화면에 값을 출력하는 고전 ABAP 출력 구문이다.

```abap
WRITE: / 'My first ABAP program'.
```

여기서 `/`는 새 줄 출력을 의미한다.

| 구문 | 의미 |
|---|---|
| `WRITE 'ABC'.` | 현재 위치에 출력 |
| `WRITE: / 'ABC'.` | 새 줄에 출력 |
| `WRITE: / 'A', 'B'.` | 같은 줄에 여러 값 출력 |

`WRITE`의 상세 포맷, 위치 지정, 색상, 정렬 등은 후속 모듈에서 단계적으로 다룬다.  
이번 모듈에서는 “프로그램 실행 결과를 확인하기 위한 최소 출력 도구”로만 사용한다.

## 4. 프로그램명 Naming Rule

SAP 고객 개발 객체는 일반적으로 `Z` 또는 `Y`로 시작한다.  
교육용 프로그램도 이 규칙을 따르는 것이 좋다.

### 4.1 교육용 이름 예시

```text
ZJY_THEORY_02_M01_HELLO
ZJY_WRITE_FIRST
ZJY_REPORT_BASIC
```

### 4.2 좋은 이름과 나쁜 이름

| 구분 | 예시 | 평가 |
|---|---|---|
| 좋은 이름 | `ZJY_THEORY_02_M01_HELLO` | 학습 위치와 목적이 드러난다. |
| 좋은 이름 | `ZJY_REPORT_BASIC` | Report 기본 예제임을 알 수 있다. |
| 나쁜 이름 | `ZTEST` | 의미가 너무 넓다. |
| 나쁜 이름 | `ZABC` | 목적을 알 수 없다. |
| 나쁜 이름 | `Z_TEMP_01` | 임시 객체처럼 보인다. |

실무에서는 회사 또는 프로젝트별 Naming Convention을 따른다.  
교육 과정에서는 Section과 Module 번호를 이름에 포함하면 이후 복습과 정리가 쉽다.

## 5. SAP GUI 800에서 프로그램 생성하기

### 5.1 SE38 사용 흐름

SAP GUI 800 기준으로 가장 단순한 Report 생성 흐름은 다음과 같다.

```text
1. SAP GUI 로그인
2. Command Field에 SE38 입력
3. Program에 ZJY_THEORY_02_M01_HELLO 입력
4. Create 버튼 선택
5. Program Type에서 Executable Program 선택
6. Title 입력
7. Save
8. Package 또는 Local Object 선택
9. 코드 작성
10. Syntax Check
11. Activate
12. Execute
```

### 5.2 Program Attributes

프로그램 생성 시 기본 속성 화면이 나타날 수 있다.

| 항목 | 설명 |
|---|---|
| Title | 프로그램 설명 |
| Type | 프로그램 유형 |
| Status | 개발 상태 또는 용도 분류 |
| Application | 프로그램이 속한 애플리케이션 영역 |
| Package | Repository 객체를 관리할 패키지 |

초급 실습에서는 다음 정도로 설정해도 충분하다.

| 항목 | 교육용 예시 |
|---|---|
| Program | `ZJY_THEORY_02_M01_HELLO` |
| Title | `ABAP Program Basic Structure` |
| Type | Executable Program |
| Package | `$TMP` 또는 강사 지정 패키지 |

`$TMP`는 Local Object를 의미하며 Transport Request 없이 로컬 개발 객체로 저장된다.  
실무 프로젝트에서는 반드시 프로젝트 Package와 Transport Request 정책을 따른다.

## 6. ADT에서 프로그램 생성하기

S/4HANA 기반 개발에서는 Eclipse ADT를 사용하는 경우도 많다.  
ADT에서 Report Program을 만들 때는 보통 ABAP Project에서 New ABAP Program을 선택한다.

일반 흐름은 다음과 같다.

```text
1. Eclipse ADT 실행
2. ABAP Project 선택
3. Package 선택
4. New → ABAP Program
5. Name 입력
6. Description 입력
7. Transport 또는 Package 선택
8. Finish
9. 코드 작성
10. Activate
11. Run As → ABAP Application
```

초급자는 SAP GUI `SE38` 흐름을 먼저 익힌 뒤 ADT 흐름을 비교하면 좋다.

| 관점 | SAP GUI | ADT |
|---|---|---|
| 대표 도구 | SE38, SE80 | Eclipse ADT |
| 장점 | 전통적이고 대부분 시스템에서 접근 가능 | 코드 편집, 검색, Git 친화적 |
| 단점 | 대규모 개발 생산성은 ADT보다 낮을 수 있음 | 초기 환경 설정 필요 |
| 교육 추천 | 초급 첫 실습에 적합 | 이후 현대 개발 흐름에 적합 |

## 7. 저장, 문법검사, 활성화, 실행

ABAP 초급자는 다음 네 단계를 자주 혼동한다.

```text
Save
Syntax Check
Activate
Execute
```

각 단계의 의미는 다르다.

| 단계 | 의미 | 초급자 이해 |
|---|---|---|
| Save | 작성한 소스 코드를 Repository에 저장 | 파일 저장과 유사 |
| Syntax Check | 문법 오류가 있는지 검사 | 컴파일 전 검문 |
| Activate | 실행 가능한 활성 버전을 생성 | 시스템에서 사용할 수 있게 반영 |
| Execute | 프로그램을 실제 실행 | 결과 확인 |

### 7.1 Save

Save는 현재 코드 내용을 저장한다.  
하지만 저장만 했다고 해서 프로그램이 실행 가능한 상태가 되는 것은 아니다.

### 7.2 Syntax Check

Syntax Check는 문법 오류를 확인한다.

예를 들어 마침표를 빠뜨리면 오류가 발생한다.

```abap
REPORT zjy_error_example

WRITE: / 'Hello'.
```

위 코드는 `REPORT` 문장 끝에 마침표가 없으므로 문법 오류가 발생한다.

수정:

```abap
REPORT zjy_error_example.

WRITE: / 'Hello'.
```

### 7.3 Activate

Activate는 프로그램의 활성 버전을 생성한다.  
ABAP Repository 객체는 변경된 소스가 있더라도 활성화되지 않으면 이전 활성 버전이 사용될 수 있다.

초급자는 다음 문장을 기억해야 한다.

```text
코드를 수정했다면 저장만 하지 말고 반드시 활성화한다.
```

### 7.4 Execute

프로그램 실행은 SAP GUI에서 F8 또는 Execute 버튼으로 수행한다.  
ADT에서는 Run As → ABAP Application 또는 관련 실행 메뉴를 사용한다.

실행 결과는 단순 Report의 경우 리스트 화면에 표시된다.

## 9. 주석의 목적

주석은 프로그램 실행에는 영향을 주지 않는 설명 문장이다.  
하지만 좋은 주석은 개발자와 유지보수자에게 매우 중요한 정보를 제공한다.

ABAP에서 대표적인 주석 방식은 다음과 같다.

| 방식 | 예시 | 설명 |
|---|---|---|
| 전체 행 주석 | `* This is comment` | 행 첫 번째 위치에 `*` |
| 인라인 주석 | `" comment` | 큰따옴표 뒤부터 주석 |
| 구간 설명 | 여러 줄 주석 블록 | 코드 영역 설명 |

### 9.1 전체 행 주석

```abap
*----------------------------------------------------------------------*
* Program : ZJY_THEORY_02_M01_HELLO
* Purpose : First ABAP report example
*----------------------------------------------------------------------*
REPORT zjy_theory_02_m01_hello.

WRITE: / 'Hello, ABAP'.
```

`*`는 행의 첫 번째 위치에 있을 때 전체 행 주석으로 사용된다.

### 9.2 인라인 주석

```abap
WRITE: / 'Hello, ABAP'. " Print greeting text
```

큰따옴표 `"` 뒤에 오는 내용은 주석이다.

### 9.3 주석 사용 시 주의점

주석은 많이 쓴다고 좋은 것이 아니다.  
좋은 주석은 “코드가 무엇을 하는지”보다 “왜 그렇게 하는지”를 설명한다.

나쁜 주석:

```abap
WRITE: / 'Hello'. " Hello를 출력한다
```

이 주석은 코드만 봐도 알 수 있는 내용을 반복한다.

좋은 주석:

```abap
* Training output is intentionally simple so beginners can focus on
* activation and execution flow before learning variables.
WRITE: / 'Hello, ABAP'.
```

이 주석은 왜 단순한 출력을 사용하는지 설명한다.

## 11. ABAP 문장의 기본 규칙

초급자가 처음에 반드시 익혀야 하는 규칙은 다음이다.

### 11.1 마침표

ABAP 문장은 마침표 `.`로 끝난다.

```abap
WRITE: / 'Hello'.
```

마침표가 없으면 다음 문장과 연결되어 Syntax Error가 발생할 수 있다.

### 11.2 대소문자

ABAP 키워드는 대소문자를 크게 구분하지 않지만, 교육과 실무에서는 가독성을 위해 일관된 스타일을 사용한다.

예:

```abap
REPORT zjy_theory_02_m01_case.

WRITE: / 'Keyword style example'.
```

또는

```abap
report zjy_theory_02_m01_case.

write: / 'Keyword style example'.
```

둘 다 동작할 수 있지만, 교육 자료에서는 키워드를 대문자로 표기하는 방식이 설명에 유리하다.

실무에서는 프로젝트의 코드 스타일 기준을 따른다.

### 11.3 문자열 리터럴

문자열은 작은따옴표 `'`로 감싼다.

```abap
WRITE: / 'Hello ABAP'.
```

문자열 안에 작은따옴표를 넣어야 할 경우에는 이스케이프 처리가 필요할 수 있다.  
이 내용은 문자열 심화 모듈에서 다룬다.

### 11.4 명령어와 식별자

ABAP 문장은 키워드와 식별자로 구성된다.

```abap
REPORT zjy_theory_02_m01_hello.
```

| 요소 | 의미 |
|---|---|
| `REPORT` | ABAP 키워드 |
| `zjy_theory_02_m01_hello` | 프로그램 식별자 |

## 12. 자주 발생하는 오류

### 12.1 마침표 누락

오류 코드 예:

```abap
REPORT zjy_theory_02_m01_error

WRITE: / 'Hello'.
```

원인:

```text
REPORT 문장 끝에 마침표가 없다.
```

수정:

```abap
REPORT zjy_theory_02_m01_error.

WRITE: / 'Hello'.
```

### 12.2 프로그램명 불일치

상황:

```abap
REPORT zjy_other_name.
```

하지만 Repository 객체명은 `ZJY_THEORY_02_M01_HELLO`일 수 있다.

문제:

프로그램명과 `REPORT` 이름이 다르면 시스템 또는 개발 도구에서 경고나 혼란이 생길 수 있다.  
교육용에서는 객체명과 `REPORT`명을 일치시킨다.

### 12.3 문자열 따옴표 누락

오류 코드:

```abap
WRITE: / 'Hello ABAP.
```

원인:

문자열을 닫는 작은따옴표가 없다.

수정:

```abap
WRITE: / 'Hello ABAP'.
```

### 12.4 활성화하지 않고 실행

상황:

코드를 수정했지만 Activate하지 않고 실행했다.

문제:

실행 결과가 기대와 다를 수 있다.  
이전 활성 버전이 실행되거나, 실행 가능한 최신 버전이 반영되지 않았을 수 있다.

해결:

```text
수정 → 저장 → 문법검사 → 활성화 → 실행
```

### 12.5 권한 부족

상황:

SE38에서 프로그램 생성 또는 실행이 되지 않는다.

가능한 원인:

- 개발 권한 없음
- 패키지/Transport 권한 부족
- 특정 Namespace 생성 권한 부족
- 운영 시스템에서 개발 금지

해결:

교육 시스템, 개발 시스템, 권한 Role을 확인한다.  
운영 시스템에서는 직접 개발하지 않는 것이 일반적이다.

## 13. Syntax Error와 Runtime Error의 차이

초급자는 오류를 모두 같은 것으로 생각하기 쉽다.  
그러나 오류에는 여러 유형이 있다.

| 오류 유형 | 발생 시점 | 예시 |
|---|---|---|
| Syntax Error | 활성화 또는 문법검사 시점 | 마침표 누락, 따옴표 누락 |
| Activation Error | 객체 활성화 시점 | 참조 객체 비활성, 구문 오류 |
| Runtime Error | 실행 중 | 0으로 나누기, 타입 변환 오류 |
| Authorization Error | 작업 수행 시 | 개발/실행 권한 부족 |

이번 모듈에서는 Syntax Error와 Activation Error를 중심으로 이해한다.  
Runtime Error와 ST22는 후속 실습에서 더 자주 다룬다.

## 14. 실무에서 주석을 잘 쓰는 기준

### 14.1 주석이 필요한 경우

| 상황 | 좋은 주석 방향 |
|---|---|
| 업무 규칙이 코드만으로 드러나지 않음 | 왜 이 조건이 필요한지 설명 |
| 예외 처리 사유가 복잡함 | 어떤 현업 상황 때문인지 설명 |
| 임시 조치가 포함됨 | 만료 기준과 후속 조치 기록 |
| 성능상 의도적인 선택 | 왜 다른 구현을 쓰지 않았는지 설명 |
| 교육용 코드 | 학습자가 주목해야 할 포인트 설명 |

### 14.2 주석이 불필요한 경우

| 상황 | 이유 |
|---|---|
| 코드 자체가 명확함 | 중복 설명은 오히려 방해 |
| 오래된 주석 | 실제 코드와 다르면 위험 |
| TODO만 남긴 주석 | 책임과 기한이 없으면 관리 안 됨 |
| 코드 비활성화 용도 | 장기간 주석 처리 코드는 삭제 또는 버전관리로 관리 |

### 14.3 좋은 주석 예

```abap
* The example intentionally avoids variables.
* Variables are introduced in THEORY-02-M02.
WRITE: / 'Hello, ABAP'.
```

이 주석은 학습 범위를 통제하는 목적이 명확하다.

### 14.4 나쁜 주석 예

```abap
WRITE: / 'Hello, ABAP'. " Hello, ABAP을 출력한다
```

이 주석은 코드와 같은 말을 반복할 뿐이다.

## 16. 강사용 설명 포인트

강의에서 강조해야 할 포인트는 다음이다.

### 16.1 첫 목표는 문법 암기가 아니라 실행 흐름 체득

초급자는 첫 시간부터 많은 문법을 배우면 혼란을 느낀다.  
따라서 이번 모듈에서는 다음 흐름을 몸에 익히는 것이 우선이다.

```text
프로그램 생성
→ 코드 입력
→ 저장
→ 문법검사
→ 활성화
→ 실행
→ 결과 확인
→ 오류 수정
```

### 16.2 `REPORT`는 단순한 장식 문장이 아니다

`REPORT`는 프로그램의 기본 선언부이다.  
Report Program이 어떤 이름으로 Repository에 존재하는지 명확히 보여준다.

### 16.3 주석은 초급자에게 학습 안내판이다

교육용 코드에서는 주석이 학습 범위를 통제하는 도구가 된다.  
예를 들어 이번 모듈에서 변수를 일부러 사용하지 않는 이유를 주석으로 설명하면 다음 모듈과의 선후수가 명확해진다.

### 16.4 오류를 숨기지 말고 기록하게 한다

초급자가 성장하려면 오류 메시지를 읽는 습관이 중요하다.  
특히 마침표 누락, 따옴표 누락, 활성화 누락은 초반에 반드시 경험하게 하는 것이 좋다.

## 17. 후속 모듈과의 연결

이번 모듈에서는 가장 작은 실행 가능한 Report Program을 만들었다.  
다음 모듈 `THEORY-02-M02 — DATA / CONSTANTS / TYPES 선언`에서는 프로그램 안에 데이터를 담는 기본 방법을 배운다.

연결 흐름은 다음과 같다.

```text
THEORY-02-M01
  ABAP Program 기본 구조와 주석
  → 프로그램 생성, REPORT, 주석, 활성화, 실행

THEORY-02-M02
  DATA / CONSTANTS / TYPES 선언
  → 변수, 상수, 로컬 타입 선언

THEORY-02-M03
  WRITE 기본 출력
  → 값 출력과 기본 포맷

THEORY-02-M04
  IF / CASE 조건 분기
  → 조건에 따른 실행 흐름 제어

THEORY-02-M05
  DO / WHILE 반복 처리
  → 반복 실행 흐름 제어

THEORY-02-M06
  문자열, 날짜, 시스템 필드 기초
  → 기본 문자열 처리와 SY 필드 활용
```

## 18. 평가 문제

### 18.1 객관식

#### Q1. 가장 작은 실행 가능한 ABAP Report Program에 일반적으로 포함되는 기본 선언은?

A. `CLASS-DATA`  
B. `REPORT`  
C. `SELECT-OPTIONS`  
D. `CALL SCREEN`

정답: B

#### Q2. ABAP 문장의 끝을 나타내는 기호는?

A. 세미콜론 `;`  
B. 콜론 `:`  
C. 마침표 `.`  
D. 쉼표 `,`

정답: C

#### Q3. 저장과 활성화의 차이로 가장 적절한 설명은?

A. 저장은 프로그램 실행이고 활성화는 출력이다.  
B. 저장은 소스 변경을 보관하는 것이고, 활성화는 실행 가능한 활성 버전을 만드는 것이다.  
C. 저장과 활성화는 완전히 같은 동작이다.  
D. 활성화는 주석을 삭제하는 기능이다.

정답: B

### 18.2 단답형

#### Q1. `REPORT` 문장의 역할을 설명하시오.

모범 답안:  
`REPORT` 문장은 ABAP Report Program의 기본 선언부로, 프로그램의 이름과 실행 가능한 Report의 시작을 나타낸다.

#### Q2. ABAP에서 주석을 사용하는 목적을 설명하시오.

모범 답안:  
주석은 프로그램 실행에는 영향을 주지 않지만, 코드의 의도, 업무 배경, 학습 포인트, 유지보수상 주의점을 설명하기 위해 사용한다.

#### Q3. 초급자가 가장 자주 하는 문법 오류 두 가지를 쓰시오.

모범 답안:  
마침표 누락, 문자열 따옴표 누락, 프로그램명 불일치, 활성화 누락 등이 있다.

### 18.3 실습 리뷰

다음 코드를 보고 문제를 찾으시오.

```abap
REPORT zjy_theory_02_m01_review

WRITE: / 'Hello ABAP'.
```

모범 답안:  
`REPORT` 문장 끝에 마침표가 없다. 다음처럼 수정해야 한다.

```abap
REPORT zjy_theory_02_m01_review.

WRITE: / 'Hello ABAP'.
```
