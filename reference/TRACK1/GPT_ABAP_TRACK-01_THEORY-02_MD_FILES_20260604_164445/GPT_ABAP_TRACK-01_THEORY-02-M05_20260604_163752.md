## 0. 이 문서의 학습 범위

이 문서는 `THEORY-02-M05 — DO / WHILE 반복 처리`만 다룬다.

이번 모듈의 핵심은 다음 네 가지이다.

| 키워드 | 의미 |
|---|---|
| `DO` | 정해진 횟수만큼 또는 명시적으로 종료될 때까지 반복하는 기본 반복문 |
| `WHILE` | 조건이 참인 동안 반복하는 조건 기반 반복문 |
| `EXIT` | 현재 반복문을 즉시 종료하는 흐름 제어문 |
| `CONTINUE` | 현재 반복 회차의 남은 처리를 건너뛰고 다음 반복으로 이동하는 흐름 제어문 |

이번 모듈은 앞선 `IF / CASE 조건 분기` 이후에 배치된다.  
조건 분기는 “상황에 따라 어느 길로 갈 것인가”를 결정하고, 반복 처리는 “같은 일을 몇 번 또는 언제까지 수행할 것인가”를 결정한다.

```text
조건 분기: 한 번의 판단으로 실행 경로를 나눈다.
반복 처리: 같은 처리 블록을 여러 번 실행한다.
```

## 3. 반복 처리가 필요한 이유

프로그램은 같은 처리를 여러 번 수행해야 하는 경우가 많다.

예를 들어 다음과 같은 요구사항을 생각해보자.

```text
1부터 5까지 숫자를 출력한다.
사용자가 입력한 횟수만큼 메시지를 출력한다.
누적 합계를 계산한다.
조건이 만족될 때까지 값을 증가시킨다.
특정 조건을 만나면 반복을 중단한다.
```

반복문이 없다면 같은 코드를 여러 번 써야 한다.

```abap
WRITE: / 1.
WRITE: / 2.
WRITE: / 3.
WRITE: / 4.
WRITE: / 5.
```

이 방식은 단순하지만 좋지 않다.

| 문제 | 설명 |
|---|---|
| 반복 코드 증가 | 횟수가 늘어나면 코드가 길어진다. |
| 변경 어려움 | 출력 형식을 바꾸려면 여러 줄을 고쳐야 한다. |
| 실수 가능성 | 일부 줄만 다르게 수정될 수 있다. |
| 확장 불가 | 5회가 아니라 500회라면 현실적이지 않다. |

반복문을 사용하면 같은 일을 간결하게 표현할 수 있다.

```abap
DO 5 TIMES.
  WRITE: / sy-index.
ENDDO.
```

## 4. `DO` 반복문의 기본 구조

### 4.1 기본 문법

`DO` 반복문의 기본 문법은 다음과 같다.

```abap
DO n TIMES.
  " 반복할 처리
ENDDO.
```

예제:

```abap
REPORT zgpt_do_basic.

DO 5 TIMES.
  WRITE: / '현재 반복:', sy-index.
ENDDO.
```

실행 결과의 의미는 다음과 같다.

```text
현재 반복: 1
현재 반복: 2
현재 반복: 3
현재 반복: 4
현재 반복: 5
```

### 4.2 `sy-index`

`sy-index`는 반복문 내부에서 현재 반복 횟수를 나타내는 시스템 필드이다.

| 항목 | 설명 |
|---|---|
| 이름 | `sy-index` |
| 의미 | 현재 반복 회차 |
| 시작값 | 일반적으로 1 |
| 사용 위치 | `DO`, `WHILE` 반복문 내부 |
| 주의 | 중첩 반복문에서는 현재 반복 수준에 따라 값 이해에 주의해야 한다. |

초급자는 먼저 다음처럼 이해하면 충분하다.

```text
반복문 안에서 sy-index는 지금 몇 번째 반복인지 알려준다.
```

### 4.3 `DO n TIMES`의 특징

`DO n TIMES`는 반복 횟수가 명확할 때 사용한다.

예:

```abap
REPORT zgpt_do_times.

DATA gv_total TYPE i.

DO 10 TIMES.
  gv_total = gv_total + sy-index.
ENDDO.

WRITE: / '1부터 10까지 합계:', gv_total.
```

이 예제는 1부터 10까지의 합계를 계산한다.

| 반복 회차 | `sy-index` | 누적 합계 |
|---:|---:|---:|
| 1 | 1 | 1 |
| 2 | 2 | 3 |
| 3 | 3 | 6 |
| ... | ... | ... |
| 10 | 10 | 55 |

## 5. `DO`와 조건 분기 함께 사용하기

반복문은 조건문과 함께 사용할 때 실무적 의미가 커진다.

예를 들어 1부터 10까지 출력하되, 짝수만 출력한다고 하자.

```abap
REPORT zgpt_do_if_even.

DO 10 TIMES.
  IF sy-index MOD 2 = 0.
    WRITE: / '짝수:', sy-index.
  ENDIF.
ENDDO.
```

여기서 `MOD`는 나머지를 계산하는 연산자이다.  
`sy-index MOD 2 = 0`은 현재 숫자를 2로 나누었을 때 나머지가 0이라는 뜻이므로 짝수를 의미한다.

실행 결과:

```text
짝수: 2
짝수: 4
짝수: 6
짝수: 8
짝수: 10
```

초급자 관점에서 중요한 구조는 다음이다.

```text
반복한다.
→ 매 반복마다 조건을 검사한다.
→ 조건이 맞을 때만 특정 처리를 한다.
```

## 6. `WHILE` 반복문의 기본 구조

### 6.1 기본 문법

`WHILE`은 조건이 참인 동안 반복한다.

```abap
WHILE condition.
  " 반복할 처리
ENDWHILE.
```

예제:

```abap
REPORT zgpt_while_basic.

DATA gv_count TYPE i VALUE 1.

WHILE gv_count <= 5.
  WRITE: / '현재 값:', gv_count.
  gv_count = gv_count + 1.
ENDWHILE.
```

실행 결과:

```text
현재 값: 1
현재 값: 2
현재 값: 3
현재 값: 4
현재 값: 5
```

### 6.2 `WHILE`의 핵심

`WHILE`에서는 반복 조건을 바꾸는 처리가 반드시 필요하다.

위 예제에서는 다음 코드가 조건을 변화시킨다.

```abap
gv_count = gv_count + 1.
```

이 코드가 없다면 `gv_count`는 계속 1이고, `gv_count <= 5` 조건은 계속 참이므로 무한 루프가 발생한다.

## 7. `DO`와 `WHILE`의 차이

| 구분 | `DO n TIMES` | `WHILE` |
|---|---|---|
| 반복 기준 | 횟수 | 조건 |
| 적합한 상황 | 몇 번 반복할지 명확할 때 | 특정 조건이 만족되는 동안 반복할 때 |
| 종료 방식 | 횟수 완료 또는 `EXIT` | 조건이 거짓이 되거나 `EXIT` |
| 무한 루프 위험 | `DO.`만 사용하면 높음 | 조건 변경 누락 시 높음 |
| 초급 사용 난이도 | 비교적 쉬움 | 조건 설계가 필요함 |

### 7.1 `DO`가 더 적합한 예

```text
5번 출력한다.
10개의 테스트 데이터를 만든다.
3회 재시도한다.
고정된 횟수만큼 계산한다.
```

### 7.2 `WHILE`이 더 적합한 예

```text
값이 특정 기준에 도달할 때까지 증가시킨다.
사용 가능한 번호를 찾을 때까지 반복한다.
조건이 만족되는 동안 입력값을 검증한다.
```

## 8. `EXIT`

### 8.1 `EXIT`의 의미

`EXIT`는 현재 반복문을 즉시 종료한다.

예제:

```abap
REPORT zgpt_exit_basic.

DO 10 TIMES.
  IF sy-index = 4.
    EXIT.
  ENDIF.

  WRITE: / '반복:', sy-index.
ENDDO.

WRITE: / '반복 종료'.
```

실행 결과:

```text
반복: 1
반복: 2
반복: 3
반복 종료
```

`sy-index = 4`가 되는 순간 `EXIT`가 실행되므로 반복문을 빠져나간다.  
따라서 4는 출력되지 않는다.

### 8.2 `EXIT`를 사용하는 상황

| 상황 | 설명 |
|---|---|
| 원하는 값을 찾음 | 더 이상 반복할 필요가 없음 |
| 오류 조건 발생 | 반복을 계속하면 의미가 없음 |
| 최대 시도 횟수 이전에 성공 | 성공 즉시 반복 종료 |
| 데이터 검증 실패 | 후속 처리를 중단 |

예:

```abap
REPORT zgpt_exit_find.

DATA gv_target TYPE i VALUE 7.

DO 10 TIMES.
  IF sy-index = gv_target.
    WRITE: / '찾은 값:', sy-index.
    EXIT.
  ENDIF.
ENDDO.
```

### 8.3 `EXIT` 남용 주의

`EXIT`는 편리하지만 너무 많이 사용하면 코드 흐름을 읽기 어려워진다.

나쁜 예:

```abap
DO 100 TIMES.
  IF condition1 = abap_true.
    EXIT.
  ENDIF.

  IF condition2 = abap_true.
    EXIT.
  ENDIF.

  IF condition3 = abap_true.
    EXIT.
  ENDIF.
ENDDO.
```

이런 코드는 반복문이 언제 끝나는지 파악하기 어렵다.  
실무에서는 종료 조건을 명확히 만들거나, 반복 내부 로직을 메서드로 분리하는 방식이 더 좋을 수 있다.

## 9. `CONTINUE`

### 9.1 `CONTINUE`의 의미

`CONTINUE`는 현재 반복 회차의 남은 처리를 건너뛰고 다음 반복으로 이동한다.

예제:

```abap
REPORT zgpt_continue_basic.

DO 5 TIMES.
  IF sy-index = 3.
    CONTINUE.
  ENDIF.

  WRITE: / '출력:', sy-index.
ENDDO.
```

실행 결과:

```text
출력: 1
출력: 2
출력: 4
출력: 5
```

`sy-index = 3`인 회차에서는 `CONTINUE`가 실행되므로 그 아래의 `WRITE`가 실행되지 않는다.

### 9.2 `CONTINUE`를 사용하는 상황

| 상황 | 설명 |
|---|---|
| 특정 데이터는 건너뛰고 싶을 때 | 조건에 맞지 않는 데이터 제외 |
| 오류 데이터만 제외하고 계속 처리 | 전체 반복은 유지 |
| 필터링 로직 | 조건 불일치 시 다음 건으로 이동 |

예:

```abap
REPORT zgpt_continue_even.

DO 10 TIMES.
  IF sy-index MOD 2 <> 0.
    CONTINUE.
  ENDIF.

  WRITE: / '짝수:', sy-index.
ENDDO.
```

이 예제는 홀수 회차를 건너뛰고 짝수만 출력한다.

## 10. `EXIT`와 `CONTINUE`의 차이

| 구분 | `EXIT` | `CONTINUE` |
|---|---|---|
| 의미 | 반복문 자체를 종료 | 현재 회차만 건너뜀 |
| 다음 반복 수행 | 하지 않음 | 수행함 |
| 사용 상황 | 더 이상 반복할 필요가 없을 때 | 일부 회차만 제외하고 싶을 때 |
| 흐름 영향 | 큼 | 중간 |
| 초급자 주의 | 반복 종료 위치를 명확히 해야 함 | 건너뛴 처리 내용을 이해해야 함 |

비교 예제:

```abap
REPORT zgpt_exit_continue_compare.

WRITE: / '--- EXIT 예제 ---'.

DO 5 TIMES.
  IF sy-index = 3.
    EXIT.
  ENDIF.
  WRITE: / sy-index.
ENDDO.

WRITE: / '--- CONTINUE 예제 ---'.

DO 5 TIMES.
  IF sy-index = 3.
    CONTINUE.
  ENDIF.
  WRITE: / sy-index.
ENDDO.
```

예상 출력:

```text
--- EXIT 예제 ---
1
2
--- CONTINUE 예제 ---
1
2
4
5
```

## 11. 무한 루프

### 11.1 무한 루프란?

무한 루프는 반복이 끝나지 않고 계속 실행되는 상황이다.

대표적인 원인은 다음과 같다.

| 원인 | 설명 |
|---|---|
| `WHILE` 조건이 계속 참 | 조건을 바꾸는 처리가 없음 |
| `DO.`만 사용하고 `EXIT` 없음 | 종료 조건이 없음 |
| 조건 변경 위치 오류 | 조건 변경 코드가 실행되지 않음 |
| 잘못된 비교 조건 | 종료 조건이 절대 만족되지 않음 |

### 11.2 잘못된 `WHILE` 예제

```abap
REPORT zgpt_infinite_bad.

DATA gv_count TYPE i VALUE 1.

WHILE gv_count <= 5.
  WRITE: / gv_count.
ENDWHILE.
```

위 코드는 `gv_count`가 증가하지 않으므로 계속 1만 출력하려고 한다.  
실제 교육 시스템에서 이런 코드는 실행하지 않는 것이 좋다.

### 11.3 올바른 수정

```abap
REPORT zgpt_infinite_fixed.

DATA gv_count TYPE i VALUE 1.

WHILE gv_count <= 5.
  WRITE: / gv_count.
  gv_count = gv_count + 1.
ENDWHILE.
```

### 11.4 안전 장치

조건 기반 반복문에는 안전 장치를 둘 수 있다.

```abap
REPORT zgpt_while_guard.

DATA gv_count TYPE i VALUE 1.
DATA gv_guard TYPE i VALUE 0.

WHILE gv_count <= 5.
  gv_guard = gv_guard + 1.

  IF gv_guard > 100.
    WRITE: / '반복이 너무 많아 중단합니다.'.
    EXIT.
  ENDIF.

  WRITE: / gv_count.
  gv_count = gv_count + 1.
ENDWHILE.
```

초급 실습에서는 반복 조건을 잘못 작성할 수 있으므로, 복잡한 `WHILE`에서는 최대 반복 횟수를 방어적으로 두는 습관이 도움이 된다.

## 12. 중첩 반복문

### 12.1 기본 개념

반복문 안에 또 다른 반복문을 넣을 수 있다.

```abap
REPORT zgpt_nested_do.

DO 3 TIMES.
  DATA(gv_outer) = sy-index.

  DO 2 TIMES.
    WRITE: / 'Outer:', gv_outer, 'Inner:', sy-index.
  ENDDO.
ENDDO.
```

예상 출력:

```text
Outer: 1 Inner: 1
Outer: 1 Inner: 2
Outer: 2 Inner: 1
Outer: 2 Inner: 2
Outer: 3 Inner: 1
Outer: 3 Inner: 2
```

### 12.2 중첩 반복문 주의점

중첩 반복문은 데이터 처리에서 자주 등장하지만, 성능과 가독성 문제가 생기기 쉽다.

| 문제 | 설명 |
|---|---|
| 반복 횟수 폭증 | 바깥 1,000건 × 안쪽 1,000건 = 1,000,000회 |
| `sy-index` 혼동 | 안쪽 반복문의 `sy-index`가 바깥 값을 덮어 보일 수 있음 |
| 가독성 저하 | 반복문이 깊어질수록 흐름 파악이 어려움 |
| 성능 문제 | 실무 데이터에서는 큰 병목이 될 수 있음 |

초급 단계에서는 중첩 반복문의 존재를 이해하되, 성능 최적화는 Internal Table과 Open SQL 학습 후 다시 다루는 것이 적절하다.

## 13. 반복문과 시스템 필드

### 13.1 `sy-index`

`sy-index`는 반복 회차를 나타내는 대표적인 시스템 필드이다.

```abap
DO 3 TIMES.
  WRITE: / sy-index.
ENDDO.
```

### 13.2 `sy-subrc`와의 차이

`sy-subrc`는 반복 횟수가 아니라 직전 명령의 성공 여부를 나타내는 시스템 필드이다.

| 시스템 필드 | 의미 |
|---|---|
| `sy-index` | 반복 회차 |
| `sy-subrc` | 직전 처리의 결과 코드 |
| `sy-datum` | 현재 날짜 |
| `sy-uname` | 현재 사용자 |

이번 모듈에서는 `sy-index`를 중심으로 다루고, `sy-subrc`는 조회/읽기/처리 결과 확인에서 더 많이 사용한다.

## 14. 실무에서 반복문을 설계하는 기준

반복문은 단순 문법처럼 보이지만, 실무에서는 성능과 유지보수성에 큰 영향을 준다.

### 14.1 반복 횟수를 먼저 예상한다

반복문을 작성하기 전에 다음 질문을 한다.

```text
최대 몇 번 반복될 수 있는가?
반복마다 DB 조회가 들어가는가?
반복문 안에서 화면 출력이나 메시지가 과도하게 발생하는가?
반복 종료 조건이 명확한가?
```

### 14.2 반복문 안의 DB 접근 주의

초급 단계에서는 DB 접근을 아직 본격적으로 다루지 않지만, 실무에서는 다음 패턴을 조심해야 한다.

```abap
LOOP AT lt_data INTO DATA(ls_data).
  SELECT SINGLE ...
    FROM ...
    WHERE ...
    INTO ...
ENDLOOP.
```

이 패턴은 데이터 건수만큼 DB 조회가 발생하여 성능 문제가 될 수 있다.  
이 내용은 Open SQL과 Internal Table 응용 단계에서 자세히 다룬다.

이번 모듈에서는 다음 원칙만 기억한다.

```text
반복문 내부의 무거운 처리는 성능 문제를 만들 수 있다.
```

### 14.3 반복문을 짧게 유지한다

반복문 내부가 너무 길면 읽기 어렵다.

나쁜 흐름:

```text
DO 반복문 시작
  100줄의 조건 처리
  여러 개의 EXIT
  여러 개의 CONTINUE
  여러 개의 WRITE
ENDDO
```

좋은 흐름:

```text
반복문은 반복 흐름을 보여준다.
상세 처리는 별도 FORM, Method, 또는 작은 블록으로 분리한다.
```

초급 과정에서는 FORM이나 Method 분리를 깊게 다루지 않지만, 반복문이 너무 길어지면 구조 개선이 필요하다는 감각은 가져야 한다.

## 19. 자주 하는 실수와 안티패턴

### 19.1 `ENDDO` 또는 `ENDWHILE` 누락

반복문은 반드시 종료 구문이 필요하다.

```abap
DO 5 TIMES.
  WRITE: / sy-index.
" ENDDO 누락
```

해결:

```abap
DO 5 TIMES.
  WRITE: / sy-index.
ENDDO.
```

### 19.2 반복 조건 변경 누락

```abap
DATA gv_count TYPE i VALUE 1.

WHILE gv_count <= 5.
  WRITE: / gv_count.
ENDWHILE.
```

해결:

```abap
DATA gv_count TYPE i VALUE 1.

WHILE gv_count <= 5.
  WRITE: / gv_count.
  gv_count = gv_count + 1.
ENDWHILE.
```

### 19.3 `EXIT`와 `CONTINUE` 혼동

```abap
IF condition = abap_true.
  EXIT. " 현재 건만 건너뛰려던 의도라면 잘못됨
ENDIF.
```

현재 건만 건너뛰려면 다음이 맞다.

```abap
IF condition = abap_true.
  CONTINUE.
ENDIF.
```

### 19.4 반복문이 너무 깊어짐

반복문 안에 반복문, 그 안에 조건문, 다시 반복문이 들어가면 코드를 읽기 어렵다.

```text
DO
  IF
    DO
      IF
        WHILE
```

초급 과정에서는 피하는 것이 좋다.  
실무에서는 구조 분리, 데이터 전처리, 적절한 Internal Table 타입 활용을 검토한다.

## 20. 디버깅 관찰 포인트

반복문은 디버깅으로 관찰하면 이해가 빠르다.

### 20.1 Breakpoint 설정 위치

다음 위치에 Breakpoint를 걸어본다.

```abap
DO 5 TIMES.
  WRITE: / sy-index.
ENDDO.
```

권장 Breakpoint:

| 위치 | 관찰할 것 |
|---|---|
| `DO` 내부 첫 줄 | 반복이 몇 번 들어오는지 |
| `IF` 조건 줄 | 조건 결과가 언제 참이 되는지 |
| `EXIT` 줄 | 반복이 언제 종료되는지 |
| `CONTINUE` 줄 | 어떤 회차가 건너뛰어지는지 |

### 20.2 관찰 변수

| 변수/필드 | 의미 |
|---|---|
| `sy-index` | 현재 반복 회차 |
| 카운터 변수 | 조건 변화 확인 |
| 합계 변수 | 누적 값 변화 확인 |
| 조건 변수 | `IF` 또는 `WHILE` 조건 결과 확인 |

## 21. 평가 문제

### 21.1 객관식

#### Q1. `DO 5 TIMES.`의 의미로 가장 적절한 것은?

A. 조건이 참인 동안 반복한다.  
B. 5회 반복한다.  
C. 데이터베이스에서 5건을 조회한다.  
D. 5초 동안 대기한다.

**정답:** B

#### Q2. `WHILE` 반복문에서 무한 루프가 발생하기 쉬운 이유는?

A. `WRITE`를 사용할 수 없기 때문이다.  
B. 조건을 변화시키는 처리가 누락될 수 있기 때문이다.  
C. `DATA` 선언이 불가능하기 때문이다.  
D. `sy-index`가 존재하지 않기 때문이다.

**정답:** B

#### Q3. 현재 반복 회차만 건너뛰고 다음 반복으로 이동하는 명령은?

A. `EXIT`  
B. `CONTINUE`  
C. `REPORT`  
D. `CASE`

**정답:** B

#### Q4. 반복문 자체를 즉시 종료하는 명령은?

A. `EXIT`  
B. `CONTINUE`  
C. `WHEN`  
D. `WRITE`

**정답:** A

### 21.2 서술형

#### Q1. `EXIT`와 `CONTINUE`의 차이를 설명하시오.

**모범 답안:**  
`EXIT`는 현재 반복문 자체를 종료한다. 따라서 이후 반복은 수행되지 않는다. `CONTINUE`는 현재 반복 회차의 남은 처리를 건너뛰고 다음 반복 회차로 이동한다.

#### Q2. `WHILE` 반복문에서 무한 루프를 방지하려면 무엇을 확인해야 하는가?

**모범 답안:**  
반복 조건이 언젠가 거짓이 되도록 조건에 영향을 주는 변수를 변경해야 한다. 또한 복잡한 반복에서는 최대 반복 횟수 같은 안전 장치를 둘 수 있다.

#### Q3. `DO n TIMES`와 `WHILE`을 각각 언제 사용하는 것이 좋은가?

**모범 답안:**  
반복 횟수가 명확할 때는 `DO n TIMES`가 적합하고, 특정 조건이 참인 동안 반복해야 할 때는 `WHILE`이 적합하다.
