## 3. WRITE란 무엇인가?

### 3.1 쉬운 정의

`WRITE`는 ABAP 프로그램에서 값을 Classic List 화면에 출력하는 문장이다.

가장 간단한 예는 다음과 같다.

```abap
REPORT zgpt_write_hello.

WRITE 'Hello ABAP'.
```

이 프로그램을 실행하면 출력 화면에 다음과 같은 결과가 나타난다.

```text
Hello ABAP
```

즉, `WRITE`는 ABAP 초급자가 가장 먼저 눈으로 결과를 확인할 수 있는 출력 명령이다.

### 3.2 표준 ABAP 관점

ABAP의 `WRITE` 문은 전통적인 Classic Report List를 생성한다.  
Classic Report List는 SAP GUI에서 실행 결과를 텍스트 기반 리스트 형태로 보여주는 출력 방식이다.

```text
ABAP Program
  → WRITE 문 실행
  → ABAP List 생성
  → SAP GUI에서 List Output 표시
```

실무에서는 단순 확인, 교육, 디버깅성 출력, 간단한 리포트 검증에 자주 사용된다.  
하지만 대량 데이터 목록, 정렬, 필터, 레이아웃 저장, 사용자 상호작용이 필요한 업무 화면에서는 보통 ALV 또는 Fiori 기반 화면을 사용한다.

## 4. WRITE의 기본 문법

### 4.1 기본 형태

```abap
WRITE 출력대상.
```

출력대상에는 문자 리터럴, 숫자 리터럴, 변수, 시스템 필드 등이 올 수 있다.

예:

```abap
WRITE 'ABAP'.
WRITE 100.
WRITE sy-datum.
```

### 4.2 문자 리터럴 출력

문자 리터럴은 작은따옴표로 감싼다.

```abap
REPORT zgpt_write_text.

WRITE 'SAP ABAP Learning'.
```

출력 결과:

```text
SAP ABAP Learning
```

### 4.3 변수 출력

앞선 모듈에서 배운 `DATA` 문으로 변수를 선언하고 값을 출력할 수 있다.

```abap
REPORT zgpt_write_variable.

DATA gv_name TYPE c LENGTH 20 VALUE 'Kim Developer'.

WRITE gv_name.
```

출력 결과:

```text
Kim Developer
```

### 4.4 리터럴과 변수 함께 출력

여러 값을 연속해서 출력할 수 있다.

```abap
REPORT zgpt_write_multi.

DATA gv_name TYPE c LENGTH 20 VALUE 'Kim Developer'.

WRITE: 'Name:', gv_name.
```

출력 결과 예:

```text
Name: Kim Developer
```

여기서 `WRITE:`는 체인 구문이다.  
여러 출력 항목을 쉼표로 이어서 작성할 수 있다.

---

## 5. WRITE 체인 구문

ABAP에서는 같은 명령을 여러 번 반복할 때 체인 구문을 사용할 수 있다.

다음 두 코드는 의미가 유사하다.

### 5.1 개별 WRITE

```abap
WRITE 'Name:'.
WRITE gv_name.
WRITE 'Age:'.
WRITE gv_age.
```

### 5.2 체인 WRITE

```abap
WRITE: 'Name:', gv_name, 'Age:', gv_age.
```

초급 단계에서는 체인 구문을 사용하면 코드가 짧아진다는 정도로 이해하면 된다.  
다만 항목이 너무 많아지면 오히려 가독성이 떨어질 수 있으므로, 출력 의도에 맞게 줄을 나누는 것이 좋다.

## 6. 줄바꿈 출력

### 6.1 `/`의 의미

`WRITE`에서 `/`는 새 줄에 출력하라는 의미로 사용된다.

```abap
REPORT zgpt_write_new_line.

WRITE: / 'Line 1',
       / 'Line 2',
       / 'Line 3'.
```

출력 결과:

```text
Line 1
Line 2
Line 3
```

### 6.2 같은 줄 출력과 새 줄 출력 비교

```abap
REPORT zgpt_write_line_compare.

WRITE: 'A', 'B', 'C'.
WRITE: / 'D', 'E', 'F'.
```

출력 개념:

```text
A B C
D E F
```

초급자가 기억할 핵심은 다음이다.

```text
WRITE: 'A', 'B'.     " 같은 줄에 이어 출력
WRITE: / 'A', 'B'.   " 새 줄에서 출력 시작
```

### 6.3 여러 줄 구성 예제

```abap
REPORT zgpt_write_profile.

DATA gv_name TYPE c LENGTH 20 VALUE 'Kim Developer'.
DATA gv_role TYPE c LENGTH 20 VALUE 'ABAP Trainee'.
DATA gv_city TYPE c LENGTH 20 VALUE 'Seoul'.

WRITE: / '=== User Profile ===',
       / 'Name :', gv_name,
       / 'Role :', gv_role,
       / 'City :', gv_city.
```

출력 결과 예:

```text
=== User Profile ===
Name : Kim Developer
Role : ABAP Trainee
City : Seoul
```

## 7. 변수 타입별 출력

### 7.1 문자 타입 출력

```abap
REPORT zgpt_write_char.

DATA gv_code TYPE c LENGTH 4 VALUE 'A001'.

WRITE: / 'Code:', gv_code.
```

문자 타입은 지정된 길이를 가진다.  
값이 길이보다 짧으면 내부적으로 공백이 포함될 수 있다.

### 7.2 정수 타입 출력

```abap
REPORT zgpt_write_integer.

DATA gv_count TYPE i VALUE 10.

WRITE: / 'Count:', gv_count.
```

출력 결과:

```text
Count: 10
```

### 7.3 Packed Number 출력

금액이나 수량처럼 소수점이 필요한 예제에서는 `p DECIMALS`를 사용할 수 있다.

```abap
REPORT zgpt_write_amount.

DATA gv_price TYPE p LENGTH 8 DECIMALS 2 VALUE '1500.50'.

WRITE: / 'Price:', gv_price.
```

출력 결과 예:

```text
Price: 1,500.50
```

실제 표시 방식은 사용자 설정, 국가별 숫자 포맷, 시스템 환경에 따라 다르게 보일 수 있다.

### 7.4 날짜 출력

ABAP의 시스템 날짜는 `sy-datum`으로 확인할 수 있다.

```abap
REPORT zgpt_write_date.

WRITE: / 'Today:', sy-datum.
```

시스템 내부 날짜 형식은 `YYYYMMDD` 형태이지만, 출력 형식은 사용자 설정에 따라 다르게 보일 수 있다.

예:

```text
Today: 20260604
```

또는 사용자 날짜 포맷에 따라 다른 형태로 보일 수 있다.

## 8. 시스템 필드 출력

초급 단계에서 자주 사용하는 시스템 필드는 다음과 같다.

| 시스템 필드 | 의미 |
|---|---|
| `sy-datum` | 현재 시스템 날짜 |
| `sy-uzeit` | 현재 시스템 시간 |
| `sy-uname` | 현재 로그인 사용자 |
| `sy-mandt` | 현재 Client |
| `sy-sysid` | 현재 시스템 ID |
| `sy-subrc` | 직전 처리 결과 코드 |
| `sy-index` | 반복문 내부의 현재 반복 횟수 |

이번 모듈에서는 `WRITE`로 시스템 필드를 출력해보는 정도만 다룬다.

```abap
REPORT zgpt_write_system_fields.

WRITE: / 'User  :', sy-uname,
       / 'Client:', sy-mandt,
       / 'Date  :', sy-datum,
       / 'Time  :', sy-uzeit,
       / 'SysID :', sy-sysid.
```

이 예제는 사용자가 실행한 시스템 환경에 따라 결과가 다르게 나타난다.

## 9. 출력 위치와 기본 정렬 감각

초급 단계에서는 복잡한 위치 제어를 깊게 다루지 않는다.  
다만 `WRITE`가 텍스트 리스트를 구성한다는 감각은 필요하다.

### 9.1 간단한 컬럼 형태 출력

```abap
REPORT zgpt_write_columns.

WRITE: / 'ID', 10 'Name', 35 'Status'.
WRITE: / '01', 10 'Kim Developer', 35 'A'.
WRITE: / '02', 10 'Lee Consultant', 35 'I'.
```

여기서 숫자 `10`, `35`는 출력 위치를 지정하는 방식으로 이해할 수 있다.

출력 개념:

```text
ID        Name                     Status
01        Kim Developer            A
02        Lee Consultant           I
```

이 문법은 초급자에게 다소 낯설 수 있으므로, 처음에는 다음 수준으로만 이해한다.

```text
WRITE에서 특정 위치에 값을 출력할 수 있다.
텍스트 기반 리스트를 표처럼 정렬할 때 사용할 수 있다.
```

### 9.2 위치 지정의 한계

위치 지정은 간단한 연습에는 좋지만, 대량 데이터의 정렬·필터·합계·레이아웃 저장에는 부적합하다.  
이런 요구는 후속 Section의 SALV, Grid ALV에서 다루는 것이 표준적인 학습 흐름이다.

## 10. 기본 서식 지정

`WRITE`는 다양한 서식 옵션을 제공하지만, 초급 단계에서는 과도하게 확장하지 않는다.  
이번 모듈에서는 다음 정도만 소개한다.

| 서식 관점 | 설명 |
|---|---|
| 줄바꿈 | `/` 사용 |
| 위치 지정 | `10`, `35` 같은 위치 지정 |
| 리터럴과 변수 혼합 | `WRITE: / 'Name:', gv_name.` |
| 시스템 필드 출력 | `sy-datum`, `sy-uname` 등 |
| 숫자 표시 | 사용자 설정에 따라 표시 형식 차이 가능 |

### 10.1 명확한 라벨 붙이기

좋은 출력은 값만 던지는 것이 아니라, 값의 의미를 함께 보여준다.

나쁜 예:

```abap
WRITE gv_name.
WRITE gv_age.
```

좋은 예:

```abap
WRITE: / 'Name:', gv_name,
       / 'Age :', gv_age.
```

값의 의미를 함께 출력하면 초급자 실습 결과를 검토하기 쉽다.

## 11. 실행 흐름

`WRITE`를 포함한 간단한 Report의 실행 흐름은 다음과 같다.

```text
1. REPORT 프로그램 작성
2. DATA 또는 CONSTANTS로 값 준비
3. WRITE로 출력 문장 작성
4. Syntax Check
5. Activate
6. Execute
7. Output List 확인
```

실습에서 가장 많이 발생하는 문제는 다음 두 가지이다.

```text
문법 오류가 있는데 Activate하려고 함
출력은 되었지만 기대한 줄바꿈 또는 라벨이 아님
```

따라서 초급자는 실행 후 출력 화면을 보고 코드와 결과를 반드시 대조해야 한다.

## 12. 실습 1 — Hello ABAP 출력

### 12.1 목표

가장 단순한 ABAP List 출력을 만든다.

### 12.2 코드

```abap
REPORT zgpt_write_hello.

WRITE 'Hello ABAP'.
```

### 12.3 확인 포인트

| 확인 항목 | 설명 |
|---|---|
| 프로그램이 Activate 되었는가? | 활성화 오류가 없어야 한다. |
| 실행 시 Output List가 표시되는가? | SAP GUI에서 결과 화면이 보여야 한다. |
| 출력 문구가 정확한가? | `Hello ABAP`이 보이는지 확인한다. |

## 13. 실습 2 — 변수 출력

### 13.1 목표

변수 값을 `WRITE`로 출력한다.

### 13.2 코드

```abap
REPORT zgpt_write_variables.

DATA gv_name TYPE c LENGTH 20 VALUE 'Kim Developer'.
DATA gv_age  TYPE i VALUE 30.

WRITE: / 'Name:', gv_name,
       / 'Age :', gv_age.
```

### 13.3 예상 결과

```text
Name: Kim Developer
Age : 30
```

### 13.4 학습 포인트

이 실습은 `DATA` 선언과 `WRITE` 출력을 연결한다.

```text
DATA는 값을 담는 그릇을 만든다.
WRITE는 그 값을 화면에 보여준다.
```

## 14. 실습 3 — 시스템 필드 출력

### 14.1 목표

현재 사용자, Client, 날짜, 시간을 출력한다.

### 14.2 코드

```abap
REPORT zgpt_write_sys.

WRITE: / 'User  :', sy-uname,

       / 'Date  :', sy-datum,
       / 'Time  :', sy-uzeit.
```


### 14.4 학습 포인트

시스템 필드는 별도 선언 없이 사용할 수 있는 ABAP Runtime 제공 값이다.  
단, 모든 시스템 필드를 이 단계에서 암기할 필요는 없다.  
초급 단계에서는 `sy-datum`, `sy-uname`, `sy-subrc` 정도를 자주 보게 된다는 것만 기억한다.

## 15. 실습 4 — 간단한 표 형태 출력

### 15.1 목표

출력 위치를 지정하여 단순한 표 형태의 리스트를 만든다.

### 15.2 코드

```abap
REPORT zgpt_write_table_like.

WRITE: / 'ID', 10 'Name', 35 'Status'.
WRITE: / '01', 10 'Kim Developer', 35 'Active'.
WRITE: / '02', 10 'Lee Consultant', 35 'Inactive'.
WRITE: / '03', 10 'Park Admin', 35 'Blocked'.
```

### 15.3 예상 출력 개념

```text
ID        Name                     Status
01        Kim Developer            Active
02        Lee Consultant           Inactive
03        Park Admin               Blocked
```

### 15.4 주의

이 방식은 “출력 위치를 조절할 수 있다”는 감각을 주기 위한 실습이다.  
실무에서 사용자가 정렬, 필터, 레이아웃 저장, 엑셀 다운로드를 원한다면 `WRITE`보다 ALV가 적합하다.

## 16. 정상 흐름과 오류 흐름

### 16.1 정상 흐름

```text
REPORT 작성
→ DATA 선언
→ WRITE 출력 작성
→ Syntax Check
→ Activate
→ Execute
→ Output List 확인
```

### 16.2 오류 흐름 1 — 작은따옴표 누락

#### 잘못된 코드

```abap
WRITE Hello ABAP.
```

#### 문제

ABAP은 `Hello`와 `ABAP`을 문자 리터럴이 아니라 식별자로 해석하려고 한다.

#### 올바른 코드

```abap
WRITE 'Hello ABAP'.
```

### 16.3 오류 흐름 2 — 마침표 누락

#### 잘못된 코드

```abap
WRITE 'Hello ABAP'
```

#### 문제

ABAP 문장은 마침표로 종료된다.

#### 올바른 코드

```abap
WRITE 'Hello ABAP'.
```

### 16.4 오류 흐름 3 — 변수명 오타

#### 잘못된 코드

```abap
DATA gv_name TYPE c LENGTH 20 VALUE 'Kim'.

WRITE gv_nam.
```

#### 문제

선언되지 않은 변수명을 출력하려고 한다.

#### 해결

선언한 변수명과 출력 변수명이 일치하는지 확인한다.

```abap
WRITE gv_name.
```

### 16.5 오류 흐름 4 — 기대한 줄바꿈이 되지 않음

#### 코드

```abap
WRITE: 'A', 'B', 'C'.
```

#### 결과

같은 줄에 출력된다.

```text
A B C
```

#### 해결

새 줄 출력이 필요하면 `/`를 사용한다.

```abap
WRITE: / 'A',
       / 'B',
       / 'C'.
```

## 17. 디버깅과 검증 포인트

`WRITE` 자체는 단순하지만, 출력값이 기대와 다르면 다음을 확인해야 한다.

| 확인 대상 | 점검 내용 |
|---|---|
| 변수 값 | 출력 전에 변수에 값이 들어갔는가? |
| 실행 순서 | WRITE 전에 값 할당이 되었는가? |
| 조건문 | 조건 때문에 WRITE 문이 실행되지 않은 것은 아닌가? |
| 줄바꿈 | `/`를 의도대로 사용했는가? |
| 타입 | 숫자, 날짜, 문자 타입에 따라 출력 형식이 달라질 수 있는가? |

예를 들어 다음 코드는 출력값이 비어 보일 수 있다.

```abap
REPORT zgpt_write_empty.

DATA gv_name TYPE c LENGTH 20.

WRITE: / 'Name:', gv_name.
```

이 경우 오류가 아니라 `gv_name`에 값이 없기 때문에 빈 값이 출력된다.

## 18. 실무 적용 기준

### 18.1 WRITE를 사용하면 좋은 경우

| 상황 | 이유 |
|---|---|
| 초급 문법 실습 | 가장 단순하게 결과 확인 가능 |
| 간단한 테스트 출력 | 변수 값 확인에 유용 |
| 교육용 샘플 | 문법 결과를 빠르게 보여줄 수 있음 |
| 일회성 확인 프로그램 | 복잡한 UI가 필요 없을 때 적합 |
| Report Event 학습 전 단계 | Classic Report 흐름 이해에 도움 |

### 18.2 WRITE가 적합하지 않은 경우

| 상황 | 권장 대안 |
|---|---|
| 대량 데이터 업무 리스트 | SALV 또는 Grid ALV |
| 사용자가 정렬/필터/합계를 원함 | ALV |
| 화면 입력/상호작용 필요 | Selection Screen, Dynpro, Fiori |
| 표준 Fiori UX 필요 | CDS/RAP/Fiori Elements |
| 운영 보고서 형식 통제 필요 | ALV, Smart Forms, Adobe Forms 등 |

`WRITE`는 초급 학습과 간단한 출력에는 좋지만, 실무 UI의 최종 형태로는 한계가 있다.  
따라서 이번 모듈의 목적은 `WRITE`를 실무 화면의 최종 해법으로 암기하는 것이 아니라, **ABAP 프로그램이 실행되고 결과를 출력하는 최소 흐름을 이해하는 것**이다.

## 19. 실무적 안티패턴

### 19.1 의미 없는 값만 출력

나쁜 예:

```abap
WRITE gv_value.
```

좋은 예:

```abap
WRITE: / 'Total Amount:', gv_value.
```

값에는 반드시 의미를 붙이는 습관이 좋다.

### 19.2 운영용 대량 리스트를 WRITE로 작성

나쁜 방향:

```text
수천 건 데이터를 WRITE로 줄줄이 출력
정렬/필터/다운로드 요구를 수작업으로 구현
```

개선 방향:

```text
SALV 또는 Grid ALV 사용
```

### 19.3 디버깅을 모두 WRITE로 해결하려고 함

초급자는 `WRITE`로 변수 값을 확인하려고 할 수 있다.  
하지만 실제 개발에서는 ABAP Debugger를 사용해 변수 값, 실행 경로, `sy-subrc` 등을 확인하는 것이 더 정확하다.

`WRITE`는 결과 표시 도구이고, Debugger는 실행 흐름 분석 도구이다.

## 20. 강사용 설명 포인트

강의에서는 다음 순서를 추천한다.

```text
1. Hello ABAP 출력
2. 변수 출력
3. 여러 줄 출력
4. 시스템 필드 출력
5. 간단한 표 형태 출력
6. WRITE의 한계와 ALV 연결 설명
```

강사가 강조할 메시지는 다음이다.

```text
WRITE는 ABAP 프로그램의 결과를 눈으로 확인하는 가장 작은 출력 도구이다.
하지만 실무 리스트 화면의 최종 해법은 보통 ALV이다.
```

이 메시지를 통해 초급자가 `WRITE`를 과소평가하지도, 과대평가하지도 않도록 한다.

## 21. 자가 진단 문제

### Q1. `WRITE` 문의 기본 목적은 무엇인가?

A. 데이터베이스 테이블을 생성한다.  
B. Classic ABAP List에 값을 출력한다.  
C. 프로그램을 활성화한다.  
D. 권한을 검사한다.

**정답:** B

### Q2. 다음 중 새 줄에 출력하기 위해 사용하는 기호는?

A. `@`  
B. `#`  
C. `/`  
D. `&`

**정답:** C

### Q3. 다음 코드의 문제는 무엇인가?

```abap
WRITE Hello.
```

**모범 답안:**  
`Hello`가 문자 리터럴로 감싸져 있지 않다. 문자 그대로 출력하려면 `WRITE 'Hello'.`처럼 작은따옴표를 사용해야 한다.

### Q4. `WRITE`보다 ALV가 더 적합한 상황을 한 가지 쓰시오.

**모범 답안:**  
사용자가 대량 데이터 목록을 정렬, 필터, 합계, 레이아웃 저장, 엑셀 다운로드 등으로 다뤄야 하는 경우에는 `WRITE`보다 ALV가 적합하다.

### Q5. 다음 코드의 출력 결과는 개념적으로 어떻게 되는가?

```abap
WRITE: / 'A',
       / 'B',
       / 'C'.
```

**정답:**

```text
A
B
C
```

## 23. 후속 모듈 연결

다음 모듈은 `THEORY-02-M04 — IF / CASE 조건 분기`이다.

이번 모듈에서는 항상 같은 값을 출력했다.  
다음 모듈에서는 조건에 따라 서로 다른 문장을 출력한다.

예:

```abap
IF gv_score >= 90.
  WRITE 'Excellent'.
ELSE.
  WRITE 'Keep practicing'.
ENDIF.
```

즉, 학습 흐름은 다음과 같다.

```text
M01: 프로그램 구조를 만든다.
M02: 값을 담을 변수를 선언한다.
M03: 값을 화면에 출력한다.
M04: 조건에 따라 다른 출력을 만든다.
M05: 반복을 통해 여러 번 출력한다.
M06: 문자열, 날짜, 시스템 필드를 더 실용적으로 다룬다.
```
