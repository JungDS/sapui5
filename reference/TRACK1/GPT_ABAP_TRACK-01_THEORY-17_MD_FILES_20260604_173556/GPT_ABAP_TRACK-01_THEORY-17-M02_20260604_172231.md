## 3. Host Variable이란 무엇인가?

Host Variable은 ABAP SQL 문장 안에서 사용되는 ABAP 프로그램 변수이다.

ABAP SQL은 SQL처럼 보이지만, 실제로는 ABAP 프로그램 안에 작성된다.  
따라서 하나의 문장 안에 두 세계가 동시에 존재한다.

```text
SQL 세계: 테이블명, 필드명, SQL 함수, SQL 조건
ABAP 세계: DATA 변수, PARAMETERS, CONSTANTS, Field Symbol, Inline Target
```

예를 들어 다음 코드를 보자.

```abap
DATA lv_carrid TYPE s_carr_id VALUE 'AA'.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @lv_carrid
  INTO TABLE @DATA(lt_scarr).
```

여기서 각 요소를 구분하면 다음과 같다.

| 코드 요소 | 소속 | 설명 |
|---|---|---|
| `scarr` | SQL/DDIC | 조회 대상 테이블 |
| `carrid`, `carrname` | SQL/DDIC | 조회 대상 필드 |
| `lv_carrid` | ABAP | ABAP 프로그램 변수 |
| `lt_scarr` | ABAP | SQL 결과를 받을 Internal Table |
| `@lv_carrid` | Host Variable | ABAP 변수를 SQL 조건값으로 전달 |
| `@DATA(lt_scarr)` | Host Declaration | SQL 결과 대상 ABAP 변수를 인라인 선언 |

`@`는 “이 이름은 SQL 필드명이 아니라 ABAP 프로그램 영역의 값이다”라고 알려주는 역할을 한다.

---

## 4. 왜 `@`가 필요한가?

### 4.1 Classic Open SQL의 모호성

Classic Open SQL에서는 다음과 같은 문법이 가능했다.

```abap
DATA lv_carrid TYPE s_carr_id VALUE 'AA'.

SELECT carrid carrname
  FROM scarr
  INTO TABLE lt_scarr
  WHERE carrid = lv_carrid.
```

이 문장에서는 `WHERE carrid = lv_carrid`에서 오른쪽 `lv_carrid`가 ABAP 변수라는 것을 문맥으로 판단한다.  
하지만 Modern ABAP SQL은 SQL 표현식, 함수, 별칭, Inline Declaration, SQL Expression이 늘어나면서 더 엄격한 구분이 필요해졌다.

### 4.2 Modern ABAP SQL의 명확성

Modern ABAP SQL에서는 다음과 같이 작성한다.

```abap
DATA lv_carrid TYPE s_carr_id VALUE 'AA'.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @lv_carrid
  INTO TABLE @DATA(lt_scarr).
```

이 방식은 다음 장점이 있다.

| 장점 | 설명 |
|---|---|
| 가독성 | SQL 필드와 ABAP 변수가 한눈에 구분된다. |
| 문법 안정성 | 컴파일러가 SQL 영역과 ABAP 영역을 명확히 해석한다. |
| 유지보수성 | 필드명과 변수명이 비슷해도 혼동이 줄어든다. |
| 확장성 | SQL Expression, Inline Target, Host Expression과 함께 사용할 수 있다. |
| 교육 효과 | SQL Pushdown 경계와 ABAP Application Server 경계를 이해하기 쉽다. |

### 4.3 필드명과 변수명이 같을 때

다음 코드는 초급자가 실제로 자주 겪는 혼동을 보여준다.

```abap
DATA carrid TYPE s_carr_id VALUE 'AA'.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @carrid
  INTO TABLE @DATA(lt_scarr).
```

여기서 왼쪽 `carrid`는 DB 테이블 필드이고, 오른쪽 `@carrid`는 ABAP 변수이다.

| 표현 | 의미 |
|---|---|
| `carrid` | SCARR 테이블의 필드 |
| `@carrid` | ABAP 프로그램 변수 `carrid` |

그래서 `@`는 단순 문법 기호가 아니라, SQL과 ABAP의 경계를 보여주는 표시라고 이해해야 한다.

## 5. `@`를 사용하는 대표 위치

Modern ABAP SQL에서 `@`는 ABAP 프로그램 쪽 요소가 SQL 문장에 들어갈 때 사용한다.

## 5.1 WHERE 조건의 값

가장 대표적인 사용 위치는 WHERE 조건이다.

```abap
PARAMETERS p_carr TYPE s_carr_id.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @p_carr
  INTO TABLE @DATA(lt_scarr).
```

여기서 `p_carr`는 Selection Screen의 ABAP 파라미터이다.  
SQL의 `WHERE` 조건값으로 전달되므로 `@p_carr`라고 작성한다.

## 5.2 INTO 대상

조회 결과를 받을 ABAP 변수나 Internal Table도 ABAP 영역이므로 `@`가 붙는다.

```abap
SELECT FROM scarr
  FIELDS carrid, carrname
  INTO TABLE @DATA(lt_scarr).
```

기존에 선언된 Internal Table을 사용할 수도 있다.

```abap
DATA lt_scarr TYPE STANDARD TABLE OF scarr.

SELECT FROM scarr
  FIELDS carrid, carrname
  INTO CORRESPONDING FIELDS OF TABLE @lt_scarr.
```

## 5.3 UP TO n ROWS

행 수를 ABAP 변수로 제어할 때도 `@`를 사용한다.

```abap
DATA lv_max_rows TYPE i VALUE 10.

SELECT FROM scarr
  FIELDS carrid, carrname
  UP TO @lv_max_rows ROWS
  INTO TABLE @DATA(lt_scarr).
```

`lv_max_rows`는 ABAP 변수이므로 `@lv_max_rows`로 작성한다.

## 5.4 ORDER BY, GROUP BY 등에서의 주의

`ORDER BY carrid`처럼 SQL 필드명을 쓰는 위치에는 보통 `@`를 붙이지 않는다.

```abap
SELECT FROM scarr
  FIELDS carrid, carrname
  ORDER BY carrid
  INTO TABLE @DATA(lt_scarr).
```

여기서 `carrid`는 DB 필드명이다.  
`@carrid`라고 쓰면 ABAP 변수로 해석하려고 하므로 의도와 달라진다.

> 핵심 기준:  
> DB 필드명, 테이블명, SQL 함수명에는 `@`를 붙이지 않는다.  
> ABAP 변수, 파라미터, 상수, Inline Target에는 `@`를 붙인다.

## 6. Host Variable 기본 패턴

### 6.1 단일 조건

```abap
DATA lv_carrid TYPE s_carr_id VALUE 'AA'.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @lv_carrid
  INTO TABLE @DATA(lt_scarr).
```

이 패턴은 초급자가 가장 먼저 익혀야 할 기본형이다.

```text
WHERE DB_FIELD = @ABAP_VARIABLE
```

### 6.2 여러 조건

```abap
DATA lv_carrid TYPE s_carr_id VALUE 'AA'.
DATA lv_connid TYPE s_conn_id VALUE '0017'.

SELECT FROM spfli
  FIELDS carrid, connid, cityfrom, cityto
  WHERE carrid = @lv_carrid
    AND connid = @lv_connid
  INTO TABLE @DATA(lt_spfli).
```

왼쪽 `carrid`, `connid`는 DB 필드이고, 오른쪽 `@lv_carrid`, `@lv_connid`는 ABAP 변수이다.

### 6.3 IN 조건

여러 값을 조건으로 넘길 때는 Range Table 또는 Selection Option을 사용할 수 있다.

```abap
SELECT-OPTIONS s_carr FOR scarr-carrid.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid IN @s_carr
  INTO TABLE @DATA(lt_scarr).
```

`s_carr`는 ABAP 프로그램의 Selection Option이므로 `@s_carr`로 전달한다.

> 주의:  
> `SELECT-OPTIONS` 자체는 이전 Section에서 다루는 Selection Screen 주제이며, 여기서는 `IN @s_carr` 형태의 Host Variable 사용 예로만 본다.

### 6.4 BETWEEN 조건

```abap
DATA lv_date_from TYPE d VALUE '20260101'.
DATA lv_date_to   TYPE d VALUE '20261231'.

SELECT FROM sflight
  FIELDS carrid, connid, fldate, price, currency
  WHERE fldate BETWEEN @lv_date_from AND @lv_date_to
  INTO TABLE @DATA(lt_flight).
```

날짜 범위도 ABAP 변수로 전달되므로 각각 `@`가 필요하다.

## 7. Host Expression이란 무엇인가?

Host Expression은 ABAP 표현식을 SQL 문장 안에 직접 작성하고 그 결과를 SQL로 전달하는 문법이다.

형태는 다음과 같다.

```abap
@( abap_expression )
```

예를 들어 사용자가 입력한 항공사 코드를 대문자로 변환한 뒤 SQL 조건에 넘기고 싶다고 하자.

```abap
PARAMETERS p_carr TYPE string LOWER CASE.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @( CONV s_carr_id( to_upper( p_carr ) ) )
  INTO TABLE @DATA(lt_scarr).
```

여기서 `to_upper( p_carr )`와 `CONV s_carr_id( ... )`는 ABAP 표현식이다.  
이 표현식은 SQL이 DB에서 실행되기 전에 ABAP Application Server 측에서 먼저 계산된다.  
그 결과값이 SQL 조건값으로 전달된다.

---

## 8. Host Variable과 Host Expression의 차이

| 구분 | Host Variable | Host Expression |
|---|---|---|
| 형태 | `@lv_value` | `@( expression )` |
| 의미 | 이미 존재하는 ABAP 값을 SQL에 전달 | ABAP 표현식을 계산한 결과를 SQL에 전달 |
| 계산 위치 | ABAP 값 참조 | ABAP Application Server에서 사전 계산 |
| 대표 예 | `WHERE carrid = @lv_carrid` | `WHERE carrid = @( to_upper( lv_carrid ) )` |
| 적합한 경우 | 단순 변수 전달 | 간단한 변환 또는 계산 후 전달 |
| 주의점 | 타입 일치 필요 | SQL Expression과 혼동 금지 |

초급자는 다음 기준으로 구분하면 된다.

```text
이미 계산된 값을 넘기면 @변수
SQL에 넘기기 직전에 ABAP 계산을 하고 싶으면 @(표현식)
```

---

## 9. Host Expression은 SQL Expression이 아니다

이 모듈에서 가장 중요한 실무 포인트 중 하나이다.

`@( ... )` 안의 코드는 ABAP Expression이다.  
DB에서 각 행마다 계산되는 SQL Expression이 아니다.

예를 들어 다음 코드는 사용자가 입력한 값을 대문자로 바꿔 SQL 조건에 넘긴다.

```abap
WHERE carrid = @( CONV s_carr_id( to_upper( p_carr ) ) )
```

이 경우 `to_upper( p_carr )`는 한 번 계산되어 값으로 전달된다.  
DB 테이블의 각 행마다 `carrid`를 대문자로 바꾸는 것이 아니다.

반대로 SQL Expression은 DB 쪽에서 데이터 행을 대상으로 계산된다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         upper( carrname ) AS carrname_upper
  INTO TABLE @DATA(lt_scarr).
```

이 예제에서 `upper( carrname )`는 SQL Expression이며 DB 필드 `carrname`을 대상으로 동작한다.

| 구분 | 예 | 계산 위치 |
|---|---|---|
| Host Expression | `@( to_upper( p_carr ) )` | ABAP Application Server |
| SQL Expression | `upper( carrname )` | Database / SQL 처리 영역 |

> 다음 모듈 이후 `CASE`, `CAST`, `COALESCE`, 문자열/날짜 SQL Function을 학습할 때 이 차이가 매우 중요해진다.

## 10. 실무에서 자주 쓰는 Host Expression 예

### 10.1 기본값 보정

```abap
DATA lv_max_rows TYPE i VALUE 0.

SELECT FROM scarr
  FIELDS carrid, carrname
  UP TO @( COND i( WHEN lv_max_rows > 0 THEN lv_max_rows ELSE 10 ) ) ROWS
  INTO TABLE @DATA(lt_scarr).
```

`lv_max_rows`가 0이면 기본 10건을 조회하도록 ABAP 표현식으로 보정한다.

다만 초급 실무에서는 지나치게 복잡한 Host Expression보다, 먼저 별도 변수로 계산한 뒤 SQL에 전달하는 방식이 더 읽기 쉽다.

```abap
DATA lv_rows TYPE i.

lv_rows = COND #( WHEN lv_max_rows > 0 THEN lv_max_rows ELSE 10 ).

SELECT FROM scarr
  FIELDS carrid, carrname
  UP TO @lv_rows ROWS
  INTO TABLE @DATA(lt_scarr).
```

### 10.2 날짜 계산 결과 전달

```abap
DATA lv_days TYPE i VALUE 30.

SELECT FROM sflight
  FIELDS carrid, connid, fldate
  WHERE fldate >= @( sy-datum - lv_days )
  INTO TABLE @DATA(lt_flight).
```

이 예제에서 `sy-datum - lv_days`는 ABAP 날짜 계산이다.  
계산 결과가 SQL 조건값으로 전달된다.

### 10.3 문자열 정규화 후 전달

```abap
PARAMETERS p_carr TYPE string LOWER CASE.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @( CONV s_carr_id( to_upper( p_carr ) ) )
  INTO TABLE @DATA(lt_scarr).
```

사용자가 `aa`로 입력해도 `AA`로 변환하여 조회할 수 있다.

## 11. 실무 가독성 기준

Host Expression은 강력하지만, 남용하면 SQL 문장이 읽기 어려워진다.

### 11.1 좋은 예

간단한 변환은 Host Expression으로 처리해도 무방하다.

```abap
WHERE carrid = @( CONV s_carr_id( to_upper( p_carr ) ) )
```

### 11.2 더 좋은 경우가 많은 예

조건 계산이 길어지면 SQL 밖에서 변수로 준비한다.

```abap
DATA lv_carrid TYPE s_carr_id.

lv_carrid = CONV #( to_upper( p_carr ) ).

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @lv_carrid
  INTO TABLE @DATA(lt_scarr).
```

이 방식은 다음 장점이 있다.

| 장점 | 설명 |
|---|---|
| 디버깅 용이 | SQL 실행 전 변수 값을 확인할 수 있다. |
| 가독성 | SQL 문장이 짧고 명확해진다. |
| 오류 분석 | 타입 변환 오류와 SQL 오류를 분리하기 쉽다. |
| 유지보수 | 조건 보정 로직을 별도로 수정하기 쉽다. |

### 11.3 권장 기준

```text
한 줄로 명확한 단순 변환이면 Host Expression 사용 가능
조건 계산이 복잡하면 SQL 전에 ABAP 변수로 분리
DB 필드를 행 단위로 계산해야 하면 SQL Expression 사용
```

## 12. 초급자가 자주 하는 오류

## 12.1 `@` 누락

### 잘못된 예

```abap
DATA lv_carrid TYPE s_carr_id VALUE 'AA'.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = lv_carrid
  INTO TABLE @DATA(lt_scarr).
```

Modern ABAP SQL 문맥에서는 ABAP 변수 앞에 `@`를 붙여야 한다.

### 올바른 예

```abap
WHERE carrid = @lv_carrid
```

## 12.2 SQL 필드명에 `@`를 붙임

### 잘못된 예

```abap
SELECT FROM scarr
  FIELDS @carrid, @carrname
  INTO TABLE @DATA(lt_scarr).
```

`carrid`, `carrname`은 DB 필드명이므로 `@`를 붙이지 않는다.

### 올바른 예

```abap
SELECT FROM scarr
  FIELDS carrid, carrname
  INTO TABLE @DATA(lt_scarr).
```

## 12.3 Host Variable을 테이블명처럼 사용하려 함

### 잘못된 방향

```abap
DATA lv_table TYPE string VALUE 'SCARR'.

SELECT FROM @lv_table
  FIELDS carrid, carrname
  INTO TABLE @DATA(lt_scarr).
```

일반적인 정적 ABAP SQL에서 `@lv_table`을 테이블명으로 사용하는 방식은 초급 학습 대상이 아니다.  
동적 SQL은 별도 문법과 보안·검증 기준이 필요하다.

초급 단계에서는 다음처럼 정적 테이블명을 사용한다.

```abap
SELECT FROM scarr
  FIELDS carrid, carrname
  INTO TABLE @DATA(lt_scarr).
```

## 12.4 Host Expression과 SQL Expression 혼동

### 잘못된 기대

```abap
WHERE carrname = @( to_upper( carrname ) )
```

이 코드는 `carrname`을 DB 필드로 보고 행마다 대문자 처리하려는 의도일 수 있다.  
하지만 `@( ... )` 안은 ABAP Expression 영역이므로 DB 필드 `carrname`을 이런 방식으로 행 단위 처리하는 개념이 아니다.

DB 필드를 대상으로 SQL 함수 처리가 필요하면 SQL Expression을 사용해야 한다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         upper( carrname ) AS carrname_upper
  INTO TABLE @DATA(lt_scarr).
```

## 12.5 타입 불일치

### 예시

```abap
DATA lv_carrid TYPE string VALUE 'AA'.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @lv_carrid
  INTO TABLE @DATA(lt_scarr).
```

`string` 값을 고정 길이 DDIC 필드와 비교할 수는 있지만, 실무에서는 타입 의미를 맞추는 것이 좋다.

더 권장되는 방식:

```abap
DATA lv_carrid TYPE s_carr_id VALUE 'AA'.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @lv_carrid
  INTO TABLE @DATA(lt_scarr).
```

또는 입력값을 보정한다.

```abap
DATA lv_carrid TYPE s_carr_id.

lv_carrid = CONV #( to_upper( p_carr ) ).
```

## 13. 디버깅 관점

Host Variable을 사용할 때는 SQL 실행 직전에 ABAP 변수 값을 확인할 수 있다.

### 13.1 디버깅 포인트

다음 코드를 기준으로 보자.

```abap
PARAMETERS p_carr TYPE s_carr_id.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @p_carr
  INTO TABLE @DATA(lt_scarr).
```

디버깅 시 확인할 항목은 다음이다.

| 확인 항목 | 이유 |
|---|---|
| `p_carr` 값 | SQL 조건에 실제 어떤 값이 전달되는지 확인 |
| 대소문자 | 내부 코드값이 대문자 기준인지 확인 |
| 공백 | 고정 길이 타입의 trailing blank 여부 이해 |
| `lt_scarr` 결과 건수 | 조건값이 실제 데이터와 맞는지 확인 |
| `sy-subrc` | 조회 성공 여부 확인 |
| `sy-dbcnt` | 조회된 행 수 확인 |

### 13.2 조회 결과가 없을 때

조회 결과가 비어 있으면 SQL 문법보다 조건값을 먼저 확인해야 한다.

```text
1. Host Variable 값이 의도한 값인가?
2. 값이 내부 형식인가?
3. 대소문자가 맞는가?
4. 현재 Client의 데이터인가?
5. 조건이 너무 좁은가?
6. 실제 테이블에 테스트 데이터가 있는가?
```

## 14. 성능과 보안 관점

### 14.1 Host Variable은 SQL Injection 방지에 유리하다

정적 ABAP SQL에서 Host Variable을 사용하면 값이 SQL 문장의 구조가 아니라 파라미터 값으로 전달된다.  
이는 문자열 결합으로 조건문을 만드는 방식보다 안전하고 명확하다.

비권장 방향:

```abap
" 동적 SQL 문자열을 임의 결합하는 방식은 초급 과정에서 피한다.
```

권장 방향:

```abap
WHERE carrid = @lv_carrid
```

### 14.2 성능 관점

Host Variable 자체가 성능 문제를 만드는 것은 아니다.  
오히려 명확한 조건값 전달은 SQL 최적화와 코드 유지보수에 도움이 된다.

그러나 다음은 성능에 영향을 줄 수 있다.

| 상황 | 영향 |
|---|---|
| 조건값이 너무 넓음 | 대량 조회 발생 |
| WHERE 조건 누락 | 전체 테이블 조회 |
| Host Expression에 과도한 전처리 | 가독성 저하와 디버깅 어려움 |
| DB 필드 행 단위 처리를 ABAP 측 루프로 처리 | Pushdown 기회 상실 가능 |
| 타입이 맞지 않는 조건 | 변환 또는 비교 비효율 가능 |

### 14.3 실무 원칙

```text
조건값은 Host Variable로 명확히 전달한다.
DB에서 행 단위로 처리할 로직은 SQL Expression을 검토한다.
ABAP에서 한 번만 계산하면 되는 값은 Host Expression 또는 사전 변수 계산을 사용한다.
WHERE 조건 없이 대량 조회하지 않는다.
```

## 15. 미니 실습

## 15.1 실습 목표

Selection Screen 입력값을 Host Variable로 SQL에 전달하고, Host Expression을 사용해 입력값을 보정한 뒤 조회한다.

## 15.2 실습 프로그램 1 — Host Variable 기본

```abap
REPORT zgpt_sql_host_var_01.

PARAMETERS p_carr TYPE s_carr_id DEFAULT 'AA'.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @p_carr
  INTO TABLE @DATA(lt_scarr).

IF sy-subrc = 0.
  LOOP AT lt_scarr INTO DATA(ls_scarr).
    WRITE: / ls_scarr-carrid, ls_scarr-carrname.
  ENDLOOP.
ELSE.
  WRITE: / 'No carrier found.'.
ENDIF.
```

### 확인할 점

| 확인 항목 | 설명 |
|---|---|
| `p_carr` | ABAP Parameter이므로 SQL 안에서 `@p_carr`로 사용 |
| `carrid` | DB 필드명이므로 `@` 없음 |
| `@DATA(lt_scarr)` | SQL 결과를 받을 ABAP Internal Table을 인라인 선언 |
| `sy-subrc` | 조회 성공 여부 확인 |

## 15.3 실습 프로그램 2 — Host Expression 사용

```abap
REPORT zgpt_sql_host_expr_01.

PARAMETERS p_carr TYPE string LOWER CASE DEFAULT 'aa'.

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @( CONV s_carr_id( to_upper( p_carr ) ) )
  INTO TABLE @DATA(lt_scarr).

IF sy-subrc = 0.
  LOOP AT lt_scarr INTO DATA(ls_scarr).
    WRITE: / ls_scarr-carrid, ls_scarr-carrname.
  ENDLOOP.
ELSE.
  WRITE: / 'No carrier found.'.
ENDIF.
```

### 확인할 점

| 확인 항목 | 설명 |
|---|---|
| `p_carr` | 사용자가 소문자로 입력 가능 |
| `to_upper( p_carr )` | ABAP Expression |
| `CONV s_carr_id( ... )` | DDIC 타입에 맞게 변환 |
| `@( ... )` | 계산 결과를 SQL 조건값으로 전달 |

## 15.4 실습 프로그램 3 — 사전 변수 계산 방식

Host Expression이 익숙하지 않은 초급자에게는 다음 방식이 더 읽기 쉽다.

```abap
REPORT zgpt_sql_host_var_02.

PARAMETERS p_carr TYPE string LOWER CASE DEFAULT 'aa'.

DATA lv_carrid TYPE s_carr_id.

lv_carrid = CONV #( to_upper( p_carr ) ).

SELECT FROM scarr
  FIELDS carrid, carrname
  WHERE carrid = @lv_carrid
  INTO TABLE @DATA(lt_scarr).

LOOP AT lt_scarr INTO DATA(ls_scarr).
  WRITE: / ls_scarr-carrid, ls_scarr-carrname.
ENDLOOP.
```

### 비교

| 방식 | 장점 |
|---|---|
| Host Expression | 코드가 짧다. 간단한 보정에 적합하다. |
| 사전 변수 계산 | 디버깅과 설명이 쉽다. 초급자와 실무 유지보수에 유리하다. |

## 16. 강사용 설명 포인트

강의에서는 `@`를 “최신 문법에서 그냥 붙이는 기호”로 설명하면 학습자가 오래 기억하지 못한다.  
다음 구조로 설명하는 것이 좋다.

```text
ABAP SQL 안에는 SQL 세계와 ABAP 세계가 함께 있다.
SQL 필드명은 그냥 쓴다.
ABAP 변수는 @로 표시한다.
ABAP 계산식을 넘길 때는 @( ... )를 쓴다.
```

강의 중 추천 질문:

```text
WHERE carrid = @lv_carrid에서 왼쪽 carrid와 오른쪽 lv_carrid는 각각 어디에 속할까요?
@DATA(lt_scarr)는 왜 @가 붙을까요?
@( to_upper( p_carr ) )는 DB에서 실행될까요, ABAP 서버에서 실행될까요?
DB 필드를 대문자로 변환하려면 Host Expression을 써야 할까요, SQL Expression을 써야 할까요?
```

이 질문을 통해 학습자는 단순 문법 암기가 아니라 실행 위치와 경계를 이해할 수 있다.

## 17. 평가 문제

### 17.1 객관식

#### Q1. Modern ABAP SQL에서 `@lv_carrid`의 의미로 가장 적절한 것은?

A. DB 테이블 필드 `lv_carrid`를 의미한다.  
B. ABAP 프로그램 변수 `lv_carrid`를 SQL에 전달한다.  
C. SQL 함수 `lv_carrid`를 호출한다.  
D. CDS View의 Association을 의미한다.

**정답:** B

#### Q2. 다음 중 `@`를 붙이는 대상은?

A. `scarr` 테이블명  
B. `carrid` DB 필드명  
C. `lv_carrid` ABAP 변수  
D. `upper` SQL 함수명

**정답:** C

#### Q3. Host Expression `@( ... )`에 대한 설명으로 가장 적절한 것은?

A. DB에서 각 행마다 실행되는 SQL 함수이다.  
B. ABAP 표현식을 SQL 실행 전에 계산해 그 결과를 SQL로 전달한다.  
C. 테이블명을 동적으로 바꾸는 표준 초급 문법이다.  
D. Field Label을 자동으로 생성한다.

**정답:** B

### 17.2 단답형

#### Q1. `WHERE carrid = @p_carr`에서 왼쪽 `carrid`와 오른쪽 `@p_carr`의 차이를 설명하시오.

**모범 답안:**  
왼쪽 `carrid`는 조회 대상 테이블의 DB 필드이고, 오른쪽 `@p_carr`는 ABAP 프로그램의 Selection Screen Parameter이다. `@`는 오른쪽 값이 ABAP 영역의 Host Variable임을 나타낸다.

#### Q2. `INTO TABLE @DATA(lt_result)`에 `@`가 붙는 이유는 무엇인가?

**모범 답안:**  
`lt_result`는 SQL 결과를 받을 ABAP 프로그램 영역의 Internal Table이므로 SQL 문장 안에서 Host Declaration으로 표시하기 위해 `@DATA(...)`를 사용한다.

#### Q3. Host Expression과 SQL Expression의 실행 위치 차이를 설명하시오.

**모범 답안:**  
Host Expression은 `@( ... )` 안의 ABAP 표현식을 SQL 실행 전에 ABAP Application Server에서 계산해 결과값을 SQL에 전달한다. SQL Expression은 DB 필드나 SQL 값을 대상으로 데이터베이스 SQL 처리 영역에서 계산된다.

## 18. 실무 리뷰 체크리스트

| 점검 항목 | 확인 |
|---|---|
| ABAP 변수 앞에 `@`가 붙어 있는가? |  |
| DB 필드명에는 불필요한 `@`를 붙이지 않았는가? |  |
| `@DATA(...)` 인라인 대상의 의미를 이해하고 있는가? |  |
| Host Expression이 너무 복잡하지 않은가? |  |
| 조건값의 타입이 DB 필드와 의미상 맞는가? |  |
| 조회 결과가 없을 때 Host Variable 값을 먼저 확인했는가? |  |
| Host Expression과 SQL Expression을 혼동하지 않았는가? |  |
| WHERE 조건 없이 대량 조회하지 않았는가? |  |

## 19. 핵심 요약

```text
Host Variable은 ABAP 프로그램의 값을 ABAP SQL 문장 안에서 사용하는 것이다.
Modern ABAP SQL에서는 Host Variable 앞에 @를 붙인다.
DB 필드명과 SQL 함수명에는 @를 붙이지 않는다.
INTO TABLE @DATA(...)도 ABAP 영역의 결과 대상을 선언하므로 @가 붙는다.
Host Expression은 @( ... ) 형태이며 ABAP 표현식을 SQL 실행 전에 계산한다.
Host Expression은 SQL Expression과 다르다.
단순 조건값은 @변수로, 간단한 전처리는 @(표현식)으로, DB 행 단위 계산은 SQL Expression으로 처리한다.
```

## 20. 후속 모듈 연결

다음 모듈은 `THEORY-17-M03 — INTO TABLE @DATA(...) Inline Target`이다.

이번 모듈에서 `@DATA(lt_scarr)`를 Host Declaration 관점에서 간단히 다루었다면, 다음 모듈에서는 이를 더 자세히 다룬다.

```text
THEORY-17-M02
  → @ Host Variable과 Host Expression
  → SQL 안에서 ABAP 값을 구분하는 방법

THEORY-17-M03
  → INTO TABLE @DATA(...)
  → SQL 결과를 받을 Inline Target과 Result Table의 타입 추론
```

즉, M02는 “ABAP 값을 SQL에 넣는 방법”이고, M03은 “SQL 결과를 ABAP 쪽에서 받는 방법”을 본격적으로 학습하는 단계이다.
