## 3. SQL Function이란 무엇인가?

SQL Function은 SELECT 문 안에서 필드 값을 계산하거나 변환하는 함수이다.

예를 들어 `SCARR-CARRNAME`에 저장된 항공사명을 대문자로 출력하고 싶다고 하자. 전통적인 방식은 데이터를 먼저 조회한 뒤 ABAP에서 LOOP를 돌며 변환하는 것이다.

```abap
SELECT carrid,
       carrname
  FROM scarr
  INTO TABLE @DATA(lt_carrier).

LOOP AT lt_carrier ASSIGNING FIELD-SYMBOL(<ls_carrier>).
  <ls_carrier>-carrname = to_upper( <ls_carrier>-carrname ).
ENDLOOP.
```

Modern ABAP SQL에서는 SELECT 문 안에서 다음처럼 표현할 수 있다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         upper( carrname ) AS carrname_upper
  INTO TABLE @DATA(lt_carrier).
```

두 방식 모두 결과를 만들 수 있지만 처리 위치가 다르다.

| 방식 | 처리 위치 | 특징 |
|---|---|---|
| ABAP 후처리 | Application Server | 익숙하지만 데이터량이 많으면 불필요한 후처리가 늘 수 있다. |
| SQL Function | SQL/DB 계층 | SELECT 결과를 만들 때 가공할 수 있어 표현력이 좋다. |

---

## 4. 왜 SQL Function을 사용하는가?

SQL Function을 사용하는 이유는 단순히 문법이 새롭기 때문이 아니다. 핵심은 **조회 결과의 의미를 SELECT 문에서 명확히 표현**하고, 불필요한 ABAP 후처리를 줄이는 것이다.

### 4.1 표현력 향상

다음 SELECT는 결과 필드의 의미가 비교적 명확하다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname,
         upper( carrname ) AS carrname_upper
  INTO TABLE @DATA(lt_result).
```

`carrname_upper`라는 Alias를 보면 “항공사명을 대문자로 변환한 결과”임을 알 수 있다.

### 4.2 후처리 감소

조회 후 LOOP에서 문자열을 반복 가공하는 로직을 줄일 수 있다.

```text
SELECT
→ LOOP
→ 문자열 변환
→ APPEND
```

이런 흐름을 다음처럼 줄일 수 있다.

```text
SELECT에서 필요한 결과 형태를 바로 구성
```

### 4.3 데이터베이스 Pushdown 감각

Modern ABAP SQL은 가능한 일부 계산을 데이터베이스에 맡기는 방향으로 발전해왔다. 물론 모든 로직을 SQL로 밀어 넣는 것이 정답은 아니다. 하지만 단순 문자열 변환, 날짜 계산, CASE 분류, NULL 처리 같은 작업은 SELECT 문에서 표현할 수 있는 경우가 많다.

실무 판단 기준은 다음과 같다.

```text
SQL에서 자연스럽고 단순하게 표현되는 계산인가?
데이터량을 줄이거나 후처리를 줄이는 데 도움이 되는가?
가독성이 나빠지지 않는가?
릴리스와 DB 호환성에 문제가 없는가?
```

## 5. 문자열 함수 개요

문자열 함수는 문자 필드의 값을 변환하거나 결합하거나 일부를 추출하는 함수이다.

초급 단계에서 자주 접하는 함수 유형은 다음과 같다.

| 함수 유형 | 목적 | 예시 |
|---|---|---|
| 대소문자 변환 | 문자열을 대문자/소문자로 변환 | `upper`, `lower` |
| 문자열 결합 | 여러 문자열을 하나로 결합 | `concat`, `concat_with_space` |
| 부분 문자열 추출 | 문자열 일부만 가져오기 | `substring` |
| 길이 계산 | 문자열 길이 확인 | `length` |
| 공백 처리 | 앞뒤 공백 제거 | `ltrim`, `rtrim` 등 |

> [추정] 사용 가능한 SQL Function 목록과 세부 문법은 SAP_BASIS/ABAP Platform 릴리스에 따라 다를 수 있다. 실제 프로젝트에서는 해당 시스템의 ABAP Keyword Documentation 또는 Syntax Check 결과를 기준으로 확인해야 한다.

## 6. `UPPER`와 `LOWER`

### 6.1 목적

`UPPER`는 문자열을 대문자로, `LOWER`는 문자열을 소문자로 변환한다.

예를 들어 항공사명을 대문자로 조회하고 싶다면 다음처럼 작성할 수 있다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname,
         upper( carrname ) AS carrname_upper,
         lower( carrname ) AS carrname_lower
  INTO TABLE @DATA(lt_carrier).
```

### 6.2 결과 해석

| 원본 CARRNAME | UPPER 결과 | LOWER 결과 |
|---|---|---|
| Lufthansa | LUFTHANSA | lufthansa |
| American Airlines | AMERICAN AIRLINES | american airlines |

### 6.3 실무 사용 예

대소문자 차이로 인해 검색 조건이 달라지는 상황에서 정규화된 비교를 구성할 때 사용할 수 있다.

```abap
DATA(lv_name) = 'lufthansa'.

SELECT FROM scarr
  FIELDS carrid,
         carrname
  WHERE upper( carrname ) = upper( @lv_name )
  INTO TABLE @DATA(lt_result).
```

다만 이런 조건은 DB 인덱스 활용에 영향을 줄 수 있다. WHERE 절에서 필드에 함수를 적용하면 일반적인 필드 직접 비교보다 성능 특성이 달라질 수 있으므로 대량 테이블에서는 신중해야 한다.

## 7. `CONCAT`와 문자열 결합

### 7.1 목적

`CONCAT`는 두 문자열을 이어붙이는 함수이다.

예를 들어 항공사 ID와 항공사명을 하나의 표시 문자열로 만들고 싶을 수 있다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname,
         concat( carrid, carrname ) AS carrier_text
  INTO TABLE @DATA(lt_carrier).
```

위 결과는 공백 없이 붙을 수 있다.

```text
AALufthansa
```

실무적으로는 중간 구분자나 공백이 필요하다.

### 7.2 `CONCAT_WITH_SPACE`

공백을 포함한 결합이 필요하면 `concat_with_space` 계열 함수를 사용할 수 있다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname,
         concat_with_space( carrid, carrname, 1 ) AS carrier_text
  INTO TABLE @DATA(lt_carrier).
```

예상 결과는 다음과 같은 형태이다.

```text
AA American Airlines
LH Lufthansa
```

### 7.3 Alias를 반드시 명확히 작성

문자열 결합 결과에는 반드시 의미 있는 Alias를 부여하는 것이 좋다.

나쁜 예:

```abap
concat_with_space( carrid, carrname, 1 ) AS text
```

좋은 예:

```abap
concat_with_space( carrid, carrname, 1 ) AS carrier_display_name
```

Alias는 후속 ABAP 코드에서 필드명처럼 사용되므로, 결과 의미를 드러내야 한다.

## 8. `SUBSTRING`

### 8.1 목적

`SUBSTRING`은 문자열의 일부를 잘라 가져오는 함수이다.

예를 들어 항공사명 앞 5글자만 조회하고 싶다면 다음처럼 작성할 수 있다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname,
         substring( carrname, 1, 5 ) AS carrname_prefix
  INTO TABLE @DATA(lt_carrier).
```

### 8.2 위치와 길이

일반적으로 `substring( 문자열, 시작위치, 길이 )` 형태로 이해하면 된다.

```text
substring( carrname, 1, 5 )
```

의 의미는 다음과 같다.

```text
carrname의 1번째 위치부터 5글자 추출
```

### 8.3 주의할 점

문자열 함수는 데이터 타입, 길이, 문자 인코딩, DB 처리 방식에 따라 세부 결과가 달라질 수 있다. 초급 단계에서는 다음 원칙만 기억한다.

```text
문자열 일부가 필요할 때는 ABAP LOOP 후처리보다 SQL에서 바로 만들 수 있는지 검토한다.
하지만 복잡한 문자열 규칙은 ABAP 로직으로 분리하는 편이 더 읽기 쉬울 수 있다.
```

## 9. `LENGTH`와 길이 계산

### 9.1 목적

`LENGTH`는 문자열 길이를 계산한다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname,
         length( carrname ) AS carrname_length
  INTO TABLE @DATA(lt_carrier).
```

### 9.2 사용 예

문자열 길이를 기준으로 결과를 정렬하거나 필터링할 수 있다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname,
         length( carrname ) AS name_length
  ORDER BY length( carrname ) DESCENDING
  INTO TABLE @DATA(lt_carrier).
```

다만 ORDER BY나 WHERE에서 함수가 들어가면 성능 특성이 달라질 수 있다. 특히 대량 데이터에서는 단순 예제와 실무 성능 판단을 구분해야 한다.

## 10. 공백 처리 함수

문자열 앞뒤 공백을 제거하거나 특정 방향의 공백을 제거하는 함수도 사용될 수 있다.

대표적인 개념은 다음과 같다.

| 함수 유형 | 의미 |
|---|---|
| 왼쪽 공백 제거 | 문자열 앞쪽 공백 제거 |
| 오른쪽 공백 제거 | 문자열 뒤쪽 공백 제거 |
| 양쪽 공백 제거 | 앞뒤 공백 제거 |

실무에서는 외부 인터페이스 데이터, 엑셀 업로드 데이터, 코드값 정리에서 공백 처리가 중요할 수 있다. 하지만 DDIC 필드가 고정 길이 CHAR인 경우 ABAP의 표시 방식과 DB 저장 방식에 대한 이해도 함께 필요하다.

> [추정] 공백 처리 함수의 정확한 이름과 지원 범위는 시스템 릴리스에 따라 차이가 있을 수 있다. 사용 전 Syntax Check로 확인한다.

## 11. 날짜 함수 개요

날짜 함수는 DATS 타입 또는 날짜 성격의 값을 계산하거나 검증할 때 사용된다.

초급자가 알아둘 만한 대표 개념은 다음과 같다.

| 함수 유형 | 목적 |
|---|---|
| 날짜 유효성 확인 | 날짜 값이 유효한지 확인 |
| 날짜 차이 계산 | 두 날짜 사이의 일수 계산 |
| 날짜 더하기/빼기 | 기준 날짜에서 며칠 또는 몇 개월 이동 |
| 현재일 기준 계산 | ABAP Host Variable의 날짜와 DB 필드 비교 |

ABAP SQL에서 날짜 함수를 사용하면 SELECT 결과에 계산된 날짜 정보를 포함할 수 있다.

## 12. `DATS_IS_VALID`

### 12.1 목적

`DATS_IS_VALID`는 DATS 형식의 날짜 값이 유효한지 확인하는 데 사용되는 함수이다.

예를 들어 날짜 값이 비정상적으로 들어올 가능성이 있는 필드를 검증할 때 사용할 수 있다.

```abap
SELECT FROM zt_jhy_demo
  FIELDS id,
         date_value,
         dats_is_valid( date_value ) AS is_valid_date
  INTO TABLE @DATA(lt_result).
```

### 12.2 해석

결과 필드 `is_valid_date`는 날짜 유효성 판단 결과를 나타낸다.

초급자는 다음만 기억하면 된다.

```text
DATS 타입처럼 보이는 값이 실제 유효한 날짜인지 SQL에서 확인할 수 있다.
```

### 12.3 사용 시 주의

표준 DDIC DATS 필드는 일반적으로 날짜 형식 검증과 연결되어 있다. 따라서 정상적인 업무 테이블에서는 잘못된 날짜가 쉽게 들어가지 않는다. 하지만 외부 연계, 임시 테이블, 문자형 날짜 저장 구조에서는 유효성 확인이 필요할 수 있다.

## 13. `DATS_DAYS_BETWEEN`

### 13.1 목적

`DATS_DAYS_BETWEEN`은 두 날짜 사이의 일수 차이를 계산한다.

예를 들어 항공편 날짜와 오늘 날짜 사이의 차이를 구하고 싶다면 다음과 같은 형태로 생각할 수 있다.

```abap
DATA(lv_today) = sy-datum.

SELECT FROM sflight
  FIELDS carrid,
         connid,
         fldate,
         dats_days_between( @lv_today, fldate ) AS days_from_today
  WHERE carrid = 'AA'
  INTO TABLE @DATA(lt_flight).
```

### 13.2 결과 해석

| 기준일 | 비행일 | 결과 의미 |
|---|---|---|
| 오늘 | 미래 날짜 | 남은 일수 |
| 오늘 | 과거 날짜 | 지난 일수 또는 음수 가능성 검토 |

부호와 정확한 결과 해석은 함수 인자 순서와 시스템 문서를 기준으로 확인해야 한다.

> [추정] 날짜 차이 함수의 부호 해석은 인자 순서에 따라 달라질 수 있으므로, 교육 환경에서는 반드시 작은 테스트 케이스로 결과를 확인한다.

## 14. `DATS_ADD_DAYS`

### 14.1 목적

`DATS_ADD_DAYS`는 기준 날짜에 일수를 더하거나 빼는 함수이다.

예를 들어 비행일 기준 7일 후를 계산할 수 있다.

```abap
SELECT FROM sflight
  FIELDS carrid,
         connid,
         fldate,
         dats_add_days( fldate, 7 ) AS plus_7_days
  WHERE carrid = 'AA'
  INTO TABLE @DATA(lt_flight).
```

7일 전을 구하고 싶다면 음수를 사용할 수 있다.

```abap
dats_add_days( fldate, -7 ) AS minus_7_days
```

### 14.2 실무 사용 예

| 사용 상황 | 예시 |
|---|---|
| 납기일 계산 | 주문일 + 7일 |
| 만료일 계산 | 시작일 + 유효기간 |
| 알림 대상 조회 | 만료일 - 3일 |
| 기간 비교 | 기준일 전후 일정 범위 계산 |

## 15. `DATS_ADD_MONTHS`

### 15.1 목적

`DATS_ADD_MONTHS`는 기준 날짜에서 월 단위로 날짜를 이동하는 함수이다.

```abap
SELECT FROM zt_contract
  FIELDS contract_id,
         valid_from,
         dats_add_months( valid_from, 1 ) AS next_month_date
  INTO TABLE @DATA(lt_contract).
```

### 15.2 월 단위 계산의 주의점

월 단위 계산은 단순한 일수 계산보다 복잡하다.

예를 들어 다음과 같은 케이스를 생각해야 한다.

```text
2026-01-31 + 1개월
2026-02-28 + 1개월
윤년의 2월 29일
```

따라서 실무에서는 월말 처리 규칙을 반드시 확인해야 한다.

> [추정] 월말 보정 규칙은 시스템 함수의 공식 동작을 기준으로 테스트해야 하며, 계약/청구/납기 업무에서는 별도 업무 규칙이 우선할 수 있다.

## 16. Host Variable과 날짜 함수

날짜 함수는 ABAP 변수와 함께 사용하는 경우가 많다.

예를 들어 현재일을 기준으로 30일 이내의 항공편을 조회한다고 하자.

```abap
DATA(lv_today) = sy-datum.
DATA(lv_to_date) = sy-datum + 30.

SELECT FROM sflight
  FIELDS carrid,
         connid,
         fldate,
         price,
         currency
  WHERE fldate BETWEEN @lv_today AND @lv_to_date
  INTO TABLE @DATA(lt_flight).
```

여기서는 ABAP에서 날짜 범위를 계산했다. 반대로 SQL Function을 사용해 SELECT 안에서 계산할 수도 있다.

```abap
DATA(lv_today) = sy-datum.

SELECT FROM sflight
  FIELDS carrid,
         connid,
         fldate,
         dats_days_between( @lv_today, fldate ) AS days_from_today
  WHERE fldate >= @lv_today
  INTO TABLE @DATA(lt_flight).
```

초급 단계에서는 둘 중 하나만 정답이라고 외우지 않는다. 기준은 다음이다.

| 방식 | 적합한 상황 |
|---|---|
| ABAP에서 변수로 계산 | 조건이 단순하고 가독성이 좋은 경우 |
| SQL Function 사용 | 조회 결과에 계산 값을 포함하거나 DB에서 함께 처리하는 것이 자연스러운 경우 |

## 17. SQL Function과 Alias

SQL Function을 사용한 결과 필드는 반드시 의미 있는 Alias를 부여하는 것이 좋다.

예:

```abap
SELECT FROM sflight
  FIELDS carrid,
         connid,
         fldate,
         dats_days_between( @sy-datum, fldate ) AS days_from_today
  INTO TABLE @DATA(lt_flight).
```

`days_from_today`라는 Alias가 없다면 후속 ABAP 코드에서 해당 계산 결과의 의미를 파악하기 어렵다.

좋은 Alias 예시는 다음과 같다.

| 계산식 | Alias 예시 |
|---|---|
| `upper( carrname )` | `carrname_upper` |
| `substring( carrname, 1, 5 )` | `carrname_prefix` |
| `dats_days_between( @lv_today, fldate )` | `days_from_today` |
| `dats_add_days( fldate, 7 )` | `flight_date_plus_7` |

## 18. SQL Function과 WHERE 조건

SQL Function은 SELECT 결과 필드뿐 아니라 조건식에서 사용될 수도 있다.

예:

```abap
DATA(lv_search_name) = 'american'.

SELECT FROM scarr
  FIELDS carrid,
         carrname
  WHERE lower( carrname ) = lower( @lv_search_name )
  INTO TABLE @DATA(lt_result).
```

하지만 WHERE 절에서 DB 필드에 함수를 적용하면 성능상 주의가 필요하다.

### 18.1 성능상 주의

일반적으로 인덱스가 있는 필드라도 다음과 같이 함수가 적용되면 DB 최적화 방식이 달라질 수 있다.

```abap
WHERE lower( carrname ) = 'abc'
```

반면 다음처럼 원본 필드를 직접 비교하면 더 단순하다.

```abap
WHERE carrname = @lv_name
```

초급자는 다음 기준을 기억한다.

```text
SELECT 결과를 꾸미는 함수 사용은 비교적 안전하게 학습할 수 있다.
WHERE 절에서 필드에 함수를 적용하는 것은 대량 데이터 성능을 고려해야 한다.
```

## 19. SQL Function과 ORDER BY

함수 결과로 정렬할 수도 있다.

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname,
         length( carrname ) AS name_length
  ORDER BY length( carrname ) DESCENDING
  INTO TABLE @DATA(lt_carrier).
```

하지만 ORDER BY에 함수가 들어가면 DB가 계산 결과를 기준으로 정렬해야 하므로 데이터량이 많을 때 비용이 커질 수 있다. 교육용 소량 테이블에서는 개념 이해에 적합하지만, 운영 대량 테이블에서는 성능 검토가 필요하다.

## 20. ABAP 후처리와 SQL Function의 비교

### 20.1 ABAP 후처리 방식

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname
  INTO TABLE @DATA(lt_carrier).

LOOP AT lt_carrier ASSIGNING FIELD-SYMBOL(<ls_carrier>).
  <ls_carrier>-carrname = to_upper( <ls_carrier>-carrname ).
ENDLOOP.
```

### 20.2 SQL Function 방식

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname,
         upper( carrname ) AS carrname_upper
  INTO TABLE @DATA(lt_carrier).
```

### 20.3 판단 기준

| 기준 | ABAP 후처리 | SQL Function |
|---|---|---|
| 로직 위치 | Application Server | SQL/DB 계층 |
| 가독성 | ABAP 개발자에게 익숙 | SQL 표현에 익숙해야 함 |
| 데이터량 | 이미 가져온 데이터 가공 | 조회 시점에 계산 |
| 재사용성 | ABAP 메서드로 분리 가능 | SELECT 문에 포함 |
| 성능 | 데이터량 많으면 부담 가능 | DB 최적화 영향 고려 |
| 테스트 | ABAP Unit으로 분리 가능 | SQL 결과 검증 필요 |

정답은 상황에 따라 다르다. 실무에서는 가독성, 성능, 유지보수성을 함께 본다.

## 21. 실습 시나리오 1 — 항공사명 문자열 가공

### 21.1 목표

`SCARR` 테이블에서 항공사명을 조회하면서 다음 값을 함께 만든다.

| 결과 필드 | 의미 |
|---|---|
| CARRID | 항공사 ID |
| CARRNAME | 항공사명 원본 |
| CARRNAME_UPPER | 대문자 항공사명 |
| CARRNAME_PREFIX | 앞 5글자 |
| DISPLAY_TEXT | 항공사 ID + 항공사명 결합 |

### 21.2 예제 코드

```abap
REPORT zgpt_sql_string_func_01.

SELECT FROM scarr
  FIELDS carrid,
         carrname,
         upper( carrname ) AS carrname_upper,
         substring( carrname, 1, 5 ) AS carrname_prefix,
         concat_with_space( carrid, carrname, 1 ) AS display_text
  INTO TABLE @DATA(lt_carrier).

LOOP AT lt_carrier INTO DATA(ls_carrier).
  WRITE: / ls_carrier-carrid,
           ls_carrier-carrname,
           ls_carrier-carrname_upper,
           ls_carrier-carrname_prefix,
           ls_carrier-display_text.
ENDLOOP.
```

### 21.3 검증 포인트

| 확인 항목 | 설명 |
|---|---|
| Syntax Check | 시스템 릴리스에서 사용 함수가 지원되는지 확인 |
| Alias | 계산 필드 이름이 의미 있게 생성되는지 확인 |
| 출력 결과 | 원본과 가공 결과가 의도대로 다른지 확인 |
| 공백 처리 | 결합 결과에 공백이 적절히 들어갔는지 확인 |

## 22. 실습 시나리오 2 — 항공편 날짜 계산

### 22.1 목표

`SFLIGHT` 테이블에서 항공편 날짜와 현재일의 차이를 계산한다.

| 결과 필드 | 의미 |
|---|---|
| CARRID | 항공사 ID |
| CONNID | 연결 번호 |
| FLDATE | 항공편 날짜 |
| DAYS_FROM_TODAY | 현재일 기준 일수 차이 |
| FLDATE_PLUS_7 | 항공편 날짜 + 7일 |

### 22.2 예제 코드

```abap
REPORT zgpt_sql_date_func_01.

DATA(lv_today) = sy-datum.

         connid,

  INTO TABLE @DATA(lt_flight).

           ls_flight-connid,
           ls_flight-fldate,
           ls_flight-days_from_today,
           ls_flight-fldate_plus_7.

```

### 22.3 검증 포인트

| 확인 항목 | 설명 |
|---|---|
| 기준일 | `lv_today` 값이 의도한 날짜인지 확인 |
| 날짜 차이 | 양수/음수 결과를 작은 데이터로 확인 |
| 날짜 더하기 | 7일 후 날짜가 정상 계산되는지 확인 |
| WHERE 조건 | `CARRID = 'AA'` 데이터가 시스템에 존재하는지 확인 |

> [추정] 교육 시스템에 `SFLIGHT` 데이터가 없거나 항공사 ID가 다를 수 있다. 이 경우 `SCARR`, `SPFLI`, `SFLIGHT` 데이터 존재 여부를 먼저 확인하거나 시스템에 존재하는 다른 샘플 테이블로 대체한다.

## 23. 오류 상황과 해결

### 23.1 함수 미지원 오류

#### 현상

```text
Function ... is unknown
```

#### 원인

사용 중인 ABAP Platform 릴리스에서 해당 SQL Function을 지원하지 않을 수 있다.

#### 해결

1. ABAP Keyword Documentation에서 지원 여부 확인
2. Syntax Check 결과 확인
3. 지원되는 함수로 대체
4. 필요한 경우 ABAP 후처리 방식 사용

---

### 23.2 Alias 누락 또는 의미 불명확

#### 현상

계산 필드 결과를 후속 코드에서 읽기 어렵다.

#### 원인

SQL Function 결과에 의미 있는 Alias를 주지 않았거나 너무 일반적인 이름을 사용했다.

#### 해결

```abap
upper( carrname ) AS carrname_upper
```

처럼 계산 의미가 드러나는 Alias를 사용한다.

---

### 23.3 데이터 타입 불일치

#### 현상

함수 인자 타입이 맞지 않아 Syntax Error가 발생한다.

#### 원인

문자열 함수에 날짜 타입을 넣거나, 날짜 함수에 문자형 필드를 넣는 등 함수가 기대하는 타입과 실제 필드 타입이 다르다.

#### 해결

1. DDIC에서 필드 타입 확인
2. 필요 시 `CAST` 사용 검토
3. 복잡하면 ABAP 후처리로 분리

---

### 23.4 날짜 결과 해석 오류

#### 현상

날짜 차이 결과의 부호나 값이 기대와 다르다.

#### 원인

함수 인자 순서를 잘못 이해했거나 기준일과 대상일을 반대로 입력했다.

#### 해결

작은 테스트 케이스로 결과를 먼저 확인한다.

```text
기준일: 20260101
대상일: 20260110
예상 차이: 9일
```

## 24. 실무 적용 기준

### 24.1 SQL Function을 사용하면 좋은 경우

| 상황 | 이유 |
|---|---|
| SELECT 결과에 단순 가공 필드가 필요 | 후처리 LOOP 감소 |
| 문자열 표시값을 조합해야 함 | 결과 의미를 SELECT에서 표현 가능 |
| 날짜 차이를 조회 결과에 포함해야 함 | DB 조회 시 계산 가능 |
| CASE/COALESCE와 함께 결과 구조를 정리 | SQL 표현력이 향상됨 |

### 24.2 SQL Function을 남발하면 안 되는 경우

| 상황 | 이유 |
|---|---|
| 계산식이 너무 복잡함 | SELECT 문 가독성 저하 |
| 업무 규칙이 자주 바뀜 | ABAP 메서드로 분리하는 편이 유지보수에 유리 |
| 릴리스 호환성이 중요함 | 함수 지원 범위 확인 필요 |
| WHERE 절 대량 필터링에 함수 적용 | 인덱스/성능 영향 검토 필요 |
| 테스트가 복잡함 | ABAP Unit 대상 로직으로 분리 필요 |

## 25. Clean ABAP 관점

SQL Function을 사용할 때도 Clean ABAP 관점은 중요하다.

### 25.1 좋은 예

```abap
SELECT FROM scarr
  FIELDS carrid,
         carrname,
         upper( carrname ) AS carrname_upper,
         concat_with_space( carrid, carrname, 1 ) AS carrier_display_name
  INTO TABLE @DATA(lt_carrier).
```

특징:

- 각 계산 필드에 의미 있는 Alias가 있다.
- 계산식이 단순하다.
- SELECT 문만 읽어도 결과 구조가 이해된다.

### 25.2 나쁜 예

```abap
SELECT FROM scarr
  FIELDS carrid,
         concat( upper( substring( carrname, 1, 3 ) ), lower( carrid ) ) AS text
  INTO TABLE @DATA(lt_data).
```

문제:

- 계산식이 지나치게 중첩되어 있다.
- Alias `text`가 의미를 설명하지 못한다.
- 후속 개발자가 결과 의도를 이해하기 어렵다.

권장 개선:

```text
복잡한 업무 규칙은 ABAP 메서드로 분리한다.
SQL Function은 단순하고 조회 의미가 명확한 계산에 사용한다.
```

## 26. 후속 모듈과의 연결

다음 모듈은 `THEORY-17-M06 — SELECT FROM @itab 기초`이다.

이번 모듈에서 배운 SQL Function은 데이터베이스 테이블을 대상으로 하는 SELECT에서 주로 사용했다. 다음 모듈에서는 ABAP Internal Table을 SQL의 Source처럼 사용하는 `SELECT FROM @itab` 기초를 학습한다.

연결 흐름은 다음과 같다.

```text
THEORY-17-M04
SQL Expression: CASE / CAST / COALESCE
  ↓
THEORY-17-M05
SQL String / Date Function
  ↓
THEORY-17-M06
SELECT FROM @itab 기초
  ↓
THEORY-17-M07
CDS로 넘어가기 전 ABAP SQL 정리
```

즉, 이번 모듈은 “SELECT 안에서 계산하는 표현력”을 확장하는 단계이고, 다음 모듈은 “SELECT의 데이터 소스를 Internal Table까지 확장하는 단계”이다.

### 27.2 서술형

#### Q1. ABAP 후처리와 SQL Function 방식의 차이를 설명하시오.

모범 답안:
ABAP 후처리는 SELECT로 데이터를 가져온 뒤 Application Server에서 LOOP 등을 통해 값을 변환하는 방식이다. SQL Function 방식은 SELECT 문 안에서 문자열 변환이나 날짜 계산을 수행하여 조회 결과 자체에 계산 필드를 포함하는 방식이다. SQL Function은 후처리를 줄이고 조회 의미를 명확히 표현할 수 있지만, 복잡한 업무 규칙이나 성능 이슈가 있는 경우에는 신중히 사용해야 한다.

#### Q2. SQL Function 결과에 Alias를 부여해야 하는 이유를 설명하시오.

모범 답안:
SQL Function 결과는 계산된 필드이므로 원본 필드명만으로 의미를 알기 어렵다. 의미 있는 Alias를 부여하면 후속 ABAP 코드에서 해당 결과 필드의 용도를 명확히 이해할 수 있고, 유지보수성이 좋아진다.

#### Q3. WHERE 절에서 필드에 SQL Function을 적용할 때 주의할 점을 설명하시오.

모범 답안:
WHERE 절에서 필드에 함수를 적용하면 DB가 원본 필드를 직접 비교하는 것과 다른 방식으로 조건을 처리할 수 있다. 이로 인해 인덱스 활용이나 성능 특성이 달라질 수 있으므로 대량 테이블에서는 실행 계획과 성능을 검토해야 한다.

## 29. 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
SQL Function은 SELECT 문 안에서 문자열과 날짜 값을 계산하거나 변환하는 기능이다.
문자열 함수는 대소문자 변환, 결합, 부분 추출, 길이 계산 등에 사용된다.
날짜 함수는 날짜 유효성 확인, 일수 차이 계산, 날짜 더하기 등에 사용된다.
계산 결과에는 의미 있는 Alias를 부여해야 한다.
WHERE 절에서 함수 사용 시 성능과 인덱스 영향을 고려해야 한다.
복잡한 업무 규칙은 SQL에 과도하게 넣기보다 ABAP 메서드로 분리하는 것이 나을 수 있다.
```
