## 3. Custom Control이란 무엇인가?

Custom Control은 Screen Painter에서 Dynpro 화면 위에 배치하는 **컨트롤 표시 영역**이다.

초급자 관점에서는 다음처럼 이해하면 된다.

```text
Custom Control = 화면 안에 컨트롤을 올려놓기 위해 비워 둔 사각형 영역
```

예를 들어 화면 0100에 ALV Grid를 표시하고 싶다고 가정한다.  
이때 화면 전체에 직접 ALV를 그리는 것이 아니라, Screen Painter에서 특정 영역을 만든다.

```text
Screen 0100
+--------------------------------------+
| Title                                |
|                                      |
| +----------------------------------+ |
| | Custom Control Area: CC_ALV      | |
| |                                  | |
| | 여기에 ALV Grid가 표시될 예정    | |
| |                                  | |
| +----------------------------------+ |
|                                      |
+--------------------------------------+
```

여기서 `CC_ALV` 같은 이름을 가진 영역이 Custom Control이다.

중요한 점은 Custom Control 자체가 ALV Grid나 Tree Control이 아니라는 것이다.  
Custom Control은 단지 “표시될 자리”를 제공한다.

---

## 4. Container란 무엇인가?

Container는 ABAP Control Framework 객체가 화면 영역과 연결되도록 해주는 객체이다.

초급자 관점에서는 다음처럼 이해하면 된다.

```text
Container = ABAP 객체와 SAP GUI 화면 영역을 연결하는 중간 객체
```

Screen Painter에서 만든 Custom Control Area는 화면 요소이다.  
하지만 ABAP 프로그램에서 `CREATE OBJECT`로 생성한 ALV Grid나 Tree Control은 ABAP 객체이다.

이 둘을 직접 연결할 수 없기 때문에 Container가 필요하다.

```text
Screen Painter의 Custom Control Area
        ↕
CL_GUI_CUSTOM_CONTAINER 객체
        ↕
CL_GUI_ALV_GRID / Tree / 기타 Control 객체
```

즉, Container는 화면상의 빈 영역과 실제 컨트롤 객체 사이의 연결점이다.

---

## 5. `CL_GUI_CUSTOM_CONTAINER`의 역할

`CL_GUI_CUSTOM_CONTAINER`는 Dynpro 화면에 배치된 Custom Control Area를 ABAP 객체로 다루기 위한 대표 클래스이다.

생성 예시는 다음과 같다.

```abap
DATA go_container TYPE REF TO cl_gui_custom_container.

CREATE OBJECT go_container
  EXPORTING
    container_name = 'CC_ALV'.
```

여기서 중요한 것은 `container_name`이다.

`container_name = 'CC_ALV'`는 Screen Painter에서 만든 Custom Control Area의 이름과 일치해야 한다.

| 항목 | 의미 |
|---|---|
| `go_container` | ABAP 프로그램에서 사용하는 Container 객체 참조변수 |
| `cl_gui_custom_container` | Custom Control Area와 연결되는 Container 클래스 |
| `container_name` | Screen Painter에 배치한 Custom Control 이름 |
| `'CC_ALV'` | 화면에 실제 존재해야 하는 Custom Control Area 이름 |

이후 Grid ALV를 만들 때는 이 Container를 Parent로 넘긴다.

```abap
DATA go_grid TYPE REF TO cl_gui_alv_grid.

CREATE OBJECT go_grid
  EXPORTING
    i_parent = go_container.
```

이 흐름은 다음 Section의 Grid ALV에서 본격적으로 사용된다.

## 6. Custom Control과 Container의 차이

초급자는 Custom Control과 Container를 혼동하기 쉽다.

| 구분 | Custom Control | Container |
|---|---|---|
| 위치 | Screen Painter / Dynpro 화면 | ABAP 프로그램 객체 |
| 성격 | 화면 요소 | Control Framework 객체 |
| 생성 방식 | Screen Painter에서 배치 | `CREATE OBJECT`로 생성 |
| 대표 이름 | `CC_ALV` | `GO_CONTAINER` |
| 역할 | 컨트롤이 표시될 영역 제공 | 화면 영역과 실제 컨트롤 객체 연결 |
| 오류 포인트 | 화면에 이름이 없거나 다름 | 객체 생성 시 이름 불일치, 생성 타이밍 오류 |

정리하면 다음과 같다.

```text
Custom Control은 화면에 있는 영역이다.
Container는 ABAP에서 그 영역을 제어하기 위한 객체이다.
```

## 7. 왜 PBO에서 생성하는가?

Container와 ALV Grid 같은 화면 컨트롤 객체는 일반적으로 PBO에서 생성한다.

PBO는 Process Before Output의 약자이며, 화면이 사용자에게 표시되기 전에 실행되는 처리 블록이다.  
화면에 컨트롤을 표시하려면 화면 출력 전에 객체가 준비되어 있어야 한다.

```text
CALL SCREEN 0100
  → PBO 실행
    → Container 생성
    → Control 생성
    → 화면 표시
  → 사용자 입력
  → PAI 실행
```

초급자에게 중요한 감각은 다음이다.

```text
화면에 보여줄 객체는 화면이 그려지기 전에 준비해야 한다.
그래서 Container 생성은 보통 PBO에서 수행한다.
```

## 8. 반복 생성 방지

PBO는 화면이 다시 그려질 때마다 반복 실행될 수 있다.

예를 들어 사용자가 버튼을 누르거나 화면 상태가 갱신되면 PBO가 다시 호출될 수 있다.  
이때 Container 객체를 매번 새로 만들면 불필요한 객체가 반복 생성되고, 화면 오류나 성능 문제, Control Framework 오류가 발생할 수 있다.

따라서 일반적으로 다음과 같이 최초 1회만 생성한다.

```abap
MODULE status_0100 OUTPUT.

  SET PF-STATUS 'S0100'.
  SET TITLEBAR 'T0100'.

  IF go_container IS INITIAL.
    CREATE OBJECT go_container
      EXPORTING
        container_name = 'CC_ALV'.
  ENDIF.

ENDMODULE.
```

핵심은 `IF go_container IS INITIAL.` 조건이다.

| 코드 | 의미 |
|---|---|
| `go_container IS INITIAL` | 아직 객체가 생성되지 않았는지 확인 |
| `CREATE OBJECT` | 최초 1회만 객체 생성 |
| 조건 없는 생성 | PBO 반복 시 중복 생성 위험 |

## 9. 최소 예제: Container만 생성하기

이번 모듈은 Grid ALV 구현 전 단계이므로, 우선 Container만 생성하는 최소 흐름을 확인한다.

### 9.1 Screen Painter 준비

화면 0100에 Custom Control Area를 하나 배치한다.

| 항목 | 값 |
|---|---|
| Screen | 0100 |
| Custom Control Name | `CC_MAIN` |
| 영역 | 화면 중앙 또는 하단 |
| 목적 | 후속 컨트롤 표시 영역 |

### 9.2 전역 변수 선언

Module Pool 프로그램의 TOP include 또는 전역 선언 영역에 다음을 둔다.

```abap
DATA go_container TYPE REF TO cl_gui_custom_container.
```

### 9.3 PBO Module

```abap
MODULE status_0100 OUTPUT.

  SET PF-STATUS 'S0100'.
  SET TITLEBAR 'T0100'.

  IF go_container IS INITIAL.
    CREATE OBJECT go_container
      EXPORTING
        container_name = 'CC_MAIN'.
  ENDIF.

ENDMODULE.
```

### 9.4 PAI Module

```abap
MODULE user_command_0100 INPUT.

  CASE sy-ucomm.
    WHEN 'BACK' OR 'EXIT' OR 'CANC'.
      LEAVE TO SCREEN 0.
  ENDCASE.

ENDMODULE.
```

### 9.5 Screen Flow Logic

Screen 0100의 Flow Logic은 다음과 같은 구조가 된다.

```abap
PROCESS BEFORE OUTPUT.
  MODULE status_0100.

PROCESS AFTER INPUT.
  MODULE user_command_0100.
```

이 예제는 화면에 눈에 띄는 ALV를 표시하지 않을 수 있다.  
목적은 Custom Control Area와 ABAP Container 객체의 연결 흐름을 이해하는 것이다.

## 10. Grid ALV와 연결되는 전체 구조

다음 Section에서는 Grid ALV를 다룬다.  
이때 Container는 다음처럼 사용된다.

```abap
DATA go_container TYPE REF TO cl_gui_custom_container.
DATA go_grid      TYPE REF TO cl_gui_alv_grid.

MODULE status_0100 OUTPUT.

  IF go_container IS INITIAL.

    CREATE OBJECT go_container
      EXPORTING
        container_name = 'CC_ALV'.

    CREATE OBJECT go_grid
      EXPORTING
        i_parent = go_container.

  ENDIF.

ENDMODULE.
```

이 구조를 그림으로 표현하면 다음과 같다.

```text
Screen 0100
└─ Custom Control Area: CC_ALV
   └─ CL_GUI_CUSTOM_CONTAINER: GO_CONTAINER
      └─ CL_GUI_ALV_GRID: GO_GRID
```

따라서 Grid ALV를 이해하려면 먼저 Container의 의미를 이해해야 한다.

Custom Control과 Container의 정상 흐름은 다음과 같다.


## 12. 오류 흐름과 해결

### 12.1 Custom Control 이름 불일치

#### 증상

Container 생성 시 오류가 발생하거나 화면 컨트롤이 표시되지 않는다.

#### 원인

ABAP 코드의 `container_name`과 Screen Painter의 Custom Control 이름이 다르다.

```abap
CREATE OBJECT go_container
  EXPORTING
    container_name = 'CC_ALV'.
```

그런데 실제 Screen Painter 이름이 `CC_MAIN`이면 연결할 수 없다.

#### 해결

두 이름을 일치시킨다.

| 위치 | 이름 |
|---|---|
| Screen Painter Custom Control | `CC_ALV` |
| ABAP `container_name` | `'CC_ALV'` |

---

### 12.2 Custom Control을 화면에 배치하지 않음

#### 증상

코드는 맞아 보이지만 컨테이너 생성에 실패한다.

#### 원인

Screen Painter에 Custom Control Area가 없다.

#### 해결

Screen Painter에서 Custom Control 요소를 실제로 배치하고 이름을 지정한다.

---

### 12.3 PBO에서 반복 생성

#### 증상

화면 갱신 시 컨트롤이 중복 생성되거나 Control Framework 오류가 발생한다.

#### 원인

PBO가 반복 실행될 때마다 `CREATE OBJECT`가 실행된다.

#### 해결

`IS INITIAL` 체크를 사용한다.

```abap
IF go_container IS INITIAL.
  CREATE OBJECT go_container
    EXPORTING
      container_name = 'CC_ALV'.
ENDIF.
```

---

### 12.4 객체 참조변수가 로컬 변수로 선언됨

#### 증상

화면이 다시 그려질 때 객체 참조가 사라지거나 예상치 못한 동작이 발생한다.

#### 원인

Container 참조변수를 PBO Module 내부의 로컬 변수로 선언했다.

```abap
MODULE status_0100 OUTPUT.
  DATA lo_container TYPE REF TO cl_gui_custom_container.
ENDMODULE.
```

#### 해결

Container 참조변수는 일반적으로 화면 흐름 동안 유지될 수 있도록 전역 영역에 둔다.

```abap
DATA go_container TYPE REF TO cl_gui_custom_container.
```

---

### 12.5 SAP GUI 환경 의존성 누락

#### 증상

백그라운드 실행 또는 GUI가 없는 환경에서 Control Framework 관련 처리가 적합하지 않다.

#### 원인

Custom Control과 Container는 SAP GUI 기반 화면 컨트롤과 연결된다.

#### 해결

GUI 기반 Dynpro 화면에서 사용하는 객체임을 명확히 이해한다.  
백그라운드 처리, 배치 작업, 서버 사이드 처리에는 적합하지 않다.

## 13. 객체 수명과 해제

Container 객체는 화면과 연결된 GUI 리소스를 가진다.  
따라서 화면을 떠나거나 프로그램을 종료할 때 적절한 정리가 필요할 수 있다.

간단한 교육용 예제에서는 `LEAVE TO SCREEN 0`만으로 충분해 보일 수 있지만, 실무에서는 Control Framework 객체 해제를 고려한다.

예시:

```abap
IF go_container IS BOUND.
  go_container->free( ).
  CLEAR go_container.
ENDIF.

cl_gui_cfw=>flush( ).
```

초급 단계에서는 `FREE`와 `FLUSH`의 모든 세부 동작을 깊게 다루지 않는다.  
다만 다음 원칙은 기억한다.

```text
GUI Control 객체는 화면 리소스를 사용한다.
객체를 만들었다면 적절한 수명 관리가 필요하다.
```

## 14. 실무 적용 기준

### 14.1 Custom Control을 사용할 때

Custom Control은 다음과 같은 경우 사용한다.

| 사용 상황 | 예 |
|---|---|
| Dynpro 화면 안에 Grid ALV를 표시 | `CL_GUI_ALV_GRID` |
| Tree Control을 표시 | `CL_GUI_SIMPLE_TREE`, `CL_GUI_ALV_TREE` |
| Text Editor를 표시 | `CL_GUI_TEXTEDIT` |
| HTML Viewer를 표시 | `CL_GUI_HTML_VIEWER` |
| 복합 화면 구성 | 여러 Custom Control 영역 사용 |

### 14.2 Custom Control을 피해야 하는 경우

| 상황 | 이유 |
|---|---|
| 단순 리스트 출력이면 충분한 경우 | Classic List 또는 SALV가 더 단순할 수 있다. |
| 웹 기반 UI가 필요한 경우 | SAPUI5/Fiori 또는 RAP/Fiori Elements 검토가 더 적절할 수 있다. |
| 백그라운드 처리 | SAP GUI 컨트롤은 GUI 클라이언트가 필요하다. |
| 대량 화면 컨트롤 남발 | 유지보수성과 성능 문제가 생길 수 있다. |

### 14.3 실무 판단 질문

Custom Control을 설계하기 전에 다음을 검토한다.

```text
정말 Dynpro 화면에 컨트롤을 직접 배치해야 하는가?
SALV로 충분하지 않은가?
Grid ALV의 편집 기능이나 이벤트가 필요한가?
화면 로직이 과도하게 복잡해지지 않는가?
Fiori/RAP 기반으로 전환할 가능성이 있는가?
GUI 컨트롤 객체의 수명 관리가 명확한가?
```

## 15. 성능과 운영 안정성 관점

Custom Control과 Container는 단순 화면 요소처럼 보이지만, 내부적으로 SAP GUI와 ABAP Application Server 간 Control Framework 통신이 연계된다.

주의할 점은 다음과 같다.

| 관점 | 주의점 |
|---|---|
| 성능 | PBO마다 컨트롤 객체를 반복 생성하지 않는다. |
| 안정성 | 화면에 없는 Custom Control 이름을 참조하지 않는다. |
| 유지보수 | 컨테이너 이름과 화면 요소 이름을 명확히 맞춘다. |
| 권한 | 화면 실행 권한과 프로그램 실행 권한을 확인한다. |
| 운영 | 운영 시스템에서 GUI Control 오류가 발생하면 재현 조건을 기록한다. |
| 배치 처리 | GUI Control은 백그라운드 처리에 부적합하다. |

## 17. 미니 실습

### 17.1 실습 목표

Screen 0100에 Custom Control Area를 배치하고, PBO에서 `CL_GUI_CUSTOM_CONTAINER` 객체를 생성한다.

### 17.2 실습 준비

| 항목 | 값 |
|---|---|
| Program Type | Module Pool |
| Program Name | `SAPMZJHY_DYNPRO_DEMO` 또는 교육 시스템 기준명 |
| Screen | 0100 |
| Custom Control Name | `CC_MAIN` |
| PF-STATUS | `S0100` |
| Titlebar | `T0100` |

[추정] 실제 교육 시스템에서는 프로그램명과 패키지명은 강사 또는 프로젝트 네이밍 규칙에 맞게 변경한다.

### 17.3 구현 순서

```text
1. Module Pool 프로그램 생성
2. Screen 0100 생성
3. Screen Painter에서 Custom Control Area 배치
4. Custom Control 이름을 CC_MAIN으로 지정
5. TOP Include에 GO_CONTAINER 선언
6. PBO에서 GO_CONTAINER 생성
7. PAI에서 BACK/EXIT/CANC 처리
8. 프로그램 실행
9. 화면 오류 없이 출력되는지 확인
```

### 17.4 최소 코드 예시

#### TOP Include

```abap
DATA go_container TYPE REF TO cl_gui_custom_container.
```

#### PBO Include

```abap
MODULE status_0100 OUTPUT.

  SET PF-STATUS 'S0100'.
  SET TITLEBAR 'T0100'.

  IF go_container IS INITIAL.
    CREATE OBJECT go_container
      EXPORTING
        container_name = 'CC_MAIN'.
  ENDIF.

ENDMODULE.
```

#### PAI Include

```abap
MODULE user_command_0100 INPUT.

  CASE sy-ucomm.
    WHEN 'BACK' OR 'EXIT' OR 'CANC'.
      IF go_container IS BOUND.
        go_container->free( ).
        CLEAR go_container.
      ENDIF.

      LEAVE TO SCREEN 0.
  ENDCASE.

ENDMODULE.
```

#### Screen Flow Logic

```abap
PROCESS BEFORE OUTPUT.
  MODULE status_0100.

PROCESS AFTER INPUT.
  MODULE user_command_0100.
```

### 17.5 실습 결과 기록

| 항목 | 기록 |
|---|---|
| Screen Number | 0100 |
| Custom Control Name | CC_MAIN |
| Container Class | CL_GUI_CUSTOM_CONTAINER |
| 생성 위치 | PBO |
| 중복 생성 방지 여부 | `IF go_container IS INITIAL` |
| 종료 처리 | BACK/EXIT/CANC |
| 오류 메시지 | 발생 시 기록 |
| 해결 방법 | 발생 시 기록 |

## 18. 강사용 설명 포인트

강사는 이 모듈에서 다음 메시지를 강조하면 좋다.

### 18.1 “Custom Control은 자리이고 Container는 연결 객체다”

이 문장이 가장 중요하다.

```text
Custom Control = 화면의 자리
Container = 그 자리를 ABAP 객체로 다루는 연결 객체
ALV Grid = Container 위에 올라가는 실제 컨트롤
```

### 18.2 PBO 반복 실행을 반드시 설명한다

초급자는 PBO가 화면 최초 표시 때 한 번만 실행된다고 오해할 수 있다.  
PBO는 화면 갱신 시 반복 실행될 수 있으므로 객체 생성 시 `IS INITIAL` 체크가 필요하다.

### 18.3 다음 Section의 Grid ALV와 연결한다

Grid ALV를 학습할 때 다음 코드가 자연스럽게 등장한다.

```abap
CREATE OBJECT go_grid
  EXPORTING
    i_parent = go_container.
```

이 코드의 `i_parent`가 바로 이번 모듈에서 배운 Container이다.

### 19.1 객관식

#### Q1. Custom Control에 대한 설명으로 가장 적절한 것은?

A. ABAP 프로그램의 로컬 변수이다.  
B. Screen Painter에서 배치하는 화면 영역이다.  
C. 데이터베이스 테이블의 Key Field이다.

정답: B

#### Q2. `CL_GUI_CUSTOM_CONTAINER`의 역할은?

A. Open SQL 결과를 정렬한다.  
B. Dynpro 화면의 Custom Control 영역과 ABAP Control 객체를 연결한다.  
C. Function Module을 생성한다.  
D. 테이블 Technical Settings를 설정한다.

정답: B

#### Q3. Container 객체를 PBO에서 생성할 때 주의할 점은?

A. 매 PBO마다 무조건 새로 생성한다.  
B. `IS INITIAL` 체크 없이 반복 생성한다.  
C. 최초 1회만 생성되도록 참조변수 상태를 확인한다.  
D. PAI에서만 생성해야 한다.

정답: C

### 19.2 서술형

#### Q1. Custom Control과 Container의 차이를 설명하시오.

모범 답안:  
Custom Control은 Screen Painter에서 화면에 배치하는 표시 영역이고, Container는 ABAP 프로그램에서 그 화면 영역을 객체로 제어하기 위해 생성하는 연결 객체이다.

#### Q2. `container_name = 'CC_MAIN'`에서 `CC_MAIN`은 어디에 정의되어 있어야 하는가?

모범 답안:  
Screen Painter에서 해당 Dynpro 화면에 배치한 Custom Control Area의 이름과 일치해야 한다.

#### Q3. PBO에서 Container 객체를 반복 생성하면 왜 문제가 될 수 있는가?

모범 답안:  
PBO는 화면 갱신 때마다 반복 실행될 수 있으므로 매번 객체를 생성하면 중복 생성, GUI 리소스 낭비, Control Framework 오류, 성능 문제가 발생할 수 있다. 따라서 참조변수가 초기 상태인지 확인하고 최초 1회만 생성하는 방식이 필요하다.

## 21. 핵심 요약

이번 모듈의 핵심은 다음이다.

```text
Custom Control은 Screen Painter에서 만드는 화면 영역이다.
Container는 그 화면 영역을 ABAP 객체와 연결하는 객체이다.
CL_GUI_CUSTOM_CONTAINER는 Custom Control 영역과 SAP GUI Control Framework를 연결한다.
Container 객체는 일반적으로 PBO에서 생성한다.
PBO는 반복 실행될 수 있으므로 객체는 최초 1회만 생성되도록 관리해야 한다.
Grid ALV는 보통 Container 위에 생성된다.
```

이 모듈을 이해하면 다음 Section의 Grid ALV 구조가 훨씬 명확해진다.

```text
Custom Control
  → Custom Container
    → ALV Grid
```
