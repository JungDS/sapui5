RAP · Fiori elements · Action 다건 처리

RAP Action 다건 선택 시, 1회 호출 + Keys 일괄 전달

List Page에서 여러 행을 선택하고 Action을 실행할 때, 기본 호출 방식(#ISOLATED) 때문에 메서드가 건별로 호출될 수 있습니다.
아래 설정으로 한 번의 호출로 선택 Keys 전체를 받을 수 있습니다.

기본 동작
#ISOLATED → 선택 건수만큼 개별 호출
목표 동작
#CHANGE_SET → 1회 호출 + Keys 다건 전달

Q질문 요약

  • List Page에서 2줄 이상 선택 후 Action 실행
  • keys에는 1건씩만 들어오고
  • 메서드가 선택한 건수만큼 호출됨

원하는 목표: 메서드 1회 호출 + 선택한 데이터가 한 번에 keys에 전달

!원인

Fiori elements는 기본적으로 Action을 #ISOLATED로 호출할 수 있습니다. 이 경우 다건 선택은 “건별 실행”으로 처리되어, 호출마다 keys가 1건씩만 전달됩니다.

포인트: UI에서 “다건 선택 → 개별 호출”이 기본인 경우가 있어, 서버 쪽 메서드가 여러 번 실행되는 것이 정상 동작일 수 있습니다.

✓해결 방법 (UI Annotation)

Action 버튼을 정의한 @UI.lineItem의 DataFieldForAction에 invocationGrouping: #CHANGE_SET를 지정합니다. 

@UI.lineItem: [
  { position: 10 },
  { type: #FOR_ACTION,
    dataAction: 'myAction',
    label: 'My Action',
    invocationGrouping: #CHANGE_SET }   " 핵심
]
적용 결과:
  • Action 메서드가 1회만 호출됩니다.
  • keys 테이블에 선택된 모든 키가 한꺼번에 전달됩니다.

ABBehavior Implementation 처리

#CHANGE_SET에서는 keys에 다건이 들어오므로, 일반적으로 LOOP 기반으로 처리합니다. 

LOOP AT keys INTO DATA(ls_key).
  " 비즈니스 로직 수행
ENDLOOP.

Tx실무 고려사항

  • 부분 성공/부분 실패를 허용할지, 전체 롤백이 필요한지 정책 결정
  • failed / reported 메시지 설계
  • 일괄 처리 시 성능(Validation/Lock/Commit) 영향 점검

Change Set 기반은 “묶음 처리” 성격이 있으므로, 에러 처리와 사용자 피드백 품질이 결과를 좌우합니다.

∑요약

  • #ISOLATED: 다건 선택 시, 서버 메서드가 건별로 여러 번 호출될 수 있음
  • #CHANGE_SET: 서버 메서드가 1번만 호출되고, keys에 선택 Keys 전체 전달
  • 일괄 처리(Action)에서는 트랜잭션/메시지 설계가 필수
